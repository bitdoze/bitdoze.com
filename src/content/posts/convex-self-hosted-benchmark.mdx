Convex self-hosted vs cloud free tier: which one is faster? I load-tested both deployments with [oha](https://www.bitdoze.com/oha-website-load-testing/) to get real benchmark numbers instead of marketing claims, and the gap turned out to be bigger than I expected.

I put the same [real-time app built with Astro and Convex](https://www.bitdoze.com/astro-convex-realtime-app/) in front of [Convex](https://go.bitdoze.com/convex) running on a VPS and running on the managed cloud free tier, then changed one thing at a time: where the CDN sits. Four configurations, 1,000 requests each. Here are the numbers.

## Benchmark notes for 2026

Since I ran these tests in November 2025, Convex has open-sourced its backend ([get-convex/convex-backend](https://github.com/get-convex/convex-backend) on GitHub), so self-hosting is now a first-party supported path instead of something you had to assemble yourself. The Docker-based deployment I benchmarked works the same way today, and the setup steps plus current image tags are in my guide on how to [self-host Convex with Docker Compose or Dokploy](https://www.bitdoze.com/convex-self-host/).

All numbers below come from a single November 2025 test run. The self-hosted architecture hasn't changed, but the backend version has moved and cloud free tier limits change often, so check Convex's current pricing page before you commit to either side.
</Notice>

## Test setup and methodology

I used [oha](https://www.bitdoze.com/oha-website-load-testing/) for the load testing. It's a Rust-based HTTP load testing tool that shows how each configuration handles concurrent requests, and it treats any URL the same way. You can run the identical test against your own server before you trust it with production traffic; I cover that separately in [how to benchmark cloud servers (VPS)](https://www.bitdoze.com/benchmark-cloud-servers/).

### Test parameters

All tests were run with the following parameters:

| Parameter | Value | Description |
|-----------|-------|-------------|
| Total Requests | 1,000 | Number of HTTP requests to send |
| Concurrent Connections | 500 | Simulated users accessing simultaneously |
| Rate Limit | 50 req/sec | Controlled request rate for consistency |

The command used:
```bash
oha -n 1000 -c 500 -q 50 https://target-url/
```

### What oha measures

oha reports:

- Success rate: Percentage of requests that returned HTTP 200
- Average response time: Mean time from request to response
- Response time distribution: Percentile breakdown showing consistency
- Throughput: Requests handled per second
- DNS+dialup time: Connection establishment overhead

These metrics show both raw performance and reliability under load.

## Test configurations

I tested four configurations:

1. **Self-Hosted (No CDN)**: Convex backend running on a VPS, accessed directly
2. **Self-Hosted (Full CDN)**: Cloudflare CDN active for both the website and Convex endpoints
3. **Self-Hosted (Site CDN Only)**: Cloudflare CDN for the website, direct access to Convex
4. **Cloud Convex Free Tier**: Standard cloud-hosted Convex with Cloudflare on the frontend

<Image src={testPaths} alt="Diagram of the four tested request paths: client direct to self-hosted VPS at 0.98 seconds average, client through Cloudflare edge to self-hosted VPS at 0.16 seconds, client through Cloudflare for site pages with the Convex API going direct at 0.63 seconds, and client through Cloudflare to managed Convex Cloud at 1.88 seconds" />

One clarification before the numbers, because it's the most common misconfiguration: "Full CDN" means the Convex API endpoints are proxied through Cloudflare too, not just the static site. Routing only the website through the edge while the API goes direct gives you roughly the "Site CDN Only" numbers.

## Benchmark results

The headline: convex self-hosted performance beat the cloud free tier on every metric, and the biggest single factor was where the CDN sits, not the backend itself.

## Analysis and insights

### Performance comparison

For convex self-hosted performance against the cloud free tier, every metric points the same way:

| Metric | Winner | Improvement vs Cloud |
|--------|--------|---------------------|
| Average Response Time | Self-Hosted + Full CDN | **11.75x faster** |
| Fastest Response | Self-Hosted + Full CDN | 2.6x faster |
| Consistency (99th percentile) | Self-Hosted + Full CDN | 13.4x better |
| Throughput | Self-Hosted + Full CDN | 12% higher |

### Why self-hosted performs better

Several factors explain the result in this benchmark:

- Geographic proximity: You can place the server near your users
- CDN caching: Cloudflare caches static assets and optimizes API responses
- Dedicated resources: No sharing infrastructure with other tenants
- Network path: Shorter hops when the CDN is configured properly
- SSL termination: CDN handles SSL at the edge, reducing backend load

### The CDN impact

Pairing Convex with a Cloudflare CDN produced the sharpest single-variable swing in these tests. Same server, same app, only the edge configuration moved:

| Configuration | Avg Response | vs No CDN |
|--------------|-------------|-----------|
| Full CDN (Site + API) | 0.16s | 6.1x faster |
| Site CDN Only | 0.63s | 1.6x faster |
| No CDN | 0.98s | baseline |

<Notice type="warning" title="CDN Configuration Matters">
Simply having a CDN isn't enough. Most of the performance jump comes from routing Convex API endpoints through the CDN as well, not just the static website assets.
</Notice>

### Data transfer comparison

| Configuration | Size/Request | Data/sec |
|--------------|-------------|----------|
| Self-Hosted (No CDN) | 128 KiB | 5.90 MiB |
| Self-Hosted (Full CDN) | 14.8 KiB | 736 KiB |
| Self-Hosted (Site CDN) | 17.6 KiB | 841 KiB |
| Cloud Convex | 17.6 KiB | 784 KiB |

The CDN configurations compressed the responses: about 88% less data per request than the uncompressed origin. That matters on top of latency: less bandwidth per request means the origin VPS can absorb more traffic before CPU or network become the bottleneck.

## Caveats and how to reproduce these tests

Before you take the 12x figure and plan an architecture around it, know what this benchmark does and doesn't measure:

- Single client location. All runs came from one connection in one region. Your users' distance to the origin and to the nearest Cloudflare edge will move these numbers.
- HTTP GET against the app's landing page only. No mutations, no WebSocket subscriptions. Real-time sync is a different traffic pattern and wasn't benchmarked here.
- A 1,000-request sample at 50 req/sec is enough to compare configurations side by side. It is not a stress test, and nothing here tells you where these setups break.
- The CDN runs were warm-cache. I hit the URL a few times before recording, so these numbers reflect steady state, not cold misses.
- The cloud result includes shared-tenancy variance you can't control. A different region or a busier day on Convex Cloud would produce different numbers.

If you want to compare your own setups fairly, this is the checklist I'd follow:

<ListCheck>
<ul>
<li>Install oha: <code>brew install oha</code> on Mac, <code>cargo install oha</code> on Linux, or <code>winget install hatoo.oha</code> on Windows</li>
<li>Pin the same flags for every run: <code>oha -n 1000 -c 500 -q 50 https://your-url/</code></li>
<li>Warm the CDN cache with a few manual requests first, or your run measures cold misses</li>
<li>Run from the region your users live in, not from wherever is convenient</li>
<li>Test both CDN-on and CDN-off so you can see what the edge contributes</li>
<li>Compare p50 and p99, not just the average. Averages hide tail latency, and tail latency is what users complain about</li>
</ul>
</ListCheck>

## When to choose each option

### Choose self-hosted + full CDN when

<ListCheck>
<ul>
<li>Performance matters for your application</li>
<li>Your users are concentrated in specific regions</li>
<li>You want predictable response times</li>
<li>You're comfortable operating a server</li>
<li>Sub-200ms response times are important</li>
</ul>
</ListCheck>

### Choose cloud Convex free tier when

When I ran the original tests, the free tier covered 1M function calls per month and 1GB of storage. As of September 2026, Convex's plans page lists the free tier at 1M function calls, 0.5 GB of database storage, and 1 GB of file storage. Check the current page before you plan around those numbers, because they move.

<ListCheck>
<ul>
<li>You're prototyping or in development</li>
<li>Traffic stays well inside the free tier limits</li>
<li>You don't want to manage infrastructure</li>
<li>Geographic distribution doesn't matter</li>
<li>1-2 second response times are acceptable</li>
</ul>
</ListCheck>

## Recommendations

Based on these benchmarks:

### For production applications

1. [Self-host Convex with Docker Compose or Dokploy](https://www.bitdoze.com/convex-self-host/) on a VPS near your users
2. Use Cloudflare for both the website and the Convex endpoints
3. Configure caching rules for your API responses
4. Re-run oha after every configuration change so you know what each change bought you

### For development/staging

1. Cloud Convex free tier works fine
2. Use self-hosted for performance testing before production
3. Keep development and production configurations similar, or follow the [Vercel deployment guide for Astro + Convex](https://www.bitdoze.com/astro-convex-vercel-deployment/) if you'd rather keep staging fully managed

### Optimal infrastructure setup

## Conclusion

Self-hosted Convex with a CDN was about 12x faster than the cloud-hosted free tier in these tests. The response time difference is substantial, especially for production applications where users notice latency.

But performance isn't the only factor. The cloud option handles infrastructure for you, which matters during development or when you don't have time to manage servers. If sub-second response times aren't critical, the cloud version works fine.

For production apps where performance matters, setting up self-hosted Convex with a CDN is worth the effort.

## FAQ

<Accordion label="How do I run these benchmarks myself?" group="faq" expanded="true">
The command is the same for any target:

```bash
oha -n 1000 -c 500 -q 50 https://your-convex-app-url/
```

Adjust the parameters based on your testing needs:
- `-n`: Total number of requests
- `-c`: Concurrent connections
- `-q`: Rate limit (requests per second)

For a fair comparison between two setups, follow the reproduce checklist above and change one variable at a time.
</Accordion>

<Accordion label="Is Cloudflare necessary for good performance?" group="faq">
You don't strictly need Cloudflare, but a CDN gets you:
- SSL termination at edge locations
- Geographic distribution of content
- DDoS protection
- Compression and optimization

Cloudflare's free tier is sufficient for most self-hosted Convex deployments. If you want a cheaper alternative, [Bunny.net CDN](https://go.bitdoze.com/bunny) is the one I'd look at first. I cover the tradeoffs in my [Bunny.net review (cheaper than Cloudflare)](https://www.bitdoze.com/bunny-net-review/). Fastly or Amazon CloudFront would do the same job.
</Accordion>

<Accordion label="What are the Convex free tier limits?" group="faq">
When I ran the original tests, the free tier included 1M function calls per month and 1GB of storage. As of September 2026, the plans page lists the free tier at 1M function calls, 0.5 GB of database storage, and 1 GB of file storage. Check the current page before relying on any of those numbers, since the terms change.

| | Cloud free tier | Self-hosted |
|---|---|---|
| Monthly cost | $0 | ~$8-20 VPS plus free Cloudflare tier, about $10-25 all-in |
| You manage | Nothing | One VPS (pricing notes in my [Hetzner Cloud review](https://www.bitdoze.com/hetzner-cloud-review/)) |
| Limits | Free tier caps apply | Your hardware |

Self-hosting becomes cost-effective when you exceed the free tier limits or need the latency numbers from the benchmark above.
</Accordion>

<Accordion label="Does self-hosting affect real-time sync performance?" group="faq">
The sync mechanism is the same in both deployments. What this benchmark measured is HTTP request/response performance, which affects:
- Initial page loads
- Data fetching
- Function calls

WebSocket-based real-time updates weren't benchmarked here. I'd expect them to gain from the same geographic proximity, but that's inference, not measurement.
</Accordion>

<Accordion label="Is the Convex backend officially open source now?" group="faq">

Convex open-sourced its backend ([get-convex/convex-backend](https://github.com/get-convex/convex-backend) on GitHub), which is why self-hosting now has an official path and why my [setup guide](https://www.bitdoze.com/convex-self-host/) exists in its current form. For the latest license and support details, check the repository README and Convex's docs directly, since that's where changes show up first.
</Accordion>
