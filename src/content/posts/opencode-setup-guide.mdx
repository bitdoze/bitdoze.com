## What OpenCode actually is

OpenCode is a terminal-based AI coding agent and an open-source Claude Code alternative. It reads your codebase, plans changes, edits files, runs commands, and iterates on failures. It runs the same loop as Claude Code, but open source and provider-agnostic. It works with 300+ providers through the [models.dev](https://models.dev) catalog: Anthropic, OpenAI, Google, Alibaba, MiniMax, DeepSeek, Xiaomi, Moonshot, and many more. You can also run local models through Ollama.

The main difference from Claude Code: you pick the model and the provider. If Claude Sonnet is too expensive for a task, switch to DeepSeek V4.1 Flash at $0.15/M input tokens. If you need maximum reasoning, switch to GLM-5.3. On the Go plan that works out to roughly $500/month of usage for $10/month. You control the cost.

v2 also adds a desktop app (beta) and a web UI via `opencode pair`, but this guide stays focused on the terminal workflow.

## Installing OpenCode on a VPS

### What you need

<ListCheck>
<ul>
<li>A Linux VPS with 1GB+ RAM (OpenCode is a thin client; the model runs at the API)</li>
<li>`curl` (present on virtually every Linux distro)</li>
<li>A provider API key or an OpenCode Go subscription</li>
<li>A terminal emulator. Image-capable terminals (WezTerm, Ghostty, Kitty) enable drag-and-drop screenshots, but they are optional. On a headless VPS over plain SSH, OpenCode works fine without them. If you want the full terminal experience, see our [WezTerm terminal setup](/install-wezterm-mac/) guide.</li>
</ul>
</ListCheck>

No Node.js required. The v2 curl installer and standalone binaries need nothing beyond a basic Linux box. For a full [VPS setup for AI coding agents](/vps-ai-coding-setup/), see that guide.

### Install with the v2 script

<Notice type="warning" title="The old install command now gives you OpenCode v1">
`https://opencode.ai/install` now redirects to the legacy v1 branch installer. The v2 install command is different. Both lines install an `opencode` command and **cannot coexist**. If you previously installed v1 (npm package `opencode-ai`), remove it first.

| Line | Install command | npm package |
|------|----------------|-------------|
| **v2 (current)** | `curl -fsSL https://opencode.ai/v2/install \| bash` | `@opencode/cli` |
| v1 (legacy) | `curl -fsSL https://opencode.ai/install \| bash` | `opencode-ai` |
</Notice>

```bash
curl -fsSL https://opencode.ai/v2/install | bash
```

This installs to `$HOME/.opencode/bin` and adds it to your PATH automatically (use `--no-modify-path` to skip that). Verify it works:

```bash
opencode --version
```

Expected output: `2.x` (current release is 2.3.2 as of November 2026). If you see `1.x`, you got the v1 installer. Remove it and use the v2 URL above.

**Failure modes to watch for:**

## Configuring a model provider

OpenCode supports several ways to connect models, from easiest to most flexible. The documented v2 flow is to run `/connect` in the TUI and pick a provider. OpenCode stores the credentials for you. For config-file-based setup, use `opencode.jsonc` with `{env:VAR}` substitution.

<Notice type="info" title="v1 habit: .env files">
If you used `~/.config/opencode/.env` with v1, note that v2 documentation does not mention `.env` file loading. The supported paths are `/connect` or exporting environment variables in your shell profile. The `.env` trick may still work on v2, but it is undocumented, so don't rely on it.
</Notice>

### Option 1: OpenCode Console (formerly Zen)

The built-in provider is now called **OpenCode Console**. Sign in at [opencode.ai/console](https://opencode.ai/console/login), get an API key, and connect:

```
/connect
```

Select `opencode` and paste your key. The Console has built-in free models you can use without a paid plan. To hide them: set `OPENCODE_DISABLE_FREE_MODELS=1`.

### Option 2: OpenRouter

OpenRouter gives you access to 300+ models through a single API key. This is the pragmatic default if you want maximum model choice without managing provider accounts.

```
/connect
```

Select OpenRouter and paste your key. For config-file setup (e.g. when you want the key managed via environment variable):

```jsonc
// opencode.jsonc: project root or ~/.config/opencode/
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openrouter/deepseek/deepseek-v4.1-flash",
  "providers": {
    "openrouter": {
      "settings": {
        "apiKey": "{env:OPENROUTER_API_KEY}"
      }
    }
  }
}
```

Then export `OPENROUTER_API_KEY` in your shell profile.

### Option 3: Direct provider keys

For specific providers you can set API keys directly. Export them in your shell profile or reference them via `{env:VAR}` in `opencode.jsonc`:

```bash
# MiniMax (https://go.bitdoze.com/minimax)
export MINIMAX_API_KEY=your-key

# Z.AI / GLM (https://go.bitdoze.com/glm)
export ZAI_API_KEY=your-key

# Xiaomi MiMo (https://go.bitdoze.com/mimo)
export MIMO_API_KEY=your-key

# DeepSeek
export DEEPSEEK_API_KEY=your-key

# Moonshot (Kimi)
export MOONSHOT_API_KEY=your-key
```

Then `/connect` in the TUI and select the provider. OpenCode also supports **Sign in with ChatGPT**. If you have a ChatGPT Plus/Pro plan, you can use it instead of an OpenAI API key (usage counts against your plan, with context caps applied).

### Local models with Ollama

In v2, Ollama is a first-class provider with auto-discovery. OpenCode probes `http://127.0.0.1:11434`, discovers your completion models, and adds them to `/models` automatically. No environment variables, no config hacks.

```bash
ollama serve
ollama pull qwen3:8b
opencode
```

The model appears in `/models` with no extra setup. For a full [Ollama Docker install guide](/ollama-docker-install/), see that walkthrough.

For a remote Ollama instance, set the base URL in `opencode.jsonc`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "https://ollama.example.com/v1",
        "apiKey": "{env:OLLAMA_API_KEY}"
      }
    }
  }
}
```

LM Studio and vLLM are also supported as local runtimes.

**Verify:** run `/models` and confirm your local model appears. **Failure mode:** Ollama is not running or is bound to a different interface. Check `curl http://127.0.0.1:11434/api/tags`.

## Working with OpenCode day to day

### Initialize a project (AGENTS.md)

The first time you open OpenCode in a project:

```bash
cd /path/to/project
opencode
```

Run `/init` to have OpenCode analyze your codebase and create an `AGENTS.md` file in the project root. This file tells OpenCode about your project structure, coding patterns, and conventions.

<Notice type="info" title="Note on /init">
`/init` is documented in the v1 docs but not in the v2 docs. It likely still works, but if it's missing in your version, write `AGENTS.md` by hand. That's the v2-safe path. The format is a plain markdown file with project conventions.
</Notice>

You can edit `AGENTS.md` manually to add custom instructions. Commit it to git so every contributor (and every OpenCode session) gets the same context.

**Verify:** `ls AGENTS.md` after running `/init`, then `git add AGENTS.md`.

### Plan mode vs build mode

This is the workflow I keep coming back to. Use **Shift+Tab** to cycle between agents. Some builds use plain Tab instead; if Tab does nothing, try Shift+Tab. You can also use `Ctrl+X, A` or `/agents`.

**Plan mode** (read-only): OpenCode reads your codebase and describes how it would implement a feature. No changes are made. You review the plan, give feedback, iterate.

**Build mode** (read-write): OpenCode makes the actual changes to your files.

The pattern:

1. Switch to plan mode
2. Describe what you want
3. Review the plan, add constraints or images
4. Switch to build mode
5. Tell it to go ahead

This is safer than letting the agent loose immediately, especially on production code.

### File references, undo/redo, shell mode, and /btw

Use `@` to point OpenCode at specific files. You can also reference line ranges:

```
Look at @src/api/auth.ts#20-45 and add the same pattern to @src/api/settings.ts
```

**Undo and redo:** if OpenCode makes a change you don't like:

```
/undo
```

It reverts the changes and shows your original prompt again so you can rephrase. `/redo` brings the changes back if you changed your mind.

Daily-driver tips:
- `!` at the start of a prompt runs a shell command (shell mode)
- `/btw` asks a side question without interrupting the current task
- `Ctrl+P` opens the command palette
- `F2` cycles through models
- `@general` invokes the built-in subagent (background by default since v2.3.0)
- Multiple tabs in the TUI let you work on several sessions at once

## Add persistent memory to OpenCode (MCP)

OpenCode supports MCP servers, which means you can give it long-term memory with [Hindsight](/hindsight-docker-deploy/). There's a [community plugin](https://hindsight.vectorize.io/integrations) that auto-retains your conversations and recalls relevant context on session start. It adds retain, recall, and reflect tools directly into OpenCode's tool palette.

If you prefer to configure MCP servers manually via `opencode.jsonc`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "hindsight": {
      "type": "local",
      "command": ["npx", "-y", "@hindsight/mcp"],
      "environment": {
        "HINDSIGHT_API_KEY": "{env:HINDSIGHT_API_KEY}"
      }
    }
  }
}
```

This is useful if you work on the same project across multiple sessions and want OpenCode to remember decisions, conventions, and past debugging sessions. You can also [connect OpenCode to 1,500+ apps with Composio MCP](/composio-mcp-guide/) for tool integrations beyond memory.

## Running OpenCode on a VPS via SSH

OpenCode works over SSH. I run it on a $6/month [Hetzner Cloud VPS](https://go.bitdoze.com/hetzner) and connect from my laptop. A few tips:

Use **tmux** so your session survives if the SSH connection drops. Check our [tmux basics and commands](/tmux-basics/) guide if you're new to it, or our [terminal multiplexers like tmux and Zellij](/best-terminal-multiplexers/) comparison for alternatives:

```bash
tmux new -s code
cd /path/to/project
opencode
```

If you detach (`Ctrl+B, D`) and reconnect later, `tmux attach -t code` puts you back where you left off.

For a better terminal experience over SSH, use **mosh** instead of plain SSH. It handles network drops and roaming better:

```bash
mosh user@your-vps-ip
```

<Notice type="info" title="Gotchas on a VPS">
- v2 runs a shared background server per user (it owns all sessions and tools). For isolation, use `opencode --standalone`. If the shared service misbehaves: `opencode service restart` or `opencode service set disabled true`.
- The installer adds `$HOME/.opencode/bin` to your PATH. If `opencode` isn't found after a fresh SSH login, run `source ~/.bashrc`.
- You don't need Node.js: the curl installer and standalone binaries work without it.
- For automation, use `opencode run --model opencode-go/minimax-m3 "Fix the failing test"` for non-interactive tasks in cron or CI. `opencode mini` gives you a minimal TUI. `opencode pair` starts a web UI with a one-time link (5-minute expiry) for occasional browser access.
</Notice>

Costs are dominated by model usage, not the box. A $6/month VPS is more than enough; the heavy lifting happens at the API provider. For more on preparing a [VPS setup for AI coding agents](/vps-ai-coding-setup/), see that guide.

## Troubleshooting and ops gotchas

| Problem | Cause | Fix |
|---------|-------|-----|
| `opencode: command not found` | PATH not reloaded | `source ~/.bashrc` or open a new SSH session |
| `opencode --version` shows 1.x | v1 installer or old npm package | `npm rm -g opencode-ai`, then install v2 with `curl -fsSL https://opencode.ai/v2/install \| bash` |
| Provider key not picked up | v1 `.env` habit doesn't work on v2 | Use `/connect` or `{env:VAR}` in `opencode.jsonc` |
| Model missing from `/models` | Ollama not running, or free models hidden | Start Ollama; check `OPENCODE_DISABLE_FREE_MODELS` |
| Shared service misbehaving | Background service conflict | `opencode service restart` or `opencode --standalone` |
| Docker container exits immediately | Wrong tag or missing TTY | Pin a v2 tag (`ghcr.io/anomalyco/opencode:2.3.2`) and use `-it` |

For more, see the [official troubleshooting docs](https://opencode.ai/docs/troubleshooting/).

To fully remove OpenCode: `opencode uninstall` (previews files before deleting). To disable the shared background service: `opencode service set disabled true`.

</Accordion>

<Accordion label="Is my code used for training?" group="faq">
Depends on the model. Open models on OpenCode Go (GLM-5.x, Kimi, MiniMax, Qwen) have zero data retention. Grok 4.7, GPT-Luna, and Claude Haiku 5.5 retain data for 30 days; Gemini 4 Argon for 55 days. Muse Spark 1.x and Iceman Contributor explicitly train on prompts. Avoid them for sensitive code. Workspace privacy defaults block endpoints that train on data. Check the current DeepSeek ZDR status if that matters for your use case.
</Accordion>

<Accordion label="How does OpenCode compare to Aider?" group="faq">
Both are terminal coding agents. OpenCode has a richer TUI with plan mode, image support, and a model marketplace. Aider is more minimal and has stronger git integration, plus support for some obscure model providers. For most developers, OpenCode is the better daily driver.
</Accordion>

<Accordion label="Can I use OpenCode alongside Hermes Agent?" group="faq">
Yes, they complement each other. OpenCode is for coding tasks: editing files, running builds, fixing bugs. Hermes Agent is for broader tasks: web searches, scheduled jobs, messaging, server management. Run both on the same VPS. The OpenCode Go endpoint (`https://opencode.ai/inference/go`) is OpenAI-compatible and officially supports Hermes ≥ v0.21.6 as a validated harness.
</Accordion>
