## Running WordPress on ARM: compatibility checklist

ARM works for WordPress, but a few things are worth verifying after provisioning:

<ListCheck>
<ul>
<li><strong>Architecture check</strong>: run <code>uname -m</code>, expect <code>aarch64</code></li>
<li><strong>PHP extensions</strong>: all standard extensions including imagick and webp ship ARM64-native</li>
<li><strong>Caching stack</strong>: Redis, Varnish, and object-cache plugins all work fine on ARM</li>
<li><strong>Docker images</strong>: official images (wordpress, mysql, mariadb, redis) are multi-arch</li>
<li><strong>Third-party binaries</strong>: check any plugin or image that bundles native code (see below)</li>
<li><strong>OS</strong>: use Ubuntu 24.04 LTS for fresh installs in 2026 (the 2025 benchmarks here used 22.04)</li>
</ul>
</ListCheck>

Run these after provisioning to confirm your stack is ARM-clean:

```bash
# Confirm architecture
uname -m
# Expected: aarch64

# Check Docker image architecture
docker image inspect --format '{{.Os}}/{{.Architecture}}' wordpress:latest
# Expected: linux/arm64

# Check if a binary is ARM-native
file /usr/local/bin/some-plugin-binary
# Expected: aarch64 / ARM aarch64
```

The main failure mode: third-party WordPress plugins or Docker images that bundle x86-only binaries. You'll get `exec format error` when the binary tries to run. Detect it with `file ./binary` (look for "x86-64" instead of "aarch64") or `docker image inspect --format '{{.Os}}/{{.Architecture}}'`. Fix by rebuilding the image with `docker buildx build --platform=linux/arm64` (check `docker buildx ls` first) or dropping the plugin. If you're running WordPress in Docker, the [full WordPress Docker Compose stack guide](/install-wordpress-docker/) covers multi-arch images. For bare-metal ARM setup, [install Docker and Docker Compose on Ubuntu ARM](/install-docker-ubuntu-arm/).

<Accordion label="Will my WordPress plugins work on ARM?" group="faq">
  Most will. Pure PHP plugins (which is the vast majority) run identically on ARM. The risk is plugins that bundle native binaries or shell out to x86-only tools. Check any performance optimization, backup, or security plugin that installs executables. If it's pure PHP, you're fine.
</Accordion>

<Accordion label="Does ARM hurt WooCommerce?" group="faq">
  FlyWP tested a WooCommerce store on ARM and found ~7% lower uncached throughput and up to 30% lower cached RPS versus x86. For a small to mid-size store behind a cache, that's not noticeable. For a high-traffic store doing heavy uncached cart/checkout operations, x86 dedicated vCPU might be worth the premium.
</Accordion>

<Accordion label="Do I need to recompile anything?" group="faq">
  No. PHP, MySQL/MariaDB, Redis, and Nginx all ship ARM64 packages for Ubuntu. The only time you'd compile from source is if you're using an obscure extension that doesn't have an ARM64 .deb. Check with <code>apt list --installed | grep php</code> after setup.
</Accordion>
