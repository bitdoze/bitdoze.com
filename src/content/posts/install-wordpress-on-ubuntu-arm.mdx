## Why run WordPress on an ARM VPS

WordPress doesn't care about CPU architecture. PHP, MariaDB, and Nginx all ship arm64 builds, and every plugin and theme you'll realistically use works fine on ARM. What changes is the cost equation at specific tiers.

At the high-RAM end, ARM is the only sane path to a 24 GB box without paying x86 prices. A larger CAX server handles that; Oracle's free tier does not (Always Free A1 tops out at 2 OCPU / 12 GB). At the entry tier (2 vCPU / 4 GB) the price advantage has mostly disappeared after the 2026 Hetzner hikes, so pick ARM there for the Oracle free option, not for savings.

The stack you get matters too. CloudPanel v2.5.4 installs Nginx 1.30 with HTTP/3 and PageSpeed, MariaDB, and PHP-FPM on your ARM VPS. That's a production-grade setup with no extra configuration.

## Get your ARM server

Pick Hetzner for predictable billing and fast provisioning. Pick Oracle for $0 if you can get capacity. Both paths converge at Step 1.

Check [Hetzner Cloud cost-optimized plans (CX23, CPX and CAX)](/hetzner-cloud-cost-optimized-plans/) if you want to compare before committing, or read the [Hetzner Cloud review after the 2026 price hikes](/hetzner-cloud-review/) for the wider picture.

### Option B: Oracle Cloud free tier

Sign up at [Oracle Cloud](https://cloud.oracle.com/) and create a compute instance:

- Image: Canonical Ubuntu 24.04 Minimal (26.04 is also available now; 24.04 is the boring default)
- Shape: **VM.Standard.A1.Flex** set to 2 OCPU, 12 GB RAM. That fills the Always Free allowance (1,500 OCPU hours and 9,000 GB hours per month, so it runs 24/7 inside the free cap; split it across two smaller A1 instances if you prefer)
- Enable a public IP

**Oracle extra step:** Open ports 80, 443, and 8443 under Networking → Virtual Cloud Networks → Security Lists → Add Ingress Rules. The CloudPanel docs require all three (8443 is the admin panel).

On stock OCI Ubuntu images, ufw is usually inactive and the security list does the filtering. Check `ufw status` and if it shows active, run `ufw disable`. CloudPanel manages iptables itself. You don't need `iptables -F`.

<Notice type="warning" title="Oracle capacity">
"Out of host capacity" is the number one Oracle free-tier failure when creating A1 instances. If you hit it, retry in another availability domain or region, try off-peak hours, or start with a smaller A1 shape and resize up to the free ceiling once the instance exists. See the troubleshooting section below.
</Notice>

One caveat on the $0 framing: Oracle can reclaim idle Always Free resources and has changed free-tier policy before. Check the current Oracle Always Free terms before betting production on it. The free Object Storage tier does pair nicely with the backups setup below.

If you're torn between the two providers, [Hetzner vs Oracle ARM VPS benchmarks after the 2026 cuts](/hetzner-oracle-arm-performance/) has the numbers.

## Step 1: Install CloudPanel on Ubuntu ARM

SSH into your server. On Hetzner you log in as root (`ssh root@YOUR_SERVER_IP`). On Oracle you log in as `ubuntu` (`ssh ubuntu@YOUR_SERVER_IP`) and then run `sudo su root`.

<Notice type="warning" title="Checksums change with every CloudPanel release">
Always copy the install command from the official installer page. The checksum below was verified 2026-11-14 against CloudPanel v2.5.4 and will fail after the next release. If `sha256sum -c` reports FAILED, re-copy from the docs.
</Notice>

The current commands as of 2026-11-14, taken from the [CloudPanel install docs](https://www.cloudpanel.io/docs/v2/getting-started/other/) and the [Oracle installer page](https://www.cloudpanel.io/docs/v2/getting-started/oracle-cloud/installation/installer/):

<Tabs>
<Tab name="Install on Hetzner">
```bash
apt update && apt -y upgrade && apt -y install curl wget sudo
curl -sS https://installer.cloudpanel.io/ce/v2/install.sh -o install.sh; \
echo "8146dbe0a488e7088b04071b0c34d59aa0ab1fe9dcec382d395fd155c9e6c476 install.sh" | \
sha256sum -c && sudo CLOUD=hetzner DB_ENGINE=MARIADB_11.8 bash install.sh
```
</Tab>
<Tab name="Install on Oracle">
```bash
apt update && apt -y upgrade && apt -y install curl wget sudo cron
curl -sS https://installer.cloudpanel.io/ce/v2/install.sh -o install.sh; \
echo "8146dbe0a488e7088b04071b0c34d59aa0ab1fe9dcec382d395fd155c9e6c476 install.sh" | \
sha256sum -c && sudo CLOUD=oci DB_ENGINE=MARIADB_11.8 bash install.sh
```
</Tab>
</Tabs>

Note the Oracle tab installs `cron` (CloudPanel's scheduled jobs need it) and sets `CLOUD=oci` so CloudPanel enables its cloud integration.

**Database engine:** CloudPanel offers MariaDB 10.11, 11.4, 11.8, 12.3 and MySQL 8.0, 8.4 (options vary by OS). For new installs use `MARIADB_11.8` (LTS) or `MARIADB_12.3`. WordPress.org recommends MariaDB 10.11+ or MySQL 8.4+, so avoid MySQL 8.0 for new sites.

The installer takes 5-10 minutes. When it finishes, open `https://YOUR_SERVER_IP:8443` in your browser.

<Notice type="info" title="Self-signed certificate">
The first visit to `https://IP:8443` shows a browser certificate warning. This is expected: the panel uses a self-signed cert until you add a real one for your admin domain. Proceed past the warning.
</Notice>

**Verify before moving on:**

```bash
clpctl system:information
```

This prints the CloudPanel version and stack details. If the command errors or isn't found, the install didn't complete. Scroll back through the installer output for the failure point.

## Step 2: Point your domain to the server

In your DNS provider (I use Cloudflare), create an A record pointing your domain to the server IP. Also create an admin subdomain (for example `admin.yourdomain.com`) for the CloudPanel interface.

<Picture formats={["webp"]} fallbackFormat="webp" src={imgDns} alt="Cloudflare DNS A records pointing the domain and admin subdomain to the CloudPanel server" />

In CloudPanel go to Settings and set the admin URL to your admin subdomain:

<Picture formats={["webp"]} fallbackFormat="webp" src={imgSettings} alt="CloudPanel Settings page changing the admin URL to a subdomain" />

Allow a few minutes for DNS propagation before requesting SSL certificates in the next step. You can check with:

```bash
dig +short yourdomain.com
```

When it returns your server IP, you're ready.

## Step 3: Create a WordPress site in CloudPanel

Go to **Sites → Add Site → Create WordPress Website**:

<Picture formats={["webp"]} fallbackFormat="webp" src={imgCreate} alt="CloudPanel Sites page with the Add Site and Create WordPress Website options" />

Enter your domain, admin username, password, and email:

<Picture formats={["webp"]} fallbackFormat="webp" src={imgDetails} alt="CloudPanel WordPress site creation form with domain, admin user and email fields" />

CloudPanel installs WordPress (currently 7.1.x) and creates the database automatically. It also requests a Let's Encrypt certificate, testing against the staging environment first to avoid rate limits. This makes the first cert request slightly slower but safer.

When the site shows up in `clpctl site:list`, the vhost and database are created and you're good.

## Step 4: Set the PHP version

Click the site in CloudPanel and go to **PHP Settings**. Set the PHP version to **8.4** (or 8.3). WordPress.org recommends PHP 8.3 or greater.

<Picture formats={["webp"]} fallbackFormat="webp" src={imgPhp} alt="CloudPanel PHP Settings page selecting PHP 8.4 for the WordPress site" />

CloudPanel v2.5.3+ also ships PHP 8.5. It works, but check plugin compatibility before moving a production site to it. 8.4 is the safe mainstream pick.

<Notice type="info" title="PHP security updates">
When a critical PHP security release lands, roll it out via CloudPanel → Site → PHP Settings. CloudPanel ships new PHP builds with its own updates, so check for a CloudPanel update and then switch the site's PHP patch level.
</Notice>

## Verify it works

Run these checks before calling the setup done. Each one takes seconds and tells you exactly what's broken if something is.

<ListCheck>
<ul>
<li>`clpctl site:list` shows your domain (vhost and DB created)</li>
<li>`systemctl status nginx` shows `active (running)`</li>
<li>`systemctl status mariadb` (or `mysql`) shows `active (running)`; also check `systemctl status php*-fpm`</li>
<li>`curl -I https://yourdomain.com` returns `HTTP/2 200` and `server: nginx`</li>
<li>Browser: `https://yourdomain.com` loads the WordPress starter page and `https://admin.yourdomain.com` (or `https://IP:8443`) loads the CloudPanel login</li>
</ul>
</ListCheck>

One quick perf sanity check:

```bash
curl -sI -o /dev/null -w '%{http_code} %{time_total}s\n' https://yourdomain.com
```

You want `200` and a time under a second for a cold request. If any check fails, jump to the troubleshooting section below.

## Set up backups

Do this on day one, not after something breaks. Go to CloudPanel Admin → **Backups**. CloudPanel supports local backups and **S3-compatible remote backups** (Hetzner Object Storage, Oracle Object Storage on the free tier, Backblaze B2, anything that speaks S3). The S3 backup permission bug was fixed in v2.5.2 and region coverage has expanded since.

My default: daily database + files to remote S3 from the start. Oracle's free Object Storage tier covers the backup destination on the $0 path. Hetzner Object Storage is a few euros per month.

For the CloudPanel-specific setup, see [CloudPanel remote backups to OneDrive and Google Drive](/cloudpanel-remote-backups/). If you prefer WordPress-side backups, compare [free WordPress backup plugins](/best-free-wordpress-backup-plugins/).

Whatever you choose: test a restore at least once. A backup you haven't restored is just a hope.

## When things break: troubleshooting

### sha256sum: FAILED

The hardcoded checksum expired. CloudPanel updates the install script checksum with every release, so any copy published before the latest one goes stale. Re-copy the full install command from the [official CloudPanel installer page](https://www.cloudpanel.io/docs/v2/getting-started/other/) and run it again.

### Oracle: "Out of host capacity"

The free-tier capacity for A1 instances is exhausted in that availability domain. Retry in another AD or region. Try off-peak hours. Or start with a smaller A1 shape (1-2 OCPU) and resize once you have the instance.

### Installer fails or MariaDB won't come up

Your server is below the minimums. You need at least 2 GB RAM, 10 GB disk, and a real VM (not an LXC container). The cheapest fix is to rebuild on a compliant shape. See the Prerequisites section.

### Site loads but no SSL

DNS wasn't propagated when you clicked "New Let's Encrypt Certificate". CloudPanel tests Let's Encrypt staging first (to avoid rate limits), then does the real issuance. Confirm with `dig +short yourdomain.com`, then re-request the cert. Check the cert tab for the staging or production error text.

### CloudPanel not reachable on :8443

On Oracle, the security list is probably missing port 80, 443, or 8443. On Hetzner, check the Cloud firewall. Confirm the service is listening with `ss -tlnp | grep 8443`. For firewall rules and hardening, see [harden CloudPanel with firewall rules, 2FA and WAF](/secure-cloudpanel/).

### Undo / teardown

<Notice type="warning" title="Deleting a site deletes its database">
`clpctl site:delete --site-name=yourdomain.com` removes the site, vhost, and database user. The database itself goes too. Take a backup first (see the backups section above).
</Notice>

CloudPanel has no one-shot uninstall. To fully reclaim the box, rebuild the server: delete it in the Hetzner console, or terminate the instance and release the reserved public IP on Oracle. CloudPanel v2.5.4 fixed crontab cleanup on `site:delete`, so no orphaned cron jobs remain.

## Next steps: speed and security

Your WordPress on ARM is running with HTTP/3 out of the box.

**Speed:** [Enable Varnish Cache in CloudPanel](/cloudpanel-varnish-cache/) for full-page caching, put Cloudflare in front for edge caching and DNS, and add Redis for object caching. The full recipe is in [speed up WordPress with Cloudflare, Varnish and Redis](/speed-up-wordpress-with-cloudflare-varnish-and-redis/). A CDN like [Bunny.net](https://go.bitdoze.com/bunny) in front of the site helps global visitors too. One Varnish caveat: there's an [open bug](https://github.com/cloudpanel-io/cloudpanel-ce/issues/812) where custom vhost templates can store NULL `varnishCacheSettings` and return 403 when Varnish is enabled. Test in staging first if you use custom vhost templates.

**Security:** [Harden CloudPanel with firewall rules, 2FA and WAF](/secure-cloudpanel/). If you rely on "allow Cloudflare traffic only" rules, be aware of an [open issue](https://github.com/cloudpanel-io/cloudpanel-ce/issues/832) where the default nginx.conf trusts `X-Real-IP` from any source, which can bypass those rules. Verify your hardening if you use Cloudflare IP restrictions. For the VPS itself, you can [secure the VPS with CrowdSec](/crowdsec-secure-server/).

**Ops:** Keep CloudPanel updated (v2.5.x cadence is steady). Roll PHP security patches via PHP Settings when they land. Add more sites through the same CloudPanel flow.

## FAQ

<Accordion label="Which database should I choose, MariaDB or MySQL?" group="faq" expanded="true">
For new installs, use `MARIADB_11.8` (LTS) or `MARIADB_12.3`. Both are solid and WordPress.org recommends MariaDB 10.11+. If you specifically want MySQL, go with MySQL 8.4. Avoid MySQL 8.0 for new sites: it's below WordPress's recommended floor and near vendor EOL.
</Accordion>

<Accordion label="Does this work on Ubuntu 26.04 or Debian 13?" group="faq">
Yes. CloudPanel v2.5.4 (released 2026-07-01) added Ubuntu 26.04 support, and Debian 13 is supported as well. Ubuntu 24.04 remains the boring default with the longest track record on ARM, so I'd start there unless you have a reason not to.
</Accordion>

<Accordion label="Is ARM actually faster or cheaper for WordPress?" group="faq">
At the 24 GB RAM class and the free tier, yes. Oracle A1 is unbeatable at $0 if you can get capacity (Always Free tops out at about 2 OCPU / 12 GB). At the 2 vCPU / 4 GB tier, not anymore: after the 2026 Hetzner price hikes, the x86 CX23 (€5.49) undercuts the ARM CAX11 (€5.99). See the [ARM vs x86 VPS benchmarks for WordPress performance and cost](/arm-vs-x86-vps-server-benchmarks/) and the [VPS price increases in 2026](/vps-price-increases/) for the full picture.
</Accordion>

<Accordion label="Can I run CloudPanel in an LXC container or on shared hosting?" group="faq">
No. CloudPanel supports only full virtual machines. It has no support for LXC, LXD, OpenVZ, or similar container platforms. If you need containers, [install WordPress with Docker Compose](/install-wordpress-docker/) instead.
</Accordion>
