## What are Herdr plugins and how do they work?

A Herdr TUI plugin is a directory with a `herdr-plugin.toml` manifest and ordinary commands executed as argv arrays; there is no restricted SDK because the entire `herdr` CLI (called via `HERDR_BIN_PATH`) is the plugin API.

![Herdr plugin architecture diagram: manifest sections, argv commands, injected runtime environment variables, and callbacks through the herdr CLI](../../assets/images/26/10/herdr-plugin-anatomy.webp)

Key manifest sections: `[[build]]` compiles on GitHub installs, `[[startup]]` runs one-shot init, `[[actions]]` expose keybindable commands, `[[events]]` fire on triggers like `worktree.created`, `[[panes]]` place overlays/splits/popups, and `[[link_handlers]]` map Ctrl+click URLs. At runtime Herdr injects `HERDR_SOCKET_PATH`, `HERDR_BIN_PATH`, `HERDR_PLUGIN_CONFIG_DIR`, and `HERDR_PLUGIN_STATE_DIR`. Keep credentials and settings in `HERDR_PLUGIN_CONFIG_DIR`, never inside `HERDR_PLUGIN_ROOT` (which updates overwrite).

<Notice type="warning" title="No sandbox, no marketplace review">
As [herdr.dev/tui/docs/plugins](https://herdr.dev/tui/docs/plugins/) states plainly, a plugin is ordinary code running with your user permissions and environment variables. The index refreshes every 30 minutes directly from GitHub's `herdr-plugin` topic without security review.
</Notice>

## How to install, update, and verify Herdr plugins safely

Inspect `herdr-plugin.toml`, install with interactive preview (never `--yes` on first install), pin a reviewed ref with `--ref`, and use `herdr plugin update` (`v0.9.4+`) when you are ready to refresh.

```bash
# Install with interactive manifest preview
herdr plugin install persiyanov/herdr-reviewr

# Or pin the exact tag you audited
herdr plugin install persiyanov/herdr-reviewr --ref v1.2.0

# Update all GitHub-installed plugins or a single one (added in Herdr v0.9.4)
herdr plugin update
herdr plugin update herdr-reviewr

# Verify registration, actions, and logs
herdr plugin list --json
herdr plugin action list --plugin plugin.id
herdr plugin log list --plugin plugin.id --limit 20
```

<Notice type="success" title="New since Herdr v0.9.4 and v0.9.5">
Earlier guides noted that Herdr had no update command. **`herdr plugin update`** shipped in `v0.9.4` (October 13, 2026): it updates GitHub-installed plugins in place while running plugin panes keep working on their old files, and new runs pick up the update with no config reload. Locally linked plugins (`herdr plugin link`) stay untouched. `v0.9.5` also fixed Windows plugin panes failing when a folder on `PATH` matched the plugin's binary name.
</Notice>

To bind a plugin action in `~/.config/herdr/config.toml` and reload:

```toml
[[keys.command]]
key = "prefix+l"
type = "plugin_action"
command = "example.layout.apply"
description = "apply layout"
```

```bash
herdr server reload-config
```

Rollback is equally clean: `herdr plugin disable ID` or `herdr plugin uninstall ID` (which preserves `HERDR_PLUGIN_CONFIG_DIR`).

## What are the 10 best Herdr TUI plugins worth installing?

Install by fully qualified `owner/repo` every time, because multiple plugins in the marketplace share identical names.

### 1. Review agent diffs: `persiyanov/herdr-reviewr`

Opens the agent's git diff in a terminal pane and sends inline line comments straight back to Claude Code, Codex, OpenCode, and Pi. Ships prebuilt Rust binaries (no Cargo compile wait). Lighter alternative: `jhochenbaum/herdr-hunk-diff`.

```bash
herdr plugin install persiyanov/herdr-reviewr
```

### 2. Inspect touched files: `smarzban/herdr-file-viewer`

A git-aware, read-only file tree with rendered Markdown and working-tree diffs. Read-only matters when agents are actively writing files so you never accidentally edit over them. If you want write support plus git staging, check `alexarthurs/herdr-sidebar`.


## How to vet a Herdr plugin in 5 minutes

![Vetting flowchart for Herdr plugins: repository, manifest, commands, scripts, author history, then pin and install, with walk-away exits at each gate](../../assets/images/26/10/herdr-plugin-vetting-flow.webp)

<ListCheck>
<ul>
<li>Read <code>herdr-plugin.toml</code> first, checking every <code>[[build]]</code>, <code>[[startup]]</code>, and <code>[[actions]]</code> command array.</li>
<li>Distrust shell wrappers (<code>["bash", "-c", "..."]</code>) and skim scripts for access to <code>~/.ssh</code>, <code>~/.aws</code>, or <code>.env</code> files.</li>
<li>Check repository history and license (avoid <code>NOASSERTION</code> repos for commercial work).</li>
<li>Pin the tag you reviewed (<code>--ref vX.Y.Z</code>) and never pass <code>--yes</code> on a first install.</li>
<li>Before exposing any remote relay plugin, follow [server firewall hardening](/bsi-security-report-docker-ufw/) and use Tailscale instead of open ports.</li>
</ul>
</ListCheck>

## Frequently asked questions

<Accordion label="How do I update Herdr plugins now?" group="faq" expanded="true">
On Herdr TUI `v0.9.4` and newer, run `herdr plugin update` to update all GitHub-installed plugins or `herdr plugin update <name>` for a single plugin. Running panes continue cleanly on old files until reopened, no config reload is required, and locally linked plugins are skipped.
</Accordion>

<Accordion label="Do Herdr TUI plugins work in the Herdr Desktop App?" group="faq">
No. TUI plugins (`herdr-plugin`) extend the `herdr` terminal multiplexer. The official `herdr-app` desktop app runs on `herdr-core` and uses QuickJS **mods** (`herdr-mod`) and JSON **layouts** (`herdr-layout`) from `herdr.dev/gallery/`.
</Accordion>

<Accordion label="Are Herdr plugins safe to install?" group="faq">
They run unsandboxed with your user permissions and the marketplace at `herdr.dev/tui/plugins` is unreviewed. Always inspect `herdr-plugin.toml`, check for credential/network access, and pin a reviewed ref.
</Accordion>

<Accordion label="What is the difference between a Herdr plugin and an Agent Skill?" group="faq">
Plugins extend the Herdr terminal runtime (panes, events, keybindings). Agent skills extend the LLM's instructions and workflow context. See [Agent Skills compared](/best-ai-skills-for-web-design/) for the skill layer.
</Accordion>
