## What a good free WordPress backup plugin needs to do

Before picking a plugin, here's what matters when something goes wrong at 2 AM:

<ListCheck>
<ul>
<li>Back up to external storage (Google Drive, S3, Dropbox, FTP), not just the same server that just died</li>
<li>Run on a schedule automatically, without you remembering</li>
<li>Handle large sites (500+ posts, several GB) without timing out</li>
<li>Make restoring straightforward: one click, not a 40-step runbook</li>
<li>Have a tested restore. A backup you haven't restored from is a hope, not a backup</li>
<li>Support retention rules so old archives don't silently fill your disk or your S3 bill</li>
</ul>
</ListCheck>

The offsite part is non-negotiable. The classic [3-2-1 backup rule](https://www.backblaze.com/blog/the-3-2-1-backup-strategy/) applies here: 3 copies of your data, on 2 different media, with 1 copy offsite. A plugin that only writes to `/wp-content/uploads/` on the same server is giving you 1 copy on 1 medium with 0 offsite. If you want to push offsite copies from the server level too, you can [mount an S3 bucket as a filesystem on your VPS](/s3-bucket-filesystem-vps/) and snapshot entire directories.

3-2-1 backup rule:

```
┌─────────────────────────────────────────────────┐
│              3-2-1 Backup Rule                   │
│                                                  │
│  ┌──────────┐   ┌──────────┐   ┌──────────┐    │
│  │ 3 copies │   │ 2 media  │   │ 1 offsite│    │
│  │ of data  │──▶│ (disk +  │──▶│ (cloud:  │    │
│  │          │   │  cloud)  │   │ GDrive,  │    │
│  │          │   │          │   │ S3, etc.)│    │
│  └──────────┘   └──────────┘   └──────────┘    │
└─────────────────────────────────────────────────┘
```

## 1. WPvivid (Backup, Migration & Staging)

<Picture formats={["webp"]} fallbackFormat="webp" src={imgWpvivid} alt="WPvivid Backup Plugin dashboard showing backup, restore, and migration options in WordPress admin" />

[WPvivid](https://wordpress.org/plugins/wpvivid-backuprestore/) (v0.9.140, updated Nov 2026) packs more into its free tier than any competitor. The plugin was recently renamed because it now covers migration and staging too. 900,000 active installs, 98/100 rating on WordPress.org.

Free remote storage includes Dropbox, Google Drive, Amazon S3, OneDrive, [DigitalOcean Spaces](https://go.bitdoze.com/do), FTP, and SFTP. If you prefer S3-compatible cheap storage, it also works with [offsite backups to Cloudflare R2](/dokploy-backups-cloudflare-r2/) and other S3-compatible endpoints.

On the free tier you get:

- Scheduled automatic backups (files + database, or either separately)
- Full site migration: copy to a new domain or server without a separate plugin
- Basic subdirectory staging (fresh WordPress install on a subdirectory for testing)
- Backup splitting for storage providers with file-size limits
- One-click restore
- Unlimited backup size and backup count
- Basic retention rules to prune old archives
- Restore directly from cloud storage

Site migration alone makes this worth installing. If you ever need to move WordPress to a new host or clone it for testing, WPvivid handles both without a second plugin.

<Notice type="info" title="Staging is basic">
  The free subdirectory staging is useful for quick tests, but it's not a full staging pipeline (no push-to-live workflow). WPvivid sells a separate "Staging & Dev Environment Pro" product for that.
</Notice>

Whatever destination you pick, confirm the first archive appears there. See the verification checklist below.

## 2. UpdraftPlus

<Picture formats={["webp"]} fallbackFormat="webp" src={imgUpdraft} alt="UpdraftPlus Backup and Restoration settings screen in the WordPress admin" />

[UpdraftPlus](https://wordpress.org/plugins/updraftplus/) has 4,000,000 active installs, the largest install base of any WordPress backup plugin. The company behind it now brands itself as TeamUpdraft (you'll see "David Anderson / Team Updraft" as the plugin author). Version 1.26.14, updated October 2026. 96/100 rating.

Free remote storage includes Dropbox, Google Drive, Amazon S3 (and compatible), Rackspace Cloud, FTP, DreamObjects, OpenStack Swift, and email.

On the free tier you get:

- Scheduled automatic backups (files + database, or either)
- One-click restore from within WordPress
- Free site migration: download the backup on the source site, upload it on the destination, and run the built-in search-and-replace engine to fix URLs
- Retention limits to control how many old backups are kept

The migration story needs a correction from older comparisons: **UpdraftPlus free does handle migration.** You download the database, plugins, and themes from the source site, upload them into the destination, and the search/replace engine fixes the URLs. What the paid "Premium migration" add-on gives you is the direct source-to-destination flow: no manual download/upload step.

The free version works well for most sites and has the longest track record. Incremental backups, database encryption, OneDrive/Azure/Backblaze support, and multisite are all behind the Premium tier. If you need current Premium pricing, check [teamupdraft.com](https://teamupdraft.com/) directly. The old pricing page no longer works.

## 3. Duplicator Lite 5.0

[Duplicator](https://wordpress.org/plugins/duplicator/) (v5.1.1, updated Nov 2026) has 1,000,000 active installs per WordPress.org (the vendor's marketing claims 1.5M+, likely including Pro). 98/100 rating. Duplicator started as a migration tool and has been growing into a backup tool. In October 2026, version 5.0 was a major step.

Duplicator Lite 5.0 runs on the Pro engine and added several features to the free tier that were previously paid-only:

- 1-click restore of any backup from the Backups page. No FTP or installer dance
- AES-256 password encryption for backups (DupArchive and ZIP formats). This is the only free backup plugin that encrypts.
- **Multiple local storage folders** with per-folder retention rules
- Duplicator Cloud integration: push backups to Duplicator's own cloud storage (requires a separate paid plan, from $29/yr for 2GB)
- Recovery connector: restore from the cloud dashboard over FTP/SFTP
- AutoTune config tester to diagnose server limits before a backup runs

Still Pro-only: scheduled backups, third-party cloud destinations (Google Drive, Dropbox, S3, FTP, SFTP), staging sites, multisite, incremental backups, and unlimited destinations.

Duplicator Pro pricing (list prices, per year): Basic $79 (2 sites), Plus $199 (5 sites), Pro $399 (20 sites), Elite $599 (100 sites). The site runs frequent ~60% promos, but those are the list prices.

<Notice type="warning" title="Recovery Points caveat">
  "Recovery Points with quick rollbacks" appears in marketing copy as a free feature, but the pricing page lists "1-Click Restore Points" under the paid Basic plan. Plain 1-click restore of a listed backup is confirmed free in 5.0, but don't rely on scheduled recovery points without checking the Lite UI first.
</Notice>

There is one footgun with encryption: the password becomes a single point of failure. If you encrypt a backup and lose the password, the archive is unrecoverable. Store it in a password manager, not in the same folder as the backup.

For manual encrypted backups with easy restore, free Duplicator is now arguably the strongest pick. For scheduled offsite backups to your own cloud storage, it still can't match WPvivid's free tier.

## Make sure your backups run

Installing a backup plugin is step one. Making sure it works is step two, and most guides skip it.

### Fix WP-Cron so schedules fire

All three plugins schedule backups through WP-Cron, which only fires when someone visits your site. On a low-traffic site, that means your "daily backup" might run at 4 PM instead of 3 AM, or not at all for days.

This is the number-one "my schedule didn't run" failure mode. Fix it by disabling WP-Cron and using a real system cron job:

```bash
# In wp-config.php, above the "That's all" line:
define('DISABLE_WP_CRON', true);
```

Then add a crontab entry (run `crontab -e` as the web server user):

```bash
# Run due WordPress cron events every 15 minutes
*/15 * * * * cd /var/www/wordpress && wp cron event run --due-now --quiet
```

If you're running on a self-managed VPS (a [Hetzner Cloud VPS](https://go.bitdoze.com/hetzner), a [DigitalOcean droplet](https://go.bitdoze.com/do), Hostinger), you control cron, so set it up properly. If you [install WordPress with Docker Compose](/install-wordpress-docker/), make sure the cron entry runs inside the container or on the host against the right path.

You can also handle the server-level side of offsite copies with [CloudPanel's built-in remote backups to OneDrive and Google Drive](/cloudpanel-remote-backups/). That's a good complement to plugin-level backups.

Install and update via WP-CLI while you're at it:

```bash
wp plugin install wpvivid-backuprestore --activate
wp plugin update --all   # backup plugins are high-severity update targets
```

### Post-setup verification checklist

A backup you haven't restored from is a hope, not a backup. Run this drill once after setup:

<ListCheck>
<ul>
<li>Trigger a manual backup now. Don't wait for the schedule.</li>
<li>Confirm the archive appears in remote storage. For S3: <code>aws s3 ls s3://my-backup-bucket/wpvivid/ --recursive | tail -5</code></li>
<li>Restore into a scratch/staging URL and click through the homepage, a post, and the admin. This doubles as your rollback rehearsal.</li>
<li>Wait for one scheduled run and confirm it fired by checking the plugin log or the timestamp on the newest archive.</li>
</ul>
</ListCheck>

If step 3 breaks URLs (images pointing to the old domain, links 404ing), run the search/replace. WPvivid and UpdraftPlus both have built-in tools for this. Duplicator's installer handles it automatically.

### Common failures and fixes

| Failure | Cause | Fix |
|---|---|---|
| Schedule never fires | WP-Cron is traffic-driven | `DISABLE_WP_CRON` + system cron (see above) |
| Remote storage auth expired | OAuth token revoked or password changed | Re-authenticate the connection in plugin settings |
| Archive missing from offsite storage | Retention rules deleted it, or upload silently failed | Check the backup log; loosen retention temporarily |
| Disk or S3 bill growing fast | Retention not configured | Set a retention limit (keep N backups, or delete after X days) |
| Restore breaks site URLs | Domain changed without search/replace | Run the plugin's search/replace tool on the restored copy |
| Encrypted backup won't open | Lost password | Unrecoverable. Prevention: store the password in a password manager |

## When a paid WordPress backup plugin is worth it

All three plugins paywall the same killer feature: incremental backups. Instead of backing up the entire site every run, incremental backups only capture what changed since the last run. On a large site (several GB, frequent updates), full backups eat disk space, bandwidth, and server time.

The cost ladder (list prices, November 2026):

- **Duplicator Cloud** from **$29/yr** (2GB): cheapest managed offsite storage, works with Duplicator Lite
- **WPvivid Pro** from **$49/yr** (Blogger plan, 2 domains): adds incremental backups, exclusion rules, external databases, and more storage backends (Wasabi, Backblaze, pCloud, WebDAV)
- **Duplicator Pro Basic** at **$79/yr** (2 sites): adds scheduled backups, third-party cloud destinations, staging, and multisite
- **UpdraftPlus Premium**: pricing not quoted here (check [teamupdraft.com](https://teamupdraft.com/) directly)

When it's worth paying: your site is large enough that full backups stop fitting in the backup window, you need direct source-to-destination migration, you run multisite, or you need policy-driven encryption across the board.

The free path costs $0 in software, but your offsite bucket costs a few dollars a month if retention isn't configured. Set retention limits on day one.

**A backup plugin is not a server backup.** If you're on a VPS, the real 3-2-1 setup is plugin-level backups + server-level snapshots. For the server side, look at [self-hosted server backups with Restic and Rclone](/pluton-self-hosted-backup/) or [Zerobyte for automated Restic backup schedules](/zerobyte-restic-gui/). Plugin backups capture WordPress; server backups capture everything else (nginx configs, SSL certs, cron jobs).

<Notice type="warning" title="Keep backup plugins updated">
  WPvivid's changelog from v0.9.128 to v0.9.140 (roughly May to November 2026) contains at least a dozen security-vulnerability fixes, credited to WPScan, Wordfence Argus, and Cipher Security Labs. A stale backup plugin is a backdoor risk. Run <code>wp plugin update --all</code> on a schedule. And while you're hardening: [secure your WordPress login with two-factor authentication](/secure-wordpress-2fa/).
</Notice>

## FAQ

<Accordion label="Is WPvivid really free?" group="faq" expanded="true">
Yes. The free tier includes scheduled backups, 7 remote storage destinations (Dropbox, Google Drive, Amazon S3, OneDrive, DigitalOcean Spaces, FTP, SFTP), site migration, subdirectory staging, backup splitting, and one-click restore. The Pro plan ($49/yr and up) adds incremental backups, exclusion rules, external database support, and more storage backends (Wasabi, Backblaze, pCloud, WebDAV).
</Accordion>

<Accordion label="Does UpdraftPlus free do migration?" group="faq">
Yes. You can migrate a site for free by downloading the backup on the source site and uploading it on the destination. UpdraftPlus includes a built-in search-and-replace engine to fix URLs. The paid "Premium migration" add-on adds a direct source-to-destination flow that skips the manual download/upload step.
</Accordion>

<Accordion label="Can Duplicator back up to Google Drive for free?" group="faq">
No. Third-party cloud storage (Google Drive, Dropbox, S3, OneDrive, FTP, SFTP) requires Duplicator Pro. The free version stores backups to local folders and optionally to Duplicator Cloud, but Duplicator Cloud requires a separate paid plan starting at $29/yr for 2GB. If free Google Drive backups are your priority, use WPvivid or UpdraftPlus instead.
</Accordion>

<Accordion label="Why didn't my WordPress backup run on schedule?" group="faq">
Because WP-Cron only fires when someone visits your site. On low-traffic sites, scheduled backups can silently miss their window. Fix it by adding <code>define('DISABLE_WP_CRON', true);</code> to wp-config.php and setting up a real system cron job to run <code>wp cron event run --due-now</code> every 15 minutes. See the WP-Cron section above for the exact commands.
</Accordion>

<Accordion label="Are free backup plugins safe?" group="faq">
Yes, when kept updated. WPvivid's changelog from mid-2026 shows a dozen-plus security fixes shipped in six months, which is exactly what you want to see: a team that patches fast. Stale plugins are the risk, whatever the price. Run <code>wp plugin update --all</code> regularly and pair backups with login hardening (2FA, strong passwords).
</Accordion>
