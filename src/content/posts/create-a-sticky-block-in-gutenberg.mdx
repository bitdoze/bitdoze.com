## What is a sticky block in Gutenberg?

A sticky block uses CSS `position: sticky`. It scrolls normally with the page until it crosses a threshold (usually `top: 0`), then it pins in place while its parent container is still in view.

The part people miss: a sticky element stays inside its parent container. It is not `position: fixed`, which would keep the element on screen forever. Once the parent scrolls past, the sticky element leaves with it. That is why native sticky works for headers (the parent is the full-height template) and why a button inside a short post block "unsticks" sooner than you expect.

<Image src={imgStickyVsFixed} alt="Diagram: a sticky block pinned at the top of a tall parent container, and the same block scrolling away when the parent container ends" />

<Notice type="info" title="Sticky is not fixed">
A sticky block stays pinned only while its parent container is in view. If the block seems to unstick too early, the parent is too short.
</Notice>

You can create a sticky block in Gutenberg three ways: a plugin that wraps any block, the built-in Position setting on Group blocks, or a custom CSS class on any block. Here is each one.

## Option 1: Sticky Block plugin for Gutenberg (free)

The free [Sticky Block for Gutenberg Editor](https://wordpress.org/plugins/sticky-block/) plugin (slug `sticky-block`, by Senff) is the simplest way to make any block sticky inside post content. It has 7,000+ active installs, is tested up to WordPress 7.1.4, requires WordPress 5.0+, and holds a 92/100 rating on WordPress.org. If you just want a button or a callout to follow the reader down a post, use this one.

### Step 1: Install the Sticky Block for Gutenberg Editor plugin

Go to **Plugins → Add New**, search for "Sticky Block" (admin search still finds it by slug even though the directory name is longer), then install and activate. Take a backup first if you don't have automated ones running; any of these [free WordPress backup plugins](https://www.bitdoze.com/best-free-wordpress-backup-plugins/) will do.

### Step 2: Add the Sticky Block wrapper

In the block editor, insert a **Sticky Block**, then drop any inner block(s) inside it (a button, an image, a Group, columns). The wrapper itself is invisible on the front end; only the nested content renders, and it stays sticky. You can place multiple Sticky Blocks on one page.

<Picture formats={["webp"]} fallbackFormat="webp" src={imgStickey} alt="Adding a Sticky Block wrapper around a button block in the Gutenberg editor" />

To verify: preview the page and scroll. The inner block should travel with the viewport instead of scrolling away. If nothing sticks, the inner block is probably outside the Sticky Block wrapper. Click List View in the editor and confirm the nesting.

### Step 3: Configure the sticky options

Select the Sticky Block to open the **Sticky Options** panel. The settings, with the labels as shipped in the plugin:

- **"Space between sticky block and top of screen"** sets the offset in pixels between the sticky element and the top of the viewport. Use it to clear a sticky header or the admin bar.
- **"Block should not be sticky on screens smaller than:"** sets a minimum viewport width in px. Below that width the plugin disables stickiness.
- **"Block should not be sticky on screens wider than:"** sets a maximum viewport width in px. Above that width the plugin disables stickiness.
- **"Pushup Element:"** takes a CSS class or ID selector for an element that pushes the sticky block out of the way as it scrolls into view. A footer works well here.
- Raise **z-index** ("Only applies once the element is sticky") if the sticky block hides behind other page elements.

The plugin is admin-bar aware, so the sticky block offsets itself when you are logged in and the WordPress admin bar is showing.

<Picture formats={["webp"]} fallbackFormat="webp" src={imgOptions} alt="Sticky Block plugin sticky options panel in Gutenberg showing top spacing, min and max screen width, pushup element, and z-index settings" />

<Notice type="warning" title="Pushup Element gotcha">
The Pushup Element selector must match exactly one element on the page. If it matches zero or multiple elements, the plugin logs `STICKY BLOCK DEBUGGER:` warnings to the browser console and disables the push-up behavior.
</Notice>

### Step 4 (optional): Style the block only while it's stuck

The plugin toggles two CSS classes on the wrapper: `.block-is-sticky` while the block is pinned, and `.block-is-not-sticky` while it scrolls normally. Use them to add a shadow or change the background only during the sticky state:

```css
/* Only while the block is stuck */
.block-is-sticky { box-shadow: 0 4px 12px rgb(0 0 0 / 0.15); }

/* Only while not stuck */
.block-is-not-sticky { background: transparent; }
```

Add the CSS in **Appearance → Customize → Additional CSS** (classic themes) or the site editor's Additional CSS panel (block themes), then scroll the page: the shadow should appear exactly when the block pins and disappear when it scrolls away.

## Option 2: Native sticky position on Group blocks (WordPress 6.2+)

Since WordPress 6.2, the Group block family (Group, Row, Stack, and Grid, all variations of the Group block) ships a **Position** setting with a **Sticky** option. No plugin needed. The catch: the control only appears on top-level blocks. If the Group is nested inside another block, the Position control disappears from the sidebar. The [official Group block docs](https://wordpress.org/documentation/article/group-block/) spell this out: only top-level Group blocks can be set as sticky.

Steps:

1. Open the Site Editor (**Appearance → Editor**) or edit a page with a root-level layout
2. Select or insert a top-level **Group** (or Row/Stack/Grid) block
3. In the block sidebar, under **Position**, choose **Sticky**
4. Preview and scroll to confirm

Native sticky pins the block to the top of the viewport on scroll. This is the WordPress sticky header pattern that most block themes use.

<Image src={imgTopLevelVsNested} alt="Diagram: a Group block at root level shows the Position Sticky control, while a Group block nested inside another block has no Position control" />

Remember the parent-container rule: native sticky sticks only within its parent container. For a header, the parent is the full-height template, so it stays pinned for the whole page. For a mid-content block, the parent is short and the element scrolls away quickly. That is by design.

<Notice type="info" title="Native sticky is for headers">
Native sticky is built for headers and site-level layout. If you need a block to stick inside post content, use Option 1 or Option 3.
</Notice>

## Option 3: Make a block sticky on scroll with custom CSS

If you do not want a plugin, give the block a custom CSS class (block sidebar → **Advanced → Additional CSS Class**, e.g. `my-sticky-block`), then add this to your site's CSS (**Appearance → Customize → Additional CSS**, or the site editor's Additional CSS panel):

```css
/* Works only if no ancestor has overflow: hidden/auto/scroll
   and the parent is taller than this block */
.my-sticky-block {
  position: sticky;
  top: 1rem;
}
```

Adjust `top` to change the offset from the viewport top. The trade-off: no visual settings panel, no push-up element, no per-screen-size thresholds. What you get is zero plugin overhead and a technique that works on any block, including blocks the plugin cannot wrap.

### Why your sticky CSS isn't working

`position: sticky` fails silently. No error, it just doesn't stick. Two causes cover almost every report:

1. **An ancestor has `overflow: hidden`, `auto`, or `scroll`.** The sticky element then sticks within that scroll container instead of the viewport. Inspect every parent up to `<body>` in DevTools and remove the overflow, or restructure the DOM.
2. **The parent element isn't taller than the sticky element.** There is no room to travel, so the parent scrolls past immediately. Make sure the sticky block sits inside a container with content to scroll through.

Quick check: DevTools → select the block → **Computed** styles → confirm `position` resolves to `sticky`, not `static` or `relative`.

<Notice type="error" title="Sticky fails silently">
Sticky silently fails (no error, it just doesn't stick) when an ancestor has `overflow: hidden/auto/scroll`. Check every parent up to `<body>` in DevTools → Computed styles.
</Notice>

## Verify your sticky block works

After setup, run this checklist on the front end. It takes about two minutes:

<ListCheck>
<ul>
<li>Open the published post or page and scroll. The block should pin at the configured offset</li>
<li>Open browser DevTools, inspect the sticky block, and check **Computed** styles for `position: sticky`</li>
<li>While stuck, check the element's classes. `.block-is-sticky` should be present (plugin method)</li>
<li>Scroll past the parent container. The block should scroll away (that is correct sticky behavior, not a bug)</li>
<li>Check the browser console for `STICKY BLOCK DEBUGGER:` warnings (push-up misconfiguration)</li>
<li>Test on mobile or narrow the browser window. The min/max width thresholds should behave as configured</li>
<li>Log in as admin. The admin bar should not obscure the sticky block</li>
</ul>
</ListCheck>

## FAQ: Sticky blocks in Gutenberg

<Accordion label="Can you make any block sticky in Gutenberg?" group="faq" expanded="true">
Yes. With the Sticky Block plugin you can wrap any block (button, image, Group, columns) and make it sticky. Custom CSS with `position: sticky` works on any block too; add a class via Additional CSS Class. The native Position → Sticky control is the exception: it only works on top-level Group-family blocks (Group, Row, Stack, Grid) and is aimed at headers. No method makes a nested block sticky through the native control.
</Accordion>

<Accordion label="Why is my sticky block not working on mobile?" group="faq">
Two common causes. First, the plugin's width thresholds: "Block should not be sticky on screens smaller than" and "Block should not be sticky on screens wider than" disable stickiness at certain viewport sizes. Check those values before anything else. Second, the CSS `overflow` failure mode from Option 3 applies on mobile too. Also note the plugin's front-end script is jQuery-based: if your theme or an optimization plugin strips jQuery, stickiness never initializes. If the problem is really mobile navigation rather than a sticky block, a [Carrd mobile responsive navbar](https://www.bitdoze.com/carrd-mobile-navbar/) is a different setup entirely.
</Accordion>

<Accordion label="Is there a free sticky block plugin for WordPress?" group="faq">
Yes. "Sticky Block for Gutenberg Editor" is completely free: 7,000+ active installs, tested up to WordPress 7.1.4 as of November 2026. It covers mid-content sticky blocks with top spacing, min/max width thresholds, a push-up element, and z-index. If you need sticky nav menus or widgets on classic themes, "Sticky Menu & Sticky Header" (90,000+ installs) is free too.
</Accordion>

For most people making a block sticky inside post content, the free Sticky Block plugin is the fastest path: stable, tested to WordPress 7.1.4, no CSS required. Native sticky covers headers.
