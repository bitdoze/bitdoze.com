### 3. Paste the code and customize your FAQ items

Paste the full code into the Embed element's Code field. Then edit the FAQ content. Each accordion item follows this pattern:

```html
<button class="accordion" aria-expanded="false">Your question here?</button>
<div class="panel">
  <p>Your answer goes here. You can include multiple paragraphs, lists, or inline HTML.</p>
</div>
```

The `aria-expanded="false"` attribute is part of the accessibility setup covered further down. Adding it now costs nothing and keeps the markup ready.

The button and its panel must stay adjacent: the script opens the element that immediately follows the clicked button.

```html
    transform: rotate(45deg);

    color: #d91a1a; /* Close (x) icon color */
  }
  .accordion.active,
  .accordion:hover {
    background-color: #4d514d; /* Hover and open tab color */
    border-radius: 10px;
  }
  .panel {
    padding: 0 18px;
    background-color: #eeebeb; /* Answer panel background */
    max-height: 0;
    overflow: hidden;
    transition: max-height 0.2s ease-out;
    border-radius: 10px;
  }
  .panel p {
    margin: 0;
    padding: 10px 10px;
    font-size: 2.1rem;
  }

```

Change the hex color values to match your site's palette. The comments in the code make it straightforward to find each property.

<Notice type="warning" title="Check the .active selector">
If your downloaded copy has a rule that starts with <code>.active, .accordion:hover</code>, change it to <code>.accordion.active, .accordion:hover</code> as shown above. Carrd puts an <code>active</code> class on the section currently on screen, so a bare <code>.active</code> selector paints your whole section in the accordion's hover color. Scoped to <code>.accordion.active</code>, it only styles the open item.
</Notice>

## Make the accordion accessible (aria-expanded)

The markup already uses real `<button>` elements, so keyboard support comes for free. What's missing is state: screen readers can't tell whether a question is open. Two lines fix that.

The click handler currently does `this.classList.toggle("active")` and ignores the result. Capture the new state and mirror it into `aria-expanded`:

<Tabs>
<Tab name="Base script">

```html
<script>
  // Accordion script
  var acc = document.getElementsByClassName("accordion");
  for (var i = 0; i < acc.length; i++) {
    acc[i].addEventListener("click", function () {
      this.classList.toggle("active");
      var panel = this.nextElementSibling;
      if (panel.style.maxHeight) {
        panel.style.maxHeight = null;
      } else {
        panel.style.maxHeight = panel.scrollHeight + "px";
      }
    });
  }
</script>
```

</Tab>
<Tab name="Accessible (aria-expanded)">

```html
<script>
  // Accordion script (accessible)
  var acc = document.getElementsByClassName("accordion");
  for (var i = 0; i < acc.length; i++) {
    acc[i].addEventListener("click", function () {
      var open = this.classList.toggle("active");
      this.setAttribute("aria-expanded", open);
      var panel = this.nextElementSibling;
      panel.style.maxHeight = open ? panel.scrollHeight + "px" : null;
    });
  }
</script>
```

</Tab>
<Tab name="Multi-embed safe">

```html
<script>
  // Accordion script (multi-embed safe)
  var acc = document.getElementsByClassName("accordion");
  for (var i = 0; i < acc.length; i++) {
    if (acc[i].dataset.bound) continue; // already wired by another copy
    acc[i].dataset.bound = "1";
    acc[i].addEventListener("click", function () {
      this.classList.toggle("active");
      var panel = this.nextElementSibling;
      if (panel.style.maxHeight) {
        panel.style.maxHeight = null;
      } else {
        panel.style.maxHeight = panel.scrollHeight + "px";
      }
    });
  }
</script>
```

</Tab>
</Tabs>

With the accessible script, each `<button class="accordion">` also needs `aria-expanded="false"` in the markup (already added in step 3). `classList.toggle` returns the new state, so the same click that opens the panel flips the attribute to `true`, and the next click flips it back.

<Notice type="info" title="Not live-tested">
This two-line variant has not been through a live Carrd publish as of October 2026. It's a small change to the base script, so verify on your published site: click a question and inspect the button in devtools to confirm <code>aria-expanded</code> flips between false and true.
</Notice>

## Embedding multiple accordion sections on the same page

If you need two or more separate FAQ groups on one Carrd site, add one Inline Embed per group. There's one catch: the plugin's script attaches a click handler to every `.accordion` button on the page, not just the ones in its own embed. With the full code pasted twice, the first group's buttons get two handlers. Each click opens the panel and immediately closes it again, so that group looks dead.

The fix is to use this version of the `<script>` block in every copy. It skips buttons that another copy already wired up. If you also want the `aria-expanded` behavior, the guard stays at the top of the loop and the two aria lines slot inside the listener, like this:

```html
<script>
  // Accordion script (multi-embed safe + accessible)
  var acc = document.getElementsByClassName("accordion");
  for (var i = 0; i < acc.length; i++) {
    if (acc[i].dataset.bound) continue; // already wired by another copy
    acc[i].dataset.bound = "1";
    acc[i].addEventListener("click", function () {
      var open = this.classList.toggle("active");
      this.setAttribute("aria-expanded", open);
      var panel = this.nextElementSibling;
      panel.style.maxHeight = open ? panel.scrollHeight + "px" : null;
    });
  }
</script>
```

The `<style>` block can stay duplicated in each embed; identical CSS rules don't conflict. Every button still needs its `<div class="panel">` directly after it, because the script opens the element that immediately follows the clicked button.

## Troubleshooting: Carrd accordion not working

If your Carrd accordion is not working after publish, the cause is almost always one of these.

If the accordion doesn't appear after publishing, check that the Embed element's Type is Code and its Style is Inline, and that it sits in the section where you expect it. Also confirm your Carrd plan supports embeds (Pro Standard or higher).

If you don't see the Embed element in Add Element, the plan is below Pro Standard. The free tier caps at 3 sites and excludes embeds entirely. Upgrade, or use the 7-day Pro trial to test first.

If the accordion looks broken or unstyled, make sure you pasted the full code, including the `<style>` block at the top, into the Code field.

If the whole section turns grey, your copy uses a bare `.active` selector that matches Carrd's active section. Change it to `.accordion.active` (see step 4).

If clicking a question does nothing, open your browser console and look for JavaScript errors. If you pasted the full code into two embeds, the first group's buttons get two click handlers that cancel each other out. Use the script from the multiple-accordion section above.

If the text is too small on mobile, add a font-size override in the style section of the code. For example: `.accordion { font-size: 16px; }` and `.panel p { font-size: 15px; }`.

If the download link shows a Cloudflare or interstitial page, open it in a normal browser. The link sits behind a bot challenge for automated tools; the plugin page itself is live and reachable by hand.

To undo everything: delete the Embed element and republish. Nothing else in Carrd is touched, so rollback is as simple as that.

## Alternatives to the code embed approach

If you'd rather not manage raw code, or you want a different visual style, there are three other routes. My default is still the CarrdMe snippet above: free, no branding, fully editable, and the smallest page-weight hit.

### No-JavaScript option: `<details>/<summary>`

Since the Inline Embed accepts arbitrary HTML, native `<details>/<summary>` gives you a working accordion with zero JavaScript. The browser handles open and close:

```html
<details class="faq">
  <summary>What is your refund policy?</summary>
  <p>Full refund within 30 days. Contact support@example.com to start the process.</p>
</details>

<details class="faq">
  <summary>How do I contact support?</summary>
  <p>Email us at support@example.com. We respond within 24 hours.</p>
</details>
```

Style `summary` like the `.accordion` bar (background, padding, border-radius, cursor) and swap the plus icon for a `summary::before` rule. The tradeoff is animation: there's no smooth max-height transition by default. The newer `interpolate-size` and `transition-behavior: allow-discrete` CSS can animate it, but browser support is still patchy as of October 2026, so I'd skip animation here.

The JS version is animated and takes the aria upgrade. `<details>/<summary>` is bulletproof but unanimated.
