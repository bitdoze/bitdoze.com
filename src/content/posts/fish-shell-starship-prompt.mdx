The Starship prompt paired with Fish Shell is one of the cleanest terminal setups you can run. Starship is a cross-shell prompt written in Rust that works with Fish, Zsh, Bash, PowerShell, and others, so you can keep the same prompt configuration no matter which shell you land in. Updated for Starship v1.27.0, October 2026.

Starship is fast, the configuration lives in a single TOML file, and it shows the information you need (git branch, language versions, command duration) without cluttering the prompt. Fish is at 4.9.x (4.9.3 as of September 2026) and the `config.fish` workflow is unchanged from earlier 4.x releases.

I previously wrote a guide on [Starship with Ghostty and Zsh](/starship-ghostty-terminal/). The Fish setup follows the same principles but the init line goes in a different config file.

## What's new in Starship (2026 update)

If you set up Starship earlier in 2026 or before, a few things worth knowing have changed:

- Starship v1.27.0 (October 2026) fixes security advisories. If you installed Starship before October 2026, upgrade to v1.27.0 or later. Details in the upgrade notice below.
- Claude Code statusline integration landed in v1.25.0. Starship can render your Claude Code statusline with model name, context window usage, and session cost. Covered in its own section below.
- `apt install starship` now works on Ubuntu 25.04+ and Debian 13+. The snap package is no longer a documented install path.
- Jujutsu VCS modules (`jj_bookmark`, `jj_change`, `jj_status`, and more) arrived in v1.27.0.
- The Maven module was added in v1.25.0, and the generic `vcs` module now works across version control systems.

<Notice type="warning" title="Upgrade to v1.27.0">
If you installed Starship before October 2026, reinstall or upgrade to v1.27.0 or later. It patches security advisories related to git command handling. Re-running the install script replaces the old binary:

```bash
curl -sS https://starship.rs/install.sh | sh
```

If you installed via a package manager, upgrade through that (`sudo apt upgrade starship`, `brew upgrade starship`, or `cargo install starship --locked`). Then check with `starship --version`. You should see v1.27.0 or later.
</Notice>

## Prerequisites

Before you start, make sure you have the following:

<ul>
<li>Fish Shell 4.x installed. See my <a href="/install-fish-shell-ubuntu/">Fish Shell installation guide for Ubuntu</a> if you need it</li>
<li>A terminal emulator (Ghostty, WezTerm, kitty, Alacritty, or similar)</li>
<li>A Nerd Font installed and selected in your terminal (see below)</li>

This guide targets Linux (Ubuntu/Debian) and macOS. The commands work the same on both unless noted.

### Install a Nerd Font

Starship uses special glyphs for its icons. Without a Nerd Font they show up as broken boxes. I recommend **MesloLGS Nerd Font** (Nerd Fonts v3.5.1 as of August 2026).

On Ubuntu or Debian:

```bash
# Download and install
mkdir -p ~/.local/share/fonts
cd ~/.local/share/fonts
curl -fLO https://github.com/ryanoasis/nerd-fonts/releases/latest/download/Meslo.tar.xz
tar -xf Meslo.tar.xz
fc-cache -fv
```

Verify the font is registered:

```bash
fc-list | grep -i meslo
```

You should see one or more Meslo entries. If the output is empty, the download or extraction failed. Check that `Meslo.tar.xz` extracted correctly.

On macOS with Homebrew:

```bash
brew install font-meslo-lg-nerd-font
```

After installing, set the font in your terminal emulator's settings. In Ghostty, add this to your config:

```
font-family = MesloLGS Nerd Font
```

For other terminals ([WezTerm](/install-wezterm-mac/), Alacritty, kitty, etc.), check their docs for the font configuration option.

## Install Starship

The recommended install method works everywhere:

```bash
curl -sS https://starship.rs/install.sh | sh
```

Or use a package manager:

```bash
# Ubuntu 25.04+ / Debian 13+
sudo apt install starship

# macOS
brew install starship

# Cargo (requires Rust toolchain)
cargo install starship --locked
```

On other distros: `apk add starship` (Alpine 3.13+), `pacman -S starship` (Arch/Manjaro), or `dnf copr enable atim/starship` then `dnf install starship` (Fedora 40+/CentOS 7+). The snap package is no longer a documented install path. Use the install script or your package manager instead.

Verify the install:

```bash
starship --version
```

You should see `starship 1.27.0` or later.

<Notice type="info" title="No self-update command">
Starship can't update itself. To upgrade, re-run the install script (it installs over the existing binary at `/usr/local/bin`) or use your package manager (`sudo apt upgrade starship`, `brew upgrade starship`).
</Notice>

If the install script can't write to `/usr/local/bin`, it will prompt you for sudo. If `starship` isn't found after install, check that `/usr/local/bin` is in your `$PATH`.

## Add Starship to Fish Shell

Add one line to the end of your Fish config:

```fish
# ~/.config/fish/config.fish
starship init fish | source
```

That's it. Open a new terminal or run `source ~/.config/fish/config.fish` and you should see the Starship prompt.

<Notice type="info" title="Placement matters">
Put the `starship init fish | source` line at the end of your `config.fish`, after any other configuration. That way Starship loads last and sets up the prompt correctly.
</Notice>

Fish 4.x still uses `~/.config/fish/config.fish` as its main config file, unchanged from earlier versions. If the prompt doesn't appear, see the Troubleshooting section below.

## Choose a Starship preset

Starship ships with 12 official presets that change the look of your prompt. List them all:

```bash
starship preset --list
```

Browse visual previews at [starship.rs/presets](https://starship.rs/presets/). Apply a preset:

```bash
starship preset tokyo-night -o ~/.config/starship.toml
```

If `~/.config/starship.toml` already exists, current versions refuse to overwrite it without the `-f` flag:

```bash
# Force overwrite an existing config
starship preset tokyo-night -o ~/.config/starship.toml -f
```

Popular presets:

- `tokyo-night` is a dark theme with purple/blue tones.
- `catppuccin-powerline` is the official Catppuccin powerline-style preset. Other Catppuccin flavors live in the community `catppuccin/starship` repo and are applied by copying TOML, not via `starship preset`.
- `gruvbox-rainbow` uses warm retro colors with per-segment backgrounds.
- `nerd-font-symbols` replaces text labels with Nerd Font icons.
- `plain-text-symbols` uses no special characters and works without Nerd Fonts.
- `pastel-powerline` uses soft pastel powerline segments.
- `pure-preset` mimics the popular Pure prompt.
- `bracketed-segments` wraps each module in brackets.

<Notice type="warning" title="Preset overwrites are safe now">
Current Starship versions refuse to clobber an existing `starship.toml` unless you pass `-f`. Starship also writes the output atomically (since v1.26.0), so you won't end up with a half-written config. Still, back up your config before force-overwriting if you've customized it.
</Notice>

After applying a preset, open a new terminal and confirm the prompt appearance changed. If you see `Error saving file, use --force to overwrite existing configuration file`, either pick a different `-o` target or add `-f` to replace your current config.

## Configure Starship with starship.toml

Starship reads its configuration from `~/.config/starship.toml`. If the file doesn't exist, Starship uses sensible defaults. Here's a practical configuration that shows relevant information without clutter:

```toml
# ~/.config/starship.toml

# General settings
format = """
$directory\
$git_branch\
$git_status\
$nodejs\
$python\
$rust\
$golang\
$docker_context\
$cmd_duration\
$line_break\
$character"""

# Don't add a blank line between prompts
add_newline = false

[directory]
truncation_length = 3
truncate_to_repo = true

[git_branch]
format = "[$symbol$branch]($style) "
symbol = " "

[git_status]
format = '([$all_status$ahead_behind]($style) )'

[nodejs]
format = "[$symbol($version)]($style) "
symbol = " "

[python]
format = "[$symbol($version)]($style) "
symbol = " "

[rust]
format = "[$symbol($version)]($style) "
symbol = " "

[golang]
format = "[$symbol($version)]($style) "
symbol = " "

[docker_context]
format = "[$symbol$context]($style) "
symbol = " "

[cmd_duration]
min_time = 2_000
format = "[$duration]($style) "

[character]
success_symbol = "[❯](green)"
error_symbol = "[❯](red)"
```

### What each section does

**format** controls which modules appear and in what order. Only modules listed here are shown. If a module is missing from `format`, it won't render regardless of its settings.

**directory** shows the current path. `truncation_length = 3` means you see at most 3 parent directories. `truncate_to_repo = true` shows the full path from the git repo root instead of a relative abbreviation.

**git_branch** and **git_status** show your branch name and whether you have uncommitted changes, ahead/behind counts, and so on. In very large repos `git_status` can be slow. See Troubleshooting for how to diagnose that before disabling it.

**Language modules** (nodejs, python, rust, golang) only appear when you're in a project that uses that language. They detect this by looking for marker files: `package.json` for Node.js, `pyproject.toml` for Python, `Cargo.toml` for Rust, and similar. If you don't have Node.js installed yet, see my guide to [install Node.js with NVM](/install-nodejs-using-nvm-macos-ubuntu/).

**cmd_duration** shows how long the last command took, but only if it took more than 2 seconds (the `min_time` threshold). Useful for noticing slow commands.

**character** shows a green `❯` on success and a red `❯` after a failed command.

## Bonus: Starship as your Claude Code statusline

<Notice type="success" title="New in Starship v1.25.0">
Starship can render the statusline inside Claude Code, showing model name, context-window usage, and session cost. This landed in v1.25.0 (April 2026) and got an `effort` variable for the model module in v1.27.0.
</Notice>

If you use Claude Code for AI-assisted development, Starship can replace the default statusline with a richer one. Add this to `~/.claude/settings.json`:

```json
{
  "statusLine": {
    "type": "command",
    "command": "starship statusline claude-code"
  }
}
```

Customize the statusline modules in `starship.toml`:

```toml
[profiles]
claude-code = "$claude_model$git_branch$claude_context$claude_cost"

[claude_model]
format = "[$symbol$model]($style) "
symbol = "🤖 "
style = "bold blue"

[claude_context]
format = "[$gauge $percentage]($style) "
gauge_width = 10
```

The three dedicated modules are:

- `claude_model` shows the model name (with an `effort` variable in v1.27.0+).
- `claude_context` shows a context-window gauge with how much of the window you've used.
- `claude_cost` shows session cost and token stats.

You can also run `/statusline` inside Claude Code and ask it to configure Starship for you. It knows about this integration.

To verify, open Claude Code and check that the statusline renders at the bottom of the panel with the model name and context gauge. If the statusline is blank, make sure `starship` is in your `$PATH` (Claude Code spawns the command in its own shell).

## Starship vs Tide for Fish Shell

If you're using Fish, you have two solid prompt options:

| | Starship | Tide |
|---|---|---|
| Works with | Fish, Zsh, Bash, etc. | Fish only |
| Configuration | TOML file | Interactive wizard |
| Async rendering | No (but fast enough) | Yes |
| Installation | Separate binary | Fisher plugin |
| Nerd Font needed | Yes (for most presets) | Yes |
| Customization | Edit `starship.toml` | `tide configure` + variables |

**Pick Starship if** you use multiple shells and want one prompt config, or if you prefer editing a config file directly.

**Pick Tide if** you only use Fish and want async rendering with a wizard-based setup. Install Tide with Fisher:

```fish
fisher install IlanCosman/tide@v6
tide configure
```

One thing to keep in mind: Tide's last release is v6.2.0 (August 2025), a slower cadence than Starship's release schedule (four releases in 2026 alone). If a slow-moving dependency bothers you, that's a point for Starship.

I cover Tide and other Fish tools in [best Fish Shell plugins and tools](/best-fish-shell-plugins/). For a full comparison of all Fish prompt options including Tide, Pure, and Hydro, see my [Fish Shell themes and prompts guide](/fish-shell-themes-prompts/).

Both are good. I use Starship because I sometimes drop into Zsh or Bash on different machines and want the same prompt everywhere.

## Advanced configuration

These tips assume you're running Fish directly. If you're inside tmux or Zellij, see my [best terminal multiplexers](/best-terminal-multiplexers/) guide. Prompt rendering and redraw behavior can differ inside a multiplexer.

### Right-side prompt

Starship supports a right prompt that appears on the right edge of your terminal:

```toml
# In starship.toml
right_format = """$time"""

[time]
disabled = false
format = "[$time]($style)"
time_format = "%H:%M"
```

This shows the current time on the right side. Fish's right prompt support works well with this.

### Custom modules

You can define custom modules that run shell commands. One important gotcha: custom `command` entries run under `/bin/sh` by default, not Fish. Fish builtins like `string split` won't work.

Here's a working example that shows your Fish version using `awk` (POSIX-compatible):

```toml
[custom.fish_version]
command = "fish --version | awk '{print $3}'"
when = "true"
format = "[fish $output]($style) "
style = "cyan"
```

If you need Fish builtins or functions, either declare Fish as the shell:

```toml
[custom.fish_version]
command = "fish --version | string split ' ' | tail -1"
shell = ["fish", "-c"]
when = "true"
format = "[fish $output]($style) "
style = "cyan"
```

Or write a Fish function and call it from the custom command. See [Fish Shell functions and custom commands](/fish-shell-functions-custom-commands/) for how to build those. If the module shows nothing in your prompt, run `starship explain` to see whether the custom module rendered and what output it produced.

### Per-directory configuration

Starship doesn't have per-directory config natively, but you can achieve something similar with Fish's `conf.d` system. Create a function that sets `STARSHIP_CONFIG` based on the current directory:

```fish
# ~/.config/fish/conf.d/starship-dir.fish
function __check_starship_config --on-variable PWD
    if test -f .starship.toml
        set -gx STARSHIP_CONFIG (pwd)/.starship.toml
    else
        set -e STARSHIP_CONFIG
    end
end
```

Now any directory with a `.starship.toml` file will use that configuration instead of the global one. The `STARSHIP_CONFIG` environment variable is still supported and is the right way to point Starship at an alternate config.

## Troubleshooting Starship in Fish

When something looks wrong, diagnose before you start disabling modules. Starship has three built-in debugging tools:

```bash
# Show which modules rendered and why
starship explain

# Print per-module render times (find the slow one)
starship timings

# Dump the computed config (catch typos in starship.toml)
starship print-config
```

<Accordion label="Icons show as boxes or question marks" group="troubleshooting" expanded="true">
You need a Nerd Font installed and selected in your terminal. Run `fc-list | grep -i meslo` (Linux) to confirm the font is registered, then check your terminal emulator's font setting. If you're on a remote machine, the font must be installed on the machine where the terminal emulator runs, not the remote server.
</Accordion>

<Accordion label="Prompt is slow" group="troubleshooting">
Run `starship timings` first. It shows which modules take more than 1ms to render. Git status in very large repos is the usual culprit. If a module is slow, disable it or reduce its scope:

```toml
[git_status]
disabled = true
```

Don't blanket-disable modules without measuring first. A slow module might only trigger in specific directories.
</Accordion>

<Accordion label="Starship not loading" group="troubleshooting">
Make sure `starship init fish | source` is in your `config.fish` and that `starship` is in your `$PATH`. Run `which starship` to verify. If it's not found, your install location (`/usr/local/bin` by default) may not be in your `$PATH`. Add it to `~/.config/fish/config.fish`:

```fish
set -gx PATH /usr/local/bin $PATH
```

Then re-source your config or open a new terminal.
</Accordion>

<Accordion label="Preset command errors with 'use --force'" group="troubleshooting">
Current versions refuse to overwrite an existing `starship.toml`. If you want to replace your config, add `-f`:

```bash
starship preset tokyo-night -o ~/.config/starship.toml -f
```

Or write to a different file and merge manually.
</Accordion>

<Accordion label="Custom module shows nothing" group="troubleshooting">
Custom commands run under `/bin/sh`, so Fish builtins like `string split` will fail silently. Either use POSIX-compatible commands (`awk`, `cut`, `grep`) or declare `shell = ["fish", "-c"]` in the module config. Run `starship explain` to see if the module rendered and what output it produced.
</Accordion>
