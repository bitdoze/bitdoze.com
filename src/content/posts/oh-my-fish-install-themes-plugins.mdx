Oh My Fish (OMF) is a framework for Fish Shell, similar to what Oh My Zsh is for Zsh. It gives you a command-line tool (`omf`) for installing themes and plugins from a curated repository: Oh My Fish themes handle the prompt, and Oh My Fish plugins fill gaps like Bash interop and directory jumping. I used it briefly before switching to Fisher, and I'll be upfront about why.

<Notice type="warning" title="OMF maintenance status (updated Nov 2026)">
Oh My Fish was dormant from 2020 until April 2026, when v8 shipped with Fish 4 support. Maintenance has resumed, with fixes landing through September 2026, but the project README still warns that some themes and packages are broken. It works for many setups. For new installs [Fisher](/best-fish-shell-plugins/) is still the safer default, and this guide covers both.
</Notice>

## What's new in Oh My Fish v8 (April 2026)

OMF v8, released 2026-04-07, is the first release since v7 of 2020-04-11. That is a six-year gap. The release notes call it a modernization pass for modern Fish: Fish 4+ compatibility (minimum fish 3.0, CI covers 4.0.2 through 4.8), installer fixes for offline, tarball, and branch handling, better theme activation, uninstall hooks, improved bundle loading, and `OMF_CONFIG` package discovery.

Commits kept landing after the release: a test-suite overhaul, installer exit-code fixes, `omf list` and `omf theme` fixes for systems without `column`, and an `omf version` fix for tarball checkouts. Last push on master as of this update: 2026-09-30. Repo health is decent on paper: 11,417 stars, 7 open issues and pull requests combined, not archived.

The README warning about broken packages is still up though. Treat OMF as usable with caution, not as a fully healthy package ecosystem.

### Update an existing OMF install to v8

If you already run a v7-era install, upgrade through the `stable` channel:

```fish
omf update          # everything, or:
omf update omf      # core only
```

Then verify:

```fish
omf version         # expect 8.x
omf doctor          # sanity check after a major update
```

`omf version` used to print nothing on tarball checkouts (fixed 2026-09-30). If it shows "unknown" now, you are on a non-git install rather than a broken one. Confirm the channel with `omf channel stable`.

## Install Oh My Fish

<ListCheck>
<ul>
<li>Fish Shell ≥ 3.0. On Ubuntu see [how to install Fish Shell on Ubuntu](/install-fish-shell-ubuntu/), on Mac see the [Fish Shell on macOS setup guide](/fish-shell-macos-setup/)</li>
<li>git ≥ 1.9.5</li>
<li>A terminal with a Nerd Font, only if you want Powerline-style themes like bobthefish</li>
<li>No root access needed. OMF installs to your home directory</li>
</ul>
</ListCheck>

The documented one-liner:

```fish
curl https://raw.githubusercontent.com/oh-my-fish/oh-my-fish/master/bin/install | fish
```

OMF lands in two places: code in `~/.local/share/omf/` (honors `$XDG_DATA_HOME`) and config in `~/.config/omf/` (honors `$XDG_CONFIG_HOME`). Knowing the split matters later: the code directory is disposable, the config directory is yours.

To verify:

```fish
omf version
omf list
```

Both should print output without errors. `omf version` prints a version number (8.x on a current install), `omf list` shows your installed packages and theme.

### Verify the installer before piping to shell

You are piping remote code into your login shell. The README documents a checksum step that takes ten seconds:

```fish
curl -sL https://raw.githubusercontent.com/oh-my-fish/oh-my-fish/master/bin/install.sha256 | shasum -a 256 --check
```

<Notice type="info" title="curl-pipe-to-shell">
Convenient, but it runs unverified remote code. The checksum step above is cheap insurance.
</Notice>

### Scripted or offline installation

The installer has separate flags for local-source and offline installs. They are not the same thing.

<Tabs>
<Tab name="From a git checkout">

Installs from the local source. The installer still fetches plugins over the network.

```fish
git clone https://github.com/oh-my-fish/oh-my-fish
cd oh-my-fish
bin/install --local-source
```

</Tab>
<Tab name="From a release tarball">

```fish
fish install --local-source=omf.tar.gz
```

</Tab>
<Tab name="Fully offline (no network)">

Implies `--local-source` and skips plugin fetching entirely. Run `omf install` later when the network is back.

```fish
bin/install --offline
```

</Tab>
</Tabs>

For servers and scripted installs, the flow I would automate on a fresh VPS (mine run on [Hetzner Cloud](https://go.bitdoze.com/hetzner)) is: download the installer, run the readiness check, then assert the exit code of every step.

```fish
curl -sL https://raw.githubusercontent.com/oh-my-fish/oh-my-fish/master/bin/install > install
fish install --check                # readiness check only
fish install --yes --noninteractive # scripted install
```

Other flags worth knowing: `--channel=stable|dev`, `--path=`, `--config=`, `--uninstall`, `--verbose`.

<Notice type="warning" title="Assert exit codes when scripting">
A pre-v8 installer bug made environment-check aborts exit 0 (fixed 2026-08-30). Use `--check` first and fail loudly in your scripts.
</Notice>

Everything here is MIT-licensed and free. The only real cost is trusting a third-party package ecosystem.

## OMF basics: essential omf commands

All management goes through the `omf` command. Fish itself covers a lot of ground natively, so before you add packages see [Fish Shell autocomplete and suggestions](/fish-shell-autocomplete-suggestions/) for the built-ins OMF does not need to touch.

### Install a package or theme

```fish
omf install bobthefish
omf install z
omf install bass
```

`omf install` also accepts URLs and `user/repo` forms:

```fish
omf install https://github.com/oh-my-fish/theme-bobthefish
omf install oh-my-fish/theme-bobthefish
```

### Search packages

Fuzzy-search the package database. The official `oh-my-fish/packages-main` repository has about 254 entries (repo pushed 2026-05-14).

```fish
omf search z
omf search -t bobthefish    # themes only
omf search -p bass          # plugins only
```

### Apply a theme

```fish
omf theme bobthefish
```

To see what is available:

```fish
omf theme
```

Screenshots of most themes live in the [Oh My Fish themes documentation](https://github.com/oh-my-fish/oh-my-fish/blob/master/docs/Themes.md).

### Update and remove

```fish
omf update          # update everything
omf update omf      # core only
omf remove z        # remove a package
```

<Notice type="warning" title="Editing bundle is not uninstalling">
Deleting a line from `~/.config/omf/bundle` does not uninstall the package. Run `omf remove <name>`.
</Notice>

### Doctor, reload, and channels

```fish
omf doctor                          # first-line troubleshooter
omf reload                          # exec-based safe reload of OMF and plugins
omf channel                         # show current channel (stable|dev)
omf channel dev                     # switch to the dev channel
omf repositories list               # list package repositories
omf repositories add user/repo      # add a third-party repo
```

`omf doctor` is the documented first step for any problem, and it is what I would run before filing an issue. `omf reload` restarts OMF in place without opening a new terminal. The default package repository is `oh-my-fish/packages-main`.

### Uninstall OMF entirely

```fish
omf destroy
```

The installer also accepts `--uninstall`. This is the undo path for the whole guide: `omf destroy` removes OMF and its packages. It does not restore anything you changed by hand in `~/.config/fish/config.fish`.

## Popular Oh My Fish themes

One caveat before browsing: some OMF themes are unmaintained or broken. The README warning is real. Check each theme's repository before you commit to it. Start with these four.

### bobthefish: the flagship theme

The most popular OMF theme, and still maintained (repo pushed 2026-05-20, 1,530 stars). Powerline-style prompt with git status, virtual environments, Node version, and more. Needs a Nerd Font or Powerline font.

```fish
omf install bobthefish
```

Configure it in `~/.config/omf/init.fish`:

```fish
set -g theme_nerd_fonts yes
set -g theme_color_scheme dracula
set -g theme_display_git yes
set -g theme_show_exit_status yes
set -g theme_display_user ssh
set -x VIRTUAL_ENV_DISABLE_PROMPT 1   # avoid double virtualenv prompt
```

That last line matters if you use Python virtualenvs. Without it, bobthefish and virtualenv both draw a prompt segment and you get a doubled prompt. If the theme does not change after install, it is almost always a missing Nerd Font (see Troubleshooting).

### agnoster, clearance, and lambda

**agnoster** is a port of the Zsh Agnoster theme. Two-line prompt with Powerline characters, git info, and virtualenv support.

```fish
omf install agnoster
```

**clearance** is clean and minimal. No special fonts needed.

```fish
omf install clearance
```

**lambda** is a minimal theme with a λ prompt character.

```fish
omf install lambda
```

Preview more themes in the [Oh My Fish themes documentation](https://github.com/oh-my-fish/oh-my-fish/blob/master/docs/Themes.md).

If you want a maintained cross-shell prompt instead of an OMF theme, [set up the Starship prompt with Fish Shell](/fish-shell-starship-prompt/). Mac users running Ghostty can pair it with the [Starship + Ghostty terminal setup](/starship-ghostty-terminal/).

## Useful Oh My Fish plugins

Fish handles [syntax highlighting](/fish-shell-syntax-highlighting/) natively, so you do not need an OMF package for it. The plugins below fill real gaps.

### bass

Runs Bash scripts and captures their environment variable changes. Useful for tools that only ship Bash configuration:

```fish
omf install bass
bass source ~/.nvm/nvm.sh
```

This is the most genuinely useful OMF package. It bridges the gap between [Fish's non-POSIX syntax](/fish-shell-vs-bash-vs-zsh/) and Bash-only tools. If nvm is your reason for reaching for bass, also consider [nvm.fish to use NVM with Fish Shell](/nvm-fish-shell/) as a native alternative.

### z

Directory jumping similar to [zoxide](/zoxide/). It tracks the directories you visit and lets you jump to them with partial names:

```fish
omf install z
z projects
```

I would pick zoxide over this. It is faster, works across shells, and is actively maintained. But if you want everything through OMF, the z plugin works.

### fish-spec

A testing framework for Fish functions. Useful if you write Fish plugins or complex functions:

```fish
omf install fish-spec
```

### extract

A universal archive extraction tool, so `extract file.tar.gz` instead of remembering tar flags:

```fish
omf install extract
```

## Oh My Fish configuration files and dotfiles

OMF's config lives in `$OMF_CONFIG` (default `~/.config/omf/`). Most guides mention two files. There are more:

- **`bundle`** lists installed packages and the active theme
- **`theme`** holds the current theme name
- **`channel`** holds the update channel (`stable` or `dev`)
- **`init.fish`** runs at startup, after plugins load
- **`before.init.fish`** (optional) runs before plugins load
- **`key_bindings.fish`** (optional) holds custom key bindings
- **`conf.d/`** (optional) is sourced in filesystem order. A file named `a_script.fish` runs after `omf.fish`, so prefix names with `00_` or `xx_` when you need explicit ordering

**`~/.config/omf/bundle`** looks like this:

```
package bass
package z
theme bobthefish
```

**`~/.config/omf/init.fish`** is where theme configuration goes:

```fish
# ~/.config/omf/init.fish
set -g theme_nerd_fonts yes
set -g theme_color_scheme dracula
```

<Notice type="warning" title="bundle edit is not uninstall">
Removing a line from `bundle` does not uninstall the package. Run `omf remove <name>` and let OMF rewrite the file.
</Notice>

Sharing `~/.config/omf/` across machines replicates your setup. Keep it in git: that is your shell-setup backup, and it costs nothing. For customizations that go beyond OMF config, see [creating custom Fish Shell functions](/fish-shell-functions-custom-commands/).

## Oh My Fish vs Fisher

Here is how they compare as of late 2026:

| | Oh My Fish | Fisher |
|---|---|---|
| Status | Revived (v8, April 2026); README warning still up | Actively maintained |
| Latest release | v8 (2026-04-07) | 4.4.8 (2026-01-25) |
| GitHub stars | 11,417 | 9,463 |
| Approach | Framework (has its own init) | Plugin manager only |
| Startup impact | Adds some overhead | Zero overhead |
| Plugin format | OMF-specific packages | Standard Fish plugins |
| Compatibility | OMF packages only | OMF packages and any Fish plugin |
| Config | `omf` commands and config files | `fisher` commands and fish_plugins file |
| Themes | Built-in theme system | Install prompt plugins directly |

Fisher is faster, maintained, and can install OMF-compatible packages. That last point is literally in Fisher's README. The main reason to use OMF today is if you already have a working OMF setup and do not want to migrate.

One Fisher caveat worth knowing before you switch: Fisher expands plugins into your fish config directory and overwrites files by default. `$fisher_path` (see [Fisher issue #640](https://github.com/jorgebucaran/fisher/issues/640)) changes where plugins land.

### Migrating from OMF to Fisher

If you want to switch:

1. Note your installed packages: `omf list`
2. Install Fisher:
   ```fish
   curl -sL https://raw.githubusercontent.com/jorgebucaran/fisher/main/functions/fisher.fish | source && fisher install jorgebucaran/fisher
   ```
3. Install equivalents through Fisher. Most OMF packages install directly:
   ```fish
   fisher install oh-my-fish/theme-bobthefish
   ```
4. Uninstall OMF: `omf destroy`

Fisher installs packages from the OMF repository using the `oh-my-fish/` prefix. Not every package works, but the popular ones do.

To verify the migration: `fisher list` shows your packages, and a new shell loads your prompt without errors.

## Creating OMF packages

To scaffold your own package or theme:

```fish
omf new plugin my-plugin
omf new theme my-theme
```

This creates a scaffold in `~/.config/omf/pkg/my-plugin/` or `~/.config/omf/themes/my-theme/`.

Plugin structure:

```
my-plugin/
├── completions/
│   └── my-plugin.fish
├── functions/
│   └── my-plugin.fish
├── init.fish
└── uninstall.fish
```

`init.fish` runs when the plugin loads. `uninstall.fish` runs when it is removed. To distribute it, submit the repo to `oh-my-fish/packages-main` or add a personal repository with `omf repositories add`. If all you need is a shortcut rather than a full plugin, [Fish Shell abbreviations vs aliases](/fish-shell-abbreviations-vs-aliases/) covers lighter-weight options.

## Troubleshooting Oh My Fish

Run `omf doctor` first. It is the documented troubleshooter and catches most setup problems before you start guessing.

**OMF commands not found.** Restart your shell after installation, or run `source ~/.config/fish/conf.d/omf.fish`.

**Theme not changing.** Some themes need a Nerd Font. Install one (MesloLGS NF works) and set it in your terminal emulator. If the prompt still looks wrong, confirm the theme name matches what `omf theme` lists.

**Plugin errors after update.** Some packages break, and the README warning is real. Check the plugin's repository for open issues or patches, or move to a Fisher-compatible alternative.

**`omf list` or `omf theme` exits 127 on minimal containers.** The `column` utility is missing (common on Alpine images). Fixed in v8-era commits (2026-09-30) with a plain-output fallback. Update OMF, or install the package: `apk add util-linux`.

**`omf version` prints "unknown".** You are on a tarball or other non-git install. Older versions had this bug; a 2026-09-30 fix addresses it. It does not mean OMF is broken.

**Scripted install exits 0 despite aborting.** A pre-v8 installer bug (fixed 2026-08-30). Use `--check` first and assert exit codes in scripts.

**bobthefish shows a double virtualenv prompt.** Add `set -x VIRTUAL_ENV_DISABLE_PROMPT 1` to your config.

For rollback, `omf destroy` (or the installer's `--uninstall` flag) removes OMF entirely. Nothing outside `~/.local/share/omf/` and `~/.config/omf/` is touched.
