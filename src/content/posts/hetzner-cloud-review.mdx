## Why Hetzner Cloud in 2026

The value that survives the price hike: EU Cost-Optimized plans (CX Gen3 and the CAX ARM line) are still much cheaper than DigitalOcean or Vultr for shared-vCPU workloads. A CX23 (2 vCPU / 4 GB / 40 GB) is €5.49/month in the EU after the June 2026 adjustment. The ARM CAX11 with the same shape is €5.99/month. For reference, the Regular Performance CPX22 with 2 vCPU / 4 GB is now €19.49/month, which tells you how hard that line got hit.

The background: DRAM and NAND flash costs went up across the industry, driven by AI infrastructure demand. Hetzner announced a price adjustment on 23 February 2026 for April 1, then rescheduled it. The server price adjustment actually took effect on 15 June 2026 at 8:00 CEST, and it applies to new orders and rescales. Servers that existed before that date kept their old prices. The full breakdown is in the pricing section below.

What you still get after the increase: 20TB of included traffic in EU locations, hourly billing, a clean API, and a console that stays out of the way. For cheap VPS in Europe, Hetzner is still my default recommendation.

## Hetzner Cloud pricing (after the June 2026 increase)

### What changed on 15 June 2026

The timeline matters, because a lot of posts (including earlier versions of this one) still say "April 2026":

1. **23 February 2026** - Hetzner publishes a statement announcing a price adjustment "as of April 1st 2026" due to DRAM and NAND flash cost increases. ([pressroom](https://www.hetzner.com/pressroom/statement-price-adjustment/))
2. **27 May 2026** - A second statement, "Details regarding the standardization and price adjustment of our server products", moves the date. Effective **15 June 2026, 8:00 CEST**, for new orders and rescales. ([pressroom](https://www.hetzner.com/pressroom/standardization-and-price-adjustment-of-our-server-products/))
3. **15 June 2026** - New cloud prices go live. The dedicated server portfolio is standardized at the same time (new `-1/-2/-3` suffixes and a cheaper "-Ltd" limited line with reduced setup fees).

**Not affected by the adjustment:** Load Balancers, Volumes, Snapshots, Object Storage, IPs, storage products, web hosting, managed servers, and Server Auction.

The honest headline is not "up to 37%". That number came from the February statement and only fits the shared-vCPU lines:

- **Cost-Optimized (CX / CAX):** +30% to +38%
- **Regular Performance (CPX):** +144% to +175%
- **Dedicated (CCX):** +113% to +173%

<Notice type="warning" title="June 2026 price adjustment">
    The server price adjustment took effect <strong>15 June 2026, 8:00 CEST</strong>, for new orders and rescales. Existing servers keep their legacy pricing unless certain changes trigger a switch. Official sources: <a href="https://www.hetzner.com/pressroom/standardization-and-price-adjustment-of-our-server-products/">the May statement</a> and the <a href="https://docs.hetzner.com/general/infrastructure-and-availability/price-adjustment/">price adjustment docs</a> (ID GE-D9256).
</Notice>

<Notice type="info" title="Plan categories (October 2025)">
    Hetzner restructured plans into Cost-Optimized, Regular Performance, and Dedicated General Purpose on 16 October 2025. Old CX/CPX plans are deprecated for new orders but existing servers keep running. [Hetzner Cloud Cost-Optimized plan pricing explained](/hetzner-cloud-cost-optimized-plans/).
</Notice>

### Included traffic & overage costs

The old "1TB in US/Asia" line is gone. Included traffic now scales with the plan:

- EU shared plans (CX / CAX / CPX) include 20 TB. EU CCX plans include 20 / 20 / 30 / 40 / 50 / 60 TB from CCX13 to CCX63. Overage is €1/TB.
- US plans: CPX11 gives 1 TB up to CPX51 with 5 TB; CCX13 gives 1 TB up to CCX63 with 8 TB. Overage is €1/TB ($1.20/TB).
- Singapore: CPX02/CPX12 give 0.5 TB, then 1 TB (CPX22) up to 5 TB (CPX62); CCX13 gives 1 TB up to CCX63 with 8 TB. Overage is **€7.40/TB**.
- A primary IP (detached or dedicated) costs €0.50/month ($0.60).

<Notice type="warning" title="Singapore egress">
    The €7.40/TB Singapore overage is the most common bill-shock on this platform. See the datacenter warning above for the fix.
</Notice>

### Existing customers: keep your old prices (the operator playbook)

This is the section I wanted most after the change, because "what do I do about my current servers" is what everyone asks first.

<ListCheck>
- Do nothing and you keep legacy pricing. The adjustment applies to new orders and rescales. Your existing servers stay on their old rates. One caveat from the docs (GE-D9256): "certain changes to servers with legacy pricing may trigger a switch to the current pricing" - so don't treat the old price as unconditionally permanent.
- Do the rebuild-vs-rescale math. Rescaling a legacy server moves it to current pricing. Migrating the workload to a fresh server (snapshot, then restore to a new CX23 at €5.49) and deleting the old box can be cheaper. Snapshots restore across locations, so you can change region at the same time.
- Watch backup costs. Backups cost 20% of the server's current price, so servers on the new pricing pay more for the same backup slots. Snapshots were excluded from the adjustment. For big disks, snapshot-only backup can now be cheaper than the 7-slot backup plan (check the current snapshot rate in your Console billing page).
- Know where the value went. CX23/CX33 (x86) and CAX11-CAX41 (ARM, EU-only) are the sweet spots for WordPress and self-hosting. For dedicated vCPU needs, compare CCX against the dedicated "-Ltd" line (for example AX41-1-LTD around €57.30/month) and Server Auction before paying CCX prices.
- Verify your own prices from the CLI instead of trusting any blog (including this one).
</ListCheck>

```bash
# hcloud CLI v1.70.x - exact price per plan and location, straight from the API
hcloud server-type list -o format='{{.Name}}: {{.Cores}} vCPU, {{.Memory}} GB'
hcloud server-type describe cx23   # per-location price + included traffic

# what am I actually running? (name, type, datacenter)
hcloud server list -o format='{{.Name}}\t{{.ServerType}}\t{{.Datacenter}}'

# which OS images are orderable today
hcloud image list -o format='{{.Name}}\t{{.Type}}\t{{.Deprecated}}' | grep -v '^$'
```

**Verify:** `hcloud server-type describe cx23` should print a price table with FSN1/NBG1/HEL1 entries (€5.49 at the time of writing). If your output shows €3.99, you are looking at cached tooling or a legacy contract view.

<Notice type="info" title="Rates to verify in your Console">
    Snapshot €/GB rates and the exact backup percentage on legacy vs new servers are rendered client-side in the billing UI and change occasionally. Check <strong>Billing → Pricing</strong> in the <a href="https://console.hetzner.com/">Hetzner Console</a> before you model costs on them.
</Notice>

## Migration to Hetzner Cloud

### From other VPS providers

1. Create a server with same or better specifications
2. Transfer data using rsync or migration tools
3. Update DNS records (lower the TTL a day beforehand)
4. Test thoroughly before switching

### Migration tools
- **Hetzner CLI** (`hcloud` v1.70.x) for automation
- **Terraform** for infrastructure as code (pin `hetznercloud/hcloud` `~> 1.70`)
- **Ansible** for configuration management
- **Custom scripts** for specific needs

`user_data` now works on server rebuilds (since January 2026), which makes reproducible rebuilds a lot easier. Snapshots restore cross-location, so a snapshot is also a migration vehicle if you are moving region.

### Pre-flight checklist

<ListCheck>
- Lower DNS TTL to 300s at least a day before cutover
- Run an rsync dry-run (<code>rsync -avn</code>) and confirm file counts match
- Confirm TLS certificates will issue on the new host (port 80/443 reachable)
- Smoke test the new server on a hosts-file entry or staging domain first
- Keep the old server alive 24-48 hours after cutover, and snapshot it before decommission
</ListCheck>

**Rollback:** if the new server misbehaves, point DNS back to the old one (which is why you kept it) and debug offline. Nothing about this migration needs to be irreversible.
