## Qué hace QwenPaw

QwenPaw es un asistente de IA autoalojado construido sobre [AgentScope](https://github.com/agentscope-ai/agentscope) y [ReMe](https://github.com/agentscope-ai/ReMe) para la gestión de la memoria. El nombre significa Qwen Personal Agent Workstation. La propuesta no ha cambiado desde la primera versión: un asistente que se conecta a tus apps de mensajería y ejecuta tareas en horarios sin que tengas que pedírselo.

Lo que sí ha cambiado desde que lo cubrí por primera vez: ahora hay una arquitectura de plugins con marketplace, integración MCP para acoplar herramientas externas, soporte multiagente vía ACP para lanzar subagentes, una interfaz de terminal a pantalla completa y una app de escritorio en Beta. La consola web en `http://127.0.0.1:8088/` sigue siendo el lugar recomendado para configurarlo todo en lugar de editar archivos de configuración a ciegas.

### QwenPaw vs OpenClaw vs nanobot

Si estás decidiendo entre los tres, así se comparan. Las columnas de OpenClaw y nanobot reflejan su estado la última vez que los revisé; esos proyectos también avanzan, así que toma esas celdas como una instantánea.

|| Característica | QwenPaw | OpenClaw | nanobot |
|---|---|---|---|---|
|| **Lenguaje** | Python | TypeScript | Python |
|| **Creado por** | AgentScope (Alibaba) | Comunidad | HKUDS |
|| **Instalación** | pip / script / Docker / escritorio / alojado | curl one-liner | pip |
|| **Consola web** | Sí (integrada en :8088) | No (dashboards de terceros) | No |
|| **Canales** | DingTalk, Lark, WeChat, Discord, Telegram, iMessage, QQ | Telegram, WhatsApp, Slack, Discord | Telegram, Discord, WhatsApp, Slack, Feishu, DingTalk, Email, QQ |
|| **Modelos locales** | QwenPaw Local (llama.cpp), Ollama, LM Studio | Ollama | vLLM |
|| **Memoria** | Tres capas: contexto de trabajo, history.db + FTS5, base de conocimiento ReMe | Basada en archivos + búsqueda semántica | Basada en archivos |
|| **Habilidades y plugins** | Habilidades integradas, Plugin Market, MCP | Habilidades de la comunidad | Integradas |
|| **Tareas programadas** | Cron + heartbeat | Cron | Cron |
|| **Superficies extra** | TUI, app de escritorio, REST API, multiagente (ACP) | Ninguna | Ninguna |
|| **Licencia** | Apache 2.0 | MIT | MIT |

Donde QwenPaw se adelanta: la consola web integrada significa que no necesitas dashboards de terceros, el soporte de DingTalk/Lark/WeChat es de primera clase en lugar de añadido a posteriori, y el stack de seguridad (sandbox, Tool Guard, File Guard) es el más completo de los tres (ver [Seguridad](#seguridad-sandbox-tool-guard-y-file-guard) más abajo). OpenClaw sigue ganando en apps de mensajería occidentales como WhatsApp y Slack. Si DingTalk o Lark es donde vive tu equipo, QwenPaw te ahorra muchos quebraderos de cabeza de configuración.

## Instalación

QwenPaw tiene siete formas de ponerse en marcha: pip, el script de una línea, Docker, un despliegue de un clic en Alibaba Cloud ECS (ComputeNest), la plataforma alojada gratuita AgentScope Platform, un fork de ModelScope Studio (mantén ese no público) y una [app de escritorio en Beta](https://github.com/agentscope-ai/QwenPaw/releases) para Windows 10+ y macOS 14+. Cubro las tres que encajan con el autoalojamiento.

<Tabs>
<Tab name="pip install">

La vía más limpia si ya tienes Python:

```bash
pip install qwenpaw          # requires Python >= 3.11, < 3.14
qwenpaw init --defaults
qwenpaw app
```

Abre `http://127.0.0.1:8088/` y verás la Consola. Eso ya es una configuración básica funcional.

Para una configuración interactiva donde eliges por adelantado tu proveedor de LLM y los canales:

```bash
qwenpaw init
```

Esto te guía por el intervalo de heartbeat, el canal de destino, las horas activas y la configuración opcional de habilidades. Dos cosas que conviene saber: el comando `copaw` sigue funcionando como alias de `qwenpaw`, y `init --defaults` acepta automáticamente la telemetría de uso anónima mientras que el `init` interactivo te pregunta (detalles en las [preguntas frecuentes](#preguntas-frecuentes)).

</Tab>
<Tab name="Script de una línea">

No necesitas Python. El instalador lo gestiona todo usando [uv](https://docs.astral.sh/uv/).

**macOS / Linux:**

```bash
curl -fsSL https://qwenpaw.agentscope.io/install.sh | bash
```

**Windows (PowerShell):**

```powershell
irm https://qwenpaw.agentscope.io/install.ps1 | iex
```

Abre una terminal nueva después de instalar (los cambios en el PATH solo aplican a shells nuevas), luego:

```bash
qwenpaw init --defaults
qwenpaw app
```

Flags útiles del instalador:

```bash
# pin a version
curl -fsSL https://qwenpaw.agentscope.io/install.sh | bash -s -- --version 2.3.0

# install from source
curl -fsSL https://qwenpaw.agentscope.io/install.sh | bash -s -- --from-source

# extras: local, whisper, channels, full
# channels/full apply the channel plugin preset offline during install
curl -fsSL https://qwenpaw.agentscope.io/install.sh | bash -s -- --extras channels,whisper
```

Para actualizar más adelante, simplemente vuelve a ejecutar el instalador. Ejecuta `qwenpaw plugins prepare-upgrade` por ti. Si tienes las antiguas URLs `copaw.agentscope.io` en scripts, reemplázalas: ese dominio ya no resuelve.

</Tab>
<Tab name="Docker">

La imagen de Docker de QwenPaw está en `agentscope/qwenpaw` (99 etiquetas; `latest` es estable, `pre` es pre-release). A diferencia de la imagen 1.x, ahora usa tres volúmenes:

```bash
docker pull agentscope/qwenpaw:latest

docker run -d --name qwenpaw --restart unless-stopped \
  -p 127.0.0.1:8088:8088 \
  -v qwenpaw-data:/app/working \
  -v qwenpaw-secrets:/app/working.secret \
  -v qwenpaw-backups:/app/working.backups \
  -e DASHSCOPE_API_KEY=your_key_here \
  agentscope/qwenpaw:latest
```

- `qwenpaw-data:/app/working`: configuración, memoria, habilidades
- `qwenpaw-secrets:/app/working.secret`: ajustes de proveedores de modelos y claves de API
- `qwenpaw-backups:/app/working.backups`: archivos de copias de seguridad

Fija `agentscope/qwenpaw:v2.3.0` si quieres despliegues aburridos; `latest` se mueve cada semana. Hay un mirror en ACR para usuarios en China: `agentscope-registry.ap-southeast-1.cr.aliyuncs.com/agentscope/qwenpaw`. El [docker-compose.yml](https://github.com/agentscope-ai/QwenPaw/blob/main/docker-compose.yml) de upstream merece un vistazo; añade `restart: always` y `init: true`, además de variables de entorno para la autenticación de la consola.

Si necesitas que QwenPaw en Docker alcance Ollama en el host:

```bash
docker run -p 127.0.0.1:8088:8088 \
  --add-host=host.docker.internal:host-gateway \
  -v qwenpaw-data:/app/working \
  -v qwenpaw-secrets:/app/working.secret \
  agentscope/qwenpaw:latest
```

Luego pon la Base URL de Ollama en `http://host.docker.internal:11434/v1` en la Consola. Usuarios de LM Studio: `http://host.docker.internal:1234/v1`. En Linux, `--network=host` también funciona (sin necesidad de `-p`).

<Notice type="warning" title="Si expones la consola">
El contenedor enlaza `127.0.0.1:8088` a propósito. Si alguna vez expones la consola a internet con un proxy inverso, define `QWENPAW_AUTH_ENABLED=true`, `QWENPAW_AUTH_USERNAME` y `QWENPAW_AUTH_PASSWORD`, o ponla detrás de la autenticación de tu proxy. Mejor aún: no la expongas en absoluto y accede a ella a través de un túnel con la [guía de túneles SSH en Linux](/es/tuneles-ssh-linux/).
</Notice>

### Instalación en un VPS de Hetzner

Si quieres QwenPaw funcionando 24/7 en un VPS, una máquina pequeña hace el trabajo. Yo uso un Hetzner CX22 (2 vCPU, 4 GB de RAM). Consulta mi [reseña de Hetzner Cloud](/es/hetzner-cloud-resena/) para los precios actuales, ya que [los precios de los VPS subieron en 2026](/es/subidas-precios-vps/).

<Notice type="success" title="Empieza con Hetzner">
[Consigue 20 € de crédito en Hetzner](https://go.bitdoze.com/hetzner) o un [VPS de Hostinger](https://go.bitdoze.com/hostinger-vps) al registrarte a través de nuestros enlaces de referido. Eso cubre unos meses de QwenPaw en marcha.
</Notice>

Conéctate por SSH a tu servidor y ejecuta:

```bash
ssh root@YOUR_SERVER_IP
apt update && apt upgrade -y
curl -fsSL https://qwenpaw.agentscope.io/install.sh | bash
```

Abre una nueva sesión de shell, luego:

```bash
qwenpaw init --defaults
qwenpaw app
```

Para mantenerlo en ejecución después de cerrar la sesión SSH, usa systemd (una sesión de tmux también vale, pero systemd sobrevive a los reinicios). Encuentra la ruta de tu binario con `which qwenpaw` y crea `/etc/systemd/system/qwenpaw.service`:

```ini
[Unit]
Description=QwenPaw assistant
After=network.target

[Service]
WorkingDirectory=/root/.qwenpaw
ExecStart=/root/.local/bin/qwenpaw app
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now qwenpaw
systemctl status qwenpaw
curl -sI http://127.0.0.1:8088
```

Ese último comando debería devolver HTTP 200. La consola solo enlaza localhost, así que adminístrala a través de un túnel con la [guía de túneles SSH en Linux](/es/tuneles-ssh-linux/): `ssh -L 8088:127.0.0.1:8088 root@YOUR_SERVER_IP`. Si la pones detrás de un proxy inverso, lee el aviso sobre autenticación de la consola en la pestaña de Docker de arriba.

### Desinstalación

```bash
qwenpaw uninstall          # keeps config and data
qwenpaw uninstall --purge  # removes everything
```

Misma semántica que antes, solo renombrado. En Docker, purge no elimina los volúmenes. Eso ya te toca a ti:

```bash
docker volume rm qwenpaw-data qwenpaw-secrets qwenpaw-backups
```

## Actualizar de CoPaw a QwenPaw

Si instalaste este asistente cuando se distribuía con el nombre antiguo, aquí tienes la migración en un solo lugar. El cambio de nombre llegó en la v1.1.0, el 2026-04-12 ([nota de versión](https://github.com/agentscope-ai/QwenPaw/releases/tag/v1.1.0)).

Lo que cambia para ti se reduce a cinco cosas. Instala `qwenpaw`; el antiguo paquete `copaw` está congelado en la 1.0.2 y no ha tenido actualizaciones desde el 2026-04-09, así que no recibirá las funciones de la 2.x. El comando ahora es `qwenpaw`, con `copaw` mantenido como alias apuntando al mismo entry point, así que la memoria muscular sigue funcionando. La imagen de Docker pasó de `agentscope/copaw` a `agentscope/qwenpaw`, y la disposición de datos pasó de un volumen a tres (`working`, `working.secret`, `working.backups`). Todo vive en `qwenpaw.agentscope.io`; el antiguo dominio `copaw.agentscope.io` está muerto, así que actualiza cualquier script o cron job que lo llame. Los datos locales viven ahora en `~/.qwenpaw/` (más `~/.qwenpaw.secret/`). Si tienes datos en `~/.copaw`, no asumas que se migran solos. Consulta la [documentación de QwenPaw](https://qwenpaw.agentscope.io/docs), copia el directorio tú mismo y confirma que la memoria y la configuración cargan antes de borrar nada. No he verificado una ruta de migración automática.

## Configuración de modelos

Antes de que QwenPaw pueda hacer algo útil, configura un LLM. Abre la Consola en `http://127.0.0.1:8088/` y ve a **Settings → Models**.

### Proveedores en la nube

QwenPaw funciona de serie con más de 14 proveedores en la nube: DashScope/Qwen, OpenAI, Anthropic, Google Gemini, DeepSeek, Kimi, OpenRouter y más. Para cualquiera de ellos:

1. Ve a **Settings → Models** en la Consola
2. Encuentra la tarjeta del proveedor y haz clic en **Settings**
3. Introduce tu clave de API y haz clic en **Save**
4. El estado de la tarjeta cambia a **Available**. Esa es tu comprobación
5. En la sección **LLM Configuration** de la parte superior, selecciona el proveedor y el modelo, y haz clic en **Save**

También puedes definir las claves de API como variables de entorno. Para DashScope:

```bash
export DASHSCOPE_API_KEY=your_key_here
```

O ponla en un archivo `.env` en el directorio de trabajo (`~/.qwenpaw/` para instalaciones nativas, `/app/working` en Docker). Las claves de herramientas (una clave de búsqueda web como `TAVILY_API_KEY`, por ejemplo) también se pueden definir en **Console → Settings → Environment variables**.

### Usar OpenAI o Azure OpenAI

Cualquier cosa con una API compatible con OpenAI funciona a través del sistema de proveedores personalizados:

1. Haz clic en **Add provider** en la página de Models
2. Introduce un Provider ID (por ejemplo `openai`) y un nombre para mostrar
3. Haz clic en **Settings**, introduce la Base URL (`https://api.openai.com/v1` para OpenAI) y la clave de API
4. Haz clic en **Models**, añade el ID del modelo al que tu cuenta tiene acceso
5. Selecciónalo en el desplegable de LLM Configuration

### Modelos locales: QwenPaw-Flash, Ollama y LM Studio

Los backends locales no necesitan claves de API. Los antiguos extras de pip por backend ya no existen; el soporte de modelos locales viene integrado.

|| Backend | Ideal para | Configuración |
|---|---|---|---|
|| **QwenPaw Local** (runtime llama.cpp integrado) | Multiplataforma, cero configuración | Haz clic en **Download** en la UI web; ofrece recomendaciones de modelos según el hardware |
|| **Ollama** | Quien ya tenga Ollama en marcha | Instala Ollama, descarga un modelo y pon la longitud de contexto en al menos 32k |
|| **LM Studio** | Usuarios de escritorio con LM Studio | Activa el Local Server; Base URL `http://localhost:1234/v1` (`http://host.docker.internal:1234/v1` desde Docker) |

<Notice type="warning" title="Longitud de contexto de Ollama">
Pon la longitud de contexto de Ollama en 32k o más para el modelo que conectes. Por debajo de eso obtienes respuestas truncadas y cortes raros a mitad de frase que parecen problemas de calidad del modelo pero no lo son.
</Notice>

Los modelos locales recomendados ahora son **QwenPaw-Flash**, modelos de agente entrenados expresamente en tamaños 2B / 4B / 9B / 35B-A3B / 27B con cuantizaciones Q4 y Q8, publicados en ModelScope y Hugging Face bajo la organización `agentscope-ai/models`. Las variantes de 2B y 4B corren en hardware modesto, la de 9B pide unos 16 GB de RAM, y la MoE 35B-A3B es la elección de calidad si tienes memoria. Para hardware que ejecuta bien estos modelos, ver [mejores mini PCs para LLM locales](/es/mejores-mini-pc-llm-local/). Si prefieres tener una máquina silenciosa en casa que alquilar un VPS, algo como el [mini PC ASUS DC510](https://go.bitdoze.com/asus-dc510) ejecuta los modelos pequeños con comodidad.

La v2.3.0 también añadió los modelos de decisión **Piccolo** (4B/9B/27B) para revisión opt-in del uso de herramientas y compactación de contexto. Está bien tenerlos, pero no son un bloqueo para la configuración.

Las descargas de modelos ocurren en la UI web: **Settings → Models**, luego **Download** en la tarjeta de QwenPaw Local. Para Ollama, descarga modelos a través de Ollama como siempre (`ollama pull qwen3:4b`) y QwenPaw se sincroniza con lo que haya disponible. Consulta la [configuración de Ollama con Docker Compose y Open WebUI](/es/ollama-docker-instalacion/) si ejecutas Ollama en un contenedor.

### Comparación de costes

No reproduzco cifras en dólares aquí. Los precios de los proveedores se mueven demasiado rápido para reimprimirlos con honestidad, y las cifras antiguas de esta guía envejecieron mal. Lo que sigue siendo cierto:

|| Vía | Ejemplo | Forma del coste |
|---|---|---|---|
|| DashScope | Modelos Qwen | Entrada en la nube más barata en la mayoría de cargas de trabajo |
|| OpenAI / Anthropic / Gemini | Modelos frontera | Más caro por token, mejor calidad bruta |
|| Local (QwenPaw-Flash) | QwenPaw-Flash 4B o 9B | Coste de API cero, solo electricidad y hardware |

Si tu asistente ejecuta un puñado de trabajos programados y chatea unas pocas veces al día, las facturas de la nube se quedan en el rango de dólares de un dígito al mes. Si procesa documentos todo el día, vete a local.

## Configuración de canales: Discord, Telegram, DingTalk y más

Los canales son la forma de hablar con QwenPaw desde tus apps de mensajería. Desde la v2.3.0 los canales son plugins: los extras de instalación `channels` y `full` ejecutan `qwenpaw plugins preset apply channels-full --offline`, y la Consola (**Control → Channels**) es donde los activas y configuras.

*Los nombres de las claves de configuración pueden cambiar entre versiones. Guarda primero el canal en la Consola y luego echa un vistazo a `config.json` en tu directorio de trabajo para ver la forma actual. Los fragmentos de abajo muestran la disposición de la 2.x, no un contrato.*

### Discord

1. Crea una aplicación de Discord en [discord.com/developers](https://discord.com/developers/applications)
2. Ve a la pestaña **Bot**, haz clic en **Reset Token** y copia el token del bot
3. En **Privileged Gateway Intents**, activa **Message Content Intent**
4. Genera una URL de invitación OAuth2 con el scope `bot` y los permisos `Send Messages` + `Read Message History`
5. Invita al bot a tu servidor
6. En la Consola de QwenPaw, ve a **Control → Channels**, haz clic en **Discord**, actívalo y pega el token

```json
{
  "channels": {
    "discord": {
      "enabled": true,
      "token": "YOUR_DISCORD_BOT_TOKEN"
    }
  }
}
```

Verificación: envía un mensaje directo al bot y espera respuesta. Si no hay respuesta y el log está en silencio, normalmente significa que Message Content Intent está desactivado.

### Telegram

1. Abre Telegram, busca **@BotFather**, envía `/newbot`
2. Elige un nombre y un nombre de usuario, copia el token
3. En la Consola, activa Telegram y pega el token

```json
{
  "channels": {
    "telegram": {
      "enabled": true,
      "token": "YOUR_TELEGRAM_BOT_TOKEN"
    }
  }
}
```

Verificación: envía un mensaje a tu bot y confirma que llega la primera respuesta.

### DingTalk

La configuración de DingTalk implica crear una app personalizada en la consola de desarrolladores de DingTalk. QwenPaw tiene una habilidad integrada llamada `dingtalk_channel_connect` que te guía por la búsqueda de credenciales, la configuración del Client ID/Secret y los pasos manuales. Activa el canal de DingTalk en la Consola y sigue las indicaciones guiadas.

### Feishu (Lark)

Misma idea que DingTalk. Crea una app en la Open Platform de Lark (Feishu), obtén el App ID y el App Secret, e introdúcelos en la Consola. QwenPaw también admite un proxy SOCKS para Lark si estás detrás de un firewall corporativo.

### WeChat y QQ

WeChat es una incorporación reciente a la lista de canales y QQ lleva ahí desde el principio. La configuración difiere según la región y la política de la plataforma, así que no voy a fingir que los pasos son estables. La [documentación de canales](https://qwenpaw.agentscope.io/docs/channels) tiene el flujo actual. Espera crear una app del lado de la plataforma y pegar credenciales en la Consola como en los demás canales.

### iMessage (solo macOS)

Si ejecutas QwenPaw en un Mac, iMessage funciona como canal. Sigue siendo uno de los pocos asistentes autoalojados que admiten iMessage de forma nativa.

### Varios canales a la vez

QwenPaw puede conectarse a varios canales simultáneamente. Los mensajes van al canal en el que hablaste por última vez, o puedes dirigir los mensajes programados a canales concretos.

## Habilidades y plugins

Las habilidades son la forma en que QwenPaw hace más que chatear. Varias vienen integradas, y desde la 2.x hay una arquitectura de plugins con marketplace e integración MCP. Esa extensibilidad es ahora la gran novedad.

### Habilidades integradas

Habilidades del núcleo a fecha de la v2.3.0:

|| Habilidad | Qué hace |
|---|---|---|
|| **cron** | Trabajos programados: crear, listar, pausar, reanudar, eliminar |
|| **file_reader** | Leer y resumir archivos de texto (.txt, .md, .json, .csv, .py, etc.) |
|| **pdf** | Leer, extraer, combinar, dividir, rotar, poner marca de agua y OCR en PDFs |
|| **docx** | Crear, leer y editar documentos Word |
|| **xlsx** | Leer, editar y crear hojas de cálculo |
|| **pptx** | Crear, leer y editar archivos PowerPoint |
|| **news** | Obtener y resumir las últimas noticias de fuentes configuradas |
|| **browser_visible** | Lanzar un navegador con interfaz para demos o escenarios con CAPTCHA |

De la v2.1.0 a la v2.3.0 se añadieron browser-use, computer-use y el Code Mode además de estas.

### Gestionar habilidades en la Consola

Ve a **Agent → Skills** en la Consola para ver todas las habilidades cargadas, activarlas o desactivarlas, crear habilidades personalizadas o editar las existentes.

### Importar habilidades desde hubs

El Plugin Market oficial (marketplace unificado desde la v2.2.0) es el primer lugar donde mirar. Hubs de la comunidad como `skills.sh`, `clawhub.ai` y `skillsmp.com` funcionaban con la 1.x, e importar desde cualquier repositorio de GitHub con un archivo `SKILL.md` es el mecanismo subyacente. Consulta la [documentación de skills](https://qwenpaw.agentscope.io/docs/skills) para ver qué admite oficialmente la versión actual.

<Notice type="warning" title="Las habilidades de terceros corren en tu máquina">
Una habilidad es código e instrucciones que se ejecutan con los permisos de tu agente. Ejecuta Tool Guard en modo STRICT mientras evalúas habilidades de terceros, y usa el Skill Scanner (ver [Seguridad](#seguridad-sandbox-tool-guard-y-file-guard) más abajo).
</Notice>

### Crear habilidades personalizadas

Coloca una carpeta con un archivo `SKILL.md` dentro de `~/.qwenpaw/customized_skills/` (la ruta sigue al directorio de trabajo, así que en Docker está bajo `/app/working`):

```
~/.qwenpaw/
  customized_skills/
    my_research_skill/
      SKILL.md
```

El `SKILL.md` es Markdown plano que describe lo que hace la habilidad:

```markdown
---
name: my_research_skill
description: Research a topic and summarize findings
---

# Research Skill

When asked to research something:
1. Search the web for current information
2. Summarize key findings in bullet points
3. List sources
```

QwenPaw recoge las nuevas habilidades al reiniciar. Las habilidades personalizadas tienen prioridad sobre las integradas cuando los nombres coinciden. Para un ejemplo real de cómo se ve una habilidad personalizada en la práctica, consulta mi [guía del skill de despliegue en Docker con IA](/es/skill-despliegue-docker-ia/).

### Plugins, el marketplace y MCP

Desde la v2.3.0, los propios canales son plugins, y **Settings → Plugins** es el centro de todo: instala desde el Plugin Market, gestiona presets y conecta **servidores MCP** como proveedores de herramientas. Si usas herramientas MCP en otra parte de tu stack, así las reutilizas dentro de tu asistente.

Dos plugins importan si ejecutas agentes de código: los backends **Codex** y **Qoder** son instalaciones opcionales vía **Settings → Plugins** (el extra de instalación `full` excluye sus SDK, así que instálalos explícitamente). Hay [notas de migración para los backends opcionales Codex y Qoder](https://qwenpaw.agentscope.io/docs/plugins#optional-codex-and-qoder-backends) en la documentación. Si la instalación de un plugin se interrumpe, consulta [Solución de problemas](#instalación-interrumpida-de-plugins-o-habilidades) más abajo antes de reejecutar a ciegas.

## Sistema de memoria

La memoria de QwenPaw es la parte que hace que parezca un asistente en lugar de un chatbot. Desde la v2.0.0 funciona en tres capas:

1. El **contexto de trabajo en vivo** es la conversación actual y lo que el agente está haciendo ahora mismo.
2. El **historial completo literal** es un `history.db` en SQLite con búsqueda de texto completo FTS5, retención por defecto de 30 días y ranking consciente del uso (recencia más frecuencia). Los turnos antiguos se pueden recuperar a través del REPL `recall_history_python`. La v2.2.1 añadió Auto Fin, una pasada proactiva de revisión de la memoria; la v2.3.0 añadió memoria de imágenes y navegación por etiquetas.
3. La **base de conocimiento autoevolutiva** está respaldada por [ReMe](https://github.com/agentscope-ai/ReMe) v0.4.0. Escribe la memoria sobre la marcha (por turnos, no al cerrar la sesión) y la guarda como Markdown que puedes leer y editar a mano.

Esa última capa es la que conviene conocer. Tiene este aspecto:

```
~/.qwenpaw/
  MEMORY.md                    # Long-term facts, preferences, decisions
  memory/
    2026-11-15.md              # Daily log
    2026-11-14.md
    ...
```

`MEMORY.md` guarda información persistente: cosas como "Prefiero Python 3.12" o "Mi equipo usa Slack para los standups". Los registros diarios capturan lo que ocurrió en cada conversación. La búsqueda en todo ello es híbrida: búsqueda semántica vectorial más texto completo, y desde la v2.0.0 el modelo de embedding se selecciona en la UI de configuración en lugar de una pila de variables de entorno.

Dile qué recordar directamente:

> "Recuerda: siempre despliego en staging antes de producción."

Esto lo escribe en `MEMORY.md`. Puedes editar los archivos tú mismo cuando el agente se equivoque:

```bash
nano ~/.qwenpaw/MEMORY.md
```

## Tareas programadas y heartbeat

QwenPaw ejecuta cosas en horarios de dos formas: trabajos cron para comandos concretos y heartbeat para check-ins periódicos.

### Trabajos cron

```bash
# Create a job that runs at 9am every day
qwenpaw cron create --type agent --name "morning-digest" --cron "0 9 * * *" --message "Summarize my pending tasks and calendar for today"

# List all jobs
qwenpaw cron list

# Check a job's state
qwenpaw cron state <job_id>
```

También puedes gestionar los trabajos cron desde la Consola en **Control → Cron Jobs**. Consulta `qwenpaw cron --help` para la lista completa de flags de tu versión. Verificación: `qwenpaw cron list` muestra el trabajo tras crearlo.

### Heartbeat

Heartbeat es el check-in programado. Escribes un bloque de preguntas en un archivo Markdown, y QwenPaw las recorre con un temporizador y envía las respuestas a tu último canal usado. Configúralo durante `qwenpaw init` o edita `HEARTBEAT.md` en el directorio de trabajo.

Ejemplo de `HEARTBEAT.md`:

```markdown
Check the following and report back:
- Any new emails from clients?
- What meetings do I have today?
- Summarize overnight GitHub notifications
```

El intervalo y las horas activas viven en los ajustes de la Consola, o en `config.json` (los nombres de las claves han cambiado entre versiones, así que confirma la forma en tu propio archivo tras definirlo en la UI):

```json
{
  "heartbeat": {
    "enabled": true,
    "interval": "2h",
    "active_hours": "08:00-22:00"
  }
}
```

Verificación: espera a que el primer heartbeat aterrice en tu canal. Si no llega nada, comprueba que haya un canal de destino configurado y que las horas activas cubran la hora actual.

## Seguridad: sandbox, Tool Guard y File Guard

Un agente que ejecuta herramientas en tu máquina es ante todo una cuestión de radio de explosión. QwenPaw trae un stack de seguridad de cinco capas. Es el argumento más fuerte para elegirlo frente a las alternativas si piensas ejecutar habilidades de terceros:

|| Capa | Qué hace |
|---|---|---|
|| **Sandbox** | Aislamiento a nivel de kernel para la ejecución de herramientas: Seatbelt en macOS, Bubblewrap + Landlock en Linux, AppContainer en Windows |
|| **Tool Guard** | Reglas YAML con niveles de aprobación: STRICT / SMART / AUTO / OFF |
|| **File Guard** | Protege por defecto `~/.qwenpaw.secret/` y `~/.ssh` del acceso de habilidades y plugins |
|| **Skill Scanner** | Inspecciona las habilidades antes de ejecutarlas: block / warn / off |
|| **Access Policy** | Restringe a qué puede acceder el agente en absoluto |

Valores por defecto prácticos que yo usaría: ejecuta Tool Guard en STRICT mientras evalúes cualquier habilidad que no hayas escrito, guarda las claves de API en el directorio de secretos protegido (la disposición de Docker separa `working.secret` en su propio volumen exactamente por esta razón), y deja el Skill Scanner en block. Para el modelo de amenazas más amplio de las habilidades no confiables en agentes autoalojados, mi [guía de seguridad de OpenClaw](/es/guia-seguridad-openclaw/) cubre el mismo enfoque de radio de explosión desde el ángulo del otro proyecto.

## Copias de seguridad, actualizaciones y operaciones del día 2

<Notice type="info" title="Haz copia de tres cosas">
La configuración, la memoria y las habilidades viven en <code>working</code>. Las claves de API y los ajustes de proveedores viven en <code>working.secret</code>. Los archivos de copias de seguridad viven en <code>working.backups</code>. Esas tres son las que importan.
</Notice>

En Docker, empaqueta los tres volúmenes en un solo tar:

```bash
docker run --rm \
  -v qwenpaw-data:/data \
  -v qwenpaw-secrets:/secrets \
  -v qwenpaw-backups:/backups \
  -v "$PWD":/backup alpine \
  tar czf /backup/qwenpaw-$(date +%F).tar.gz data secrets backups
```

De forma nativa:

```bash
tar czf qwenpaw-$(date +%F).tar.gz ~/.qwenpaw ~/.qwenpaw.secret
```

La [documentación de copias de seguridad](https://qwenpaw.agentscope.io/docs/backup) oficial cubre la restauración. Programa el tar con cron y súbelo a S3 o a cualquier destino externo en el que ya confíes.

Actualizaciones: `pip install -U qwenpaw` para instalaciones con pip, reejecuta el instalador para la vía del script (gestiona las actualizaciones de plugins), o vuelve a descargar la imagen para Docker. Fija `agentscope/qwenpaw:v2.3.0` en compose si quieres revisar las notas de versión antes de moverte. `latest` cambia semanalmente y este proyecto pasó de la 2.0.0 a la 2.3.0 en cuatro meses con betas semanales de por medio. Lee las [notas de versión](https://github.com/agentscope-ai/QwenPaw/releases) antes de saltar una versión menor.

Una divulgación para la gente de operaciones: `qwenpaw init --defaults` acepta automáticamente la telemetría de uso anónima (una vez por versión, sin datos personales). El `init` interactivo pregunta primero. Detalles en las preguntas frecuentes.

## ¿Qué debes saber sobre solución de problemas?

### La consola no carga / QwenPaw no responde

Si `http://127.0.0.1:8088/` no carga:

1. ¿Está el proceso en ejecución? (`systemctl status qwenpaw` o `docker ps`)
2. ¿Está el puerto ocupado? `ss -ltnp | grep 8088`. Un proceso residual o una ejecución con `--network=host` puede estar acaparándolo
3. Revisa la salida de la terminal o `docker logs qwenpaw` en busca de errores de arranque
4. Si la consola carga pero nada funciona, ve a **Settings → Models** y verifica que un proveedor esté **Available** con un modelo seleccionado

### Problemas con la clave de API

Si ves errores de autenticación:

- Revisa bien la clave de API en **Settings → Models**
- Para DashScope, verifica la clave en [dashscope.console.aliyun.com](https://dashscope.console.aliyun.com/)
- Prueba a definir la clave como variable de entorno: `export DASHSCOPE_API_KEY=xxx`
- Recuerda que las variables de entorno de Docker solo aplican cuando se definen en `docker run` o en compose

### Docker no alcanza Ollama

Dentro de un contenedor, `localhost` apunta al contenedor, no al host. Usa `--add-host=host.docker.internal:host-gateway` y pon la Base URL de Ollama en `http://host.docker.internal:11434/v1`.

En Linux también puedes usar `--network=host`:

```bash
docker run --network=host \
  -v qwenpaw-data:/app/working \
  -v qwenpaw-secrets:/app/working.secret \
  agentscope/qwenpaw:latest
```

Y pon la longitud de contexto de Ollama en al menos 32k, o te toparás con el problema de truncado de abajo.

### El canal no recibe mensajes

- Verifica que el canal esté activado en **Control → Channels**
- Comprueba que los tokens y las credenciales sean correctos
- Para Discord, asegúrate de que **Message Content Intent** esté activado en el portal de desarrolladores
- Reinicia QwenPaw tras cambiar la configuración de canales

### Respuestas truncadas o raras de los modelos locales

Si las respuestas del modelo local se cortan a mitad de frase o pierden el hilo de una petición larga, la causa habitual es una longitud de contexto de Ollama o LM Studio por debajo de 32k. Revisa los ajustes de contexto del modelo en el lado que lo sirve, no en QwenPaw.

### Particularidades de Windows

En ediciones LTSC o con Constrained Language Mode, puede que el instalador no actualice el PATH. Añade `%USERPROFILE%\.qwenpaw\bin` y el directorio de uv a mano. El primer arranque de la app de escritorio tarda de 10 a 60 segundos. Es normal, no un cuelgue.

### Instalación interrumpida de plugins o habilidades

Si la instalación de un plugin o habilidad muere a mitad, reejecuta el instalador (ejecuta `qwenpaw plugins prepare-upgrade` al actualizar) o reaplica el preset a mano:

```bash
qwenpaw plugins preset apply channels-full --offline
```

Luego reinicia y comprueba **Settings → Plugins** en busca de las entradas esperadas.

## Preguntas frecuentes

<Accordion label="Preguntas frecuentes" group="faq" expanded="true">

**¿Qué pasó con CoPaw?**

El proyecto se renombró a QwenPaw en la v1.1.0, el 2026-04-12. Mismo equipo (AgentScope, Alibaba), mismo código, nombre nuevo. El paquete de pip ahora es `qwenpaw` (el antiguo está congelado en la 1.0.2), la imagen de Docker es `agentscope/qwenpaw`, y el comando `copaw` sigue funcionando como alias de la CLI. Los enlaces antiguos de GitHub redirigen. La URL de esta guía mantuvo el slug original, por eso sigue apareciendo `copaw` en ella.

**¿Necesito saber Python?**

No. El instalador de una línea, Docker y la app de escritorio no necesitan Python. Solo la vía `pip install qwenpaw` lo requiere, y pide Python 3.11 a 3.13. Saber Python solo importa si escribes habilidades personalizadas o instalas desde el código fuente.

**¿Con qué proveedor en la nube debería empezar?**

DashScope es el predeterminado y suele ser la entrada más barata. Si ya tienes una clave de OpenAI, Anthropic o Gemini, añádela y listo. Para coste de API cero, usa QwenPaw Local u Ollama con un modelo local.

**¿Puedo ejecutarlo en una Raspberry Pi?**

Bien como relevo hacia modelos en la nube en una Pi 4 o 5 con 4 GB de RAM. Débil para modelos locales; incluso QwenPaw-Flash 4B irá lento. Un VPS barato o un mini PC de segunda mano es mejor experiencia.

**¿Funciona en Windows?**

Sí. Usa el instalador de PowerShell (`irm https://qwenpaw.agentscope.io/install.ps1 | iex`), Docker o la [app de escritorio en Beta](https://github.com/agentscope-ai/QwenPaw/releases) (Windows 10+, sin Python necesario). La vía pip también funciona si tienes Python 3.11+. En LTSC, consulta la nota de particularidades de Windows en Solución de problemas.

**¿Pueden varias personas usar una instancia?**

Dos opciones. QwenPaw responde en el canal donde hablaste por última vez, así que los canales de grupo en DingTalk, Lark o Discord valen para uso compartido. Para un aislamiento multiusuario en regla, la v2.2.0 añadió QwenPaw Hub, un modo multiusuario autoalojado.

**¿Mis datos son privados?**

Tu configuración, memoria, conversaciones y archivos se quedan en tu máquina, y las únicas llamadas externas son al proveedor de LLM que configuraste. Con modelos locales, nada sale del equipo en absoluto. Una salvedad honesta: `qwenpaw init` envía datos anónimos de uso una vez por versión (versión, método de instalación, SO, versión de Python, arquitectura, GPU sí/no; sin datos personales, sin IP, sin archivos). `init --defaults` lo autoacepta; el `init` interactivo te pregunta. Consulta la documentación para el opt-out si la pregunta te importa.

**¿Cómo se compara con OpenClaw?**

OpenClaw tiene un soporte más amplio de mensajería occidental (WhatsApp, Slack). QwenPaw tiene soporte de primera clase de DingTalk, Lark y WeChat, una consola web integrada, tres backends de modelos locales y un stack de seguridad real. Ambos son open source y autoalojados. Consulta mi [guía de configuración de OpenClaw](/es/guia-configuracion-openclaw/) para el otro lado.
