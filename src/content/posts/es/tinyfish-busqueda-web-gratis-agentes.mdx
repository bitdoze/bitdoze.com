La solución es acceso web en vivo: búsqueda y fetch de páginas reales, en tiempo real.

TinyFish hizo gratis Search y Fetch. Sin tarjeta, sin periodo de prueba. Hay cupos (los diarios se explican abajo), pero son suficientes para un agente de codificación.

## Lo que TinyFish te da gratis

Dos endpoints, ambos gratis:

**TinySearch** toma una consulta y devuelve resultados JSON estructurados. No enlaces azules diseñados para ojos humanos, sino datos limpios y estables en ranking que tu agente puede parsear directamente. La latencia típica es de 1 a 3 segundos. Puedes pasar pistas de ubicación e idioma para resultados geolocalizados.

**TinyFetch** toma una o más URLs y devuelve contenido limpio. La página se renderiza en un navegador Chromium real (JavaScript, SPAs, todo), y luego se eliminan barras de navegación, banners de cookies, anuncios y scripts. Recibes markdown, HTML o JSON. Tu modelo deja de pagar tokens por HTML basura.

### Límites del nivel gratuito

Los productos ahora llevan el prefijo Tiny: TinySearch y TinyFetch (antes Search y Fetch), TinyAgent (antes Agent), TinyBrowser (antes Browser).

| Producto | Límite | Coste |
|----------|--------|-------|
| **TinySearch** | 30 peticiones/min, 500/hora, 12.000/día | Gratis |
| **TinyFetch** | 150 URLs/min, 1.000 URLs/día, máx. 10 URLs por petición | Gratis |
| **TinyAgent** | 2 ejecuciones concurrentes | $0.016/paso |
| **TinyBrowser** | 5 sesiones concurrentes | $0.002/min |
| **TinyMonitor** | 50 monitores/cuenta | $0.005/comprobación + la llamada Search o Fetch subyacente |
| **TinyResearch** | Hasta 5 ejecuciones concurrentes | $2 por ejecución `deep`, $3 por `max` |
| **TinySet** | 1 a 250 filas por dataset | $0.10/fila |

La cifra de 500/hora sale de la página de precios y la de 12.000/día de los docs, así que si lanzas ráfagas, el número por hora es el más ajustado.

Para uso con agentes de codificación, Search y Fetch cubren la mayor parte de lo que necesitas. TinyAgent y TinyBrowser se cobran de un Wallet prepago (sin planes ni mínimos). Las cuentas nuevas empiezan con $8 en fondos de Wallet sin tarjeta, pero la mayoría de flujos de codificación ni los tocan. Las llamadas Search/Fetch subyacentes de TinyMonitor cuentan para tu cupo diario gratuito, así que un puñado de comprobaciones programadas te cuesta la tarifa de $0.005 por comprobación y nada más.

<Notice type="warning" title="Fetch tiene un tope diario: 1.000 URLs">
TinyFetch es gratis hasta 1.000 URLs obtenidas con éxito por día (TinySearch: 12.000 peticiones por día). Ambos se reinician a las 00:00 UTC. Las URLs fallidas no cuentan. Con el gasto desactivado recibes HTTP 429 `RATE_LIMIT_EXCEEDED` con `details.reason = "free_allowance_exhausted"`. Los docs que leí no publican una tarifa por URL más allá del cupo, así que mira el dashboard o pregunta a ventas antes de construir sobre eso.
</Notice>

## Por qué tu agente de codificación necesita acceso web

La mayoría de agentes de codificación dependen de los datos de entrenamiento del modelo para cualquier cosa fuera de tu codebase. Eso funciona para patrones estables y APIs bien documentadas. Se rompe con versiones recientes, peculiaridades específicas de versiones, soluciones de la comunidad en GitHub y documentación actual.

Darle a tu agente un pipeline de búsqueda+fetch cambia la respuesta de "creo que funciona así" a "aquí está la documentación actual".

### Ahorro de tokens

TinyFish Fetch elimina navegación, scripts y boilerplate de las páginas antes de devolver el contenido. Tu modelo procesa el contenido real del artículo, no tres kilobytes de banners de consentimiento de cookies y enlaces de pie de página. Esto recorta el uso de tokens por fetch comparado con fetch de HTML crudo.

### Opción 2: CLI + Skill

La CLI es la opción más portable. Funciona con cualquier agente que pueda ejecutar comandos de shell, y el skill le enseña a tu agente cuándo usar búsqueda vs fetch.

**Instala la CLI:**

```bash
npm install -g @tiny-fish/cli@latest
```

**Autentícate:**

```bash
tinyfish auth login
```

Esto abre la página de claves API en tu navegador. Pega tu clave cuando te la pida. La clave se guarda en `~/.tinyfish/config.json`.

Para CI/CD o montajes no interactivos:

```bash
echo $TINYFISH_API_KEY | tinyfish auth set
```

**Verifica que funciona:**

```bash
tinyfish --version
tinyfish auth status --pretty
```

**Instala el skill** (enseña a tu agente la jerarquía de herramientas):

```bash
npx skills add github.com/tinyfish-io/tinyfish-cookbook --skill use-tinyfish
```

El skill cubre la escalera de escalada: search para encontrar URLs, fetch para leer páginas, agent para tareas interactivas de navegador, y browser para control CDP en bruto. El mismo formato `SKILL.md` alimenta skills de calidad de diseño, mira mi comparativa de [mejores skills de IA para diseño web](/es/mejores-skills-ia-diseno-web/).

**Pruébalo:**

```bash
# Search
tinyfish search query "best Docker monitoring tools 2026" --pretty

# Fetch
tinyfish fetch content get --format markdown "https://docs.docker.com"
```

La CLI lee `TINYFISH_API_KEY` del entorno. Pon `TINYFISH_NO_TELEMETRY` para desactivar la analítica.

### Opción 3: API REST

Para integraciones personalizadas o agentes que no soportan MCP:

```bash
# Search
curl "https://api.search.tinyfish.ai?query=docker+compose+healthcheck" \
  -H "X-API-Key: $TINYFISH_API_KEY"

# Fetch
curl -X POST https://api.fetch.tinyfish.ai \
  -H "X-API-Key: $TINYFISH_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"urls": ["https://docs.docker.com/compose/how-tos/startup-order/"]}'
```

Ambos endpoints devuelven JSON. Search te da resultados rankeados con títulos, snippets y URLs. Fetch te da el contenido limpio de la página más metadatos (título, idioma, autor, fecha de publicación).

## Ejemplos prácticos

El acceso web gratuito le da a tu agente estas tareas:

### Consultar documentación actual

```bash
tinyfish fetch content get --format markdown "https://docs.docker.com/compose/how-tos/startup-order/"
```

Tu agente lee los docs reales en vez de adivinar desde los datos de entrenamiento.

### Buscar soluciones a errores

```bash
tinyfish search query "TypeError: Cannot read property of undefined React 19" --pretty
```

Encuentra issues de GitHub, respuestas de Stack Overflow y posts de blog sobre el error exacto.

### Comprobar versiones de librerías y changelogs

```bash
tinyfish search query "Next.js 15 breaking changes" --pretty
tinyfish fetch content get --format markdown "https://nextjs.org/blog/next-15"
```

Verifica qué cambió antes de que tu agente sugiera código que funciona con la API vieja.

### Investigar buenas prácticas

```bash
tinyfish search query "Docker healthcheck best practices 2026" --pretty
```

Obtén recomendaciones actuales en vez de patrones desactualizados de 2023.

### Fetch de una sola sección de una página (solo REST)

La CLI no tiene flag de selectores, así que usa curl si quieres solo una parte de la página:

```bash
curl -X POST https://api.fetch.tinyfish.ai \
  -H "X-API-Key: $TINYFISH_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "urls": ["https://docs.docker.com/compose/how-tos/startup-order/"],
    "format": "markdown",
    "include_selectors": ["main"],
    "exclude_selectors": ["nav", "footer"]
  }'
```

Menos salida significa menos tokens en tu modelo y la misma URL contra tu cupo diario.

## ¿Cómo me mantengo bajo el tope gratuito de fetch?

Busca primero, haz fetch solo de las 2 o 3 mejores URLs y agrúpalas. 1.000 URLs al día se gastan rápido si un agente hace fetch de cada resultado de búsqueda. Hábitos que lo mantienen bajo:

- **Busca primero y haz fetch solo de las 2 o 3 mejores URLs.** Los snippets de búsqueda suelen responder la pregunta por sí solos.
- **Agrupa hasta 10 URLs por petición** en vez de una llamada por URL. El conteo contra el cupo es el mismo, pero ahorras idas y vueltas y presión por minuto.
- **Recorta la página** con `include_selectors` y `exclude_selectors` (de 1 a 20 selectores CSS cada uno, exclude se aplica primero).
- **Conoce la caché.** Si omites `ttl`, se acepta cualquier entrada en caché. `ttl: 0` fuerza un fetch en vivo, y `ttl: 3600` acepta una entrada de menos de una hora. Usa `ttl: 0` solo cuando importe la frescura.
- **Fetch condicional** para una sola URL: envía `if_none_match` con el etag de una respuesta anterior (activa `include_etag_and_last_modified`), o `if_modified_since`.
- **Pon `per_url_timeout_ms`** (1 a 110000) para que las páginas lentas fallen rápido. Las URLs fallidas no cuentan. Mantén el timeout del cliente en 150 segundos o más para no cortar una petición que sigue en marcha.
- **Revisa tu uso:**

```bash
tinyfish fetch usage --status completed --start-after 2026-11-27T00:00:00Z --limit 1000 --pretty
tinyfish search usage
```

El equivalente REST es `GET https://api.fetch.tinyfish.ai/usage`.

### Filtros de búsqueda que conviene conocer

TinySearch acepta `recency_minutes` (1 a 5256000), `domain_type` (`web`, `news` o `research_paper`), `include_domains` y `exclude_domains` (una cadena separada por comas, no un array), y `purpose` (por qué buscas, hasta 2000 caracteres, mejora los resultados). `recency_minutes` no se puede combinar con `after_date`/`before_date`. El operador `site:` sigue funcionando pero está deprecado para filtrar dominios.

```bash
curl "https://api.search.tinyfish.ai?query=next.js+breaking+changes&recency_minutes=10080&domain_type=news&include_domains=nextjs.org,vercel.com&purpose=check+what+changed+this+week" \
  -H "X-API-Key: $TINYFISH_API_KEY"
```

### Opciones de Fetch

Además de `format`, `links` e `image_links`, TinyFetch tiene una opción `highlights` (`query`, `max_passages` de 1 a 20, `include_full_page_text`) que devuelve pasajes literales ordenados que responden una pregunta. Está en beta, solo markdown y se activa por cuenta: sin acceso recibes HTTP 403 `FORBIDDEN`.

## La escalera de escalada de herramientas

El skill de TinyFish le enseña a tu agente a elegir la herramienta adecuada para el trabajo:

| Herramienta | Cuándo usarla | Velocidad | Coste |
|-------------|---------------|-----------|-------|
| **TinySearch** | Encontrar URLs, hechos actuales, docs, precios | La más rápida | Gratis (12.000/día) |
| **TinyFetch** | Leer URLs conocidas, obtener contenido limpio | Rápida | Gratis (1.000 URLs/día) |
| **TinyResearch** | Informes con citas sintetizados de múltiples fuentes | Minutos | $2 por ejecución (`deep`), $3 (`max`) |
| **TinyMonitor** | Recomprobar una página o tema en un calendario | Programada | $0.005/comprobación |
| **TinyAgent** | Interactuar con páginas, clicar, rellenar formularios | Más lenta | $0.016/paso |
| **TinyBrowser** | Control CDP en bruto para automatización compleja | La más lenta | $0.002/min |

Empieza con la herramienta más ligera que pueda responder la pregunta. Escala solo cuando haga falta.

### TinyMonitor: comprobaciones programadas de páginas y temas

TinyMonitor se asienta sobre Search y Fetch. Apúntalo a una URL (un monitor de página, con fetch `ttl: 0`) y vuelve a hacer fetch en tu calendario, compara el contenido y marca lo que cambió. Apúntalo a una consulta de búsqueda (un monitor de tema) y vigila nuevos resultados. Puedes describir el cambio que importa, como "el precio baja de $500", y TinyFish lo evalúa.

- Coste: $0.005 por comprobación completada más la llamada Search o Fetch subyacente, que cuenta para el cupo diario gratuito. Las comprobaciones fallidas son gratis. Un monitor diario cuesta unos $0.15/mes, uno cada hora unos $3.65/mes.
- Límites: 50 monitores por cuenta. Los monitores de tema corren como máximo cada 30 minutos y devuelven de 1 a 10 resultados por ejecución.
- Entrega: dashboard, webhook (cada ejecución programada, con 3 reintentos) o email (solo si hay cambio, salvo que actives "Email every run").

### TinyResearch: informes con citas bajo demanda

TinyResearch devuelve un informe respaldado por fuentes con citas, no una lista de enlaces. Haz `POST` de una pregunta a `https://agent.tinyfish.ai/v1/automation/run-research` y devuelve el progreso en streaming por SSE. También existe `run-research-async`, y `GET /v1/research-run/{id}` para consultar el estado.

- Coste: $2.00 por ejecución en modo `deep`, $3.00 en modo `max`, cobrado al completarse. Las ejecuciones fallidas, canceladas o con timeout son gratis.
- Tiempo: `deep` suele tardar de 5 a 20 minutos, `max` de 5 a 45 minutos (presupuesto máximo de 45 minutos). Hasta 5 ejecuciones concurrentes.
- Los seguimientos usan `prior_run_id` o `session_id`, y cada seguimiento es una ejecución de pago nueva.
- Debe estar activado en tu cuenta, si no recibes HTTP 403.
- CLI: `tinyfish research run`. Python: `client.research.run(query=..., mode="deep")`.

Responde el tipo de pregunta que de otro modo le costaría a tu agente una docena de idas y vueltas de search+fetch. Tengo más detalles en mi [review de TinyFish](/es/tinyfish-busqueda-web-agentes-ia/).

### TinySet y TinyAnswer

**TinySet** construye un dataset de filas sacadas de la web: `tinyfish dataset create "Specialty coffee shops in Oakland with their website and rating" --rows 25 --pretty`. Cuesta $0.10 por fila, admite de 1 a 250 filas y una ejecución tarda unos 5 a 20 minutos. Úsalo cuando conoces las columnas y quieres muchas filas, y TinyResearch cuando quieres un informe con citas.

**TinyAnswer** devuelve una sola respuesta con citas desde `POST https://api.answer.tinyfish.ai/` con `{"question": "..."}`. Debe activarse por cuenta y solo funciona con una clave API personal.

## Comparación con alternativas

| Característica | TinyFish Fetch | Firecrawl | Fetch nativo del LLM | Playwright artesanal |
|----------------|----------------|-----------|----------------------|----------------------|
| **Renderizado JavaScript** | Sí (Chromium real) | Sí | No (solo HTML estático) | Sí |
| **Extracción de contenido limpio** | Sí | Sí | HTML crudo | Manual |
| **Stealth/anti-bot** | Integrado | Varía | No | Configuración manual |
| **Nivel gratuito** | Sí (Search + Fetch) | Gratis limitado | Depende del proveedor | Pagas el cómputo |
| **Optimización de tokens** | Elimina boilerplate | Elimina boilerplate | HTML completo | Manual |
| **Agrupación multi-URL** | Hasta 10 URLs/llamada | Varía | No | Manual |

La principal ventaja de TinyFish sobre hacer Playwright a mano es que no gestionas instancias de navegador, rotación de proxies ni detección anti-bot. La principal ventaja sobre el fetch nativo del LLM es el renderizado JavaScript. La mayoría de sitios de docs modernos son SPAs que devuelven cascarones vacíos sin él.

<Accordion label="¿Cómo se compara TinyFish con Brave Search API?" group="alternatives">
Brave Search API ofrece un nivel gratuito (2.000 consultas/mes) pero devuelve resultados de búsqueda tradicionales sin fetch de páginas. Obtienes títulos, URLs y snippets, pero no el contenido completo de la página. TinyFish te da tanto búsqueda como fetch limpio de páginas gratis. Sus 30 búsquedas/min son una tasa, no una cuota mensual: el techo real es el cupo de 12.000 búsquedas/día (y 1.000 URLs obtenidas/día), unas 360.000 búsquedas en un mes de 30 días si lo usaras entero.
</Accordion>

<Accordion label="¿Puedo usar TinyFish con mi propia clave API de OpenCode Go?" group="alternatives">
TinyFish es un servicio independiente de OpenCode Go. Necesitas una clave API de TinyFish desde [agent.tinyfish.ai](https://go.bitdoze.com/tinyfish). La buena noticia es que es gratis, así que puedes usar tanto OpenCode Go para tus modelos LLM como TinyFish para acceso web sin ningún conflicto.
</Accordion>

<Accordion label="¿Qué pasa si alcanzo los límites de tasa?" group="alternatives">
Los límites por minuto (Search 30 peticiones, Fetch 150 URLs) devuelven HTTP 429 hasta que se reinicia la ventana. Los cupos diarios (Search 12.000 peticiones, Fetch 1.000 URLs obtenidas con éxito) se reinician a las 00:00 UTC. Pasado un cupo diario recibes HTTP 402 `INSUFFICIENT_CREDITS` si el gasto del Wallet está activado y tu Wallet está vacío, o HTTP 429 `RATE_LIMIT_EXCEEDED` (`details.reason = "free_allowance_exhausted"`) si el gasto está desactivado. Límites más altos son un extra Enterprise, y TinyFish for Startups recibe 4x los límites de tasa por defecto. Detalles en [tinyfish.ai/pricing](https://tinyfish.ai/pricing).
</Accordion>

<Accordion label="¿TinyFish sigue siendo gratis?" group="alternatives">
Sí, dentro de los cupos: Search es gratis hasta 30 peticiones/min, 500/hora y 12.000/día, y Fetch es gratis hasta 150 URLs/min y 1.000 URLs obtenidas con éxito/día. Ambos siguen funcionando con saldo $0 en el Wallet. TinyAgent, TinyBrowser, TinyMonitor, TinyResearch y TinySet se pagan del Wallet, y las cuentas nuevas empiezan con $8.
</Accordion>

## Qué me gusta y qué no

Llevo semanas usando TinyFish a través de Pi y Mastra. Esta es la opinión honesta.

**Lo que funciona bien:** Los resultados de búsqueda son limpios y rápidos. Fetch renderiza las SPAs correctamente, lo que importa para sitios de docs basados en React. El nivel gratuito cubre el uso diario con agentes de codificación, siempre que tu agente no haga fetch de más de 1.000 URLs al día. El contenido limpio gasta menos tokens por fetch que el HTML crudo.

**Lo que podría mejorar:** El tope diario de fetch es real, y un agente que hace fetch de cada resultado de búsqueda puede alcanzarlo. Fetch puede ser lento en páginas pesadas (5-10 segundos en sitios con mucho JavaScript). Search devuelve ocasionalmente resultados desactualizados para eventos muy recientes. Y TinyAgent y TinyBrowser se acumulan si necesitas automatización interactiva.

**En resumen:** Para darle a tu agente de codificación acceso web, el nivel gratuito Search + Fetch funciona bien. Lo tengo cableado en Pi a través de pi-tinyfish y en Mastra a través del SDK. Se ha convertido en una parte estándar de mi configuración de agentes.
