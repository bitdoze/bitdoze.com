WordPress es dinámico: cada petición de página dispara la ejecución de PHP y una consulta a la base de datos. Con tráfico normal no hay problema. Bajo carga se convierte en un cuello de botella muy rápido. Varnish Cache se sitúa delante de Nginx y sirve HTML prerenderizado directamente desde la memoria, saltándose PHP y MySQL por completo en la mayoría de las peticiones.

CloudPanel incluye soporte integrado para Varnish, así que la configuración es mucho más sencilla que hacerlo manualmente.

CloudPanel usa una configuración de proxy inverso. Varnish escucha en el puerto público y Nginx corre detrás en el puerto **6081**. Cuando llega una petición:

1. Varnish comprueba si tiene una copia en caché en memoria
2. Si la tiene, sirve el HTML cacheado directamente — sin PHP, sin base de datos
3. Si no, la petición pasa a Nginx, PHP la procesa y Varnish guarda el resultado

Los recursos estáticos (imágenes, CSS, JS) los sirve Nginx directamente y evitan Varnish — ya son rápidos de por sí.

## Cómo activar Varnish en CloudPanel

Ve a tu sitio en CloudPanel → **Varnish Cache** → actívalo.

<Picture formats={["webp"]} fallbackFormat="webp" src={imgVarnish} alt="Panel de configuración de Varnish Cache en CloudPanel" />

En el campo de exclusiones, añade las rutas que nunca deben cachearse — carrito, pago, páginas de cuenta y todo lo que sea específico del usuario:

```
/wp-admin/
/cart/
/checkout/
/my-account/
/wp-login.php
```

## Detalles de configuración

**Asignación de memoria:** Varnish usa 512 MB por defecto. Para aumentarla, edita:

```
/lib/systemd/system/varnish.service
```

Busca el parámetro `-s malloc` y cambia el valor.

**Controlador PHP** (excluye páginas concretas de la caché):
```
/home/<siteUser>/.varnish-cache/controller.php
```

**Registros:**
```
/home/<siteUser>/logs/varnish-cache/
```

## Duración de la caché

CloudPanel usa por defecto una duración de caché de 7 días. Puedes cambiarla en el panel de configuración de Varnish Cache. Para sitios que se actualizan con frecuencia (noticias, publicaciones diarias), bájala a 1-2 días. Para sitios mayormente estáticos, 7-14 días está bien. La caché se purga automáticamente cuando usas el plugin de WordPress que verás a continuación.

## Plugin de WordPress CLP Varnish Cache

Instala el plugin [CLP Varnish Cache](https://wordpress.org/plugins/clp-varnish-cache/) en WordPress (versión actual 1.0.2, probado hasta WordPress 6.7.4). Te permite purgar la caché de Varnish desde la barra de administración de WordPress, algo útil después de publicar contenido nuevo o actualizar ajustes. No requiere una configuración compleja; conecta WordPress con la instalación de Varnish de CloudPanel automáticamente.

## Qué se cachea y qué no

Varnish en CloudPanel omite automáticamente el caché en:
- El panel de administración de WordPress
- La página de inicio de sesión
- Las páginas con cookies de sesión activas
- Las páginas de carrito y pago

Todo lo demás — entradas, páginas, archivos — se cachea en la primera visita y se sirve desde memoria en las siguientes.

## Combinar Varnish con PageSpeed

CloudPanel también incluye un módulo PageSpeed integrado (mod_pagespeed) que comprime imágenes, minifica CSS/JS y optimiza la entrega. Puedes activarlo junto a Varnish para ganar velocidad extra. Varnish se encarga de la capa de caché; PageSpeed, de la optimización de recursos. No entran en conflicto entre sí.

## Resultado

El efecto práctico es que un servidor que antes aguantaba 50 visitantes simultáneos antes de ralentizarse puede manejar varios cientos con Varnish delante. El uso de CPU y memoria baja porque PHP y MySQL solo se ejecutan para el primer visitante de cada página. La documentación de CloudPanel afirma que las páginas cargan entre 100 y 250 veces más rápido con Varnish activado, lo que coincide con mis pruebas en sitios de poco tráfico, donde las páginas cacheadas cargan en menos de 50 ms.

Es una de las mejoras de velocidad más efectivas que puedes hacer en un sitio WordPress sin cambiar de hosting ni añadir hardware.
