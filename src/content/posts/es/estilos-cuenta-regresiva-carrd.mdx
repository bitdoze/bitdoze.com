## Cuándo Usar un Temporizador de Cuenta Regresiva en tu Sitio de Carrd

Los temporizadores de cuenta regresiva se ganan su lugar cuando existe una fecha límite real:

1. **Lanzamientos de producto** - para crear expectación antes del estreno
2. **Ventas y promociones** - una oferta por tiempo limitado con un final concreto (una fecha de fin real supera al texto de «solo por tiempo limitado»); combínala con una [tabla de precios en Carrd](https://www.bitdoze.com/carrd-add-pricing-table/) para que el descuento sea visible mientras el reloj corre
3. **Registro a eventos** - plazos de inscripción
4. **Páginas de «próximamente»** - avisar a los visitantes cuándo volver
5. **Webinars y eventos en vivo** - la cuenta atrás hasta la hora de inicio

Un reloj en marcha crea una urgencia que el texto estático no puede igualar. También impone un requisito estricto: para un lanzamiento o una oferta, el temporizador tiene que llegar a cero en el mismo instante para cada visitante. Ese detalle suele fallar, así que no te saltes la [sección de zonas horarias](#configura-tu-fecha-objetivo-a-prueba-de-zonas-horarias) de abajo.

## Cómo Añadir un Temporizador de Cuenta Regresiva Personalizado a Carrd

Todos los diseños de este artículo pasan por el mismo elemento: el Embed. El flujo nunca cambia: añade el elemento, pon «Type» en «Code», pega un snippet y publica.

### Paso 1: Añade un Elemento Embed («Type»: «Code», «Style»: «Inline»)

Haz clic en el botón `+` del editor y añade un elemento **Embed**; luego pon «Type» en «Code» y «Style» en «Inline».

Pega tu HTML/CSS/JS en el campo de código. `Inline` renderiza la cuenta regresiva justo donde colocaste el elemento en el layout. La otra opción, `Hidden`, inyecta el código en el Head, Body Top o Body End de la página: correcta para scripts globales como la analítica, incorrecta para una cuenta regresiva visible. (Tutoriales antiguos mencionan un estilo «Above»; esa opción ya no existe.)

Para encontrar o reeditar el embed más tarde, usa el panel de elementos: **More Actions → Elements…** lista todos los elementos de la página y, desde octubre de 2026, también muestra el estado de visibilidad de cada uno, incluidos los excluidos de la publicación u ocultos con CSS. Útil cuando un embed «desaparece»: revisa el panel antes de sospechar del código.

<Notice type="warning" title="Los embeds son invisibles en el editor">
La documentación de Carrd lo dice claramente: el elemento Embed no muestra nada en el editor. Un hueco en blanco donde debería estar tu cuenta regresiva es normal. Publica el sitio y aparecerá. Es la falsa alarma número uno con el código personalizado en Carrd.
</Notice>

### Paso 2: Elige tu Estilo de Cuenta Regresiva

Elige uno de los cinco diseños de abajo y pégalo en el campo de código del embed. La única edición obligatoria es la fecha objetivo al inicio del script, explicada en [Configura tu Fecha Objetivo](#configura-tu-fecha-objetivo-a-prueba-de-zonas-horarias).

<Notice type="info" title="¿Dos temporizadores en una misma página?">
Cada snippet usa sus propios IDs (<code>countdown1</code>…<code>countdown5</code>), así que estilos distintos pueden coexistir. Dos copias del mismo estilo no: los IDs duplicados hacen que solo el primer temporizador funcione. Renombra cada <code>id</code> de la segunda copia (<code>days1</code> → <code>days6</code>, <code>countdown1</code> → <code>countdown6</code>, <code>dayCircle</code> → <code>dayCircle2</code>, <code>day1Card</code> → <code>day1Card2</code>) y las cadenas <code>getElementById</code> correspondientes en su script, y funcionará.
</Notice>

## Opción 1: Cuenta Regresiva con Tarjetas Modernas

Tarjetas con degradado limpio y la etiqueta bajo cada número. La elevación al pasar el ratón es sutil y las tarjetas se reordenan en móvil.

```html
<style>
  .countdown-modern {
    display: flex;
    justify-content: center;
    gap: 20px;
    flex-wrap: wrap;
    font-family: -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif;
    padding: 20px 0;
  }

  .countdown-item {
    background: linear-gradient(135deg, #667eea 0%, #764ba2 100%);
    border-radius: 16px;
    padding: 25px 20px;
    min-width: 100px;
    text-align: center;
    box-shadow: 0 10px 30px rgba(102, 126, 234, 0.3);
    transition: transform 0.3s;
  }

  .countdown-item:hover {
    transform: translateY(-5px);
  }

  .countdown-value {
    font-size: 48px;
    font-weight: 700;
    color: white;
    line-height: 1;
    margin-bottom: 8px;
  }

  .countdown-label {
    font-size: 14px;
    color: rgba(255, 255, 255, 0.8);
    text-transform: uppercase;
    letter-spacing: 2px;
  }

  @media (max-width: 500px) {
    .countdown-item {
      min-width: 70px;
      padding: 18px 15px;
    }
    .countdown-value {
      font-size: 32px;
    }
    .countdown-label {
      font-size: 11px;
    }
  }

  @media (prefers-reduced-motion: reduce) {
    .countdown-item {
      transition: none;
    }
    .countdown-item:hover {
      transform: none;
    }
  }
</style>

<div class="countdown-modern" id="countdown1" role="timer">
  <div class="countdown-item">
    <div class="countdown-value" id="days1">00</div>
    <div class="countdown-label">Days</div>
  </div>
  <div class="countdown-item">
    <div class="countdown-value" id="hours1">00</div>
    <div class="countdown-label">Hours</div>
  </div>
  <div class="countdown-item">
    <div class="countdown-value" id="minutes1">00</div>
    <div class="countdown-label">Minutes</div>
  </div>
  <div class="countdown-item">
    <div class="countdown-value" id="seconds1">00</div>
    <div class="countdown-label">Seconds</div>
  </div>
</div>

<script>
(function() {
  // March 1, 2027 at 09:00 UTC - Date.UTC months are 0-indexed too (2 = March)
  var targetDate = Date.UTC(2027, 2, 1, 9, 0, 0);

  function updateCountdown() {
    var distance = targetDate - Date.now();

    if (distance < 0) {
      clearInterval(iv);
      document.getElementById('countdown1').innerHTML = '<p style="font-size: 24px; font-weight: 700; color: #667eea;">Event has started!</p>';
      return;
    }

    var days = Math.floor(distance / 86400000);
    var hours = Math.floor((distance % 86400000) / 3600000);
    var minutes = Math.floor((distance % 3600000) / 60000);
    var seconds = Math.floor((distance % 60000) / 1000);

    document.getElementById('days1').innerHTML = (days < 10 ? '0' : '') + days;
    document.getElementById('hours1').innerHTML = (hours < 10 ? '0' : '') + hours;
    document.getElementById('minutes1').innerHTML = (minutes < 10 ? '0' : '') + minutes;
    document.getElementById('seconds1').innerHTML = (seconds < 10 ? '0' : '') + seconds;
  }

  var iv = setInterval(updateCountdown, 1000);
  updateCountdown();
})();
</script>
```

Para personalizarlo: cambia la línea `Date.UTC(2027, 2, 1, 9, 0, 0)`. Es la única línea que editas. Los meses empiezan en 0 (enero = 0, marzo = 2). Publica y mira cómo corre; si al cargar muestra «Event has started!», tu fecha objetivo está en el pasado.

## Configura tu Fecha Objetivo (a Prueba de Zonas Horarias)

Cada snippet define su fecha límite en una línea:

```javascript
var targetDate = Date.UTC(2027, 2, 1, 9, 0, 0);
```

Esta es la línea que cambias. `Date.UTC(year, month, day, hour, minute, second)` acepta los mismos argumentos que `new Date(...)`, y los meses siguen empezando en 0: enero = 0, marzo = 2, diciembre = 11.

Ejemplos con fechas futuras:

- 1 de marzo de 2027 a las 09:00 UTC: `Date.UTC(2027, 2, 1, 9, 0, 0)`
- 25 de diciembre de 2027 a las 09:00 UTC: `Date.UTC(2027, 11, 25, 9, 0, 0)`
- 4 de julio de 2027 a las 18:00 UTC: `Date.UTC(2027, 6, 4, 18, 0, 0)`

Un hábito que te ahorra republicar: mientras pruebas, elige una fecha cómodamente en el futuro. Una cuenta regresiva cuyo objetivo ya pasó muestra su mensaje de fin al cargar, lo que parece roto aunque el código esté bien. Cuando tengas la fecha real, cambia el año en lugar de dejar una fecha vieja.

### Fechas Límite: Hora Local del Visitante vs UTC

`Date.UTC(...)` y `new Date(y, m, d)` parecen intercambiables, pero no lo son:

- `new Date(2027, 2, 1)` cuenta hasta la medianoche **en la zona horaria de cada visitante**. Un visitante en Londres llega a cero cinco horas antes que uno en Nueva York. Para una fecha límite global (un lanzamiento, el fin de una oferta, el inicio de un webinar), eso es un bug real: algunos visitantes ven «Sale has ended!» mientras otros aún ven horas restantes.
- `Date.UTC(2027, 2, 1, 9, 0, 0)` es un instante fijo. El temporizador de cada visitante llega a cero en el mismo momento; cada navegador solo renderiza el tiempo restante contra su propio reloj.

Regla general: fecha límite global → `Date.UTC`. Evento local (apertura de puertas, promo en tienda) → `new Date(y, m, d)` con hora local del visitante está bien.

<Tabs>
<Tab name="Date.UTC">

```javascript
var targetDate = Date.UTC(2027, 2, 1, 9, 0, 0);
```

</Tab>
<Tab name="Cadena ISO">

```javascript
var targetDate = new Date("2027-03-01T09:00:00Z").getTime();
```

</Tab>
</Tabs>

Ambas son el mismo instante: 1 de marzo de 2027 a las 09:00 UTC. Elige la sintaxis que prefieras leer dentro de seis meses.

<Notice type="info" title="El mes empieza en 0">
Tanto en `new Date(y, m, d)` como en `Date.UTC(y, m, d, ...)`, enero es el mes 0 y diciembre el 11. A todos nos pica una vez. Si tu cuenta regresiva se desvía exactamente un mes, esta es la razón.
</Notice>

## Qué Pasa Cuando la Cuenta Regresiva Termina

Cada snippet sustituye el temporizador por un mensaje al llegar a cero y detiene su propio intervalo, así que no sigue corriendo invisiblemente para siempre. Dos patrones cubren la mayoría de las necesidades:

<Tabs>
<Tab name="Mostrar un mensaje">

```javascript
if (distance < 0) {
  clearInterval(iv);
  document.getElementById('countdown1').innerHTML = '<p>We are live!</p>';
  return;
}
```

</Tab>
<Tab name="Redirigir al vencer">

```javascript
if (distance < 0) {
  clearInterval(iv);
  window.location.href = 'https://yoursite.com/launch';
  return;
}
```

</Tab>

<Notice type="info" title="Detén el reloj">
`setInterval` sigue disparándose después de la fecha límite a menos que lo canceles. La llamada `clearInterval(iv)` en estos snippets apaga el temporizador en el momento en que se ejecuta el mensaje o la redirección. Sin ella, el intervalo sigue corriendo sin hacer nada.
</Notice>

Cuando el reloj llega a cero, cambiar la CTA por un [modal emergente](https://www.bitdoze.com/carrd-popup-modal/) que capture la lista de espera es el siguiente paso.

Apunta la redirección a una página de tu propio [dominio personalizado](https://www.bitdoze.com/carrd-add-domain/) para que la URL sobreviva a un rediseño. Pro Plus (49 $/año) también incluye «Redirects» nativos y una opción «Framing» en Publish → Settings, pero una redirección JavaScript de tres líneas dentro del embed basta para la mayoría de las cuentas regresivas.

Una nota de seguridad, por si estás valorando un temporizador basado en iframe: los sitios de Carrd publicados envían `content-security-policy: frame-ancestors https://carrd.com` y `x-frame-options: deny`. Eso solo restringe quién puede incrustar tu página de Carrd en un iframe. Los scripts en línea como estos snippets funcionan sin problema, igual que los scripts de widgets de terceros.

## Solución de Problemas y Preguntas Frecuentes

<Accordion label="¿Por qué no se ve mi cuenta regresiva en el editor de Carrd?" group="faq">
Los elementos Embed no renderizan nada en el editor: la documentación de Carrd lo afirma directamente. Publica el sitio y fuerza la recarga de la página en vivo. Si sigue en blanco después de publicar, abre DevTools y busca un error de script en la consola. Si también falta después de publicar, abre **More Actions → Elements…**: desde octubre de 2026 el panel muestra si un elemento está excluido de la publicación u oculto con CSS.
</Accordion>

<Accordion label="¿Por qué mi cuenta regresiva dice «Event has started!» nada más cargar?" group="faq">
Tu fecha objetivo está en el pasado. Revisa la línea `Date.UTC(...)` al inicio del script y muévela hacia adelante. Recuerda que el mes empieza en 0: `Date.UTC(2027, 2, 1)` es el 1 de marzo de 2027, no el 1 de febrero.
</Accordion>

<Accordion label="¿Por qué mi cuenta regresiva llega a cero a la hora equivocada?" group="faq">
Probablemente usaste `new Date(y, m, d)`, que cuenta hasta la medianoche en la zona horaria local de cada visitante. Para una fecha límite que debe llegar en el mismo instante en todo el mundo, cambia a `Date.UTC(y, m, d, h, min, s)` o `new Date("2027-03-01T09:00:00Z").getTime()`.
</Accordion>

<Accordion label="¿Necesito un plan de pago para un temporizador de cuenta regresiva en Carrd?" group="faq">
Sí. El elemento Embed requiere Pro Standard o superior, mínimo 19 $/año. Los planes Free y Pro Lite no pueden añadir código personalizado en absoluto, así que no hay alternativa gratuita dentro de Carrd.
</Accordion>

<Accordion label="¿Puedo añadir dos o más cuentas regresivas en una página?" group="faq">
Sí. Los distintos estilos coexisten porque sus IDs difieren (de `countdown1` a `countdown5`). Dos copias del mismo estilo chocan: renombra cada ID de la segunda copia y actualiza las cadenas `getElementById` de su script para que coincidan.
</Accordion>

<Accordion label="¿Por qué el reloj flip muestra días incorrectos pasados los 100 días?" group="faq">
El campo de días tiene dos tarjetas de dígitos, así que no puede mostrar un número de tres cifras. `pad2(150)` devuelve «150» y `dStr[1]` toma el dígito del medio. El snippet lo limita con `Math.min(days, 99)`, o puedes añadir una tercera tarjeta para tres dígitos reales.
</Accordion>

<Accordion label="¿Son accesibles estos snippets de cuenta regresiva?" group="faq">
En su mayoría, sí. Cada contenedor tiene `role="timer"` y los estilos animados incluyen una protección con `prefers-reduced-motion` que desactiva los efectos de volteo y hover para los usuarios que lo piden. No añadas `aria-live` a un temporizador que marca segundos; una región en vivo que anuncia cada tick es peor que no anunciar nada.
</Accordion>

<Accordion label="¿Puedo probar el temporizador en la prueba gratuita de Pro de 7 días de Carrd?" group="faq">
Probablemente no. La prueba cubre formularios, widgets, conectar un [dominio personalizado a Carrd](https://www.bitdoze.com/carrd-add-domain/) y la analítica nativa de Carrd, pero el elemento Embed (código personalizado) no está en la lista documentada de funciones de la prueba en carrd.com/docs/pro/trial. Necesitarás Pro Standard (19 $/año) para pegar y publicar estos snippets.
</Accordion>

## Conclusión

El elemento «Timer» integrado de Carrd cubre lo básico, pero un embed personalizado es la forma de conseguir una cuenta regresiva que combine con tu diseño. Elige un estilo, cambia una línea `Date.UTC`, publica y comprueba que corre. Gastarás menos que con un widget y no cargarás ningún script externo.

Combina el temporizador con un [modal emergente](https://www.bitdoze.com/carrd-popup-modal/) para captar emails, un [botón de WhatsApp](https://www.bitdoze.com/carrd-whatsapp-button/) para que los visitantes te contacten cuando el reloj llegue a cero, y un [aviso de cookies](https://www.bitdoze.com/add-cookie-notice-carrd/) si tienes tráfico de la UE. La lista de tutoriales de arriba tiene el resto de montajes con código personalizado para Carrd.
