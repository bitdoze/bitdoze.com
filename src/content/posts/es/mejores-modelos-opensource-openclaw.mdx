Llevo tiempo ejecutando [OpenClaw](/es/guia-configuracion-openclaw/) y la alineación de modelos no deja de moverse. A finales de 2026, los **mejores modelos open source para OpenClaw** son **GLM-5.3** para el trabajo duro de agentes, **MiniMax M3.1 Flash** y **GLM-5.3-Flash** para el tráfico del día a día, y **Kimi K3.1 Pro** cuando un solo trabajo necesita la máxima capacidad.

A continuación: qué cambió en los últimos meses, cómo conectar cada modelo, los detalles de configuración de OpenClaw que rompen setups antiguos, por qué enrutar una suscripción de Claude Code o Gemini CLI a través de OpenClaw sigue siendo una mala idea, y cuánto cuesta esto al mes.

<Notice type="warning" title="Advertencia de riesgo de suscripción">

Usar los tokens OAuth de tu suscripción de Claude Code, Gemini CLI o ChatGPT/Codex con OpenClaw puede hacer que tu cuenta sea baneada. Anthropic, Google y OpenAI vigilan patrones de uso automatizado que quedan fuera del uso normal del CLI. Quédate con claves API.

</Notice>

## Qué cambió desde julio de 2026: GLM-5.3, M3.1 Flash y Kimi K3.1 Pro

Este post se revisa con frecuencia. Esto es lo que se movió desde la última actualización.

<ListCheck>

- **GLM-5.3 se lanzó el 18 de agosto de 2026** y reemplaza a GLM-5.2 como la elección principal. GLM-5.2 sigue funcionando pero se auto-enruta a 5.3 en los Coding Plans.
- **GLM-5.3-Flash llegó el 26 de agosto** como un nivel multimodal ultra barato ($0.15/M entrada, $0.50/M salida) que ataca directamente el hueco económico de MiniMax.
- **MiniMax M3.1-Flash** bajó el precio de M3 ($0.15/$0.60 frente a $0.30/$1.20). M2.5 y M2.7 dejan de aceptar usuarios nuevos y se retiran el 18 de noviembre de 2026.
- **Kimi K3.1 Pro ya está en la API.** Los pesos abiertos están prometidos "para el 4 de noviembre" según el proveedor. La serie K2 cierra a nuevos usuarios el 31 de octubre y se retira a finales de diciembre de 2026.
- **El esquema de configuración de OpenClaw cambió.** `fallback` ahora es `fallbacks` (array), los IDs de proveedor usan `zai/*` en vez de `z-ai/*`, y un nuevo slot `utilityModel` maneja el tráfico en segundo plano.
- **El Coding Plan de Z.AI ahora funciona por puntos** (desde $18/mes, el horario valle quema 50% de puntos), y desde el 16 de octubre las claves del Coding Plan y las claves API estándar se facturan por separado.

</ListCheck>

Dos cosas no cambiaron. La tesis central se mantiene: los modelos abiertos vía claves API le ganan al OAuth de suscripción para agentes 24/7. Y los anclajes de precio aguantaron. GLM-5.3 lanzó al mismo precio de $1.40 entrada / $4.40 salida por millón de tokens que GLM-5.2, y la tarifa de $0.30/$1.20 de MiniMax M3 sigue siendo el precio permanente con 50% de descuento.

## Por qué los modelos open source tienen sentido para OpenClaw

OpenClaw corre 24/7 en tu servidor. Maneja mensajes, trabajos programados y skills sin parar. Esa carga continua se vuelve cara rápido con modelos propietarios.

Los modelos open source a través de proveedores de API te dan:

<ListCheck>

- **Costos predecibles**: Pagas por token, sin sorpresas por exceso de suscripción.
- **Sin riesgo de baneo**: El acceso API está hecho para uso automatizado.
- **Flexibilidad de modelo**: Cambia modelos en la config sin cambiar de plataforma.
- **Mejores límites de tasa**: Los niveles de API suelen superar al OAuth de suscripción en throughput.
- **Libertad de failover**: Encadena cualquier proveedor como respaldo. Sin depender de un solo proveedor.

</ListCheck>

La lista de modelos recomendados del propio OpenClaw ahora abre con las mismas opciones abiertas (`glm-5.3`, `minimax-m3.1-flash`, `kimi-k3.1-pro`). Eso es confirmación externa, no solo mi sesgo. Para el resumen más amplio de modelos de codificación que cubre Qwen 3.8, MiMo V2.6 Pro, DeepSeek V4.1 y alternativas propietarias, consulta [los mejores LLMs open source para programar](/es/mejores-llms-opensource-alternativa-claude/).

## Los riesgos de usar suscripciones de Claude Code o Gemini CLI

Me hacen esta pregunta constantemente, así que la respondo de entrada.

OpenClaw puede tomar tokens OAuth de Claude Code, Gemini CLI y OpenAI Codex. Técnicamente puedes apuntar un plan Claude Pro de $20/mes o una suscripción de Google AI a OpenClaw en lugar de pagar créditos de API. Funciona. También estás apostando.

### Por qué te pueden banear

Anthropic, Google y OpenAI restringen cómo pueden usarse los tokens de suscripción. Enruta un token OAuth de Claude Code a través de OpenClaw y esto es lo que cambia:

<ListCheck>

- **Patrones de uso**: El Claude Code normal parece un humano en una terminal. OpenClaw dispara solicitudes automatizadas las 24 horas, a menudo en ráfagas cuando corren trabajos.
- **Volumen de tokens**: Un asistente siempre activo quema más que una sesión de codificación humana.
- **Reintentos y llamadas paralelas**: Los fallos y el fan-out parecen scraping para los detectores.
- **IP y fingerprinting**: El tráfico de un VPS de datacenter no se parece al de una laptop en internet residencial.

</ListCheck>

### Qué pasa cuando te banean

| Plataforma | Consecuencia | Recuperación |
|----------|-------------|----------|
| **Claude Code** | Cuenta suspendida, suscripción cancelada | Existe apelación, sin garantía |
| **Gemini CLI** | Cuenta de Google marcada, acceso API revocado | Puede extenderse a otros servicios de Google |
| **OpenAI Codex** | Cuenta baneada, suscripción terminada | Opciones de apelación limitadas |

<Notice type="error" title="Riesgo real">

Hilos en la comunidad de OpenClaw describen suspensiones de cuenta a los pocos días de enrutar tokens de suscripción por herramientas automatizadas. La detección sigue mejorando. La documentación de OpenClaw sigue tratando OAuth como auth de operador, no como un puente de suscripción a API. Una suscripción Claude Max no vale el riesgo por unos pocos dólares de gasto en API.

</Notice>

### Qué hacer en su lugar

Usa claves API. Cada proveedor vende acceso de pago por uso hecho para automatización:

- **Anthropic API**: [console.anthropic.com](https://console.anthropic.com/)
- **Google AI**: [aistudio.google.com](https://aistudio.google.com/)
- **OpenAI API**: [platform.openai.com](https://platform.openai.com/)

O sáltate la pregunta del baneo por completo y usa modelos abiertos vía API. De eso va el resto de este post.

## 1. GLM-5.3: el mejor modelo open source para trabajo serio en OpenClaw

**[GLM-5.3](/es/mejores-llms-opensource-alternativa-claude/)** de Z.AI es el modelo abierto en el que más confío para la ruta difícil de OpenClaw. Razona bien, sostiene trabajo de agente de múltiples pasos sin desarmarse, y rara vez inventa datos cuando no debería. En Z.ai Code Bench puntúa 34.5% en esfuerzo Max, lo que supera el 29.5% de Claude Opus 4.8 en esfuerzo High (aunque Claude Fable 5 lidera con 39.5%). DeepSWE v1.1 está en 66.9%.

<Notice type="info" title="Las versiones de benchmark importan">

Terminal-Bench 2.1, Terminal-Bench 3.0 y Terminal-Bench 4.0 son suites diferentes con dificultad diferente. Igual para SWE-Bench Pro vs DeepSWE v1.1. Revisa siempre de qué versión viene una puntuación antes de comparar entre modelos. Que GLM-5.2 tuviera 81.0% en TB 2.1 no significa que GLM-5.3 retrocedió con 28.3% en TB 3.0; la suite nueva es mucho más difícil.

</Notice>

### Por qué GLM-5.3 funciona para OpenClaw

OpenClaw no es un chatbot. Planifica, llama herramientas, ejecuta scripts y mantiene contexto a lo largo de hilos largos. GLM-5.3 maneja ese tipo de trabajo de forma fiable.

- **DeepSWE v1.1: 66.9%** y números fuertes en benches de agentes. Importa cuando OpenClaw edita o ejecuta código en tu máquina.
- **Contexto de 1M de tokens**: Espacio para el historial largo de OpenClaw más volcados de salida de herramientas.
- **Razonamiento siempre activo** con `reasoning_effort` low/high/max (max por defecto). Ajusta la profundidad por agente.
- **Reputación de baja alucinación**: Cuando el asistente ejecuta comandos en un servidor en vivo, las respuestas equivocadas duelen.
- **Capacidad de auditoría de seguridad**: CyberGym 84.5%, ExploitBench 54.4%. Útil para skills de seguridad y una razón más para usar sandbox. Mira la [guía de seguridad de OpenClaw](/es/guia-seguridad-openclaw/).
- **Licencia open source**: Vale para flujos de trabajo comerciales automatizados.

Un breaking change a conocer: GLM-5.3 rechaza `thinking.type: "disabled"`. Si tu config todavía lo tiene de la era GLM-5.2, las solicitudes fallarán. Migra a `thinking.type: "enabled"` con `reasoning_effort: "low"` en su lugar. Notas completas de migración en la sección de config más abajo.

### Precios y especificaciones de GLM-5.3

| Feature | GLM-5.3 | GLM-5.3-Flash (preview) |
|---|---|---|
| **Parámetros** | No revelados | 320B (18B activos) MoE |
| **Contexto** | 1M tokens | 1M tokens |
| **Salida máxima** | 128K tokens | 128K tokens |

<Notice type="info" title="GLM Coding Plans: puntos, no por token">

Los Coding Plans de Z.AI cambiaron a un sistema de puntos. Lite da 2,000 puntos cada 5 horas más 10,000/semana; Pro da 12,000 cada 5 horas más 60,000/semana. Los planes empiezan en $18/mes. ### Configurar GLM-5.3 con OpenClaw

El camino más rápido es el atajo de onboard:

```bash
openclaw onboard --auth-choice zai-api-key   # auto-detects general vs coding endpoint
openclaw models set zai/glm-5.3              # or zai/glm-5.3-flash for budget agents
openclaw gateway restart
```

Variable de entorno: `ZAI_API_KEY`. Endpoints:

| Propósito | URL |
|---|---|
| API general (pago por uso) | `https://api.z.ai/api/paas/v4` |
| Coding Plan (facturación por puntos) | `https://api.z.ai/api/coding/paas/v4` |
| Protocolo Anthropic (pago por uso) | `https://api.z.ai/api/anthropic` |

O edita la config directamente. Fíjate en la clave `fallbacks` (array) y el prefijo de proveedor `zai/`:

```json
{
  "agents": {
    "defaults": {
      "model": {
        "primary": "zai/glm-5.3",
        "fallbacks": ["minimax/MiniMax-M3", "minimax/MiniMax-M3.1-Flash"]
      }
    }
  }
}
```

<Tabs>
<Tab name="Clave de Coding Plan">

Si te suscribes a un Coding Plan de Z.AI, tu clave funciona solo en el **endpoint de codificación compatible con OpenAI Chat Completion** (`https://api.z.ai/api/coding/paas/v4`). No funcionará en el endpoint de protocolo Anthropic. La facturación es por puntos como se describió arriba.

</Tab>
<Tab name="Clave API de pago por uso">

Las claves API estándar funcionan en todos los endpoints, incluido el de protocolo Anthropic (`https://api.z.ai/api/anthropic`). La facturación es por token a las tarifas de la tabla de arriba. Esta es la opción correcta si quieres el transporte de protocolo Anthropic en OpenClaw.

</Tab>
</Tabs>

<Notice type="warning" title="División de claves de Z.AI desde el 16 de octubre de 2026">

Las claves de Coding Plan y las claves API estándar ahora se gestionan y facturan por separado. Usar una clave de Coding Plan contra el endpoint de API general (o viceversa) produce errores de auth que parecen una clave mala. Comprueba qué tipo de clave tienes antes de depurar la conectividad. Mira el aviso de gestión de claves de Z.AI en sus docs de devpack.

</Notice>

**Verifica que funciona:**

```bash
openclaw models list --provider zai    # should show glm-5.3 and glm-5.3-flash
openclaw models status                  # primary should report healthy
openclaw doctor                         # overall config sanity check
```

Si `models list` no muestra nada bajo `zai`, tu tipo de clave o tu endpoint están mal. Si `models status` reporta fallos de auth, regenera la clave y asegúrate de que la variable de entorno está definida en el mismo shell o unidad systemd que ejecuta el gateway.

### Dónde brilla GLM-5.3 en OpenClaw

- **Tareas programadas**: Briefings matutinos, chequeos de servidor, cron jobs que tienen que funcionar.
- **Skills de codificación**: Scripts, configs de Docker, ediciones de repo.
- **Investigación**: Combina bien con la [búsqueda DuckDuckGo](/es/busqueda-duckduckgo-openclaw/).
- **Cadenas de herramientas de varios pasos**: Ejecuciones de agente largas sin perder el hilo.
- **Sesiones largas**: El contexto de 1M ayuda cuando el historial se acumula.
- **Skills de auditoría de seguridad**: Los números de CyberGym/ExploitBench lo convierten en la mejor opción abierta para escaneo y auditoría. Una razón más para mantenerlo en sandbox; la [guía de seguridad de OpenClaw](/es/guia-seguridad-openclaw/) cubre el lote de advisories de septiembre de 2026 y la checklist de lockdown.

## 2. GLM-5.3-Flash y MiniMax M3.1 Flash: los modelos OpenClaw baratos

La mayoría del tráfico de OpenClaw no necesita el buque insignia. Preguntas rápidas, recordatorios, operaciones de archivos, resúmenes en segundo plano. Dos modelos compiten ahora fuerte por este hueco.

**GLM-5.3-Flash** ($0.15/M entrada, $0.50/M salida) trae soporte multimodal nativo (imagen, video, archivo), contexto de 1M y eficiencia de cuota 3x en Coding Plans. **MiniMax M3.1-Flash** ($0.15/M entrada, $0.60/M salida, $0.015/M lectura de caché) ofrece profundidad de thinking ajustable y razonamiento intercalado a precios similares. Ambos quedan aproximadamente 10x por debajo del nivel buque insignia.

MiniMax M3 se queda en la alineación como la alternativa probada con números reales de codificación publicados (59.0% SWE-Bench Pro, 66.0% Terminal-Bench 2.1). Si quieres benchmarks de codificación probados en tu modelo económico, M3 sigue siendo la elección.

Para más opciones en este rango de precio en otros agentes, mira [los modelos de IA más baratos por debajo de $1/M tokens](/es/mejores-modelos-baratos-hermes-agent/).

### Precios y especificaciones de MiniMax M3 y M3.1 Flash

| Feature | MiniMax M3.1-Flash | MiniMax M3 (≤512k entrada) | MiniMax M3 (>512k entrada) |
|---|---|---|---|
| **Costo de entrada** | $0.15/M | $0.30/M | $0.60/M |
| **Costo de salida** | $0.60/M | $1.20/M | $2.40/M |
| **Lectura de caché** | $0.015/M | $0.06/M | $0.12/M |
| **Contexto** | 1M tokens | 1M tokens | 1M tokens |

Los precios de M3 mostrados son las tarifas promocionales permanentes con 50% de descuento (el precio de lista es $0.60/$2.40). Hay un nivel prioritario a 1.5x el estándar vía `service_tier: "priority"` si necesitas menor latencia.

Un hilo de OpenClaw con contexto de 1M que se llene va a chocar con esto. Compacta tus sesiones o enruta el trabajo de contexto largo a M3.1-Flash, que tiene tarifa plana.

</Notice>

### Configurar MiniMax con OpenClaw

```bash
openclaw onboard --auth-choice minimax-global-api   # or minimax-cn-api for the China endpoint
```

Variable de entorno: `MINIMAX_API_KEY`. Las refs de modelo correctas van en mayúsculas: `minimax/MiniMax-M3` y `minimax/MiniMax-M3.1-Flash`. El viejo slug en minúsculas `minimax/m3` puede no resolver en builds actuales.

Si tu build de OpenClaw aún no trae M3.1-Flash, regístralo explícitamente:

```json
{
  "agents": {
    "defaults": {
      "model": {
        "primary": "minimax/MiniMax-M3",
        "fallbacks": ["zai/glm-5.3"]
      },
      "utilityModel": {
        "primary": "minimax/MiniMax-M3.1-Flash"
      }
    }
  },
  "models": {
    "mode": "merge",
    "providers": {
      "minimax": {
        "baseUrl": "https://api.minimax.io/anthropic",
        "apiKey": "${MINIMAX_API_KEY}",
        "api": "anthropic-messages",
        "models": [
          {
            "id": "MiniMax-M3.1-Flash",
            "name": "MiniMax M3.1 Flash",
            "reasoning": true,
            "input": ["text", "image"],
            "cost": {
              "input": 0.15,
              "output": 0.6,
              "cacheRead": 0.015,
              "cacheWrite": 0
            },
            "contextWindow": 1000000,
            "maxTokens": 131072
          }
        ]
      }
    }
  }
}
```

**Verifica que funciona:**

```bash
openclaw models list --provider minimax   # should show MiniMax-M3 and MiniMax-M3.1-Flash
openclaw models status
```

Si no aparece nada bajo `minimax`, comprueba que tu ref usa el ID de modelo en mayúsculas. Configs antiguas con `minimax/m3` o `minimax/m2.7` necesitan actualizarse.

### Dónde brillan los modelos económicos en OpenClaw

- **Chat siempre activo**: Tan barato que dejas de racionar mensajes.
- **Ruido de utilidad y cron**: Títulos, resúmenes, trabajos en segundo plano. Enrútalos a un modelo Flash para que nunca coman tu presupuesto primario.
- **Tareas rápidas**: Recordatorios, operaciones de archivos, búsquedas simples.
- **Skills multimodales**: Entrada de capturas de pantalla y video corto cuando un skill necesita ojos.
- **Servicio de respaldo**: Recoge cuando el primario llega a límites de tasa o se cae.

El slot `utilityModel` de la config es la forma más limpia de manejar el tráfico de utilidad. Setup completo en la sección de config más abajo.

## 3. Kimi K3.1 Pro: la opción peak para trabajos de agente duros

**[Kimi K3.1 Pro](/es/mejores-llms-opensource-alternativa-claude/)** es un modelo post-entrenado de clase 3T con contexto de 1M, entrada de visión más video, y `reasoning_effort` low/high/max. Se apoya en K3 (2.8T, atención híbrida KDA), que lideró SWE Marathon y Frontend Code Arena y sacó 88.3% en Terminal-Bench 2.1.

K3.1 Pro ya está disponible por API. Los pesos abiertos están prometidos "para el 4 de noviembre" según el proveedor, así que no lo llamaré totalmente open-weight al momento de escribir. Una variante Highspeed ofrece la misma inteligencia a aproximadamente 2-3x de velocidad para uso interactivo.

**No** lo ejecuto como mi modelo por defecto. OpenRouter lo lista en torno a $2.00/M entrada, $10.00/M salida, $0.20/M lectura de caché (verifícalo en [platform.kimi.ai/docs/pricing/chat](https://platform.kimi.ai/docs/pricing/chat) antes de citarlo; las tablas oficiales se renderizan por JS y pueden diferir). Salida más barata que los viejos $3/$15 de K3, pero aún cara para uso siempre activo. Usa K3.1 Pro para:

- Maratones de codificación y agentes difíciles de varias horas.
- Investigación web intensiva donde importan sus puntajes clase BrowseComp.
- Skills con mucho frontend donde el rango en Arena se traduce en calidad.

### Configurar Kimi K3.1 Pro con OpenClaw

Kimi ahora va a través de un plugin:

```bash
openclaw plugins install @openclaw/moonshot-provider
openclaw gateway restart
openclaw onboard --auth-choice moonshot-api-key
openclaw models set moonshot/kimi-k3.1-pro
```

Variable de entorno: `MOONSHOT_API_KEY`. URLs base: `https://api.moonshot.ai/v1` (internacional) o `https://api.moonshot.cn/v1` (China). Kimi Code tiene su propio proveedor integrado (`kimi/kimi-for-coding`) si usas ese producto en su lugar.

**Verifica que funciona:**

```bash
openclaw models list --provider moonshot    # should show kimi-k3.1-pro
openclaw plugins update @openclaw/moonshot-provider   # keep the plugin current
```

Notas de facturación: Kimi usa precio plano sin niveles por contexto. El cacheo automático de contexto usa TTLs de 5 minutos o 1 hora; fija el TTL de 1h cuando los huecos entre llamadas superen 5 minutos o pierdes los beneficios de caché. La recarga mínima es $1.

Nota: la serie K2 (`kimi-k2.6`, `kimi-k2.5`) está en retirada. Cerró a nuevos usuarios el 31 de octubre y la retirada es a finales de diciembre de 2026. Si un ejemplo de las docs de OpenClaw muestra `moonshot/kimi-k2.6`, usa `moonshot/kimi-k3.1-pro` en su lugar.

## Config de OpenClaw: fallbacks, utilityModel y failover

La config de modelos de OpenClaw ganó nuevos slots y renombró claves desde la última versión de este post. Aquí va la anatomía.

**Primario y fallbacks**: `model.primary` toma una ref de modelo. `model.fallbacks` toma un array de refs de modelo que se prueban en orden cuando el primario falla. La vieja clave `fallback` (singular) todavía carga en algunos builds pero el esquema y las docs actuales usan `fallbacks`. Arréglalo antes de actualizar.

**Slots de utilidad y especializados**: `utilityModel` maneja títulos, resúmenes y tareas en segundo plano. `imageModel`, `mediaModels` y `pdfModel` existen para enrutamiento específico de medios. Apunta `utilityModel` a un modelo de nivel Flash para que el ruido rutinario cueste centavos.

**Parámetros por modelo**: Cada entrada de modelo soporta `params` como `cacheRetention: "long"` y `promptCacheTtl`. Controlan el comportamiento del cacheo de prompts e importan para el costo.

Un bloque consolidado:

```json
{
  "agents": {
    "defaults": {
      "model": {
        "primary": "zai/glm-5.3",
        "fallbacks": ["minimax/MiniMax-M3", "minimax/MiniMax-M3.1-Flash"]
      },
      "utilityModel": {
        "primary": "minimax/MiniMax-M3.1-Flash"
      },
      "imageModel": {
        "primary": "minimax/MiniMax-M3"
      }
    }
  }
}
```

### Problemas de migración y modos de fallo

Si estás actualizando desde una config antigua de OpenClaw o desde GLM-5.2, esto es lo que se rompe.

- **De `fallback` a `fallbacks`**: La clave se renombró y ahora es un array. Las configs antiguas pueden seguir cargando pero las docs nuevas y el esquema usan `fallbacks`. Actualiza antes de la próxima actualización mayor.
- **GLM-5.3 rechaza `thinking.type: "disabled"`**: Las solicitudes con ese ajuste fallan directamente. Usa `thinking.type: "enabled"` con `reasoning_effort: "low"` para el nivel de razonamiento más barato. Es un breaking change respecto a GLM-5.2.
- **Conflicto de tipo de clave de Z.AI**: Desde el 16 de octubre de 2026, las claves de Coding Plan y las claves API estándar se facturan por separado. Una clave de Coding Plan en el endpoint de API general (o viceversa) da errores de auth. Las claves de Coding Plan solo funcionan en el endpoint de codificación compatible con OpenAI.
- **Prefijo de proveedor**: `z-ai/*` es el prefijo de OpenRouter. El proveedor Z.AI integrado de OpenClaw usa `zai/*`. Si tienes `z-ai/glm-5.2` en tu config, cámbialo a `zai/glm-5.3`. Conviene probar si las refs legacy `z-ai/` siguen resolviendo tras una actualización antes de confiar en ellas.
- **Ejemplos de docs desactualizados**: `minimax/m2.7` y `moonshot/kimi-k2.6` aparecen en algunas páginas de docs de OpenClaw pero ambos modelos están muriendo. Usa `minimax/MiniMax-M3.1-Flash` y `moonshot/kimi-k3.1-pro`.
- **Las mayúsculas importan**: `minimax/MiniMax-M3` (ID de modelo en mayúsculas), no `minimax/m3`.

### Failover de modelos explicado

OpenClaw ahora hace failover en dos etapas, más sofisticado que una simple lista de respaldo.

**Etapa 1: rotación de auth-profile.** Si una solicitud falla por problemas de auth o límites de tasa, OpenClaw prueba claves API alternativas para el mismo modelo antes de caer a un modelo diferente.

**Etapa 2: cadena de fallbacks.** Si la rotación de auth falla, recorre el array `fallbacks` en orden. Cada fallback recibe el mismo tratamiento.

Antes de que nada de eso entre en juego, OpenClaw intenta una recuperación acotada en el mismo modelo que preserva el trabajo parcial (para que una llamada de herramienta fallida no fuerce un reinicio completo). Puertas de admisión de TPM (tokens por minuto) por modelo evitan el consumo desbocado. El tráfico interactivo tiene prioridad sobre los trabajos en segundo plano.

![Cadena de failover en dos etapas de OpenClaw: la solicitud va al modelo primario, luego a la rotación de auth-profile, luego a la cadena de fallbacks, con recuperación en el mismo modelo preservando trabajo parcial](@assets/images/15/02/openclaw-failover-chain.svg)

**Para revertir un cambio de config**: restaura el archivo de config anterior y ejecuta `openclaw gateway restart`. Para un cambio temporal de modelo sin editar config, usa `/model` en el chat.

**Verifica que el failover funciona:**

```bash
openclaw doctor
openclaw models status
openclaw gateway restart
```

Envía un mensaje de prueba tras el reinicio. Para probar el fallback a propósito, apunta temporalmente `primary` a una ref de modelo inválida y confirma que el primer fallback maneja la solicitud. Restaura la ref primaria real al terminar.

## Consejos de ejecutar esta configuración

### Ajuste de prompts

GLM y MiniMax reaccionan distinto al mismo prompt. GLM prefiere instrucciones claras y estructuradas. MiniMax tolera chat casual pero necesita reglas de formato explícitas para salida estructurada.

Pon guardarraíles compartidos en `~/.openclaw/workspace/SOUL.md`:

```markdown
When executing tasks:
- Break complex requests into clear steps
- Confirm before running destructive commands
- Use structured output for research results
```

### Cacheo de prompts: la mayor palanca de costo

El cacheo de prompts es donde se esconden los ahorros reales. Un system prompt pegajoso que acierta caché en cada llamada convierte la entrada de $1.40/M en $0.26/M en GLM-5.3. En MiniMax M3.1-Flash, las lecturas de caché cuestan $0.015/M frente a $0.15/M en fresco.

Define `params.cacheRetention: "long"` en modelos donde tu system prompt se mantiene estable. Para Kimi, fija el TTL de caché de 1h cuando los huecos entre llamadas superen 5 minutos. Para cron jobs de larga duración y agentes con system prompts persistentes, los prefijos cacheados no son opcionales; son la diferencia entre $30/mes y $100/mes.

### Gestión de contexto

Tanto GLM como MiniMax soportan 1M tokens, pero los hilos más cortos siguen funcionando mejor y cuestan menos. Usa `/compact` cuando el historial se infle, o `/new` cuando la sesión esté vieja. En MiniMax M3 específicamente, la compactación es una acción de costo, no solo de calidad: cruzar 512K de entrada duplica el precio de cada token.

### Monitoreo de costos

Vigila tu uso la primera semana. Los skills de cron y segundo plano queman más tokens que el chat solo.

- **Z.AI**: [z.ai/dashboard](https://z.ai/dashboard)
- **MiniMax**: [platform.minimax.io](https://platform.minimax.io)

Para visibilidad de sesiones, costos y cron dentro del propio OpenClaw, mira [dashboards de OpenClaw para seguimiento de sesión y costo](/es/mejores-dashboards-openclaw/). Ejecuta `openclaw promos` para ver ofertas promocionales de modelos.

### Fijado de versiones y actualizaciones

OpenClaw publica casi a diario (de v2026.9.34 a v2026.10.8 pasó en días). Ese ritmo es genial para features y arriesgado para la estabilidad. Fija tu versión de Gateway, lee las notas de versión antes de actualizar, y reinicia el gateway tras actualizaciones de plugins:

```bash
openclaw plugins update @openclaw/moonshot-provider
openclaw gateway restart
```

### Configuración de respaldo

Siempre define una cadena de fallbacks. Los proveedores se caen. Si GLM está caído a las 3 AM y hay un briefing programado, MiniMax debería recogerlo. El patrón de config completo está en la [sección de config](#config-de-openclaw-fallbacks-utilitymodel-y-failover) de arriba.
