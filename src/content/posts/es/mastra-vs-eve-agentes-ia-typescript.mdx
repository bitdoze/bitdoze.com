## ¿Qué es Mastra?

Mastra fue creado por Sam Bhagwat y el equipo fundador de Gatsby. Levantó una ronda semilla de $13M (YC W25) con inversores como Paul Graham y Guillermo Rauch (el CEO de Vercel). Ese último detalle es interesante dada la competencia.

La filosofía es composición basada en código. Piensa en el modelo mental de un ORM o un cliente de base de datos: defines agentes, herramientas y workflows como objetos tipados en código. La configuración es explícita. Lo ves todo delante de ti.

![Diagrama de arquitectura de Mastra](@assets/images/26/07/mastra-architecture.svg)

### Funciones clave de Mastra: agentes, workflows, memoria y evals

Los **agentes** son la primitiva central. Creas una clase `Agent` con instrucciones, herramientas, memoria y un modelo, y luego llamas a `generate()` o `stream()`:

```typescript
import { Agent } from '@mastra/core/agent';
import { openai } from '@ai-sdk/openai';
import { Memory } from '@mastra/memory';

const weatherAgent = new Agent({
  id: 'weather-agent',
  name: 'Weather Bot',
  instructions: 'You are a helpful weather assistant.',
  model: openai('gpt-4o-mini'),
  tools: { getWeather },
  memory: new Memory({ storage: { type: 'postgres' } }),
});

const response = await weatherAgent.generate('What is the weather in Tokyo?');
```

Los **workflows** usan un patrón builder basado en grafos con `.then()`, `.branch()` y `.parallel()`. Soportan suspend/resume para escenarios con humano en el bucle:

```typescript
import { Workflow, Step } from '@mastra/core/workflow';

export const onboardingWorkflow = new Workflow({
  name: 'onboarding',
  triggerSchema: z.object({ accountId: z.string() }),
})
  .step(new Step({ id: 'verify', execute: verifyAccount }))
  .step(new Step({ id: 'enrich', execute: enrichWithCRM }))
  .parallel([
    new Step({ id: 'send_welcome', execute: sendWelcomeEmail }),
    new Step({ id: 'schedule_call', execute: scheduleKickoff }),
  ])
  .commit();
```

La **memoria** es donde Mastra realmente brilla. Tiene cuatro niveles: historial de mensajes, memoria de trabajo, recuerdo semántico (95% en el benchmark LongMemEval) y RAG. El [Memory Gateway](https://mastra.ai/blog/announcing-mastra-platform) corre como servicio independiente. Si te interesa la memoria de agentes, lee nuestra comparación de [sistemas de memoria para agentes](/cognee-vs-hindsight/).

Los **evals** permiten puntuar el rendimiento del agente con evaluadores por modelo, por reglas y estadísticos:

```typescript
import { evaluate } from '@mastra/evals';

await evaluate(refundAgent, {
  testCases: refundGoldenSet,
  scorers: [policyComplianceScorer, costScorer],
  threshold: 0.9,
});
```

El **soporte MCP** te permite tanto crear como consumir servidores MCP. Si no conoces el protocolo, consulta [qué es MCP y cómo funciona](/mcp-introduction-beginners/). Para saber cuándo las herramientas nativas de Mastra superan a un MCP siempre activo (y el coste en RAM de los servidores stdio), lee [herramientas de Mastra vs MCP](/es/herramientas-mastra-vs-mcp/).

La **observabilidad** incluye una UI de navegador Studio en local, una plataforma cloud y logs/trazas/métricas completos. En mi propio asistente, Studio es lo que uso a diario para el chat y las trazas mientras desarrollo.

<Notice type="info">
Mastra soporta entre 40 y 124 proveedores de modelos y entre 600 y más de 4,000 modelos a través de su propio router. Eve usa Vercel AI Gateway en su lugar.
</Notice>

## ¿Qué es Vercel Eve?

Eve se lanzó el 17 de junio de 2026 en la conferencia Vercel Ship. Está construido por Vercel, el equipo detrás de Next.js.

La filosofía es filesystem primero, convención sobre configuración. Tu agente es un directorio. Suelta archivos en las carpetas correctas y el framework se encarga del resto. Sin registro, sin cableado de boilerplate. El nombre del archivo se convierte en el nombre de la herramienta.

Vercel está ejecutando Eve en producción. Más de 100 agentes internos impulsan desde análisis de datos hasta automatización de ventas.

### La arquitectura de Eve: filesystem primero

Un agente Eve es un directorio con una estructura concreta:

```
my-agent/
└── agent/
    ├── agent.ts            # model and runtime config
    ├── instructions.md     # always-on system prompt
    ├── tools/              # typed functions the model can call
    │   └── get_weather.ts
    ├── skills/             # procedures loaded on demand
    │   └── plan_a_trip.md
    ├── channels/           # message channels
    │   └── slack.ts
    ├── schedules/          # recurring cron jobs
    │   └── weekly_recap.ts
    └── subagents/          # specialized child agents
```

![Estructura de directorios de Vercel Eve](@assets/images/26/07/eve-directory-structure.svg)

Una herramienta es simplemente un archivo en `tools/`:

```typescript
import { defineTool } from 'eve/tools';
import { z } from 'zod';

export default defineTool({
  description: 'Return mock weather data for a city.',
  inputSchema: z.object({ city: z.string().min(1) }),
  async execute({ city }) {
    return { city, condition: 'Sunny', temperatureF: 72 };
  },
});
```

La configuración del agente es mínima:

```typescript
import { defineAgent } from 'eve';

export default defineAgent({
  model: 'anthropic/claude-sonnet-4.6',
});
```

Y tu system prompt es solo un archivo markdown:

```markdown
# Identity
You are an expert weather assistant.
You can fetch the weather for any city in the world.
```

Otras funciones clave:

- **Ejecución durable** (Vercel Workflow SDK): los pasos con checkpoint sobreviven a caídas, redespliegues y arranques en frío.
- **Computación en sandbox**: Vercel Sandbox (VM aislada) para producción, más backends locales: Docker, microsandbox, bash. Si te interesa [ejecutar herramientas de IA en contenedores aislados](/docker-podman-ai-cli-tools-safe-environment/), el enfoque de sandbox de Eve merece un vistazo.
- **Humano en el bucle**: añade `needsApproval: true` en cualquier herramienta. La sesión se pausa hasta que alguien aprueba.
- **Multicanal**: Slack, Discord, Teams, Telegram, Twilio, GitHub, Linear, API HTTP. El mismo agente, todos los canales.
- **Vercel Connect**: OAuth intermediado. El modelo nunca ve las credenciales.
- **AI Gateway**: enrutado de modelos con fallback entre proveedores.

Los ejemplos de producción internos de Vercel muestran lo que Eve puede hacer:

| Agente | Rol | Escala |
|---|---|---|
| **d0** | Análisis de datos | Más de 30K consultas de Slack/mes, aplica permisos de datos |
| **Lead Agent** | SDR autónomo | ~$5K/año de coste, ROI de 32x, 1 ingeniero a tiempo parcial |
| **Vertex** | Agente de soporte | 92% de resolución automática |
| **Athena** | Cabina de ventas | Construido por RevOps en 6 semanas sin ingeniería |

<Notice type="info" title="El Filesystem Primero Es un Patrón en Crecimiento">
Eve no está solo en este enfoque. Flue también usa un patrón de filesystem-como-API. Es una tendencia más amplia en los frameworks de agentes de 2026.
</Notice>

### Precios de Eve: costes de infraestructura de Vercel

Eve en sí es gratis (Apache 2.0). Los costes vienen de la infraestructura de Vercel:

- **Plan Vercel Pro:** $20/mes (incluye $20 de crédito para recursos)
- **Functions:** precios estándar de Vercel Functions
- **Workflows:** precios de Vercel Workflows
- **Sandbox:** ~$0.128/h por computación en sandbox
- **AI Gateway:** tokens del proveedor de modelos + markup de Vercel
- **Tokens de modelo:** pase directo al proveedor

No hay una línea separada de "Eve" en tu factura. Todo se factura contra los recursos de tu plan de Vercel.

El truco: la predictibilidad de costes. Los precios de Mastra son por niveles y fijos. Los de Eve son por uso y escalan con la computación. Para agentes siempre activos, el sandbox a $0.128/h suma (~$92/mes por agente siempre activo).

### Ventajas y desventajas de Eve

**Ventajas:**

<ListCheck>
<ul>
<li>El camino más rápido de cero a agente desplegado en Vercel</li>
<li>La DX de filesystem primero es intuitiva si conoces las convenciones de Next.js</li>
<li>Multicanal de serie (Slack, Discord, Teams, etc.). Sin integración personalizada</li>
<li>Computación en sandbox integrada. Sin configuración de sandbox aparte</li>
<li>El uso interno en producción de Vercel (más de 100 agentes) da credibilidad pese al estado beta</li>
<li>La ejecución durable gestiona caídas y arranques en frío automáticamente</li>
</ul>
</ListCheck>

**Desventajas:**

- Fuerte dependencia de Vercel: ejecución durable, sandbox, conectores y gateway requieren Vercel
- Muy nuevo / beta (v0.11.4). Las APIs pueden cambiar antes de la GA
- Deriva de dependencias: los paquetes pre-release (`@ai-sdk`, `@vercel/connect`) pueden romperse. Hay que fijar versiones
- Observabilidad escasa para fallos previos a la ejecución (webhook mal configurado, etc.)
- Trampa silenciosa en la ruta del trigger: la integración con Slack requiere un flag específico o falla en silencio
- Los límites de cron más estrictos que una vez al día requieren un plan de pago
- Sin soporte para Python

<Notice type="warning" title="Aviso de Dependencia de Plataforma">
Las mejores funciones de Eve (ejecución durable, sandbox, conectores, AI Gateway) están fuertemente acopladas a la infraestructura de Vercel. Migrar a un runtime que no sea Vercel es técnicamente posible mediante el patrón adaptador, pero espera una fricción considerable.
</Notice>

## Mastra vs Eve: comparación directa de los factores clave de decisión

Las funciones son similares sobre el papel. Las diferencias reales emergen cuando miras el despliegue, la madurez, el coste y la experiencia de desarrollador en condiciones reales.

### Flexibilidad de despliegue y dependencia del proveedor

**Mastra** se despliega en cualquier parte: Vercel, Netlify, Cloudflare Workers, Hono/Express/Next.js independiente, tu propio VPS. Cero dependencia de plataforma. El núcleo es Apache 2.0. Si quieres autoalojarlo en un Hetzner de $5/mes, adelante. Así es exactamente como ejecuto mi [asistente Mastra](/build-ai-agent-mastra/) en la práctica. Si quieres algo aún más ligero para agentes autoalojados, mira la [guía de configuración de Hermes Agent](/es/guia-configuracion-hermes-agent/).

**Eve** requiere Vercel para producción. El desarrollo local es posible con backends de Docker o microsandbox, pero la ejecución durable, el sandbox, los conectores y el AI Gateway necesitan infraestructura de Vercel.

El impacto en el mundo real: si Vercel cambia sus precios o necesitas moverte a otra nube, Mastra es portable. Eve exige una refactorización importante. El sentimiento de la comunidad en Reddit refleja esto. Los desarrolladores escarmentados por el acoplamiento de Next.js son escépticos ante otra dependencia de Vercel.

### Memoria, estado y ejecución durable

**Mastra** tiene un sistema de memoria de 4 niveles: historial de mensajes, memoria de trabajo, recuerdo semántico (95% en el benchmark LongMemEval) y RAG. El Memory Gateway corre como servicio independiente. La compresión de memoria mediante llamadas LLM en segundo plano sí añade coste. Para una mirada más profunda a los enfoques de memoria de agentes, consulta [Cognee vs Hindsight](/cognee-vs-hindsight/).

**Eve** gestiona la persistencia de sesión mediante el Vercel Workflow SDK. Los pasos con checkpoint sobreviven a caídas, redespliegues y arranques en frío. No hay servicio de memoria independiente. El enfoque de Eve trata más del estado de ejecución que del recuerdo semántico a largo plazo.

La diferencia práctica: Mastra es mejor para agentes que necesitan recordar y recuperar información entre sesiones (soporte al cliente, personalización). Eve es mejor para agentes que necesitan sobrevivir a eventos de infraestructura (caídas, redespliegues) dentro de una sesión.

Ambos ofrecen ejecución durable. Mastra lo hace mediante suspend/resume de workflows. Eve lo hace mediante checkpoints del Vercel Workflow SDK.

## Marco de decisión: cuándo elegir Mastra y cuándo Eve

No hay un ganador universal. La infraestructura, el equipo y la tolerancia al riesgo lo deciden.

![Diagrama de decisión: Mastra vs Eve](@assets/images/26/07/decision-flowchart.svg)

### Elige Mastra si...

<ListCheck>
<ul>
<li>Necesitas desplegar fuera de Vercel (AWS, GCP, autoalojado, Cloudflare, Netlify)</li>
<li>La independencia de plataforma es un requisito (empresas, sectores regulados)</li>
<li>Necesitas un framework maduro y probado con cumplimiento SOC 2</li>
<li>Tus agentes necesitan memoria entre sesiones (memoria de 4 niveles, recuerdo semántico)</li>
<li>Quieres precios predecibles (niveles fijos frente a pago por uso)</li>
<li>Estás construyendo productos de agentes y necesitas portabilidad</li>
<li>Quieres autoalojarlo todo, incluida la observabilidad</li>
</ul>
</ListCheck>

### Elige Eve si...

<ListCheck>
<ul>
<li>Tu infraestructura ya está en Vercel (app Next.js, Vercel Functions, etc.)</li>
<li>Quieres el camino más rápido de la idea al agente desplegado</li>
<li>Importa el soporte multicanal de serie (Slack, Discord, Teams)</li>
<li>Prefieres convención sobre configuración (DX de filesystem primero)</li>
<li>Tu equipo conoce las convenciones de Next.js y quiere un modelo mental similar</li>
<li>Necesitas computación en sandbox integrada para ejecutar código</li>
<li>Te sientes cómodo con APIs beta y el riesgo de early adopter</li>
</ul>
</ListCheck>

### Considera alternativas si...

<ListCheck>
<ul>
<li>Necesitas Python. Mira LangGraph, CrewAI o Pydantic AI</li>
<li>Solo necesitas UI de streaming y llamadas a herramientas básicas. Vercel AI SDK por sí solo puede bastar</li>
<li>Quieres máxima madurez de ecosistema. LangGraph (Python) aún lidera en integraciones</li>
<li>Te gusta la DX de filesystem primero pero no la dependencia de Vercel. Vigila Flue (agnóstico de plataforma)</li>
</ul>
</ListCheck>

<Accordion label="¿Y qué pasa con Vercel AI SDK vs Eve?" group="faq" expanded="false">
Vercel AI SDK es la capa de UI y enrutado de modelos. Eve es el framework de agentes construido encima. Si solo necesitas UI de streaming y llamadas a modelos, AI SDK basta. Si necesitas agentes con herramientas, memoria, workflows y canales, necesitas Eve (o Mastra).
</Accordion>

## Alternativas que vale la pena considerar

Más allá de Mastra y Eve, hay algunas opciones que conviene conocer:

**Vercel AI SDK** es para casos de uso más simples. UI de streaming, enrutado de modelos, llamadas a herramientas básicas. Sin abstracciones de agente, sin memoria, sin workflows. Si eso es todo lo que necesitas, sáltate un framework de agentes completo.

**LangGraph.js** es el port a TypeScript de LangGraph. Más pesado, pero encaja mejor si tu equipo también usa LangGraph en Python y quiere el mismo modelo mental.

**Flue** es nuevo, filesystem primero como Eve pero agnóstico de plataforma. Vale la pena vigilarlo si te gusta la DX de Eve sin la dependencia de Vercel.

El patrón "agente como directorio" es común en 2026. Eve y Flue lo usan. Es una reacción contra el estilo cargado de boilerplate de frameworks anteriores.

Para una comparación de frameworks de estilo similar, consulta [Astro vs Next.js vs TanStack Start](/astro-vs-nextjs-vs-tanstack-start-which-wins-2026/).

Si quieres un agente de codificación con IA en lugar de un framework para construir agentes, [OpenCode Go](https://go.bitdoze.com/opencode-go) es un camino distinto. Para enrutado multi-modelo sin un framework de agentes completo, [Agent Router](https://go.bitdoze.com/agentrouter) unifica Claude Code, OpenAI Codex y Gemini CLI.

## Veredicto final: Mastra vs Eve en 2026

El trade-off sigue siendo **portabilidad vs comodidad nativa de Vercel**.

Para la mayoría de los equipos TypeScript que envían agentes a producción hoy, **Mastra es la apuesta más segura**. Es maduro, portable, cumple SOC 2 y está probado a escala. El sistema de memoria de 4 niveles es sólido. Puedes desplegar en cualquier parte y mover la infraestructura sin reescribir agentes. Por eso construí mi propio [asistente de archivos/web/navegador sobre Mastra](/build-ai-agent-mastra/) y sigo mejorándolo en abierto.

Para equipos nativos de Vercel que quieren la DX más rápida y pueden vivir con el riesgo beta, **Eve es atractivo**. El filesystem primero es una DX agradable. El multicanal de serie ahorra trabajo de integración. El dogfooding interno de Vercel (más de 100 agentes) sugiere que madurará rápido tras la GA.

Eve después de la GA puede cerrar la brecha de madurez. Los docs y el ecosistema de Mastra aún necesitan trabajo. La competencia aquí es buena para ambos.

<Notice type="success" title="En Resumen">
Mastra para portabilidad y preparación para producción. Eve para velocidad y DX nativas de Vercel. Ambos son Apache 2.0, ambos son solo TypeScript, y ambos avanzan rápido.
</Notice>

## Preguntas frecuentes

<Accordion label="¿Mastra es gratis?" group="faq" expanded="true">
Sí. El núcleo de Mastra es Apache 2.0 y puede autoalojarse sin coste. La Mastra Platform (cloud) tiene un plan Starter gratuito con 100K eventos de observabilidad y 24 horas de CPU. El plan Teams cuesta $250/equipo/mes.
</Accordion>

<Accordion label="¿Puedo usar Eve sin Vercel?" group="faq" expanded="false">
Para desarrollo local, sí. Eve soporta backends de Docker, microsandbox y bash. Para funciones de producción como ejecución durable, sandbox y conectores multicanal, necesitas infraestructura de Vercel.
</Accordion>

<Accordion label="¿Qué framework tiene mejor soporte de TypeScript?" group="faq" expanded="false">
Ambos son solo TypeScript. Mastra ofrece definiciones de tipos más explícitas a través de sus clases Agent/Workflow/Step. Eve usa esquemas Zod para validar la entrada de herramientas y se apoya en convenciones. Ambos tienen buen soporte en el IDE.
</Accordion>

<Accordion label="¿La dependencia de Eve es tan mala como la de Next.js?" group="faq" expanded="false">
Es similar en patrón. El núcleo open source de Eve (Apache 2.0) significa que puedes leer y bifurcar el código. Pero las funciones que hacen potente a Eve (ejecución durable, sandbox, conectores, AI Gateway) son servicios específicos de Vercel. Si ya estás en Vercel, esto es una ventaja, no un problema.
</Accordion>

<Accordion label="¿Qué pasó con el incidente de cadena de suministro de Mastra?" group="faq" expanded="false">
En junio de 2026, una cuenta de colaborador dormida de Mastra fue secuestrada y se publicaron más de 140 paquetes maliciosos. El equipo de Mastra lo resolvió, pero es un recordatorio de fijar las dependencias y auditar los paquetes. Ese consejo aplica a cualquier proyecto del ecosistema npm, no solo a Mastra.
</Accordion>
