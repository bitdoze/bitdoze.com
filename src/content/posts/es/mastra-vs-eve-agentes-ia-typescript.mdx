## ¿Qué es Mastra?

Mastra es un framework TypeScript para agentes, workflows, herramientas y memoria, creado por Sam Bhagwat y el equipo fundador de Gatsby. Es estable desde la versión 1.0, el 20 de enero de 2026.

![Diagrama de arquitectura de Mastra: el código de agente, workflow y herramientas alimenta el runtime, y luego memoria, almacenamiento, MCP y trazas, Studio y los destinos de despliegue](@assets/images/26/07/mastra-vs-eve-typescript-ai-agents-mastra-architecture.webp)

*Cómo encaja Mastra: objetos tipados en código, un runtime, y cualquier host Node.js o la plataforma Mastra. Fuentes: [documentación de Mastra](https://mastra.ai/docs) y [precios](https://mastra.ai/pricing).*

La filosofía es composición basada en código. Piensa en el modelo mental de un ORM o un cliente de base de datos: defines agentes, herramientas y workflows como objetos tipados en código. La configuración es explícita. Lo ves todo delante de ti.

Una ronda semilla de $13M en octubre de 2025 incluyó a YC, pg, Gradient, Amjad, Guillermo y más de 120 inversores, y la [página about](https://mastra.ai/about) ahora reporta $35M recaudados. Guillermo Rauch es el CEO de Vercel, un detalle curioso dada la competencia.

### Funciones de Mastra: agentes, workflows, memoria y evals

Los **agentes** son la primitiva central. Creas una clase `Agent` con instrucciones, herramientas, memoria y un modelo, y luego llamas a `generate()` o `stream()`:

```typescript
import { Agent } from '@mastra/core/agent';
import { createTool } from '@mastra/core/tools';
import { z } from 'zod';

const getWeather = createTool({
  id: 'get-weather',
  description: 'Return weather data for a city.',
  inputSchema: z.object({ city: z.string() }),
  execute: async ({ city }) => {
    return { city, condition: 'Sunny', temperatureF: 72 };
  },
});

export const weatherAgent = new Agent({
  id: 'weather-agent',
  name: 'Weather Agent',
  instructions: 'You are a helpful weather assistant.',
  model: 'openai/gpt-4o-mini',
  tools: { getWeather },
});

const response = await weatherAgent.generate('What is the weather in Tokyo?');
```

El modelo es una cadena `provider/model`. El router de Mastra la resuelve desde una variable de entorno como `OPENAI_API_KEY`, así que no hace falta ningún paquete de proveedor. Registra el agente en una instancia `Mastra` para compartir almacenamiento, logging y trazas.

![Quickstart de la documentación de Mastra con el constructor Agent (id, name, instructions y una cadena provider/model) junto a la instancia Mastra que lo registra](@assets/images/26/07/mastra-vs-eve-typescript-ai-agents-mastra-docs-agent.webp)

*La definición del agente en la documentación de Mastra: un objeto `Agent`, registrado en una instancia `Mastra`. Fuente: [mastra.ai/docs/agents/overview](https://mastra.ai/docs/agents/overview).*

Los **workflows** usan un patrón builder basado en grafos con `.then()`, `.branch()` y `.parallel()`. Soportan suspend/resume para escenarios con humano en el bucle:

```typescript
import { createStep, createWorkflow } from '@mastra/core/workflows';
import { z } from 'zod';

const account = z.object({ accountId: z.string() });
const verified = account.extend({ verified: z.boolean() });

const verify = createStep({
  id: 'verify',
  inputSchema: account,
  outputSchema: verified,
  execute: async ({ inputData }) => ({ accountId: inputData.accountId, verified: true }),
});

const sendWelcome = createStep({
  id: 'send_welcome',
  inputSchema: verified,
  outputSchema: account,
  execute: async ({ inputData }) => ({ accountId: inputData.accountId }),
});

// scheduleCall sigue la misma forma con id 'schedule_call'
export const onboardingWorkflow = createWorkflow({
  id: 'onboarding',
  inputSchema: account,
  outputSchema: z.object({ send_welcome: account, schedule_call: account }),
})
  .then(verify)
  .parallel([sendWelcome, scheduleCall])
  .commit();
```

El 28 de noviembre de 2026 este workflow corrió en unos 10 ms a través de `createRun()` y `start()`. Devolvió un objeto de resultado con una clave por id de paso.

La **memoria** tiene cuatro partes: historial de mensajes, memoria de trabajo, recuerdo semántico y memoria observacional. Mastra reporta un 94.87% en LongMemEval para la memoria observacional con GPT-5 mini. Los procesadores de memoria recortan el contexto cuando se llena, y la memoria observacional lanza llamadas al modelo en segundo plano que suman coste. El [Memory Gateway](https://mastra.ai/blog/announcing-mastra-platform) alojado ofrece la misma memoria a agentes construidos sobre otros frameworks. Si te importa la memoria de agentes, lee nuestra comparación de [sistemas de memoria para agentes](/es/cognee-vs-hindsight/).

Los **evals** te permiten puntuar el rendimiento del agente con scorers basados en modelo, en reglas y estadísticos:

```typescript
import { Agent } from '@mastra/core/agent';
import { createAnswerRelevancyScorer } from '@mastra/evals/scorers/prebuilt';

export const refundAgent = new Agent({
  id: 'refund-agent',
  name: 'Refund Agent',
  instructions: 'You handle refund requests by the policy document.',
  model: 'openai/gpt-4o-mini',
  scorers: {
    relevancy: {
      scorer: createAnswerRelevancyScorer({ model: 'openai/gpt-4o-mini' }),
      sampling: { type: 'ratio', rate: 0.5 },
    },
  },
});
```

Los scorers corren en segundo plano sobre una parte de las salidas en vivo. Los datasets guardan casos de prueba versionados, y los experimentos los reproducen contra un nuevo prompt, modelo o conjunto de herramientas.

El **soporte MCP** te permite tanto crear como consumir servidores MCP. Si no conoces el protocolo, consulta [qué es MCP y cómo funciona](/es/introduccion-mcp-principiantes/). Para saber cuándo las herramientas nativas de Mastra superan a un MCP siempre activo (y el coste en RAM de los servidores stdio), lee [herramientas de Mastra vs MCP](/es/herramientas-mastra-vs-mcp/).

La **observabilidad** incluye una UI de navegador Studio en local, una plataforma cloud y logs/trazas/métricas completos. En mi propio asistente, Studio es lo que uso a diario para el chat y las trazas mientras desarrollo. Studio arranca con `mastra dev` en el puerto 4111; define la variable de entorno `PORT` para cambiarlo.

## ¿Qué es Vercel Eve?

Eve se lanzó el 17 de junio de 2026 en la conferencia Vercel Ship. Lo construye Vercel, el equipo detrás de Next.js.

La filosofía es filesystem primero, convención sobre configuración. Tu agente es un directorio. Suelta archivos en las carpetas correctas y el framework se encarga del resto. Sin registro, sin cableado de boilerplate. El nombre del archivo se convierte en el nombre de la herramienta.

Vercel está ejecutando Eve en producción. Más de 100 agentes internos impulsan desde análisis de datos hasta automatización de ventas.

Eve 1.0 llegó a disponibilidad general el 17 de noviembre de 2026, tras más de 230 releases desde la preview de junio. El post de la 1.0 de Vercel cita a Rillet y Clay entre los negocios que lo usan. Para un primer proyecto, la [guía de iniciación a Eve](/es/vercel-eve-agente-ia/) de este sitio recorre un agente durable paso a paso.

### La arquitectura de Eve: filesystem primero

Un agente Eve es un directorio con una estructura concreta:

```text
my-agent/
├── agent/
│   ├── agent.ts            # model and runtime config (optional)
│   ├── instructions.md     # the always-on system prompt (required)
│   ├── tools/              # typed functions the model can call
│   │   └── get_weather.ts
│   ├── skills/             # procedures loaded on demand
│   ├── channels/           # HTTP, Slack, Discord, Teams and more
│   ├── connections/        # MCP and OpenAPI services
│   ├── memory/             # cross-session memory slots
│   ├── schedules/          # recurring cron jobs
│   └── subagents/          # specialist child agents
└── evals/                  # *.eval.ts files run with eve eval
```

![Diagrama de arquitectura de Eve con el directorio del agente, el runtime eve, canales, conexiones, backends intercambiables y los dos destinos de despliegue](@assets/images/26/07/mastra-vs-eve-typescript-ai-agents-eve-architecture.webp)

*Cómo encaja Eve: archivos en un directorio, un runtime, backends intercambiables, y Vercel o tu propio servidor Node. Fuente: [documentación de eve.dev](https://eve.dev/docs).*

Cada ruta tiene un trabajo, y `eve info` imprime lo que Eve descubrió en ella. En el agente de laboratorio listó la herramienta, las instrucciones y las rutas de mensajería, con 0 errores.

Una herramienta es simplemente un archivo en `tools/`:

```typescript
import { defineTool } from 'eve/tools';
import { z } from 'zod';

export default defineTool({
  description: 'Return mock weather data for a city.',
  inputSchema: z.object({ city: z.string().min(1) }),
  async execute({ city }) {
    return { city, condition: 'Sunny', temperatureF: 72 };
  },
});
```

La configuración del agente es mínima:

```typescript
import { defineAgent } from 'eve';

export default defineAgent({
  model: 'anthropic/claude-sonnet-5.5',
});
```

Y tu system prompt es solo un archivo markdown:

```markdown
# Identity
You are an expert weather assistant.
You can fetch the weather for any city in the world.
```

![Página Agent Files de la documentación de Eve con los slots del directorio del agente, de agent.ts e instructions.md a tools, memory y subagents](@assets/images/26/07/mastra-vs-eve-typescript-ai-agents-eve-docs-agent-files.webp)

*El directorio del agente en la documentación de Eve: un slot por responsabilidad, con nombres derivados de las rutas de archivo. Fuente: [eve.dev/docs/reference/agent-files](https://eve.dev/docs/reference/agent-files).*

Otras funciones integradas:

- **Ejecución durable**: cada sesión es una ejecución sobre el [Workflow SDK](https://workflow-sdk.dev) de código abierto. Una caída o un redespliegue se reanuda desde el último checkpoint, y una aprobación estaciona el turno sin retener cómputo.
- **Cómputo en sandbox**: Vercel Sandbox en producción, Docker cuando es accesible, y una shell en JavaScript puro (just-bash) en desarrollo. Si te interesa [ejecutar herramientas de IA en contenedores aislados](/es/docker-podman-entorno-seguro-ia/), el enfoque de sandbox de Eve merece un vistazo.
- **Humano en el bucle**: añade una regla `needsApproval` a cualquier herramienta. La sesión se detiene hasta que alguien aprueba.
- **Multicanal**: Slack, Discord, Teams, Telegram, Twilio, GitHub, Linear, iMessage, Web Chat y la API HTTP. El mismo agente, todos los canales.
- **Conexiones**: un archivo por servidor MCP o API OpenAPI. El modelo nunca ve la URL ni las credenciales. [Vercel Connect](https://vercel.com/connect) gestiona el OAuth, o `defineInteractiveAuthorization` lo hace en tu propio host.
- **Memoria y evals**: los slots de memoria viven en `agent/memory/`, y los archivos `evals/*.eval.ts` puntúan el agente con `eve eval`.

La UI de desarrollo local es una terminal: `eve dev` arranca el servidor y lo abre en el puerto 2000 por defecto.

### Precios de Eve: costes de infraestructura de Vercel

Eve en sí es gratis (Apache 2.0). Los costes vienen de la infraestructura de Vercel:

- **Plan Vercel Pro:** cuota de plataforma de $20/mes con un crédito de uso de $20 al mes
- **Workflows:** $0.02 por 1K eventos, $0.50 por GB escrito, $0.50 por GB-mes retenido
- **Sandbox:** $0.128 por hora de CPU activa y $0.0212 por GB-hora de memoria aprovisionada
- **Functions:** tarifas de Vercel Functions para las rutas del agente y la ejecución de herramientas
- **AI Gateway:** el precio de lista del proveedor sin recargo en los tokens; pueden aplicar comisiones de procesamiento de pago
- **Blob:** un almacén privado para la memoria de archivos, con 1 GB/mes incluido en Hobby

Hobby cubre pruebas pequeñas con cuotas: 5 horas de CPU de sandbox y 420 GB-horas de memoria al mes, más 50K eventos de workflow y 1 GB escrito. Las tareas cron corren una vez al día, y Hobby no guarda datos retenidos de workflows. Las tarifas vienen de las páginas de precios de [Sandbox](https://vercel.com/docs/sandbox/pricing), [Workflows](https://vercel.com/docs/workflows/pricing) y [AI Gateway](https://vercel.com/docs/ai-gateway/pricing), comprobadas el 28 de noviembre de 2026.

No hay una línea separada "Eve" en tu factura. Todo se factura contra los recursos de tu plan de Vercel.

El truco: la predictibilidad de costes. La plataforma de Mastra es un plan fijo con tarifas de exceso publicadas. Eve en Vercel se paga por uso. Vercel factura CPU activa, no tiempo de reloj, así que un sandbox siempre activo cuesta menos de lo que sugieren los $0.128/hr en bruto. Un sandbox con 2 vCPUs al 10% de CPU media, activo 730 horas, cuesta $18.69 en CPU más $61.90 por 4 GB de memoria, unos $81/mes. Ese supuesto del 10% coincide con los ejemplos de Vercel, que descuentan el tiempo esperando llamadas al modelo.

Eve autoalojado no genera factura de Vercel: pagas tu propio servidor, almacenamiento y tokens del modelo. En Vercel, la versión 1.0 también recortó la parte de workflow de una sesión larga. Vercel estima que el coste de Workflows de una sesión de 50 turnos bajó de 5.4 centavos a 1.3 centavos.

### Ventajas y desventajas de Eve

**Ventajas:**

<ListCheck>
<ul>
<li>El camino más rápido de cero a agente desplegado en Vercel</li>
<li>La DX de filesystem primero es intuitiva si conoces las convenciones de Next.js</li>
<li>Multicanal de serie (Slack, Discord, Teams, etc.). Sin integración personalizada</li>
<li>Cómputo en sandbox integrado. Sin configuración de sandbox aparte</li>
<li>El uso interno en producción de Vercel (más de 100 agentes) y una versión 1.0 con versionado semántico</li>
<li>La ejecución durable gestiona caídas y arranques en frío automáticamente</li>
<li>Se autoaloja como servidor Node desde la documentación de la 1.0: estado en disco o Postgres, sandbox con Docker o just-bash, trazas OpenTelemetry</li>
</ul>
</ListCheck>

**Desventajas:**

Estas notas vienen de la preview v0.11 de julio de 2026. Eve 1.0 reemplazó la capa de trazas tras más de 230 releases, así que vuelve a probar cada una en una versión actual.

- El camino más suave sigue siendo Vercel: `eve deploy`, Vercel Connect y Agent Runs son servicios de Vercel
- Autoalojar implica escribir tu propia autenticación de rutas y operar tu propio backend de telemetría
- Base de código más joven: cinco meses de la preview a la GA, con 1,005 issues y pull requests abiertos el 28 de noviembre de 2026 (Mastra: 921)
- Deriva de dependencias: los paquetes pre-release (`@ai-sdk`, `@vercel/connect`) pueden romperse. Hay que fijar versiones
- Observabilidad escasa para fallos previos a la ejecución (webhook mal configurado, etc.)
- Trampa silenciosa en la ruta del trigger: la integración con Slack requiere un flag específico o falla en silencio
- Vercel Hobby corre las tareas cron una vez al día; cualquier cosa más frecuente necesita Pro
- Sin soporte para Python

<Notice type="warning" title="Aviso de dependencia de plataforma">
El núcleo de Eve ahora corre fuera de Vercel: el Workflow SDK es de código abierto, el world por defecto guarda el estado en disco, y el sandbox puede ser Docker o just-bash. `eve deploy`, Vercel Connect, Agent Runs y el Sandbox alojado siguen necesitando Vercel. Salir de Vercel implica reemplazarlos con tu propia autenticación, almacenamiento y trazas.
</Notice>

## Mastra vs Eve: comparación directa de los factores clave de decisión

Las funciones son similares sobre el papel. Las diferencias reales emergen cuando miras el despliegue, la madurez, el coste y la experiencia de desarrollador en condiciones reales.

### Flexibilidad de despliegue y dependencia del proveedor

**Mastra** se despliega en cualquier parte: Vercel, Netlify, Cloudflare Workers, Hono/Express/Next.js independiente, tu propio VPS. Cero dependencia de plataforma. El núcleo es Apache 2.0. Si quieres autoalojarlo en un Hetzner de $5/mes, adelante. Así es exactamente como ejecuto mi [asistente Mastra](/es/crear-agente-ia-mastra/) en la práctica. Si quieres algo aún más ligero para agentes autoalojados, mira la [guía de configuración de Hermes Agent](/es/guia-configuracion-hermes-agent/). Los runtimes documentados son Node.js 22.13 o posterior, Bun, Deno y Cloudflare, con 14 guías de despliegue que van de Vercel y Netlify a Kubernetes y Temporal. Para las opciones de sandbox, lee [sandboxes de agentes de IA autoalojados con p9m y Mastra Factory](/es/sandboxes-agentes-ia-p9m-mastra-factory/).

**Eve** tiene dos destinos documentados. `eve deploy` publica en Vercel, y `eve build` más `eve start` ejecutan el agente como un servidor Node en tu propia infraestructura. Los valores por defecto autoalojados guardan el estado del workflow en disco y usan Docker para el sandbox cuando es accesible. El estado en Postgres y un sandbox en JavaScript puro están a un cambio de configuración.

El impacto real es menor que en junio de 2026. Sacar un agente Eve de Vercel ya no significa reescribir el directorio del agente. Eso sí, reemplazas el OAuth de Vercel Connect, Agent Runs y el Sandbox alojado con tu propia autenticación, backend OpenTelemetry y Docker. El sentimiento de la comunidad en Reddit sigue tratando a Eve como Vercel primero. Los desarrolladores escarmentados por el acoplamiento de Next.js son escépticos ante otro producto de Vercel.

<Notice type="warning">
Si la independencia de plataforma importa, Mastra documenta más destinos: cuatro runtimes y 14 guías de despliegue. Eve tiene dos destinos, y uno de ellos es cualquier host con Node 24+ que operes tú mismo.
</Notice>

Si te autoalojas, proveedores de VPS económicos como [Hetzner](https://go.bitdoze.com/hetzner) hacen que los despliegues de Mastra sean rentables.

### Precios a escala: lo que pagarás de verdad

**Mastra** tiene niveles predecibles. Gratis si lo autoalojas. Starter cuesta $25/mes y Team $250/mes en la plataforma, con tarifas de exceso publicadas. El crédito del Gateway lleva una comisión de procesamiento del 3%, exenta hasta el 31 de diciembre de 2026.

**Eve** es pago por uso vía Vercel. Pro cuesta $20/mes con un crédito de uso de $20. Workflows, Sandbox, Functions, almacenamiento Blob y tokens del modelo suman coste a medida que crece el tráfico, así que el gasto es más difícil de predecir.

Así quedan las cuentas a diferentes escalas:

| Escenario | Mastra | Eve |
|---|---|---|
| **Dev solo, 1 agente, poco tráfico** | Gratis (autoalojado) o el plan Free de la plataforma | Cuotas de Hobby: 5 horas de CPU de sandbox, 50K eventos de workflow, cron una vez al día |
| **Equipo pequeño, 5 agentes, tráfico moderado** | $25 Starter o el plan Team de $250 | $20/mes de Pro más uso |
| **Flota en producción, 20+ agentes, mucho tráfico** | Enterprise (personalizado) | Escala con el cómputo, potencialmente significativo |

La plataforma de Mastra es más predecible. Eve puede ser más barato para cargas de trabajo intermitentes; para agentes siempre activos, la memoria del sandbox es la línea a vigilar.

### Memoria, estado y ejecución durable

**Mastra** tiene cuatro partes de memoria: historial de mensajes, memoria de trabajo, recuerdo semántico y memoria observacional. Mastra reporta un 94.87% en LongMemEval para la memoria observacional con GPT-5 mini. Los procesadores de memoria recortan el contexto cuando se llena, y la memoria observacional lanza llamadas al modelo en segundo plano que suman coste. Para una mirada más profunda a los enfoques de memoria de agentes, consulta [Cognee vs Hindsight](/es/cognee-vs-hindsight/).

**Eve** ejecuta cada sesión como un workflow sobre el Workflow SDK de código abierto, así que los checkpoints sobreviven a caídas, redespliegues y arranques en frío, tanto en Vercel como en tu propio servidor. Desde la 1.0 también tiene memoria entre sesiones: cada slot es un archivo bajo `agent/memory/`, respaldado por memoria de archivos o un proveedor. Un proveedor es Hindsight, cubierto en esta [guía de despliegue de Hindsight con Docker](/es/desplegar-hindsight-docker/).

La diferencia práctica es menor que en junio de 2026. Mastra tiene el historial más largo y más tipos de memoria, incluidos hilos multiusuario. Eve empareja un sistema de memoria más joven con una durabilidad de sesión que no necesita configuración.

Ambos ofrecen ejecución durable. Mastra lo hace mediante suspend/resume de workflows y el harness (agentes durables, tareas en segundo plano, horarios). Eve guarda un checkpoint de cada paso de la sesión. Su documentación advierte de que la recuperación no hace que los efectos externos sean exactamente una vez, así que da a las herramientas con efectos irreversibles un id de operación estable.

## Alternativas que vale la pena considerar

Más allá de Mastra y Eve, hay algunas opciones que conviene conocer:

**Vercel AI SDK** es para casos de uso más simples. UI de streaming, enrutado de modelos, llamadas a herramientas básicas. Sin abstracciones de agente, sin memoria, sin workflows. Si eso es todo lo que necesitas, sáltate un framework de agentes completo.

**LangGraph.js** es el port a TypeScript de LangGraph. Más pesado, pero encaja mejor si tu equipo también usa LangGraph en Python y quiere el mismo modelo mental.

**Flue** es nuevo, filesystem primero como Eve pero agnóstico de plataforma. Vale la pena vigilarlo si te gusta la DX de Eve sin la dependencia de Vercel.

El patrón "agente como directorio" es común en 2026. Eve y Flue lo usan. Es una reacción contra el estilo cargado de boilerplate de frameworks anteriores.

Para una comparación de frameworks de estilo similar, consulta [Astro vs Next.js vs TanStack Start](/es/astro-vs-nextjs-vs-tanstack-start-cual-gana/).

Si quieres un agente de codificación con IA en lugar de un framework para construir agentes, [OpenCode Go](https://go.bitdoze.com/opencode-go) es un camino distinto. Para enrutado multi-modelo sin un framework de agentes completo, [Agent Router](https://go.bitdoze.com/agentrouter) unifica Claude Code, OpenAI Codex y Gemini CLI.

## Veredicto final: Mastra vs Eve en 2026

El trade-off ahora es **objetos tipados y elección libre de runtime, frente a un directorio de archivos con sesiones durables integradas**.

Para la mayoría de los equipos TypeScript que envían agentes a producción hoy, **Mastra es la apuesta más segura**. Es maduro, portable, cumple SOC 2 y está probado a escala. Su sistema de memoria cubre historial de mensajes, memoria de trabajo, recuerdo semántico y memoria observacional. Puedes desplegar en cualquier parte y mover la infraestructura sin reescribir agentes. Por eso construí mi propio [asistente de archivos/web/navegador sobre Mastra](/es/crear-agente-ia-mastra/) y sigo mejorándolo en abierto.

Para equipos que quieren un agente en Slack o Teams esta semana, **Eve es el arranque más rápido**. El filesystem primero mantiene cada responsabilidad en un archivo. El multicanal y las sesiones durables vienen de serie. Desde la 1.0 ya no es una apuesta beta, y el uso interno de Vercel (más de 100 agentes) sugiere que seguirá madurando.

Eve puede cerrar la brecha de madurez ahora que la 1.0 está fuera. Los docs y el ecosistema de Mastra aún necesitan trabajo. La competencia aquí es buena para ambos.

<Notice type="success" title="Lo esencial">

## Preguntas frecuentes

<Accordion label="¿Mastra es gratis?" group="faq" expanded="true">
Sí. El núcleo de Mastra es Apache 2.0 y puede autoalojarse sin coste. Mastra Platform tiene un plan Free con 100K eventos de observabilidad y 40 vCPU-horas. Starter cuesta $25/mes y Team $250/mes por workspace.
</Accordion>

<Accordion label="¿Puedo usar Eve sin Vercel?" group="faq" expanded="false">
Sí, desde la versión 1.0. `eve build` genera un servidor Node en `.output/` y `eve start` lo ejecuta en Node 24 o posterior. Tú aportas una credencial de modelo, almacenamiento persistente para el estado del workflow, una política de autenticación de rutas y un proxy inverso para `/eve/` y `/.well-known/workflow/`. En la ejecución de laboratorio, `GET /eve/v1/health` devolvió `ready` y una petición de sesión sin autenticación devolvió 401.
</Accordion>

<Accordion label="¿Qué framework tiene mejor soporte de TypeScript?" group="faq" expanded="false">
Ambos son solo TypeScript. Mastra ofrece definiciones de tipos más explícitas a través de sus clases Agent/Workflow/Step. Eve usa esquemas Zod para validar la entrada de herramientas y se apoya en convenciones. Ambos tienen buen soporte en el IDE.
</Accordion>

<Accordion label="¿La dependencia de Eve es tan mala como la de Next.js?" group="faq" expanded="false">
Menos que en junio de 2026. El núcleo es Apache 2.0 y cada sesión corre sobre el Workflow SDK de código abierto, en Vercel o en tu propio servidor. Las partes exclusivas de Vercel son `eve deploy`, Vercel Connect, Agent Runs y el Sandbox alojado. Autoalojar las reemplaza con tu propia autenticación, estado en disco o Postgres, y OpenTelemetry.
</Accordion>

<Accordion label="¿Qué pasa con el incidente de cadena de suministro de Mastra?" group="faq" expanded="false">
En junio de 2026, se secuestró una cuenta dormida de colaborador de Mastra. Unos 144 paquetes del scope `@mastra` se volvieron a publicar con una dependencia maliciosa, como [informó The Hacker News](https://thehackernews.com/2026/06/144-mastra-npm-packages-compromised-via.html). npm retiró las versiones maliciosas. Fija las dependencias y audita los paquetes; ese consejo aplica a cualquier proyecto npm.
</Accordion>

<Accordion label="¿Cuántas descargas y estrellas tiene cada framework?" group="faq" expanded="false">
El 28 de noviembre de 2026, `@mastra/core` tenía 14,741,397 descargas en npm en los 30 días anteriores y `eve` tenía 9,268,355. GitHub mostraba 29,866 estrellas para mastra-ai/mastra y 6,100 para vercel/eve. Fuente: api.npmjs.org y la API de GitHub.
</Accordion>

<Accordion label="¿Qué UI de desarrollo local incluye cada framework?" group="faq" expanded="false">
Mastra arranca Studio, una UI de navegador, con `mastra dev` en el puerto 4111; define la variable de entorno `PORT` para cambiarlo. Eve abre una UI de terminal con `eve dev`, donde `/traces` muestra las trazas locales y `--no-ui` corre sin interfaz.
</Accordion>
