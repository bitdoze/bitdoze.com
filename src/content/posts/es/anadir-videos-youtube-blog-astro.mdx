¿Quieres añadir vídeos de YouTube a tu blog de Astro sin actualizar nada a mano? Esta guía muestra cómo traer automáticamente los últimos vídeos de un canal a tu sitio con Astro 7 en tiempo de build con loaders de la Content Layer (SSG) o bajo demanda con islas de servidor `server:defer` (SSR).

Ambos métodos usan el feed RSS gratuito de YouTube (sin clave de API), y cubriré los problemas del mundo real: por qué el endpoint RSS a veces devuelve 404, por qué `maxresdefault.jpg` puede romper tu build y cómo migrar a la YouTube Data API cuando necesites más fiabilidad.

Tanto si usas el [tema gratuito de blog de Astro](https://www.bitdoze.com/es/crear-blog-astro-gratis/) como tu propia configuración, esta guía incluye código listo para copiar y pegar para ambos métodos.

## 🎯 Lo que aprenderás

<ListCheck>

- **SSG con loader personalizado de la Content Layer**: el método recomendado en tiempo de build, con seguridad de tipos
- **SSR con islas de servidor `server:defer`**: renderizado bajo demanda para actualizaciones en tiempo real
- **Feed RSS de YouTube**: cómo funciona, por qué puede dar 404 y cómo hacerlo resistente
- **Optimización de miniaturas**: el fallback `hqdefault.jpg` para evitar imágenes rotas
- **Ruta de actualización a la YouTube Data API**: sigue siendo gratuita a escala de blog y es más fiable que el RSS
- **Resolución de problemas**: caídas del RSS, miniaturas que faltan, fallos de islas

</ListCheck>

### Encuentra el ID de tu canal de YouTube desde un @handle

<Notice type="warning" title="Las URL de canal ahora muestran @handles, no IDs">

Las URL de los canales de YouTube tienen el formato `youtube.com/@tucanal`. Eso es un handle, no el ID `UC...` que necesita el feed RSS. Así se encuentra el ID real:

1. Abre la página de tu canal en un navegador
2. Clic derecho → **Ver código fuente de la página**
3. Busca (Ctrl+F) `"channelId":"UC` o `"externalId":"UC`
4. Copia la cadena `UC...`

Alternativamente, abre cualquier vídeo del canal y busca en el código fuente de la misma forma. El feed RSS solo devuelve los **~15 vídeos más recientes** por canal.

</Notice>

## 📡 Cómo funciona el feed RSS de YouTube (y por qué puede dar 404)

Ambos métodos de esta guía usan el mismo endpoint sin coste:

```
https://www.youtube.com/feeds/videos.xml?channel_id=YOUR_CHANNEL_ID
```

Sin clave de API, sin autenticación, sin cuota. Devuelve un feed Atom XML con los ~15 vídeos más recientes del canal: ID de vídeo, título, fecha de publicación, URL de la miniatura y más.

<Notice type="warning" title="Fiabilidad del feed RSS">

El endpoint RSS de YouTube tiene errores 404 y 500 intermitentes documentados. Estas caídas suelen concentrarse entre las 09:00 y las 12:00 UTC, afectan a canales distintos de forma aleatoria y pueden durar horas. Un header User-Agent de navegador **no** lo arregla de forma fiable.

Esto significa que un fetch ingenuo en tiempo de build puede fallar en un despliegue normal. La mitigación: usa `AbortSignal.timeout()` para acotar el tiempo del fetch, añade un reintento con backoff y, para SSG, guarda en el repo una copia JSON del último estado válido para que un tropiezo de YouTube nunca rompa tu build.

</Notice>

<Notice type="success" title="¿Por qué RSS y no la API?">

El RSS es gratuito y no requiere clave, pero no tiene SLA y está limitado a ~15 vídeos. La YouTube Data API es el camino resistente y de nivel profesional, y sigue siendo gratuita a escala de blog (1-3 unidades de API por actualización de las 10.000 diarias). Cubro la ruta de actualización en la [sección de la Data API](#-ruta-de-actualización-a-la-youtube-data-api-resistente-y-sigue-gratis) más abajo.

</Notice>

## 🏗️ Método 1: SSG con loader de la Content Layer (recomendado)

El enfoque moderno de SSG usa la **Content Layer API** de Astro con un loader personalizado. Esto sustituye al patrón antiguo de hacer fetch del RSS en el frontmatter de un componente y parsearlo con regex. Ventajas: seguridad de tipos con Zod, caché en el data store, tipos con `astro sync` y un componente que solo se ocupa de la presentación.

### Paso 1: Crea el loader de contenido de YouTube

Instala el parser de XML:

```bash
npm install fast-xml-parser
```

Crea el loader en `src/loaders/youtube.ts`:

```ts
// src/loaders/youtube.ts
import type { Loader } from 'astro/loaders';
import { z } from 'astro/zod';
import { XMLParser } from 'fast-xml-parser';

export function youtubeVideosLoader(options: {
  channelId: string;
  maxVideos?: number;
}): Loader {
  return {
    name: 'youtube-videos-loader',
    load: async ({ store, parseData, logger }) => {
      const url = `https://www.youtube.com/feeds/videos.xml?channel_id=${options.channelId}`;
      const res = await fetch(url, { signal: AbortSignal.timeout(10_000) });

      if (!res.ok) {
        logger.error(`YouTube feed returned ${res.status}`);
        return; // keeps prior data in store, build won't fail
      }

      const xml = new XMLParser({ ignoreAttributes: false }).parse(
        await res.text()
      );
      const entries = (xml.feed?.entry ?? []).slice(0, options.maxVideos ?? 6);

      store.clear();
      for (const entry of entries) {
        const id = entry['yt:videoId'];
        const data = await parseData({
          id,
          data: {
            id,
            title: entry.title,
            published: new Date(entry.published),
            thumbnail: `https://i.ytimg.com/vi/${id}/hqdefault.jpg`,
            url: `https://www.youtube.com/watch?v=${id}`,
          },
        });
        store.set({ id, data, digest: JSON.stringify(data) });
      }
    },
    schema: z.object({
      id: z.string(),
      title: z.string(),
      published: z.date(),
      thumbnail: z.string(),
      url: z.url(),
    }),
  } satisfies Loader;
}
```

<Notice type="info" title="¿Por qué un loader de la Content Layer?">

Un loader de la Content Layer te da seguridad de tipos (esquema Zod), caché en el data store (los datos anteriores sobreviven a un fetch fallido) y `astro sync` genera los tipos de la colección. El componente que renderiza los vídeos se queda simple: solo llama a `getCollection()`. Es el patrón que Astro recomienda para datos externos en tiempo de build.

</Notice>

### Paso 2: Registra el loader en `content.config.ts`

```ts
// src/content.config.ts
import { defineCollection } from 'astro:content';
import { youtubeVideosLoader } from './loaders/youtube';

export const collections = {
  youtube: defineCollection({
    loader: youtubeVideosLoader({
      channelId: import.meta.env.YOUTUBE_CHANNEL_ID,
      maxVideos: 6,
    }),
  }),
};
```

Añade el ID de tu canal a `.env`:

```bash
YOUTUBE_CHANNEL_ID=UCGsUtKhXsRrMvYAWm8q0bCg
```

Después genera los tipos de la colección:

```bash
npx astro sync
```

<Notice type="info" title="Ejecuta astro sync tras conectar el loader">

`npx astro sync` genera los tipos de TypeScript para tus colecciones. Ejecútalo tras cualquier cambio en `content.config.ts`. Los tipos te dan autocompletado y detectan errores en tiempo de build.

</Notice>

## 🚀 Método 2: SSR, islas de servidor con server:defer

El enfoque SSR usa `server:defer` para crear una **isla de servidor**. La página carga al instante con HTML estático y el componente de YouTube se renderiza bajo demanda en el servidor. No hace falta JavaScript en el cliente.

### Paso 1: Instala un adaptador

`server:defer` requiere un adaptador de servidor. **No** necesitas `output: 'server'`: mantén la salida `'static'` por defecto y solo la isla se renderiza bajo demanda. Es más ligero que renderizar en servidor todas las páginas.

<Tabs>
<Tab name="Adaptador Node">

```bash
npx astro add node
```

Esto configura `astro.config.mjs`:

```js
// astro.config.mjs
import { defineConfig } from 'astro/config';
import node from '@astrojs/node';

export default defineConfig({
  adapter: node({
    mode: 'standalone',
  }),
});
```

Compila y ejecuta:

```bash
astro build && node dist/server/entry.mjs
```

Para producción, [despliega el build SSR en un VPS](https://www.bitdoze.com/es/desplegar-astro-en-vps/): un VPS económico como [Hetzner](https://go.bitdoze.com/hetzner) o [Hostinger](https://go.bitdoze.com/hostinger-vps) funciona bien para esto.

_Los precios de los VPS subieron en 2026 — si estás replanteándote un servidor alquilado, mira [qué cambió y cuándo gana un mini PC](/es/subidas-precios-vps/)._

</Tab>
<Tab name="Adaptador Cloudflare">


### Paso 2: Crea el componente SSR con server:defer

```astro
---
// src/components/YouTubeVideosSSR.astro
import { Icon } from "astro-icon/components";

export interface Props {
  channelId: string;
  maxVideos?: number;
}

const { channelId, maxVideos = 6 } = Astro.props;

let videos: Array<{
  id: string;
  title: string;
  published: Date;
  thumbnail: string;
  url: string;
}> = [];
let error: string | null = null;

try {
  const response = await fetch(
    `https://www.youtube.com/feeds/videos.xml?channel_id=${channelId}`,
    { signal: AbortSignal.timeout(10_000) }
  );

  if (!response.ok) {
    throw new Error(`HTTP error! status: ${response.status}`);
  }

  const xmlText = await response.text();

  // Parse XML to extract video data
  const videoRegex =
    /<entry>.*?<yt:videoId>(.*?)<\/yt:videoId>.*?<title>(.*?)<\/title>.*?<published>(.*?)<\/published>.*?<\/entry>/gs;

  let match;
  while (
    (match = videoRegex.exec(xmlText)) !== null &&
    videos.length < maxVideos
  ) {
    const [, videoId, title, published] = match;
    videos.push({
      id: videoId,
      title: title
        .replace(/&amp;/g, "&")
        .replace(/&lt;/g, "<")
        .replace(/&gt;/g, ">")
        .replace(/&quot;/g, '"')
        .replace(/&#39;/g, "'")
        .replace(/&apos;/g, "'"),
      published: new Date(published),
      thumbnail: `https://i.ytimg.com/vi/${videoId}/hqdefault.jpg`,
      url: `https://www.youtube.com/watch?v=${videoId}`,
    });
  }
} catch (err: any) {
  console.error("Error fetching YouTube videos:", err);
  error = err.message;
}
---
```

<Notice type="info" title="Props serializables">

Las props que se pasan a una isla `server:defer` deben ser serializables. Si la URL de props serializadas supera los 2048 bytes, la isla cambia a POST y pierde la caché del navegador. Con un string `channelId` y un número `maxVideos`, estás muy por debajo del límite.

</Notice>

### Paso 3: Notas de operación y caché

Algunas cuestiones de producción para las islas de servidor:

**Los despliegues continuos necesitan `ASTRO_KEY`.** Si despliegas en varias regiones o haces reinicios escalonados, las props cifradas y el contenido del slot (cifrados desde Astro 6) necesitan una clave estable:

```bash
npx astro create-key
```

Establece la salida como variable de entorno `ASTRO_KEY` en tu CI o plataforma de hosting.

**Dentro de una isla, `Astro.url` apunta a `/_server-islands/...`**, no a la URL real de la página. Si necesitas la URL real, léela del header `Referer`.

**La caché de rutas de Astro 7** ya es estable. Puedes cachear la respuesta de la isla a nivel de CDN o de memoria:

```js
// astro.config.mjs
import { defineConfig, memoryCache } from 'astro/config';

export default defineConfig({
  cache: { provider: memoryCache() },
  routeRules: {
    '/': { maxAge: 300, swr: 60 },
  },
});
```

Esto es más idiomático que una caché `Map` hecha a mano (que falla en silencio en serverless/edge porque solo existe por proceso).

## 🔑 Ruta de actualización a la YouTube Data API (resistente y sigue gratis)

Cuando el RSS se queda corto —necesitas más historial, recuentos de visitas, duraciones o simplemente más fiabilidad— la YouTube Data API v3 es la actualización. A escala de blog, es prácticamente gratuita.

La cadena de llamadas:

1. `channels.list` → obtiene el ID de la playlist de subidas (1 unidad)
2. `playlistItems.list` → obtiene los IDs de vídeo de la playlist de subidas (1 unidad)
3. `videos.list` → obtiene títulos, miniaturas, duraciones y recuentos de visitas (1 unidad)

Total: **2-3 unidades por actualización** de una cuota por defecto de 10.000 unidades/día. Tendrías que actualizar miles de veces al día para llegar al límite.

<Notice type="success" title="Sigue siendo gratuita a escala de blog">

Un canal, un par de llamadas a la API por build = 1-3 unidades de 10.000/día. Nunca llegarás al límite. No hay opción de pagar por más cuota, solo un formulario de auditoría manual si necesitas más.

</Notice>

Gestiona la clave de API con `astro:env`:

```js
// astro.config.mjs
import { defineConfig, envField } from 'astro/config';

export default defineConfig({
  env: {
    schema: {
      YOUTUBE_API_KEY: envField.string({
        context: 'server',
        access: 'secret',
      }),
      YOUTUBE_CHANNEL_ID: envField.string({
        context: 'server',
        access: 'public',
      }),
    },
  },
});
```

Después, en tu loader o código de servidor:

```ts
import { YOUTUBE_API_KEY, YOUTUBE_CHANNEL_ID } from 'astro:env/server';

const res = await fetch(
  `https://www.googleapis.com/youtube/v3/channels?part=contentDetails&id=${YOUTUBE_CHANNEL_ID}&key=${YOUTUBE_API_KEY}`
);
const data = await res.json();
const uploadsPlaylistId =
  data.items[0].contentDetails.relatedPlaylists.uploads;
```

<Accordion label="¿Cómo funciona la cuota de la API de YouTube?" group="faq">

La cuota por defecto es de 10.000 unidades al día por proyecto de Google Cloud, y se reinicia a medianoche (hora del Pacífico). Llamadas baratas: `playlistItems.list`, `videos.list` y `channels.list` cuestan 1 unidad cada una. Llamada cara: `search.list` cuesta 100 unidades por llamada (o, según la documentación más reciente, tiene su propio cupo de 100 llamadas/día a 1 unidad cada una; el modelo de cuotas tiene algo de ambigüedad). Si recibes un 403 con `quotaExceeded`, has alcanzado el límite diario. Para el caso de este artículo (un canal, 2-3 llamadas por build), ni te acercarás.

</Accordion>

## 🖼️ Miniaturas y optimización de imágenes

<Notice type="warning" title="maxresdefault puede romper tu build">

`maxresdefault.jpg` (1280 px) **no está disponible para todos los vídeos**. Las subidas antiguas, los originales en baja resolución y algunos contenidos en directo o restringidos devuelven un 404. En el camino SSG con el componente `<Image>` de Astro, una miniatura remota que falta puede **romper el build**, porque `<Image>` descarga la imagen remota en tiempo de build.

Usa `hqdefault.jpg` (480 px) como opción segura: siempre está presente. También disponibles: `mqdefault.jpg` (320 px) y `default.jpg` (120 px).

</Notice>

<Accordion label="¿Qué tamaño de miniatura de YouTube debería usar?" group="faq">

| Tamaño | Resolución | ¿Siempre disponible? | Caso de uso |
|------|-----------|-------------------|----------|
| `default.jpg` | 120×90 | Sí | Vistas previas diminutas, no recomendado |
| `mqdefault.jpg` | 320×180 | Sí | Tarjetas pequeñas, móvil |
| `hqdefault.jpg` | 480×360 | **Sí** | **Opción recomendada** |
| `sddefault.jpg` | 640×480 | Normalmente | Buen equilibrio, 404 raros |
| `maxresdefault.jpg` | 1280×720 | **No** | Solo si verificas disponibilidad |

Para el camino SSG, usa `<Image format="webp" loading="lazy">` para optimización automática en tiempo de build. Para la isla SSR, un simple `<img loading="lazy">` con `i.ytimg.com` es más sencillo, ya que la optimización remota ocurre en tiempo de petición. Consulta [acelerar los builds de Astro](https://www.bitdoze.com/es/astro-ssg-optimizacion-build/) para más sobre el rendimiento del build.

</Accordion>

## ⚖️ Cuándo usar SSG frente a islas de servidor

### Usa SSG cuando:

<ListCheck>

- **El rendimiento es crítico**: el HTML estático carga al instante
- **No necesitas actualizaciones en tiempo real**: los vídeos se actualizan al recompilar
- **Quieres cero costes de servidor**: sin runtime, solo archivos estáticos
- **El SEO importa**: el contenido estático es fácil de rastrear
- **Prefieres la simplicidad**: sin adaptador ni infraestructura de servidor

</ListCheck>

### Usa islas de servidor cuando:

<ListCheck>

- **Las actualizaciones en tiempo real importan**: los vídeos aparecen justo tras publicarse
- **Ya tienes infraestructura de servidor**: un servidor Node.js o Cloudflare Workers
- **Quieres caché por componente**: `Cache-Control` en el endpoint de la isla
- **Necesitas los datos más recientes sin recompilar**: sin triggers de CI/CD

</ListCheck>

## 🔍 Resolución de problemas comunes

### El feed RSS no carga (404/500)

<Notice type="warning" title="Este es el problema nº 1 en producción">

El endpoint RSS de YouTube tiene caídas intermitentes documentadas; no es un problema de CORS. El riesgo real es un 404 durante tu build o el renderizado de la isla.

**Mitigación:**
- Usa `AbortSignal.timeout(5000)` para acotar el tiempo del fetch
- Añade un reintento con backoff exponencial (1 s, 2 s, 4 s)
- Para SSG: guarda en el repo una copia JSON del último estado válido y úsala cuando el feed falle
- Verifica que el feed responde antes de desplegar: `curl "https://www.youtube.com/feeds/videos.xml?channel_id=UC..."`

</Notice>

### Los vídeos no se muestran / miniaturas rotas

1. **Revisa el ID de tu canal**: usa el método del código fuente de los [requisitos previos](#encuentra-el-id-de-tu-canal-de-youtube-desde-un-handle). Un ID incorrecto devuelve un feed vacío, no un error.
2. **Revisa las URL de las miniaturas**: busca `hqdefault` o `maxresdefault` en el HTML generado. Si ves 404 de `maxresdefault`, cambia a `hqdefault` en tu loader.
3. **Revisa los logs del build**: el loader de la Content Layer registra errores con `logger.error()`. Busca `YouTube feed returned 4xx/5xx`.
4. **Comprueba el feed RSS directamente**: abre la URL en un navegador. Si da 404, espera y reintenta (las ventanas de caída suelen ser cortas).

### La isla de servidor no se renderiza

1. **Adaptador no instalado**: `server:defer` requiere un adaptador. Ejecuta `npx astro add node` o `npx astro add cloudflare`.
2. **`ASTRO_KEY` no definida**: en despliegues continuos o multirregión, las props cifradas no se pueden descifrar sin una clave estable. Ejecuta `npx astro create-key` y define la variable de entorno.
3. **Props demasiado grandes**: si las props serializadas superan los 2048 bytes, la isla cambia a POST y pierde la caché del navegador. Mantén las props pequeñas (ID de canal + número máximo está bien).
4. **Comprueba el endpoint directamente**: visita `/_server-islands/YouTubeVideosSSR` (o el nombre de tu componente) para ver si la isla responde.

### quotaExceeded de la API de YouTube

Un 403 con `quotaExceeded` significa que has alcanzado el límite diario de 10.000 unidades. A escala de blog (1-3 unidades/build) no debería pasar. Si pasa, busca llamadas accidentales a `search.list` (100 unidades cada una). No hay forma de pagar por más cuota, solo un formulario de auditoría manual para ampliaciones.

## Preguntas frecuentes

<Accordion label="¿Necesito una clave de API de YouTube?" group="faq">

No: el feed RSS (`/feeds/videos.xml`) funciona sin autenticación. Solo necesitas una clave de API si migras a la YouTube Data API v3 para más historial, recuentos de visitas o mayor fiabilidad. A escala de blog, la Data API es gratuita (1-3 unidades de 10.000/día).

</Accordion>

<Accordion label="¿Cuántos vídeos devuelve el feed RSS?" group="faq">

El feed RSS devuelve los **~15 vídeos más recientes** por canal. Si necesitas más, usa el endpoint `playlistItems.list` de la YouTube Data API, que puede paginar por toda la playlist de subidas.

</Accordion>

<Accordion label="¿Puedo usar esto con Cloudflare Pages?" group="faq">

Sí: instala el adaptador de Cloudflare con `npx astro add cloudflare`. Desde Astro 6, el servidor de desarrollo corre sobre `workerd` para mantener paridad. Necesitas **Wrangler `^4.125.0`** y debes verificar la `compatibility_date` generada. Consulta [desplegar tu blog de Astro en Cloudflare Pages](https://www.bitdoze.com/deploy-astrojs-cloudflare/) para la guía completa.

</Accordion>

<Accordion label="¿Qué versión de Astro necesito?" group="faq">

Los loaders de la Content Layer funcionan desde Astro 5.0 (diciembre de 2024). Las islas de servidor también funcionan desde Astro 5. Esta guía apunta a **Astro 7** (estable actual). A partir de Astro 6 se requiere **Node 22.12.0+**.

</Accordion>

<Accordion label="¿Funcionará esto con Astro 5?" group="faq">

Los loaders de la Content Layer funcionan desde Astro 5.0. Las islas de servidor también están soportadas. Sin embargo, Astro 6+ requiere Node 22.12.0+ e introdujo cambios importantes en el adaptador de Cloudflare. Si estás en Astro 5, el código funciona pero no obtendrás las mejoras de velocidad de build del compilador Rust de Astro 7.

</Accordion>
