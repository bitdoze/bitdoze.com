He usado los tres shells para trabajo real. Bash fue mi opción predeterminada durante años porque simplemente estaba ahí. Me pasé a Zsh cuando Oh My Zsh se hizo popular, y lo usé durante bastante tiempo. Después probé Fish por curiosidad, y se convirtió en mi shell de uso diario. Cada shell tiene su personalidad, y el mejor shell de Linux para ti depende de lo que te importa.

Esta comparación de Fish Shell vs Bash vs Zsh no es teórica. Voy a repasar lo que importa cuando te sientas y escribes comandos todos los días: sintaxis, autocompletado, rendimiento, plugins y los detalles que te muerden cuando cambias de shell.

## Fish vs Bash vs Zsh de un vistazo (2026)

| Característica | Fish | Bash | Zsh |
|---|---|---|---|
| Última estable | **4.9.3** (sep 2026) | **5.3** (jul 2025) | **5.9** (may 2022) |
| Autosugerencias | Integradas | No (necesita ble.sh) | Plugin (zsh-autosuggestions) |
| Resaltado de sintaxis | Integrado | No | Plugin (zsh-syntax-highlighting) |
| Completado con Tab | Completo, listo para usar | Básico | Bueno con plugins |
| Compatible con POSIX | No | Sí | Mayormente sí |
| Sintaxis de scripting | Propia | POSIX sh | Mayormente POSIX + extensiones |
| Archivo de configuración | `~/.config/fish/config.fish` | `~/.bashrc` | `~/.zshrc` |
| Predeterminado en Linux | No | Generalmente sí | No (predeterminado en macOS) |
| Escrito en | Rust (desde 4.0) | C | C |
| Configuración web | Sí (`fish_config`) | No | No |
| Gestores de plugins | Fisher, Oh My Fish (sin mantenimiento) | Ninguno integrado | Oh My Zsh, Antigen, zinit |

Zsh viene como shell predeterminado en macOS, así que si quieres Fish ahí tendrás que [configurar Fish Shell en macOS](/es/fish-shell-macos-configuracion/) por separado. La fila de "última estable" merece atención: Fish publicó seis versiones con novedades solo en 2026, mientras que Zsh no lanza una versión estable desde 2022.

## Autosugerencias y completados

Aquí es donde Fish toma ventaja de inmediato. Abre una instalación nueva de Fish, empieza a escribir, y obtienes sugerencias en gris de tu historial de comandos. Presiona la flecha derecha para aceptar. Sin configuración, sin plugins, nada que instalar. Escribí una guía completa sobre [autocompletado y sugerencias de Fish Shell](/es/fish-shell-autocompletado-sugerencias/) que cubre todo lo que este sistema puede hacer.

Bash no tiene nada parecido de serie. Puedes instalar `ble.sh` (sigue en desarrollo activo, aunque su última versión etiquetada es vieja - se instala desde git master) o usar `fzf` para búsqueda difusa en el historial, pero requiere esfuerzo.

Zsh lo consigue con `zsh-autosuggestions`, pero tienes que instalarlo tú mismo. Escribí una guía sobre [cómo habilitar autocompletado de comandos en Zsh](/es/activar-autocompletado-comandos-zsh/) si prefieres esa ruta.

Fish también analiza las páginas man para generar completados automáticamente. Escribe `git` y presiona tab, y obtienes completados para subcomandos, flags y nombres de ramas sin ninguna configuración adicional. Zsh puede igualar esto con la configuración adecuada (compinit más plugins), pero requiere trabajo. El completado con tab de Bash es muy básico en comparación.

Desde Fish 4.9.0, las abreviaturas también pueden mostrar descripciones en el paginador de completados - una pequeña mejora de calidad de vida que llevaba años pidiéndose. Si todavía no has probado las abreviaturas, mira [abreviaturas vs alias de Fish Shell](/es/fish-shell-abreviaturas-vs-alias/) para saber cuándo usar cada una.

## Resaltado de sintaxis

Fish resalta tus comandos mientras los escribes. Los comandos válidos tienen un color, los inválidos aparecen en rojo, y las cadenas de texto tienen su propio color. Puedes detectar errores tipográficos antes de presionar enter. Tengo una guía detallada sobre el [resaltado de sintaxis de Fish Shell](/es/fish-shell-resaltado-sintaxis/) si quieres ver cómo funciona internamente.

Zsh necesita `zsh-syntax-highlighting` para el mismo comportamiento. Escribí sobre [habilitar resaltado de sintaxis en Zsh](/es/activar-resaltado-sintaxis-zsh/) si lo quieres.

Bash no tiene resaltado de sintaxis integrado en absoluto.

## Scripting y compatibilidad con POSIX

Artículos antiguos (incluida la versión anterior de este) se equivocan con los datos de compatibilidad entre Fish y Bash.

Fish tiene su propia sintaxis de scripting que intencionalmente no es compatible con POSIX. Los desarrolladores de Fish tomaron esta decisión para obtener un lenguaje más limpio. La sintaxis es más fácil de leer:

<Tabs>
<Tab name="Sintaxis Fish">
```fish
# Fish - sintaxis más limpia
if test -f ~/.config/fish/local.fish
    source ~/.config/fish/local.fish
end

for file in *.txt
    echo $file
end

# Variables
set greeting "hello"
echo $greeting
```
</Tab>
<Tab name="Sintaxis Bash">
```bash
# Bash - estilo POSIX
if [ -f ~/.bashrc_local ]; then
    source ~/.bashrc_local
fi

for file in *.txt; do
    echo "$file"
done

# Variables
greeting="hello"
echo "$greeting"
```
</Tab>
</Tabs>

Ahora bien, la brecha al copiar y pegar es mucho menor que antes. Fish soporta `&&`, `||` y `$(command)` desde hace años (`&&`/`||` desde fish 3.0 en 2018, `$()` desde 3.4 en 2022), así que la mayoría de one-liners modernos se pegan sin problema. Fish 4.6.0 incluso añadió `|&` como escritura compatible con Bash de `&|`. Esto es lo que funciona y lo que no:

```fish
# Todo esto funciona en Fish hoy:
git pull && git push          # && desde fish 3.0 (2018)
echo (date)                   # sustitución nativa de fish
echo $(date)                  # $() desde fish 3.4 (2022)
some-command |& less          # |& alias de &| desde fish 4.6.0 (2026)

# Sigue siendo diferente de Bash:
env FOO=bar some-command      # en vez de FOO=bar some-command
set -gx FOO bar               # en vez de export FOO=bar
echo $status                  # en vez de $?
test -f /tmp/x && echo ok     # no existe [[ ]] - usa test o [
```

Lo que sigue fallando al pegar Bash en Fish:

<ListCheck>
<ul>
<li>Variables de entorno en línea: <code>FOO=bar command</code> no funciona. Usa <code>env FOO=bar command</code> o <code>set -x FOO bar</code>.</li>
<li><code>export FOO=bar</code> se convierte en <code>set -gx FOO bar</code>.</li>
<li><code>$?</code> es <code>$status</code> en Fish.</li>
<li>Las pruebas <code>[[ ]]</code> no existen. Usa <code>test</code> o <code>[</code>.</li>
</ul>
</ListCheck>

Bash tampoco está parado. Bash 5.3 llegó en julio de 2025 con una nueva sustitución de comandos sin fork (`${| command; }`) y una variable `GLOBSORT` para ordenar resultados de globs. Está mantenido activamente - solo que no trae las funcionalidades de UX interactiva (autosugerencias, resaltado de sintaxis) que Fish tiene integradas y Zsh consigue con plugins.

En la práctica, la diferencia de scripting importa menos de lo que pensarías. La mayor parte del tiempo estás ejecutando comandos, no escribiendo scripts de shell. Y cuando necesitas un script, pones `#!/bin/bash` al principio y lo ejecutas como script de Bash desde Fish. Para comandos personalizados específicos de Fish, revisa mi guía sobre [funciones de Fish Shell](/es/fish-shell-funciones-comandos-personalizados/).

<Notice type="info" title="Consejo de compatibilidad POSIX">
Puedes ejecutar cualquier script de Bash desde Fish. Solo usa `bash script.sh` o haz el script ejecutable con un shebang `#!/bin/bash`. La sintaxis no-POSIX de Fish solo afecta lo que escribes interactivamente y los scripts específicos de Fish.
</Notice>

## Configuración

Fish almacena su configuración en `~/.config/fish/config.fish` y soporta un directorio `conf.d/` para archivos de configuración modulares. También tiene una herramienta de configuración web: ejecuta `fish_config` y se abre un navegador donde puedes cambiar colores, ver funciones y establecer variables. Suena superfluo, pero es útil para previsualizar temas de colores rápidamente.

Desde la 4.7.0, Fish ya no aplica el tema por defecto en shells no interactivos, así que la salida de tus scripts queda limpia. Detalle pequeño, pero elimina el típico susto de "por qué la salida de mi script sale con colores".

Bash usa `~/.bashrc` (y a veces `~/.bash_profile`). Todo es edición manual.

Zsh usa `~/.zshrc`. Con Oh My Zsh instalado, obtienes un framework que gestiona plugins y temas, pero el archivo de configuración puede volverse largo. Cubrí algunos de los [mejores plugins de Oh My Zsh](/es/mejores-plugins-oh-my-zsh/) si estás en el equipo Zsh.

## Rendimiento y cadencia de versiones en 2026

Fish 4.0 fue reescrito de C++ a Rust, lanzado en febrero de 2025. A noviembre de 2026 la última estable es **4.9.3** (septiembre de 2026). Fish publicó versiones con novedades más o menos trimestrales durante 2026 - 4.5, 4.6, 4.7, 4.8 y 4.9 - además de parches rápidos. Desde la 4.5.0, Fish ya no lee terminfo en absoluto, eliminando por completo la dependencia de ncurses/terminfo.

Así se comparan las líneas de tiempo de lanzamientos:

![Línea de tiempo de versiones de Fish Shell vs Bash vs Zsh de 2022 a 2026](@assets/images/26/02/fish-shell-release-timeline-2026.svg)

Zsh 5.9 (mayo de 2022) sigue siendo la última versión estable - más de cuatro años sin una versión estable nueva. Bash 5.3 llegó en julio de 2025, así que Bash tampoco está congelado, pero va claramente a un ritmo más lento que Fish.

En velocidad bruta: el arranque de Fish se siente instantáneo en mis máquinas. Es ligeramente más pesado que un shell Bash básico, pero la diferencia se mide en milisegundos y no lo vas a notar. Zsh con Oh My Zsh cargado y varios plugins puede ser notablemente lento al iniciar, a veces tardando más de un segundo. Hay soluciones (carga diferida, gestores de plugins más ligeros como zinit), pero es algo que tienes que gestionar activamente. Bash puro arranca más rápido porque es el más minimalista.

Para uso interactivo, Fish se siente el más ágil porque las autosugerencias y los completados funcionan al instante. El rendimiento que más importa para un shell es lo rápido que responde mientras escribes, y Fish gana aquí.

Estas son impresiones del día a día, no números de benchmarks. No he ejecutado benchmarks rigurosos de arranque de shell, y encontrarás números muy distintos según tu configuración y plugins.

Fish 4.7 y 4.8 también arreglaron problemas históricos de fiabilidad del historial: corrupción con bytes NUL cuando el shell recibía SIGTERM/SIGHUP (#10300), y búsqueda en el historial entre sesiones concurrentes. Si usas varios paneles de tmux o sesiones SSH y te importa el historial del shell, esto importa. Para gestionar varias sesiones de terminal, mira mi guía de los [mejores multiplexores de terminal](/es/mejores-multiplexores-terminal/).

## Ecosistemas de plugins

Fish tiene dos gestores de plugins principales:

- **[Fisher](https://github.com/jorgebucaran/fisher)** - ligero, rápido, sin configuración. Unas 9.500 estrellas a noviembre de 2026. Ejecuta `fisher install author/plugin` y listo.
- **[Oh My Fish](https://github.com/oh-my-fish/oh-my-fish)** - un framework similar a Oh My Zsh. Su README sigue abriendo con una advertencia de que lleva años sin mantenimiento. Yo recomendaría Fisher para instalaciones nuevas, pero si tienes curiosidad, tengo una guía sobre [instalación y uso de Oh My Fish](/es/oh-my-fish-instalar-temas-plugins/).

Profundizo mucho más en esto en [Mejores plugins y herramientas para Fish Shell](/es/mejores-plugins-fish-shell/).

Zsh tiene el ecosistema de plugins más grande gracias a Oh My Zsh, que tiene unos 370 plugins y 140 temas (recuento real del repo a noviembre de 2026). El propio Oh My Zsh supera las 190.000 estrellas en GitHub. Antigen, zinit y zplug son gestores de plugins alternativos con diferentes perfiles de rendimiento.

Para historial compartido entre shells, [Atuin](https://github.com/atuinsh/atuin) se ha convertido en la herramienta de referencia (unas 32.000 estrellas a noviembre de 2026). Funciona con Fish, Zsh y Bash, sincronizando tu historial con una búsqueda mejor que `Ctrl+R`. Si quieres entender cómo gestiona Fish el historial de forma nativa, mira [cómo funcionan la búsqueda y la persistencia del historial de Fish Shell](/es/fish-shell-historial-persistencia/).

Bash no tiene un ecosistema de plugins real. Existen frameworks de dotfiles como bash-it, pero la adopción es mucho menor.

## Curva de aprendizaje

Bash: probablemente ya lo conoces. Está en todas partes, y la mayoría de tutoriales de Linux asumen que lo estás usando. Si necesitas repasar los [comandos esenciales de Linux](/es/comandos-linux/), funcionan igual en todos los shells - solo cambia la fontanería del shell (variables, sustitución, pruebas).

Zsh: casi sin curva de aprendizaje viniendo de Bash. La sintaxis es casi idéntica, y Oh My Zsh proporciona una experiencia guiada. Es esencialmente Bash con extras.

Fish: hay un pequeño periodo de adaptación. Las diferencias de sintaxis te confunden durante el primer día o dos, especialmente en torno a la asignación de variables (`set` en lugar de `=`) y la sustitución de comandos. Después de eso, las funcionalidades integradas significan que tienes menos que aprender en general porque no necesitas configurar tanto.

## Cuándo usar qué shell en 2026

Este es mi flujo de decisión para elegir el mejor shell de Linux en 2026:

![Flujo de decisión para elegir shell: scripts portables a Bash, UX sin configuración a Fish, ecosistema OMZ a Zsh](@assets/images/26/02/fish-shell-decision-flow-2026.svg)

**Elige Fish si** quieres un shell que funcione bien desde el primer momento, no escribes scripts POSIX con frecuencia, y valoras las autosugerencias y el resaltado de sintaxis sin configuración. El impulso de Fish en 2026 (seis versiones con novedades, una reescritura en Rust estable) lo convierte en una apuesta sólida. Si esto te describe, revisa [cómo instalar Fish Shell en Ubuntu](/es/instalar-fish-shell-ubuntu/) para empezar.

**Elige Zsh si** quieres sintaxis compatible con Bash con funcionalidades modernas mediante plugins. Te sientes cómodo configurando cosas. Oh My Zsh te da una gran comunidad y montones de temas, aunque la cadencia de versiones se haya ralentizado.

**Elige Bash si** escribes scripts de shell que necesitan ejecutarse en cualquier lugar, trabajas en servidores donde Bash es el único shell disponible, o prefieres la máxima compatibilidad POSIX. Bash 5.3 está mantenido activamente - solo que no persigue funcionalidades de UX interactiva.

Los tres shells son gratis. El coste es la consistencia. Usa Fish donde controles el entorno (estación de trabajo, VPS gestionado con dotfiles), y Bash en el resto (shells de rescate, contenedores mínimos, runners de CI). Mantén los scripts de automatización como `#!/bin/bash` sea cual sea tu shell de login.

### Los paquetes de las distros van con retraso: Fish actual en un VPS

Fish publica versiones cada trimestre, pero los paquetes de las distros van muy por detrás. Es una trampa real si sigues una guía de "apt install fish y ya":

- **Debian 13 "trixie" (estable)** trae fish 4.0.2 - nueve versiones con novedades por detrás de la 4.9.3.
- **Ubuntu 24.04 LTS** trae fish 3.7.0, la vieja build en C++ anterior a Rust.

En un VPS, no confíes en `apt install fish` para tener Fish actual. Usa el binario independiente. Si quieres una máquina de desarrollo barata donde controles el entorno del shell, un [VPS de Hetzner Cloud](https://go.bitdoze.com/hetzner) cuesta unos pocos euros al mes y te da acceso root completo.

Esta es la ruta de instalación con el binario:

```bash
# 1. Descarga el binario independiente (ejemplo x86_64)
#    Saca la URL exacta de https://github.com/fish-shell/fish-shell/releases
wget https://github.com/fish-shell/fish-shell/releases/download/4.9.3/fish-4.9.3-linux-x86_64.tar.xz

# 2. Extrae e instala
tar -xJf fish-4.9.3-linux-x86_64.tar.xz
sudo cp fish-4.9.3-linux-x86_64/bin/* /usr/local/bin/

# 3. Registra el shell (obligatorio antes de chsh)
echo /usr/local/bin/fish | sudo tee -a /etc/shells

# 4. Establécelo como shell de login
chsh -s /usr/local/bin/fish
```

Verifica la instalación:

```bash
fish --version
# Esperado: fish, version 4.9.3

grep fish /etc/shells
# Esperado: /usr/local/bin/fish
```

<Notice type="warning" title="Los servidores se quedan con Bash">
Tu shell de login y tu shell de scripts son cosas distintas. `chsh` solo afecta a los logins interactivos. Mantén los scripts como `#!/bin/bash` sea cual sea tu shell de login. Fish interactivo en tu estación de trabajo o en un VPS gestionado con dotfiles está bien - los servidores a los que entras por SSH para administración deberían quedarse con Bash. Si alguna vez necesitas deshacerlo: `chsh -s /bin/bash` restaura el shell de login, y `rm /usr/local/bin/fish*` elimina la instalación independiente.
</Notice>

Si estás en Ubuntu y quieres una ruta más sencilla que se mantiene al día, la guía de [instalar el último Fish Shell en Ubuntu](/es/instalar-fish-shell-ubuntu/) cubre la vía del PPA.

<Accordion label="Errores comunes de instalación" group="install-errors">

**`chsh: /usr/local/bin/fish is not in /etc/shells`**
El binario independiente no está registrado. Solución: `echo /usr/local/bin/fish | sudo tee -a /etc/shells`, y reintenta `chsh`.

**Compilar desde el tarball fuente de GitHub falla**
El "Source code (tar.gz)" autogenerado de GitHub no compila. Usa el tarball fuente oficial `fish-4.9.3.tar.xz` de los assets de la release - trae el sistema de build preconfigurado.

**`apt install fish` instala una versión antigua**
Es lo esperado. Debian estable y Ubuntu LTS van meses por detrás. Usa el binario independiente o el PPA de fish-shell. Fija la versión y trata las actualizaciones como las de cualquier herramienta pequeña.

</Accordion>

## Mi opinión

Un año de desarrollo rápido de Fish 4.x ha validado la apuesta. Fish publicó seis versiones con novedades en 2026, la reescritura en Rust aguanta bien, y el proyecto sigue sacando mejoras de calidad de vida (descripciones en abreviaturas, arreglos de fiabilidad del historial, compatibilidad `|&`). Mientras tanto, la estable de Zsh sigue siendo la 5.9 de 2022.

Me pasé a Fish y no he mirado atrás. La experiencia de uso desde el primer momento es simplemente mejor que cualquier cosa que logré construir con plugins de Zsh. Las autosugerencias, el resaltado de sintaxis, los completados de páginas man y la sintaxis de scripting limpia hacen el trabajo diario más rápido.

La incompatibilidad con POSIX me molestó durante una semana aproximadamente. Aprendí a usar `bash -c 'command'` para los comandos ocasionales, y mantengo mis scripts de automatización como scripts de Bash. No es un problema.
