Casi todo desarrollador acaba buscando un sustituto de Docker Desktop por una de dos razones: los ventiladores del MacBook se disparan con tres contenedores en reposo, o compras ha revisado la licencia comercial de Docker (gratis para uso personal y empresas de menos de 250 empleados y menos de 10 millones de dólares de facturación, de pago por encima).

En 2026 las alternativas son mucho más sólidas. OrbStack se ha consolidado en Mac, Colima sigue siendo ligero y gratuito, Podman Desktop cerró casi todas las brechas con Compose y un nuevo runtime escrito en Rust llamado **Kiri** aterrizó en beta con una arquitectura distinta. Aquí tienes cómo se comparan en licencias, uso diario y migración sin romper tus archivos `docker compose`.

## Comparativa rápida (noviembre 2026)

| Herramienta | Licencia y precio comercial | Plataformas | Motor / Arquitectura | GUI | Kubernetes local |
|---|---|---|---|---|---|
| **OrbStack** | Propietaria; gratis personal, **$8/usuario/mes** comercial ($96/año) | Solo macOS | VM ligera propia + motor Docker | App nativa macOS | k8s de un nodo integrado |
| **Colima** | **MIT** (gratis para todo uso) | macOS, Linux | VM Lima + Docker o containerd | Ninguna (solo CLI) | `colima start --kubernetes` (k3s) |
| **Kiri (0.2.2 beta)** | Gratis durante la beta (propietaria) | macOS, Windows (WSL2), Linux nativo | Un solo demonio Rust con `clone3` (sin shim por contenedor) | Nativa AppKit / Win32 | `kiri k8s start` (k3s, ~20s) |
| **Podman Desktop** | **Apache-2.0** (gratis para todo uso) | macOS, Windows, Linux | Podman (rootless, sin demonio) | App Electron | Plugins kind / minikube |
| **Rancher Desktop** | **Apache-2.0** (gratis para todo uso) | macOS, Windows, Linux | Lima / WSL2 + containerd o `dockerd` | App Electron | k3s integrado (elige versión exacta) |

Si trabajas a diario en **Linux**, no necesitas ninguno de estos: Docker Engine nativo (`docker-ce`) es gratuito, no usa VM y funciona directo sobre tu kernel. Esta lista es sobre todo para macOS y Windows (o equipos Linux que quieren el modelo rootless de Podman o el demonio de Kiri).

## 1. OrbStack: el cambio más fácil en macOS

Si usas Mac y quieres borrar Docker Desktop en cinco minutos sin tocar un solo script, OrbStack sigue siendo la transición con menos fricción. Arranca en segundos, devuelve RAM sin usar a macOS, soporta Rosetta para imágenes `linux/amd64` en Apple Silicon y da a cada contenedor un dominio automático `*.orb.local` con HTTPS.

Las máquinas Linux integradas (`orb create ubuntu`) son un extra muy práctico para probar playbooks o paquetes Linux compartiendo tus carpetas del Mac.

Las dos pegas son claras: **solo existe para macOS** (no sirve para equipos mixtos Mac/Windows) y el uso comercial o freelance cuesta **$8/usuario/mes** ($96/año). Para proyectos personales es gratis; para empresas que buscan eliminar licencias por asiento, solo cambia una factura por otra más barata.

## 2. Colima: gratuito, abierto y pensado para terminal

Colima (`brew install colima docker docker-compose`) envuelve Lima y te da un demonio Docker estándar mediante un contexto (`colima`). Sin Electron, sin pantallas de login, licencia MIT para cualquier empresa.

```bash
brew install colima docker docker-compose
colima start --cpu 4 --memory 8 --vm-type vz --vz-rosetta --mount-type virtiofs
docker context use colima
```

Usar `--vm-type vz --mount-type virtiofs` en Apple Silicon acerca el rendimiento de los volúmenes al de OrbStack. Sin esos flags, Colima cae en opciones más lentas, que es de donde vienen casi todas las quejas sobre su velocidad de disco.

La pega es que no trae interfaz gráfica. Si quieres ver logs y contenedores visualmente, combínalo con Lazydocker o una UI ligera como [Dockhand o Arcane](/es/arcane-vs-dockhand/). Para equipos cómodos en terminal con presupuesto cero por asiento, Colima es difícil de batir.

## 3. Kiri (0.2.2 beta): el recién llegado escrito en Rust

[Kiri](https://runkiri.com/) generó mucho ruido en Hacker News en noviembre de 2026 porque cambia cómo habla el runtime con el kernel. Docker Desktop y OrbStack pasan cada `docker run` por cinco capas (`docker` CLI, `dockerd`, `containerd`, `containerd-shim`, `runc`) dejando un proceso shim residente por contenedor. Kiri reduce todo a un único demonio Rust dentro de una VM mínima en macOS (WSL2 en Windows, `clone3` nativo en Linux) sin shims por contenedor.

Según los benchmarks publicados por Kiri en Apple Silicon (límite 2 CPU / 8 GB por motor), `docker run --rm alpine true` tarda **22 ms** en Kiri frente a **152 ms** en Colima, **178 ms** en Docker Desktop y **279 ms** en OrbStack, con un demonio en reposo de ~15 MB y arranque en frío de 112 ms. Habla la API de Docker directamente, así que `docker`, `docker compose` y `buildx` funcionan sin cambios, además de incluir:

- Dominios HTTPS locales automáticos `myapp.kiri.local`
- `kiri k8s start` para levantar k3s local y `kiri machine create` para máquinas Linux
- `kiri share web` para compartir un contenedor local mediante HTTPS público temporal en `runkiri.cloud`
- Migración directa de imágenes y volúmenes desde Docker Desktop u OrbStack en Mac

La advertencia honesta: Kiri está en **beta 0.2.2**, es propietario y todavía no hay precios post-beta. Pruébalo en tu equipo personal si buscas velocidad bruta, y mantén Colima o Podman Desktop como red estable en equipo hasta que llegue a 1.0 con licencia definitiva.

## 4. Podman Desktop: GUI gratuita y contenedores rootless

Podman Desktop (Apache-2.0) es la mejor opción cuando tu equipo mezcla Windows y macOS, no quiere cuotas por usuario y necesita interfaz visual. Al ser rootless y sin demonio central por defecto, un contenedor comprometido no puede escalar a través de un socket root. Detallé las diferencias internas en [Podman vs Docker](/es/podman-vs-docker/).

Incluye un socket de compatibilidad con Docker para mantener la mayoría de comandos y archivos Compose, además de exportar manifiestos de Kubernetes (`podman generate kube`).

Dónde conviene probar antes: Testcontainers, scripts viejos de Compose con dependencias específicas de red de Docker y permisos UID en montajes rootless. Ejecuta siempre tu stack real en Podman antes de migrar a todo un equipo.

## 5. Rancher Desktop: ideal si necesitas fijar versiones de Kubernetes

Si tu trabajo exige replicar una versión exacta de k3s/Kubernetes en local, Rancher Desktop (Apache-2.0, macOS/Windows/Linux) permite elegir la versión exacta desde un desplegable y alternar entre `containerd` (`nerdctl`) o `dockerd`. Para uso puro de Docker Compose resulta más pesado que Colima u OrbStack.

## Cómo migrar sin romper tu entorno

<Tabs>
<Tab name="macOS (Colima)">

```bash
# 1. Cierra Docker Desktop primero para evitar conflictos de puertos
# 2. Instala las herramientas CLI y Colima
brew install colima docker docker-compose docker-buildx

# 3. Inicia con Apple Virtualization.framework + VirtioFS
colima start --cpu 4 --memory 8 --disk 60 --vm-type vz --vz-rosetta --mount-type virtiofs

# 4. Comprueba que el CLI de docker apunta a Colima
docker context ls
docker run --rm hello-world
```

</Tab>
<Tab name="macOS (OrbStack / Kiri)">

Tanto OrbStack (`brew install --cask orbstack`) como Kiri (`.dmg` desde `runkiri.com`) configuran su contexto Docker automáticamente y ofrecen un asistente para importar imágenes y volúmenes desde Docker Desktop. Verifica el contexto activo antes de desinstalar Docker Desktop:

```bash
docker context ls
docker compose version
```

</Tab>
<Tab name="Windows y multiplataforma (Podman)">

```powershell
# Windows con winget
winget install RedHat.Podman-Desktop

# Inicializa la máquina Podman (WSL2 en Windows)
podman machine init --cpus 4 --memory 8192
podman machine start
```

Activa **Docker Compatibility** en los ajustes de Podman Desktop si tus scripts llaman a `docker` en vez de `podman`.

</Tab>
</Tabs>

<Notice type="info" title="Qué suele romperse al dejar Docker Desktop">
Las imágenes y volúmenes locales no se transfieren solos (salvo usando el importador de OrbStack o Kiri). Haz un `pg_dump` o `mysqldump` de tus bases locales antes de borrar nada y revisa scripts que fijen `/var/run/docker.sock` a mano en lugar de leer `DOCKER_HOST` o el contexto activo. Repasa los comandos de contexto y limpieza en mi [guía de comandos Docker](/es/comandos-docker/).
</Notice>

## ¿Cuál te conviene?

<ListCheck>
<ul>
<li><b>Desarrollador individual en macOS:</b> OrbStack (gratis para uso personal, muy pulido). Prueba Kiri 0.2.2 si quieres experimentar con arranques instantáneos y enlaces públicos rápidos.</li>
<li><b>Usuario de Mac que quiere 100% código abierto:</b> Colima con `--vm-type vz --mount-type virtiofs`.</li>
<li><b>Equipo mixto Mac + Windows sin licencias por asiento:</b> Podman Desktop (o Rancher Desktop si fijáis versiones de Kubernetes).</li>
<li><b>Escritorio Linux o servidor casero:</b> Ninguno de los anteriores. Instala Docker Engine nativo y monta tu [stack de contenedores Docker en casa](/es/contenedores-docker-servidor-casa/).</li>
</ul>
</ListCheck>

## Preguntas frecuentes

<Accordion label="¿De verdad tengo que pagar por Docker Desktop?" group="faq" expanded="true">
Solo en empresas comerciales con 250 o más empleados o más de 10 millones de dólares de ingresos anuales. Uso personal, proyectos open source, educación y pequeñas empresas por debajo de ambos límites siguen siendo gratuitos.
</Accordion>

<Accordion label="¿OrbStack es gratis para freelance o empresa?" group="faq">
No. OrbStack es gratis únicamente para uso personal no comercial. El trabajo freelance y empresarial requiere OrbStack Pro a $8/usuario/mes ($96/año), con 30 días de margen.
</Accordion>

<Accordion label="¿Mis archivos docker-compose.yml siguen funcionando en Colima o Kiri?" group="faq">
Sí. Ambos responden a la API estándar de Docker Engine, así que `docker compose up -d` funciona igual. Solo revisa rutas fijas a `/var/run/docker.sock`, ya que cada runtime coloca su socket en la ruta del contexto activo.
</Accordion>

<Accordion label="¿Puede Kiri reemplazar a OrbStack hoy?" group="faq">
Para pruebas personales sí, y su demonio único es realmente rápido. Para trabajo crítico diario, trátalo como software beta 0.2.2 hasta que alcance 1.0 y publique precios definitivos.
</Accordion>
