## ¿Qué es AssemblyAI?

Una API de voz a texto alojada en la nube, de una empresa fundada en 2017 por Dylan Fox. Envías audio por HTTPS o por un WebSocket y recibes texto, marcas de tiempo por palabra y etiquetas de hablante. Los extras opcionales incluyen resúmenes, análisis de sentimiento y redacción de datos personales (PII). Los modelos corren en la nube de AssemblyAI, en una región de EE. UU. o de la UE. No puedes descargarlos.

Cuatro endpoints cubren casi todos los casos de uso, y cada uno tiene su precio:

![Diagrama de los cuatro endpoints de AssemblyAI: los archivos grabados van a la API pregrabada a 0,21 $ por hora, las reuniones en directo van al modelo Realtime a 0,30 $, los agentes de voz van al modelo Realtime-Agent a 0,45 $ y la escritura por voz va a la Dictation API a 0,62 $ con la limpieza incluida](@assets/images/26/11/assemblyai-endpoints.svg)

El diagrama es el modelo de precios en una imagen. Un archivo grabado es la entrada más barata porque nadie lo está esperando. AssemblyAI factura un stream en directo por el tiempo que el WebSocket permanece abierto, no por la cantidad de audio que envías. Cobra más por hora que por un archivo. La Dictation API cuesta cerca de tres veces la tarifa de archivo, y esa tarifa ya incluye un paso de LLM que quita las muletillas y resuelve las autocorrecciones.

Los tres endpoints de voz usan modelos de la familia AssemblyAI-STT-3.7, publicada el 17 de noviembre de 2026. La Dictation API usa el modelo de streaming anterior, Universal-3.6 Pro, y añade el paso de limpieza:

## ¿Qué tal es la diarización de hablantes de AssemblyAI?

Lo bastante buena para confiar en ella en mis pruebas. Etiquetó a 5 de 5 hablantes reales en un archivo y a 10 de 10 segmentos en otro, donde Fish Audio y Deepgram fusionaron dos voces cada uno. La diarización es también donde AssemblyAI ganó a Fish Audio por el margen más amplio. El diálogo a dos voces volvió como seis enunciados, cada uno con una letra de hablante y tiempos de inicio y fin en milisegundos. Con los cinco lectores de LibriSpeech, AssemblyAI devolvió cinco etiquetas, de la A a la E, una por voz. Fish Audio devolvió cuatro etiquetas para el mismo audio y fusionó a dos lectores distintos.

Activarla lleva un solo campo:

```json
{
  "audio_url": "https://example.com/meeting.wav",
  "speech_models": ["assemblyai-stt-3-7"],
  "speaker_labels": true
}
```

Dos ajustes opcionales cambian el resultado. `speakers_expected` fija un número exacto, y la documentación lo describe como un límite estricto: si pasas un número equivocado, el modelo divide o fusiona hablantes para encajarlo. `speaker_options` acepta un rango, que es lo que la documentación recomienda cuando no estás seguro:

```json
{
  "audio_url": "https://example.com/meeting.wav",
  "speech_models": ["assemblyai-stt-3-7"],
  "speaker_labels": true,
  "speaker_options": {
    "min_speakers_expected": 2,
    "max_speakers_expected": 5
  }
}
```

El número de hablantes es opcional. En un segundo archivo con cinco voces, diez frases mezcladas para que cada hablante vuelva después de otros dos, probé cinco ajustes. El valor por defecto, un rango de 2 a 6 y un 5 exacto produjeron las mismas cinco etiquetas correctas. También un rango de 8 a 10, fijado demasiado alto. Un 3 exacto, que era incorrecto, fusionó tres voces en una sola etiqueta, que es de lo que avisa la documentación. Deja margen por encima del número que esperas, pero no mucho. La documentación también pide al menos 30 segundos de habla continua por hablante para obtener los mejores resultados. Mi diálogo de 32 segundos nunca llegó a eso y salió bien. Trata los 30 segundos como una guía y no como un requisito para llamar a la API.

En streams, la diarización cuesta +0,12 $ por hora, seis veces el precio de la misma función en archivos.

## ¿AssemblyAI admite streaming y agentes de voz?

Sí, con dos modelos de streaming: `assemblyai-stt-3-7-realtime` a 0,30 $ por hora de sesión y `assemblyai-stt-3-7-realtime-agent` a 0,45 $. No ejecuté ninguna sesión de streaming, así que el resto de esta sección resume lo que AssemblyAI publica. El modelo Realtime es para reuniones en directo, subtítulos y tomadores de notas. Las etiquetas de hablante son definitivas en el momento en que termina un turno. Las transcripciones parciales llegan aproximadamente una vez por segundo, y los 32 idiomas funcionan en un solo stream con detección automática. El modelo Realtime-Agent es para agentes de voz. Decide cuándo el interlocutor ha terminado de hablar. En el benchmark de AssemblyAI devuelve la transcripción final 86 ms después de que termina el habla, frente a 172 ms del modelo que sustituye.

Ambos hacen streaming desde `wss://streaming.assemblyai.com/v3/ws`. AssemblyAI desconectó el antiguo endpoint v2, así que los tutoriales antiguos fallan al conectar. Un agente de voz completo es Realtime-Agent para escuchar, el LLM Gateway para la respuesta y la API de TTS para pronunciarla. La Voice Agent API independiente se retira el 1 de febrero de 2027.

Las cuentas de pago empiezan con 200 streams nuevos por minuto, y el límite sube un 10 % cada minuto que uses el 80 % o más. Las cuentas gratuitas se quedan en 5.

## ¿Qué sustituyó a LeMUR y cómo funcionan los resúmenes?

El LLM Gateway y los complementos de Speech Understanding sustituyeron a LeMUR, un modelo de resumen de audio que AssemblyAI dejó obsoleto el 31 de marzo de 2026. Los resúmenes pasan ahora por dos vías:

- Complementos de Speech Understanding sobre una transcripción terminada: resumen, tareas pendientes, capítulos, sentimiento, detección de entidades, detección de temas y frases destacadas. AssemblyAI los factura por hora de audio, como en la tabla de arriba.
- El LLM Gateway, un endpoint de chat compatible con OpenAI que da acceso a 65 modelos de OpenAI, Anthropic, Google y otros proveedores y factura por token. Úsalo cuando quieras tu propio prompt sobre la transcripción.

Ejecuté el complemento de resumen sobre un vídeo de dominio público de 9 minutos. La petición va dentro del trabajo de transcripción como `"speech_understanding": {"request": {"summarization": {"summary_type": "paragraph"}}}`, y el resultado es una lista de secciones con hora de inicio, titular y párrafo. Tres ejecuciones devolvieron 4, 5 y 5 secciones: los límites se mantuvieron cercanos y el texto de los titulares cambió cada vez, así que léelos antes de publicar. No ejecuté las tareas pendientes ni el LLM Gateway. Dos entradas de la propia documentación de AssemblyAI merecen la pena leerse antes de depender de ellas. La referencia de modelos lista `auto_chapters` y `summarization` en el antiguo Universal-3.5 Pro como una trampa conocida: el trabajo se cuelga y termina en un 500 genérico. Y una entrada del changelog del 23 de octubre de 2026 describe otro fallo. El resumen había estado fallando en el 2 al 4 % de las peticiones y en la mayoría de los archivos largos antes de una corrección.

## ¿Dónde falla AssemblyAI?

En la velocidad con clips cortos, las tres llamadas por archivo, los cambios de modelo y el límite de 32 idiomas en el mejor modelo.

La cola por lotes. Cada archivo gasta de 5 a 8 segundos de sobrecarga antes de que aparezca texto. Para un trabajo que transcribe miles de clips de noche, la cola es el diseño correcto. Para cualquier cosa que una persona esté mirando, es el endpoint equivocado.

Tres llamadas por archivo. Subir, enviar, consultar. [Deepgram](/es/assemblyai-vs-deepgram/) y Fish Audio devuelven cada uno una transcripción desde una sola petición HTTP, lo que supone menos código que escribir y menos código que puede fallar a mitad. Un webhook elimina las consultas, pero su carga útil solo contiene el ID de la transcripción y un estado. Tu handler hace igualmente una segunda petición para recuperar el texto.

Cambios de modelo. AssemblyAI dejó obsoleto Universal-3.5 Pro el día que se lanzó STT-3.7 y también figura Universal-3 Pro como obsoleto. Fija el ID del modelo en tus peticiones y lee la página de obsolescencias antes de actualizar una dependencia. Los nombres de los parámetros también se mueven: `word_boost` enviado junto a STT-3.7 redirige en silencio todo el trabajo a Universal-2.

Una lista de idiomas más corta en el mejor modelo. STT-3.7 maneja 32 idiomas. El resto va a Universal-2 a 0,15 $ por hora, y los propios niveles de precisión de AssemblyAI califican ese modelo como regular o moderado en decenas de ellos.

Los archivos se quedan en la nube. La opción de autoalojamiento cubre solo streaming y necesita un compromiso inicial de 50.000 $.

## ¿AssemblyAI cumple HIPAA y adónde va tu audio?

Sí, con un BAA que firmas desde el panel de control, y en cuanto sales del entrenamiento AssemblyAI borra el audio subido en un plazo de 24 a 48 horas.

Al registrarte, AssemblyAI puede usar tu audio para entrenar modelos hasta que desactivas el programa de mejora de modelos en el panel de control. Tras desactivarlo, AssemblyAI no conserva audio ni transcripciones de streaming, Sync y Dictation. En archivos, borra el audio subido en un plazo de 24 a 48 horas por defecto. Conserva la transcripción terminada durante 30 días, salvo que la borres o fijes un tiempo de vida más corto. Una petición `DELETE` a la URL de la transcripción la elimina cuando quieras.

El BAA de HIPAA es autoservicio, sin llamada de ventas ni sobreprecio, y SOC 2 Type 2 e ISO 27001 también van incluidos. Los endpoints de la UE (`api.eu.assemblyai.com`) cuestan lo mismo que los de EE. UU. Las dos opciones están disponibles en el pago por uso, lo que importa si tu audio son datos de salud que deben quedarse en Europa.

## Cómo empezar con AssemblyAI

1. Crea una cuenta en [AssemblyAI](https://go.bitdoze.com/assemblyai) y copia la clave API desde el panel de control. No necesitas tarjeta para los 50 $ de crédito.
2. Exporta la clave y ejecuta el script de abajo contra un archivo local.

La API pregrabada es un trabajo de cuatro pasos:

![Diagrama del flujo de petición por lotes de AssemblyAI en cuatro pasos: sube el archivo para obtener una URL, envía un trabajo de transcripción con el modelo y las etiquetas de hablante, espera un estado completado consultando o por webhook y después lee el texto, los enunciados por hablante, los tiempos por palabra y el SRT, con notas sobre autenticación, límites de consulta, webhooks y borrado](@assets/images/26/11/assemblyai-batch-flow.svg)

```bash
export ASSEMBLYAI_API_KEY=tu_clave

# 1. Sube el archivo y obtén una URL temporal
upload_url=$(curl -s -X POST https://api.assemblyai.com/v2/upload \
  -H "authorization: $ASSEMBLYAI_API_KEY" \
  --data-binary @meeting.wav | jq -r '.upload_url // empty')
[ -z "$upload_url" ] && { echo "upload failed"; exit 1; }

# 2. Lanza el trabajo
id=$(curl -s -X POST https://api.assemblyai.com/v2/transcript \
  -H "authorization: $ASSEMBLYAI_API_KEY" \
  -H "content-type: application/json" \
  -d "{\"audio_url\": \"$upload_url\",
       \"speech_models\": [\"assemblyai-stt-3-7\"],
       \"speaker_labels\": true}" \
  | jq -r '.id // empty')
[ -z "$id" ] && { echo "submit failed"; exit 1; }

# 3. Consulta hasta que termine
while :; do
  result=$(curl -s https://api.assemblyai.com/v2/transcript/$id \
    -H "authorization: $ASSEMBLYAI_API_KEY")
  status=$(echo "$result" | jq -r .status)
  [ "$status" = "completed" ] && break
  [ "$status" = "error" ] && { echo "$result" | jq -r .error; break; }
  sleep 1
done

# 4. Muestra una línea por turno de hablante
echo "$result" | jq -r '.utterances[] | "Speaker \(.speaker): \(.text)"'
```

Dos detalles hacen tropezar los primeros intentos. La cabecera `authorization` lleva la clave en bruto, sin el prefijo `Bearer`. La subida necesita `--data-binary @file`, porque con `-d` a secas se envía el nombre del archivo como texto y el trabajo falla con un error de transcodificación. Las consultas están limitadas a 60 peticiones por minuto por transcripción, y una respuesta 429 lleva una cabecera `Retry-After`. Las transcripciones por lotes conservan las muletillas por defecto. `disfluencies: false` es el interruptor documentado para quitarlas. En tres ejecuciones con mi clip de dictado quitó la muletilla una vez y la conservó dos, así que fíltralas en tu propio código si te importan.

Los SDK oficiales hacen los cuatro pasos en una llamada. El SDK de Python actual expone la API pregrabada bajo `assemblyai.prerecorded.v2`:

```python
import os

from assemblyai import TranscriptStatus
from assemblyai.prerecorded.v2 import Transcriber, TranscriptionConfig

config = TranscriptionConfig(
    speech_models=["assemblyai-stt-3-7", "universal-2"],
    language_detection=True,
    speaker_labels=True,
)

transcriber = Transcriber(api_key=os.environ["ASSEMBLYAI_API_KEY"])
transcript = transcriber.transcribe("meeting.wav", config=config)

if transcript.status == TranscriptStatus.error:
    raise RuntimeError(f"Transcription failed: {transcript.error}")

for utterance in transcript.utterances:
    print(f"Speaker {utterance.speaker}: {utterance.text}")
```

Para subtítulos, pide el SRT a la transcripción terminada en lugar de construirlo tú:

```bash
curl -s "https://api.assemblyai.com/v2/transcript/$id/srt?chars_per_caption=32" \
  -H "authorization: $ASSEMBLYAI_API_KEY" > meeting.srt
```

Cambia `srt` por `vtt` para obtener WebVTT. El endpoint SRT escribe bloques de hasta 32 caracteres, que pueden cortar un cambio de turno. Para un vídeo entero, con bloques que se cortan en cada hablante y una lista de capítulos para la descripción, mi [guía de YouTube a SRT](/es/transcribir-video-youtube-srt-assemblyai/) tiene un script probado.
