Si ejecutas WordPress (o cualquier aplicación) en un VPS, enviar correo directamente desde el servidor no es fiable. La mayoría de los proveedores de VPS bloquean el puerto 25, y aunque no lo hagan, el correo saliente de un servidor pelado acaba en spam. La solución es un **relay SMTP de ZeptoMail**: enrutar todo el correo saliente a través de un servicio de correo dedicado. (ZeptoMail ahora es Zoho CPaaS, y los ajustes SMTP no han cambiado.)

Yo uso [Zoho CPaaS (antes ZeptoMail)](https://www.zoho.com/cpaas/). Te dan un paquete gratuito de créditos para empezar (10.000 correos), y después compras créditos según necesites, sin suscripción mensual. La facturación es por pago por uso y los créditos caducan a los 6 meses. La entrega ha sido fiable para mí en varios servidores. Si usas CloudPanel, este mismo relay cubre el correo de WordPress, las notificaciones de cron y las alertas del sistema. Puedes [instalar WordPress con CloudPanel](/es/instalar-wordpress-ubuntu-arm/) y aprovechar para [asegurar tu instalación de CloudPanel](/es/securizar-cloudpanel/). Si prefieres resolver el correo a nivel de aplicación en vez de en todo el servidor, puedes [enviar correos de WordPress con Zoho SMTP y FluentSMTP](/es/enviar-emails-wordpress-zoho-smtp-fluentsmtp/).

## Por qué tu VPS necesita un relay SMTP

Los proveedores de VPS bloquean el puerto saliente 25 por defecto. Es una medida antispam y casi nunca te la levantan. Incluso con el puerto 25 abierto, enviar directo al MX desde la IP de un VPS pelado acaba en spam: sin reputación de envío, sin rDNS/PTR coincidiendo con tu dominio y con la posibilidad de que la IP ya arrastre historial en listas negras.

El modelo de relay es directo. Tus aplicaciones entregan al Postfix local. Postfix reenvía todo mediante una conexión cifrada y autenticada (puerto 587) al proveedor de correo. El proveedor se encarga de la entrega, la reputación y la firma DKIM.

```
WordPress / cron / correo del sistema
        │
        ▼
Postfix en tu VPS   ──✗ directo (puerto 25 bloqueado)
        │
        │  relayhost [smtp.zeptomail.com]:587 (TLS + auth)
        ▼
Bandeja del destinatario
```

Qué resuelve un relay:

<ListCheck>
<ul>
<li>Bloqueos del puerto 25: el correo sale por el 587</li>
<li>Entregas en spam: reputación del proveedor y firma DKIM</li>
<li>Configuración SMTP por app: un único Postfix cubre todas las apps del servidor</li>
<li>Rotación de credenciales: un solo sitio donde actualizar contraseñas</li>
</ul>
</ListCheck>

## Paso 1: Configura ZeptoMail (Zoho CPaaS)

<Button text="Crear una cuenta gratuita en Zoho CPaaS" link="https://cpaas.zoho.com/" variant="solid" color="blue" size="md" />

Regístrate, completa el formulario de validación de cliente (mira el aviso de arriba), añade tu dominio y asócialo a un Agent. Cuando esté verificado, abre la pestaña SMTP/API del Agent para obtener tus credenciales. Las necesitarás en el Paso 4.

### Añade los registros DNS DKIM y CNAME

Tras añadir tu dominio, Zoho te muestra uno o más registros DKIM y un registro CNAME (el CNAME es un alias de return-path/rebotes). Publica ambos tipos en tu DNS y pulsa Verificar.

<Notice type="info" title="Ya no hace falta registro SPF">
La verificación SPF se eliminó en junio de 2024. El CNAME de return-path cubre la alineación. Solo hacen falta los registros DKIM y CNAME.
</Notice>

La propagación puede tardar hasta 48 horas. Zoho vuelve a comprobar automáticamente y te avisa por correo cuando el dominio queda verificado. Puedes confirmar que los registros están publicados antes de pulsar Verificar:

```bash
dig TXT selector._domainkey.yourdomain.com +short
dig CNAME mail.yourdomain.com +short
```

La salida debe coincidir con lo que muestra el panel. Fallos típicos de DNS: registros aún sin propagar (espera, no los vuelvas a crear), registros en la zona equivocada (subdominio vs dominio raíz) o tener el proxy de Cloudflare activado en el CNAME (deja estos registros en modo "Solo DNS" en Cloudflare).

### Obtén tus credenciales SMTP

| Ajuste | Valor |
|---|---|
| Servidor | `smtp.zeptomail.com` |
| Puertos | 465 (SSL) o 587 (TLS) |
| Usuario | `emailapikey` |
| Contraseña | Desde el panel → Agent → SMTP/API |
| TLS | Soporta TLS v1.2 |
| Tamaño máx. | 15 MB |

Algunos apuntes: el usuario es literalmente `emailapikey`, no tu login de Zoho. Si tu aplicación se atraganta con contraseñas largas, el panel tiene una opción para generar una más corta (menos robusta). Algunas apps prefieren usar la dirección From como usuario; Zoho soporta ese fallback. Y si tu panel muestra un endpoint regional (`smtp.zeptomail.eu` o similar), usa exactamente el que te indique tu panel.

El primer crédito es gratis, pero no podrás comprar créditos adicionales hasta que se complete la revisión de tu cuenta.

## Paso 2: Instala Postfix en Ubuntu

Muchas imágenes de proveedores traen Postfix preinstalado, así que compruébalo primero:

```bash
dpkg -l postfix
```

Si no está (o quieres una instalación limpia):

```bash
sudo apt update
sudo apt install -y mailutils
```

Elige **Internet Site** durante el diálogo de debconf e introduce tu dominio (p. ej., `yourdomain.com`). Si contestaste mal, vuelve a ejecutar `sudo dpkg-reconfigure postfix`.

En servidores de [Hetzner Cloud](https://go.bitdoze.com/hetzner), Postfix suele venir preinstalado según la imagen base. Si quieres [comparar planes VPS de Hetzner, Vultr y DigitalOcean](/es/digitalocean-vs-vultr-vs-hetzner/) antes de elegir servidor, cada proveedor incluye paquetes distintos por defecto.

Verifica la instalación:

```bash
postfix --version
```

## Paso 3: Configura Postfix como relay SMTP

Si ya has usado Postfix con servidores SMTP externos, la estructura te resultará familiar. Aquí tienes la [receta general para relay SMTP externo](/es/postfix-smtp-externo/) si quieres ver el contexto más amplio.

Edita `/etc/postfix/main.cf`:

```bash
sudo nano /etc/postfix/main.cf
```

Añade (o sustituye cualquier bloque `relayhost` previo) al final:

```
# Zoho CPaaS (formerly ZeptoMail) SMTP relay
relayhost = [smtp.zeptomail.com]:587
smtp_sasl_auth_enable = yes
smtp_sasl_password_maps = hash:/etc/postfix/sasl_passwd
smtp_sasl_security_options = noanonymous
smtp_tls_security_level = encrypt
smtp_tls_note_starttls_offer = yes
header_size_limit = 4096000
sender_canonical_classes = envelope_sender, header_sender
sender_canonical_maps = regexp:/etc/postfix/sender_canonical
smtp_header_checks = regexp:/etc/postfix/smtp_header_checks
```

Por qué `encrypt` en vez de `may`: el TLS oportunista (`may`) permite caer a texto plano. ZeptoMail exige STARTTLS (error 530 sin él) y habla TLS 1.2, así que fuerza el cifrado. `smtp_tls_note_starttls_offer = yes` es opcional pero ayuda al depurar la negociación TLS.

El límite por defecto `message_size_limit` de Postfix es de 10 MB, por debajo del techo de 15 MB de ZeptoMail, así que el valor por defecto es seguro.

Vigila si había una línea `relayhost` vieja de otro relay anterior. Sustitúyela, no acumules líneas.

## Paso 4: Guarda las credenciales SMTP en sasl_passwd

Crea `/etc/postfix/sasl_passwd`:

```bash
sudo nano /etc/postfix/sasl_passwd
```

Añade tus credenciales de ZeptoMail. El usuario es `emailapikey`, no tu cuenta de Zoho:

```
[smtp.zeptomail.com]:587 emailapikey:YOUR_SMTP_PASSWORD
```

Genera la base de datos hash y protege el archivo:

```bash
sudo postmap /etc/postfix/sasl_passwd
sudo chown root:root /etc/postfix/sasl_passwd /etc/postfix/sasl_passwd.db
sudo chmod 0600 /etc/postfix/sasl_passwd /etc/postfix/sasl_passwd.db
```

<Notice type="warning" title="Seguridad del archivo de credenciales">
Tu contraseña SMTP está en texto plano dentro de este archivo. Los permisos 0600 solo para root son obligatorios. Después de cada cambio vuelve a ejecutar `sudo postmap`, o un `.db` desactualizado provocará fallos de autenticación que parecen credenciales erróneas.
</Notice>

Fallos típicos aquí: pegar la contraseña con un salto de línea o comillas al final (provoca error 535), caracteres especiales en la contraseña (usa la opción de contraseña corta del panel si hace falta), o editar `sasl_passwd` olvidando ejecutar `sudo postmap` y `sudo postfix reload`.

## Paso 5: Reescribe la dirección del remitente

Sin esto, ZeptoMail rechaza los correos de WordPress u otras aplicaciones porque el dominio del campo "From" no coincide con tu dominio verificado. El error oficial es `553 Relaying disallowed as <address>`, que indica que envías desde un dominio "from" no verificado. Desde abril de 2024, las direcciones de remitente no verificadas no pueden enviar nada, así que la reescritura debe apuntar a una dirección de tu **dominio verificado**.

Crea `/etc/postfix/sender_canonical`:

```
/.+/ noreply@yourdomain.com
```

Crea `/etc/postfix/smtp_header_checks`:

```
/From:.*/ REPLACE From: noreply@yourdomain.com
```

O con nombre visible:

```
/From:.*/ REPLACE From: Your Name <noreply@yourdomain.com>
```

Usa una dirección del dominio que verificaste en Zoho CPaaS. La línea `sender_canonical_classes` del Paso 3 cubre tanto el remitente del sobre (envelope) como el de cabecera. Se reescriben ambos.

Qué vigilar: reescribir hacia un dominio no verificado (seguirá dando 553), comas o comillas en el nombre visible de la línea REPLACE, y asegurarse de que `sender_canonical_classes` incluye tanto `envelope_sender` como `header_sender`.

Si prefieres resolver esto por aplicación en WordPress en lugar de hacerlo a nivel de servidor, la opción de FluentSMTP enlazada en la introducción lo gestiona sin tocar Postfix.

## Paso 6: Revisa /etc/mailname

Si el hostname de tu VPS es un subdominio (p. ej., `cloud.yourdomain.com`), Postfix puede intentar usarlo como dominio de envío. Corrígelo:

```bash
sudo nano /etc/mailname
```

Déjalo solo con el dominio raíz:

```
yourdomain.com
```

## Paso 7: Valida y recarga Postfix

Ejecuta `postfix check` antes de recargar: detecta errores de sintaxis sin tocar el correo en vuelo:

```bash
sudo postfix check
sudo postfix reload
```

`postfix check` no imprime nada cuando la configuración está limpia. Si avisa de algo, corrígelo antes de recargar.

Revisa la cola:

```bash
postqueue -p
```

La cola debería estar vacía o vaciándose. Errores de permisos sobre los archivos de mapas suelen significar que faltaron los pasos `chown`/`chmod` del Paso 4.

## Paso 8: Prueba el relay SMTP

Envía un mensaje de prueba:

```bash
echo "test message" | mail -s "test subject" you@example.com
```

Vigila los logs para confirmar la entrega.

<Tabs>
<Tab name="/var/log/mail.log">
En Ubuntu 22.04 y la mayoría de imágenes de proveedores:

```bash
tail -f /var/log/mail.log
```

Un envío correcto se ve así:

```
postfix/smtp: status=sent (250 Message received)
```
</Tab>
<Tab name="journalctl (24.04+)">
En Ubuntu 24.04+ donde mail.log puede ir solo por journald:

```bash
journalctl -u postfix -f
```

Misma salida esperada: `status=sent (250 Message received)`.
</Tab>
</Tabs>

Tras un envío correcto, confirma tres cosas: el mensaje llegó (no solo quedó en cola), la cabecera From muestra tu dirección reescrita (revisa las cabeceras del correo recibido) y los registros del panel de Zoho muestran la entrega (retención de 60 días).

Si `mail` devuelve "command not found", no se instaló `mailutils`: vuelve al Paso 2. Si el correo queda retenido, ejecuta `postqueue -p` y lee la línea de error en el log.

Una vez que funcione, todas las aplicaciones del servidor salen automáticamente por ZeptoMail: WordPress, avisos de cron y correo del sistema. Eso incluye las alertas de nuestra [guía para monitorizar CPU y enviar alertas por email en Linux](/es/monitorizar-cpu-alertas-email-linux/).

## Solución de problemas: códigos de error SMTP de ZeptoMail

| Código | Mensaje | Causa |
|---|---|---|
| 530 | Must issue a STARTTLS command first | Conexión sin TLS (puerto 587 sin STARTTLS o puerto 25 plano) |
| 535 | Authentication Failed | Clave/usuario inválido, créditos caducados, créditos bloqueados o cuenta bloqueada |
| 553 | Relaying disallowed as `<addr>` | Envío desde un dominio 'from' no verificado |
| 552 | 5.7.1 virus detected | Antivirus activado sobre el mensaje |
| n/a | 5.2.1 Subject is Mandatory | Línea de asunto vacía |
| n/a | 5.2.0 Email size exceeded the policy | Supera el límite de 15 MB |

### 535 authentication failed

Este es el que corta el correo en silencio a las 3 de la mañana. El usuario debe ser `emailapikey` (no tu login de Zoho). Revisa la línea de credenciales en `/etc/postfix/sasl_passwd` por saltos de línea o comillas sobrantes. Ejecuta `sudo postmap /etc/postfix/sasl_passwd` tras cualquier cambio.

Pero la causa más traicionera: **créditos caducados o cuenta bloqueada**. El correo simplemente deja de salir. Revisa el estado de tus créditos y de la cuenta en el panel. Si la contraseña tiene caracteres especiales, prueba la opción de contraseña más corta del panel.

<Notice type="error" title="Los créditos caducan en silencio">
El correo muere sin ruido cuando se agotan o caducan los créditos. Activa las notificaciones de caducidad de créditos en el panel y valora la recarga automática (mira abajo). Este es el fallo de las 3 a.m. que nadie planifica.
</Notice>

### 553 relaying disallowed

Envío desde un dominio 'from' no verificado, justo lo que evita el Paso 5. Asegúrate de que la reescritura en `/etc/postfix/sender_canonical` apunta a una dirección de tu dominio verificado. Revisa el estado del dominio en el panel; si la verificación sigue pendiente, espera el correo de confirmación de Zoho.

### 530 must issue a STARTTLS command first

Te estás conectando sin cifrado: puerto 587 sin TLS o puerto 25 en claro. La solución es `smtp_tls_security_level = encrypt` en el Paso 3, usando el puerto 587 con TLS (o 465 con SSL). Por eso la configuración de esta guía usa `encrypt` en vez de `may`.

### Correos atascados en la cola

Ejecuta `postqueue -p` para ver qué hay en cola y luego `postqueue -f` para forzar el envío. Lee la línea de motivo diferido en el log; se corresponderá con uno de los códigos de error de arriba.

## Mantenimiento: costes, límites y endurecimiento

### Cómo funciona la facturación

1 crédito de correo = 10.000 correos. El primer crédito es gratuito. Los créditos son válidos durante 6 meses desde la compra.

<Notice type="info" title="Se factura por destinatario, no por mensaje">
Un correo con 1 Para y 3 CC cuenta como 4 contra tu crédito. Si envías avisos de formularios de contacto con copias en CC, quemarás créditos 2–4 veces más rápido de lo que sugiere la idea de "10.000 envíos". A 1 destinatario por correo sí obtienes 10.000 envíos por crédito.
</Notice>

Existe recarga automática y merece la pena activarla: salta al bajar de un umbral mínimo de créditos (máximo 2 créditos por recarga por defecto). Para un relay, es la diferencia entre que el correo siga saliendo o ver errores 535 de madrugada. Hay IPs dedicadas para remitentes de gran volumen; no hacen falta en cargas habituales de VPS o WordPress.

Consulta el precio vigente de los créditos en tu panel o en [zoho.com/cpaas/pricing.html](https://www.zoho.com/cpaas/pricing.html). Los precios van por crédito y varían por región. En perspectiva, el coste en créditos son céntimos frente a las [subidas de precios de VPS](/es/subidas-precios-vps/) de los últimos dos años.

### Reversión: quitar el relay

Si necesitas dar marcha atrás, comenta las líneas de relay, SASL, TLS y reescritura de remitente que añadiste en `/etc/postfix/main.cf`:

```
# relayhost = [smtp.zeptomail.com]:587
# smtp_sasl_auth_enable = yes
# smtp_sasl_password_maps = hash:/etc/postfix/sasl_passwd
# smtp_sasl_security_options = noanonymous
# smtp_tls_security_level = encrypt
# smtp_tls_note_starttls_offer = yes
# sender_canonical_classes = envelope_sender, header_sender
# sender_canonical_maps = regexp:/etc/postfix/sender_canonical
# smtp_header_checks = regexp:/etc/postfix/smtp_header_checks
```

Después:

```bash
sudo postfix check && sudo postfix reload
```

El correo volverá a intentar entrega directa, aunque el puerto 25 probablemente siga bloqueado por tu proveedor, así que espera que quede en cola si no configuras otro relay.

## Alternativas a ZeptoMail

ZeptoMail me funciona bien, pero hay otras opciones según tu volumen y presupuesto:

- **Amazon SES** cuesta ~0,10 $ por cada 1.000 correos. La más barata a escala, pero gestionas reputación y configuración por tu cuenta. Buena opción si ya estás en AWS.
- **Postmark** ronda los ~15 $/mes por 10.000 correos. Conocido por su entrega rápida y buena entregabilidad. Más caro pero muy cómodo.
- **Resend** tiene nivel gratuito, con planes de pago desde ~20 $/mes para más volumen. API moderna, popular entre desarrolladores. Relativamente nuevo.
- **Brevo (antes Sendinblue)** empieza en ~9 $/mes. Combina correo transaccional y marketing si necesitas ambos.

Para un VPS pequeño con unos pocos sitios WordPress, el modelo de pago por uso de ZeptoMail es difícil de batir en precio. Si envías más de 50.000 correos al mes, Amazon SES suele salir más barato.

Dos opciones más a conocer: la [reseña del servicio SMTP barato Mail.Baby](/es/resena-mail-baby/) cubre un competidor directo para la misma tarea, y [Cloudflare Email Sending para sitios estáticos](/es/emdash-enviar-email/) es una alternativa ligera si no necesitas un relay completo. Zoho también publica comparativas propias (Postmark, SES, SendGrid, SparkPost) si quieres verlas cara a cara. Y si vienes de Resend, ZeptoMail incorporó en julio de 2026 una herramienta de migración en un clic (dominios, plantillas, webhooks).

<Accordion label="¿Puedo enviar newsletters o correo comercial a través de este relay?" group="faq">
No. ZeptoMail es solo para correo transaccional: restablecimientos de contraseña, recibos, alertas. El correo masivo de marketing viola los términos. Usa Zoho Campaigns o una plataforma dedicada de newsletters como EmailOctopus para eso.
</Accordion>

<Accordion label="¿Necesito añadir un registro SPF?" group="faq">
No. La verificación SPF se eliminó en junio de 2024. La verificación de dominio usa solo registros DKIM y un CNAME (alias de return-path). Ese CNAME cubre lo que antes requería el SPF.
</Accordion>

<Accordion label="¿Necesito una IP dedicada?" group="faq">
No con volúmenes normales de VPS o WordPress. Una IP dedicada solo importa cuando envías un volumen alto sostenido y necesitas controlar tu propia reputación de envío. Para la mayoría de instalaciones, el pool de IPs compartidas funciona bien.
</Accordion>

<Accordion label="Mi correo de prueba funciona pero el de WordPress no. ¿Por qué?" group="faq">
WordPress fija su propia cabecera From, que puede esquivar la reescritura de Postfix. Asegúrate de tener aplicada la reescritura de remitente del Paso 5 (cubre tanto el sobre como la cabecera). O resuélvelo a nivel de aplicación con FluentSMTP; el enlace está en la introducción.
</Accordion>

Sin suscripción, pago por uso y todas las aplicaciones del servidor salen por una única ruta autenticada. Si algo falla, el Paso 8 tiene los comandos de verificación y la tabla de solución de problemas de arriba traduce cada código de error en su solución.
