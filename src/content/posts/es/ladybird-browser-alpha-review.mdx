Ladybird lanzó su primera alpha el 23 de noviembre de 2026. Es el primer navegador descargable en años que funciona con un motor que nadie más escribió: sin Blink, sin WebKit, sin Gecko. Lo instalé en mi MacBook Pro, abrí cuatro pestañas y miré el Monitor de Actividad siete minutos después. El resultado fue 19 procesos y 2,86 GB.

Ese número es la razón de este artículo. Mi conclusión tras una sesión es que el motor no decide cuánta memoria usa un navegador. Chrome, el WebKit de Safari y un motor desde cero como Ladybird acaban siendo pesados cuando abres la web tal como existe hoy. Abajo: qué es la alpha, qué encontraron otros, los números de mi pantalla y por qué creo que la memoria sigue alta sea cual sea el que instales.

<Notice type="info" title="Cómo lo probé">
Un MacBook Pro (Apple M1 Pro), la alpha de Ladybird desde la página de descarga, cuatro pestañas abiertas (una búsqueda de Google, un vídeo de YouTube en reproducción, los ajustes de Ladybird y Gmail), leído en el Monitor de Actividad de macOS 7 minutos y 31 segundos después de abrirlo. No ejecuté Chrome ni Safari al lado, así que nada de esto es una comparación directa. Todo lo que cuento de los resultados de otras personas lleva su enlace a la fuente.
</Notice>

## Qué es Ladybird

Ladybird es un navegador con su propio motor. HTML, CSS, el DOM, el layout, JavaScript y WebAssembly están implementados desde cero, según las [notas de la versión](https://github.com/LadybirdBrowser/ladybird/releases/tag/2026.47.7). Nació como el navegador del sistema operativo de aficionados SerenityOS y hoy lo desarrolla una organización sin ánimo de lucro de EE. UU., financiada con patrocinios y donaciones en lugar de acuerdos con buscadores ([OMG! Ubuntu](https://www.omgubuntu.co.uk/2026/11/ladybird-browser-enters-alpha)).

Todavía toma prestadas algunas piezas. Simon Willison enumera [HarfBuzz para el texto, Skia para los gráficos 2D, ffmpeg para el vídeo y SQLite](https://simonwillison.net/2026/Nov/23/ladybird) como componentes externos. "Desde cero" se refiere al motor, no a cada biblioteca.

| | Ladybird alpha |
|---|---|
| Plataformas | Macs con Apple silicon (macOS 14.4 o posterior), Linux x86-64 y Arm64 |
| No incluido | Windows, Macs con Intel, móviles |
| Actualizaciones | Canal continuo con actualizaciones automáticas |
| Lenguajes del motor | C++, migrando a Rust (el motor de JavaScript y el cálculo de estilos ya están en Rust) |
| Herramientas de desarrollo | WebDriver y el protocolo de DevTools de Firefox |
| Hoja de ruta | Beta en 2027, estable en 2028 (según las FAQ del proyecto, [resumidas por Sulat](https://news.sulat.com/2026/11/24/ladybird-browser)) |

El equipo es claro sobre el estado actual. El [anuncio](https://ladybird.org/posts/alpha/) de Andreas Kling dice que algunos sitios no funcionarán, que se cerrará de forma inesperada y que no hay promesas de seguridad.

<Notice type="warning" title="No inicies sesión en nada importante">
El proyecto pide a los investigadores de seguridad que lo hackeen y no hace "ninguna promesa sobre seguridad hoy". Simon Willison lo conserva solo para navegar de forma anónima y no lo usa para GitHub ni Gmail. Mi prueba tenía Gmail abierto, algo que yo evitaría en una máquina que te importe. Usa una cuenta desechable o una máquina virtual.
</Notice>

## Instalación

<Tabs>
<Tab name="macOS">
Descarga la imagen de disco desde [ladybird.org/download](https://ladybird.org/download/), ábrela y arrastra Ladybird a Aplicaciones. La versión es solo para Apple silicon.
</Tab>
<Tab name="Linux (Flatpak)">
El proyecto recomienda el Flatpak. Estos dos comandos vienen de [Linux und Ich](https://linuxundich.de/en/ladybird-alpha-browser-engine-linux), que los ejecutó en TUXEDO OS. Yo no los ejecuté.

```bash
flatpak install --from https://flatpak.ladybird.org/ladybird.flatpakref
flatpak run org.ladybird.Ladybird
```
</Tab>
<Tab name="Ubuntu (apt)">
Ubuntu 24.04 y 26.04 tienen un repositorio apt, con actualizaciones a través del actualizador de software habitual. Estos comandos vienen de [OMG! Ubuntu](https://www.omgubuntu.co.uk/2026/11/ladybird-browser-enters-alpha); yo no los ejecuté.

```bash
sudo wget -qO /etc/apt/keyrings/ladybird.asc 'https://apt.ladybird.org/ladybird.asc'

# Ubuntu 26.04 LTS
sudo wget -qO /etc/apt/sources.list.d/ladybird.sources 'https://apt.ladybird.org/ladybird-resolute.sources'

# Ubuntu 24.04 LTS (o Linux Mint 22.x)
sudo wget -qO /etc/apt/sources.list.d/ladybird.sources 'https://apt.ladybird.org/ladybird-noble.sources'

sudo apt update && sudo apt install ladybird
```
</Tab>
</Tabs>

## Cómo puntúa

Ladybird se mide con las Web Platform Tests, la batería compartida que usan los fabricantes de navegadores para comprobar el soporte de estándares. Estas son las cifras de finales de octubre de su [boletín de octubre](https://ladybird.org/newsletter/2026-10-31):

| Navegador | Subpruebas superadas | Porcentaje de Chrome |
|---|---|---|
| Chrome | 2.244.397 | 100% |
| Firefox | 2.189.315 | 97,5% |
| Ladybird | 2.184.722 | 97,3% |
| Safari Technology Preview | 2.172.990 | 96,8% |

Los porcentajes son cálculo mío. Esto mide cobertura de estándares, no cuántos sitios reales funcionan, y la mayor parte del salto de octubre llegó en cinco días tras poner agentes de programación con IA a trabajar sobre la batería. Kling también usó Claude Code y Codex para portar partes del motor de JavaScript de C++ a Rust, como cuenta en [Ladybird adopts Rust, with help from AI](https://ladybird.org/posts/adopting-rust/). Si quieres ver cómo se comparan esos agentes para tu trabajo, mi [comparativa de herramientas de programación con IA](/es/herramientas-codificacion-ia/) y la [reseña de Freebuff](/es/freebuff-agente-ia-gratis/) cubren las opciones gratuitas.

La velocidad es donde los números flaquean. El boletín de agosto de Ladybird llama a sus puntuaciones de benchmark "todavía modestas junto a los motores maduros", como [cita Sulat](https://news.sulat.com/2026/11/24/ladybird-browser), y el resultado de Speedometer de arriba es un portátil en un día.

### Por qué la cifra de un solo proceso engaña

Varios comentaristas de Hacker News publicaron cifras bajas. Uno contó "53mb de memoria con varias pestañas abiertas" y otro "menos de 100 mb de RAM". Un tercero respondió a una afirmación parecida con la pieza que faltaba: Ladybird abre las pestañas como procesos separados, así que el proceso principal no es el total, y una sola pestaña de YouTube ocupó 300 MB en su propio proceso WebContent.

El árbol de procesos de Simon Willison muestra lo mismo con siete pestañas:

![Diagrama del árbol de procesos de Ladybird: el proceso de interfaz lanza un Hub, que gestiona procesos WebContent, RequestServer, Compositor y MediaServer, con las cifras de memoria del árbol de Simon Willison](@assets/images/26/11/ladybird-process-tree.webp)

*Nombres de procesos y tamaños del [árbol de Simon Willison](https://simonwillison.net/2026/Nov/23/ladybird) (16 procesos, unos 2,1 GB). Las funciones salen de los boletines de [septiembre](https://ladybird.org/newsletter/2026-09-30) y [octubre](https://ladybird.org/newsletter/2026-10-31) de Ladybird. Los totales de pestañas y de soporte son cálculo mío.*

Sus siete pestañas ocupaban 1.448 MB, y una de ellas 819 MB. Los procesos de soporte (interfaz, hub, red, compositor, medios) sumaban otros 655 MB. Así que la parte "pesada" son unas pocas pestañas, y la parte de "sobrecarga" es real pero menor.

## Por qué la memoria sigue alta con cualquier motor

Mi lectura, tras ver mis números junto a los de todos los demás, es que cuatro cosas determinan la memoria de un navegador y ninguna depende de quién escribió el motor.

**1. Todo navegador moderno paga por el aislamiento.** La [explicación de Engadget sobre Chrome y la RAM](https://www.engadget.com/2294261/why-google-chrome-using-so-much-ram/) dice que los fabricantes eligen entre compartir procesos entre pestañas para ahorrar memoria o dar a cada sitio su propio proceso, y Chrome elige lo segundo. Un fallo se queda en una pestaña y una página hostil no puede leer fácilmente tu pestaña del banco. Ladybird tomó la misma decisión y fue más allá en octubre: procesos separados para la red, la decodificación de imágenes, el audio y el vídeo, además de renderizadores propios para los iframes entre sitios. Más muros, más memoria. Es el coste del modelo de seguridad, no una señal de mal código.

**2. La web ya está hecha de aplicaciones.** Gmail más un reproductor de YouTube no es una carga pequeña. Un artículo de un proveedor sitúa las aplicaciones web pesadas en [200 a 500 MB por pestaña](https://supasidebar.com/blog/reduce-chrome-memory-usage-tabs-2026). Tómalo como una guía aproximada, porque la fuente vende un gestor de pestañas. Mis tres procesos más grandes (710, 694 y 672 MB) quedan por encima de ese rango, y no puedo decir qué pestañas eran.

**3. La memoria se retiene, no se libera.** El boletín de septiembre de Ladybird describe páginas que se recargan solas con un temporizador. Las pestañas en segundo plano de Politico llegaron a 11 GB tras cuatro horas y las de El País a 15 GB tras veinte, porque cada documento sustituido seguía vivo. Se corrigió en septiembre, y octubre incluyó un arreglo parecido para Gmail. Un motor nuevo con un recolector de basura moderno cayó igualmente, porque la web incluye páginas que se portan mal.

**4. La RAM libre es RAM desperdiciada.** El argumento de Engadget es que un navegador que llena la memoria libre con pestañas preparadas está haciendo su trabajo. En mi Mac, el 83% de la memoria estaba en uso con 549 procesos en marcha, y el navegador era uno más. Cuando un usuario planteó el uso de memoria de Ladybird a principios de noviembre, Kling respondió que al equipo aún le queda trabajo, según [PiunikaWeb](https://piunikaweb.com/2026/11/05/ladybird-update-makes-scrolling-and-text-selection-much-smoother/).

Dos matices, porque es una sola sesión. Primero, una alpha es el peor caso para la memoria, ya que la optimización llega después de las funciones. Segundo, no ejecuté Chrome ni Safari al lado, así que no afirmo que Ladybird sea igual a ellos. Mi afirmación es más estrecha: un motor desde cero construido en 2026 y sin la historia de Chrome no escapó al problema, así que no esperaría que cambiar de motor lo arregle.

La misma presión aparece fuera de los navegadores. Las aplicaciones de escritorio basadas en Electron incluyen su propio Chromium, y mi comparativa [Orca vs T3 Code](/es/orca-vs-t3-code/) pone una app Electron junto a un servidor con clientes web. En Mac, los contenedores tienen el mismo problema, por eso comparé las [alternativas a Docker Desktop](/es/mejores-alternativas-docker-desktop/) en RAM y consumo en reposo.

## Qué hacer con la memoria del navegador

- **Suma el grupo entero.** En el Monitor de Actividad, busca el nombre del navegador y lee el panel del grupo, no una sola fila. El boletín de septiembre de Ladybird también describe un Administrador de tareas nativo con árbol de procesos y columna de memoria ordenable, pero yo no lo abrí.
- **Cierra las pestañas pesadas, no las ligeras.** Tres procesos eran más del 70% de mi total. Encontrarlos es más rápido que cerrarlo todo.
- **Activa el bloqueador de contenido.** Viene desactivado. El boletín de septiembre rastrea un caso de CPU descontrolada hasta un script de anuncios que un bloqueador había eliminado. No medí si reduce la memoria.
- **Usa un navegador que descargue pestañas.** Según Engadget, Chrome tiene Memory Saver y Firefox descarga pestañas cuando el sistema anda justo de memoria.
- **Compra memoria para tu trabajo real.** Si ejecutas modelos locales o muchos agentes, la sobrecarga del navegador es la factura menor. Mi [guía de Mac mini para OpenClaw](/es/mejor-mac-mini-openclaw/) hace ese cálculo.

## ¿Deberías usarlo?

<ListCheck>
- Úsalo para probar tu propio sitio en un cuarto motor. WebDriver y el protocolo de DevTools de Firefox están en la alpha. Mi [reseña de Modern Web Guidance](/es/modern-web-guidance-escaneo-codigo/) cubre auditorías que combinan bien con un motor extra.
- Úsalo para navegar de forma anónima en una máquina donde un cierre inesperado no te cueste nada.
- Úsalo si quieres apoyar a un motor sin ánimo de lucro. Entre los patrocinadores están Cloudflare, Proton y Shopify, según [OMG! Ubuntu](https://www.omgubuntu.co.uk/2026/11/ladybird-browser-enters-alpha) y Sulat.
- No lo uses como navegador diario. Sin extensiones, sin importación, vídeo entrecortado y sin promesas de seguridad.
- No lo uses si necesitas Windows o un Mac con Intel. Ninguno está en la alpha.
</ListCheck>

Si automatizas navegadores, un motor independiente importa hoy menos que uno estable. Herramientas como [Pinchtab](/es/pinchtab-agentes-ia-navegador/) controlan Chrome o Chromium porque es contra lo que se prueban los sitios. El soporte de WebDriver de Ladybird merece seguimiento, no una apuesta.

## Mi veredicto

Ladybird impresiona para ser una alpha. Los sitios reales se renderizan, el equipo publica rápido y el motor supera alrededor del 97% de las subpruebas de Web Platform Tests de Chrome. Es más lento que Chrome y Firefox en el único benchmark que encontré, y necesita más pulido.

En memoria, salí sin convencerme de que algún motor me dé un navegador ligero. Cuatro pestañas costaron 2,86 GB en un motor desde cero, y la explicación (aislamiento, páginas del tamaño de una aplicación, memoria que se retiene, un Mac ya cerca del 83%) vale también para Chrome y WebKit. Es mi lectura de una sola sesión, no una medición. Lo que volveré a mirar es el boletín de noviembre, que debería traer las primeras cifras posteriores a la alpha.

## Preguntas frecuentes

<Accordion label="¿Ladybird es un fork de Chromium o Firefox?" group="faq" expanded="true">
No. Las notas de la versión dicen que HTML, CSS, el DOM, el layout, JavaScript y WebAssembly están implementados desde cero. Sí usa bibliotecas como Skia, HarfBuzz, ffmpeg y SQLite, según Simon Willison.
</Accordion>

<Accordion label="¿Puedo usar Ladybird como navegador diario?" group="faq">
Todavía no. El proyecto dice que algunos sitios no funcionarán y que se cerrará de forma inesperada, y no hace promesas de seguridad. No hay sistema de extensiones ni importación desde otros navegadores.
</Accordion>

<Accordion label="¿Ladybird usa menos memoria que Chrome?" group="faq">
No lo medí. Mi sesión de cuatro pestañas usó 2,86 GB repartidos en 19 procesos. Algunos comentaristas de Hacker News publicaron cifras menores, pero al menos una era de un solo proceso y no del grupo, así que compara solo totales.
</Accordion>

<Accordion label="¿Ladybird tiene extensiones o bloqueador de anuncios?" group="faq">
No hay sistema de extensiones. Sí hay un bloqueador de contenido integrado con listas de filtros como EasyList, y está desactivado hasta que lo actives en la página de bienvenida o en los ajustes.
</Accordion>

<Accordion label="¿Hay versión para Windows?" group="faq">
No en la alpha. El proyecto dice que Windows llega en una etapa posterior. HWBusters cuenta que por ahora la indicación es compilar la versión de Linux dentro de WSL2.
</Accordion>

<Accordion label="¿Puedo usar Ladybird para probar mi sitio web?" group="faq">
Sí, es el uso más claro hoy. Admite WebDriver para pruebas automatizadas y el protocolo de DevTools de Firefox. Espera huecos: Simon Willison se topó con un error de service worker en Datasette Lite y abrió una incidencia.
</Accordion>

<Accordion label="¿Quién financia Ladybird?" group="faq">
Una organización sin ánimo de lucro de EE. UU. financiada con donaciones y patrocinios. El proyecto dice que no acepta acuerdos de buscador predeterminado y que los patrocinadores no opinan sobre la hoja de ruta técnica.
</Accordion>
