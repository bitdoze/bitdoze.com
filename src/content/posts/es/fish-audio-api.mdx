## Cómo funciona la API de Fish Audio

Cada petición va a `https://api.fish.audio` con una cabecera `Authorization: Bearer <clave>` y una cabecera `model` que elige el motor. Las peticiones TTS envían JSON (o MessagePack para audio de referencia en línea) y reciben bytes de audio por fragmentos en mp3, wav, pcm u opus. Como el audio llega en streaming por fragmentos, la reproducción puede empezar antes de que termine la generación.

![Ciclo de vida de una petición TTS en Fish Audio mostrando cliente, api.fish.audio, tarea TTS y bytes de audio devueltos](@assets/images/26/11/fish-audio-api-lifecycle.webp)

*El ciclo de vida de una petición TTS: un POST de entrada, bytes de audio por fragmentos de salida y errores JSON si algo falla.*

La superficie de la API abarca más que TTS. Hay un endpoint de voz a texto, un WebSocket de transcripción en tiempo real, gestión de modelos de voz y diseño de voz a partir de un prompt de texto. Este tutorial usa POST /v1/tts, POST /v1/asr, POST /model y el WebSocket de TTS.

![Mapa de endpoints de la API de Fish Audio incluyendo tts, asr, creación de modelos, websockets en tiempo real, diseño de voz y MCP](@assets/images/26/11/fish-audio-api-endpoints.webp)

## Cómo conseguir una clave API de Fish Audio

Creas las claves en la aplicación web, sin un registro aparte para desarrolladores. Regístrate en fish.audio, verifica tu correo electrónico y abre la página Get Started en `fish.audio/app/developers/get-started/`. Haz clic en "Get your API key" y la clave se genera en un clic. La misma clave sirve para la API REST, el SDK de Python y el SDK de JavaScript. Las claves existentes están en la página API Keys en `fish.audio/app/api-keys`.

<Notice type="warning" title="La clave solo se muestra una vez">
Cópiala de inmediato. Si la pierdes, tendrás que crear una nueva desde la página API Keys. No la subas nunca a git.
</Notice>

![Pasos en la documentación de Fish Audio para crear una cuenta y generar una clave API en un solo clic](@assets/images/26/11/fish-audio-api-key-steps.webp)

*Los pasos oficiales para crear una clave en docs.fish.audio.*

Guárdala como variable de entorno, que es lo que esperan todos los SDK y ejemplos de la documentación:

```bash
export FISH_API_KEY="your_api_key_here"
```

Si una clave se filtra, Fish Audio documenta un [endpoint de revocación para claves expuestas](https://docs.fish.audio/api-reference/endpoint/apikey/revoke-api-keys) sin inicio de sesión. Así, los escáneres de secretos pueden anular claves en repositorios públicos. La revocación es permanente y la clave devuelve 401 al instante.

## ¿Es gratis la API de Fish Audio?

Sí, para desarrollo. El modelo `s2.1-pro-free` cuesta 0 $ por millón de bytes UTF-8 y apunta al mismo endpoint que S2.1 Pro de pago, así que nada cambia al actualizar. Como las cuentas nuevas empiezan con saldo cero, todos los ejemplos iniciales usan `s2.1-pro-free`.

Las condiciones provienen del [anuncio oficial de la API gratuita de S2.1 Pro](https://fish.audio/blog/s2-1-pro-free-api/) de Fish Audio, que consulté el 26 de noviembre de 2026:

- Uso ilimitado bajo una política de uso justo (Fair Use Policy). Fish Audio puede limitar el uso que parezca abuso en lugar de desarrollo.
- Sin SLA, sin garantía de disponibilidad ni de latencia, solo bajo mejor esfuerzo.
- Las peticiones pueden usarse para mejorar la calidad del modelo.
- Algunos escenarios comerciales tienen restricciones, y los productos con más de 1 millón de dólares de ARR deben contactar con Fish Audio antes de usar el nivel gratuito.

<Notice type="info" title="La ventana gratuita tiene fecha de fin">
El 26 de noviembre de 2026, el anuncio indicaba que el acceso gratuito estaba disponible hasta el 30 de noviembre de 2026, con aviso previo ante cualquier cambio. La misma publicación muestra que la ventana ya se amplió varias veces antes (hasta el 31 de agosto y luego hasta el 30 de noviembre). ## Tu primera llamada TTS en Python y curl

Instala el SDK oficial de Python con `pip install fish-audio-sdk` y genera un clip con el modelo gratuito:

<Tabs>
<Tab name="Python">

```python
from fishaudio import FishAudio
from fishaudio.utils import save

client = FishAudio()  # reads FISH_API_KEY

audio = client.tts.convert(
    text="Hello! Welcome to Fish Audio.",
    model="s2.1-pro-free",
)
save(audio, "welcome.mp3")
```

</Tab>
<Tab name="curl">

```bash
curl -X POST https://api.fish.audio/v1/tts \
  -H "Authorization: Bearer $FISH_API_KEY" \
  -H "Content-Type: application/json" \
  -H "model: s2.1-pro-free" \
  -d '{
    "text": "Hello! Welcome to Fish Audio.",
    "format": "mp3"
  }' \
  --output welcome.mp3
```

</Tab>
</Tabs>

Reproduce el archivo con `mpg123 welcome.mp3` en Linux o `afplay welcome.mp3` en macOS. Ese es todo el ciclo.

<Notice type="info" title="La cabecera model hace fallback en silencio">
Según la [referencia de texto a voz](https://docs.fish.audio/api-reference/endpoint/openapi-v1/text-to-speech), si omites o escribes mal la cabecera `model`, tu petición corre en el motor de pago `s2.1-pro`. El [inicio rápido](https://docs.fish.audio/developer-guide/getting-started/quickstart) indica que los modelos de pago devuelven `402` hasta que añades saldo de API. El SDK de Python lleva el mismo valor por defecto, así que pasa `model` de forma explícita en cada llamada. El endpoint ASR tiene el mismo comportamiento de fallback, cubierto en la sección de transcripción.
</Notice>

Otros motores TTS válidos son `s2-pro`, el obsoleto `s1` y `drama-3`. `drama-3` es el modelo más expresivo a 50 $ por millón de bytes, rebajado un 80% a 10 $ hasta el 30 de noviembre de 2026. Evita `s1` en código nuevo, ya que se retira el 31 de diciembre de 2026 y redirige a `s2.1-pro`.

![Página de documentación quickstart de la API de Fish Audio mostrando los primeros ejemplos de petición TTS](@assets/images/26/11/fish-audio-api-quickstart.webp)

*El inicio rápido oficial con variantes en cURL, Python y JavaScript de la primera petición.*

Campos útiles del cuerpo de la petición, extraídos del esquema OpenAPI:

| Campo | Valor por defecto | Qué hace |
| --- | --- | --- |
| `text` | obligatorio | El texto que se va a locutar |
| `reference_id` | null | ID del modelo de voz, cadena o array para varios hablantes |
| `format` | `mp3` | `wav`, `pcm`, `mp3` u `opus` |
| `sample_rate` | por defecto del formato | 44100 Hz para la mayoría de formatos, 48000 Hz para opus |
| `mp3_bitrate` | `128` | 64, 128 o 192 kbps |
| `latency` | `normal` | `normal` mejor calidad, `balanced` latencia reducida, `low` mínima latencia |
| `prosody` | null | Velocidad (0.5 a 2.0) y volumen en dB, p. ej. `{"speed": 1.2}` |
| `temperature` | 0.7 | Más alto es más expresivo, más bajo es más consistente |
| `chunk_length` | 300 | Tamaño del segmento de texto para procesar |
| `normalize` | true | Desarrolla números, fechas y unidades antes de la síntesis |

Para diálogos con varios hablantes en la familia S2, pasa `reference_id` como un array y etiqueta el texto con marcadores de hablante:

```python
audio = client.tts.convert(
    text="<|speaker:0|>Good morning!<|speaker:1|>Morning! How are you?",
    reference_id=["voice-id-alice", "voice-id-bob"],
    model="s2.1-pro-free",
)
```

## Reproducción en streaming para baja latencia

Existen dos modos de streaming. El streaming HTTP viene activado por defecto porque el servidor envía la respuesta en bytes por fragmentos que puedes escribir o reproducir al instante.

<Tabs>
<Tab name="Python">

```python
from fishaudio import FishAudio

client = FishAudio()

with open("out.mp3", "wb") as f:
    for chunk in client.tts.stream(
        text="Streaming keeps latency low.",
        model="s2.1-pro-free",
    ):
        f.write(chunk)  # or send to a speaker as it arrives
```

</Tab>
<Tab name="curl">

```bash
curl --request POST https://api.fish.audio/v1/tts \
  --header "Authorization: Bearer $FISH_API_KEY" \
  --header "Content-Type: application/json" \
  --header "model: s2.1-pro-free" \
  --no-buffer \
  --data '{ "text": "Streaming keeps latency low.", "format": "mp3" }' \
  --output out.mp3
```

</Tab>
</Tabs>

El segundo modo es un WebSocket para texto que todavía se está generando, normalmente tokens de un LLM. El SDK de Python gestiona el protocolo con `tts.stream_websocket`, que recibe un iterable de cadenas y eventos, tal como se muestra en la [guía de WebSocket del SDK](https://docs.fish.audio/developer-guide/sdk-guide/python/websocket):

```python
from fishaudio import FishAudio
from fishaudio.types import TextEvent, FlushEvent

client = FishAudio()

def script():
    yield TextEvent(text="First sentence. ")
    yield "Second sentence. "
    yield FlushEvent()  # force generation of everything buffered
    yield "Third sentence."

for chunk in client.tts.stream_websocket(
    script(),
    reference_id="YOUR_VOICE_ID",
    model="s2.1-pro-free",
):
    pass  # play or forward each chunk
```

Un `FlushEvent` fuerza la generación inmediata del texto en búfer, que es la forma de controlar los límites de turno en un agente de voz. En cuanto a la latencia, el esquema REST usa `latency: normal` por defecto. La guía del SDK indica que `balanced` es el valor por defecto del SDK para streaming y ofrece el menor tiempo hasta el primer audio. Indícalo explícitamente si te importa. El [anuncio del nivel gratuito](https://fish.audio/blog/s2-1-pro-free-api/) de Fish Audio cita unos 70 ms hasta el primer audio para S2.1 Pro en una sola petición. El resumen de modelos indica 100 ms para s2-pro. Ambos son datos del proveedor que no he medido por mi cuenta.

Si conectas esto a un framework de agentes, escribí una guía para [añadir Fish Audio TTS a Mastra](/es/mastra-fish-audio-tts/), y sus ejemplos de streaming usan estas mismas primitivas.

## Etiquetas de emoción y voces de referencia

Los modelos S2 interpretan indicaciones en lenguaje natural entre corchetes dentro del texto. Es una de las pocas cosas que hace Fish Audio y que la mayoría de las APIs de TTS no ofrecen.

```text
[happy] What a beautiful day!
[sad][whispering] I miss you so much.
[very excited] This is absolutely amazing!
```

La [referencia de emociones](https://docs.fish.audio/api-reference/emotion-reference) documenta 24 emociones básicas (`[happy]`, `[sad]`, `[angry]`, `[calm]`, `[sarcastic]`) y 25 avanzadas. Incluye también 6 marcadores de tono como `[whispering]` y `[emphasis]`, sonidos humanos (`[laughing]`, `[sighing]`, `[clear throat]`) y pausas (`[break]`, `[long-break]`). Coloca las indicaciones al inicio de la oración y combina modificadores de intensidad como `[slightly sad]` o `[extremely angry]`. Los corchetes aceptan pistas libres como `[warm and tired]` en 13 idiomas compatibles, incluidos inglés, español, japonés, chino y árabe.

Las etiquetas de emoción cuentan dentro de la longitud del texto, así que inclúyelas en tu cálculo de bytes. La documentación del servidor MCP indica que se facturan por byte, y es probable que la API REST las mida igual al cobrar por byte UTF-8 de entrada.

Ten en cuenta una diferencia de migración. El modelo retirado `s1` usaba paréntesis como `(happy)`, mientras que todos los modelos actuales esperan corchetes. Los tutoriales antiguos con etiquetas entre paréntesis apuntan a `s1`.

Para las voces, pasa `reference_id` con el ID de un modelo de voz. Cada voz en la biblioteca pública de fish.audio tiene uno en la URL de su página, por ejemplo `fish.audio/m/ca3007f96ae7499ab87d27ea3599956a`:

```python
audio = client.tts.convert(
    text="This is a custom voice from the Fish Audio library.",
    reference_id="ca3007f96ae7499ab87d27ea3599956a",
    model="s2.1-pro-free",
)
```

La biblioteca tiene una gran cantidad de voces de la comunidad, por lo que el rango de calidad es muy amplio. Pruébala antes de comprometerte con una en producción.

## Clonar una voz a través de la API

La clonación de voz es un POST multipart a `/model` (ojo: no está bajo `/v1`). Subes una o más muestras de audio y recibes un ID de modelo de voz, como se describe en la [referencia para crear modelos](https://docs.fish.audio/api-reference/endpoint/model/create-model):

<Tabs>
<Tab name="Python">

```python
from fishaudio import FishAudio

client = FishAudio()

with open("sample.wav", "rb") as f:
    voice = client.voices.create(
        title="My Voice",
        voices=[f.read()],
        description="Cloned from a studio sample",
        visibility="private",
    )

print(voice.id, voice.state)
```

</Tab>
<Tab name="curl">

```bash
curl --request POST https://api.fish.audio/model \
  --header "Authorization: Bearer $FISH_API_KEY" \
  --form type=tts \
  --form title="My Voice" \
  --form "description=Cloned from a studio sample" \
  --form visibility=private \
  --form train_mode=fast \
  --form voices=@sample.wav
```

</Tab>
</Tabs>

Las muestras pueden estar en wav, mp3, m4a u opus. Procura aportar al menos 10 segundos de audio limpio con un solo hablante por clip. Uno o dos minutos mejoran la fidelidad. La opción `enhance_audio_quality` viene activada por defecto y reduce el ruido de la entrada, así que déjala activada salvo que tu grabación ya tenga calidad de estudio. Con el valor por defecto `train_mode=fast`, el campo `state` pasa de `created` a `trained` (o `failed`). Después usa el ID exactamente igual que una voz de la biblioteca:

```python
audio = client.tts.convert(
    text="Now I speak in my cloned voice.",
    reference_id=voice.id,
    model="s2.1-pro-free",
)
```

También puedes hacer clonación en un solo paso pasando `references=[ReferenceAudio(audio=..., text=...)]` (desde `fishaudio.types`) directamente en la petición TTS. El SDK gestiona la codificación MessagePack por ti. En cambio, `curl` puro exige empaquetado manual, así que `POST /model` con limpieza posterior resulta más simple en scripts CLI puntuales. Consulta mi [guía para clonar voces con Fish Audio](/es/fish-audio-clonar-voz/) para ver todo el flujo y la interfaz web.

## Transcribir audio con el endpoint ASR

[`POST /v1/asr`](https://docs.fish.audio/api-reference/endpoint/openapi-v1/speech-to-text) transcribe un archivo de audio por petición. Ambos modelos cuestan 0,36 $ por hora de audio, y los errores no se facturan. Envía el archivo como multipart form data y selecciona el modelo con la cabecera `model`:

```bash
curl --request POST https://api.fish.audio/v1/asr \
  --header "Authorization: Bearer $FISH_API_KEY" \
  --header "model: transcribe-1-pro" \
  --form audio=@conversation.wav \
  --form ignore_timestamps=false
```

Esa cabecera es estricta. Envía `model: transcribe-1-pro` exactamente en minúsculas según la documentación. Cualquier error tipográfico u omisión enruta y factura tu llamada en silencio bajo el antiguo motor `transcribe-1` para clips cortos sin diarización de hablantes.

`ignore_timestamps` es `true` por defecto, así que solo obtienes `segments` a nivel de palabra y `speaker_turns` cuando lo pones en `false`, como arriba. La respuesta es un JSON con `text`, `duration` en segundos (silencio incluido), `segments` y `speaker_turns` para grabaciones con varios hablantes. En `transcribe-1-pro`, los cambios de hablante se marcan también en línea en `text` con etiquetas `<|speaker:0|>`. Las señales como `[laughter]` quedan en la transcripción salvo que pases `tag_audio_events=false`. `transcribe-1-pro` acepta grabaciones de hasta 60 minutos en wav, mp3, AAC/m4a, flac, ogg, webm y mov (en archivos de vídeo usa la primera pista de audio).

Ten cuidado con un fallo de timeout en producción cuando las grabaciones se alargan. Los timeouts por defecto del SDK pueden vencer a mitad de archivo. Para evitar el límite de 5 minutos de fetch, la documentación recomienda `RequestOptions(timeout=900)` en Python y `setGlobalDispatcher` de `undici` en Node.

A 0,36 $ por hora, el precio compite con los proveedores de transcripción de mi comparativa de [alternativas a OpenAI Whisper](/es/alternativas-openai-whisper/), aunque [AssemblyAI](/es/resena-assemblyai/) sigue ofreciendo funciones por lotes más completas. Para salidas locales más simples, consulta mi [script en Python para texto a voz con uv](/es/script-uv-texto-a-voz/).

## Errores, límites de tasa y precios

Las respuestas de error son JSON con `status` y `message`. Los códigos importantes:

| Estado | Significado | Qué hacer |
| --- | --- | --- |
| 400 | `reference_id` o parámetros incorrectos | Lee `message` y corrige la petición |
| 401 | Falta la clave API o no es válida | Comprueba `FISH_API_KEY` |
| 402 | Sin saldo para un modelo de pago | Usa `s2.1-pro-free` o recarga saldo |
| 413 | Petición demasiado grande | Comprime audios largos a mp3/opus |
| 429 | Has alcanzado tu límite de concurrencia | Reintenta con backoff exponencial |
| 503 | Servicio sobrecargado | Reintenta con backoff |

Los límites de tasa miden peticiones concurrentes en lugar de peticiones por segundo y se comparten entre todas las claves API de la cuenta. En la [página de precios y límites de tasa](https://docs.fish.audio/developer-guide/models-pricing/pricing-and-rate-limits), Starter (menos de 100 $ pagados) tiene 5 peticiones concurrentes, 100 $+ tiene 15 y 1.000 $+ tiene 50. Las respuestas HTTP 429 omiten la cabecera `Retry-After`, así que debes implementar el backoff exponencial por tu cuenta. En Starter, una respuesta de agente de voz de 4 segundos rinde unas 75 peticiones por minuto. Los bloques de audiolibro de 60 segundos bajan a unas 5 por minuto.

La tabla completa de precios a 26 de noviembre de 2026:

| Modelo | Precio |
| --- | --- |
| `s2.1-pro` / `s2-pro` TTS | 15,00 $ por millón de bytes UTF-8 |
| `s2.1-pro-free` TTS | 0,00 $, sin SLA, sujeto a uso justo |
| `drama-3` TTS | 50,00 $ por millón de bytes |
| `transcribe-1` / `transcribe-1-pro` | 0,36 $ por hora de audio |
| `transcribe-stream-1` ASR en tiempo real | 0,36 $ por hora de sesión (preview) |
| `voice-design-1` | 0,01 $ por petición exitosa |

No hay cuotas de suscripción ni mínimos mensuales para acceder a la API. Es pago por uso puro sobre saldo prepago.

## El atajo del servidor MCP

Si tu cliente soporta MCP, puedes ahorrarte escribir código para trabajo exploratorio. Fish Audio ofrece un [servidor MCP](https://docs.fish.audio/overview/mcp) por HTTP streamable en `https://api.fish.audio/mcp` con acceso OAuth. Expone búsqueda de voces, clonación, TTS, transcripción y generación de imagen y vídeo como herramientas. En Claude Code es un solo comando:

```bash
claude mcp add --transport http fish-audio https://api.fish.audio/mcp
```

Ejecuta `/mcp` dentro de Claude Code para autenticarte y lanza búsquedas de voces o lecturas de `intro.md` directamente desde los prompts. Las llamadas MCP descuentan créditos de la aplicación web (1 crédito por byte UTF-8 de entrada TTS, etiquetas de audio incluidas) en lugar del saldo de la API de desarrollador. Los límites del plan aplican por herramienta, exigiendo Plus o superior para vídeo y topando la generación gratuita de imágenes. Por eso MCP resulta ideal para prototipos rápidos.

## Notas para producción

Algunas cosas que dejaría resueltas antes de llevar esto a producción:

<ListCheck>
<ul>
<li><strong>Guarda las generaciones en caché.</strong> Calcula el hash del cuerpo de la petición (texto, voz, ajustes) y guarda el audio en disco u object storage para evitar latencia y coste al repetir. Con temperatura 0.7 la salida varía entre ejecuciones, así que una caché también conserva la toma que ya aprobaste.</li>
<li><strong>Reintenta solo lo que sea reintentable.</strong> Los códigos 429 y 5xx llevan backoff exponencial con jitter. Los 400, 401 y 402 nunca van a funcionar al reintentar, así que corrige la petición. Los errores no se facturan.</li>
<li><strong>Mantén las conexiones abiertas.</strong> Reutiliza conexiones HTTP keep-alive cuando generes en serie, para que el handshake TLS no se coma una generación por debajo del segundo.</li>
<li><strong>Decide cuándo basta el modelo gratuito.</strong> Prototipos, herramientas internas y bots con poco tráfico funcionan bien con `s2.1-pro-free`. Pasa a `s2.1-pro` de pago cuando necesites garantía de TTFA o un DPA, o al acercarte al millón de dólares de ARR que exige contacto previo.</li>
<li><strong>No dividas transcripciones largas.</strong> Las etiquetas de hablante solo son consistentes dentro de una misma respuesta, así que envía toda la conversación en una sola llamada a `/v1/asr`.</li>
</ul>
</ListCheck>

Si prefieres autoalojar, el proyecto hermano de pesos abiertos [fish-speech](https://github.com/fishaudio/fish-speech) corre en tu propia GPU. Su README sitúa el código y los pesos de Drama 3 bajo la Fish Audio Community License, mientras que los pesos de S2-Pro usan la Fish Audio Research License. Lee ambas licencias con atención antes de un uso comercial, o compara motores permisivos en [mejores motores TTS de código abierto](/es/mejores-motores-tts-codigo-abierto/).

## Preguntas frecuentes

<Accordion label="¿Es gratis la API de Fish Audio?" group="faq">
Sí, para desarrollo. El modelo `s2.1-pro-free` cuesta 0 $ por millón de bytes UTF-8 bajo una política de uso justo (Fair Use Policy), y es el mismo modelo que `s2.1-pro`. Las contrapartidas son falta de SLA y de garantía de latencia. Tus peticiones pueden usarse para mejorar el modelo, y por encima de 1 millón de dólares de ARR piden contactar con Fish Audio. El 26 de noviembre de 2026 la ventana gratuita anunciada llegaba hasta el 30 de noviembre de 2026, así que revisa la página de precios para ver qué aplica hoy.
</Accordion>

<Accordion label="¿Dónde encuentro mi clave API de Fish Audio?" group="faq">
Inicia sesión en fish.audio y abre la página Get Started en `fish.audio/app/developers/get-started/`. Haz clic en "Get your API key" y se crea en un clic. La clave se muestra una sola vez, así que cópiala de inmediato. Las claves existentes se gestionan en `fish.audio/app/api-keys`.
</Accordion>

<Accordion label="¿Cuánto cuesta la API de Fish Audio?" group="faq">
El TTS de pago en `s2.1-pro` o `s2-pro` cuesta 15 $ por millón de bytes UTF-8 de texto de entrada, aproximadamente 180.000 palabras en inglés o 12 horas de habla. `drama-3` cuesta 50 $ por millón de bytes en tarifa estándar. La transcripción cuesta 0,36 $ por hora de audio tanto para `transcribe-1` como para `transcribe-1-pro`. No hay mínimos mensuales. Funciona bajo pago por uso prepago.
</Accordion>

<Accordion label="¿Cuáles son los límites de tasa de la API de Fish Audio?" group="faq">
Los límites miden peticiones concurrentes, no por segundo: 5 en Starter (menos de 100 $ pagados), 15 desde 100 $ y 50 desde 1.000 $. Todas las claves API de la cuenta comparten el mismo cupo. Las respuestas 429 no incluyen cabecera `Retry-After`, así que implementa el backoff exponencial por tu cuenta.
</Accordion>

<Accordion label="¿Puedo usar comercialmente el audio generado por la API de Fish Audio?" group="faq">
El uso de pago es la vía segura. Para `s2.1-pro-free`, el anuncio señala que algunos escenarios comerciales pueden tener restricciones. Los productos por encima de 1 millón de dólares de ARR deben contactar antes con Fish Audio. Las peticiones gratuitas también pueden usarse para mejorar sus modelos, así que no envíes texto sensible por el nivel gratuito. Lee los términos vigentes en la página de precios antes de lanzar a producción.
</Accordion>

<Accordion label="¿Cómo clono una voz con la API de Fish Audio?" group="faq">
Envía un POST multipart form data a `https://api.fish.audio/model` con `type=tts`, un `title` y uno o más archivos de audio en `voices`. Sirven wav, mp3, m4a y opus, recomendando al menos 10 segundos de audio limpio con un solo hablante. La respuesta devuelve el ID de la voz, que luego pasas como `reference_id` en tus peticiones TTS.
</Accordion>

<Accordion label="¿La API de Fish Audio admite streaming?" group="faq">
Sí, de dos formas. Toda respuesta TTS ya llega fragmentada por HTTP, así que `--no-buffer` en curl o `tts.stream()` en Python reproducen el audio conforme se genera. Para entrada token a token desde un LLM, el método `stream_websocket()` del SDK de Python abre una sesión WebSocket con eventos de vaciado (flush) para controlar los turnos.
</Accordion>

<Accordion label="¿Qué idiomas soporta la API de Fish Audio?" group="faq">
S2.1 Pro soporta 83 idiomas con un único modelo, sin endpoints ni precios por idioma. La referencia de emociones enumera 13 idiomas para los marcadores de emoción, incluidos inglés, español, japonés, chino y árabe. El campo `language` del cuerpo solo orienta la normalización del texto, no la voz en sí.
</Accordion>
