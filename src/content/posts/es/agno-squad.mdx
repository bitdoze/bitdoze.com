Un equipo de Agno es un objeto `Team` con un modelo líder y agentes miembros. Con `mode="coordinate"` el líder delega en los miembros según su rol y luego escribe una sola respuesta. Este tutorial construye siete miembros detrás de un chat de Streamlit, sobre Agno 3.2.1.

Los miembros buscan en la web, leen páginas, obtienen los subtítulos de YouTube, listan historias de Hacker News, consultan GitHub, envían correo y responden preguntas generales. Cada sesión de navegador guarda su historial de chat en un archivo SQLite. Si aún no has construido un solo agente de Agno, lee primero [primeros pasos con Agno](/es/empezar-agno/).

## ¿Qué parámetros de Agno cambiaron desde la versión 1?

Ocho parámetros que el código de Agno 1.x pasaba a `Agent` y `Team` cambiaron de nombre o desaparecieron. Agno 2.0.0 lo hizo el 2025-09-09, y 3.2.1 mantiene los nombres de 2.0.

| Agno 1.x | Agno 3.2.1 | Nota |
|---|---|---|
| `add_history_to_messages=True` | `add_history_to_context=True` | Necesita un `db` y un `session_id` |
| `num_history_responses=3` | `num_history_runs=3` | |
| `add_datetime_to_instructions=True` | `add_datetime_to_context=True` | |
| `success_criteria="..."` | Eliminado | Pon la regla en `instructions` y ponle tope con `tool_call_limit` |
| `enable_agentic_context=True` | Eliminado | El historial del líder es `add_history_to_context` más una base de datos |
| `enable_team_history=True` | `add_team_history_to_members=True` | |
| `num_of_interactions_from_history=5` | `num_history_runs=5` | |
| `show_tool_calls=False` | Eliminado | |
| `from agno.run.response import RunResponse` | `from agno.run.team import TeamRunEvent` | `run()` devuelve `TeamRunOutput`, o eventos con `stream=True` |

La lista completa está en el [changelog de Agno v2.0](https://docs.agno.com/other/v2-changelog).

## ¿Qué necesitas antes de empezar?

Una clave de OpenRouter ejecuta la app. Los miembros de GitHub y de correo añaden dos claves y una dirección de remitente, y las otras cuatro herramientas no necesitan nada.

| Miembro | Herramienta | Paquete | Clave o ajuste |
|---|---|---|---|
| Líder y todos los miembros | modelo `OpenRouter` | viene con la instalación de abajo | `OPENROUTER_API_KEY` |
| internet-searcher | `WebSearchTools` | `ddgs` | ninguna |
| web-crawler | `Crawl4aiTools` | `crawl4ai` y un navegador Playwright | ninguna |
| youtube-analyst | `YouTubeTools` | `youtube-transcript-api` | ninguna |
| hackernews-monitor | `HackerNewsTools` | parte de Agno | ninguna |
| github-researcher | `GithubTools` | `PyGithub` | `GITHUB_ACCESS_TOKEN` |
| email-assistant | `ResendTools` | `resend` | `RESEND_API_KEY`, `EMAIL_FROM`, `EMAIL_TO` |

`GithubTools()` sin token lanza `ValueError: GitHub access token is required` al construirse, así que ese miembro solo se une cuando el token está definido. La documentación de GitHub lista Metadata, Issues y Pull requests como permisos separados en un token de grano fino, cada uno con un ajuste de solo lectura. Ese conjunto de solo lectura es lo que yo le daría a un miembro cuyas cuatro funciones solo leen. Resend necesita una clave y una dirección de remitente en un dominio que hayas verificado en Resend.

<Notice type="warning" title="Dos miembros actúan fuera de la app">
EmailAssistant envía correo real cuando el modelo decide hacerlo, y el kit completo de GitHub expone 39 funciones, incluida `delete_repository`. El código de abajo conserva cuatro funciones de GitHub de solo lectura y construye esos dos miembros solo cuando sus claves están definidas.
</Notice>

## ¿Cómo montas el proyecto con uv?

`uv init` crea el proyecto y una sola línea de `uv add` instala Agno con el extra de SQLite, Streamlit y los paquetes de herramientas. Las claves van en un archivo `.env` que `uv run` carga con su flag de archivo de entorno.

```bash
uv init --name ai-research-team --python 3.12
cd ai-research-team
uv add "agno[sqlite]" streamlit ddgs crawl4ai youtube-transcript-api resend PyGithub
```

El bloque de dependencias del `pyproject.toml` que eso produjo, en uv 0.9.28:

```toml
dependencies = [
    "agno[sqlite]>=3.2.1",
    "crawl4ai>=0.9.6",
    "ddgs>=9.16.1",
    "pygithub>=2.10.0",
    "resend>=2.56.2",
    "streamlit>=1.67.0",
    "youtube-transcript-api>=1.2.5",
]
```

`agno[sqlite]` importa. Sin él, `from agno.db.sqlite import SqliteDb` falla con `ModuleNotFoundError: No module named 'sqlalchemy'`, y el equipo no tiene historial de chat. `duckduckgo-search` no está en la lista. `DuckDuckGoTools` de Agno lanza `ImportError` y señala `ddgs` como el paquete que falta.

Pon las claves en `.env`:

```text

GITHUB_ACCESS_TOKEN=github_pat_your-token
RESEND_API_KEY=re_your-key
EMAIL_FROM=research@your-verified-domain.example
EMAIL_TO=you@example.com
```

### app.py, parte 1: imports, claves y estado de sesión

Las cinco partes de código de abajo, en orden, son todo el `app.py`.

```python
# app.py
import os
from uuid import uuid4

import streamlit as st

from agno.agent import Agent
from agno.db.sqlite import SqliteDb
from agno.models.openrouter import OpenRouter
from agno.run.agent import RunEvent
from agno.run.team import TeamRunEvent
from agno.team import Team
from agno.tools.crawl4ai import Crawl4aiTools
from agno.tools.github import GithubTools
from agno.tools.hackernews import HackerNewsTools
from agno.tools.resend import ResendTools
from agno.tools.websearch import WebSearchTools
from agno.tools.youtube import YouTubeTools

st.set_page_config(page_title="Research Assistant Team", page_icon="RS", layout="wide")

# --- Configuration ---
# `uv run --env-file .env` puts the .env file into the process environment.
OPENROUTER_API_KEY = os.getenv("OPENROUTER_API_KEY")
GITHUB_ACCESS_TOKEN = os.getenv("GITHUB_ACCESS_TOKEN")
RESEND_API_KEY = os.getenv("RESEND_API_KEY")
EMAIL_FROM = os.getenv("EMAIL_FROM")
EMAIL_TO = os.getenv("EMAIL_TO")

if not OPENROUTER_API_KEY:
    st.error(
        "OPENROUTER_API_KEY is not set. Put it in .env and start the app with "
        "`uv run --env-file .env streamlit run app.py`."
    )
    st.stop()

# --- Model ---
# One model object. Every member without its own model inherits a copy of it.
model = OpenRouter(id="openai/gpt-5-mini", retries=2, exponential_backoff=True)
model_name = "OpenRouter (openai/gpt-5-mini)"

# --- Session State ---
# Streamlit reruns this script after every interaction. The team lives in
# session_state, so it is built once per browser session.
def new_session_id():
    """One id per browser session. It names the stored runs in research_team.db."""
    return f"streamlit-team-session-{uuid4().hex[:12]}"


if "team_session_id" not in st.session_state:
    st.session_state.team_session_id = new_session_id()
if "messages" not in st.session_state:
    st.session_state.messages = []
```

`openrouter/optimus-alpha` no está en el [catálogo de OpenRouter](https://openrouter.ai/api/v1/models) el 2026-11-27, y su endpoint de modelo lista cero endpoints. `openai/gpt-5-mini` es el id de la documentación de OpenRouter de Agno y está en el catálogo con un contexto de 400,000 tokens y soporte de herramientas. `OPENROUTER_API_KEY` viene del entorno, así que el código no pasa ninguna clave.

## ¿Cómo funciona un equipo de Agno en modo coordinate?

El modelo líder ve el `id`, el `name` y el `role` de cada miembro en su mensaje de sistema y llama a `delegate_task_to_member(member_id, task)` para los que elige. Cada miembro delegado se ejecuta como un agente aparte con su propio mensaje de sistema y sus herramientas, y el líder escribe la respuesta final a partir de sus resultados.

Este es el plantel tal como lo capturó el laboratorio desde el prompt del líder:

```text
<team_members>
<member id="internet-searcher" name="InternetSearcher">
  Role: Find current information on the web
</member>
<member id="web-crawler" name="WebCrawler">
  Role: Read the content of a web page from its URL
</member>
...
</team_members>
```

El mismo prompt le dice al líder que trabaja en modo coordinate y que la salida de un miembro es evidencia, no la respuesta. Por eso `role` hace el enrutamiento y por eso cada miembro de abajo lleva un `id` explícito. Sin un `id`, Agno genera uno en tiempo de ejecución.

![Flujo de una pregunta: Streamlit llama al líder del equipo en modo coordinate, el líder entrega tareas a siete miembros con sus herramientas y claves, los resultados vuelven y el líder escribe una sola respuesta que se guarda en research_team.db](@assets/images/25/03/agno-squad-workflow.webp)

Coordinate es uno de cuatro modos:

| Modo | Ajuste | Qué ocurre | Coste | Úsalo cuando |
|---|---|---|---|---|
| Coordinate | `mode="coordinate"` (por defecto) | El líder elige miembros y escribe una sola respuesta | Llamadas al líder para seleccionar y sintetizar, además de cada ejecución de miembro | Las subtareas necesitan herramientas distintas |
| Route | `mode="route"` | Un miembro responde, sin paso de síntesis | Una llamada al líder para la selección y una ejecución de miembro | Cada pregunta tiene un solo dueño |
| Broadcast | `mode="broadcast"` | Todos los miembros reciben la misma tarea, el líder fusiona | Todos los miembros se ejecutan, uno tras otro en una ejecución síncrona y a la vez en una asíncrona | Quieres varios enfoques sobre una pregunta |
| Tasks | `mode="tasks"` | El líder avanza por una lista de tareas hasta terminar o llegar a `max_iterations` (10) | Las llamadas al líder y a los miembros se repiten hasta que se termina la lista o el límite detiene la ejecución | El trabajo tiene varios pasos ordenados |

El líder y los miembros hacen llamadas al modelo por separado, así que cada delegación cuesta tiempo y tokens. Cuando el orden de los pasos es fijo, uso un [Workflow de Agno](/es/equipo-escritura-agno-workflow/) en su lugar.

## ¿Cómo defines los siete agentes?

Cada miembro es un `Agent` con un `id`, un `name`, un `role`, y con `tools` e `instructions` opcionales. Los miembros sin `model` heredan una copia del modelo del equipo.

```python
# --- Agent Definitions ---
# Shared settings: each member remembers its own earlier turns. The team's telemetry flag
# does not reach the members, so it is turned off here as well.
member_defaults = {"add_history_to_context": True, "num_history_runs": 3, "telemetry": False}

search_agent = Agent(
    id="internet-searcher",
    name="InternetSearcher",
    role="Find current information on the web",
    tools=[WebSearchTools(enable_search=True, enable_news=False, fixed_max_results=5)],
    instructions=[
        "Use web_search for anything that needs a current source.",
        "Cite the URL behind every claim you take from a result.",
    ],
    add_datetime_to_context=True,
    markdown=True,
    **member_defaults,
)

crawler_agent = Agent(
    id="web-crawler",
    name="WebCrawler",
    role="Read the content of a web page from its URL",
    tools=[Crawl4aiTools(max_length=None)],
    instructions=[
        "Use crawl to read the URLs you are given.",
        "Summarize the key points and include the URL.",
    ],
    markdown=True,
    **member_defaults,
)

youtube_agent = Agent(
    id="youtube-analyst",
    name="YouTubeAnalyst",
    role="Get captions and metadata of a YouTube video",
    tools=[YouTubeTools(enable_get_video_timestamps=False)],
    instructions=[
        "Use get_youtube_video_captions and get_youtube_video_data for YouTube URLs.",
        "Summarize the key points and include the video URL.",
    ],
    markdown=True,
    **member_defaults,
)

email_agent = (
    Agent(
        id="email-assistant",
        name="EmailAssistant",
        role="Send an email with the findings",
        tools=[ResendTools(from_email=EMAIL_FROM, api_key=RESEND_API_KEY)],
        instructions=[
            "Send an email only when the user asks for one.",
            f"The default recipient is {EMAIL_TO}. Use the recipient from the query when it names one.",
            "Include URLs and links clearly.",
        ],
        markdown=True,
        **member_defaults,
    )
    if RESEND_API_KEY and EMAIL_FROM
    else None
)

github_agent = (
    Agent(
        id="github-researcher",
        name="GitHubResearcher",
        role="Search GitHub repositories, pull requests and issues",
        # Read-only subset: the full toolkit also exposes delete_repository and create_issue.
        tools=[
            GithubTools(
                access_token=GITHUB_ACCESS_TOKEN,
                include_tools=["search_repositories", "get_repository", "get_pull_requests", "list_issues"],
            )
        ],
        instructions=[
            "Search repositories or list pull requests based on the query.",
            "Include repository URLs and summarize the findings briefly.",
        ],
        add_datetime_to_context=True,
        markdown=True,
        **member_defaults,
    )
    if GITHUB_ACCESS_TOKEN
    else None
)

hackernews_agent = Agent(
    id="hackernews-monitor",
    name="HackerNewsMonitor",
    role="Fetch the top stories on Hacker News",
    tools=[HackerNewsTools(enable_get_user_details=False)],
    instructions=[
        "Fetch top stories with get_top_hackernews_stories.",
        "Summarize the discussions and include the story URLs.",
    ],
    add_datetime_to_context=True,
    markdown=True,
    **member_defaults,
)

general_agent = Agent(
    id="general-assistant",
    name="GeneralAssistant",
    role="Answer general questions that fit no other member",
    instructions=[
        "Answer general questions directly.",
        "When the query asks for a summary, combine the specialist findings.",
    ],
    markdown=True,
    add_history_to_context=True,
    num_history_runs=5,
    telemetry=False,
)

# The two members that need their own keys join only when the key is set.
members = [search_agent, crawler_agent, youtube_agent, hackernews_agent, general_agent]
if github_agent is not None:
    members.append(github_agent)
if email_agent is not None:
    members.append(email_agent)
```

| Parámetro | Por defecto | Qué hace aquí |
|---|---|---|
| `id` | Se genera a partir del nombre en tiempo de ejecución | La cadena exacta que el líder pasa a `delegate_task_to_member` |
| `name` | None | Se muestra en el plantel |
| `role` | None | El texto con el que el líder casa una tarea |
| `tools` | None | Kits de herramientas cuyos nombres de función llama el modelo |
| `instructions` | None | Se añade al mensaje de sistema del miembro |
| `add_datetime_to_context` | `False` | Añade una línea con la hora actual |
| `add_history_to_context` | `False` | Añade las ejecuciones anteriores del propio miembro en la sesión del equipo |
| `num_history_runs` | 3 | Cuántas de esas ejecuciones |
| `markdown` | `False` | Añade "Use markdown to format your answers." |
| `telemetry` | `True` | Envía un registro por ejecución a os-api.agno.com salvo que valga `False` |

Las instrucciones nombran las funciones de las herramientas a propósito. El modelo elige una función por su nombre, y `duckduckgo_search` y `web_crawler` no están registradas en 3.2.1. Las funciones de búsqueda son `web_search` y `search_news`, y la función de rastreo es `crawl`. Un miembro también puede llevar herramientas de un servidor MCP, como en [Context7 MCP con Agno](/es/agno-herramientas-mcp-context7/).

Uso `WebSearchTools` en lugar de `DuckDuckGoTools` por lo que cada una devolvió desde mi laboratorio. `DuckDuckGoTools` es una subclase de `WebSearchTools` que solo fija el backend en duckduckgo.

| Clase | Backend | Resultado en el laboratorio para `Agno agent framework` | Contrapartida |
|---|---|---|---|
| `DuckDuckGoTools` | `duckduckgo` | `No results found` | Un solo backend, así que un rechazo deja al miembro sin nada |
| `WebSearchTools` | `auto` | Resultados en dos ejecuciones | El backend automático elige por su cuenta, y las dos ejecuciones devolvieron distintos primeros resultados |

## ¿Cómo construyes el equipo?

`Team(mode="coordinate", members=members, db=SqliteDb(...))` lo construye. El `db` es lo que hace funcionar el historial de chat, porque Agno guarda cada ejecución bajo el `session_id` que pasas a `run()`.

```python
# --- Team ---
def initialize_team():
    """Build the team. Called once per browser session and again after a reset."""
    return Team(
        name="ResearchAssistantTeam",
        model=model,
        mode="coordinate",
        members=members,
        instructions=[
            "Analyze the query and assign tasks to the specialists.",
            "Delegate based on task type:",
            "Web searches: internet-searcher",
            "URL content: web-crawler",
            "YouTube videos: youtube-analyst",
            "Hacker News: hackernews-monitor",
            "GitHub queries: github-researcher",
            "Emails: email-assistant",
            "General questions and synthesis: general-assistant",
            "Answer from the earlier turns in your context when the query refers to them.",
            "Synthesize the member responses into one answer and cite sources.",
            "Once you have enough information, answer directly. Delegate at most 7 times per request.",
        ],
        # Memory: runs are stored per session_id; the leader gets the last 5 runs back.
        db=SqliteDb(db_file="research_team.db"),
        add_history_to_context=True,
        num_history_runs=5,
        # Members get the last 3 team turns and the responses of members that ran before them.
        add_team_history_to_members=True,
        num_team_history_runs=3,
        share_member_interactions=True,
        # Hard cap on delegations per question. The next one returns "Tool call limit reached".
        tool_call_limit=7,
        markdown=True,
        telemetry=False,
    )


if "team" not in st.session_state:
    st.session_state.team = initialize_team()
```

| Parámetro | Por defecto | Aquí | Coste o contrapartida |
|---|---|---|---|
| `mode` | `coordinate` | `"coordinate"` | Llamadas al líder para seleccionar y sintetizar |
| `db` | None | `SqliteDb(db_file="research_team.db")` crea las tablas `agno_sessions` y `agno_runs` | Un archivo que crece con cada ejecución |
| `add_history_to_context` | `False` | `True`, el líder recibe las ejecuciones anteriores | Los mensajes anteriores, llamadas a herramientas incluidas, van a cada prompt del líder |
| `num_history_runs` | 3 | 5 | Más ejecuciones añaden más tokens a cada pregunta |
| `add_team_history_to_members` | `False` | `True`, las tareas de los miembros empiezan con la entrada y la respuesta de ejecuciones anteriores | Prompts de miembro más largos |
| `num_team_history_runs` | 3 | 3 | Se mantiene el valor por defecto |
| `share_member_interactions` | `False` | `True`, los miembros posteriores ven la tarea y la respuesta de los miembros anteriores de la misma ejecución | La tarea de un miembro posterior crece con cada respuesta anterior |
| `tool_call_limit` | None | 7, una delegación por miembro como máximo | Una delegación rechazada devuelve una cadena de error al líder |
| `stream_member_events` | `True` | Se deja por defecto para que los errores de los miembros lleguen a la app | El stream también lleva texto de los miembros, así que el bucle debe filtrarlo |
| `markdown` | `False` | `True` | Una instrucción más en cada prompt |
| `telemetry` | `True` | `False`, en el equipo y en cada miembro | Ninguno |
| `retries` | 0 | Se deja en 0, los reintentos van en el objeto del modelo | Un reintento a nivel de ejecución repite toda la ejecución |

`success_criteria` ya no existe. La última instrucción y `tool_call_limit` hacen su trabajo en 3.2.1. Con el límite en 3 en el laboratorio, la cuarta delegación volvió como "Tool call limit reached. Tool call delegate_task_to_member not executed. Don't try to execute it again." Para un equipo detrás de un bot en lugar de una página web, mira [el bot de Discord construido sobre un equipo de Agno](/es/crear-tu-propio-agente-ia/).

## ¿Cómo transmite la app de Streamlit la respuesta?

`team.run(question, stream=True, session_id=...)` devuelve un iterador de eventos. Añade texto solo desde `TeamRunEvent.run_content`, porque el equipo también reenvía los eventos de los miembros y, de lo contrario, acabarían en la burbuja del líder.

La ejecución de laboratorio de abajo hizo que el líder delegara una vez y luego respondiera. El primer evento de contenido es el del miembro:

```text
RunStartedEvent
ModelRequestStartedEvent
RunContentEvent  event='RunContent' content='HN member: three stories'
ModelRequestCompletedEvent
RunContentCompletedEvent
RunCompletedEvent
RunContentEvent  event='TeamRunContent' content='LEADER FINAL ONE'
```

Una ejecución fallida no lanza una excepción. Devuelve un evento de error cuyo `content` es el mensaje de error, así que el bucle maneja tres tipos de evento.

```python
# --- Streamlit UI ---
st.title("Research Assistant Team")
st.markdown(
    "This team coordinates specialists for web searches, website content, "
    "YouTube videos, Hacker News, GitHub, email and general questions."
)

# Display chat messages from history
for message in st.session_state.messages:
    with st.chat_message(message["role"]):
        st.markdown(message["content"])

# Handle user input
user_query = st.chat_input("Ask the research team anything...")

if user_query:
    # Add user message to chat history
    st.session_state.messages.append({"role": "user", "content": user_query})

    # Display user message
    with st.chat_message("user"):
        st.markdown(user_query)

    # Display team response (streaming)
    with st.chat_message("assistant"):
        message_placeholder = st.empty()
        full_response = ""
        member_errors = []
        team_error = None
        try:
            response_stream = st.session_state.team.run(
                user_query, stream=True, session_id=st.session_state.team_session_id
            )

            for event in response_stream:
                # The leader's answer arrives as TeamRunContent chunks.
                if event.event == TeamRunEvent.run_content and isinstance(event.content, str):
                    full_response += event.content
                    message_placeholder.markdown(full_response + "▌")  # Add cursor effect
                # Member runs are forwarded too. Their text is not the answer, their errors matter.
                elif event.event == RunEvent.run_error:
                    member_errors.append(f"{event.agent_name}: {event.content}")
                elif event.event == TeamRunEvent.run_error:
                    team_error = event.content

            if team_error:
                message_placeholder.empty()
                st.error(f"The team run failed: {team_error}")
            else:
                message_placeholder.markdown(full_response)  # Final response without cursor
            for failure in member_errors:
                st.warning(f"Member failed, the answer may be incomplete: {failure}")

            # Add the outcome to Streamlit's chat history
            if team_error:
                st.session_state.messages.append({"role": "assistant", "content": f"Error: {team_error}"})
            else:
                st.session_state.messages.append({"role": "assistant", "content": full_response})

        except Exception as e:
            message_placeholder.empty()
            st.exception(e)
```

## ¿Cómo fluye la memoria entre Streamlit y Agno?

Streamlit guarda lo que muestra la pantalla y Agno guarda lo que lee el modelo. `st.session_state.messages` contiene las burbujas, `research_team.db` contiene cada ejecución, y el id de sesión une las dos cosas.

![Diagrama de memoria: st.session_state guarda los mensajes, el equipo y el id de sesión; research_team.db guarda agno_sessions y agno_runs; el líder lee las últimas 5 ejecuciones, cada miembro lee sus propias últimas 3 ejecuciones, los últimos 3 turnos del equipo y las respuestas de los miembros anteriores; el botón de reinicio borra la sesión](@assets/images/25/03/agno-squad-memory.webp)

| Almacén | Qué contiene | Contrapartida |
|---|---|---|
| `st.session_state.messages` | Las burbujas | Se pierde al cerrar la pestaña, nunca se envía al modelo |
| `st.session_state.team` | El objeto `Team` | Se vuelve a construir en cada reinicio |
| `st.session_state.team_session_id` | El nombre de la sesión guardada | Nuevo después de cada reinicio |
| `research_team.db` | Una fila por sesión en `agno_sessions`, una fila por ejecución del líder o de un miembro en `agno_runs` | Se queda en disco y crece con cada ejecución hasta que borras el archivo |

En la pregunta siguiente los mensajes del líder empiezan con los mensajes anteriores de usuario, asistente, herramienta y asistente de las últimas cinco ejecuciones. Una tarea de miembro recibe delante la entrada y la respuesta de ejecuciones anteriores. Este es el mensaje de usuario de un miembro tal como lo capturó el laboratorio con un equipo de dos miembros y textos guionizados:

```text
<team_history_context>
[run-1]
input: USER QUESTION RUN 1
response: LEADER FINAL RUN 1

[run-2]
input: USER QUESTION RUN 2
response: LEADER FINAL RUN 2

</team_history_context>


task three A
```

Un miembro delegado más tarde en la misma ejecución también ve lo que devolvieron los miembros anteriores:

```text
<member_interaction_context>
See below interactions with other team members.
Member: HackerNewsMonitor
Task: task three A
Response: HN member: three stories

</member_interaction_context>
```

Cada miembro recibe también sus propias ejecuciones anteriores, por `add_history_to_context=True` en `member_defaults`. La barra lateral muestra lo que hay guardado:

## ¿Cuántas llamadas al modelo cuesta una pregunta?

Una pregunta sin delegación es una llamada al líder. Una delegación añade una llamada al líder y una ejecución de miembro, así que tres llamadas como mínimo.

Siete delegaciones en una pregunta fueron 15 llamadas en el laboratorio, ocho del líder y siete de los miembros. Conté los prompts con `count_tokens` de Agno (tiktoken) sobre la configuración de arriba:

| Quién llama | Mensaje de sistema | Esquemas de herramientas | Primer prompt completo | Herramientas |
|---|---|---|---|---|
| Líder | 659 | 89 | 750 | 1 |
| internet-searcher | 78 | 62 | 145 | 1 |
| web-crawler | 58 | 55 | 156 | 1 |
| youtube-analyst | 67 | 113 | 242 | 2 |
| hackernews-monitor | 79 | 54 | 215 | 1 |
| general-assistant | 53 | 0 | 154 | 0 |
| github-researcher | 78 | 472 | 670 | 4 |
| email-assistant | 70 | 52 | 262 | 1 |

El proveedor factura cada llamada por tokens de entrada y de salida, así que el número de miembros, el tamaño de sus esquemas de herramientas y el historial fijan la factura. Un miembro que llama a una herramienta hace al menos dos llamadas, una para elegir la función y otra para escribir su respuesta. El historial hace crecer el prompt del líder con cada pregunta. Con una delegación por pregunta el primer prompt del líder pasó de 751 a 867 tokens en cinco preguntas. Con siete delegaciones por pregunta, los prompts de una pregunta pasaron de 8,486 a 12,924 tokens en tres preguntas.

`tool_call_limit=7` pone tope a las delegaciones por pregunta. `num_history_runs` y `num_team_history_runs` ponen tope a lo que añaden las ejecuciones anteriores, y la documentación de Agno lista `max_tool_calls_from_history` para descartar resultados de herramientas antiguos del historial del líder. El caché de prompts depende del modelo y del proveedor, como señala la página de OpenRouter de Agno, y los mensajes de sistema de los miembros se repiten en cada llamada.

## ¿Qué falla y qué aspecto tiene?

La mayoría de los fallos aparecen como texto en el chat, no como un stack trace. Esto es lo que la app mostró en el laboratorio para cada caso.

| Fallo | Qué ves | Arreglo |
|---|---|---|
| Sin `OPENROUTER_API_KEY` | Un recuadro rojo en una página vacía | Define la clave en `.env` y arranca con el flag de archivo de entorno |
| Clave de OpenRouter no válida | "The team run failed: User not found." | Crea una clave nueva en la página de claves de OpenRouter |
| Id de modelo que ningún proveedor sirve | Un error 404 `not_found`, según la tabla de errores de OpenRouter (no ejecutado en el laboratorio) | Elige un id del catálogo |
| Límite de tasa (429) | Una línea de log por intento, y luego un evento `TeamRunError` cuando se agotan los reintentos | `retries=2, exponential_backoff=True` en el modelo |
| Falla el modelo de un miembro | Un recuadro amarillo, y el líder responde igualmente | Deja `stream_member_events` en su valor por defecto y vigila `RunEvent.run_error` |
| Falla una herramienta | El modelo recibe el texto del error como resultado de la herramienta y sigue | Comprueba la clave de esa herramienta |
| `exponential_backoff=True` sin `retries` | Una llamada, y luego el error | Define `retries` en el objeto del modelo |

![La app arrancada sin OPENROUTER_API_KEY: una alerta roja en una página vacía, con el mensaje de que la clave no está definida y el comando que arranca la app con el archivo de entorno](@assets/images/25/03/agno-squad-no-key-error.webp)

Sin clave, el texto de error de Agno es `OPENROUTER_API_KEY not set. Please set the OPENROUTER_API_KEY environment variable.`, y la app se detiene antes de que se muestre el chat por su propia comprobación. Con una clave no válida la clase OpenRouter real respondió 401 y el stream llevó un evento `TeamRunError` con `User not found.`:

![El chat después de una pregunta enviada con una clave de OpenRouter no válida: la burbuja de la pregunta y un recuadro rojo que dice The team run failed: User not found](@assets/images/25/03/agno-squad-chat-error.webp)

El objeto del modelo reintenta un límite de tasa. Con `retries=2` y `exponential_backoff=True`, un 429 guionizado produjo las líneas de log `Model provider error during stream (attempt 1/3)` y `Retrying in 1s...`, y luego `(attempt 2/3)` y `Retrying in 2s...`. El objeto del modelo no reintenta un 401. El log dijo `Non-retryable model provider error` después de una llamada.

Que un miembro falle no detiene el equipo. Cuando el modelo suplente respondió 429 al miembro de Hacker News, el líder recibió un resultado vacío y escribió su respuesta. La app mostró "Member failed, the answer may be incomplete: HackerNewsMonitor: 429 rate limit hit". Ese recuadro pertenece a la ejecución que lo produjo, así que el siguiente rerun lo quita.

Una herramienta que lanza una excepción entrega el error al modelo y la ejecución sigue. El miembro de GitHub con un token malo recibió esto como resultado de su herramienta:

```text
{"error": "401 {\"message\": \"Bad credentials\", \"documentation_url\": \"https://docs.github.com/rest\", \"status\": \"401\"}"}
```

GitHub limita las peticiones por hora y añade límites secundarios por demasiadas peticiones concurrentes, y OpenRouter documenta el 429 como `rate_limit_exceeded` con una cabecera `Retry-After`. Para comparar un segundo framework, empieza con [Google ADK](/es/empezar-google-adk/).

## Preguntas frecuentes

<Accordion label="¿Por qué falla el código de Agno escrito para la versión 1 en una instalación actual?" group="faq">

Agno 2.0.0 cambió el nombre de `add_history_to_messages` a `add_history_to_context` y eliminó `success_criteria`, `enable_agentic_context`, `enable_team_history` y `show_tool_calls`. Agno 3.2.1 mantiene los nombres de 2.0. La tabla del principio de esta página asocia cada parámetro antiguo con su sustituto.

</Accordion>

<Accordion label="¿Qué claves necesita la app?" group="faq">

`OPENROUTER_API_KEY` es la única que la app exige. `GITHUB_ACCESS_TOKEN` añade el miembro de GitHub, y `RESEND_API_KEY` con `EMAIL_FROM` añade el miembro de correo. La búsqueda web, el rastreo, los metadatos de YouTube y Hacker News funcionan sin ninguna clave.

</Accordion>

<Accordion label="¿Por qué necesita el equipo una base de datos para el historial de chat?" group="faq">

Agno guarda cada ejecución bajo el `session_id` pasado a `run()`, y `add_history_to_context=True` lee esas filas de vuelta en la pregunta siguiente. Sin un `db` no hay nada que leer. `SqliteDb(db_file="research_team.db")` del extra `agno[sqlite]` es lo que usa esta app.

</Accordion>

<Accordion label="¿Cuántas llamadas al modelo cuesta una pregunta?" group="faq">

Una llamada al líder sin delegación, tres con una delegación y 15 con siete. Cada miembro delegado se ejecuta como su propio agente, así que cada miembro añade su mensaje de sistema y sus esquemas de herramientas a la factura. `tool_call_limit` en el `Team` pone tope al número de delegaciones por pregunta.

</Accordion>

<Accordion label="¿exponential_backoff=True reintenta por su cuenta?" group="faq">

No. `retries` vale 0 por defecto, así que `exponential_backoff=True` no cambia nada hasta que defines `retries` en el mismo objeto. En el modelo, `OpenRouter(id="openai/gpt-5-mini", retries=2, exponential_backoff=True)` espera 1 segundo y luego 2 segundos entre intentos.

</Accordion>

<Accordion label="¿Por qué aparecen las respuestas de los miembros en la burbuja del líder?" group="faq">

`stream_member_events` vale `True` por defecto, así que el stream lleva los eventos `RunContent` de los miembros junto a los eventos `TeamRunContent` del líder. Añade texto solo cuando `event.event == TeamRunEvent.run_content`, o pon `stream_member_events=False` en el equipo.

</Accordion>

<Accordion label="¿Por qué el chat dice User not found?" group="faq">

OpenRouter responde 401 con ese texto cuando la clave es desconocida o está revocada. Agno lo convierte en un evento `TeamRunError` en lugar de una excepción, y la app lo muestra como "The team run failed: User not found.". Crea una clave nueva, ponla en `.env` y reinicia con el flag de archivo de entorno.

</Accordion>

<Accordion label="¿Envían datos de uso Agno y Streamlit?" group="faq">

Ambos lo hacen por defecto. Agno 3.2.1 pone `telemetry=True` y envía un registro por ejecución a os-api.agno.com. Streamlit 1.67.0 pone `browser.gatherUsageStats` en true. Pon `telemetry=False` en el equipo y en cada miembro, o `AGNO_TELEMETRY=false` en el entorno, y añade un `.streamlit/config.toml` con `gatherUsageStats = false`.

</Accordion>
