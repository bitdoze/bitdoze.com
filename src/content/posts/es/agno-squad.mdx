## Requisitos previos y configuración del entorno con uv

Antes de sumergirnos en la creación de agentes, configuremos nuestro entorno de desarrollo. Usaremos `uv`, la alternativa sobrealimentada a pip, que es hasta 100 veces más rápida y está construida en Rust (porque hoy en día todo lo genial parece estar construido en Rust).

### ¿Por qué uv?

Imagina que esperas la entrega de una pizza. `pip` es como ese repartidor que se pierde, toma las calles equivocadas y te entrega la pizza fría una hora después. `uv` es el cohete de reparto que deja la pizza en tu puerta antes de que termines de hacer el pedido. Es así de rápido.

### Instalación de uv

Para macOS/Linux:
```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Para Windows:
```powershell
irm https://astral.sh/uv/install.ps1 | iex
```

### Configuración del proyecto

Creemos un proyecto nuevo e instalemos las dependencias:

```bash
mkdir ai-research-team
cd ai-research-team

# Create and activate a virtual environment
uv venv
source .venv/bin/activate  # On Windows: .venv\Scripts\activate

# Install dependencies at warp speed
uv add agno streamlit python-dotenv duckduckgo-search crawl4ai youtube-transcript-api resend pygithub hackernews
```

### Variables de entorno

Nuestro equipo de agentes necesita claves de API para acceder a varios servicios. Crea un archivo `.env` en el directorio de tu proyecto:


## Entendiendo los agentes de Agno: conceptos clave

Antes de empezar a construir nuestro equipo soñado, entendamos qué hace funcionar a los agentes de Agno. Piensa en Agno como el cazatalentos, el entrenador y el mánager de tu escuadrón de IA: se encarga de toda la maquinaria compleja para que tú te centres en crear agentes con superpoderes.

### ¿Qué compone a un agente de Agno?

En esencia, un agente de Agno consta de cuatro componentes esenciales:

1. **Model**: el cerebro de tu agente. Normalmente es un modelo de lenguaje grande (LLM) como los modelos de OpenAI o, en nuestro caso, modelos a los que se accede mediante OpenRouter, como Quasar Alpha.

2. **Tools**: habilidades especiales que tu agente puede usar para interactuar con el mundo. Van desde búsquedas en la web (DuckDuckGo) hasta el envío de correos electrónicos (Resend) o el análisis de vídeos de YouTube.

3. **Instructions**: el manual de juego de tu agente. Son pautas específicas que moldean cómo el agente aborda los problemas.

4. **Memory**: la capacidad del agente para recordar interacciones previas, que puede almacenarse en bases de datos como SQLite.

### El ciclo de vida de un agente

Cuando un usuario envía una consulta a un agente de Agno, se desencadena un proceso fascinante:

1. **Procesamiento de la entrada**: el agente recibe el mensaje del usuario.
2. **Composición del contexto**: el agente reúne el contexto relevante, incluidas sus instrucciones y su historial.
3. **Selección de herramientas**: el agente decide si debe usar herramientas y cuáles (como buscar en la web).
4. **Generación de la respuesta**: el LLM genera una respuesta basada en toda la información disponible.
5. **Actualización de la memoria**: la interacción se almacena en la memoria del agente para futuras consultas.

Este ciclo se produce de forma transparente entre bastidores, dando a los usuarios la impresión de conversar con una entidad experta en lugar de con una compleja pieza de software.

### Modos de agente frente a equipo

Agno admite dos formas principales de organizar tu fuerza de trabajo de IA:

1. **Agentes individuales**: entidades especializadas centradas en tareas concretas. Como contratar a un consultor experto.

2. **Equipos**: conjuntos de agentes coordinados para abordar tareas complejas. Como reunir un grupo operativo especializado.

Nuestro proyecto utilizará el modo de equipo «coordinate», en el que un líder de equipo (coordinador) descompone las tareas complejas, las asigna a los especialistas y sintetiza sus resultados en un todo cohesivo. Es como tener un jefe de proyecto que sabe exactamente a qué miembro del equipo recurrir para cada subtarea.

| Modo | Ideal para | Analogía del mundo real |
|------|----------|--------------------|
| Agente individual | Tareas acotadas con límites claros | Consultor independiente |
| Equipo (Coordinate) | Tareas complejas que requieren varias especialidades | Equipo de proyecto con jefe |

Ahora que entendemos los fundamentos, ¡empecemos a construir nuestros agentes especializados!

### El buscador de Internet: tu detective web

El primero es nuestro detective web, capaz de encontrar la información más reciente en todo internet. Este agente es esencial para los datos en tiempo real que no están en nuestra base de conocimiento.

```python
search_agent = Agent(
    name="InternetSearcher",
    model=model,
    tools=[DuckDuckGoTools(search=True, news=False)],
    add_history_to_messages=True,
    num_history_responses=3, # Limit history passed to agent
    description="Expert at finding information online.",
    instructions=[
        "Use duckduckgo_search for web queries.",
        "Cite sources with URLs.",
        "Focus on recent, reliable information."
    ],
    add_datetime_to_instructions=True, # Add time context
    markdown=True,
    exponential_backoff=True # Add robustness
)
```

**Características clave:**
- **DuckDuckGoTools**: la lupa de nuestro agente para investigar la web
- **add_history_to_messages**: lleva el registro de los resultados de búsqueda anteriores
- **exponential_backoff**: gestiona con elegancia los límites de peticiones (porque hasta los detectives digitales necesitan pausas para el café)

## Coordinación con el modo de equipo: construir todo el escuadrón

Ya tenemos nuestros agentes especializados listos, pero son solo expertos individuales sin una forma de colaborar. Ahora es el momento de reunirlos bajo el modo de equipo «coordinate» de Agno; piénsalo como nombrar a un jefe de proyecto que sabe exactamente a qué especialista llamar para cada parte de una tarea compleja.

### Creación del equipo de investigación

Aquí es donde definimos la estructura de nuestro equipo y cómo trabajarán juntos los agentes:

```python
# --- Team Initialization (in Session State) ---
def initialize_team():
    """Initializes or re-initializes the research team."""
    return Team(
        name="ResearchAssistantTeam",
        mode="coordinate",
        model=model,
        members=[
            search_agent,
            crawler_agent,
            youtube_agent,
            email_agent,
            github_agent,
            hackernews_agent,
            general_agent
        ],
        description="Coordinates specialists to handle research tasks.",
        instructions=[
            "Analyze the query and assign tasks to specialists.",
            "Delegate based on task type:",
            "- Web searches: InternetSearcher",
            "- URL content: WebCrawler",
            "- YouTube videos: YouTubeAnalyst",
            "- Emails: EmailAssistant",
            "- GitHub queries: GitHubResearcher",
            "- Hacker News: HackerNewsMonitor",
            "- General or synthesis: GeneralAssistant",
            "Synthesize responses into a cohesive answer.",
            "Cite sources and maintain clarity.",
            "Always check previous conversations in memory before responding.",
            "When asked about previous information or to recall something mentioned before, refer to your memory of past interactions.",
            "Use all relevant information from memory when answering follow-up questions."
        ],
        success_criteria="The user's query has been thoroughly answered with information from all relevant specialists.",
        enable_agentic_context=True,      # Coordinator maintains context
        share_member_interactions=True, # Members see previous member interactions in context
        show_members_responses=False,     # Don't show raw member responses in final output
        markdown=True,
        show_tool_calls=False,            # Don't show raw tool calls in final output
        enable_team_history=True,         # Pass history between coordinator/members
        num_of_interactions_from_history=5 # Limit history passed
    )

if "team" not in st.session_state:
    st.session_state.team = initialize_team()
```

### Cómo funciona la coordinación del equipo

Analicemos qué ocurre en este modo «coordinate»:

1. **Creación del equipo**: creamos un objeto `Team` con una colección de agentes especializados como miembros.

2. **Rol del coordinador**: el equipo funciona en modo «coordinate», donde el modelo especificado (en nuestro caso, el mismo `model` que usamos para los agentes individuales) actúa como coordinador.

3. **Delegación de tareas**: cuando llega una consulta del usuario, el coordinador la analiza y decide a qué especialista o especialistas involucrar.

4. **Flujo de información**: el coordinador envía subtareas a los agentes apropiados, recopila sus respuestas y sintetiza una respuesta final.

5. **Gestión de la memoria**: con `enable_team_history=True`, tanto el coordinador como los miembros tienen acceso al historial de la conversación, lo que hace que las preguntas de seguimiento sean fluidas.

### Explicación de las opciones de configuración del equipo

Exploremos las opciones de configuración clave que hacen que nuestro equipo sea eficaz:

| Parámetro | Propósito | Impacto |
|-----------|---------|--------|
| `mode="coordinate"` | Establece el patrón de funcionamiento del equipo | Crea una estructura jerárquica con un coordinador |
| `enable_agentic_context` | Da al coordinador un contexto persistente | Mantiene la conciencia a lo largo de las interacciones |
| `share_member_interactions` | Comparte los resultados de los especialistas entre los miembros | Crea conciencia colaborativa |
| `show_members_responses` | Controla la visibilidad de las respuestas sin procesar | Se establece en `False` para respuestas finales limpias |
| `enable_team_history` | Habilita el acceso al historial para todos | Crea continuidad de memoria para las preguntas de seguimiento |

### Explicación de los «criterios de éxito»

Una de las funciones más potentes del modo de equipo de Agno es la posibilidad de definir criterios de éxito. Esto da al coordinador una guía clara sobre cuándo se considera completada una tarea:

```python
success_criteria="The user's query has been thoroughly answered with information from all relevant specialists."
```

Esta simple declaración tiene un impacto profundo: le indica al coordinador que siga trabajando (y delegando) hasta reunir suficiente información de los especialistas adecuados para ofrecer una respuesta completa.

Piénsalo como establecer el estándar de lo que constituye un «trabajo bien hecho» para tu equipo de IA. Sin esto, el coordinador podría precipitarse hacia conclusiones o pasar por alto aportaciones importantes de los especialistas.

## Integración con Streamlit: dale una cara a tu equipo

Ahora que tenemos un potente equipo de investigación rugiendo bajo el capó, es hora de construir una interfaz de usuario intuitiva con Streamlit. ### Construcción de la interfaz de Streamlit

El streaming es la clave aquí: los usuarios quieren ver las respuestas aparecer en tiempo real, igual que en ChatGPT o Claude. Configuremos nuestra app de Streamlit para ofrecer esa experiencia:

```python
# --- Streamlit UI ---
st.title("🤖 Research Assistant Team")
st.markdown("""
This team coordinates specialists to assist with:
- 🔍 Web searches
- 🌐 Website content extraction
- 📺 YouTube video analysis
- 📧 Email drafting/sending
- 💻 GitHub repository exploration
- 📰 Hacker News trends
- 🧠 General queries and synthesis
""")

# Display chat messages from history
for message in st.session_state.messages:
    with st.chat_message(message["role"]):
        st.markdown(message["content"])

# Handle user input
user_query = st.chat_input("Ask the research team anything...")

if user_query:
    # Add user message to chat history
    st.session_state.messages.append({"role": "user", "content": user_query})

    # Display user message
    with st.chat_message("user"):
        st.markdown(user_query)

    # Display team response (Streaming)
    with st.chat_message("assistant"):
        message_placeholder = st.empty()
        full_response = ""
        try:
            # Use stream=True for the team run
            response_stream: Iterator[RunResponse] = st.session_state.team.run(user_query, stream=True) # Ensure type hint

            for chunk in response_stream:
                # Check if content is present and a string
                if chunk.content and isinstance(chunk.content, str):
                    full_response += chunk.content
                    message_placeholder.markdown(full_response + "▌") # Add cursor effect
            message_placeholder.markdown(full_response) # Final response without cursor

            # Update memory debug information for display
            if hasattr(st.session_state.team, 'memory') and hasattr(st.session_state.team.memory, 'messages'):
                try:
                    # Extract only role and content safely
                    st.session_state.memory_dump = [
                        {"role": m.role if hasattr(m, 'role') else 'unknown',
                         "content": m.content if hasattr(m, 'content') else str(m)}
                        for m in st.session_state.team.memory.messages
                    ]
                except Exception as e:
                    st.session_state.memory_dump = f"Error accessing memory messages: {str(e)}"
            else:
                st.session_state.memory_dump = "Team memory object or messages not found/accessible."

            # Add the final assistant response to Streamlit's chat history
            st.session_state.messages.append({"role": "assistant", "content": full_response})

        except Exception as e:
            st.exception(e) # Show full traceback in Streamlit console for debugging
            error_message = f"An error occurred: {str(e)}\n\nPlease check your API keys and tool configurations. Try rephrasing your query."
            st.error(error_message)
            message_placeholder.markdown(f"⚠️ {error_message}")
            # Add error message to history for context
            st.session_state.messages.append({"role": "assistant", "content": f"Error: {str(e)}"})
```

### Cómo trabajan juntos Streamlit y Agno

Analicemos los puntos de integración entre Streamlit y nuestro equipo de Agno:

| Función de Streamlit | Propósito | Integración con Agno |
|-------------------|---------|----------------------|
| `st.session_state` | Mantiene el estado de la app entre interacciones | Almacena la instancia del equipo y el historial de la conversación |
| `st.chat_message` | Crea burbujas de chat para la conversación | Muestra las consultas del usuario y las respuestas del equipo |
| `st.empty()` | Crea un marcador de posición para el streaming | Se actualiza fragmento a fragmento con la respuesta transmitida del equipo |
| Componentes de la barra lateral | Ofrecen opciones de configuración y depuración | Muestran la memoria del equipo y permiten reiniciar la sesión |

La magia ocurre en el bucle de respuesta en streaming. Cuando un usuario envía una consulta:

1. La consulta se añade al historial de chat de Streamlit
2. Se pasa al equipo de Agno mediante `team.run(query, stream=True)`
3. A medida que llegan los fragmentos de la respuesta, se añaden al marcador de posición, logrando ese satisfactorio efecto en tiempo real
4. La respuesta final se almacena en el historial de la sesión para el contexto futuro

### Manejo de errores: cuando las cosas se tuercen

Hemos incorporado un manejo de errores robusto para que tus usuarios no vean trazas de error crípticas:

- Los problemas con las claves de API, los límites de peticiones o los fallos de las herramientas se capturan y se muestran como mensajes de error amigables
- La sesión del equipo permanece intacta, lo que permite a los usuarios volver a intentarlo con una consulta diferente
- La información de depuración está disponible en la barra lateral para la resolución de problemas

Este enfoque resistente significa que tu app de Streamlit no se bloqueará aunque uno de tus agentes especializados tenga un problema: ¡el espectáculo debe continuar!

## Añadir memoria y gestión de sesiones

Hemos construido un equipo potente y una interfaz elegante, pero falta un ingrediente crucial: la **memoria**. Igual que el equipo de Ocean sería bastante inútil si olvidara el plano del casino a mitad del atraco, nuestro equipo de IA necesita recordar las interacciones previas para ser realmente eficaz.

### Session state: el arma secreta de Streamlit

Streamlit ofrece un sistema de estado de sesión integrado que persiste entre las interacciones dentro de una sesión del navegador. Lo usamos para almacenar tres elementos clave:

1. **La instancia del equipo**: el equipo de investigación completo con todos sus agentes miembros
2. **El historial de mensajes**: todos los intercambios previos con el usuario
3. **El ID de sesión**: un identificador único para esta conversación concreta

Así es como inicializamos estos componentes:

```python
# --- Session State Initialization ---
# Initialize team_session_id for this specific browser session
if "team_session_id" not in st.session_state:
    st.session_state.team_session_id = f"streamlit-team-session-{int(time.time())}"
# Initialize chat message history
if "messages" not in st.session_state:
    st.session_state.messages = []
```

Esta sencilla inicialización garantiza que cada nueva sesión del navegador obtenga una instancia nueva del equipo y un historial de mensajes limpio, manteniendo al mismo tiempo la continuidad dentro de la sesión.

### La arquitectura de memoria de Agno

Agno ofrece tres tipos de memoria para nuestro equipo:

1. **Historial de chat**: la secuencia de interacciones entre el usuario y el equipo
2. **Contexto agéntico**: la comprensión que tiene el coordinador de la conversación en curso
3. **Historial del equipo**: contexto compartido entre todos los miembros del equipo

Veamos los ajustes específicos de memoria en la configuración de nuestro equipo:

```python
enable_agentic_context=True,      # Coordinator maintains context
share_member_interactions=True,     # Members see previous member interactions
enable_team_history=True,           # Pass history between coordinator/members
num_of_interactions_from_history=5  # Limit history passed
```

### El flujo de memoria en acción

Cuando un usuario envía una consulta, comienza una elegante danza de memoria:

1. La consulta se añade a los mensajes del estado de sesión de Streamlit
2. Se pasa al equipo de Agno, que accede a su propio historial
3. El coordinador examina la consulta en el contexto de las interacciones previas
4. Los agentes individuales reciben las partes relevantes del historial cuando se les asignan tareas
5. La respuesta final se añade de nuevo a los mensajes del estado de sesión

Este bucle continuo garantiza que las conversaciones resulten naturales y coherentes. ¡Pregunta «¿cuál fue mi primera pregunta?» y el equipo lo sabrá de verdad!

### Equilibrio entre memoria y rendimiento

La memoria es poderosa, pero tiene un coste. Hemos implementado varias optimizaciones para que todo funcione con fluidez:

| Estrategia | Implementación | Beneficio |
|----------|----------------|--------|
| Historial limitado | `num_of_interactions_from_history=5` | Evita el desbordamiento del contexto |
| Visualización selectiva | `show_members_responses=False` | Salida más limpia e historial más pequeño |
| Interruptor de depuración | Casilla en la barra lateral para inspeccionar la memoria | Visibilidad de la memoria bajo demanda |
| Botón de reinicio | "Clear Chat & Reset Team" | Un nuevo comienzo cuando se necesita |

Estas estrategias garantizan que nuestro equipo siga siendo rápido y receptivo incluso en conversaciones largas.
