## Qué debe hacer un buen plugin gratuito de copias de seguridad para WordPress

Antes de elegir un plugin, esto es lo que importa cuando algo va mal a las 2 de la madrugada:

<ListCheck>
<ul>
<li>Copiar a almacenamiento externo (Google Drive, S3, Dropbox, FTP), no solo al mismo servidor que acaba de morir</li>
<li>Ejecutarse en una programación automática, sin que tengas que acordarte</li>
<li>Manejar sitios grandes (más de 500 entradas, varios GB) sin agotar el tiempo de ejecución</li>
<li>Restaurar de forma sencilla: un clic, no un manual de 40 pasos</li>
<li>Tener una restauración probada. Una copia de la que nunca has restaurado es una esperanza, no una copia</li>
<li>Soportar reglas de retención para que los archivos antiguos no llenen tu disco o disparen tu factura de S3 en silencio</li>
</ul>
</ListCheck>

La parte externa no es negociable. Se aplica la clásica [regla de copias 3-2-1](https://www.backblaze.com/blog/the-3-2-1-backup-strategy/): 3 copias de tus datos, en 2 soportes distintos, con 1 copia fuera del sitio. Un plugin que solo escribe en `/wp-content/uploads/` del mismo servidor te da 1 copia en 1 soporte con 0 fuera del sitio. Si también quieres enviar copias externas a nivel de servidor, puedes [montar un bucket S3 como sistema de archivos en tu VPS](/es/montar-bucket-s3-sistema-archivos-vps/) y hacer snapshots de directorios enteros.

Regla de copias 3-2-1:

```
┌─────────────────────────────────────────────────┐
│              Regla 3-2-1                         │
│                                                  │
│  ┌──────────┐   ┌──────────┐   ┌──────────┐    │
│  │ 3 copias │   │ 2 tipos  │   │ 1 copia  │    │
│  │ de datos │──▶│ de soporte│──▶│ externa │    │
│  │          │   │ (disco + │   │ (nube:   │    │
│  │          │   │  nube)   │   │ GDrive,  │    │
│  │          │   │          │   │ S3, etc.)│    │
│  └──────────┘   └──────────┘   └──────────┘    │
└─────────────────────────────────────────────────┘
```

## 1. WPvivid (Backup, Migration & Staging)

<Picture formats={["webp"]} fallbackFormat="webp" src={imgWpvivid} alt="Panel del plugin WPvivid Backup mostrando las opciones de copia, restauración y migración en el admin de WordPress" />

[WPvivid](https://wordpress.org/plugins/wpvivid-backuprestore/) (v0.9.140, actualizado en noviembre de 2026) incluye más en su plan gratuito que cualquier competidor. El plugin cambió de nombre hace poco porque ahora también cubre migración y staging. 900.000 instalaciones activas, valoración 98/100 en WordPress.org.

El almacenamiento remoto gratuito incluye Dropbox, Google Drive, Amazon S3, OneDrive, [DigitalOcean Spaces](https://go.bitdoze.com/do), FTP y SFTP. Si prefieres almacenamiento barato compatible con S3, también funciona con [copias externas a Cloudflare R2](/es/backups-dokploy-cloudflare-r2/) y otros endpoints compatibles con S3.

En el plan gratuito obtienes:

- Copias automáticas programadas (archivos + base de datos, o cada una por separado)
- Migración completa del sitio: copia a un nuevo dominio o servidor sin un plugin aparte
- Staging básico en subdirectorio (instalación limpia de WordPress en un subdirectorio para pruebas)
- División de copias para proveedores de almacenamiento con límites de tamaño de archivo
- Restauración con un clic
- Tamaño y número de copias ilimitados
- Reglas básicas de retención para podar archivos antiguos
- Restauración directa desde el almacenamiento en la nube

La migración de sitios por sí sola ya justifica instalarlo. Si alguna vez necesitas mover WordPress a un nuevo hosting o clonarlo para pruebas, WPvivid resuelve ambas cosas sin un segundo plugin.

<Notice type="info" title="El staging es básico">
  El staging gratuito en subdirectorio sirve para pruebas rápidas, pero no es un pipeline de staging completo (sin flujo de publicación a producción). WPvivid vende un producto aparte, «Staging & Dev Environment Pro», para eso.
</Notice>

Elijas el destino que elijas, confirma que el primer archivo aparece allí. Mira la lista de verificación de abajo.

## 2. UpdraftPlus

<Picture formats={["webp"]} fallbackFormat="webp" src={imgUpdraft} alt="Pantalla de ajustes de UpdraftPlus Backup and Restoration en el admin de WordPress" />

[UpdraftPlus](https://wordpress.org/plugins/updraftplus/) tiene 4.000.000 de instalaciones activas, la mayor base instalada de cualquier plugin de copias para WordPress. La empresa detrás se hace llamar ahora TeamUpdraft (verás «David Anderson / Team Updraft» como autor del plugin). Versión 1.26.14, actualizada en octubre de 2026. Valoración 96/100.

El almacenamiento remoto gratuito incluye Dropbox, Google Drive, Amazon S3 (y compatibles), Rackspace Cloud, FTP, DreamObjects, OpenStack Swift y correo electrónico.

En el plan gratuito obtienes:

- Copias automáticas programadas (archivos + base de datos, o cada una)
- Restauración con un clic desde WordPress
- Migración gratuita del sitio: descarga la copia en el sitio de origen, súbela en el de destino y ejecuta el motor integrado de buscar y reemplazar para corregir las URL
- Límites de retención para controlar cuántas copias antiguas se conservan

La historia de la migración necesita una corrección frente a comparativas antiguas: **UpdraftPlus gratuito sí hace migración.** Descargas la base de datos, los plugins y los temas del sitio de origen, los subes al de destino y el motor de buscar/reemplazar corrige las URL. Lo que te da el complemento de pago «Premium migration» es el flujo directo de origen a destino: sin paso manual de descarga/subida.

La versión gratuita funciona bien para la mayoría de sitios y tiene el historial más largo. Las copias incrementales, el cifrado de base de datos, el soporte de OneDrive/Azure/Backblaze y el multisitio están todos en el nivel Premium. Si necesitas los precios actuales de Premium, consulta [teamupdraft.com](https://teamupdraft.com/) directamente. La antigua página de precios ya no funciona.

## 3. Duplicator Lite 5.0

[Duplicator](https://wordpress.org/plugins/duplicator/) (v5.1.1, actualizado en noviembre de 2026) tiene 1.000.000 de instalaciones activas según WordPress.org (el marketing del fabricante dice 1,5M+, probablemente incluyendo Pro). Valoración 98/100. Duplicator empezó como herramienta de migración y ha ido creciendo hasta ser una herramienta de copias. En octubre de 2026, la versión 5.0 fue un paso importante.

Duplicator Lite 5.0 funciona con el motor Pro y añadió al plan gratuito varias funciones que antes eran solo de pago:

- Restauración con un clic de cualquier copia desde la página de copias. Sin baile de FTP ni instalador
- Cifrado de copias con contraseña AES-256 (formatos DupArchive y ZIP). Es el único plugin gratuito de copias que cifra.
- **Múltiples carpetas de almacenamiento local** con reglas de retención por carpeta
- Integración con Duplicator Cloud: sube copias al almacenamiento en la nube propio de Duplicator (requiere un plan de pago aparte, desde 29 $/año por 2GB)
- Conector de recuperación: restaura desde el panel en la nube por FTP/SFTP
- Probador de configuración AutoTune para diagnosticar los límites del servidor antes de ejecutar una copia

Sigue siendo solo Pro: copias programadas, destinos en la nube de terceros (Google Drive, Dropbox, S3, FTP, SFTP), sitios de staging, multisitio, copias incrementales y destinos ilimitados.

Precios de Duplicator Pro (precios de lista, al año): Basic 79 $ (2 sitios), Plus 199 $ (5 sitios), Pro 399 $ (20 sitios), Elite 599 $ (100 sitios). El sitio hace promociones frecuentes de ~60%, pero esos son los precios de lista.

<Notice type="warning" title="Aviso sobre Recovery Points">
  «Recovery Points with quick rollbacks» aparece en el material de marketing como función gratuita, pero la página de precios lista «1-Click Restore Points» dentro del plan Basic de pago. La restauración con un clic de una copia listada está confirmada como gratuita en 5.0, pero no confíes en puntos de recuperación programados sin comprobar antes la interfaz de Lite.
</Notice>

Hay una trampa con el cifrado: la contraseña se convierte en un punto único de fallo. Si cifras una copia y pierdes la contraseña, el archivo es irrecuperable. Guárdala en un gestor de contraseñas, no en la misma carpeta que la copia.

Para copias manuales cifradas con restauración fácil, Duplicator gratuito es ahora posiblemente la opción más fuerte. Para copias programadas fuera del sitio hacia tu propio almacenamiento en la nube, sigue sin igualar al plan gratuito de WPvivid.

## Asegúrate de que tus copias se ejecutan

Instalar un plugin de copias es el paso uno. Asegurarte de que funciona es el paso dos, y la mayoría de guías se lo saltan.

### Arregla WP-Cron para que las programaciones se disparen

Los tres plugins programan copias a través de WP-Cron, que solo se dispara cuando alguien visita tu sitio. En un sitio con poco tráfico, eso significa que tu «copia diaria» puede ejecutarse a las 4 PM en lugar de a las 3 AM, o no ejecutarse en días.

Este es el modo de fallo número uno de «mi programación no se ejecutó». Arréglalo desactivando WP-Cron y usando una tarea cron real del sistema:

```bash
# En wp-config.php, encima de la línea "That's all":
define('DISABLE_WP_CRON', true);
```

Luego añade una entrada al crontab (ejecuta `crontab -e` como el usuario del servidor web):

```bash
# Ejecuta los eventos cron pendientes de WordPress cada 15 minutos
*/15 * * * * cd /var/www/wordpress && wp cron event run --due-now --quiet
```

Si estás en un VPS autogestionado (un [VPS de Hetzner Cloud](https://go.bitdoze.com/hetzner), un [droplet de DigitalOcean](https://go.bitdoze.com/do), Hostinger), tú controlas cron, así que configúralo bien. Si [instalas WordPress con Docker Compose](/es/instalar-wordpress-docker/), asegúrate de que la entrada de cron se ejecuta dentro del contenedor o en el host contra la ruta correcta.

También puedes cubrir la parte de copias externas a nivel de servidor con las [copias remotas integradas de CloudPanel a OneDrive y Google Drive](/es/copias-seguridad-remotas-cloudpanel/). Es un buen complemento a las copias a nivel de plugin.

Instala y actualiza por WP-CLI mientras estás:

```bash
wp plugin install wpvivid-backuprestore --activate
wp plugin update --all   # los plugins de copias son objetivos de actualización de alta severidad
```

### Lista de verificación posterior a la instalación

Una copia de la que nunca has restaurado es una esperanza, no una copia. Ejecuta este simulacro una vez tras la instalación:

<ListCheck>
<ul>
<li>Lanza una copia manual ahora. No esperes a la programación.</li>
<li>Confirma que el archivo aparece en el almacenamiento remoto. Para S3: <code>aws s3 ls s3://my-backup-bucket/wpvivid/ --recursive | tail -5</code></li>
<li>Restaura en una URL de pruebas/staging y recorre la portada, una entrada y el admin. Esto sirve además como ensayo de rollback.</li>
<li>Espera una ejecución programada y confirma que se disparó mirando el registro del plugin o la fecha del archivo más reciente.</li>
</ul>
</ListCheck>

Si el paso 3 rompe las URL (imágenes apuntando al dominio antiguo, enlaces con 404), ejecuta el buscar/reemplazar. WPvivid y UpdraftPlus tienen herramientas integradas para esto. El instalador de Duplicator lo hace automáticamente.

### Fallos habituales y soluciones

| Fallo | Causa | Solución |
|---|---|---|
| La programación nunca se dispara | WP-Cron depende del tráfico | `DISABLE_WP_CRON` + cron del sistema (ver arriba) |
| La autenticación del almacenamiento remoto caducó | Token OAuth revocado o contraseña cambiada | Vuelve a autenticar la conexión en los ajustes del plugin |
| El archivo no llega al almacenamiento externo | Las reglas de retención lo borraron, o la subida falló en silencio | Revisa el registro de copias; afloja la retención temporalmente |
| El disco o la factura de S3 crece rápido | Retención no configurada | Pon un límite de retención (conserva N copias, o borra tras X días) |
| La restauración rompe las URL del sitio | El dominio cambió sin buscar/reemplazar | Ejecuta la herramienta de buscar/reemplazar del plugin en la copia restaurada |
| La copia cifrada no se abre | Contraseña perdida | Irrecuperable. Prevención: guarda la contraseña en un gestor de contraseñas |

## Cuándo merece la pena un plugin de copias de pago

Los tres plugins ponen detrás del pago la misma función estrella: las copias incrementales. En lugar de copiar el sitio entero en cada ejecución, las incrementales solo capturan lo que cambió desde la última. En un sitio grande (varios GB, actualizaciones frecuentes), las copias completas consumen disco, ancho de banda y tiempo de servidor.

La escalera de costes (precios de lista, noviembre de 2026):

- **Duplicator Cloud** desde **29 $/año** (2GB): el almacenamiento externo gestionado más barato, funciona con Duplicator Lite
- **WPvivid Pro** desde **49 $/año** (plan Blogger, 2 dominios): añade copias incrementales, reglas de exclusión, bases de datos externas y más backends de almacenamiento (Wasabi, Backblaze, pCloud, WebDAV)
- **Duplicator Pro Basic** a **79 $/año** (2 sitios): añade copias programadas, destinos en la nube de terceros, staging y multisitio
- **UpdraftPlus Premium**: precio no citado aquí (consúltalo directamente en [teamupdraft.com](https://teamupdraft.com/))

Cuándo merece la pena pagar: tu sitio es lo bastante grande para que las copias completas ya no quepan en la ventana de copia, necesitas migración directa de origen a destino, usas multisitio, o necesitas cifrado gobernado por políticas en todo el conjunto.

El camino gratuito cuesta 0 $ en software, pero tu bucket externo cuesta unos pocos dólares al mes si no configuras la retención. Pon límites de retención desde el primer día.

**Un plugin de copias no es una copia del servidor.** Si estás en un VPS, el verdadero montaje 3-2-1 es copias a nivel de plugin + snapshots a nivel de servidor. Para la parte del servidor, mira las [copias autoalojadas con Restic y Rclone](/es/pluton-backup-autoalojado/) o [Zerobyte para programar copias Restic automatizadas](/es/zerobyte-interfaz-grafica-restic/). Las copias de plugin capturan WordPress; las del servidor capturan todo lo demás (configs de nginx, certificados SSL, tareas cron).

<Notice type="warning" title="Mantén los plugins de copias actualizados">
  El changelog de WPvivid de la v0.9.128 a la v0.9.140 (aproximadamente de mayo a noviembre de 2026) contiene al menos una docena de correcciones de vulnerabilidades de seguridad, atribuidas a WPScan, Wordfence Argus y Cipher Security Labs. Un plugin de copias desactualizado es un riesgo de puerta trasera. Ejecuta <code>wp plugin update --all</code> de forma programada. Y ya que estás reforzando: [asegura tu login de WordPress con autenticación de dos factores](/es/securizar-wordpress-2fa/).
</Notice>
