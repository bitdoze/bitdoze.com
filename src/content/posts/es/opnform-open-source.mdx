OpnForm es un creador de formularios de código abierto bajo AGPLv3 que puedes autoalojar con Docker Compose o usar como servicio alojado en opnform.com. Autoalojarlo es gratuito y tiene un límite de 2 usuarios por instancia, salvo que compres una licencia Enterprise. Autoaloja cuando las respuestas deben quedar en tu propio disco, y toma el plan Free alojado para un formulario de contacto en solitario.

Para este análisis de OpnForm ejecuté la v2.8.7, la última versión el 2026-11-27, en un proyecto Compose desechable en esta máquina (Docker 29.2.1, Compose v5.0.2). El repositorio en [github.com/OpnForm/OpnForm](https://github.com/OpnForm/OpnForm), movido desde JhumanJ/OpnForm, contaba ese día con 4,038 estrellas en GitHub. El proyecto se llamaba `rf-opn`, así que todos los nombres de contenedor de abajo empiezan con ese prefijo. Creé un formulario, lo envié como visitante, adjunté una notificación por correo, apunté un webhook a un listener y ejecuté una copia de seguridad con una restauración de prueba.

## Qué incluye el editor

El editor pide primero un estilo, Classic (preguntas en una o varias páginas) o Focused (una pregunta a la vez). Después pide un punto de partida: un formulario de contacto, una plantilla o una importación desde Typeform, Tally o Fillout.

## ¿Deberías autoalojar OpnForm o usar el servicio en la nube?

Autoalojar no cuesta ninguna licencia e incluye contraseñas, fechas de cierre, analíticas, envíos editables y SMTP para toda la instancia, todas funciones Pro en el lado alojado. OpnForm lo limita a 2 usuarios por instancia, así que toma el servicio alojado cuando más gente tenga que trabajar en la cuenta.

Todo lo que está fuera de `api/app/Enterprise` es AGPLv3, y ese directorio tiene su propia licencia. La [página de la licencia self-hosted](https://docs.opnform.com/deployment/self-hosted-license) lo resume en una tabla: uso personal sí, uso comercial sí, modificar y redistribuir el núcleo bajo AGPLv3 sí. La sección 13 de la AGPL es la parte que leer antes de construir sobre ella. Cambia el núcleo y ofrécelo por red, y esos usuarios pueden pedir tu código fuente modificado.

Sin licencia, una instancia autoalojada es la edición Community, y todas esas funciones estaban en mi instancia de prueba.

## ¿Cómo self-hostear OpnForm con Docker Compose?

Clona el repositorio, cambia el puerto de entrada en el archivo Compose y ejecuta `./scripts/docker-setup.sh --public-url https://forms.example.com`. El script escribe los dos archivos env y arranca ocho contenedores.

Necesitas git, openssl, Docker con el plugin Compose v2, unos 2 GB de disco para las imágenes y un puerto que puedas reservar.

Clona el repositorio y detente antes del primer arranque:

```bash
git clone https://github.com/OpnForm/OpnForm.git
cd OpnForm
```

El script de instalación escribe `api/.env` y `client/.env` a partir de las plantillas Docker. Genera `APP_KEY`, `JWT_SECRET` y el secreto compartido que `FRONT_API_SECRET` y `NUXT_API_SECRET` deben contener ambos, y define las cuatro variables de URL. También termina con `docker compose up -d`, así que antes van dos cambios en `docker-compose.yml`.

La entrada publica `80:80` en todas las interfaces. Eso choca con lo que ya ocupe el puerto 80 y deja el contenedor por delante de tu firewall, un problema que trata [Docker evita el firewall](/es/docker-evita-firewall/). Enlázalo a loopback y deja el puerto público para tu proxy inverso:

```yaml
  ingress:
    ports:
      - "127.0.0.1:8431:80"
```

La contraseña de la base de datos también vale `forge` por defecto (`${DB_PASSWORD:-forge}`). Pon una real en un archivo `.env` junto al archivo Compose, donde Compose resuelve esos marcadores. Un valor en `api/.env` pierde contra el bloque `environment:`. [Secretos en Docker Compose](/es/secretos-docker-compose/) tiene opciones más fuertes.

Ahora ejecuta el script:

```bash
chmod +x scripts/docker-setup.sh
./scripts/docker-setup.sh --public-url https://forms.example.com
```

Para una prueba en tu propia máquina, pasa `--public-url http://localhost:8431` en su lugar, la URL en la que corrió mi instancia de prueba.

## Ajustes que cambiar antes del tráfico real

Docker lee los valores del entorno cuando crea un contenedor. Después de cualquier cambio en `api/.env` o `client/.env`, ejecuta `docker compose down && docker compose up -d`. Un reinicio conserva los valores antiguos.

<Notice type="warning" title="Una instancia nueva no envía correo">
La plantilla de Docker trae `MAIL_MAILER=log`. Hasta que las variables `MAIL_*` apunten a un servidor SMTP, cada integración de correo termina como un evento de error con el motivo "The configured mail transport does not deliver email."
</Notice>

Adjunté una notificación por correo al formulario de prueba y envié una respuesta. El mensaje fue al log de `api-worker` y el evento de la integración tomó el estado `error`. Un segundo mensaje al administrador, "Integration issue with your form", lo siguió hasta el log. El bloque que lo arregla, en `api/.env`:

```ini
MAIL_MAILER=smtp
MAIL_HOST=smtp.example.com
MAIL_PORT=587
MAIL_USERNAME=forms@example.com
MAIL_PASSWORD=change-me
MAIL_ENCRYPTION=tls
MAIL_FROM_ADDRESS=forms@example.com
MAIL_FROM_NAME=Forms
```

La [configuración del relay SMTP de ZeptoMail](/es/configurar-relay-smtp-zeptomail/) muestra una forma de conseguir ese relay con Postfix en un VPS.

Las subidas caen en el disco local dentro del volumen `opnform_storage`, bajo `storage/app/forms/<form id>/submissions/`. Para almacenamiento de objetos en su lugar, apunta cuatro variables en `api/.env` a un bucket: `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_DEFAULT_REGION` y `AWS_BUCKET`. [RustFS](/es/rustfs-autoalojado/) o cualquier servicio compatible con S3 sirve. El ejemplo de CORS de la documentación permite cualquier origen; acótalo al dominio de tu formulario. En mi instancia el bloque File aceptó un límite por campo de 1 MB a 10 MB.

Pon Caddy, Traefik o lo que uses delante de la entrada. Haz que envíe `X-Forwarded-Proto: https` y sobrescriba lo que haya mandado el cliente. Luego define `TRUSTED_PROXIES` en `api/.env` con la dirección o el CIDR desde el que se conecta el proxy. Sin esa variable OpnForm confía en la cabecera de protocolo de cualquier llamador, lo que alcanza para detectar HTTPS pero pierde la IP real del cliente en los límites de frecuencia. Un `TRUSTED_PROXIES=` vacío y explícito desactiva la confianza en el proxy.

Tres llamadas salientes ocurren por defecto. La telemetría de la instancia reporta contadores de uso, un ID de instancia y tu nombre de host al proveedor; `OPNFORM_TELEMETRY_DISABLED=true` la detiene. Desde la v2.8.7, las analíticas consultan el país de cada visitante a través de InternetData cuando `IPINFO_TOKEN` no está definida, lo que envía las IPs públicas de los visitantes a ese servicio; `IP_LOCATION_PROVIDER=none` registra Unknown en su lugar. El editor de administrador también carga iconos desde api.iconify.design en el navegador, un problema para una instalación aislada de la red.

Planifica en torno a una regla. Las URLs de webhook deben ser HTTPS. Un listener en la red de Compose, `http://hook:8080/hook`, devolvió un 422:

```text
{"message":"The webhook URL must use HTTPS.","errors":{"data.webhook_url":["The webhook URL must use HTTPS."]}}
```

El código que hay detrás (`api/app/Service/Security/PublicWebhookUrl.php`) también exige que el host resuelva a direcciones públicas, salvo que `WEBHOOKS_ALLOW_PRIVATE_URLS=true`. Esa variable está en el código de la v2.8.7 y ni en la documentación ni en las plantillas env. Las direcciones privadas siguen necesitando HTTPS, y no probé esa ruta.

La generación de formularios con IA necesita `OPEN_AI_API_KEY` en `api/.env`. Sin ella el botón de generar acepta el texto y el trabajo falla unos segundos después con "You didn't provide an API key".

## Dónde viven los datos, y las copias de seguridad

Dos volúmenes guardan estado. `postgres-data` tiene los formularios, los envíos, los usuarios y los ajustes del espacio de trabajo. `opnform_storage` tiene los archivos subidos y la `oauth-private.key` que el entrypoint de la API genera en el primer arranque para OAuth. Pierde ese volumen y el entrypoint genera una clave nueva, y los tokens firmados con la antigua dejan de funcionar. Redis guarda caché, sesiones y la cola, así que no necesita copia de seguridad.

Vuelca la base de datos a través del contenedor db y copia el volumen de almacenamiento con un contenedor desechable:

```bash
mkdir -p backup
docker compose exec -T db pg_dump -U forge -d forge | gzip > backup/opnform-db.sql.gz
docker run --rm -v opnform_storage:/data:ro -v "$PWD/backup:/backup" alpine tar czf /backup/opnform-storage.tgz -C /data .
ls -l backup
```

```text
total 72
-rw-rw-r-- 1 dragos dragos 16046 Nov 27 16:57 opnform-db.sql.gz
-rw-r--r--  1 root   root   54733 Nov 27 16:57 opnform-storage.tgz
```

Reemplaza `forge` dos veces si cambiaste el nombre y el usuario de la base de datos, y el nombre del volumen si tu proyecto no se llama `OpnForm`. tar tiene que correr como root, así que el archivo pertenece a root. El archivo de clave tiene modo 600 y pertenece a www-data, y el mismo comando con `--user $(id -u)` falló con `tar: can't open './oauth-private.key': Permission denied`. Cámbiale el propietario después.

Cargué el volcado en una base de datos temporal en el mismo servidor y conté 44 tablas, 1 formulario y 1 envío.

La llamada de envío responde 200 con "Form submission saved" mientras la fila sigue siendo un trabajo en Redis; `api-worker` la escribe y dispara las integraciones un momento después. Así que `docker compose down` vale para recrear, y `docker compose down -v` no, porque los trabajos que esperan en Redis se van con el volumen.

## Actualizaciones

El archivo Compose sigue `latest`. Fija las dos imágenes de la aplicación a una versión, `jhumanj/opnform-api:2.8.7` y `jhumanj/opnform-client:2.8.7`, para que tú elijas cuándo moverlas. Muévelas juntas, porque el cliente y la API salen en pareja. Una actualización queda así:

```bash
git pull origin main
docker compose pull
docker compose up -d
docker compose logs api | grep -A2 "Running DB Migrations"
```

```text
api-1  | Running DB Migrations
api-1  |
api-1  |    INFO  Preparing database.
```

El entrypoint del contenedor de la API ejecuta `php artisan migrate --force` en cada arranque. Una versión con migraciones las aplica las hayas planeado o no (la v2.7.0 trajo cuatro, la v2.8.0 y la v2.8.7 ninguna). El `git pull` también importa. Desde la v2.8.7 el archivo Compose lleva un tercer worker, `api-country-worker`. Revertir las imágenes funciona hasta que una migración ha cambiado el esquema. Pasado ese punto la restauración sale del volcado. [Cómo actualizar contenedores de Docker Compose](/es/actualizar-contenedor-docker-compose/) tiene la secuencia de reversión.

## Preguntas frecuentes

<Accordion label="¿OpnForm es de verdad gratuito y de código abierto?" group="faq">
Sí. El núcleo es AGPLv3 y gratuito para uso personal y comercial, y el plan Free alojado tiene formularios y envíos ilimitados con marca. El código bajo `api/app/Enterprise` sale bajo una licencia aparte.
</Accordion>

<Accordion label="¿Cuántos usuarios puede tener una instancia autoalojada de OpnForm?" group="faq">
Dos en total en toda la instancia. El registro público se cierra después de la primera cuenta de administrador, así que el administrador invita al segundo usuario. Más usuarios requieren una licencia Enterprise self-hosted, $1,999 al año por instancia el 2026-11-27.
</Accordion>

<Accordion label="¿Cuánta RAM necesita OpnForm autoalojado?" group="faq">
Los ocho contenedores usaron unos 480 MiB en reposo en mi prueba, 167 MiB de ellos en el cliente Nuxt. Un VPS de 1 GB aloja la pila y un proxy inverso con poco margen, así que empezaría con 2 GB.
</Accordion>

<Accordion label="¿Por qué no llegan correos de OpnForm tras un envío?" group="faq">
La plantilla de Docker define `MAIL_MAILER=log`, así que el correo va al log de `api-worker` y el evento de la integración falla con "The configured mail transport does not deliver email." Define `MAIL_MAILER=smtp` con los valores de `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD` y `MAIL_FROM_ADDRESS`, y luego ejecuta `docker compose down && docker compose up -d`.
</Accordion>

<Accordion label="¿Por qué OpnForm rechaza mi URL de webhook?" group="faq">
Las URLs de webhook tienen que ser HTTPS, así que una dirección `http://` en la red de Compose devuelve 422 con "The webhook URL must use HTTPS." El host también debe resolver a direcciones públicas, salvo que `WEBHOOKS_ALLOW_PRIVATE_URLS=true` esté definida, una variable que el código de la v2.8.7 tiene y la documentación no. Revisa la cabecera `X-Webhook-Signature` cuando definas un secreto.

Haz un `pg_dump` primero, ejecuta `git pull origin main` para el archivo Compose y luego `docker compose pull && docker compose up -d`. El contenedor de la API ejecuta `php artisan migrate --force` al arrancar, así que revisa `docker compose logs api` para ver las líneas de migración.
