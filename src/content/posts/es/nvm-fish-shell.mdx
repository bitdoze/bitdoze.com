El nvm original (Node Version Manager) es un script de Bash. No funciona en Fish. Si intentas cargarlo con source en Fish, obtienes errores de sintaxis porque nvm depende de características POSIX shell que [Fish deliberadamente no soporta](/es/fish-shell-vs-bash-vs-zsh-comparacion/).

La solución es **nvm.fish**, un gestor de versiones de Node separado, escrito completamente en Fish. Mismo concepto (instalar y cambiar entre versiones de Node), implementación diferente. Está hecho por la misma persona que creó [Fisher](/es/mejores-plugins-fish-shell/), y funciona muy bien. Si quieres usar NVM con Fish Shell, esta es la herramienta que debes elegir. Funciona en fish 3.x y 4.x, así que la era de la reescritura en Rust de fish no ha roto nada.

Esta guía cubre la configuración completa, incluyendo lo que nvm.fish no hace, algo que conviene saber antes de depender de él.

## Instalar nvm.fish con Fisher

<ListCheck>
<ul>
<li>Fish 3.x o 4.x instalado (consulta las guías de <a href="/es/instalar-fish-shell-ubuntu/">Ubuntu</a> o <a href="/es/fish-shell-macos-configuracion/">macOS</a> si lo necesitas)</li>
<li>Fisher (se instala abajo si no lo tienes)</li>
<li>Acceso de red a `nodejs.org` o a un mirror</li>
<li>Unos 10 minutos</li>
</ul>
</ListCheck>

Necesitas [Fisher](/es/mejores-plugins-fish-shell/) primero. Si no lo tienes:

```fish
curl -sL https://raw.githubusercontent.com/jorgebucaran/fisher/main/functions/fisher.fish | source && fisher install jorgebucaran/fisher
```

Luego instala nvm.fish:

```fish
fisher install jorgebucaran/nvm.fish
```

Eso es todo. No necesitas ninguna configuración adicional. Reinicia tu shell o abre una nueva pestaña de terminal.

<Notice type="info" title="Estado del proyecto (2026)">
El último release etiquetado de nvm.fish es **2.2.17 (2025-02-07)**. La rama `main` reporta la versión 2.2.18, y los commits desde la última etiqueta son en su mayoría de Dependabot y CI. El proyecto no está archivado y sigue funcionando bien, pero tiene un mantenimiento bajo. Aun así lo recomiendo por su simplicidad en Fish puro. Si necesitas herramientas multi-runtime más potentes, mira fnm o mise más adelante en este artículo.
</Notice>

### Verificar la instalación

```fish
fisher list          # should show jorgebucaran/nvm.fish
nvm -v               # prints a version number
nvm -h               # shows the command list
```

Si `fisher list` no muestra `jorgebucaran/nvm.fish`, la instalación no se completó. Vuelve a ejecutar el comando `fisher install`. Si `nvm -v` no imprime una versión, tu shell no se ha recargado. Abre una nueva terminal.

### Actualizar o fijar nvm.fish

Para actualizarlo más adelante:

```fish
fisher update jorgebucaran/nvm.fish
```

Para fijar una versión concreta (Fisher soporta `@tag`, `@branch` o `@commit`):

```fish
fisher install jorgebucaran/nvm.fish@2.2.17
```

Comprueba lo que está instalado con `fisher list`. Nota: un `fisher install` sin más resuelve a lo que Fisher tenga por defecto, así que verifica `nvm -v` tras una instalación nueva para confirmar qué versión obtuviste.

## Instalar versiones de Node

```fish
# Latest release line
nvm install latest

# Latest LTS line (currently Node 26, Lithium)
nvm install lts

# A specific major line
nvm install 24
nvm install 22

# An exact version
nvm install 22.11.0

# An LTS line by codename
nvm install jod      # Node 22
nvm install krypton  # Node 24
nvm install lithium  # Node 26
```

Líneas LTS actuales a finales de 2026:

| Línea | Nombre clave | LTS desde | EOL | Estado |
|---|---|---|---|---|
| 22 | Jod | 2024-10-29 | 2027-04-30 | Mantenimiento |
| 24 | Krypton | 2025-10-28 | 2028-04-30 | Mantenimiento |
| 26 | Lithium | 2026-10-28 | 2029-04-30 | LTS activa |

Node 18 (Hydrogen) y Node 20 (Iron) han llegado al final de su vida útil. No los instales para nada que planees mantener en funcionamiento.

nvm.fish descarga binarios precompilados de Node y los almacena en `~/.local/share/nvm/` (siguiendo la especificación XDG Base Directory). Cada versión tiene su propio directorio. Para ver todo lo disponible en el mirror:

```fish
nvm list-remote          # all versions
nvm list-remote 24       # filter by regex
```

### Verificar que Node está instalado

```fish
node --version    # e.g. v26.13.0
npm --version
nvm current       # shows the active version
nvm list          # shows all installed versions
```

Si `node --version` dice "command not found", aún no has activado una versión. Ejecuta `nvm use <version>` o define una por defecto (siguiente sección).

En disco, cada versión de Node instalada es un runtime completo, aproximadamente entre 100 y 200 MB descomprimidos por versión. Compruébalo con `du -sh ~/.local/share/nvm/*` para ver la cifra real. `nvm uninstall` libera ese espacio.

## Cambiar entre versiones

```fish
# Activate a specific version (current session only)
nvm use 24
nvm use lts
nvm use latest

# Drop back to the system-installed Node
nvm use system

# Return to your configured default
nvm use default

# Read the nearest .nvmrc or .node-version (no argument)
nvm use

# Check what's active
nvm current

# List installed versions
nvm list

# List installable versions from the mirror
nvm list-remote

# Silent mode (no output), useful in scripts and the autoswitch function below
nvm use --silent 24
nvm use -s 24
```

`nvm use` cambia la versión activa de Node solo para tu sesión actual del shell. Cuando abres una nueva terminal, arranca con lo que tenga definido `nvm_default_version` (o con nada, si no la has configurado). **No** lee el `.nvmrc` del directorio por sí solo. Consulta la siguiente sección.

**Verifica:** tras `nvm use 24`, ejecuta `node --version`. Debería mostrar `v24.x.x`. `nvm list` marca la versión activa.

## Establecer una versión de Node por defecto

Sin una versión por defecto, las nuevas sesiones del shell no tendrán ningún Node gestionado por nvm en el PATH. Configúrala con una variable universal:

```fish
set --universal nvm_default_version 24
```

Ahora cada nueva sesión interactiva de Fish arranca con Node 24 activo. Puedes usar `lts`, `latest`, un nombre clave como `jod`, o un número de versión específico.

Qué ocurre en el arranque: `conf.d/nvm.fish` ejecuta `nvm use --silent $nvm_default_version`, pero solo en shells interactivos. Esta es la única auto-activación que hace nvm.fish. Los shells no interactivos (scripts, `fish -c`, runners de CI) lo omiten por completo. Consulta ["Lo que nvm.fish no hace"](#lo-que-nvmfish-no-hace) para las implicaciones.

**Verifica:** abre una pestaña de terminal completamente nueva y ejecuta `nvm current`. Debería mostrar tu versión por defecto. `node --version` debería funcionar sin ningún `nvm use` manual.

## Cambiar versiones por proyecto (.nvmrc / .node-version)

Aquí es donde nvm.fish gestiona las versiones de Node específicas por proyecto, pero es más manual de lo que cabría esperar.

Crea un archivo `.nvmrc` en el directorio raíz de un proyecto:

```bash
echo "22" > ~/projects/legacy-app/.nvmrc
echo "24" > ~/projects/new-app/.nvmrc
```

Luego, cuando estés en el directorio del proyecto, ejecuta `nvm use` (sin argumentos). Lee el archivo `.nvmrc` o `.node-version` más cercano y activa esa versión:

```fish
cd ~/projects/legacy-app
nvm use          # reads .nvmrc → activates Node 22
node --version   # v22.x.x

cd ~/projects/new-app
nvm use          # reads .nvmrc → activates Node 24
node --version   # v24.x.x
```

¿Primera vez en un proyecto? `nvm install` (sin argumentos) también lee `.nvmrc`. Instala la versión especificada y la activa:

```fish
cd ~/projects/new-app
nvm install      # installs the .nvmrc version and activates it
```

La búsqueda recorre el árbol de directorios *hacia arriba* hasta encontrar un archivo `.nvmrc` o `.node-version`, así que ejecutar `nvm use` desde un subdirectorio también funciona.

<Notice type="warning" title="nvm.fish no cambia de versión automáticamente al hacer cd">
No hay ningún hook de cd en nvm.fish. Ninguna versión del plugin ha cambiado jamás automáticamente de versión de Node al hacer `cd` a un directorio. Debes ejecutar `nvm use` manualmente. Las nuevas sesiones de terminal arrancan con `nvm_default_version`, no con el `.nvmrc` del directorio. Si quieres un cambio automático real, mira la función opcional de abajo.
</Notice>

<Notice type="info" title="Formatos de .nvmrc">
nvm.fish soporta los mismos formatos de `.nvmrc` que el nvm original: números de versión (`22`, `22.11`, `22.11.0`), `lts`, `latest` y nombres clave de LTS (`jod`, `krypton`, `lithium`). Los archivos llamados `.node-version` también funcionan. El parseo es estricto: sin comentarios finales ni espacios en blanco. Un `.nvmrc` que contenga `22 # mi proyecto` no coincidirá.
</Notice>

**Verifica:** haz `cd` al proyecto, ejecuta `nvm use` y luego `node --version`. Debería coincidir con el valor de `.nvmrc`.

### ¿Quieres un cambio automático real al hacer cd?

nvm.fish no lo hace, pero puedes añadirlo con una función personalizada de Fish. Pon esto en `~/.config/fish/functions/_nvm_autoswitch.fish`:

```fish
function _nvm_autoswitch --on-variable PWD --description "Switch Node on .nvmrc dirs"
    set --local dir $PWD
    while test -n "$dir" -a "$dir" != "/"
        if test -f $dir/.nvmrc -o -f $dir/.node-version
            nvm use --silent
            return
        end
        set dir (dirname $dir)
    end
end
```

Esto **no está integrado en nvm.fish**. Es tu propia función. Se dispara cada vez que `$PWD` cambia, recorre hacia arriba buscando `.nvmrc`, y ejecuta `nvm use --silent` (un no-op cuando la versión correcta ya está activa). No gestiona la desactivación cuando sales de un directorio de proyecto. Este snippet es sencillo, pero deberías probarlo en tu versión de fish antes de depender de él. Si estás creando helpers personalizados como este, consulta [cómo escribir tus propias funciones de Fish shell](/es/fish-shell-funciones-comandos-personalizados/).

## Instalar paquetes globales por defecto

Si quieres que ciertos paquetes npm se instalen cada vez que instalas una nueva versión de Node:

```fish
set --universal nvm_default_packages yarn typescript tsx
```

Ahora `nvm install 24` también ejecutará `npm install -g yarn typescript tsx` después de descargar Node.

Ten en cuenta que los árboles de paquetes globales de npm son **por versión de Node instalada**, no compartidos. Cada versión nueva tiene su propio conjunto de globales. Si gestionas dependencias entre versiones, consulta [cómo actualizar todas las dependencias de Node.js a la última versión](/es/actualizar-dependencias-nodejs/).

## Desinstalar versiones de Node

```fish
nvm uninstall 24.22.2
nvm uninstall v22
```

Esto elimina los binarios instalados del directorio de datos de nvm y libera el espacio en disco.

### Eliminar nvm.fish por completo (rollback)

Si quieres desmontarlo todo:

```fish
fisher remove jorgebucaran/nvm.fish
set --erase --universal nvm_default_version
set --erase --universal nvm_default_packages
```

Luego elimina el directorio de datos. **Verifica bien la ruta antes de ejecutar `rm -rf`**, especialmente si definiste un `$nvm_data` personalizado:

```fish
# Default location (XDG):
rm -rf ~/.local/share/nvm/

# Or if you set a custom nvm_data:
# rm -rf ~/.nvm/
```

Abre una nueva terminal y verifica que `nvm` ha desaparecido: `nvm -v` debería decir "command not found". Node también desaparece. Reinstálalo desde los paquetes de tu distro, Homebrew, o nvm.fish de nuevo.

## Mirror, directorio de datos y arquitectura

Tres opciones de configuración que conviene conocer:

Cambia el mirror de descarga si estás detrás de un proxy corporativo o en algún lugar donde `nodejs.org` va lento:

```fish
set --global nvm_mirror https://npmmirror.com/mirrors/node
```

El valor por defecto es `https://nodejs.org/dist`.

El directorio de datos es donde se almacenan las versiones de Node (por defecto: `$XDG_DATA_HOME/nvm`, es decir, `~/.local/share/nvm/`):

```fish
set --global nvm_data ~/.nvm
```

Si antes usabas el nvm basado en Bash y tienes versiones de Node en `~/.nvm/`, esto permite que nvm.fish use ese mismo directorio. Las versiones instaladas por cualquiera de las dos herramientas deberían funcionar.

Para sistemas Alpine/musl donde los binarios glibc por defecto no funcionan, sobrescribe la arquitectura:

```fish
set --global nvm_arch x64-musl
```

Sin esto, las instalaciones en sistemas basados en musl (contenedores Alpine, algo de Linux embebido) descargarán binarios que fallan en tiempo de ejecución.

<Notice type="warning" title="No las definas como universales">
`nvm_data` y `nvm_mirror` deben definirse con `set --global`, no con `set --universal`. La lógica de actualización del plugin borra los valores universales de estas dos y los restablece como globales. `nvm_default_version` y `nvm_default_packages` *sí* son universales, así que no confundas las reglas.
</Notice>

## Lo que nvm.fish no hace

Esta es la parte que la mayoría de las guías omiten. nvm.fish tiene límites reales:

No hay cambio automático al hacer cd. No existe ningún hook `--on-variable PWD` en el plugin. Ejecutas `nvm use` manualmente en cada proyecto, o construyes la función personalizada mostrada arriba.

No tiene integración con direnv/.envrc. nvm.fish no lee archivos `.envrc`. Hay un [issue abierto sobre ello](https://github.com/jorgebucaran/nvm.fish/issues) (2025). Si usas direnv para la gestión del entorno, tendrás que unir ambos con tus propias funciones.

La activación en el arranque es solo para shells interactivos. La barrera `status is-interactive` significa que las sesiones de fish no interactivas nunca tienen la versión de Node por defecto en el PATH. Esto afecta a scripts, one-liners con `fish -c`, runners de CI y algunas configuraciones de multiplexores de terminal.

### En servidores y en CI

nvm.fish es una herramienta de shell para desarrolladores. No dependas de ella en contextos no interactivos. En un servidor o en CI, usa una de estas opciones en su lugar:

- Una ruta absoluta: `~/.local/share/nvm/v24.22.2/bin/node`
- Una imagen de Docker con Node incluido
- Node de la distro o del gestor de paquetes (`apt install nodejs`, `brew install node`)

<Notice type="warning" title="Los shells no interactivos no tienen Node">
Si ejecutas `fish -c "node script.js"` o un paso de CI con fish, la versión por defecto no se activa. Node no estará en el PATH. Usa una ruta absoluta o un Node del gestor de paquetes para cualquier cosa no interactiva.
</Notice>

Si despliegas apps de Node en un VPS y quieres un entorno barato y fiable donde ejecutarlas, [Hetzner Cloud VPS](https://go.bitdoze.com/hetzner) es lo que uso para mi propia flota: hardware europeo sólido sin precios de hyperscaler.

## nvm.fish vs nvm (la versión Bash)

| | nvm.fish | nvm (Bash) |
|---|---|---|
| Soporte de shell | Solo Fish | Shells POSIX (bash, zsh, sh…); Fish solo vía wrappers |
| Escrito en | Fish | Bash/POSIX sh |
| Instalación | Plugin de Fisher | Script con curl |
| Versión actual | 2.2.17 (2025-02-07) | v0.40.8 (2026-09-21) |
| Coste en arranque | Ninguno hasta definir una versión por defecto; luego un `nvm use` silencioso por shell interactivo | Carga un script de ~4.000 líneas en cada sesión |
| Soporte de `.nvmrc` | Sí | Sí |
| Completado con Tab | Sí (nativo de Fish) | Básico |
| Nombres clave LTS | Sí | Sí |

La diferencia de rendimiento es real. El nvm basado en Bash carga su script completo en cada nueva sesión, una queja de larga data. nvm.fish solo se carga cuando ejecutas `nvm`, o ejecuta un único `nvm use` silencioso en el arranque si definiste una versión por defecto. Sigue siendo órdenes de magnitud más ligero.

Si necesitas la versión Bash en macOS o Ubuntu, consulta [cómo instalar Node.js con el nvm original en macOS y Ubuntu](/es/instalar-nodejs-nvm-macos-ubuntu/). Los wrappers como FabioAntunes/fish-nvm ejecutan el nvm.sh real dentro de Fish, pero apenas se mantienen (último release en 2023). Te conviene más nvm.fish o fnm.

## nvm.fish vs fnm vs Volta vs mise

Hay otros gestores de versiones de Node que funcionan con Fish:

| | nvm.fish | fnm | Volta | mise |
|---|---|---|---|---|
| Versión | 2.2.17 (2025-02) | v1.39.0 (2026-03) | v2.0.2 (2024-12) | v2026.11.0 (2026-11) |
| Lenguaje | Fish | Rust | Rust | Rust |
| Estrellas | ~2.7k | ~27k | ~13k | ~36k |
| Multi-shell | Solo Fish | Cualquiera (vía `fnm env`) | Cualquiera | Cualquiera |
| Cambio automático al hacer cd | No (`nvm use` manual) | Sí (`--use-on-cd`) | Pinning por proyecto | Sí (`.tool-versions` / `.node-version`) |
| Multi-runtime | Solo Node | Solo Node | Node, Python, … | Node, Python, Ruby, Go, … |
| Mantenimiento | Bajo | Activo | Bajo | Muy activo |

Mi opción por defecto es nvm.fish por su simplicidad en Fish puro cuando solo gestionas Node. Para soporte multi-shell y cambio automático real, fnm es la opción más rápida. Para configuraciones políglotas/multi-herramienta (Node + Python + Go y compañía), mise es el estándar moderno de 2026. El pinning por proyecto de Volta está bien, pero no empieces proyectos nuevos con él. Su desarrollo se ha ralentizado.

Si estás evaluando el ecosistema de Node en general, merece la pena conocer [Bun, un runtime y gestor de paquetes de JavaScript todo en uno](/es/gestor-paquetes-bun/).

<Tab name="fnm">
Instálalo con `brew install fnm` o `cargo install fnm`. Luego crea `~/.config/fish/conf.d/fnm.fish`:

```fish
fnm env --use-on-cd --shell fish | source
```

El flag `--shell` explícito es más rápido y evita la detección del árbol de procesos. El `--use-on-cd` de fnm es un hook de cd real: cambia de versión cuando entras en un directorio de proyecto.
</Tab>
<Tab name="Volta">
Instalación:

```fish
curl https://get.volta.sh | bash
```

Luego añade a `~/.config/fish/config.fish`:

```fish
set -gx VOLTA_HOME ~/.volta
fish_add_path $VOLTA_HOME/bin
```

Volta 2.0 eliminó el soporte de glibc antiguas (adiós CentOS 6), movió el instalador de Windows a winget, y añadió builds ARM para Linux/Windows más un binario universal de macOS. Funciona, pero su desarrollo es lento. Trátalo como maduro pero estancado.
</Tab>
<Tab name="mise">
Instálalo desde [mise.jdx.dev](https://mise.jdx.dev). Luego añade a `~/.config/fish/config.fish`:

```fish
~/.local/bin/mise activate fish | source
```

(Las instalaciones de Homebrew se activan sin esta línea.) mise gestiona Node, Python, Ruby, Go y más desde una sola herramienta, con archivos de configuración `.tool-versions` / `.mise.toml`. Si gestionas más que solo Node, es la opción más sólida ahora mismo.
</Tab>
</Tabs>

## Solución de problemas

<Accordion label="nvm: command not found" group="troubleshooting" expanded="true">
Fisher no se instaló correctamente, o tu shell no se ha recargado. Ejecuta `fisher list` para verificar si aparece `jorgebucaran/nvm.fish`. Si falta, vuelve a ejecutar `fisher install jorgebucaran/nvm.fish`. Si aparece pero `nvm` sigue sin funcionar, abre una nueva terminal. La función se autocarga en el primer uso en una sesión nueva.
</Accordion>

<Accordion label="Node no encontrado tras la instalación" group="troubleshooting">
Instalaste una versión pero no la has activado. Ejecuta `nvm use <version>`. O define una por defecto para que cada shell nuevo la tenga: `set --universal nvm_default_version lts`. Si `node --version` sigue fallando, comprueba `nvm list`. ¿Está instalada la versión?
</Accordion>

<Accordion label=".nvmrc no se lee automáticamente" group="troubleshooting">
Este es el comportamiento esperado. nvm.fish lee `.nvmrc` solo cuando ejecutas `nvm install` o `nvm use` sin argumento de versión. Ninguna versión de nvm.fish cambia automáticamente al hacer `cd`. Ejecuta `nvm use` en el directorio del proyecto. Revisa también el contenido de tu `.nvmrc`: el parseo es estricto. Un archivo con `22 # comentario` o espacios finales no coincidirá. Limítalo a un número de versión o nombre clave simple.
</Accordion>

<Accordion label="Error en _nvm_index_update / 'test: Missing argument' / 'Invalid redirection target'" group="troubleshooting">
Este es el [issue #255](https://github.com/jorgebucaran/nvm.fish/issues/255) (abierto el 2026-08-19, reportado en fish 4.8.1 + WSL). El índice del mirror (`$nvm_mirror/index.tab`) no se descarga ni se crea. Soluciones:

```fish
mkdir -p ~/.local/share/nvm   # ensure the data dir exists
nvm install lts               # retry
```

Si eso no funciona, reinstala vía Fisher: `fisher remove jorgebucaran/nvm.fish && fisher install jorgebucaran/nvm.fish`.
</Accordion>

<Accordion label="Sin Node en tmux / terminal de VS Code / fish -c" group="troubleshooting">
El hook de arranque de nvm.fish solo se ejecuta en shells interactivos (`status is-interactive`). Los paneles de tmux que no ejecutan un arranque interactivo, los terminales integrados de VS Code con ciertas configuraciones, y los one-liners `fish -c` lo omiten. Solución: usa una ruta absoluta (`~/.local/share/nvm/v24.22.2/bin/node`) o asegúrate de que tu configuración de tmux/terminal inicia fish de forma interactiva. Para detalles de configuración de tmux, consulta [los mejores multiplexores de terminal (tmux y compañía)](/es/mejores-multiplexores-terminal/).
</Accordion>

<Accordion label="La instalación falla en Alpine / musl" group="troubleshooting">
Los binarios de Node por defecto están enlazados a glibc y no funcionan en sistemas musl. Define la arquitectura:

```fish
set --global nvm_arch x64-musl
```

Luego reintenta `nvm install lts`.
</Accordion>

<Accordion label="Arranque del shell más lento de lo esperado" group="troubleshooting">
Una vez definido `nvm_default_version`, cada shell interactivo ejecuta un `nvm use` silencioso en el arranque. Sigue siendo mucho más ligero que cargar el script de nvm de Bash, pero no es cero. Si el tiempo de arranque importa, quita la versión por defecto y activa las versiones manualmente por proyecto.
</Accordion>
