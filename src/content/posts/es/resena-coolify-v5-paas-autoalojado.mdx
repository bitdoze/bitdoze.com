Los precios de Heroku no dejan de subir y las facturas de ancho de banda de Vercel pillan a la gente por sorpresa. Coolify es la respuesta open source: un PaaS autoalojado donde despliegas aplicaciones, bases de datos y más de 280 servicios con un clic en tus propios servidores.

Coolify v4.0.0 alcanzó la versión estable en abril de 2026 tras dos años en beta. v4.1.0 llegó en mayo con compilaciones Railpack, registro de auditoría y soporte para MCP. v5, con escalabilidad multiservidor, está en desarrollo activo.

Llevo usando Coolify desde las primeras betas de v4. Esto es lo que funciona, lo que no, y si deberías cambiarte.

## ¿Qué es Coolify?

Coolify es una plataforma como servicio (PaaS) open source y autoalojable. Piensa en Heroku o Vercel, pero ejecutándose en tu propio VPS. Obtienes:

- Despliegues con Git push desde GitHub, GitLab o [Forgejo](/es/forgejo-woodpecker-ci-cicd/)
- Plantillas de servicios con un clic (más de 280 aplicaciones, bases de datos y herramientas)
- Certificados SSL automáticos con Let's Encrypt
- Gestión de proxy inverso (basada en Caddy)
- Copias de seguridad de bases de datos con soporte para S3/R2
- Registros de despliegue en tiempo real
- Gestión de equipos con acceso basado en roles
- Despliegues de vista previa para pull requests

La diferencia con Heroku: el servidor es tuyo. Sin dependencia del proveedor, sin cambios de precio sorpresa, sin datos en infraestructura ajena.

## Qué cambió en la v4 estable

v4.0.0 salió de beta tras dos años y 474 versiones beta. Esto es lo que se estabilizó:

- **Navegación SPA**: se reemplazaron las recargas de página completa de Livewire por una aplicación de una sola página de verdad. La navegación es más rápida y el estado persiste entre cambios de página.
- **Refuerzo de seguridad**: los secretos de webhook se cifran con verificación HMAC. Las rutas de volúmenes y los comandos de health check se validan contra inyecciones. El aislamiento por equipo se reforzó en los flujos de creación de recursos.
- **Fiabilidad del proxy**: almacenamiento de la configuración del proxy en base de datos con recuperación automática y copias de seguridad versionadas. Las configuraciones de Caddy ya no se rompen en silencio tras un fallo.
- **Integración con GitLab**: soporte completo de GitLab como fuente, con claves SSH de despliegue y autenticación HTTP básica. Ya no es solo GitHub.
- **Plantillas de servicios actualizadas**: Beszel 0.18.7, se añadió el servicio de captcha Cap, Plane se reactivó y Cal.com se eliminó (pasó a ser cerrado).

## Novedades de v4.1.0

La versión v4.1.0 (mayo de 2026) añadió funciones importantes:

- **Build pack Railpack**: una nueva opción de build pack en beta junto a Nixpacks y Docker. Railpack soporta variables de entorno en tiempo de compilación, fusión de configuraciones y compilaciones multi-etapa. Consulta nuestra [comparativa de Nixpacks vs Railpack](/es/railpack-vs-nixpacks/).
- **Registro de auditoría estructurado**: las mutaciones de la API, los eventos de webhook, la autenticación y los resultados de autorización ahora se registran en formato estructurado. Útil para cumplimiento y depuración.
- **Soporte MCP**: servidor MCP a nivel de instancia con herramientas de solo lectura para los recursos de Coolify. Actívalo desde la API o la interfaz para integrarlo con agentes de IA.
- **Barra lateral plegable**: mejora de la interfaz con estado persistente, tooltips y un menú de equipo compacto.
- **Períodos de gracia de parada configurables**: períodos de gracia por aplicación para paradas manuales, vistas previas y despliegues.
- **Marcadores para omitir CI/CD**: `[skip ci]` y `[skip cd]` en mensajes de commit o títulos de PR omiten los webhooks de despliegue.
- **Seguimiento de diferencias en la configuración de despliegue**: los cambios pendientes y las modificaciones que afectan a la compilación se muestran antes de volver a desplegar.

## Qué traerá v5

v5 es el próximo gran hito. La función central es la **escalabilidad multiservidor completa**. Actualmente, Coolify gestiona un solo servidor. v5 añade la capacidad de conectar varios servidores a una única instancia de Coolify, lo que te da una infraestructura tipo nube con tu propio hardware.

De las notas de la versión v4.0.0: "La mayor novedad será la escalabilidad completa en el núcleo, para que tengas infraestructura de nube, pero con tus propios servidores."

Esto significa:
- Desplegar en varios VPS desde un solo panel de Coolify
- Balancear la carga de las aplicaciones entre servidores
- Escalar horizontalmente sin gestionar cada servidor por separado
- Orquestación tipo nube en Hetzner, DigitalOcean o bare metal

El creador (Andras Bacsai) ya tiene una implementación funcional del núcleo. v5 no significa que se abandone v4: ambas se mantendrán en paralelo.

## Cómo instalar Coolify

<Tabs>
<Tab name="Instalación nueva">

El script oficial de instalación se encarga de Docker, Coolify y Caddy:

```bash
wget -q https://get.coollabs.io/coolify/install.sh \
  -O install.sh; sudo bash ./install.sh
```

Tarda entre 5 y 10 minutos. Cuando termine, abre `http://your-server-ip:3000` y crea tu cuenta de administrador.

Para instrucciones de configuración detalladas (incluida la configuración del dominio y la integración con GitHub), consulta nuestra [guía de instalación de Coolify](/es/instalar-coolify-alternativa-heroku/) original.

</Tab>
<Tab name="Actualizar desde v4 beta">

Si estás ejecutando una versión beta, para actualizar a v4.0.0 estable:

```bash
# Coolify auto-updates by default
# Check your version in Settings > Coolify Settings
# Or trigger manually:
docker pull ghcr.io/coollabsio/coolify:latest
docker compose up -d
```

Tus datos y configuraciones persisten entre actualizaciones. Haz una copia de seguridad de la base de datos antes de los saltos a versiones mayores.

</Tab>
</Tabs>

### Requisitos mínimos del servidor

<ListCheck>

## Desplegar aplicaciones

### Desde Git

1. Añade tu cuenta de GitHub o GitLab en Settings > Git Sources
2. Crea un recurso nuevo, selecciona Application, elige tu repositorio y rama
3. Coolify detecta el framework (Astro, Next.js, Django, etc.) y selecciona el build pack
4. Configura tu dominio, añade las variables de entorno y pulsa Deploy
5. Coolify compila, despliega y provisiona el SSL automáticamente

Sube un commit nuevo y Coolify vuelve a desplegar. También puedes activar el despliegue automático en cada push.

### Desde Docker Compose

Coolify soporta Docker Compose como build pack. Pega o sube tu `docker-compose.yml`, configura las variables de entorno y despliega el stack completo. Es útil para aplicaciones complejas con varios servicios.

Consulta la [documentación de Docker Compose de Coolify](https://coolify.io/docs/knowledge-base/docker/compose) para más detalles sobre las variables de entorno mágicas y la gestión de volúmenes.

### Servicios con un clic

Las más de 280 plantillas de servicios incluyen bases de datos (PostgreSQL, MySQL, MongoDB, Redis, ClickHouse), monitorización (Uptime Kuma, Beszel), analítica (Plausible, Umami), automatización (n8n), wikis (Outline) y muchas más. Un clic, configuras un par de opciones y el servicio está en marcha.

## Qué hace bien Coolify

Tras meses usándolo:

**Los despliegues son fiables.** Los despliegues con Git push funcionan de forma consistente. Los registros de compilación son en tiempo real y se pueden buscar. Los despliegues fallidos muestran mensajes de error claros. Las vistas previas para PR son útiles para equipos.

**La gestión de SSL es automática.** Los certificados de Let's Encrypt se provisionan y renuevan sin intervención. Caddy gestiona la capa de proxy de forma limpia.

**Los servicios con un clic ahorran tiempo.** Desplegar una base de datos PostgreSQL con copias de seguridad configuradas lleva tres clics. Montar monitorización con [Beszel](/es/beszel-uptime-kuma/) o Uptime Kuma es igual de rápido.

**La comunidad es activa.** Los issues se corrigen en cuestión de días. El servidor de Discord tiene miles de miembros. Las plantillas de servicios se actualizan con regularidad.

**El ahorro es real.** Ejecutar 8 aplicaciones, 2 bases de datos y 3 servicios en un solo Hetzner CX32 ($8/mes) cuesta menos que un único dyno de Heroku.

## Lo que aún está verde

**Falta el multiservidor.** Actualmente solo puedes gestionar un servidor por instancia de Coolify. Si necesitas aplicaciones repartidas en varios VPS, necesitas varias instancias de Coolify. v5 lo soluciona, pero aún no está disponible.

**No hay CDN integrado.** Coolify sirve las aplicaciones desde tu VPS. Para recursos estáticos y audiencias globales, necesitas una CDN delante. [Bunny.net](/es/resena-bunny-net/) funciona bien para esto.

**No existen clientes móviles.** La gestión es solo a través de la interfaz web. No hay app móvil para comprobaciones rápidas.

**Algunas plantillas de servicios están desactualizadas.** Las plantillas mantenidas por la comunidad a veces van por detrás de las versiones oficiales. Comprueba las versiones antes de desplegar.

**Depurar problemas del proxy sigue siendo tedioso.** Los problemas de configuración de Caddy requieren intervención manual de vez en cuando. El almacenamiento del proxy en base de datos de v4.1 ayuda, pero quedan casos límite.

## Alternativas a Coolify

Si Coolify no encaja:

- **Dokploy**: más simple, menos funciones, instalación más fácil. Bueno para despliegues de una sola aplicación. Consulta nuestra [guía de instalación de Dokploy](/dokploy-install/).
- **Kamal 2**: solo CLI, cero sobrecarga en el servidor. Creado por el equipo de Rails en 37signals. Genial si no necesitas un panel web.
- **CapRover**: más antiguo pero estable. Modo clúster disponible. Menos servicios con un clic.
- **Easypanel**: interfaz limpia, centrada en la simplicidad. Consulta nuestra [reseña de Easypanel](/es/easypanel-panel-servidor-moderno/).
- **Pangolin**: no es un PaaS, pero es útil para exponer servicios autoalojados mediante túneles. Consulta nuestra [guía de Pangolin](/es/pangolin-alternativa-cloudflare-tunnels/).

Para una comparativa detallada de las tres mejores opciones, consulta nuestra guía [Coolify vs Dokploy vs Kamal 2](/es/coolify-vs-dokploy-vs-kamal-2/).

## ¿Deberías cambiarte?

Si estás en Heroku y pagas más de $10/mes, Coolify te ahorra dinero de inmediato. Un VPS de $5-8/mes maneja lo que Heroku cobra a más de $25/mes.

Si estás en Vercel y te topas con los límites de ancho de banda, Coolify te da ancho de banda ilimitado en tu propio servidor. La contrapartida es que no hay red edge: tu VPS lo sirve todo. Añade una CDN si necesitas rendimiento global.

Si autoalojas con Docker Compose a pelo, Coolify añade una capa de gestión que facilita despliegues, monitorización y copias de seguridad. Solo las plantillas de servicios con un clic ya ahorran horas de configuración.

Si necesitas orquestación multiservidor ahora mismo, Coolify aún no puede hacerlo. v5 lo añadirá. Para configuraciones de un solo servidor, v4.1.0 está lista para producción.

El [sitio web de Coolify](https://coolify.io/) tiene guías de instalación, y el [repositorio de GitHub](https://github.com/coollabsio/coolify) sigue el desarrollo activo. El Discord de la comunidad responde bien para resolver problemas.

## Preguntas frecuentes

<Accordion label="¿Puedo ejecutar Coolify junto a otros proxies inversos?" group="coolify-faq" expanded="true">
Coolify usa Caddy como proxy inverso interno. Si ya tienes Traefik o Nginx ejecutándose en el mismo servidor, entrarán en conflicto en los puertos 80/443. Puedes: dejar que Coolify gestione la capa de proxy (recomendado), o ejecutar Coolify en un VPS dedicado sin ningún otro proxy.
</Accordion>

<Accordion label="¿Coolify soporta servidores ARM?" group="coolify-faq">
Sí. Coolify funciona en ARM (incluidas las instancias ARM64 de Hetzner y las VMs ARM del nivel gratuito de Oracle). Algunas plantillas de servicios pueden tener problemas de compatibilidad con ARM, pero la funcionalidad principal funciona.
</Accordion>

<Accordion label="¿Cómo funcionan las copias de seguridad?" group="coolify-faq">
Coolify soporta copias de seguridad programadas de bases de datos, guardadas en local o enviadas a almacenamiento compatible con S3 ([Bunny Storage](/es/bunny-storage-vs-s3-vs-backblaze/), AWS S3, Backblaze). Las copias de seguridad de los datos de las aplicaciones requieren snapshots manuales de los volúmenes. Para copias de seguridad completas del servidor, considera [zerobyte-restic-gui](/es/zerobyte-interfaz-grafica-restic/).
</Accordion>

<Accordion label="¿Coolify está listo para producción?" group="coolify-faq">
v4.0.0 estable está lista para producción en configuraciones de un solo servidor. Miles de empresas ejecutaron la beta en producción durante 1-2 años. Tiene bugs (el creador lo reconoce), pero se corrigen rápido. Para cargas de trabajo críticas, monta monitorización con [Beszel](/es/beszel-uptime-kuma/) y mantén las copias de seguridad al día.
</Accordion>

<Accordion label="¿Qué pasa con Coolify Cloud?" group="coolify-faq">
Coolify ofrece una versión cloud gestionada en la que ellos ejecutan la instancia de Coolify por ti en sus servidores. Tus aplicaciones se siguen desplegando en tu VPS conectado. Cuesta $5/mes por la capa de gestión, además del coste de tu VPS. Útil si no quieres mantener tú mismo la instancia de Coolify.
</Accordion>
