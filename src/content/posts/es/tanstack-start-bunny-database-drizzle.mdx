## Qué vamos a construir

Una app de tareas de una sola página con:

<ListCheck>
- Una tabla `todos` en Bunny Database (libSQL gestionado), con los cambios en vivo
- Una capa Drizzle ORM con migraciones SQL generadas y versionadas
- Funciones de servidor a través del `createServerFn` de TanStack Start, así que el acceso a la base de datos nunca sale del servidor
- Una interfaz React con estilos de shadcn y Tailwind, hidratada desde un render SSR
</ListCheck>

El resultado es una interfaz pequeña donde escribes una tarea, pulsas intro, la marcas o la borras. Cada acción va y vuelve a Bunny Database.

![Diagrama del camino de la petición: el navegador llama a una función de servidor, el servidor guarda el token y consulta Bunny Database por HTTPS](@assets/images/26/06/tanstack-start-bunny-database-drizzle-architecture.webp)

*El navegador nunca habla con Bunny Database. Llama a una función de servidor, y el servidor guarda el token y hace la petición HTTPS.*

## Requisitos previos

Antes de empezar, necesitas:

- Una [cuenta de Bunny.net](https://go.bitdoze.com/bunny). Bunny Database sigue en vista previa pública, con un límite de [50 bases de datos y 1 GB cada una](https://bunny.net/docs/database/limits)
- Node.js o Bun instalado. Aquí usé Bun porque las instalaciones y los scripts van rápidos. La [guía del gestor de paquetes Bun](/es/gestor-paquetes-bun/) cubre la configuración
- Conocimientos de TypeScript, React y SQL

La prueba del 28 de noviembre usó Bun 1.3.14 y Node 24.17.0. `bun run db:generate` arranca `drizzle-kit` en Node, no en Bun, así que ambos runtimes cuentan.

## Paso 1: Generar el proyecto TanStack Start con shadcn

La CLI de shadcn tiene una plantilla para TanStack Start. Un solo comando te da un proyecto TanStack Start con Tailwind, los componentes de shadcn y rutas por archivos, y el 28 de noviembre terminó en 7 segundos.

```bash
bunx --bun shadcn@latest init \
  --preset b1aIcEaeG \
  --base base \
  --template start \
  --pointer
```

La CLI pide un nombre de proyecto (`start-app` por defecto) y crea el proyecto en una carpeta con ese nombre. El flag `--name` fija ese nombre en la línea de comandos.

Qué hace cada flag:

- `--preset b1aIcEaeG` aplica una configuración compartida. Con este preset escribe el estilo `base-luma` y el color base `neutral` en `components.json`
- `--base base` elige Base UI como librería de componentes. Las otras opciones son `radix` y `aria`
- `--template start` genera TanStack Start en lugar de Next.js o Vite a secas
- `--pointer` activa el cursor de puntero en los botones

Al terminar, el proyecto se parece más o menos a esto:

```
start-app/
├── src/
│   ├── components/
│   │   └── ui/           # shadcn components (button, etc.)
│   ├── lib/
│   │   └── utils.ts      # cn() helper for class merging
│   ├── routes/
│   │   ├── __root.tsx    # root layout + providers
│   │   └── index.tsx     # home route
│   ├── router.tsx
│   ├── routeTree.gen.ts  # generated, do not edit
│   └── styles.css        # Tailwind entry
├── components.json  # shadcn configuration
├── package.json
├── vite.config.ts
└── tsconfig.json
```

La CLI también ejecuta `git init`, hace un commit inicial y añade `.env*` al `.gitignore` del starter.

Instala las dependencias y arranca el servidor de desarrollo para confirmar que arranca:

```bash
bun install
bun run dev
```

El comando ya había instalado las dependencias, así que `bun install` solo las comprueba. El 28 de noviembre el servidor de desarrollo imprimió `VITE v8.4.0 ready in 1259 ms`. Abre la URL Local que muestra y deberías ver esto:

## Paso 2: Crear tu Bunny Database

Bunny Database es una base de datos relacional gestionada construida sobre libSQL, un fork de SQLite. Tienes SQL estándar, replicación global opcional, facturación por uso (entra en reposo cuando nada la consulta) y varias formas de conectarte: API HTTP, SDK nativos y ORMs como Drizzle.

El 28 de noviembre de 2026 seguía en [vista previa pública](https://docs.bunny.net/database), y gratis mientras dure la vista previa. Las unidades publicadas después son $0.30 por mil millones de filas leídas, $0.30 por millón de filas escritas y $0.10 por GB por región activa al mes ([Precios de Bunny Database](https://bunny.net/database)).

### Crear la base de datos en el panel

1. Entra en el [panel de Bunny.net](https://go.bitdoze.com/bunny)
2. En la barra lateral izquierda, pulsa **+ Add** y luego **Database** dentro del grupo Edge Platform
3. Ponle un nombre (por ejemplo `todotest`). Ese nombre aparece en tu URL de conexión
4. Elige una opción bajo **Region settings**:
   - **Automatic region selection**: Bunny elige las regiones donde espera mejor rendimiento para tu ubicación
   - **Single region deployment**: sin replicación, la opción más barata, y la mejor para desarrollo o para usuarios de una sola zona
   - **Manual region selection**: tú eliges la ubicación de almacenamiento, la región principal y las réplicas, por latencia o por requisitos de cumplimiento
5. Pulsa **Add Database**

![Mockup del panel de Bunny: el formulario Add Database con sus opciones de región y la pestaña Access con sus botones de token](@assets/images/26/06/tanstack-start-bunny-database-drizzle-bunny-dashboard-mockup.webp)

*Mockup de las dos pantallas del panel, dibujado para esta guía: el formulario Add Database y la pestaña Access.*

¿Prefieres la terminal? `bunny db create --name todotest --primary FR --link --token --save-env` crea la base de datos, enlaza la carpeta y escribe ambas variables en `.env` ([referencia de la CLI](https://bunny.net/docs/cli/commands/db)). Viene de la documentación de Bunny y no se ejecutó.

### Obtener tus credenciales

Abre la base de datos y ve a la pestaña **Access**:

- **Database URL**: tiene la forma `libsql://<your-database-id>.lite.bunnydb.net`. Todas las librerías cliente usan este endpoint
- **Access Token**: pulsa **Generate Tokens**. Obtienes un token **Full Access** (lectura y escritura, úsalo para la app) y un token **Read Only** (limitado a `SELECT`, útil para analítica)

Copia la URL y el token Full Access enseguida. Los tokens se muestran una sola vez. **Generate Tokens** crea un par nuevo y deja válidos los tokens anteriores, así que úsalo cuando pierdas uno. **Regenerate Tokens** invalida todos los tokens existentes, así que úsalo solo después de una fuga ([Auth & Access](https://bunny.net/docs/database/connect/authorization)).

<Notice type="warning" title="Nunca subas credenciales al repositorio">
  Mantén los tokens fuera del control de versiones. Las pondremos en un archivo `.env` que está en `.gitignore`.
</Notice>

### Guardar las credenciales en .env

Crea un `.env` en la raíz del proyecto:

```bash
BUNNY_DATABASE_URL="libsql://your-database-id.lite.bunnydb.net/"
BUNNY_DATABASE_AUTH_TOKEN="your-full-access-token"
BUNNY_DATABASE_READ_ONLY_AUTH_TOKEN="your-read-only-token"
```

Añade un `.env.example` (se puede subir sin riesgo) para que la siguiente persona sepa qué espera la app:

```bash
BUNNY_DATABASE_URL="libsql://your-database-id.lite.bunnydb.net/"
BUNNY_DATABASE_AUTH_TOKEN="your-full-access-token"
BUNNY_DATABASE_READ_ONLY_AUTH_TOKEN="your-read-only-token"
```

El `.gitignore` del starter tiene una línea `.env*`, y ese patrón también oculta `.env.example`. Añade una línea de negación para que el archivo de ejemplo se pueda subir:

```gitignore
# .gitignore
.env*
!.env.example
```

## Paso 3: Instalar Drizzle y el cliente libSQL

Bunny Database habla libSQL, así que usamos el `@libsql/client` oficial como driver y el adaptador libSQL de Drizzle para consultas con tipado seguro.

```bash
bun add drizzle-orm @libsql/client
bun add -d drizzle-kit
```

- `drizzle-orm` es el ORM
- `@libsql/client` es el driver que habla el protocolo libSQL por HTTP
- `drizzle-kit` es una dependencia de desarrollo para generar migraciones, subir el esquema y abrir Drizzle Studio

El starter no incluye TanStack Query, y los pasos 10 y 11 lo importan. Añádelo ahora:

```bash
bun add @tanstack/react-query
```

Añade tres líneas dentro del objeto `scripts` de `package.json`. Deja quietos los demás scripts del starter, porque los scripts de build y preview se usan más adelante:

```json
"db:generate": "drizzle-kit generate",
"db:migrate": "bun run src/db/migrate.ts",
"db:studio": "drizzle-kit studio"
```

El starter trae `"dev": "vite dev --port 3000"`. Añade `--host` a esa línea cuando desarrolles en un VPS y quieras llegar al servidor desde el navegador de tu portátil. Así Vite se enlaza a tus interfaces de red en lugar de a localhost.

El 28 de noviembre, `bun run db:studio` imprimió `Drizzle Studio is up and running on https://local.drizzle.studio`, con un aviso de beta delante.

## Paso 4: Configurar Drizzle

Crea `drizzle.config.ts` en la raíz del proyecto. Le dice a drizzle-kit dónde está el esquema, a dónde van las migraciones y cómo llegar a la base de datos:

```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit"

export default defineConfig({
  schema: "./src/db/schema.ts",
  out: "./drizzle",
  dialect: "turso",
  dbCredentials: {
    url: process.env.BUNNY_DATABASE_URL!,
    authToken: process.env.BUNNY_DATABASE_AUTH_TOKEN!,
  },
})
```

Cuatro ajustes importan:

- `dialect: "turso"` le dice a drizzle-kit que emita SQL compatible con SQLite, que es lo que quiere libSQL (y Bunny Database)
- `libsql` no es un valor válido de `dialect`. drizzle-kit 0.31.11 y 1.0.0-rc.6 lo rechazan en ambos casos, con `postgresql`, `mysql`, `sqlite`, `turso` y `singlestore` en la lista de aceptados
- `out: "./drizzle"` es donde aterrizan los archivos de migración
- `dbCredentials` lee las mismas variables de entorno de `.env`, porque drizzle-kit carga ese archivo por su cuenta

drizzle-kit 1.0.0-rc.6, el release candidate vigente el 28 de noviembre, sigue aceptando `turso` pero escribe una carpeta por migración (`drizzle/<timestamp>_<name>/migration.sql`). La disposición descrita aquí es la que produjo `bun add -d drizzle-kit` ese día, la versión 0.31.11.

## Paso 5: Definir el esquema

Crea `src/db/schema.ts`. Es la única fuente de verdad de la forma de la base de datos:

```ts
// src/db/schema.ts
import { sqliteTable, integer, text } from "drizzle-orm/sqlite-core"

export const todos = sqliteTable("todos", {
  id: integer("id").primaryKey({ autoIncrement: true }),
  title: text("title").notNull(),
  completed: integer("completed", { mode: "boolean" }).notNull().default(false),
  createdAt: integer("created_at", { mode: "timestamp" })
    .notNull()
    .$defaultFn(() => new Date()),
})

export type Todo = typeof todos.$inferSelect
export type NewTodo = typeof todos.$inferInsert
```

La tabla `todos` tiene cuatro columnas:

- `id` es una clave primaria de entero con autoincremento
- `title` guarda el texto de la tarea y no puede ser nulo
- `completed` se guarda como 0/1 en SQLite, y Drizzle lo devuelve como `boolean` a través de `mode: "boolean"`
- `created_at` es una marca de tiempo Unix de entero que Drizzle devuelve como un `Date` de JavaScript a través de `mode: "timestamp"`

Drizzle deduce los dos tipos exportados, `Todo` y `NewTodo`, a partir del esquema. Nunca los escribes a mano, y se mantienen sincronizados a medida que cambia el esquema.

## Paso 6: Crear el cliente de base de datos

Crea `src/db/index.ts`. Inicializa el cliente libSQL y lo envuelve con Drizzle:

```ts
// src/db/index.ts
import { drizzle } from "drizzle-orm/libsql"
import { createClient } from "@libsql/client/web"
import * as schema from "./schema"

const client = createClient({
  url: process.env.BUNNY_DATABASE_URL!,
  authToken: process.env.BUNNY_DATABASE_AUTH_TOKEN!,
})

export const db = drizzle(client, { schema })
export { schema }
```

Usamos `@libsql/client/web` (el transporte HTTP) en lugar del de socket nativo, porque llegas a Bunny Database por HTTPS. La prueba del 28 de noviembre lo usó bajo Bun para las migraciones y bajo Node para el servidor.

El bundle del navegador también se mantiene limpio. El 28 de noviembre el build de este código no puso ninguna de las cadenas `libsql`, `drizzle`, `createClient` o `BUNNY_DATABASE` en el bundle del cliente. Aparecieron solo en el chunk del servidor.

## Paso 7: Generar la primera migración

Con el esquema listo, genera la migración SQL:

```bash
bun run db:generate
```

drizzle-kit lee `src/db/schema.ts`, lo compara con el historial de migraciones y escribe un archivo nuevo bajo `./drizzle/`. Para la tabla `todos` produce algo así:

![Diagrama de la canalización de migraciones: el archivo de esquema, drizzle-kit generate, los archivos SQL y la carpeta meta, el script migrate, la base de datos](@assets/images/26/06/tanstack-start-bunny-database-drizzle-migration-pipeline.webp)

*Toda la canalización: edita el esquema, genera el SQL, aplícalo con el script migrate y sube la carpeta SQL con sus archivos meta.*

```sql
-- drizzle/0000_certain_bug.sql
CREATE TABLE `todos` (
  `id` integer PRIMARY KEY AUTOINCREMENT NOT NULL,
  `title` text NOT NULL,
  `completed` integer DEFAULT false NOT NULL,
  `created_at` integer NOT NULL
);
```

Eso es sintaxis SQLite corriente, que Bunny Database acepta sin cambios. El prefijo numérico ordena los archivos, y el sufijo aleatorio (`certain_bug` aquí) mantiene únicos los nombres.

El comando también escribe `drizzle/meta/`, con un `0000_snapshot.json` del esquema y un `_journal.json` que lista las migraciones en orden. Sube esa carpeta junto con el SQL, porque drizzle-kit compara el siguiente cambio con la instantánea.

## Paso 8: Aplicar la migración

Para ejecutar migraciones por código, crea `src/db/migrate.ts`:

```ts
// src/db/migrate.ts
import { migrate } from "drizzle-orm/libsql/migrator"
import { db } from "./index"

async function main() {
  console.log("Running migrations...")
  await migrate(db, { migrationsFolder: "./drizzle" })
  console.log("Migrations complete.")
  process.exit(0)
}

main().catch((err) => {
  console.error("Migration failed:", err)
  process.exit(1)
})
```

## Paso 9: Construir las funciones de servidor

Con la capa de base de datos lista, exponemos las operaciones al frontend a través de las funciones de servidor de TanStack Start. Estas se ejecutan solo en el servidor, aunque las importes y las llames como funciones async normales desde código de cliente. Así el cliente de base de datos y tus credenciales se quedan fuera del bundle del navegador.

Crea `src/db/queries.ts`:

```ts
// src/db/queries.ts
import { eq } from "drizzle-orm"
import { createServerFn } from "@tanstack/react-start"
import { db, schema } from "./index"
import type { NewTodo } from "./schema"

export const getTodos = createServerFn({ method: "GET" }).handler(async () => {
  const rows = await db.select().from(schema.todos).orderBy(schema.todos.id)
  return rows
})

export const addTodo = createServerFn({ method: "POST" })
  .validator((title: string) => ({ title }))
  .handler(async ({ data }) => {
    const newTodo: NewTodo = { title: data.title }
    const [created] = await db.insert(schema.todos).values(newTodo).returning()
    return created
  })

export const toggleTodo = createServerFn({ method: "POST" })
  .validator((input: { id: number; completed: boolean }) => ({
    id: input.id,
    completed: input.completed,
  }))
  .handler(async ({ data }) => {
    const [updated] = await db
      .update(schema.todos)
      .set({ completed: data.completed })
      .where(eq(schema.todos.id, data.id))
      .returning()
    return updated
  })

export const deleteTodo = createServerFn({ method: "POST" })
  .validator((id: number) => ({ id }))
  .handler(async ({ data }) => {
    await db.delete(schema.todos).where(eq(schema.todos.id, data.id))
    return { id: data.id }
  })
```

Cada función sigue la misma forma:

1. `.validator()` analiza y valida el argumento que llega y te entrega un objeto `data` con tipo
2. `.handler()` ejecuta la consulta Drizzle contra Bunny Database y devuelve el resultado
3. La función es async y devuelve el resultado con tipo, así que quien la llama desde React tiene seguridad de tipos completa

La documentación de TanStack Start sugiere dividir esto en un archivo `.server.ts` para el código de base de datos y un archivo `.functions.ts` para los wrappers ([Server Functions](https://tanstack.com/start/latest/docs/framework/react/guide/server-functions)). Un solo archivo funciona igual de bien. En el build del 28 de noviembre el código de base de datos se quedó en el chunk del servidor, como muestra el paso 6.

## Paso 10: Conectar el QueryClientProvider

Actualiza `src/routes/__root.tsx`. Frente al archivo del starter son cuatro cambios: importar `QueryClient` y `QueryClientProvider`, crear un cliente encima de la ruta, fijar el título de la página en `Todos` y envolver `{children}` con el provider. Deja `defaultPreload: "intent"` fuera de este archivo, porque el starter ya lo fija en `src/router.tsx` y el tipo de la ruta raíz lo rechaza.

## Paso 11: Construir la interfaz de tareas

El último paso sustituye `src/routes/index.tsx` por la interfaz de tareas. Usa `useQuery` para cargar la lista y `useMutation` para cada acción, e invalida la consulta `todos` después de cada mutación para que la lista se actualice.

El layout es una columna centrada: un título, una fila con el input y el botón para añadir tareas, y la lista debajo. Cada elemento tiene un botón circular para marcarla, el texto de la tarea (tachado cuando está completa) y un icono de papelera. Cada mutación llama a `queryClient.invalidateQueries({ queryKey: ["todos"] })` cuando tiene éxito, lo que vuelve a pedir los datos a través de la función de servidor para que la lista muestre lo que hay en la base de datos.

![Diagrama de flujo de añadir una tarea: envío del formulario, función de servidor, insert de Drizzle, invalidación de la consulta, nueva petición, nuevo render](@assets/images/26/06/tanstack-start-bunny-database-drizzle-add-todo-flow.webp)

*Una adición son dos peticiones: la escritura que inserta la fila y la lectura que actualiza la lista.*

<Accordion label="src/routes/index.tsx completo" group="code" expanded="false">

```tsx
// src/routes/index.tsx
import { useState } from "react"
import { createFileRoute } from "@tanstack/react-router"
import { useQuery, useMutation, useQueryClient } from "@tanstack/react-query"
import { Check, Plus, Trash2 } from "lucide-react"
import { getTodos, addTodo, toggleTodo, deleteTodo } from "@/db/queries"
import { Button } from "@/components/ui/button"
import { cn } from "@/lib/utils"

export const Route = createFileRoute("/")({ component: TodoApp })

function TodoApp() {
  const queryClient = useQueryClient()
  const [newTitle, setNewTitle] = useState("")

  const { data: todos = [], isLoading } = useQuery({
    queryKey: ["todos"],
    queryFn: () => getTodos(),
  })

  const addMutation = useMutation({
    mutationFn: (title: string) => addTodo({ data: title }),
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ["todos"] })
      setNewTitle("")
    },
  })

  const toggleMutation = useMutation({
    mutationFn: (vars: { id: number; completed: boolean }) =>
      toggleTodo({ data: vars }),
    onSuccess: () => queryClient.invalidateQueries({ queryKey: ["todos"] }),
  })

  const deleteMutation = useMutation({
    mutationFn: (id: number) => deleteTodo({ data: id }),
    onSuccess: () => queryClient.invalidateQueries({ queryKey: ["todos"] }),
  })

  return (
    <div className="flex min-h-svh justify-center p-6">
      <div className="flex w-full max-w-md flex-col gap-6">
        <div>
          <h1 className="text-2xl font-semibold tracking-tight">Todos</h1>
          <p className="text-sm text-muted-foreground">
            Bunny Database + Drizzle + TanStack Start
          </p>
        </div>

        <form
          className="flex gap-2"
          onSubmit={(e) => {
            e.preventDefault()
            const title = newTitle.trim()
            if (!title) return
            addMutation.mutate(title)
          }}
        >
          <input
            value={newTitle}
            onChange={(e) => setNewTitle(e.target.value)}
            placeholder="What needs to be done?"
            className="flex-1 rounded-md border border-input bg-background px-3 py-2 text-sm shadow-sm placeholder:text-muted-foreground focus-visible:outline-none focus-visible:ring-1 focus-visible:ring-ring"
          />
          <Button type="submit" disabled={addMutation.isPending} size="icon">
            <Plus className="size-4" />
          </Button>
        </form>

        {isLoading ? (
          <p className="text-sm text-muted-foreground">Loading...</p>
        ) : todos.length === 0 ? (
          <p className="text-sm text-muted-foreground">
            No todos yet. Add one above.
          </p>
        ) : (
          <ul className="flex flex-col gap-1">
            {todos.map((todo) => (
              <li
                key={todo.id}
                className="flex items-center gap-3 rounded-md border border-border px-3 py-2"
              >
                <button
                  type="button"
                  onClick={() =>
                    toggleMutation.mutate({
                      id: todo.id,
                      completed: !todo.completed,
                    })
                  }
                  className={cn(
                    "flex size-5 shrink-0 items-center justify-center rounded-full border transition-colors",
                    todo.completed
                      ? "border-primary bg-primary text-primary-foreground"
                      : "border-input hover:border-primary",
                  )}
                  aria-label={todo.completed ? "Mark incomplete" : "Mark complete"}
                >
                  {todo.completed && <Check className="size-3" />}
                </button>

                <span
                  className={cn(
                    "flex-1 text-sm",
                    todo.completed && "text-muted-foreground line-through",
                  )}
                >
                  {todo.title}
                </span>

                <button
                  type="button"
                  onClick={() => deleteMutation.mutate(todo.id)}
                  className="text-muted-foreground hover:text-destructive"
                  aria-label="Delete todo"
                >
                  <Trash2 className="size-4" />
                </button>
              </li>
            ))}
          </ul>
        )}
      </div>
    </div>
  )
}
```

## ¿Cómo ejecutar una app TanStack Start en un VPS?

Ejecuta la salida de un build de Nitro con `node .output/server/index.mjs` en el VPS o en un contenedor, y pasa las dos variables de base de datos a ese proceso. Las funciones de servidor necesitan un runtime Node o Bun, así que un host estático no puede servir la app.

Cuando desarrollas en el propio VPS, el flag `--host` enlaza Vite a `0.0.0.0` para que puedas llegar desde tu portátil:

```bash
bun run dev
# Local:   http://localhost:3000/
# Network: http://your-vps-ip:3000/
```

Comprueba el build de producción y sírvelo una vez con el comando preview:

```bash
bun run build
bun run preview
```

`vite preview` sirve para comprobar un build en tu propia máquina. La documentación de Vite dice que no lo uses como servidor de producción ([Vite CLI](https://vite.dev/guide/cli)). Para un proceso de larga duración, añade el plugin de Nitro para que el build también emita un servidor Node:

```bash
bun add nitro
```

```ts
// vite.config.ts: two additions to the starter file
import { nitro } from "nitro/vite"

plugins: [devtools(), tailwindcss(), tanstackStart(), nitro(), viteReact()],
```

El 28 de noviembre, `bun run build` escribió entonces `.output/server/index.mjs`, y el código de Drizzle y libSQL quedó en sus chunks de servidor. La [guía de hosting de TanStack Start](https://tanstack.com/start/latest/docs/framework/react/guide/hosting) empareja ese archivo con un script `"start": "node .output/server/index.mjs"`.

`node` no lee `.env`, así que las dos variables tienen que venir del entorno del proceso:

```bash
BUNNY_DATABASE_URL="libsql://your-database-id.lite.bunnydb.net" \
BUNNY_DATABASE_AUTH_TOKEN="your-full-access-token" \
node .output/server/index.mjs
```

Sin ellas la petición de la lista devuelve un 500 y el log muestra `LibsqlError: URL_INVALID: The URL 'undefined' is not in a valid format`. Envuelve ese comando en systemd o PM2, o ponlo en un contenedor. Los Magic Containers de Bunny encajan aquí, porque puedes adjuntar las credenciales de la base de datos como variables de entorno directamente desde el panel de la base de datos.

<Notice type="info" title="Adjuntar credenciales a un Magic Container">
  Despliega en un Bunny Magic Container y te saltas el archivo `.env`. Desde la pestaña **Access** de la base de datos, pulsa **Add Secrets to Magic Container App**, elige tu app de contenedor y Bunny inyecta `BUNNY_DATABASE_URL` y `BUNNY_DATABASE_AUTH_TOKEN` por ti ([Magic Containers](https://bunny.net/docs/database/connect/magic-containers)). Tu código ya lee `process.env`, así que no cambia nada.
</Notice>

## ¿Por qué usar TanStack Start con Bunny Database y Drizzle?

El esquema de Drizzle pone tipo a cada consulta y función de servidor, Bunny Database acepta sintaxis SQLite corriente por HTTPS, y una base de datos inactiva factura solo por almacenamiento.

<ListCheck>
- **Renombrar una columna se convierte en un error de compilación**: el esquema de Drizzle es la fuente de verdad, y TypeScript deduce de él los resultados de las funciones de servidor y los datos que renderizan los componentes React
- **`dialect: "turso"` es todo lo que necesita drizzle-kit**: Bunny Database habla libSQL, un fork de SQLite, así que el SQL que conoces y las herramientas de SQLite que tienes siguen funcionando
- **Una base de datos inactiva factura solo por almacenamiento**: las lecturas cuestan $0.30 por mil millones de filas y las escrituras $0.30 por millón de filas cuando vuelve el tráfico, así que un proyecto personal tranquilo se mantiene barato
- **El primer HTML trae el armazón de la página**: TanStack Start renderiza el título y el formulario en el servidor, y las filas llegan justo después de la hidratación, como muestra el paso 11
- **Los componentes de shadcn están en `src/components/ui`**: el starter los trae como archivos corrientes del proyecto, así que los editas como cualquier otro archivo
- **Dos comandos por cambio de esquema**: edita `schema.ts`, ejecuta `db:generate` y luego `db:migrate`, y el 28 de noviembre una columna nueva salió como un archivo `ALTER TABLE`
- **Las mismas dos variables en desarrollo y en producción**: `.env` las guarda en local y Magic Containers las inyecta en producción, mientras el código lee `process.env` en ambos casos
</ListCheck>

La [comparativa Astro vs Next.js vs TanStack Start](/es/astro-vs-nextjs-vs-tanstack-start-cual-gana/) tiene los equilibrios entre frameworks. Para el mismo framework con una base de datos alojada y sin migraciones que ejecutar, está [empezar con TanStack Start y Convex](/es/empezar-tanstack-start/).

## Solución de problemas

Unas cuantas cosas me tropezaron mientras montaba esto:

<Accordion label="No QueryClient set durante el SSR" group="troubleshoot" expanded="true">

Olvidaste envolver la app en `QueryClientProvider` dentro de `__root.tsx`. El log del servidor muestra `Error in renderToReadableStream: Error: No QueryClient set, use QueryClientProvider to set one`, y la página muestra ese mensaje en lugar de la interfaz de tareas. Añade el provider como se ve en el paso 10.

</Accordion>

<Accordion label="Cannot find module '@tanstack/react-query'" group="troubleshoot">

El starter no incluye TanStack Query. Ejecuta `bun add @tanstack/react-query`; la prueba del 28 de noviembre instaló 5.108.4. El mismo typecheck también reporta `'defaultPreload' does not exist in type RootRouteOptions` mientras esa línea siga en `__root.tsx`, así que bórrala.

</Accordion>

<Accordion label="Protocol libsql not supported in libcurl" group="troubleshoot">

Esto aparece cuando intentas pedir la URL de la base de datos directamente con curl. curl responde `Protocol "libsql" not supported or disabled in libcurl`. El esquema `libsql://` es solo para librerías cliente. Para llamadas HTTP en crudo, conviértelo a `https://` y haz un POST a `/v2/pipeline`, como en el paso 8.

</Accordion>

<Accordion label="Tokens mostrados una sola vez" group="troubleshoot">

Si pierdes un token de acceso de Bunny, pulsa **Generate Tokens** en la pestaña **Access**. Eso crea un par nuevo y mantiene válidos los tokens anteriores. **Regenerate Tokens** es el botón de apagado. Invalida todos los tokens existentes, así que actualiza cada app que usara uno ([Auth & Access](https://bunny.net/docs/database/connect/authorization)).

</Accordion>

<Accordion label="La migración falla con un error" group="troubleshoot">

El 28 de noviembre aparecieron dos errores. ``Invalid enum value. Expected 'postgresql' | 'mysql' | 'sqlite' | 'turso' ... received 'libsql'`` significa que `dialect` debe ser `"turso"` en `drizzle.config.ts`, porque Bunny Database usa el dialecto libSQL/SQLite. ``SQL_INPUT_ERROR: SQL input error: table `todos` already exists`` significa que la tabla existe mientras `__drizzle_migrations` no tiene registro de su archivo, como después de que `drizzle-kit push` la creara. Usa `push` o `generate` con `migrate` en una misma base de datos, no ambos.

</Accordion>

<Accordion label="Puerto ya en uso" group="troubleshoot">

Vite pasa al siguiente puerto libre. El 28 de noviembre la prueba de laboratorio imprimió `Port 55945 is in use, trying another one...` y arrancó en el puerto siguiente; con el script por defecto el número es 3000. Lee en la salida de arranque el puerto que eligió. Un segundo `bun run dev` en el mismo proyecto se detiene con `Found another Vite dev process for this project`; cierra el primero o pasa `--bypass-lock`.

</Accordion>

<Accordion label="La página de producción muestra una lista vacía" group="troubleshoot">

`node .output/server/index.mjs` no lee `.env`. Sin `BUNNY_DATABASE_URL` la petición de la lista devuelve un 500, el log del servidor muestra `LibsqlError: URL_INVALID: The URL 'undefined' is not in a valid format` y la interfaz dice `No todos yet`. Exporta ambas variables en el entorno del proceso, como en la sección del VPS.

</Accordion>

<Accordion label="¿Por qué funciones de servidor en lugar de una API REST?" group="faq">

Las funciones de servidor mantienen tu cliente de base de datos y tus credenciales en el servidor mientras te dejan llamarlas como funciones async corrientes desde el cliente. Te ahorras escribir y mantener una capa de API aparte, y los tipos llegan intactos. Para una app pequeña como esta, eso es mucho menos código repetitivo.

</Accordion>

<Accordion label="¿Cobra Bunny por consulta?" group="faq">

Bunny Database factura por uso, no por consulta. El 28 de noviembre de 2026 era gratis mientras durara la vista previa pública. Las unidades publicadas son $0.30 por mil millones de filas leídas, $0.30 por millón de filas escritas y $0.10 por GB por región activa al mes. En reposo solo se cobra el almacenamiento ([Precios de Bunny Database](https://bunny.net/database)). Los límites de la vista previa ponen a cada cuenta en 50 bases de datos de 1 GB cada una ([Limits](https://bunny.net/docs/database/limits)).

</Accordion>

<Accordion label="¿Puedo añadir más tablas más adelante?" group="faq">

Sí, y esa es la parte buena. Añade una tabla o una columna a `src/db/schema.ts`, ejecuta `bun run db:generate` para crear la migración y luego `bun run db:migrate` para aplicarla. El 28 de noviembre, añadir una columna `due_at` que admite nulos produjo `drizzle/0001_brief_captain_cross.sql` con una sentencia `ALTER TABLE`, y el migrator registró el segundo archivo junto al primero en `__drizzle_migrations`.

</Accordion>

<Accordion label="¿Con qué versiones se ejecutó esta guía?" group="faq">

La prueba del 28 de noviembre de 2026 usó TanStack Start 1.169.7, React Router 1.170.46, React Query 5.108.4, drizzle-orm 0.45.4, drizzle-kit 0.31.11, @libsql/client 0.18.0 y Bun 1.3.14. `bun add drizzle-orm` y `bun add -d drizzle-kit` instalaron esas dos versiones de Drizzle, así que la disposición de migraciones mostrada es la de `0000_<name>.sql`.

</Accordion>

<Accordion label="¿Por qué ver el código fuente muestra Loading en lugar de la lista?" group="faq">

El servidor renderiza el armazón: el título, el input y `Loading...`. El SSR no espera a `useQuery`, así que las filas llegan desde la función de servidor `getTodos` justo después de la hidratación. La documentación de TanStack Start señala el `loader` de la ruta como el lugar para traer datos.

</Accordion>

<Accordion label="¿Es turso el dialecto correcto de drizzle-kit para Bunny Database?" group="faq">

Sí. `dialect: "turso"` hace que drizzle-kit emita SQL compatible con SQLite, y drizzle-kit 0.31.11 y 1.0.0-rc.6 rechazan `libsql` como valor no válido. Luego el migrator de `drizzle-orm/libsql/migrator` aplica los archivos con el mismo cliente que usa la app.
