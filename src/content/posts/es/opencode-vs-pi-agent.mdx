He estado usando [OpenCode](/es/guia-configuracion-opencode/) y [Pi](/es/guia-configuracion-pi-agent/) en paralelo durante meses. Ambos son agentes de codificación en terminal open source, ambos se conectan a modelos baratos de pesos abiertos, y ambos corren sin problemas en un VPS de $6/mes. A principios de este año la comparación era simple: OpenCode era la TUI con todo incluido, y Pi era el harness minimalista de cuatro herramientas.

Entonces ambos proyectos publicaron reescrituras masivas. **OpenCode 2.0** pasó a un daemon persistente en segundo plano con sub-agentes integrados, git worktrees y un cliente de escritorio/web. **Pi 1.0** (ahora bajo Earendil, construido por Mario Zechner y Armin Ronacher) revirtió su postura de siempre de «no MCP» con un sandbox QuickJS llamado **Codemode** y publicó **Pi Durable** para agentes en segundo plano siempre activos y a prueba de fallos.

Sigo teniendo ambos instalados, y la división entre ellos es más marcada ahora que en el lanzamiento. Esto es lo que cambió y cómo se comparan hoy.

## Qué cambió a finales de 2026: OpenCode 2.0 y Pi 1.0

Si leíste comparaciones antiguas de estas dos herramientas, la mitad de los puntos ya son incorrectos.

<ListCheck>
<ul>
<li><strong>OpenCode 2.0 se convirtió en un daemon en segundo plano.</strong> Reescrito en TypeScript y Effect, OpenCode 2 ejecuta un daemon local (puerto `49374` en Linux/macOS/WSL, `45278` en Windows). Tu TUI de terminal, la Desktop App en beta, la Web UI (`opencode pair`) y los scripts de `@opencode/sdk` se conectan todos al mismo servicio en ejecución.</li>
<li><strong>OpenCode 2 añadió sub-agentes y git worktrees.</strong> La versión 1 no tenía sub-agentes. La versión 2 incluye los sub-agentes `@general`, `@explore` y `@scout` que corren de forma asíncrona en segundo plano, además de aislamiento con git worktrees para que las tareas en paralelo no rompan tu checkout actual.</li>
<li><strong>Pi 1.0 añadió MCP nativo vía Codemode.</strong> Durante más de un año, Pi se negó a integrar MCP en el núcleo porque los esquemas JSON crudos de las herramientas hinchaban el prompt. El 1 de octubre de 2026, Pi 1.0 lo resolvió con <strong>Codemode</strong>: un sandbox QuickJS donde el modelo escribe pequeños fragmentos de JavaScript para llamar, filtrar y paralelizar herramientas MCP sin volcar salidas crudas en la transcripción del chat.</li>
<li><strong>Pi Durable (`@earendil-works/pi-durable`) se publicó junto a Pi 1.0.</strong> Hace checkpoint de cada turno del modelo, llamada a herramienta y paso de compactación en SQLite, JSONL o Cloudflare Durable Objects. Si un contenedor se reinicia o tu VPS se reinicia a mitad de tarea, el proceso reanuda desde el punto de guardado exacto con comprobaciones de idempotencia en la repetición de herramientas.</li>
<li><strong>Pi se movió a `@earendil-works/pi-coding-agent`.</strong> El repo vive en `earendil-works/pi` y requiere Node.js 22.19+.</li>
</ul>
</ListCheck>

## Filosofía: workspace de daemon compartido vs harness programable

Incluso después de ambas actualizaciones, la división central se mantiene.

OpenCode 2 quiere ser tu entorno de codificación completo en terminal, navegador y escritorio. Lo instalas, ejecutas `/connect`, e inmediatamente tienes los agentes `build` y `plan` (alterna con `Tab`), sub-agentes `@explore`, `/init`, `/undo`, arrastrar y soltar imágenes, y emparejamiento remoto (`opencode pair --remote`). No escribes TypeScript para que sea útil.

Pi 1.0 sigue empezando pequeño —`read`, `write`, `edit`, `bash`, una TUI a pantalla completa y Codemode— y espera que tú le des forma. ¿Quieres memoria persistente en Markdown, guardias de bash personalizadas o un bucle de revisión especializado? Dejas archivos `.ts` en `~/.pi/agent/extensions/`. Y si estás construyendo tu propio daemon de agente en segundo plano o un bot multi-inquilino en lugar de usar una UI ya hecha, **Pi Durable** te da la máquina de estados y las primitivas de recuperación de fallos como librería npm.

## Instalación

Fíjate en las nuevas URLs de v2 para OpenCode y el nuevo scope de paquete `@earendil-works` para Pi 1.0 (que ahora requiere **Node.js 22.19+**).

### OpenCode 2

```bash
curl -fsSL https://opencode.ai/v2/install | bash
```

Si estás actualizando una instalación v1 existente, ejecuta `opencode upgrade --major` (v1 y v2 comparten el nombre de binario `opencode`). También puedes instalar vía npm (`npm i -g @opencode/cli@latest`), Homebrew (`brew install anomalyco/tap/opencode-v2`), o Docker:

```bash
docker run -it --rm ghcr.io/anomalyco/opencode:2.0.0
```

### Pi 1.0 y Pi Durable

La instalación recomendada del CLI de Pi 1.0 es el script oficial:

```bash
curl -fsSL https://pi.dev/install.sh | sh
```

O vía npm, Bun o Nix:

```bash
# npm (requires Node.js 22.19+)
npm install -g --ignore-scripts @earendil-works/pi-coding-agent

# Nix
nix profile add github:earendil-works/pi/stable
```

Si estás construyendo un servicio en segundo plano a prueba de fallos o una app de agente personalizada con **Pi Durable**, instala los paquetes del SDK en tu proyecto TypeScript:

```bash
npm install @earendil-works/pi-durable @earendil-works/pi-ai @earendil-works/chord
```

## Arquitectura: el daemon de OpenCode 2 vs Pi Durable

Esta es la diferencia técnica más interesante entre los dos a finales de 2026. Ambos equipos se dieron cuenta de que un agente de codificación atado a un solo TTY interactivo muere en el momento en que tu conexión SSH se cae o tu portátil se suspende —pero lo resolvieron desde extremos opuestos.

### Cómo funciona el daemon de OpenCode 2

Cuando lanzas `opencode`, arranca un daemon en segundo plano que escucha localmente en el puerto `49374` (o `45278` en Windows). Cada interfaz es solo un cliente hablando con ese servicio:

- Empieza una refactorización en la TUI de terminal
- Ejecuta `opencode pair` para abrir la misma sesión en vivo en la Web UI o en la Desktop App beta (macOS, Windows, Linux)
- Usa `opencode pair --remote` para crear un túnel cifrado de extremo a extremo protegido por una contraseña de servidor, para poder revisar una sesión de un servidor casero o VPS desde otra máquina
- Controla el daemon programáticamente con `@opencode/client` y `@opencode/sdk`

### Cómo funciona Pi Durable

Pi mantuvo el CLI `pi` como un runner de terminal interactivo limpio y sacó el estado de larga duración a **`@earendil-works/pi-durable`**.

En lugar de un único daemon local de escritorio, Pi Durable es un motor de ejecución para agentes que deben sobrevivir a caídas de proceso, redespliegues de contenedores o reinicios de servidor:

- **Checkpointing a nivel de tarea**: cada llamada al LLM, ejecución de herramienta y compactación de contexto se confirma como un paso discreto en SQLite, JSONL o Cloudflare Durable Objects.
- **Recuperación exacta de fallos**: si tu proceso worker muere a mitad de turno, un nuevo proceso abre el almacén SQLite/JSONL y retoma justo donde el paso interrumpido se detuvo.
- **Seguridad en la repetición (idempotencia)**: al recuperarse de una caída, no quieres que un agente re-ejecute a ciegas un `git push`, una migración de base de datos o un cargo de Stripe. Pi Durable hace que las herramientas declaren si son seguras de re-ejecutar automáticamente. Las herramientas de lectura idempotentes se re-ejecutan automáticamente; las no idempotentes devuelven el estado interrumpido al modelo para que inspeccione qué pasó antes de actuar.

Si quieres una app multi-cliente ya hecha que puedas emparejar con tu navegador hoy, el daemon de OpenCode 2 gana. Si estás escribiendo tus propios bots de DevOps o codificación siempre activos en TypeScript y necesitas recuperación de estado transaccional, Pi Durable está construido para ese trabajo.

## Soporte de modelos

Ambos agentes se conectan a los mismos modelos baratos de pesos abiertos.

### OpenCode 2

OpenCode soporta más de 75 proveedores a través de *Models.dev* y motores locales como Ollama y LM Studio. Configura tus claves en `.env` o ejecuta `/connect` en la TUI.

<Notice type="warning" title="Guarda las API keys de los proveedores en variables de entorno locales">
El 17 de octubre de 2026, OpenCode reveló una brecha en su sistema Console heredado que expuso API keys de terceros almacenadas (OpenAI, Anthropic, Google) de aproximadamente el 1.4% de los usuarios de Console. Guarda tus claves de proveedor localmente en `~/.config/opencode/.env` o en variables de entorno en lugar de guardar claves de producción crudas dentro de dashboards web de terceros.
</Notice>

### Pi 1.0

Pi soporta más de 20 proveedores integrados más endpoints personalizados en `~/.pi/agent/models.json` (que se recarga en caliente al abrir `/model`). Pi 1.0 también añadió **modelos virtuales** para cambio de modelo estilo router y carga diferida de herramientas.

Ambos agentes funcionan desde el primer momento con OpenRouter y [OpenCode Go](https://go.bitdoze.com/opencode-go). El [plan OpenCode Go](/es/opencode-go-plan/) ahora incluye **31 modelos por $10/mes** (más un nivel Go Plus de $40/mes con límites 2-4x más altos), cubriendo GPT 6 Luna, GLM-5.3, DeepSeek V4.1 Flash, Kimi K3, MiniMax M3 y Qwen 3.8. Consulta la [guía de mejores modelos baratos](/es/mejores-modelos-baratos-hermes-agent/) y la [reseña de OpenCode Go](/es/opencode-go-plan/) para los límites exactos de peticiones por 5 horas.

## Comparación de flujos de trabajo

### Modo plan

OpenCode 2 tiene `plan` y `build` como agentes principales. Presiona `Tab` para alternar entre la planificación de solo lectura y la edición activa de archivos.

Pi sigue manteniendo la planificación modular a través de la extensión `pi-plan` (o LazyPi), dándote planificación de solo lectura y puertas de aprobación una vez instalada.

### Code Mode vs Codemode: cómo ambos arreglaron la hinchazón de MCP

Esta es una convergencia curiosa: ambos proyectos publicaron casi exactamente la misma solución al mayor defecto de MCP e incluso le dieron nombres casi idénticos.

Conectar 30 herramientas MCP de la forma tradicional vuelca miles de líneas de esquema JSON en tu prompt de sistema antes de que escribas una palabra. Ambos agentes ahora evitan eso:

- **«Code Mode» de OpenCode 2**: expone los servidores MCP y herramientas conectados como funciones JavaScript programables para que el agente pueda encadenar y componer múltiples operaciones en una sola pasada en lugar de quemar tokens en turnos de herramientas de ida y vuelta.
- **«Codemode» de Pi 1.0**: ejecuta un **sandbox QuickJS** del lado del harness. El MCP nativo ahora está integrado en el núcleo de Pi 1.0 (no se requiere `pi-mcp-adapter`), y el modelo escribe pequeños scripts JS dentro del sandbox para llamar herramientas MCP en paralelo, filtrar los datos localmente y devolver solo el resultado compacto a la conversación.

### Sub-agentes y trabajo en paralelo

OpenCode 2 cerró la brecha aquí. Obtienes sub-agentes integrados —`@general`, `@explore` y `@scout`— a los que el agente principal delega automáticamente o que puedes invocar con `@mentions`. Combinado con el soporte de git worktrees de OpenCode 2, las tareas en segundo plano y las builds corren de forma asíncrona sin bloquear tu terminal.

Pi maneja los agentes en paralelo a través de `pi-subagents` y su API de extensiones, o a nivel de infraestructura vía `@earendil-works/pi-durable` y `@earendil-works/chord` cuando orquestas grafos multi-agente en código.

### Memoria

OpenCode 2 sigue dependiendo de `AGENTS.md` para reglas de proyecto estáticas y de servidores MCP de memoria (como [Hindsight](/es/desplegar-hindsight-docker/) o Cognee) si quieres recuerdo entre sesiones.

Pi usa la extensión `pi-memory-md` para leer y escribir notas Markdown persistentes sobre tu repo automáticamente entre sesiones, mientras que Pi Durable persiste checkpoints completos de ejecución en SQLite o JSONL.

### Sesiones y automatización CLI

OpenCode 2 te da `/undo`, `/redo`, `/share`, sincronización de sesiones entre TUI/Web/Desktop vía el daemon local, y `opencode pair`.

Pi te da `/resume`, `/new`, `/tree`, `/fork` y `/clone` para ramificar conversaciones como el historial de git, además de `pi -p "prompt"` con `--mode json` o `--mode rpc` para pipelines de CI y scripts de shell.

## Extensiones y SDKs

### OpenCode 2 (`@opencode/sdk`)

OpenCode 2 introdujo paquetes programáticos oficiales —`@opencode/client` y `@opencode/sdk`— que hablan con el daemon v2 sobre su API local HTTP/WebSocket. Ten en cuenta que como v2 fue una reescritura desde cero en Effect, los plugins heredados de v1 tuvieron cambios incompatibles.

### Pi 1.0 (`~/.pi/agent/extensions/` + `pi-durable`)

El sistema de extensiones TypeScript de Pi sigue siendo la forma más fácil de hackear tu propio agente interactivo: suelta un archivo `.ts` en `~/.pi/agent/extensions/`, intercepta llamadas a herramientas, añade comandos slash o widgets de TUI personalizados, y ejecuta `/reload`. [LazyPi](https://lazypi.org/) sigue instalando más de 60 habilidades y 76 temas de una vez, y `pi-config` provee guardias de bash y herramientas web ya hechas.

## Cuándo elegir OpenCode 2

- Quieres un sistema completo justo después de instalar sin buscar extensiones
- Te gusta empezar una tarea en la terminal y revisarla en una ventana de navegador o de escritorio vía `opencode pair`
- Quieres los sub-agentes integrados `@explore` y `@general` con aislamiento de git worktree
- Quieres `/init`, `/undo`, `/redo` y más de 75 proveedores preconfigurados desde el primer momento

## Cuándo elegir Pi 1.0 (y Pi Durable)

- Quieres un agente de terminal rápido y minimalista donde cada comportamiento extra es un archivo `.ts` legible que tú controlas
- Te gusta el **Codemode** QuickJS de Pi 1.0 para encadenar herramientas MCP sin hinchazón de contexto
- Usas la ramificación de conversaciones (`/tree`, `/fork`, `/clone`) y el scripting headless `pi -p`
- Estás construyendo tus propios agentes en segundo plano de larga duración o bots multi-usuario y necesitas el checkpointing SQLite y la recuperación de herramientas idempotente de **Pi Durable**

## Cuándo usar ambos

Yo sigo ejecutando ambos en el mismo VPS. OpenCode 2 es mi opción por defecto cuando quiero el bucle `plan` -> `build`, sub-agentes `@explore` en segundo plano, o `opencode pair --remote` a una pestaña del navegador. Pi 1.0 es lo que uso cuando quiero una sesión de terminal reducida con extensiones `.ts` personalizadas, o cuando estoy montando un flujo de trabajo duradero en segundo plano que no puede permitirse perder estado en un reinicio. Ambos comparten la misma `OPENCODE_API_KEY` y `OPENROUTER_API_KEY`.

<Accordion label="¿Puedo usar la misma API key para OpenCode 2 y Pi 1.0?" group="faq" expanded="true">
Sí. Ambos leen `OPENROUTER_API_KEY` y `OPENCODE_API_KEY` de tu entorno. Una suscripción de OpenCode Go de $10/mes funciona en ambas herramientas y comparte el mismo límite de 5 horas y semanal.
</Accordion>

<Accordion label="¿Qué es Pi Durable y lo necesito para codificación normal por CLI?" group="faq">
No —si solo ejecutas `pi` interactivamente en tu terminal, el CLI estándar `@earendil-works/pi-coding-agent` ya guarda y reanuda tus transcripciones de chat. **Pi Durable** (`@earendil-works/pi-durable`) es para desarrolladores que construyen agentes en segundo plano de larga duración, daemons o aplicaciones web donde el agente debe sobrevivir a caídas de proceso o reinicios de servidor y repetir o saltar de forma segura llamadas a herramientas interrumpidas.
</Accordion>

<Accordion label="¿Cómo actualizo de OpenCode v1 a OpenCode 2?" group="faq">
Ejecuta `opencode upgrade --major` o instala directamente con `curl -fsSL https://opencode.ai/v2/install | bash`. Como v1 y v2 usan ambos el nombre de binario `opencode`, v2 reemplaza a v1 en tu PATH. Si usabas plugins personalizados de v1, revísalos después de actualizar porque la reescritura en Effect de v2 introdujo cambios de API incompatibles.
</Accordion>

<Accordion label="¿Pi 1.0 realmente añadió soporte MCP nativo?" group="faq">
Sí. Tras resistirse a MCP durante más de un año por la hinchazón de tokens de los esquemas, Pi 1.0 añadió soporte MCP nativo el 1 de octubre de 2026 vía **Codemode**. En lugar de volcar cada esquema MCP en el prompt, el modelo escribe JavaScript dentro de un sandbox QuickJS para llamar y filtrar herramientas MCP localmente.
</Accordion>

<Accordion label="¿Puedo ejecutar ambos en el mismo VPS?" group="faq">
Sí. OpenCode 2 ejecuta su daemon en segundo plano en el puerto `49374` por defecto, mientras que Pi corre como un proceso independiente en tu directorio. No entran en conflicto.
</Accordion>
