## ¿Qué es OpenClaw? Un asistente de IA autoalojado 24/7

La mayoría de las herramientas de IA esperan a que les preguntes algo. OpenClaw hace cosas: limpia tu bandeja de entrada, programa reuniones, investiga empresas, da seguimiento a tareas y ejecuta automatizaciones en tu servidor.

La arquitectura es simple. Las apps de chat alimentan mensajes a un gateway que se ejecuta en tu máquina, el gateway llama al LLM que elegiste, y el modelo puede invocar herramientas y skills en tu equipo.

![Arquitectura de OpenClaw: las apps de chat alimentan el gateway en tu VPS o Mac Mini, el gateway llama a un proveedor LLM, y las herramientas y skills se ejecutan en tu servidor; solo las llamadas al modelo salen de tu máquina](@assets/images/26/01/openclaw-architecture.svg)

Todo se queda en tu máquina excepto las llamadas a la IA. Tus datos no viven en el servidor de alguna empresa. El gateway simplemente se ejecuta en segundo plano como un servicio. Los mensajes llegan desde Telegram o Slack, se enrutan al modelo, y el modelo puede mover archivos, ejecutar scripts o navegar por la web a través de herramientas.

Una cosa más que cambió este año: OpenClaw ahora tiene clientes de primera clase. Hay una app de iOS en la App Store, una app de Android en Google Play, un Hub nativo para Windows, una app de barra de menú para macOS y una Control UI en el navegador. Se emparejan como *nodos* al gateway. Tu teléfono se convierte en un control remoto, no en el servidor. Más sobre esto en la sección de instalación.

## OpenClaw en Mac Mini vs VPS: cuál elegir

Una situación curiosa: la comunidad de OpenClaw provocó una pequeña corrida de Mac Mini M4. La gente los compraba solo para ejecutar esto. Aquí te explico cómo decidir qué ruta tiene sentido para ti.

| Característica | Mac Mini | VPS |
|---------|----------|-----|
| Soporte de iMessage | Sí | No |
| Apps nativas de macOS | Sí | No |
| Inferencia de modelos locales | Excelente (chip M4) | Limitada |
| Consumo de energía | ~10W en reposo | N/A (alojado) |

Si quieres iMessage, el Mac Mini es tu única opción. El soporte es real y está documentado (vía la ruta de API privada `imsg`), pero sigue siendo solo para Mac. El chip M4 también maneja bien los modelos locales si intentas evitar facturas de API. Pero necesitas internet doméstico y electricidad sólidos, sin cortes.

Para elegir hardware, consulta [qué modelo de Mac mini necesitas para OpenClaw](/es/mejor-mac-mini-openclaw/).

## Instala OpenClaw en un VPS de Hetzner

Tarda unos 20 minutos de principio a fin en cualquier VPS con Ubuntu 24.04. Yo uso Hetzner, pero estos pasos funcionan en prácticamente cualquier proveedor. Dos rutas soportadas: el instalador de una línea (lo que quieren la mayoría de operadores en solitario) y la ruta oficial de Docker con VM-runtime.

<ListCheck>
<ul>
<li>VPS con Ubuntu 24.04, 1+ vCPU, 2-4 GB de RAM mínimo (8 GB da margen para otros servicios)</li>
<li>Par de claves SSH (`ssh-keygen -t ed25519` si no tienes una)</li>
<li>No se requiere dominio: el acceso al gateway es por túnel SSH</li>
<li>Una clave API o suscripción de LLM (Anthropic, OpenAI, Gemini), u Ollama para modelos locales</li>
</ul>
</ListCheck>

El instalador provisiona Node por sí mismo. **No** necesitas NodeSource ni una instalación manual de Node.

### Crear el servidor

1. Ve a [Hetzner Cloud Console](https://console.hetzner.cloud/) (vía [Hetzner Cloud](https://go.bitdoze.com/hetzner) si te registras desde cero)
2. Crea un nuevo proyecto llamado `openclaw`
3. Haz clic en **Create Server**
4. Selecciona:
   - **Location**: Alemania (la más barata) o tu región más cercana
   - **Image**: Ubuntu 24.04
   - **Type**: el nivel CX de entrada (CX23 en la línea actual), unos €5.49/mes tras las subidas de 2026. Confirma la línea exacta en la consola; cambia con el tiempo.
   - **IPv4**: déjalo activado
5. Añade tu clave SSH
6. Nómbralo `openclaw` y créalo

Espera 30 segundos a que arranque el servidor y anota la dirección IP. En el firewall cloud de Hetzner, permite **solo TCP 22**. Nada más necesita ser alcanzable, y eso incluye el puerto del gateway.

### Instalar OpenClaw (ruta de una línea)

Conéctate por SSH a tu servidor:

```bash
ssh root@YOUR_SERVER_IP
apt update && apt upgrade -y
```

Instala OpenClaw y ejecuta el asistente de incorporación:

```bash
curl -fsSL https://openclaw.ai/install.sh | bash
```

El asistente te guía por todo:
- Selección de gateway local vs remoto
- Autenticación del modelo (claves API u OAuth)
- Configuración del canal (Telegram, WhatsApp, etc.)
- Instalación del servicio en segundo plano

Usa `curl -fsSL https://openclaw.ai/install.sh | bash -- --no-onboard` si quieres los binarios sin el asistente, y luego ejecuta `openclaw onboard --install-daemon` más tarde.

¿Prefieres npm? Esa ruta también funciona (npm 12+):

```bash
npm install -g openclaw@latest --allow-scripts=openclaw
openclaw onboard --install-daemon
```

<Notice type="warning" title="Node 22 no está soportado">
Si seguiste guías antiguas e instalaste Node 22 desde NodeSource, elimínalo y vuelve a ejecutar el instalador. El mínimo de motor es `>=24.22.1 <25` o `>=26.12.1`. Se recomienda Node 26; el instalador de Linux trae Node 24 LTS. Si `openclaw update` se niega a ejecutarse o ves un error de motor de Node, esta es la razón: las versiones de seguridad de Node de octubre de 2026 (claves de certificados TLS comprometidas) convirtieron 24.22.1/26.12.1 en mínimos estrictos.
</Notice>

### Instalar OpenClaw en un VPS con Docker (ruta oficial)

Esta es la ruta a la que apuntan ahora los docs oficiales de Hetzner. Aísla el estado y te da valores por defecto sensatos.

```bash
apt-get update && apt-get install -y git curl ca-certificates
curl -fsSL https://get.docker.com | sh
```

Las imágenes vienen de `ghcr.io/openclaw/openclaw` (mirror en Docker Hub en `openclaw/openclaw`). Los tags incluyen `latest`, `extended-stable` y variantes `slim` / `-browser` (la imagen `-browser` incluye Chromium). El estado vive en directorios configurados por entorno (`OPENCLAW_CONFIG_DIR`, `OPENCLAW_WORKSPACE_DIR`, `OPENCLAW_AUTH_PROFILE_SECRET_DIR`), así que puedes ponerlos en un volumen persistente. El entrypoint de la imagen ejecuta Doctor antes de arrancar y sale si el estado no puede repararse; si el contenedor muere inmediatamente, lee primero la salida de Doctor en los logs.

<Notice type="error" title="Nunca expongas el puerto 18789 a internet">
La Control UI del gateway escucha en el puerto 18789. Las instalaciones en host se vinculan a loopback por defecto; las imágenes de contenedor se exponen con autenticación requerida, pero aun así no quieres ese puerto público. Accede a través de un túnel SSH o Tailscale. El firewall cloud de Hetzner debería permitir TCP 22 y nada más.
</Notice>

![Acceso a la Control UI a través de un túnel SSH: tu navegador llega a http://127.0.0.1:18789 vía ssh -N -L 18789:127.0.0.1:18789; el 0.0.0.0:18789 público nunca es aceptable, y el firewall cloud solo permite TCP 22](@assets/images/26/01/openclaw-gateway-ssh-tunnel.svg)

```bash
# from your laptop, then open http://127.0.0.1:18789/
ssh -N -L 18789:127.0.0.1:18789 root@YOUR_SERVER_IP
```

Si el túnel falla con "administratively prohibited", añade `AllowTcpForwarding local` a `/etc/ssh/sshd_config` en el VPS y reinicia sshd.

Modos de fallo en esta ruta:
- **El build de Docker se queda sin memoria en un servidor pequeño.** No necesitas compilar. Usa la imagen precompilada. ≥6 GB de RAM solo se requieren si compilas desde el código fuente; las imágenes precompiladas funcionan bien con 2-4 GB.
- **El contenedor sale inmediatamente.** Revisa la salida de Doctor en `docker logs`. Se niega a arrancar con estado no reparado.
- **El túnel conecta pero la página no carga.** Asegúrate de que el gateway se esté ejecutando dentro del contenedor y de que estás accediendo a `127.0.0.1`, no a la IP pública del VPS.

### Verifica tu instalación

No des la victoria por cantada cuando "el asistente terminó". Ejecuta este checklist:

<ListCheck>
<ul>
<li>`openclaw doctor`: espera salida limpia, o una lista de correcciones (ejecuta `openclaw doctor --fix` para aplicar las seguras)</li>
<li>`openclaw security audit`: espera que no haya desviaciones de severidad alta; cada verificación tiene severidad y la mayoría tienen auto-corrección</li>
<li>`openclaw channels status --probe`: espera que tu canal aparezca conectado</li>
<li>`openclaw status` y `openclaw health`: espera el gateway ejecutándose y saludable</li>
<li>Envía tu primer DM de Telegram, luego `openclaw pairing list` y `openclaw pairing approve telegram <CODE>` (los códigos expiran tras 1 hora)</li>
<li>`openclaw dashboard --no-open`: reimprime la URL de la Control UI si la perdiste</li>
</ul>
</ListCheck>

Si `doctor` está limpio, `security audit` no tiene nada alto, y tu DM de prueba obtuvo respuesta, la instalación está terminada.

### Actualizaciones, copias de seguridad y rollback

OpenClaw publica releases semanales o más rápido. Mantenerse al día no es higiene opcional. 75 avisos de seguridad de GitHub llegaron solo el 2026-09-11 (30 de ellos de severidad alta), y el problema del certificado comprometido de Node de octubre de 2026 es la razón de que exista el mínimo de Node.

```bash
openclaw backup        # always before an upgrade
openclaw update        # stable channel
openclaw update --channel beta   # opt-in
```

Los canales son `stable`, `beta` y `dev` (`openclaw update --channel dev`). Hay una verificación automática de actualizaciones, y los docs mantienen un runbook de rollback y recuperación. Léelo antes de necesitarlo. Las copias de seguridad son locales por defecto: `openclaw backup` escribe estado verificado en el servidor, así que copia la salida a algún lugar fuera del servidor (el almacenamiento compatible con S3 es el hogar obvio) o morirá con el VPS.

### Control UI y apps móviles

La Control UI del navegador vive en el puerto 18789 del gateway. Accede a través del túnel SSH de arriba, o por Tailscale. Si solo tienes el teléfono, `/controlui` la abre como una Mini App de Telegram. Los dispositivos nuevos que aparecen necesitan aprobación: `openclaw devices list`, luego `openclaw devices approve <requestId>`.

Clientes oficiales: app de iOS en la App Store (iOS/iPadOS 26.2+), Android en Google Play (`ai.openclaw.app`) más un APK firmado en la página de releases de GitHub, una app Hub nativa de Windows (instalador firmado, bandeja, chat, modo nodo) instalada con `iwr -useb https://openclaw.ai/install.ps1 | iex`, y una app de barra de menú para macOS.

<Notice type="info" title="Tu teléfono es un cliente, no el servidor">
Las apps móviles se emparejan como *nodos* acompañantes con modo Talk, activación por voz, acceso a cámara/pantalla/ubicación y `system.run`. El gateway sigue viviendo en el equipo Mac, Linux o Windows. Esta es la configuración de "asistente en tu bolsillo" sin poner el cerebro en el teléfono.
</Notice>

## Opciones de proveedor LLM

OpenClaw funciona con varios proveedores de IA. Los docs actuales recomiendan el modelo más potente de última generación para agentes con herramientas, más un `utilityModel` barato para tareas internas como títulos y resúmenes. Las referencias de modelo se ven como `anthropic/claude-sonnet-4-6` y `openai/gpt-5.5` (GPT-5.6 se menciona en las notas de v2026.10.6). Define valores por defecto con `openclaw models set`, o cambia por sesión en el chat con `/model <m>` (`-s` sesión, `-a` agente, `-g` global).

### Anthropic (Claude)

Esto es lo que recomendaría para la mayoría. Dos formas de conectar:

<Tabs>
<Tab name="Clave API">

1. Ve a [console.anthropic.com](https://console.anthropic.com/)
2. Crea una clave API (empieza con `sk-ant-`)
3. Pégala cuando el asistente la pida

Pagas por token. Directo, funciona en todas partes.
</Tab>
<Tab name="Suscripción de Claude (OAuth)">

Si tienes Claude Pro/Max, usa tu suscripción en lugar de pagar por créditos de API:

```bash
claude setup-token
```

Esto genera un token que pegas en el asistente. Funciona con Claude Code CLI. Los docs tratan las credenciales de suscripción como un perfil de autenticación distinto, así que puedes mantener ambas configuradas.
</Tab>
</Tabs>

### OpenAI

Para modelos de la era GPT-5.5:
1. Ve a [platform.openai.com](https://platform.openai.com/)
2. Crea una clave API
3. Ingrésala durante la incorporación

Si tienes una suscripción de ChatGPT Plus o Codex, OAuth funciona igual que con Claude.

### Google Gemini

Gemini 3 Flash es rápido y barato, y el flujo OAuth de Gemini CLI es fácil:

```bash
openclaw configure --section model
```

El asistente te pedirá autenticarte a través de Google. (Algunos docs antiguos muestran `--section models`; si la flag es rechazada, prueba la grafía en plural.)

### Modelos locales (Ollama)

Si quieres evitar los costos de API por completo, OpenClaw funciona con Ollama. Instálalo en tu servidor:

```bash
curl -fsSL https://ollama.ai/install.sh | sh
ollama pull llama3.2
```

Luego apunta OpenClaw al endpoint local en tu configuración. Un Mac Mini M4 es el mejor anfitrión para inferencia local; la mayoría de los VPS tendrán problemas con cualquier cosa más allá de modelos pequeños. Para elegir hardware y ajustes, consulta [ejecutar OpenClaw con modelos locales vía Ollama](/es/openclaw-ollama-modelos-locales/).

### Comparación de costos

Las tablas de dólares por modelo envejecen mal y las páginas de precios de los proveedores mienten por omisión, así que aquí van rangos honestos:

| Ruta | Costo mensual típico |
|-------|---------------------|
| Anthropic Claude (API) | Decenas bajas de USD para uso personal ligero; $50-150+ para uso agéntico intensivo |
| OpenAI GPT (API) | Mismo rango que Anthropic |
| Google Gemini 3 Flash (API) | Normalmente la API de laboratorio frontera más barata |
| Suscripción OAuth (Claude Pro/Max, ChatGPT Plus) | $20-100/mes fijos, sin factura por token |
| Local (Ollama) | $0 de costo de API (solo electricidad y cómputo) |

Las verdaderas palancas de costo, en orden de impacto:

1. Enruta las llamadas internas baratas (títulos, resúmenes) a un modelo pequeño con `utilityModel`. Configúralo una vez en `agents.defaults.utilityModel`.
2. Usa OAuth de suscripción en lugar de claves API si ya pagas por Claude o ChatGPT. Consulta [VibeProxy](/es/guia-vibeproxy-suscripciones-ia/) si quieres enrutar el acceso de suscripción a otras herramientas.
3. Usa embeddings locales para la búsqueda de memoria: la memoria semántica funciona con cero factura extra de API (detalles abajo).
4. Configura fallbacks de modelo: pon un modelo barato detrás del principal para que un límite de tasa no detenga al asistente.

Para las referencias de modelo en sí, nuestro resumen de los [mejores modelos open source para OpenClaw](/es/mejores-modelos-opensource-openclaw/) cubre lo que funciona bien. Alternativas más baratas de laboratorios frontera como [MiniMax](https://go.bitdoze.com/minimax) y [GLM](https://go.bitdoze.com/glm) cuestan una fracción de Anthropic y OpenAI. La [guía de configuración de nanobot](/es/guia-configuracion-nanobot/) cubre cómo ejecutar esos proveedores de principio a fin.

## Configuración de canales

Telegram, WhatsApp, Slack y Discord son los cuatro principales, pero OpenClaw ahora también soporta Matrix, Microsoft Teams, Signal, Google Chat, SMS, X/Twitter, IRC, Nostr, Mattermost, Nextcloud Talk, además de opciones regionales como Feishu/LINE/QQ/WeChat/Zalo. Los [docs de canales](https://docs.openclaw.ai/channels) tienen guías por canal para todos ellos.

### Configuración del bot de Telegram (la más fácil)

1. Abre Telegram y busca **@BotFather**
2. Envía `/newbot`
3. Elige un nombre y usuario para tu bot
4. Copia el token de bot que te da BotFather
5. Busca **@userinfobot** y envía cualquier mensaje para obtener tu ID de usuario
6. Pásale ambos a OpenClaw:

```bash
openclaw channels add --channel telegram --token <bot-token>
```

Eso escribe el bloque del canal por ti. La forma en `~/.openclaw/openclaw.json` se ve así (nota que la clave es `botToken`, no `token`):

```json5
{
  channels: {
    telegram: {
      enabled: true,
      botToken: "123:abc",
      dmPolicy: "pairing",
      groups: { "*": { requireMention: true } },
    },
  },
}
```

<Notice type="warning" title="Restringe quién puede hablar con el bot">
La política de DM por defecto es `pairing`: los remitentes desconocidos reciben un código en lugar de acceso, y tú los apruebas con `openclaw pairing approve telegram <CODE>`. Los códigos de emparejamiento **expiran tras 1 hora**, así que vuelve a enviar un DM al bot para obtener uno nuevo si tardas. En grupos, mantén `requireMention: true` para que el bot solo reaccione cuando lo mencionen. Usa `/whoami@bot` para confirmar los IDs de usuario. No cambies a DMs abiertos a menos que entiendas el radio de explosión: cualquiera que encuentre el bot podría entonces manejar un agente con acceso shell en tu servidor.
</Notice>

Para verificar, envía `/status` al bot y espera una respuesta. Si no llega nada, `openclaw channels status --probe` y `openclaw logs --follow` te dirán qué mitad está rota.

1. Crea una app de Slack en [api.slack.com/apps](https://api.slack.com/apps)

## Sistema de memoria

OpenClaw recuerda cosas de chats anteriores. La configuración de memoria tiene varias partes.

### Cómo funciona la memoria

La memoria a corto plazo es el contexto de la conversación actual. La memoria a largo plazo son hechos sobre ti en `~/.openclaw/workspace/MEMORY.md` y `~/.openclaw/workspace/USER.md`, más notas diarias en `memory/YYYY-MM-DD.md` (hoy y ayer se cargan automáticamente) y `DREAMS.md`. La búsqueda semántica encuentra conversaciones pasadas relevantes. Los proveedores de embeddings ahora incluyen **Local** (llama.cpp GGUF gestionado, ~0.3 GB, sin clave API), LM Studio, endpoints compatibles con Ollama, Bedrock, DeepInfra, Gemini, GitHub Copilot y Mistral.

Esa opción de embeddings locales importa: la memoria semántica puede funcionar con **cero factura extra de API**. Si prefieres omitir los embeddings por completo, el modo solo-palabras-clave es una flag de configuración (`memory.search.provider: "none"`). También hay memoria activa, barridos de "dreaming" y compactación ejecutándose en segundo plano.

### Hacer que las cosas perduren

Si OpenClaw sigue olvidando algo, díselo directamente:

> "Recuerda: prefiero las invitaciones de reuniones en Google Calendar, no en Outlook."

Lo almacena en tus archivos de memoria. También puedes editarlos directamente:

```bash
nano ~/.openclaw/workspace/USER.md
```

Añade tus preferencias, contexto de trabajo, detalles de proyectos, cualquier cosa que quieras que siempre sepa.

Los archivos del workspace viven en `~/.openclaw/workspace/`. Para la lista completa de opciones de configuración, consulta la [referencia de AGENTS.default](https://docs.openclaw.ai/reference/AGENTS.default).

| Archivo | Propósito |
|------|---------|
| `~/.openclaw/workspace/USER.md` | Tu información personal y preferencias |
| `~/.openclaw/workspace/SOUL.md` | Personalidad del bot y reglas de comportamiento |
| `~/.openclaw/workspace/MEMORY.md` | Memorias a largo plazo que acumula |
| `~/.openclaw/workspace/memory/YYYY-MM-DD.md` | Notas diarias (hoy/ayer se cargan automáticamente) |
| `~/.openclaw/workspace/DREAMS.md` | Salida de los barridos de dreaming/mantenimiento |
| `~/.openclaw/workspace/AGENTS.md` | Configuración de agentes para tareas especializadas |

## Archivos de configuración

<Notice type="info" title="config.json → openclaw.json">
La configuración principal ahora es `~/.openclaw/openclaw.json` (no `config.json`, y no dentro de la subcarpeta workspace). Es JSON5 (los comentarios y las comas finales están bien), y el gateway lo **recarga en caliente**, así que muchas ediciones se aplican sin reiniciar. Si estás siguiendo un tutorial de la era de enero, esa es la primera ruta que necesitas corregir.
</Notice>

Secciones clave:

### Configuración del modelo

```json5
{
  agents: {
    defaults: {
      model: {
        primary: "anthropic/claude-sonnet-4-6",
        fallbacks: ["google/gemini-3-flash"],
      },
      utilityModel: "google/gemini-3-flash",  // cheap internal tasks
    },
  },
}
```

Los docs llaman a la clave de fallback `fallbacks`. Snippets antiguos mostraban `fallback`. Si la clave es rechazada, prueba esa grafía, pero `fallbacks` es la que aparece en el FAQ de modelos actual.

### Configuración de canales

```json5
{
  channels: {
    telegram: {
      enabled: true,
      botToken: "YOUR_BOT_TOKEN",
      dmPolicy: "pairing",
      groups: { "*": { requireMention: true } },
    },
  },
}
```

Usa los comandos configure integrados para la ruta interactiva:

```bash
openclaw configure --section channels
openclaw configure --section model
```

O edita `~/.openclaw/openclaw.json` directamente y deja que la recarga en caliente lo aplique. `openclaw gateway restart` solo se necesita cuando la recarga en caliente te dice que no puede aplicar un cambio.

Para la integración MCP (Model Context Protocol), consulta nuestra [introducción a MCP para principiantes](/es/introduccion-mcp-principiantes/).

## Skills

Los skills son básicamente flujos de trabajo reutilizables que OpenClaw puede ejecutar. Añaden capacidades más allá de solo chatear.

### Skills integrados

Algunas capacidades funcionan de inmediato:
- Gestión de archivos (organizar carpetas, encontrar archivos)
- Búsqueda web: una clave API de Brave es una opción, pero puedes [añadir búsqueda web gratuita de DuckDuckGo a OpenClaw sin claves API](/es/busqueda-duckduckgo-openclaw/). Empieza por ahí antes de pagar por una API de búsqueda.
- Calendario y email (con la autenticación apropiada)
- Ejecutar scripts y comandos

### Añadir skills

Explora skills de la comunidad en [ClawHub](https://clawhub.ai). Instala con:

```bash
openclaw skills search "calendar"
openclaw skills install @openclaw/demo
openclaw skills update --all
openclaw plugins install clawhub:<package>
```

El prefijo `clawhub:` es obligatorio en plugins hasta v2026.10.4. Las páginas del registro muestran versiones, changelogs y **resúmenes de análisis de seguridad**. Léelos. La cadena de suministro de ClawHub ya produjo un CVE real (CVE-2026-25253), así que trata la instalación de skills como `curl | bash`, porque lo es.

### Crear skills personalizados

Los skills se definen en `~/.openclaw/workspace/skills/`. Un skill es básicamente una plantilla de prompt con parámetros:

```markdown
# Research Skill

Research {topic} and provide:
- 3 key findings
- Relevant sources
- Next steps
```

También puedes pedirle a OpenClaw que cree skills por ti:

> "Crea un skill que revise mis repos de GitHub por nuevos issues cada mañana."

### Carpetas de skills personalizadas

Carga skills desde una ubicación personalizada:

```json
{
  "skills": {
    "paths": ["~/.openclaw/workspace/skills", "~/my-custom-skills"]
  }
}
```

### Skills de herramientas de código (Claude Code, Codex, Gemini CLI)

Uno de los skills más útiles de OpenClaw le permite manejar herramientas de código con IA directamente. Con Claude Code, OpenAI Codex CLI o Gemini CLI instalados en tu servidor, puedes enviarle un mensaje a OpenClaw desde tu teléfono:

> "Usa Claude Code para crear una app FastAPI con autenticación de usuarios y despliégala en mi servidor."

OpenClaw lanza el CLI de código, pasa tus requisitos como prompts, monitorea la sesión y reporta de vuelta. Asegúrate de que el CLI esté instalado y autenticado:

```bash

```

Luego dile a OpenClaw qué hay disponible ("Tengo Claude Code instalado. Úsalo cuando te pida construir algo"). Lo almacena en memoria.

Una nota de higiene: las aprobaciones de exec han tenido avisos reales (el lote del 2026-09-11 incluía aprobaciones que sobrevivían a su directorio de trabajo). No dejes aprobaciones de exec generales por ahí; revísalas igual que revisarías reglas de sudo. Si manejas los tres CLIs, [Agent Router](https://go.bitdoze.com/agentrouter) te da acceso unificado desde un endpoint.

## Automatizaciones de OpenClaw: trabajos programados y recordatorios

Aquí es donde deja de ser un chatbot y empieza a automatizar cosas.

<Notice type="info" title="Heartbeat está retirado">
El antiguo sistema de monitores heartbeat/HEARTBEAT.md desapareció. El trabajo programado ahora son **trabajos de automatización** de primera clase con un planificador persistido integrado (`openclaw automations ...`; `openclaw cron` se mantiene como alias). Si configuraste monitores heartbeat en enero, ejecuta `openclaw doctor --fix`: los migra. Nunca fue el cron del sistema operativo, pese a lo que dicen algunas guías.
</Notice>

### Recordatorios y trabajos de una sola vez

Los recordatorios simples funcionan de inmediato:

> "Recuérdame revisar los logs del servidor cada lunes a las 9am."

> "En 3 horas, recuérdame revisar el pull request."

Cuando necesites precisión, omite el lenguaje natural y usa el CLI:

```bash
openclaw automations create "2027-02-01T16:00:00Z" --name "Reminder" --session main \
  --system-event "Reminder: check the automations docs draft" --wake now --delete-after-run
openclaw automations list
openclaw automations runs <job-id>
```

`--delete-after-run` evita que los trabajos de una sola vez se acumulen. El historial de ejecuciones vive en `automations runs <job-id>`. Revísalo cuando un recordatorio no se haya disparado.

### Programaciones recurrentes

Los horarios estilo cron siguen funcionando en lenguaje natural:

> "Ejecuta una verificación de espacio en disco cada día a medianoche."

> "Cada 6 horas, verifica si mi sitio web responde y avísame si está caído."

Estos también crean trabajos de automatización. `openclaw cron list` funciona como alias de `openclaw automations list`. Usa el atajo de chat `/loop` para órdenes permanentes. Más allá del reloj, los trabajos también pueden dispararse desde webhooks y Gmail PubSub. Consulta los [docs de automatización](https://docs.openclaw.ai/automation/cron-jobs) para esos.

### Monitoreo proactivo

A diferencia de ChatGPT o Claude web, OpenClaw te escribe primero:

> "Monitorea el uso de CPU de mi servidor. Si supera el 80% durante más de 5 minutos, envíame un mensaje."

> "Vigila mi bandeja de entrada por emails de [cliente]. Cuando llegue uno, resúmelo y envíamelo inmediatamente."

Exprésalos como trabajos de automatización recurrentes u órdenes permanentes de `/loop` en lugar de los antiguos monitores heartbeat.

### Ejemplo: asistente de standup diario

> "Cada día laborable a las 8:30am:
> 1. Revisa mi calendario para las reuniones de hoy
> 2. Escanea mi email por elementos urgentes
> 3. Mira mis notificaciones de GitHub
> 4. Envíame un solo mensaje resumiendo todo esto"

Un mensaje de Telegram cubre lo que necesita atención antes de que abras el portátil.

## Ejecutar Agno y scripts de Python con OpenClaw

[Agno](/es/empezar-agno/) es un framework de Python para construir agentes de IA. Combínalo con [uv](/es/empezar-uv/) para gestión rápida de paquetes y puedes construir scripts que OpenClaw ejecuta por ti. Esto es integración a nivel de SO (OpenClaw invoca tu script por shell), así que funciona sin importar qué LLM uses.

OpenClaw maneja el lado de la mensajería. Agno maneja el trabajo complejo de IA: configuraciones multi-agente, pipelines RAG, uso de herramientas. Le envías un mensaje a OpenClaw por Telegram, ejecuta tu script de Agno, Agno hace la investigación o el análisis, y los resultados vuelven a través de OpenClaw.

Instala uv en tu servidor:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Crea un directorio de scripts:

```bash
mkdir -p ~/openclaw-scripts
cd ~/openclaw-scripts
uv init
uv add agno openai duckduckgo-search
```

### Ejemplo: script de agente de investigación

```python
#!/usr/bin/env python3
# ~/openclaw-scripts/research_agent.py
# /// script
# requires-python = ">=3.11"
# dependencies = ["agno", "openai", "duckduckgo-search"]
# ///

import sys
from agno.agent import Agent
from agno.models.openai import OpenAIChat
from agno.tools.duckduckgo import DuckDuckGoTools

def research(topic: str) -> str:
    agent = Agent(
        model=OpenAIChat(id="gpt-4o"),
        tools=[DuckDuckGoTools()],
        instructions=[
            "You are a research assistant.",
            "Search the web for current information.",
            "Provide concise, factual summaries.",
        ],
        markdown=True,
    )

    response = agent.run(f"Research this topic and provide key findings: {topic}")
    return response.content

if __name__ == "__main__":
    topic = " ".join(sys.argv[1:]) if len(sys.argv) > 1 else "AI agents"
    print(research(topic))
```

```bash
chmod +x ~/openclaw-scripts/research_agent.py
```

Cuéntale a OpenClaw sobre él:

> "Tengo un script de Python en ~/openclaw-scripts/research_agent.py que hace investigación web. Cuando te pida investigar algo complejo, ejecútalo con uv así: `uv run ~/openclaw-scripts/research_agent.py [tema]`"

Luego envía el mensaje "Investiga los últimos desarrollos en agentes de IA autónomos" y ejecuta el script, que lanza su propio agente y devuelve los resultados.

Scripts que podrías construir:

<li>Un revisor de código que lee un PR de GitHub y da feedback</li>
<li>Un agente de preparación de reuniones que investiga a los asistentes antes de una llamada</li>

## Solución de problemas

### El bot no responde

```bash
openclaw status --all
openclaw logs --follow
```

Normalmente es uno de estos:
- El gateway falló o no se está ejecutando
- La clave API expiró o fue rotada
- El token del canal está mal o expiró
- Node demasiado viejo: `openclaw update` se niega a ejecutarse por debajo de 24.22.1/26.12.1

### Código de emparejamiento requerido (o expirado)

La seguridad por defecto requiere aprobar nuevos remitentes:

```bash
openclaw pairing list telegram
openclaw pairing approve telegram <code>
```

Los códigos expiran tras 1 hora. Si el tuyo caducó, envía otro DM al bot para obtener uno nuevo.

### Contexto demasiado grande

Las conversaciones largas alcanzan los límites de tokens:

```
/compact
```

O empieza de nuevo:

```
/new
```

### El contenedor de Docker sale al arrancar

Lee la salida de Doctor; `docker logs <container>` muestra el porqué. El entrypoint ejecuta Doctor antes del gateway y sale si el estado no puede repararse. Causas comunes: permisos incorrectos en el volumen de config/workspace, o un `openclaw.json` migrado a medias.

### El túnel SSH dice "administratively prohibited"

Añade `AllowTcpForwarding local` a `/etc/ssh/sshd_config` en el VPS, `systemctl restart ssh`, y reconecta el túnel. Y no, abrir 18789 públicamente no es la solución.

### OOM en un VPS pequeño

Si intentaste compilar la imagen de Docker en un servidor de 2 GB, no lo hagas. Usa la imagen precompilada `ghcr.io/openclaw/openclaw`. Para la instalación directa, 2 GB es viable, 4 GB es cómodo.

### Puerto 18789 ya en uso

Algo más tomó el puerto de la Control UI. `ss -tlnp | grep 18789` muestra quién. Detenlo o mueve el puerto del gateway en la config.

### SSH pide contraseña cuando tienes una clave

```bash
ssh -i ~/.ssh/id_ed25519 root@YOUR_SERVER_IP
```

### Necesitas rehacer la configuración

```bash
openclaw reset
openclaw onboard --install-daemon
```

## Consideraciones de seguridad de OpenClaw

OpenClaw tiene acceso shell a tu servidor. Esa es la función y el riesgo. Empieza con la verificación canónica:

```bash
openclaw security audit
```

Es un catálogo de IDs de verificación con severidades y auto-correcciones. Ejecútalo después de cada cambio de configuración y después de cada actualización. Luego trabaja el resto.

**Exposición del gateway.** Las instalaciones en host se vinculan a loopback por defecto. Nunca abras TCP 18789 públicamente. Usa el túnel SSH o Tailscale (ver la sección de instalación con Docker arriba). Tu firewall cloud debería permitir TCP 22 y nada más.

**Valores de emparejamiento por defecto.** La política de DM por defecto es `pairing`: los remitentes desconocidos obtienen un código en lugar de acceso al bot. No lo desactives a menos que entiendas las implicaciones. El acceso a grupos se mantiene detrás de `requireMention: true`.

**Un límite de confianza por gateway.** OpenClaw no es un límite multi-inquilino. Los usuarios que no deberían ver los datos de otros, o que podrían atacar activamente al agente, necesitan gateways separados: usuarios de SO separados, hosts separados. Añadir a todos a una lista `allowFrom` está bien para tu casa, no para inquilinos hostiles.

**Mantente al día.** 75 avisos de seguridad de GitHub se publicaron solo el 2026-09-11 (30 de severidad alta, incluyendo aprobaciones de exec que sobrevivían a su directorio de trabajo, alcance entre turnos de la herramienta de login de WhatsApp, confusión de IDs de usuario de Matrix, y hashes de revisión de config exponiendo verificadores de contraseña). ClawHub tuvo CVE-2026-25253. El incidente del certificado comprometido de Node de octubre de 2026 es la razón de que exista el mínimo de Node. La cadencia de releases es semanal o superior, así que `openclaw update` es parte de las operaciones ahora, no una tarea ocasional.

Higiene de operaciones:

<ListCheck>
<ul>
<li>Usa `dmPolicy: "pairing"` y `allowFrom` para restringir quién puede enviar mensajes a tu bot</li>
<li>Crea una cuenta de email/GitHub separada para el bot si necesita acceso a cuentas</li>
<li>Revisa la configuración del sandbox si se ejecuta en una máquina con datos sensibles</li>
<li>Mantén las claves API fuera de los archivos de memoria y las conversaciones: se persisten</li>
<li>Monitorea el uso de API: las tareas descontroladas pueden quemar créditos</li>
<li>Sabe dónde se configuran el rate limiting y los bloqueos del gateway</li>
<li>El filtrado a nivel DNS en el VPS (a mí me gusta [NextDNS](https://go.bitdoze.com/nextdns)) corta rutas de exfiltración accidentales</li>
<li>Respuesta a incidentes: contener (`openclaw gateway stop`), rotar (tokens, claves API, tokens de bot), auditar (`openclaw security audit` + `openclaw logs`)</li>
</ul>
</ListCheck>

Si algo fue abusado, trátalo como cualquier otro servicio comprometido: detén el gateway primero, luego rota credenciales, luego lee los logs. No depures mientras sigue ejecutándose.

5. Añade búsqueda web: la [búsqueda web gratuita de DuckDuckGo sin claves API](/es/busqueda-duckduckgo-openclaw/) es el valor por defecto correcto. Usa Brave o una API de búsqueda para agentes de pago como [TinyFish](https://go.bitdoze.com/tinyfish) solo si necesitas más
6. Conecta más herramientas: GitHub, Google Drive, integraciones de calendario
7. Instala las apps móviles y empárjalas como nodos (ver la sección de Control UI arriba)
8. Mantenlo actualizado con `openclaw backup` + `openclaw update` mensuales como mínimo (ver Actualizaciones, copias de seguridad y rollback)

Los [docs oficiales](https://docs.openclaw.ai/) tienen guías detalladas de configuración para integraciones específicas.

<Accordion label="Preguntas frecuentes" group="faq" expanded="true">

**¿Necesito habilidades técnicas para configurar OpenClaw?**

Comodidad básica con la línea de comandos ayuda. Si puedes hacer SSH a un servidor y copiar-pegar comandos, puedes configurarlo. El asistente maneja la mayor parte de la complejidad.

**¿Es OpenClaw un asistente de IA autoalojado?**

Sí, esa es la descripción honesta. El gateway, los archivos de memoria, los skills y los logs viven todos en tu máquina. Lo único que sale es la llamada al modelo hacia el proveedor LLM que elijas (a menos que ejecutes un modelo local vía Ollama, en cuyo caso nada sale). Ese límite de datos es la razón principal para autoalojar en lugar de usar un producto de chat alojado.

**¿Cuánto cuesta ejecutarlo?**

VPS: ~€5.49/mes por el nivel CX de entrada en Hetzner tras las subidas de 2026. Costos de API: orden de magnitud $15-100/mes dependiendo del uso y la elección de modelo, o unos $20-100/mes fijos si enrutas una suscripción de Claude/ChatGPT por OAuth. Total: $20-110/mes para la mayoría de usuarios. Dos ahorros fáciles: pon `utilityModel` en un modelo barato para llamadas internas, y usa embeddings locales para la búsqueda de memoria para que el recuerdo semántico no cueste nada.

**¿Pueden varias personas usar un OpenClaw?**

Sí, dentro de un mismo límite de confianza. Añade múltiples IDs de usuario a `allowFrom` (o listas de permitidos de grupo) y cada persona obtiene su propio contexto de conversación. Para equipos, Slack o Discord funcionan mejor que bots individuales de Telegram. Si los usuarios son hostiles entre sí, necesitan gateways separados; ver la sección de seguridad.

**¿Funciona en Windows?**

Sí, de forma nativa ahora. Hay un instalador firmado de Windows Hub (bandeja, chat, modo nodo): `iwr -useb https://openclaw.ai/install.ps1 | iex`. WSL2 sigue funcionando bien si prefieres la ruta de Linux.

**¿Puedo ejecutarlo en una Raspberry Pi?**

Los docs tienen una página dedicada a Raspberry Pi, así que está soportado. Espera rendimiento más lento y presión de memoria en conversaciones grandes de lo que una Pi 4/5 de 4 GB+ puede manejar cómodamente. Un mini PC usado suele ser menos doloroso.

**¿Cuál es la diferencia entre stable y beta?**

Stable recibe funciones probadas. Beta (y `dev`) reciben lo nuevo primero pero pueden tener bugs. Para cualquier cosa de la que dependas, quédate con stable. Los canales se cambian con `openclaw update --channel beta` (o `--channel dev`).
