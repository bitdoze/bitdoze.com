Así que apunté OpenClaw a una instancia local de Ollama y no miré atrás. Esta guía cubre cómo ejecutar OpenClaw con Ollama usando los mejores modelos locales de 2026: niveles de hardware, modelos recomendados actuales y ejemplos completos de configuración.

La lista de modelos de 2026 ha cambiado mucho desde que se publicó esta guía por primera vez. Las recomendaciones por defecto anteriores (qwen2.5-coder, Llama 3.x, Mistral) ahora muestran advertencias de obsolescencia cuando se lanzan como modelos de agente. La selección actual se centra en `qwen3.5`, `gemma4`, `gpt-oss` y el sorprendentemente capaz `Nanbeige4.2-3B` para hardware económico. Los repasaré todos.

## Por Qué Ejecutar OpenClaw con Modelos Locales

Tres razones para molestarse con esto en lugar de simplemente usar una API:

<ListCheck>
<ul>
<li>**$0 por token**: Ollama es gratis. Sin facturas de API, sin límites de velocidad, sin topes de uso</li>
<li>**Privacidad**: las conversaciones nunca salen de tu máquina. Sin logging de terceros, sin políticas de retención de datos que leer</li>
<li>**Sin dependencia de internet**: funciona en una red aislada, durante cortes, en un avión</li>
</ul>
</ListCheck>

La contrapartida es real: los modelos locales son más lentos y menos capaces que Claude Opus o GPT-5. Pero para las tareas cotidianas de OpenClaw como responder mensajes y ejecutar trabajos programados, un modelo local decente lo maneja bien. Y si quieres un término medio, Ollama Cloud ahora ofrece desbordamiento barato en la nube a través del mismo daemon. Más sobre esto en la sección híbrida más abajo.

## Requisitos de Hardware

Esta es la parte en la que la mayoría de guías se equivocan. Te dicen el tamaño del modelo y se olvidan de la experiencia real. Esto es lo que puedes esperar en diferentes niveles.

### La VRAM Es Lo Que Importa

Los modelos se ejecutan en la VRAM de la GPU cuando está disponible. Si el modelo no cabe en la VRAM, se desborda a la RAM del sistema y se vuelve mucho más lento. La inferencia solo con CPU funciona, pero espera respuestas 5-10x más lentas. Una regla aproximada: los modelos con cuantización Q4 necesitan alrededor de 0.6GB por cada mil millones de parámetros, más 2-4GB de margen para el contexto y la sobrecarga del sistema.

| Nivel de Hardware | VRAM / RAM | Mejor Tamaño de Modelo | Velocidad de Respuesta |
|---|---|---|---|
| **Gama baja** (sin GPU, 8GB RAM) | 8GB sistema | Modelos 1B-3B | Lenta (orden de magnitud: 5-15 tok/s) |
| **Gama media** (sin GPU, 16-32GB RAM) | 16-32GB sistema | Modelos 7B-12B | Moderada (10-25 tok/s) |
| **GPU básica** (RTX 3060 12GB / M1 16GB) | 12-16GB | Modelos 7B-14B | Buena (30-60 tok/s) |
| **GPU media** (RTX 4070 Ti 16GB / M2 Pro 32GB) | 16-32GB | Modelos 14B-32B | Buena (40-80 tok/s) |
| **GPU alta** (RTX 4090 24GB / M4 Max 128GB) | 24-128GB | Modelos 32B-70B | Rápida (50-100+ tok/s) |

Los valores de velocidad anteriores son estimaciones de orden de magnitud, no benchmarks portados. Tus cifras dependerán de la cuantización, la longitud del contexto y de si el modelo se carga en frío.

<Notice type="warning" title="Nota sobre Apple Silicon">
Los Mac con M1/M2/M3/M4 comparten memoria unificada entre CPU y GPU, así que Ollama puede usar toda la RAM del sistema como VRAM. Desde Ollama v0.40, **MLX es el runtime por defecto en Apple Silicon**. Esto afecta tanto a la velocidad como a la cantidad de memoria que necesita un modelo. Un Mac Mini M4 con 32GB de RAM puede ejecutar cómodamente modelos de 14B-32B. ¿Estás buscando uno ahora? La guía del [mejor Mac mini para OpenClaw](/es/mejor-mac-mini-openclaw/) cubre los niveles de memoria del M6 y el M5 Pro de 2026.
</Notice>

## Instalar Ollama

Un solo comando en Linux (URL canónica a noviembre de 2026; `ollama.ai/install.sh` aún redirige, pero usa el nuevo dominio):

```bash
curl -fsSL https://ollama.com/install.sh | sh
```

En macOS, descarga desde [ollama.com](https://ollama.com) o usa Homebrew:

```bash
brew install ollama
```

**Verifica que está funcionando:**

```bash
ollama --version
# expect 0.40.x as of Nov 2026
curl http://localhost:11434/api/tags
# empty list = healthy daemon
```

Si `curl` devuelve una respuesta JSON (incluso con cero modelos), ya lo tienes listo. Si dice "connection refused", el daemon no se está ejecutando.

**Modos de fallo:**
- **Puerto 11434 ya en uso**: `ss -tlnp | grep 11434` para encontrar qué lo está ocupando
- **Servicio no iniciado en Linux**: `systemctl status ollama` y `systemctl start ollama`

## Mejores Modelos para OpenClaw en 2026

<Notice type="warning" title="Los Modelos Antiguos Están Obsoletos">
Si sigues ejecutando `qwen2.5-coder`, `llama3.3`, `mistral`, `codellama` o `starcoder` como modelos de agente, Ollama v0.32.0 (2026-07-11) ahora muestra una advertencia de obsolescencia al iniciar. Estos modelos siguen funcionando, pero ya no se mantienen para tool calling de agentes. La selección de abajo es la generación actual.
</Notice>

No todos los modelos funcionan bien con OpenClaw. Necesitas **soporte de tool calling** (para que el agente pueda usar sus herramientas) e idealmente **buen seguimiento de instrucciones**. Las capacidades de visión y pensamiento son un extra deseable. Aquí están los modelos que rinden bien en 2026.

### Mejores Modelos por Nivel

| Modelo | Tamaño | VRAM (est. Q4) | Tool Calling | Mejor Para |
|---|---|---|---|---|
| `gemma4:31b` | 31B | ~18GB | Sí | Mejor calidad local |
| `qwen3.5:27b` | 27B | ~16GB | Sí | Programación, tareas complejas |
| `qwen3.5:35b` | 35B | ~20GB | Sí | Cargas de trabajo pesadas |
| `gpt-oss:20b` | 20B | ~14GB | Sí | General, uso de herramientas |
| `qwen3.5:9b` | 9B | ~6GB | Sí | Propósito general |
| `gemma4:12b` | 12B | ~8GB | Sí | Equilibrio velocidad/calidad |
| `qwen3.5:4b` | 4B | ~3GB | Sí | General económico |
| `gemma4:e4b` | 4B | ~3GB | Sí | Económico + visión |
| `Nanbeige4.2-3B`* | 3B | ~2.5GB | Ver nota | Económico, gama baja |
| `deepseek-r1:70b` | 70B | ~42GB | Sí | Mejor razonamiento local |

\* Subida comunitaria en Ollama. Consulta la sección de Nanbeige más abajo para ver las salvedades sobre tool calling.

Los valores de VRAM son estimaciones para cuantización Q4. Para el nivel de "mejor calidad local", consulta también los [mejores LLMs open source para reemplazar a Claude Opus](/es/mejores-llms-opensource-alternativa-claude/).

### Mis Recomendaciones

- **Mac Mini de 32GB o GPU de 16GB+**: `qwen3.5:27b` como principal, `qwen3.5:9b` como fallback
- **16GB RAM, sin GPU**: `gemma4:12b` como principal, `qwen3.5:9b` como fallback
- **8GB RAM**: `Nanbeige4.2-3B` como principal, fallback de Ollama Cloud para desbordamiento

Descarga tu modelo elegido:

```bash
# For 32GB Mac / 16GB+ GPU:
ollama pull qwen3.5:27b

# For 16GB no-GPU:
ollama pull gemma4:12b

# For 8GB budget:
ollama pull ndavat/Nanbeige4.2-3B

# General purpose alternatives:
ollama pull gemma4
ollama pull qwen3.5:9b
ollama pull gpt-oss:20b
```

### Verifica Que Funciona

<Notice type="success" title="Verificar">
Después de descargar los modelos, ejecuta esta comprobación en tres pasos:

1. `openclaw models list --provider ollama`: confirma que OpenClaw ve tus modelos
2. `openclaw models status`: muestra la salud y las asignaciones actuales
3. `openclaw agent --model ollama/gemma4 "ping"`: prueba de inferencia en vivo

Si el paso 3 devuelve una respuesta, estás conectado. Si los modelos no aparecen en el paso 1, puede que aún no estén cargados en memoria. Compruébalo con `curl http://localhost:11434/api/ps` y ejecuta `ollama run <modelo>` una vez para cargarlo en memoria.
</Notice>

## Nanbeige4.2-3B: La Sorpresa Económica

Nanbeige4.2-3B es un modelo de 3B parámetros de Nanbeige Lab que rinde muy por encima de su categoría. Utiliza una arquitectura Looped Transformer. El modelo reutiliza sus capas internas en lugar de tener capas únicas para cada bloque, razón por la cual un modelo de 4B totales / 3B sin embeddings puede competir con modelos mucho más grandes. Ocupa el puesto #1 en la tabla de clasificación de modelos pequeños de Artificial Analysis y apunta explícitamente a OpenClaw como estructura de asistente personal local.

Los benchmarks frente a modelos 3-4x más grandes son difíciles de ignorar:

| Benchmark | Nanbeige4.2-3B | Qwen3.5-9B | Gemma4-12B |
|---|---|---|---|
| **Claw-Gym** (tareas de agente) | **65.0** | 56.1 | 40.8 |
| **SWE-Bench Verified** (programación) | **63.6** | 53.1 | 44.2 |
| **Terminal-Bench 2.0** | **44.1** | n/d | n/d |
| **GPQA-Diamond** (ciencia) | **87.4** | n/d | n/d |
| **LiveCodeBench-V6** (programación) | **72.5** | n/d | n/d |

Tiene una ventana de contexto de 256K, licencia Apache-2.0, y su informe técnico está en [arXiv:2607.22083](https://arxiv.org/abs/2607.22083). Nanbeige4.5 está en entrenamiento para finales de 2026.

<Notice type="info" title="Nota de Versión Anterior">
La versión previa, Nanbeige4.1-3B, sigue disponible como `tomng/nanbeige4.1` en Ollama. Si ya la tienes descargada sigue funcionando, pero 4.2 es el modelo a usar de ahora en adelante.
</Notice>

### Cuándo Usarlo

- Tu máquina tiene 8GB de RAM y no tiene GPU
- Quieres un modelo de respaldo que use recursos mínimos
- Estás ejecutándolo en una Raspberry Pi 5 o placa ARM similar
- Necesitas un fallback de emergencia cuando tu modelo principal es demasiado lento

### Cuándo NO Usarlo

- Tienes hardware para modelos más grandes; los de 9B+ seguirán dando mejores resultados en tareas complejas
- Necesitas escritura creativa extensa o conversación con matices
- Estás haciendo refactorización pesada de código en múltiples archivos

### Instalar Nanbeige4.2-3B

La vía principal es una subida comunitaria en Ollama (2.6GB, 256K de contexto):

```bash
ollama pull ndavat/Nanbeige4.2-3B
```

**Verifica que está cargado y comprueba el soporte de herramientas:**

```bash
ollama show ndavat/Nanbeige4.2-3B | grep -i tools
```

<Notice type="warning" title="Advertencia sobre Tool Calling">
Las subidas comunitarias pueden no anunciar la capacidad `tools` que requiere el descubrimiento automático de OpenClaw. Si el grep anterior no devuelve nada, tienes dos opciones: configurar el modelo explícitamente en `openclaw.json` (ver Paso 3 más abajo), o añadir `compat.supportsTools: false` en la entrada del modelo si el modelo se bloquea con esquemas de herramientas. No des por hecho que el tool calling funciona hasta que lo hayas visto funcionar.
</Notice>

También puedes importar una cuantización GGUF específica desde HuggingFace (las cuantizaciones de bartowski están bien mantenidas):

```bash
# Download a Q4_K_M quantization from:
# huggingface.co/bartowski/Nanbeige_Nanbeige4.2-3B-GGUF

cat > Modelfile << 'EOF'
FROM ./Nanbeige4.2-3B-Q4_K_M.gguf
PARAMETER temperature 0.6
PARAMETER top_p 0.95
PARAMETER repeat_penalty 1.0
TEMPLATE """{{- if .System }}{{ .System }}{{ end }}
{{- range .Messages }}
{{- if eq .Role "user" }}
{{ .Content }}
{{- else if eq .Role "assistant" }}
{{ .Content }}
{{- end }}
{{- end }}"""
EOF

ollama create nanbeige4.2-3b -f Modelfile
```

## Configurar OpenClaw para Ollama

<Notice type="info" title="¿Actualizando Desde una Configuración Antigua?">
Si tienes un `openclaw.json` anterior a mediados de 2026, ejecuta primero `openclaw doctor --fix`. Migra los perfiles de autenticación heredados (de JSON plano a SQLite) y ajusta automáticamente las claves de presupuesto de contexto.
</Notice>

### Paso 1: Habilitar Ollama

<Notice type="info" title="Cambio en la Autenticación">
Desde el lanzamiento de Ollama Cloud, `OLLAMA_API_KEY` en el entorno se trata como la **convención de Ollama Cloud** y no se envía a hosts locales o autoalojados por defecto. Para URLs de Ollama en loopback, red privada, `.local` o nombres de host simples, el marcador `ollama-local` es lo que buscas. Los hosts remotos públicos necesitan una credencial real (variable de entorno, perfil de autenticación o `apiKey` del proveedor).
</Notice>

Para una instancia local de Ollama, establece el marcador:

```bash
export OLLAMA_API_KEY="ollama-local"
```

O añádelo permanentemente:

```bash
echo 'OLLAMA_API_KEY=ollama-local' >> ~/.openclaw/.env
```

### Paso 2: Verificar el Descubrimiento

OpenClaw descubre automáticamente los modelos de Ollama capaces de usar herramientas, pero con una salvedad: solo considera los modelos **cargados en memoria** (visibles en `/api/ps`) con soporte de herramientas y ≥16K de contexto confirmado. Un modelo que está instalado pero no cargado no aparecerá.

```bash
# Check what's loaded:
curl http://localhost:11434/api/ps

# Check what OpenClaw found:
openclaw models list --provider ollama
```

**Si un modelo está descargado pero no aparece en la lista:** no está cargado. Ejecútalo una vez (`ollama run <modelo>`) o configúralo explícitamente en el siguiente paso.

### Paso 3: Establecer Tu Modelo

Para una configuración sencilla con un solo modelo:

```bash
openclaw models set ollama/gemma4
```

O edita tu archivo de configuración (`~/.openclaw/openclaw.json`):

```json
{
  "agents": {
    "defaults": {
      "model": {
        "primary": "ollama/qwen3.5:27b"
      }
    }
  }
}
```

<Notice type="warning" title="Nunca Uses /v1">
Al configurar una `baseUrl` personalizada, usa la API nativa de Ollama, sin el sufijo `/v1`. El endpoint `/v1/chat/completions` compatible con OpenAI rompe el tool calling: los modelos emiten JSON de tool calls en bruto como texto plano en lugar de llamadas estructuradas. Usa siempre `"api": "ollama"` con una `baseUrl` como `http://localhost:11434`.
</Notice>

### Paso 4: Configurar Fallbacks

Los fallbacks importan más con modelos locales porque un solo modelo puede ser demasiado lento o quedarse sin contexto. Configura una cadena:

```json
{
  "agents": {
    "defaults": {
      "model": {
        "primary": "ollama/qwen3.5:27b",
        "fallbacks": [
          "ollama/qwen3.5:9b",
          "ollama/gemma4:12b"
        ]
      }
    }
  }
}
```

O usa la CLI:

```bash
openclaw models fallbacks add ollama/qwen3.5:9b
openclaw models fallbacks add ollama/gemma4:12b
```

Si el modelo de 27B se atasca con un contexto largo, OpenClaw pasa al de 9B, y luego a gemma4.

### Ejemplo de Configuración Completa (Hardware de Gama Media)

Aquí tienes una configuración completa para un Mac Mini de 32GB:

```json
{
  "models": {
    "providers": {
      "ollama": {
        "baseUrl": "http://localhost:11434",
        "apiKey": "ollama-local",
        "api": "ollama",
        "timeoutSeconds": 300,
        "models": [
          {
            "id": "qwen3.5:27b",
            "name": "qwen3.5:27b",
            "reasoning": true,
```

## Ollama Cloud: La Configuración Híbrida Local + Nube

Ollama ahora tiene un nivel en la nube, y encaja perfectamente en la cadena de fallbacks de OpenClaw. Obtienes privacidad local primero con desbordamiento económico en la nube cuando tu modelo local no puede con una tarea.

Hay tres modos de configuración:

<Tabs>
<Tab name="Solo Local">

**Puro local: coste cero, sin dependencia de red**

No necesitas cuenta de Ollama Cloud. Los modelos se ejecutan en tu hardware, las respuestas nunca salen de tu máquina. Esta es la opción por defecto si quieres la máxima privacidad.

Configura fallbacks entre modelos locales de diferentes tamaños (27B → 9B → 3B). No se consumen tokens en la nube.

</Tab>
<Tab name="Nube + Local (recomendado)">

**Híbrido: principal local, desbordamiento en la nube**

Inicia sesión en Ollama Cloud desde tu daemon:

```bash
ollama signin
```

Luego usa modelos con el sufijo `:cloud` en tu cadena de fallbacks:

```json
{
  "agents": {
    "defaults": {
      "model": {
        "primary": "ollama/qwen3.5:27b",
        "fallbacks": [
          "ollama/qwen3.5:9b",
          "ollama/glm-5.3-flash:cloud"
        ]
      }
    }
  }
}
```

Cuando el modelo local alcanza sus límites (contexto demasiado largo, tarea demasiado compleja), OpenClaw pasa automáticamente al modelo en la nube. Solo pagas por el desbordamiento: centavos por mensaje, no dólares.

</Tab>
<Tab name="Solo Alojado (ollama-cloud)">

**Sin daemon local: API pura a través de la nube de Ollama**

Usa el proveedor dedicado `ollama-cloud` si no quieres ejecutar Ollama localmente en absoluto:

```bash
export OLLAMA_API_KEY="olw_your_key_here"
openclaw onboard --auth-choice ollama-cloud
```

Luego establece `ollama-cloud/kimi-k3` o similar como tu modelo principal. Esta es la vía más limpia si solo quieres el ecosistema de Ollama sin gestionar un daemon.

</Tab>
</Tabs>

## Cambiar de Modelo Sobre la Marcha

No tienes que reiniciar OpenClaw para cambiar de modelo. Usa el comando `/model` en el chat:

```
/model                        # Show available models
/model list                   # Full list with providers
/model ollama/qwen3.5:9b     # Switch to a different model
/model default                # Clear session override
```

Para modelos de pensamiento/razonamiento (qwen3.5, gemma4), puedes controlar la profundidad de razonamiento:

```
/think low                    # Light reasoning (faster)
/think medium                 # Balanced
/think high                   # Deep reasoning
/think max                    # Maximum effort
/think off                    # Disable thinking
```

Equivalente en CLI: `openclaw agent --model ollama/gemma4 --thinking low`. Por defecto es Off. Una peculiaridad: en Qwen3.5, `low` cuenta como pensamiento activado, así que no quedará completamente desactivado.

**Verificar:** `/model status` muestra el modelo actual y el estado de autenticación.

Nota: un modelo descargado después de iniciar OpenClaw puede no aparecer en `/model list` hasta que esté cargado en memoria (consulta la salvedad de descubrimiento en el Paso 2 arriba).

## Ajuste de Rendimiento

### Ventana de Contexto

Hay tres claves que controlan el contexto, y configurarlas mal es la causa más común de "por qué mi modelo olvida cosas":

- **`contextWindow`**: los metadatos de ventana nativa del modelo (informativo)
- **`contextTokens`**: limita el presupuesto de entrada activa de OpenClaw (el descubrimiento automático limita a 32,768)
- **`params.num_ctx`**: establece el contexto real de petición de Ollama (por defecto: 4096)

El adaptador nativo establece `options.num_ctx` a partir de `params.num_ctx` primero, y luego `contextTokens`. Solo si ninguno está configurado Ollama recurre a su propio valor por defecto de 4096. Mantenlos alineados cuando el hardware no pueda ejecutar el contexto completo anunciado:

```json
{
  "models": {
    "providers": {
      "ollama": {
        "models": [{
          "id": "qwen3.5:27b",
          "contextTokens": 32768,
          "params": {
            "num_ctx": 32768
          }
        }]
      }
    }
  }
}
```

Las ventanas de contexto más grandes usan más VRAM (la caché KV escala con el contexto). Si estás alcanzando límites de memoria, reduce `params.num_ctx`. El `maxTokens` a nivel de proveedor controla el valor por defecto de tokens de salida.

### Mantener Modelos Cargados y Ejecutar Múltiples

El problema del "segundo mensaje lento" es casi siempre una carga en frío del modelo. Arréglalo con `keep_alive`:

```json
{
  "params": {
    "keep_alive": "15m"
  }
}
```

Esto mantiene el modelo en memoria durante 15 minutos después de la última petición. La variable de entorno global `OLLAMA_KEEP_ALIVE` sigue funcionando como valor por defecto.

Para ejecutar múltiples modelos simultáneamente (por ejemplo, un modelo de programación y uno general), `OLLAMA_NUM_PARALLEL` controla la concurrencia. **El valor por defecto ahora es 1** (antes era más alto). El uso de RAM escala con `num_ctx × parallel`, así que auméntalo con cuidado:

```bash
OLLAMA_NUM_PARALLEL=2 ollama serve
```

En Apple Silicon con MLX (por defecto desde Ollama v0.40), las características de ajuste de memoria y velocidad pueden diferir de la ruta CUDA. Haz pruebas antes de fijar un número de procesos en paralelo.

### Capas de GPU

<Notice type="error" title="Corrección: Variable de Entorno Inexistente">
Una versión anterior de esta guía mostraba `OLLAMA_GPU_LAYERS=35 ollama serve`. Esa variable de entorno no existe y nunca existió. El mecanismo correcto es el parámetro por modelo `num_gpu`, que OpenClaw reenvía como `options.num_gpu` en `/api/chat`.
</Notice>

Para descargar un número específico de capas en GPU (por ejemplo, un modelo de 70B en 24GB de VRAM que no cabe por completo):

```json
{
  "models": {
    "providers": {
      "ollama": {
        "models": [
          {
            "id": "llama3.3:70b",
            "params": {
              "num_gpu": 35
            }
          }
        ]
      }
    }
  }
}
```

Más capas en GPU = más rápido pero más VRAM. Experimenta para encontrar tu punto ideal. Si dejas `num_gpu` sin establecer, Ollama decide automáticamente según la memoria disponible.

## Solución de Problemas

<Accordion label="Problemas Comunes" group="troubleshooting" expanded="true">

**El modelo no aparece en `openclaw models list`**

El descubrimiento automático de OpenClaw solo muestra modelos que están cargados en memoria (`/api/ps`), tienen soporte de herramientas y reportan ≥16K de contexto. Si un modelo está descargado pero no aparece en la lista, ejecútalo una vez para cargarlo en memoria o configúralo explícitamente en `models.providers.ollama`. Compruébalo con:
```bash
curl http://localhost:11434/api/ps
ollama list
```

**Las respuestas son extremadamente lentas**

Tu modelo probablemente se está ejecutando en CPU. Comprueba si el modelo cabe en tu VRAM/RAM disponible. Soluciones:
- Cambia a un modelo más pequeño (`qwen3.5:9b` en lugar de `qwen3.5:27b`)
- En Mac: cierra otras aplicaciones para liberar memoria unificada
- En Linux con GPU: comprueba `nvidia-smi` para ver el uso de VRAM

**Errores de "Connection refused"**

Ollama no está ejecutándose. Inícialo:
```bash
ollama serve
```
O en macOS, abre la aplicación Ollama. Verifica que la API es accesible:
```bash
curl http://localhost:11434/api/tags
```

**Las tool calls fallan o son ignoradas**

Puede que el modelo no soporte bien el tool calling. Cambia a un modelo conocido por manejar bien las herramientas: `gemma4`, `qwen3.5`, `gpt-oss` o `Nanbeige4.2-3B`. Evita modelos más antiguos como `llama2`, `codellama` o `qwen2.5-coder` para OpenClaw.

**Crashes por falta de memoria**

El modelo es demasiado grande. Opciones:
- Descarga una cuantización más pequeña: `ollama pull qwen3.5:9b-q4_0`
- Cambia a un modelo más pequeño
- Añade más RAM/swap (no es ideal pero funciona)

**Nanbeige4.2-3B no encontrado**

Es una subida comunitaria, no está en la biblioteca oficial. Descárgalo con el namespace:
```bash
ollama pull ndavat/Nanbeige4.2-3B
```

</Accordion>

<Accordion label="Nuevos Problemas en 2026" group="troubleshooting-2026" expanded="false">

**Bucle de reinicios en WSL2 al arrancar**

Síntoma: Windows se reinicia o se congela cuando WSL2 arranca con Ollama.
Causa: `ollama.service` usa `Restart=always` + carga de modelo CUDA durante el arranque → fijado de memoria → Windows mata la VM de WSL2 → bucle de reinicios ([ollama/ollama#11317](https://github.com/ollama/ollama/issues/11317)).
Solución: deshabilita el inicio automático y limita la memoria:
```bash
sudo systemctl disable ollama
```
En `%USERPROFILE%\.wslconfig`:
```ini
[experimental]
autoMemoryReclaim=disabled
```
Luego ejecuta `wsl --shutdown` y reinicia.

**El modelo emite JSON de tool-call en bruto como texto plano**

Síntoma: las respuestas contienen etiquetas XML como `<tool_call>` o `Action: ...` en lugar de tool calls estructuradas.
Causa: el modelo no maneja bien los esquemas de herramientas, o estás usando el endpoint `/v1` compatible con OpenAI en lugar de la API nativa de Ollama.
Solución: OpenClaw reintenta automáticamente una llamada nativa cuando detecta texto de tool-call en bruto. Para modelos pequeños que fallan de forma consistente, establece `"compat": { "supportsTools": false }` en la entrada del modelo. Y revisa tu `baseUrl`: sin sufijo `/v1`.

**El primer mensaje agota el tiempo de espera en un modelo en frío**

Síntoma: `openclaw agent` se queda colgado o da error en la primera petición, pero funciona después.
Causa: cargar en frío un modelo grande supera el presupuesto de tiempo de espera por defecto.
Solución: añade `timeoutSeconds: 300` a la configuración del proveedor (consulta el Ejemplo de Configuración Completa arriba).

**Modelo descargado pero no aparece en el descubrimiento automático**

Síntoma: `openclaw models list --provider ollama` no muestra tu modelo.
Causa: el descubrimiento automático solo considera modelos cargados en memoria con soporte de herramientas y ≥16K de contexto.
Solución: ejecuta `ollama run <modelo>` una vez para cargarlo, o configúralo explícitamente en `models.providers.ollama.models[]`.

</Accordion>

## Consideraciones de Seguridad

Ejecutar modelos localmente es inherentemente más privado que las llamadas a API, pero no te saltes lo básico:

- **Ollama no tiene autenticación**: cualquiera en tu red que pueda alcanzar el puerto 11434 puede usar tus modelos. Vincúlalo a localhost o usa un firewall. El marcador `ollama-local` significa que no se envía ninguna credencial a hosts locales. No lo reutilices para endpoints públicos.
- **Descargas de modelos**: Ollama descarga modelos desde ollama.com. Si te preocupa la seguridad, verifica los checksums de los modelos o usa instalaciones aisladas (airgapped).
- **Seguridad de OpenClaw**: los modelos locales no cambian el modelo de amenazas de OpenClaw. Sigue aplicando la [guía de seguridad de OpenClaw](/es/guia-seguridad-openclaw/) para el enlace del gateway, el modo sandbox y la revisión de skills.

<Accordion label="Preguntas Frecuentes" group="faq" expanded="true">

**¿Puedo ejecutar OpenClaw completamente offline con Ollama?**

Sí, una vez que los modelos estén descargados y OpenClaw esté instalado. No se necesita internet para la inferencia. No tendrás búsqueda web ni integraciones de canales (Telegram, WhatsApp), pero la CLI y las sesiones locales funcionan perfectamente.

**¿Qué modelo ofrece la mejor calidad por vatio (o por euro)?**

En un Mac Mini de 32GB, `qwen3.5:27b` ofrece los mejores resultados para su consumo eléctrico. En un VPS económico, `gemma4:12b` es el punto ideal. Con 8GB de RAM, `Nanbeige4.2-3B` es el mejor equilibrio entre velocidad y capacidad. Si quieres calidad sin ningún coste de hardware, el nivel gratuito de Ollama Cloud te da modelos de nivel API con tarifas de pago por uso.

**¿Cómo se compara Nanbeige4.2-3B con modelos de API como GLM-5.3?**

GLM-5.3 y Kimi-K3 siguen siendo mejores para tareas complejas de múltiples pasos. Nanbeige4.2-3B es competitivo en benchmarks (supera a modelos mucho más grandes en tareas de agente y programación), pero el uso real de OpenClaw implica contextos largos y conversaciones de múltiples turnos donde los modelos más grandes tienen ventaja. Usa Nanbeige para tareas rápidas y mensajes, y modelos de API para lo pesado.

**¿Puedo usar Ollama y proveedores de API al mismo tiempo?**

Sí, y lo recomiendo. Configura un modelo de Ollama como principal y un modelo de API económico como fallback. OpenClaw gestiona el cambio automáticamente. Ollama Cloud es el camino más sencillo para esto. Mismo proveedor, mismo daemon, solo un sufijo `:cloud` en el modelo de fallback.

**¿Funciona el tool calling con todos los modelos de Ollama?**

No. El descubrimiento automático de OpenClaw solo muestra modelos que reportan soporte de herramientas y están cargados en memoria. Los modelos más antiguos y algunos más pequeños no lo soportan. Los modelos listados en esta guía todos soportan tool calling (verifica Nanbeige4.2 por separado, consulta la advertencia arriba). Compruébalo con `ollama show <modelo>` y busca `tools` en las capacidades.

**¿Qué hay de ejecutar Ollama en una Raspberry Pi?**

Una Raspberry Pi 5 con 8GB de RAM puede ejecutar modelos de 1B-3B. `Nanbeige4.2-3B` o `qwen3.5:2b` son tus mejores opciones. Las respuestas serán lentas (del orden de 2-5 tokens/segundo), pero funcionales para tareas simples. No esperes que maneje preguntas de programación.

**¿Es vLLM mejor que Ollama para OpenClaw?**

vLLM ofrece mejor throughput en configuraciones multi-GPU y cargas de trabajo en producción. Ollama es más sencillo de configurar y mejor para escenarios de un solo usuario. Para una instancia personal de OpenClaw, Ollama es la elección correcta. Si estás ejecutando múltiples agentes o necesitas inferencia concurrente, considera vLLM.

**¿Cuánta RAM necesito realmente para el modelo X?**

Fórmula aproximada: parámetros del modelo × 0.6GB para cuantización Q4. Así que un modelo de 9B necesita ~5.4GB, uno de 12B necesita ~7.2GB, uno de 27B necesita ~16.2GB. Añade 2-4GB de margen para el sistema y la sobrecarga de Ollama. Estos son mínimos. Más RAM significa ventanas de contexto más grandes.

**¿Qué es Ollama Cloud y lo necesito?**

Ollama Cloud es el nivel de inferencia alojada de Ollama. No lo necesitas para uso puramente local. Pero si quieres desbordamiento económico cuando tu modelo local llega a sus límites, es la opción más limpia. Mismas herramientas, misma API, solo modelos `:cloud` en tu cadena de fallbacks. El nivel Free ($0, pago por uso) es suficiente para uso ocasional.

**¿Qué es el modo agente propio de la CLI `ollama`?**

Desde Ollama v0.32, el comando `ollama` a secas lanza un agente interactivo, y `ollama launch openclaw` inicia OpenClaw a través de las propias herramientas de Ollama. Es una puerta de entrada paralela, no un reemplazo de esta guía. Los consejos de configuración y selección de modelos aquí aplican en ambos casos.

</Accordion>

La configuración híbrida (local como principal + nube como fallback) significa privacidad y coste cero la mayor parte del tiempo, con calidad de API cuando realmente la necesitas.

Empieza con lo que se ajuste a tu hardware. Mac Mini → `qwen3.5:27b`. Presupuesto de 8GB → `Nanbeige4.2-3B`. ¿Quieres desbordamiento sin configuración? → prueba el nivel gratuito de Ollama Cloud.
