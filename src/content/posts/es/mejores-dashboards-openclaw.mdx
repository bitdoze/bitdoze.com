## Empieza aquí: la Control UI oficial de OpenClaw

Antes de instalar cualquier cosa de terceros, ten en cuenta que OpenClaw incluye tres interfaces: la CLI, una TUI y la **Control UI**, un dashboard web servido por el gateway en el puerto 18789. Si estás en una versión reciente, ya tienes un dashboard. Sin instalación, sin proceso extra, sin capa de autenticación separada.

Lánzala con:

```bash
openclaw dashboard                      # abre http://localhost:18789
```

### Qué cubre la Control UI

La Control UI es una aplicación de una sola página hecha con Vite + Solid que el gateway sirve en el mismo puerto. Cubre la mayoría de las necesidades del día a día de una configuración de un solo agente.

<ListCheck>
<ul>
<li>**Chat y sesiones**: Habla con tu agente, explora el historial de sesiones, mira qué se está ejecutando</li>
<li>**Página de uso**: Medidores de contexto y desgloses de tokens por sesión</li>
<li>**Actividad de herramientas**: Símbolos que muestran qué herramientas llamó el agente y cuándo</li>
<li>**Catálogo de UIs de plugins**: Descubre y configura interfaces de plugins y MCP Apps</li>
<li>**Editor de configuración**: Inspecciona y edita tu configuración de OpenClaw desde el navegador</li>
</ul>
</ListCheck>

Dos ajustes de configuración importan para los operadores:

```bash
# opcional: gateway.controlUi.enabled: false   # se aplica en caliente, deshabilita solo la UI
# opcional: gateway.controlUi.basePath: "/openclaw"
```

Establecer `OPENCLAW_CONFIG_READONLY=1` muestra un banner limpio de solo lectura en lugar de una configuración editable, lo cual es útil si quieres el dashboard visible pero los cambios de configuración bloqueados. Puedes personalizar el texto del banner con `OPENCLAW_CONFIG_READONLY_NOTICE`.

**Verifica que funciona**: ejecuta `openclaw dashboard`, abre la página de uso y confirma que el recuento de sesiones coincide con lo que reporta la CLI `openclaw`. **Modo de fallo:** el dashboard no carga → el gateway no está en ejecución, `gateway.controlUi.enabled` está en `false`, o estás en una versión antigua de OpenClaw anterior a la Control UI.

<Notice type="warning" title="No Expongas el 18789 Públicamente">
La Control UI es servida por el gateway, lo que significa que el puerto 18789 transporta tanto la API como la UI web. Nunca lo expongas directamente a internet. Protégelo detrás de Tailscale, un túnel SSH o un proxy inverso con autenticación. Más sobre esto en la [sección de seguridad](#cómo-securizar-cualquier-dashboard-de-openclaw) más abajo.
</Notice>

### Cuándo necesitas un dashboard de terceros

La Control UI cubre sesiones, chat, medidores de uso y configuración. No te da analítica de costos con límites de presupuesto, pipelines de orquestación de tareas basados en kanban, cuadrículas de widgets de arrastrar y soltar, editores de alma/identidad, vistas de flota multi-máquina ni monitores estilo terminal. Si algo de eso te importa, los proyectos de la comunidad de abajo cubren los huecos. Si no, la Control UI más la CLI probablemente es todo lo que necesitas.

## Autensa (Mission Control): el mejor para pipelines de tareas autónomas

<Button text="Repositorio GitHub" link="https://github.com/crshdn/mission-control" variant="solid" color="blue" size="md" />

Mission Control cambió de nombre a **Autensa** y se convirtió en algo más ambicioso que un tablero kanban. Ahora es un «Autonomous Product Engine» (v2.5.1, 2026-04-29) con un pipeline que ejecuta Investigación → Ideación → Aprobación por swipe → Desarrollo → Pruebas → Revisión → Pull Request. El antiguo kanban de siete etapas ya no existe. Esto es un flujo completo de desarrollo de producto con planificación de IA en cada paso.

Cinco cosas lo distinguen de todo lo demás de esta lista:

<ListCheck>
<ul>
<li>**Product Autopilot**: La investigación de mercado programada produce ideas de funciones puntuadas; las apruebas con un swipe y los agentes recogen el trabajo</li>
<li>**Convoy Mode**: Ejecuta de 3 a 5 agentes en paralelo con un grafo de dependencias DAG, detección de atascos/zombis, auto-empujones y puntos de recuperación ante fallos</li>
<li>**Seguimiento de costos por tarea con límites de presupuesto**: Mira exactamente cuánto gastó cada tarea, establece límites estrictos antes de que los agentes se descontrolen</li>
<li>**Chat de operador**: Envía notas y mensajes a mitad de desarrollo a los agentes sin romper su contexto</li>
<li>**Almacenamiento SQLite, despacho por WebSocket**: Sin base de datos externa; las tareas se despachan a los agentes en tiempo real a través del gateway</li>
</ul>
</ListCheck>

Hay una [demo en vivo](https://missioncontrol.ghray.com) si quieres curiosear antes de instalar.

```bash
git clone https://github.com/crshdn/mission-control.git
cd mission-control
npm install
cp .env.example .env.local
# Establece OPENCLAW_GATEWAY_URL y OPENCLAW_GATEWAY_TOKEN en .env.local
# Obtén el token: openclaw config get gateway.auth.token
npm run dev
```

Abre `http://localhost:4000`.

**Verifica**: crea una tarea de prueba y confirma que genera una sesión de agente que aparece en el feed de eventos en vivo. **Modo de fallo:** `OPENCLAW_GATEWAY_TOKEN` ausente o inválido → la conexión WebSocket falla y las tareas se encolan sin despacharse.

<Notice type="warning" title="Colisión de Nombres">
Buscar «OpenClaw mission control» lleva a un repositorio archivado de 4.100 estrellas (`abhi1693/openclaw-mission-control`) que ya no se mantiene. El proyecto activo es `crshdn/mission-control` (Autensa). Consulta la [sección de advertencia](#advertencia-algunos-resultados-de-openclaw-mission-control-están-archivados) para más detalles.
</Notice>

**Nota de costos**: Autopilot y Convoy Mode generan agentes según horarios. Eso es gasto real de tokens incluso en reposo. Habilita los límites de presupuesto desde el primer día y considera combinarlo con un [modelo más barato](/es/mejores-modelos-opensource-openclaw/) una vez que conozcas el flujo de trabajo.

## OpenClaw Studio: el mejor dashboard web limpio

<Button text="Repositorio GitHub" link="https://github.com/grp06/openclaw-studio" variant="solid" color="green" size="md" />

OpenClaw Studio es una UI web limpia, casi oficial (2.033 ⭐), con chat, aprobaciones, configuración de trabajos/cron y una vista general de agentes. Se conecta al gateway por WebSocket y su documentación es la mejor fuente sobre las tres topologías de despliegue reales que te vas a encontrar.

```bash
npx -y openclaw-studio@latest           # requiere Node 20.9+
# Abre http://localhost:3000, se conecta a ws://localhost:18789
```

**Verifica**: abre `http://localhost:3000`, confirma que el indicador de estado del gateway muestra conectado y envía un mensaje de chat de prueba. **Modo de fallo:** Node < 20.9 (npx se niega a ejecutar), error tipográfico en la URL upstream (`ws://` vs `wss://` cuando hay TLS en el camino), o Tailscale no está corriendo en el host del gateway.

Las tres topologías:

<Tabs>
<Tab name="Local / Local">

Tanto el gateway como Studio en la misma máquina. Es la configuración por defecto y la más simple. Studio se conecta a `ws://localhost:18789` y todo queda en una sola máquina. Sin red extra.

</Tab>
<Tab name="Gateway en la Nube + Studio Local">

El gateway corre en un VPS; Studio corre en tu portátil. Expón el gateway a través de Tailscale en el lado del servidor:

```bash
# en el host del gateway
tailscale serve --yes --bg --https 443 http://127.0.0.1:18789
```

Luego apunta el upstream de Studio a `wss://<gateway-host>.ts.net` en lugar de `ws://localhost:18789`. Si quieres [autoalojar tu servidor de control de Tailscale con Headscale](/es/headscale-tailscale-autoalojado/), el patrón es idéntico.

</Tab>
<Tab name="Nube / Nube">

Tanto el gateway como Studio en un VPS. Igual que local/local pero detrás de Tailscale o un proxy inverso para el acceso remoto. Studio debe alcanzar el gateway por `ws://` (plano) en el mismo host o `wss://` sobre TLS. Mezclar los dos es el error de configuración más común.

</Tab>
</Tabs>

Para la comparación completa de topologías con los detalles de `wss://`, la documentación del proyecto merece la lectura. Si estás decidiendo entre opciones de VPN de malla, consulta la [comparativa de Tailscale vs Headscale vs NetBird](/es/netbird-vs-headscale-vs-tailscale/).

## AI Maestro: el mejor centro de comando de OpenClaw para flotas multi-máquina

<Button text="Repositorio GitHub" link="https://github.com/23blocks-OS/ai-maestro" variant="solid" color="purple" size="md" />

AI Maestro nació como solución para ejecutar 35 agentes en múltiples terminales y tener que retransmitir el contexto entre ellos a mano. Ha crecido hasta convertirse en un sistema operativo multiagente completo (v0.106.29, 839 ⭐, muy activo, último push 2026-10-30) construido alrededor de una malla de pares donde las máquinas se unen como nodos iguales y cada agente es visible desde un único dashboard.

<ListCheck>
<ul>
<li>**Malla multi-máquina**: Sin servidor central; las máquinas se conectan como pares y las nuevas computadoras se unen automáticamente</li>
<li>**Protocolo de Mensajería de Agentes (AMP)**: Los agentes se coordinan directamente con niveles de prioridad y firmas criptográficas</li>
<li>**Tarjetas de aprobación**: Revisa y aprueba las acciones de los agentes desde el dashboard antes de que se ejecuten</li>
<li>**Tablero Matrix**: Vista de prioridades estilo Eisenhower para la gestión de tareas en toda la flota</li>
<li>**Tarjetas de Secretos enmascarados**: Los agentes usan credenciales por nombre sin ver jamás los valores reales</li>
<li>**Funciona con cualquier agente**: Soporte completo para Claude Code, Codex y Grok Build; solo lanzamiento para Pi, OpenClaw y GitHub Copilot CLI</li>
</ul>
</ListCheck>

```bash
curl -fsSL https://raw.githubusercontent.com/23blocks-OS/ai-maestro/main/scripts/remote-install.sh | sh
```

El dashboard se abre en `http://localhost:23000`. Requiere Node.js 18+ y tmux.

**Verifica**: tras la instalación, confirma que una segunda máquina puede unirse a la malla y que ambas aparecen en la vista de flota. **Modo de fallo:** tmux ausente en un VPS nuevo (`apt install tmux` o `dnf install tmux` primero); curl-pipe-to-sh bloqueado por un proxy corporativo: descarga el script manualmente e inspecciónalo.

**Nota de costos**: la coordinación de agentes a escala de flota quema tokens incluso en reposo, y el uso escala con el tamaño de la flota. Combina AI Maestro con un dashboard de seguimiento de costos y considera [suscripciones de modelos baratos vía OpenCode Go vs ClinePass](/es/opencode-go-vs-clinepass-modelos-baratos/) para mantener la factura a raya. Las páginas adaptadas a móvil también significan que puedes [controlar agentes de IA desde tu teléfono](/es/controlar-agentes-ia-desde-telefono-moshi-herdr/) cuando estás lejos del escritorio.

**Cuándo usarlo**: Si estás ejecutando 10+ agentes y necesitas que se coordinen sin que tú actúes de intermediario. Excesivo para una configuración de un solo agente.

## OpenClaw Agent Dashboard: el mejor monitor con seguridad reforzada

<Button text="Repositorio GitHub" link="https://github.com/tugcantopaloglu/openclaw-dashboard" variant="solid" color="blue" size="md" />

Este proyecto saltó de 60 a 700 estrellas en ocho meses. Es el dashboard más consciente de la seguridad de la lista: hash de contraseñas PBKDF2 (100.000 iteraciones), MFA TOTP opcional (compatible con Google Authenticator, Authy, 1Password), limitación de tasa, HSTS, cabeceras CSP, protección contra traversal de rutas y un registro de auditoría completo, todo con cero dependencias externas. Node.js puro, sin base de datos, sin framework.

Más allá de la seguridad, la lista de funciones ha crecido desde principios de 2026: gestión de sesiones, análisis de costos, monitoreo de límites de tasa, visor de archivos de memoria (MEMORY.md, HEARTBEAT.md, notas diarias), gestión de trabajos cron, integración con Tailscale y un feed en vivo de mensajes de agentes. Las novedades incluyen un gestor de archivos, control de servicios, visor de logs, un mapa de calor de actividad de 30 días con rachas y atajos de teclado.

<ListCheck>
<ul>
<li>**MFA TOTP**: Autenticación de dos factores opcional, se habilita desde Configuración → Seguridad</li>
<li>**Cero dependencias**: Node.js puro sin paquetes npm requeridos</li>
<li>**Análisis de costos**: Desglose de gastos por modelo, sesión y período de tiempo</li>
<li>**Visor de memoria**: Navega por MEMORY.md, HEARTBEAT.md y notas de memoria diarias</li>
<li>**Gestión de cron**: Ver, habilitar/deshabilitar y activar manualmente trabajos programados</li>
<li>**Gestor de archivos y visor de logs**: Explora archivos del workspace y logs del gateway desde la UI</li>
</ul>
</ListCheck>

```bash
git clone https://github.com/tugcantopaloglu/openclaw-dashboard.git
cd openclaw-dashboard
node server.js
```

Visita `http://localhost:7000` y registra una cuenta en el primer inicio.

<Notice type="info" title="Configuración de Seguridad">
La primera vez que lo ejecutas, se imprime un token de recuperación en la consola. Guárdalo. Lo necesitarás si olvidas tu contraseña. Para habilitar MFA, ve a Configuración → Seguridad → Habilitar MFA después de iniciar sesión. El modelo de autenticación completo se describe en la [guía de seguridad de OpenClaw](/es/guia-seguridad-openclaw/).
</Notice>

**Verifica**: regístrate, guarda el token de recuperación y comprueba que el análisis de costos muestra el gasto del día actual y que la lista de cron coincide con tus trabajos programados. **Modo de fallo:** olvidaste guardar el token de recuperación → es tu única vía de restablecer la contraseña; el puerto 7000 ya está en uso → cambia el puerto o mata el proceso en conflicto.

## LobsterBoard: el mejor constructor de dashboards de arrastrar y soltar

<Button text="Repositorio GitHub" link="https://github.com/Curbob/LobsterBoard" variant="solid" color="green" size="md" />

LobsterBoard adopta un enfoque diferente a todo lo demás en esta lista. En lugar de un diseño fijo, es un constructor de dashboards con arrastrar y soltar con más de 60 widgets. Estadísticas del sistema, clima, feeds RSS, cotizaciones de acciones, seguimiento de costos de la API de Claude, monitores de sesión activa, sensores de hogar inteligente. Elige lo que importa y organízalo como quieras. Cinco temas de fábrica: Default, Terminal CRT, Paper, Feminine y Feminine Dark.

Se ejecuta como un único servidor Node.js sin framework y sin paso de compilación. La configuración se guarda en un único archivo JSON. Todo corre en local, sin dependencia de la nube.

<ListCheck>
<ul>
<li>**Más de 60 widgets**: Monitoreo del sistema, seguimiento de costos de IA, hogar inteligente, finanzas, medios y más</li>
<li>**5 temas**: Incluidos un modo Terminal CRT y un tema Paper</li>
<li>**Monitoreo de servidores remotos**: Instala `lobsterboard-agent` en otros VPS para traer sus estadísticas a tu cuadrícula</li>
<li>**Galería de plantillas**: Exporta tu diseño, importa los de otros, comparte configuraciones</li>
<li>**Páginas personalizadas**: Añade páginas completas más allá de la cuadrícula de widgets: notas, tableros kanban, lo que quieras</li>
<li>**Widgets de OpenClaw**: Estado de autenticación, estado de trabajos cron, monitor de sesión activa, indicador de tokens (opcional; también funciona de forma independiente)</li>

cd node_modules/lobsterboard
node server.cjs
# Para monitoreo de hosts remotos:

Abre `http://localhost:8080`, presiona **Ctrl+E** para el modo de edición, arrastra widgets desde la barra lateral, guarda.

**Verifica**: tras arrancar, Ctrl+E → arrastra un widget → guarda → recarga la página y confirma que el diseño persiste. **Modo de fallo:** ejecutar `node server.cjs` desde el directorio equivocado (debes hacer `cd` a `node_modules/lobsterboard` primero); agente instalado en un host remoto pero sin widgets → comprueba que el agente está en ejecución y es alcanzable.

## Claw Dashboard: el mejor monitor estilo terminal

<Button text="Repositorio GitHub" link="https://github.com/spleck/claw-dashboard" variant="solid" color="green" size="md" />

Si vives en la terminal y quieres algo que parezca btop o htop en lugar de una aplicación web, Claw Dashboard es el indicado. Logo en ASCII art, colores degradados, gráficos de donut, barras de progreso, todo renderizado con la biblioteca `blessed` y actualizado cada dos segundos. Muestra el uso de CPU por núcleo, indicadores de memoria, estadísticas de GPU (solo Apple Silicon), procesos principales y sesiones activas de OpenClaw.

El proyecto está activo (último push 2026-10-26, npm 2.2.0) y ha ganado funciones de calidad de vida: una paleta de comandos (`Ctrl+K`), reordenación de widgets (`w`), fijado (`Alt+1-9`), instantáneas y programación de exportaciones.

```bash
npx claw-dashboard                      # de un solo uso, sin instalación global
# o: npm install -g claw-dashboard && clawdash
```

Controles de teclado: `q` para salir, `r` para actualizar, `s` para configuración, `Ctrl+K` para la paleta de comandos.

**Verifica**: `clawdash` se renderiza y la lista de sesiones coincide con el gateway. **Modo de fallo:** Node < 22 es un requisito estricto. Es el fallo de instalación más probable en imágenes de VPS antiguas. Compruébalo con `node --version`. Las estadísticas de GPU solo aparecen en Apple Silicon; en Linux tendrás CPU/memoria/procesos pero sin indicador de GPU. Para flujos de trabajo por SSH donde prefieres una sesión de terminal persistente, la guía de [mejores multiplexores de terminal](/es/mejores-multiplexores-terminal/) cubre alternativas a tmux y Zellij.

**Ideal para**: Monitoreo rápido sin abrir un navegador. Funciona muy bien en un [Mac Mini](/es/mejor-mac-mini-openclaw/) donde de todas formas estás conectado por SSH.

## VidClaw: tablero de tareas y editor de alma

<Button text="Repositorio GitHub" link="https://github.com/madrzak/vidclaw" variant="solid" color="purple" size="md" />

VidClaw se centra en lo que tu agente está trabajando en lugar de la infraestructura que lo rodea. Tiene un tablero Kanban donde las tareas se asignan a skills de OpenClaw, un editor de alma para SOUL.md, IDENTITY.md y USER.md con plantillas de persona e historial de versiones, y seguimiento de uso analizado directamente desde los transcript de sesión. El cambio de modelo desde el dashboard se recarga en caliente vía un observador de configuración.

El modelo de seguridad es el más simple de la lista: se vincula solo a localhost. Accedes a través de un túnel SSH. SSH es la capa de autenticación.

```bash
cd ~/.openclaw/workspace
git clone https://github.com/madrzak/vidclaw.git dashboard
cd dashboard
./setup.sh
```

Accede a través de un túnel SSH: `ssh -L 3333:localhost:3333 root@tu-servidor`, luego abre `http://localhost:3333`. La [guía de seguridad de OpenClaw](/es/guia-seguridad-openclaw/) cubre el patrón del túnel con más detalle.

**Verifica**: abre la URL del túnel y confirma que los números de uso derivados de los transcript coinciden con una sesión conocida. **Modo de fallo:** ejecutar el setup desde el directorio equivocado: debe estar bajo `~/.openclaw/workspace`.

VidClaw está estancado desde marzo de 2026 (último push 2026-03-18). Además **no tiene archivo de licencia**. Se aplica el copyright por defecto, lo que técnicamente significa que no hay derechos de reutilización. Para uso personal autoalojado esto rara vez importa en la práctica, pero conviene saber en qué te metes. El kanban y el editor de alma funcionan bien tal cual; solo no esperes actualizaciones.

## ¿Necesitas siquiera un dashboard de terceros?

Para la mayoría de las configuraciones de un solo agente: no. La Control UI de `openclaw dashboard` más la CLI `openclaw` y la TUI oficial cubren sesiones, chat, uso, configuración y monitoreo básico. Eso es aproximadamente el 80% de lo que la gente consulta.

Los dashboards de terceros se ganan su lugar en huecos específicos: analítica de costos con límites de presupuesto, pipelines de orquestación de tareas (kanban → PR), cuadrículas de widgets de arrastrar y soltar, editores de alma/identidad, vistas de flota multi-máquina y monitores estilo terminal. Si no encajas en ninguno de esos, prueba la UI oficial gratuita una semana antes de instalar nada.

## Cómo securizar cualquier dashboard de OpenClaw

Todos los dashboards de esta página se conectan a lo mismo: tu gateway de OpenClaw. Si el gateway o el puerto del dashboard está expuesto a internet, has entregado tu agente. Aquí está el panorama consolidado.

**Qué dashboards tienen autenticación:**

- OpenClaw Agent Dashboard tiene MFA TOTP con hash de contraseñas PBKDF2, limitación de tasa y registro de auditoría.
- Autensa (Mission Control) tiene autenticación por token Bearer, validación con Zod y protección contra traversal de rutas.
- Clawd Control genera una contraseña en el primer arranque.
- VidClaw se vincula solo a localhost, así que el túnel SSH es la autenticación.
- La Control UI es autorizada por el gateway en cada petición y respeta `OPENCLAW_CONFIG_READONLY=1`.
- Asume que cualquiera no listado no tiene ninguna. El viejo Clawtrol no tenía autenticación en absoluto.

**El patrón estándar para todos ellos:**

<Notice type="warning" title="Nunca Expongas Estos Puertos">
Nunca expongas estos puertos directamente a internet público: **3000, 3100, 3333, 4000, 4781, 7000, 7001, 8080, 18789**. Vincúlalos a localhost y alcanza el dashboard a través de un túnel SSH o `tailscale serve`. Si prefieres un proxy inverso, la guía de [configuración de panel con SSH, Caddy, Docker y seguridad](/es/guia-panel-hermes/) cubre el mismo patrón para cualquier dashboard.
</Notice>

La topología que quieres:

```
  [ VPS ]                                [ Tu portátil / móvil ]
  ┌─────────────────────────┐            ┌──────────────────────┐
  │ OpenClaw Gateway :18789 │◄─malla────►│ Navegador / terminal │
  │   (Control UI)          │  VPN o     │                      │
  │ Dashboard :3000/:7000   │  túnel SSH │ ssh -L 7000:...      │
  │ Dashboard :8080/:23000  │            │ tailscale serve      │
  │ Todo ligado a 127.0.0.1 │            └──────────────────────┘
  └─────────────────────────┘
       ✗ Sin acceso directo a internet público
```

<ListCheck>
<ul>
<li>**Vincula a localhost**: no cambies el bind por defecto a 0.0.0.0 solo para «hacerlo funcionar en remoto»</li>
<li>**Túnel o VPN de malla**: túnel SSH o `tailscale serve` para el acceso; la [comparativa de Tailscale vs Headscale vs NetBird](/es/netbird-vs-headscale-vs-tailscale/) si necesitas elegir uno</li>
<li>**Autenticación activada**: MFA TOTP donde esté disponible; no confíes en que «nadie conoce el puerto»</li>
<li>**Token rotado**: `openclaw config get gateway.auth.token` para comprobarlo; rótalo si alguna vez se pegó en un chat o repositorio</li>
<li>**Host parcheado**: [securiza tu VPS con CrowdSec](/es/crowdsec-servidor-seguro/) y mantén la máquina actualizada; si quieres [autoalojar tu servidor de control de Tailscale con Headscale](/es/headscale-tailscale-autoalojado/), es un tercero menos en el camino</li>
</ul>
</ListCheck>

**Fallo común**: «funciona en mi portátil pero no en remoto». El bind es localhost, que es el comportamiento correcto. Usa un túnel; no cambies el bind. Y si pruebas con un bind público temporalmente, cierra inmediatamente la regla del firewall después.

## Combina tu dashboard con la configuración correcta

Un dashboard solo es tan útil como lo que está monitoreando. Hay algunas cosas que vale la pena resolver antes de instalar uno.

Si estás controlando costos, un modelo eficiente importa más que la UI del dashboard. La guía de [mejores modelos open source para OpenClaw](/es/mejores-modelos-opensource-openclaw/) cubre [GLM-5](https://go.bitdoze.com/glm) y [MiniMax M2.5](https://go.bitdoze.com/minimax), que juntos cuestan una fracción de la API de Claude. La mayoría de los dashboards hacen obvia la diferencia de costos una vez que cambias. Para la parte de la API, [suscripciones de modelos baratos vía OpenCode Go vs ClinePass](/es/opencode-go-vs-clinepass-modelos-baratos/) muestra cómo mantener las facturas de tokens bajas entre herramientas.

Antes de instalar cualquier dashboard que se conecte a tu gateway, asegúrate de que tu instancia está protegida. La [guía de seguridad de OpenClaw](/es/guia-seguridad-openclaw/) cubre CVE-2026-25253, el ataque a la cadena de suministro de ClawHub y procedimientos de endurecimiento paso a paso.

Varios dashboards muestran llamadas de herramientas activas en tiempo real, lo que hace que valga la pena configurar la integración de búsqueda. La [guía de búsqueda DuckDuckGo para OpenClaw](/es/busqueda-duckduckgo-openclaw/) explica cómo añadir búsqueda web gratuita sin clave de API.

Si estás evaluando dashboards como parte de decidir qué plataforma de agente usar, el resumen de [alternativas a OpenClaw](/es/alternativas-openclaw/) cubre NanoClaw, IronClaw, NullClaw y otros que traen sus propios enfoques de dashboard. Para el enfoque basado en contenedores de NanoClaw, consulta la [guía de despliegue de NanoClaw](/es/guia-despliegue-nanoclaw/). Para la huella más pequeña posible con un binario Zig, consulta la [guía de despliegue de NullClaw](/es/guia-despliegue-nullclaw/).

Si aún no has instalado OpenClaw, la [guía de configuración de OpenClaw](/es/guia-configuracion-openclaw/) cubre la instalación completa en un [VPS de Hetzner Cloud](https://go.bitdoze.com/hetzner) o Mac Mini, incluyendo el token de gateway que la mayoría de estos dashboards necesitan. Con presupuesto ajustado, un [VPS KVM de Hostinger](https://go.bitdoze.com/hostinger-vps) ejecuta el nivel de dashboard sin problemas. Los agentes son el costo, no la UI. ¿Todavía eligiendo el hardware? Consulta la guía del [mejor Mac mini para OpenClaw](/es/mejor-mac-mini-openclaw/).

Para dar a tus agentes de OpenClaw memoria persistente entre sesiones, [Hindsight](/es/desplegar-hindsight-docker/) tiene una integración directa con control de acceso en el servidor y embeddings autogestionados. Es un paso por encima de la memoria básica basada en archivos con la que vienen la mayoría de los agentes.

<Notice type="info" title="Nota de Costos">
Los dashboards que generan agentes (el Autopilot de Autensa, la coordinación de flota de AI Maestro) queman tokens incluso en reposo. Establece límites de presupuesto antes de habilitar los modos autónomos. Para modelos locales que no cuestan nada por token, consulta [ejecutar OpenClaw con Ollama](/es/openclaw-ollama-modelos-locales/).
</Notice>

<Accordion label="Preguntas Frecuentes" group="faq" expanded="true">

**¿Hay algún dashboard oficial de OpenClaw?**

Sí. La Control UI (`openclaw dashboard`, puerto 18789) y la TUI son ambas oficiales. Vienen con el propio OpenClaw. Todo lo demás de esta lista está construido por la comunidad. Las interfaces oficiales son el punto de partida adecuado para la mayoría de la gente.

**¿OpenClaw Mission Control sigue mantenido?**

El de crshdn sí. Cambió de nombre a **Autensa** y se desarrolla activamente (v2.5.1, 2.155 ⭐). Pero el `abhi1693/openclaw-mission-control` de 4.100 estrellas está **archivado** (agosto de 2026), y el desarrollo se movió a Wardn AI, un producto diferente. Si buscas «OpenClaw mission control» y llegas al repositorio archivado, no lo instales.

**¿Cuál es el mejor dashboard de OpenClaw para seguimiento de costos?**

OpenClaw Agent Dashboard tiene análisis de costos integrado con desgloses por modelo, sesión y período de tiempo. Autensa va más lejos con seguimiento de costos por tarea y límites de presupuesto. Si los costos son tu preocupación principal, el dashboard importa menos que el modelo. Consulta los [mejores modelos open source para OpenClaw](/es/mejores-modelos-opensource-openclaw/).

**¿Puedo ejecutar dos dashboards a la vez?**

Sí. Una combinación común es Autensa para la creación de tareas junto con Claw Dashboard para verificaciones rápidas del sistema. Leen diferentes partes del gateway de OpenClaw de forma independiente. La Control UI puede quedarse activa junto a cualquiera de ellos sin conflictos. Solo mantén todo detrás del mismo túnel o VPN de malla.

**¿Es LobsterBoard gratuito para uso comercial?**

No. Business Source License 1.1 (la licencia del README; el campo de GitHub dice «Other») permite el autoalojamiento personal y no comercial. Los despliegues comerciales necesitan una licencia separada del autor. Ten en cuenta que varios proyectos de esta lista no son MIT: Clawe es AGPL-3.0 y VidClaw no tiene licencia en absoluto.

**¿Qué dashboard debería probar primero?**

La Control UI. Ya está instalada. Si necesitas análisis de costos o monitoreo de cron, añade OpenClaw Agent Dashboard después. Para orquestación de tareas y flujos de trabajo autónomos, Autensa. Para flotas multi-máquina, AI Maestro. En ese orden.

**¿Cuál funciona en un Mac Mini?**

Claw Dashboard es la mejor opción de terminal. Incluso muestra estadísticas de GPU en Apple Silicon. La Control UI sobre Tailscale funciona para el acceso web. Para el nicho de pantalla remota que Clawtrol solía cubrir, mira openclaw-nerve (verifica su README primero) o simplemente usa VNC sobre Tailscale. Los detalles de hardware están en la guía del [mejor Mac mini para OpenClaw](/es/mejor-mac-mini-openclaw/). Si prefieres ejecutar una máquina x86 como el [mini PC ASUS DC510](https://go.bitdoze.com/asus-dc510) en lugar de un Mac Mini, las opciones de dashboard son las mismas menos las estadísticas de GPU de Apple Silicon.

</Accordion>

La Control UI oficial cambió la pregunta por defecto de «¿qué dashboard?» a «¿necesito algo más que el integrado?». Para la mayoría de las configuraciones de un solo agente, la respuesta es no. Pero una vez que los costos necesitan límites de presupuesto, las tareas necesitan pipelines de orquestación o los agentes se reparten entre máquinas, las herramientas de la comunidad se ganan su lugar. Empieza con lo que se adapte a tu escala; la mayoría funcionan juntos sin conflictos.
