## ¿Qué es PicoClaw?

PicoClaw es un asistente de IA de código abierto de Sipeed, la empresa de hardware RISC-V detrás de NanoKVM y MaixCAM. Compila a un único binario Go para x86_64, ARM64, ARMv6/7, RISC-V, MIPS, LoongArch y s390x, además de una build para Android. Sin Python, sin Node, sin runtime que instalar. El objetivo de diseño es la propia placa LicheeRV-Nano de $10 de Sipeed, así que cualquier cosa con 128MB de RAM es lujosa en comparación.

El flujo de mensajes tiene la misma forma que nanobot: los mensajes llegan desde una app de chat, el gateway los enruta al LLM que hayas configurado, y el modelo puede llamar a herramientas integradas para ejecutar comandos shell, leer y escribir archivos, buscar en la web y gestionar memoria. Todo excepto las llamadas a la API del LLM se queda en tu máquina.

![Arquitectura de PicoClaw: más de 18 canales de entrada, un único gateway Go en tu hardware, más de 30 proveedores LLM y herramientas locales](@assets/images/26/02/picoclaw-architecture.svg)

La línea v0.3.x añadió la superficie que importa para 2026: un lanzador WebUI en el navegador, soporte MCP nativo, skills instalables desde ClawHub, fallbacks por modelo y rotación de claves, y un APK de Android que no necesita Termux. El núcleo sigue siendo el mismo binario único.

### PicoClaw vs OpenClaw vs NanoBot vs ZeroClaw

Cuatro asistentes autoalojados, cuatro apuestas diferentes. Los números de abajo son los declarados por los proyectos (cifras del README, finales de 2026), no un benchmark que yo haya ejecutado.

| Aspecto | PicoClaw | NanoBot | ZeroClaw | OpenClaw |
|--------|----------|---------|----------|----------|
| Lenguaje | Go | Python | Rust | TypeScript |
| RAM | 10-20MB\* | ~100MB | < 5MB | > 1GB |
| Arranque (núcleo único débil) | < 1s | > 30s | < 10ms | > 500s |
| Binario | Binario Go único | N/A (scripts) | Binario Rust de ~3.4MB | ~28MB (dist) |
| Costo mínimo de hardware | Placa de $10 | SBC de ~$50 | SBC de ~$10-50 | Mac Mini de $599 |
| Canales | 18+ | 9 | ~8 | 4 |
| Proveedores | 30+ | 13+ | 22+ | Varios |
| Memoria | Workspace basado en archivos | Basada en archivos | Búsqueda híbrida SQLite | Archivo + semántica |
| Seguridad | Sandbox de workspace | Listas de permitidos | Emparejamiento + sandbox | Listas de permitidos + sandbox |
| Instalación | tarball / .deb / Docker | pip | cargo / binario | npm / toolchain de Node |

\* Las builds recientes de PicoClaw usan 10-20MB en lugar de la cifra original por debajo de 10MB. La optimización está planeada para después de la estabilización de funciones. Sigue siendo diminuto.

Conclusiones de la comparación: PicoClaw es el más barato de desplegar, nanobot tiene la comunidad más grande y la mejor cobertura de canales, ZeroClaw tiene el sistema de memoria más potente (ahora se posiciona como un "runtime de agentes" en v0.8.6 con plugins WASM y OIDC), y OpenClaw es el peso pesado que ejecutas cuando quieres la experiencia completa de agente de escritorio y puedes pagar [lo que OpenClaw necesita para funcionar bien](/es/mejor-mac-mini-openclaw/). Para los demás, consulta la [guía de configuración de nanobot](/es/guia-configuracion-nanobot/) y la [guía de configuración de ZeroClaw](/es/guia-configuracion-zeroclaw/). Si quieres la ruta original de OpenClaw, también hay una [guía de configuración de OpenClaw](/es/guia-configuracion-openclaw/).

## Modelos PicoClaw a finales de 2026: GLM-5.3 + un modelo Flash

La combinación de modelos que yo usaría por defecto para un bot personal siempre activo: un modelo de nivel Flash para el tráfico diario y un flagship como fallback para tareas difíciles. La entrada de nivel Flash cuesta unos $0.15 por millón de tokens, así que un bot que responde unas docenas de mensajes al día se mantiene en un solo dígito de dólares al mes. Cuando el modelo barato se atasca, `fallbacks` deriva en cascada a GLM-5.3 o MiniMax M3. Esa cadena es donde se ahorra el dinero. Los precios en vivo se mueven rápido, así que revisa nuestros [precios actuales de GLM-5.3 y MiniMax M3.1-Flash](/es/mejores-modelos-opensource-openclaw/) antes de comprometerte.

<Notice type="error" title="¿Migrando una configuración de febrero?">
MiniMax M2.5 y M2.7 se cerraron a nuevos usuarios el 2026-10-19 y dejan de funcionar por completo el **2026-11-18**. GLM-5 y los ejemplos de configuración con `glm-4.7` quedan reemplazados por GLM-5.3 (publicado el 2026-08-18). Si tu `config.json` todavía dice `MiniMax-M2.5` o `glm-4.7`, migra ahora: cambia las entradas al formato `model_list` de esta guía y ejecuta `picoclaw migrate` si estás en una versión antigua de la configuración. Un ID de modelo muerto en un bot 24/7 es una caída silenciosa hasta que notas que nadie responde.
</Notice>

<Notice type="info" title="Los planes y tipos de clave de Z.AI cambiaron">
Los Coding Plans de Z.AI funcionan por puntos (desde $18/mes; las horas valle incluyendo fines de semana consumen el 50% de la cuota; GLM-5.3-Flash consume un tercio). Desde el 2026-10-16, las claves del plan de codificación y las claves de API estándar se facturan por separado. Usar una clave de plan en el endpoint de API estándar (o al revés) falla con un error de autenticación que parece una clave mala. Usa el prefijo de proveedor `zai-coding` de PicoClaw para las claves de plan y `zhipu` para las claves estándar.
</Notice>

### GLM-5.3 y GLM-5.3-Flash (Z.AI)

GLM-5.3 es el flagship, GLM-5.3-Flash es el modelo de volumen. Ambos tienen una ventana de contexto de 1M de tokens, lo que significa que un bot de Discord parlanchín no alcanzará los límites de contexto en mucho tiempo.

| Especificación | GLM-5.3 | GLM-5.3-Flash |
|------|---------|---------------|
| Precio (entrada/salida por M) | $1.40 / $4.40 | $0.15 / $0.50 |
| Ventana de contexto | 1M tokens | 1M tokens |
| Arquitectura | MoE clase 744B | MoE 320B, 18B activos |
| Benchmarks | DeepSWE v1.1 66.9%, TB3.0 28.3 | multimodal (preview) |

Una trampa: GLM-5.3 rechaza las llamadas con `thinking.type: "disabled"`. Si configuras controles de thinking a través de `extra_body`, no intentes desactivar el thinking a la fuerza en este modelo.

Endpoints: API general en `https://api.z.ai/api/paas/v4`, API del plan de codificación en `https://api.z.ai/api/coding/paas/v4`, compatible con Anthropic en `https://api.z.ai/api/anthropic`. ### MiniMax M3.1-Flash y MiniMax M3

MiniMax retiró la generación M2.x y la reemplazó con la línea M3. Para un bot siempre activo, M3.1-Flash es la opción barata y M3 es el fallback para tareas difíciles.

| Especificación | MiniMax M3.1-Flash | MiniMax M3 |

## Cómo instalar PicoClaw (v0.3.1)

Así se instala PicoClaw en menos de cinco minutos. v0.3.1 publica tarballs, paquetes `.deb`/`.rpm`, zips, un bundle de Android y un archivo `picoclaw_<version>_checksums.txt`. Los antiguos nombres de archivo sueltos `picoclaw-linux-amd64` de las primeras guías ya no existen en la página de releases. Cada comando de abajo usa el patrón `releases/latest/download/`, así que seguirá funcionando en la próxima versión.

Lo que necesitas antes de empezar:

<li>Opcionalmente una cuenta de Discord o Telegram para el canal de chat</li>

### Instalar desde el tarball precompilado

La ruta por defecto. Para Linux x86_64:

```bash
wget https://github.com/sipeed/picoclaw/releases/latest/download/picoclaw_Linux_x86_64.tar.gz
tar xzf picoclaw_Linux_x86_64.tar.gz
sudo mv picoclaw /usr/local/bin/
```

Para ARM64 (Raspberry Pi 4/5, la mayoría de SBC modernos, Termux):

```bash
wget https://github.com/sipeed/picoclaw/releases/latest/download/picoclaw_Linux_arm64.tar.gz
tar xzf picoclaw_Linux_arm64.tar.gz
sudo mv picoclaw /usr/local/bin/
```

Otras arquitecturas usan el mismo patrón: `picoclaw_Linux_armv7.tar.gz`, `picoclaw_Linux_riscv64.tar.gz`, `picoclaw_Linux_mipsle.tar.gz`, `picoclaw_Linux_loong64.tar.gz`, `picoclaw_Linux_s390x.tar.gz`. Si `uname -m` imprime algo que no coincide con el nombre del asset, descargaste el archivo equivocado.

Opcionalmente verifica el checksum. Cada release publica un archivo `picoclaw_<version>_checksums.txt`. A diferencia de los tarballs, ese nombre de archivo incluye la versión, así que toma el actual de la [página de releases](https://github.com/sipeed/picoclaw/releases) en lugar de fijarlo para siempre:

```bash
# example for v0.3.1, use the checksums filename from the release you downloaded
wget https://github.com/sipeed/picoclaw/releases/latest/download/picoclaw_0.3.1_checksums.txt
sha256sum picoclaw_Linux_x86_64.tar.gz
# compare against the matching line in the checksums file
```

Luego inicializa y comprueba:

```bash
picoclaw version
picoclaw onboard
picoclaw status
```

`picoclaw version` debería imprimir `0.3.1` (o más reciente). `picoclaw onboard` crea `~/.picoclaw/` con un `config.json` por defecto y un directorio `workspace/`. Si `picoclaw` no se encuentra tras la instalación, `/usr/local/bin` no está en tu PATH u olvidaste el `sudo mv`.

### Instalar con .deb o .rpm

v0.3.1 publica paquetes nativos para x86_64, aarch64, armv6/armv7, riscv64, loong64 y s390x. Descarga el correcto desde [picoclaw.io/download](https://picoclaw.io/download) o la página de releases, luego:

```bash
# Debian / Ubuntu
sudo dpkg -i picoclaw_*_amd64.deb

# RHEL / Fedora / Alma
sudo rpm -i picoclaw-*.x86_64.rpm
```

Verifica con `picoclaw version`, luego ejecuta `picoclaw onboard`. Las instalaciones por paquete ponen el binario en el PATH por ti.

### Lanzador WebUI de PicoClaw

Si prefieres no editar JSON a mano primero, v0.3.x incluye `picoclaw-launcher`, una UI en el navegador para configuración y chat:

```bash
picoclaw-launcher
# opens http://localhost:18800
```

Desde una máquina remota, Docker o una VM, añade `-public` y accede a través de tu propio túnel o proxy inverso. En macOS, Gatekeeper bloquea binarios sin firmar: haz clic derecho en el launcher en Finder, elige **Abrir**, luego **Abrir de todos modos**. Los binarios no están notarizados. Ese es el modo de fallo, no malware.

<Notice type="warning" title="Token de la WebUI">
El token del dashboard es aleatorio en cada reinicio a menos que definas `PICOCLAW_LAUNCHER_TOKEN` en el entorno. Un token aleatorio significa que tus marcadores se rompen tras un reinicio. Peor aún, exponer el puerto 18800 públicamente sin un token fijo significa que cualquiera que adivine o registre el token obtiene tu configuración, incluidas las rutas a tus claves de API. Define el token y mantén el 18800 detrás de un proxy inverso o un túnel SSH. Nunca lo redirijas sin más a internet.
</Notice>

### Compilar desde el código fuente (Go 1.25+)

El requisito de Go subió de 1.21 a 1.25 en la rama main actual. Si estás desarrollando o quieres una build personalizada:

```bash
git clone https://github.com/sipeed/picoclaw.git
cd picoclaw
make deps
make build
make install        # build + install to /usr/local/bin
```

Objetivos útiles del Makefile: `make build-all` (compilación cruzada), `make build-launcher` (WebUI), `make build-pi-zero` (Pi Zero 2W, 32 y 64 bits), `make build-android-bundle`. Verifica con `picoclaw version`.

### Ejecutar PicoClaw con Docker

Dos detalles cambiaron desde las primeras guías: el archivo compose se movió a `docker/docker-compose.yml` (así que cada comando necesita la flag `-f`) y el workspace es un bind mount `./data:/root/.picoclaw`, no un volumen con nombre. Tu configuración y memoria quedan en `docker/data/` en el host, lo que hace las copias de seguridad triviales.

```bash
git clone https://github.com/sipeed/picoclaw.git
cd picoclaw

# First run generates docker/data/config.json and exits.
# Edit it, then start the gateway:
docker compose -f docker/docker-compose.yml --profile gateway up -d

# Watch startup
docker compose -f docker/docker-compose.yml logs -f picoclaw-gateway

# One-shot query without the gateway
docker compose -f docker/docker-compose.yml run --rm picoclaw-agent -m "What is 2+2?"
```

El nuevo perfil `launcher` ejecuta la WebUI en el puerto 18800 con el gateway en 18790 y `PICOCLAW_GATEWAY_HOST=0.0.0.0` definido dentro del contenedor:

```bash
docker compose -f docker/docker-compose.yml --profile launcher up -d
# http://localhost:18800
```

Las imágenes son `docker.io/sipeed/picoclaw:latest` y `docker.io/sipeed/picoclaw:launcher`. Para confirmar el despliegue, `logs -f picoclaw-gateway` debería mostrar un arranque limpio y la llamada puntual `picoclaw-agent -m` debería devolver una respuesta. Si el gateway no es accesible desde fuera del contenedor, ese es el problema de bind del host cubierto en Solución de problemas.

Recompila tras las actualizaciones de versión y desmonta limpiamente cuando termines:

```bash
docker compose -f docker/docker-compose.yml --profile gateway build --no-cache
docker compose -f docker/docker-compose.yml --profile gateway up -d

# teardown
docker compose -f docker/docker-compose.yml --profile gateway down
```

### APK de Android y Termux

Desde el 2026-03-31 hay una build real de Android: `picoclaw-android-universal.zip` en la página de releases contiene un APK. No se necesita Termux.

Si prefieres Termux de todos modos (por ejemplo, quieres un espacio de usuario Linux compartido), usa el tarball arm64 y proot:

```bash
wget https://github.com/sipeed/picoclaw/releases/latest/download/picoclaw_Linux_arm64.tar.gz
tar xzf picoclaw_Linux_arm64.tar.gz
pkg install proot
termux-chroot ./picoclaw onboard
```

Verifica con `picoclaw version` dentro de Termux o en la pantalla de información del APK. Raspberry Pi y otros SBC usan el mismo tarball arm64 de la sección de instalación anterior.

**Comandos que usarás**

| Comando | Qué hace |
|---------|-------------|
| `picoclaw onboard` | Inicializar configuración y workspace |
| `picoclaw version` | Mostrar la versión instalada |
| `picoclaw status` | Mostrar el estado actual |
| `picoclaw agent -m "..."` | Enviar un solo mensaje |

| `picoclaw gateway` | Iniciar el gateway (canales de chat) |

| `picoclaw migrate` | Migrar un formato de configuración antiguo |

En modo interactivo, escribe `exit`, `quit` o presiona `Ctrl+D` para salir.

## Configuración de PicoClaw: model_list y channel_list (esquema v3)

Dos hechos rompen cada snippet de configuración escrito antes de mediados de 2026:

1. La configuración `"version": 3` usa **`model_list`** y **`channel_list`**. Los antiguos bloques `providers` y `channels` son legado.
2. Las claves de API y los tokens de canal ya no viven en `config.json`. Van a `~/.picoclaw/.security.yml`.

Aquí hay una configuración v3 completa con un flagship GLM-5.3, un fallback Flash, Discord, búsqueda web, heartbeat y el bloque gateway:

```json
{
  "version": 3,
  "agents": {
    "defaults": {
      "workspace": "~/.picoclaw/workspace",
      "model_name": "glm53",
      "max_tokens": 8192,
      "temperature": 0.7,
      "max_tool_iterations": 20,
      "context_window": 131072,
      "summarize_message_threshold": 20,
      "summarize_token_percent": 75,
      "max_llm_retries": 2,
      "llm_retry_backoff_secs": 2,
      "restrict_to_workspace": true
    }
  },
  "model_list": [
    {
      "model_name": "glm53",
      "provider": "zhipu",
      "model": "glm-5.3",
      "api_keys": ["YOUR_ZAI_API_KEY"],
      "api_base": "https://api.z.ai/api/paas/v4",
      "fallbacks": ["flash"]
    },
    {
      "model_name": "flash",
      "provider": "zhipu",
      "model": "glm-5.3-flash",
      "api_keys": ["YOUR_ZAI_API_KEY"],
      "api_base": "https://api.z.ai/api/paas/v4"
    }
  ],
  "channel_list": {
    "discord": {
      "enabled": true,
      "type": "discord",
      "allow_from": ["YOUR_USER_ID"],
      "settings": { "token": "YOUR_DISCORD_BOT_TOKEN" }
    }
  },
  "tools": {
    "web": {
      "provider": "auto",
      "duckduckgo": { "enabled": true, "max_results": 5 },
```

### model_list: modelos, claves API y fallbacks

`model_list` es donde vive cada modelo. Los campos que importan:

- `model_name` es **tu alias**. `agents.defaults.model_name` lo referencia. No es el ID de modelo del proveedor.
- `model` es el **ID nativo** que el proveedor espera (`glm-5.3`, `z-ai/glm-5.3`, `MiniMax-M3.1-Flash`).
- `api_keys` es un **array**. PicoClaw rota las claves por petición. Una entrada basta; varias reparten los límites de tasa.
- `provider` fija el prefijo de proveedor. Omítelo y el primer segmento de `model` antes de `/` infiere el proveedor.
- `fallbacks` lista otros alias de `model_name` a probar cuando este falla.
- Entradas duplicadas de `model_name` se convierten en balanceo de carga entre las entradas.

Opciones opcionales por modelo: `thinking_level` (`off|low|medium|high|xhigh|adaptive`), `streaming.enabled` (opt-in por modelo y canal), `rpm` (límite de tasa), `api_base`, `proxy`, `extra_body`, `custom_headers`, `tool_schema_transform`, `enabled`.

La configuración recomendada (flagship con un fallback Flash):

```json
{
  "agents": { "defaults": { "model_name": "glm53" } },
  "model_list": [
    {
      "model_name": "glm53",
      "provider": "zhipu",
      "model": "glm-5.3",
      "api_keys": ["YOUR_KEY"],
      "api_base": "https://api.z.ai/api/paas/v4",
      "fallbacks": ["flash"]
    },
    {
      "model_name": "flash",
      "provider": "zhipu",
      "model": "glm-5.3-flash",
      "api_keys": ["YOUR_KEY"],
      "api_base": "https://api.z.ai/api/paas/v4"
    }
  ]
}
```

### channel_list: Discord, Telegram y más de 18 canales

Cada canal es una entrada en `channel_list` con un `type`, una lista `allow_from` y un objeto `settings` que contiene el token:

```json
"channel_list": {
  "discord": {
    "enabled": true,
    "type": "discord",
    "allow_from": ["YOUR_USER_ID"],
    "settings": { "token": "YOUR_DISCORD_BOT_TOKEN" }
  }
}
```

Campos por canal: `enabled`, `type`, `allow_from`, `group_trigger.mention_only` (los bots responden en grupos solo cuando se les menciona), `reasoning_channel_id` y `settings`. La lista: Telegram, Discord, WhatsApp (QR o bridge), Weixin (QR), QQ, Slack (Socket Mode), Matrix, Delta Chat, DingTalk, Feishu/Lark, LINE, WeCom, VK, IRC, OneBot, MQTT, MaixCam, Pico, Pico Client.

Los canales tipo webhook (LINE y amigos) comparten un único servidor HTTP en `gateway.host:gateway.port`, por defecto `127.0.0.1:18790`. Feishu usa WebSocket en su lugar. Si ejecutas canales webhook, necesitas un proxy inverso delante del 18790, cubierto en la sección de VPS. Un bot callado tras la configuración suele significar intents, `allow_from` o permisos (Solución de problemas abajo).

### Secretos en .security.yml

En la migración o el onboard, los valores sensibles salen de `config.json` hacia `~/.picoclaw/.security.yml`. Esas son las claves de API y los tokens de canal.

<Notice type="warning" title="Respalda .security.yml">
Los backups antiguos se restauran sin secretos. Si tu tarea de backup es anterior a la separación de `.security.yml`, una restauración te devuelve una configuración sin claves y un bot que no puede alcanzar ningún modelo. Respalda estos tres juntos:
<ListCheck>
<ul>
<li>`~/.picoclaw/workspace/` (memoria, sesiones, cron, skills)</li>
<li>`~/.picoclaw/config.json`</li>
<li>`~/.picoclaw/.security.yml` (chmod 600, solo el propietario)</li>
</ul>
</ListCheck>
</Notice>

Incluye el archivo en cualquier tarea de backup que ya ejecutes (Rclone a S3, restic, un tarball por cron). Mantén permisos estrictos: `chmod 600 ~/.picoclaw/.security.yml`. Si una clave se filtra, rótala en el proveedor y vuelve a ejecutar `picoclaw onboard` o edita el archivo.

### Migrar una configuración antigua con `picoclaw migrate`

Movimiento defensivo para quien arrastra una configuración desde febrero:

- Las configuraciones de versión 0 (el formato original `providers`/`channels`) se migran automáticamente en la primera ejecución.
- Las versiones 1 y 2 necesitan una ejecución manual:

```bash
picoclaw migrate
picoclaw status
```

Tras la migración, comprueba tres cosas: `"version": 3` al principio de `config.json`, `model_list`/`channel_list` presentes, y tus claves en `.security.yml`. Si faltan secretos, vuelve a introducirlos con `picoclaw onboard` o la WebUI.

## Configuración de Discord en PicoClaw

Discord es el canal más común para bots personales. Los pasos son los mismos que en la guía de v0.1; lo que cambió es la forma de la configuración.

### Crear un bot de Discord

1. Ve a [discord.com/developers/applications](https://discord.com/developers/applications)
2. Haz clic en **New Application**, dale un nombre
3. Ve a **Bot** en la barra lateral izquierda, haz clic en **Add Bot**
4. Copia el token del bot

### Habilitar intents

Todavía en la página de configuración del Bot:

1. Baja hasta **Privileged Gateway Intents**
2. Habilita **MESSAGE CONTENT INTENT** (obligatorio)
3. Opcionalmente habilita **SERVER MEMBERS INTENT** si vas a usar listas de permitidos por miembro

<Notice type="warning" title="MESSAGE CONTENT INTENT">
Sin este intent el bot se conecta, se queda en línea y no lee nada. Es la causa más común de "mi bot está callado". Habilítalo antes de depurar cualquier otra cosa.
</Notice>

### Obtener tu ID de usuario

1. Configuración de Discord → **Avanzado** → habilita **Modo desarrollador**
2. Haz clic derecho en tu avatar en cualquier parte
3. Haz clic en **Copiar ID de usuario**

### Configurar PicoClaw

Añade la entrada de Discord a `channel_list` en `~/.picoclaw/config.json`:

```json
"channel_list": {
  "discord": {
    "enabled": true,
    "type": "discord",
    "allow_from": ["YOUR_USER_ID"],
    "settings": { "token": "YOUR_DISCORD_BOT_TOKEN" }
  }
}
```

Bloquea `allow_from` a tu ID de usuario para un bot personal. Una lista vacía permite que cualquiera en el servidor maneje tu agente, lo que incluye manejar su herramienta shell. No lo hagas.

### Invitar el bot a tu servidor

1. En el portal de desarrolladores: **OAuth2** → **URL Generator**
2. Scopes: marca `bot`
3. Bot Permissions: `Send Messages` y `Read Message History`
4. Abre la URL generada y elige tu servidor

### Iniciar el gateway

```bash
picoclaw gateway
```

Envía un mensaje en Discord. El bot debería responder en unos segundos. Si no: `picoclaw status`, luego los logs del gateway (`journalctl -u picoclaw -f` bajo systemd, `docker compose -f docker/docker-compose.yml logs -f picoclaw-gateway` en Docker). Arreglos habituales: el intent está desactivado, tu ID de usuario no está en `allow_from`, o el bot no tiene permiso de Send Messages en ese canal.

## Búsqueda web: Brave, DuckDuckGo y SearXNG

PicoClaw ahora soporta unos diez motores de búsqueda. La antigua configuración de dos motores (Brave + DuckDuckGo) sigue funcionando, pero el cambio interesante es que dos de las mejores opciones no necesitan clave de API en absoluto.

<ListCheck>
<ul>
<li>DuckDuckGo, Sogou (habilitado en la configuración de ejemplo), SearXNG autoalojado y GLM Search (con un modelo de Z.AI) funcionan sin clave de API.</li>
<li>Brave da 2,000 consultas/mes gratis con clave, Tavily da 1,000/mes y Baidu da 1,500/mes.</li>
<li>Kagi, Perplexity y Gemini Google Search grounding son de pago.</li>
</ul>
</ListCheck>

| Motor | ¿Clave necesaria? | Nivel gratis | Notas |
|--------|-----------|-----------|-------|
| DuckDuckGo | No | n/a | Funciona de inmediato |
| Sogou | No | n/a | Activado por defecto en la config de ejemplo |
| SearXNG | No | n/a | Autoalojado, sin límites, sin telemetría |
| GLM Search | Clave Z.AI | n/a | Grounding nativo para modelos GLM |
| Brave | Sí | 2,000/mes | Buena calidad de resultados |
| Tavily | Sí | 1,000/mes | Snippets orientados a agentes |
| Baidu | Sí | 1,500/mes | Fuerte para consultas en chino |
| Gemini grounding | Sí | n/a | Herramienta de búsqueda nativa de Gemini |
| Kagi | Sí | De pago | Alta calidad, sin rastreo |
| Perplexity | Sí | De pago | [API de Perplexity](https://go.bitdoze.com/perplexity) para resultados de motor de respuestas |

Configuración para un defecto sensato sin clave más Brave como mejora de calidad:

```json
"tools": {
  "web": {
    "provider": "auto",
    "prefer_native": true,
    "format": "plaintext",
    "duckduckgo": { "enabled": true, "max_results": 5 },
    "searxng": { "enabled": true, "api_base": "http://your-searxng:8080", "max_results": 5 },
    "brave": { "enabled": true, "api_keys": ["YOUR_BRAVE_KEY"], "max_results": 5 }
  }
}
```

`provider: auto` elige el mejor motor disponible; `prefer_native` usa la búsqueda integrada de un modelo cuando la tiene (Gemini grounding, GLM Search); `format: plaintext` mantiene los resultados baratos en tokens. Brave ahora acepta un array `api_keys` para rotación como `model_list`. Mantén DuckDuckGo habilitado como fallback cuando Brave llegue al límite de tasa. Para el endpoint de SearXNG, [autoaloja SearXNG con Docker](/es/searxng-busqueda-privada-autoalojada/) y apunta `api_base` a él. Esa combinación (SearXNG + DuckDuckGo) es un stack de búsqueda completamente gratuito.

## MCP, skills y evolución

Tres áreas de funciones llegaron después de v0.2 que cambian lo que PicoClaw puede hacer.

**MCP (Model Context Protocol)** es nativo desde v0.2.1. Hay un gestor por CLI:

```bash
picoclaw mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem /tmp
picoclaw mcp list
picoclaw mcp test filesystem
```

Los servidores se declaran bajo `tools.mcp.servers` en la configuración. Una salvedad: `picoclaw mcp` edita la configuración y ejecuta pruebas; no mantiene los servidores MCP en ejecución. Se lanzan por uso. Si eres nuevo en el protocolo, la [introducción a MCP para principiantes](/es/introduccion-mcp-principiantes/) explica qué te aportan los servidores.

**Skills** son paquetes de capacidades instalables:

```bash
picoclaw skills search flight-tracker
picoclaw skills install flight-tracker
picoclaw skills list
```

Los registros se configuran bajo `tools.skills.registries.clawhub` y `tools.skills.registries.github` (los campos antiguos `tools.skills.github.*` están obsoletos). ClawHub es el registro por defecto.

<Notice type="warning" title="Las skills de terceros son código">
Una skill puede dirigir el comportamiento del agente y el uso de herramientas. Trata las instalaciones de skills como instalaciones de paquetes: sabe de dónde vienen antes de ejecutarlas contra un workspace que contiene datos reales. Para los modos de fallo que esto crea en la práctica, consulta las notas de [endurecimiento de seguridad de agentes IA](/es/guia-seguridad-openclaw/) sobre skills maliciosas.
</Notice>

**Evolución** es la pieza de autoaprendizaje. El bloque de configuración `evolution` (por defecto: observar) registra los turnos completados y puede redactar o aplicar skills a partir de patrones de tareas recurrentes. Déjalo en modo observar hasta que confíes en los patrones que extrae.

Otras funciones de v0.3.x que conviene conocer:

<ListCheck>
<ul>
<li>Hooks: observar, interceptar o aprobar llamadas de herramientas, con una acción de respuesta</li>
<li>Steering: inyectar mensajes en un bucle en ejecución</li>
<li>Subagentes SubTurn con control de concurrencia</li>
<li>Lanzamiento de tareas asíncronas para trabajos largos</li>
<li>Pipeline de visión: imágenes base64 a modelos multimodales</li>
<li>Voz: transcripción Groq Whisper más respuestas `send_tts`</li>
<li>Streaming, opt-in por modelo y canal</li>
</ul>
</ListCheck>

## Memoria, archivos del workspace y heartbeat

Todo lo que el agente sabe de ti vive en `~/.picoclaw/workspace/`:

```
~/.picoclaw/workspace/
├── sessions/          # Conversation sessions and history
├── memory/            # Long-term memory (MEMORY.md)
├── state/             # Persistent state (last channel, etc.)
├── cron/              # Scheduled jobs database
├── skills/            # Installed skills
├── AGENT.md           # Agent behavior guide (was AGENTS.md)
├── HEARTBEAT.md       # Periodic task prompts
├── IDENTITY.md        # Agent identity
├── SOUL.md            # Agent personality
└── USER.md            # Your info and preferences
```

El renombrado de `AGENTS.md` a `AGENT.md` ocurrió en la plantilla del repositorio; los workspaces antiguos pueden seguir con el nombre viejo. `TOOLS.md` ya no forma parte de la plantilla, así que no construyas flujos de trabajo alrededor de él. Dile al bot que recuerde algo y lo escribe en `memory/MEMORY.md`. Las sesiones se almacenan por conversación.

```bash
nano ~/.picoclaw/workspace/USER.md
```

Pon el contexto que el bot debería tener siempre: proyectos, preferencias, trasfondo técnico. El mismo modelo que los [archivos de workspace de nanobot](/es/guia-configuracion-nanobot/). La recarga en caliente es ahora comportamiento oficial: las ediciones de `AGENT.md`, `SOUL.md`, `USER.md` y `MEMORY.md` se recogen vía mtime del archivo sin reiniciar el gateway. Edita el archivo, envía un mensaje, el nuevo contexto está en juego.

**Heartbeat** ejecuta `HEARTBEAT.md` en un temporizador (por defecto cada 30 minutos):

```markdown
# Periodic Tasks

- Check the weather forecast
- Search the web for AI news and summarize
```

```json
"heartbeat": {
  "enabled": true,
  "interval": 30
}
```

Las tareas largas generan un subagente no bloqueante que trabaja en segundo plano y responde a través de la herramienta `message`, así que el bucle de heartbeat nunca se atasca. Los trabajos puntuales y recurrentes funcionan desde el CLI:

```bash
picoclaw cron add --name "morning" --message "Good morning! What's in the news?" --cron "0 9 * * *"
picoclaw cron list
picoclaw cron disable morning
picoclaw cron remove morning
```

Los trabajos viven en `~/.picoclaw/workspace/cron/`. Verifica: `picoclaw cron list` muestra el trabajo, y editar `USER.md` cambia el comportamiento sin reiniciar.

## Sandbox de seguridad

PicoClaw ejecuta en sandbox por defecto. Con `restrict_to_workspace: true`, el agente solo puede tocar archivos y ejecutar comandos dentro del workspace.

| Herramienta | Función | Restricción |
|------|----------|-------------|
| `read_file` | Leer archivos | Solo workspace |
| `write_file` | Escribir archivos | Solo workspace |
| `list_dir` | Listar directorios | Solo workspace |
| `edit_file` | Editar archivos | Solo workspace |
| `append_file` | Añadir a archivos | Solo workspace |
| `exec` | Ejecutar comandos | Las rutas deben estar dentro del workspace |

La herencia del sandbox es la propiedad importante: el agente principal, los subagentes y las tareas de heartbeat comparten `restrict_to_workspace`, y la documentación afirma que no hay forma de eludir el límite a través de subagentes o trabajos programados. Documentación más antigua también listaba una lista de bloqueo de comandos peligrosos (`rm -rf`, `mkfs`, `dd`, escrituras directas a disco, `shutdown`, fork bombs) que se aplicaba incluso con las restricciones desactivadas. No he vuelto a verificar esa lista contra la documentación de v0.3.1, así que no trates una lista de bloqueo como tu frontera de seguridad. El sandbox es la frontera.

Para permitir que el agente alcance fuera del workspace:

```json
{
  "agents": {
    "defaults": {
      "restrict_to_workspace": false
    }
  }
}
```

<Notice type="warning" title="Riesgo de seguridad">
Desactivar la restricción de workspace permite al agente leer y escribir cualquier ruta que el usuario del proceso pueda. Combinado con una herramienta shell y un vector de inyección de prompts (una página web, un mensaje de Discord, una skill de terceros), eso es acceso completo a la máquina a nivel de usuario. Hazlo solo en entornos controlados donde confíes en cada entrada. Para el modelo de amenazas más amplio, incluyendo CVEs y skills maliciosas en esta clase de agentes, consulta el artículo de [endurecimiento de seguridad de agentes IA](/es/guia-seguridad-openclaw/).
</Notice>

Flujo en Ubuntu 24.04 limpio, usando la instalación por tarball:

```bash
ssh root@YOUR_SERVER_IP
apt update && apt upgrade -y

# dedicated non-root user
useradd -m -s /bin/bash picoclaw

# install binary
wget https://github.com/sipeed/picoclaw/releases/latest/download/picoclaw_Linux_x86_64.tar.gz
tar xzf picoclaw_Linux_x86_64.tar.gz
sudo mv picoclaw /usr/local/bin/

# initialize as the service user
sudo -u picoclaw -H picoclaw onboard
sudo -u picoclaw -H nano /home/picoclaw/.picoclaw/config.json
```

Antes de exponer nada, [asegura tu servidor SSH](/es/securizar-servidor-ssh-linux/): solo claves, sin autenticación por contraseña. Luego la unidad systemd endurecida en `/etc/systemd/system/picoclaw.service`:

```ini
[Unit]
Description=PicoClaw gateway
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=picoclaw
Environment=HOME=/home/picoclaw
Environment=PICOCLAW_LOG_LEVEL=warn
ExecStart=/usr/local/bin/picoclaw gateway
Restart=always
RestartSec=10
# optional hardening:
# ProtectSystem=strict
# ReadWritePaths=/home/picoclaw/.picoclaw

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now picoclaw
systemctl status picoclaw
journalctl -u picoclaw -f
```

Verifica: `systemctl status picoclaw` muestra `active (running)`, y `journalctl -u picoclaw -f` transmite el arranque del gateway sin errores.

Para canales webhook (LINE, estilo DingTalk), el gateway sirve HTTP en `127.0.0.1:18790` por defecto. Pon TLS delante:

![Topología del gateway de PicoClaw: proxy inverso con TLS delante de 127.0.0.1:18790 y la WebUI protegida por token en 18800](@assets/images/26/02/picoclaw-gateway-topology.svg)

Caddy, Traefik o Nginx terminan TLS y hacen proxy al 18790. Mantén el 18800 (WebUI) fuera de la interfaz pública o detrás del mismo proxy con `PICOCLAW_LAUNCHER_TOKEN` definido. El `log_level` del gateway (`debug|info|warn|error|fatal`, env `PICOCLAW_LOG_LEVEL`) es tu primer control de depuración; `debug` es verboso pero útil cuando un canal no conecta.

<ListCheck>
<ul>
<li>Ejecutar como usuario dedicado sin root con `User=` y `Environment=HOME=`</li>
<li>`chmod 600` en `.security.yml`</li>
<li>Solo claves SSH, autenticación por contraseña desactivada</li>
<li>Firewall: abrir solo 22 y 443; 18790/18800 se quedan en localhost</li>
<li>Backups cubriendo `workspace/`, `config.json` y `.security.yml`</li>
<li>`Restart=always` y un `PICOCLAW_LOG_LEVEL` sensato</li>
</ul>
</ListCheck>

**Backups y desmontaje.** Respalda `~/.picoclaw/workspace/`, `config.json` y `.security.yml` juntos (ver la sección de secretos). Para eliminar PicoClaw por completo:

```bash
systemctl disable --now picoclaw
sudo rm /etc/systemd/system/picoclaw.service /usr/local/bin/picoclaw
rm -rf /home/picoclaw/.picoclaw    # deletes memory and sessions. back up first.
```

El desmontaje en Docker es `docker compose -f docker/docker-compose.yml --profile gateway down`. El directorio `docker/data/` montado por bind sobrevive; bórralo manualmente si quieres empezar de cero.

### Raspberry Pi, Android y hardware de $10

Este es el hardware para el que PicoClaw fue diseñado. El [documento de compatibilidad de hardware](https://docs.picoclaw.io) cubre el rango desde placas RISC-V de $5 hasta Raspberry Pis y teléfonos Android.

- La **LicheeRV-Nano ($10)** es el objetivo de diseño: Ethernet o WiFi6, ejecuta la build RISC-V, sirve como asistente personal con margen.
- La **LicheeRV-Claw** está en AliExpress desde el 2026-05-11 como placa sucesora si quieres más E/S.
- La **NanoKVM ($30-50)** hace mantenimiento automatizado de servidores junto a la máquina que cuida.
- La **MaixCAM** cubre casos de uso de monitoreo inteligente con el pipeline de cámara.
- Cualquier **Raspberry Pi** con red ejecuta el tarball arm64. Incluso una Pi Zero 2W lo maneja con 10-20MB de RAM (`make build-pi-zero` si quieres compilar localmente). Esa es la respuesta a "¿funciona PicoClaw en una Raspberry Pi?": sí, trivialmente.
- Los **teléfonos Android** antiguos ejecutan el APK sin Termux. Termux + proot también funciona (sección de instalación anterior).

Para modelos locales junto a PicoClaw, [instalar Ollama con Docker](/es/ollama-docker-instalacion/) te da un endpoint compatible con OpenAI en la misma máquina, y apuntar PicoClaw a él es un cambio de una línea en `api_base`. Si quieres más margen que un SBC sin una torre completa, un mini PC compacto como el [ASUS DC510 mini PC](https://go.bitdoze.com/asus-dc510) sirve también como servidor doméstico. En costos: $10 una vez para la ruta SBC, ~$50 por una placa mejor, o €4-5/mes alquilado.

## Solución de problemas de PicoClaw

Siete modos de fallo con los que la gente se topa, cada uno con su arreglo.

<Accordion label="model ... not found in model_list" group="troubleshooting">

**Síntoma:** `picoclaw agent` falla con `model ... not found in model_list`, u OpenRouter devuelve "free is not a valid model ID".

**Causa:** `agents.defaults.model_name` no coincide con ningún alias `model_name` en `model_list`, o `model` contiene tu alias en lugar del ID nativo del proveedor.

**Solución:** Revisa primero la cadena de alias (`model_name: "glm53"` debe existir en `model_list`). Luego revisa el ID nativo. Para los modelos gratuitos de OpenRouter, define el proveedor explícitamente:

```json
{ "model_name": "or-free", "provider": "openrouter", "model": "free",
  "api_keys": ["sk-or-your-key"], "api_base": "https://openrouter.ai/api/v1" }
```

Sin `provider`, una `/` en `model` infiere el proveedor del primer segmento; en caso de duda, define `provider` explícitamente.

</Accordion>

<Accordion label="Restauraste un backup y las claves desaparecieron" group="troubleshooting">

**Síntoma:** Tras restaurar `config.json` desde un backup, todos los proveedores devuelven errores de autenticación.

**Causa:** Los secretos viven en `.security.yml` desde la separación de la config v3. Los backups hechos antes de eso, o los backups que solo incluyen `config.json`, se restauran sin claves.

**Solución:** Vuelve a introducir las claves con `picoclaw onboard` o la WebUI, luego `chmod 600 ~/.picoclaw/.security.yml` y añade el archivo a tu tarea de backup de ahora en adelante.

</Accordion>

<Accordion label="La config con MiniMax M2.5 falla después del 2026-11-18" group="troubleshooting">

**Síntoma:** Una configuración que funcionó todo el año de repente devuelve 404/model-not-found de MiniMax.

**Causa:** MiniMax M2.5 y M2.7 se retiraron el 2026-11-18. Cualquier entrada `model: "MiniMax-M2.5"` está muerta después de esa fecha.

**Solución:** Cambia a la línea M3 en `model_list`:

```json
{ "model_name": "flash", "provider": "minimax", "model": "MiniMax-M3.1-Flash",
  "api_keys": ["YOUR_MINIMAX_KEY"] }
```

Las configuraciones con GLM-5 / `glm-4.7` deberían pasar a `glm-5.3` de la misma forma. Ejecuta `picoclaw migrate` si la configuración sigue en una versión antigua.

</Accordion>

<Accordion label="Z.AI devuelve un error de autenticación de clave inválida" group="troubleshooting">

**Síntoma:** 401/403 de Z.AI con una clave que es definitivamente válida.

**Causa:** Desde el 2026-10-16, las claves del plan de codificación y las claves de API estándar se facturan por separado y son aceptadas por endpoints diferentes. Una clave de plan en la API general (o al revés) parece exactamente una clave mala.

**Solución:** Las claves del plan de codificación usan el prefijo `zai-coding` con `https://api.z.ai/api/coding/paas/v4`. Las claves estándar usan el prefijo `zhipu` con `https://api.z.ai/api/paas/v4`. Comprueba qué tipo de clave generaste antes de cambiar cualquier otra cosa.

</Accordion>

<Accordion label="El gateway de Docker no es accesible" group="troubleshooting">

**Síntoma:** `docker compose ... --profile gateway up -d` se ejecuta, pero nada puede alcanzar el gateway.

**Causa:** El gateway escucha en `127.0.0.1:18790` dentro del contenedor por defecto. Además, los comandos deben referenciar `docker/docker-compose.yml` y el bind mount del workspace es `./data`.

**Solución:** Define `PICOCLAW_GATEWAY_HOST=0.0.0.0` en el entorno del contenedor, y pasa siempre `-f docker/docker-compose.yml`. Confirma que tu configuración quedó en `docker/data/config.json` (la primera ejecución la genera y sale). Verifica con `docker compose -f docker/docker-compose.yml logs -f picoclaw-gateway`.

</Accordion>

<Accordion label="macOS bloquea el launcher" group="troubleshooting">

**Síntoma:** "picoclaw-launcher cannot be opened because the developer cannot be verified."

**Causa:** Los binarios no están notarizados. Gatekeeper bloquea descargas sin firmar.

**Solución:** Clic derecho en el binario en Finder → **Abrir** → **Abrir de todos modos** en Ajustes del Sistema → Privacidad y Seguridad. Es el comportamiento esperado, no una señal de manipulación; verifica el checksum si quieres certeza.

</Accordion>

<Accordion label="El bot de Discord está en línea pero callado" group="troubleshooting">

**Síntoma:** El bot aparece en línea en Discord pero nunca responde.

**Causa:** Tres candidatos, en orden de frecuencia: MESSAGE CONTENT INTENT desactivado, tu ID de usuario ausente de `allow_from`, o el bot no tiene permiso de Send Messages en ese canal.

**Solución:** Habilita el intent en el portal de desarrolladores (Bot → Privileged Gateway Intents). Comprueba que `allow_from` contiene el ID exacto que copiaste (Modo desarrollador → clic derecho → Copiar ID de usuario). Repite la invitación OAuth2 con `Send Messages` y `Read Message History` marcados. Reinicia con `picoclaw gateway` y observa los logs mientras envías un mensaje de prueba.

</Accordion>

<Notice type="info" title="¿Sigues atascado?">
Ejecuta `picoclaw status`, luego `journalctl -u picoclaw -f` (o los logs de Docker). Define `PICOCLAW_LOG_LEVEL=debug` para verbosidad completa. El proyecto tenía 31 issues abiertas a fecha de 2026-10-30; revisa las [issues de GitHub](https://github.com/sipeed/picoclaw/issues) antes de asumir que eres el único.
</Notice>

**Desmontaje limpio / rollback.** Para deshacer todo: `systemctl disable --now picoclaw`, `docker compose -f docker/docker-compose.yml --profile gateway down`, `sudo rm /usr/local/bin/picoclaw`, y `rm -rf ~/.picoclaw`. Ese último borra memoria y sesiones, así que respalda primero `workspace/`, `config.json` y `.security.yml` si algo de eso importa.

## Preguntas frecuentes

<Accordion label="¿Cuánto cuesta ejecutar PicoClaw?" group="faq" expanded="true">

El software es gratis. Los costos son la API del modelo y la máquina.

Con modelos de nivel Flash: GLM-5.3-Flash y MiniMax M3.1-Flash cuestan $0.15/M de entrada y $0.50-0.60/M de salida. Un bot personal que responde unas docenas de mensajes al día queda en unos pocos dólares al mes, menos con aciertos de caché (las lecturas de caché de M3.1-Flash son $0.015/M). Las llamadas de fallback al flagship cuestan más ($1.40/M de entrada para GLM-5.3), pero la cadena de fallback solo se activa en preguntas difíciles.

Las viejas cuentas de "MiniMax M2.5 Lightning a ~$1/hora de uso continuo" murieron con el modelo. No presupuestes con ellas.

Para la máquina: ~€4-5/mes por un VPS como el Hetzner CX22, o $10 una vez si lo ejecutas en un SBC. Niveles gratuitos para empezar: OpenRouter 200K tokens/mes, Zhipu 200K/mes, Brave 2,000 búsquedas/mes. Para las opciones más baratas entre proveedores, consulta los [modelos de IA más baratos por debajo de $1 por millón de tokens](/es/mejores-modelos-baratos-hermes-agent/).

</Accordion>

<Accordion label="¿Puedo usar PicoClaw sin costos de API?" group="faq">

Parcialmente. La búsqueda de DuckDuckGo, Sogou y SearXNG autoalojado no necesita clave. Para el LLM en sí necesitas un modelo local: apunta una entrada de `model_list` a un endpoint compatible con OpenAI de Ollama, LM Studio o vLLM y `api_keys` puede omitirse. [Instalar Ollama con Docker](/es/ollama-docker-instalacion/) es el camino rápido. Cambias calidad y velocidad por una factura de API de cero.

</Accordion>

<Accordion label="¿PicoClaw funciona en una Raspberry Pi?" group="faq">

Sí. Descarga `picoclaw_Linux_arm64.tar.gz` y se ejecuta en cualquier Pi con red. 10-20MB de RAM significa que incluso una Pi Zero 2W lo maneja; hay un objetivo dedicado `make build-pi-zero` para esa placa. Consulta la [sección de hardware](#raspberry-pi-android-y-hardware-de-10) para la lista completa.

</Accordion>

<Accordion label="¿Pueden varias personas usar una instancia de PicoClaw?" group="faq">

Sí. Añade varios IDs de usuario a `allow_from` en la configuración del canal. Cada persona obtiene su propio contexto de conversación a través del sistema de sesiones. Mantén la lista ajustada; un `allow_from` vacío abre el bot a todo el servidor.

</Accordion>

<Accordion label="¿Cuál es la diferencia entre agent y gateway?" group="faq">

`picoclaw agent` es chat directo por CLI: puntual (`-m "..."`) o interactivo. `picoclaw gateway` es el servicio de larga duración que conecta con Discord, Telegram y los demás canales. Para uso 24/7, ejecuta el gateway bajo systemd (o el perfil gateway de Docker).

</Accordion>

<Accordion label="¿Puedo añadir Telegram junto a Discord?" group="faq">

Sí. Añade una entrada `telegram` a `channel_list` junto a `discord` y el gateway maneja ambos a la vez. Necesitas un token de bot de @BotFather. La [guía de configuración de nanobot](/es/guia-configuracion-nanobot/) tiene el recorrido de BotFather; los pasos son idénticos.

</Accordion>

<Accordion label="¿PicoClaw soporta mensajes de voz?" group="faq">

Sí. Con una clave de API de Groq configurada, los mensajes de voz entrantes (de Telegram, por ejemplo) se transcriben a través de la integración Whisper de Groq, y el agente puede responder con `send_tts`. La voz es una de las áreas de funciones de v0.3.x más que un canal central, así que espera bordes rugosos.

</Accordion>

<Accordion label="¿Existe un token cripto de PicoClaw?" group="faq">

No. No hay token, ni airdrop, ni listado en pump.fun. PicoClaw es software de código abierto bajo licencia MIT de Sipeed. Cualquiera que venda un token $PICOCLAW u organice una "preventa" está ejecutando una estafa. picoclaw.io es el único dominio oficial.

</Accordion>

<Accordion label="¿Por qué mi bot usa 15-20MB de RAM ahora?" group="faq">

Las builds recientes usan 10-20MB en lugar de la cifra original por debajo de 10MB. El README lo atribuye a las rápidas fusiones de PRs y dice que la optimización de recursos está planeada para después de la estabilización de funciones. Sigue estando uno o dos órdenes de magnitud por debajo de las alternativas en Python y Node. Si mediste 8MB en v0.1.x y 18MB en v0.3.1, es lo esperado, no una fuga.

</Accordion>

<Accordion label="¿Qué pasó con MiniMax M2.5 y GLM-5?" group="faq">

Ambos avanzaron. MiniMax M2.5/M2.7 dejaron de aceptar nuevos usuarios el 2026-10-19 y se retiran el 2026-11-18; los usuarios del plan se redirigen automáticamente a M3.1-Flash. GLM-5 fue reemplazado por GLM-5.2 y luego GLM-5.3 (2026-08-18). Actualiza cualquier configuración que referencie los IDs antiguos, pásala a `model_list` y ejecuta `picoclaw migrate` si estás en una versión antigua de la configuración. El [resumen de modelos](/es/mejores-modelos-opensource-openclaw/) sigue la alineación y los precios actuales.

</Accordion>
