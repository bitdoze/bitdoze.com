Si estás buscando los mejores cursos online de Gatsby.js en 2026, ten una cosa clara desde el principio: Gatsby está en modo de mantenimiento. [Gatsby](https://www.gatsbyjs.com/) es un generador de sitios estáticos basado en React con una capa de datos GraphQL. Obtiene contenido de sistemas CMS headless como WordPress, Contentful o Sanity y pre-renderiza páginas estáticas rápidas. Es más complejo que WordPress: React, GraphQL y la cadena de herramientas de Node.js tienen que encajar. Un curso estructurado supera a improvisar juntando tutoriales gratuitos cuando eres nuevo en ese stack.

Esta lista es para quienes mantienen un sitio Gatsby existente, o quienes aprenden los patrones antes de pasarse a Astro o Next.js. ¿Vas a empezar un proyecto nuevo desde cero? **[Astro](https://astro.build/)** es el reemplazo más cercano al caso de uso de Gatsby: sitios con mucho contenido, blogs, documentación. Genera casi cero JavaScript por defecto y soporta React, Vue, Svelte y MDX. Aquí es donde aterrizó la mayoría de los antiguos desarrolladores de Gatsby.

## ¿Merece la pena aprender Gatsby en 2026?

Respuesta directa: sí si mantienes un sitio Gatsby existente, te pagan por trabajar en uno, o quieres el modelo mental de SSG y CMS headless que Gatsby dominó. No para proyectos nuevos desde cero. No hay ningún escenario en 2026 en el que Gatsby sea la mejor elección para un proyecto nuevo.

Si mantienes un sitio y la cadena de dependencias se vuelve frágil, planifica la salida. Astro tiene [una guía de migración desde Gatsby](https://docs.astro.build/en/guides/migrate-to-astro/from-gatsby/) que sigue bien documentada, y si hay WordPress de por medio, consulta [cómo migrar un sitio de WordPress a Astro y MDX](/es/migracion-wordpress-a-astro/). Cuanto más esperes, más frágil se vuelve la cadena de plugins.

### Mantener un sitio Gatsby a finales de 2026

El stack soportado es más estrecho que antes, pero está documentado. Aquí está la matriz.

<ListCheck>
**Soportado hoy (gatsby 5.16.x, publicado el 2026-02-10):**
- Gatsby 5.16.x es la línea actual (las actualizaciones 5.15/5.16 no rompían nada)
- Node 22 (soportado desde 5.15.0) o Node 24 (desde 5.16.0); el campo `engines` de npm es `>=18 <26`
- React 18 o React 19 (soportado oficialmente desde 5.16.0; según las notas de la versión, ninguna de las vulnerabilidades de seguridad de React 19 afecta a Gatsby)
- Planifica pensando en Node 26: la LTS llega el 2026-10-28 y todavía no está dentro del rango de engines
</ListCheck>

<Notice type="warning" title="Node 22.7.0-22.9.0 rompe gatsby develop">
Hay un modo de fallo real en la matriz actual. `gatsby develop` se rompe en Node 22.7.0 a 22.9.0 (bug de Node en upstream). Quédate en el último parche 22.x y no tendrás problemas. Node 22 tiene soporte hasta 2027-04, Node 24 hasta 2028-04.
</Notice>

Verifica antes de tocar nada:

```bash
# what Node range does your Gatsby version support?
npm view gatsby engines          # -> {"node":">=18.0.0 <26"}

# is this plugin abandoned? check last publish date
npm view <plugin-name> time.modified

# upgrade to the current line (5.15/5.16 were non-breaking)
npm install gatsby@latest        # React 19 optional; stay on 18 if you like
gatsby build                     # run in a branch/CI BEFORE merging
```

Ejecuta `gatsby build` en una rama o en CI antes de fusionar cualquier actualización. Las líneas 5.15/5.16 no rompían nada, pero "no rompe nada" es una promesa del changelog hasta que tu build pasa. Ya que estás ahí, [actualiza todas las dependencias de Node.js a la última versión](/nodejs-update-dependencies/) de forma selectiva en lugar de un `npm update` a ciegas. Si gestionas Node con Fish Shell, consulta [cómo usar NVM con Fish Shell](/es/nvm-fish-shell/).

Realidad del ecosistema: los plugins oficiales todavía reciben alguna versión coordinada ocasional (la última el 2026-01-26: gatsby-plugin-image 3.16.0, gatsby-source-wordpress 7.17.0, gatsby-source-contentful 8.17.0, gatsby-plugin-sharp 5.16.0), pero la mayoría de los plugins de la comunidad llevan años abandonados. Ejecuta siempre la comprobación con `npm view` de arriba antes de instalar algo nuevo.

Y sí: no empieces proyectos nuevos con Gatsby.

## Preguntas frecuentes

<Accordion label="¿Está muerto Gatsby en 2026?" group="faq" expanded="true">
No está muerto, está en modo de mantenimiento. El repositorio no está archivado y recibe commits (último push en septiembre de 2026), pero espera unas dos versiones estables al año y una diferencia de 18:1 en descargas mensuales de npm frente a Astro. Bien para mantener un sitio existente. Mal para trabajo nuevo desde cero.
</Accordion>

<Accordion label="¿Debería aprender Gatsby en 2026?" group="faq">
Solo si te pagan por mantener un sitio Gatsby existente o quieres el modelo mental de sitio estático y CMS headless que enseña. Si no, empieza con Astro; los patrones (enrutamiento por archivos, capas de datos, pipelines de imágenes) se transfieren.
</Accordion>

<Accordion label="¿Cuánto se tarda en aprender Gatsby?" group="faq">
Con fundamentos de React, calcula 1-2 semanas de tardes para completar un curso de fundamentos más proyectos. Añade una semana si GraphQL es nuevo para ti. Para trabajo de mantenimiento en concreto, la matriz de versiones de arriba importa más que otras 20 horas de vídeo.
</Accordion>

<Accordion label="¿Necesito saber React y GraphQL primero?" group="faq">
Sí para React. GraphQL se puede aprender junto con Gatsby; el curso de proyectos lo cubre desde cero. Empezar sin React va a doler: los componentes, los hooks y la cadena de herramientas de build aparecen por todas partes.
</Accordion>

Elige el curso que encaje con tu situación: mantén en Gatsby con el curso de proyectos, o migra y aprende Astro en su lugar. Si vas a migrar, empieza con la guía oficial de Gatsby a Astro y hazlo en una rama.
