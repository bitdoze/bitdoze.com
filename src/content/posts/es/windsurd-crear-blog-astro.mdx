### De Windsurf a Devin Desktop: qué cambió en 2026

- **Abril de 2025:** Codeium se renombró oficialmente a Windsurf.
- **Julio de 2025:** Cognition adquirió la propiedad intelectual, el producto y a ~210 empleados de Windsurf por ~250 M$ (después de que expirara una oferta de 3.000 M$ de OpenAI y de que Google cerrara un «reverse-acquihire» de 2.400 M$ para fichar a ejecutivos clave).
- **2 de junio de 2026:** Cognition lanzó Windsurf como «Devin Desktop» mediante una actualización over-the-air. Los ajustes, las extensiones y los atajos de teclado se trasladaron automáticamente.
- **1 de julio de 2026:** El agente Cascade (el antiguo backend de IA) llegó a su fin de vida y fue reemplazado por Devin Local, una reescritura en Rust que añade subagentes en paralelo.
- El modelo por defecto ahora es SWE-1.6 en los planes de pago (gratis en Pro y superiores). El plan gratuito tiene disponibilidad de modelos limitada. Los modelos frontera de Anthropic, OpenAI y Google están disponibles en los planes de pago.

## Configuración inicial: crea el esqueleto de tu tema de blog en Astro

Estos son los pasos básicos del scaffolding. Yo los ejecuté manualmente al principio y después le pasé el proyecto al IDE de IA para la construcción de componentes. Cada comando de abajo se ejecuta desde un terminal estándar. El IDE de programación con IA acelera el proceso generando componentes y layouts mediante chat, pero la configuración en sí es manual.

<Notice type="info" title="IDE de IA opcional">
Cada comando de abajo se ejecuta desde un terminal estándar. El IDE de programación con IA (Devin Desktop, Cursor, Claude Code, etc.) acelera el proceso generando componentes y layouts mediante chat, pero la configuración en sí es manual.
</Notice>

### Paso 1: Instala Astro 7

Crea un nuevo proyecto de Astro con la CLI oficial:

```bash
npm create astro@latest
```

Preguntas del asistente:
- **Directorio:** `.` (carpeta actual)
- **Plantilla:** un starter básico y mínimo
- **Dependencias:** Sí
- **Git:** Sí

Esto te da una instalación limpia de Astro con un servidor de desarrollo y Git inicializado. Astro 7 también añade `astro dev --background` para sesiones del servidor de desarrollo en segundo plano, útil si ejecutas un agente de IA que necesita comprobar el estado del servidor sin bloquear un terminal.

**Verificación:** Ejecuta `npm run dev` y abre `http://localhost:4321`. Deberías ver la página de bienvenida de Astro.

### Paso 2: Añade Tailwind CSS 4

Integra Tailwind CSS para los estilos:

```bash
npx astro add tailwind
```

Esto instala `@tailwindcss/vite` y `tailwindcss` (actualmente ~4.3.x), crea `./src/styles/global.css` y actualiza `astro.config.mjs` para incluir el plugin de Tailwind para Vite. Importa la hoja de estilos en tu archivo de layout (`src/layouts/Layout.astro`) para aplicar los estilos globalmente.

<Notice type="warning" title="Error de compilación conocido">
El comando `astro add tailwind` puede fallar con un error de rolldown-vite (`Missing field 'tsconfigPaths'`). Si te ocurre, cambia a la integración de PostCSS en su lugar:

```bash
npm uninstall @tailwindcss/vite
npm install @tailwindcss/postcss
```

Luego crea `postcss.config.mjs`:

```js
// postcss.config.mjs
export default { plugins: { "@tailwindcss/postcss": {} } };
```

Elimina `@tailwindcss/vite` del array `vite.plugins` en `astro.config.mjs`. Puede que esto ya esté corregido en el último parche de Astro 7. Haz una prueba antes de asumir que necesitas la solución alternativa.
</Notice>

**Verificación:** Ejecuta `npm run dev` de nuevo. Añade una clase de utilidad de Tailwind (como `class="text-blue-500"`) a cualquier elemento de la página y confirma que se renderiza con el color correcto.

### Paso 3: Tipografía, MDX e iconos de Astro

Instala las dependencias restantes en una sola pasada:

```bash
npm install -D @tailwindcss/typography
npx astro add mdx
npx astro add astro-icon
npm install @iconify-json/mdi
```

- `@tailwindcss/typography`: aplica estilos al contenido en prosa de Markdown/MDX sin CSS manual.
- `@astrojs/mdx`: permite mezclar Markdown y JSX en los archivos de contenido.
- `astro-icon` + `@iconify-json/mdi`: iconos ligeros del conjunto Material Design Icons.

En tu `src/styles/global.css`, usa el patrón de configuración CSS-first de Tailwind 4:

```css
@import "tailwindcss";
@plugin "@tailwindcss/typography";
/* theme tokens via @theme { --color-...: ...; } */
```

Si necesitas una gestión de contenido más completa que el MDX basado en archivos, hay buenas [opciones de CMS headless para Astro](/es/mejores-cms-headless-astro/) que combinan bien con esta configuración.

### Verifica tu configuración

Repasa esta lista de comprobación antes de continuar:

<ListCheck>
<ul>
<li>`npm run dev` sirve en `http://localhost:4321`</li>
<li>`npm run build` termina sin errores y se crea la carpeta `dist/`</li>
<li>Las clases de utilidad de Tailwind se renderizan (comprueba cualquier elemento con una clase de color o espaciado)</li>
<li>El contenido MDX se renderiza (crea un archivo `.mdx` de prueba en `src/content/` y confirma que compila)</li>
<li>Los Astro Icons cargan (añade un componente `<Icon name="mdi:home" />` y confirma que se renderiza)</li>
</ul>
</ListCheck>

Si usas el repositorio del tema publicado, también incluye `npm run verify`, que ejecuta la comprobación de tipos y una compilación de producción.

### Creando un tema de blog a base de chat

Así fue el flujo de trabajo con los prompts:

- **Primer prompt:** «Build a blog with Astro and Tailwind CSS 4. Use theme variables and Tailwind.» La IA analizó mi proyecto y comenzó el scaffolding.
- **CSS global:** Le pedí que definiera colores y fuentes personalizados en `src/styles/global.css`. Creó una configuración de tema flexible usando la directiva `@theme` de Tailwind 4.
- **Funcionalidades:** Solicité un interruptor de modo oscuro/claro, paginación y un menú responsive. Actualizó los layouts y componentes sobre la marcha.

**Consejo sobre agrupar prompts:** yo pedía 3-4 funcionalidades a la vez (p. ej., «Add header, footer, and pagination»). Esto minimiza el consumo de cuota y maximiza el resultado. Con el sistema de cuotas actual, las operaciones fallidas no consumen cuota, así que hay menos penalización por los prompts ambiciosos.

### Funciones clave: búsqueda, modo oscuro, paginación y SEO

El IDE de IA entregó un tema con todos los componentes estándar:

- Una cabecera limpia y responsive con menú hamburguesa para móvil.
- Páginas para autores, categorías, etiquetas y series (tutoriales) con paginación.
- Migas de pan, tabla de contenidos, artículos relacionados (basados en etiquetas) y botones para compartir en redes sociales.
- Búsqueda en el lado del cliente (consulta la siguiente sección para más detalles).
- Acordeones, pestañas, botones y cajas de notificación para un contenido más rico.
- Componentes de metadatos optimizados, etiquetas Open Graph y datos estructurados.
- Un formulario de contacto que funciona sin necesidad de backend. Puedes [añadir un formulario de contacto a tu blog de Astro](/es/anadir-formulario-contacto-astro/) sin escribir código del lado del servidor.

Si el contenido MDX basado en archivos se te queda corto, un CMS headless es el siguiente paso natural. Consulta [opciones de CMS headless para Astro](/es/mejores-cms-headless-astro/) para ver una comparación.

### Búsqueda en el lado del cliente: Fuse.js o Pagefind

El tema original usa Fuse.js para la búsqueda en el lado del cliente: sin React, sin servidor, solo Astro y un índice JSON. Funciona bien para blogs pequeños y medianos. Pero Pagefind se ha consolidado como una alternativa sólida, con un índice generado en tiempo de compilación y cero JS en el cliente para la infraestructura de búsqueda.

<Tabs>
<Tab name="Fuse.js">
Enfoque actual del tema. Instálalo y úsalo:

```bash
npm install fuse.js
```

Crea un componente de búsqueda que cargue un índice JSON de tu contenido y ejecute la coincidencia difusa en el lado del cliente. Funciona sin dependencias de frameworks: Astro puro.

**Ideal para:** Blogs pequeños y medianos (< 500 artículos) donde la simplicidad importa más que el tamaño del índice de búsqueda.
</Tab>
<Tab name="Pagefind">
Indexación en tiempo de compilación con cero JS en tiempo de ejecución para el propio índice:

```bash
npx pagefind --site dist
```

También existe una integración de Astro (`@stanniel/astro-pagefind` / `astro-pagefind`) que se engancha automáticamente al pipeline de compilación.

**Ideal para:** Blogs más grandes o sitios en los que no quieres servir en absoluto un índice de búsqueda en el cliente.
</Tab>
</Tabs>

Fuse.js funciona muy bien para blogs pequeños y medianos; Pagefind escala mejor y no envía ningún JS del lado del cliente para el índice de búsqueda.

## Astro 7 y Tailwind CSS 4: novedades en 2026

Si estás actualizando desde el tema original (Astro 5.4 / Tailwind 4.0) o vienes de un proyecto de Astro más antiguo, esta sección cubre los cambios importantes.

### Velocidad de compilación de Astro 7 y el compilador en Rust

Astro 7 (junio de 2026) es una versión importante:

- **Vite 8 / Rolldown:** El bundler es de 10 a 30 veces más rápido que el Vite 6 que venía con Astro 5.
- **Compilador `.astro` en Rust:** Ahora es el predeterminado. Compilación de plantillas más rápida. Sin embargo, es «tal cual»: las etiquetas sin cerrar y los atributos sin terminar ahora **dan error** en lugar de corregirse silenciosamente. También se aplican las reglas de espacios en blanco de JSX: los saltos de línea entre elementos en línea colapsan.
- **Pipeline de Markdown/MDX de Sätteri:** Las tablas GFM, las notas al pie, el tachado, la puntuación inteligente, los IDs de encabezados y más vienen integrados. No se necesitan plugins de remark/rehype para las funciones estándar.
- **Queued Rendering:** renderizado de páginas ~2,4 veces más rápido por defecto.
- **`astro dev --background`:** Arranca el servidor de desarrollo en segundo plano y consúltalo mediante logging en JSON — ideal para flujos de trabajo con agentes de IA.

El resultado: las compilaciones son un 15-61 % más rápidas según el tamaño del sitio. Consulta [las compilaciones más rápidas de Astro 7](/es/astro-7-compilaciones-mas-rapidas/) para ver benchmarks en un sitio de 743 páginas. Si quieres ir más allá, hay una guía detallada sobre cómo [acelerar tu compilación de Astro](/es/astro-ssg-optimizacion-build/).

### Resolución de problemas comunes de la actualización

<Accordion group="troubleshooting" label="Error de compilación con astro add tailwind">
El comando `astro add tailwind` puede instalar `@tailwindcss/vite`, que puede fallar con `Missing field 'tsconfigPaths'` en compilaciones basadas en Rolldown (issue #16542 de GitHub).

**Solución:** Cambia a la integración de PostCSS:

```bash
npm uninstall @tailwindcss/vite
npm install @tailwindcss/postcss
```

Crea `postcss.config.mjs`:

```js
export default { plugins: { "@tailwindcss/postcss": {} } };
```

Elimina `@tailwindcss/vite` del array `vite.plugins` en `astro.config.mjs`.
</Accordion>

<Accordion group="troubleshooting" label="Espacios en blanco inesperados tras la actualización">
El compilador en Rust de Astro 7 aplica las reglas de espacios en blanco al estilo de JSX. Si ves que elementos de texto se juntan (p. ej., `<span>Hello</span><span>World</span>` se renderiza como «HelloWorld» en lugar de «Hello World»), añade espacios explícitos o usa `gap` de CSS en los contenedores flex.

Es un cambio de comportamiento, no un bug. El compilador antiguo lo corregía silenciosamente; el nuevo no.
</Accordion>

<Accordion group="troubleshooting" label="Los plugins de remark/rehype no funcionan">
El pipeline de Markdown de Sätteri de Astro 7 reemplaza por defecto el antiguo pipeline basado en unified. Si tu tema dependía de plugins personalizados de remark o rehype, puede que necesiten el fallback de unified `@astrojs/markdown-remark`. Revisa la configuración `markdown:` de tu `astro.config.mjs` y consulta la guía de migración de Astro 7.
</Accordion>

## Nuevas funciones de Astro que vale la pena explorar

Astro 6 y 7 introdujeron capacidades que este tema podría aprovechar:

- **Fonts API** (`astro:fonts`): Aloja fuentes localmente, genera fallbacks y precarga las fuentes críticas — todo desde la configuración de Astro. Directamente relevante para un tema de blog.
- **CSP API** (`security: { csp: true }`): Cabeceras de Content Security Policy con un solo flag. Una victoria de «fiabilidad aburrida» para cualquier blog autoalojado.
- **Live Content Collections:** Contenido dinámico que se actualiza sin recompilar. Solo relevante si abandonas lo puramente estático, pero conviene conocerlo.
- **Caché de rutas + proveedores de CDN:** Cabeceras de caché integradas para despliegues compatibles con CDN.
