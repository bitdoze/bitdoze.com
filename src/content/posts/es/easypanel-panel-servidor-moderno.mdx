Easypanel.io es un panel de control de servidor autoalojado que convierte un VPS en una PaaS autoalojada. Corre sobre Docker por debajo, pero tienes una UI web limpia para desplegar aplicaciones, gestionar bases de datos y emitir certificados SSL sin vivir en la terminal. Esta reseña de Easypanel está actualizada para la versión 2.36 (septiembre 2026), la nueva CLI y el servidor MCP, y los precios de 2026.

Si has usado Heroku, Netlify o Vercel, el flujo se siente familiar: conecta tu código, y Easypanel lo buildea y despliega. La diferencia es que posees la infraestructura y solo pagas el VPS, más una licencia de panel opcional.

### Easypanel CLI: gestiona servidores desde la terminal

La CLI llegó en 2.33.0. Se instala en tu portátil (macOS, Linux o Windows) y habla con uno o más servidores Easypanel a través de API keys por usuario. Los comandos reflejan la versión del servidor al que estás conectado, así que el comportamiento coincide con lo que hace la UI.

Instálala con el script oficial:

<Tabs>
<Tab name="macOS / Linux">

```sh
curl -fsSL https://get.easypanel.io/cli | sh
```

</Tab>
<Tab name="Windows">

```powershell
irm https://get.easypanel.io/cli.ps1 | iex
```

</Tab>
</Tabs>

Luego genera una API key en el panel (Settings > Server > Users > Generate API Key) y registra el servidor:

```sh
easypanel server add production https://panel.example.com
```

**Verifica:** `easypanel --help` (o `ep --help`) imprime la lista de comandos, y `easypanel server list` muestra el servidor que acabas de añadir. Si la auth falla, la clave se copió con espacios en blanco o pertenece a otro usuario.

### Easypanel MCP: gestiona tu panel desde un agente IA

Esta es la parte que no habría esperado de un panel de hosting hace dos años. Easypanel expone un endpoint MCP remoto, así que clientes como Claude Code, Codex o Cursor pueden inspeccionar y gestionar tus proyectos y servicios con tus permisos de usuario.

El endpoint vive en tu propio panel:

```
https://YOUR_SERVER_DOMAIN/api/mcp            # Authorization: Bearer <API key>
https://YOUR_SERVER_DOMAIN/api/mcp/<API_KEY>  # for URL-only clients
```

El transporte es Streamable HTTP. Los clientes nuevos usan la primera forma con un bearer token; los clientes viejos o solo-URL pueden incrustar la clave en la ruta. La nueva API pública tras esto está documentada y pretende quedarse estable, a diferencia de la vieja API interna, que aún funciona pero puede cambiar sin aviso.

<Notice type="warning" title="Las API keys son credenciales completas">
Una API key de MCP o CLI hereda los permisos de ese usuario. Trátala como una contraseña: una clave por cliente, revócala desde la misma pantalla cuando dejes de usarla.
</Notice>

Si quieres ver hasta dónde puede llegar esto, describo [cómo despliego apps Docker con un solo mensaje de IA](/ai-docker-deploy-skill/) usando la misma idea: dale al agente una API acotada y un verbo de deploy claro.

## ¿Qué es Easypanel? Una PaaS autoalojada para tu VPS

Easypanel se sienta sobre Docker Swarm y Traefik. Maneja:

- **Despliegue de aplicaciones** desde repos GitHub, imágenes Docker, Dockerfiles o archivos fuente
- **Gestión de bases de datos** para PostgreSQL (18 por defecto), MySQL, MariaDB, MongoDB y Redis
- **SSL automático** vía Let's Encrypt con renovación automática
- **Deployments sin downtime** usando la estrategia de rolling update de Docker Swarm
- **Terminal web** para correr comandos dentro de contenedores sin SSH
- **Librería de plantillas** con más de 750 instaladores de un clic

<Image
  src={archSvg}
  alt="Easypanel architecture diagram: browser and AI clients hit Traefik on ports 80 and 443 with auto-SSL, Traefik routes to Docker Swarm app, database, and template services, and the Easypanel control plane manages Swarm through a read-only docker.sock"
/>

En el lado del build, Easypanel auto-detecta el lenguaje de tu app y construye una imagen sin obligarte a escribir un Dockerfile. Hay cuatro builders ahora, y los docs recomiendan Railpack para apps nuevas:

| Builder | Cuándo usarlo | Notas |
|---------|-------------|-------|
| **Railpack** | Recomendado para apps nuevas sin Dockerfile | Auto-detección moderna vía BuildKit |
| **Dockerfile** | Tienes un Dockerfile en el Build Path | Auto-seleccionado cuando el archivo está presente |
| **Cloud Native Buildpacks** | Quieres builds estilo buildpack | Imagen de builder configurable, env de build, `project.toml` |
| **Nixpacks** | Sin ajustes de build guardados aún | Fallback legacy |

Si usas monorepos, apunta el **Build Path** al subdirectorio correcto para que el builder vea el proyecto correcto. Dos tipos de servicio más cubren los huecos: un servicio Box (runtime basado en módulos con Node.js, PHP, Python, Ruby, NGINX y un IDE en navegador) para gente que no quiere Dockerfile en absoluto, y un servicio Compose para stacks multi-contenedor.

Una corrección a los write-ups antiguos de internet: las plantillas no son "stacks de Docker Compose pre-configurados". Las plantillas se despliegan como servicios nativos de Easypanel (App, Postgres, Redis, Compose, etc.), y hay un tipo de servicio Compose dedicado para gente que quiere traer su propio stack.

## Qué puedes desplegar

### Bases de datos

Easypanel trata las bases de datos como servicios de primera clase. Puedes levantar cualquiera de estas con unos clics:

- **PostgreSQL**: la versión 18 es el default desde 2.34.0. El servicio trae herramientas de admin en navegador PgWeb y DbGate
- **MySQL / MariaDB**: la elección estándar para WordPress, Laravel y la mayoría de apps PHP
- **MongoDB**: almacén de documentos para esquemas flexibles
- **Redis**: caché en memoria y broker de mensajes

También hay un tipo de servicio WordPress dedicado si quieres el CMS sin montar el stack tú mismo.

Cada base de datos puede quedarse privada (alcanzable solo desde servicios del mismo servidor) o exponerse públicamente. Mantenla privada a menos que tengas razón para no hacerlo. Y haz backup de las bases de datos fuera del servidor: la programación de backups de bases de datos integrada necesita el plan Hobby, así que los usuarios del plan Free deberían scriptar `pg_dump`/`mysqldump` a object storage por su cuenta.

### Plantillas

La [librería de plantillas](https://easypanel.io/templates) ha crecido mucho. Easypanel declara más de 750 servicios open-source a octubre de 2026 (la 2.31.0 sola añadió 121 plantillas y actualizó 400). Opciones populares:

- **WordPress**: CMS completo con temas y plugins
- **Plausible**: analítica web centrada en privacidad
- **n8n**: automatización de flujos de trabajo. Mira [autoalojar n8n para automatización de flujos](/n8n-self-host-workflow-automation/) para un setup completo
- **Listmonk**: gestor de newsletters autoalojado
- **Grafana**: visualización de métricas y dashboards
- **Uptime Kuma**: monitorización de uptime con notificaciones. Lo cubro en [cómo instalar Uptime Kuma](/install-uptime-kuma/)
- **Gitea**: alojamiento Git ligero
- **Ghost**: plataforma de publicación para newsletters y blogs

OpenSEO fue la adición notable en 2.36.0. Puedes personalizar variables de entorno, volúmenes y puertos tras desplegar cualquier plantilla.

### Aplicaciones

Para código propio, conectas un repositorio de GitHub y Easypanel se encarga del resto. Los repos públicos no necesitan token. Los repos privados usan un personal access token de GitHub configurado en el servidor (Settings > GitHub). Cada push a la rama conectada dispara el webhook de deploy.

Las fuentes son flexibles: repositorio Git, imagen Docker, Dockerfile, o una subida de fuente (zip, tar, 7z, rar soportados desde 2.32.0). El builder auto-detecta el lenguaje con Railpack, o elige el builder Dockerfile si existe un `Dockerfile` en el Build Path. Easypanel inyecta una variable de entorno `GIT_SHA` durante los builds de repo, útil para cache busting y banners de versión.

Los App Scripts (2.27.0) te dejan definir comandos con nombre por app y correrlos desde una pestaña "Scripts", que es cómo manejo migraciones puntuales y trabajos de seed sin SSH.

Un gotcha que vale grabarse en memoria: guardar ajustes no los despliega. Pulsa **Deploy**.

Para un recorrido específico de framework, mira [Cómo Desplegar Astro en tu VPS con EasyPanel](/es/desplegar-astro-easypanel/).

Así es como conseguir Easypanel corriendo en un VPS limpio y desplegar algo real.

### Requisitos

Requisitos oficiales: un servidor Ubuntu limpio con al menos 2 GB de RAM, y **los puertos 80 y 443 deben estar disponibles**. El script de instalación se niega a correr como no-root, y no correrá en macOS ni dentro de un contenedor.

<ListCheck>
<ul>
<li>Ubuntu 22.04 o 24.04 LTS limpio (mi recomendación; cualquier Ubuntu reciente vale)</li>
<li>2 GB de RAM mínimo, más si vas a buildear en la máquina</li>
<li>Acceso root o sudo</li>
<li>Un dominio que controles, con acceso a DNS</li>
<li>Puertos 80 y 443 libres en el host</li>
<li>Un VPS de un proveedor en el que confíes</li>
</ul>
</ListCheck>

<Notice type="warning" title="Preflight del instalador">
El instalador aborta si los puertos 80 u 443 ya están en uso. Para nginx, Apache o Caddy antes de correrlo.
</Notice>

### Paso 1: Actualiza el servidor

```sh
apt update && apt -y upgrade
reboot
```

**Verifica:** tras el reinicio, `uptime` muestra que la máquina volvió, y `lsb_release -a` confirma la release de Ubuntu que esperas.

### Paso 2: Añade swap (si hace falta)

Algunos proveedores, Hetzner incluido, no añaden swap por defecto. Ajusta el tamaño a tu RAM:

```sh
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

**Verifica:** `free -h` muestra swap, y `swapon --show` lista `/swapfile`. Si `fallocate` falla, usa `dd if=/dev/zero of=/swapfile bs=1M count=2048` en su lugar.

### Paso 3: Instala Easypanel

Un comando:

```sh
curl -sSL https://get.easypanel.io | sh
```

El script instala Docker CE del repo apt oficial de Docker cuando hace falta, inicializa Docker Swarm, corre el contenedor de setup de Easypanel con `/etc/easypanel` y el socket de Docker montados, y despliega Traefik como reverse proxy. Espera 2-5 minutos.

Cuando termina, obtienes la URL de acceso:

```
Easypanel was installed successfully on your server!

    http://YOUR_SERVER_IP:3000
```

El puerto 3000 es lo que la salida del setup imprime; los docs no lo fijan, así que confía en lo que diga tu salida de instalación y ajusta la regla de firewall a juego.

**Verifica:** `docker ps` debería mostrar el panel, el proxy y el servicio de páginas de error:

```sh
docker ps
# CONTAINER ID   IMAGE                  NAMES
# a1b2c3d4e5f6   easypanel/error-pages  error-pages
# b2c3d4e5f6a7   easypanel/easypanel    easypanel
# c3d4e5f6a7b8   traefik                traefik
```

Luego `curl -I http://localhost:3000` debería devolver una respuesta del panel. Si los contenedores faltan, re-corre el instalador y lee la salida desde arriba.

### Paso 4: Configura el panel

**Apunta un dominio al servidor.** Crea un registro A en tu proveedor de DNS apuntando a la IP de tu servidor. Un subdominio como `panel.tudominio.com` funciona bien.

**Pon el dominio en Easypanel.** Abre el panel en `http://YOUR_SERVER_IP:3000`, crea tu cuenta de admin, luego ve a **Settings > General** e introduce tu dominio.

<Picture formats={["webp"]} fallbackFormat="webp"
  src={img1}
  alt="Easypanel domain settings screen where panel.yourdomain.com is set as the server domain"
/>

**Activa 2FA.** Ve a **Settings > Authentication** y configura autenticación de dos factores con una app authenticator.

<Notice type="warning" title="El panel posee tu servidor">
Easypanel puede arrancar, parar y borrar cualquier cosa en el host. Activa 2FA antes de exponer el panel públicamente, y trata la cuenta de admin como un login root. Para más hardening del host, mira [cómo aseguré mi servidor Docker](/bsi-security-report-docker-ufw/).
</Notice>

**Conecta GitHub.** Si vas a desplegar repos privados, ve a **Settings > GitHub** y añade un [personal access token](https://github.com/settings/tokens).

Una vez puesto el dominio, Traefik emite un certificado Let's Encrypt y lo renueva automáticamente.

**Verifica:** `dig panel.tudominio.com` devuelve la IP de tu servidor, y `curl -I https://panel.tudominio.com` muestra un certificado Let's Encrypt válido.

### Paso 5: Despliega tu primer proyecto

Haz clic en **Create Project**, luego añade un servicio. Para una app de GitHub:

<Picture formats={["webp"]} fallbackFormat="webp"
  src={img2}
  alt="Easypanel app service screen connecting a GitHub repository for automatic build and deployment"
/>

1. Selecciona **App** como tipo de servicio
2. Conecta tu repositorio de GitHub
3. Elige un método de build: Railpack (recomendado), o Dockerfile si el repo tiene uno
4. Añade tu dominio bajo la pestaña **Domains**
5. Deploy

El plan gratis permite 3 proyectos, pero cada proyecto puede alojar múltiples servicios (app + base de datos + caché, por ejemplo).

Para más detalle sobre desplegar un framework concreto, mira [Cómo Desplegar Astro en tu VPS con EasyPanel](/es/desplegar-astro-easypanel/).

**Verifica:** el deploy termina en verde en la UI, los logs de build acaban con una línea de éxito, y `curl -I https://app.tudominio.com` devuelve 200. Si falla, comprueba los tres sospechosos habituales: variables de entorno que faltan, versión de runtime equivocada, o un build sin memoria (añade swap, o descarga builds a un Docker builder remoto como se cubre abajo).

## Operaciones de día 2

La noche de instalación es la parte fácil. Así se ve correr Easypanel.

**Actualizaciones.** El panel muestra un banner de actualización cuando aterriza una release nueva; un clic la aplica. Si prefieres la terminal o la UI es inalcanzable:

```sh
docker image pull easypanel/easypanel && docker service update easypanel --force
```

Los docs también cubren un canal canary (`RELEASE_TAG=canary`) y fijar una versión concreta si prefieres no moverte automáticamente.

**Backups.** Easypanel puede programar backups para apps, volúmenes y bases de datos. Destinos: Amazon S3 y almacenes compatibles con S3 (Cloudflare R2 tiene preset desde 2.32.0, más DigitalOcean Spaces, Backblaze B2, Wasabi), Google Drive, Dropbox, FTP/SFTP y disco local. La restauración de un clic está anunciada.

No confíes en un backup que no has restaurado. Mi rutina mínima: dispara un backup manualmente, confirma que el objeto existe en el bucket, luego restáuralo en un proyecto de pruebas. Para WordPress, haz backup de la base de datos **y** del volumen de uploads; uno sin el otro no es una restauración.

Los backups de bases de datos necesitan el plan Hobby (10,9-14,9 $/mes según facturación) más unos céntimos de object storage. En el plan Free tus volúmenes viven solo en la máquina, así que scripta tus propias copias fuera del servidor.

**Monitorización.** Desde 2.29.0, Easypanel tiene métricas impulsadas por Prometheus (CPU, memoria, disco, red, por servicio y del sistema entero) y búsqueda de logs impulsada por Loki con niveles, streaming en vivo y config de retención. Actívalo en Settings > Monitoring. La monitorización avanzada es parte del upsell Hobby. Yo sigo emparejando el panel con chequeos externos: [monitorización de servidor con Beszel y Uptime Kuma](/beszel-uptime-kuma/) te da una segunda opinión desde fuera del propio stack de Easypanel.

**Extras de mantenimiento que vale conocer:** el comando de reseteo de contraseña de admin en los docs (lo necesitarás algún día), guías de config propia de Traefik y del dashboard de Traefik, setup de dominios wildcard, notificaciones (plan Hobby), soporte GPU vía el NVIDIA Container Toolkit, cron jobs, y el Docker builder remoto para servidores pequeños donde los builds locales castigan el swap.

<Notice type="warning" title="Reinicia Traefik tras actualizar más allá de 2.35.0">
La actualización a Traefik 3.7.13 aterriza con el panel, pero el propio Traefik debe reiniciarse para recogerla. Si te lo saltas, te quedas en la versión vieja del proxy.
</Notice>

**Checklist de producción:**

<ListCheck>
<ul>
<li>Backups yendo fuera del servidor, más una prueba de restauración registrada</li>
<li>2FA activado en cada usuario del panel</li>
<li>Monitorización de uptime externa apuntando a URLs públicas</li>
<li>Rotación de logs de Docker configurada (ver troubleshooting)</li>
<li>Actualizaciones del panel aplicadas mensualmente, Traefik reiniciado tras actualizaciones del proxy</li>
<li>Reglas de firewall revisadas (ver el gotcha Docker/UFW de abajo)</li>
</ul>
</ListCheck>

**Verifica tras cualquier actualización:** `docker service ps easypanel` muestra la tarea corriendo y sana.

La fuerza de Easypanel es la experiencia más limpia estilo-Heroku en un solo VPS. Pagas por eso con precios por-servidor y un panel closed-source (los repos públicos easypanel-io alojan plantillas y ejemplos, no el panel en sí). Coolify es la elección cuando gratis y open-source es innegociable: tiene más funciones a coste cero, incluyendo multi-servidor. Mi opinión más a fondo está en [nuestra reseña de Coolify v5](/coolify-v5-self-hosted-paas-review/), y si estás eligiendo entre las opciones de PaaS autoalojada en general, [Coolify vs Dokploy vs Kamal 2](/coolify-vs-dokploy-vs-kamal-2/) recorre la decisión.

Portainer es un gestor de contenedores, no una PaaS: genial para control directo de Docker, herramienta equivocada si quieres push-to-deploy. Dokku es excelente si vives en la terminal y no quieres una UI web en absoluto.

## Troubleshooting

**Panel inaccesible tras la instalación.** Comprueba que el puerto del panel (3000 por defecto; confirma en tu salida de setup) está abierto en el firewall de tu servidor. Si usas Cloudflare, pon el registro DNS a "DNS only" (nube gris) durante el setup.

**La instalación aborta, o puertos 80/443 ya en uso.** El nuevo preflight se niega a continuar. Para nginx, Apache o Caddy, o mueve el servicio conflictivo. Trampa relacionada: Docker publica puertos de contenedores más allá de UFW, así que el firewall puede "verse bien" mientras el tráfico sigue llegando. Aquí está [cómo Docker esquiva UFW y cómo arreglarlo](/docker-bypasses-firewall/).

**Builds de app fallando.** Abre los logs de build en la UI. Causas habituales: variables de entorno que faltan, versión de runtime equivocada, o memoria insuficiente. Añadir swap ayuda en máquinas pequeñas. En servidores donde los builds hacen OOM constantemente, descárgalos a un Docker builder remoto (Easypanel tiene una guía). Easypanel inyecta `GIT_SHA` durante los builds de repo, así que los trucos de cache-busting pueden usar esa variable.

<Accordion label="El certificado SSL no se aprovisiona" group="faq">
Asegúrate de que el registro A de DNS está totalmente propagado antes de poner el dominio en Easypanel. Let's Encrypt usa validación HTTP-01 y debe alcanzar tu servidor en el puerto 80. Si el dominio está proxied por Cloudflare, cámbialo a DNS only hasta que el certificado se emita.
</Accordion>

<Accordion label="Ajustes guardados pero nada cambió" group="faq">
Guardar ajustes no es desplegar. Pulsa el botón **Deploy** del servicio. Es un gotcha documentado en los docs del servicio App y normalmente por qué una env var parece no hacer nada.
</Accordion>

<Accordion label="Traefik sigue en la versión vieja tras una actualización" group="faq">
Tras 2.35.0, la actualización del panel trae Traefik 3.7.13 pero debes reiniciar el servicio Traefik para recogerla. Reinícialo desde el panel o con una actualización de servicio y re-comprueba la versión.
</Accordion>

<Accordion label="Contenedores comiendo disco" group="faq">
Comprueba si la rotación de logs está configurada en tu daemon de Docker. Este es consejo general de Docker más que un default verificado de Easypanel: si ves crecimiento de disco por logs de contenedores, pon `max-size` y `max-file` en `/etc/docker/daemon.json` y reinicia Docker. Empareja eso con la limpieza de backups y volúmenes en el panel para que los snapshots viejos no se acumulen.
</Accordion>
