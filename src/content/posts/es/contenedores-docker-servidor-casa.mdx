[Docker](https://www.docker.com/) empaqueta una app con su runtime para que corra igual en un mini PC, un VPS o un rack — por eso se convirtió en la forma por defecto de distribuir apps de home server en 2026. Esta página es un catálogo de los **mejores contenedores Docker para un home server** en 2026, no una checklist de "instálalo todo". Si aún estás sopesando si merece la pena una máquina en casa, empieza por [por qué necesitas un home server en 2026](/why-need-home-server/).

## Cómo usar esta página

1. **Elige un objetivo** en la tabla de abajo (medios, archivos, plano de control del lab, …).
2. **Instala el stack inicial corto** si eres nuevo.
3. **Abre una categoría** que te interese. Cada sección empieza con una **tabla de elecciones rápidas**, luego notas cortas sobre las herramientas importantes.
4. Salta el resto hasta que lo necesites.

Datos de versiones comprobados en **octubre de 2026** (feeds de releases actualizados el 14 de octubre de 2026). Donde un proyecto murió o quedó archivado este año, la sección lo dice en vez de listar silenciosamente un zombi.

### Qué ha cambiado en 2026 (corto)

- **El streaming remoto de Plex necesita un pase de pago** (en local sigue siendo gratis). El precio del Lifetime Pass para compradores nuevos volvió a subir en julio de 2026 (mira plex.tv para la cifra actual). Si no quieres pagar, **Jellyfin** es el cambio.
- **Filebrowser Quantum** es el fork activo del gestor de archivos (el original está solo en mantenimiento).
- **Watchtower (`containrrr`) está archivado** (diciembre de 2025). Usa el fork mantenido y migra si sigues en la imagen vieja.
- **El Overseerr original está archivado** (2026). **Jellyseerr** es ahora la UI de peticiones tanto para Plex como para Jellyfin.
- **Coolify / Dokploy**, **Gluetun**, **Dozzle** y **Pocket ID** son ya defaults habituales.

Más detalle en [Qué ha cambiado en 2026](#qué-ha-cambiado-en-2026) al final.

## Stack inicial (haz esto primero)

Este stack inicial es el conjunto de **contenedores Docker esenciales** que la mayoría de home servers necesitan. Si empiezas desde cero, este conjunto cubre streaming, descargas, archivos, dashboard, DNS, gestión y monitorización básica.

| # | Contenedor | Rol | Por qué | Detalles |
| --- | --- | --- | --- | --- |
| 1 | Dockge | Gestionar stacks Compose | Más fácil que la CLI a pelo | [Red](#contenedores-de-gestión-de-red) |
| 2 | AdGuard Home o Pi-hole | DNS + anuncios | Toda la red: [bloquea anuncios y malware con AdGuard Home](/block-ads-malware-dns-protection/) | [Red](#contenedores-de-gestión-de-red) |
| 3 | Homepage o Glance | Dashboard | Una URL para todo | [Dashboards](#contenedores-de-dashboards-personales) |
| 4 | Filebrowser Quantum | Archivos web | Subida rápida sin cloud completa | [Archivos](#contenedores-de-archivos-y-sincronización) |
| 5 | Jellyfin | Medios | Remoto gratis; sin impuesto Plex | [Medios](#contenedores-de-gestión-de-medios) |
| 6 | qBittorrent + Gluetun opcional | Descargas | VPN solo para el descargador | [Medios](#contenedores-de-gestión-de-medios) |
| 7 | CrowdSec | IPS | Bloquea atacantes ruidosos | [Seguridad](#contenedores-de-seguridad-y-privacidad) |
| 8 | Uptime Kuma + Dozzle + Beszel | Ops | ¿Arriba? ¿Por qué caído? ¿Logs? | [Monitorización](#contenedores-de-monitorización-y-analítica) |

**Orden que funciona:** Dockge → DNS → dashboard → archivos → medios → descargas → CrowdSec → monitorización.

**Hábito de verificación:** tras cada stack, `docker compose ps` debería mostrar el servicio `Up`, y añades una comprobación en Uptime Kuma. Si no está verde ahí, el stack no está terminado. Un servicio que solo funciona en la shell de tu portátil no está corriendo.

### Ejemplo mínimo de compose

Tres servicios para coger memoria muscular de Docker. Añade el resto como stacks separados en Dockge.

```yaml
services:
  adguardhome:
    image: adguard/adguardhome
    container_name: adguardhome
    ports:
      - "53:53/tcp"
      - "53:53/udp"
      - "3000:3000/tcp"
    volumes:
      - ./adguard/work:/opt/adguardhome/work
      - ./adguard/conf:/opt/adguardhome/conf
    restart: unless-stopped

  homepage:
    image: ghcr.io/gethomepage/homepage:latest
    container_name: homepage
    environment:
      - TZ=America/New_York
    volumes:
      - ./homepage-config:/app/config
      - /var/run/docker.sock:/var/run/docker.sock:ro
    ports:
      - "3001:3000"
    restart: unless-stopped

  dockge:
    image: louislam/dockge:1
    container_name: dockge
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      - ./dockge-data:/app/data
      - ./dockge-stacks:/opt/stacks
    ports:
      - "5001:5001"
    restart: unless-stopped
```

<ListCheck>
<ul>
<li>IP estática (o reserva DHCP) en el servidor</li>
<li>Archivos compose + muestras de env en Git</li>
<li>Datos en SSD; las librerías de medios pueden vivir en HDDs</li>
<li>Ningún puerto público sin reverse proxy + auth</li>
<li>Tras cada stack: `docker compose ps` en verde + una comprobación en Uptime Kuma</li>
</ul>

#### Servidores de medios

**Jellyfin ⭐** - [jellyfin.org](https://jellyfin.org/)
Gratis, open source, sin cuenta. Tras el paywall de Plex esta es la recomendación habitual para streaming remoto. Imagen: `jellyfin/jellyfin`. Guía: [self-host Jellyfin](/self-host-jellyfin/).

**Plex ⭐** - [plex.tv](https://www.plex.tv/)
Sigue teniendo los clientes más pulidos. **El streaming remoto es de pago** desde abril de 2025 (Plex Pass o Remote Watch Pass). En local en la LAN sigue gratis. El Lifetime Pass para compradores nuevos volvió a subir en julio de 2026 (mira plex.tv para el precio actual); los que ya tienen lifetime conservan el suyo. Imagen: `linuxserver/plex`.

| | Plex | Jellyfin | Emby |
| --- | --- | --- | --- |
| Remoto | De pago | Gratis | Gratis / extras premium |
| Open source | No | Sí | Parcial |
| Mejor si | Las apps más bonitas + presupuesto para el Pass | Remoto gratis + control | Ya estás en Emby |

Imagen de Emby: `emby/embyserver`.

#### Automatización *arr y descargas

**Prowlarr ⭐** - Configura los indexadores una vez; sincroniza con Sonarr/Radarr. Prefiere esto sobre Jackett para instalaciones nuevas. `linuxserver/prowlarr`

**Sonarr ⭐** / **Radarr ⭐** - TV y películas. `linuxserver/sonarr`, `linuxserver/radarr`

**qBittorrent ⭐** - Cliente torrent por defecto para *arr. Enrótalo a través de Gluetun. `linuxserver/qbittorrent`

**Gluetun ⭐** - Contenedor cliente VPN (40+ proveedores). Usa `network_mode: "service:gluetun"` para que solo las descargas salgan por VPN. `qmcgaw/gluetun` (el repo se movió a la org passteque; el nombre de imagen en Docker Hub no cambia)

**Bazarr ⭐** - Subtítulos para Sonarr/Radarr. `linuxserver/bazarr`

**Jellyseerr ⭐** - UI de peticiones para la familia. Este es el default para **tanto Plex como Jellyfin**: el Overseerr original (`sct/overseerr`) quedó archivado en 2026 y la imagen `linuxserver/overseerr` lleva rancia desde febrero de 2026. Las instalaciones nuevas deberían usar Jellyseerr, y los montajes existentes de Overseerr deberían planear una migración. Imagen: `fallenbagel/jellyseerr`.

**Audiobookshelf ⭐** - Audiolibros + podcasts con apps y sincronización de progreso. `advplyr/audiobookshelf`

**Navidrome ⭐** - Servidor de música compatible con Subsonic. Ligero en recursos, funciona con las apps móviles Subsonic habituales, y es la mitad que faltaba de un montaje de medios self-hosted si tu librería es principalmente música. Imagen: `deluan/navidrome`.

### Contenedores de archivos y sincronización

Reemplaza Dropbox/Google Drive, o simplemente pon una UI web sobre tus discos.

#### Elecciones rápidas

| Necesidad | Elección | Imagen |
| --- | --- | --- |
| Cloud personal completa | **Nextcloud** ⭐ | `nextcloud` |
| Sync rápido, librerías grandes | **Seafile** ⭐ | `seafileltd/seafile-mc` |
| Sync P2P entre dispositivos, sin servidor "cloud" | **Syncthing** ⭐ | `syncthing/syncthing` |

| Almacenamiento compatible con S3 | **RustFS** ⭐ | `rustfs/rustfs` |

**Nextcloud ⭐** - Cloud de todo incluido: archivos, calendario, contactos, oficina. Enorme ecosistema de apps; puede sentirse pesado en librerías grandes. `nextcloud`

**Seafile ⭐** - Normalmente mucho más rápido que Nextcloud. Compromiso: almacenamiento de bloques propietario en disco. `seafileltd/seafile-mc`

**Syncthing ⭐** - Sync cifrado peer-to-peer, sin cuenta central. El estable actual es v2.x (una reescritura mayor: config SQLite, mejor rendimiento); el nombre de la imagen no cambia, pero las guías anteriores a 2025 que describen el viejo layout de config están desactualizadas. `syncthing/syncthing`

**Filebrowser Quantum ⭐** - Fork activo del Filebrowser clásico (el original está solo en mantenimiento). Multi-fuente, OIDC/2FA, ya en estable 2.x. Instalaciones nuevas: usa Quantum. Imagen: `gtsteffaniak/filebrowser`. Notas más viejas: [Deploy Filebrowser](https://www.bitdoze.com/deploy-filebrowser-docker/).

**RustFS ⭐** - Almacenamiento de objetos compatible con S3 (estilo MinIO). Guía: [Self-host RustFS](https://www.bitdoze.com/rustfs-self-host/). `rustfs/rustfs`

**DNS:** AdGuard suele ser más fácil para instalaciones nuevas; Pi-hole tiene más guías. Prefiere un [firewall DNS en la nube como NextDNS](https://go.bitdoze.com/nextdns) si prefieres externalizar el filtrado por completo. Una precaución: Pi-hole v6 (desde febrero de 2025) dejó el viejo montaje de lighttpd. La mayoría de guías de Pi-hole anteriores a 2025 están desactualizadas.
**Remoto:** Tailscale para la mayoría; Headscale si quieres el plano de control self-hosted ([guía](https://www.bitdoze.com/headscale-self-hosted-tailscale-setup/)). NetBird cuando quieres OSS de extremo a extremo. Lado a lado: [NetBird vs Headscale vs Tailscale](/netbird-vs-headscale-vs-tailscale/).
**Proxy:** Caddy para Caddyfiles simples; NPM para click-ops; Traefik si te gustan los Docker labels ([Traefik reverse proxy en Docker](/traefik-proxy-docker/)).
**UI de Docker:** Dockge para Compose ([instalación](https://www.bitdoze.com/dockge-install/)); Portainer está bien pero compara [alternativas a Portainer](https://www.bitdoze.com/portainer-alternatives/) (Komodo multi-host, etc.). El desarrollo de Dockge es lento; Komodo es la elección activa si quieres gestión multi-host.

| Herramienta tipo VPN | Trabajo |
| --- | --- |
| Tailscale / NetBird | Mesh: *tú* llegas al lab |
| WireGuard Easy | VPN clásica + peers por QR |
| Gluetun | *Contenedores* salen por VPN comercial |
| Cloudflare Tunnel | Publica un servicio HTTP sin port forwards |
| Pangolin | Misma idea, self-hosted (túnel + acceso consciente de identidad) |

**Pangolin ⭐** - Reverse proxy tunelizado self-hosted con acceso consciente de identidad. La elección habitual cuando quieres publicación estilo Cloudflare Tunnel sin entregar el tráfico a un tercero. Guía de despliegue: [Pangolin: alternativa self-hosted a Cloudflare Tunnels](/pangolin-cloudflare-tunnels-alternative/).

Unbound (`mvance/unbound`) se empareja con Pi-hole como resolvedor recursivo si quieres eso.

<Accordion label="Buenas prácticas y resolución de problemas (expande cuando algo se rompa)" group="ops">

**Organización**
- Nombra los stacks con claridad (`media-sonarr`, no `app2`)
- Un stack compose por asunto
- Redes compartidas por grupo; archivos compose en Git

**Recursos**
- Límites de memoria en Immich, Nextcloud, BDs, LLMs
- Codificación por hardware para medios cuando puedas
- `docker stats` tras añadir servicios

**Seguridad**
- Solo imágenes de confianza; cuidado con el socket de Docker
- Secretos: [Compose secrets](https://www.bitdoze.com/docker-compose-secrets/), no contraseñas commiteadas
- Reverse proxy + SSO antes de cualquier cosa pública
- CrowdSec (o Fail2Ban) en el borde

**Actualizaciones**
- Watchtower (el fork mantenido) solo para apps de bajo riesgo; **nunca** auto-actualices bases de datos
- Fija las versiones mayores de BD (`postgres:18`). Las actualizaciones mayores necesitan `pg_upgrade`, no un bump de tag. Si Postgres se niega a arrancar tras un bump con un desajuste de versión del directorio de datos, el arreglo es `pg_upgrade` o una restauración desde backup, no un reinicio. Más detalle: [cómo actualizar un contenedor con Docker Compose](/updating-container-docker-compose/)
- Backups programados (Backrest / Kopia / Duplicati) y una restauración de prueba
- Dozzle + Uptime Kuma para muertes nocturnas

**Arreglos rápidos**
- Puertos: `docker ps` · Redes: `docker network ls`
- Conflictos: renombra contenedores, arregla bind mounts
- RAM: `docker stats`, luego límites o más hardware
- ¿El stack no arranca tras un bump de imagen? `git checkout` del pin anterior del compose y `docker compose up -d` de nuevo

</Accordion>

### Qué ha cambiado en 2026

- **El streaming remoto de Plex está bajo paywall** (desde abril de 2025). El precio del Lifetime Pass para compradores nuevos volvió a subir en julio de 2026. En local gratis; Jellyfin es el cambio sin pagar.
- **Watchtower (`containrrr`) está archivado** (diciembre de 2025). El fork mantenido es el default; migra desde la imagen vieja.
- **El Overseerr original está archivado** (2026). Jellyseerr es la UI de peticiones tanto para Plex como para Jellyfin.
- **Coolify** y **Dokploy** son las principales opciones de PaaS self-hosted.
- **Filebrowser Quantum** reemplazó al original en solo-mantenimiento (ahora estable 2.x).
- **Pocket ID**, **Gluetun**, **Dozzle**, **Karakeep**, **Dawarich**, **Actual Budget** son nuevos defaults habituales.
- Immich para fotos (estable desde v2.0, ya no beta), Valkey en lugar de Redis, Tailscale para acceso familiar siguen vigentes.

1. Stack inicial de arriba (Dockge → DNS → dashboard → archivos → medios)
2. Uptime Kuma + Dozzle

4. Backups antes de que los datos importen
