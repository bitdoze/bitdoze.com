## Qué es realmente Hermes Agent

Nous Research creó Hermes Agent como lo que ellos llaman un asistente de IA "auto-mejorable". Esa etiqueta es exacta. El agente observa lo que hace, extrae habilidades reutilizables de tareas complejas y refina esas habilidades la próxima vez que las ejecuta. La mayoría de los otros asistentes en esta categoría olvidan todo entre sesiones. Hermes lleva adelante lo que aprendió.

La arquitectura:

```
You (CLI / TUI / Telegram / Discord / Slack / WhatsApp / Signal / Email / Teams)
    ↓
Hermes Gateway (single process or Docker s6 supervision)
    ↓
AI Agent (session store, memory, skills, MCP, tools)
    ↓
LLM Provider (OpenRouter, Nous Portal, OpenAI, Anthropic, Ollama, custom)
    ↓
40+ Tools + MCP servers (terminal, web search, browser, files, code, TTS)
```

Los mensajes llegan desde cualquier plataforma que uses. El gateway los enruta a través de un almacén de sesiones por chat, el agente los procesa con acceso a más de 40 herramientas integradas, y todo se ejecuta desde un solo proceso. Sin microservicios, sin servidor de base de datos.

El ciclo de aprendizaje es lo que separa a Hermes de los otros tres. Después de pedirle a Hermes que haga algo complejo (por ejemplo, desplegar un servicio Docker), extrae ese flujo de trabajo en una habilidad. La próxima vez que pidas algo similar, usa y refina esa habilidad. La búsqueda de sesiones FTS5 significa que puede recordar detalles de conversaciones de hace semanas. Y el modo de voz en canales de voz de Discord es algo que ninguno de los otros proyectos ofrece.

OpenClaw todavía tiene la comunidad más grande, más dashboards de terceros y un historial más largo. Si OpenClaw ya te funciona, el comando de migración hace que cambiar sea indoloro cuando estés listo.

## Instalación

El instalador de una línea se encarga de Python, Node.js, dependencias y el comando `hermes`. Funciona en Linux, macOS, WSL2 y Windows nativo (PowerShell). Una instalación nueva aterriza en la última versión estable. Prefiere Docker Compose si quieres un gateway y un panel contenedorizados en un VPS.

<Tabs>
<Tab name="One-line install">

El método recomendado para instalaciones en máquina física o VPS.

```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
```

Después de que termine, recarga tu shell:

```bash
source ~/.bashrc   # or source ~/.zshrc
```

Verifica la instalación:

```bash
hermes --version
```

La versión estable actual es la v0.23.4 (23 de noviembre de 2026). Cualquier versión más antigua necesita `hermes update` (más abajo, [¿Cómo actualizo Hermes Agent?](#cómo-actualizo-hermes-agent)). Para añadir la app de escritorio sobre una instalación de solo CLI, ejecuta `hermes desktop` (macOS 13 o posterior en Apple Silicon, Windows 11 22H2 o posterior, Linux tras una instalación desde el código fuente). La app de escritorio es donde vive Bot Mode.

En Windows nativo (PowerShell):

```powershell
iex (irm https://hermes-agent.nousresearch.com/install.ps1)
```

</Tab>
<Tab name="Docker Compose">

La mejor opción para un VPS 24/7. La imagen oficial monta `~/.hermes` en `/opt/data` y ejecuta el gateway bajo la supervisión de s6.

```bash
mkdir -p ~/.hermes

# First-time setup wizard (writes API keys to ~/.hermes/.env)
docker run -it --rm \
  -v ~/.hermes:/opt/data \
  nousresearch/hermes-agent setup
```

Después crea un `docker-compose.yml` (o clona el [archivo del repo](https://github.com/NousResearch/hermes-agent/blob/main/docker-compose.yml)):

```yaml
services:
  hermes:
    image: nousresearch/hermes-agent:latest
    container_name: hermes
    restart: unless-stopped
    command: gateway run
    ports:
      - "8642:8642"   # gateway API
      - "9119:9119"   # dashboard (with HERMES_DASHBOARD=1)
    volumes:
      - ~/.hermes:/opt/data
    environment:
      - HERMES_DASHBOARD=1
      # Match host ownership of ~/.hermes (required on most VPS/NAS mounts)
      - HERMES_UID=${HERMES_UID:-1000}
      - HERMES_GID=${HERMES_GID:-1000}
      # Dashboard auth (required when bound beyond loopback)
      # - HERMES_DASHBOARD_BASIC_AUTH_USERNAME=admin
      # - HERMES_DASHBOARD_BASIC_AUTH_PASSWORD=change-me
      # Optional OpenAI-compatible API server (do not expose publicly without a key):
      # - API_SERVER_ENABLED=true
      # - API_SERVER_HOST=0.0.0.0
      # - API_SERVER_KEY=${API_SERVER_KEY}
    deploy:
      resources:
        limits:
          memory: 4G
          cpus: "2.0"
```

Inícialo:

```bash
export HERMES_UID="$(id -u)"
export HERMES_GID="$(id -g)"
docker compose up -d
docker compose logs -f
```

Abre el panel en `http://127.0.0.1:9119` (usa un túnel SSH para el acceso remoto: `ssh -L 9119:localhost:9119 user@your-server`). Establece `HERMES_DASHBOARD_HOST=127.0.0.1` para esa configuración. Sin ello el panel se enlaza a `0.0.0.0` dentro del contenedor y necesita un proveedor de autenticación, o se niega a arrancar.

Los detalles completos de Docker están en la [sección de Docker Compose](#despliegue-con-docker-compose) de abajo.

## Despliegue con Docker Compose

Ejecutar Hermes en Docker mantiene el árbol de instalación inmutable bajo `/opt/hermes` y guarda todo el estado del usuario (configuración, claves, sesiones, habilidades, memorias) en `~/.hermes` montado en `/opt/data`. Puedes actualizar descargando una imagen nueva sin perder la configuración. Las etiquetas `latest` y `stable` apuntan a la misma imagen validada por versión, y `main` a las compilaciones de desarrollo. Fija `X.Y.Z` o un digest cuando quieras un despliegue exacto.

El repo oficial incluye un [`docker-compose.yml`](https://github.com/NousResearch/hermes-agent/blob/main/docker-compose.yml) con servicios `gateway` y `dashboard` separados sobre la red del host. La documentación también muestra una disposición de un solo servicio con red bridge y puertos publicados. Ambas funcionan; elige según cómo quieras exponer el panel.

### Opción A: Servicio único (red bridge)

Simple y portable. Buena opción por defecto para la mayoría de VPS.

```bash
mkdir -p ~/.hermes

# One-time interactive setup
docker run -it --rm \
  -v ~/.hermes:/opt/data \
  nousresearch/hermes-agent setup
```

Crea `docker-compose.yml`:

```yaml
services:
  hermes:
    image: nousresearch/hermes-agent:latest
    container_name: hermes
    restart: unless-stopped
    command: gateway run
    ports:
      - "8642:8642"   # gateway OpenAI-compatible API + health
      - "9119:9119"   # web dashboard
    volumes:
      - ~/.hermes:/opt/data
    environment:
      - HERMES_DASHBOARD=1
      - HERMES_UID=${HERMES_UID:-1000}
      - HERMES_GID=${HERMES_GID:-1000}
      # Required when dashboard binds beyond loopback:
      # - HERMES_DASHBOARD_BASIC_AUTH_USERNAME=admin
      # - HERMES_DASHBOARD_BASIC_AUTH_PASSWORD=change-me
    deploy:
      resources:
        limits:
          memory: 4G
          cpus: "2.0"
```

```bash
export HERMES_UID="$(id -u)"
export HERMES_GID="$(id -g)"
docker compose up -d
```

### Opción B: Compose del repo oficial (red del host)

Coincide con el [`docker-compose.yml` upstream](https://github.com/NousResearch/hermes-agent/blob/main/docker-compose.yml). El gateway y el panel comparten la red y el espacio de nombres PID del host para que el panel pueda detectar si el gateway está vivo.

```bash
git clone https://github.com/NousResearch/hermes-agent.git
cd hermes-agent

mkdir -p ~/.hermes
# Run setup once if ~/.hermes is empty
docker run -it --rm -v ~/.hermes:/opt/data nousresearch/hermes-agent setup

export HERMES_UID="$(id -u)"
export HERMES_GID="$(id -g)"
docker compose up -d --build
```

Núcleo de ese archivo (abreviado):

```yaml
services:
  gateway:
    build: .
    image: hermes-agent
    container_name: hermes
    restart: unless-stopped
    network_mode: host
    volumes:
      - ~/.hermes:/opt/data
    environment:
      - HERMES_UID=${HERMES_UID:-10000}
      - HERMES_GID=${HERMES_GID:-10000}
      # Optional API server (needs a key if you bind beyond localhost):
      # - API_SERVER_HOST=0.0.0.0
      # - API_SERVER_KEY=${API_SERVER_KEY}
    command: ["gateway", "run"]

  dashboard:
    image: hermes-agent
    container_name: hermes-dashboard
    restart: unless-stopped
    network_mode: host
    depends_on:
      - gateway
    volumes:
      - ~/.hermes:/opt/data
    environment:
      - HERMES_UID=${HERMES_UID:-10000}
      - HERMES_GID=${HERMES_GID:-10000}
    # Localhost-only. For remote access: ssh -L 9119:localhost:9119 user@host
    command: ["dashboard", "--host", "127.0.0.1", "--no-open"]
```

### Comandos de Docker útiles

```bash
docker compose logs -f                  # Live logs
docker logs --tail 50 hermes            # Recent gateway output
docker exec hermes hermes gateway status
docker exec hermes hermes doctor
docker exec -it hermes hermes           # Interactive CLI against the same data dir
docker compose pull && docker compose up -d   # Upgrade image
```

El gateway también escribe sus logs en `~/.hermes/logs/gateways/<profile>/current` dentro del volumen del host, así que sobreviven a los reinicios del contenedor. Al actualizar, el contenedor ejecuta las migraciones del esquema de configuración contra el `config.yaml` montado antes de arrancar el gateway, y escribe primero copias con marca de tiempo de `config.yaml` y `.env`. Comprueba qué ejecutas con `docker exec hermes hermes --version`.

### Notas de seguridad de Docker

<Notice type="warning" title="No expongas el panel sin autenticación">
El panel integrado guarda API keys. Mantenlo en `127.0.0.1` y usa un túnel SSH, o ponlo detrás de autenticación (variables de entorno de basic auth, OAuth o un proxy inverso). `HERMES_DASHBOARD_INSECURE` es un no-op obsoleto; los enlaces fuera de loopback requieren un proveedor de autenticación real.
</Notice>

- Establece `HERMES_UID` / `HERMES_GID` (o `PUID` / `PGID`) al usuario del host que posee `~/.hermes` para que los archivos sigan siendo legibles después de que el contenedor renuncie a sus privilegios.
- Nunca ejecutes dos contenedores del gateway contra el mismo directorio `~/.hermes` a la vez (los archivos de sesiones y memoria no soportan varios escritores).
- Si activas el servidor de API compatible con OpenAI, establece `API_SERVER_KEY` (mínimo 8 caracteres) y no lo publiques en internet sin un proxy inverso.
- Para las herramientas de navegador (Playwright), añade `--shm-size=1g` o su equivalente en Compose bajo `shm_size: 1gb`.

### Dimensionamiento de recursos

| Recurso | Mínimo | Recomendado |
|---|---|---|
| Memoria | 1 GB | 2 a 4 GB |
| CPU | 1 núcleo | 2 núcleos |
| Disco (volumen de datos) | 500 MB | 2+ GB (crece con sesiones/habilidades) |

La automatización del navegador es la que consume memoria. Sin ella, 1 GB bastan. Con Playwright, reserva al menos 2 GB.

## ¿Cómo actualizo Hermes Agent?

Una instalación desde el código fuente se actualiza con `hermes update`. Una instalación Docker necesita `docker compose pull && docker compose up -d` con el mismo montaje de datos, y la Store y las apps empaquetadas se actualizan solas.

| Instalación | Método de actualización |
|---|---|
| Checkout del código fuente (el instalador de una línea) | `hermes update` |
| Docker | `docker compose pull && docker compose up -d` con el mismo montaje de datos |
| App de Microsoft Store | Se actualiza a través de la Store |
| App empaquetada de macOS | El control Update dentro de la app |

```bash
hermes update --check    # is there a new release? changes nothing
hermes update --plan     # the update plan: install kind, services, restarts
hermes update            # apply
hermes --version
```

Un checkout del código fuente sigue el canal estable: la última versión `vX.Y.Z` publicada, en su commit exacto. `hermes update --set-channel main` lo cambia a cada commit de `main`. Después del pull, Hermes reinicia los perfiles del gateway del home que actualizó e imprime una matriz de versiones por perfil. Si algún gateway sigue con código antiguo, la salida indica el comando exacto de reinicio. `hermes update --force` detiene todos los gateways a la vez en lugar de esperar a que terminen los turnos en curso, los cron jobs y los subagentes en segundo plano; úsalo cuando sea aceptable interrumpir ese trabajo.

**Actualiza cualquier versión anterior a la v0.23.2.** La v0.23.2 (16 de noviembre de 2026) corrigió GHSA-p22p-9ph6-gmrh (CVE-2026-130164, valoración High). Con Bot Desktop ejecutándose dentro de un backend de terminal `docker` o `ssh`, Hermes ahora valida y añade a una lista permitida el archivo de entorno de pantalla. Los valores procedentes de una pantalla alojada en el backend ya no se mezclan en los procesos que arrancan en la máquina del agente. Fuente: [notas de la versión v0.23.2](https://github.com/NousResearch/hermes-agent/releases/tag/v0.23.2).

La v0.23.2 también trajo subagentes duraderos. Un hijo arrancado con `delegate_task` conserva un registro duradero en el `state.db` del perfil, así que `continue` funciona tras un reinicio del gateway, un kill forzado o un fallo. El hijo mantiene su propia conversación. Nada se reanuda solo a menos que establezcas `delegation.auto_resume: true`; por defecto continúas el hijo a mano.

## Elegir un proveedor de modelos

Hermes es agnóstico respecto al proveedor. Los secretos van en `~/.hermes/.env`; los ajustes que no son secretos van en `~/.hermes/config.yaml`. El selector interactivo coloca cada valor en su sitio:

```bash
hermes model
```

En una instalación nueva, `hermes setup` hace una sola pregunta, "How do you want to power Hermes?", y luego aplica valores por defecto recomendados a todo lo demás. Tus opciones:

| Respuesta | Lo que obtienes |
|---|---|
| Free, start now | Sin cuenta ni API key. Funciona con el modelo gratuito `nous/welcome`. Se ofrece una vez por usuario del sistema operativo, nunca en un contenedor, CI o ejecución con script |
| Sign in to Nous Portal | Login OAuth, más de 300 modelos, Tool Gateway (búsqueda web, generación de imágenes, TTS, navegador en la nube) bajo una sola suscripción |
| Use my own API key or a subscription | El selector de `hermes model`: OpenRouter, Anthropic, OpenAI, modelos locales y el resto |
| Full Setup | Recorres tú cada proveedor, herramienta y opción |
| Blank Slate | Agente mínimo (solo archivos + terminal); activas herramientas más adelante |

```bash
hermes setup --portal   # Nous Portal + Tool Gateway in one shot
hermes setup            # first run: one question, then defaults
```

Si la configuración encuentra OpenClaw, Claude Code, Codex CLI o Cursor en la máquina, ofrece importar esa configuración antes de la pregunta.

<Notice type="info" title="Contexto mínimo: 64K tokens">
Hermes necesita un modelo con al menos **64,000 tokens** de contexto para las llamadas a herramientas en varios pasos. La mayoría de los modelos alojados lo cumplen. Para modelos locales (Ollama, llama.cpp), establece el contexto en al menos 64K (por ejemplo `-c 65536` o `--ctx-size 65536`).
</Notice>

Elecciones de proveedor habituales:

| Proveedor | Configuración | Notas |
|---|---|---|
| **Nous Portal** | `hermes setup --portal` | Una suscripción para modelos + herramientas |
| **OpenRouter** | API key + `openrouter/free` o un modelo de pago | Tier gratuito disponible; mira abajo |
| **Anthropic / OpenAI** | API key u OAuth con `hermes model` | Acceso directo al proveedor |
| **Ollama / vLLM / personalizado** | URL base del endpoint + nombre del modelo | Totalmente local o auto-alojado |
| **MiniMax, DeepSeek, xAI, Gemini, etc.** | Configúralos con `hermes model` | Catálogo amplio; mira la [documentación de proveedores](https://hermes-agent.nousresearch.com/docs/integrations/providers) |

Para modelos de producción baratos (MiniMax, MiMo, GLM y compañía), consulta nuestra guía de los [mejores modelos baratos para Hermes Agent](/es/mejores-modelos-baratos-hermes-agent/).

```bash

# or just:
hermes model
```

Cuando te pregunte por un proveedor, selecciona **OpenRouter** y pega tu clave.

**Configuración manual:**

Añade tu API key a `~/.hermes/.env`:

```bash
echo "OPENROUTER_API_KEY=sk-or-v1-your-key-here" >> ~/.hermes/.env
```

Establece el modelo en `~/.hermes/config.yaml`:

```yaml
model:
  provider: "openrouter"
  default: "openrouter/free"
```

El modelo `openrouter/free` enruta al mejor modelo gratuito disponible. También puedes establecerlo con:

```bash
hermes config set model openrouter/free
```

### Cambiar de modelo sobre la marcha

```bash
hermes model
```

O a mitad de conversación:

```
/model openrouter/free
```

### Usar modelos de pago más adelante

```bash
hermes config set model anthropic/claude-sonnet-4.6
# or
hermes config set model openai/gpt-5.4
```

OpenRouter se encarga del enrutamiento. Tu API key sigue siendo la misma.

## Primera conversación

Empieza a chatear (el CLI clásico o el TUI más reciente):

```bash
hermes          # classic CLI
hermes --tui    # modern TUI (modal overlays, mouse selection)
```

Verás un banner de bienvenida mostrando tu modelo, herramientas disponibles y habilidades. Escribe un mensaje y pulsa Enter:

```

```

Algunas cosas para probar de inmediato:

```
❯ What's my disk usage? Show the top 5 largest directories.
❯ Search the web for the latest Docker release and summarize it.
❯ Create a Python script that monitors CPU usage and alerts me above 80%.
```

El agente ejecuta comandos de terminal, busca en la web, lee y edita archivos, y ejecuta código. No se necesita configuración adicional.

## Sistema de memoria

Hermes tiene tres capas de memoria que funcionan juntas.

### MEMORY.md: las notas del propio agente

El agente escribe sus propias notas sobre tu entorno, convenciones y cosas que aprendió. Se almacena en `~/.hermes/memories/MEMORY.md`. Limitado a 2,200 caracteres (~800 tokens) para mantener acotado el system prompt.

El agente gestiona esto automáticamente. Cuando descubre que tu servidor ejecuta Ubuntu 22.04 con Docker instalado, lo guarda. Cuando aprende que prefieres respuestas concisas, también lo guarda. No necesitas decirle que recuerde; observa datos útiles y los almacena.

### USER.md: tu perfil

Información sobre ti: nombre, preferencias, estilo de comunicación, zona horaria. Se almacena en `~/.hermes/memories/USER.md`. Limitado a 1,375 caracteres (~500 tokens).

### Búsqueda de sesiones

Más allá de los dos archivos markdown, Hermes almacena todas las conversaciones pasadas en SQLite con búsqueda de texto completo FTS5. Puede buscar entre semanas de conversaciones antiguas para encontrar algo que discutiste antes:

```
❯ What did we discuss about the Nginx configuration last week?
```

El agente busca en su historial de sesiones, resume las partes relevantes y te da la respuesta. Ningún otro asistente de la familia OpenClaw hace esto.

### Configurar la memoria

En `~/.hermes/config.yaml`:

```yaml
memory:
  memory_enabled: true
  user_profile_enabled: true
  memory_char_limit: 2200
  user_char_limit: 1375
```

Tres cosas que conviene saber. Un dato guardado en la sesión actual es visible para la siguiente sesión, no para una que ya está en ejecución, así que inicia una sesión nueva (`/new`) después de una escritura importante. En plataformas de mensajería el chat es una sola sesión larga que sobrevive a los reinicios, así que ejecuta `/new` en límites naturales o la compactación procesa un historial cada vez más largo en cada turno. Y la memoria es por perfil: `hermes -p work` lee `~/.hermes/profiles/work/memories/`, lo que importa en cuanto tienes varios Bots. Comprueba un guardado con `cat ~/.hermes/memories/MEMORY.md`; "lo recordaré" es solo texto hasta que la herramienta `memory` se ha ejecutado.

<Notice type="info" title="Pasa a memoria basada en vectores">
Hermes puede usar [Hindsight](/es/desplegar-hindsight-docker/) como backend de memoria en lugar de MEMORY.md y la búsqueda de sesiones integrados. Hindsight guarda las memorias como embeddings vectoriales con extracción de entidades. Mira la [integración con Hindsight](https://hindsight.vectorize.io/integrations) para los detalles de configuración.
</Notice>

## Sistema de habilidades

Esta es la funcionalidad a la que sigo volviendo. Las habilidades no son plugins preconstruidos que instalas desde un hub. El agente las crea a partir de tareas que completa.

### Cómo funciona la creación de habilidades

1. Le pides a Hermes que haga algo complejo (desplegar un servicio, configurar un pipeline de CI, configurar Nginx)
2. Hermes completa la tarea usando sus herramientas
3. Después de terminar, extrae el flujo de trabajo en una habilidad reutilizable
4. La próxima vez que pidas algo similar, usa y refina esa habilidad

Las habilidades también se auto-mejoran. Cada vez que una se ejecuta, el agente verifica si los pasos podrían ser mejores y actualiza la habilidad si es así.

El agente hace esto con su herramienta `skill_manage`. Establece `skills.write_approval: true` en `config.yaml` para retener a revisión las escrituras de habilidades hechas fuera del CLI interactivo antes de que se apliquen. Una revisión en segundo plano después de una sesión también puede sugerir cambios en habilidades; `auxiliary.background_review` dirige esa revisión a un modelo más barato.

### Buscar e instalar habilidades de la comunidad

```bash
hermes skills browse                          # list hub skills
hermes skills search react --source skills-sh
hermes skills inspect official/security/1password
hermes skills install official/mcp/fastmcp    # security scan runs first
```

Las habilidades instaladas se convierten automáticamente en comandos slash. O usa `/skills` dentro del chat.

```bash
hermes skills check      # audit installed skills
hermes skills update     # update hub-installed skills
```

### Skills Hub

Las habilidades siguen el estándar abierto agentskills.io, y el hub recoge de varias fuentes: habilidades oficiales opcionales, skills.sh, ClawHub, LobeHub, repos de GitHub directos y URLs sin más. El system prompt lista cada habilidad como `name: description`, y cada fila muestra por defecto los primeros 60 caracteres. Si tus habilidades dejan sus frases disparadoras más allá del carácter 60, sube `skills.index_desc_limit` (rango aceptado de 60 a 1024). Para ejemplos de habilidades bien hechas, mira mi comparación de las [mejores skills de IA para diseño web](/es/mejores-skills-ia-diseno-web/).

## Servidores MCP

Hermes puede cargar servidores [Model Context Protocol](https://modelcontextprotocol.io/) para que el agente gane herramientas externas (GitHub, bases de datos, navegadores y más) sin código a medida.

Añádelos en `~/.hermes/config.yaml`:

```yaml
mcp_servers:
  github:
    command: npx
    args: ["-y", "@modelcontextprotocol/server-github"]
    env:
      GITHUB_PERSONAL_ACCESS_TOKEN: "ghp_your_token"
```

Reinicia el CLI o el gateway después de editar. Mantén los tokens en `.env` cuando sea posible y pon solo el cableado no secreto en `config.yaml`.

## Panel web integrado

Hermes incluye un panel web (puerto 9119 por defecto) para configuración, sesiones y ajustes del proveedor. En Docker, actívalo con `HERMES_DASHBOARD=1` (mira [Docker Compose](#despliegue-con-docker-compose)). En una instalación sin Docker:

```bash
hermes dashboard
# or bind loopback only for remote SSH tunnels:
hermes dashboard --host 127.0.0.1 --no-open
```

El panel se enlaza a `127.0.0.1` por defecto. Cualquier otro enlace activa la barrera de autenticación, y falla cerrado: sin un proveedor registrado, `hermes dashboard` se niega a enlazarse. Incluye tres proveedores: usuario/contraseña (solo LAN de confianza o VPN), OAuth a través de Nous Portal (el que hay que usar para un panel expuesto a internet) y OIDC auto-alojado. `hermes dashboard password` establece el usuario y la contraseña sin preguntar en la terminal. El flag antiguo `--insecure` es un no-op obsoleto. Para un repaso más a fondo de la interfaz integrada y las opciones de terceros, consulta la [guía del panel de Hermes](/es/guia-panel-hermes/) y los [mejores paneles para Hermes](/es/mejores-paneles-hermes/).

La v0.23.4 añadió `hermes gateway migrate --backends`, que mueve al gateway un backend de `hermes dashboard` o `hermes serve` ejecutado a mano, para que la Webapp del gateway sirva la dirección antigua. Empieza con el plan:

```bash
hermes gateway migrate --backends --apply --dry-run   # plan and blockers, changes nothing
hermes gateway migrate --backends --apply             # migrate (asks unless you pass --yes)
hermes gateway migrate --backends --restore           # undo a finished migration
hermes webapp --status
```

Dentro de un contenedor Docker sale con código 6 e imprime los pasos manuales, porque no edita tu archivo Compose. La página System del panel tiene una tarjeta para el mismo movimiento.

`hermes serve` es el mismo servidor sin la interfaz del navegador, en el mismo puerto 9119, y es a lo que se conecta Hermes Desktop cuando el backend se ejecuta en otra máquina.

### Ejecutar el gateway como servicio

En un VPS, quieres que el gateway se ejecute al arrancar:

```bash
# Install as a systemd service
hermes gateway install

# Start it
hermes gateway start

# Check status
hermes gateway status

# View logs
journalctl --user -u hermes-gateway -f

# Enable lingering so it survives logout
sudo loginctl enable-linger $USER
```

En un VPS sin interfaz gráfica, usa el servicio del sistema en su lugar:

```bash
sudo hermes gateway install --system
sudo hermes gateway start --system
```

`hermes gateway list` muestra cada perfil y si su gateway está en ejecución. `--all` en `start`, `restart` y `stop` actúa sobre el gateway de cada perfil, lo que importa en cuanto ejecutas varios Bots. `stop` y `restart` listan los turnos en curso, cron jobs y delegaciones que interrumpirían y preguntan primero; sin terminal se niegan a menos que pases `--yes`.


## Backends de terminal

Por defecto, Hermes ejecuta comandos directamente en tu máquina. Por seguridad, puedes aislar la ejecución de comandos en un contenedor o enviarla a un servidor remoto.

```yaml
# In ~/.hermes/config.yaml
terminal:
  backend: local    # or: docker, ssh, modal, daytona, vercel_sandbox, or a plugin backend
  timeout: 180
```

| Backend | Qué hace | Ideal para |
|---|---|---|
| `local` | Ejecuta en tu máquina (por defecto) | Desarrollo, tareas confiables |
| `docker` | Contenedores aislados | Seguridad, reproducibilidad |
| `ssh` | Servidor remoto | Mantener al agente lejos de su propio código |
| `daytona` | Workspace sandbox en la nube | Entornos de desarrollo remotos persistentes |
| `modal` | Serverless en la nube | Escalar a cero, pago por uso |
| `vercel_sandbox` | MicroVM de Vercel Sandbox en la nube | Ejecución en la nube con persistencia de archivos basada en instantáneas |
| `singularity`, `sprites` | Backends de plugin: contenedores HPC, un sandbox de Fly.io | `hermes plugins install singularity` |

Singularity salió del núcleo y pasó a ser un plugin oficial. `hermes update` lo instala en los perfiles que ya lo usan; el resto ejecuta `hermes plugins install singularity`. El backend de terminal es por perfil, así que un Bot puede ejecutarse en un contenedor mientras el perfil por defecto se queda en `local`.

### Aislamiento con Docker

```yaml
terminal:
  backend: docker
  docker_image: python:3.11-slim
  container_cpu: 1
  container_memory: 5120
  container_disk: 51200
  container_persistent: true
```

Los contenedores se ejecutan con un sistema de archivos raíz de solo lectura, todas las capacidades de Linux eliminadas, sin escalación de privilegios, límites de PID y aislamiento de namespaces.

### Backend SSH

Ejecuta comandos en una máquina completamente separada:

```yaml
terminal:
  backend: ssh
```

```bash
# In ~/.hermes/.env
TERMINAL_SSH_HOST=my-server.example.com
TERMINAL_SSH_USER=myuser
TERMINAL_SSH_KEY=~/.ssh/id_rsa
```

## Modo de voz

Hermes tiene soporte de voz en CLI y mensajería. Puedes hablarle con tu micrófono en la terminal, obtener respuestas habladas en Telegram y Discord, y tener conversaciones de voz en vivo en canales de voz de Discord.

### Prerrequisitos

```bash
# System dependencies (Ubuntu/Debian)
sudo apt install portaudio19-dev ffmpeg libopus0
sudo apt install espeak-ng   # only for the local NeuTTS engine
```

Elige los proveedores de voz a texto y TTS con `hermes tools`; descarga los requisitos integrados que falten. El extra `voice` cubre el audio del CLI y, donde está soportado, Faster-Whisper local, así que la transcripción local no necesita API key. No uses pip para instalar dentro de la app de escritorio empaquetada. Faster-Whisper local queda excluido en Windows ARM64 nativo y macOS Intel; allí usa un proveedor en la nube.

### Modo de voz en CLI

Inicia el CLI y activa la voz:

```bash
hermes
/voice on
```

Pulsa `Ctrl+B` para grabar. Habla, y cuando pares, detecta automáticamente el silencio después de 3 segundos y transcribe tu audio. Si TTS está habilitado (`/voice tts`), el agente pronuncia su respuesta.

### Respuestas de voz en mensajería

En Telegram o Discord, envía:

```
/voice tts
```

El agente ahora envía audio hablado junto con texto en cada respuesta.

### Canales de voz de Discord

El agente puede unirse a un canal de voz de Discord, escucharte hablar y responder con audio hablado:

```
/voice join
```

Esto requiere permisos adicionales del bot de Discord (Connect, Speak, Use Voice Activity) y el códec Opus en tu servidor.

La URL de invitación de la pestaña de Discord lleva permisos de solo texto. Para voz, vuelve a invitar con `permissions=309240908864` (añade Connect y Speak).

### Proveedores de TTS

| Proveedor | Coste | Calidad | Configuración |
|---|---|---|---|
| Edge TTS | Gratis | Buena | Funciona de serie |
| NeuTTS | Gratis | Buena | Runtime opcional aparte, necesita `espeak-ng`; descarga modelos en el primer uso |
| ElevenLabs | De pago | Premium | Establecer `ELEVENLABS_API_KEY` |
| OpenAI TTS | De pago | Buena | Establecer `VOICE_TOOLS_OPENAI_KEY` |

Configura en `~/.hermes/config.yaml`:

```yaml
tts:
  provider: "edge"
  edge:
    voice: "en-US-AriaNeural"

stt:
  provider: "local"
  local:
    model: "base"
```

## Tareas programadas

Hermes tiene un programador cron integrado. Solo dile lo que quieres en lenguaje normal:

```
❯ Every morning at 9am, check Hacker News for AI news and send me a summary on Telegram.
❯ Every Friday at 5pm, back up the PostgreSQL database and report the size.
❯ Every hour, check if nginx is running and restart it if not.
```

El agente crea cron jobs que se ejecutan a través del gateway. Los resultados llegan a la plataforma que hayas configurado.

Desde una shell:

```bash
hermes cron list                                   # every job, with its pinned model and time zone
hermes cron create "every 2h" "Check server status"
hermes cron edit <job_id> --pin                    # lock the current main model onto one job
hermes cron edit <job_id> --deliver telegram       # send the output somewhere
```

El modelo con el que se ejecuta un job se resuelve en el momento del disparo: primero el pin del propio job, luego `cron.model` en `config.yaml` y después el modelo del agente principal. Fija un modelo barato en los jobs rutinarios para que cambiar el modelo de chat nunca altere lo que cuesta una comprobación de las 3 de la mañana. Desde la v0.23.2 un job puede ejecutarse en un hilo nuevo en cada pasada y desactivar la envoltura de entrega (`wrap_response`), así que un informe llega sin la cabecera. Los jobs de solo script se saltan el modelo por completo. Un script se ejecuta según su programación y su stdout sale tal cual.

## Migrar desde OpenClaw y otros agentes

`hermes import-agent` importa una configuración existente de OpenClaw, Claude Code, Codex CLI, Cursor, Grok Bot u OpenBot. Primero ves un plan por elemento, y `--dry-run` no escribe nada. El comando viene en el plugin oficial `agent-importers`.

**Durante la primera configuración:** en una instalación nueva, `hermes setup` busca `~/.openclaw`, `~/.claude`, `~/.codex` y `~/.cursor` (más las apps de Grok Bot y OpenBot) antes que nada y pregunta si quieres importar. Para OpenClaw pasa `--migrate-secrets`, así que las claves y los tokens de bot vienen con él, igual que hacía el paso integrado antiguo.

**En cualquier momento después de instalar:**

```bash
hermes migrate                                # detect what is on this machine and offer to import
hermes migrate openclaw                       # force one: openclaw, claude-code, codex, cursor, grok-bot, openbot
hermes migrate openclaw --migrate-secrets     # OpenClaw API keys and bot tokens come over only with this flag
hermes import-agent openclaw --dry-run        # the underlying command
hermes import-agent --sync                    # re-import Claude Code, Codex and Cursor sources that changed
```

`hermes claw migrate` sigue funcionando. Es la grafía antigua de `hermes import-agent openclaw`. Ambos necesitan el plugin; sin él imprimen la línea de instalación (`hermes plugins install agent-importers`).

Lo que cubre la importación desde OpenClaw:
- SOUL.md, MEMORY.md, USER.md y AGENTS.md
- Habilidades de cuatro directorios de origen
- Modelo por defecto, proveedores personalizados y servidores MCP
- Tokens de plataformas de mensajería y listas de permitidos (Telegram, Discord, Slack, WhatsApp, Signal, Matrix, Mattermost)
- Reglas de aprobación, lista de comandos permitidos y valores por defecto del agente
- Ajustes de TTS, navegador y herramientas
- API keys, pero solo con `--migrate-secrets`

El importador se salta los cron jobs, plugins, hooks y el backend de memoria, y los archiva para revisión manual. Escribe un zip premigración de `~/.hermes/` bajo `~/.hermes/backups/` antes de aplicar nada. Para los otros agentes, convierte instrucciones y reglas en entradas de memoria, las reglas de permiso en `command_allowlist`, coloca los servidores MCP en `mcp_servers` y copia las habilidades. Las credenciales que no son de OpenClaw nunca vienen con él.

## Solución de problemas

Cuando algo va mal, ejecuta esta secuencia antes de añadir más funciones:

```bash
hermes doctor           # Config / env / dependency checks
hermes model            # Re-select provider and model
hermes setup            # Re-run wizard if needed
hermes sessions list    # Confirm sessions and profile
hermes --continue       # Resume last chat
hermes gateway status   # Messaging gateway health
```

| Síntoma | Causa probable | Solución |
|---|---|---|
| Respuestas vacías o rotas | Autenticación del proveedor o modelo incorrectos | `hermes model` y volver a autenticar |
| Un endpoint personalizado devuelve basura | URL base o nombre de modelo equivocados | Prueba el endpoint fuera de Hermes primero |
| El gateway arranca pero no llegan mensajes | Token, lista de permitidos o configuración de la plataforma | `hermes gateway setup` + `hermes gateway status` |
| `--continue` no encuentra nada | Otro perfil o sesión sin guardar | `hermes sessions list` |
| Errores de permisos de Docker en `~/.hermes` | UID/GID no coinciden | Establece `HERMES_UID` / `HERMES_GID` al propietario del host |
| El panel falla al enlazarse en una dirección pública | Se requiere autenticación | Variables de entorno de basic auth, OAuth, o enlaza a `127.0.0.1` |
| No se encuentra `hermes cron` ni `hermes peer` | La instalación es anterior a la v0.23 | `hermes update`, y confirma con `hermes --version` |
| No hay herramienta `message_agent` en el chat de un Bot | Una instalación sin interfaz nunca escribió el Bot Chat ni el marcador del plantel | Sigue los pasos para VPS sin interfaz bajo Bot Mode |

## Cómo se diferencia Hermes Agent de OpenClaw

He usado ambos extensamente. Estas son las diferencias que realmente importan en el día a día:

**El ciclo de aprendizaje cambia tu forma de trabajar con él.** En OpenClaw, cada tarea compleja empieza desde cero. En Hermes, una vez que has guiado al agente a través del despliegue de un servicio Docker, crea una habilidad para ese flujo de trabajo. La próxima vez que digas "despliega la API de staging", ya conoce los pasos.

**La búsqueda de sesiones le da memoria a largo plazo.** La memoria de OpenClaw está limitada a lo que cabe en sus archivos de contexto. Hermes almacena cada conversación en SQLite con búsqueda de texto completo. Pregunta "¿en qué puerto configuramos Redis el mes pasado?" y encuentra la respuesta en sesiones antiguas.

**El sistema de personalidad es más estructurado.** OpenClaw usa un system prompt que editas a mano. Hermes tiene SOUL.md como archivo de identidad duradero, capas de `/personality` a nivel de sesión y 14 presets integrados.

**El modo de voz funciona de extremo a extremo.** Entrada de micrófono en el CLI, respuestas TTS en mensajería y conversaciones en vivo en canales de voz de Discord. Nada más en la familia OpenClaw hace esto.

**Aislamiento del backend de terminal.** OpenClaw ejecuta comandos en tu máquina local. Hermes puede ejecutarlos en contenedores Docker, en servidores remotos vía SSH o en entornos serverless como Modal y Daytona. Si el agente rompe algo, rompe el sandbox, no tu servidor.

**La migración es indolora.** `hermes migrate openclaw` trae memorias, habilidades, configuraciones de plataforma y API keys si añades `--migrate-secrets`. No empiezas de cero.

**Donde OpenClaw todavía gana:** comunidad más grande, más dashboards y skins de terceros, historial más largo. Si quieres la opción más probada en batalla, OpenClaw sigue siendo la elegida.

Si prefieres un plantel de bots a un único agente que aprende, [Bot Mode](#bot-mode-un-plantel-de-bots-especializados) te lo da dentro de Hermes Desktop. Para alternativas de apps de chat independientes más cercanas al Grok Bot de xAI, consulta nuestras [alternativas open source a Grok Bot](/es/mejores-alternativas-grok-bot-open-source/). Hermes está en esa lista junto a Rakazo, OpenMausBot y OpenBot.

## Bot Mode: un plantel de bots especializados

Bot Mode convierte los perfiles de Hermes en un plantel de Bots con nombre. Cada Bot tiene su propio rol, modelo, memoria, habilidades y avatar. Los Bots ejecutan rutinas recurrentes, deliberan en chats de grupo y se envían mensajes directamente. Viene dentro de Hermes Desktop y está activado por defecto en las compilaciones actuales (comprobado en la v0.23.4). El antiguo repo del plugin independiente `Hermes-Bot-Mode` está archivado; no lo instales.

Si lo único que quieres es un asistente que aprende, sáltate esta sección. Si sigues deseando un investigador, un revisor y un bot de guardia en lugar de un chat largo, sigue leyendo.

### Un Bot es un perfil

No hay ninguna primitiva nueva. Un Bot es un perfil de Hermes: configuración, memoria, habilidades, credenciales e historial de chat aislados bajo `~/.hermes/profiles/<name>/`. Bot Mode es una interfaz sobre eso, así que todo lo que hace es visible desde el CLI. `hermes -p <bot> chat` abre el mismo agente, y las rutinas de los Bots aparecen en `hermes cron list`. Sin parches en el núcleo, sin demonios extra.

Lo que Bot Mode añade sobre un perfil normal:

- Un **Bot Chat** permanente por Bot. Haz clic en el Bot y vuelves a la misma conversación. `/new` (o `/reset`) dentro de un Bot Chat se redirige a `/compact`: contexto de trabajo nuevo, misma conversación.
- Todos los Bots en un solo plantel con avatar, último mensaje y estado de no leído.
- Los Bots se envían mensajes y comparten chats de grupo.
- Las rutinas de cada Bot se programan y se editan junto a su chat.

No confundas cuatro términos. Un perfil es el hogar persistente. Un Bot es un perfil que se muestra en el plantel. Un bot de mensajería es una cuenta de plataforma (Telegram, Discord, Slack) conectada a través del gateway. Un subagente es un hijo generado por `delegate_task` con una conversación nueva.

### Crear un Bot

En la app de escritorio, abre la pestaña Bots y pulsa **New Agent**. El camino rápido son tres campos (Name, Title, Description). El Bot existe en segundos y se presenta en su Bot Chat.

Las opciones de **Advanced**:

| Opción | Qué hace |
|---|---|
| Clonar desde un perfil existente | Partir de la configuración, habilidades, SOUL y memoria de otro Bot, o elegir Fresh profile |
| Create empty | Saltarse las habilidades empaquetadas |
| Fijar modelo y proveedor | Cualquier pareja proveedor/modelo que Hermes conozca. Bots distintos pueden ejecutar modelos distintos a la vez. Sin fijar, hereda del perfil de arranque |
| SOUL.md personalizado | La persona del Bot y sus instrucciones permanentes |
| Activación por habilidad, por conjunto de herramientas y por servidor MCP | Marca solo lo que este especialista necesita |
| Copiar API keys del perfil principal | Activado por defecto. Las API keys estáticas se copian |

La copia tiene un hueco con el que tropezarás en un VPS. Los logins OAuth de un solo uso (Anthropic, OpenAI Codex, xAI) no se copian, porque una copia de un refresh token de un solo uso es la misma credencial con dos dueños. Inicia sesión en el Bot a mano:

```bash
hermes -p <bot> auth add <provider>
```

Haz clic derecho en un Bot para **Edit Profile**, **Duplicate** (un clon completo, memoria incluida) y **Delete Profile** (permanente; el perfil por defecto no se puede borrar). Con más de una conexión registrada en Settings, Gateways, un selector **Create on** te permite crear el Bot en el backend de otra máquina.

### Las rutinas son cron jobs

Una rutina es una tarea recurrente adjunta al Bot que la ejecuta. El selector de programación construye la programación, y un campo Advanced acepta la cadena de programación de Hermes en crudo. En el fondo una rutina es un cron job normal llamado `[bot:<name>] <routine>`. Aparece en `hermes cron list` y en la página Cron del panel, y las ejecuciones caen en el propio historial de chat del Bot.

### Chats de grupo

Haz clic derecho en un Bot local, **Manage groups**, o **New Group Chat**. Una sala admite de 2 a 6 Bots.

- Tu mensaje dispara hasta tres rondas en serie de turnos de los miembros. Los Bots mencionados con @ responden; cuando no se menciona a nadie, responden todos. La sala se asienta cuando una ronda completa queda en silencio.
- Límites duros: 10 mensajes por envío y 3 rondas. En una sala propiedad de un gateway el límite pausa la discusión ("Paused after N messages") con **Continue** (un presupuesto más, hasta 5 veces) y **Stop**.
- Los Bots se incorporan entre sí con `@name` y te escalan a ti las decisiones de criterio con `@user`. La fila del grupo muestra una insignia de "te necesita". `@hermes` pasa el turno al Bot principal.
- Un Bot habla solo cuando tiene algo nuevo que aportar. No todos los Bots responden a cada mensaje.
- Quién responde a un mensaje que no nombra a nadie es una elección en los ajustes de la sala: Everyone (por defecto), un líder que pasa el mensaje, o "Pick who answers automatically". La elección automática cuesta una llamada corta a un modelo sin herramientas por mensaje; dirígela a un modelo barato con `auxiliary.group_router` (`hermes model`, auxiliary, Group router).
- El turno de cada miembro incluye todos los mensajes de la sala desde su propio último turno, hasta unos 200 mensajes o 32,000 caracteres. Cuando un miembro empieza a responder con respuestas vacías, **Compress history** en los ajustes del grupo ejecuta la misma compactación que `/compress` sobre la sesión oculta de sala de ese miembro.

Las salas propiedad de un gateway siguen funcionando con Desktop cerrado. Un chat de grupo puede abarcar varias máquinas. Cada sala nueva pertenece al gateway de la conexión activa, y los Bots de otros ordenadores se unen a través de sus propios gateways (solo texto para los miembros remotos).

### Mensajes entre bots

En cualquier chat, escribe `@researcher have a look at this`. El Bot activo compone su propio mensaje y lo envía con la herramienta `message_agent`; tu texto nunca se reenvía tal cual. Cada Bot Chat lleva `message_agent`, por ejemplo `message_agent(target="researcher", message="...")`. El destino puede ser un nombre de perfil, un nombre amistoso (`hermes profile rename` o el título de Bot Mode) o una etiqueta @. `@hermes` siempre significa el Bot principal. El plantel de compañeros (nombres y roles a partir del título y la descripción de cada perfil) forma parte del system prompt de cada Bot Chat.

La entrega es de tipo fire-and-forget. El remitente recibe `status: queued` y un `delivery_id`, que significa entregado en mano, no respondido. La notificación de finalización trae después una frase de resultado por destino (`@beta answered.` o `@gamma never answered: <why>`).

No hay interrupción en vivo. El Bot receptor recoge el mensaje en su siguiente turno. Ese turno es el siguiente turno de un Bot Chat abierto en Desktop o en el TUI, o un turno silencioso del CLI cuando no hay ningún chat abierto. Para trabajo que tiene que informar de vuelta a la conversación actual, usa un subagente (`delegate_task`), no un mensaje directo a un Bot.

El guarda de bucles impide que dos Bots se mantengan ocupados entre sí para siempre. Una respuesta al Bot que le escribió es solo de notificación, y pasadas las `gateway.bot_loop_guard.max_hops` (4 por defecto) una nueva llamada se rechaza. Enviar el mismo mensaje al mismo compañero dos veces en un intercambio también se rechaza.

```yaml
# ~/.hermes/config.yaml
gateway:
  bot_loop_guard:
    max_hops: 4                       # bot-to-bot messages per exchange
    bot_replies_expect_reply: false   # true: a Bot's reply to a Bot may be answered
```

Un turno de entrega fallido se reintenta como mucho una vez, y solo por fallos transitorios (runtime del destino apagado, tiempo de espera de entrega agotado, límite de tasa o error de servidor del proveedor, desbordamiento de contexto). Los fallos de autenticación, cuota y configuración nunca se reintentan solos. Los fallos llevan un código de motivo tipado: `provider_auth_or_access`, `provider_quota_limit`, `provider_rate_limit`, `provider_server_error`, `context_overflow`, `missing_config`, `model_unavailable`, `runtime_offline`, `queued_expired`, `delivery_timeout`, `target_busy` o `unknown`. La notificación de finalización va etiquetada con `[reason: <code>]`, así que "vuelve a iniciar sesión" y "espera y reintenta" se ven distintos tanto para el Bot como para ti.

### Bot Mode en un VPS sin interfaz

Esta es la parte que las capturas de escritorio no te cuentan. La interfaz del plantel es la app de escritorio. En un VPS con solo el gateway y Telegram nada dibuja un plantel, y falta una herramienta: `message_agent` existe solo en sesiones canónicas de Bot Chat en instalaciones gestionadas por Bot Mode. Los chats normales, las sesiones de miembros de sala de grupo y las sesiones del CLI nunca la ven.

Un chat cuenta como Bot Chat solo cuando hay dos marcadores:

1. La sesión se titula exactamente `Bot Chat`.
2. Al menos un perfil de la instalación lleva un bloque `ui_meta: { hermes-bots: ... }` en su `profile.yaml`.

En una instalación de escritorio el panel de Bots escribe ambos. No hay ningún comando del CLI que escriba el segundo, así que en una máquina sin interfaz lo escribes a mano. Crea primero el perfil y su chat permanente (las ejecuciones posteriores lo reanudan):

```bash
hermes profile create researcher
hermes -p researcher model            # pick this Bot's model
hermes -p researcher chat -c "Bot Chat" --create-if-missing
```

Después añade el marcador al `profile.yaml` de cualquier Bot:

```yaml
# ~/.hermes/profiles/researcher/profile.yaml : an empty block marks the whole install
ui_meta:
  hermes-bots: {}
```

A partir del siguiente turno en ese Bot Chat, la sesión recoge el plantel de compañeros, la sección del protocolo y `message_agent`, incluso con `hermes -p <bot> chat` en una máquina de solo terminal. El interruptor maestro es `agent.bot_mode_protocol` (`true` por defecto); déjalo activado.

Para comprobarlo, vuelve a abrir el chat con `hermes -p researcher chat -c "Bot Chat"` y pregunta a qué compañeros puede enviar mensajes. Un Bot Chat que recibió el protocolo lista el plantel construido a partir de los títulos y descripciones de los otros perfiles; una sesión normal dice que no tiene esa herramienta. El camino del marcador escrito a mano no está probado aquí; las dos condiciones salen de la documentación de Bot Mode.

Para el plantel en sí, ejecuta Hermes Desktop en tu portátil y apúntalo al VPS: Settings, Gateways y luego Remote gateway (un backend `hermes serve`), SSH o Hermes Cloud. No hay una descarga de Desktop solo remota; instala el paquete y conéctate desde Settings. Un backend fuera de loopback necesita un proveedor de autenticación, y OAuth a través de Nous Portal es el recomendado para cualquier cosa accesible más allá de tu propia máquina. La [guía del panel de Hermes](/es/guia-panel-hermes/) recorre la configuración remota; [los mejores paneles para Hermes](/es/mejores-paneles-hermes/) te ayudan a elegir una interfaz.

### Bots entre varias máquinas

Dos caminos. El primero es el relé de Desktop: cada gateway registrado en Settings, Gateways es una línea que Desktop mantiene abierta. Los Bot Chat listan compañeros en otras máquinas, y `message_agent` les llega con `target="moxie"` o `target="moxie@<connection>"`. Desktop hace de mensajero, así que la entrega entre conexiones solo funciona mientras se ejecuta un Desktop que conozca ambas conexiones. Un mensaje retransmitido da al Bot destino 10 minutos para su turno.

El segundo es `hermes peer`, sin Desktop en el camino:

```bash
hermes peer add spark --url http://spark.lan:8377 --key <API_SERVER_KEY>
hermes peer list
hermes peer dm spark "which certificate expires next?"
hermes peer run spark --idempotency-key ticket-123 "audit the staging stack and write a report"
hermes peer status spark <run_id>
```

`peer dm` entrega en el Bot Chat canónico del agente remoto, ejecuta un turno allí e imprime la respuesta. Resérvalo a consultas cortas; mantiene una conexión HTTP abierta hasta que termina el turno. `peer run` devuelve un `run_id` al instante; consúltalo con `peer status`. La máquina par necesita la plataforma `api_server` con una `API_SERVER_KEY` robusta. La clave queda en `~/.hermes/.env` como `HERMES_PEER_<NAME>_KEY`; los nombres y las URL viven en `config.yaml` bajo `bot_peers`. Una vez registrado un par, el protocolo de cada Bot Chat incluye el plantel de pares, así que `message_agent(target="spark/researcher", ...)` funciona.

El NAT es el obstáculo. La accesibilidad es en un solo sentido: una máquina en casa puede llamar a un VPS público; al revés hace falta una ruta. Pon la autoridad de un chat de grupo entre máquinas en un host al que todos los participantes puedan llegar (normalmente el VPS), o tiende un puente con Tailscale o una VPN.

### Coste y radio de daño

Cada Bot es un agente completo. Tiene sus propias claves o login, su propia memoria y habilidades, y las mismas herramientas que el perfil por defecto, terminal incluido. Un Bot investigador con el backend `local` en tu VPS puede hacer todo lo que puede hacer el agente principal. Establece el backend de terminal por Bot en `~/.hermes/profiles/<bot>/config.yaml` y activa solo las habilidades y conjuntos de herramientas que necesite en el diálogo New Agent.

La documentación no publica cifras de tokens para un plantel. Guíate por los límites: uno de tus mensajes en un chat de grupo cuesta hasta 10 turnos de miembros, y cada Continue añade hasta 10 más, cinco veces. Fija un modelo barato en los Bots trabajadores (`hermes -p <bot> model`) y dirige también a uno el router de grupo. La guía de los [mejores modelos baratos para Hermes Agent](/es/mejores-modelos-baratos-hermes-agent/) tiene recomendaciones.

Un Bot no añade ningún demonio. Un proceso de gateway por host posee las sesiones de todos los perfiles locales, así que cerrar Desktop nunca lo detiene; `hermes gateway stop` sí. Cada perfil tiene su propio `.env`, y Hermes rechaza dos perfiles que comparten un token de bot: bloquea el segundo gateway con un error que nombra el perfil en conflicto. La memoria y las credenciales son también por perfil, y una exportación de perfil excluye las credenciales por diseño, así que una exportación por sí sola no es una copia de seguridad. Usa `hermes backup`.

### Desactivar Bot Mode

Capabilities, Plugins, Bots: apaga el interruptor de Desktop. No hace falta reiniciar. Los perfiles, sesiones y cron jobs quedan intactos, así que las rutinas siguen ejecutándose hasta que las quites en `hermes cron list`. Borra un Bot con clic derecho, Delete Profile, cuando también quieras eliminar sus datos.

### Lo mismo desde una shell

| En Bot Mode | Desde una shell |
|---|---|
| Chatear con un Bot | `hermes -p <bot> chat` |
| Archivos, habilidades y memoria de un Bot | `~/.hermes/profiles/<bot>/` |
| Rutinas | `hermes cron list` (jobs llamados `[bot:<name>] ...`) |
| Crear o inspeccionar perfiles | `hermes profile create`, `hermes profile list` |
| El modelo de un Bot | `hermes -p <bot> model` |
| Reiniciar el gateway de todos los perfiles | `hermes gateway restart --all` |

Cuando el trabajo necesita un tablero duradero con dependencias en lugar de una conversación, un chat de grupo es la herramienta equivocada. Mira la [guía de Kanban con Hermes](/es/guia-kanban-hermes/).

## Referencia de configuración

La estructura completa del directorio:

```
~/.hermes/
├── config.yaml     # Settings (model, terminal, TTS, MCP, compression, etc.)
├── .env            # API keys and secrets
├── auth.json       # OAuth provider credentials
├── SOUL.md         # Agent identity
├── memories/       # MEMORY.md, USER.md
├── skills/         # Agent-created and hub skills
├── cron/           # Scheduled jobs
├── sessions/       # Conversation history
├── profiles/       # One folder per profile (every Bot is one)
└── logs/           # Logs (secrets auto-redacted)
```

Las opciones de `config.yaml` que más importan:

```yaml
model:
  provider: "openrouter"

terminal:

memory:
  memory_enabled: true
  user_profile_enabled: true

tts:
  provider: "edge"

stt:
  provider: "local"

display:
  tool_progress: all
```

## Preguntas frecuentes

<Accordion label="¿Necesito una GPU para ejecutar Hermes Agent?" group="faq" expanded="true">

No. Hermes Agent es el cliente: envía peticiones a un proveedor LLM como OpenRouter, que ejecuta el modelo en su propio hardware. Tu servidor solo necesita RAM para el proceso de Python (alrededor de 200MB), o al menos 2 GB cuando las herramientas de navegador están activadas.

</Accordion>

<Accordion label="¿Puedo usar Hermes Agent con Ollama para inferencia local?" group="faq">

Sí. Establece `OPENAI_BASE_URL=http://localhost:11434/v1` y `OPENAI_API_KEY=ollama` en `~/.hermes/.env`, o usa `hermes model` y selecciona "Custom endpoint". Hermes necesita un modelo con al menos 64,000 tokens de contexto para las llamadas a herramientas en varios pasos, así que configúralo también en Ollama. Mira nuestra [guía de Ollama con Docker](/es/ollama-docker-instalacion/) para montar Ollama.

</Accordion>

<Accordion label="¿Puedo migrar desde OpenClaw?" group="faq">

Sí. Ejecuta `hermes migrate openclaw` (la grafía antigua es `hermes claw migrate`) e importa tu persona, memorias, habilidades y configuraciones de plataforma. Añade `--migrate-secrets` para traer las API keys y los tokens de bot; sin ello se quedan donde están. Empieza con `--dry-run` para previsualizar el plan.

</Accordion>

<Accordion label="¿Hermes funciona en Windows?" group="faq">

Sí, de forma nativa. Ejecuta el instalador de PowerShell: `iex (irm https://hermes-agent.nousresearch.com/install.ps1)`. El paquete de escritorio necesita Windows 11 22H2 o posterior. WSL2 sigue funcionando si prefieres un entorno Linux; allí ejecuta el gateway con `hermes gateway run` porque el soporte de systemd en WSL no es fiable.

</Accordion>

<Accordion label="¿Puedo ejecutar Hermes con Docker Compose?" group="faq">

Sí. Monta `~/.hermes` en `/opt/data`, ejecuta `nousresearch/hermes-agent setup` una vez y después `docker compose up -d` con `gateway run`. Añade `HERMES_DASHBOARD=1` para levantar el panel en el mismo contenedor. Mira la [sección de Docker Compose](#despliegue-con-docker-compose) y el [`docker-compose.yml` oficial](https://github.com/NousResearch/hermes-agent/blob/main/docker-compose.yml).

</Accordion>

<Accordion label="¿Pueden varias personas usar una instancia de Hermes?" group="faq">

Sí, a través del gateway de mensajería. Cada chat de plataforma tiene su propia sesión, así que varios usuarios de Telegram o canales de Discord comparten la instancia con historiales separados. Usa listas de permitidos o emparejamiento por DM para controlar quién tiene acceso: `hermes pairing approve telegram XKGH5N7P`.

</Accordion>

<Accordion label="¿Puedo usar Bot Mode en un VPS sin interfaz?" group="faq">

En parte. El plantel es la app de escritorio, así que ejecuta Hermes Desktop en tu portátil y conéctalo al VPS desde Settings, Gateways. Los propios Bots son perfiles, así que `hermes -p <bot> chat` y `hermes cron list` funcionan en el servidor. El `message_agent` entre bots necesita dos marcadores que una instalación sin interfaz nunca escribe: una sesión titulada `Bot Chat` y un bloque `ui_meta: { hermes-bots: {} }` en un `profile.yaml`.

</Accordion>

<Accordion label="¿Cuánto cuesta un plantel de Bots?" group="faq">

No hay una cifra fija; la documentación no publica números de tokens. Cada turno de un Bot es una llamada a un modelo. Un chat de grupo está limitado a 10 mensajes por envío y 3 rondas, y Continue puede añadir hasta 5 presupuestos más. Fija un modelo barato en los Bots trabajadores con `hermes -p <bot> model` y dirige el router de grupo a uno con `auxiliary.group_router`. Cada Bot lleva también sus propias claves y su backend de terminal, así que trátalo como otro agente completo en la máquina.

</Accordion>
