Bienvenido a la parte 3 de nuestra serie de FastHTML. En este tutorial construimos una aplicación web con IA usando FastHTML y PydanticAI, dos bibliotecas de Python para aplicaciones web full-stack con salida de IA estructurada. Sin necesidad de frameworks de JavaScript.

Si eres nuevo en FastHTML, empieza con [FastHTML para principiantes](/es/empezar-fasthtml/), donde cubrimos lo básico, y sigue con nuestro tutorial de [estructura FastHTML multipágina](/es/fasthtml-multiples-paginas/). ¿Nuevo en la integración de IA? Lee nuestra [guía para principiantes de programación con IA](/es/guia-programacion-ia-principiantes/). ¿Quieres saber cómo se compara FastHTML con otras opciones? Mira nuestro resumen de los [mejores frameworks web de Python](/best-python-web-frameworks/).

Nuestro proyecto es un Generador de Títulos con IA que ayuda a creadores de contenido a desarrollar títulos para blogs, vídeos de YouTube, publicaciones en redes sociales y más. Usamos la salida estructurada de PydanticAI para obtener respuestas validadas y con tipado seguro del modelo de IA, y OpenRouter para un acceso a modelos económico e independiente del proveedor.

<Notice type="info" title="Versiones objetivo">
Este tutorial está orientado a **PydanticAI >= v2.0** (estable desde junio de 2026) y **FastHTML >= 0.14.11**. Si usas una versión anterior, consulta la [guía de actualización de PydanticAI](https://pydantic.dev/docs/ai/project/changelog/).

### Paso 2: creación del servicio de IA

Este es el cambio principal. El código antiguo construía manualmente un cliente `AsyncOpenAI` y usaba chat completions sin procesar. PydanticAI ahora tiene soporte nativo para OpenRouter con `OpenRouterModel` y `OpenRouterProvider`, lo que significa menos código repetitivo y salida estructurada integrada.

**Archivo: `ai_service.py`**

```python
from pydantic_ai import Agent, ModelSettings
from pydantic_ai.models.openrouter import OpenRouterModel
from pydantic_ai.providers.openrouter import OpenRouterProvider
import config

import YouTubeEmbed from "../../components/widgets/YouTubeEmbed.astro";


class AIService:
    """Service for interacting with AI models via OpenRouter."""

    def __init__(self, model_name=None, output_type=None, system_prompt=None):
        self.model_name = model_name or config.DEFAULT_MODEL
        model = OpenRouterModel(
            self.model_name,
            provider=OpenRouterProvider(api_key=config.OPENROUTER_API_KEY),
        )
        self.agent = Agent(
            model,
            instructions=system_prompt,
            output_type=output_type,
        )

    async def run_structured(self, user_message: str, temperature: float = 0.8):
        """Run the agent and return validated structured output."""
        result = await self.agent.run(
            user_message,
            model_settings=ModelSettings(temperature=temperature),
        )
        return result.output
```

Compara esto con la versión anterior que tenía ~90 líneas con `AsyncOpenAI`, `OpenAIModel`, `chat_completion()`, `structured_completion()` y construcción manual de mensajes.

<Accordion label="¿Por qué salida estructurada en lugar de chat sin procesar?" group="explanation">
El tutorial anterior definía modelos Pydantic (`TitleGenerationResponse`) pero luego llamaba a `chat_completion()` y analizaba la respuesta de texto con regex. Eso es frágil: los LLM cambian el formato, añaden markdown o incluyen texto extra.

La salida estructurada de PydanticAI envía el esquema Pydantic al modelo y valida la respuesta contra él. Si el modelo devuelve algo que no coincide, PydanticAI reintenta automáticamente. Obtienes datos con tipado seguro directamente: `result.output.titles` es una `list[str]`, no una cadena que tienes que analizar.

Esto significa menos código y menos modos de fallo.
</Accordion>

### Paso 3: creación de la herramienta generadora de títulos

La salida estructurada sustituye aquí al frágil análisis con regex. El antiguo método `_extract_titles_from_response()` (más de 40 líneas de regex, lógica de respaldo y división de cadenas) ha desaparecido por completo.

**Archivo: `tools/title_generator.py`**

```python
from pydantic import BaseModel
from pydantic_ai import Agent, ModelSettings
from pydantic_ai.models.openrouter import OpenRouterModel
from pydantic_ai.providers.openrouter import OpenRouterProvider
import config


class TitleGenerationResponse(BaseModel):
    """Schema for title generation response."""
    titles: list[str]


SYSTEM_PROMPT = """You are an expert title generator specializing in creating
engaging, click-worthy titles appropriate for different platforms.

Guidelines:
- Create titles that grab attention without being misleading
- Adapt the style and format to the specified platform
- Ensure titles are relevant to the topic
- Keep titles concise and effective
- Return exactly the number of titles requested"""


class TitleGenerator:
    """Tool for generating titles for various platforms."""

    def __init__(self):
        model = OpenRouterModel(
            config.DEFAULT_MODEL,
            provider=OpenRouterProvider(api_key=config.OPENROUTER_API_KEY),
        )
        self.agent = Agent(
            model,
            instructions=SYSTEM_PROMPT,
            output_type=TitleGenerationResponse,
            model_settings=ModelSettings(temperature=0.8),
        )

    async def generate_titles(
        self,
        topic: str,
        platform: str = "Blog",
        style: str = "Professional",
        number_of_titles: int = 5,
    ) -> list[str]:
        """Generate titles based on the given parameters."""
        user_prompt = (
            f"Generate {number_of_titles} engaging {platform} titles about: {topic}\n"
            f"Style: {style}"
        )
        result = await self.agent.run(user_prompt)
        return result.output.titles[:number_of_titles]
```

<Notice type="success" title="Ventaja de la salida estructurada">
Con la salida estructurada de PydanticAI ya no necesitamos análisis con regex. La respuesta de la IA se valida directamente contra nuestro modelo Pydantic, lo que significa menos líneas de código y resultados más fiables. Si el modelo devuelve menos títulos de los pedidos, `result.output.titles` simplemente tiene menos elementos. Si la respuesta no coincide con el esquema, PydanticAI reintenta automáticamente.
</Notice>

<Notice type="warning" title="Corrección de seguridad del botón Copiar">
El botón de copiar original usaba JavaScript en línea con interpolación de cadenas (`title.replace("'", "\\'")`), que se rompe con títulos que contienen comillas, barras invertidas o saltos de línea, y es un riesgo de inyección con texto generado por IA. La versión actualizada guarda el título en un atributo `data-title` y lo lee con `this.dataset.title`, lo cual es seguro sin importar el contenido del título.
</Notice>

**Verifica:** Abre `http://localhost:5001/title-generator` en tu navegador y confirma que el formulario se renderiza con todas las etiquetas visibles y los desplegables funcionando. Haz clic en cada etiqueta: el campo correspondiente debería recibir el foco.

### Paso 6: creación de la aplicación principal

**Archivo: `main.py`**

```python
import logging
from fasthtml.common import *

from pages.home import home as home_page
from pages.title_generator import title_generator_form, title_generator_results
from components.page_layout import page_layout
from tools.title_generator import TitleGenerator
import config

# Set up logging
logging.basicConfig(level=logging.DEBUG if config.DEBUG else logging.INFO)
logger = logging.getLogger(__name__)

app = FastHTML()
title_generator = TitleGenerator()


@app.get("/")
def home():
    """Handler for the home page route."""
    return page_layout(
        title=f"Home - {config.APP_NAME}",
        content=home_page(),
        current_page="/"
    )


@app.get("/title-generator")
def title_generator_page():
    """Handler for the title generator page route."""
    return page_layout(
        title=f"Title Generator - {config.APP_NAME}",
        content=title_generator_form(),
        current_page="/title-generator"
    )


@app.post("/title-generator/generate")
async def generate_titles(topic: str, platform: str, style: str, number_of_titles: str):
    """Handler for processing title generation requests."""
    try:
        if not topic:
            error_message = Div(
                H1("Error", cls="text-3xl font-bold text-red-600 mb-4"),
                P("Please provide a topic for your titles.", cls="mb-4"),
                A("Try Again", href="/title-generator",
                  cls="bg-blue-600 hover:bg-blue-700 text-white font-bold py-2 px-4 rounded"),
                cls="max-w-2xl mx-auto bg-white p-6 rounded-lg shadow-md"
            )
            return page_layout(
                title=f"Error - {config.APP_NAME}",
                content=error_message,
                current_page="/title-generator"
            )

        num_titles = int(number_of_titles)

        titles = await title_generator.generate_titles(
            topic=topic,
            platform=platform,
            style=style,
            number_of_titles=num_titles,
        )

        return page_layout(
            title=f"Generated Titles - {config.APP_NAME}",
            content=title_generator_results(
                topic=topic,
                platform=platform,
                style=style,
                titles=titles,
            ),
            current_page="/title-generator"
        )
    except ValueError:
        error_message = Div(
            H1("Error", cls="text-3xl font-bold text-red-600 mb-4"),
            P("Invalid number of titles. Please select a valid option.", cls="mb-4"),
            A("Try Again", href="/title-generator",
              cls="bg-blue-600 hover:bg-blue-700 text-white font-bold py-2 px-4 rounded"),
            cls="max-w-2xl mx-auto bg-white p-6 rounded-lg shadow-md"
        )
        return page_layout(
            title=f"Error - {config.APP_NAME}",
            content=error_message,
            current_page="/title-generator"
        )
    except Exception as e:
        logger.exception("Title generation failed")
        error_message = Div(
            H1("Error", cls="text-3xl font-bold text-red-600 mb-4"),
            P("Something went wrong while generating titles. Please try again.", cls="mb-4"),
            A("Try Again", href="/title-generator",
              cls="bg-blue-600 hover:bg-blue-700 text-white font-bold py-2 px-4 rounded"),
            cls="max-w-2xl mx-auto bg-white p-6 rounded-lg shadow-md"
        )
        return page_layout(
            title=f"Error - {config.APP_NAME}",
            content=error_message,
            current_page="/title-generator"
        )


@app.get("/{path:path}")
def not_found(path: str):
    """Handler for 404 Not Found errors."""
    error_content = Div(
        H1("404 - Page Not Found", cls="text-3xl font-bold text-gray-800 mb-4"),
        P(f"Sorry, the page '/{path}' does not exist.", cls="mb-4"),
        A("Return Home", href="/",
          cls="bg-blue-600 hover:bg-blue-700 text-white font-bold py-2 px-4 rounded"),
        cls="max-w-2xl mx-auto bg-white p-6 rounded-lg shadow-md text-center"
    )
    return page_layout(
        title=f"404 Not Found - {config.APP_NAME}",
        content=error_content,
        current_page="/"
    )


if __name__ == "__main__":
    serve()
```

Cambios clave respecto al `main.py` original:

- **`serve()` en lugar de `uvicorn.run()`** — el `serve()` integrado de FastHTML detecta la app automáticamente, usa el puerto 5001 por defecto y muestra un enlace clicable. No hace falta `import uvicorn`.
- **El manejador de errores no filtra excepciones** — el código antiguo mostraba `str(e)` a los usuarios, lo que podía exponer claves de API o fragmentos de la pila. Ahora registra el traceback completo en el servidor y muestra un mensaje genérico.
- **Guarda de `ValueError`** — captura las conversiones fallidas de `int(number_of_titles)` por separado del resto de errores.

**Verifica:** Arranca la app y confirma que inicia sin errores:

```bash
python main.py
# Should print something like: Link: http://0.0.0.0:5001
```

**Si falla:**
- `Port 5001 already in use` — mata el otro proceso (`lsof -i :5001`) o define `PORT=8000` en tu `.env`
- `ImportError` — comprueba que todos los archivos están en los directorios correctos y que existen los archivos `__init__.py`

</Accordion>

## Mejorar el generador de títulos

Estas son las mejores formas de ampliar este proyecto:

1. **Modelos de salida más ricos** — Añade campos a `TitleGenerationResponse` como `description: str`, `keywords: list[str]` o `seo_score: float`. PydanticAI los valida todos automáticamente.

2. **Más plataformas** — Amplía a TikTok, Pinterest, LinkedIn o Substack. Actualiza el desplegable de plataformas y ajusta el system prompt con indicaciones específicas por plataforma.

3. **Variaciones de títulos** — Añade una función para generar variaciones de un título existente para pruebas A/B.

4. **Favoritos e historial** — Guarda los títulos generados para que los usuarios puedan consultarlos. Puedes [añadir una base de datos SQLite](/es/fasthtml-sqlite-db/) para persistir el historial de generación.

5. **Exportar a CSV** — Permite que los usuarios descarguen sus títulos generados como archivo para uso por lotes.

## Notas de producción: coste, seguridad y despliegue

Antes de exponer esta app más allá de localhost, esto es lo que debes considerar.

### Desglose de costes

<Notice type="info" title="Coste por petición">
Una generación típica de 5 títulos usa ~500–1.000 tokens en total. Con el precio de gpt-4o-mini (~$0.15/$0.60 por 1M de tokens vía OpenRouter), eso es menos de $0.001 por generación. Los modelos gratuitos de OpenRouter están disponibles pero tienen límites de uso estrictos (~50 solicitudes/día).
</Notice>

Puedes registrar el uso de tokens en tu código mediante `result.usage` (una propiedad del resultado de la ejecución del agente). Ten en cuenta que el endpoint POST público no tiene autenticación: cualquiera que pueda alcanzarlo puede gastar tus créditos. Añade limitación de tasa o autenticación antes de exponerlo públicamente.

### Desarrollo vs. producción

`serve()` con los valores por defecto se ejecuta con `reload=True`: eso es solo para desarrollo. Para producción:

- Usa `serve(reload=False)` o un gestor de procesos
- Pon un proxy inverso (Caddy o nginx) delante para TLS y archivos estáticos
- Tailwind vía CDN está bien en desarrollo; usa un paso de compilación en producción
- Considera Docker para despliegues consistentes

Para alojamiento VPS económico donde desplegar tu app, [Hetzner Cloud](https://go.bitdoze.com/hetzner) parte de ~4 EUR/mes con un rendimiento sólido. [Hostinger VPS](https://go.bitdoze.com/hostinger-vps) es otra opción económica con almacenamiento NVMe.
