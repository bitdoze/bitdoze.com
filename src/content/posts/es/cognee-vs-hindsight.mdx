Llevo unos meses ejecutando tanto Cognee como Hindsight. Resuelven problemas relacionados pero con enfoques muy diferentes, y elegir el equivocado para tu caso de uso te hará perder semanas de trabajo de integración.

Ambos son open source. Ambos van más allá del RAG básico. Ambos dan a los agentes de IA memoria persistente y estructurada. Ahí terminan las similitudes.

Este artículo desglosa cómo difieren a nivel arquitectónico, en qué es realmente bueno cada uno, qué integraciones soportan y cuándo deberías elegir uno sobre el otro (o ambos).

## Comparación rápida

| | Cognee | Hindsight |
|---|---|---|
| **Arquitectura** | Grafo de conocimiento + búsqueda vectorial | Híbrido multi-estrategia (semántico + BM25 + grafo + temporal) |
| **Fortaleza principal** | Ingesta de datos y extracción de conocimiento desde documentos | Memoria de interacciones del agente con recuperación multi-estrategia |
| **Tipo de memoria** | Institucional (conocimiento de tus datos) | Personalización + institucional |
| **Fuentes de datos** | Más de 30 conectores (PDFs, Slack, Notion, imágenes, audio) | Conversaciones del agente e input estructurado |
| **Benchmark (LongMemEval)** | Sin clasificar | 94.6% (estado del arte) |
| **SDKs** | Solo Python | Python, TypeScript, Go |
| **Protocolo** | API REST | MCP-first |
| **Almacenamiento** | SQLite + LanceDB + Kuzu (o PostgreSQL + pgvector) | PostgreSQL con pgvector |
| **Licencia** | Open core | MIT |
| **UI web** | Solo CLI (`cognee-cli -ui`) | Control Plane integrado |
| **Estrellas en GitHub** | ~12K | ~4K (creciendo rápido) |

## Cómo funciona cada uno

### Cognee: convierte tus datos en un grafo de conocimiento

Cognee es un pipeline. Le pasas datos de varias fuentes, extrae entidades y relaciones, construye un grafo de conocimiento y añade embeddings vectoriales encima. Cuando lo consultas, el recorrido del grafo y la búsqueda vectorial trabajan juntos.

El bucle central:

1. **Ingesta** - Extrae datos de más de 30 conectores (PDFs, Slack, Notion, bases de datos, imágenes, audio)
2. **Procesa** - Divide el texto en chunks, extrae entidades, resuelve relaciones
3. **Almacena** - SQLite para metadatos, LanceDB para vectores, Kuzu para el grafo de conocimiento (o PostgreSQL + pgvector para los tres)
4. **Consulta** - Recorrido híbrido del grafo + similitud vectorial

La API es directa:

```python
import cognee

await cognee.remember("The production database runs PostgreSQL 17")
results = await cognee.recall("What database does production use?")
```

La nueva API de Cognee usa las operaciones `remember`, `recall`, `forget` e `improve`. La llamada `remember` almacena datos en el grafo de conocimiento, `recall` lo consulta e `improve` permite al agente aprender del feedback.

Donde Cognee brilla: tomar un corpus de documentos, transcripciones de reuniones o repositorios de código y convertirlos en conocimiento estructurado y consultable. Si tu agente necesita responder preguntas basadas en la documentación de la empresa, el pipeline de Cognee se encarga de la extracción y la construcción del grafo.

### Hindsight: aprende de las interacciones del agente

Hindsight toma un enfoque diferente. En lugar de ingerir fuentes de datos externas, captura y estructura lo que los agentes realmente aprenden durante la operación: conversaciones, decisiones, correcciones y resultados.

Organiza la memoria en tres categorías:

- **Hechos del mundo** - Cosas que son verdad ("El proyecto usa PostgreSQL 17")
- **Experiencias** - Cosas que pasaron ("El último despliegue falló por un problema de migración")
- **Modelos mentales** - Patrones formados al reflexionar sobre hechos y experiencias ("Este usuario prefiere respuestas concisas")

Cuando almacenas una memoria con `retain`, Hindsight ejecuta un LLM para extraer entidades, relaciones y datos temporales. Cuando buscas con `recall`, ejecuta cuatro estrategias de recuperación en paralelo:

1. Búsqueda semántica (similitud vectorial)
2. Coincidencia de palabras clave (BM25)
3. Recorrido del grafo (enlaces de entidades y relaciones)
4. Filtrado temporal (rangos de tiempo)

Los resultados se fusionan con reciprocal rank fusion y se reordenan. Este enfoque multi-estrategia es la razón por la que Hindsight alcanza el 94.6% en el benchmark LongMemEval, la puntuación más alta de cualquier sistema de memoria para agentes probado.

```python
from hindsight_client import Hindsight

client = Hindsight(base_url="http://localhost:8888")

client.retain(bank_id="my-project", content="Alice prefers concise responses")
results = client.recall(bank_id="my-project", query="How should I talk to Alice?")
```

La operación `reflect` va más allá. Reúne memorias relacionadas y genera nuevas observaciones. Un gestor de proyectos de IA podría reflexionar sobre riesgos, un agente de ventas podría reflexionar sobre patrones de contacto, un agente de soporte podría reflexionar sobre lagunas en la documentación.

## Diferencias de arquitectura

<Tabs>
  <Tab name="Almacenamiento">
    **Cognee** usa tres capas de almacenamiento por defecto: SQLite para metadatos, LanceDB para vectores y Kuzu para el grafo de conocimiento. Puedes cambiarlas por PostgreSQL + pgvector (gestionando tanto datos relacionales como vectoriales) más Neo4j o FalkorDB para grafos. Esta flexibilidad es útil pero significa más piezas móviles.

    **Hindsight** usa una única instancia de PostgreSQL con pgvector. Una base de datos gestiona vectores, metadatos, grafos de entidades e índices temporales. Más simple de desplegar, más simple de respaldar, más simple de escalar.
  </Tab>
  <Tab name="Recuperación">
    **Cognee** combina el recorrido del grafo con la similitud vectorial. La estructura del grafo de conocimiento permite consultas multi-salto, siguiendo relaciones de entidades a través de puntos de datos conectados. Bueno para "¿Qué documentos mencionan el mismo proyecto que esta transcripción de reunión?"

    **Hindsight** ejecuta cuatro estrategias de recuperación en paralelo y fusiona los resultados. La búsqueda semántica gestiona coincidencias conceptuales, BM25 captura términos exactos, el recorrido del grafo sigue enlaces de entidades y el filtrado temporal entiende expresiones de tiempo como "la semana pasada" o "antes de la migración". Ninguna estrategia por sí sola cubre todos los tipos de consulta, así que el enfoque paralelo cubre los puntos ciegos.
  </Tab>
  <Tab name="Ingesta de datos">
    **Cognee** tiene más de 30 conectores: PDFs, Slack, Notion, Google Drive, SharePoint, bases de datos, imágenes (vía modelos de visión), audio (vía transcripción). Si necesitas ingerir desde fuentes externas, Cognee está hecho para eso.

    **Hindsight** no se conecta a fuentes de datos externas. Captura memoria de las interacciones del agente: conversaciones, decisiones, correcciones y resultados. Le pasas información a través de la API retain, no a través de conectores.
  </Tab>
</Tabs>

## Integraciones

Aquí es donde los dos divergen significativamente.

### Integraciones de Cognee

Cognee es solo Python en el SDK. Si tu agente está escrito en TypeScript o Go, necesitarás usar la API REST o construir un wrapper.

Integraciones disponibles:
- **Servidor MCP** - Funciona con Cursor, Claude Code y otros clientes MCP
- **Plugin de Claude Code** - Se engancha al ciclo de vida de la sesión para captura automática de memoria
- **Plugin de OpenClaw** - `cognee-openclaw` para workflows de agentes OpenClaw
- **API REST** - API completa para cualquier lenguaje

### Integraciones de Hindsight

Hindsight incluye SDKs para Python, TypeScript y Go. El diseño MCP-first significa que cualquier agente compatible con MCP funciona sin SDK.

Integraciones disponibles:
- **Claude Code** - Hooks para captura automática de conversaciones y recuperación de contexto
- **OpenCode** - Plugin de la comunidad con auto-retain y recall al inicio de sesión
- **OpenClaw** - Integración directa con control de acceso del lado del servidor
- **Hermes Agent** - Backend de memoria para el framework multi-agente Hermes
- **Agno** - Integración directa para memoria estructurada a largo plazo
- **Zed** - Memoria a largo plazo para el asistente de IA del editor Zed
- **Cursor** - Integración con servidor MCP
- **n8n** - Nodo de la comunidad para automatización de workflows
- **LangChain/LangGraph** - Memory Tools, Graph Nodes, adaptador BaseStore
- **LlamaIndex** - Soporte de BaseToolSpec y BaseMemory
- **Vercel AI SDK** - Memoria para aplicaciones AI SDK y AI Chatbot
- **Pipecat** - Memoria para pipelines de voz con IA
- **Dify** - Plugin para apps de chatflow y agentes
- **LiteLLM** - Callbacks de proxy para memoria sin cambios de código
- **CrewAI, Pydantic AI, AutoGen, AG2, Strands** - Integraciones específicas por framework

La amplitud de las integraciones de Hindsight es un resultado directo del soporte de SDKs multi-lenguaje. El enfoque solo-Python de Cognee limita su alcance fuera del ecosistema Python.

## Rendimiento en benchmarks

Hindsight tiene la puntuación más alta en el benchmark LongMemEval con un 94.6%. Este benchmark prueba el rendimiento de sistemas de memoria en escenarios de IA conversacional, incluyendo:

- Recordar hechos de conversaciones pasadas
- Entender relaciones temporales
- Manejar razonamiento multi-salto a través de memorias
- Mantener consistencia en historiales de interacción largos

Cognee no tiene una puntuación publicada en LongMemEval. Esto no significa que sea peor en todo, significa que el benchmark está enfocado en memoria conversacional, que es la fortaleza de Hindsight. El enfoque de grafo de conocimiento de Cognee destaca en tareas diferentes, como extraer información estructurada de documentos y razonar a través de puntos de datos conectados.

El benchmark importa si tu caso de uso es memoria de interacciones del agente. Si tu caso de uso es extracción de conocimiento de documentos, el benchmark es menos relevante.

## Cuándo usar Cognee

Elige Cognee cuando:

- **Tu necesidad principal es extracción de conocimiento desde datos existentes.** Miles de PDFs, hilos de Slack, transcripciones de reuniones o repositorios de código que necesitan convertirse en conocimiento estructurado y consultable.
- **Trabajas con datos multimodales.** Cognee procesa imágenes mediante modelos de visión y audio mediante transcripción, integrando el conocimiento extraído en el mismo grafo.
- **Tu stack es solo Python.** El SDK de Python es limpio y la afirmación de "6 líneas de código" se cumple para casos de uso básicos.
- **Quieres un grafo de conocimiento local-first.** SQLite + LanceDB + Kuzu corre completamente en local sin dependencias externas.
- **Reducir las alucinaciones es tu prioridad.** El grafo de conocimiento proporciona rutas trazables desde la consulta hasta la fuente.

## Cuándo usar Hindsight

Elige Hindsight cuando:

- **Tu agente necesita aprender de sus propias interacciones.** Preferencias de usuario, decisiones pasadas, correcciones e historial contextual entre sesiones.
- **Necesitas recuperación multi-estrategia.** Algunas consultas necesitan similitud semántica, otras necesitan palabras clave exactas, otras necesitan razonamiento temporal. Ejecutar las cuatro en paralelo cubre los puntos ciegos de cada método.
- **Tu stack es multi-lenguaje.** SDKs de Python, TypeScript y Go, más soporte del protocolo MCP.
- **Quieres integración nativa con MCP.** Memoria plug-and-play con cualquier agente compatible con MCP.
- **El razonamiento temporal importa.** Preguntas como "¿Qué cambió desde el último despliegue?" o "¿Qué dijo el usuario sobre los precios antes de la revisión del Q3?"
- **Quieres una UI web.** El Control Plane de Hindsight te da una interfaz de navegador para gestionar bancos de memoria y probar consultas. La UI de Cognee requiere ejecutar un CLI localmente.

## ¿Puedes usar ambos juntos?

Sí. Resuelven problemas diferentes:

- **Cognee** construye conocimiento desde tus datos existentes (documentos, transcripciones, código)
- **Hindsight** captura conocimiento del runtime del agente (conversaciones, decisiones, resultados)

Una configuración práctica: Cognee ingiere la documentación de tu empresa y construye un grafo de conocimiento. Hindsight recuerda lo que tu agente aprende mientras ayuda a los usuarios. El agente consulta Cognee cuando necesita conocimiento institucional y Hindsight cuando necesita recordar preferencias de usuario o interacciones pasadas.

Ambos corren sobre PostgreSQL con pgvector, así que puedes usar el mismo servidor de base de datos si quieres mantener la infraestructura simple.

## Comparación de costes

Ambos son gratis de autoalojar. Los costes principales son:

- **Infraestructura** - Un VPS con 4GB de RAM maneja ambos. PostgreSQL con pgvector es compartido, así que no duplicas los costes de base de datos.
- **Uso de API de LLM** - Ambos necesitan un LLM para extracción y razonamiento. Cognee lo usa para extracción de entidades durante la ingesta. Hindsight lo usa para extracción de hechos durante operaciones retain y para reflect. Los costes escalan con la cantidad de datos que procesas.
- **Uso de API de embeddings** - Ambos generan embeddings vectoriales. Perfil de coste similar ya que ambos usan los mismos modelos de embeddings (OpenAI, Cohere, etc.).

Usar modelos locales con Ollama puede reducir los costes de API a casi cero para ambas herramientas, a costa de un procesamiento más lento y una calidad de extracción potencialmente menor.

## Conclusión

Cognee es un motor de extracción de conocimiento. Apúntalo a tus datos y construye un grafo que puedes consultar. Hindsight es un sistema de memoria de interacciones. Deja que tu agente lo use y se vuelve más inteligente con el tiempo.

Si tu agente olvida cosas que los usuarios le dijeron, elige Hindsight. Si tu agente no puede responder preguntas sobre tu documentación, elige Cognee. Si ambos problemas te suenan familiares, ejecuta ambos.

Las herramientas de memoria están junto a asistentes y frameworks en el catálogo de [los mejores repos de IA en GitHub](/es/mejores-repos-github-ia/).
