El historial de Fish Shell es una de esas funciones que funciona lo bastante bien como para que dejes de pensar en ella. Los comandos se guardan automáticamente, las autosugerencias recuperan entradas anteriores y Ctrl+R encuentra las cosas rápido. Pero los detalles importan cuando quieres limpiar un secreto filtrado, mantener los experimentos fallidos fuera de tus sugerencias o compartir el historial entre máquinas.

Esta guía cubre el panorama completo del historial de fish shell: dónde se guarda el archivo de historial en disco, cómo funciona la búsqueda (no es lo que la mayoría asume), cómo eliminar y filtrar entradas, el modo privado para sesiones sensibles y la sincronización entre máquinas con atuin. Actualizado para fish 4.9.3 (septiembre de 2026).

<Notice type="info" title="Actualizado para fish 4.9.3">

</Notice>

## Dónde se guarda el archivo de historial de Fish Shell

Fish almacena el historial en un único archivo de texto plano:

```
~/.local/share/fish/fish_history
```

Si tienes `XDG_DATA_HOME` definida, la ruta es `$XDG_DATA_HOME/fish/fish_history`.

Cada entrada usa un formato estilo YAML con un comando, una marca de tiempo y, opcionalmente, una lista de rutas de archivos que aparecieron en el comando:

```
- cmd: git commit -m "fix auth"
  when: 1708784400
  paths:
    - src/auth.ts
```

El campo `paths:` es lo que alimenta las autosugerencias de rutas de archivos de Fish. No necesitas crearlo a mano: Fish lo escribe automáticamente.

También puedes apuntar Fish a un archivo de historial distinto por sesión definiendo la variable `fish_history`:

```fish
set fish_history work
# El historial ahora va a ~/.local/share/fish/work_history
```

Cualquier nombre distinto del predeterminado también evita que Fish importe tu historial de Bash en una máquina nueva. Útil para presentaciones o cuando quieres empezar de cero.

### Límite de tamaño

Fish limita el historial a **262.144 entradas** (256 x 1024). Este límite existe desde fish 3.7.0. Cuando se alcanza el tope, las entradas más antiguas se recortan. No hay ninguna variable tipo `HISTSIZE` para cambiarlo. Consulta [cómo se compara Fish Shell con Bash y Zsh](/es/fish-shell-vs-bash-vs-zsh-comparacion/) para más sobre las diferencias de configuración. En la práctica, nunca llegarás a 262 mil entradas a menos que añadas historial mediante scripts.

**Verificar:**

```fish
ls -la ~/.local/share/fish/fish_history
head -5 ~/.local/share/fish/fish_history
wc -l ~/.local/share/fish/fish_history
```

Deberías ver el archivo, algunas entradas `- cmd:` y un recuento de líneas. Si el archivo aún no existe, ejecuta cualquier comando y aparecerá.

Como el archivo es texto plano, entra tal cual en cualquier copia de seguridad. Más sobre esto en la [sección de copias de seguridad](#guardar-añadir-y-respaldar-el-archivo-de-historial).

## Buscar en el historial de Fish Shell

Fish te da tres formas de buscar en el historial: las teclas de flecha, el paginador Ctrl+R y el comando `history search`. Esto es lo que hace cada una.

### Teclas de flecha (búsqueda por contenido)

Pulsa la **flecha arriba** para recorrer los comandos anteriores, del más reciente al más antiguo. Si ya has escrito algo, la flecha arriba busca comandos que **contienen** esa cadena en cualquier parte, no solo los que empiezan por ella.

Escribe `git` y pulsa la flecha arriba. Verás `git commit`, `git push`, pero también `sudo apt install git`, porque la coincidencia es por "contiene", no por "empieza por". Esto despista a quienes vienen de Bash, donde la flecha arriba busca por prefijo. (La documentación oficial usa el mismo ejemplo: escribe `make`, pulsa arriba y obtén todos los comandos que contienen "make".)

**Búsqueda por token:** pulsa `Alt+Up` o `Alt+Down` para buscar comandos del historial que contengan un token igual a la palabra bajo el cursor. Útil cuando un comando largo tiene un argumento distintivo en medio.

**Verifica el comportamiento de "contiene":** escribe `git`, pulsa arriba. Si aparecen tanto `git commit` como `sudo apt install git`, la búsqueda es por contenido, como se esperaba.

### Ctrl+R y el paginador de historial

Pulsa `Ctrl+R` para abrir el paginador de historial de Fish. No es un simple prompt de búsqueda inversa: es un paginador completo con sus propias teclas:

- **Escribe** para afinar la búsqueda (la barra de búsqueda está seleccionada al abrir el paginador)
- **Ctrl+R** de nuevo salta a coincidencias más antiguas
- **Ctrl+S** salta a coincidencias más recientes
- **Escape** o **PageDown** detiene la búsqueda y deja la cadena editable en la línea de comandos
- **Enter** ejecuta el comando seleccionado

La búsqueda interactiva es **smart-case**: no distingue mayúsculas a menos que tu cadena de búsqueda contenga una mayúscula. Así, `docker` coincide con `Docker` y `docker`, pero `Docker` solo coincide con `Docker`.

La sintaxis glob funciona dentro del paginador (desde fish 4.0.0). Escribe `git*fix` para coincidir con comandos que contienen "git" seguido más adelante de "fix".

Si usas el modo vi, `/` abre el mismo paginador.

El [plugin fzf.fish](/es/mejores-plugins-fish-shell/) reemplaza Ctrl+R con un buscador difuso basado en fzf que muestra vista previa y admite selección múltiple. Lo prefiero al paginador integrado para uso intensivo, pero el paginador es sólido una vez que conoces las teclas.

### El comando history

Para búsquedas precisas y programables, usa `history search`:

```fish
# Buscar comandos que contengan "docker"
history search docker

# Buscar por prefijo
history search --prefix "git commit"

# Coincidencia exacta
history search --exact "git push origin main"

# Mostrar marcas de tiempo
history search --show-time docker

# Formato de marca de tiempo personalizado (strftime)
history search --show-time="%Y-%m-%d %H:%M:%S " docker

# Limitar resultados
history search --max 10 docker

# Búsqueda sensible a mayúsculas
history search --case-sensitive Docker

# Del más antiguo al más reciente en lugar del orden habitual
history search --reverse docker
```

Por defecto, `history search` no distingue mayúsculas y ordena del más reciente al más antiguo. Añade `--reverse` para invertir el orden. Añade `--color never` si envías la salida a otra herramienta y quieres una salida limpia (fish 4.4.0 añadió `--color auto|always|never`).

**Verificar:**

```fish
history search --show-time --max 5 docker
```

Deberías ver marcas de tiempo y como máximo 5 líneas.

<Notice type="warning" title="Los comandos multilínea rompen los pipes ingenuos">
Las entradas del historial pueden abarcar varias líneas (las autosugerencias incluyen comandos multilínea desde fish 4.3.0). Si envías la salida de `history search` a una herramienta basada en saltos de línea como `grep` o `while read`, las entradas multilínea se dividen incorrectamente. Usa <code>--null</code> con <code>read -z</code> para un procesamiento seguro:
</Notice>

```fish
history search --null docker | while read -z entry
    echo "--- $entry"
end
```

## Eliminar y limpiar el historial de Fish Shell

A veces ejecutas un comando con un error tipográfico o pegas accidentalmente una contraseña en la línea de comandos. Fish te permite limpiarlo a posteriori y prevenirlo la próxima vez.

### Eliminación interactiva

```fish
history delete docker
```

Esto busca comandos que coincidan con "docker" y muestra coincidencias numeradas. Introduce números de entrada concretos, un rango o `all` para eliminar todas las coincidencias. Pulsa Enter sin escribir nada para no eliminar nada (cancelar).

### Eliminación exacta

```fish
history delete --exact --case-sensitive "docker login -p my_secret_password"
```

Esto elimina ese comando concreto sin preguntar. Ese es el contrato del builtin. El selector interactivo de arriba es el comportamiento de la *función* `history` añadido por encima.

**Limpieza por patrón:** si rotaste una contraseña y la antigua está en tu historial, elimínala por prefijo:

```fish
history delete --prefix "mysql -p"
```

**Verificar:** `history search --exact "<deleted command>"` no debería devolver nada.

### Eliminar mientras escribes (Shift+Delete)

Pulsa **Shift+Delete** para eliminar al instante del historial el elemento actual (o la autosugerencia mostrada). Es la herramienta más rápida para el "ups, no debería haber escrito eso". También funciona durante la búsqueda con flecha arriba (desde fish 4.0.0).

También puedes usar `fish_config` (la interfaz de configuración web) para explorar y eliminar entradas del historial. El flujo de eliminación se volvió más usable en fish 4.7.0.

<Notice type="warning" title="Bug de inicio de fish_config en 4.7.0">
Fish 4.7.0 tuvo una regresión que impedía que <code>fish_config</code> arrancara. Corregido en 4.7.1 (2026-05-08). Si <code>fish_config</code> no se inicia, actualiza a 4.7.1 o posterior.
</Notice>

### Eliminar automáticamente comandos fallidos con sponge

El [plugin sponge](/es/mejores-plugins-fish-shell/) elimina automáticamente de tu historial los comandos que terminan con un código de salida distinto de cero. Instálalo con fisher (o a través de [Oh My Fish (OMF)](/es/oh-my-fish-instalar-temas-plugins/)):

```fish
fisher install meaningful-ooo/sponge
```

Sponge funciona mediante manejadores de eventos. Elimina las entradas *después* de que el comando se ejecute. Esto se debe a que Fish escribe el historial *antes* de ejecutar el comando (para que los comandos largos sean visibles de inmediato en las sesiones nuevas), lo que significa que un filtro pre-ejecución no puede comprobar el código de salida.

<Notice type="warning" title="sponge está sin mantenimiento">
meaningful-ooo/sponge no se actualiza desde enero de 2024 (último push 2024-01-21). Puede que siga funcionando en fish 4.x, pero pruébalo antes de confiar en él. El flujo principal más seguro es el filtro <code>fish_should_add_to_history</code> más <code>history delete</code> para la limpieza (cubierto a continuación). Sponge es un extra, no una base.
</Notice>

## Controlar qué se guarda en el historial

### El espacio inicial omite el historial (integrado)

Prefijar un comando con un espacio evita que Fish lo guarde en el historial. Esto está integrado **desde fish 2.0.0 (2013)**. Es el equivalente al `HISTCONTROL=ignorespace` de Bash y no necesitas configurar nada.

El comando sigue siendo recuperable con la flecha arriba hasta que ejecutes el siguiente comando. Después de eso, desaparece del historial persistente.

**Verificar:** ejecuta esto (fíjate en el espacio inicial):

```fish
 echo "this should not be saved"
```

Luego busca:

```fish
history search --exact 'echo "this should not be saved"'
```

Sin coincidencias. Es el comportamiento integrado haciendo su trabajo.

### La función fish_should_add_to_history

Para un control programático sobre lo que se guarda, define `fish_should_add_to_history`. Fish 4.0.0 añadió este hook.

```fish
# ~/.config/fish/functions/fish_should_add_to_history.fish
function fish_should_add_to_history
    # Reimplementar la regla del espacio inicial (ver aviso más abajo)
    string match -qr '^\s' -- $argv[1]; and return 1

    # No guardar comandos muy cortos
    test (string length -- $argv[1]) -lt 3; and return 1

    # No guardar comandos que coincidan con patrones sensibles
    string match -qr 'password|secret|token|api.key' -- $argv[1]; and return 1

    return 0
end
```

El contrato (según la documentación oficial):

- `$argv[1]` es la línea de comandos a punto de ejecutarse.
- La función se ejecuta **antes** de que el comando se ejecute, así que `$status` no está disponible. Es así por diseño. Los comandos se escriben en el historial antes de ejecutarse, para que los comandos largos o los de `exec` aparezcan de inmediato en las sesiones nuevas.
- Devuelve 0 para guardar el comando. Devuelve un valor distinto de cero para omitirlo. Los comandos omitidos siguen siendo recuperables durante una ejecución más y luego desaparecen.

<Notice type="warning" title="Definir esta función desactiva la regla del espacio inicial">
Si <code>fish_should_add_to_history</code> existe, asume todas las tareas de filtrado del historial. La regla integrada de "el espacio omite el historial" deja de aplicarse a menos que tu función la reimplemente. Por eso el ejemplo anterior comprueba el espacio inicial con <code>string match -qr '^\s'</code>. Sin esa línea, los comandos con espacio inicial volverían a guardarse. Consulta la <a href="/es/fish-shell-funciones-comandos-personalizados/">guía de la función fish_should_add_to_history</a> para más patrones de funciones.
</Notice>

Así fluye la decisión cuando se introduce un comando:

- Si `fish_should_add_to_history` **no** existe: el comando se guarda a menos que empiece con un espacio.
- Si la función **sí** existe: la función lo decide todo. Devolver 0 guarda, devolver un valor distinto de cero omite. La regla del espacio inicial se pasa por alto a menos que la función la compruebe.

## Modo privado: comandos que nunca llegan al historial

A veces necesitas ejecutar comandos sin dejar rastro: screencasts, sesiones compartidas o trabajo sensible en una máquina de producción. Fish tiene tres mecanismos distintos, cada uno con un compromiso diferente.

<Tabs>
<Tab name="Grabación / demo">

```fish
fish --private
# o: fish -P
# o dentro de una sesión: set fish_private_mode
```

Oculta el historial existente y no escribe nada en disco. El historial antiguo es invisible (así que no hay filtraciones en las autosugerencias) y nada de lo que escribas persiste. Los scripts pueden comprobarlo:

```fish
if test -n "$fish_private_mode"
    echo "running in private mode"
end
```

Ideal para demos, grabaciones y pantallas compartidas.

</Tab>
<Tab name="Sesión puntual sensible">

```fish
set fish_history ""
```

El historial no se almacena en absoluto durante esta sesión. El truco del nombre de sesión pone el archivo de historial con un nombre vacío, así que nada se escribe. Esto también inhibe la importación del historial de Bash en máquinas nuevas.

Ideal cuando quieres una sesión de aspecto normal (la búsqueda en el historial sigue funcionando dentro de la sesión) pero con persistencia cero.

</Tab>
<Tab name="Historial de proyecto separado">

```fish
set fish_history work
```

El historial va a un archivo `work_history` separado. Cualquier nombre distinto del predeterminado también inhibe la importación del historial de Bash, lo que mantiene limpia tu máquina de presentaciones.

Ideal cuando quieres historial para un proyecto concreto sin mezclarlo en tu archivo principal.

</Tab>
</Tabs>

Para limpiar a posteriori (en lugar de prevenir), usa `history clear-session`, cubierto en la siguiente sección.

**Nota operativa:** el modo privado es la forma más barata de hacer una demo en un VPS de producción sin filtrar hostnames, rutas ni claves. Un flag, cero limpieza.

## Historial entre múltiples sesiones

Fish gestiona el historial entre sesiones de forma diferente a Bash. Cada sesión de Fish mantiene su propio historial en memoria y escribe en el archivo de historial compartido a medida que ejecutas comandos:

- Cuando ejecutas un comando, pasa a la memoria de la sesión actual y se escribe en `fish_history` en disco.
- Las demás sesiones en ejecución no ven el nuevo comando de inmediato.
- Las sesiones nuevas que se inicien después de guardar el comando sí lo verán.
- `history merge` fuerza a la sesión actual a cargar comandos de otras sesiones.

Un matiz de la documentación: Fish normalmente ignora los cambios de historial procedentes de sesiones iniciadas *después* de la actual. Así que si abres una terminal nueva, ejecutas algo y vuelves a una terminal más antigua, la antigua no verá el nuevo comando a menos que fusiones.

### Fusionar historial

```fish
history merge
```

Esto trae el historial de otras sesiones de Fish. Útil cuando ejecutaste algo en otra pestaña y quieres tenerlo disponible con Ctrl+R o la flecha arriba.

Vincúlalo a una tecla para acceso rápido:

```fish
bind \em 'history merge; commandline -f repaint'
```

Ahora `Alt+M` fusiona y redibuja el prompt.

**Verificar:** abre dos paneles de terminal. En uno, ejecuta `echo test-12345`. En el otro, ejecuta `history merge` y luego `history search test-12345`. Debería aparecer.

### Limpiar el historial

```fish
# Limpiar todo (pide confirmación)
history clear

# Limpiar solo el historial de la sesión actual
history clear-session

# Limpiar sin el prompt de confirmación (para scripts)
builtin history clear
```

`clear-session` es útil cuando has estado experimentando y no quieres que esos comandos contaminen tu historial, pero quieres conservar todo lo anterior.

<Notice type="warning" title="builtin history clear omite el prompt">
<code>builtin history clear</code> omite el prompt de confirmación. Es cómodo en scripts pero irreversible sin una copia de seguridad. Compruébalo dos veces antes de ejecutarlo, sobre todo en un script que podría ejecutarse inesperadamente.
</Notice>

**Modo de fallo (nota de operador):** antes de fish 4.7.0, las sesiones terminadas por `kill` o por desconexiones SSH podían corromper `fish_history` con bytes NUL. Corregido en 4.7.0 (issue #10300). Fish 4.8.1 corrigió otro caso límite en el que la búsqueda en el historial "olvidaba" comandos re-ejecutados en sesiones concurrentes. Si usas muchos paneles en [multiplexores de terminal como tmux](/es/mejores-multiplexores-terminal/) en un VPS y ves comportamientos raros del historial, comprueba primero tu versión de fish.

## Sincronizar el historial de Fish Shell entre máquinas con atuin

Fish no sincroniza el historial entre máquinas de forma nativa. El viejo consejo era crear un enlace simbólico o sincronizar `fish_history` con los dotfiles, pero eso se rompe rápido: dos máquinas escribiendo en el mismo archivo a la vez no tienen semántica de fusión y acabas con conflictos o entradas perdidas.

La respuesta estándar actual es **atuin**. Es una herramienta de historial de shell que guarda los comandos en una base de datos SQLite local (capturando el comando, el código de salida, el directorio de trabajo, el hostname y la duración), reemplaza Ctrl+R y opcionalmente la flecha arriba con una mejor interfaz de búsqueda, y ofrece **sincronización cifrada de extremo a extremo** opcional entre máquinas. A noviembre de 2026, atuin tiene más de 32k estrellas en GitHub en la v18.24.5 y se mantiene activamente. Es compatible con Fish y tu `fish_history` existente no se reemplaza: atuin lo importa.

### Instalación

1. Instala el binario de atuin (consulta la [documentación oficial de instalación](https://docs.atuin.sh/latest/guide/installation/) para el one-liner de tu SO).

2. Añade el snippet de inicio a `~/.config/fish/config.fish`, dentro del guard interactivo:

```fish
if status is-interactive
    atuin init fish | source
end
```

3. Registra una cuenta (o inicia sesión en las demás máquinas):

```fish
atuin register -u <your-username> -e <your-email>
# En las demás máquinas: atuin login -u <your-username>
```

4. Importa tu historial de Fish existente:

```fish
atuin import auto
```

5. Sincroniza:

```fish
atuin sync
```

**Verificar:**

```fish
atuin stats
atuin history list | head
```

Deberías ver tus entradas importadas y las estadísticas de uso. Pulsa Ctrl+R y debería abrirse la interfaz de búsqueda de atuin.

<Button text="Documentación de atuin" link="https://docs.atuin.sh" variant="outline" color="gray" size="sm" icon="arrow-right" />

### Endurecimiento y notas de operación

<Notice type="info" title="Mantén los secretos fuera del historial sincronizado">
atuin sincroniza todo lo que captura. Usa <code>history_filter</code> en <code>~/.config/atuin/config.toml</code> para mantener los comandos sensibles fuera del almacén compartido:
</Notice>

```toml
# ~/.config/atuin/config.toml
history_filter = [
    "password",
    "secret",
    "token",
    "api.key",
    "curl.*-u ",
]
```

Otras cosas que conviene saber. Tu clave de cifrado protege los datos sincronizados: piérdela y perderás el acceso a la sincronización (el almacén local no se ve afectado), así que haz una copia de seguridad. atuin reemplaza Ctrl+R por defecto, pero muchos operadores mantienen la flecha arriba nativa y solo vinculan atuin a Ctrl+R; el ajuste existe en la configuración de atuin. Si no quieres Atuin Cloud, puedes alojar el servidor de sincronización tú mismo. Funciona bien en [un VPS asequible como Hetzner](https://go.bitdoze.com/hetzner). Encaja bien si ya tienes una máquina pequeña para copias de seguridad o monitorización. Y si quieres salirte, atuin mantiene su propio almacén SQLite y no modifica tu `fish_history`. Desinstálalo y tu historial original queda intacto.

**Modo de fallo:** poner `atuin init fish | source` fuera del bloque `if status is-interactive` provoca errores en shells no interactivos (scripts, SCP, etc.). Protégelo siempre.

**Nota de coste:** Atuin Cloud tiene un nivel gratuito y planes de pago pequeños para uso más intenso. Autoalojar el servidor de sincronización cuesta lo que cueste un VPS pequeño, del orden de 5 $/mes.

## Guardar, añadir y respaldar el archivo de historial

### Guardar el historial manualmente

```fish
history save
```

Esto fuerza una escritura inmediata en disco. Fish guarda automáticamente de forma periódica y al salir, así que normalmente no deberías necesitarlo. La documentación señala que está "provisto para uso interno". Fish 4.1.0 añadió mejoras de robustez a las rutinas de guardado, pero confiar en guardados manuales no sustituye a entender cuándo escribe Fish (en cada comando).

### Añadir comandos sin ejecutarlos

```fish
history append "some command I want to remember"
```

Esto añade el comando al historial sin ejecutarlo. Útil para marcar comandos que quieras encontrar después con Ctrl+R.

### Copia de seguridad y restauración

El archivo de historial es trivialmente portable:

```fish
cp ~/.local/share/fish/fish_history ~/fish_history_backup
```

Para restaurar:

```fish
cp ~/fish_history_backup ~/.local/share/fish/fish_history
history merge
```

<Notice type="warning" title="Restaurar copias de seguridad antiguas">
Fish rechaza los archivos de historial en formato antiguo 1.x. Verás "unsupported history file format 1.x" y el archivo no cargará. Si restauras una copia procedente de una instalación de Fish anterior a 3.0 en un sistema moderno, simplemente no funcionará. Conviértelo o empieza de cero. Además: no edites <code>fish_history</code> a mano mientras haya sesiones de Fish abiertas. Usa <code>history delete</code> en su lugar. Las escrituras concurrentes de una sesión abierta sobrescribirán tus ediciones.
</Notice>

**Verificar:** después de la copia, `head -2 ~/fish_history_backup` debería mostrar entradas `- cmd:`. Restaura primero en una ruta de prueba e inspecciónalo antes de sobrescribir tu archivo real.

Si gestionas dotfiles entre máquinas, puedes incluir el archivo de historial en tu sincronización, pero las escrituras concurrentes desde varias máquinas causarán conflictos. Para una sincronización real entre máquinas, usa atuin (ver la [sección de sincronización](#sincronizar-el-historial-de-fish-shell-entre-máquinas-con-atuin) de arriba).

## Consejos útiles sobre el historial

**Usa abreviaturas en lugar de buscar en el historial.** Si escribes un comando cada día, añádelo como [abreviatura](/es/fish-shell-abreviaturas-vs-alias/) en lugar de buscarlo cada vez.

**Combínalo con fzf.** El [plugin fzf.fish](/es/mejores-plugins-fish-shell/) reemplaza Ctrl+R con una búsqueda difusa más rápida de navegar. Muestra vista previa y admite selección múltiple.

**Elimina por patrón tras rotar un secreto.** Si cambiaste una contraseña y la antigua está en tu historial, `history delete --prefix "mysql -p"` lo limpia de una vez.

**Marcas de tiempo personalizadas para auditorías.** `history search --show-time="%Y-%m-%d %H:%M:%S " --max 20 docker` te da un rastro con marcas de tiempo. Útil cuando reconstruyes lo que pasó en una máquina.

## FAQ

<Accordion label="¿Dónde guarda fish su archivo de historial?" group="faq" expanded="true">
Fish guarda el historial en `~/.local/share/fish/fish_history` (o `$XDG_DATA_HOME/fish/fish_history`). Puedes apuntar una sesión a un archivo distinto con `set fish_history <nombre>`, que escribe en `<nombre>_history` en su lugar.
</Accordion>

<Accordion label="¿Cómo elimino una entrada del historial de fish?" group="faq">
Tres opciones: `history delete --exact --case-sensitive "<command>"` para una eliminación silenciosa de un solo paso, `history delete <término>` para un selector interactivo, o **Shift+Delete** mientras la entrada está visible (funciona durante la búsqueda con flecha arriba y para las autosugerencias).
</Accordion>

<Accordion label="¿Tiene fish un límite de tamaño de historial como HISTSIZE?" group="faq">
Sí. Fish limita el historial a 262.144 entradas (256 x 1024), en vigor desde fish 3.7.0. Las entradas más antiguas se recortan al alcanzar el tope. No hay ninguna variable para cambiarlo.
</Accordion>

<Accordion label="¿Cómo ejecuto un comando sin que fish lo guarde?" group="faq">
Prefija el comando con un espacio (integrado desde fish 2.0.0). Para toda una sesión, usa `fish --private` o `set fish_history ""`. Para filtrado programático, define `fish_should_add_to_history`, pero ten en cuenta que definirla desactiva la regla integrada del espacio inicial a menos que tu función la reimplemente.
</Accordion>

<Accordion label="¿Por qué no carga mi copia de historial antigua?" group="faq">
Fish rechaza los archivos de historial en formato antiguo 1.x ("unsupported history file format 1.x"). Si tu copia proviene de una instalación de Fish anterior a 3.0, no cargará en un Fish moderno. Empieza de cero o convierte el archivo.
</Accordion>

<Accordion label="¿Sincroniza fish el historial entre máquinas?" group="faq">
No de forma nativa. La respuesta fiable es [atuin](#sincronizar-el-historial-de-fish-shell-entre-máquinas-con-atuin), que guarda el historial en SQLite y ofrece sincronización cifrada de extremo a extremo. Enlazar el archivo `fish_history` directamente es frágil: las escrituras concurrentes desde varias máquinas causan conflictos.
</Accordion>
