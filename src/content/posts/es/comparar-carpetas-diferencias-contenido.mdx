Para comparar dos carpetas, ejecuta `diff -rq old new`. Lista cada archivo que existe en una sola de las dos carpetas y cada archivo común cuyo contenido difiere. Añade `-x node_modules` para omitir una carpeta por su nombre. Después, `diff -u` muestra qué cambió dentro de un archivo, `git diff --no-index` cuenta las líneas cambiadas y `rsync -n` dice qué haría una sincronización.

Mi caso fue un zip de código terminado. Contraté a alguien para arreglar unos problemas en este sitio hecho con Astro. Me envió el resultado como archivo comprimido y, antes de copiar nada, necesitaba ver qué archivos había modificado.

Todos los bloques de salida de abajo son reales. Las ejecuciones de `diff`, `find`, `sha256sum`, `comm` y `grep` salen de GNU diffutils 3.10, findutils 4.9.0, coreutils 9.4 y grep 3.11 en un contenedor de Ubuntu 24.04. `rsync` 3.5.1 y `git` 2.43.0 corrieron en el host. Las dos carpetas son `old`, mi checkout, y `new`, la entrega descomprimida. Entre ellas hay tres archivos cambiados, `README.md` ya no está, `new` añade un post y ambos lados traen `node_modules`. No ejecuté nada en macOS, así que las notas sobre macOS citan sus páginas de manual.

Necesitas `diff`, que Linux y macOS traen de serie. `git` y `rsync` cubren las secciones posteriores y no necesitan ningún repositorio. `grep` aparece a lo largo de todo el artículo, y la [referencia de comandos de Linux](/es/comandos-linux/) tiene sus opciones. Para dos rutas largas, [zoxide](/es/zoxide-tutorial/) salta entre directorios.

## Qué comando responde a qué pregunta

| Quieres saber | Comando | Lee el contenido de los archivos |
|---|---|---|
| Qué archivos existen en un solo lado y qué archivos comunes difieren | `diff -rq -x node_modules old new` | Sí: cada archivo común, en ambos lados |
| Qué nombres existen en cada lado, sin leer los archivos | `diff <(cd old && find . \| sort) <(cd new && find . \| sort)` | No |
| Qué cambió dentro de un archivo | `diff -u old/package.json new/package.json` | Solo esa pareja |
| Cuántas líneas cambiaron en cada archivo | `git diff --no-index --stat old new` | Sí |
| Qué archivos se añadieron, modificaron o borraron | `git diff --no-index --name-status old new` | Sí |
| Qué copiaría, sobrescribiría o borraría una sincronización | `rsync -rn -avi --delete new/ old/` | No: solo tamaño y fecha; con `-c`, sí |
| Si dos archivos son idénticos byte a byte | `git hash-object a b` | Solo esos dos |

`diff -rq` lee cada archivo que existe en ambos lados. `rsync -n` solo mira el tamaño y la fecha de modificación, así que no abre ningún archivo, y se le escapa un tipo de cambio.

## ¿Cómo comparo dos carpetas y veo los archivos distintos?

Ejecuta `diff -rq old new`. Imprime una línea `Only in` por cada archivo que existe en un solo lado y una línea `Files ... differ` por cada archivo común cuyo contenido difiere.

`-r` (`--recursive`) entra en las subcarpetas. `-q` (`--brief`) imprime una línea por archivo en lugar de las líneas que cambian.

```bash
diff -rq old new
echo "exit status: $?"
```

```text
Only in old: README.md
Files old/node_modules/astro/package.json and new/node_modules/astro/package.json differ
Files old/package.json and new/package.json differ
Files old/public/favicon.ico and new/public/favicon.ico differ
Only in new/src: .DS_Store
Only in new/src/assets: brand logo.svg
Files old/src/config/menu.json and new/src/config/menu.json differ
Only in new/src/content/posts: contractor-notes.mdx
Files old/src/layouts/Base.astro and new/src/layouts/Base.astro differ
exit status: 1
```

Hay dos tipos de línea:

- `Only in old: README.md`: la entrada existe en un solo lado. La carpeta es la ruta que le diste a `diff` y el nombre que va después de los dos puntos es la entrada. Una carpeta presente en un solo lado recibe una sola línea para la carpeta.
- `Files old/package.json and new/package.json differ`: la misma ruta relativa en ambos lados, con contenido distinto.

Dos líneas son ruido. La carpeta `node_modules` de este sitio contiene 35,940 archivos, y `.DS_Store` es un archivo de ajustes que el Finder de macOS escribe dentro de las carpetas. Sin `-r`, `diff` compara solo los archivos del nivel superior e imprime `Common subdirectories: old/src and new/src` por cada subcarpeta.

### Omite el ruido

`-x NAME` (`--exclude=PATTERN`) salta todos los archivos o carpetas que llevan ese nombre, a cualquier profundidad. Repítelo por cada nombre y entrecomilla un patrón con comodines, como en `-x '*.md'`, que salta todos los archivos Markdown. `-X FILE` (`--exclude-from=FILE`) lee los patrones de un archivo, uno por línea.

```bash
diff -rq -x node_modules -x .DS_Store old new
echo "exit status: $?"
```

```text
Only in old: README.md
Files old/package.json and new/package.json differ
Files old/public/favicon.ico and new/public/favicon.ico differ
Only in new/src/assets: brand logo.svg
Files old/src/config/menu.json and new/src/config/menu.json differ
Only in new/src/content/posts: contractor-notes.mdx
Files old/src/layouts/Base.astro and new/src/layouts/Base.astro differ
exit status: 1
```

`-s` (`--report-identical-files`) hace que `diff` liste también los archivos que encontró iguales, cinco en este caso. Esa es la prueba de que un archivo que falta en la lista más corta es idéntico:

```bash
diff -rqs -x node_modules -x .DS_Store old new
```

```text
Only in old: README.md
Files old/astro.config.mjs and new/astro.config.mjs are identical
Files old/package.json and new/package.json differ
Files old/public/favicon.ico and new/public/favicon.ico differ
Files old/scripts/build.sh and new/scripts/build.sh are identical
Only in new/src/assets: brand logo.svg
Files old/src/config/menu.json and new/src/config/menu.json differ
Files old/src/consts.ts and new/src/consts.ts are identical
Files old/src/content/posts/add-accordion-carrd.mdx and new/src/content/posts/add-accordion-carrd.mdx are identical
Only in new/src/content/posts: contractor-notes.mdx
Files old/src/layouts/Base.astro and new/src/layouts/Base.astro differ
Files old/src/pages/index.astro and new/src/pages/index.astro are identical
```

### Estado de salida en los scripts

`diff` sale con 0 si hay coincidencia, 1 si hay diferencias y 2 si no pudo terminar:

```bash
diff -rq old/src/pages new/src/pages
echo "exit status: $?"
diff -rq old missing
echo "exit status: $?"
```

```text
exit status: 0
diff: missing: No such file or directory
exit status: 2
```

El estado 1 es un resultado normal, así que `diff -rq old new || echo "they differ"` imprime su mensaje también cuando la ruta está mal escrita. Bifurca según el estado:

```bash
diff -rq -x node_modules -x .DS_Store old new > /tmp/differences.txt
case $? in
  0) echo "same" ;;
  1) echo "differences in /tmp/differences.txt" ;;
  *) echo "diff could not finish, check the paths" ;;
esac
```

```text
differences in /tmp/differences.txt
```

Con carpetas idénticas eso imprime `same`; con una ruta que falta, `diff could not finish, check the paths`. La redirección va primero para que la salida caiga en el archivo mientras `$?` sigue siendo el de `diff`.

### Enlaces simbólicos

`diff` sigue un enlace simbólico y compara aquello a lo que apunta. Supón que `new/astro.config.mjs` es un enlace a mi copia en vez de un archivo:

```bash
rm new/astro.config.mjs
ln -s ../old/astro.config.mjs new/astro.config.mjs
diff -rq -x node_modules -x .DS_Store old new | grep astro.config
echo "grep exit status: $?"
```

```text
grep exit status: 1
```

El enlace resuelve a un contenido idéntico, así que `diff` no dice nada. `--no-dereference` compara el enlace en sí:

```bash
diff -rq --no-dereference -x node_modules -x .DS_Store old new | grep astro.config
```

```text
File old/astro.config.mjs is a regular file while file new/astro.config.mjs is a symbolic link
```

Un enlace roto cambia el estado de salida. `diff` imprime `diff: new/astro.config.mjs: No such file or directory`, lista el resto y sale con 2. `find new -xtype l` nombra esos enlaces antes de que `diff` tropiece con ellos.

### Opciones para comparar carpetas

| Opción | Forma larga | Efecto |
|---|---|---|
| `-r` | `--recursive` | Entra en las subcarpetas |
| `-q` | `--brief` | Una línea por archivo que difiere |
| `-s` | `--report-identical-files` | Lista también los archivos idénticos |
| `-x PATTERN` | `--exclude=PATTERN` | Salta los nombres que coinciden, a cualquier profundidad |
| `-X FILE` | `--exclude-from=FILE` | Lee los patrones de un archivo |
| `-N` | `--new-file` | Un archivo que falta cuenta como vacío, así que aparece como líneas añadidas o quitadas |
| ninguna | `--unidirectional-new-file` | Como `-N`, solo para los archivos que faltan en la primera carpeta |
| ninguna | `--no-dereference` | Compara los enlaces como enlaces |
| ninguna | `--strip-trailing-cr` | Trata igual CRLF y LF |
| ninguna | `--ignore-file-name-case` | `Menu.json` coincide con `menu.json` |
| `-i`, `-w`, `-b`, `-B` | `--ignore-case`, `--ignore-all-space`, `--ignore-space-change`, `--ignore-blank-lines` | Ignora mayúsculas y minúsculas, espacios o líneas en blanco dentro de los archivos |

En macOS, `diff` es la implementación de BSD. Su [página de manual](https://keith.github.io/xcode-man-pages/diff.1.html), fechada el 7 de enero de 2025, lista las mismas opciones `-r`, `-q`, `-s`, `-x`, `-X`, `-N` y `--no-dereference` y define los mismos estados de salida. Añade `-P` como forma corta de `--unidirectional-new-file`. En modo carpeta, el `diff` de BSD compara solo archivos regulares y carpetas, e imprime un diagnóstico para cualquier otra cosa. No lo ejecuté.

<Notice type="warning" title="Comprueba qué diff estás ejecutando">
Algunos sistemas Linux traen una versión reescrita en Rust en lugar de la de GNU. [uutils coreutils es el predeterminado desde Ubuntu 25.10](https://uutils.org/users/), y en uno de los hosts donde ejecuté esto, `diff --version` imprime `diff (pi-uu-diff) 0.8.0`. Su salida con `-rq`, `-r`, `-rqs` y `-rqN` coincidió con la de GNU línea por línea en estas dos carpetas. Aparecieron dos diferencias. La cabecera de `diff -r` omitía las opciones, y `-q` junto con `--brief` se detenía con `error: the argument '--brief' cannot be used multiple times`. Comprueba `diff --version` antes de que un script analice la salida.
</Notice>

## Filtra la salida de `diff` con grep

Los archivos que existen en un solo lado:

```bash
diff -rq old new | grep '^Only in'
```

```text
Only in old: README.md
Only in new/src: .DS_Store
Only in new/src/assets: brand logo.svg
Only in new/src/content/posts: contractor-notes.mdx
```

Los archivos comunes que difieren:

```bash
diff -rq old new | grep differ
```

```text
Files old/node_modules/astro/package.json and new/node_modules/astro/package.json differ
Files old/package.json and new/package.json differ
Files old/public/favicon.ico and new/public/favicon.ico differ
Files old/src/config/menu.json and new/src/config/menu.json differ
Files old/src/layouts/Base.astro and new/src/layouts/Base.astro differ
```

Un nombre ruidoso quitado después de la ejecución:

```bash
diff -rq old new | grep -v node_modules
```

```text
Only in old: README.md
Files old/package.json and new/package.json differ
Files old/public/favicon.ico and new/public/favicon.ico differ
Only in new/src: .DS_Store
Only in new/src/assets: brand logo.svg
Files old/src/config/menu.json and new/src/config/menu.json differ
Only in new/src/content/posts: contractor-notes.mdx
Files old/src/layouts/Base.astro and new/src/layouts/Base.astro differ
```

`^` ancla el patrón al inicio de la línea y `-v` invierte la coincidencia. `diff` leyó `node_modules` igualmente para producir esas líneas, así que `-x` es para carpetas grandes y `grep -v` para el ruido que notaste tarde.

### Nombres con espacios

En esa línea, solo el `: ` separa una carpeta de un nombre de archivo. Un análisis que corta por espacios pierde todo lo que viene después del primer espacio:

```bash
diff -rq old new | grep '^Only in' | awk '{print $4}'
```

```text
README.md
.DS_Store
brand
contractor-notes.mdx
```

La cuarta palabra de `Only in new/src/assets: brand logo.svg` es `brand`. Toma mejor todo lo que viene después del último `: `, como hace el script de abajo.

## Mira qué cambió dentro de los archivos

`diff -rq` se queda en el nombre del archivo. Para ver el contenido de un archivo:

```bash
diff -u old/package.json new/package.json
echo "exit status: $?"
```

```text
--- old/package.json	2026-11-10 09:00:00.000000000 +0000
+++ new/package.json	2026-11-20 18:30:00.000000000 +0000
@@ -3,6 +3,7 @@
   "type": "module",
   "version": "1.2.0",
   "dependencies": {
-    "astro": "^4.16.0"
+    "astro": "^4.16.0",
+    "@astrojs/sitemap": "^3.2.1"
   }
 }
exit status: 1
```

`---` y `+++` nombran los dos archivos, y `@@ -3,6 +3,7 @@` da los números de línea de cada lado. Las líneas `-` ya no están y las líneas `+` son nuevas. El contratista añadió la integración del sitemap.

Sin `-q`, `diff -r` imprime los cambios de cada archivo que difiere, en su formato predeterminado más antiguo:

```bash
diff -r -x node_modules -x .DS_Store old new
```

```text
Only in old: README.md
diff -r -x node_modules -x .DS_Store old/package.json new/package.json
6c6,7
<     "astro": "^4.16.0"
---
>     "astro": "^4.16.0",
>     "@astrojs/sitemap": "^3.2.1"
Binary files old/public/favicon.ico and new/public/favicon.ico differ
Only in new/src/assets: brand logo.svg
diff -r -x node_modules -x .DS_Store old/src/config/menu.json new/src/config/menu.json
3a4
>   { "text": "Deals", "link": "/deals/" },
Only in new/src/content/posts: contractor-notes.mdx
diff -r -x node_modules -x .DS_Store old/src/layouts/Base.astro new/src/layouts/Base.astro
6a7
>     <meta name="generator" content={Astro.generator} />
```

`6c6,7` significa que la línea 6 del primer archivo pasó a ser las líneas 6 y 7 del segundo. `3a4` significa que el segundo archivo añade una línea 4 después de la línea 3. Las líneas `<` vienen del primer archivo y las `>` del segundo. Un archivo binario recibe una sola línea `Binary files ... differ`.

### Trata un archivo que falta como vacío con `-N`

Para un parche, un archivo que existe en un solo lado debería aparecer como contenido. `-N` (`--new-file`) lo compara con un archivo vacío:

```bash
diff -r old/src/content/posts new/src/content/posts
echo "exit status: $?"
diff -rN old/src/content/posts new/src/content/posts
echo "exit status: $?"
```

```text
Only in new/src/content/posts: contractor-notes.mdx
exit status: 1
diff -rN old/src/content/posts/contractor-notes.mdx new/src/content/posts/contractor-notes.mdx
0a1,5
> ---
> title: What Changed in This Delivery
> date: 2026-11-20
> ---
> Sitemap integration and a new menu entry.
exit status: 1
```

`--unidirectional-new-file` hace lo mismo solo con los archivos que faltan en la primera carpeta, así que `README.md` sigue siendo una línea `Only in old`. Deja `-N` fuera de las ejecuciones con `-q`. Ahí convierte las líneas `Only in` en líneas `Files ... differ` y oculta en qué lado está el archivo.

### Un solo parche para toda la entrega

`-u` con `-r` y `-N` hace un solo parche con la comparación. `git apply --stat` lo lee fuera de cualquier repositorio:

```bash
diff -ruN -x node_modules -x .DS_Store old new > delivery.patch
git apply --stat delivery.patch
```

```text
 README.md                              |    3 ---
 package.json                           |    3 ++-
 src/assets/brand logo.svg              |    1 +
 src/config/menu.json                   |    1 +
 src/content/posts/contractor-notes.mdx |    5 +++++
 src/layouts/Base.astro                 |    1 +
 6 files changed, 10 insertions(+), 4 deletions(-)
```

El favicon no aparece porque `diff` escribe `Binary files ... differ` en el parche y ningún dato, así que los cambios binarios necesitan una copia a mano. Dentro de `old`, `git apply --check ../delivery.patch` dice `applies cleanly`. `git apply` aplica el parche y `git apply -R` lo revierte.

## Cuenta las líneas cambiadas con git

`git diff --no-index` compara dos rutas sin necesidad de repositorio. La [referencia de comandos de git](/es/comandos-git/) también tiene una sección sobre `git diff`. Supón que `new/scripts/build.sh` perdió su bit de ejecución, `chmod 644 new/scripts/build.sh`. `--stat` da una línea por archivo:

```bash
git diff --no-index --stat old new
echo "exit status: $?"
```

```text
 old/README.md => /dev/null                              |   3 ---
 {old => new}/node_modules/astro/package.json            |   2 +-
 {old => new}/package.json                               |   3 ++-
 {old => new}/public/favicon.ico                         | Bin 514 -> 584 bytes
 {old => new}/scripts/build.sh                           |   0
 /dev/null => new/src/.DS_Store                          | Bin 0 -> 6148 bytes
 /dev/null => new/src/assets/brand logo.svg              |   1 +
 {old => new}/src/config/menu.json                       |   1 +
 /dev/null => new/src/content/posts/contractor-notes.mdx |   5 +++++
 {old => new}/src/layouts/Base.astro                     |   1 +
 10 files changed, 11 insertions(+), 5 deletions(-)
exit status: 1
```

`{old => new}/package.json` es la forma que tiene git de escribir las dos rutas de un mismo archivo. `old/README.md => /dev/null` es una eliminación. `{old => new}/scripts/build.sh` muestra cero líneas cambiadas porque git cuenta un cambio de modo como una modificación. `diff -q` no imprime nada para esa pareja, porque solo lee contenido. `--summary` nombra el cambio:

```bash
git diff --no-index --summary old new
```

```text
 delete mode 100644 old/README.md
 mode change 100755 => 100644 new/scripts/build.sh
 create mode 100644 new/src/.DS_Store
 create mode 100644 new/src/assets/brand logo.svg
 create mode 100644 new/src/content/posts/contractor-notes.mdx
```

`--name-status` da lo mismo con una letra por archivo: `A` añadido, `M` modificado, `D` borrado. Imprime la ruta antigua para `M` y `D`, y la ruta nueva para `A`. git 2.43.0 no acepta pathspec en este modo y responde con el texto de uso y el estado de salida 129, así que el ruido pasa por `grep`. La [documentación de git](https://git-scm.com/docs/git-diff) dice que las versiones más recientes aceptan pathspecs después de dos carpetas. No lo ejecuté.

```bash
git diff --no-index --name-status old new | grep -v -e node_modules -e .DS_Store
```

```text
D	old/README.md
M	old/package.json
M	old/public/favicon.ico
M	old/scripts/build.sh
A	new/src/assets/brand logo.svg
M	old/src/config/menu.json
A	new/src/content/posts/contractor-notes.mdx
M	old/src/layouts/Base.astro
```

## Previsualiza una sincronización con una simulación de rsync

`rsync -n` dice qué pasaría si hicieras desaparecer las diferencias:

```bash
rsync -rn -avi --delete --exclude node_modules --exclude .DS_Store new/ old/
```

```text
sending incremental file list
*deleting   README.md
.d..t...... ./
>f.st...... package.json
>f.st...... public/favicon.ico
.f...p..... scripts/build.sh
.d..t...... src/
.d..t...... src/assets/
>f+++++++++ src/assets/brand logo.svg
>f.st...... src/config/menu.json
.d..t...... src/content/posts/
>f+++++++++ src/content/posts/contractor-notes.mdx
>f.st...... src/layouts/Base.astro

sent 624 bytes  received 74 bytes  1,396.00 bytes/sec
total size is 1,816  speedup is 2.60 (DRY RUN)
```

`-n` (`--dry-run`) no cambia nada. `-a` es recursivo y conserva permisos, fechas, enlaces, propietario y grupo. `-v` imprime la lista de archivos y `-i` (`--itemize-changes`) añade el código delante de cada nombre. `--delete` convierte el destino en un espejo, así que rsync lista también los archivos que faltan en el origen. `--exclude` hace en rsync lo que `-x` hace en `diff`. La [guía de exclude de rsync](/es/excluir-directorios-archivos-copiar-remoto/) tiene las reglas de los patrones.

Los códigos:

| Código | Significado |
|---|---|
| `>f+++++++++` | Archivo nuevo que rsync copiaría: `>` enviado, `f` archivo, nueve `+` por nuevo |
| `>f.st......` | Archivo que rsync sobrescribiría: el tamaño (`s`) y la fecha (`t`) difieren |
| `.f...p.....` | Archivo que rsync no copia y al que solo da permisos nuevos (`p`) |
| `.d..t......` | Carpeta cuya marca de tiempo rsync actualizaría |
| `cd+++++++++` | Carpeta que rsync crearía |
| `*deleting` | Archivo que falta en el origen, así que rsync lo borraría |

El primer carácter es la acción (`>` copiar, `.` no copiar, `c` crear, `*` mensaje) y el segundo el tipo (`f` archivo, `d` carpeta). Los otros nueve son atributos en un orden fijo: checksum, tamaño, fecha, permisos, propietario, grupo, fecha de acceso, ACL y atributos extendidos. En esos nueve, `.` es sin cambios, `+` es nuevo y una letra es cambiado. Esta ejecución copia seis archivos, borra uno y corrige un permiso. `diff -rq` listó ocho archivos aquí, los mismos siete más `src/consts.ts`, que la simulación no vio.

### ¿Por qué la simulación se salta un archivo que cambió?

La comprobación rápida de rsync compara solo el tamaño y la fecha de modificación, en segundos enteros por defecto, así que una edición que mantiene ambos no recibe línea. Para mostrarlo, cambié una letra en `new/src/consts.ts` y le di al archivo el tamaño y la marca de tiempo de la copia antigua:

```bash
sed -i 's/Bitdoze/Bitdozc/' new/src/consts.ts
touch -r old/src/consts.ts new/src/consts.ts
diff -q old/src/consts.ts new/src/consts.ts
stat -c '%s bytes, %y, %n' old/src/consts.ts new/src/consts.ts
```

```text
Files old/src/consts.ts and new/src/consts.ts differ
88 bytes, 2026-11-10 09:00:00.000000000 +0000, old/src/consts.ts
88 bytes, 2026-11-10 09:00:00.000000000 +0000, new/src/consts.ts
```

`diff` ve el cambio y la simulación no. `grep consts` sobre la salida de la simulación no imprime nada. `-c` (`--checksum`) hace que `rsync` calcule primero el hash de cada archivo del mismo tamaño:

```bash
rsync -rnc -avi --delete --exclude node_modules --exclude .DS_Store new/ old/ | grep consts
```

```text
>fc........ src/consts.ts
```

La `c` en la tercera posición es la diferencia de checksum. `-c` lee todos los archivos de ambos lados, así que cuesta lo mismo que `diff -rq`.

### La barra al final del origen

Una barra al final del origen significa el contenido de la carpeta. Sin ella, `rsync` copia la propia carpeta dentro del destino, un nivel de más:

```bash
mkdir -p slash/src slash/dst
echo one > slash/src/file.txt
echo keep > slash/dst/file.txt
rsync -rn -avi slash/src slash/dst
rsync -rn -avi slash/src/ slash/dst
```

```text
sending incremental file list
cd+++++++++ src/
>f+++++++++ src/file.txt

sent 107 bytes  received 23 bytes  260.00 bytes/sec
total size is 4  speedup is 0.03 (DRY RUN)
sending incremental file list
>f.s....... file.txt

sent 87 bytes  received 19 bytes  212.00 bytes/sec
total size is 4  speedup is 0.04 (DRY RUN)
```

La primera ejecución crearía `dst/src/` y dejaría `dst/file.txt` como está. La segunda reemplazaría `dst/file.txt`. Con `old` y `new`, `rsync -rn -avi --delete new old` empieza con `cd+++++++++ new/`, así que `new` acabaría dentro de `old/new/` y nada en `old/` cambiaría.

`-n` es lo único que separa este comando de una sincronización real, así que déjalo hasta que cada línea de la salida sea la que esperas. Para la ejecución real, `--backup --backup-dir` mueve a una carpeta todo lo que la sincronización sobrescribe o borra:

```bash
cp -a old old.copy
rsync -a --delete --backup --backup-dir=../removed new/ old.copy/
ls removed
```

```text
README.md
node_modules
package.json
public
src
```

`removed/` contiene las cinco entradas que la sincronización reemplazó o borró. Esa carpeta es la forma de deshacer. La sincronización en sí quedó incompleta, y `diff -rq` sobre el resultado lo dice:

```bash
diff -rq old.copy new
```

```text
Files old.copy/src/consts.ts and new/src/consts.ts differ
```

`consts.ts` conservó su contenido antiguo porque la comprobación rápida no vio motivo para copiarlo. Así que el orden es simulación, ejecución real y después `diff -rq` sobre el resultado. Añade `-c` cuando un archivo pueda cambiar sin cambiar de tamaño ni de segundo.

<Notice type="info" title="macOS trae openrsync">
Desde macOS 15.4, macOS solo trae openrsync como `rsync`, y allí `rsync --version` imprime `openrsync: protocol version 29`, como cuenta una [respuesta de Apple StackExchange actualizada para 15.4](https://apple.stackexchange.com/questions/479291/shell-scripts-that-call-rsync-no-longer-work-in-macos-sequoia). La [página de manual de openrsync(1)](https://keith.github.io/xcode-man-pages/openrsync.1.html) de Apple, fechada el 21 de febrero de 2025, describe `-n` como "Do not actually modify the destination. Mainly useful in combination with -v". La misma página documenta la lista detallada solo como el token `%i` del formato de log, y no le dedica una sección propia a `--itemize-changes`. No lo ejecuté y no afirmo nada sobre su salida en una simulación. Para las líneas de arriba, `brew install rsync` te da rsync 3. La [fórmula de Homebrew](https://formulae.brew.sh/formula/rsync) estaba en la versión 3.5.2 el 2026-11-27.
</Notice>

## Ordena la salida con un script pequeño

Cuando el siguiente comando necesite las listas, convierte las líneas en registros `added`, `removed` y `modified`:

```bash
#!/usr/bin/env bash
# tree-diff.sh OLD NEW
# Prints one line per file that NEW adds, removes or modifies relative to OLD,
# with the path relative to the tree root.
# A name that contains ": " or " and " is misparsed. Use
# git diff --no-index --name-status for trees with such names.
old=${1%/}; new=${2%/}

report=$(diff -rq -x node_modules -x .DS_Store "$old" "$new"); status=$?
if [ "$status" -gt 1 ]; then
  printf 'diff exited with status %s\n' "$status" >&2
  exit "$status"
fi

while IFS= read -r line; do
  case $line in
    "Only in $new: "*|"Only in $new/"*)
      path=${line#Only in }; name=${path##*: }
      dir=${path%: "$name"}; rel=${dir#"$new"}
      printf 'added    %s\n' "${rel:+${rel#/}/}$name"
      ;;
    "Only in $old: "*|"Only in $old/"*)
      path=${line#Only in }; name=${path##*: }
      dir=${path%: "$name"}; rel=${dir#"$old"}
      printf 'removed  %s\n' "${rel:+${rel#/}/}$name"
      ;;
    "Files $old/"*" differ")
      rel=${line#Files "$old"/}; rel=${rel%" and "*}
      printf 'modified %s\n' "$rel"
      ;;
    "File "*)
      printf 'conflict %s\n' "$line"
      ;;
  esac
done <<< "$report"
```

Guárdalo como `tree-diff.sh`. El nombre es todo lo que viene después del último `: `, así que los espacios sobreviven. Un fallo de `diff` termina el script con el estado de salida del propio `diff` en lugar de con media lista. `sort` agrupa los registros por etiqueta:

```bash
bash tree-diff.sh old new | sort
```

```text
added    src/assets/brand logo.svg
added    src/content/posts/contractor-notes.mdx
modified package.json
modified public/favicon.ico
modified src/config/menu.json
modified src/consts.ts
modified src/layouts/Base.astro
removed  README.md
```

El recuento es la comprobación: ocho líneas de `diff -rq`, ocho registros del script. Una carpeta presente en un solo lado da un registro para la carpeta, `added    src/components`, porque esa es la línea que `diff` imprime. El script interpreta mal un nombre que contiene `: ` o ` and `, así que usa `git diff --no-index --name-status` con esas carpetas.

## Compara checksums cuando no importan las fechas ni los modos

`diff -rq` necesita las dos carpetas en la misma máquina y las lee juntas. Una lista de checksums parte eso en dos: calcula el hash de cada archivo una vez, guarda la lista pequeña y compara listas en lugar de carpetas. Las fechas, los permisos y los nombres no intervienen en un hash.

```bash
(cd old && find . -type f -not -path './node_modules/*' -not -name .DS_Store -exec sha256sum {} + | sort -k 2) > old.sha
(cd new && find . -type f -not -path './node_modules/*' -not -name .DS_Store -exec sha256sum {} + | sort -k 2) > new.sha
head -3 old.sha
```

```text
b22c6fd0ac24afafa671f33d166ff29e4f44a5b6130b8da1783c499bf0f916f0  ./README.md
120ba8fb0361a1d1cc97a40129d83406307d6e1f131ea3601c607b6980e78f22  ./astro.config.mjs
13d8cf208372a9146bf8b5c49a492d58df8d78185651c3b2f641cefb012d79fa  ./package.json
```

Cada línea es el SHA-256 del contenido, dos espacios y después la ruta. Ejecuta la segunda línea en la otra máquina y copia `new.sha`; el resto funciona sobre dos archivos de texto. `comm` imprime las líneas exclusivas del primer archivo (`-23`) o del segundo (`-13`), y `cut` toma la ruta que va después del hash:

```bash
comm -23 <(cut -d' ' -f3- old.sha) <(cut -d' ' -f3- new.sha)
```

```text
./README.md
```

```bash
comm -13 <(cut -d' ' -f3- old.sha) <(cut -d' ' -f3- new.sha)
```

```text
./src/assets/brand logo.svg
./src/content/posts/contractor-notes.mdx
```

Una ruta con dos hashes distintos es el mismo nombre con contenido distinto. Este pipeline conserva las rutas que `diff` informa en ambos lados:

```bash
diff old.sha new.sha | grep '^[<>]' | sed -E 's/^[<>] [0-9a-f]{64}  //' | sort | uniq -d
```

```text
./package.json
./public/favicon.ico
./src/config/menu.json
./src/consts.ts
./src/layouts/Base.astro
```

Para el mismo contenido con nombres distintos, agrupa por hash. `new` tiene un SVG en dos sitios, `src/assets/brand logo.svg` y `public/brand-logo.svg`. `-w 64` compara solo el hash y `-D` imprime todas las líneas que tienen un gemelo:

```bash
cp "new/src/assets/brand logo.svg" new/public/brand-logo.svg
(cd new && find . -type f -not -path './node_modules/*' -not -name .DS_Store -exec sha256sum {} + | sort -k 2) > new.sha
sort new.sha | uniq -w 64 -D
```

```text
678f2b25181b2d024f509ee159abb63795427c002f01682a3d8b8a3032d0f918  ./public/brand-logo.svg
678f2b25181b2d024f509ee159abb63795427c002f01682a3d8b8a3032d0f918  ./src/assets/brand logo.svg
```

Para dos archivos, `git hash-object` da el mismo id al contenido idéntico, sea cual sea el nombre, la fecha o el modo:

```bash
git hash-object old/src/pages/index.astro new/src/pages/index.astro "new/src/assets/brand logo.svg" new/public/brand-logo.svg new/package.json
```

```text
6f9d3c0b6d62b942e5f2b930b539176944540fe0
6f9d3c0b6d62b942e5f2b930b539176944540fe0
461e31ea70867921ebe305ed769ba8a621142597
461e31ea70867921ebe305ed769ba8a621142597
80b4232aee789d56eedd4496fb6603bf16645bd0
```

El mismo `find` construye esas listas en un Mac, la herramienta detrás de [encontrar los archivos más grandes de un Mac](/es/mac-encontrar-archivos-grandes/). Si una carpeta está en otra máquina, ejecuta allí la línea de `find` y copia la lista. Calcular hashes a través de un montaje [NFS](/es/configurar-nfs-linux/) trae cada byte por la red. El `sed` de ese pipeline solo quita el prefijo del hash. [sed para buscar y reemplazar](/es/sed-buscar-reemplazar/) muestra la sintaxis completa. Para carpetas que gestiona una herramienta de copias de seguridad, primero va la comprobación propia de esa herramienta, por ejemplo [Pluton](/es/pluton-backup-autoalojado/) para repositorios de Restic.

## Qué falla y cómo arreglarlo

Cada fila viene de una ejecución con `old` y `new`, o de una pareja creada sobre la marcha para provocar el fallo.

| Lo que ves | Causa | Arreglo |
|---|---|---|
| Miles de líneas de `node_modules` o `.DS_Store` | `diff` compara todo lo que encuentra | `-x node_modules -x .DS_Store` |
| `Only in old/: README.md` | Una barra al final de un argumento de carpeta | Pasa `old` y `new` sin ella, o quítala como hace el script (`${1%/}`) |
| `diff: new/x: No such file or directory`, estado de salida 2 | Un enlace simbólico no apunta a nada | `find new -xtype l`, y después `--no-dereference` |
| `File old/x is a regular file while file new/x is a directory` | Un archivo se convirtió en carpeta, o al revés | Decide a mano cuál se queda; las herramientas solo lo informan |
| `cd+++++++++ new/` en una simulación | El origen perdió su barra final | `new/ old/` |
| Un archivo cambiado que falta en una sincronización | Mismo tamaño y mismo segundo que la copia antigua | `-c`, y después `diff -rq` sobre el resultado |
| Dos archivos de aspecto idéntico informados como distintos | Finales de línea CRLF contra LF | `--strip-trailing-cr` |

## Preguntas frecuentes

<Accordion label="¿diff -rq compara el contenido de los archivos o solo nombres y fechas?" group="faq">
Compara contenidos. `diff` lee cada archivo común y compara los bytes, y una fecha o un permiso cambiados no producen ninguna línea. Por eso `diff -q` no dice nada sobre `scripts/build.sh` después de que `new` perdiera su bit de ejecución, mientras que `git diff --no-index --summary` muestra `mode change 100755 => 100644`.
</Accordion>

<Accordion label="¿Cómo comparo solo la estructura de carpetas?" group="faq">
Compara listas de nombres ordenadas en lugar de contenidos: `diff <(cd old && find . | sort) <(cd new && find . | sort)`. No lee ningún archivo y responde qué nombres existen en cada lado. `diff -rq` también responde eso, y qué archivos comunes difieren.
</Accordion>

<Accordion label="¿Cómo listo los archivos que existen en un solo lado?" group="faq">
`diff -rq old new | grep '^Only in'` conserva esas líneas, cuatro en `old` y `new`. `Only in old` nombra un archivo que le falta a `new` y `Only in new` uno que le falta a `old`. `comm -23` y `comm -13` sobre dos listas de checksums dan la misma división, con las rutas a secas.
</Accordion>

<Accordion label="¿Qué significan los códigos de salida de diff -rq en un script?" group="faq">
0 significa que no hay diferencias, 1 que `diff` encontró diferencias y 2 que algo salió mal, como en `diff: missing: No such file or directory`. El estado 1 es un resultado normal, así que comprueba el 2 por separado. `diff -rq a b || echo failed` imprime su mensaje en ambos casos.
</Accordion>

<Accordion label="¿Qué hace que rsync ignore un archivo editado?" group="faq">
La comprobación rápida de rsync compara solo el tamaño y la fecha de modificación, en segundos enteros por defecto. Un archivo editado con la misma longitud y marca de tiempo, como `src/consts.ts` del ejemplo, no recibe ninguna línea. Añade `-c` y rsync calcula primero el hash de los archivos del mismo tamaño. La línea entonces es `>fc........ src/consts.ts`.
</Accordion>

<Accordion label="¿Cómo comparo dos carpetas en máquinas distintas?" group="faq">
Genera la lista de `sha256sum` de la sección de checksums en cada lado, copia los dos archivos de lista a una misma máquina y compáralos con `comm` o `diff`. Lees cada carpeta una vez, en la máquina que la contiene. `diff -rq` nunca ve la otra carpeta.
</Accordion>

<Accordion label="¿Puedo deshacer una sincronización hecha con --delete?" group="faq">
No después de haberla ejecutado, así que ejecuta primero el mismo comando con `-n` y lee cada línea. Para la ejecución real añade `--backup --backup-dir=../removed`. Con `old` y `new`, esa carpeta contenía entonces las cinco entradas que la sincronización había sobrescrito o borrado.
</Accordion>

<Accordion label="¿Esto funciona en macOS?" group="faq">
El `diff` de BSD en macOS acepta las mismas opciones `-r`, `-q`, `-s`, `-x`, `-N` y `--no-dereference` e imprime los mismos dos tipos de línea. Su página de manual tiene fecha del 7 de enero de 2025; aquí no lo ejecuté. rsync es distinto. Desde macOS 15.4, macOS solo trae openrsync como `rsync`, así que `brew install rsync` te da rsync 3.
</Accordion>
