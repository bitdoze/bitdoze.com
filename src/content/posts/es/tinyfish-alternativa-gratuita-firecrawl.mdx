## ¿Qué es TinyFish?

[TinyFish](https://go.bitdoze.com/tinyfish) es una plataforma de infraestructura web construida para agentes de IA. Los productos llevan ahora prefijo Tiny (TinyAgent era «Agent», TinyBrowser era «Browser»). Los cuatro principales salen de una única clave API:

1. **TinySearch** (Search): búsqueda web en vivo que devuelve resultados JSON estructurados. Renderizada en navegador, nunca desde caché.
2. **TinyFetch** (Fetch): renderiza cualquier URL en un navegador real y devuelve markdown limpio, JSON o HTML.
3. **TinyBrowser** (Browser): sesiones de navegador sigilosas que evitan la protección anti-bot, mantienen el estado de login y gestionan contenido dinámico.
4. **TinyAgent** (antes Agent, Web Agent): agentes de IA que navegan por páginas, rellenan formularios, se autentican en sitios y devuelven resultados estructurados.

Tres productos más nuevos van encima: **TinyMonitor** (comprobaciones programadas de cambios en páginas y temas), **TinyResearch** (informes de investigación con citas) y **TinySet** (datasets creados a partir de un prompt). Se tratan en la sección «Novedades» más abajo.

La propuesta es simple: una clave API, un Wallet, cero código de enrutamiento. Tú describes lo que quieres en lenguaje natural, y TinyFish gestiona el navegador, el proxy, la inferencia del LLM y la infraestructura anti-bot en las ejecuciones de TinyAgent y TinyBrowser.

## Por qué empecé a buscar más allá de Firecrawl

Firecrawl es bueno en lo que hace. Los endpoints `/scrape` y `/crawl` están bien diseñados, la salida en markdown es limpia, y el repositorio open source tiene más de 123.000 estrellas en GitHub. Si necesitas ingerir un sitio de documentación en un pipeline RAG, Firecrawl lo resuelve rápido.

Pero tres cosas me empujaban a buscar alternativas:

### Acumulación de créditos

Firecrawl anuncia 1 crédito por página. En la práctica, el modo JSON añade 4 créditos, el modo Enhanced añade otros 4. Un plan Standard de 100.000 créditos (83 $/mes) puede entregar tan solo 11.000 páginas útiles si necesitas ambas funciones activas. Los créditos no se acumulan de un mes a otro. Los reintentos en páginas fallidas consumen los mismos créditos que los primeros intentos.

### Sitios protegidos

Pruebas independientes de Proxyway sitúan la tasa de éxito de Firecrawl en torno al 34 % en sitios protegidos a 2 peticiones por segundo. Las plataformas de redes sociales están explícitamente restringidas. Si tus objetivos usan detección de bots moderna, estás pagando por fallos.

### Sin autenticación

Firecrawl gestiona páginas públicas. Si tu flujo de trabajo requiere iniciar sesión, navegar por un panel o tomar decisiones basadas en el contenido de la página, tienes que construir esa orquestación tú mismo. El endpoint `/interact` ayuda con acciones básicas, pero para flujos autenticados de varios pasos a través de muchos sitios, estás uniendo llamadas API y gestionando el estado de sesión por tu cuenta.

## Donde TinyFish hace cosas que Firecrawl no puede

### Búsqueda y fetch gratuitos

Esta es la que captó mi atención. [TinySearch](https://go.bitdoze.com/tinyfish) y TinyFetch son gratis y siguen funcionando con un saldo de Wallet de 0 $, dentro de estos límites:

| | TinySearch | TinyFetch |
|---|---|---|
| Por minuto | 30 peticiones | 150 URLs |
| Por día | hasta 12.000 peticiones (docs); 500 por hora (página de precios) | 1.000 URLs |
| Por petición | n/d | máx. 10 URLs |

La cuota diaria se reinicia a las 00:00 UTC. TinyFetch cuenta solo las URLs descargadas con éxito; las fallidas no cuentan. Superada la cuota necesitas saldo positivo en el Wallet (si no, HTTP 402 `INSUFFICIENT_CREDITS`), o recibes un 429 si el gasto del Wallet está desactivado. La documentación que leí no publica una tarifa por URL más allá de la cuota, así que revisa tu panel o pregunta a ventas antes de planificar un trabajo de gran volumen.

Esta es la principal diferencia práctica con Firecrawl. El nivel gratuito de Firecrawl te da 1.000 créditos al mes. La búsqueda cuesta 2 créditos por 10 resultados. El scrape cuesta 1 crédito por página. Cuando esos 1.000 créditos se acaban, esperas al mes siguiente o pagas. TinyFish te da una cuota diaria. 1.000 URLs descargadas al día son 30.000 al mes si la usas entera todos los días (1.000 x 30, aritmética, no una promesa). Los picos de volumen son donde el tope se nota.

Consulta tu propio uso con `tinyfish fetch usage` (y `tinyfish search usage`). Los fondos del Wallet solo se gastan en TinyAgent, TinyBrowser y los demás productos de pago, o en fetch y búsqueda por encima de la cuota.

### Autenticación y flujos de trabajo de varios pasos

Aquí las dos herramientas se separan. Firecrawl extrae páginas. [TinyFish](https://go.bitdoze.com/tinyfish) completa flujos de trabajo.

Ejemplo: necesitas iniciar sesión en el portal de un proveedor, navegar hasta una sección de precios que carga vía AJAX tras una espera de 2 segundos, comprobar qué SKUs han cambiado desde la semana pasada, y devolver la diferencia como JSON estructurado. En 50 portales.

Firecrawl no puede hacer esto. No está construido para ello. Tendrías que montar tu propia automatización de navegador encima de la API de Firecrawl, gestionar credenciales y estado de sesión tú mismo, y encargarte de la orquestación entre pasos.

TinyFish gestiona toda la secuencia en una sola llamada API. Describes el objetivo, y el agente se encarga del login, la navegación, la espera del contenido dinámico y la extracción de datos. Un endpoint de entrada, JSON estructurado de salida.

### Gestión anti-bot

Firecrawl usa Fire-Engine, una capa anti-bot propietaria que solo funciona en la versión alojada (no en la versión open source autoalojada). Las pruebas independientes muestran resultados mixtos en sitios fuertemente protegidos.

TinyFish ejecuta cada petición a través de una sesión de navegador nativa basada en Chromium, con gestión de peticiones a nivel de infraestructura y rotación de proxies residenciales. Defines `browser_profile: "stealth"` y TinyFish se encarga del resto. El enrutamiento geográfico está soportado (US, GB, CA, DE, FR, JP, AU) con un solo parámetro.

Ninguna herramienta es perfecta contra los sistemas de protección más agresivos. Pero el enfoque de TinyFish está incluido en todos los planes sin coste adicional, mientras que la capa anti-bot de Firecrawl es una de las funciones que cuesta créditos extra.

### Resultados de benchmarks

TinyFish informa de un 91,1 % en el benchmark WebVoyager, quedando primero frente a BrowserUse (88,3 %), Smooth (86,6 %) y Notte (84,2 %). Según lo publicado por TinyFish, la evaluación fue ejecutada de forma independiente por Mersault, con todos los agentes usando el mismo modelo subyacente (Claude Sonnet) y calificados por GPT-4o para eliminar el sesgo de autopreferencia.

En Mind2Web, TinyFish informa de un 89,9 % de precisión. Son benchmarks sobre sitios web en vivo, no sobre instantáneas en caché.

El endpoint `/agent` de Firecrawl aún no tiene un benchmark público comparable, y según la documentación de facturación de Firecrawl, las peticiones de agente se facturan incluso cuando fallan.

## Ejemplo de coste en el mundo real

Supongamos que necesitas extraer precios de productos de 100 páginas.

**Escenario 1: Las páginas son públicas y estáticas.**
Firecrawl gana en coste bruto. 100 créditos en cualquier plan, probablemente menos de un dólar. TinyFish usaría de 3 a 5 pasos de agente por página (300 a 500 pasos), con un coste de 4,80 $ a 8,00 $ a 0,016 $ por paso.

**Escenario 2: Las páginas requieren login y navegación.**
Firecrawl requiere que construyas tú mismo la lógica de autenticación y navegación. Tu tiempo de ingeniería es el coste real aquí, no los créditos de API. TinyFish lo gestiona en una llamada API a 0,016 $ por paso. Un flujo de trabajo de 20 pasos en 100 sitios son 2.000 pasos, que cuestan 32 $ en total, infraestructura incluida.

**Escenario 3: Solo necesitas búsqueda y fetch.**
TinyFish cuesta 0,00 $ dentro de las cuotas. Un pipeline con 5.000 búsquedas y 10.000 fetches al mes promedia unos 333 fetches al día, muy por debajo del tope de 1.000 al día. Un día de pico por encima de 1.000 URLs necesita saldo positivo en el Wallet, o las peticiones extra fallan. Firecrawl cuesta 2 créditos por cada 10 resultados de búsqueda más 1 crédito por página descargada, así que el mismo pipeline usaría unos 6.000 créditos de Firecrawl al mes.

## Cuándo usar Firecrawl en su lugar

Quiero ser justo aquí. Firecrawl no es una mala herramienta. Es la herramienta equivocada para ciertos trabajos, y la correcta para otros.

Usa Firecrawl cuando:

- Necesites rastrear un sitio de documentación o blog completo hacia un pipeline RAG. Los endpoints `/crawl` y `/map` están hechos expresamente para esto y son más baratos que cualquier enfoque basado en agentes.
- Tus objetivos sean públicos, estáticos y no estén detrás de una detección de bots agresiva. Firecrawl es rápido y fiable para este caso de uso.
- Necesites extracción con esquemas Pydantic desde páginas estáticas. El endpoint `/extract` con esquemas tipados es limpio y predecible.
- Quieras open source y autoalojable. El núcleo es AGPL-3.0, y si tu organización requiere inspección de código o despliegue propio, Firecrawl te da esa opción. TinyFish es un servicio gestionado.
- La comunidad y el ecosistema te importen. 123.000 estrellas en GitHub, integraciones nativas con LangChain y LlamaIndex, y una gran comunidad de desarrolladores escribiendo extensiones.

Usa TinyFish cuando:

- Tu flujo de trabajo implique login, autenticación o navegación de varios pasos.
- Necesites evitar la protección anti-bot sin gestionar tu propia infraestructura de proxies.
- Quieras búsqueda web y fetch de páginas gratuitos dentro de cuotas diarias en lugar de créditos mensuales.
- Estés ejecutando flujos de agentes en paralelo a través de muchos sitios.
- Necesites enrutamiento geográfico para contenido específico de una ubicación.
- Quieras una sola API en lugar de unir herramientas de búsqueda, fetch, navegador y agentes de distintos proveedores.

<Notice type="info" title="Usando ambos juntos">

Un patrón de producción común usa Firecrawl para la ingesta masiva de páginas públicas (`/crawl` y `/scrape`) y TinyFish para flujos de trabajo autenticados o interactivos. Cubren partes diferentes del mismo pipeline. El coste es tener dos cuentas y dos facturas.

</Notice>

## Novedades del lado de TinyFish

- **TinyResearch:** una ejecución de investigación profunda que devuelve un informe con citas. 2,00 $ por ejecución `deep`, 3,00 $ por ejecución `max`, cobrado al completarse. Debe estar activado en tu cuenta.
- **TinySet:** describes una tabla en un prompt y recibes filas, a 0,10 $ por fila (de 1 a 250 filas). `/extract` y `/crawl` de Firecrawl cubren otros trabajos: parten de URLs que tú das, mientras que TinySet busca las filas en la web.
- **Opciones de TinyFetch:** `include_selectors` y `exclude_selectors` (selectores CSS, hasta 20 cada uno) recortan la página antes de que llegue a tu contexto, y `format` acepta `markdown`, `html` o `json`.
- **`highlights`:** devuelve pasajes literales ordenados que responden a una pregunta. Es beta y se activa por cuenta, así que espera un 403 si la tuya no lo tiene.
- **Alcance del fetch:** TinyFetch funciona por URL, máx. 10 por petición. Sigue sin haber un endpoint de crawl.

## Cómo empezar con TinyFish

Configurar [TinyFish](https://go.bitdoze.com/tinyfish) lleva aproximadamente un minuto.

1. **Regístrate** en [agent.tinyfish.ai/sign-up](https://go.bitdoze.com/tinyfish) y obtén tu clave API. Sin tarjeta de crédito. Las cuentas nuevas empiezan con 8 $ en fondos de Wallet.

2. **Elige tu superficie de integración.** TinyFish funciona con:
   - API REST (`api.search.tinyfish.ai` y `api.fetch.tinyfish.ai`)
   - Servidor MCP (Claude, Cursor, Codex, ChatGPT de escritorio, cualquier cliente compatible con MCP)
   - CLI (`npm install -g @tiny-fish/cli`)
   - SDK de Python (`pip install tinyfish`)
   - SDK de TypeScript (`npm install @tiny-fish/sdk`)
   - Entornos de agentes: Claude Code, Codex, Cursor, OpenClaw, Hermes Agent, OpenCode, Cline, Goose

3. **Empieza con las operaciones gratuitas.** La búsqueda y el fetch no cuestan nada dentro de las cuotas diarias. Prueba tus flujos de trabajo antes de gastar fondos del Wallet en TinyAgent o TinyBrowser, y ejecuta `tinyfish fetch usage` para ver cuánta cuota de hoy has usado.

Aquí tienes una llamada de búsqueda rápida:

```bash
curl "https://api.search.tinyfish.ai?query=best+web+scraping+tools+2026" \
  -H "X-API-Key: $TINYFISH_API_KEY"
```

Y una llamada de fetch:

```bash
curl -X POST https://api.fetch.tinyfish.ai \
  -H "X-API-Key: $TINYFISH_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"urls": ["https://example.com"]}'
```

Configuración MCP para Claude o Cursor (el servidor alojado usa inicio de sesión OAuth con tu cuenta de TinyFish la primera vez):

```json
{
  "mcpServers": {
    "tinyfish": {
      "url": "https://agent.tinyfish.ai/mcp"
    }
  }
}
```

Comandos de una línea para clientes de terminal:

```bash
claude mcp add --transport http tinyfish https://agent.tinyfish.ai/mcp
codex mcp add tinyfish --url https://agent.tinyfish.ai/mcp
```
