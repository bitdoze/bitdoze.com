Un primer agente con Google ADK es una carpeta con dos archivos: `__init__.py` y un `agent.py` que define `root_agent`. Pon una API key de Gemini en `.env` y `adk run agent_module` chatea con él. Este tutorial le da a ese agente memoria de estado de sesión y una herramienta de búsqueda web con Tavily, y después lo ejecuta de tres formas.

Cada bloque de salida de este artículo es real, de `google-adk` 2.15.1 el 2026-11-27, en un proyecto de prueba desechable y sin clave de Gemini. No se hizo ninguna llamada al modelo. La única captura que muestra una conversación sale de un callback que hace de Gemini, y el texto lo dice donde aparece.

## ¿Qué es el Google Agent Development Kit?

El Agent Development Kit (ADK) es el kit open source de Google para construir, ejecutar y desplegar agentes de IA. El paquete de Python es `google-adk`, con licencia Apache-2.0, publicado por primera vez el 2025-04-09 y en la versión 2.15.1 el 2026-11-25 ([releases](https://github.com/google/adk-python/releases)).

Cuatro piezas aparecen en todo proyecto. Un `Agent` (la clase es `LlmAgent`) guarda un nombre, un modelo, una instrucción y una lista de herramientas. Una herramienta es una función de Python normal. El `Runner` ejecuta el agente para un mensaje. Un servicio de sesiones guarda la conversación y su estado.

[ADK 2.0](https://adk.dev/2.0/), disponible de forma general desde el 2026-05-19, añadió flujos de trabajo basados en grafos para sistemas con muchos nodos. Un agente con dos herramientas no los necesita.

## ¿Qué ha cambiado en ADK desde abril de 2025?

Tres cosas de los tutoriales de 2025 fallan o avisan en 2.15.1. La ruta de importación del wrapper de LangChain se movió, la variable de `.env` que elegía el backend está obsoleta y `create_session` ahora es una corutina.

Los imports y los parámetros de `Agent`, `Runner` e `InMemorySessionService` no cambian.

| En los tutoriales de 2025 | En 2.15.1 | Qué ves |
|---|---|---|
| Python 3.9 o posterior | Python 3.11 o posterior | `uv init` eligió 3.11 en el proyecto de prueba |
| `GOOGLE_GENAI_USE_VERTEXAI="False"` en `.env` | Solo `GOOGLE_API_KEY` | `DeprecationWarning: GOOGLE_GENAI_USE_VERTEXAI is deprecated, please use GOOGLE_GENAI_USE_ENTERPRISE instead` |
| `model="gemini-2.0-flash-exp"` | `gemini-flash-latest` o un ID de modelo fijo | El 2026-11-27 la [página de modelos de Gemini](https://ai.google.dev/gemini-api/docs/models) marca 2.0 Flash como retirado |
| `session = session_service.create_session(...)` | Ponle `await`, o llama a `create_session_sync` | `AttributeError: 'coroutine' object has no attribute 'state'` |
| `from google.adk.tools.langchain_tool import LangchainTool` | `from google.adk.integrations.langchain import LangchainTool` | `DeprecationWarning: google.adk.tools.langchain_tool is moved to google.adk.integrations.langchain` |
| `TavilySearchResults` de `langchain_community` | `tavily-python` en una función normal, o `langchain-tavily` | `DeprecationWarning: langchain-community is being sunset and is no longer actively maintained` |
| `InMemorySessionService` en tu propio script | `adk run` y `adk web` también escriben `agent_module/.adk/session.db` | una carpeta `.adk/` nueva junto a `agent.py` |

La documentación también se movió. `google.github.io/adk-docs` redirige ahora a [adk.dev](https://adk.dev/).

## ¿Cómo doy una API key de Gemini a un agente de ADK?

Pon `GOOGLE_API_KEY` en un archivo `.env` dentro de la carpeta del agente o en cualquier carpeta superior, y mantenlo fuera del código. La CLI de ADK carga el primer `.env` que encuentra al subir desde la carpeta del agente, antes de importar el agente.

`adk create` construye la carpeta del agente con un comando. Sus flags responden a sus preguntas por adelantado, así que el comando no pregunta nada y ninguna clave pasa por la línea de comandos. `<FILL_IN_MODEL>` es el marcador que ofrece la propia CLI:

```bash
uv run adk create agent_module --model "<FILL_IN_MODEL>" --type code
```

```text
Agent created in /tmp/bitdoze-refresh-adk/final/my-adk-agent/agent_module:
- .env
- .gitignore
- __init__.py
- agent.py

Next steps:
- Chat with your agent in the terminal: adk run agent_module
- Or in the browser: adk web .
- Have your coding agent evaluate and deploy it: uvx google-agents-cli setup
  (other install options: https://adk.dev/get-started/agents-cli/)
```

El comando imprime también un aviso de que los secretos se guardan en `.env`. Sin flags pregunta por el modelo, el backend (Google AI, Vertex AI o Login with Google), la clave de Google AI y el tipo de agente (config YAML, experimental o código).

Conserva `__init__.py` y `.gitignore`, sustituye `agent.py` por el código de este tutorial y borra el `agent_module/.env` vacío para que un solo archivo guarde las claves. La estructura queda así:

```text
my-adk-agent/
├── .env
├── .gitignore
├── .python-version
├── main.py
├── pyproject.toml
└── agent_module/
    ├── .gitignore
    ├── __init__.py
    └── agent.py
```

`__init__.py` debe importar `agent`, y el objeto del agente debe llevar el nombre `root_agent`. `adk run` y `adk web` buscan en cada subcarpeta `agent.py`, `__init__.py` o `root_agent.yaml` y toman `root_agent` de ahí. El archivo generado ya lo hace:

```python
from . import agent as agent
```

Las claves van en `my-adk-agent/.env`:

```dotenv
GOOGLE_API_KEY="PASTE_YOUR_GEMINI_API_KEY_HERE"
TAVILY_API_KEY="PASTE_YOUR_TAVILY_API_KEY_HERE"
```

`TAVILY_API_KEY` puede quedarse como marcador en una primera ejecución. La sección de búsqueda explica el modo sin clave.

Para Google Cloud en lugar de la API de Gemini, la [página de modelos de Gemini](https://adk.dev/agents/models/google-gemini/) enumera tres líneas más:

```text
GOOGLE_CLOUD_PROJECT=your-project-id
GOOGLE_CLOUD_LOCATION=location-code
GOOGLE_GENAI_USE_ENTERPRISE=True
```

<Notice type="warning" title="Deja dos archivos fuera de git">
El `.gitignore` que escribe `uv init` lista los archivos de compilación de Python y `.venv`, no `.env`. Añade `.env` y `.adk/`, como hace `adk create` dentro de la carpeta del agente. Una variable que ya está definida en tu shell conserva su valor y gana al archivo `.env`.
</Notice>

## Escribe el primer agente

Abre `agent_module/agent.py` y define el agente:

| Parámetro | Tipo | Qué hace |
|---|---|---|
| `name` | str, obligatorio | Identifica al agente en eventos y logs |
| `model` | str u objeto de modelo | El modelo al que llama el agente. `gemini-flash-latest` sigue la versión más reciente de Flash |
| `description` | str, vacío por defecto | Una línea sobre lo que hace el agente. Otros agentes la leen cuando reparten trabajo |
| `instruction` | str o función | El prompt de sistema. ADK rellena una clave de estado escrita entre llaves antes de cada llamada al modelo |
| `tools` | lista, vacía por defecto | Funciones y objetos de herramienta que el modelo puede llamar |
| `output_key` | str o None | Guarda el texto de la respuesta final bajo esta clave de estado |

El agente más pequeño que funciona:

```python
from google.adk.agents import Agent

root_agent = Agent(
    name="my_first_adk_agent",
    model="gemini-flash-latest",
    description="A helpful assistant that chats.",
    instruction="You are a friendly and helpful assistant. Answer briefly.",
)
```

La comprobación del import no necesita clave:

```bash
uv run python -c "from agent_module import agent; print(agent.root_agent.name, [t.__name__ for t in agent.root_agent.tools])"
```

```text
my_first_adk_agent []
```

## ¿Cómo funciona un turno en ADK?

El Runner toma tu mensaje, pide la sesión al servicio de sesiones, ejecuta el agente y añade cada evento que el agente emite a la sesión. El agente va y vuelve entre Gemini y sus herramientas hasta que Gemini responde con texto plano.

![Diagrama de un turno de ADK: adk run, adk web o tu script pasan un mensaje al Runner, que carga la sesión, ejecuta el agente y añade cada evento, mientras el agente llama a Gemini, ejecuta la herramienta que este pide y devuelve la respuesta guardada bajo output_key](@assets/images/25/03/google-adk-start-request-flow.webp)

1. El Runner obtiene la sesión del servicio de sesiones y añade tu texto como un evento con el autor `user`.
2. Ejecuta el agente con esa sesión, así el agente ve el estado y el historial.
3. El agente envía la instrucción, las declaraciones de herramientas y la conversación a Gemini.
4. Gemini pide una herramienta o responde. Para una llamada a herramienta, el agente ejecuta la función, devuelve el resultado y el paso 3 se repite.
5. El Runner añade cada evento a través del servicio de sesiones, que aplica el `state_delta` del evento a `session.state`.

La interfaz de desarrollo lista estos eventos como filas numeradas. Un turno con el agente de este tutorial se ve así:

| Evento | Autor | Contenido | Estado que escribe |
|---|---|---|---|
| #1 | user | `Please remember that I like tea.` | ninguno |
| #2 | el agente | llamada a función `remember_something("I like tea")` | ninguno |
| #3 | el agente | respuesta de función de `remember_something` | `user_data` |
| #4 | el agente | el texto de la respuesta | `last_answer` |

## ¿Cómo añado memoria con session state?

Escribe en `context.state` dentro de una herramienta o de un callback, y léelo de la misma forma o a través de una clave entre llaves en la instrucción. Cada escritura viaja en el `state_delta` del evento, y el servicio de sesiones la aplica cuando el Runner añade el evento.

```python
def remember_something(data_to_remember: str, tool_context: ToolContext) -> dict:
    """Saves a note in the session state and reports what was stored before.

    Args:
        data_to_remember: The fact the user asks the agent to keep.
        tool_context: Injected by ADK, never seen by the model.

    Returns:
        A dict with a status and a message for the model.
    """
    previous = tool_context.state.get("user_data", "nothing")
    tool_context.state["user_data"] = data_to_remember
    return {
        "status": "success",
        "message": (
            f"I remembered '{data_to_remember}'. Before that, I knew about '{previous}'."
        ),
    }
```

- ADK encuentra el parámetro `tool_context` por su tipo `ToolContext`, no por su nombre. Rellena el parámetro y lo oculta al modelo, cuya declaración lista solo `data_to_remember`.
- El valor devuelto es un dict con un `status`, la forma que pide la [página de herramientas de función](https://adk.dev/tools-custom/function-tools/).
- La escritura es un string bajo una clave. El estado debe seguir siendo serializable, así que guarda IDs y valores simples, nunca objetos.

La escritura en la herramienta es la mitad de la memoria. La otra mitad es devolver el valor al modelo, que solo ve texto. Una instrucción no puede decir "usa la nota del estado de sesión" y quedarse ahí. Nombra la clave de estado entre llaves y ADK inserta su valor antes de cada llamada al modelo:

```python
    instruction="""You are a friendly and helpful assistant.
The note stored for this user is: {user_data?}
1. If the user asks about recent events or anything you are not sure about, use the 'tavily_search' tool.
2. If the user asks you to remember something, call 'remember_something' and mention what was stored before.
3. Use the stored note when it is relevant to the question.
4. Otherwise, answer from your own knowledge.""",
```

En una sesión nueva, la segunda línea llega al modelo como `The note stored for this user is: ` sin nada detrás. Después de que la herramienta se ejecutó una vez, se lee `The note stored for this user is: I like tea`. El signo de interrogación importa. Sin él, una clave que falta detiene el turno:

```text
KeyError: "Context variable not found: `user_data` in agent 'my_first_adk_agent'."
```

`output_key` es el atajo para la respuesta final. Con `output_key="last_answer"`, el texto del evento #4 acaba en `session.state["last_answer"]`.

Un prefijo en la clave fija su ámbito:

| Prefijo | Ámbito | Se conserva entre reinicios con un servicio persistente |
|---|---|---|
| ninguno | Esta sesión | Sí |
| `user:` | Todas las sesiones de este usuario en la app | Sí |
| `app:` | Todos los usuarios y sesiones de la app | Sí |
| `temp:` | Solo el turno actual | No. El servicio lo descarta cuando termina el turno |

El servicio decide dónde vive el estado. La [página de sesiones](https://adk.dev/sessions/session/) enumera tres, y la CLI añade uno por defecto:

| Servicio | Guarda en | Necesita | Úsalo cuando |
|---|---|---|---|
| `InMemorySessionService` | Memoria del proceso | Nada | Aprendizaje y pruebas. Todo se pierde cuando el proceso termina |
| `DatabaseSessionService` | Tablas de PostgreSQL, MySQL o SQLite | `google-adk[db]` y una `db_url` con un driver asíncrono | Las sesiones deben sobrevivir a un reinicio en tu propio servidor |
| `VertexAiSessionService` | Google Cloud Agent Platform | `google-adk[gcp]`, un proyecto y un recurso Agent Runtime | El agente se ejecuta en Google Cloud |
| El valor por defecto de la CLI | `agent_module/.adk/session.db` | Nada | `adk run` y `adk web` conservan las sesiones entre reinicios. `--in_memory` lo desactiva |

El servicio de base de datos bloquea por sesión cuando añade eventos. `InMemorySessionService` no es seguro con varios hilos sobre una misma sesión. Para SQLite la URL necesita el driver asíncrono. En el proyecto de prueba esta URL guardó una sesión y la leyó de vuelta a través de una segunda instancia del servicio:

```bash
uv add "google-adk[db]"
```

```python
from google.adk.sessions import DatabaseSessionService

session_service = DatabaseSessionService(db_url="sqlite+aiosqlite:///./sessions.db")
```

## Añade una herramienta de búsqueda web

El conocimiento del modelo termina en sus datos de entrenamiento. Una herramienta de búsqueda cierra ese hueco, y ADK ofrece cuatro formas de añadir una:

| Opción | Modelo | Necesita | Contrapartida |
|---|---|---|---|
| `google_search` integrado | Solo Gemini | Ningún paquete ni clave extra | Una herramienta integrada por agente, salvo que la construyas con `GoogleSearchTool(bypass_multi_tools_limit=True)`. Google mide el grounding por petición |
| Tavily a través de una función normal (este tutorial) | Cualquiera | `tavily-python` y una clave de Tavily, o el modo gratuito sin clave | Tres paquetes más. Una búsqueda básica cuesta un crédito |
| Tavily a través de `LangchainTool` | Cualquiera | `langchain-tavily`, que trae los paquetes de LangChain | Un segundo framework que actualizar. La herramienta falla al construirse sin clave |
| El servidor MCP de Tavily a través de `McpToolset` | Cualquiera | `google-adk[mcp]` y una conexión a `mcp.tavily.com` | La lista de herramientas viene del servidor de Tavily. Mira la [guía de MCP para principiantes](/es/introduccion-mcp-principiantes/) |

Yo me quedo con la función normal. Añade tres paquetes, el camino de error es visible en el código y nada en ella depende de LangChain. El [tutorial del equipo de investigación multiagente](/es/google-adk-busqueda-multi-agente/) muestra la ruta con `LangchainTool` en una construcción más grande.

```python
@functools.lru_cache(maxsize=1)
def _tavily() -> TavilyClient:
    """Builds the Tavily client once, after the .env file has been loaded."""
    return TavilyClient()


def tavily_search(query: str) -> dict:
    """Searches the web with Tavily and returns the top results.

    Args:
        query: The search query.

    Returns:
        A dict with a status, an optional direct answer and a list of results.
    """
    try:
        response = _tavily().search(query, max_results=3, include_answer=True)
    except Exception as e:
        return {"status": "error", "error_message": f"Tavily search failed: {e}"}
    results = [
        {"title": r["title"], "url": r["url"], "content": r["content"]}
        for r in response.get("results", [])
    ]
    return {
        "status": "success",
        "answer": response.get("answer"),
        "results": results,
    }
```

La herramienta construye el cliente de Tavily en la primera llamada, después de que la CLI o `load_dotenv()` hayan cargado `.env`, arranque el agente como arranque. Tavily responde con una lista `results`, donde cada elemento guarda un `title`, una `url`, un fragmento `content` y un `score`, más una `answer` opcional cuando `include_answer=True` ([referencia del SDK](https://docs.tavily.com/sdk/python/reference)). La función se queda con los tres campos que necesita el modelo. Si falla, devuelve `status: "error"` con el motivo, para que el modelo pueda transmitirlo en lugar de que el turno muera.

Sin `TAVILY_API_KEY` el cliente no falla. Funciona en un modo gratuito sin clave y con límite de frecuencia. Cuando alcanzas el límite, el SDK lanza este error (texto real) y la herramienta lo pasa a `error_message`:

```text
TavilyKeylessLimitError: You reached the daily keyless Tavily limit. To continue immediately, pay via x402 agentic payment (https://docs.tavily.com/documentation/machine-payments/x402) or sign up at https://tavily.com for a Tavily API key. Otherwise, retry after the time given in the Retry-After response header.
```

La alternativa integrada ocupa dos líneas, siempre que el modelo sea Gemini:

```python
from google.adk.tools.google_search_tool import GoogleSearchTool

tools=[GoogleSearchTool(bypass_multi_tools_limit=True), remember_something]
```

La instancia compartida `google_search` de `google.adk.tools` mantiene el flag desactivado, y la [página de limitaciones de herramientas](https://adk.dev/tools/limitations/) la lista como no admitida junto a otra herramienta.

La ruta de LangChain, para un proyecto que ya tiene esos paquetes (`uv add langchain-tavily`):

```python
from google.adk.integrations.langchain import LangchainTool
from langchain_tavily import TavilySearch

adk_tavily_tool = LangchainTool(tool=TavilySearch(max_results=3, include_answer=True))
```

Necesita la clave en el momento de la construcción:

```text
pydantic_core._pydantic_core.ValidationError: 1 validation error for TavilySearchAPIWrapper
Value error, Did not find tavily_api_key, please add an environment variable `TAVILY_API_KEY` which contains it, or pass `tavily_api_key` as a named parameter.
```

Costes el 2026-11-27, según la [página de créditos de Tavily](https://docs.tavily.com/documentation/api-credits) y la [página de precios de Gemini](https://ai.google.dev/gemini-api/docs/pricing):

- El plan gratuito de Tavily tiene 1,000 créditos al mes y no pide tarjeta. Una búsqueda básica cuesta un crédito, una avanzada dos.
- Gemini factura por token. La página de precios tiene una columna Free Tier por modelo, y en varios modelos actuales dice "Not available", así que mira la fila del modelo que elijas.
- Google mide el grounding con Search por petición de búsqueda, aparte de los tokens. Un prompt puede disparar varias búsquedas.

## Código completo del agente

El `agent_module/agent.py` completo:

```python
import functools

from google.adk.agents import Agent
from google.adk.tools import ToolContext
from tavily import TavilyClient


@functools.lru_cache(maxsize=1)
def _tavily() -> TavilyClient:
    """Builds the Tavily client once, after the .env file has been loaded."""
    return TavilyClient()


def remember_something(data_to_remember: str, tool_context: ToolContext) -> dict:
    """Saves a note in the session state and reports what was stored before.

    Args:
        data_to_remember: The fact the user asks the agent to keep.
        tool_context: Injected by ADK, never seen by the model.

    Returns:
        A dict with a status and a message for the model.
    """
    previous = tool_context.state.get("user_data", "nothing")
    tool_context.state["user_data"] = data_to_remember
    return {
        "status": "success",
        "message": (
            f"I remembered '{data_to_remember}'. Before that, I knew about '{previous}'."
        ),
    }


def tavily_search(query: str) -> dict:
    """Searches the web with Tavily and returns the top results.

    Args:
        query: The search query.

    Returns:
        A dict with a status, an optional direct answer and a list of results.
    """
    try:
        response = _tavily().search(query, max_results=3, include_answer=True)
    except Exception as e:
        return {"status": "error", "error_message": f"Tavily search failed: {e}"}
    results = [
        {"title": r["title"], "url": r["url"], "content": r["content"]}
        for r in response.get("results", [])
    ]
    return {
        "status": "success",
        "answer": response.get("answer"),
        "results": results,
    }


root_agent = Agent(
    name="my_first_adk_agent",
    model="gemini-flash-latest",
    description="A helpful assistant that searches the web and keeps notes.",
    instruction="""You are a friendly and helpful assistant.
The note stored for this user is: {user_data?}
1. If the user asks about recent events or anything you are not sure about, use the 'tavily_search' tool.
2. If the user asks you to remember something, call 'remember_something' and mention what was stored before.
3. Use the stored note when it is relevant to the question.
4. Otherwise, answer from your own knowledge.""",
    tools=[tavily_search, remember_something],
    output_key="last_answer",
)
```

## ¿Cómo ejecuto un agente de ADK?

Tres comandos leen la misma carpeta `agent_module`: `adk run`, `adk web` y un `Runner` en tu propio script. `adk run` chatea en la terminal, `adk web` abre la interfaz de desarrollo en un navegador y el `Runner` ejecuta el agente desde código.

`adk api_server` añade una API REST sin autenticación para pruebas con curl.

### Ejecuta en la terminal con `adk run`

```bash
uv run adk run agent_module "hello"
```

Sin `.env` y sin clave en el shell, `adk run` crea la sesión y el turno falla en la llamada al modelo:

```text
Log setup complete: /tmp/agents_log/agent.20261127_195337.log
To access latest log: tail -F /tmp/agents_log/agent.latest.log
Session ID: 69b41d33-f7f7-4c25-a2b2-f17e6a8a207a
Error: No API key was provided. Please pass a valid API key. Learn how to create an API key at https://ai.google.dev/gemini-api/docs/api-key.
```

Todo lo anterior al modelo funciona cuando ves esas líneas. Con una clave válida, el mismo comando ejecuta un turno y termina. Quita el mensaje y obtienes un prompt, que se cierra con Ctrl+C o Ctrl+D. `echo "What is ADK?" | adk run agent_module` pasa una pregunta por una tubería.

La ejecución creó `agent_module/.adk/session.db` y un archivo de log en `/tmp/agents_log/`. Pasa `--in_memory` para mantener la sesión solo en memoria.

### Ejecuta en el navegador con `adk web`

Arranca la interfaz de desarrollo desde la carpeta del proyecto, la padre de `agent_module`:

```bash
uv run adk web --port 8463
```

```text
+-----------------------------------------------------------------------------+
| ADK Web Server started                                                      |
|                                                                             |
| For local testing, access at http://127.0.0.1:8463.                         |
+-----------------------------------------------------------------------------+
```

El puerto por defecto es 8000. El primer arranque pregunta si quieres activar la telemetría de uso. Sigue desactivada hasta que respondas que sí, y `adk telemetry status` muestra el ajuste.

Abre la dirección. La cabecera muestra la versión y un desplegable con el nombre de la app. Elige `agent_module` ahí si no está seleccionado:

![La interfaz de desarrollo de ADK con el desplegable de apps abierto, que lista agent_module bajo Root con una marca de verificación](@assets/images/25/03/google-adk-start-dev-ui-select-app.webp)

Escribe un mensaje. El primer mensaje crea la sesión, así que el selector `NEW SESSION` dice `No sessions found for user 'user'` hasta entonces. La columna de la derecha lista cada evento con su número, y la pestaña `State` muestra lo que hay en `session.state`.

El servidor escucha en `127.0.0.1` y no tiene inicio de sesión. Su texto de ayuda dice que lo ejecutes solo en una red de confianza.

### Ejecuta desde tu propio script

`adk run` oculta el Runner. Un script muestra el Runner, y un servicio incrustaría el mismo código. Sustituye `main.py` por:

```python
import asyncio

from dotenv import load_dotenv
from google.adk.runners import Runner
from google.adk.sessions import InMemorySessionService
from google.genai import types

from agent_module.agent import root_agent

load_dotenv()

APP_NAME = "my_first_adk_app"
USER_ID = "user_dev_1"
SESSION_ID = "session_main_1"


async def chat() -> None:
    session_service = InMemorySessionService()
    session = await session_service.create_session(
        app_name=APP_NAME, user_id=USER_ID, session_id=SESSION_ID
    )
    runner = Runner(
        agent=root_agent,
        app_name=APP_NAME,
        session_service=session_service,
    )
    print(f"Session '{session.id}' is ready for agent '{root_agent.name}'.")
    print("Type a message, or quit to exit.")
    while True:
        try:
            user_query = input("You: ")
        except EOFError:
            break
        if user_query.strip().lower() == "quit":
            break
        content = types.Content(role="user", parts=[types.Part(text=user_query)])
        try:
            async for event in runner.run_async(
                user_id=USER_ID, session_id=SESSION_ID, new_message=content
            ):
                if event.is_final_response() and event.content and event.content.parts:
                    print("Agent:", event.content.parts[0].text)
        except Exception as e:
            print(f"Error: {e}")
            continue
        state = await session_service.get_session(
            app_name=APP_NAME, user_id=USER_ID, session_id=SESSION_ID
        )
        print("State:", state.state)


if __name__ == "__main__":
    asyncio.run(chat())
```

- El script espera con `await` a `create_session`. Sin `await` la variable guarda una corutina y `session.id` falla.
- `load_dotenv()` lee primero el `.env` del proyecto, y la herramienta construye el cliente de Tavily después.
- El bucle imprime solo las respuestas finales. `event.is_final_response()` es falso para las llamadas a herramientas y sus resultados.

Sin clave, el script imprime estas líneas. ADK además registra su propio traceback del turno fallido entre la línea `You:` y la línea `Error:`:

```bash
printf "hello\nquit\n" | uv run python main.py
```

```text
Session 'session_main_1' is ready for agent 'my_first_adk_agent'.
Type a message, or quit to exit.
You: Error: No API key was provided. Please pass a valid API key. Learn how to create an API key at https://ai.google.dev/gemini-api/docs/api-key.
You:
```

Arranca el script con `uv run python main.py`, no con `python -m agent_module.agent`. El import del paquete en `__init__.py` y el import del módulo con `-m` cargan el archivo del agente dos veces, y Python avisa:

```text
<frozen runpy>:128: RuntimeWarning: 'agent_module.agent' found in sys.modules after import of package 'agent_module', but prior to execution of 'agent_module.agent'; this may result in unpredictable behaviour
```

## Comprueba el agente completo sin API key

Un `before_model_callback` que devuelve un `LlmResponse` se salta la llamada al modelo, y ADK usa la respuesta devuelta como si el modelo la hubiera enviado ([callbacks](https://adk.dev/callbacks/types-of-callbacks/)). Una segunda carpeta de agente puede aprovecharlo para probar las herramientas, el estado y la lista de eventos antes de tener cualquier clave.

Crea `standin_agent/__init__.py` con la misma línea `from . import agent as agent` y `standin_agent/agent.py` con:

```python
from google.adk.models import LlmResponse
from google.genai import types

from agent_module.agent import root_agent as base


def stand_in(callback_context, llm_request):
    last = llm_request.contents[-1] if llm_request.contents else None
    answered = bool(last and last.parts and any(p.function_response for p in last.parts))
    if answered:
        part = types.Part(text="Noted. You told me: I like tea.")
    else:
        part = types.Part(
            function_call=types.FunctionCall(
                name="remember_something", args={"data_to_remember": "I like tea"}
            )
        )
    return LlmResponse(content=types.Content(role="model", parts=[part]))


root_agent = base.model_copy(update={"name": "standin_agent", "before_model_callback": stand_in})
```

Vuelve a arrancar `adk web`, elige `standin_agent` en el desplegable y envía cualquier mensaje. El callback pide primero `remember_something` y responde con texto cuando vuelve el resultado de la herramienta. Esta captura nunca llegó al modelo:

![La interfaz de desarrollo de ADK con el agente sustituto: la pestaña State guarda user_data y last_answer, y la lista Events muestra el mensaje, la llamada a la herramienta, su respuesta y la respuesta final](@assets/images/25/03/google-adk-start-dev-ui-state.webp)

El evento #3 lleva `State: user_data` y el evento #4 lleva `State: last_answer`. Ese es el mecanismo de memoria de este tutorial en una captura, sin gastar un token. Borra la carpeta cuando llegue la clave.

## Modos de fallo y arreglos

La tabla del principio del artículo cubre los avisos de obsolescencia y los errores de corutina. Estos son el resto:

| Qué ves | Causa | Arreglo |
|---|---|---|
| `Error: No API key was provided. Please pass a valid API key.` | No se encontró `.env` y no hay `GOOGLE_API_KEY` en el shell | Pon la clave en `.env` en la carpeta del agente o en una superior |
| `Error: 400 INVALID_ARGUMENT. ... 'API key not valid. Please pass a valid API key.'` | Un marcador o una clave revocada | Copia la clave otra vez desde AI Studio y repite el comando |
| `Error: Invalid value for 'AGENT': Directory 'agent_module' does not exist.` | `adk run` se arrancó desde la carpeta equivocada | Arráncalo desde la carpeta padre de `agent_module`, o dale la ruta |
| `SessionNotFoundError: Session not found: session_typo_123` | El Runner recibió un ID de sesión que todavía no existe | Llama antes a `create_session`, o construye el Runner con `auto_create_session=True` |
| `KeyError: "Context variable not found: ..."` | Una instrucción nombra una clave de estado que no existe | Añade `?` después de la clave, o pasa la clave en `state=` al crear la sesión |
| `TavilyKeylessLimitError: You reached the daily keyless Tavily limit.` | Búsquedas sin clave de Tavily | Añade `TAVILY_API_KEY` a `.env` |

Una clave marcador en `.env` aparece en la interfaz de desarrollo como el segundo evento, una tarjeta roja con el código de la tabla:

## Preguntas frecuentes

<Accordion label="¿Google ADK es gratis?" group="faq">
El kit es gratis y tiene licencia Apache-2.0. Pagas por el modelo y, con Tavily, por las búsquedas que superan la cuota de 1,000 créditos gratuitos al mes, donde una búsqueda básica cuesta un crédito. Sin clave de Tavily la búsqueda funciona en un modo sin clave con límite de frecuencia.
</Accordion>

<Accordion label="¿Qué diferencia hay entre adk run, adk web y adk api_server?" group="faq">
`adk run` es un bucle de chat en la terminal. `adk web` sirve la interfaz de desarrollo en `http://127.0.0.1:8000` con la lista de eventos, el estado y las trazas. `adk api_server` expone los mismos agentes a través de una API REST sin autenticación para pruebas con curl, y su texto de ayuda dice que pongas tu propia autenticación delante.
</Accordion>

<Accordion label="¿Necesito Vertex AI para usar el Agent Development Kit?" group="faq">
No. `GOOGLE_API_KEY` de AI Studio basta para la API de Gemini. Google Cloud necesita `GOOGLE_CLOUD_PROJECT`, `GOOGLE_CLOUD_LOCATION` y `GOOGLE_GENAI_USE_ENTERPRISE=True` en lugar de esa clave.
</Accordion>

<Accordion label="¿Por qué parece que create_session no hace nada?" group="faq">
Es una corutina en 2.15.1. Sin `await` la llamada devuelve un objeto corutina, `session.state` falla con `AttributeError: 'coroutine' object has no attribute 'state'`, y Python imprime `coroutine 'InMemorySessionService.create_session' was never awaited` al salir. Usa `await session_service.create_session(...)` o `create_session_sync(...)`.
</Accordion>

<Accordion label="¿Cuánto dura el estado de sesión de ADK?" group="faq">
Mientras el servicio conserve la sesión. `InMemorySessionService` lo pierde cuando el proceso termina. `DatabaseSessionService` y el archivo `.adk/session.db` que crean `adk run` y `adk web` lo conservan entre reinicios. El servicio descarta las claves con el prefijo `temp:` al final de cada turno.
</Accordion>

<Accordion label="¿Puedo usar la herramienta Google Search integrada con mis propias herramientas?" group="faq">
Solo si la construyes tú con `GoogleSearchTool(bypass_multi_tools_limit=True)` de `google.adk.tools.google_search_tool`. La instancia compartida `google_search` deja el flag desactivado, y la documentación la lista como no admitida junto a otra herramienta. La herramienta funciona solo con modelos Gemini.
</Accordion>

<Accordion label="¿Arranca adk web sin API key?" group="faq">
Sí. La interfaz se abre y lista la app sin clave, y el primer mensaje es donde hace falta la clave. Sin `.env` ese mensaje falla con `No API key was provided`. Con una clave marcador, el evento 2 muestra `API key not valid. Please pass a valid API key.`
</Accordion>

<Accordion label="¿Qué versión de Python necesita google-adk?" group="faq">
3.11 o posterior, según los metadatos de PyPI de 2.15.1. El inicio rápido de Python en adk.dev todavía dice 3.10 o posterior. `uv init` escribe en `.python-version` el intérprete que encuentra, y `uv python pin 3.12` lo fija a una versión.
</Accordion>
