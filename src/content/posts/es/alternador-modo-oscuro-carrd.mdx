## Por Qué Añadir Modo Oscuro a tu Sitio Carrd

Cinco razones, una línea cada una:

1. Menos fatiga visual: las interfaces oscuras son más cómodas con poca luz.
2. Ahorro de batería: en pantallas OLED los píxeles oscuros consumen menos energía.
3. Preferencia del usuario: mucha gente simplemente prefiere una interfaz oscura. Ofrecer la opción es un gesto de respeto barato.
4. Sensibilidad a la luz: algunos visitantes necesitan de verdad interfaces más oscuras, y para ellos el modo oscuro es una función de accesibilidad.
5. Expectativa moderna: todas las grandes apps ya traen un tema oscuro.

El modo oscuro ya no es una novedad. Los visitantes buscan el interruptor, y cuando no lo encuentran se van a un sitio que sí lo tenga.

## Cómo Funciona el Modo Oscuro en Carrd

Carrd no tiene modo oscuro integrado. Revisé de nuevo la documentación y el changelog en septiembre de 2026: sigue sin existir una función de cambio de tema. El código personalizado es el único camino.

El enfoque es el de siempre:

1. Un atributo `data-theme` en la raíz de la página (`light` o `dark`)
2. Variables CSS para los colores, intercambiadas por `[data-theme="dark"]`
3. Un botón alternador que invierte el atributo
4. `localStorage` para que la elección sobreviva a las recargas
5. `prefers-color-scheme` como valor por defecto antes de que el visitante elija nada

La mejora frente a un snippet ingenuo es el **patrón de dos embeds**. El Embed n.º 1 es un pequeño bootstrap en un embed Hidden → Head que establece `data-theme` antes de que la página se pinte. El Embed n.º 2 contiene la interfaz del alternador y el manejador del clic (Inline o Hidden → Body End).

<Notice type="info" title="¿Por qué dos embeds?">
Un embed Inline único aplica el tema desde JavaScript después del primer pintado. Los usuarios con el sistema en oscuro ven un destello blanco en cada carga. El bootstrap del head se ejecuta antes del pintado, así que el primer frame ya lleva el tema correcto.
</Notice>

Las páginas más grandes aguantan bien. Los sitios con varias secciones construidos con el elemento Page de Carrd mantienen el tema automáticamente. Todo es un único documento, así que `data-theme` y `localStorage` persisten entre secciones.

Los scripts del head se ejecutan antes del pintado por especificación, así que la solución es sólida en principio. El orden exacto de inyección de Carrd aun así merece una confirmación en tu propio sitio publicado. Mira la checklist de pruebas más abajo.

<Notice type="warning" title="Style: Hidden, Location: Head (no Inline)">
La corrección del destello blanco necesita un embed Hidden dirigido al Head. Una configuración solo Inline lo hace imposible, porque el código Inline se renderiza en el cuerpo de la página después del pintado. Usaremos ambos estilos: Hidden → Head para el bootstrap, e Inline (o Hidden → Body End) para el alternador.
</Notice>

Pega esto en el campo Code:

```html
<script>
(function () {
  var t;
  try { t = localStorage.getItem('theme'); } catch (e) {}
  if (!t) t = window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
  document.documentElement.setAttribute('data-theme', t);
})();
</script>
<style>
  :root { color-scheme: light; }
  [data-theme="dark"] { color-scheme: dark; }
</style>
```

Qué hace:

- Lee `localStorage.theme` dentro de `try/catch`, de modo que los modos privados que lanzan error al acceder al almacenamiento no rompan la página
- Recurre a `prefers-color-scheme: dark` cuando el visitante nunca eligió un tema
- Establece `data-theme` en la raíz del documento antes del primer pintado
- Emite `color-scheme: light|dark` para que los controles de formulario nativos, las barras de scroll y el autocompletado sigan el tema (`color-scheme` está soportado en Chrome/Edge 81+, Firefox 96+, Safari 13+)

Carrd no inyecta ninguna pista de `color-scheme` en los sitios publicados. Revisé el HTML en bruto de un ejemplo publicado en septiembre de 2026: no hay nada. El snippet lo establece por sí mismo. No des por hecho que la plataforma lo hace por ti.

**Comprueba:** publica y abre el sitio en una ventana de incógnito en un equipo o móvil configurado en modo oscuro. La página debería cargar oscura sin destello blanco. Si aún ves un destello, el embed de head falta, está mal ubicado, o estás viendo una página en caché (fuerza la recarga).

### Opción 1: Botón Alternador Flotante

Mi opción por defecto. Un pequeño botón fijo en la esquina, funciona con cualquier diseño y no estorba. Esta versión alterna un único emoji sol/luna, mantiene `aria-pressed` sincronizado, limita las transiciones para que el primer pintado sea instantáneo, respeta `prefers-reduced-motion`, sobrevive a los errores de almacenamiento en modo privado, sigue los cambios de tema del sistema en vivo y añade una transición de fundido cruzado con view-transition donde el navegador lo soporta.

```html
<style>
  /* Light mode (default) colors */
  :root {
    --dm-bg-primary: #ffffff;
    --dm-bg-secondary: #f8fafc;
    --dm-text-primary: #1e293b;
    --dm-text-secondary: #64748b;
    --dm-border: #e2e8f0;
    --dm-accent: #3b82f6;
  }

  /* Dark mode colors */
  [data-theme="dark"] {
    --dm-bg-primary: #0f172a;
    --dm-bg-secondary: #1e293b;
    --dm-text-primary: #f1f5f9;
    --dm-text-secondary: #94a3b8;
    --dm-border: #334155;
    --dm-accent: #60a5fa;
  }

  /* Apply colors to Carrd elements */
  [data-theme="dark"] body,
  [data-theme="dark"] #wrapper,
  [data-theme="dark"] #main,
  [data-theme="dark"] section {
    background-color: var(--dm-bg-primary) !important;
  }

  [data-theme="dark"] h1,
  [data-theme="dark"] h2,
  [data-theme="dark"] h3,
  [data-theme="dark"] h4,
  [data-theme="dark"] p,
  [data-theme="dark"] span,
  [data-theme="dark"] li,
  [data-theme="dark"] a:not(.button) {
    color: var(--dm-text-primary) !important;
  }

  /* Style form inputs */
  [data-theme="dark"] input,
  [data-theme="dark"] textarea,
  [data-theme="dark"] select {
    background-color: var(--dm-bg-secondary) !important;
    color: var(--dm-text-primary) !important;
    border-color: var(--dm-border) !important;
  }

  /* Smooth transitions, scoped so the first paint is instant */
  @media (prefers-reduced-motion: no-preference) {
    [data-theme-ready] body,
    [data-theme-ready] #wrapper,
    [data-theme-ready] #main,
    [data-theme-ready] section,
    [data-theme-ready] h1,
    [data-theme-ready] h2,
    [data-theme-ready] h3,
    [data-theme-ready] h4,
    [data-theme-ready] p,
    [data-theme-ready] span,
    [data-theme-ready] li,

    [data-theme-ready] input,

      transition: background-color 0.3s ease, color 0.3s ease, border-color 0.3s ease;
    }
  }

  /* Toggle button */
  .theme-toggle {
    position: fixed;
    bottom: 25px;
    left: 25px;
    width: 50px;
    height: 50px;
    border-radius: 50%;

    cursor: pointer;

    align-items: center;
    justify-content: center;

    z-index: 9999;
    background: var(--dm-bg-secondary);
    box-shadow: 0 4px 15px rgba(0, 0, 0, 0.15);
    transition: transform 0.2s, background-color 0.3s;
  }

  .theme-toggle:hover {
    transform: scale(1.1);
  }

  .theme-toggle:focus-visible {
    outline: 2px solid var(--dm-accent);
    outline-offset: 2px;
  }
</style>

<button class="theme-toggle" id="themeToggle" aria-label="Toggle dark mode" aria-pressed="false">
  <span aria-hidden="true">☀️</span>
</button>

<script>
(function () {
  var toggle = document.getElementById('themeToggle');

  function apply(theme) {
    document.documentElement.setAttribute('data-theme', theme);
    document.documentElement.setAttribute('data-theme-ready', '');
    toggle.setAttribute('aria-pressed', theme === 'dark' ? 'true' : 'false');
    toggle.firstElementChild.textContent = theme === 'dark' ? '🌙' : '☀️';
  }

  function current() {
    return document.documentElement.getAttribute('data-theme') || 'light';
  }

  apply(current());

  toggle.addEventListener('click', function () {
    var next = current() === 'dark' ? 'light' : 'dark';
    try { localStorage.setItem('theme', next); } catch (e) {}
    if (document.startViewTransition) {
      document.startViewTransition(function () { apply(next); });
    } else {
      apply(next);
    }
  });

  window.matchMedia('(prefers-color-scheme: dark)')
    .addEventListener('change', function (e) {
      var saved = null;
      try { saved = localStorage.getItem('theme'); } catch (err) {}
      if (!saved) apply(e.matches ? 'dark' : 'light');
    });
})();
</script>
```

Notas sobre las partes clave:

- Las transiciones solo se aplican después de que `data-theme-ready` se establezca en la raíz, así que el tema inicial no se anima.
- `document.startViewTransition` es una mejora progresiva (Chrome/Edge 111+, Firefox 144+, Safari 18+). Los navegadores sin soporte simplemente cambian al instante.
- El listener de cambio del sistema solo actúa cuando el visitante no tiene elección guardada. Una vez que pulsa el alternador, su elección manda hasta que la borre.
- Los emoji se renderizan de forma distinta en Windows y en Android antiguos. Si quieres iconos con píxeles consistentes, sustituye los caracteres `☀️` / `🌙` por formas SVG en línea de sol y luna.

**Comprueba:** pulsa el alternador y los colores deberían fundirse. Recarga y el tema debería mantenerse (`localStorage.theme` contiene `light` o `dark`). Navega con Tab hasta el botón y deberías ver el anillo de foco, con `aria-pressed` cambiando en DevTools → Elements.

### Consejos de Diseño para el Modo Oscuro

Prueba el contraste. El texto debe seguir siendo legible sobre el fondo oscuro. Pasa la paleta por un comprobador de contraste cuando tengas dudas.

No uses negro puro. `#000000` es duro a la vista. Usa grises oscuros como `#0f172a` o `#1e293b` en su lugar.

Aclara tu color de acento. Los colores que funcionan sobre blanco suelen verse apagados sobre oscuro. `#3b82f6` se convierte en `#60a5fa` en la paleta de arriba por exactamente esa razón.

Revisa cada sección. Recorre toda la página en ambos temas. Algunos elementos necesitarán selectores extra (siguiente sección).

Ten en cuenta las imágenes. Los logos y gráficos diseñados para fondos blancos pueden necesitar una segunda versión, un filtro o un marco sutil.

## Elementos e Imágenes Específicos de Carrd

Carrd genera selectores estructurales estables: `#wrapper`, `#main` y `.inner` están presentes en los sitios publicados (verificado en el HTML en bruto de un ejemplo publicado en septiembre de 2026). Los nombres de clase específicos de cada plantilla varían, así que los elementos rebeldes necesitan un apuntado extra.

```css
/* Target specific Carrd elements */
[data-theme="dark"] .inner,
[data-theme="dark"] .container,
[data-theme="dark"] [class*="style1"],
[data-theme="dark"] [class*="style2"] {
  background-color: var(--dm-bg-primary) !important;
  color: var(--dm-text-primary) !important;
}

/* Target Carrd buttons (ul.buttons > li > a.button); a:not(.button) above only covers text links */
[data-theme="dark"] .buttons .button {
  background-color: var(--dm-accent) !important;
}

/* Target Carrd icons (ul.icons > li > a > svg) */
[data-theme="dark"] .icons svg {
  filter: brightness(0) invert(1);
}
```

<Notice type="warning" title="Varianza entre plantillas">
Los nombres de clase `style1`…`style5` difieren según la plantilla, y trucos como `[data-theme="dark"] .inner > * { background: transparent !important }` pueden borrar los fondos de botones y tarjetas en algunas plantillas. Prueba en la tuya. Si los botones pierden su fondo en modo oscuro, quita esa regla primero. Nada de esto es universal. Verifica cada override en tu página publicada.
</Notice>

Las imágenes de fondo no responden a los overrides de `background-color`. Si una sección se niega a oscurecer, la culpable es probablemente una imagen de fondo. Cámbiala, o atenúala con una capa superpuesta:

```css
[data-theme="dark"] img {
  opacity: 0.9;
  filter: brightness(0.95);
}

/* Or give images a subtle frame */
[data-theme="dark"] img {
  border: 1px solid var(--dm-border);
  border-radius: 8px;
}
```

Si tienes una cabecera sticky, espera un choque: una barra de cabecera todavía clara en una página por lo demás oscura. La guía del [sticky header para Carrd](https://www.bitdoze.com/add-stickey-header-carrd/) muestra qué selectores tocar para que la barra se oscurezca con el resto.

## Probar y Solucionar Problemas del Alternador de Modo Oscuro en Carrd

Los embeds no renderizan nada en el editor, así que cada comprobación de abajo se hace en el sitio publicado.

<ListCheck>
<ul>
<li>Publica y luego abre el sitio en una ventana de incógnito en un sistema configurado en oscuro: el tema se aplica sin destello blanco</li>
<li>Pulsa el alternador y recarga: la elección persiste en `localStorage` (clave `theme`)</li>
<li>La consola de DevTools está limpia (sin `Uncaught SecurityError` de `localStorage` en modo privado)</li>
<li>El Tab del teclado llega al alternador y el anillo de foco es visible</li>
<li>`aria-pressed` (o `aria-checked` en la Opción 2) cambia en el panel Elements al alternar</li>
<li>Sin elección guardada, cambia el tema del SO en vivo: la página lo sigue</li>
</ul>
</ListCheck>

Si algo se comporta mal:

<Accordion label="El destello blanco sigue apareciendo" group="troubleshooting" expanded="true">
El bootstrap del head falta, está en la ubicación equivocada (debe ser Style: Hidden, Location: Head), o estás viendo una copia en caché. Confirma que el embed existe con el estilo y la ubicación correctos, luego fuerza la recarga o prueba en una ventana privada. Verifica también una vez en tu propio sitio publicado que el código del head se ejecuta antes del pintado. El orden de inyección de Carrd merece una única comprobación de extremo a extremo, ya que el editor no te lo muestra. Si el embed de head está bien y queda un destello corto, mueve el bloque `<style>` del alternador también al embed de head (ver Paso 2).
</Accordion>

<Accordion label="El alternador hace clic pero nada cambia" group="troubleshooting">
Tres sospechosos habituales: un error de script en la consola (pega de nuevo todo el bloque de código; las etiquetas sin cerrar son la causa común), los selectores CSS oscuros que no coinciden con tu plantilla, o el sitio que no se publicó de verdad después de tu edición. Mira la consola primero, luego inspecciona el elemento `<html>`. `data-theme` debería cambiar al hacer clic.
</Accordion>

<Accordion label="Los botones o las tarjetas perdieron su fondo en modo oscuro" group="troubleshooting">
Es la regla `[data-theme="dark"] .inner > * { background: transparent !important }` haciendo de las suyas. Depende de la plantilla y suele ser demasiado agresiva. Quítala y dale a `.button` y a los contenedores de tarjetas sus propios overrides de fondo en su lugar.
</Accordion>

<Accordion label="El alternador tapa el menú móvil o los iconos sociales" group="troubleshooting">
`z-index: 9999` más una posición en esquina se solapa con la interfaz de Carrd en pantallas pequeñas. Baja el z-index, o recoloca el alternador en una esquina libre (ver la sección de posicionamiento). Prueba al ancho de un móvil, no solo en escritorio.
</Accordion>

<Accordion label="Algunas secciones nunca cambian de color" group="troubleshooting">
O la plantilla usa clases `styleN` que tus selectores no cubren, o el fondo de la sección es una imagen. Inspecciona el elemento, añade su clase al bloque CSS oscuro, y cambia o atenúa las imágenes de fondo. Los iconos SVG en línea también ignoran los overrides de color. Recolóralos con reglas `fill`/`stroke` o un `filter`.
</Accordion>

<Accordion label="La preferencia no se guarda o hay Uncaught SecurityError en la consola" group="troubleshooting">
Los modos de navegación privada pueden bloquear `localStorage`. El código envuelve cada lectura/escritura en `try/catch`, así que el alternador sigue funcionando durante la sesión. Simplemente no puede recordar la elección. No hay nada que arreglar; la degradación es intencionada.
</Accordion>

<Notice type="info" title="Volver atrás">
Nada fuera de los dos embeds queda modificado. Borra ambos elementos Embed y publica: el sitio vuelve a su estado original. Para limpiar la preferencia atascada de un visitante, abre DevTools → Application → Local Storage y elimina la clave `theme`.
</Notice>
