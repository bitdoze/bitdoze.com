Si autoalojas tus aplicaciones en CloudPanel y no tienes copias de seguridad remotas, estás a una cuenta de hosting comprometida o un ataque de ransomware de perderlo todo. Las copias de seguridad locales en el mismo VPS no sirven de nada cuando el servidor desaparece.

[CloudPanel](https://www.cloudpanel.io/) es un panel de hosting gratuito y de código abierto, y uno de los [mejores paneles de servidores autoalojados](/es/mejores-paneles-autoalojados/) disponibles. Utiliza [Rclone](https://rclone.org/) internamente para las copias de seguridad remotas, con soporte para proveedores como Amazon S3, Dropbox, SFTP y más. Para algunos proveedores (DigitalOcean Spaces, Dropbox, SFTP), la configuración se hace directamente en la interfaz. Pero para **OneDrive** y **Google Drive personal**, tienes que usar la ruta de Custom Rclone Config.

Esta guía cubre la configuración completa para ambos proveedores, además de los pasos de restauración y la solución de problemas que la mayoría de los tutoriales omiten. Si prefieres copias de seguridad a nivel de plugin específicamente para WordPress, consulta los [plugins de copias de seguridad para WordPress](/es/mejores-plugins-gratuitos-backup-wordpress/) como alternativa a nivel de aplicación.

## Qué respalda CloudPanel (archivos, bases de datos y configuración)

Antes de configurar nada, conviene saber qué incluye exactamente una copia de seguridad remota de CloudPanel.

<ListCheck>

**Incluido en cada copia de seguridad:**
- El directorio home de cada sitio (todos los archivos)
- La configuración del sitio y del vhost
- Las bases de datos, que se respaldan _antes_ de que se ejecute la copia de archivos (desde CloudPanel v2.4.0)

**Excluido por defecto:**
- Los directorios `.ssh`
- Los directorios `logs`
- Los directorios `tmp`

</ListCheck>

<Notice type="info" title="Copia con prioridad a la base de datos">
Desde CloudPanel v2.4.0, las bases de datos se vuelcan antes de crear el archivo de la copia de seguridad remota. Esto significa que, si la copia de archivos falla a mitad de camino, seguirás teniendo un snapshot consistente de la base de datos en el archivo.
</Notice>

También puedes usar el campo **Excludes** de la interfaz de CloudPanel para omitir sitios o rutas concretas. Esto es útil si tienes directorios grandes de recursos estáticos que no necesitan una copia de seguridad diaria externa.

Si alojas WordPress en CloudPanel, la copia de seguridad lo incluye todo: wp-content, uploads, la base de datos y la configuración. Consulta cómo [alojar sitios WordPress en CloudPanel](/es/instalar-wordpress-ubuntu-arm/) para más detalles sobre la configuración.

## Requisitos previos para las copias de seguridad remotas de CloudPanel

Asegúrate de que todo esto esté listo antes de empezar la configuración de Rclone.

### Comprueba la zona horaria de tu instancia

La documentación de CloudPanel lo indica explícitamente: la zona horaria debe ser correcta para que las copias de seguridad programadas se ejecuten a la hora esperada.

Compruébala con:

```sh
timedatectl
```

Si no es correcta, corrígela:

```sh
sudo timedatectl set-timezone Europe/Bucharest
```

Sustituye `Europe/Bucharest` por tu zona horaria real.

<Notice type="warning" title="Zona horaria incorrecta = copias a horas incorrectas">
Si la zona horaria de tu servidor no es correcta, las copias de seguridad se ejecutarán a horas inesperadas. Esto importa si tienes ventanas de mantenimiento o quieres que las copias se ejecuten en periodos de poco tráfico.
</Notice>

### Crea una carpeta de destino en OneDrive o Google Drive

Ve a tu proveedor de nube y crea una carpeta dedicada para las copias de seguridad _antes_ de ejecutar la configuración de Rclone. Ni CloudPanel ni Rclone la crearán por ti. Si la carpeta no existe, obtendrás errores.

Para esta guía usaré una carpeta llamada `dragos-cloudpanel-backups`.

**Costes de almacenamiento a tener en cuenta:**

| Proveedor | Nivel gratuito | Nivel de pago | Notas |
|-----------|----------------|---------------|-------|
| Google Drive | 15 GB | 100 GB ~ $1.99/mes | Límite de subida no documentado de ~750 GB/día |
| OneDrive | 5 GB | 100 GB ~ $1.99/mes, 1 TB con M365 ~ $6.99/mes | El refresh token caduca tras 90 días de inactividad |

Ambos descuentan las copias de seguridad de tu cuota de almacenamiento. Planifica la retención en consecuencia.

### Conéctate mediante un túnel SSH para la autenticación en el navegador

Rclone necesita un navegador para OAuth, pero tu servidor no tiene entorno gráfico. La solución es un túnel SSH que redirige el puerto 53682 del servidor a tu máquina local.

<Notice type="info" title="El túnel solo durante la configuración">
El túnel SSH solo es necesario durante el paso inicial de `rclone config`. Las copias de seguridad del día a día funcionan sin él.
</Notice>

<Tabs>
<Tab name="Mac / Linux">
```sh
ssh -L localhost:53682:localhost:53682 username@your_server_ip
```
Sustituye `username` por tu usuario SSH y `your_server_ip` por la IP del servidor. Funciona en cualquier terminal.
</Tab>
<Tab name="Windows (WSL)">
Si tienes WSL instalado, usa el mismo comando:
```sh
ssh -L localhost:53682:localhost:53682 username@your_server_ip
```
Si no tienes WSL, usa PuTTY: ve a **Connection → SSH → Tunnels**, pon `53682` en Source port y `localhost:53682` en Destination, haz clic en **Add** y conéctate.
</Tab>
</Tabs>

Para más detalles, consulta la [documentación de configuración remota de Rclone](https://rclone.org/remote_setup/).

Si todavía no has instalado CloudPanel, primero [instala CloudPanel en tu servidor](/es/instalar-cloudpanel-alojar-nodejs/). Asegúrate también de [mantener tu instalación de CloudPanel actualizada](/es/actualizar-cloudpanel-seguro/). Las funciones de copia de seguridad han mejorado desde la v2.4.0.

### Verifica la configuración de Rclone

Antes de tocar la interfaz de CloudPanel, comprueba que Rclone realmente puede escribir en el remoto:

```sh
touch /tmp/test-file
rclone copy /tmp/test-file remote:dragos-cloudpanel-backups/
```

Revisa tu carpeta de OneDrive. El archivo de prueba debería aparecer en cuestión de segundos. Si aparece, bórralo:

```sh
rclone delete remote:dragos-cloudpanel-backups/test-file
```

<Notice type="success" title="¿Prueba superada?">
Si el archivo de prueba aparece en tu carpeta en la nube, Rclone está configurado correctamente. Si obtienes errores de autenticación o «directory not found», vuelve a ejecutar `rclone config` y comprueba el nombre de la carpeta.
</Notice>

Este paso detecta fallos de autenticación, carpetas inexistentes y problemas de permisos antes de que rompan silenciosamente tus copias de seguridad reales.

### Configura CloudPanel para usar la configuración personalizada de Rclone

1. Inicia sesión en CloudPanel
2. Ve a **Admin Area → Backups**
3. Elige **Custom Rclone Config**
4. Configura **Frequency** (diaria, semanal), **Time**, **Retention Period** (días) y **Storage Directory** (la carpeta que creaste, p. ej. `dragos-cloudpanel-backups`)
5. Opcionalmente, usa el campo **Excludes** para omitir sitios o rutas concretas
6. Haz clic en **Save** y luego en **Create Backup** para ejecutar una de inmediato

<Picture formats={["webp"]} fallbackFormat="webp" src={imag1} alt="Configuración de copias de seguridad Custom Rclone Config de CloudPanel" />

Después de unos minutos (según el tamaño del sitio), revisa OneDrive. Deberías ver cómo aparecen los archivos de la copia de seguridad.

### Usa tu propio Client ID de Google (recomendado)

<Notice type="info" title="El client_id compartido funciona, pero tiene límites">
El client_id compartido por defecto de Rclone funciona para la configuración inicial. Desde Rclone v1.74.4, se muestra un aviso al usar el ID compartido. Google puede limitar o revocar los ID compartidos con un uso intensivo. Crear el tuyo propio es gratis y está recomendado para copias de seguridad en producción.
</Notice>

Crear tu propio Client ID lleva unos 5 minutos:

1. Ve a [Google Cloud Console](https://console.cloud.google.com/)
2. Crea un proyecto (o usa uno existente)
3. Habilita la **API de Google Drive**
4. Ve a **APIs & Services → Credentials**
5. Crea un **OAuth 2.0 Client ID** (aplicación de escritorio)
6. Copia el client_id y el client_secret
7. Introdúcelos durante `rclone config` en lugar de pulsar Enter para usar los valores por defecto

## Cómo restaurar copias de seguridad de CloudPanel desde OneDrive o Google Drive

<Notice type="warning" title="No hay restauración con un clic">
CloudPanel no tiene restauración con un clic desde las copias de seguridad remotas. Es una [petición de función](https://feature-requests.cloudpanel.io/posts/27/one-click-restore-from-backup) que existe desde los primeros días. La restauración es un proceso manual.
</Notice>

### Restaurar archivos (restauraciones pequeñas de menos de 2 GB)

1. Descarga `backup.tar` desde OneDrive o Google Drive
2. Súbelo a la carpeta `tmp` del sitio usando el **File Manager** de CloudPanel
3. Haz clic derecho en el archivo → **Extract**
4. Copia los archivos a sus ubicaciones correctas

### Restaurar copias de seguridad grandes mediante SFTP y SSH

Para copias de seguridad de más de 2 GB, el File Manager puede agotar el tiempo de espera. Usa SFTP en su lugar:

1. Sube `backup.tar` por SFTP al directorio `~/tmp/` del usuario del sitio
2. Conéctate por SSH como el usuario del sitio
3. Extrae:

```sh
tar xf ~/tmp/backup.tar
```

4. Mueve los archivos a los directorios correctos

### Restaurar bases de datos mediante la CLI

El archivo de la copia de seguridad contiene los volcados SQL de tus bases de datos. Para restaurar una base de datos:

```sh
clpctl db:restore --databaseName=your_database --filePath=/path/to/dump.sql
```

<Notice type="warning" title="Prueba antes de tocar producción">
Prueba siempre las restauraciones primero en un entorno de staging. La base de datos debe existir ya. Créala en la interfaz de CloudPanel si restauras en un servidor nuevo.
</Notice>

## Personalizar la programación de las copias de seguridad de CloudPanel

CloudPanel guarda la programación de las copias de seguridad en `/etc/cron.d/clp`. El valor por defecto es este:

```sh
15 3 * * * clp /usr/bin/bash -c "/usr/bin/clpctl db:backup --ignoreDatabases='db1,db2' --retentionPeriod=7" &> /dev/null
15 4 * * * clp /home/clp/scripts/create_backup.sh &> /dev/null
```

Esto es lo que hace cada línea:

- **La línea 1** ejecuta las copias de seguridad de las bases de datos a las 3:15 con un periodo de retención de 7 días. El flag `--ignoreDatabases` permite excluir bases de datos concretas (sustituye `db1,db2` por nombres reales o elimina el flag).
- **La línea 2** ejecuta la copia de seguridad remota completa (archivos + bases de datos) a las 4:15. Es la que sube los datos a OneDrive/Google Drive mediante Rclone.

<Notice type="info" title="Frecuencia frente a cron">
El cron se ejecuta a diario, pero CloudPanel comprueba el ajuste **Frequency** de la interfaz para decidir si realmente ejecuta la copia de seguridad ese día. Si pones Frequency en «Weekly», el cron sigue ejecutándose a diario, pero solo realiza la copia una vez a la semana.
</Notice>

Puedes cambiar las horas para adaptarlas a tu planificación. Solo mantén la copia de las bases de datos antes que la copia completa (la línea 1 antes que la línea 2) para que los volcados estén actualizados.

## Solución de problemas de las copias de seguridad remotas de CloudPanel

<Accordion label="Solucionar la caducidad del token (límite de 90 días de OneDrive)" group="troubleshooting">

Los refresh tokens de OneDrive caducan tras 90 días de inactividad. Si las copias de seguridad se ejecutan al menos una vez cada 90 días, el token se renueva automáticamente y ni te enteras. Pero si las copias dejan de ejecutarse (desactivadas, servidor caído, frecuencia demasiado baja), el token caduca y las subidas fallan silenciosamente.

**Solución:** vuelve a autenticar Rclone:

```sh
rclone config reconnect remote:
```

Esto abre el navegador a través del túnel SSH (necesitarás el túnel abierto de nuevo). Tras volver a autenticarte, prueba con:

```sh
rclone lsd remote:dragos-cloudpanel-backups/
```

Si lista el directorio, todo está bien.

**Prevención:** pon un recordatorio en el calendario cada 60 días o monitoriza los logs de las copias de seguridad en busca de errores de autenticación.

</Accordion>

<Accordion label="Error 'Remote not found'" group="troubleshooting">

CloudPanel espera que el remoto de Rclone se llame exactamente `remote` (en minúsculas). Si le pusiste otro nombre durante la configuración, no funcionará.

Comprueba lo que tienes:

```sh
rclone listremotes
```

Si muestra algo distinto de `remote:`, cámbiale el nombre:

```sh
rclone config
```

Luego usa la opción **r) Rename remote**.

</Accordion>

<Accordion label="No se encuentra la carpeta de copias de seguridad" group="troubleshooting">

La carpeta de destino debe existir en OneDrive/Google Drive antes de configurar CloudPanel. Si ves errores sobre rutas inexistentes:

1. Ve a tu proveedor de nube y crea la carpeta manualmente
2. Verifica que Rclone puede verla:

```sh
rclone lsd remote:
```

3. Vuelve a ejecutar la copia de seguridad desde CloudPanel

</Accordion>

<Accordion label="Errores de permisos en OneDrive Personal" group="troubleshooting">

OneDrive Personal tiene algunas limitaciones de API en comparación con Business:

- `rclone cleanup` no funciona (no se pueden eliminar versiones)
- El borrado definitivo no está soportado
- El campo de descripción ya no está soportado (desde Rclone v1.73.0)

Esto no rompe las copias de seguridad; solo limita algunas operaciones de gestión. Las copias de seguridad y las restauraciones funcionan bien.

</Accordion>

<Accordion label="Problemas con el túnel SSH en Windows" group="troubleshooting">

Si el túnel SSH no funciona desde el símbolo del sistema de Windows o PowerShell:

1. **Usa WSL** (Windows Subsystem for Linux). El comando `ssh -L` funciona exactamente igual
2. **Usa PuTTY**: ve a **Connection → SSH → Tunnels**, pon `53682` en Source port y `localhost:53682` en Destination, haz clic en **Add** y conéctate
3. Si el puerto 53682 está bloqueado por un firewall local, permítelo temporalmente durante la configuración. Solo es necesario para la autenticación inicial de `rclone config`

</Accordion>

## Reflexiones finales

Las copias de seguridad remotas no son opcionales en el autoalojamiento. El método de Custom Rclone Config descrito aquí funciona de forma fiable tanto con OneDrive como con Google Drive personal. No es un truco: es el enfoque oficial cuando las opciones nativas de la interfaz no cubren tu proveedor.

Algunas cosas a tener en cuenta:

- **Prueba tus restauraciones.** Una copia de seguridad de la que nunca has restaurado no es una copia de seguridad: es una esperanza. Descarga el archivo, extráelo y confirma que los archivos están intactos y la base de datos se importa sin problemas.
- **Vigila la caducidad del token de OneDrive.** Es la principal causa de fallos silenciosos: las copias parecen ejecutarse, pero no se sube nada.
- **Mantén CloudPanel actualizado.** Las funciones de copia de seguridad han mejorado desde la v2.4.0 (copia con prioridad a la base de datos, inclusión del vhost). Las correcciones de seguridad también importan: varias CVE de escalada de privilegios se parchearon en la v2.5.0.
