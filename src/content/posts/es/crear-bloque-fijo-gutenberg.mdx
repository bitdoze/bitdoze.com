Un bloque fijo (sticky) en Gutenberg permanece visible mientras el lector se desplaza por todo lo que hay a su alrededor. Es el patrón detrás de los botones de afiliado con llamada a la acción, avisos flotantes y cajas promocionales. Si quieres hacer que un bloque se quede fijo al hacer scroll en lugar de dejar que salga del viewport, esta es la técnica.

La misma idea de elemento flotante está detrás de [añadir un menú flotante a un sitio web en Carrd](/es/menu-flotante-carrd/), [un botón de volver arriba en Carrd](/es/boton-volver-arriba-carrd/), [un botón flotante de chat de WhatsApp](/es/boton-whatsapp-carrd/) y [un aviso de cookies en un sitio Carrd](/es/anadir-aviso-cookies-carrd/). Si gestionas un sitio de una sola página en [Carrd](https://go.bitdoze.com/carrd), esas guías cubren la misma técnica allí. En WordPress tienes tres caminos reales: el plugin gratuito Sticky Block, el posicionamiento nativo del bloque Grupo o unas pocas líneas de CSS personalizado. Abajo tienes cada uno, con los ajustes exactos, los fallos habituales y una lista de verificación para comprobar que funciona. Una nota de partida: WordPress incluye posicionamiento fijo nativo solo para bloques de Grupo de nivel superior, así que cualquier elemento dentro del contenido sigue necesitando un plugin o CSS.

## ¿Qué es un bloque fijo en Gutenberg?

Un bloque fijo usa CSS `position: sticky`. Se desplaza normalmente con la página hasta que cruza un umbral (normalmente `top: 0`), y entonces queda fijado en su sitio mientras su contenedor padre siga visible.

La parte que mucha gente pasa por alto: un elemento `sticky` permanece dentro de su contenedor padre. No es `position: fixed`, que mantendría el elemento en pantalla para siempre. En cuanto el contenedor padre termina de desplazarse, el elemento fijo se marcha con él. Por eso el posicionamiento fijo nativo funciona para cabeceras (el padre es la plantilla de altura completa) y por eso un botón dentro de un bloque corto de una entrada «deja de estar fijo» antes de lo que esperas.

<Image src={imgStickyVsFixed} alt="Diagrama: un bloque fijo anclado en la parte superior de un contenedor padre alto, y el mismo bloque desplazándose fuera cuando termina el contenedor padre" />

<Notice type="info" title="Sticky no es fixed">
Un bloque sticky permanece fijado solo mientras su contenedor padre está visible. Si el bloque parece soltarse demasiado pronto, el contenedor padre es demasiado corto.
</Notice>

Puedes crear un bloque fijo en Gutenberg de tres formas: un plugin que envuelve cualquier bloque, el ajuste integrado de Posición en bloques de Grupo o una clase CSS personalizada en cualquier bloque. Aquí tienes cada una.

## Opción 1: Plugin Sticky Block para Gutenberg (gratis)

El plugin gratuito [Sticky Block for Gutenberg Editor](https://wordpress.org/plugins/sticky-block/) (slug `sticky-block`, de Senff) es la forma más sencilla de fijar cualquier bloque dentro del contenido de una entrada. Tiene más de 7.000 instalaciones activas, está probado hasta WordPress 7.1.4, requiere WordPress 5.0+ y mantiene una valoración de 92/100 en WordPress.org. Si solo quieres que un botón o un aviso siga al lector por la entrada, usa este.

### Paso 1: Instala el plugin Sticky Block for Gutenberg Editor

Ve a **Plugins → Añadir nuevo**, busca "Sticky Block" (el buscador del administrador sigue encontrándolo por el slug aunque el nombre en el directorio sea más largo), instálalo y actívalo. Haz una copia de seguridad antes si no tienes copias automatizadas activas; cualquiera de estos [plugins gratuitos de backup para WordPress](/es/mejores-plugins-gratuitos-backup-wordpress/) sirve.

### Paso 2: Añade el contenedor Sticky Block

En el editor de bloques, inserta un **Sticky Block** y mete cualquier bloque interior dentro de él (un botón, una imagen, un Grupo, columnas). El contenedor en sí es invisible en el front end; solo se renderiza el contenido anidado, y permanece fijo. Puedes colocar varios Sticky Blocks en una misma página.

<Picture formats={["webp"]} fallbackFormat="webp" src={imgStickey} alt="Añadiendo un contenedor Sticky Block alrededor de un bloque de botón en el editor Gutenberg" />

Para verificarlo: previsualiza la página y haz scroll. El bloque interior debería viajar con el viewport en lugar de quedar atrás. Si no se fija nada, probablemente el bloque interior quedó fuera del contenedor Sticky Block. Haz clic en Vista de lista en el editor y confirma el anidamiento.

### Paso 3: Configura las opciones de fijación

Selecciona el Sticky Block para abrir el panel **Sticky Options**. Los ajustes, con las etiquetas tal como aparecen en el plugin:

- **"Space between sticky block and top of screen"** define el desplazamiento en píxeles entre el elemento fijo y la parte superior del viewport. Úsalo para dejar libre una cabecera fija o la barra de administración.
- **"Block should not be sticky on screens smaller than:"** establece un ancho mínimo de viewport en px. Por debajo de ese ancho el plugin desactiva la fijación.
- **"Block should not be sticky on screens wider than:"** establece un ancho máximo de viewport en px. Por encima de ese ancho el plugin desactiva la fijación.
- **"Pushup Element:"** acepta un selector CSS de clase o ID para un elemento que empuja al bloque fijo fuera del camino cuando entra en pantalla al hacer scroll. Un pie de página funciona muy bien aquí.
- Sube **z-index** ("Only applies once the element is sticky") si el bloque fijo queda oculto detrás de otros elementos de la página.

El plugin tiene en cuenta la barra de administración de WordPress, así que el bloque fijo ajusta su desplazamiento automáticamente cuando estás conectado y la barra está visible.

<Picture formats={["webp"]} fallbackFormat="webp" src={imgOptions} alt="Panel de opciones Sticky Options del plugin Sticky Block en Gutenberg mostrando el espacio superior, ancho mínimo y máximo de pantalla, elemento de empuje y z-index" />

<Notice type="warning" title="Cuidado con Pushup Element">
El selector de Pushup Element debe coincidir exactamente con un elemento en la página. Si coincide con cero o varios elementos, el plugin registra advertencias `STICKY BLOCK DEBUGGER:` en la consola del navegador y desactiva el comportamiento de empuje.
</Notice>

### Paso 4 (opcional): Estiliza el bloque solo mientras está fijo

El plugin alterna dos clases CSS en el contenedor: `.block-is-sticky` mientras el bloque está fijado y `.block-is-not-sticky` mientras se desplaza normalmente. Úsalas para añadir una sombra o cambiar el fondo solo durante el estado fijo:

```css
/* Only while the block is stuck */
.block-is-sticky { box-shadow: 0 4px 12px rgb(0 0 0 / 0.15); }

/* Only while not stuck */
.block-is-not-sticky { background: transparent; }
```

Añade el CSS en **Apariencia → Personalizar → CSS adicional** (temas clásicos) o en el panel de CSS adicional del Editor del Sitio (temas de bloques), y luego haz scroll en la página: la sombra debería aparecer exactamente cuando el bloque se fija y desaparecer cuando vuelve a desplazarse.

## Opción 2: Posición fija nativa en bloques Grupo (WordPress 6.2+)

Desde WordPress 6.2, la familia de bloques Grupo (Grupo, Fila, Pila y Cuadrícula, todas variaciones del bloque Grupo) incluye un ajuste de **Posición** con la opción **Fijo** (**Sticky**). No necesita plugin. La pega: el control solo aparece en bloques de nivel superior. Si el Grupo está anidado dentro de otro bloque, el control de Posición desaparece de la barra lateral. La [documentación oficial del bloque Grupo](https://wordpress.org/documentation/article/group-block/) lo deja claro: solo los bloques Grupo de nivel superior pueden fijarse.

Pasos:

1. Abre el Editor del Sitio (**Apariencia → Editor**) o edita una página con un diseño de nivel raíz
2. Selecciona o inserta un bloque **Grupo** (o Fila/Pila/Cuadrícula) de nivel superior
3. En la barra lateral del bloque, bajo **Posición**, elige **Fijo**
4. Previsualiza y haz scroll para confirmarlo

El posicionamiento fijo nativo ancla el bloque a la parte superior del viewport al hacer scroll. Este es el patrón de cabecera fija en WordPress que usan la mayoría de los temas de bloques.

<Image src={imgTopLevelVsNested} alt="Diagrama: un bloque Grupo a nivel raíz muestra el control Posición Fijo, mientras que un bloque Grupo anidado dentro de otro bloque no tiene control de Posición" />

Recuerda la regla del contenedor padre: la fijación nativa solo se mantiene dentro de su contenedor padre. Para una cabecera, el padre es la plantilla de altura completa, así que permanece anclada durante toda la página. Para un bloque a mitad del contenido, el padre es corto y el elemento desaparece rápido. Es así por diseño.

<Notice type="info" title="El posicionamiento fijo nativo es para cabeceras">
La fijación nativa está pensada para cabeceras y maquetación a nivel de sitio. Si necesitas que un bloque se fije dentro del contenido de una entrada, usa la Opción 1 o la Opción 3.
</Notice>

## Opción 3: Haz fijo un bloque al hacer scroll con CSS personalizado

Si no quieres usar un plugin, asigna al bloque una clase CSS personalizada (barra lateral del bloque → **Avanzado → Clases CSS adicionales**, por ejemplo `my-sticky-block`) y añade esto al CSS de tu sitio (**Apariencia → Personalizar → CSS adicional**, o el panel de CSS adicional del Editor del Sitio):

```css
/* Works only if no ancestor has overflow: hidden/auto/scroll
   and the parent is taller than this block */
.my-sticky-block {
  position: sticky;
  top: 1rem;
}
```

Ajusta `top` para cambiar el desplazamiento desde la parte superior del viewport. La contrapartida: no hay panel de ajustes visual, ni elemento de empuje, ni umbrales por tamaño de pantalla. A cambio tienes cero sobrecarga de plugins y una técnica que funciona en cualquier bloque, incluidos bloques que el plugin no puede envolver.

### Por qué tu CSS fijo no funciona

`position: sticky` falla en silencio. Sin errores: simplemente no se fija. Dos causas cubren casi todos los casos:

1. **Un elemento ancestro tiene `overflow: hidden`, `auto` o `scroll`.** Entonces el elemento sticky se fija dentro de ese contenedor con scroll en lugar del viewport. Inspecciona cada elemento padre hasta `<body>` en DevTools y elimina el `overflow`, o reestructura el DOM.
2. **El elemento padre no es más alto que el elemento fijo.** No hay espacio para desplazarse, así que el padre sale de pantalla de inmediato. Asegúrate de que el bloque fijo esté dentro de un contenedor con contenido suficiente por el que hacer scroll.

Comprobación rápida: DevTools → selecciona el bloque → estilos **Computed** → confirma que `position` se resuelve como `sticky`, no `static` ni `relative`.

<Notice type="error" title="Sticky falla en silencio">
Sticky falla en silencio (sin error, simplemente no se fija) cuando un ancestro tiene `overflow: hidden/auto/scroll`. Revisa cada padre hasta `<body>` en DevTools → Computed.
</Notice>

## Comprueba que tu bloque fijo funciona

Después de configurarlo, pasa esta lista de verificación en el front end. Lleva unos dos minutos:

<ListCheck>
<ul>
<li>Abre la entrada o página publicada y haz scroll. El bloque debería anclarse en el desplazamiento configurado</li>
<li>Abre las DevTools del navegador, inspecciona el bloque fijo y comprueba en estilos **Computed** que aparece `position: sticky`</li>
<li>Mientras está fijado, revisa las clases del elemento. `.block-is-sticky` debería estar presente (método con plugin)</li>
<li>Haz scroll más allá del contenedor padre. El bloque debería marcharse con el scroll (ese es el comportamiento correcto de sticky, no un bug)</li>
<li>Revisa la consola del navegador por si aparecen advertencias `STICKY BLOCK DEBUGGER:` (mala configuración del elemento de empuje)</li>
<li>Prueba en móvil o estrecha la ventana del navegador. Los umbrales de ancho mínimo/máximo deberían comportarse según lo configurado</li>
<li>Inicia sesión como administrador. La barra de administración no debería tapar el bloque fijo</li>
</ul>
</ListCheck>

## Preguntas frecuentes: Bloques fijos en Gutenberg

<Accordion label="¿Se puede hacer fijo cualquier bloque en Gutenberg?" group="faq" expanded="true">
Sí. Con el plugin Sticky Block puedes envolver cualquier bloque (botón, imagen, Grupo, columnas) y hacerlo fijo. El CSS personalizado con `position: sticky` también funciona en cualquier bloque; añade una clase mediante Clases CSS adicionales. El control nativo Posición → Fijo es la excepción: solo funciona en bloques de la familia Grupo en el nivel superior (Grupo, Fila, Pila, Cuadrícula) y está pensado para cabeceras. Ningún método hace fijo un bloque anidado a través del control nativo.
</Accordion>

<Accordion label="¿Por qué no funciona mi bloque fijo en móvil?" group="faq">
Dos causas habituales. Primera, los umbrales de ancho del plugin: «Block should not be sticky on screens smaller than» y «Block should not be sticky on screens wider than» desactivan la fijación en ciertos tamaños de viewport. Revisa esos valores antes que nada. Segunda, el fallo de `overflow` en CSS de la Opción 3 también aplica en móvil. Ten en cuenta además que el script del plugin en el front end se basa en jQuery: si tu tema o un plugin de optimización elimina jQuery, la fijación nunca se inicializa. Si el problema es en realidad la navegación móvil y no un bloque fijo, una [barra de navegación responsive para móvil en Carrd](/es/navbar-movil-carrd/) es una configuración completamente distinta.
</Accordion>

<Accordion label="¿Existe un plugin gratuito de bloque fijo para WordPress?" group="faq">
Sí. «Sticky Block for Gutenberg Editor» es completamente gratuito: más de 7.000 instalaciones activas, probado hasta WordPress 7.1.4 a noviembre de 2026. Cubre bloques fijos dentro del contenido con espaciado superior, umbrales de ancho mínimo/máximo, elemento de empuje y z-index. Si necesitas menús de navegación o widgets fijos en temas clásicos, «Sticky Menu & Sticky Header» (más de 90.000 instalaciones) también es gratuito.
</Accordion>

Para la mayoría de las personas que fijan un bloque dentro del contenido de una entrada, el plugin gratuito Sticky Block es el camino más rápido: estable, probado hasta WordPress 7.1.4 y sin necesidad de CSS. El posicionamiento fijo nativo cubre las cabeceras. El CSS personalizado cubre el resto. Los tres métodos son reversibles: desactiva el plugin, elimina la clase o devuelve Posición a Por defecto.
