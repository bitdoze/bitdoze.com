Orca vs T3 Code se reduce a una pregunta: un IDE de escritorio o un plano de control. Elige Orca si trabajas en una sola ventana de escritorio con muchos agentes, muchos repositorios y, desde hace poco, bots que reciben trabajo desde Slack. Elige T3 Code si quieres un servidor que controlas desde un portátil, un navegador y un móvil. Probé ambos en Linux el 24 de noviembre de 2026, les di una tarea pequeña sobre el mismo repositorio y no cambié nada más.

Los dos son gratuitos y con licencia MIT. Ninguno vende tokens. Cada uno se apoya en los CLI de agentes por los que ya pagas (Claude Code, Codex, OpenCode, Pi y el resto) y te da un sitio donde ejecutar varios a la vez sin perderles la pista. Orca es un IDE al que le crecieron una capa de chat y una capa de bots. T3 Code es un plano de control con clientes.

<Notice type="info" title="Cómo los probé">
Ambas herramientas corrrieron en la misma máquina Linux: Orca 1.4.272 desde el AppImage y T3 Code 0.1.11 a través de su servidor `t3` y su aplicación web. Cada uno recibió una tarea sobre el mismo repositorio de sitio estático, y todas las capturas de este artículo salen de esas sesiones. No probé las apps de móvil, Orca Bots de principio a fin (los conectores de Slack, GitHub y Linear necesitan una cuenta de Orca), T3 Connect ni hosts remotos. Una ejecución por herramienta es una observación, no un benchmark.
</Notice>

## Qué es cada uno

Orca se define como "un IDE de escritorio para ejecutar varios agentes de código con IA en paralelo" ([documentación](https://orca.dev/docs)). Es una aplicación Electron de Stably AI, respaldada por Y Combinator, y su página principal abre ahora con los bots: "pásales trabajos desde Slack, Linear o GitHub, y entra en acción cuando te necesiten". Cada tarea tiene su propio worktree de git, su propio chat de agente o terminal, y su propia pestaña de navegador.

T3 Code se define como "el plano de control open source para agentes de código" ([README](https://github.com/pingdotgg/t3code)). Es un servidor que corre en la máquina donde está tu código, más una app de escritorio, una app web alojada, y apps para iOS y Android que son todas clientes de ese servidor. La app de escritorio incluye el servidor. La app web y los móviles se conectan a él.

![Diagrama de Orca: la app de escritorio lanza la mayoría de los CLI de agentes con flags de omisión de permisos, que se ejecutan en este ordenador, un host SSH, un Remote Orca Server o una VM en la nube](@assets/images/26/11/orca-architecture.webp)

*Cómo encaja Orca. Fuentes: la documentación sobre [worktrees](https://orca.dev/docs/model/worktrees), [agentes](https://orca.dev/docs/agents/supported) y [formas de ejecutarlo](https://orca.dev/docs/ways-to-run).*

![Diagrama de T3 Code: los clientes de escritorio, web y móvil se conectan a un servidor T3, que ejecuta los CLI de agentes mediante ACP dentro de una carpeta de proyecto o de un worktree](@assets/images/26/11/t3-code-architecture.webp)

*Cómo encaja T3 Code. Fuentes: la documentación de [arquitectura](https://github.com/pingdotgg/t3code/blob/main/docs/internals/01_architecture.md) y de [acceso remoto](https://github.com/pingdotgg/t3code/blob/main/docs/user/remote-access.md).*

## Comparación rápida

| | Orca 1.4.272 | T3 Code 0.1.11 |
|---|---|---|
| Autor | Stably AI (Y Combinator) | T3 Tools |
| Licencia | MIT | MIT para el código; el nombre y los logos son marca registrada |
| Forma | App de escritorio (Electron) más un complemento móvil | Un servidor, con clientes de escritorio, web y móvil |
| Instalación | macOS 13.4+, Windows 10/11, Linux (AppImage, deb, rpm) | macOS, Windows, Linux (dmg, exe, deb, AppImage) y el CLI `t3` |
| Agentes | 34 con nombre en el README, más cualquier agente con CLI | 10 integrados, más agentes del ACP Registry |
| Conexión de agentes | Lanza el CLI en una terminal o en un chat estructurado | Ejecuta cada proveedor integrado detrás de un adaptador; los demás agentes hablan ACP |
| Aislamiento | Un worktree de git por tarea | Un worktree por hilo, opcional |
| Permisos por defecto | Acceso total, con el flag de omisión de la mayoría de los CLI | Acceso total para los hilos nuevos |
| Móvil | Orca Mobile (beta) a través de Orca Relay o de tu LAN | Apps para iOS y Android; las notificaciones push requieren T3 Connect |
| Hosts remotos | Hosts SSH, Remote Orca Server (beta), VM en la nube (experimental) | Entornos SSH, Tailscale, T3 Connect (3 máquinas gratis) |
| Trabajo asíncrono | Orca Bots (beta), automatizaciones, horarios y disparadores | Tareas programadas, un servidor MCP para agentes externos, enlaces a hilos |
| Navegador integrado | Sí, con Design Mode | Sí; la primera pestaña descarga unos 120 MB de Chrome headless |
| Precio | Gratis; las VM en la nube las factura tu propio proveedor | Gratis; T3 Connect es gratis hasta 3 máquinas |

Dos filas merecen una frase cada una. "Agentes" es donde la brecha es mayor: Orca lanza cualquier cosa que corra en una terminal, mientras que T3 Code añade agentes externos a través del ACP Registry o de un comando ACP local. "Trabajo asíncrono" es donde Orca se adelanta, y tiene su propia sección más abajo.

## Instalar ambos

<Tabs>
<Tab name="Orca">
```bash
# macOS (usa el nombre completo: "orca" a secas es un cask sin relación)
brew install --cask stablyai/orca/orca

# Arch Linux
yay -S stably-orca-bin

# Cualquier otra distribución Linux: el AppImage, el .deb y el .rpm están en la página de versiones
chmod +x orca-linux.AppImage && ./orca-linux.AppImage
```

En Linux el binario de línea de comandos se llama `orca-ide`, así que no choca con el lector de pantalla Orca de GNOME. El primer arranque pasa por cinco pasos de configuración inicial: chat o terminal, agente por defecto, apariencia, tareas de GitHub y notificaciones. En mi máquina encontró 16 CLI de agentes en el `PATH` sin ayuda.
</Tab>
<Tab name="T3 Code">
```bash
# App de escritorio
brew install --cask t3-code        # macOS
winget install T3Tools.T3Code      # Windows
sudo apt install ./T3-Code-*.deb   # Debian, Ubuntu

# El comando t3: arranca el servidor y abre la app web
curl -fsSL https://t3.codes/install.sh | sh

# O pruébalo una vez sin instalarlo
npx t3@latest
```

El servidor escucha en `127.0.0.1` (puerto 3773 en el ejemplo de la documentación). Flags que confirmé con `t3 --help`: `--port`, `--host`, `--no-browser`, `--lan`, `--tailscale-serve` y `--base-dir` para un segundo servidor independiente. La pantalla de bienvenida muestra qué agentes tienen la sesión iniciada y ofrece importar proyectos desde tu historial de Claude Code, Codex y Pi. Añade una carpeta a mano con `t3 project add ./my-project`.
</Tab>
</Tabs>

Hay algo que Orca hace y que debes saber: modifica la configuración de los propios CLI de agentes. En un perfil limpio, la versión 1.4.272 escribió entradas de hooks para `SessionStart`, `PreToolUse`, `PermissionRequest`, `Stop` y otros en `~/.claude/settings.json`, añadió una línea de estado y creó `~/.codex/hooks.json`. Los scripts están en `~/.orca/agent-hooks/`. Así es como muestra los estados de trabajando, esperando y terminado. Settings, Agents, "Agent status hooks" lo desactiva y elimina los hooks.

## Ejecutar una tarea en cada uno

### Orca: primero un worktree, luego un chat

Pulsa el botón más junto a un proyecto y aparece el diálogo Create worktree (crear worktree): proyecto, dónde se ejecuta, el ref desde el que parte, un nombre, una rama nueva o existente y, opcionalmente, un agente. Advanced esconde un worktree padre, una nota y el sparse checkout.

![Diálogo Create worktree de Orca con el proyecto demo-repo, Local Linux como destino de ejecución, origin/main como base, el nombre add-bean-prices y Claude como agente opcional](@assets/images/26/11/orca-create-worktree-dialog.webp)

*El diálogo Create worktree en Orca 1.4.272 sobre Linux.*

Los worktrees van a `~/orca/workspaces/<project>/<name>` si mantienes las carpetas por defecto. Lancé Pi con el modelo Beam gratuito y le pedí que añadiese precios a la lista de cafés. Terminó en 23 segundos con tres archivos modificados, y el chat muestra el resultado como una tarjeta.

![Chat de Orca donde un agente de Pi informa de Changes complete, una tarjeta con 3 archivos modificados y su número de líneas, y el worktree add-bean-prices en la barra lateral](@assets/images/26/11/orca-pi-chat-thread.webp)

*Un turno terminado en la interfaz de chat de Orca: la respuesta, los archivos modificados y el worktree en la barra lateral.*

Despliega la fila "Worked for" y tienes la línea de tiempo completa: los comandos, las lecturas de archivos y las ediciones de ese turno.

![Línea de tiempo de actividad de Orca para un turno de agente: cuatro comandos bash, entre ellos un find en todo el sistema de archivos, cuatro lecturas de archivos y tres ediciones](@assets/images/26/11/orca-chat-activity.webp)

*El mismo turno con la actividad desplegada. No apareció ninguna solicitud de aprobación.*

Lee esa línea de tiempo con atención. Un comando fue `find / -path /proc -prune -o -name "*beans*" ...`, una búsqueda en todo el sistema de archivos, no solo en el worktree. El worktree mantiene limpio el estado de git. No mantiene al agente dentro de la carpeta.

### T3 Code: un hilo, con worktree si quieres uno

Un hilo nuevo empieza en un compositor: el cuadro de mensaje, un selector de modelo y, debajo, tres controles pequeños para Workspace (espacio de trabajo: el checkout actual o un worktree nuevo), Branch y Permissions.

![Pantalla de hilo nuevo de T3 Code con el compositor, el selector de modelo GPT-6 Astra y los controles Workspace, Branch y Permissions bajo el cuadro de mensaje](@assets/images/26/11/t3-new-thread.webp)

*Un hilo nuevo en T3 Code 0.1.11. El panel derecho lista el contexto de ejecución, el editor y las acciones de git.*

Elegí Codex con GPT-6 Astra, cambié Permissions a Supervised (supervisado) y volví a enviar la tarea, redactada para Codex. T3 Code se detuvo tres veces: para ejecutar `cat app.js index.html styles.css`, para actualizar `styles.css` y para ejecutar `git diff --check && node --check app.js && git diff --stat`. El turno tardó 1 minuto y 25 segundos y modificó tres archivos. No lo compares con los 23 segundos de Orca. Agente distinto, modelo distinto.

![Hilo de T3 Code esperando la aprobación de un comando cat, con los botones Decline y Approve y una insignia Approval en la barra lateral](@assets/images/26/11/t3-approval-prompt.webp)

*El modo Supervised en acción: el comando, Decline y Approve, y una insignia Approval en el hilo de la barra lateral.*

![Hilo de T3 Code tras el turno: la respuesta del agente, una tarjeta de 3 archivos modificados con el número de líneas de cada uno y el compositor ajustado en Supervised](@assets/images/26/11/t3-thread-done.webp)

*El turno terminado en T3 Code: la respuesta y los archivos modificados, con el hilo aún en modo Supervised.*

Olvida los tiempos, porque los agentes y los modelos cambian. Lo que importa es que T3 Code ofrecía un modo Supervised que pude elegir con un clic, mientras que el valor por defecto de Orca dejó al agente buscar fuera del proyecto sin preguntar.

## Agentes y modelos

La regla de Orca es "cualquier agente con CLI": el selector solo lanza un proceso. El README nombra 34, la tabla de la documentación lista 43, y en mi instalación aparecieron 16 detectados más 29 disponibles para instalar desde Settings. 21 tienen una interfaz de chat estructurada en lugar de una terminal en bruto, y lo eliges agente por agente. También puedes hacer clic derecho en una pestaña para mover una sesión en marcha entre el chat y el CLI, o pasar una conversación a otro agente ([documentación](https://orca.dev/docs/agents/native-chat)).

T3 Code empieza con Claude Code, Codex, Cursor, OpenCode, Grok Build, Antigravity, Kiro, Pi, Muse Code y fx, y luego añade cualquier cosa del ACP Registry desde Settings, Providers, "Show more". Cada proveedor tiene su propia ruta al binario, sus argumentos de lanzamiento, sus variables de entorno y su lista de modelos. Dos cosas que T3 Code hace en un paso:

- Cambiar de modelo en mitad de un hilo. T3 Code transfiere el contexto de la conversación al cambiar, con un margen por defecto de 16,000 tokens de historial.
- Hacer Mayús-clic en varios modelos del selector para enviar un mismo prompt a todos. Cada selección arranca su propio hilo y worktree.

Si aún estás configurando los propios agentes, la [guía de configuración de Pi](/es/guia-configuracion-pi-agent/) y la [guía de configuración de OpenCode](/es/guia-configuracion-opencode/) cubren esa parte, y [OpenCode vs Pi](/es/opencode-vs-pi-agent/) explica en qué se diferencian.

## Permisos: cambia esto antes del primer prompt

Las dos herramientas llegan con los frenos quitados. Es el primer ajuste que tocar en cualquiera de las dos.

En Orca, "Permissions" para los agentes nuevos dice **Full access** (acceso total) tras una instalación limpia. Funciona por flag: la mayoría de los CLI compatibles se lanzan con su propia omisión de permisos. Pi y OpenCode arrancan sin ella.

![Settings de Orca, página Agents, lista Installed que muestra que Claude se lanza con --dangerously-skip-permissions y Codex con --dangerously-bypass-approvals-and-sandbox](@assets/images/26/11/orca-settings-agent-commands.webp)

*Settings, Agents en Orca 1.4.272: el comando con el que se lanza cada agente.*

Claude recibe `--dangerously-skip-permissions`, Codex recibe `--dangerously-bypass-approvals-and-sandbox`, Grok recibe `--permission-mode bypassPermissions`, y Gemini, Cursor y Hermes reciben `--yolo`. La documentación explica el porqué: "La idea es que el propio worktree sea el sandbox: los agentes pueden trabajar sin que un prompt de aprobación por herramienta rompa el flujo". Puedes cambiar cada agente, o todos a la vez, a Manual o Auto en Settings, Agents.

En T3 Code hay cuatro modos, y el valor inicial para los hilos nuevos también es Full access:

| Modo | Qué hace |
|---|---|
| Supervised | Pide aprobación para comandos y cambios de archivos |
| Auto-accept edits | Aprueba automáticamente las ediciones de archivos; otras acciones pueden seguir requiriendo aprobación |
| Auto | Usa la revisión automática del proveedor para aprobar acciones rutinarias y preguntar por el resto |
| Full access | Permite comandos y ediciones sin prompts de aprobación |

![Popover Permissions de T3 Code con cuatro modos y la opción Full access seleccionada, descrita como la que permite comandos y ediciones sin prompts](@assets/images/26/11/t3-code-permission-modes-detail.webp)

*El control Permissions bajo el compositor de T3 Code. Full access está seleccionado, como en todos los hilos nuevos.*

Cámbialo por hilo desde ese control, o una sola vez para todo en Settings, Threads, New threads, Permissions. Los proyectos pueden anular el valor por defecto del entorno, y un administrador puede limitar los modos con una política gestionada ([documentación](https://github.com/pingdotgg/t3code/blob/main/docs/user/permission-modes.md)). Fíjate en el detalle: en Full access, "los comandos sobre los que la comprobación de comandos peligrosos de Codex preguntaría se ejecutan sin preguntar".

Ninguna de las dos documenta un sandbox del sistema operativo para los agentes. Una petición de sandboxes con Docker tiene 62 reacciones en el tracker de Orca y sigue abierta. En T3 Code, solo los agentes del Registry traen "sus propias reglas de sandbox y aprobación". Usa ambas solo con agentes en los que ya confíes.

## Revisión, commits y pull requests

Aquí Orca llega más lejos. La pestaña Changes muestra un diff combinado contra el ref desde el que arrancó el worktree, con modo lado a lado, ajuste de línea y staging por hunk o por línea.

![Pestaña Changes de Orca con un diff de código de app.js, index.html y styles.css que muestra líneas eliminadas y añadidas, y una barra de herramientas con Side by Side y Wrap](@assets/images/26/11/orca-diff-review.webp)

*La pestaña Changes en Orca, abierta desde la tarjeta de 3 archivos modificados.*

Tres funciones te ahorran un viaje de ida y vuelta:

- Comenta una línea modificada y "Send to agent" entrega todos los comentarios como un único prompt. Los comentarios siguen a la línea en ediciones posteriores ([documentación](https://orca.dev/docs/review/annotate-ai-diff)).
- Los mensajes de commit y los detalles de la pull request pueden generarse a partir del diff. Un hook de pre-commit que falla recibe un botón "Fix with AI" que pasa la salida a un agente con un prompt de solo reparación ([documentación](https://orca.dev/docs/review/commit-push)).
- En una pull request de GitHub con checks fallidos, "Fix broken checks" envía los nombres de los checks y sus enlaces a un agente.

T3 Code mantiene la revisión dentro del hilo. "Open diff" abre un panel acotado al último turno; una comparación de ramas cubre todo contra la base, y una vista Commits lista los 100 commits locales más recientes.

![Panel Diff de T3 Code a la derecha con los cambios de app.js en rojo y verde y un recuento de 16 líneas añadidas y 2 eliminadas](@assets/images/26/11/t3-diff-view.webp)

*El panel Diff en T3 Code, abierto desde la tarjeta de cambios del hilo.*

Desde las acciones de git del hilo haces commit, push y abres una pull request, con mensajes de commit y descripciones generados. La vista Pull requests gestiona comentarios, revisores y merges. Hosts: GitHub, GitLab, Forgejo, Gitea, Bitbucket, Azure DevOps, GitCafe y Cursor Origin. Las instantáneas se guardan como refs ocultas de git, así que un checkpoint nunca añade un commit a tu rama ([documentación](https://github.com/pingdotgg/t3code/blob/main/docs/user/source-control.md)).

## Orca Bots: agentes que reciben trabajo de Slack, Linear y GitHub

Los bots son la parte nueva de Orca, aún marcados como beta, y T3 Code no tiene nada con la misma forma. La documentación los define así: "Un bot recibe trabajos de su chat, de Slack, Linear, GitHub o de un horario. Trabaja en tu ordenador con tu propio Claude Code o Codex, u otro agente compatible, e informa donde se lo pediste".

![Diagrama de flujo de un bot de Orca: Slack, GitHub, Linear y un horario llegan a Orca Cloud, la carpeta del bot en tu ordenador se conecta hacia fuera, un agente trabaja en un worktree nuevo y las decisiones esperan bajo Needs you](@assets/images/26/11/orca-bots-flow.webp)

*Cómo llega un trabajo a un bot de Orca y vuelve como pull request. Fuente: la documentación de [bots](https://orca.dev/docs/bots) y de [seguridad](https://orca.dev/docs/bots/security).*

Cuatro datos deciden si los bots encajan contigo:

- Un bot vive en una carpeta de un solo ordenador, este o un servidor emparejado, y solo trabaja mientras ese ordenador está despierto y conectado. Su forma de ser y su memoria son archivos Markdown simples (`SOUL.md`, `MEMORY.md`) que puedes leer y editar.
- Slack, GitHub, Linear y los webhooks se conectan a través de Orca Cloud. Tu ordenador se conecta hacia fuera para recoger las peticiones, así que no necesita ningún puerto abierto. Las peticiones esperan hasta un día.
- Los horarios se ejecutan cada hora, a diario, entre semana, cada semana o por cron. Los disparadores se activan con eventos de GitHub (pull requests, pushes, checks fallidos, merges, alertas de seguridad), eventos de Linear, correo nuevo y webhooks.
- Dos trabajos corren por su cuenta: "Look around", un repaso de solo lectura cada 4 horas entre las 8 y las 20 de lunes a viernes, y "Memory upkeep", una limpieza nocturna sin herramientas.

No tienes que escribir uno desde cero. La galería de plantillas incluye 24 bots en seis grupos: código (revisión de pull requests, investigación de bugs, actualizaciones de dependencias, revisión de seguridad), releases y CI, soporte y triaje, planificación y documentación, operaciones (notas de incidentes, relevo de guardia) y un grupo de asistente personal (respuestas que debes, notas del standup diario, resumen de correo, preparación de reuniones).

![Galería de plantillas de bots de Orca con las categorías Coding, Releases and CI, Support and triage, Planning and docs, Ops y Personal assistant](@assets/images/26/11/orca-bot-templates.webp)

*La galería de plantillas de bots en Orca 1.4.272. Algunas plantillas, como la de fallos de CI, piden configuración adicional.*

"Use template" abre un diálogo corto: el ordenador, el agente y lo que incluye el bot. El bot de revisión de pull requests es una skill y una automatización, y no comentará en GitHub hasta que se lo permitas.

![Diálogo New bot de Orca para la plantilla Pull request review, con el ordenador Local Linux, el agente Claude, una skill, una automatización y una nota Needs GitHub](@assets/images/26/11/orca-bot-new-dialog.webp)

*Creando un bot a partir de la plantilla Pull request review.*

Conoce los límites antes de apuntar uno a un canal compartido. La documentación los separa por ti ([seguridad](https://orca.dev/docs/bots/security)):

| Impuesto por Orca | Solo indicado |
|---|---|
| Solo la gente de "Who can ask" puede hablar con el bot, y la lista empieza con el propietario | Aprobar o hacer merge de pull requests solo cuando se le pide |
| "Look around" es de solo lectura | Redactar correo en lugar de enviarlo |
| "Memory upkeep" no tiene herramientas | Tratar los mensajes entrantes como información, no como órdenes |
| Importar un bot omite claves, inicios de sesión y bases de datos | No pedir nunca un token |
| Una persona debe pulsar Create bot, responder a las preguntas bajo "Needs you" y añadir gente a la lista | Las automatizaciones que trae un bot importado empiezan en pausa |

Las palabras de la propia documentación para la columna de la derecha: "Ninguno de estos ajustes es una garantía". Dos avisos más de la misma página: la gente que añades "usa tu acceso, no el suyo", y las automatizaciones por eventos y los webhooks saltan la lista Who can ask. Un bot nuevo empieza además con el permiso de chat por defecto de Orca, Full access. Cámbialo a Ask for approval en cualquier bot al que pueda llegar otra gente.

El ritmo de versiones aquí es rápido. De la v1.4.268 a la v1.4.271 (21 y 22 de noviembre) llegaron los bots a Cursor, GitHub Copilot, Hermes, Kiro, Kimi Code, Gemini CLI, Goose y otros, se añadieron grupos de bots entre ordenadores emparejados y se pudo editar la memoria y las automatizaciones de un bot desde el móvil. La v1.4.272 (23 de noviembre) hizo que los bots se reanuden tras pausas por límite de uso, cuelgues y reinicios ([changelog](https://orca.dev/changelog)). Slack, GitHub y Linear necesitan una cuenta de Orca. Si quieres bots sin un relay en la nube de por medio, las [alternativas open source a Grok Bot](/es/mejores-alternativas-grok-bot-open-source/) que comparé antes están pensadas para ejecutarse en tu propia infraestructura.

## Trabajo remoto y el móvil

Orca trata el móvil como un mando a distancia. "La app móvil no pretende ser un editor completo", dice la documentación, y "el escritorio sigue siendo el dueño del agente". Emparejas con un código de un solo uso a través de Orca Relay (beta, requiere iniciar sesión) o por LAN o Tailscale. Desde el móvil tienes agentes de varios hosts, el estado de los worktrees, archivos, chat o terminal en bruto, control de código fuente, notificaciones push y, desde la v1.4.271, los ajustes de los bots. Para máquinas, Orca tiene tres caminos: hosts SSH (instala un servidor gestionado en el host), Remote Orca Server (beta, `orca serve`, con una unidad de systemd de usuario mediante `orca serve service install`) y una VM en la nube experimental por worktree en la que tú pones el proveedor ([documentación](https://orca.dev/docs/ways-to-run)).

T3 Code está construido al revés: el servidor es el producto y todo lo demás es un cliente. Eso se nota en las opciones para alcanzarlo ([documentación](https://github.com/pingdotgg/t3code/blob/main/docs/user/remote-access.md)):

| Camino | Qué obtienes |
|---|---|
| Red local | `t3 up --lan` o `t3 serve --lan`; un código de emparejamiento es la única protección |
| Tailscale | `t3 serve --tailscale-serve`, por HTTPS con MagicDNS |
| SSH | Añade un entorno en Settings; el servidor se descarga en `~/.t3/runtime` en el host |
| T3 Connect | Sin reenvío de puertos; 3 máquinas por cuenta, gratis por ahora; códigos de aprobación de dispositivos opcionales |
| App web | `app.t3.codes` es un cliente alojado que se conecta directamente a tu servidor |

El coste: las notificaciones push en el móvil requieren T3 Connect. "Una conexión directa o por Tailscale por sí sola no activa las notificaciones push". Cuando funcionan, recibes un aviso cuando un agente termina, falla, necesita aprobación o pide información, y al tocarlo se abre el hilo.

Dos extras de T3 Code que no encontré en la documentación de Orca. Los enlaces a hilos (`app.t3.codes/threads/<environment>/<thread>`) meten un hilo en marcha en un mensaje de Slack o en un comentario de GitHub. Y un servidor MCP permite que agentes que T3 Code no inició, como Claude Code en tu propia terminal o ChatGPT, lean proyectos y arranquen hilos o les escriban, con `t3 thread start` y `t3 thread send` para scripts ([documentación](https://github.com/pingdotgg/t3code/blob/main/docs/user/outside-agents.md)). Para otro enfoque del control desde el móvil, ya escribí sobre [Herdr Mobile y Moshi](/es/controlar-agentes-ia-desde-telefono-moshi-herdr/).

## Diferencias en el día a día

Estas son las que noté o encontré en la documentación.

| Orca | T3 Code |
|---|---|
| Design Mode: pulsa cualquier elemento del navegador integrado y envía su HTML, sus estilos y su selector al agente | La sección Working (en curso) recoge los hilos en ejecución y los devuelve arriba cuando te necesitan |
| La página de nueva pestaña del navegador lista los servidores que ya corren en el espacio de trabajo | Reanuda un turno parado de Claude, Codex, OpenCode o Cursor sin un mensaje nuevo |
| Los agentes siguen corriendo cuando cierras la app o se actualiza (un demonio en segundo plano es dueño de las terminales); un reinicio los mata | Mantiene el ordenador despierto mientras trabajan los agentes (v0.1.10) |
| Editor Monaco, pero sin servidor de lenguaje: "editor-first, not IDE-first" | Una vista Usage que agrupa las ventanas de suscripción de todos los proveedores |
| Plugins de temas, iconos y editores (desde el 30 de octubre) | Un agente puede cambiar el estilo de toda la app si el hilo corre en Full access |
| Automatizaciones: `orca automations create --name review --trigger daily --time 09:00 --prompt "..."` | Sugerencia del siguiente prompt (Labs), entrada de voz, enlaces de invitado y entornos vinculados (beta) |

![Design Mode de Orca: la cabecera de una página de demo está seleccionada y un popover de anotación ofrece Change o Question con un botón Add](@assets/images/26/11/orca-design-mode.webp)

*Design Mode en el navegador integrado de Orca, con una anotación lista para el agente.*

La fila del editor importa si tratas esta ventana como tu IDE. "Have LSP support" es una de las peticiones abiertas con más reacciones en el tracker de Orca. T3 Code deja la edición para un editor externo: su panel de hilo tiene los botones "Open in Cursor" y "Choose editor".

## Precio y telemetría

Ninguna de las dos tiene precio. "T3 Code no revende tokens", dice su sitio, y las FAQ responden a "¿Cuánto cuesta T3 Code?" con "Nada". La página de Orca dice "Gratis y open source", y `orca.dev/pricing` devolvió un 404 cuando lo comprobé. Tu coste son los planes de agentes que ya tienes. Para modelos más baratos detrás de cualquiera de las dos, mira [OpenCode Go vs ClinePass](/es/opencode-go-vs-clinepass-modelos-baratos/).

Hay dos bordes de pago. T3 Connect es gratis "por ahora" para 3 máquinas; un plan de pago de T3 Chat sube ese límite a 10 o 100, y las FAQ añaden: "No queremos cobrar por esto, pero si la factura se vuelve insoportable quizá tengamos que cambiar de rumbo". En el lado de Orca, la documentación no dice cuánto cuesta Orca Cloud ni si el código de su servidor está publicado, y las VM en la nube las factura el proveedor que aportes.

Ambas tienen telemetría, y ambas te dejan apagarla:

| | Orca | T3 Code |
|---|---|---|
| Lo que envía | Versión, sistema operativo, eventos de funciones, tipo de agente, resúmenes de uso de tokens | Proveedor, modelo, esfuerzo de razonamiento, modo de permisos, resultados de turnos, recuentos de tokens, IDs de cuenta con hash |
| Lo que no envía (según ellos) | Contenido de archivos, prompts, respuestas de agentes, salida de la terminal | Prompts, respuestas, contenido de archivos, tokens de autenticación |
| Cómo excluirse | Settings, Privacy, o `ORCA_TELEMETRY_DISABLED=1` o `DO_NOT_TRACK=1` | `T3CODE_TELEMETRY_ENABLED=false` antes de arrancar el servidor |

La telemetría de Orca también se apagó sola en mi máquina, porque había una variable de entorno de CI definida. T3 Code tiene un segundo interruptor: "Publish agent activity" envía los títulos de proyectos e hilos al relay de T3 Connect para las notificaciones en el móvil, y excluirse de la telemetría no lo desactiva ([documentación](https://github.com/pingdotgg/t3code/blob/main/docs/user/telemetry.md)).

## ¿Cuál deberías usar?

![Diagrama de decisión: bots en Slack, Linear o GitHub lleva a Orca; aprobaciones desde el móvil y muchas máquinas lleva a T3 Code; design mode y muchos agentes en una ventana lleva a Orca; cualquier otra cosa cae en T3 Code](@assets/images/26/11/orca-vs-t3-code-decision.webp)

*Tres preguntas que lo zanjan para la mayoría.*

Elige Orca si:

- Quieres Orca Bots: agentes que recogen trabajo de Slack, Linear o GitHub mientras tu escritorio se ocupa de la revisión pesada.
- Ejecutas más de dos o tres agentes a la vez y quieres sus diffs, terminales y navegadores en paralelo.
- Tus agentes van más allá de los nombres de siempre. Cualquier cosa con CLI corre.
- Revisas código generado por IA todo el día. Los comentarios por línea que vuelven directamente al agente valen la instalación.

Elige T3 Code si:

- Empiezas a trabajar en un escritorio y apruebas desde el móvil o un navegador, en más de una máquina.
- Te gusta tener una bandeja de entrada: los hilos se esconden mientras trabajan y vuelven cuando te necesitan.
- Cambias de modelo en mitad de un hilo, o quieres que varios modelos respondan a un mismo prompt a la vez.
- Quieres que scripts y otros agentes arranquen hilos a través de un único CLI y un único servidor MCP.

No chocan entre sí. Orca es una app de escritorio y T3 Code es un servidor en un puerto, así que puedes mantener ambos y dejar el que dejes de abrir. Si prefieres quedarte en la terminal, la [reseña de Herdr](/es/herdr-multiplexor-agentes/) cubre una tercera forma de ejecutar muchos agentes. El [hilo de Hacker News sobre la incorporación de Conductor a Meta](https://news.ycombinator.com/item?id=50369503) tiene a usuarios de Orca y de T3 Code explicando su elección.

Elijas el que elijas, haz esto primero: abre el ajuste de permisos y quítalo de Full access antes del primer prompt. Después ejecuta una tarea desechable en un repositorio que puedas borrar y lee su registro de actividad antes de apuntar la herramienta a algo que importe.

<Accordion label="¿De verdad son gratis Orca y T3 Code?" group="faq" expanded="true">
Sí. Ambos tienen licencia MIT y ninguno revende tokens. Pagas a los proveedores de agentes que ya usas. Los únicos bordes de pago son los planes de T3 Chat, que suben el límite de T3 Connect de 3 máquinas a 10 o 100, y las VM en la nube de Orca, que factura tu propio proveedor.
</Accordion>

<Accordion label="¿Cuál es más seguro por defecto?" group="faq">
Ninguno. Orca rellena por defecto el flag de omisión de permisos de cada CLI compatible (por ejemplo `claude --dangerously-skip-permissions`), y T3 Code arranca los hilos nuevos en Full access. T3 Code es más rápido de dejar seguro: elige Supervised en el compositor y pregunta antes de cada comando y cambio de archivo. En Orca, pon el agente en Manual en Settings, Agents.
</Accordion>

<Accordion label="¿Puedo usar mi suscripción de Claude Code o Codex con ambos?" group="faq">
Sí. Los dos controlan los CLI en los que ya tienes la sesión iniciada. Ejecuta `claude auth login` o `codex login` una vez en la máquina que va a ejecutar los agentes, y cada herramienta lo encuentra. T3 Code busca el CLI en el `PATH` del servidor y te deja definir una ruta de binario por proveedor.
</Accordion>

<Accordion label="¿T3 Code tiene bots como Orca?" group="faq">
No en la misma forma. T3 Code tiene tareas programadas, enlaces a hilos que puedes pegar en Slack y un servidor MCP que permite a agentes externos arrancar hilos y escribir en ellos. No tiene ningún bot integrado para Slack, Linear o GitHub. Es la única función en la que hoy Orca va solo.
</Accordion>

<Accordion label="¿Puedo ejecutar los dos en la misma máquina?" group="faq">
Sí. Orca es una app de escritorio y T3 Code es un servidor ligado a un puerto local, así que no se pisan. Ejecuta `t3 serve --base-dir ~/.t3-second` si quieres un segundo servidor T3 independiente junto a uno que ya tengas. No apuntes dos herramientas al mismo checkout a la vez; dale a cada una su propio worktree.
</Accordion>

<Accordion label="¿Cuál funciona mejor desde un móvil?" group="faq">
Para aprobaciones y respuestas, T3 Code. Sus apps de iOS y Android son clientes completos del servidor, y las notificaciones push llegan cuando un hilo termina, falla o te necesita, siempre que te conectes a través de T3 Connect. Orca Mobile es un complemento beta para un escritorio que sigue corriendo, y funciona por Orca Relay o por tu LAN, sin cuenta en el caso de la LAN.
</Accordion>

<Accordion label="¿Los worktrees protegen el resto de mis archivos?" group="faq">
No. Un worktree da a cada tarea su propio checkout y su propia rama, nada más. En mi ejecución con Orca el agente buscó en todo el sistema de archivos con `find /` sin ningún prompt. Mantén los secretos fuera del alcance del agente, o usa un modo que pregunte primero. La documentación de Orca describe los sandboxes con Docker como una petición de función abierta.
</Accordion>

<Accordion label="¿Cuál debería elegir si solo uso un agente?" group="faq">
T3 Code. Una lista de hilos y un servidor bastan para un solo agente, y las apps de móvil vienen con él. Orca justifica su tamaño de ventana cuando manejas varios agentes, varios repositorios o bots. Si usas un solo agente y quieres la configuración más ligera, la [app de Codex con cualquier modelo](/es/codex-app-cualquier-modelo/) es otra opción.
</Accordion>
