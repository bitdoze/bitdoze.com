## Mejores paneles web de Hermes Agent

Los paneles web se ejecutan en un navegador y son ideales para la gestión remota desde cualquier dispositivo. Puedes autoalojarlos en un VPS, ejecutarlos localmente o tunelizarlos a través de SSH. Las opciones siguientes empiezan con las dos oficiales, el panel de administración y la Webapp, y luego cubren cuatro proyectos comunitarios hasta llegar a un workspace completo estilo IDE.

### Panel web oficial de Hermes

El panel integrado forma parte del paquete principal de Hermes (se incluye desde Hermes Agent v0.16+; v0.23.4 es la release actual a noviembre de 2026). Lánzalo con `hermes dashboard` y obtienes un backend FastAPI/Uvicorn con un frontend React 19 + TypeScript + Tailwind en el puerto 9119.

Lo que obtienes:

- Una página de estado con una vista general en vivo que se actualiza cada 5 segundos
- Una pestaña Chat que incrusta la TUI con soporte PTY a través de WebSocket, así tienes la experiencia de terminal completa en el navegador
- Un editor de configuración basado en formularios que cubre los más de 150 campos de `config.yaml`
- Exploración de sesiones con búsqueda FTS5, exportación y limpieza
- Logs del agente, del gateway y de errores con filtros por nivel y componente, y un tail en vivo
- Analíticas de tokens a 7, 30 o 90 días, con seguimiento de costes y desglose por modelo
- Una página de cron para programar, pausar, reanudar, ejecutar y editar tareas en todos los perfiles
- Páginas de Skills y MCP para explorar, buscar y activar skills, y para añadir, probar, habilitar o deshabilitar servidores MCP
- Creación, cambio y clonación de perfiles, además de páginas para API keys, webhooks, emparejamiento y canales
- Una página System con métricas del host, un indicador de actualizaciones, arranque/parada/reinicio del gateway y accesos directos a `doctor`, auditoría de seguridad, copia de seguridad y restauración

Las opciones de autenticación son OAuth vía Nous Portal, usuario/contraseña y OIDC autoalojado; un bind que no sea de loopback se niega a arrancar sin una de ellas (detalles en la sección de seguridad de abajo). Incluye ocho temas integrados, y puedes añadir tu propio tema o plugin sin hacer un fork.

Requisitos previos: instala primero los extras web y PTY.

```bash
pip install -e ".[web,pty]"
```

El panel oficial tiene una API REST completa, así que puedes programar por script cualquier operación de gestión. Para la configuración de seguridad completa, incluidos túneles SSH y proxy inverso, consulta nuestra [guía de configuración del panel de Hermes Agent](/es/guia-panel-hermes/).

**Ideal para:** gestión autoalojada con la configuración más sencilla y sin dependencias extra.

**Contrapartidas:** un bind que no es de loopback se niega a arrancar sin un proveedor de autenticación.

#### Temas y plugins

El panel incluye ocho temas integrados: Hermes Teal, Hermes Teal Large, Nous Blue, Midnight, Ember, Mono, Cyberpunk y Rosé. No necesitas hacer un fork de nada para ir más allá. La página [Extending the Dashboard](https://hermes-agent.nousresearch.com/docs/user-guide/features/extending-the-dashboard) documenta tres capas que se añaden directamente:

- Un tema es un archivo YAML en `~/.hermes/dashboard-themes/`. Todos los campos son opcionales, así que un tema puede ser tan pequeño como dos colores. Puede definir paleta, tipografía, diseño (radio, densidad y las variantes `standard`, `cockpit` y `tiled`), recursos de imagen, el cromo de cada componente y CSS en bruto.
- Un plugin de UI es un directorio con un `manifest.json` y un bundle de JavaScript precompilado en `~/.hermes/plugins/<name>/dashboard/`. Puede añadir una pestaña, reemplazar una página integrada, inyectar widgets en una página integrada a través de slots o rellenar slots del shell. Llama al SDK en `window.__HERMES_PLUGIN_SDK__` en lugar de empaquetar React.
- Un plugin de backend es un archivo Python con un router FastAPI. Sus rutas se montan bajo `/api/plugins/<name>/`.

Los tres se cargan en tiempo de ejecución, sin clonar el repositorio ni compilar el panel. La app de escritorio tiene un SDK de plugins aparte (`@hermes/plugin-sdk`), así que un plugin del panel no se traslada a Desktop.

### Webapp oficial: el workspace de escritorio en un navegador

El gateway puede servir el workspace de escritorio a un navegador normal. La documentación es directa sobre lo que es: esto no es el panel web. Obtienes la UI de escritorio centrada en el chat con sesiones, perfiles, Capabilities, Messaging, Artifacts, tareas programadas, el árbol de archivos del host, revisión de Git, vistas previas y el raíl de terminal. Las funciones solo nativas se quedan en la app de escritorio: atajos globales, overlays siempre visibles, inspección de ventanas del sistema operativo, lanzamiento de terminal externa y el actualizador.

Actívala una vez:

```bash
hermes config set webapp.enabled true
hermes gateway restart
hermes webapp            # builds the bundle when out of date, opens a one-use sign-in link
hermes webapp --status   # is the gateway serving it, and on which address
```

Se sirve en `http://127.0.0.1:9120`. El enlace de `hermes webapp` funciona una vez, durante 60 segundos, y el navegador lo canjea por un inicio de sesión que sobrevive a recargas y reinicios del gateway. Una pestaña nueva o una URL simple muestra instrucciones en lugar de acceso, así que ejecuta `hermes webapp` de nuevo para obtener un enlace nuevo. Los chats se ejecutan en el gateway, el mismo proceso que sirve el CLI, la app de escritorio y la mensajería.

Se diferencia de `hermes dashboard` en su propósito. El panel en el puerto 9119 es el panel de administración (Status, Config, API Keys, Sessions, Logs, Analytics, Cron, Skills, MCP, System), y su pestaña Chat opcional incrusta la TUI a través de un pseudoterminal. La Webapp en el puerto 9120 es donde trabajas, con las mismas conversaciones y paneles que la app de escritorio más un raíl de terminal que ejecuta la shell interactiva del host. Usa el panel para administrar y la Webapp para chatear.

Desde otra máquina, la Webapp está detrás de la misma puerta de inicio de sesión del panel. Define `webapp.host` como `0.0.0.0` o como una dirección IP de la máquina (una dirección de LAN o Tailscale), o mantén loopback y define `webapp.public_url` tras un proxy inverso. En la app de escritorio, Settings, Web Access la activa para otros dispositivos tras iniciar sesión con tu cuenta de Nous. Trata la URL como acceso a la shell y prefiere un túnel SSH, Tailscale u otra VPN. El HTTP simple en otro host también pierde el micrófono, el pegado desde el portapapeles y las notificaciones del sistema, así que usa HTTPS o un túnel.

**Ideal para:** el workspace de escritorio en un navegador en un teléfono u otro ordenador, sin instalar nada. Es gratis.

**Contrapartidas:** un usuario con sesión iniciada en la Webapp puede ejecutar comandos arbitrarios como la cuenta del sistema operativo que ejecuta Hermes, así que trata la URL como acceso a la shell. La documentación no dice si la Webapp incluye el panel Bots de Bot Mode, así que por ahora trata la lista de bots como una función de la app de escritorio.

### Hermes WebUI de nesquena

<Button text="Repositorio en GitHub" link="https://github.com/nesquena/hermes-webui" variant="solid" color="blue" size="md" />

El panel comunitario más popular, con 19.6K estrellas en GitHub (noviembre de 2026), MIT. Su rasgo distintivo: cero dependencias. Sin Node.js, sin bundler, sin framework. Solo el servidor HTTP de la biblioteca estándar de Python y JavaScript puro. Se mantiene activamente. El último push llegó el 2026-11-27.

<ListCheck>
<ul>
<li>Chat con streaming vía SSE y soporte de modelos multiproveedor</li>
<li>Gestión de sesiones: fijar, archivar, proyectos, etiquetas, búsqueda, exportar/importar</li>
<li>Diseño responsive para móvil (sidebar tipo hamburguesa, áreas táctiles de 44px)</li>
<li>Entrada de voz vía Web Speech API</li>
<li>Explorador de archivos del workspace con detección de git</li>
<li>Tablero Kanban para gestión de tareas</li>
<li>Puente de sesiones CLI (importa sesiones desde la terminal)</li>
<li>Más de 6 temas con sistema de skins</li>
<li>Sistema de extensiones para inyectar scripts y estilos personalizados</li>
<li>Autenticación por contraseña, WebAuthn/passkeys y OIDC</li>
<li>Soporte de Docker y Nix</li>
<li>~11.500 tests en ~1.150 archivos</li>
</ul>
</ListCheck>

Comandos de lanzamiento:

```bash
# Clona primero y luego ejecuta el bootstrap (recomendado)
git clone https://github.com/nesquena/hermes-webui.git
cd hermes-webui
python3 bootstrap.py

# O usa el script de shell tras clonar
./start.sh

# Docker
docker pull ghcr.io/nesquena/hermes-webui:latest
docker run -d -p 8787:8787 -v ~/.hermes:/home/hermeswebui/.hermes \
  ghcr.io/nesquena/hermes-webui:latest
# Abre http://localhost:8787
```

El diseño responsive lo convierte en el mejor panel web para acceder desde el teléfono: el sidebar tipo hamburguesa y las áreas táctiles están diseñados para ello. También tiene un tablero Kanban integrado (consulta la [guía de configuración de Hermes Kanban](/es/guia-kanban-hermes/) para más detalles) y capacidades de búsqueda web que combinan bien con [la búsqueda gratuita de TinyFish para agentes de codificación IA](/es/tinyfish-busqueda-web-gratis-agentes/).

Si quieres ampliar Hermes con búsqueda web y obtención de páginas para tu agente, la [API de búsqueda web de TinyFish](https://go.bitdoze.com/tinyfish) es un complemento sencillo. Le da a tu agente 30 búsquedas/min y 150 fetch/min gratis (el fetch es gratis hasta 1.000 URLs al día), lo que funciona junto con la extracción de páginas propia del WebUI.

**Ideal para:** usuarios que quieren una interfaz web ligera y sin dependencias que funcione en navegadores móviles sin configuración adicional.

### Hermes Workspace

<Button text="Repositorio en GitHub" link="https://github.com/outsourc-e/hermes-workspace" variant="solid" color="green" size="md" />

Hermes Workspace es la opción estilo IDE: chat, terminal integrada, explorador de archivos, visor de memoria, hub de skills, gestión de MCP y orquestación multi-agente en una sola interfaz React/TypeScript. 6.8K estrellas (noviembre de 2026), licencia MIT, último push el 2026-11-05.

Las funciones Conductor / Swarm son lo que lo diferencia. Describes una tarea compleja y el workspace la divide en subtareas, despacha agentes especializados y fusiona los resultados. Bot Mode en la app de escritorio oficial y los flujos de trabajo visuales de Ekko Studio ahora cubren parte del mismo terreno (chats grupales, traspasos entre agentes), así que compara los tres antes de decidirte por uno.

<ListCheck>
<ul>
<li>Terminal web integrada (xterm.js): shell completo sin una sesión SSH aparte</li>
<li>Explorador de archivos/workspace con soporte de edición</li>
<li>Descomposición de tareas multi-agente con Conductor / Swarm</li>
<li>Hub de skills y catálogo/marketplace completo de MCP</li>
<li>PWA móvil + acceso remoto compatible con Tailscale</li>
<li>Múltiples temas (Hermes, Nous, Bronze, Slate, Mono)</li>
</ul>
</ListCheck>

```bash
# Docker Compose (recomendado)
git clone https://github.com/outsourc-e/hermes-workspace.git
cd hermes-workspace
docker compose up -d
# Workspace en el puerto 3000, gateway de Hermes en 8642
```

**Ideal para:** usuarios que quieren una consola completa de operaciones del agente (terminal + archivos + multi-agente), no solo chat.

### Ekko Studio de EKKOLearnAI

<Button text="Repositorio en GitHub" link="https://github.com/EKKOLearnAI/ekko-studio" variant="solid" color="purple" size="md" />

Ekko Studio es el nuevo nombre de Hermes Studio. El paquete antiguo `hermes-web-ui` sigue recibiendo las mismas releases. 11.8K estrellas (noviembre de 2026), último push el 2026-11-26. Sigue siendo la opción comunitaria con más funciones.

Está construido con Vue 3 + TypeScript + Vite + Naive UI, con un backend Koa y Socket.IO para chat en tiempo real. También soporta su propio Ekko Agent y 14 integraciones de agentes de código, que es una de las razones por las que superó el nombre limitado a Hermes.

- Una terminal web construida sobre node-pty y xterm.js

- Un explorador de archivos que alcanza backends locales, Docker, SSH y Singularity
- Gestión de modelos con descubrimiento de proveedores
- Clonación, exportación e importación de perfiles
- Analíticas de uso de tokens, costes y distribución por modelo
- Un tablero Kanban consciente del perfil (ver la [guía de configuración de Hermes Kanban](/es/guia-kanban-hermes/))

### Hermes Control Interface (HCI)

<Button text="Repositorio en GitHub" link="https://github.com/xaspx/hermes-control-interface" variant="solid" color="green" size="md" />

HCI es el panel de administración centrado en la seguridad. 903 estrellas (noviembre de 2026), MIT, JS puro + Vite + Express. Prioriza RBAC, CSRF, rate limiting y auditabilidad por encima del acabado visual.

Lo que obtienes:

- Puerta de acceso con contraseña con hashing bcrypt, CSRF en endpoints que modifican datos, rate limiting
- ~20 permisos repartidos en roles admin / viewer / personalizados
- Terminal en el navegador (xterm.js), explorador de archivos, sesiones, cron, métricas del sistema
- Monitor de enjambre multi-agente / Office con vistas de tareas tipo kanban
- PWA instalable en la pantalla de inicio

```bash
git clone https://github.com/xaspx/hermes-control-interface.git
cd hermes-control-interface
cp .env.example .env   # set HERMES_CONTROL_PASSWORD + HERMES_CONTROL_SECRET
npm install && npm run build
node server.js         # http://localhost:10274
```

Requiere Node.js 20+ y el CLI `hermes` en el PATH de la misma máquina.

**Ideal para:** equipos que necesitan control de acceso granular y una superficie de administración endurecida, más que una interfaz de chat bonita.

**Contrapartidas:** el último push llegó el 2026-06-28, cinco meses antes de la comprobación de noviembre de 2026, así que reserva tiempo para mantenerlo tú mismo.

### Panel Scarf: nativo de macOS

<Button text="Repositorio en GitHub" link="https://github.com/awizemann/scarf" variant="solid" color="purple" size="md" />

Una app nativa de macOS (Swift/SwiftUI) que lee el SQLite de Hermes directamente para datos en tiempo real. 923 estrellas (noviembre de 2026), licencia MIT, último push el 2026-11-26. Las releases se distribuyen como binarios universales firmados con Developer ID y notarizados (Apple Silicon e Intel) desde [GitHub Releases](https://github.com/awizemann/scarf/releases), porque Scarf necesita acceso sin sandbox a `~/.hermes/` y al binario `hermes`. Las actualizaciones llegan a través de Sparkle.

Sus ventanas cubren un panel, analíticas, un explorador de sesiones, un feed de actividad, chat en vivo (Rich ACP o terminal), un editor de memoria, un explorador de skills, una GUI de plataformas, personalidades, un gestor de cron, monitorización de salud, control del gateway y paneles de proyecto personalizados que los agentes pueden autogenerar mediante widgets JSON.

El soporte multiventana permite monitorizar varios servidores Hermes a la vez (local + remoto por SSH). Un icono de estado en la barra de menús mantiene la salud del agente siempre visible. Scarf para macOS también recopila estadísticas de uso: nombres de eventos y un identificador de instalación con hash, nunca contenido, rutas ni nombres de host. ScarfGo es el compañero para iOS (cubierto en la sección de móvil).

#### Bot Mode: una lista de bots

El gran cambio de Hermes Desktop es Bot Mode. Se incluye en la app de escritorio y está activado por defecto (comprobado con v0.23.4). Una pestaña Bots está junto a Sessions en el sidebar izquierdo, y un mosaico Routines se acopla junto a la conversación mientras la pestaña Bots está activa.

Un Bot es un perfil de Hermes con su propio rol, modelo, memoria, skills y avatar. Su configuración, memoria, skills, credenciales e historial de chat viven bajo `~/.hermes/profiles/<name>/`. Bot Mode es una interfaz sobre esa primitiva, no un segundo runtime. `hermes -p <bot> chat` abre el mismo agente desde una shell, y una rutina es una tarea cron normal llamada `[bot:<name>] <routine>` que aparece en `hermes cron list`. Abrir un Bot local ejecuta `hermes gateway ensure --json` para su perfil, que se conecta al gateway en ejecución o inicia uno. Cerrar Desktop no detiene el gateway; `hermes gateway stop` sí.

Lo que el panel Bots añade sobre los perfiles simples:

- Un Bot Chat permanente por Bot. Haz clic en el Bot y vuelves a la misma conversación, y `/new` dentro de un Bot Chat se redirige a `/compact` para que el historial se conserve.
- Una lista con avatar, último mensaje y estado de no leído, además de secciones (carpetas como Clients o Team), Hide Bot, Duplicate y Delete Profile (permanente). El estado de sección y de oculto se guarda en los metadatos del perfil del Bot, así que acompañan al Bot a todos los escritorios de ese backend.
- New Agent: un Name, Title y Description, y el Bot se presenta en su Bot Chat en cuestión de segundos. El desplegable Advanced clona un perfil existente o empieza de cero, fija un modelo y un proveedor por Bot, define un `SOUL.md` personalizado y habilita skills, toolsets y servidores MCP por Bot.
- Routines: tareas recurrentes asociadas al Bot que las ejecuta, con un selector de horario y un campo de horario en bruto. Las ejecuciones caen en el historial de chat del propio Bot.
- Chats grupales de 2 a 6 Bots. Tu mensaje dispara hasta tres rondas en serie de turnos de los miembros, con un límite de 10 mensajes por envío. Los Bots se involucran entre sí con `@name` y te escalan las decisiones de criterio con `@user`, lo que pone una insignia de "te necesita" en la sala.
- Mensajes entre Bots. Escribe `@researcher have a look at this` en cualquier chat y el Bot activo redacta su propio mensaje y lo envía con `message_agent`. La entrega no es una interrupción en vivo. El Bot receptor recoge el mensaje en su siguiente turno, y un protector contra bucles (`gateway.bot_loop_guard.max_hops`, por defecto 4) evita que dos Bots se mantengan ocupados entre sí para siempre.

Bot Mode funciona contra un backend remoto. Los chats grupales propiedad del gateway siguen funcionando con Desktop cerrado, y un chat grupal puede abarcar varias máquinas, con Bots de otros ordenadores uniéndose a través de sus propios gateways. Para desactivar Bot Mode, usa Capabilities, Plugins, Bots. No hace falta reiniciar, y los perfiles, sesiones y cron jobs quedan intactos. No instales el plugin independiente antiguo. [NousResearch/Hermes-Bot-Mode](https://github.com/NousResearch/Hermes-Bot-Mode) está archivado (último push el 2026-08-17), y las compilaciones actuales de Desktop tienen Bot Mode integrado.

Crear Bots, rutinas y chats grupales lleva tiempo, así que tiene su propia sección en [nuestra guía de configuración de Hermes Agent](/es/guia-configuracion-hermes-agent/).

#### Conectar Desktop a un backend remoto

Desktop puede controlar un backend de Hermes que se ejecuta en otra máquina: un VPS, un servidor en casa, un Mini detrás de Tailscale. No hay una descarga solo remota. Instala el paquete y luego abre Settings, Gateways. El modo de conexión ofrece tres alternativas al gateway local:

- Remote gateway: la URL de un backend `hermes serve` que ejecutas tú mismo (puerto por defecto 9119), y luego inicia sesión
- Hermes Cloud: inicia sesión una vez y elige un agente de tu cuenta
- SSH: un host SSH

El backend remoto ya debe estar ejecutando `hermes serve`; Desktop se conecta a él y no lo inicia. Un bind que no es de loopback activa la puerta de autenticación del panel descrita en la sección de seguridad de abajo. Usa OAuth a través de Nous Portal para cualquier cosa accesible más allá de tu propia máquina, y usuario/contraseña solo en una LAN o VPN de confianza. En Tailscale, enlaza el backend a la IP de Tailscale de la máquina y usa `http://<tailscale-ip>:9119` como Remote URL.

**Ideal para:** usuarios que quieren la experiencia de escritorio oficial, mantenida por Nous Research, y cualquiera que quiera Bot Mode, ya que el panel Bots forma parte de esta app.

**Contrapartidas:** no hay bundles para Mac Intel ni para macOS 12 o anterior; esas máquinas usan el instalador del CLI.

## Acceso móvil vía canales de mensajería

La forma más sencilla de tener Hermes en tu teléfono: usar el gateway de mensajería integrado. Sin apps extra que instalar; solo chatea con tu agente a través de Telegram, Discord, WhatsApp, Signal o Slack.

<Notice type="info" title="El camino más rápido al acceso móvil">
Telegram es la forma más rápida de tener Hermes en tu teléfono. La configuración lleva menos de 5 minutos y obtienes sincronización entre dispositivos, notas de voz y la misma app de chat que probablemente ya tienes abierta.
</Notice>

| Canal | Configuración | Ventajas | Desventajas |
|---|---|---|---|
| Telegram | Baja | El camino más rápido, notas de voz, sincronización entre dispositivos | Vista de una sola sesión, retardo en la cola de mensajes |
| Discord | Baja | Reacciones, hilos, un canal por tema | Más configuración que Telegram |
| WhatsApp | Media | Todo el mundo lo tiene | Requiere número de teléfono y emparejamiento |
| Signal | Media | Centrada en la privacidad | Menos funciones |
| Slack | Media | Amigable para equipos, canales | Requiere workspace |

La configuración es sencilla:

```bash
# Configura el gateway de mensajería
hermes gateway setup
# Sigue las indicaciones para tu plataforma (p. ej., el token del bot de Telegram)

# Inicia el gateway
hermes gateway start
```

**Limitaciones de Telegram** que conviene conocer (según el feedback de la comunidad): solo tienes una vista de sesión única, hay retardo en la cola de mensajes, no se muestra el conteo de tokens ni la información del modelo, y los reinicios de la ventana de contexto no se comunican. Para uso casual está genial. Para trabajo de desarrollo intensivo, usa un panel o una app de escritorio en condiciones.

## ¿Qué interfaz de Hermes Agent deberías elegir?

Para Bot Mode, elige el Hermes Desktop oficial; para una interfaz web con recursos mínimos, elige Hermes WebUI. En un teléfono sin instalar nada, usa el gateway de Telegram o Discord; en Android con un agente en el dispositivo, usa Hermes Agent Android; y en iOS para chatear, usa Hermex o ScarfGo.

| Tu situación | Herramienta recomendada | Por qué |
|---|---|---|
| Quieres Bot Mode: una lista de bots, rutinas, chats grupales | Hermes Desktop oficial | Bot Mode está integrado y activado por defecto; ver la [guía de configuración](/es/guia-configuracion-hermes-agent/) |
| Usuario de macOS que quiere una app nativa | Scarf | Swift nativo, lee SQLite directamente, icono en la barra de menús |
| Usuario de escritorio multiplataforma | Hermes Desktop oficial o Hermes One | La app oficial sigue las releases y se conecta a un backend remoto; Hermes One añade una instalación guiada y una interfaz 3D |
| Hermes en un VPS, interfaz en tu portátil | Desktop oficial con Remote gateway o SSH | Settings, Gateways se conecta a un backend `hermes serve` en el puerto 9119 |
| UI de escritorio en un teléfono o un portátil de trabajo, sin instalar nada | Webapp oficial | Puerto 9120, servida por el gateway, misma puerta de inicio de sesión que el panel |
| Prioridad al navegador, autoalojado, simple | Panel oficial | Integrado, `hermes dashboard` en el puerto 9119 |
| Prioridad al navegador, recursos mínimos | Hermes WebUI | Sin paso de compilación, JS puro, responsive para móvil |
| Prioridad al navegador, máximas funciones | Ekko Studio | Chat grupal, flujos de trabajo visuales, 10 configuraciones de plataforma |

## Consideraciones de seguridad para el acceso remoto

Cualquier panel o app móvil expuesta a la red necesita autenticación. Esto no es negociable: un panel de Hermes sin autenticación da a cualquiera control total sobre tu agente, tus API keys y, potencialmente, tu servidor.

<Notice type="error" title="Nunca expongas sin autenticación">
Desde el endurecimiento de junio de 2026, `hermes dashboard` enlazado a una dirección que no es de loopback se niega a arrancar sin un proveedor de autenticación, y `--insecure` se acepta pero se ignora. Las compilaciones antiguas arrancaban `hermes dashboard --host 0.0.0.0` sin ninguna autenticación, lo que era una puerta trasera abierta. Actualiza cualquier instalación anterior a v0.23.2 (esa release también corrige CVE-2026-130164), y acompaña siempre los paneles expuestos al público con autenticación y HTTPS.
</Notice>

### La puerta de autenticación del panel

La puerta se activa cuando el host de enlace es cualquier cosa distinta de `127.0.0.1`, `::1` o `localhost`. Se incluyen tres proveedores: usuario/contraseña (para una red de confianza o una VPN, nunca para internet público), OAuth a través de Nous Portal (el que hay que usar para despliegues accesibles desde internet y para una conexión remota de Hermes Desktop) y OIDC autoalojado. Falla en cerrado. Con la puerta activada y ningún proveedor registrado, `hermes dashboard` se niega a enlazar. Cuando lo ejecutas de forma interactiva sin proveedor, ofrece configurar uno en el momento. Docker y otras ejecuciones no interactivas omiten el prompt y terminan con el error de fallo en cerrado. Para ver en qué punto está un backend, comprueba su endpoint de estado desde la propia máquina:

```bash
curl -s http://127.0.0.1:9119/api/status | jq '.auth_required, .auth_providers'
```

`auth_required: true` significa que la puerta está activada.

### Túneles SSH (lo más fácil)

El enfoque seguro más simple es tunelizar el puerto del panel a través de SSH. El backend se queda en loopback, así que la puerta nunca se activa y no se expone ningún puerto:

```bash
# Túnel hacia la WebUI (puerto 8787)
ssh -N -L 8787:127.0.0.1:8787 user@your-server

# Túnel hacia el panel oficial (puerto 9119)
ssh -L 9119:localhost:9119 user@your-vps

# Túnel hacia la Webapp (puerto 9120) para el workspace de escritorio en un navegador
ssh -L 9120:127.0.0.1:9120 user@your-vps

# Luego abre http://localhost:8787 o http://localhost:9119 en local
```

### Tailscale (lo más seguro para uso habitual)

Instala Tailscale en tu servidor y en tu teléfono o portátil, y accede al panel a través de su IP de Tailscale. No se expone ningún puerto a internet público. El enlace no es de loopback, así que la puerta de autenticación se activa igualmente y el proveedor va primero. La documentación de Hermes llama opción limpia a enlazar a la IP de Tailscale de la máquina para un backend `hermes serve` al que se conecta Desktop. Ares tiene soporte de Tailscale integrado, y la guía de configuración de Hermex recomienda Tailscale Serve, que pone el panel detrás de un nombre HTTPS en tu tailnet.

### Protección con contraseña

Define el usuario y la contraseña con `hermes dashboard password`. Escribe `username`, un `password_hash` con scrypt y (si falta) un `secret` de firma bajo `dashboard.basic_auth` en `config.yaml`. Nunca almacena ni imprime la contraseña y nunca la acepta como argumento. La pide en la terminal, o lee la primera línea de la entrada estándar con `--password-stdin`, así que funciona en scripts, contenedores y configuraciones de servicios.

```bash
# La contraseña viene de un archivo de secretos, nunca de la línea de comandos
hermes dashboard password --username admin --password-stdin < /run/secrets/dashboard_password

# Ahora el bind que no es de loopback puede arrancar
hermes dashboard --host 0.0.0.0 --no-open
```

Cambiar el usuario o la contraseña termina todas las sesiones. `/auth/password-login` tiene límite de frecuencia por IP de cliente (10 intentos por minuto, luego HTTP 429). Usuario/contraseña es para una LAN o VPN de confianza. Para cualquier cosa en internet público, registra la instalación con tu cuenta de Nous Portal: `hermes dashboard register` escribe `HERMES_DASHBOARD_OAUTH_CLIENT_ID` en `~/.hermes/.env`.

### Tras un proxy inverso

Mantén el backend en loopback y deja que Caddy o Nginx terminen el TLS:

```bash
hermes dashboard --host 127.0.0.1 --port 9119 --no-open
```

Luego define `dashboard.public_url` (o `HERMES_DASHBOARD_PUBLIC_URL`) con la URL pública completa, y añade la IP exacta del proxy a `dashboard.trusted_proxies` cuando el terminador TLS se conecta desde otro contenedor u host:

```yaml
dashboard:
  public_url: "https://dashboard.example.com/hermes"
  trusted_proxies: ["172.20.0.5"]
```

Declarar una `public_url` que no es de loopback activa siempre la puerta de autenticación, aunque el backend enlace a loopback, así que configura primero un proveedor o Hermes falla en cerrado al arrancar. `0.0.0.0/0` y `::/0` se rechazan como proxies de confianza, y con razón: con un rango tan amplio, cualquier contenedor de una red de confianza puede suministrar cabeceras de reenvío. Usa la IP exacta del proxy o un CIDR acotado. El nombre de host de `public_url` también se acepta como valor de Host HTTP y de Origin WebSocket, y los comodines no. Esa es la protección contra DNS rebinding.

### Desktop y la Webapp contra un backend remoto

Los mismos proveedores protegen las dos superficies más nuevas. Hermes Desktop se conecta a un backend `hermes serve` desde Settings, Gateways: Remote gateway (la URL del backend, puerto por defecto 9119), Hermes Cloud (inicia sesión y elige un agente) o SSH. La app detecta qué proveedor anuncia el backend y muestra un formulario Sign in o Sign in with Nous Research. La Webapp usa el inicio de sesión del panel: define `webapp.host` con una dirección de LAN o Tailscale, o `webapp.public_url` tras un proxy, y el gateway lo exige.

La documentación detalla el radio del daño. Un usuario con sesión iniciada en la Webapp puede ejecutar comandos arbitrarios como la cuenta del sistema operativo que ejecuta Hermes. Las credenciales que Desktop guarda para sus gateways viven en `gateway-connections.json` y `gateway-connection-tokens.json` en tu home de Hermes, solo para el propietario (0600), como texto plano, porque el servidor de la Webapp tiene que leerlas. Prefiere un túnel SSH, Tailscale u otra VPN antes que abrir cualquiera de los dos puertos.

## Preguntas frecuentes

<Accordion label="¿Existe una app móvil oficial de Hermes Agent?" group="faq" expanded="true">
No. Nous Research no tiene una app móvil oficial. Todas las apps móviles vienen de la comunidad. Las superficies oficiales son el CLI, la app de escritorio (`hermes desktop`), su versión en navegador, la Webapp (`hermes webapp`) y el panel de administración (`hermes dashboard`). Un navegador de teléfono también puede abrir la Webapp oficial. Todas las apps de Android e iOS cubiertas arriba son proyectos de terceros.
</Accordion>

<Accordion label="¿Puedo ejecutar Hermes Agent en mi teléfono?" group="faq">
En Android, sí. Hermes Agent Android (Google Play) ejecuta el runtime completo de Hermes directamente en el dispositivo. Necesitas tu propia API key y unos 200MB de almacenamiento. En iOS, no. El sandboxing de iOS impide ejecutar Hermes directamente. Todas las apps de iOS se conectan a una instancia remota de Hermes vía SSH o API.
</Accordion>

<Accordion label="¿Cuál es el mejor panel gratuito de Hermes?" group="faq">
El panel oficial integrado (`hermes dashboard`) y Hermes WebUI de nesquena son gratuitos y buenos. El panel oficial es el más sencillo de configurar, ya que viene incluido con Hermes, y la Webapp oficial (`hermes webapp`) también es gratis si lo que quieres sobre todo es chatear en lugar de administrar. Hermes WebUI es más ligero en recursos (sin paso de compilación, sin framework) y tiene mejor respuesta en móvil. Si además necesitas una API key gratuita, mira cómo configurar [Hermes Agent con modelos gratuitos en Nous Portal](/es/hermes-agent-mimo-v2-pro/).
</Accordion>

<Accordion label="¿Cómo accedo a mi panel de Hermes de forma remota?" group="faq">
Cuatro rutas, más o menos de la más fácil a la más laboriosa: (1) Túnel SSH: `ssh -L 9119:localhost:9119 user@your-vps`, y luego abre localhost:9119; sin puerta de autenticación, ya que el backend se queda en loopback. (2) Tailscale: instálalo en ambos dispositivos y usa la IP de Tailscale; la puerta está activada, así que define antes una contraseña. (3) La Webapp oficial: `hermes webapp` sirve el workspace de escritorio en el puerto 9120, y Settings, Web Access en la app de escritorio la activa para otros dispositivos tras iniciar sesión con tu cuenta de Nous. (4) Proxy inverso con HTTPS: mantén el backend en `127.0.0.1`, define `dashboard.public_url` y registra OAuth con `hermes dashboard register` para cualquier cosa pública. El flag `--insecure` ya no hace nada, así que no hay forma de saltarse la puerta.
</Accordion>

<Accordion label="¿Qué panel de Hermes usa menos recursos?" group="faq">
Hermes WebUI de nesquena. Usa el servidor HTTP de la biblioteca estándar de Python y JavaScript puro, sin Node.js, sin bundler y sin framework. El arranque es rápido y el uso de memoria es mínimo comparado con las alternativas basadas en React/Vue.
</Accordion>

<Accordion label="¿Puedo usar varios paneles al mismo tiempo?" group="faq">
Sí. Los paneles son aplicaciones web independientes que se ejecutan en puertos diferentes. Puedes ejecutar el panel oficial en el puerto 9119, la Webapp en 9120, Hermes WebUI en 8787, Ekko Studio en 8648, Hermes Workspace en 3000 y HCI en 10274 simultáneamente. Todos leen del mismo directorio de datos de Hermes, así que las sesiones, la configuración y los perfiles se comparten.
</Accordion>

<Accordion label="¿Es un problema la licencia BSL-1.1 de Ekko Studio (antes Hermes Studio)?" group="faq">
Para uso personal, no. Para uso comercial, revisa los términos de la licencia. La BSL-1.1 de Ekko Studio (Business Source License) concede solo uso no comercial; venderlo, alojarlo como SaaS o integrarlo en un producto comercial necesita una licencia comercial aparte. El archivo de licencia indica el 2029-05-10 como fecha de cambio, cuando se convierte a Apache 2.0. Si necesitas un panel con licencia MIT completa para uso comercial, elige el panel oficial o Hermes WebUI.
</Accordion>

<Accordion label="¿Bot Mode necesita la app Hermes Desktop?" group="faq">
Para la interfaz de la lista, sí. El panel Bots, el editor de rutinas y la ventana de chat grupal viven en la app de escritorio, donde Bot Mode está activado por defecto. Los Bots en sí no la necesitan: un Bot es un perfil de Hermes, así que `hermes -p <bot> chat` abre el mismo agente desde una shell y `hermes cron list` muestra sus rutinas como tareas llamadas `[bot:<name>]`. En un VPS sin interfaz gráfica, instala Desktop en tu portátil y conéctalo al VPS a través de Settings, Gateways. Los mensajes entre Bots solo se ejecutan en los Bot Chats que configura el panel Bots, así que esa parte depende de Desktop a menos que marques la instalación a mano. Los chats grupales propiedad de un gateway siguen funcionando con Desktop cerrado. El recorrido está en la [guía de configuración de Hermes Agent](/es/guia-configuracion-hermes-agent/).
</Accordion>

<Accordion label="¿Cuál es la diferencia entre la Webapp y el panel?" group="faq">
`hermes dashboard` en el puerto 9119 es el panel de administración: Status, Config, API Keys, Sessions, Logs, Analytics, Cron, Skills, MCP y System, con una pestaña Chat opcional que incrusta la TUI. La Webapp en el puerto 9120 es el workspace de escritorio en un navegador, servido por el gateway: la misma UI centrada en el chat, árbol de archivos, revisión de Git y raíl de terminal que la app de escritorio. Actívala con `hermes config set webapp.enabled true`, `hermes gateway restart` y luego `hermes webapp`. Usa el panel para administrar y la Webapp para trabajar.
</Accordion>

## Conclusión

No hay una única interfaz "mejor" de Hermes Agent. La correcta depende de tu dispositivo y de tu flujo de trabajo. La versión corta, con cifras de estrellas de noviembre de 2026:

<ListCheck>
<ul>
<li>Bot Mode es la razón para elegir la app de escritorio oficial: una lista de bots con su propio modelo, memoria y rutinas, más chats grupales y mensajes entre bots (comprobado con v0.23.4)</li>
<li>El panel oficial es el punto de partida más sencillo para administrar: gratis, integrado, `hermes dashboard` en el puerto 9119</li>
<li>La Webapp oficial te da el workspace de escritorio en cualquier navegador en el puerto 9120, tras la misma puerta de inicio de sesión</li>
<li>Hermes WebUI es la opción web más ligera, con un diseño pensado para navegadores de teléfono (19.6K estrellas)</li>
<li>Ekko Studio, antes Hermes Studio, concentra más funciones comunitarias: chat grupal, flujos de trabajo visuales y 10 canales de plataforma (11.8K estrellas)</li>
<li>Hermes Workspace es el mejor workspace completo (terminal + archivos + Conductor/Swarm, 6.8K estrellas)</li>
<li>Hermes Control Interface es la elección cuando más importan RBAC y una administración endurecida, pero no tiene pushes desde junio de 2026</li>
<li>Para macOS, Scarf es la app nativa de macOS; Hermes One es la opción comunitaria para escritorio multiplataforma (14.6K estrellas)</li>
<li>Para Android, Hermes Agent Android te da el runtime completo en el dispositivo; Ares (antes Hermes Android) es el cliente para servidores remotos</li>
<li>Para iOS, Onepilot es lo más cercano a una cabina de desarrollo completa; Hermex y ScarfGo son los clientes de chat nativos</li>
<li>El gateway de Telegram es el camino más rápido al acceso móvil, sin necesidad de ninguna app extra</li>
<li>La seguridad no es opcional: la puerta de autenticación falla en cerrado, así que acompaña el acceso remoto con un proveedor, un túnel SSH o Tailscale</li>
</ul>
</ListCheck>

Elige una opción, configúrala e itera. La mayoría de estas herramientas son gratuitas o tienen niveles gratuitos, así que experimentar no cuesta nada.
