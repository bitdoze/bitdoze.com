Tengo un Ubuntu 22.04 en un [VPS de Hetzner](https://go.bitdoze.com/hetzner) y en un [VPS de Hostinger](https://go.bitdoze.com/hostinger-vps), y actualicé los paquetes a la última versión. Durante la actualización, el kernel de Ubuntu también se actualizó a la última versión, que era: **_5.15.0-71-generic_**

_Los precios de los VPS se dispararon en 2026 — si estás reconsiderando un servidor alquilado, echa un vistazo a [qué cambió y cuándo gana un mini PC](/es/subidas-precios-vps/)._

Todo fue bien y reinicié el servidor, pero nunca volvió a levantar. Entré en la consola y vi que se quedaba atascado durante el arranque con el error:

```
Kernel Panic - Not Syncing: VFS: Unable to Mount Root FS on Unknown-Block(0,0)
```

Kernel Panic - Not Syncing: VFS: Unable to Mount Root FS on Unknown-Block(0,0) es un error común que puede ocurrir en Ubuntu cuando el sistema no puede montar el sistema de archivos raíz durante el arranque. Este mensaje de error indica que el kernel no puede encontrar el sistema de archivos raíz, que es necesario para que el sistema operativo arranque correctamente.

## Cómo solucionar el Kernel Panic en Ubuntu

Los pasos siguientes me ayudaron a superar el error y conseguir un arranque limpio al final. Los detallo para que puedas seguirlos y resolver tu problema de forma efectiva.

### Inicia sesión en la consola y elige Advanced options for Ubuntu

Si no estás en un portátil y usas un servidor VPS, el proveedor debe ofrecer una consola que te permita ver lo que ocurre durante el arranque. Elige **Advanced options for Ubuntu**; ahí verás los kernels más recientes entre los que puedes elegir y debes seleccionar uno que no sea el último, como en la imagen de abajo:

### Comprueba el sistema de archivos

Inicia sesión en tu VPS y ejecuta el siguiente comando:

```bash
sudo fdisk -l
```

Aquí verás el dispositivo del sistema de archivos Linux; en mi caso es **_/dev/sda1_**

### Actualiza el sistema de archivos raíz

A continuación, debes montar y actualizar el sistema de archivos:

```bash
sudo mount /dev/sda1 /mnt
sudo mount --bind /dev /mnt/dev
sudo mount --bind /dev/pts /mnt/dev/pts
sudo mount --bind /proc /mnt/proc
sudo mount --bind /sys /mnt/sys
sudo chroot /mnt
```

### Actualiza el sistema de archivos temporal

Ahora ejecuta el siguiente comando:

```bash
root@cloud:/# update-initramfs -u -k 5.15.0-71-generic
output:
update-initramfs: Generating /boot/initrd.img-5.15.0-71-generic
```

En mi caso el problema estaba en el kernel **_5.15.0-71-generic_** que se instaló con la actualización; tú debes usar tu kernel, que debería aparecer en las opciones avanzadas de Ubuntu.

El comando update-initramfs -u -k 5.15.0-71-generic se usa para actualizar el sistema de archivos RAM inicial (initramfs) de la versión del kernel 5.15.0-71-generic en Ubuntu.

El initramfs es un sistema de archivos temporal que se carga en memoria durante el proceso de arranque, antes de que se monte el sistema de archivos raíz. Contiene los archivos y drivers necesarios para inicializar el hardware y cargar el sistema de archivos raíz.

Al ejecutar este comando, actualizas el initramfs de la versión del kernel especificada y te aseguras de que los archivos y drivers necesarios estén disponibles durante el proceso de arranque. Esto puede ser útil si has instalado hardware nuevo o has hecho cambios en el sistema que requieren drivers actualizados.

La opción -u indica al comando que actualice el initramfs, y la opción -k especifica la versión del kernel a actualizar. La parte 5.15.0-71-generic del comando indica la versión concreta del kernel que se va a actualizar.

El comando update-grub se usa para actualizar la configuración del gestor de arranque GRUB en Ubuntu.

GRUB (Grand Unified Bootloader) es un gestor de arranque que se usa para cargar el kernel de Linux e iniciar el proceso de arranque de Ubuntu. El archivo de configuración de GRUB se encuentra en /boot/grub/grub.cfg y contiene información sobre los kernels disponibles y las opciones de arranque.

Cuando ejecutas el comando update-grub, este escanea tu sistema y detecta cualquier cambio en los kernels disponibles y las opciones de arranque. Después actualiza el archivo de configuración de GRUB con la nueva información.

Ahora puedes reiniciar tu servidor y debería arrancar correctamente.
