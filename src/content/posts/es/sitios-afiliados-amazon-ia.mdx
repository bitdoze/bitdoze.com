## ¿Qué es un sitio web de afiliados de Amazon potenciado por IA?

Es un sitio web estático normal con tres partes unidas entre sí:



<YouTubeEmbed url="https://youtube.com/embed/..." label="Título del vídeo" />
- **Contenido en archivos Markdown/MDX** que viven en un repositorio Git, no en una base de datos.
- **Componentes de producto** (en mi caso un widget `<AmazonProduct>`) que renderizan nombre, especificaciones, valoración, pros, contras y un enlace de compra como una tarjeta enmarcada dentro del artículo.
- **Un agente de IA con una herramienta de scraping** que obtiene datos en vivo de Amazon, escribe el artículo alrededor de ellos y rellena las cajas de producto.

En mi configuración el agente es [Factory.ai Droid CLI](https://go.bitdoze.com/droid-cli), la herramienta de scraping es [BrightData MCP](https://go.bitdoze.com/brightdata) y el sitio es Astro. Puedes cambiar el agente por Codex, Claude Code u OpenCode (comparé las opciones en mi [recopilación de herramientas de codificación con IA de 2026](/es/herramientas-codificacion-ia/)), pero la estructura se mantiene igual.

Lo que esto no es: un script que genera 500 páginas ligeras de «mejor X» a partir de una lista de palabras clave. Esa versión del manual es a lo que apunta la política de abuso de contenido a escala de Google, y dejó de funcionar hace años. La diferencia aquí es que cada artículo se construye sobre datos de productos scrapeados que un humano revisa antes de publicar.

## Por qué funcionan los sitios de afiliados con IA en 2026

La economía cambió porque las partes caras de la escritura de afiliación se volvieron casi gratuitas, mientras que la parte que importa (elegir sobre qué escribir y verificar las afirmaciones) siguió siendo manual.

<li><b>La calidad de redacción es suficiente para editar.</b> Claude Sonnet 4.5 produce textos de comparación estructurados y legibles. Es un primer borrador que puedes corregir, no algo que publicas sin tocar.</li>

Apunta la IA a esas.

### Por qué falla el contenido de afiliados genérico con IA

El coste no es la limitación. El control de calidad lo es. Google no tiene una penalización para el «contenido de IA» como categoría, pero sí tiene políticas contra el abuso de contenido a escala, las páginas de afiliados sin valor y el contenido escrito principalmente para posicionar en lugar de para las personas. La prueba práctica es si un lector obtiene algo que no podría obtener de la página de producto de Amazon.

Contenido que funciona:

<ListCheck>
<ul>
<li>Compara productos entre sí y dice cuál comprar</li>
<li>Usa valoraciones en vivo, número de reseñas y rangos de precio de Amazon</li>
<li>Nombra un caso de uso específico y un lector específico (cocinas pequeñas, meal prep por lotes, batidos de proteínas)</li>
<li>Señala las desventajas del producto que estás recomendando</li>
<li>Está estructurado con encabezados que un humano puede escanear en 30 segundos</li>
</ul>
</ListCheck>

Contenido que no funciona:

- «En el mundo acelerado de hoy, todo el mundo necesita una batidora.»
- Tablas de especificaciones copiadas y pegadas sin ninguna opinión
- La misma plantilla de 800 palabras en 40 artículos con el sustantivo cambiado
- H2 repletos de palabras clave sin contenido debajo
- Precios de hace dos años
- Afirmaciones falsas de «lo probé durante seis meses»

Las reglas que sigo: el agente escribe, yo decido qué se publica, y ningún artículo sale sin al menos una observación específica del producto que no esté en la página de Amazon.

## Configuración paso a paso

### Paso 1: configura tu sitio de afiliados Astro

Si nunca has hecho esto, sigue mi [guía para crear un blog gratis con Astro y Cloudflare](/es/crear-blog-astro-gratis/) de principio a fin. La versión corta:

```bash
# 1. Fork bitdoze-astro-theme on GitHub, then clone your fork
git clone https://github.com/YOUR-USERNAME/your-site.git
cd your-site

# 2. Install dependencies
npm install

# 3. Start the dev server
npm run dev
```

Visita `http://localhost:4321` y deberías ver el sitio de demostración del tema.

**Verifica:** ejecuta `npm run build`. Debería terminar sin errores de esquema y producir una carpeta `dist/`. Si el build falla con un error de colección de contenido, a tu frontmatter le falta un campo obligatorio (`title`, `date`, `description`, `image`, `authors`, `categories` son todos requeridos por el esquema).

### Paso 2: configura BrightData MCP con Droid CLI

Crea `~/.factory/mcp.json`:

```json
{
  "mcpServers": {
    "brightdata-mcp": {
      "command": "npx",
      "args": ["-y", "@brightdata/mcp"],
      "env": {
        "API_TOKEN": "your_brightdata_api_key_here",
        "PRO_MODE": "true"
      }
    }
  }
}
```

Inicia sesión en BrightData, ve a la sección API del panel y genera un token. Pégalo en lugar del placeholder.

**Verifica:** inicia `droid` en el directorio de tu proyecto y pregúntale `list your available MCP tools`. Deberías ver las funciones `web_data_amazon_*` en la respuesta. Si el servidor nunca conecta, comprueba que `npx -y @brightdata/mcp` se ejecuta por sí solo en una terminal.

**Cómo se ve cuando falla:** un 401 en los logs de Droid significa que el token está mal o fue regenerado. Un error de `npx` suele significar que Node es demasiado viejo (necesitas 20+). Si faltan los extractores de Amazon pero los genéricos funcionan, estás en modo Rapid, no en PRO.

Si MCP es nuevo para ti, lee primero la [introducción al Model Context Protocol para principiantes](/es/introduccion-mcp-principiantes/), hace el archivo de configuración mucho menos misterioso.

### Paso 3: crea AGENTS.md

Este es el archivo de mayor impacto del proyecto. Le dice al agente cómo funciona tu sitio, cuáles son los estándares de contenido y qué widgets existen. Sin él obtienes markdown genérico que no encaja con tu tema.

Crea `AGENTS.md` en la raíz del proyecto:

```markdown
# Agents guide for <your site>

## Commands

- dev: `npm run dev` (localhost:4321)
- build: `npm run build`
- preview: `npm run preview`

## Architecture

- Astro v5 blog with MDX, RSS, sitemap
- Content collections: posts/, authors/, pages/ in src/content/
- Config: site.ts, menu.json, social.json in src/config/
- Layouts: Layout.astro, PostLayout.astro
- Styling: Tailwind CSS v4 with @tailwindcss/typography
- Assets: src/assets/ for images, public/ for static files

## Content guidelines

- Write informative, practical, specific content. No filler intros.
- One H1 (the title). H2 for sections, H3 for subsections. Never skip levels.
- Include a pros/cons list and at least one concrete use case per product.
- Use the AmazonProduct widget for every product you feature.
- Max 3 tags per article. Kebab-case filenames.
- Internal links: 3-5 per article, descriptive anchor text, never "click here".
- Generate the featured image as a simple 16:9 SVG saved into the assets image folder.

## Available widgets (import from @components/widgets/)

- AmazonProduct: product box with specs, rating, pros, cons
- Notice: info | success | warning | error callouts
- ListCheck: checkmark list
- Accordion: expandable FAQ entries
- Button: CTA button

## AmazonProduct usage

<AmazonProduct productName="..." productDescription="..." productFeatures={["...", "..."]} productLink="https://amazon.com/dp/ASIN" productImage="https://m.media-amazon.com/images/..." productRating={4.5} pros={["..."]} cons={["..."]} />
```

Guárdalo en la raíz del proyecto. Cada nueva sesión en ese directorio lo recoge.

**Verifica:** pregunta al agente `what are the content guidelines for this project?` Debería citarte el archivo. Si inventa una respuesta, el archivo está en el directorio equivocado.

### Paso 4: genera contenido de afiliados de Amazon con IA

Abre tu terminal en el proyecto e inicia el agente:

```bash
droid
```

Luego usa este patrón de prompt:

```
Write a comprehensive roundup article about the best [PRODUCT CATEGORY].

Use BrightData MCP to fetch the top 5 products on Amazon for that category and
add each one to an AmazonProduct component with real specifications, ratings,
and buyer feedback.

For every product, say who it is for and who should skip it. Use my real
opinion as the default recommendation at the end. No filler opening paragraph.
```

Una versión concreta:

```
Write a comprehensive roundup article about the best blenders for frozen fruit
smoothies under $200.

Use BrightData MCP to fetch the top 5 products on Amazon and add each one to an
AmazonProduct component with real specifications, ratings, and buyer feedback.

For every product, say who it is for and who should skip it. Pick one clear
default recommendation for a small kitchen. No filler opening paragraph.
The slug is best-blenders-frozen-fruit-smoothies.
```

La IA hará:

1. Buscará productos candidatos en Amazon
2. Obtendrá datos de producto (precio, valoración, número de reseñas, especificaciones)
3. Extraerá reseñas para encontrar quejas recurrentes
4. Escribirá el artículo con la estructura de AGENTS.md
5. Renderizará widgets `<AmazonProduct>` para cada elección
6. Generará la imagen destacada SVG y la guardará en la carpeta de assets

![Factory.ai Droid CLI generando un artículo de afiliados de Amazon con datos de producto obtenidos a través de BrightData MCP](@assets/images/25/10/droid-ai-article.png)

Terminas con un archivo MDX en `src/content/posts/`. Ejecuta `npm run build` antes de confiar en él. La validación del esquema detecta frontmatter faltante y props de componentes incorrectas, que es la mayor parte de lo que sale mal.

**Verifica antes de publicar, siempre:**

```bash
npm run build && npm run preview
```

Luego haz clic en cada enlace de afiliado. Los enlaces `https://amazon.com/dp/ASIN` son fáciles de alucinar para el modelo, y un ASIN muerto es un clic de afiliado muerto. Comprueba que los precios de las cajas coinciden con la página actual de Amazon. Si el precio está desactualizado, las reglas de Amazon Associates no te permiten mostrarlo.
## Reglas de Amazon Associates y declaración de contenido con IA

Esta es la sección que la gente se salta y por la que luego le cierran la cuenta. Las reglas que aplican a un sitio de afiliados asistido por IA:

- **Declara la relación.** Una línea clara cerca del inicio de cada post: «Como Asociado de Amazon gano por compras que califiquen.» Ponla donde sea visible sin hacer scroll, no enterrada en el pie de página.
- **Mantén precios y disponibilidad exactos o quítalos.** El Acuerdo Operativo de Amazon exige que cualquier información de precio o disponibilidad que muestres esté vigente. Si tus cajas de producto muestran precios, hay que actualizarlos (ver la rutina trimestral de abajo), y deberías enlazar el precio a la página de Amazon.
- **No afirmes cosas que no has verificado.** «Lo probé durante seis meses» cuando no lo hiciste es una afirmación falsa, y es el tipo de cosa que trae tanto una acción manual de Google como quejas de lectores.
- **No metas la etiqueta de afiliado por todas partes.** Etiquetas en enlaces que no son de producto, enlaces en PDFs o enlaces en emails son todas violaciones. Los enlaces van en el artículo, en la página, en ningún otro sitio.
- **Mantén la IA fuera de la parte de declaración.** La declaración, la configuración de la etiqueta de afiliado y las reglas de precios son tu responsabilidad. Los agentes se equivocan en esto de formas que parecen bien en un borrador.
- **Revisa antes de publicar.** Tú lo estás publicando. «Lo escribió la IA» no es una defensa en una revisión de Amazon ni en una acción manual de Google.

<Notice type="error" title="No publiques contenido de IA sin revisar a escala">
Publicar en masa páginas generadas sin paso editorial choca contra dos muros distintos: la política de abuso de contenido a escala de Google y el requisito de Amazon de no tergiversar productos o precios. Ambos resultados se evitan con una revisión de 10 minutos por artículo.
</Notice>

## SEO para contenido de afiliados generado con IA

El flujo de contenido está automatizado. La estrategia no. En lo que realmente dedico tiempo:

- **Palabras clave long-tail con intención de compra.** «Mejor batidora para fruta congelada por menos de 200 $» gana a «mejor batidora» siempre, y es mucho menos probable que se la trague un AI Overview.
- **Artículos de comparación como páginas de dinero.** El formato «A vs B» convierte, y es el formato que un agente escribe bien porque ambos lados son datos scrapeados.
- **Autoridad temática sobre volumen.** Diez artículos completos sobre un nicho, enlazados entre sí, ganan a sesenta aleatorios.
- **Enlaces internos, siempre.** De tres a cinco por artículo, con texto ancla descriptivo. Esta es la parte que el agente olvida sistemáticamente a menos que AGENTS.md se lo recuerde.
- **Analítica real.** Sigo qué posts reciben clics y qué cajas de producto se pulsan. [SEO Gets](/seo-gets-tool/) reúne datos de Search Console y GA4 en un solo lugar, y [Plausible en Cloudflare Workers](/astro-plausible-cloudflare-workers/) es la opción más ligera si solo quieres seguimiento de páginas y eventos sin cookies.

### Mantén los datos de producto actualizados

Los precios de Amazon se mueven constantemente y los productos se descatalogan. Una caja de producto desactualizada es tanto un problema de cumplimiento como de conversión. Yo actualizo trimestralmente, e inmediatamente si noto un precio que parece mal:

```
Update the Amazon products in src/content/posts/[article-name].mdx using
BrightData MCP. For each ASIN, check the current price, rating, review count,
and availability. Flag any product that is discontinued or now ships from a
third-party seller at a much higher price, and suggest a replacement from the
same category.
```

Lee el diff antes de hacer commit. Este es el paso donde un modelo es más propenso a «arreglar» un precio redondeándolo o inventando un precio de oferta.

### Añade experiencia personal (E-E-A-T)

Esta es la parte que la IA no puede hacer por ti, y es lo que separa una página que posiciona de una que no:

- Tus propias fotos, incluso fotos de móvil, de los productos que realmente tienes
- Casos de uso con los que te has encontrado (la batidora que sobrevive al mango congelado pero no al hielo)
- Preguntas de lectores que has tenido que responder dos veces
- El único producto de la recopilación que no comprarías, y por qué
- Notas de pruebas reales con fechas, si realmente probaste

Añade un párrafo de eso a cada artículo y el cuerpo escrito por IA deja de leerse como escrito por IA.

## Publicando tu sitio de afiliados con IA

Revisa el artículo, luego haz commit:

```bash
git add .
git commit -m "Add affiliate article: best blenders for frozen fruit smoothies"
git push
```

Si configuraste el proyecto con la [guía de Astro y Cloudflare](/es/crear-blog-astro-gratis/), el push dispara un build de Cloudflare Pages y la página está en vivo en un par de minutos. Los detalles de despliegue paso a paso, incluyendo el comando de build y la configuración del directorio de salida, están en [cómo desplegar un blog Astro en Cloudflare](/deploy-astrojs-cloudflare/).

<Notice type="success" title="Despliegues automáticos">
Una vez que el repo está conectado a Cloudflare Pages, cada push a `main` despliega. Sin servidor, sin monitorización de uptime, sin renovación de SSL. Si un build falla, la versión anterior sigue en vivo, que es exactamente el comportamiento de rollback que quieres.
</Notice>

Si necesitas deshacer algo, haz `git revert` del commit y push. Los fallos fallan cerrados: un build roto no tira el sitio en vivo.

| Flujo de contenido | editor de bloques, base de datos | archivos MDX en Git |
| Actualización de contenido | manual, quedaba obsoleto rápido | re-scrape y reescritura bajo demanda |

Sobre la calidad del contenido, el resumen honesto: más comparaciones de productos por artículo, información de producto vigente en lugar de especificaciones de hace dos años, estructura consistente y mejor enlazado interno. La escritura no es mejor que la de un buen redactor humano. Es mejor que lo que yo producía solo en el tiempo que tenía, y está al día.

Costes mensuales de funcionamiento para un sitio como este:

- **Hosting**: 0 $ (nivel gratuito de Cloudflare Pages)
- **Dominio**: ~1 $/mes (12 $/año)
- **Droid CLI**: 0 $ en el nivel gratuito para este volumen

El ahorro es real, pero no es el punto. El punto es que una actualización de contenido ahora cuesta una tarde en lugar de una línea de presupuesto.

## FAQ: sitios web de afiliados con IA

<Accordion label="¿Es ético el contenido de afiliados con IA?" group="faq" expanded="true">
Sí, cuando la IA hace la investigación y el borrador y tú tomas las decisiones. La línea es si un lector obtiene valor: datos reales de producto, una recomendación clara, desventajas honestas y una declaración. Cruzar esa línea significa publicar páginas cuyo único propósito es interceptar una consulta de búsqueda, y tanto lectores como motores de búsqueda lo notan.
</Accordion>

<Accordion label="¿Penalizará Google el contenido de afiliados generado con IA?" group="faq">
Google no penaliza el contenido por estar generado con IA. Sus políticas de spam apuntan al abuso de contenido a escala, a las páginas de afiliados sin valor y al contenido hecho principalmente para posicionar en lugar de para las personas. En la práctica: si una página es exacta, está al día, añade información más allá de la ficha de Amazon y tiene un revisor real detrás, la herramienta usada para redactarla no es el factor decisivo. Si es una de 500 páginas de plantilla sin valor, no posicionará sin importar cómo fue escrita.
</Accordion>

<Accordion label="¿Se puede escalar un sitio web de afiliados con IA?" group="faq">
La herramienta no es el límite. Los dos límites son el control de calidad y la profundidad del tema. Puedo generar muchos más artículos de los que puedo revisar adecuadamente, y publicar 200 artículos sobre un nicho no es posible sin convertirse en un sitio de contenido vacío. El ritmo viable es 10-20 artículos revisados para lanzar, luego 5-10 al mes, más una actualización trimestral de todo lo ya publicado.
</Accordion>

<Accordion label="¿Cuánto cuesta mantener un sitio de afiliados con IA?" group="faq">
Unos 1 $/mes en costes fijos (un dominio). El hosting en Cloudflare Pages es gratis a esta escala, el nivel gratuito de Droid CLI cubrió 40 artículos, y BrightData MCP tiene 5.000 solicitudes gratuitas al mes en modo Rapid. El coste real es tu tiempo de revisión, unos 10-15 minutos por artículo antes de publicarlo.
</Accordion>

<Accordion label="¿Necesito tener los productos sobre los que escribo?" group="faq">
Ayuda y mejora el artículo, pero no es obligatorio y fingir lo contrario es un error. Lo obligatorio es que cada afirmación factual en la caja de producto venga de los datos scrapeados de Amazon, que la recomendación sea tuya y que no inventes pruebas prácticas que nunca hiciste.
</Accordion>

## Conclusión

Crear un sitio web de afiliados no tiene que ser caro ni lento. Con las herramientas actuales los números son: 40 artículos reescritos, unos 2 $ en costes, alojado gratis, más rápido y más fácil de mantener que el sitio WordPress que reemplazó. Las herramientas están al alcance de un operario en solitario con un portátil y una tarde.

Lo que no ha cambiado es que alguien tiene que decidir qué productos vale la pena recomendar y respaldar la recomendación. La IA se encarga de la investigación y el borrador. El criterio sigue siendo el trabajo.
