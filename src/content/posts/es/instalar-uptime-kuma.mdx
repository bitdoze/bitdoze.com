Si quieres instalar Uptime Kuma y monitorizar el tiempo de actividad de tu sitio web desde tu propio VPS, esta es la herramienta a la que siempre vuelvo. Envía alertas por correo electrónico, Slack, Discord, Telegram y más de 90 canales cuando algo se cae, y guarda un historial de los tiempos de respuesta para que detectes qué ha estado lento. Es monitorización autoalojada y gratuita que funciona en un solo contenedor Docker.

El proyecto está en desarrollo activo. La versión actual es **2.5.11** (noviembre de 2026). Desde la v2.0 de octubre de 2025, la rama 2.x ha añadido soporte para MariaDB en despliegues grandes, imágenes de Docker rootless, sondas mundiales con Globalping, monitorización de la caducidad de dominios, monitores SFTP/NTP/OracleDB y dos parches de seguridad para fallos de ejecución remota de código. El changelog completo está en los [GitHub releases](https://github.com/louislam/uptime-kuma/releases).

Puedes probarlo antes de instalarlo en la [demo oficial](https://demo.kuma.pet).

<Notice type="info" title="Fuente oficial">
La fuente oficial de Uptime Kuma es el [repositorio de GitHub](https://github.com/louislam/uptime-kuma). El dominio `uptimekuma.co` (que a menudo aparece primero en Google) **no** es el sitio oficial.
</Notice>

Esta guía explica cómo instalar Uptime Kuma en Ubuntu con Docker Compose, usando Nginx como proxy inverso y un certificado SSL de Let's Encrypt.

Cinco bloques de comandos para dejarlo funcionando. Las explicaciones completas y los pasos de verificación están más abajo.

**1. Instala Docker:**

```bash
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /usr/share/keyrings/docker-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/docker-archive-keyring.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt update && sudo apt install docker-ce docker-ce-cli containerd.io docker-compose-plugin -y
```

**2. Escribe el archivo compose:**

```bash
mkdir -p /docker-vol/uptime-kuma /opt/uptime-kuma && cd /opt/uptime-kuma
cat > docker-compose.yml << 'EOF'
services:
  uptime-kuma:
    image: louislam/uptime-kuma:2
    container_name: uptime-kuma
    volumes:
      - /docker-vol/uptime-kuma:/app/data
    ports:
      - 8001:3001
    restart: unless-stopped
    security_opt:
      - no-new-privileges:true
EOF
```

**3. Arráncalo:**

```bash
docker compose up -d
```

**4. Proxy inverso con Nginx:**

```bash
sudo apt install nginx -y
sudo tee /etc/nginx/sites-available/uptime-kuma.conf > /dev/null << 'EOF'
server {
    listen 80;
    server_name your_domain_here;
    location / {
        proxy_set_header   X-Real-IP $remote_addr;
        proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header   Host $host;
        proxy_pass         http://localhost:8001;
        proxy_http_version 1.1;
        proxy_set_header   Upgrade $http_upgrade;
        proxy_set_header   Connection "upgrade";
    }
}
EOF
sudo ln -s /etc/nginx/sites-available/uptime-kuma.conf /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

**5. SSL con Certbot:**

```bash
sudo apt install certbot python3-certbot-nginx -y
sudo certbot --nginx -d your_domain_here
```

## Por qué Uptime Kuma

Uptime Kuma monitoriza HTTP(s), chequeos de palabra clave y consultas JSON sobre HTTP(s), puertos TCP, Ping, registros DNS, contenedores Docker, servidores de juegos de Steam, monitores push (webhook entrante), endpoints WebSocket, dispositivos SNMP/SNMPv3, caducidad de dominios vía RDAP, SFTP, NTP y OracleDB. Es mucha cobertura para un solo contenedor.

En el apartado de notificaciones envía alertas a través de más de 90 servicios: Telegram, Discord, Slack, Gotify, SMTP, WhatsApp, Plivo SMS, Jira Service Management, Google Sheets y muchos más. Incluye una interfaz de páginas de estado rápida (múltiples páginas de estado, historial de incidentes, RSS de incidentes), métricas para Prometheus, soporte de proxy y opciones multi-idioma. Todo gratis y autoalojado.

Si además quieres métricas a nivel de servidor (CPU, RAM, disco, estadísticas de Docker) junto a los chequeos de disponibilidad, puedes [ejecutar Beszel junto a Uptime Kuma para una monitorización completa del servidor](/es/beszel-uptime-kuma/).

Comparado con opciones SaaS como Uptime Robot o BetterStack, la monitorización autoalojada con Uptime Kuma te da monitores ilimitados, historial ilimitado y ninguna factura mensual. La contrapartida es que lo operas tú: las actualizaciones, las copias de seguridad y la disponibilidad del propio monitor son tu problema. Para alguien que ya gestiona unos pocos sitios en un VPS, ese intercambio merece la pena.

## 2. Instala Uptime Kuma en Ubuntu

Todo lo que viene a continuación se puede copiar y pegar en un VPS Ubuntu recién instalado.

### 2.1 Actualiza el sistema e instala Nginx

```bash
sudo apt update && sudo apt upgrade -y
sudo reboot
sudo apt install nginx git -y
```

**Verifica:** `systemctl status nginx` muestra `active (running)` y `curl -I http://localhost` devuelve un HTTP 200.

### 2.2 Instala Docker y Docker Compose

Sigue la [guía oficial de instalación de Docker](https://docs.docker.com/engine/install/ubuntu/) o ejecuta:

```bash
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /usr/share/keyrings/docker-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/docker-archive-keyring.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt update
sudo apt install docker-ce docker-ce-cli containerd.io docker-compose-plugin -y
```

> **Nota:** La forma recomendada actualmente es el `docker-compose-plugin` (v2). Usa `docker compose` (sin guion) de ahora en adelante.

Si estás en ARM (Oracle Ampere, Raspberry Pi), mira cómo [instalar Docker y Docker Compose en Ubuntu ARM](/es/instalar-docker-ubuntu-arm/). Las líneas del repositorio cambian ligeramente.

**Verifica:**

```bash
docker --version && docker compose version
docker run --rm hello-world
```

Si `hello-world` no se descarga ni se ejecuta, el demonio de Docker no está corriendo o el repositorio apt no se registró. Repite el paso de `gpg --dearmor` y comprueba que `lsb_release -cs` coincide con el nombre clave de tu Ubuntu.

### 2.3 Crea los directorios y escribe un archivo compose

```bash
mkdir -p /docker-vol/uptime-kuma
mkdir -p /opt/uptime-kuma
cd /opt/uptime-kuma
```

Crea `docker-compose.yml`:

```yaml
services:
  uptime-kuma:
    image: louislam/uptime-kuma:2
    # Usa louislam/uptime-kuma:2-slim para una imagen más pequeña (sin MariaDB/Chromium)
    container_name: uptime-kuma
    volumes:
      - /docker-vol/uptime-kuma:/app/data
    ports:
      - 8001:3001
    restart: unless-stopped
    security_opt:
      - no-new-privileges:true
```

<Notice type="warning" title="No uses NFS ni montajes de red para /app/data">
La wiki oficial advierte explícitamente de que NFS y sistemas de archivos de red similares NO están soportados. SQLite necesita bloqueos de archivos POSIX que NFS no proporciona correctamente. Mapea <code>/app/data</code> solo a un directorio local o a un volumen de Docker.
</Notice>

<Notice type="warning" title="No uses la etiqueta :latest">
La etiqueta <code>latest</code> está obsoleta y sigue apuntando a la v1. Fija siempre <code>:2</code> para quedarte en la rama v2 y evitar cambios inesperados cuando salga la v3.
</Notice>

Elige la variante de imagen según tus necesidades:

<Tabs>
<Tab name="Completa (por defecto)">
<code>louislam/uptime-kuma:2</code>: ~590 MB. Incluye MariaDB embebido (para despliegues grandes) y Chromium embebido (para el monitor Browser Engine). Usa esta salvo que sepas que no los necesitas.
</Tab>
<Tab name="Slim">
<code>louislam/uptime-kuma:2-slim</code>: ~176 MB. Prescinde de MariaDB y Chromium embebidos. Vale para chequeos HTTP, TCP, DNS y de palabra clave con notificaciones externas. Ahorra disco y tiempo de descarga en un VPS pequeño.
</Tab>
<Tab name="Rootless">
<code>louislam/uptime-kuma:2-rootless</code> o <code>2-slim-rootless</code>: se ejecuta como <code>node:node</code> (1000:1000) en lugar de root. Mejor práctica de seguridad para servidores compartidos. Asegúrate de que el directorio de datos pertenece a 1000:1000 antes de arrancar. El monitor de contenedores Docker necesita configuración extra del socket en las imágenes rootless.
</Tab>
</Tabs>

Para Raspberry Pi u otro hardware de baja potencia, añade `UPTIME_KUMA_SQLITE_SINGLE_CONNECTION=true` como variable de entorno para evitar problemas de bloqueo de SQLite.

Si prefieres saltarte el archivo compose manual por completo, puedes [desplegar Uptime Kuma con un clic usando Coolify](/es/desplegar-uptime-kuma/). Y si quieres una interfaz web para gestionar el stack compose a partir de ahora, [gestiona este stack compose con Dockge](/es/instalar-dockge/).

Arranca el contenedor:

```bash
docker compose up -d
```

**Verifica:**

```bash
docker compose ps          # El contenedor debería mostrar "Up"
docker compose logs -f     # Comprueba errores de arranque (Ctrl+C para salir)
curl -I http://localhost:8001   # Debería devolver una respuesta HTTP
```

Si el puerto 8001 ya está en uso, compruébalo con `ss -tlnp | grep 8001` y cambia el puerto del host en el compose (p. ej. `8002:3001`). Después actualiza el `proxy_pass` de Nginx para que coincida.

### 2.4 Abre el firewall para Nginx

```bash
sudo ufw allow "Nginx Full"
sudo ufw enable
```

**Verifica:** `sudo ufw status` muestra `Nginx Full` como ALLOW.

<Notice type="warning" title="Docker se salta UFW">
Los puertos publicados de los contenedores se saltan las reglas de UFW. Docker manipula iptables directamente. Por eso el archivo compose mapea el 8001 en el host. Una vez funcione el proxy inverso, puedes restringirlo a <code>127.0.0.1:8001:3001</code> en el compose para que el puerto solo sea accesible desde localhost. Mira [cómo interactúa Docker con las reglas de UFW](/es/docker-evita-firewall/) para más detalles.
</Notice>

### 2.5 Configura Nginx como proxy inverso

Crea `/etc/nginx/sites-available/uptime-kuma.conf` y pega:

```nginx
server {
    listen 80;
    server_name your_domain_here;

    location / {
        proxy_set_header   X-Real-IP $remote_addr;
        proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header   Host $host;
        proxy_pass         http://localhost:8001;
        proxy_http_version 1.1;
        proxy_set_header   Upgrade $http_upgrade;
        proxy_set_header   Connection "upgrade";
    }
}
```

Las cabeceras `Upgrade` y `Connection "upgrade"` son obligatorias. La interfaz de Uptime Kuma se comunica por WebSocket. Sin estas cabeceras la página carga pero el panel se queda colgado o muestra un "WebSocket error". Es el fallo número uno del proxy inverso con Uptime Kuma.

Habilita el sitio y recarga Nginx:

```bash
sudo ln -s /etc/nginx/sites-available/uptime-kuma.conf /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

**Verifica:** `sudo nginx -t` devuelve `syntax is ok`, y `curl -I http://your_domain_here` devuelve una respuesta de Nginx (no "connection refused").

Si prefieres una interfaz gráfica en lugar de Nginx escrito a mano, puedes [configurar CloudPanel como proxy inverso](/es/configurar-dockge-cloudpanel/).

<Notice type="info" title="Activa Trust Proxy">
Cuando el sitio esté en marcha, ve a Settings → Reverse Proxy → HTTP Headers en la interfaz de Uptime Kuma y activa <strong>Trust Proxy</strong>. Sin esto, las IP de cliente en los logs mostrarán la IP del servidor Nginx en lugar de la IP real del visitante.
</Notice>

## 3. Apunta tu dominio al servidor

Inicia sesión en tu proveedor de DNS y añade un **registro A** que apunte tu dominio o subdominio a la dirección IP del VPS.

**Verifica:** antes de ejecutar Certbot, confirma que el DNS se ha propagado:

```bash
dig +short your_domain_here
```

Debe devolver la IP de tu VPS. Si no lo hace, espera. Certbot fallará si el DNS no se ha propagado.

## 4. Añade un certificado SSL con Let's Encrypt

Instala Certbot y genera un certificado:

```bash
sudo apt install certbot python3-certbot-nginx -y
sudo certbot --nginx -d your_domain_here
```

Certbot modifica la configuración de Nginx automáticamente y configura la renovación automática. Tu sitio estará disponible por HTTPS de inmediato.

**Verifica:**

```bash
certbot renew --dry-run
```

Debería completarse sin errores. Abre `https://your_domain_here` en un navegador y confirma que aparece el candado.

Si Certbot agota el tiempo o devuelve "connection refused", el puerto 80 no es accesible. Revisa tu firewall (§2.4) y la propagación del DNS (§3). Si alojas varios servicios en la misma máquina y prefieres un certificado wildcard, [configura un certificado wildcard gratuito de Let's Encrypt con Traefik](/es/traefik-certificado-wildcard/).

<Notice type="info" title="Tu panel ya está expuesto a internet">
Activa el 2FA de inmediato (se explica en §5) y considera reforzar el servidor con CrowdSec: [securiza el VPS con CrowdSec](/es/crowdsec-servidor-seguro/) para una protección continua contra fuerza bruta y escaneos de exploits.
</Notice>

## 5. Configura tu primer monitor

En el primer inicio de sesión creas una cuenta de administrador. Antes de añadir monitores, ve a Settings → Security y activa el **2FA**. Este panel está expuesto a internet y guarda credenciales de tus canales de notificación. Trátalo como corresponde.

Después añade un monitor: pon el tipo en HTTP(s), dale un nombre descriptivo y configura el intervalo de heartbeat en 300 segundos. Comprobar cada 5 minutos es suficiente para la mayoría de los sitios. El intervalo mínimo es de 20 segundos, y desde la 2.5.0 ya no hay tope superior en los intervalos (antes eran 24 días).

## Cómo actualizar Uptime Kuma

Actualizar es una sola secuencia de comandos. La etiqueta `:2` flota al último parche 2.x al hacer pull:

```bash
cd /opt/uptime-kuma
docker compose pull
docker compose up -d --force-recreate
```

**Verifica:** `docker compose logs` muestra un arranque limpio, y la versión en el pie de la interfaz coincide con la release esperada.

Antes de actualizar en producción, revisa las [notas de release en GitHub](https://github.com/louislam/uptime-kuma/releases) por si hay cambios que rompen compatibilidad, y haz primero una copia de seguridad del directorio de datos (siguiente sección). Si el contenedor no arranca tras una actualización, consulta las notas de release para los pasos de migración y restaura la copia si hace falta.

## Copia de seguridad de los datos de Uptime Kuma

La función de copia/restauración en JSON de la v1 ya no existe en la v2. El único método de copia soportado es copiar el directorio `data`. Un solo comando:

```bash
tar -czf /backups/kuma-$(date +%F).tar.gz /docker-vol/uptime-kuma
```

Prográmalo a diario con cron:

```bash
# crontab -e
0 3 * * * tar -czf /backups/kuma-$(date +\%F).tar.gz /docker-vol/uptime-kuma
```

Para restaurar: para el contenedor, descomprime en la misma ruta y arranca de nuevo:

```bash
cd /opt/uptime-kuma && docker compose down
tar -xzf /backups/kuma-2026-11-13.tar.gz -C /
docker compose up -d
```

<ListCheck>
<ul>
<li>Crea un archivo tar de <code>/docker-vol/uptime-kuma</code></li>
<li>Verifica el archivo (<code>tar -tzf kuma-*.tar.gz | head</code>)</li>
<li>Copia el tarball fuera de la máquina: a almacenamiento compatible con S3, a otro host, a cualquier sitio que no sea el mismo disco que está muriendo</li>
<li>Prueba una restauración una vez para saber que el proceso funciona</li>
</ul>
</ListCheck>

Una copia de seguridad en el mismo disco no es una copia de seguridad. Sube el tarball a almacenamiento compatible con S3 o a otro host. Las copias de seguridad solo cuestan disciplina; la copia externa es el único paso innegociable.

## Solución de problemas de Uptime Kuma

Si el panel no carga o las alertas no se disparan, casi siempre es una de estas causas.

<Accordion label="WebSocket error / la interfaz se cuelga tras Nginx" group="troubleshooting">
Faltan las cabeceras <code>Upgrade</code> y <code>Connection "upgrade"</code> en la configuración de Nginx. Es el problema número uno del proxy inverso. El bloque correcto:

```nginx
proxy_http_version 1.1;
proxy_set_header   Upgrade $http_upgrade;
proxy_set_header   Connection "upgrade";
```

Recarga Nginx después de arreglarlo (<code>sudo nginx -t && sudo systemctl reload nginx</code>).
</Accordion>

<Accordion label="&quot;database is locked&quot; / errores de SQLite" group="troubleshooting">
No uses NFS ni montajes de red para <code>/app/data</code>. SQLite necesita bloqueos de archivos POSIX. En hardware de baja potencia (Raspberry Pi), define <code>UPTIME_KUMA_SQLITE_SINGLE_CONNECTION=true</code>. Comprueba también el espacio en disco con <code>df -h</code>. Un disco lleno bloquea SQLite.
</Accordion>

<Accordion label="Subdirectorio no soportado" group="troubleshooting">
Uptime Kuma requiere un dominio o subdominio dedicado. Ejecutarlo en <code>example.com/kuma</code> nunca funcionará. Usa <code>status.example.com</code> en su lugar.
</Accordion>

<Accordion label="La imagen rootless no arranca / falta el monitor de Docker" group="troubleshooting">
El directorio de datos debe pertenecer a <code>node:node</code> (1000:1000) en las imágenes rootless: <code>chown -R 1000:1000 /docker-vol/uptime-kuma</code>. El monitor de contenedores Docker requiere configuración extra del socket en las imágenes rootless.
</Accordion>

<Accordion label="Puerto ya en uso (8001)" group="troubleshooting">
Compruébalo con <code>ss -tlnp | grep 8001</code>. Si otra cosa ocupa el 8001, cambia el puerto del host en <code>docker-compose.yml</code> (p. ej. <code>8002:3001</code>) y actualiza el <code>proxy_pass</code> de Nginx para que coincida.
</Accordion>

<Accordion label="Fallos de Certbot / TLS" group="troubleshooting">
Tres causas habituales: el DNS no se ha propagado (<code>dig +short your_domain_here</code> debe devolver la IP de tu VPS), el puerto 80 está bloqueado (revisa <code>sudo ufw status</code>) o hay un enlace simbólico obsoleto en <code>sites-enabled</code>. Para problemas de renovación, ejecuta <code>certbot renew --dry-run</code>. Comprueba también que no hayas descargado por error la etiqueta <code>latest</code> obsoleta (que es la v1). Cambia a <code>:2</code> y recrea el contenedor.
</Accordion>

## Conclusión

Uptime Kuma funciona silenciosamente en Docker, comprueba tus sitios y te envía un mensaje cuando algo se rompe. Gestiona la caducidad del SSL, la caducidad de dominios, DNS, puertos TCP, SNMP, SFTP, NTP y más. Coste total en un VPS compartido: prácticamente nada, unos $4-6/mes por una máquina de 1 vCPU / 1 GB si aún no tienes una.

Mantenlo actualizado (docker compose pull), haz copias de seguridad (tar + copia externa) y activa el 2FA. Si quieres ampliar la monitorización a métricas de servidor como CPU, RAM y uso de disco, [ejecuta Beszel junto a Uptime Kuma para una monitorización completa del servidor](/es/beszel-uptime-kuma/). Y si gestionas varios servicios autoalojados, puedes [comparar los mejores paneles de servidores autoalojados](/es/mejores-paneles-autoalojados/) para encontrar uno que encaje en tu stack.
