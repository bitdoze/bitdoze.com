OpenClaw ahora incluye un plugin oficial de búsqueda DuckDuckGo, en fase experimental. Agregar la búsqueda de DuckDuckGo a OpenClaw toma dos comandos y te da búsqueda web gratuita sin claves API, registros ni paneles de facturación. Si aplicaste un parche manual a `web-search.ts` (incluido el método que documentó la primera versión de este artículo), elimina ese parche e instala el plugin en su lugar. La vía del código casero desapareció desde que OpenClaw movió la búsqueda web a una arquitectura de plugins en marzo de 2026.

Una advertencia honesta antes de empezar: el endpoint HTML de DuckDuckGo sirve páginas de desafío anti-bot a las IP de centros de datos, que es donde se ejecutan la mayoría de las instancias de OpenClaw. Sin clave no significa confiable en un VPS. Esta guía cubre la instalación, la configuración, la verificación, la realidad de la detección de bots y qué usar en su lugar cuando necesitas una búsqueda que no falle (SearXNG si te autoalojas, Brave o Tavily si pagas).

## Qué cambió: DuckDuckGo ahora es un plugin oficial de OpenClaw

La primera versión de este artículo (febrero de 2026) documentaba un parche manual: editar `~/.openclaw/openclawd/src/agents/tools/web-search.ts` a mano, agregar una entrada de proveedor, escribir un analizador HTML, invocar curl y recompilar el árbol de código fuente. Funcionaba, y eran 11 pasos de TypeScript que tenías que mantener tú mismo.

El 23/03/2026 OpenClaw fusionó un plugin oficial integrado de DuckDuckGo (PR #52629) y lo marcó como experimental el mismo día. La búsqueda web ahora vive en la arquitectura de plugins (`extensions/<provider>/` en el repositorio, distribuidos como paquetes npm). Ya no hay checkout del código fuente, ni `npm run build`, ni TypeScript editado a mano. El paquete npm es `@openclaw/duckduckgo-plugin`, versionado al mismo ritmo que OpenClaw (2026.10.8 al 27/10/2026).

![Flujo del antiguo parche manual de web-search.ts frente al nuevo flujo de instalación del plugin oficial de DuckDuckGo en OpenClaw](@assets/images/15/02/duckduckgo-openclaw-search-old-vs-new.svg)

Internamente, el plugin difiere del antiguo parche casero en aspectos que importan: peticiones GET con parámetros de consulta en lugar de un cuerpo de formulario POST, un User-Agent honesto (`openclaw-duckduckgo/<version>`) en lugar de una cadena de navegador falsificada, soporte de `region` y `safeSearch`, y una caché de resultados integrada (15 minutos por defecto).

<Notice type="warning" title="Experimental">
La documentación oficial clasifica DuckDuckGo como «experimental, no oficial». Hace scraping del endpoint HTML de DuckDuckGo, así que si DuckDuckGo cambia el marcado de su página, el analizador se rompe hasta que el plugin publique una corrección. Esa es la contrapartida de la búsqueda sin clave.
</Notice>

## Cómo agregar la búsqueda de DuckDuckGo a OpenClaw (2 comandos)

Tres pasos, dos de ellos comandos. Ejecútalos desde una shell en el equipo que ejecuta tu gateway.

**1. Instala el plugin:**

```bash
openclaw plugins install @openclaw/duckduckgo-plugin
```

**2. Reinicia el gateway:**

```bash
openclaw gateway restart
```

La documentación dice que un gateway en ejecución detecta un plugin nuevo automáticamente. El reinicio es la vía segura si quieres un comportamiento determinista ahora mismo.

**3. Selecciona DuckDuckGo como proveedor de búsqueda:**

```bash
openclaw configure --section web
```

Elige «duckduckgo» de la lista de proveedores.

Eso es todo. No necesitas una clave API ni una cuenta, y no hay paso de compilación. Las versiones del plugin siguen los lanzamientos de OpenClaw, así que `@openclaw/duckduckgo-plugin@2026.10.8` corresponde a OpenClaw 2026.10.8.

<Button text="Documentación de Plugins de OpenClaw" link="https://docs.openclaw.ai/tools/duckduckgo-search" variant="outline" color="blue" size="sm" icon="arrow-right" />

Ahora confirma que funciona antes de depender de ello.

### Configura el proveedor de búsqueda DuckDuckGo

El archivo de configuración está en `~/.openclaw/openclaw.json`. Si vienes de la guía anterior: la ruta cambió de `~/.openclaw/config.json`, y el formato es JSON5 (se permiten comentarios y comas finales). `OPENCLAW_CONFIG_PATH` anula la ubicación si está definida en el entorno del gateway.

<Tabs>
<Tab name="Archivo de Configuración (JSON5)">

```json5
{
  tools: { web: { search: { provider: "duckduckgo" } } },
  plugins: {
    entries: {
      duckduckgo: {
        config: {
          webSearch: {
            region: "us-en",        // optional: us-en, uk-en, de-de, ...
            safeSearch: "moderate", // strict | moderate | off
          },
        },
      },
    },
  },
}
```

Ambos ajustes a nivel de plugin son opcionales. `region` usa por defecto la propia estimación de DuckDuckGo; `safeSearch` es `moderate` por defecto.

</Tab>
<Tab name="Comandos CLI de Una Línea">

```bash
# What is configured right now?
openclaw config get tools.web.search.provider

# Select DuckDuckGo
openclaw config set tools.web.search.provider "duckduckgo"

# Optional plugin-level defaults
openclaw config set plugins.entries.duckduckgo.config.webSearch.region "us-en"
openclaw config set plugins.entries.duckduckgo.config.webSearch.safeSearch "moderate"

# Remove a setting again
openclaw config unset plugins.entries.duckduckgo.config.webSearch.region
```

Mismo resultado que editar el archivo. Usa el que vayas a recordar.

</Tab>
</Tabs>

También hay una interfaz de control en `http://127.0.0.1:18789` (Settings → Search) si prefieres hacer clic antes que teclear.

Un comportamiento que conviene conocer de antemano: la detección automática de proveedor de OpenClaw solo considera proveedores con credenciales utilizables, así que DuckDuckGo nunca se selecciona automáticamente. Debes establecer `provider: "duckduckgo"` explícitamente, como arriba.

### Parámetros por consulta: count, region, safeSearch

Cada llamada a `web_search` acepta parámetros que anulan la configuración a nivel de plugin:

| Parámetro | Tipo | Por defecto | Notas |
|---|---|---|---|
| `query` | string | requerido | La consulta de búsqueda |
| `count` | number | 5 | De 1 a 10 resultados |
| `region` | string | config del plugin | Código `kl` de DuckDuckGo: `us-en`, `uk-en`, `de-de`, etc. |
| `safeSearch` | string | `moderate` | `strict`, `moderate` u `off` (corresponde al parámetro `kp` de DuckDuckGo) |

Los códigos de región corresponden al [parámetro `kl` de DuckDuckGo](https://duckduckgo.com/params). La lista cambia con el tiempo, así que consulta esa página en lugar de fijar un código copiado de un blog.

Dos valores por defecto que conviene tener en el radar: los resultados se guardan en caché en el proceso durante 15 minutos (la clave de caché incluye proveedor, consulta, count, region y safeSearch), y el tiempo de espera de la petición es de 20 segundos. Las consultas idénticas repetidas dentro de la ventana de caché no vuelven a contactar con DuckDuckGo.

## El problema: la detección de bots de DuckDuckGo en IP de VPS

«Gratis para siempre» tiene letra pequeña. El endpoint HTML de DuckDuckGo (`https://html.duckduckgo.com/html/`, y la variante `lite.duckduckgo.com/lite/`) responde a las IP de centros de datos con una página de desafío anti-bot en lugar de resultados de búsqueda. No obtienes un bloqueo con un código de error claro. Lo que vuelve es una página de aspecto normal: HTTP 202, un widget CAPTCHA («Select all squares containing a duck») y `id="challenge-form"` en el marcado. Cero resultados orgánicos.

Y ahí es exactamente donde se ejecutan la mayoría de las instancias de OpenClaw: un VPS en Hetzner, OVH o el rack de cualquier otro proveedor.

<Notice type="warning" title="Sin clave ≠ confiable en un VPS">
Trata la búsqueda DuckDuckGo como de mejor esfuerzo en cualquier IP de centro de datos. Espera fallos intermitentes bajo carga. Para cualquier cosa que deba funcionar siempre, usa SearXNG (autoalojado) o un proveedor con API (Brave, Tavily) en su lugar. Detalles en la sección de opciones más abajo.
</Notice>

<Notice type="error" title="Cómo Se Ve el Fallo">
El plugin oficial detecta la firma de la página de desafío y lanza <code>DuckDuckGo returned a bot-detection challenge.</code> en lugar de devolver basura en silencio. Comprueba tu propio VPS con una sola petición:

```bash
curl -s "https://html.duckduckgo.com/html/?q=openclaw" | grep -c "challenge-form"
# 0 = you got a real results page; 1 or more = you got a bot challenge
```
</Notice>

Las pruebas desde IP de centros de datos el 28/10/2026 toparon con esta página de desafío. Vuelve a ejecutar la comprobación desde tu propio VPS antes de decidir en cuánto puedes confiar. Esto va cambiando.

![Flujo de detección de bots de DuckDuckGo: una IP de centro de datos de VPS recibe una página de desafío HTTP 202 mientras una IP residencial obtiene resultados orgánicos](@assets/images/15/02/duckduckgo-openclaw-search-bot-detection.svg)

### Cómo reducir los fallos por detección de bots

Si quieres mantener DuckDuckGo como tu proveedor de todos modos, algunas cosas ayudan:

1. **Apóyate en la caché.** Los resultados se guardan en caché 15 minutos por consulta. Las búsquedas idénticas repetidas no vuelven a tocar DuckDuckGo dentro de esa ventana. Menos consultas únicas significa menos desafíos.
2. **Mantén `count` realista.** Pedir 10 resultados en cada llamada multiplica la superficie de análisis sin ganancia real. 5 es el valor por defecto por una razón.
3. **Ejecuta desde una IP residencial.** Un equipo doméstico o un Mac mini recibe muchos menos desafíos que un VPS. Si OpenClaw en casa es una opción para ti, consulta el [mejor Mac mini para OpenClaw](/es/mejor-mac-mini-openclaw/) para elegir el modelo adecuado.
4. **Mantén el User-Agent honesto.** Desde el 07/10/2026 (commit #164726) el plugin envía deliberadamente `openclaw-duckduckgo/<version>` en lugar de hacerse pasar por un navegador. No «arregles» esto con un UA de Chrome falsificado. El viejo consejo de rotar user-agents de la versión anterior de esta guía es ahora un riesgo de inconsistencia de huella digital, no una mitigación.
5. **O deja de hacer scraping.** Si las búsquedas deben funcionar siempre, pasa a la siguiente sección: SearXNG para búsqueda autoalojada sin clave, Brave o Tavily para búsqueda con API.

## Búsqueda web gratuita sin claves API: todas tus opciones en OpenClaw

DuckDuckGo no es la única forma de tener búsqueda web en OpenClaw sin tarjeta de crédito. Aquí está la comparación honesta:

| Proveedor | Clave API | Costo | Confiabilidad | Filtros de frescura | Mejor para |
|---|---|---|---|---|---|
| Plugin DuckDuckGo | Ninguna | Gratis | Media: scraping HTML, desafíos anti-bot en IP de centros de datos | No | Uso personal, pruebas |
| SearXNG | Ninguna | Gratis (autoalojado; VPS de ~6 €/mes) | Alta: API JSON nativa, sin scraping | Depende de la instancia | Autoalojado gratuito confiable |
| Brave Search | Requerida | ~1.000 consultas gratis/mes en crédito renovable (según la documentación de OpenClaw) | Alta: API oficial | Sí: `freshness`, `date_after`/`date_before` | Producción |
| Ollama Web Search | Ninguna con Ollama local, o `OLLAMA_API_KEY` | Gratis autoalojado / precios del hospedado | Alta | No | Stacks totalmente autoalojados |
| Tavily | `TAVILY_API_KEY` | Nivel gratuito (comúnmente citado en 1.000 créditos/mes, sin verificar) | Alta: API oficial | Ver documentación de Tavily | Agentes que también necesitan extracción de páginas |

Mi recomendación por defecto: uso personal y pruebas → plugin DuckDuckGo (dos comandos, costo cero). Autoalojado gratuito en serio → SearXNG. Producción, o cualquier cosa que no deba fallar → Brave o Tavily.

### SearXNG: la opción gratuita autoalojada confiable

Esta es la opción que yo elegiría para un VPS. SearXNG es un metabuscador autoalojado, y el plugin SearXNG integrado de OpenClaw habla con su API JSON nativa. No hace scraping, así que los desafíos anti-bot no forman parte del trato, y no hay clave API que gestionar. El inconveniente es que ejecutas SearXNG tú mismo, lo que supone un contenedor más, aunque pequeño.

Requisitos: `json` en `search.formats` del `settings.yml` de tu instancia de SearXNG, y OpenClaw 2026.6.9+ (esa es la versión mínima del host para el plugin).

Inicio rápido si SearXNG ya se ejecuta en el equipo:

```bash
export SEARXNG_BASE_URL="http://localhost:8888"   # instance needs format "json" enabled
openclaw configure --section web                   # choose "searxng"
```

O fíjalo en `~/.openclaw/openclaw.json`:

```json5
{
  plugins: {
    entries: {
      searxng: {
        config: {
          webSearch: {
            baseUrl: "http://localhost:8888",
            categories: "general",
            language: "en",
          },
        },
      },
    },
  },
  tools: { web: { search: { provider: "searxng" } } },
}
```

También puedes definir `SEARXNG_BASE_URL` en el entorno del gateway en lugar de la configuración. El plugin valida las URL base (protección SSRF), así que limítate a la dirección de tu propia instancia.

SearXNG es ligero. 1 vCPU y 2 GB de RAM cubren la instancia de búsqueda por sí sola. En Hetzner, el nivel optimizado en costo [CX23](https://go.bitdoze.com/hetzner) (2 vCPU, 4 GB a 5,49 €/mes más 0,50 € por la dirección IPv4, precios de octubre de 2026) es más que suficiente para SearXNG más el propio OpenClaw. Esos planes han estado agotados a veces, así que consulta las [tablas de precios de Hetzner Cloud](/es/hetzner-cloud-precios-2026/) para verificar disponibilidad antes de pedir.

<Button text="Autoaloja SearXNG con Docker" link="/es/searxng-busqueda-privada-autoalojada/" variant="solid" color="green" size="md" icon="arrow-right" />

El recorrido completo, incluido el cambio en `settings.yml` para la salida JSON y las notas de copias de seguridad, está en la guía de [autoalojar SearXNG con Docker](/es/searxng-busqueda-privada-autoalojada/).

### Brave Search: la elección para producción

Brave Search es la opción por defecto con API. Obtienes una API oficial en lugar de scraping: filtros de frescura (`freshness`, `date_after`/`date_before` en modo `llm-context`), segmentación por país e idioma, y ningún riesgo de detección de bots.

El precio pasó a un modelo de créditos prepagados. Según la documentación de OpenClaw, cada plan incluye 5 $/mes en crédito gratuito renovable, y el plan Search cuesta 5 $ por cada 1.000 peticiones, así que el crédito cubre aproximadamente 1.000 consultas/mes. La página de marketing de Brave cita una cifra mensual más alta; revisa tu panel de Brave antes de presupuestar sobre cualquier número. Las cuentas antiguas del plan gratuito original de 2.000 consultas/mes siguen siendo respetadas.

Cambiar a Brave (o volver a él):

```json5
{
  plugins: { entries: { brave: { config: { webSearch: { apiKey: "YOUR_BRAVE_API_KEY" } } } } },
  tools: { web: { search: { provider: "brave" } } },
}
```

O sáltate el archivo de configuración y exporta `BRAVE_API_KEY` en el entorno del gateway. Ten en cuenta que `apiKey` ya no vive bajo `tools.web.search`. La ruta antigua de guías anteriores (incluida la versión previa de esta) ahora es incorrecta.

Si usas el stack MiniMax/GLM, la misma configuración de proveedor aplica en la [guía de configuración de NanoBot con Brave Search](/es/guia-configuracion-nanobot/).

### Búsqueda web de Ollama y Tavily

Dos opciones integradas más que vale la pena conocer:

- **Ollama Web Search** no requiere clave a través de tu propia instancia de Ollama (inicia sesión con `ollama signin`), u hospedado vía `OLLAMA_API_KEY` con `plugins.entries.ollama.config.webSearch.baseUrl: "https://ollama.com"`. Si ya estás [ejecutando OpenClaw con Ollama](/es/openclaw-ollama-modelos-locales/) para modelos locales, esto te da búsqueda sin clave en el mismo stack. ¿Aún no tienes Ollama? [Ollama con Docker Compose y Open WebUI](/es/ollama-docker-instalacion/) es la vía de instalación más rápida.
- **Tavily** se distribuye como `@openclaw/tavily-plugin` con `TAVILY_API_KEY`. Proporciona `tavily_search` y `tavily_extract` (obtener el contenido de las páginas después de una búsqueda es realmente útil para agentes), con un tiempo de espera de búsqueda de 30 segundos. Los créditos del nivel gratuito se citan comúnmente en 1.000/mes, aunque no he verificado la cifra actual.

Exa, Parallel y Firecrawl también son proveedores integrados, y `x_search` (publicaciones de X) y `web_fetch` existen como herramientas separadas además de `web_search`. [Perplexity](https://go.bitdoze.com/perplexity) es otro proveedor integrado si prefieres respuestas sintetizadas por IA con citas en lugar de enlaces sin procesar. Si prefieres pagar por una API de búsqueda dedicada para agentes, [TinyFish](https://go.bitdoze.com/tinyfish) ofrece APIs de búsqueda web y fetch detrás de una sola clave.

## Migrar desde el antiguo parche manual de web-search.ts

<Notice type="info" title="¿Vienes de la Guía Anterior?">
Si seguiste la primera versión de este artículo (o cualquier parche casero de <code>web-search.ts</code>), esa vía de código ya no existe. La búsqueda web se movió a la arquitectura de plugins. Así es como dejarlo limpio.
</Notice>

1. **Revierte o elimina tus ediciones manuales.** El archivo `~/.openclaw/openclawd/src/agents/tools/web-search.ts` ya no existe. Si clonaste o bifurcaste el árbol de código fuente para parchearlo, haz `git pull` o reinstala OpenClaw para volver a un árbol limpio.
2. **Instala el plugin oficial** con `openclaw plugins install @openclaw/duckduckgo-plugin` (ver la sección de instalación más arriba).
3. **Establece el proveedor** en `"duckduckgo"` en `~/.openclaw/openclaw.json`. Recuerda que el archivo de configuración se movió desde `~/.openclaw/config.json`. Si tus ajustes «dejaron de aplicarse» por la época en que actualizaste OpenClaw, este es el motivo.
4. **Verifica** con la lista de comprobación de arriba.

La reversión es trivial: vuelve a poner `tools.web.search.provider` en `"brave"` (o lo que usaras antes). El plugin de DuckDuckGo puede quedarse instalado sin usar.

Una nota histórica: existió un fork de la comunidad (`jokelord/openclaw-local-model-tool-calling-patch`) con DuckDuckGo preimplementado. Su último push fue el 06/02/2026, antes de que existiera el plugin oficial. No lo uses.

## Solución de problemas de la búsqueda DuckDuckGo en OpenClaw

### "DuckDuckGo returned a bot-detection challenge"

Este es el error esperado número uno en IP de centros de datos. DuckDuckGo sirvió una página CAPTCHA en lugar de resultados, y la detección de firma del plugin la capturó. Las mitigaciones de arriba (caché, menor frecuencia, IP residencial) reducen la frecuencia con la que lo ves; no lo eliminan. El fallo es intermitente. Una consulta que falla ahora puede tener éxito en cinco minutos.

### Resultados vacíos o ausentes

Tres causas habituales:

1. **Deriva en la estructura HTML.** DuckDuckGo cambió su marcado y el analizador (aún marcado como experimental) ya no coincide. Revisa `openclaw plugins list` para ver el estado del plugin y actualízalo.
2. **Caché obsoleta.** Un conjunto de resultados vacío puede quedarse en la caché de 15 minutos. Espera a que expire o reinicia el gateway para limpiar la caché en el proceso.
3. **`count` por encima de lo disponible.** Pedir 10 resultados en una consulta con 4 resultados reales devuelve menos de 10. Eso no es un bug.

### DuckDuckGo nunca se selecciona automáticamente

Esto confunde a la gente. La detección automática de proveedor de OpenClaw solo considera proveedores con credenciales utilizables, así que un proveedor sin clave nunca se elige solo. Instalar el plugin no es suficiente. Debes establecer `tools.web.search.provider` en `"duckduckgo"` explícitamente:

```bash
openclaw config get tools.web.search.provider   # if this is not "duckduckgo", that's your problem
openclaw config set tools.web.search.provider "duckduckgo"
```

### Configuración no aplicada / plugin no encontrado

Revisa esto en orden:

- **Ruta de configuración incorrecta.** El archivo ahora es `~/.openclaw/openclaw.json`, no `~/.openclaw/config.json`. Si `OPENCLAW_CONFIG_PATH` está definida en el entorno del gateway, ese es el archivo que se lee.
- **Error de sintaxis JSON5.** Los comentarios y las comas finales están bien, pero todo lo demás debe parsear. Un archivo de configuración roto hace que OpenClaw vuelva a los valores por defecto en silencio.
- **Versión demasiado antigua.** El plugin necesita OpenClaw 2026.3.x o superior para la arquitectura de extensiones. `openclaw --version` te dice dónde estás.
- **Reinicio pendiente.** Si el plugin aparece como instalado pero la búsqueda sigue dando errores, ejecuta `openclaw gateway restart` y prueba de nuevo.

## Preguntas frecuentes

<Accordion label="¿Es gratuita la búsqueda DuckDuckGo con OpenClaw?" group="faq" expanded="false">
Sí. Sin clave API ni cuenta, y nada que pagar. El plugin hace scraping del endpoint HTML público de DuckDuckGo, así que el costo es confiabilidad en lugar de dinero: en una IP de centro de datos te encontrarás con páginas de desafío anti-bot parte del tiempo. En una IP residencial normalmente va bien para uso personal.
</Accordion>

<Accordion label="¿Puedo usar Brave y DuckDuckGo a la vez?" group="faq" expanded="false">
Sí. Ambos plugins pueden permanecer instalados. Cambia entre ellos en cualquier momento poniendo `tools.web.search.provider` en `"brave"` o `"duckduckgo"`. Ten en cuenta que la detección automática nunca selecciona DuckDuckGo por sí sola, así que «ambos» realmente significa «cambiar explícitamente cuando quieras el otro».
</Accordion>

<Accordion label="¿Esto va contra los Términos de Servicio de DuckDuckGo?" group="faq" expanded="false">
El plugin es oficial por parte de OpenClaw y está marcado como experimental. Consulta el endpoint HTML públicamente accesible de DuckDuckGo, el mismo que usa un navegador sin JavaScript. Para uso intensivo o comercial, la propia documentación de OpenClaw recomienda un proveedor con API como Brave Search. Es un buen consejo.
</Accordion>

<Accordion label="¿Cómo vuelvo a Brave?" group="faq" expanded="false">
Establece el proveedor y dale a Brave su clave. La clave va ahora en la configuración del plugin, no bajo `tools.web.search`:

```json5
{
  plugins: { entries: { brave: { config: { webSearch: { apiKey: "YOUR_BRAVE_API_KEY" } } } } },
  tools: { web: { search: { provider: "brave" } } },
}
```

O exporta `BRAVE_API_KEY` en el entorno del gateway y simplemente pon `tools.web.search.provider` en `"brave"`.
</Accordion>

<Accordion label="¿Funcionará esto con futuras versiones de OpenClaw?" group="faq" expanded="false">
El plugin se versiona al mismo ritmo que OpenClaw, así que actualízalo junto con el gateway: `openclaw plugins install @openclaw/duckduckgo-plugin@latest`. Si DuckDuckGo cambia su HTML y los resultados quedan vacíos, la corrección llega al plugin (revisa el changelog de `extensions/duckduckgo` en el repo), no al código que mantienes tú. Ese es precisamente el objetivo de abandonar el parche manual.
</Accordion>
