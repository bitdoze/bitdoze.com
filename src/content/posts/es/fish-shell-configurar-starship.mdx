El prompt de Starship combinado con Fish Shell es una de las configuraciones de terminal más limpias que puedes usar. Starship es un prompt multi-shell escrito en Rust que funciona con Fish, Zsh, Bash, PowerShell y otros, así que puedes mantener la misma configuración de prompt sin importar en qué shell termines. Actualizado para Starship v1.27.0, octubre de 2026.

Starship es rápido, la configuración vive en un solo archivo TOML y muestra la información que necesitas (rama de git, versiones de lenguajes, duración del comando) sin saturar el prompt. Fish está en la versión 4.9.x (4.9.3 a septiembre de 2026) y el flujo de trabajo con `config.fish` no ha cambiado respecto a las versiones 4.x anteriores.

Anteriormente escribí una guía sobre [Starship con Ghostty y Zsh](/es/terminal-starship-ghostty/). La configuración con Fish sigue los mismos principios, pero la línea de inicialización va en un archivo de configuración diferente.

## Novedades de Starship (actualización 2026)

Si configuraste Starship a principios de 2026 o antes, hay algunos cambios que conviene conocer:

- Starship v1.27.0 (octubre de 2026) corrige avisos de seguridad. Si instalaste Starship antes de octubre de 2026, actualiza a v1.27.0 o posterior. Detalles en el aviso de actualización de abajo.
- La integración con la statusline de Claude Code llegó en v1.25.0. Starship puede renderizar tu statusline de Claude Code con el nombre del modelo, el uso de la ventana de contexto y el coste de la sesión. Se cubre en su propia sección más abajo.
- `apt install starship` ahora funciona en Ubuntu 25.04+ y Debian 13+. El paquete snap ya no es una vía de instalación documentada.
- Los módulos de Jujutsu VCS (`jj_bookmark`, `jj_change`, `jj_status` y más) llegaron en v1.27.0.
- El módulo de Maven se añadió en v1.25.0, y el módulo genérico `vcs` ahora funciona en distintos sistemas de control de versiones.

<Notice type="warning" title="Actualiza a v1.27.0">
Si instalaste Starship antes de octubre de 2026, reinstala o actualiza a v1.27.0 o posterior. Corrige avisos de seguridad relacionados con el manejo de comandos de git. Volver a ejecutar el script de instalación reemplaza el binario antiguo:

```bash
curl -sS https://starship.rs/install.sh | sh
```

Si lo instalaste con un gestor de paquetes, actualiza a través de ese (`sudo apt upgrade starship`, `brew upgrade starship` o `cargo install starship --locked`). Después comprueba con `starship --version`. Deberías ver v1.27.0 o posterior.
</Notice>

## Requisitos previos

Antes de empezar, asegúrate de tener lo siguiente:

<ListCheck>
<ul>
<li>Fish Shell 4.x instalado. Consulta mi <a href="/es/instalar-fish-shell-ubuntu/">guía de instalación de Fish Shell para Ubuntu</a> si la necesitas</li>
<li>Un emulador de terminal (Ghostty, WezTerm, kitty, Alacritty o similar)</li>
<li>Una Nerd Font instalada y seleccionada en tu terminal (ver abajo)</li>
<li>Familiaridad básica con la edición de archivos de configuración en `~/.config/`</li>

Esta guía está dirigida a Linux (Ubuntu/Debian) y macOS. Los comandos funcionan igual en ambos salvo que se indique lo contrario.

### Instalar una Nerd Font

Starship usa glifos especiales para sus iconos. Sin una Nerd Font aparecen como cuadros rotos. Recomiendo **MesloLGS Nerd Font** (Nerd Fonts v3.5.1 a agosto de 2026).

En Ubuntu o Debian:

```bash
# Descargar e instalar
mkdir -p ~/.local/share/fonts
cd ~/.local/share/fonts
curl -fLO https://github.com/ryanoasis/nerd-fonts/releases/latest/download/Meslo.tar.xz
tar -xf Meslo.tar.xz
fc-cache -fv
```

Verifica que la fuente esté registrada:

```bash
fc-list | grep -i meslo
```

Deberías ver una o más entradas de Meslo. Si la salida está vacía, la descarga o la extracción fallaron. Comprueba que `Meslo.tar.xz` se extrajo correctamente.

En macOS con Homebrew:

```bash
brew install font-meslo-lg-nerd-font
```

Después de instalarla, configura la fuente en los ajustes de tu emulador de terminal. En Ghostty, agrega esto a tu configuración:

```
font-family = MesloLGS Nerd Font
```

Para otros terminales ([WezTerm](/es/instalar-wezterm-mac/), Alacritty, kitty, etc.), consulta su documentación para la opción de configuración de fuentes.

## Instalar Starship

El método de instalación recomendado funciona en todas partes:

```bash
curl -sS https://starship.rs/install.sh | sh
```

O usa un gestor de paquetes:

```bash
# Ubuntu 25.04+ / Debian 13+
sudo apt install starship

# macOS
brew install starship

# Cargo (requires Rust toolchain)
cargo install starship --locked
```

En otras distribuciones: `apk add starship` (Alpine 3.13+), `pacman -S starship` (Arch/Manjaro), o `dnf copr enable atim/starship` y luego `dnf install starship` (Fedora 40+/CentOS 7+). El paquete snap ya no es una vía de instalación documentada. Usa el script de instalación o tu gestor de paquetes en su lugar.

Verifica la instalación:

```bash
starship --version
```

Deberías ver `starship 1.27.0` o posterior.

<Notice type="info" title="No hay comando de autoactualización">
Starship no puede actualizarse a sí mismo. Para actualizar, vuelve a ejecutar el script de instalación (instala sobre el binario existente en `/usr/local/bin`) o usa tu gestor de paquetes (`sudo apt upgrade starship`, `brew upgrade starship`).
</Notice>

Si el script de instalación no puede escribir en `/usr/local/bin`, te pedirá sudo. Si `starship` no se encuentra después de la instalación, comprueba que `/usr/local/bin` esté en tu `$PATH`.

## Agregar Starship a Fish Shell

Agrega una línea al final de tu configuración de Fish:

```fish
# ~/.config/fish/config.fish
starship init fish | source
```

Eso es todo. Abre una nueva terminal o ejecuta `source ~/.config/fish/config.fish` y deberías ver el prompt de Starship.

<Notice type="info" title="El orden importa">
Coloca la línea `starship init fish | source` al final de tu `config.fish`, después de cualquier otra configuración. Esto asegura que Starship cargue de último y pueda configurar el prompt correctamente.
</Notice>

Fish 4.x sigue usando `~/.config/fish/config.fish` como su archivo de configuración principal, sin cambios respecto a versiones anteriores. Si el prompt no aparece, consulta la sección de solución de problemas más abajo.

## Elegir un preset de Starship

Starship incluye 12 presets oficiales que cambian la apariencia de tu prompt. Enuméralos todos:

```bash
starship preset --list
```

Explora vistas previas en [starship.rs/presets](https://starship.rs/presets/). Aplicar un preset:

```bash
starship preset tokyo-night -o ~/.config/starship.toml
```

Si `~/.config/starship.toml` ya existe, las versiones actuales se niegan a sobrescribirlo sin el flag `-f`:

```bash
# Force overwrite an existing config
starship preset tokyo-night -o ~/.config/starship.toml -f
```

Presets populares:

- `tokyo-night` es un tema oscuro con tonos púrpura/azul.
- `catppuccin-powerline` es el preset oficial de Catppuccin estilo powerline. Otras variantes de Catppuccin están en el repo de la comunidad `catppuccin/starship` y se aplican copiando el TOML, no con `starship preset`.
- `gruvbox-rainbow` usa colores retro cálidos con fondos por segmento.
- `nerd-font-symbols` reemplaza las etiquetas de texto con iconos de Nerd Font.
- `plain-text-symbols` no usa caracteres especiales y funciona sin Nerd Fonts.
- `pastel-powerline` usa segmentos powerline en tonos pastel suaves.
- `pure-preset` imita el popular prompt Pure.
- `bracketed-segments` envuelve cada módulo entre corchetes.

<Notice type="warning" title="Las sobrescrituras de presets ahora son seguras">
Las versiones actuales de Starship se niegan a destruir un `starship.toml` existente a menos que pases `-f`. Starship también escribe la salida de forma atómica (desde v1.26.0), así que no acabarás con una configuración escrita a medias. Aun así, haz una copia de seguridad de tu configuración antes de forzar la sobrescritura si la has personalizado.
</Notice>

Después de aplicar un preset, abre una nueva terminal y confirma que la apariencia del prompt cambió. Si ves `Error saving file, use --force to overwrite existing configuration file`, elige un destino `-o` diferente o añade `-f` para reemplazar tu configuración actual.

## Configurar Starship con starship.toml

Starship lee su configuración de `~/.config/starship.toml`. Si el archivo no existe, Starship usa valores por defecto razonables. Esta es una configuración práctica que muestra información relevante sin saturar:

```toml
# ~/.config/starship.toml

# Configuración general
format = """
$directory\
$git_branch\
$git_status\
$nodejs\
$python\
$rust\
$golang\
$docker_context\
$cmd_duration\
$line_break\
$character"""

# No agregar línea en blanco entre prompts
add_newline = false

[directory]
truncation_length = 3
truncate_to_repo = true

[git_branch]
format = "[$symbol$branch]($style) "
symbol = " "

[git_status]
format = '([$all_status$ahead_behind]($style) )'

[nodejs]
format = "[$symbol($version)]($style) "
symbol = " "

[python]
format = "[$symbol($version)]($style) "
symbol = " "

[rust]
format = "[$symbol($version)]($style) "
symbol = " "

[golang]
format = "[$symbol($version)]($style) "
symbol = " "

[docker_context]
format = "[$symbol$context]($style) "
symbol = " "

[cmd_duration]
min_time = 2_000
format = "[$duration]($style) "

[character]
success_symbol = "[❯](green)"
error_symbol = "[❯](red)"
```

### Qué hace cada sección

**format** controla qué módulos aparecen y en qué orden. Solo se muestran los módulos listados aquí. Si un módulo no está en `format`, no se renderizará sin importar su configuración.

**directory** muestra la ruta actual. `truncation_length = 3` significa que ves como máximo 3 directorios padre. `truncate_to_repo = true` muestra la ruta completa desde la raíz del repositorio git en lugar de una abreviatura relativa.

**git_branch** y **git_status** muestran el nombre de tu rama y si tienes cambios sin confirmar, conteos de adelante/atrás, etc. En repositorios muy grandes `git_status` puede ser lento. Consulta la sección de solución de problemas para saber cómo diagnosticarlo antes de desactivarlo.

**Módulos de lenguajes** (nodejs, python, rust, golang) solo aparecen cuando estás en un proyecto que usa ese lenguaje. Lo detectan buscando archivos marcador: `package.json` para Node.js, `pyproject.toml` para Python, `Cargo.toml` para Rust y similares. Si aún no tienes Node.js instalado, consulta mi guía para [instalar Node.js con NVM](/es/instalar-nodejs-nvm-macos-ubuntu/).

**cmd_duration** muestra cuánto tardó el último comando, pero solo si tardó más de 2 segundos (el umbral de `min_time`). Útil para detectar comandos lentos.

**character** muestra un `❯` verde en caso de éxito y un `❯` rojo después de un comando fallido.

## Extra: Starship como statusline de Claude Code

<Notice type="success" title="Nuevo en Starship v1.25.0">
Starship puede renderizar la statusline dentro de Claude Code, mostrando el nombre del modelo, el uso de la ventana de contexto y el coste de la sesión. Esto llegó en v1.25.0 (abril de 2026) y el módulo del modelo ganó una variable `effort` en v1.27.0.
</Notice>

Si usas Claude Code para desarrollo asistido por IA, Starship puede reemplazar la statusline por defecto con una más completa. Añade esto a `~/.claude/settings.json`:

```json
{
  "statusLine": {
    "type": "command",
    "command": "starship statusline claude-code"
  }
}
```

Personaliza los módulos de la statusline en `starship.toml`:

```toml
[profiles]
claude-code = "$claude_model$git_branch$claude_context$claude_cost"

[claude_model]
format = "[$symbol$model]($style) "
symbol = "🤖 "
style = "bold blue"

[claude_context]
format = "[$gauge $percentage]($style) "
gauge_width = 10
```

Los tres módulos dedicados son:

- `claude_model` muestra el nombre del modelo (con una variable `effort` en v1.27.0+).
- `claude_context` muestra un indicador de la ventana de contexto con cuánto de la ventana has usado.
- `claude_cost` muestra el coste de la sesión y estadísticas de tokens.

También puedes ejecutar `/statusline` dentro de Claude Code y pedirle que configure Starship por ti. Conoce esta integración.

Para verificar, abre Claude Code y comprueba que la statusline se renderiza en la parte inferior del panel con el nombre del modelo y el indicador de contexto. Si la statusline está en blanco, asegúrate de que `starship` esté en tu `$PATH` (Claude Code ejecuta el comando en su propio shell).

Esto combina bien con los flujos de trabajo de codificación con IA que cubro en mi recopilación de [las mejores herramientas y agentes de codificación con IA](/es/herramientas-codificacion-ia/). Si ejecutas Claude Code dentro de un espacio de trabajo de terminal dedicado, vale la pena ver la guía del [terminal cmux para agentes de codificación con IA](/es/terminal-cmux/). Y si alternas entre Claude Code y otros agentes de codificación, herramientas como [Agent Router](https://go.bitdoze.com/agentrouter) mantienen todo unificado.

## Starship vs Tide para Fish Shell

Si usas Fish, tienes dos buenas opciones de prompt:

| | Starship | Tide |
|---|---|---|
| Funciona con | Fish, Zsh, Bash, etc. | Solo Fish |
| Configuración | Archivo TOML | Asistente interactivo |
| Renderizado asíncrono | No (pero lo suficientemente rápido) | Sí |
| Instalación | Binario separado | Plugin de Fisher |
| Necesita Nerd Font | Sí (para la mayoría de presets) | Sí |
| Personalización | Editar `starship.toml` | `tide configure` + variables |

**Elige Starship si** usas múltiples shells y quieres una sola configuración de prompt, o si prefieres editar un archivo de configuración directamente.

**Elige Tide si** solo usas Fish y quieres renderizado asíncrono con una configuración basada en asistente. Instala Tide con Fisher:

```fish
fisher install IlanCosman/tide@v6
tide configure
```

Una cosa a tener en cuenta: la última versión de Tide es v6.2.0 (agosto de 2025), una cadencia más lenta que el calendario de lanzamientos de Starship (cuatro versiones solo en 2026). Si una dependencia que avanza despacio te molesta, es un punto a favor de Starship.

Hablo de Tide y otras herramientas de Fish en [los mejores plugins y herramientas para Fish Shell](/es/mejores-plugins-fish-shell/). Para una comparación completa de todas las opciones de prompt para Fish incluyendo Tide, Pure e Hydro, consulta mi [guía de temas y prompts de Fish Shell](/es/fish-shell-temas-prompts/).

Ambas son buenas opciones. Yo uso Starship porque a veces trabajo con Zsh o Bash en otras máquinas y quiero el mismo prompt en todas partes.

## Configuración avanzada

Estos consejos asumen que ejecutas Fish directamente. Si estás dentro de tmux o Zellij, consulta mi guía de [los mejores multiplexores de terminal](/es/mejores-multiplexores-terminal/). El renderizado del prompt y el comportamiento de redibujado pueden diferir dentro de un multiplexor.

### Prompt del lado derecho

Starship soporta un prompt derecho que aparece en el borde derecho de tu terminal:

```toml
# En starship.toml
right_format = """$time"""

[time]
disabled = false
format = "[$time]($style)"
time_format = "%H:%M"
```

Esto muestra la hora actual en el lado derecho. El soporte de prompt derecho de Fish funciona bien con esto.

### Módulos personalizados

Puedes definir módulos personalizados que ejecutan comandos de shell. Una trampa importante: las entradas `command` personalizadas se ejecutan bajo `/bin/sh` por defecto, no Fish. Los builtins de Fish como `string split` no funcionarán.

Aquí un ejemplo funcional que muestra tu versión de Fish usando `awk` (compatible con POSIX):

```toml
[custom.fish_version]
command = "fish --version | awk '{print $3}'"
when = "true"
format = "[fish $output]($style) "
style = "cyan"
```

Si necesitas builtins o funciones de Fish, declara Fish como el shell:

```toml
[custom.fish_version]
command = "fish --version | string split ' ' | tail -1"
shell = ["fish", "-c"]
when = "true"
format = "[fish $output]($style) "
style = "cyan"
```

O escribe una función de Fish y llámala desde el comando personalizado. Consulta [funciones y comandos personalizados en Fish Shell](/es/fish-shell-funciones-comandos-personalizados/) para saber cómo crearlas. Si el módulo no muestra nada en tu prompt, ejecuta `starship explain` para ver si el módulo personalizado se renderizó y qué salida produjo.

### Configuración por directorio

Starship no tiene configuración por directorio de forma nativa, pero puedes lograr algo similar con el sistema `conf.d` de Fish. Crea una función que establezca `STARSHIP_CONFIG` según el directorio actual:

```fish
# ~/.config/fish/conf.d/starship-dir.fish
function __check_starship_config --on-variable PWD
    if test -f .starship.toml
        set -gx STARSHIP_CONFIG (pwd)/.starship.toml
    else
        set -e STARSHIP_CONFIG
    end
end
```

Ahora cualquier directorio con un archivo `.starship.toml` usará esa configuración en lugar de la global. La variable de entorno `STARSHIP_CONFIG` sigue siendo compatible y es la forma correcta de apuntar Starship a una configuración alternativa.

## Solución de problemas de Starship en Fish

Cuando algo parezca ir mal, diagnostica antes de empezar a desactivar módulos. Starship tiene tres herramientas de depuración integradas:

```bash
# Show which modules rendered and why
starship explain

# Print per-module render times (find the slow one)
starship timings

# Dump the computed config (catch typos in starship.toml)
starship print-config
```

<Accordion label="Los iconos aparecen como cuadros o signos de interrogación" group="troubleshooting" expanded="true">
Necesitas una Nerd Font instalada y seleccionada en tu terminal. Ejecuta `fc-list | grep -i meslo` (Linux) para confirmar que la fuente está registrada, luego revisa la configuración de fuente de tu emulador de terminal. Si estás en una máquina remota, la fuente debe estar instalada en la máquina donde corre el emulador de terminal, no en el servidor remoto.
</Accordion>

<Accordion label="El prompt va lento" group="troubleshooting">
Ejecuta `starship timings` primero. Muestra qué módulos tardan más de 1 ms en renderizarse. El estado de git en repositorios muy grandes es el culpable habitual. Si un módulo es lento, desactívalo o reduce su alcance:

```toml
[git_status]
disabled = true
```

No desactives módulos a ciegas sin medir primero. Un módulo lento podría activarse solo en directorios específicos.
</Accordion>

<Accordion label="Starship no carga" group="troubleshooting">
Asegúrate de que `starship init fish | source` esté en tu `config.fish` y que `starship` esté en tu `$PATH`. Ejecuta `which starship` para verificar. Si no se encuentra, tu ubicación de instalación (`/usr/local/bin` por defecto) puede no estar en tu `$PATH`. Agrégala a `~/.config/fish/config.fish`:

```fish
set -gx PATH /usr/local/bin $PATH
```

Luego recarga tu configuración o abre una nueva terminal.
</Accordion>

<Accordion label="El comando preset da error con 'use --force'" group="troubleshooting">
Las versiones actuales se niegan a sobrescribir un `starship.toml` existente. Si quieres reemplazar tu configuración, añade `-f`:

```bash
starship preset tokyo-night -o ~/.config/starship.toml -f
```

O escribe en un archivo distinto y combínalo manualmente.
</Accordion>

<Accordion label="El módulo personalizado no muestra nada" group="troubleshooting">
Los comandos personalizados se ejecutan bajo `/bin/sh`, así que los builtins de Fish como `string split` fallarán silenciosamente. Usa comandos compatibles con POSIX (`awk`, `cut`, `grep`) o declara `shell = ["fish", "-c"]` en la configuración del módulo. Ejecuta `starship explain` para ver si el módulo se renderizó y qué salida produjo.
</Accordion>
