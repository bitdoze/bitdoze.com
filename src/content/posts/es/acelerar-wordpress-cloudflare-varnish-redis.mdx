## Cómo funcionan las capas juntas

Cada capa gestiona un tipo de petición distinto:

1. **Cloudflare** — los visitantes llegan primero a Cloudflare. Si la página está en la caché de su CDN, se sirve desde el nodo edge más cercano sin tocar tu servidor.
2. **Varnish** — si la página no está en la caché de Cloudflare (primera visita, tras publicar, contenido dinámico), la petición llega a Varnish en tu servidor. Varnish sirve el HTML cacheado sin ejecutar PHP.
3. **Redis** — cuando Varnish necesita generar una página nueva, PHP habla con Redis para la caché de objetos y consultas en lugar de golpear MySQL repetidamente.

El resultado son cargas rápidas para los visitantes que vuelven y una carga del servidor manejable durante los picos de tráfico.

## Plugins necesarios

Tres plugins gratuitos se encargan de todo:

- **[CLP Varnish Cache](https://wordpress.org/plugins/clp-varnish-cache/)** — le indica a WordPress que purgue Varnish cuando cambia el contenido. Instálalo y actívalo, no necesita configuración.
- **[Redis Object Cache](https://wordpress.org/plugins/redis-cache/)** (v2.7.0) -- conecta WordPress con Redis. Después de activarlo, ve a **Ajustes → Redis** y haz clic en **Enable Object Cache**. También hay una versión de pago (Object Cache Pro) con optimizaciones para WooCommerce y analíticas de caché, pero la versión gratuita funciona bien para la mayoría de los sitios.
- **[Super Page Cache for Cloudflare](https://wordpress.org/plugins/wp-cloudflare-page-cache/)** -- conecta WordPress con la caché de Cloudflare y gestiona la invalidación de la caché al publicar. Alternativa gratuita a Cloudflare APO (5 $/mes).

## Configuración de Varnish en CloudPanel

Activa Varnish para tu sitio en CloudPanel:

En CloudPanel, ve a los ajustes de tu sitio y activa **Varnish Cache**. El plugin CLP Varnish Cache se encarga de la purga automática cuando publicas o actualizas contenido.

## Configuración del plugin de Cloudflare

En los ajustes de **Super Page Cache for Cloudflare**:

1. Añade tu token de API de Cloudflare o la clave Global API
2. Selecciona tu dominio de la lista de zonas
3. Establece el modo de caché en "Standard" y activa la caché de páginas
4. Configura reglas de bypass para el carrito/checkout de WooCommerce si es necesario

El plugin crea una versión en caché de cada página en la CDN de Cloudflare y la purga automáticamente cuando la página cambia.

## Una nota sobre el contenido dinámico

Esta pila funciona bien para contenido mayormente estático: entradas de blog, landing pages, páginas de producto estáticas. Si tienes páginas con contenido por usuario (carrito, datos de usuarios con sesión iniciada, elementos personalizados), asegúrate de configurar reglas de bypass tanto en el plugin de Cloudflare como en los ajustes de Varnish. Servir páginas cacheadas a usuarios con sesión iniciada causa problemas evidentes.

Consulta la [configuración de Varnish Cache en CloudPanel](https://www.bitdoze.com/es/varnish-cache-cloudpanel/) para ver las opciones detalladas de configuración de Varnish.

## Cloudflare APO vs el plugin Super Page Cache

Cloudflare APO (Automatic Platform Optimization) cuesta 5 $/mes y cachea el HTML en el edge de Cloudflare sin necesitar un plugin. Funciona bien pero cuesta dinero. El plugin Super Page Cache for Cloudflare hace prácticamente lo mismo gratis usando la API de Cloudflare. Ambos enfoques cachean páginas completas en Cloudflare y las purgan al publicar.

Si ya pagas Cloudflare Pro (20 $/mes), APO está incluido gratis. Si estás en el plan gratuito de Cloudflare, el plugin Super Page Cache es la mejor opción.

## Cuando esta pila no es suficiente

Esta configuración de tres capas funciona bien para la mayoría de los sitios WordPress. Si aun así topas con límites de rendimiento, los siguientes pasos son:

- Ampliar a un VPS más grande (más núcleos de CPU ayudan con las peticiones no cacheadas)
- Usar una CDN dedicada como BunnyCDN o KeyCDN junto a Cloudflare
- Cambiar a un plugin de caché especializado como FlyingPress o LiteSpeed Cache si tu hosting lo soporta
- Considerar Object Cache Pro si usas WooCommerce con una carga pesada de base de datos
