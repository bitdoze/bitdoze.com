Instalar el último Fish Shell en Ubuntu significa usar el PPA oficial, porque los repositorios propios de Ubuntu traen versiones antiguas. Ubuntu 24.04 LTS sigue con fish 3.7.0, e incluso la recién llegada 26.04 lleva la 4.2.1. La última versión estable de Fish es **4.9.3** (lanzada el 8 de septiembre de 2026). El PPA del equipo de Fish te da la versión actual en tres comandos. Esta guía cubre instalaciones en escritorio y en VPS/servidor, el cambio de shell predeterminado sin riesgos, configuración, plugins y los detalles que le fallan a la gente en producción.

Si estás en Mac, mira mi [guía de configuración de Fish Shell en macOS](/es/fish-shell-macos-configuracion/) en su lugar.

## Instalar Fish Shell en Ubuntu desde el PPA oficial

El equipo de Fish mantiene un PPA en Launchpad que sigue la última versión estable. Añádelo, actualiza e instala:

```bash
sudo add-apt-repository ppa:fish-shell/release-4
sudo apt update
sudo apt install fish
```

(`apt-add-repository` también funciona: es un alias antiguo de `add-apt-repository`.)

Verifica que se instaló correctamente:

```bash
fish --version
```

Deberías ver `fish, version 4.9.3`. Ahora confirma que el paquete viene del PPA y no de los repos de Ubuntu:

```bash
apt policy fish
```

La línea candidata debería mostrar `ppa.launchpadcontent.net/fish-shell/release-4/...` como origen. Si muestra el archivo de Ubuntu, el PPA no se añadió bien o `apt update` no se ha ejecutado. Mira la sección de problemas más abajo.

Por qué importa el PPA: una comparación rápida de lo que trae cada fuente:

| Versión de Ubuntu | Repos de Ubuntu | PPA oficial |
|---|---|---|
| 24.04 LTS (noble) | 3.7.0 | 4.9.3 |
| 25.10 (questing) | 4.0.6 | 4.8.0 |
| 26.04 (resolute) | 4.2.1 | 4.9.3 |

Incluso la versión más reciente de Ubuntu va meses por detrás del PPA. Si quieres fish actual, usa el PPA.

<ListCheck>
<ul>
<li><code>fish --version</code> muestra <code>fish, version 4.9.3</code></li>
<li><code>apt policy fish</code> muestra la URL del PPA como origen (<code>ppa.launchpadcontent.net</code>)</li>
</ul>
</ListCheck>

<Notice type="info" title="Soporte de versiones de Ubuntu">
El PPA publica builds para Ubuntu 20.04, 22.04 LTS, 24.04 LTS, 24.10, 25.04, 25.10 y 26.04. Las versiones LTS actuales (22.04, 24.04, 26.04) reciben las builds más nuevas (4.9.3-1 a septiembre de 2026). Las versiones antiguas e intermedias van por detrás: 20.04 recibe la 4.1.1, 24.10 la 4.0.2, 25.04 la 4.3.3, 25.10 la 4.8.0. Ubuntu 23.04 y 23.10 están en fin de vida y no tienen builds en el PPA. Para versiones sin soporte, mira la sección del binario independiente más abajo.
</Notice>

## Novedades de Fish Shell 4.6 a 4.9

Si vienes de fish 4.5 o anterior, esto es lo que cambió en las cuatro versiones con novedades desde entonces. Es una lista de destacados, no un changelog. Mira la [página de releases en GitHub](https://github.com/fish-shell/fish-shell/releases) para todo.

<Accordion label="Destacados de Fish 4.6 a 4.9" group="whats-new" expanded="false">

- **4.6.0**: fish acepta `|&` (forma compatible con Bash de redirigir stdout y stderr juntos, junto al propio `&|` de fish). Soporta las variables de entorno `SHELL_PROMPT_PREFIX`, `SHELL_PROMPT_SUFFIX` y `SHELL_WELCOME` (las pone `run0` de systemd). El ancho por defecto de los emoji ahora es 2. Pon `$fish_emoji_width` a 1 si las líneas se desalinean en tu terminal.

- **4.7.0**: Los shells no interactivos ya no establecen las variables del tema por defecto (`fish_color_*`). El historial ya no se corrompe con bytes NUL al recibir SIGTERM/SIGHUP. `fish_update_completions` maneja los escapes groff más nuevos.

- **4.8.0**: `cd` soporta los flags `-L` y `-P` (resolución de ruta lógica vs física). Las abreviaturas ganaron `--position=command|anywhere`, `--regex`, `--command`, `--set-cursor` y `--function`. Ruta de actualización más limpia: fish ya no crea la variable universal `__fish_initialized` ni te suelta un `fish_frozen_theme.fish` sorpresa en tu `conf.d/` al actualizar desde valores de la era 3.x.

- **4.9.x**: Las abreviaturas pueden llevar una **descripción** que se muestra en el paginador de completados (`abbr -a --description "git status" gst git status`). Completado con tab más rápido en directorios con symlinks lentos (montajes de red, home en NFS). Workaround del protocolo kitty-keyboard de Konsole.

</Accordion>

## Probar Fish sin cambiar tu shell predeterminado

No tienes que comprometerte de inmediato. Solo escribe:

```bash
fish
```

Esto te pone en una sesión de Fish. Obtienes [autosugerencias](/es/fish-shell-autocompletado-sugerencias/), [resaltado de sintaxis](/es/fish-shell-resaltado-sintaxis/) y completado con tab de inmediato. Pruébalo. Escribe algunos comandos. Si no te gusta, escribe `exit` y vuelves a Bash.

## Establecer Fish como tu shell predeterminado en Ubuntu

Cuando estés listo para dar el paso, usa el flujo recomendado por la documentación oficial de fish. Primero asegúrate de que fish aparece en `/etc/shells`, y después cambia tu shell de login:

```bash
command -v fish | sudo tee -a /etc/shells
chsh -s "$(command -v fish)"
```

La forma `$(command -v fish)` es a prueba de rutas: funciona independientemente de dónde esté instalado fish. El `/usr/bin/fish` fijo también vale para las builds del PPA, pero la forma dinámica no se rompe si luego cambias a un binario independiente o a otro prefijo de instalación.

Cierra sesión y vuelve a iniciarla (o abre una nueva terminal). Verifica el cambio:

<ListCheck>
<ul>
<li><code>echo $SHELL</code> muestra <code>/usr/bin/fish</code></li>
<li><code>getent passwd $USER</code> muestra fish como tu shell de login</li>
</ul>
</ListCheck>

Para volver a Bash después:

```bash
chsh -s /usr/bin/bash
```

<Notice type="warning" title="Trampa del PATH en el shell de login">
Fish no lee <code>/etc/profile</code> ni <code>/etc/profile.d/</code>. Si herramientas como nvm, SDKman o scripts de login corporativos configuran tu PATH mediante perfiles de login, acabarás con un PATH incompleto tras cambiar a fish. Tienes dos opciones: replicar la configuración del PATH en <code>~/.config/fish/config.fish</code> usando <code>fish_add_path</code> (mira mi guía de [NVM con Fish Shell](/es/nvm-fish-shell/) para el caso de nvm), o dejar Bash como shell de login y apuntar tu emulador de terminal a fish solo para uso interactivo. En servidores donde los scripts de login componen el PATH, esa segunda opción es el predeterminado más seguro.
</Notice>

<Notice type="warning" title="Mantén Bash instalado">
No elimines Bash. Muchos scripts del sistema dependen de él, y lo vas a necesitar para ejecutar scripts de shell POSIX. Fish reemplaza tu shell interactivo, no el intérprete de scripts del sistema. Si todavía estás comparando shells, mi comparación de [Fish Shell vs Bash vs Zsh](/es/fish-shell-vs-bash-vs-zsh-comparacion/) cubre los compromisos.
</Notice>

## Instalar Fish Shell desde los binarios independientes

Si tu versión de Ubuntu no está en la lista de soporte del PPA (versiones en fin de vida como 23.04/23.10, o setups muy antiguos), o prefieres no añadir un repo de terceros en un servidor bloqueado, el proyecto fish publica builds estáticos de Linux en las releases de GitHub. Para la 4.9.3 son `fish-4.9.3-linux-x86_64.tar.xz` (~3,2 MB) y `fish-4.9.3-linux-aarch64.tar.xz` (~2,9 MB).

<Notice type="info" title="Cuándo usar esto">
El binario independiente es un plan B. Para la mayoría de usuarios el PPA (arriba) es la mejor vía: se integra con apt, recibe actualizaciones de seguridad y gestiona las dependencias. Usa las builds estáticas cuando el PPA no cubre tu versión o no puedes añadir repositorios de terceros.
</Notice>

Descarga y extrae:

```bash
# Para x86_64
wget https://github.com/fish-shell/fish-shell/releases/download/4.9.3/fish-4.9.3-linux-x86_64.tar.xz
# Para aarch64 (ARM64)
# wget https://github.com/fish-shell/fish-shell/releases/download/4.9.3/fish-4.9.3-linux-aarch64.tar.xz

tar -xf fish-4.9.3-linux-x86_64.tar.xz
```

El directorio extraído contiene el binario de fish y sus archivos de apoyo. Muévelo a un lugar permanente y añádelo a tu PATH:

```bash
sudo mv fish-4.9.3-linux-x86_64 /opt/fish
sudo ln -s /opt/fish/bin/fish /usr/local/bin/fish
fish --version
```

Son builds estáticas oficiales del proyecto fish. No he probado la estructura exacta del tarball en cada versión de Ubuntu. Si el binario no arranca por bibliotecas compartidas que faltan, busca un `README` en el directorio extraído o instala `libpcre2-8-0` y `libcrypt1` desde apt.

## Configuración inicial

El archivo de configuración de Fish se encuentra en `~/.config/fish/config.fish`. El archivo es opcional: fish funciona bien sin él y no lo crea por ti. Créalo cuando quieras ajustes personalizados. Aquí tienes una configuración inicial básica:

```fish
# ~/.config/fish/config.fish

# Agregar rutas personalizadas
fish_add_path ~/bin
fish_add_path ~/.local/bin

# Desactivar el mensaje de bienvenida
set -g fish_greeting

# Establecer tu editor preferido
set -gx EDITOR vim
```

Algunas cosas a tener en cuenta:

- `fish_add_path` es la forma de Fish para agregar directorios a tu `$PATH`. No intentes usar `export PATH=...` como en Bash.
- `set -g` establece una variable global para la sesión actual. `set -gx` además la exporta a los procesos hijos.
- `set -g fish_greeting` sin valor suprime el mensaje predeterminado "Welcome to fish".

### Configuración modular con conf.d

Fish carga cada archivo `.fish` en `~/.config/fish/conf.d/` al iniciar. Esto es más limpio que meter todo en un solo archivo. Por ejemplo, podrías crear:

```fish
# ~/.config/fish/conf.d/aliases.fish
abbr -a gst git status
abbr -a gco git checkout
abbr -a gp git push
```

Cubro las abreviaturas frente a los alias en detalle en [abreviaturas vs alias de Fish Shell](/es/fish-shell-abreviaturas-vs-alias/). En resumen: las abreviaturas de Fish se expanden al comando completo antes de ejecutarse, lo cual es mejor que los alias en la mayoría de casos.

Desde fish 4.8 y 4.9, las abreviaturas pueden hacer más. Puedes adjuntarles una descripción (visible en el paginador de completados) y controlar dónde se expande la abreviatura:

```fish
# Descripción visible cuando la abreviatura aparece en los completados
abbr -a --description "git status" gst git status

# Expandir en cualquier punto de la línea de comandos, no solo al inicio
abbr -a --position anywhere -- -C --color
```

Mira [abreviaturas con descripciones y posiciones personalizadas](/es/fish-shell-abreviaturas-vs-alias/) para el conjunto completo de flags.

## Instalar un gestor de plugins

Fish funciona perfectamente sin plugins, pero un gestor de plugins te permite agregar cosas como mejor integración con git, búsqueda con fzf, y [gestión de versiones de Node](/es/nvm-fish-shell/).

**Fisher** es la opción más popular (v4.4.8, en mantenimiento activo):

```fish
curl -sL https://raw.githubusercontent.com/jorgebucaran/fisher/main/functions/fisher.fish | source && fisher install jorgebucaran/fisher
```

Ahora puedes instalar plugins con `fisher install`. Por ejemplo:

```fish
fisher install PatrickF1/fzf.fish
fisher install jorgebucaran/nvm.fish
```

Si prefieres un framework más opinado en lugar de un instalador ligero, [Oh My Fish (OMF) temas y plugins](/es/oh-my-fish-instalar-temas-plugins/) es la alternativa: tiene su propio sistema de temas y formato de paquetes.

Tengo una guía completa sobre [los mejores plugins y herramientas para Fish Shell](/es/mejores-plugins-fish-shell/) si quieres recomendaciones.

## Configurar tu prompt

Fish viene con un prompt predeterminado decente, pero tienes varias opciones para personalizarlo.

<Tabs>
<Tab name="Temas integrados">
Ejecuta `fish_config` y se abre una ventana del navegador donde puedes elegir entre varios estilos de prompt y esquemas de colores integrados.

Si estás en un servidor remoto por SSH y no puedes abrir un navegador, usa la interfaz de terminal en su lugar:

```fish
fish_config theme show
fish_config theme choose "Solarized Light"
```

`fish_config theme show` lista los temas disponibles directamente en tu terminal. `fish_config theme choose` aplica uno sin necesitar navegador. Este es el flujo a usar en un VPS sin entorno gráfico.
</Tab>
<Tab name="Tide">
Tide es un prompt popular nativo de Fish con un asistente de configuración. Instálalo a través de Fisher:

```fish
fisher install IlanCosman/tide@v6
```

Luego ejecuta `tide configure` para pasar por la configuración. Tide va por la v6.2.1 (noviembre de 2026). El pin `@v6` es correcto y sigue la rama major actual.
</Tab>
<Tab name="Starship">
Starship es un prompt cross-shell escrito en Rust que funciona con Fish, Zsh, Bash y otros. Tengo una guía dedicada sobre [cómo configurar Starship con Fish Shell](/es/fish-shell-configurar-starship/). Si has usado Starship con Zsh antes (como en mi [guía de Starship y Ghostty](/es/terminal-starship-ghostty/)), la configuración con Fish es casi idéntica.
</Tab>
</Tabs>

Para una comparación completa de todas las opciones de prompt de Fish, mira mi [guía de temas y prompts de Fish Shell](/es/fish-shell-temas-prompts/).

## Cosas útiles que conviene saber de entrada

**Búsqueda en el historial de comandos.** Presiona `Ctrl+R` para buscar en tu historial. Fish usa sintaxis glob por defecto, así que `git*commit` coincide con cualquier entrada del historial que contenga "git" seguido después de "commit". La búsqueda no distingue mayúsculas salvo que tu consulta contenga letras mayúsculas. Cubro la gestión del historial en profundidad en mi [guía de historial y persistencia de Fish Shell](/es/fish-shell-historial-persistencia/).

**Autosugerencias.** Mientras escribes, Fish muestra sugerencias en gris basadas en tu historial y los completados disponibles. Presiona la tecla de flecha derecha para aceptar, o `Alt+Right` para aceptar una palabra a la vez.

**Completado con tab.** Fish genera completados a partir de las páginas man automáticamente. Prueba a escribir `git checkout` y presionar tab. Verás nombres de ramas, flags y más sin instalar nada adicional.

**Configuración web.** Ejecuta `fish_config` para abrir una herramienta basada en el navegador para cambiar tus colores, prompt y ver funciones definidas. Es una forma rápida de ver lo que hay disponible.

## Ejecutar Fish en un servidor o VPS

Si quieres fish en un servidor de producción o VPS, hay algunas restricciones que conviene conocer.

**Solo por usuario.** No hagas `chsh` a root ni a cuentas de servicio. Instala fish y cámbiate a él solo para tu login interactivo. Deja a root, `www-data` y cualquier cosa que ejecuten systemd o cron tal como están.

**Los scripts no se ven afectados.** Tener fish como shell interactivo no cambia lo que ejecutan las unidades de systemd, los cron jobs o los pipelines de CI. Esos siguen usando `/bin/sh` o `bash` vía sus shebangs. Tus scripts existentes siguen funcionando exactamente igual.

**Imágenes Docker.** Fish no viene en las imágenes Docker slim ni alpine. Sigue usando `bash -c` o `sh` en Dockerfiles y configs de CI. Mira mi guía de [instalar Docker y Docker Compose en Ubuntu ARM](/es/instalar-docker-ubuntu-arm/) si estás montando contenedores en un servidor.

**Coste.** Todo esto es gratis y open source. El único coste son unos 10 MB de disco para la instalación de fish.

Si estás montando un VPS Ubuntu nuevo para probar esto, [Hetzner Cloud](https://go.bitdoze.com/hetzner) tiene máquinas Linux asequibles que van bien para esto.

<li>Jobs de cron/systemd sin afectar (usan shebangs <code>/bin/sh</code> o <code>bash</code>)</li>
<li>Las builds de Docker usan <code>bash -c</code> o <code>sh</code>, no fish</li>

## Problemas comunes

<Accordion label="PPA añadido pero sigue instalando fish 3.7.0" group="issues" expanded="true">
Ejecuta `apt policy fish` para ver de dónde viene el paquete candidato:

```bash
apt policy fish
```

Si el candidato muestra el archivo de Ubuntu en lugar de `ppa.launchpadcontent.net`, el PPA no se añadió bien o `apt update` no se ha ejecutado desde entonces. Repite:

```bash
sudo add-apt-repository ppa:fish-shell/release-4
sudo apt update
sudo apt install fish
```

Ten en cuenta también: en las versiones intermedias de Ubuntu la build del PPA va por detrás de la última. Ubuntu 25.10 recibe fish 4.8.0 del PPA, no la 4.9.3. Las versiones LTS (22.04, 24.04, 26.04) reciben las builds más nuevas.
</Accordion>

<Accordion label="Fish no aparece en /etc/shells" group="issues">
Si `chsh` se queja, puede que necesites agregar Fish a los shells permitidos manualmente:

```bash
command -v fish | sudo tee -a /etc/shells
chsh -s "$(command -v fish)"
```

Si fish se instaló desde el binario independiente, `command -v fish` devolverá la ruta donde lo enlazaste (p. ej. `/usr/local/bin/fish`), y eso es lo que se añade a `/etc/shells`.
</Accordion>

<Accordion label="Los scripts de Bash no funcionan en Fish" group="issues">
Eso es esperado. Fish tiene su propia sintaxis. Ejecuta scripts de Bash con `bash script.sh` o agrega `#!/bin/bash` al principio y hazlos ejecutables. Tus scripts existentes no necesitan cambiar, solo ejecútalos explícitamente con Bash.
</Accordion>

<Accordion label="Faltan variables de entorno de .bashrc" group="issues">
Fish no lee `.bashrc` ni `.bash_profile`. Necesitas establecer tus variables de entorno en `~/.config/fish/config.fish` usando `set -gx`:

```fish
set -gx JAVA_HOME /usr/lib/jvm/java-21
set -gx GOPATH ~/go
fish_add_path $GOPATH/bin
```

Lo mismo aplica a las entradas de PATH que herramientas como nvm o SDKman añaden en los perfiles de login. Replícalas en `config.fish` o usa fish solo como shell interactivo. Mira [NVM con Fish Shell](/es/nvm-fish-shell/) para el caso de nvm.
</Accordion>
