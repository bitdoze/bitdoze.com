Si vienes a Fish desde Bash o Zsh, probablemente configuraste alias para los comandos que usas con frecuencia. Las abreviaturas de Fish Shell funcionan de forma diferente: en lugar de envolver un comando en una función, se expanden al texto completo del comando en tu línea de comandos antes de que se ejecute. Yo cambié todos mis alias por abreviaturas después de una semana con Fish, y en la mayoría de los casos es la mejor opción.

Esta guía cubre cómo funciona cada mecanismo, cuándo usar cuál y qué cambió recientemente, incluyendo las descripciones de abreviaturas que llegaron con fish 4.9. Todo lo que sigue está fijado a fish 4.9.3 (septiembre de 2026), la versión estable actual.

<ListCheck>
<ul>
<li>Las abreviaturas se expanden en tu línea de comandos, así que el historial guarda el comando real, no un atajo</li>
<li>Los alias envuelven comandos en funciones, lo cual es mejor para scripts, CI y flags por defecto</li>
<li>fish 4.9 añade <code>--description</code> para anotar las abreviaturas en el paginador de completado</li>
<li>Las abreviaturas nunca se expanden en scripts, así que usa una función cuando un atajo deba funcionar en todas partes</li>
</ul>
</ListCheck>

## ¿Qué son los alias en Fish Shell?

Un alias en Fish funciona igual que en otros shells. Defines un atajo que se expande a un comando más largo:

```fish
alias gs="git status"
alias ll="ls -la"
alias dc="docker compose"
```

Cuando escribes `gs` y presionas enter, Fish ejecuta `git status`. En tu historial de comandos, guarda `gs`, no `git status`.

Fish implementa los alias como funciones envolventes. Cuando ejecutas `alias gs="git status"`, Fish crea una función llamada `gs` que ejecuta `git status`. Puedes verificarlo con:

```fish
type gs
# verify: output looks like this
# gs is a function with definition
# function gs --wraps='git status' --description 'alias gs=git status'
#   git status $argv
# end
```

Este comportamiento no ha cambiado hasta fish 4.9.3. Los alias han funcionado así desde los primeros días de la serie 3.x, y no hay cambios pendientes en master.

Para hacer los alias persistentes, agrégalos a `~/.config/fish/config.fish` o a un archivo en `~/.config/fish/conf.d/`.

## ¿Qué son las abreviaturas en Fish Shell?

Las abreviaturas se ven similares cuando las defines:

```fish
abbr -a gs git status
abbr -a ll ls -la
abbr -a dc docker compose
```

La diferencia está en lo que pasa cuando las usas. Escribe `gs` y presiona espacio o enter, y Fish reemplaza `gs` con `git status` *en la línea de comandos* antes de ejecutarlo. Ves el texto completo `git status`, y eso es lo que queda en tu historial.

Es un sistema de expansión de texto, no un envoltorio de comandos. La expansión es un evento de edición de la línea de comandos: tu abreviatura se dispara, el texto en la línea cambia y luego se ejecuta lo que quedó en ella.

<Notice type="info" title="Las abreviaturas son solo interactivas">
Las abreviaturas no se expanden en scripts ni en ningún contexto no interactivo. Solo los comandos tecleados de forma interactiva las disparan. Si pones <code>gs</code> en un script de shell, se queda como <code>gs</code>. No se convierte en <code>git status</code>.
</Notice>

## Por qué las abreviaturas de Fish Shell suelen ser mejores

### Tu historial se mantiene legible

Con alias, tu historial está lleno de códigos cortos. Alguien que mire `gs` en tu [historial de Fish Shell](/es/fish-shell-historial-persistencia/) (o tú mismo, seis meses después) tiene que recordar qué significa `gs`. Con abreviaturas, el historial muestra `git status` porque eso es lo que se ejecutó.

Esto también significa que la búsqueda en el historial con `Ctrl+R` funciona con los comandos reales. Busca "git status" y lo encontrarás, aunque hayas escrito `gs`.

### Otras personas pueden leer tu pantalla

Si compartes tu terminal (programación en pareja, grabaciones de pantalla, tutoriales), las abreviaturas muestran los comandos reales. Nadie tiene que descifrar tus atajos personales.

### Puedes editar antes de ejecutar

Después de que una abreviatura se expande, el texto completo está en tu línea de comandos y puedes modificarlo. Escribe `gs`, presiona espacio (se expande a `git status`) y luego agrega `--short` al final para obtener `git status --short`. Con alias, no puedes insertar flags fácilmente en medio del comando aliasado.

### Sin sobrecarga de funciones

Los alias crean funciones envolventes que ocupan tu espacio de nombres de funciones. Las abreviaturas no. Son puro reemplazo de texto. La diferencia práctica es mínima, pero las abreviaturas son conceptualmente más simples: nada existe en tiempo de ejecución hasta que escribes el disparador.

## Cuándo usar los alias de Fish Shell en su lugar

Las abreviaturas son la opción por defecto, pero los alias (o mejor dicho, las funciones detrás de ellos) siguen ganando en tres casos.

### Cuando necesitas manipular los argumentos del comando

Si tu atajo necesita manipular argumentos de formas que van más allá del reemplazo de texto, una [función personalizada de Fish Shell](/es/fish-shell-funciones-comandos-personalizados/) tiene más sentido:

```fish
# This needs to be a function, not an abbreviation
function mkcd
    mkdir -p $argv[1] && cd $argv[1]
end
```

Una abreviatura solo puede expandir texto. No puede crear un directorio y luego entrar en él usando el mismo argumento dos veces.

### Cuando necesitas flags por defecto en comandos existentes

Si quieres que `ls` siempre use `--color=auto`, un alias funciona:

```fish
alias ls="ls --color=auto"
```

Podrías hacerlo con una abreviatura, pero la expansión sería visible cada vez, lo cual resulta molesto para comandos que ejecutas constantemente.

### Cuando el atajo debe funcionar en scripts, config.fish o CI

Este es el caso que toma a la gente por sorpresa. Las abreviaturas nunca se expanden en scripts. Una función respaldada por un alias funciona en todas partes: `config.fish`, scripts de jobs de CI, Makefiles, otros scripts de shell.

<Tabs>
<Tab name="Shell interactivo">
```fish
# You type:
gs
# Fish expands it to git status before running.
# Works fine. Abbreviations expand here.
```
</Tab>
<Tab name="En un script">
```bash
# deploy.sh
gs   # stays literal "gs"; no expansion happens
# The script fails with: gs: command not found
# Use "git status" directly, or define a function.
```
</Tab>
</Tabs>

<Notice type="warning" title="Los scripts y las abreviaturas no se mezclan">
Si un atajo debe funcionar en scripts, pipelines de CI o cualquier contexto no interactivo, usa una función o un alias. Las abreviaturas solo existen en la línea de comandos interactiva.
</Notice>

Una regla práctica: abreviaturas para la memoria muscular interactiva, funciones para todo lo que deba ejecutarse sin supervisión.

## Funcionalidades de las abreviaturas de Fish Shell (en fish 4.9)

Las abreviaturas de Fish se han vuelto más potentes a lo largo de la serie 4.x. Esta sección cubre las funcionalidades a fecha de fish 4.9.3 (septiembre de 2026). Si estás en un 4.x más antiguo, casi todo aplica igual. Las adiciones destacadas se indican con números de versión.

Un apunte rápido sobre un flag relacionado: desde fish 4.3.3, `abbr` admite `--color auto|always|never` para controlar el resaltado de sintaxis de su salida. Combina bien con el [resaltado de sintaxis de Fish Shell](/es/fish-shell-resaltado-sintaxis/) si quieres que tu listado de abreviaturas se vea coherente con tu prompt.

### Posición: command vs. anywhere

Por defecto, las abreviaturas solo se expanden cuando están en posición de comando (la primera palabra en la línea):

```fish
abbr -a gs git status              # only expands as a command
abbr -a -p anywhere L "| less"     # expands anywhere on the line
```

La abreviatura `L` te permite escribir `cat file.txt L` y se expande a `cat file.txt | less`.

Una nota rápida de historia: fish 4.8.0 permitió que las abreviaturas en posición anywhere aparecieran en el completado con Tab en posición de argumento (issue #12630), pero 4.8.1 revirtió eso para mantener el paginador de completado despejado (issue #12838). En 4.9.x, los nombres de abreviaturas aparecen solo como completados en posición de comando. No esperes verlos en el completado con Tab en posición de argumento.

### Abreviaturas específicas por comando (`--command`)

Desde Fish 4.0, las abreviaturas pueden restringirse a comandos específicos:

```fish
abbr -a --command git co checkout
abbr -a --command git br branch
abbr -a --command docker ps "ps --format 'table {{.Names}}\t{{.Status}}'"
```

Ahora `co` solo se expande a `checkout` cuando el comando en la línea es `git`. Escribe `co` por sí solo y no pasa nada.

Esto es genial para flujos de trabajo con git: puedes escribir `git co` y que se expanda a `git checkout` sin contaminar el espacio global de abreviaturas. Pero hay cuatro matices que la documentación detalla y que suelen confundir a la gente.

Primero, `--command` implica `--position anywhere`. No puedes combinarlo con `--position command`, porque la abreviatura debe poder expandirse a mitad de línea (después de la palabra de comando), así que fish fuerza la posición `anywhere`. No luches contra esto; es lo que hace que `git co` funcione.

Segundo, varios comandos usan la sintaxis de llaves:

```fish
abbr -a --command={git,hg} co checkout   # works with git or hg
```

Tercero, un `--command ''` vacío significa "solo cuando no hay comando":

```fish
abbr -a --command '' new "type new"   # expands only in empty command position
```

Cuarto, los nombres deben ser únicos entre todos los comandos. No puedes definir `co` para `git` y un `co` distinto para `docker`; el segundo `--add` falla. Si necesitas que la misma palabra se expanda de forma diferente según el comando, usa `--regex` con una función en su lugar (ver más abajo).

### Descripciones de abreviaturas (fish 4.9+)

La funcionalidad estrella de las abreviaturas en fish 4.9.0 (issue #11291): puedes adjuntar una descripción legible a cualquier abreviatura, y aparece en el paginador de completado.

```fish
abbr -a --description "git status (expanded)" gs git status
abbr -a -d "docker compose up detached" dcu docker compose up -d
```

El flag `-d` es la forma corta de `--description`. Cuando escribes el disparador de la abreviatura y presionas Tab, el paginador muestra tu descripción junto a la expansión. Esto es útil cuando tienes muchas abreviaturas y quieres recordar *por qué* existe un atajo, no solo a qué se expande.

También difumina un poco la línea entre alias y abreviaturas: las funciones han tenido `--description` desde hace mucho (aparece en la salida de `type`), y ahora las abreviaturas pueden llevar el mismo tipo de anotación. Para más detalles sobre cómo funcionan el paginador y las sugerencias, mira [el autocompletado y sugerencias de Fish Shell](/es/fish-shell-autocompletado-sugerencias/).

<Notice type="info" title="Requiere fish 4.9.0 o superior">
El flag <code>-d</code>/<code>--description</code> no se reconoce en fish 4.8.x ni en versiones anteriores. Si estás en una versión más vieja, actualiza primero, o la definición de la abreviatura fallará con un error de "unknown option".
</Notice>

Para verificarlo, define una abreviatura con descripción, luego escribe su nombre y presiona Tab. El paginador debería mostrar el texto de tu descripción junto a la expansión.

### Abreviaturas con regex

Puedes usar expresiones regulares para coincidir con los disparadores de abreviaturas. La documentación trae dos ejemplos canónicos que vale la pena robar.

El primero es un alias de sufijo (estilo zsh): abre cualquier archivo `.txt` en vim escribiendo su nombre.

<Tabs>
<Tab name="Alias de sufijo (archivos .txt)">
```fish
function vim_edit
    vim $argv[1]
end
abbr -a --regex '.+\.txt' --position command --function vim_edit
```

Ahora, al escribir `notes.txt` y presionar espacio, se expande a `vim notes.txt`. El regex usa sintaxis PCRE2.
</Tab>
<Tab name="multicd (punto-punto)">
```fish
function multicd
    echo cd (string repeat -n (math (string length -- $argv[1]) - 1) ../)
end
abbr --add dotdot --regex '^\.\.+$' --function multicd
```

Escribe `..` para obtener `cd ../`, `...` para `cd ../../`, `....` para `cd ../../../`, y así sucesivamente. Es la demostración canónica de `--regex + --function` de la documentación de fish.
</Tab>
</Tabs>

El contrato de `--function` aplica a todas las abreviaturas basadas en funciones, incluidas las de regex:

- La función recibe el token coincidente como primer argumento (`$argv[1]`).
- Si la función sale con código 0, el token se reemplaza por su salida stdout.
- Si sale con un código distinto de cero, el token queda sin cambios. No pasa nada.
- No puedes dar una EXPANSIÓN separada junto a `--function`; la función *es* la expansión.

### Posición del cursor con `--set-cursor`

Puedes controlar dónde queda el cursor después de la expansión:

```fish
abbr -a gcm --set-cursor "git commit -m '%'"
```

Escribe `gcm`, presiona espacio, y se expande a `git commit -m ''` con tu cursor entre las comillas. El marcador `%` (el valor por defecto) se elimina y el cursor aterriza ahí.

También puedes usar un marcador personalizado y plantillas de varias líneas. Este es el ejemplo del bucle for de la documentación:

```fish
abbr 4DIRS --set-cursor=! "$(string join \n -- 'for dir in */' 'cd $dir' '!' 'cd ..' 'end')"
```

Escribe `4DIRS`, presiona espacio y obtienes un esqueleto de bucle for multilínea con el cursor en la posición de `!`. Las abreviaturas funcionan como un sistema ligero de snippets, no solo como forma de acortar comandos.

### Abreviaturas basadas en funciones

Para expansiones dinámicas, puedes apuntar una abreviatura a una función sin regex (entonces coincide con el nombre exacto):

```fish
function last_history_item
    echo $history[1]
end
abbr -a !! --position anywhere --function last_history_item
```

Esto recrea la funcionalidad `!!` de Bash (último comando). Escribe `sudo !!` y se expande a `sudo <tu-último-comando>`. El mismo contrato de `--function` de la sección de regex aplica: la función recibe `!!` como `$argv[1]`, sale con 0 y su salida reemplaza al token.

## Problemas frecuentes y soluciones

<Notice type="warning" title="Lee esto antes de rendirte con las abreviaturas">
Estos son los problemas que más confunden a la gente. Revisa aquí antes de reportar un bug o volver a los alias.
</Notice>

<Accordion label="Las abreviaturas no se expanden en scripts" group="faq" expanded="true">
Pusiste un disparador de abreviatura en un script, Makefile o job de CI y se queda literal. El script falla con "command not found".

Esto es intencional. Fish solo expande abreviaturas en un prompt interactivo: no quieres que tus scripts dependan de las abreviaturas personales de alguien.

Para arreglarlo, usa el comando real en los scripts, o define una función (las funciones funcionan en todas partes):

```fish
# works in scripts and interactively
function gs
    git status $argv
end
```
</Accordion>

<Accordion label="Ctrl+Espacio no expande la abreviatura" group="faq">
Presionaste Ctrl+Espacio y la abreviatura se quedó como estaba.

Ese es el comportamiento documentado. `Ctrl+Espacio` inserta un espacio literal *sin* disparar la expansión. Es la válvula de escape para cuando quieres la palabra literal, por ejemplo un nombre de archivo que coincide con el nombre de una abreviatura.

Nada está roto. Usa `Ctrl+Espacio` para suprimir la expansión a propósito, y espacio o enter normal para expandir.
</Accordion>

<Accordion label="La abreviatura no se expandió al presionar enter" group="faq">
Escribiste una abreviatura, moviste el cursor a otra parte de la línea, presionaste enter y el token sin expandir se ejecutó (o falló).

Fish 3.7.0 (issue #8423) endureció la regla de expansión: las abreviaturas solo se expanden cuando el cursor está *adyacente* al token (justo después de él) al presionar espacio o enter. Si te mueves con las flechas y luego presionas enter, fish ejecuta lo que está literalmente en la línea.

Presiona espacio inmediatamente después de escribir la abreviatura para expandirla primero, luego edita la línea expandida. Si ya ejecutaste el token sin expandir, solo obtienes un "command not found". No pasa nada destructivo.
</Accordion>

<Accordion label="abbr --erase o --rename falla en una abreviatura con ámbito de comando" group="faq">
Definiste `abbr -a --command git co checkout`, luego ejecutaste `abbr --erase co` y obtuviste un error.

Para las abreviaturas con ámbito de comando, `--erase` y `--rename` necesitan que repitas el flag `--command` para que fish sepa a qué abreviatura te refieres. Sin él, la búsqueda por nombre falla.

La sintaxis correcta:

```fish
abbr --erase --command git co     # correct
abbr --rename --command git co ci # rename within the git scope
```
</Accordion>

<Accordion label="Aparece '# imported from a universal variable' en tu lista de abreviaturas" group="faq">
Al ejecutar `abbr` aparecen líneas como `abbr -a -- foo bar # imported from a universal variable`. Tu salida de `abbr --list` se ve desordenada.

Antes de fish 3.6, las abreviaturas se guardaban en variables universales. Fish 3.6 las movió al almacenamiento normal de abreviaturas, pero las instalaciones actualizadas pueden seguir cargando los datos viejos de variables universales, que fish importa con un marcador de comentario en cada arranque.

La receta de limpieza de la documentación:

```fish
abbr >> ~/.config/fish/config.fish   # then edit out the comment lines
abbr --erase (abbr --list)           # clear the legacy entries
```

Reinicia fish y vuelve a añadir abreviaturas limpias (o carga el config editado). Si estás en macOS y te topas con esto tras una actualización, mi [guía completa de configuración de Fish Shell para macOS](/es/fish-shell-macos-configuracion/) cubre un enfoque desde cero.
</Accordion>

## Gestión de abreviaturas de Fish Shell

```fish
abbr                             # list all abbreviations (output is re-usable as commands)
abbr --show gs                   # show exact stored definition (import/export format)
abbr --list                      # list abbreviation names only
abbr --query gs; echo $status    # 0 if gs is an abbreviation
abbr --erase gs                  # remove an abbreviation
abbr --rename gs gst             # rename an abbreviation
```

Dos distinciones importan aquí:

- `abbr --show gs` imprime el formato limpio de importación/exportación, exactamente lo que pondrías en un archivo de configuración. `abbr` a secas (sin flags) lista todo, pero puede añadir comentarios `# imported from a universal variable` para entradas heredadas (ver la sección de problemas de más arriba).
- `abbr --query gs` devuelve estado de salida 0 si `gs` es una abreviatura. El `echo $status` que le sigue es cómo ves el resultado en la misma línea.

<ListCheck>
<ul>
<li>Ejecuta <code>abbr --query gs; echo $status</code> después de definirla. Debería imprimir <code>0</code></li>
<li>Escribe el disparador y presiona espacio, luego verifica que la expansión aparece en la línea de comandos</li>
<li>Ejecuta el comando expandido y revisa <code>history</code>. Debería guardarse el texto expandido, no el disparador</li>
</ul>
</ListCheck>

Para las abreviaturas con ámbito de comando, `--erase` y `--rename` requieren repetir `--command`. Mira la sección de problemas más arriba para la sintaxis exacta.

### Guardar abreviaturas

La forma recomendada es poner tus comandos `abbr -a` en un archivo de configuración:

```fish
# ~/.config/fish/conf.d/abbreviations.fish
abbr -a gs git status
abbr -a ga git add
abbr -a gc git commit
abbr -a gp git push
abbr -a gd git diff
abbr -a gl git log --oneline
abbr -a dc docker compose
abbr -a dcu docker compose up -d
abbr -a dcd docker compose down
abbr -a k kubectl
```

También puedes volcar tus abreviaturas actuales a un archivo:

```fish
abbr --show > ~/.config/fish/conf.d/abbreviations.fish
```

`abbr --show` es el volcado más limpio (formato de importación/exportación, sin comentarios heredados). Esto las guarda en un formato que Fish puede cargar directamente.

<Notice type="warning" title="La redirección sobrescribe el archivo">
<code>abbr --show &gt; archivo</code> (o <code>abbr &gt; archivo</code> a secas) sobrescribe el archivo destino completo. No añade al final. La documentación lo recomienda intencionalmente: reemplaza el archivo con una instantánea limpia para que no tengas duplicados ni resucites abreviaturas eliminadas. No uses <code>&gt;&gt;</code> pensando que añade. Si quieres fusionar, vuelca a un archivo temporal y edita a mano.
</Notice>

La ubicación en `conf.d/` es el mismo patrón que usarías para otra configuración de fish. Si gestionas versiones de herramientas como Node.js, la misma estructura de directorios aplica cuando [configuras NVM con Fish Shell](/es/nvm-fish-shell/).

## Mi configuración de abreviaturas

Esto es lo que uso día a día, con descripciones `-d` en algunas entradas para mostrar el flag de fish 4.9 en la práctica:

```fish
# Git
abbr -a -d "git status" gs git status
abbr -a ga git add
```
