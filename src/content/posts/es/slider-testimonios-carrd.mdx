## Por qué usar un slider de testimonios en Carrd

Un carrusel de testimonios en Carrd supera a un muro de citas estáticas:

1. Ahorra espacio. Muestra de 5 a 10 testimonios en el espacio de uno.

2. Mantiene el contenido fresco. Los visitantes que permanecen en la página ven citas distintas sin hacer scroll.

3. Atrae la atención. El movimiento capta la mirada y dirige el foco hacia tu prueba social.

4. Se ve profesional. Es un patrón habitual en sitios bien diseñados.

5. Funciona en móvil. Diseño con deslizamiento pensado para dispositivos táctiles.

## Cómo añadir un slider de testimonios a Carrd

Así se añaden testimonios a Carrd en tres estilos: inserta un elemento Embed, pega uno de los snippets de abajo, publica y verifica en la URL en vivo. El flujo de trabajo es corto, pero la parte de publicar y verificar no es opcional.

![Cómo un slider de testimonios en Carrd pasa del embed a la página en vivo: añadir elemento en el builder, código del embed en línea, publicar cambios, el sitio en vivo muestra el slider, con un aviso de que el builder no renderiza nada hasta que publicas](@assets/images/26/01/carrd-testimonial-slider-workflow.svg)

### Paso 1: Añade un elemento Embed en Carrd

Haz clic en el signo `+` y añade un elemento Embed:

- Type: Code
- Style: **Inline** (importante: esto muestra el slider en tu página)

<Picture formats={["webp"]} fallbackFormat="webp" src={imag1} alt="Panel de ajustes del elemento Embed de Carrd con Type en Code y el desplegable de Style" />

La captura viene del tutorial del botón de volver arriba, así que sus desplegables de Style muestran Hidden y Head. Para el slider, abre el mismo desplegable de Style y elige **Inline**.

En una página larga, usa el Elements Panel (More Actions, luego Elements, añadido al builder el 2026-08-07) para saltar directamente al embed que acabas de añadir en lugar de hacer scroll.

Este es el mismo flujo de embeds que usan todos los widgets de Carrd en este sitio. Si quieres un segundo ejemplo resuelto antes de tocar los testimonios, [añade primero un botón de volver arriba con un embed](https://www.bitdoze.com/carrd-back-to-top-button/).

<Notice type="warning" title="No verás el slider en el editor">
Carrd no renderiza el código de los embeds en el editor. Tras pegar, haz clic en **Publish Changes**, abre la URL en vivo y fuerza la recarga. El slider aparece donde queda el embed en el orden de la sección. Un hueco en blanco en el editor no significa que algo esté roto.
</Notice>

<Notice type="info" title="Consejo pro: separa el código del marcado">
Mantén el embed visible puramente presentacional. Pon el HTML y el CSS en el embed Inline, y luego coloca la mitad del `<script>` en un segundo Embed con Style **Hidden** y ubicación **Body End**. Carrd documenta ambos estilos, además de las ubicaciones Head, Body Top y Body End para embeds Hidden, en la <a href="https://carrd.co/docs/building/embedding-custom-code" target="_blank" rel="noopener noreferrer">documentación oficial de embeds</a>.
</Notice>

**Verifica:** Publish Changes, abre la URL en vivo y fuerza la recarga. Resultado esperado: el slider se renderiza bajo la posición del embed con el primer testimonio visible. Si está roto se ve así: un hueco vacío en la página en vivo (falta código o Style está en Hidden) o texto de código en bruto en la página (Type puesto en algo distinto de Code).

Cuatro pequeñas mejoras que vale la pena pegar encima del bloque anterior. Ninguna cambia la estructura del marcado, así que el copiar y pegar sigue funcionando.

Acota las variables del tema. El snippet declara sus colores en `:root`, que es global a la página. Vale para un embed; mal para dos. Mueve las variables a `.testimonial-slider` (consulta Personalizar los colores en la sección de personalización).

Dos atributos ARIA hacen que el contenedor se anuncie como carrusel a los lectores de pantalla. Edita las etiquetas de apertura existentes en su sitio y mantén el div `.testimonial-container` entre ellas. Explicación completa en la sección de accesibilidad más abajo.

```html

  <div class="testimonial-container">
    <div class="testimonial-track" id="testimonialTrack" aria-live="off">
```

Un cuarto slide necesita un cuarto punto. El track, el autoplay y la lógica de deslizamiento cuentan los slides en tiempo de ejecución. Los puntos están fijados en el código. Cuando añadas un slide, añade su botón:

```html
<!-- Add inside .testimonial-dots when you add a 4th slide -->
<button class="testimonial-dot" onclick="goToSlide(3)" aria-label="Go to testimonial 4"></button>
```

Para un autoplay accesible con pausa fuera de pantalla, pega estas líneas al final del mismo bloque de script. Cambian el intervalo por funciones de inicio/parada protegidas, omiten el autoplay por completo para usuarios con reduced-motion, solo rotan mientras el slider está en pantalla y pausan cuando entra el foco del teclado. Solo APIs estándar del navegador (`IntersectionObserver` y `matchMedia`). Prueba en tu sitio publicado; la vista previa del builder no ejecuta los scripts de los embeds.

```js
// Accessibility + offscreen pause. Paste at the end of the existing <script> block.
var reduceMotion = window.matchMedia('(prefers-reduced-motion: reduce)').matches;
var rotationStopped = false; // set to true to turn autoplay off completely

function startAuto() {
  if (reduceMotion || rotationStopped || slideInterval) return;
  slideInterval = setInterval(nextSlide, 5000);
}

function stopAuto() {
  clearInterval(slideInterval);
  slideInterval = null;
}

// Replaces the plain setInterval start and the mouse and touch handlers above
stopAuto();
startAuto();

testimonialTrack.onmouseenter = stopAuto;
testimonialTrack.onmouseleave = startAuto;

var swipeStart = testimonialTrack.ontouchstart;
var swipeEnd = testimonialTrack.ontouchend;
testimonialTrack.ontouchstart = function (e) { swipeStart(e); stopAuto(); };
testimonialTrack.ontouchend = function (e) { swipeEnd(e); stopAuto(); startAuto(); };

document.querySelector('.testimonial-slider').addEventListener('focusin', stopAuto);
document.querySelector('.testimonial-slider').addEventListener('focusout', startAuto);

if (!reduceMotion) {
  var testimonialObserver = new IntersectionObserver(function (entries) {
    entries.forEach(function (entry) {
      if (entry.isIntersecting) { startAuto(); } else { stopAuto(); }
    });
  }, { threshold: 0.3 });
  testimonialObserver.observe(document.getElementById('testimonialTrack'));
}

document.addEventListener('visibilitychange', function () {
  if (document.hidden) { stopAuto(); } else { startAuto(); }
});
```

Como `startAuto()` es idempotente (se niega a apilar un segundo intervalo) y el bloque reasigna los manejadores de ratón y toque, pegar esto después del script original es seguro. Si omites este bloque, el slider sigue funcionando; simplemente continúa rotando fuera de pantalla.

## Personalizar tu slider de testimonios

### Añadir tus propios testimonios

Sustituye el contenido de ejemplo en cada slide:

1. Cambia el contenido del párrafo por tu testimonio real.
2. Actualiza el nombre por el de tu cliente.
3. Cambia el cargo y la empresa.
4. Sustituye la URL de la imagen por la foto de tu cliente (los servicios de marcador como pravatar.cc son solo para pruebas).

Mantén el atributo `alt` descriptivo. El nombre del cliente funciona bien. Los alt genéricos o vacíos fallan con los usuarios de lectores de pantalla y desperdician una victoria fácil de accesibilidad.

### Añadir más slides

Copia un bloque de slide completo y pégalo tras el último slide. El slider se adapta a cualquier número de slides porque el track, el autoplay y la lógica de deslizamiento cuentan los elementos slide en tiempo de ejecución. **Pero en la Opción 1 también debes añadir un botón de punto correspondiente por cada slide nuevo.** Los puntos están fijados en el código, así que un cuarto slide sin un cuarto botón no se puede alcanzar haciendo clic (el deslizamiento y el autoplay sí lo mostrarán). La Opción 2 no necesita nada extra: su contador `1 / N` se calcula a partir del número de slides.

```html
<!-- Add inside .testimonial-dots when you add a 4th slide -->
<button class="testimonial-dot" onclick="goToSlide(3)" aria-label="Go to testimonial 4"></button>
```

![Anatomía del slider de testimonios para copiar y pegar: el contenedor envuelve el track con un bloque de slide por testimonio, más una fila de puntos con un botón por slide, con indicaciones sobre dónde añadir slides y puntos](@assets/images/26/01/carrd-testimonial-slider-anatomy.svg)

### Cambiar la velocidad del autoplay

Busca las llamadas a `setInterval` y cambia el número (en milisegundos):

- `5000` = 5 segundos
- `7000` = 7 segundos
- `3000` = 3 segundos

La Opción 1 repite `5000` en cada lugar que reinicia el temporizador (el inicio inicial, al salir el ratón, al terminar el deslizamiento y los bloques opcionales de accesibilidad y del botón). Cámbialos todos al mismo valor. La Opción 2 usa `6000` al final de su script. El mismo cambio.

### Desactivar el autoplay

Elimina o comenta el bloque `setInterval` si quieres navegación solo manual. En la Opción 1 los manejadores de salida del ratón y de deslizamiento también llaman a `setInterval`, así que quita esas líneas también. Si pegaste la mejora de accesibilidad en la Opción 1, cambia `var rotationStopped = false;` por `var rotationStopped = true;` en su lugar. Eso bloquea todas las vías de reinicio.

### Personalizar los colores

Cada snippet trae sus colores en `:root`. Eso funciona con un embed. Con dos embeds en una página, las custom properties de `:root` son globales, así que dos widgets que redefinen `--testimonial-accent` se pisan entre sí. En su lugar, acota las variables al contenedor del widget:

```css
.testimonial-slider {
  --testimonial-bg: #ffffff;
  --testimonial-text: #1f2937;
  --testimonial-secondary: #6b7280;
  --testimonial-accent: #4f46e5;
  --testimonial-quote: #e5e7eb;
  --testimonial-radius: 16px;
  --testimonial-max-width: 700px;
}
```

La misma idea para los otros dos snippets: mueve las variables a `.card-slider` o `.testimonial-grid`. Mantén los nombres de las variables y el resto del CSS sin cambios.

## Solución de problemas de tu slider de testimonios en Carrd

<Notice type="error" title="Problema más común: no se renderiza nada en el editor">
Los embeds no producen nada en el editor de Carrd. Empieza por el primer punto de abajo antes de depurar cualquier otra cosa.
</Notice>

### El slider no aparece en el editor ni en el sitio en vivo

**Síntoma.** Pegaste el código y ves un hueco en blanco.

**Causa.** El builder nunca renderiza el código de los embeds. Si la página en vivo también está en blanco, aún no has publicado, o el Style del embed está en Hidden sin contenido de ubicación.

**Solución.** Haz clic en Publish Changes, abre la URL en vivo y fuerza la recarga. Confirma que Type es Code y Style es Inline. Resultado esperado: el slider aparece en la posición del embed dentro del orden de la sección. Texto de código en bruto en la página significa que Type está en algo distinto de Code.

### Dos sliders (o un slider + otro Embed) entran en conflicto

**Síntoma.** Hacer clic en un punto mueve el slider equivocado, o la consola del navegador se queja de IDs duplicados o de `goToSlide`.

**Causa.** Los snippets fijan IDs (`testimonialTrack`, `cardTrack`) y la función global `goToSlide`. Pegar el mismo snippet dos veces choca.

**Solución.** Renombra IDs, clases y funciones en cada instancia. Para un segundo slider usa `testimonialTrack2`, `goToSlide2`, y así sucesivamente. Mantén coherentes todos los renombrados en HTML y JS, incluidos los atributos `onclick` de los puntos.

### El slider es más ancho que su sección

**Síntoma.** El slider desborda su columna o ignora el padding de tu sección.

**Causa.** El `max-width: 700px` u `800px` fijo asume una sección a todo lo ancho.

**Solución.** Baja `--testimonial-max-width` (Opción 1) o el `max-width` de `.card-slider` y `.testimonial-grid`, o mueve el embed a una sección a todo lo ancho. Las media queries para móvil ya reducen el padding por debajo de 600 px.

### Variables de tema que se filtran entre embeds

**Síntoma.** Dos embeds se cambian los colores entre sí, y gana el último que se carga.

**Causa.** Las custom properties declaradas en `:root` son globales a la página.

**Solución.** Acótalas al contenedor del widget. Consulta Personalizar los colores en la sección de personalización de arriba.

### El autoplay sigue ejecutándose fuera de pantalla o en pestañas en segundo plano

**Síntoma.** El intervalo sigue disparándose mientras el slider está fuera de la vista o la pestaña está oculta. Ciclos desperdiciados, y molesta a los usuarios de lectores de pantalla.

**Causa.** `setInterval` se ejecuta incondicionalmente.

**Solución.** Usa la mejora de accesibilidad de la Opción 1. Condiciona la rotación a `IntersectionObserver`, `matchMedia('(prefers-reduced-motion: reduce)')`, el foco del teclado y `visibilitychange`. Si solo quieres la parte de pestañas en segundo plano, este es el parche mínimo para la Opción 1 (pégalo al final de su script):

```js
document.addEventListener('visibilitychange', function () {
  clearInterval(slideInterval);
  slideInterval = null;
  if (!document.hidden) {
    slideInterval = setInterval(nextSlide, 5000);
  }
});
```

### Las imágenes de avatar fallan o generan avisos de privacidad

**Síntoma.** Los avatares devuelven 404, o tu herramienta de consentimiento marca una petición a terceros al cargar la página.

**Causa.** `i.pravatar.cc` es un servicio de terceros en producción. Vale para pruebas. En una página publicada es una petición externa que se dispara a cada visitante, lo que da mala imagen en materia de GDPR para audiencias de la UE y supone un punto único de fallo más.

**Solución.** Aloja tú las fotos de los clientes: súbelas como recursos de imagen de Carrd o apunta el `src` de `img` a tus propias URLs de medios. Mantén el texto `alt` descriptivo en cualquier caso. Si tu sitio publicado hace peticiones a terceros, añade un [aviso de cookies para Carrd](https://www.bitdoze.com/add-cookie-notice-carrd/) para que la información coincida con el comportamiento real.

## Accesibilidad: haz que el carrusel sea apto para lectores de pantalla

De fábrica, estos sliders solo se pausan al pasar el ratón. El <a href="https://www.w3.org/WAI/ARIA/apg/patterns/carousel/" target="_blank" rel="noopener noreferrer">patrón de carrusel de las ARIA Authoring Practices del W3C</a> exige más a cualquier carrusel con rotación automática. La versión corta:

<ListCheck>
<ul>
<li>Pausar la rotación al pasar el ratón y cuando el foco del teclado entra en el carrusel</li>
<li>Ofrecer un control visible para detener y reanudar la rotación</li>
<li>Etiquetar cada botón de punto para que nombre el slide que abre</li>
<li>Marcar el contenedor como carrusel con una etiqueta en lenguaje claro</li>
<li>Omitir por completo la rotación automática para usuarios con prefers-reduced-motion</li>
</ul>
</ListCheck>

El bloque de autoplay accesible de la Opción 1 cubre la pausa por foco, la omisión por reduced-motion y la pausa fuera de pantalla. Para la parte del marcado, añade estos atributos al contenedor y al track de la Opción 1:

```html
<div class="testimonial-slider" aria-roledescription="carousel" aria-label="Customer testimonials">
  <div class="testimonial-container">
    <div class="testimonial-track" id="testimonialTrack" aria-live="off">
```

El `aria-live="off"` del track es deliberado. Mientras la rotación está activa, anunciar cada cambio es ruido. Si desactivas el autoplay por completo, cámbialo a `aria-live="polite"` para que la navegación manual sí se anuncie.

Etiqueta cada botón de punto según su destino, por ejemplo `aria-label="Go to testimonial 4"`.

Para el control de parada e inicio, coloca un botón dentro de `.testimonial-slider`, justo encima de los puntos. Se apoya en el bloque de autoplay accesible, así que pega ese bloque primero. El botón cambia `rotationStopped`, lo que impide que el hover, el foco, el deslizamiento y el scroll reinicien la rotación después de que un visitante la detenga. El CSS de Carrd resetea los estilos de los botones, así que el snippet le da al botón su propio aspecto:

```html
<style>
  .testimonial-toggle {
    display: block;
    margin: 20px auto 0;
    padding: 6px 14px;
    border: 1px solid var(--testimonial-secondary);
    border-radius: 6px;
    background: transparent;
    color: var(--testimonial-secondary);
    font-size: 14px;
    cursor: pointer;
  }
</style>
<button class="testimonial-toggle" onclick="toggleAutoplay()" aria-label="Stop auto-rotating testimonials">Stop rotation</button>
```

```js
// Paste after the accessible autoplay block, inside the same <script>
var testimonialToggle = document.querySelector('.testimonial-toggle');

function toggleAutoplay() {
  rotationStopped = !rotationStopped;
  if (rotationStopped) {
    stopAuto();
    testimonialToggle.textContent = 'Start rotation';
    testimonialToggle.setAttribute('aria-label', 'Start auto-rotating testimonials');
  } else {
    startAuto();
    testimonialToggle.textContent = 'Stop rotation';
    testimonialToggle.setAttribute('aria-label', 'Stop auto-rotating testimonials');
  }
}
```

Estas adiciones usan APIs estándar del navegador (`IntersectionObserver`, `matchMedia`, `addEventListener`). No se han probado contra una combinación concreta de temas de Carrd, así que verifica en tu sitio publicado.

**Verifica:** publica, abre la página en vivo y pulsa Tab hasta que el foco llegue al slider. La rotación debería detenerse. Pulsa el botón de parada y la rotación debería quedar detenida. Activa «reducir movimiento» en los ajustes de tu SO y recarga: nada debería rotar solo. Si está roto se ve así: la rotación continúa mientras un botón de punto tiene el foco, o no hay forma de detener el carrusel sin salir de la página.

## Consejos para mejores testimonios

Usa fotos reales. Las fotos de stock parecen falsas. Pide a los clientes retratos o usa sus fotos de LinkedIn con permiso.

Mantén las citas cortas. Los testimonios largos pierden atención. Redúcelos a las 2-3 frases más potentes.

Incluye datos concretos. «¡Gran trabajo!» se olvida. «Aumentaron nuestra tasa de conversión un 40 %» se recuerda.

Diversifica tus testimonios. Muestra distintos tipos de clientes y los diferentes beneficios que recibieron.

Mantén un documento fuente de verdad. Una simple tabla con citas aprobadas, nombres, cargos y URLs de fotos convierte una actualización del embed en un trabajo de dos minutos en lugar de una excavación arqueológica. El formulario de recolección de Senja resuelve el mismo problema con software si se te queda pequeña una hoja de cálculo.
