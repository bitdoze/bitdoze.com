## ¿Qué es nanobot? Novedades de la v0.4.0

nanobot es un proyecto de código abierto de HKUDS (Universidad de Hong Kong). Es un asistente de IA que se ejecuta en tu servidor y se conecta a la app de chat que prefieras. El núcleo sigue siendo una base de código Python pequeña y legible, pero la v0.4.0 (publicada el 2026-10-28) añadió una superficie de administración completa: una WebUI integrada, una interfaz de terminal nativa, un SDK de Python y una API compatible con OpenAI.

La arquitectura no ha cambiado:

```
You (Discord / Telegram / WhatsApp / Slack / etc.)
    ↓
nanobot Gateway (running on your VPS)
    ↓
LLM Provider (GLM-5.3, MiniMax M3.1 Flash, Ollama, OpenRouter, etc.)
    ↓
Tools (file access, shell commands, web search, MCP servers)
```

Los mensajes llegan desde tu app de chat, nanobot los enruta al LLM que hayas configurado y el modelo puede usar herramientas para hacer las cosas. Todo, excepto las llamadas a la API del LLM, se queda en tu máquina.

Esto es lo nuevo desde los tiempos de la v0.1:

| Función | Qué hace |
|---------|-------------|
| **WebUI** (`nanobot webui`) | Panel de administración en el navegador en el puerto 8765: proveedores, modelos, Apps (MCP), Tasks/Calendar |
| **TUI nativa** (`nanobot`) | Interfaz de terminal completa, no solo `nanobot agent` |
| **Presets de modelos** | Configuraciones de modelo con nombre y cadenas `fallbackModels` |
| **Historial en SQLite** | El historial de sesiones se guarda en una base de datos, no en archivos sueltos |
| **Docker Compose** | Despliegue con un solo comando, con health checks y valores por defecto endurecidos |
| **Integración con systemd** | `nanobot gateway install-service` genera e instala un servicio de usuario |
| **Automations** | Tareas programadas gestionadas en la WebUI, que reemplazan al antiguo CLI de cron |
| **~40 proveedores** | GLM, MiniMax, OpenRouter, Anthropic, Bedrock, Ollama/vLLM locales y más |
| **Transcripción de voz** | Integrada, con Groq como proveedor por defecto |

Para un bot siempre activo quieres modelos baratos por token, con ventanas de contexto grandes y buenos en el uso de herramientas. ### GLM-5.3 y GLM-5.3-Flash: especificaciones y precios

GLM-5.3 es el flagship actual de Zhipu. GLM-5.3-Flash es la variante barata y rápida que más sentido tiene para un bot de chat:

| Especificación | GLM-5.3 | GLM-5.3-Flash |
|------|---------|---------------|
| Arquitectura | Solo texto, misma base que GLM-5.2 | 320B en total, 18B activos |
| Ventana de contexto | 1M tokens | 1M tokens |
| Salida máxima | 128K tokens | 128K tokens |
| Costo de entrada | $1.40/M tokens | $0.15/M tokens |
| Costo de salida | $4.40/M tokens | $0.50/M tokens |
| Entrada en caché | $0.26/M tokens | - |
| Razonamiento | Siempre activo (`reasoning_effort`: low/high/max) | Siempre activo |
| Licencia | MIT | MIT |

GLM-5.3 ahora razona siempre. Desactivar el razonamiento hace que las solicitudes fallen. Si migras desde configuraciones GLM antiguas, pon `thinking.type: "enabled"` y `reasoning_effort: "low"` para mantener los costos bajos. GLM-5.3-Flash usa atención dispersa y lineal para lograr una eficiencia de atención aproximadamente 3x respecto a 5.3. También existe GLM-5.3-FlashX a $0.37/$1.25 si necesitas 200 tokens/seg. Para uso intensivo, el plan GLM Coding de Z.AI empieza en $18/mes.

Las cifras de eficiencia y throughput de arriba son las publicadas por el proveedor, Z.ai.

El antiguo GLM-5 sigue listado a $1.0/$3.2 por M de tokens pero está reemplazado. No empieces configuraciones nuevas con él.

### MiniMax M3.1 Flash: especificaciones y precios

MiniMax M3.1 Flash es el reemplazo de M2.5 y el emparejamiento obvio con GLM-5.3-Flash:

| Especificación | Valor |
|------|-------|
| Ventana de contexto | 1M tokens |
| Costo de entrada | $0.15/M tokens |
| Costo de salida | $0.60/M tokens |
| Lectura de caché | $0.015/M tokens |
| Profundidad de pensamiento | Ajustable con el parámetro `effort` |

El parámetro `effort` te permite subir o bajar la profundidad de razonamiento según la tarea. Para un bot de chat, un esfuerzo bajo suele ser suficiente y mantiene la latencia baja.

MiniMax también ofrece MiniMax-M3, un modelo de codificación multimodal a $0.30/$1.20 (nivel estándar, ≤512k de entrada, 50% de descuento permanente) o $0.60/$2.40 por encima de 512k. Vale la pena si tu bot hace trabajo de programación. Ambos modelos funcionan en la plataforma global de MiniMax (`platform.minimax.io`) y en la plataforma de China continental (`minimaxi.com`).

## Instala nanobot en tu VPS

nanobot requiere Python 3.11+. Hay wheels para Linux x64/ARM64 (glibc 2.17+), Windows y Python 3.14.

<Tabs>
<Tab name="Script oficial (recomendado)">

El camino más rápido. El script instala nanobot y lanza el asistente de configuración:

```bash
curl -fsSL https://raw.githubusercontent.com/HKUDS/nanobot/main/scripts/install.sh | bash
```

En Windows, usa `install.ps1`. Después de la instalación, verifica:

```bash
nanobot --version
```

</Tab>
<Tab name="uv o pip">

Si prefieres gestionar los paquetes de Python por tu cuenta:

```bash
# With uv (recommended - faster, isolated)
uv tool install nanobot-ai

# Or with pip
pip install nanobot-ai
```

Si todavía no tienes uv, mira [cómo empezar con uv](/es/empezar-uv/). Verifica:

```bash
nanobot --version
```

</Tab>
<Tab name="Desde el código fuente">

Para las últimas funciones o si planeas modificar el código. Requiere Git, Python 3.11+ y [Bun](https://bun.sh/) (sirve la TUI desde el checkout):

```bash
git clone https://github.com/HKUDS/nanobot.git
cd nanobot
python -m pip install -e .
```

Verifica:

```bash
nanobot --version
```

</Tab>
</Tabs>

Después de instalar, inicializa el workspace y la configuración:

```bash
nanobot onboard
```

Esto crea `~/.nanobot/` con un `config.json` y una carpeta `workspace/` para la memoria, las skills y los archivos de bootstrap.

## Primer arranque: onboarding y la WebUI de nanobot

nanobot v0.4.0 te da dos caminos para el primer arranque: un asistente en la terminal o la WebUI en el navegador. Ambos crean la misma estructura `~/.nanobot/config.json` y `workspace/`.

<Notice type="warning" title="La WebUI es acceso de administración total">
Cualquiera con acceso a la WebUI puede cambiar modelos, leer archivos de memoria y ejecutar herramientas. No expongas el puerto 8765 a internet. Usa un túnel SSH o una VPN mesh como [Headscale](/es/headscale-tailscale-autoalojado/) para acceder de forma remota.
</Notice>

### Configuración con `nanobot onboard --wizard`

El camino solo por terminal. Los prompts interactivos te guían por la selección de proveedor, las claves API y la configuración de canales:

```bash
nanobot onboard --wizard
```

Para refrescar la configuración de forma no interactiva después de editar `config.json` a mano:

```bash
nanobot onboard --refresh
```

Verifica que todo esté conectado:

```bash
nanobot status
```

Esto imprime un resumen de la configuración/workspace y valida tu proveedor y modelo activos. Si la clave del proveedor es incorrecta o falta, te lo dice aquí.

### Configuración desde el navegador con `nanobot webui` (puerto 8765)

La WebUI es la nueva forma recomendada de configurar nanobot. Te guía por proveedores, presets de modelos, apps MCP y tareas programadas en el navegador:

```bash
nanobot webui
```

Esto abre `http://127.0.0.1:8765` e imprime un enlace de login con un fragmento de credencial `#`. Flags útiles:

- `--no-open`: no abre el navegador automáticamente (útil en un VPS sin entorno gráfico)
- `--detach`: ejecuta la WebUI en segundo plano

Para un VPS remoto, tuneliza el puerto por SSH:

```bash
ssh -N -L 127.0.0.1:8765:127.0.0.1:8765 user@YOUR_SERVER_IP
```

Luego abre `http://127.0.0.1:8765` en tu navegador local. También puedes definir `NANOBOT_WEB_TOKEN` para exigir un token de login.

Desde la WebUI puedes gestionar proveedores, cambiar presets de modelos, instalar apps MCP desde un catálogo de presets y ver Tasks/Calendar para las Automations.

## Configurar MiniMax M3.1 Flash

La configuración vive en `~/.nanobot/config.json`. Usa referencias a variables de entorno para los secretos, así las claves API nunca quedan en texto plano en archivos de configuración.

### Obtener una clave API de MiniMax

1. Ve a [platform.minimax.io](https://platform.minimax.io) (global) o [minimaxi.com](https://www.minimaxi.com) (China continental)
2. Crea una cuenta y genera una clave API
3. Fíjate en qué plataforma estás, porque la URL base de la API es diferente

M3.1-Flash está disponible para todos los usuarios. M2.5 no (usuarios nuevos bloqueados desde el 2026-10-19).

<Notice type="success" title="Plan de codificación de MiniMax">
MiniMax ofrece planes de codificación con precios pensados para cargas de trabajo de desarrolladores. [Obtén un 10% de descuento con nuestro enlace de referencia](https://go.bitdoze.com/minimax). Si quieres [usar modelos GLM y MiniMax con la app Codex](/es/codex-app-cualquier-modelo/), las mismas claves API funcionan ahí también.
</Notice>

Exporta la clave para que nanobot pueda resolverla:

```bash
export MINIMAX_API_KEY="your-minimax-api-key"
```

Añádela a `~/.bashrc` o `~/.profile` para que persista entre sesiones.

### Añadir MiniMax a la configuración

Para la plataforma global:

```json
{
  "providers": {
    "minimax": {
      "apiKey": "${MINIMAX_API_KEY}"
    }
  },
  "modelPresets": {
    "minimax-flash": {
      "provider": "minimax",
      "model": "MiniMax-M3.1-Flash",
      "maxTokens": 8192,
      "contextWindowTokens": 1000000
    }
  },
  "agents": {
    "defaults": {
      "modelPreset": "minimax-flash"
    }
  }
}
```

Para la plataforma de China continental, añade el override de `apiBase`:

```json
{
  "providers": {
    "minimax": {
      "apiKey": "${MINIMAX_API_KEY}",
      "apiBase": "https://api.minimaxi.com/v1"
    }
  }
}
```

La sintaxis `${MINIMAX_API_KEY}` se resuelve desde el entorno al arrancar y nunca se escribe de vuelta en el archivo de configuración. Pruébalo:

```bash
nanobot -m "What's 42 * 17?"
```

Si obtienes una respuesta, MiniMax está conectado correctamente.

### Modo de pensamiento con el proveedor `minimaxAnthropic`

Si quieres profundidad de pensamiento ajustable (`reasoningEffort`), usa el endpoint compatible con Anthropic de MiniMax a través del proveedor `minimaxAnthropic`:

```json
{
  "providers": {
    "minimaxAnthropic": {
      "apiKey": "${MINIMAX_API_KEY}",
      "apiBase": "https://api.minimax.io/anthropic"
    }
  }
}
```

Para China continental, el endpoint es `https://api.minimaxi.com/anthropic`. La misma clave API funciona para ambos.

## Presets de modelos y modelos de fallback

nanobot v0.4.0 usa `modelPresets` para configuraciones de modelo con nombre. Cada preset fija un proveedor, un nombre de modelo, límites de tokens y una ventana de contexto. La sintaxis antigua `agents.defaults.model` sigue funcionando (se convierte en un preset `default` implícito), así que las configuraciones existentes no se rompen.

Esta es la configuración recomendada con dos presets y una cadena de fallback:

```json
{
  "providers": {
    "zhipu": { "apiKey": "${ZHIPU_API_KEY}" },
    "minimax": { "apiKey": "${MINIMAX_API_KEY}" }
  },
  "modelPresets": {
    "fast": {
      "provider": "zhipu",
      "model": "glm-5.3-flash",
      "maxTokens": 8192,
      "contextWindowTokens": 1000000
    },
    "deep": {
      "provider": "minimax",
      "model": "MiniMax-M3.1-Flash",
      "maxTokens": 8192,
      "contextWindowTokens": 1000000
    }
  },
  "agents": {
    "defaults": {
      "modelPreset": "fast",
      "fallbackModels": ["deep"]
    }
  }
}
```

El array `fallbackModels` significa: si el preset principal falla (rate limit, proveedor caído, error de autenticación), nanobot prueba el siguiente. Para máxima resiliencia, añade un fallback local con Ollama:

```json
{
  "modelPresets": {
    "ollama": {
      "provider": "ollama",
      "model": "qwen3:8b",
      "contextWindowTokens": 32000
    }
  },
  "agents": {
    "defaults": {
      "modelPreset": "fast",
      "fallbackModels": ["deep", "ollama"]
    }
  }
}
```

Ojo con la regla de la ventana de contexto más pequeña: nanobot construye el contexto hasta la ventana más pequeña de tu cadena, así que un modelo local de 32K lo limitará todo a 32K aunque tu principal sea de 1M. Si quieres modelos locales como fallback, [el mejor mini PC para LLMs locales y Ollama](/es/mejores-mini-pc-llm-local/) cubre la parte de hardware. Para instalar Ollama en sí, mira [instalar Ollama con Docker](/es/ollama-docker-instalacion/). Tanto `ollama` (`http://localhost:11434/v1`) como `vllm` son proveedores locales integrados.

En tiempo de ejecución, cambia de preset con `/model <name>` en el chat. Fija `"provider"` en cada preset. No confíes en la coincidencia de nombre de modelo para enrutar al proveedor correcto: es la fuente más común de errores de "model not found".

## Búsqueda web: DuckDuckGo por defecto, Brave Search opcional

Desde la v0.3.x, la búsqueda web por defecto de nanobot es DuckDuckGo. Es gratis, no necesita clave API y funciona de fábrica. Si no configuras nada, tu bot ya puede buscar en la web.

Si quieres mejores resultados o más control, Brave Search es la mejora. Eso sí, ten en cuenta que Brave pasó de suscripciones a créditos prepagados (hasta $20/mes gratis).

### Obtener una clave API de Brave Search

1. Ve a [brave.com/search/api](https://brave.com/search/api/)
2. Regístrate para una cuenta
3. El nivel gratuito te da hasta $20 en créditos prepagados al mes (sin suscripción)
4. Genera una clave API desde el dashboard

### Activar Brave en la configuración

```json
{
  "tools": {
    "web": {
      "search": {
        "provider": "brave",
        "apiKey": "${BRAVE_API_KEY}",
        "maxResults": 5
      }
    }
  }
}
```

Exporta la clave:

```bash
export BRAVE_API_KEY="your-brave-search-api-key"
```

<Notice type="warning" title="El campo `provider` es obligatorio">
Sin `"provider": "brave"` en la configuración, nanobot vuelve silenciosamente a DuckDuckGo aunque hayas puesto una clave API de Brave. Esto le pasa a todo el mundo que migra desde el formato de configuración antiguo. Si quieres DuckDuckGo, simplemente omite todo el bloque `tools.web.search`.
</Notice>

`maxResults` controla cuántos resultados trae nanobot por búsqueda (5 por defecto, rango 1-10). Otros proveedores de búsqueda integrados: tavily, jina (nivel gratuito de 10M de tokens), kagi, olostep, bocha, volcengine, keenable (gratis) y searxng (autoalojado).

## Configuración de Discord

Discord funciona bien para configuraciones de bots personales y de equipo. Los pasos de abajo coinciden con la documentación oficial de nanobot y no han cambiado desde la v0.1.

### Crear un bot de Discord

1. Ve a [discord.com/developers/applications](https://discord.com/developers/applications)
2. Haz clic en **New Application**, dale un nombre
3. Ve a **Bot** en la barra lateral izquierda, haz clic en **Add Bot**
4. Copia el token del bot

### Habilitar intents

Todavía en la página de configuración del Bot:

1. Baja hasta **Privileged Gateway Intents**
2. Habilita **MESSAGE CONTENT INTENT** (obligatorio, o el bot no podrá leer mensajes)
3. Opcionalmente habilita **SERVER MEMBERS INTENT** si planeas usar listas de permitidos

### Obtener tu ID de usuario

1. Abre la Configuración de Discord, ve a **Advanced**, habilita **Developer Mode**
2. Haz clic derecho en tu avatar en cualquier lugar de Discord
3. Haz clic en **Copy User ID**

### Configurar nanobot

```json
{
  "channels": {
    "discord": {
      "enabled": true,
      "token": "${DISCORD_BOT_TOKEN}",
      "allowFrom": ["YOUR_USER_ID"],
      "allowChannels": [],
      "groupPolicy": "mention",
      "streaming": true,
      "replyToMessage": false
    }
  }
}
```

Exporta el token del bot:

```bash
export DISCORD_BOT_TOKEN="your-discord-bot-token"
```

Desglose de campos:

- `allowFrom`: restringe quién puede hablar con el bot. Array vacío = cualquiera. Añade IDs de usuario para limitarlo. Para un bot personal, configúralo siempre.
- `allowChannels`: restringe en qué canales responde el bot. Vacío = todos los canales.
- `groupPolicy`: `"mention"` (por defecto) significa que el bot solo responde en canales de grupo cuando se le @menciona. Los MD siempre funcionan.
- `streaming`: transmite las respuestas token a token en vez de esperar la respuesta completa.
- `replyToMessage`: responde al mensaje concreto en vez de enviar uno nuevo.

### Invitar el bot a tu servidor

1. En el portal de desarrolladores de Discord, ve a **OAuth2** y luego **URL Generator**
2. En **Scopes**, marca `bot`
3. En **Bot Permissions**, marca `Send Messages` y `Read Message History`
4. Copia la URL generada y ábrela en tu navegador
5. Selecciona el servidor al que quieres añadir el bot

### Iniciar el gateway y verificar

Para una prueba rápida:

```bash
nanobot gateway
```

Envía un MD al bot en Discord. Debería responder. Si no pasa nada, revisa `nanobot status` y mira los logs del gateway. Para uso en producción, configura un servicio systemd (mira la [sección de systemd](#ejecutar-nanobot-como-servicio-systemd) más abajo).

## Ejemplo de configuración completa (v0.4)

Así se ve un `~/.nanobot/config.json` completo con GLM-5.3-Flash como principal, MiniMax M3.1 Flash como fallback, Brave Search, Discord y endurecimiento de seguridad:

```json
{
  "providers": {
    "zhipu": {
      "apiKey": "${ZHIPU_API_KEY}"
    },
    "minimax": {
      "apiKey": "${MINIMAX_API_KEY}"
    }
  },
  "modelPresets": {
    "fast": {
      "provider": "zhipu",
      "model": "glm-5.3-flash",
      "maxTokens": 8192,
      "contextWindowTokens": 1000000
    },
    "deep": {
      "provider": "minimax",
      "model": "MiniMax-M3.1-Flash",
      "maxTokens": 8192,
      "contextWindowTokens": 1000000
    }
  },
  "agents": {
    "defaults": {
      "modelPreset": "fast",
      "fallbackModels": ["deep"],
      "workspace": "~/.nanobot/workspace"
    }
  },
  "channels": {
    "discord": {
      "enabled": true,
      "token": "${DISCORD_BOT_TOKEN}",
      "allowFrom": ["YOUR_USER_ID"],
      "allowChannels": [],
      "groupPolicy": "mention",
      "streaming": true
    }
  },
  "tools": {
    "web": {
      "search": {
        "provider": "brave",
        "apiKey": "${BRAVE_API_KEY}",
        "maxResults": 5
      }
    },
    "exec": {
      "maxRuntime": 60,
      "sandbox": "bwrap"
    },
    "restrictToWorkspace": true
  },
  "gateway": {
    "host": "127.0.0.1",
    "port": 18790
  }
}
```

### Explicación de las configuraciones

| Configuración | Por defecto | Qué hace |
|---------|---------|-------------|
| `modelPresets.<name>.provider` | - | Qué adaptador de proveedor usar (fíjalo, no confíes en la coincidencia de nombre) |
| `modelPresets.<name>.model` | - | ID de modelo enviado al proveedor |
| `modelPresets.<name>.contextWindowTokens` | varía | Tamaño de la ventana de contexto; AutoCompact se dispara antes de este límite |
| `agents.defaults.modelPreset` | `default` | Qué preset usar por defecto |
| `agents.defaults.fallbackModels` | `[]` | Nombres de presets a probar si el principal falla |
| `agents.defaults.workspace` | `~/.nanobot/workspace` | Dónde viven la memoria, las skills y los archivos de bootstrap |
| `tools.exec.maxRuntime` | `3600` | Límite estricto de ejecución para comandos shell en segundos (`tools.exec.timeout` es un alias heredado) |
| `tools.exec.sandbox` | ninguno | Aislamiento de shell a nivel de proceso: `"bwrap"` (Linux) o `"seatbelt"` (macOS) |
| `tools.restrictToWorkspace` | `false` | Cuando es true, el acceso a archivos/shell se limita al workspace |
| `tools.web.search.provider` | `duckduckgo` | Proveedor de búsqueda web |
| `gateway.host` | `127.0.0.1` | Dirección de escucha. Usa `0.0.0.0` solo con autenticación configurada |
| `gateway.port` | `18790` | Puerto del gateway |

El contexto ahora se gestiona automáticamente: AutoCompact maneja los límites de tokens y Dream se encarga de la consolidación de memoria. Las antiguas configuraciones `maxToolIterations` y `memoryWindow` ya no están en la referencia de configuración.

## Sistema de memoria y archivos del workspace

nanobot guarda la memoria a largo plazo en dos archivos dentro del workspace:

| Archivo | Propósito |
|------|---------|
| `~/.nanobot/workspace/memory/MEMORY.md` | Datos a largo plazo que el bot recuerda |
| `~/.nanobot/workspace/memory/USER.md` | Tu información personal y preferencias (destino de la consolidación) |

Dile al bot que recuerde algo y lo escribe en `MEMORY.md`. El sistema Dream (`/compact`, `/dream`, `/dream-log`) consolida el historial de conversaciones en estos archivos periódicamente. El historial de sesiones en sí vive en SQLite desde la v0.4.0.

### Archivos de bootstrap del workspace

El workspace también tiene archivos de bootstrap que definen cómo se comporta el bot:

| Archivo | Propósito |
|------|---------|
| `AGENTS.md` | Configuración e instrucciones del agente |
| `SOUL.md` | Personalidad y reglas de comportamiento |
| `USER.md` | Tu información personal y preferencias |
| `TOOLS.md` | Instrucciones de uso de herramientas |
| `IDENTITY.md` | Overrides de identidad del bot |

Estos se cargan en el prompt del sistema cada vez que el bot procesa un mensaje. Edita `USER.md` para contarle al bot sobre ti:

```bash
nano ~/.nanobot/workspace/USER.md
```

Añade todo el contexto que quieras que el bot tenga siempre. Detalles de proyectos, estilo de comunicación preferido, preferencias técnicas. Edita `SOUL.md` para cambiar cómo se comunica.

## Soporte MCP

nanobot soporta [Model Context Protocol](/es/introduccion-mcp-principiantes/) para conectar servidores de herramientas externos. El formato de configuración es el mismo que Claude Desktop y Cursor, así que puedes copiar configuraciones de servidores MCP desde el README de cualquier servidor MCP. Desde la v0.4.0, los servidores MCP también se gestionan desde la sección **Apps** de la WebUI con un catálogo de presets.

### Añadir un servidor MCP

```json
{
  "tools": {
    "mcpServers": {
      "filesystem": {
        "command": "npx",
        "args": ["-y", "@modelcontextprotocol/server-filesystem", "/home/user/documents"]
      }
    }
  }
}
```

Funcionan dos modos de transporte:

| Modo | Campos de configuración | Ejemplo |
|------|--------------|---------|
| Stdio | `command` + `args` | Proceso local via `npx` o `uvx` |
| HTTP | `url` | Endpoint remoto como `https://mcp.example.com/sse` |

Las herramientas MCP se descubren y registran automáticamente cuando nanobot arranca. Para conectar con más de 1,500 apps via MCP, mira la [guía de Composio MCP para conectar más de 1,500 apps](/es/guia-composio-mcp/).

## Despliegue con Docker y Docker Compose

Docker Compose es el camino documentado y recomendado para nanobot en contenedores. No hay imagen oficial en un registry; la compilas desde el repo.

<Notice type="warning" title="El fallo de bind en Docker: el error nº 1">
El gateway se liga a `127.0.0.1` por defecto. El flag `-p` de Docker no puede alcanzar la interfaz loopback de un contenedor. Para publicar puertos, debes poner `gateway.host` en `0.0.0.0` en `config.json` Y configurar un `token`, `tokenIssueSecret` o `trustedProxyAuth`: nanobot se niega a arrancar WebSocket en `0.0.0.0` sin autenticación. Por eso "funciona en local pero no en Docker". Ten en cuenta también [por qué Docker se salta las reglas del firewall UFW](/es/docker-evita-firewall/).
</Notice>

### Inicio rápido con Docker Compose

```bash
git clone https://github.com/HKUDS/nanobot.git && cd nanobot
docker compose up -d
docker compose logs
```

El primer arranque inicializa la configuración con las direcciones de bind del contenedor y credenciales aleatorias para la WebUI. La contraseña se imprime en los logs. Abre `http://YOUR_HOST:8765` y configura tu proveedor en Settings.

El mount de datos es `~/.nanobot:/home/nanobot/.nanobot` (el contenedor corre como UID 1000, no root: no uses `/root/.nanobot`).

Verifica:

```bash
curl --fail http://127.0.0.1:18790/health
```

El endpoint de salud debería devolver 200. Publícalo solo en el loopback del host, no en internet.

### Build y ejecución manual con Docker

Si no quieres Compose:

```bash
# Build
docker build -t nanobot .

# Run with your config mounted
docker run -d \
  -v ~/.nanobot:/home/nanobot/.nanobot \
  -p 127.0.0.1:18790:18790 \
  --name nanobot \
  nanobot gateway
```

Los build args te permiten incluir canales y extras específicos: `NANOBOT_CHANNELS=telegram,slack`, `NANOBOT_EXTRAS=bedrock`. No uses imágenes Docker de terceros para nanobot; la documentación las marca explícitamente como no confiables.

La configuración de Compose incluye valores por defecto endurecidos (capability drop, no-new-privileges) y un override opcional de sandbox bwrap.

## Ejecutar nanobot como servicio systemd

Para operación 24/7, usa el instalador de servicios integrado de nanobot. Genera e instala un servicio systemd de usuario:

```bash
nanobot gateway install-service --manager systemd
```

Esto crea `~/.config/systemd/user/nanobot-gateway.service`, lo habilita y lo arranca. Previsualiza sin instalar:

```bash
nanobot gateway install-service --manager systemd --dry-run
```

Gestiona el servicio:

```bash
systemctl --user status nanobot-gateway
systemctl --user restart nanobot-gateway
journalctl --user -u nanobot-gateway -f
```

Para mantener los servicios de usuario vivos después de cerrar sesión:

```bash
loginctl enable-linger $USER
```

Para configuraciones multi-instancia (bot personal + bot de equipo), usa los flags `--name`, `--config` y `--workspace`. Desinstala con `nanobot gateway uninstall-service --manager systemd`.

<Notice type="info" title="Por qué falla el enfoque del unit file manual">
Los unit files escritos a mano con `ExecStart=/usr/local/bin/nanobot gateway` se rompen en instalaciones con `uv tool` (el binario vive en `~/.local/bin/`) y se ejecutan sin el entorno del usuario. El instalador integrado maneja las rutas y el entorno correctamente.
</Notice>

Para una alternativa más ligera a systemd, usa el modo daemon integrado:

```bash
nanobot gateway --background
nanobot gateway stop
nanobot gateway restart
```

## Automations: tareas programadas y /goal

Los comandos `nanobot cron add/list/remove` de la v0.1 ya no están en la referencia del CLI. La programación de tareas ahora la manejan las **Automations**, gestionadas en las vistas Tasks/Calendar de la WebUI.

Para crear una automatización, solo pídeselo al bot en una conversación: "Cada mañana a las 9, revisa el uso de disco de mi servidor y mándame un resumen." El bot crea la programación y aparece en la WebUI, donde puedes pausarla, reanudarla, renombrarla o editarla.

Para triggers locales (pipelines de CI, webhooks, scripts de shell), crea el trigger en el chat o en el tema de la WebUI donde deben llegar los resultados:

```
/trigger PR review
```

nanobot responde con un ID de trigger y un comando listo para copiar:

```bash
nanobot trigger trg_8K4P2Q9X "Review PR #4502"
```

Ejecuta ese comando desde tu script, webhook o job de CI para empujar un mensaje a la sesión. Si ejecutas varias instancias de nanobot, pasa la opción `--config` o `--workspace` correspondiente para que el trigger llegue a la correcta. El agente también tiene una herramienta `cron` que puede usar para tareas autoprogramadas.

`/goal` maneja tareas de larga duración: le das un objetivo de varios pasos y va trabajando en él con el tiempo.

Heartbeat está habilitado por defecto en el gateway (`gateway.heartbeat.enabled`). Revisa `HEARTBEAT.md` en tu workspace para tareas periódicas.

<Notice type="warning" title="Las programaciones perdidas no se reejecutan">
Si el gateway se reinicia, las programaciones de automatizaciones perdidas no se reejecutan. No confíes en Automations para trabajos críticos de facturación sin monitorización externa.
</Notice>

## Endurecimiento de seguridad

Lo básico importa más que las configuraciones exóticas. Esto es lo que debes configurar:

### Restricción de workspace y sandbox

```json
{
  "tools": {
    "restrictToWorkspace": true,
    "exec": {
      "sandbox": "bwrap"
    }
  }
}
```

`restrictToWorkspace` limita el acceso a archivos y shell a `~/.nanobot/workspace/`. Es una barrera a nivel de aplicación. Para aislamiento real a nivel de proceso, añade `exec.sandbox: "bwrap"` (Linux) o `"seatbelt"` (macOS). Usa ambos.

### Secretos en variables de entorno

Nunca pongas claves API en texto plano en la configuración. Usa la sintaxis `${VAR_NAME}`:

```json
{
  "providers": {
    "zhipu": { "apiKey": "${ZHIPU_API_KEY}" }
  }
}
```

Se resuelven desde el entorno al arrancar y nunca se escriben de vuelta en el archivo de configuración.

### Control de acceso por canal

Usa `allowFrom` (IDs de usuario) y `allowChannels` (IDs de canal) para restringir quién puede hablar con el bot. `groupPolicy: "mention"` (el valor por defecto) significa que el bot solo responde en chats de grupo cuando se le @menciona.

### Seguridad de la WebUI

No expongas el puerto 8765. Usa un túnel SSH o una VPN mesh. Si necesitas acceso desde la LAN, define `NANOBOT_WEB_TOKEN` o configura `trustedProxyAuth`.

### A nivel de red

Si estás en un VPS con Docker, lee [cómo aseguré mi servidor Docker de Hetzner](/es/informe-seguridad-bsi-docker-ufw/) para un endurecimiento de firewall y red que también aplica aquí. `tools.ssrfWhitelist` te permite restringir a qué URLs puede llegar la herramienta de fetch web del bot.

## Solución de errores comunes de nanobot

| Error | Causa | Solución |
|-------|-------|-----|
| 401 Unauthorized | Falta la clave API, tiene espacios en blanco o es del proveedor equivocado | Revisa `providers.<name>.apiKey`; verifica que las variables de entorno estén exportadas (`echo $MINIMAX_API_KEY`) |
| "model not found" | ID de modelo incorrecto para el proveedor | Revisa la lista de modelos del proveedor; fija `provider` en el preset |
| Connection refused | Servidor local caído o puerto `apiBase` incorrecto | Revisa la URL de `apiBase`; confirma que Ollama/vLLM esté corriendo |
| Funciona en el CLI pero no en el chat | Problema del gateway o del canal | Revisa `nanobot status`, los logs del canal, `allowFrom`/`allowChannels` |
| Clave de proveedor + modelo mezclados | **El fallo más común del primer arranque**: clave API de un proveedor con ID de modelo de otro | Haz coincidir la clave con el proveedor que sirve ese modelo |
| La WebUI no carga en Docker | Gateway ligado a `127.0.0.1`, `-p` no puede alcanzarlo | Pon `gateway.host: "0.0.0.0"` y configura un token de autenticación |
| Brave no se usa | Falta el campo `"provider": "brave"` | Añade el campo `provider` a `tools.web.search` |

Vale la pena repetir el error de clave proveedor/modelo mezclados: si copias un nombre de modelo GLM pero tu única clave configurada es de MiniMax, nanobot intentará usar la clave de MiniMax contra la API de Zhipu y fallará con un error confuso. Fija tus proveedores.

## Actualizar nanobot de forma segura

Actualiza con el mismo método que usaste para instalar:

```bash
# uv
uv tool upgrade nanobot-ai

# pip
pip install -U nanobot-ai

# From source
cd nanobot && git pull && python -m pip install -e .
```

<Notice type="info" title="Haz backup antes de actualizar">
Haz siempre backup de `~/.nanobot/` antes de actualizar. Ahí viven la configuración, la memoria del workspace y el historial de sesiones. Para el gateway primero, luego copia:
</Notice>

```bash
nanobot gateway stop
cp -r ~/.nanobot ~/.nanobot.bak
# Now upgrade
uv tool upgrade nanobot-ai
```

La v0.4.0 migra el historial de sesiones a SQLite (importa las conversaciones existentes y conserva backups de origen). Las actualizaciones dentro de la app desde la WebUI requieren aprobación verificada de releases.

Para volver atrás: restaura el backup y reinstala la versión anterior (`uv tool install nanobot-ai==0.3.5` o la que tuvieras).

|--------|---------|----------|

| Tiempo de configuración | ~5 minutos | ~20 minutos |

OpenClaw tiene un asistente de configuración pulido y el flujo OAuth para usar suscripciones existentes de Claude/ChatGPT está bien. nanobot se instala más rápido, soporta más proveedores y canales, y tiene la WebUI para tareas de administración. </Accordion>

Por supuesto. Configura ambos canales en el mismo `config.json` y el gateway los maneja simultáneamente. Mira la [guía de configuración de OpenClaw](/es/guia-configuracion-openclaw/) para los pasos de creación del bot de Telegram: el flujo de BotFather es idéntico.
</Accordion>

<Accordion label="¿Qué es `nanobot serve`?" group="faq">
Inicia una API compatible con OpenAI en el puerto 8900 con los endpoints `/v1/chat/completions`, `/v1/models` y `/health`. Apunta cualquier herramienta compatible con OpenAI a tu instancia de nanobot. Útil si quieres que otras apps usen el mismo pipeline de modelo.
</Accordion>

<Accordion label="¿Soporta nanobot la voz?" group="faq">
Sí. La transcripción de voz está integrada, con Groq como proveedor por defecto. También se soportan OpenAI, OpenRouter, Xiaomi MiMo, StepFun, AssemblyAI y SiliconFlow.
</Accordion>
