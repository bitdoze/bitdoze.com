## Cómo scrapear un sitio web a WordPress sin plugin

Antes de pagar por un plugin, considera mantener el scraping **fuera** de la caja de WordPress por completo. Un scraper de contenido que corre dentro de tu sitio acopla tres dominios de fallo: cambios en el sitio de destino, límites de recursos de PHP y tu base de datos de producción. Un scraper externo que publica por la REST API de WordPress (`/wp-json/wp/v2/posts` con una contraseña de aplicación) maneja objetivos cargados de JavaScript mejor que cualquier plugin de aquí y falla de forma segura: el peor caso es una petición rechazada, no una entrada a medio escribir.

Dos rutas funcionan bien: un flujo de trabajo autoalojado de n8n, o un script de Python/Playwright programado con cron.

**Requisitos previos:**

<ListCheck>
<ul>
<li>Contraseña de aplicación de WordPress creada (Usuarios → Perfil → Contraseñas de aplicación (tu sitio necesita HTTPS))</li>
<li><code>curl</code> y <code>xmllint</code> instalados (o Python 3 + Playwright para la ruta del script)</li>
<li>Robots.txt y ToS del sitio de destino revisados</li>
<li>Una copia de seguridad hecha antes de que aterrice la primera entrada automatizada</li>
</ul>
</ListCheck>

<Tab name="n8n (sin código)">
n8n te da un flujo de trabajo visual: un nodo HTTP Request o HTML Extract obtiene y parsea la página de destino, luego un nodo de WordPress (o un nodo HTTP Request normal) publica en `/wp-json/wp/v2/posts`. La programación viene integrada, así que no tocas WP-Cron en absoluto.

Si ya usas Docker, [autoaloja n8n para flujos de scraping y publicación](/es/automatizacion-n8n-autoalojado/). Lleva unos diez minutos y mantiene el editor de flujos en tu propia máquina.

La ruta de n8n es la que yo elegiría para no desarrolladores: ves cada paso, puedes repetir un solo nodo para depurar, y un selector roto falla en n8n en lugar de publicar una entrada vacía.
</Tab>
<Tab name="Python + Playwright (código)">
Para objetivos cargados de JS, Playwright es la respuesta honesta: renderiza la página como un navegador real, espera a los selectores y extrae lo que necesitas. Mantén el script fuera del document root de WordPress, ejecútalo desde cron y publica por la REST API.

```python
import requests
from playwright.sync_api import sync_playwright

WP = "https://yoursite.com"
AUTH = ("admin", "xxxx-xxxx-xxxx-xxxx")  # contraseña de aplicación

with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.goto("https://example.com/target-page")
    page.wait_for_selector("h2.title")
    title = page.locator("h2.title").first.inner_text()
    body = page.locator("div.article-body").first.inner_html()
    browser.close()

# publica como borrador primero; revisa antes de publicar
r = requests.post(f"{WP}/wp-json/wp/v2/posts", auth=AUTH, json={
    "title": title,
    "content": body,
    "status": "draft",
})
print(r.status_code, r.json().get("id"))
```

Para mantener las dependencias fuera del host, [ejecuta un scraper de Python Playwright en Docker](/es/docker-ejecutar-python/) y programa el contenedor con cron o temporizadores de systemd.
</Tab>
<Tab name="Comprobación puntual con cURL">
Antes de configurar cualquier plugin o flujo, comprueba que tu selector coincide. Este one-liner obtiene la página y extrae un nodo sin ningún plugin de por medio:

```bash
curl -s -A "Mozilla/5.0" https://example.com/target-page | xmllint --html --xpath '//h2[@class="title"]/text()' - 2>/dev/null | head
```

Si no imprime nada, tu selector está mal. Arréglalo aquí, no dentro de WordPress. Luego crea la entrada por la REST API con una contraseña de aplicación:

```bash
curl -u "admin:xxxx-xxxx-xxxx-xxxx" https://yoursite.com/wp-json/wp/v2/posts \
  -H "Content-Type: application/json" \
  -d '{"title":"Scraped title","content":"<p>Body content</p>","status":"draft"}'
```

**Verifica:** abre wp-admin → Entradas → Borradores (o `GET /wp-json/wp/v2/posts?status=draft`) y confirma que el borrador está ahí con el título y el cuerpo correctos. Un `401` significa que la contraseña de aplicación está mal; un `404` en el endpoint significa que los permalinks bonitos o la REST API están desactivados.
</Tab>
</Tabs>

<Notice type="warning" title="Publica como borrador primero">
Crea siempre las entradas con `"status": "draft"` hasta que hayas confirmado que la extracción funciona de punta a punta. Revisa uno o dos borradores y luego cambia el flujo a publicar. Esto evita el fallo clásico en el que un cambio de selector publica una riada de entradas vacías en tu sitio en producción.
</Notice>

## Solución de problemas de plugins scraper de WordPress: WP-Cron, límites y fallos silenciosos

Todo plugin crawler acaba chocando con los mismos cuatro modos de fallo. Ninguno aparece en las capturas de la página de ventas. Si vas a dejar que un crawler escriba entradas automáticamente, asegúrate de tener primero [plugins gratuitos de copias de seguridad para WordPress](/es/mejores-plugins-gratuitos-backup-wordpress/) en marcha.

### Los scrapeos programados no se disparan (WP-Cron)

WordPress programa estas tareas con WP-Cron, que solo se dispara cuando alguien visita tu sitio. En un sitio con poco tráfico, las programaciones derivan en silencio y tu scraper corre a las 3 PM en lugar de a las 3 AM, o no corre. La solución es desactivar WP-Cron y llamarlo desde el cron del sistema:

```php
// wp-config.php
```

### Límites de memoria y timeouts en hosting compartido

Obtener y parsear páginas es más pesado que servirlas. En hosting compartido, un rastreo de 50 URL puede agotar `memory_limit` o chocar con `max_execution_time` a mitad de ejecución, dejando contenido a medio importar. Empieza con 3-5 URL por ejecución y vigila `php -i` para ambos valores. Si los límites muerden de forma consistente, tienes dos opciones: ajustar el caché para que tus workers de PHP queden libres para el crawler ([acelera WordPress con Cloudflare, Varnish y Redis](/es/acelerar-wordpress-cloudflare-varnish-redis/)), o moverte a una máquina con más margen. Un VPS pequeño cuesta un dígito de dólares al mes frente a 10-30 $ del WordPress gestionado. Para esto, [un VPS barato de Hetzner](https://go.bitdoze.com/hetzner) es lo que yo elegiría por defecto, o [hosting gestionado de WordPress como Cloudways](https://go.bitdoze.com/cloudways) si no quieres administrar un servidor en absoluto. Si esperas rastreos programados pesados, mira [cómo elegir un VPS que los aguante (benchmarks ARM vs x86)](/es/comparativa-arm-vs-x86-vps/).

### Fallos silenciosos: entradas vacías cuando el sitio de destino cambia

<Notice type="warning" title="El fallo silencioso nº 1">
El sitio de destino cambia su marcado, tus selectores devuelven cadenas vacías y el plugin publica alegremente una entrada vacía o a medias en la programación. Nada da error. Nadie se entera en dos semanas. Así es como los sitios scraper mueren en silencio.
</Notice>

Tres hábitos evitan que esto ocurra:
- Revisa las entradas recientes y el registro del plugin semanalmente. Lleva dos minutos.
- Activa «saltar la publicación si el contenido es más corto que N caracteres» donde el plugin lo ofrezca (la mayoría de las opciones de pago lo tienen).
- Audita lo que el crawler publicó: [exporta todas las URL y títulos de tus entradas de WordPress](/es/exportar-urls-titulos-wordpress/) y compara la lista con lo que esperabas.

### Peticiones bloqueadas (403/429)

Un 403 o 429 significa que el destino te está limitando la tasa o bloqueando. No vayas primero al proxy. Ralentiza la programación del rastreo, identifica tu crawler en el User-Agent y corrige el ritmo. Los cuatro plugins de pago soportan proxies cuando de verdad los necesitas, pero el ancho de banda residencial a más de 2,50 $/GB suma rápido, y no deberías pagar proxies para arreglar un problema de límite de tasa que un cron más lento resuelve gratis.

Para multifuente social o generación con IA, WordPress Automatic es la elección: nada más aquí importa de YouTube, Reddit y Amazon y genera artículos a partir de palabras clave. Para scraping estándar de HTML estático con selector visual, [Scrapes](https://octolooks.com/wordpress-auto-post-and-crawler-plugin-scrapes/) es la compra más segura hoy (fabricante vivo, 29 $, amable con hosting compartido); [WP Content Crawler](https://1.envato.market/kPGkz) tiene el inspector más bonito e integración con ChatGPT, pero lee antes el aviso sobre el estado del fabricante. Para migración puntual de páginas, [WP Scraper](https://wordpress.org/plugins/wp-scraper/) es gratis y suficiente.

No compres por la lista de funciones. Compra por si el fabricante respondió tickets de soporte este mes. Crawlomatic y WordPress Automatic (ambos de ValvePress) publicaron actualizaciones durante 2025; el último dato firme de Scraper es de 2023; los docs de WP Content Crawler están caídos. Presupuesta en consecuencia.

Elijas el plugin que elijas, acompáñalo de un servicio de proxy si scrapeas a un volumen real. [Bright Data](https://go.bitdoze.com/brightdata) cubre residencial desde 2,50 $/GB y datacenter desde 0,90 $/IP. Y revisa siempre los términos de servicio del sitio de destino: scrapear contenido con copyright sin permiso puede crear problemas legales uses la herramienta que uses.

## Preguntas frecuentes

<Accordion label="¿Es legal scrapear contenido de otros sitios?" group="faq" expanded="true">
Para datos de acceso público en EE. UU., el scraping es en gran medida una cuestión contractual más que penal. hiQ v. LinkedIn fue reafirmado por el Noveno Circuito para datos públicos después de que *Van Buren v. United States* (2021) estrechara la CFAA. Las limitaciones reales son los términos de servicio del sitio y la ley de copyright. No republiques contenido con copyright al por mayor; extractos cortos con enlace de vuelta son el camino aburrido y seguro. Revisa los ToS antes de scrapear, no después.
</Accordion>

<Accordion label="¿Necesito un proxy para scrapear hacia WordPress?" group="faq">
No a bajo volumen con programaciones educadas: unas pocas páginas al día con pausas adecuadas rara vez dispara nada. Sí cuando empieces a ver respuestas 403/429, y sí para cualquier volumen real. Arregla primero la programación; luego añade proxies. El ancho de banda residencial empieza en unos 2,50 $/GB con [Bright Data](https://go.bitdoze.com/brightdata); las IPs de datacenter son más baratas (desde 0,90 $/IP) y valen para obtenciones sencillas.
</Accordion>

<Accordion label="¿Pueden los plugins scraper de WordPress con sitios renderizados por JavaScript?" group="faq">
Solo uno lo hace dentro del plugin: Crawlomatic (navegador headless). Scraper puede con su complemento PRO a 9 $/mes. Todo lo demás de la tabla obtiene HTML crudo y nada más. Para un objetivo fiablemente cargado de JS, el script externo de Playwright de [la sección sin plugin](#cómo-scrapear-un-sitio-web-a-wordpress-sin-plugin) supera a todos. Renderiza las páginas como un navegador real y publica por la REST API.
</Accordion>

<Accordion label="¿Cuál es la forma más barata de scrapear un sitio web a WordPress?" group="faq">
0 $ si la fuente publica un feed RSS: FeedWordPress. 0 $ para importaciones puntuales de páginas: WP Scraper. Si no, las opciones de pago cuestan 29-39 $ en un pago, que es el coste de dos meses de la mayoría de scrapers SaaS. No pagues cuota mensual a menos que necesites renderizado de JavaScript a escala.
</Accordion>

<Accordion label="¿Por qué mi scraper publica entradas vacías o duplicadas?" group="faq">
Las entradas vacías suelen significar que el sitio de destino cambió su marcado y los selectores ya no coinciden con nada. Las entradas duplicadas suelen significar que la detección de duplicados está apagada o que las URL de origen cambiaron. Ambas están cubiertas en [la sección de solución de problemas](#solución-de-problemas-de-plugins-scraper-de-wordpress-wp-cron-límites-y-fallos-silenciosos). La versión corta es: pon una puerta a la publicación con una longitud mínima de contenido, y revisa lo que el crawler publica cada semana.
</Accordion>

Elige la opción mantenida. Ejecuta una obtención manual antes de activar cualquier programación, y revisa los términos del sitio de destino antes de la primera petición. Un scraper que publica con fiabilidad a ritmo lento supera a uno rápido que consigue que te bloqueen la IP o que llena tu sitio de entradas vacías.
