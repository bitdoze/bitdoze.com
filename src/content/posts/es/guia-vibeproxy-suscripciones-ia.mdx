Ya pagas por Claude Code, ChatGPT Plus u otra suscripción de IA. ¿Por qué volver a pagar por acceso a la API? VibeProxy es una app de macOS para la barra de menús que enruta tus suscripciones existentes hacia herramientas de código como Factory AI Droids, Amp Code, Zed, Codex CLI y cualquier otra aplicación compatible con OpenAI. Sin claves API: entra OAuth, salen llamadas a modelos.

Desde la primera versión de esta guía, la lista de proveedores ha crecido más allá de Claude, Codex y Gemini. VibeProxy ahora también conecta GitHub Copilot, Kimi y Z.AI GLM (Qwen ya estaba antes), y puede ejecutar varias cuentas por proveedor con failover automático.

- **Deja de pagar dos veces** por la IA reutilizando las suscripciones que ya financias
- **Instala VibeProxy** en macOS con descargas DMG/ZIP verificadas (builds para Intel incluidas)
- **Conecta Claude Code, Codex, Gemini, GitHub Copilot, Kimi, Qwen y Z.AI GLM**
- **Configura Factory Droids, Amp Code, Zed, Codex CLI y otras herramientas** contra el proxy local
- **Ejecuta round-robin multi-cuenta** y fija proveedores con los interruptores Priority
- **Consulta los IDs de modelo vigentes** de cada proveedor compatible (tablas de referencia 2026)

</Notice>

## ¿Qué es VibeProxy?

[VibeProxy](https://github.com/automazeio/vibeproxy) es una app de macOS gratuita con licencia MIT de Automaze (unas 3.393 estrellas en GitHub a fecha de 2026-10-21). Se ejecuta en la barra de menús y crea un proxy local en el puerto **8317**. Tus herramientas de código hablan con ese proxy; el proxy habla con tus suscripciones existentes a través del [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) integrado, que gestiona OAuth, la renovación de tokens y el enrutado. (El binario incluido todavía se llama `cli-proxy-api-plus`, un vestigio del fork retirado CLIProxyAPIPlus. Ignora el nombre.)

![Arquitectura de VibeProxy: las herramientas de código se conectan por loopback al proxy de VibeProxy en el puerto 8317, que enruta a través del backend CLIProxyAPI integrado en el puerto 8318 hacia los proveedores de suscripciones](@assets/images/25/12/vibeproxy-architecture.svg)

Dos puertos locales importan: **8317** es el proxy al que apuntan tus herramientas, **8318** es el backend de CLIProxyAPI que hay detrás. Ambos hacen bind a loopback. Más sobre esto en [Consideraciones de seguridad](#consideraciones-de-seguridad).

### ¿Por qué usar VibeProxy?

<ListCheck>

- Gasta la cuota de tu suscripción de tarifa plana en lugar de pagar tarifas de API por token
- Un solo proxy sirve muchos modelos: Claude Opus 4.7, Sonnet 4.6, GPT-5.5, Gemini 3.1, modelos alojados en Copilot, GLM-5
- OAuth en el navegador por proveedor, así que no hay claves API que gestionar; los tokens permanecen en local y se renuevan automáticamente
- Varios inicios de sesión por proveedor te dan distribución round-robin y failover cuando una cuenta alcanza un límite de peticiones
- Los sufijos `-thinking-N` exponen los presupuestos de razonamiento de Claude
- Sparkle comprueba a diario y actualiza tanto VibeProxy como el CLIProxyAPI integrado
- Cualquier cosa que hable el formato de API de OpenAI o Anthropic puede apuntar a él

</ListCheck>

**[COSTE]** La propia VibeProxy cuesta 0 $. El ahorro viene de no pagar dos veces: si ya financias un plan de Claude o ChatGPT de más de 20 $/mes, cada llamada a la API a través de una herramienta de terceros es dinero que no gastas dos veces.

## Instalación de VibeProxy en macOS (DMG + SHA-256, nota sobre Intel)

<Notice type="warning" title="Requisitos del sistema">

- **macOS 13.0 (Ventura)** o posterior (`LSMinimumSystemVersion` en el bundle de la app)
- **Apple Silicon** (M1/M2/M3/M4/M5) o **Intel x86_64**. Las builds para Intel se distribuyen desde la v1.8.58 (2026-01-15) pero están oficialmente marcadas como **sin probar**. Úsalas e informa de los problemas en el repositorio.
- Una suscripción activa (o una clave API de GLM) de al menos un proveedor compatible
- Nada más escuchando en los puertos **8317** (proxy) o **8318** (backend)

</Notice>

### Requisitos previos

<ListCheck>

- macOS 13.0+ en Apple Silicon o Intel
- Al menos una suscripción de IA compatible
- Puertos 8317 y 8318 libres en la máquina

</ListCheck>

Comprobación rápida de conflictos de puertos:

```bash
lsof -i :8317 -i :8318
# empty output = ports are free
```

### Descargar y verificar la release

Las releases se publican por arquitectura tanto en DMG como en ZIP, cada una con un archivo `.sha256` (el DMG más reciente pesa unos 34 MB en la v1.8.341, 2026-10-21):

| Archivo | Uso |
|------|---------|
| `VibeProxy-arm64.dmg` / `.zip` | Macs con Apple Silicon |
| `VibeProxy-x86_64.dmg` / `.zip` | Macs Intel (builds sin probar) |
| `*.sha256` | archivo de checksum junto a cada paquete |

<Tabs>
<Tab name="Instalar con DMG">
1. Descarga `VibeProxy-arm64.dmg` (o `VibeProxy-x86_64.dmg`) desde la [página de releases](https://github.com/automazeio/vibeproxy/releases)
2. Verifica el checksum:

```bash
shasum -a 256 -c VibeProxy-arm64.dmg.sha256
# expect: VibeProxy-arm64.dmg: OK
```

3. Haz doble clic en el DMG y arrastra `VibeProxy.app` a `/Applications`
4. Expulsa el DMG y abre VibeProxy desde Aplicaciones

</Tab>

```bash
# expect: VibeProxy-arm64.zip: OK
```

3. Descomprime y mueve la app:

```bash
unzip VibeProxy-arm64.zip
```

4. Abre VibeProxy desde `/Applications`

**Verificación:** `VibeProxy.app` está en `/Applications` y se abre sin diálogo de Gatekeeper. **Si falla:** en raras ocasiones puede aparecer un diálogo de «damaged». Elimina la cuarentena y reintenta:


### Primer inicio

1. Abre VibeProxy desde `/Applications`
2. Aparece un icono en la barra de menús (punto verde = servidor en marcha)
3. Haz clic en el icono y selecciona «Open Settings»
4. El proxy se inicia automáticamente en el puerto **8317**

**Verificación:** el estado en la barra de menús está en verde, y una sonda rápida responde en el puerto del proxy:

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8317
# any HTTP status means the listener is up (404/401 are fine for a bare probe)
```

**Si falla:** que no aparezca el icono en la barra de menús indica una build antigua con un bug de TCC/entitlements (corregido en la v1.8.313). Actualiza la app desde la página de releases.

## Conectar tus suscripciones de IA

Con VibeProxy en marcha, autentica cada proveedor que quieras usar. El flujo es el mismo en todas partes: haz clic en «Connect» en Settings, completa el OAuth en el navegador y VibeProxy detecta la finalización automáticamente.

### Conectar Claude Code

1. Haz clic en el icono de VibeProxy en la barra de menús y selecciona «Open Settings»
2. Haz clic en «Connect» junto a Claude Code
3. Inicia sesión cuando se abra el navegador
4. VibeProxy detecta la finalización y guarda los tokens

**Si falla:** si el token caducó o el proveedor aparece desconectado, usa «Disconnect» y luego «Connect» de nuevo (ver [Solución de problemas](#solución-de-problemas)).

### Conectar OpenAI Codex

1. Haz clic en «Connect» junto a Codex en Settings
2. Completa la autenticación en el navegador con tu cuenta de ChatGPT
3. Espera a que VibeProxy confirme la conexión

### Conectar Antigravity (Gemini 3 y Claude-via-Antigravity)

<Notice type="info" title="Antigravity frente a Gemini CLI">

- **Antigravity** te da **Gemini 3.x** (`gemini-3.1-pro-preview`, `gemini-3-pro-preview`) **y** los modelos Claude-via-Antigravity con una generosa cuota compartida
- **Gemini CLI** te da la familia **2.x** (`gemini-2.5-pro`, `gemini-2.5-flash`)
- Conecta ambos si quieres la gama completa

</Notice>

1. Haz clic en «Connect» junto a Antigravity
2. Inicia sesión con tu cuenta de Google y concede acceso a los modelos
3. Reinicia VibeProxy para activar la lista de modelos Gemini 3.x

### Conectar Gemini CLI

1. Haz clic en «Connect» junto a Gemini
2. Inicia sesión con tu cuenta de Google
3. Selecciona un proyecto de Google Cloud (o acepta el predeterminado)
4. VibeProxy guarda las credenciales en `~/.cli-proxy-api/`

### Conectar GitHub Copilot

1. Haz clic en «Connect» junto a GitHub Copilot en Settings
2. Introduce el código de dispositivo en GitHub (el código se copia con su guion, así que pegarlo funciona directamente)
3. Autoriza a VibeProxy contra tu cuenta de GitHub

Necesitas una suscripción Copilot activa. La recompensa merece la pena: obtienes **modelos de Claude, GPT y Gemini a través de la API de GitHub con una cuota separada**. Si estás eligiendo o replanteándote ese plan, lee primero [nuestra guía de GitHub Copilot Pro](/es/guia-completa-github-copilot/).

<Notice type="warning" title="Multiplicadores de solicitudes premium de Copilot">

Copilot factura los modelos premium a tarifas diferentes. A finales de 2026: `claude-opus-4.6` cuenta como **3x**, `claude-sonnet-4.6` como **1x**, `claude-haiku-4.5` como **0.33x**. Opus a través de Copilot es la forma más rápida de quemar un plan. Si tu uso acaba de pasar a facturarse por consumo, [los cambios de precio por uso de GitHub Copilot y las alternativas más baratas](/es/alternativas-github-copilot-2026/) repasa los números y las salidas.

</Notice>

### Conectar Kimi, Qwen y Z.AI GLM

- **Kimi** y **Qwen**: el mismo flujo de Connect y OAuth. Los IDs de modelo de Kimi no están enumerados en la documentación oficial; usa la lista de proveedores dentro de la app.
- **Z.AI GLM** es la excepción. Usa una clave API en lugar de OAuth: genera una en tu cuenta de Z.AI (página de gestión de claves API), luego pulsa «Add Account» en los ajustes de VibeProxy y pégala. La clave se guarda en `~/.cli-proxy-api/` igual que los tokens OAuth.

**Verificación (todos los proveedores):** cada proveedor que vayas a usar aparece como «Connected» en Settings. Luego ejecuta un prompt de prueba desde cualquier herramienta configurada y confirma que recibes una respuesta. Un error como `auth_unavailable: no auth available` significa que el proveedor de ese modelo aún no está autenticado.

## Configurar Factory AI Droids

[Factory Droid CLI](https://go.bitdoze.com/droid-cli) es un agente de código con IA que acepta definiciones de modelos personalizadas. Apunta esas definiciones a VibeProxy y tus suscripciones ejecutan toda la sesión.

### Instalar Factory CLI

```bash
curl -fsSL https://app.factory.ai/cli | sh
```

### Configurar modelos personalizados

Crea o edita `~/.factory/config.json`. El patrón: los modelos de Claude con formato Anthropic usan `base_url: http://localhost:8317` con `provider: "anthropic"`; todo lo demás pasa por `http://localhost:8317/v1` con `provider: "openai"`. El `api_key` es un placeholder; VibeProxy lo ignora.

```json

  "custom_models": [
    {
      "model_display_name": "CC: Opus 4.7 (High)",
      "model": "claude-opus-4-7-thinking-32000",
      "base_url": "http://localhost:8317",
      "api_key": "dummy-not-used",
      "provider": "anthropic"
    },
    {
      "model_display_name": "CC: Sonnet 4.6",
      "model": "claude-sonnet-4-6",
      "base_url": "http://localhost:8317",
      "api_key": "dummy-not-used",
      "provider": "anthropic"
    },
    {
      "model_display_name": "GPT-5.3 Codex",
      "model": "gpt-5.3-codex",
      "base_url": "http://localhost:8317/v1",
      "api_key": "dummy-not-used",
      "provider": "openai"
    },
    {
      "model_display_name": "Gemini 3.1 Pro",
      "model": "gemini-3.1-pro-preview",
      "base_url": "http://localhost:8317/v1",
      "api_key": "dummy-not-used",
      "provider": "openai"
    }
  ]
}
```

### Usar Factory con VibeProxy

1. Ejecuta Factory CLI:

```bash
droid
```

2. Selecciona un modelo con `/model` y elige una de tus entradas personalizadas
3. A programar. Todas las peticiones se enrutan por VibeProxy automáticamente.

**Verificación:** `/model` lista tus modelos personalizados y un prompt de prueba devuelve una respuesta. **Si falla:** los 404 de Factory suelen significar que VibeProxy no está en marcha o que el `base_url` es incorrecto. Revisa el estado en la barra de menús y los valores de `base_url` de arriba.

## Configurar Amp Code

[Amp Code](/es/amp-code-agente-ia-gratis/) de Sourcegraph funciona con VibeProxy, pero las reglas han cambiado. El viejo truco del secrets.json ya no existe, y **no hay fallback a créditos de Amp** para modelos que no hayas autenticado. Eso concuerda con [por qué se pausó el tier gratuito de Amp Code](/es/amp-code-agente-ia-gratis/): cuando todos los interruptores de proveedor están apagados, Amp recurre a su propio tier gratuito con límite de peticiones. Para cualquier otra cosa, autenticas el proveedor o no obtienes nada.

<Notice type="warning" title="Ya no hay fallback">

Si Amp pide un modelo cuyo proveedor no está conectado, obtienes `auth_unavailable: no auth available`. Amp **no** gasta sus propios créditos en silencio. Autentica el proveedor (o elige un modelo de un proveedor que sí hayas autenticado).

</Notice>

### Apuntar Amp a VibeProxy

```bash

echo '{"amp.url": "http://localhost:8317"}' > ~/.config/amp/settings.json
```

**Cómo se divide el tráfico de Amp:** las llamadas de gestión (`/auth/cli-login`, `/api/*`) se reenvían a ampcode.com; las llamadas de modelo (`/provider/*`) van al backend de CLIProxyAPI en **8318**. No hay nada que configurar para esa división.

## Multi-cuenta y prioridad de proveedores

Dos funciones del mismo panel de Settings hacen el trabajo pesado en el uso diario.

### Multi-cuenta (v1.7.0+)

Añade varias cuentas por proveedor. VibeProxy distribuye las peticiones entre ellas en round-robin y conmuta automáticamente cuando una cuenta alcanza un límite de peticiones. Las listas de cuentas son plegables; las cuentas se pueden eliminar individualmente.

**[COSTE]** Esta es la mitigación práctica de límites de peticiones para usuarios de Max/Pro. Dos cuentas de Claude significan que una puede enfriarse en la ventana de 5 horas mientras la otra sirve. No duplica tu cuota por ventana; la reparte y le da respaldo.

### Interruptores de prioridad de proveedores (v1.8.51+)

Activa o desactiva proveedores en Settings. Los proveedores desactivados ven sus modelos excluidos de la lista servida (`oauth-excluded-models` internamente), y el cambio se recarga en caliente sin reiniciar la app.

Cuándo usar los interruptores:

<ListCheck>

- **Fija un solo proveedor** cuando quieras un enrutado predecible
- **Omite un proveedor limitado** por tasa de peticiones sin cerrar su sesión
- **Resuelve colisiones de nombres de modelo** entre proveedores (el problema de punto vs guion de la referencia de modelos)

</ListCheck>

**Verificación:** desactiva un proveedor en Settings y confirma que sus modelos desaparecen de la lista de modelos de tu herramienta conectada sin reiniciar.

<Accordion label="¿Añadir una segunda cuenta duplica mi cuota?" group="faq">

No. Los proveedores miden por cuenta (y a menudo por organización). Una segunda cuenta te da una segunda ventana independiente y capacidad de failover, no una supercuota fusionada. Si ambas cuentas están en el mismo plan de equipo, pueden compartir límites a nivel de equipo.

</Accordion>

## Modo de pensamiento extendido

VibeProxy expone el Extended Thinking de Claude codificando el presupuesto en el nombre del modelo. Añade un sufijo a cualquier ID de modelo de Claude:

```
{model-name}-thinking-{NUMBER}
```

**Presets** (las mismas etiquetas que usa el ecosistema de Claude):

- `-thinking-4000`: «think» (~4K tokens)
- `-thinking-10000`: «think harder» (~10K tokens)
- `-thinking-32000`: «ultra think» (~32K tokens)

Funciona en Claude 3.7+, Opus 4/4.7 y Sonnet 4/4.6. Ejemplo:

```json
{
  "model": "claude-opus-4-7-thinking-10000"
}
```

Qué ocurre: VibeProxy quita el sufijo `-thinking-10000`, fija el parámetro de presupuesto de pensamiento en 10.000 tokens y reenvía la petición. La respuesta incluye los pasos de razonamiento.

## Overrides avanzados de `config.yaml`

Los usuarios avanzados disponen de un archivo de overrides persistente en `~/.cli-proxy-api/config.yaml`. VibeProxy lo fusiona con los valores por defecto incluidos en `~/.cli-proxy-api/merged-config.yaml` y recarga en caliente sin reiniciar la app.

<Notice type="info" title="Nunca edites merged-config.yaml">

`merged-config.yaml` se regenera en cada fusión. Es un diagnóstico de solo lectura: útil para confirmar cuál es la configuración efectiva. Pon tus ediciones en `~/.cli-proxy-api/config.yaml`.

</Notice>

El ejemplo del README que conviene conocer: forzar verbosidad baja en todas las peticiones GPT.

```yaml
payload:
  default:
    - models:
        - name: "gpt-*"
      protocol: "codex"
      params:
        "text.verbosity": "low"
```

Dos semánticas entre las que elegir:

| Clave | Comportamiento |
|-----|----------|
| `default` | Rellena el parámetro solo cuando el cliente no envía nada (no anula a una herramienta que fija su propio valor) |
| `override` | Impone siempre el valor, independientemente de lo que haya enviado el cliente |

Valores de verbosidad: `low`, `medium`, `high`.

**Verificación:** cambia el archivo y envía la siguiente petición. El cambio debería aplicarse sin reiniciar VibeProxy. **Si falla:** una errata de YAML hace que tu regla no se aplique en silencio; revisa el log de la app/proxy y luego haz diff contra `merged-config.yaml` para ver si tu regla llegó a la configuración efectiva.

<Accordion label="Estado de VibeProxy en la barra de menús" group="troubleshoot">

- Un punto verde significa que el servidor está en marcha; un punto rojo, que se detuvo
- Haz clic en el estado para encender y apagar el servidor

¿No hay icono en absoluto? Era un bug de TCC/entitlements en builds antiguas, corregido en la v1.8.313 (2026-09-27). Actualiza la app.

</Accordion>

<Accordion label="Problemas de conexión" group="troubleshoot">

| Problema | Solución |
|---------|----------|
| No se puede conectar a Claude/Codex | Vuelve a pulsar «Connect» en los ajustes de VibeProxy |
| Factory muestra errores 404 | VibeProxy no está en marcha o el `base_url` es incorrecto (revisa la barra de menús) |
| La autenticación caducó | Desconecta y vuelve a conectar el proveedor |
| El puerto 8317 u 8318 ya está en uso | Cierra otras instancias de VibeProxy o CLIProxyAPI. A veces quedan procesos huérfanos tras salir de la app: `lsof -i :8317 -i :8318`, y luego `kill` al PID |
| `auth_unavailable: no auth available` | El proveedor de ese modelo no tiene inicio de sesión. Autentícalo (ver los comandos de login de Amp de arriba) y reinicia VibeProxy |

- Espera un drenaje más rápido de la ventana de 5 horas durante sesiones agénticas intensas

## Consideraciones de seguridad

<Notice type="warning" title="Información de seguridad importante">

- Los tokens OAuth se guardan localmente en `~/.cli-proxy-api/` con permisos 0600
- Desde la v1.8.313 (2026-09-27), el puerto 8317 solo hace bind a 127.0.0.1. Las builds anteriores enlazaban todas las interfaces; el comportamiento actual es obligatorio
- El interruptor «Allow LAN connections (port 8317)» de Settings expone el proxy a tu red, con un aviso en la interfaz y diagnósticos del modo de bind en el log del proxy. Si lo activas, cualquier máquina de la LAN puede gastar la cuota de tu suscripción. Usa la IP LAN de la máquina en las configuraciones de las herramientas y trata el interruptor como temporal
- El tráfico hacia los proveedores de IA es TLS de extremo a extremo
- Los tokens se renuevan antes de caducar, así que no estás guardando contraseñas en crudo

</Notice>

<Notice type="error" title="Riesgo de términos de servicio">

Usar tokens OAuth de suscripción a través de un proxy de terceros puede violar los términos de servicio de los proveedores. La propia documentación del proyecto advierte sobre suspensión de cuentas y baneos permanentes. VibeProxy añade una vía de escape oficial: puedes enrutar las peticiones de Claude a través de **Vercel AI Gateway** para un acceso sancionado a una suscripción Claude Max en lugar de llamar a Anthropic con tokens OAuth directamente. Vercel AI Gateway es un servicio de pago basado en créditos; consulta la [documentación de Vercel AI Gateway](https://vercel.com/docs/ai-gateway) para precios y configuración vigentes. Úsalo bajo tu propia responsabilidad.

</Notice>

<Accordion label="¿VibeProxy es gratis?" group="faq" expanded="true">

Sí. Licencia MIT, 0 $, descárgalo de GitHub y ejecútalo todo el tiempo que quieras. Aun así necesitas al menos una suscripción de IA de pago (o una clave API de GLM) para que el proxy tenga algo que enrutar.

</Accordion>

<Accordion label="¿Funciona en Macs Intel?" group="faq">

Sí, con matices. Las builds x86_64 se publican desde la v1.8.58 (2026-01-15), pero el proyecto las marca como **sin probar**. Si ejecutas una, informa de los resultados en el repositorio para que eso cambie.

</Accordion>

<Accordion label="¿Puede esto hacer que me baneen la cuenta?" group="faq">

Existe un riesgo real. Usar tokens OAuth de suscripción a través de un proxy puede violar los TOS de los proveedores, y la propia documentación del proyecto advierte sobre suspensión y baneos permanentes. Si quieres un acceso a Claude Max de menor riesgo, usa la ruta de Vercel AI Gateway descrita en [Consideraciones de seguridad](#consideraciones-de-seguridad).

</Accordion>

<Accordion label="¿Puedo usarlo con Linux o Windows?" group="faq">

La app VibeProxy es solo para macOS. El CLIProxyAPI subyacente funciona en otras plataformas si lo inicias manualmente. Consulta el [repositorio de CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI).

</Accordion>

<Accordion label="¿Cómo actualizo VibeProxy?" group="faq">

Desde la v1.6, VibeProxy comprueba actualizaciones a diario y las instala vía Sparkle. Las releases son casi diarias y a menudo siguen los bumps de CLIProxyAPI, así que deja que la auto-actualización haga su trabajo. Las descargas manuales desde la página de releases también funcionan.

</Accordion>

<Accordion label="¿Qué pasa si un modelo no funciona?" group="faq">

1. Confirma que el proveedor del modelo está autenticado en Settings
2. Comprueba el ID de modelo contra las tablas de referencia de arriba (ojo con la notación punto vs guion)
3. Para los nombres de modelo de Copilot, ejecuta `copilot --help`
4. Reinicia VibeProxy tras los cambios de configuración (excepto los interruptores Priority, que se recargan en caliente)
5. Revisa los logs de Console.app, busca «VibeProxy»

</Accordion>

<Accordion label="¿Por qué se agota más rápido el uso de mi suscripción a través de VibeProxy?" group="faq">

Reportado por la comunidad (issues #313/#292): los CLIs agénticos de terceros pueden quemar la ventana de 5 horas 2-3 veces más rápido que Claude Code o Codex nativos para el mismo trabajo nominal. Ese número proviene de reportes de usuarios, no de una medición. Vigila el panel de uso del propio proveedor y usa modelos más baratos para ediciones rutinarias. Detalles en [Solución de problemas](#solución-de-problemas).

</Accordion>

<Accordion label="¿Necesito claves API?" group="faq">

No. Esa es la gracia. Los proveedores se autentican con OAuth en el navegador. La única clave API real del flujo es la de Z.AI GLM. Los campos «API key» del lado de la herramienta aceptan un placeholder como `dummy-not-used`.

</Accordion>

## Conclusión

VibeProxy te permite usar las suscripciones de IA que ya pagas en todas las herramientas de código que posees, en lugar de comprar acceso a la API una segunda vez. Claude Code, ChatGPT Plus, Gemini, GitHub Copilot, Kimi, Qwen y Z.AI GLM se enrutan por un único proxy local. El lado de las herramientas también está cubierto: Factory Droids, Amp Code, Zed, Codex CLI, extensiones de VS Code, cualquier cosa compatible con OpenAI. Los IDs de modelo se mantienen al día con la documentación incluida (Opus 4.7, Sonnet 4.6, GPT-5.5, Gemini 3.1, modelos alojados en Copilot, GLM-5), y los controles del día a día están ahí cuando los necesitas: round-robin multi-cuenta, interruptores Priority, overrides de `config.yaml`, pensamiento extendido. Es una app nativa de macOS, solo loopback por defecto, con auto-actualizaciones y releases verificadas con SHA-256.

Ya uses [GitHub Copilot](/es/guia-completa-github-copilot/), [Amp Code](/es/amp-code-agente-ia-gratis/), Factory Droids u otra cosa, VibeProxy es el aburrido proxy local que hace que una suscripción funcione en todas partes.
