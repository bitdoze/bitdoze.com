Nadie lo vio venir hace tres años. La categoría de UI en «Python puro» (Reflex, NiceGUI, Flet, Gradio) ha pasado de ser un experimento de nicho a una opción seria para apps en producción. ## Tipos de frameworks web de Python

Los frameworks web de Python se dividen en cuatro categorías principales en 2026. La distinción entre «frameworks asíncronos» y «frameworks de API» se ha vuelto lo suficientemente importante como para separarlos: la mayor parte del trabajo moderno con APIs apunta directamente a ASGI, mientras que los frameworks de red puramente asíncronos sirven a un propósito diferente y de más bajo nivel.

- **Frameworks full-stack**: incluyen ORM, plantillas, autenticación y paneles de administración: todo lo que necesitas para una aplicación web renderizada en servidor. Django es la opción dominante aquí.
- **Frameworks de API**: optimizados para construir APIs REST y GraphQL con documentación automática, validación de tipos e inyección de dependencias. FastAPI, Litestar y Django Ninja lideran esta categoría.
- **Frameworks asíncronos**: frameworks de red asíncronos de bajo nivel para construir apps en tiempo real, servidores WebSocket o protocolos personalizados sobre asyncio de Python.
- **Frameworks de UI y apps de datos**: frameworks de «Python puro» que te permiten construir interfaces web sin escribir JavaScript. Streamlit, Gradio, Reflex y NiceGUI son los principales actores aquí.

Cada categoría sirve a un tipo de proyecto diferente. Elige primero la categoría y luego el framework dentro de ella.

## Ventajas de usar frameworks web de Python

Los frameworks web de Python reducen el tiempo de desarrollo al encargarse de las partes repetitivas del desarrollo web. Esto es lo que obtienes de serie:

<ListCheck>
<ul>
<li>Desarrollo rápido: componentes preconstruidos para enrutado, plantillas, autenticación y acceso a bases de datos que te permiten lanzar antes</li>
<li>Seguridad integrada: protección contra CSRF, XSS, inyección SQL y otras vulnerabilidades web comunes</li>
<li>Escalabilidad: la mayoría de los frameworks gestionan el aumento de tráfico mediante soporte async, capas de caché y pooling de conexiones</li>
<li>Comunidad grande: los frameworks populares tienen miles de preguntas respondidas, patrones probados en producción y extensiones mantenidas</li>
<li>Ecosistema rico: ORMs, herramientas de migración, paneles de administración, generadores de documentación de API y utilidades de testing que se integran limpiamente</li>
</ul>
</ListCheck>

## Los mejores frameworks web de Python para 2026

### Frameworks full-stack

Los frameworks full-stack proporcionan un kit de herramientas completo para aplicaciones web renderizadas en servidor: ORM, plantillas, autenticación, interfaz de administración y gestión de formularios. Si quieres un solo framework que lo haga todo, esta es la categoría.

- **[Django](https://www.djangoproject.com/)** (5.2 LTS, 88.189 ★): El peso pesado del desarrollo web con Python. Django 5.2 LTS (publicado en abril de 2025) añade claves primarias compuestas e importación automática de modelos en el shell. El soporte LTS se extiende hasta abril de 2028. Django 6.0 (publicado en diciembre de 2025) añadió parciales de plantilla, cabeceras CSP integradas y tareas en segundo plano. Estas funciones potencian el patrón HTMX+Django que está ganando tracción entre desarrolladores en solitario que quieren evitar un frontend JavaScript separado. **[Repositorio de Django](https://github.com/django/django)**

- **[Pyramid](https://trypyramid.com)** (2.1): La filosofía de Pyramid es «empieza pequeño, termina grande». Te da enrutado y plantillas de serie, pero te permite cambiar la capa de base de datos, el sistema de autenticación y el motor de plantillas por los tuyos. Buena opción cuando Django se queda grande y Flask se queda corto. **[Repositorio de Pyramid](https://github.com/Pylons/pyramid)**

- **[TurboGears](https://turbogears.org)** (2.5.0): Empieza como una app de un solo archivo y escala hasta una solución full-stack. Construido sobre varios otros componentes (SQLAlchemy, ToscaWidgets, Genshi/Mako). Nota: verifica el soporte de Python 3.10+ antes de comprometerte; consulta las notas de la versión 2.5.0. **[Repositorio de TurboGears](https://github.com/TurboGears/tg2)**

- **[Masonite](https://docs.masoniteproject.com/)** (v5): Un framework centrado en el desarrollador con una arquitectura MVC inspirada en Laravel. Masonite v5 se publica como `masonite-framework` en PyPI.

<Notice type="warning" title="Cambio de repositorio de Masonite">
El repositorio original de Masonite 4.x (`MasoniteFramework/masonite`) está archivado y ya no se mantiene. Masonite 5 se publica como `masonite-framework` en PyPI. Si estás empezando un proyecto nuevo, asegúrate de instalar desde el paquete correcto.
</Notice>

- **[Emmett](https://github.com/emmett-framework/emmett)**: Un framework full-stack asíncrono creado por el desarrollador detrás de Granian (el servidor HTTP basado en Rust). Emmett se integra estrechamente con Granian para el despliegue y soporta async/await en todo su ORM y capa de plantillas. Su comunidad aún es relativamente pequeña, pero merece seguimiento si buscas una alternativa async moderna a Django.

### Frameworks de API

Esta es la categoría que más crece y la que tiene el desarrollo más activo. Los frameworks de API están optimizados para construir APIs REST y GraphQL con documentación OpenAPI automática, validación basada en Pydantic e inyección de dependencias.

<Notice type="info" title="FastAPI lidera el mercado">
El uso de FastAPI alcanzó el 38% en la encuesta JetBrains 2024 (frente al 25% de 2022), convirtiéndolo en el framework web de Python n.º 1 por adopción. La encuesta Stack Overflow 2025 confirma la tendencia: FastAPI con un 14,8% global entre todos los frameworks web, Flask con un 14,4%. Esta categoría es donde empiezan la mayoría de los nuevos proyectos web de Python.
</Notice>

- **[FastAPI](https://fastapi.tiangolo.com/)** (0.115.x, 100.813 ★): El framework que cambió el desarrollo web con Python. Construido sobre Starlette y Pydantic v2, FastAPI genera documentación interactiva de API (Swagger + ReDoc) a partir de tus type hints. El extra `[standard]` instala Uvicorn y otros esenciales:

```bash
pip install "fastapi[standard]"
# Iniciar el servidor de desarrollo
fastapi dev main.py
# Visita http://localhost:8000/docs para la documentación de API autogenerada
```

La cadencia de publicaciones de FastAPI se ha ralentizado a medida que el proyecto madura, pero es estable en producción y está ampliamente probado. **[Repositorio de FastAPI](https://github.com/fastapi/fastapi)**

- **[Flask](https://flask.palletsprojects.com/)** (3.1.3, 71.998 ★): El microframework original de Python, sigue con fuerza. Flask 3.0 eliminó el soporte de Python 3.7; la 3.1 añadió mejoras async. Está basado en WSGI (no ASGI), lo que importa a la hora de elegir el despliegue. El ecosistema de extensiones de Flask es enorme: hay un paquete para casi todo. Ideal cuando quieres control total sobre tu stack. **[Repositorio de Flask](https://github.com/pallets/flask)**

- **[Litestar](https://litestar.dev/)** (8.356 ★): El framework ASGI que más rápido crece en 2025-2026. Litestar se posiciona como «FastAPI con más estructura integrada». Incluye DTOs (objetos de transferencia de datos), inyección de dependencias integrada, soporte GraphQL, manejadores WebSocket y una CLI para scaffolding:

```bash
pip install litestar
litestar new my-app
cd my-app && litestar run
# Visita /schema para la documentación OpenAPI autogenerada
```

Litestar no afirma ser «mejor» que FastAPI: ofrece concesiones diferentes. Si quieres valores por defecto más opinados y más funciones integradas, Litestar reduce el boilerplate. Si prefieres máxima flexibilidad y una comunidad más grande, FastAPI es la apuesta segura. **[Repositorio de Litestar](https://github.com/litestar-org/litestar)**

- **[Django Ninja](https://django-ninja.dev/)** (9.148 ★): Lleva la ergonomía estilo FastAPI a Django. Usa Pydantic v2, type hints de Python y soporte async, pero vive dentro de tu proyecto Django existente con acceso al ORM, al admin y al middleware de Django. La mejor opción cuando quieres añadir una API moderna a una app Django sin cambiar de framework. **[Repositorio de Django Ninja](https://github.com/vitalik/django-ninja)**

- **[Falcon](https://falconframework.org/)** (4.0.2, ~9.500 ★): Un framework de API web de Python de bajo nivel centrado en el rendimiento puro. Falcon 4.0 añadió soporte ASGI junto a su modo WSGI existente. Cero dependencias. Usado por LinkedIn, OpenStack y otros sistemas de alto tráfico. Ideal cuando necesitas máximo throughput con mínima sobrecarga. **[Repositorio de Falcon](https://github.com/falconry/falcon)**

- **[Sanic](https://sanic.dev/)** (25.3, ~18.000 ★): Un servidor web y framework construido para velocidad con soporte async/await. Sanic ahora usa una convención de versionado `YY.M`. La versión 25.3 se publicó en marzo de 2025. Requiere Python 3.10+. **[Repositorio de Sanic](https://github.com/sanic-org/sanic)**

- **[Quart](https://quart.palletsprojects.com/)** (0.20.0): Mantenido por la organización Pallets (el mismo equipo detrás de Flask), Quart es un framework ASGI con la misma API que Flask. Si quieres soporte async pero ya conoces la API de Flask, Quart es la ruta de migración. Las extensiones de Flask pueden ejecutarse en Quart con cambios mínimos. **[Repositorio de Quart](https://github.com/pallets/quart)**

- **[BlackSheep](https://www.neoteroi.dev/blacksheep/)** (2.351 ★): Un framework ASGI de alto rendimiento inspirado en Flask y ASP.NET Core. Ofrece una inyección de dependencias limpia, documentación OpenAPI automática y un excelente soporte de type hints. Comunidad más pequeña pero mantenida activamente. **[Repositorio de BlackSheep](https://github.com/Neoteroi/BlackSheep)**

- **[Esmerald](https://esmerald.dev/)**: Un framework ASGI modular diseñado tanto para APIs como para aplicaciones completas. Gran énfasis en modularidad, escalabilidad y arquitectura conectable. Todavía está creciendo en adopción, pero el diseño es sólido para proyectos complejos que necesitan estructura. **[Repositorio de Esmerald](https://github.com/dymmond/esmerald)**

### Frameworks asíncronos

Son frameworks de red asíncronos de bajo nivel. No están construidos específicamente para APIs REST (para eso están los frameworks de API de arriba), sino para construir aplicaciones en tiempo real, servidores WebSocket, protocolos personalizados o cualquier cosa que se beneficie de E/S no bloqueante.

- **[AIOHTTP](https://docs.aiohttp.org/)** (3.11.18, ~15.000 ★): A la vez cliente HTTP async y framework de servidor. En la práctica, la mayoría de los desarrolladores usan AIOHTTP como cliente HTTP (para hacer peticiones asíncronas) más que como framework web. La parte de servidor (`aiohttp.web`) es sólida pero se usa menos en proyectos nuevos. **[Repositorio de AIOHTTP](https://github.com/aio-libs/aiohttp)**

- **[Starlette](https://www.starlette.io/)**: Un toolkit ASGI ligero, no un framework completo. FastAPI está construido sobre Starlette. Usarías Starlette directamente cuando quieres manejo ASGI puro sin la capa opinada de FastAPI encima. Bueno para middleware personalizado, tareas en segundo plano o servicios solo-WebSocket. **[Repositorio de Starlette](https://github.com/encode/starlette)**

- **[Tornado](https://www.tornadoweb.org)** (6.4.2): Un framework web de Python y biblioteca de red asíncrona, desarrollado originalmente en FriendFeed (ahora parte de Facebook). El uso de Tornado ha bajado al 2% en la encuesta de JetBrains, pero sigue mantenido y funciona bien para long-polling, WebSockets y servidores TCP personalizados. **[Repositorio de Tornado](https://github.com/tornadoweb/tornado)**

- **[Robyn](https://robyn.tech/)** (7.322 ★): Un framework web de Python con runtime en Rust. Robyn compila el bucle principal de su servidor en Rust vía PyO3, lo que le da un rendimiento cercano al de un lenguaje compilado manteniendo Python para tu código de aplicación. Soporta Python 3.13. Si necesitas el máximo throughput de un servidor web Python, merece la pena hacer benchmark de Robyn con tu carga de trabajo. **[Repositorio de Robyn](https://github.com/sparckles/Robyn)**

<Notice type="warning" title="UvLoop no es un framework web">
UvLoop aparecía antes en esta sección. En realidad es un reemplazo ultrarrápido y directo del bucle de eventos asyncio de Python (construido con Cython y libuv). Potencia frameworks como Sanic internamente, pero es infraestructura, no un framework web. Úsalo como optimización de rendimiento para cualquier framework basado en asyncio: `pip install uvloop`.
</Notice>

### Frameworks de UI y apps de datos

Esta categoría apenas existía cuando se escribió el artículo original. En 2026, los frameworks de UI web en «Python puro» son una de las áreas de mayor crecimiento del ecosistema Python. Reflex, Flet, NiceGUI y Taipy pasaron colectivamente de unas 10.000 a más de 80.000 estrellas de GitHub en dos años. Estos frameworks te permiten construir aplicaciones web completas sin escribir JavaScript.

<Notice type="success" title="El boom de la UI en Python puro">
La categoría de «UI en Python puro» ha explotado: Reflex (28.667 ★), Flet (16.372 ★), NiceGUI (16.052 ★) y Taipy (19.333 ★) pasaron colectivamente de ~10k a más de 80k estrellas en dos años. Solo Gradio tiene 43.191 estrellas. Si eres un desarrollador Python que no quiere tocar JavaScript, esta es la categoría a vigilar.
</Notice>

- **[Streamlit](https://streamlit.io/)** (~36.000 ★): El estándar para construir apps de datos y dashboards de ML en Python. Streamlit 1.52+ añadió `st.datetime_input`, pestañas dinámicas y temas avanzados con Google Fonts. Requiere Python 3.9+. Consulta la comparativa [Streamlit vs Taipy](/es/streamlit-vs-taipy/) si necesitas más funciones empresariales. También puedes [desplegar Streamlit en un VPS](/es/desplegar-streamlit-vps-cloudflare/) para uso en producción. **[Repositorio de Streamlit](https://github.com/streamlit/streamlit)**

- **[Gradio](https://www.gradio.app/)** (43.191 ★): El framework dominante para demos de modelos de ML e interfaces de apps de IA. Respaldado por Hugging Face. Gradio 5 se centró en la preparación para producción; Gradio 6 está en desarrollo. Si estás construyendo una demo para un modelo de machine learning o una aplicación de IA, Gradio es la opción por defecto: se integra directamente con Hugging Face Spaces para hosting gratuito. **[Repositorio de Gradio](https://github.com/gradio-app/gradio)**

- **[Reflex](https://reflex.dev/)** (28.667 ★): Antes llamado Pynecone. Reflex compila tu código Python a un frontend React con un backend Next.js. La versión 0.8.x trajo builds 2-3x más rápidos con Vite+Rolldown y más de 60 componentes de UI integrados. El comando `reflex deploy` gestiona el despliegue, o puedes autoalojarlo. **[Repositorio de Reflex](https://github.com/reflex-dev/reflex)**

- **[Flet](https://flet.dev/)** (16.372 ★): Construye apps interactivas multiusuario para web, móvil y escritorio en Python. Flet 1.0 Alpha (junio de 2025) es una reescritura mayor con un runtime Python propio, control de permisos y rebuilds más rápidos. Lo multiplataforma es el diferencial de Flet: el mismo código corre en web, iOS, Android, Windows, macOS y Linux. **[Repositorio de Flet](https://github.com/flet-dev/flet)**

- **[NiceGUI](https://nicegui.io/)** (16.052 ★): Un framework de interfaz de usuario para construir aplicaciones web solo con Python. La versión 2.x añadió renderizado de escenas 3D, controles de cámara y eventos de ventana nativos. Consulta la [comparativa Streamlit vs NiceGUI](/es/streamlit-vs-nicegui/) para saber cuándo elegir cada uno. Revisa la [guía de NiceGUI para principiantes](/es/empezar-nicegui/) para empezar. **[Repositorio de NiceGUI](https://github.com/zauberzeug/nicegui)**

- **[Taipy](https://www.taipy.io/)** (19.333 ★): Framework de aplicaciones de datos orientado a la empresa. Taipy 4.x apunta a pipelines de datos en producción con gestión de escenarios, orquestación de nodos de datos y programación de trabajos. Consulta la comparativa [Streamlit vs Taipy](/es/streamlit-vs-taipy/) para más detalles. **[Repositorio de Taipy](https://github.com/Avaiga/taipy)**

- **[Dash (Plotly)](https://plotly.com/dash/)** (3.0.4): Un framework para construir apps de visualización de datos sobre Flask, Plotly.js y React.js. Dash 3.0 fue una versión mayor. Ideal para construir dashboards analíticos con gráficos interactivos muy personalizados en Python puro, sin necesidad de JavaScript. **[Repositorio de Dash](https://github.com/plotly/dash)**

- **[Panel](https://panel.holoviz.org/)**: Una solución de dashboards de alto nivel del ecosistema HoloViz. Panel funciona con Bokeh, Matplotlib, HoloViews y muchas otras bibliotecas de gráficos de Python. Buena opción cuando ya estás dentro del ecosistema científico de Python. **[Repositorio de Panel](https://github.com/holoviz/panel)**

- **[ReactPy](https://reactpy.dev/)** (8.144 ★): Crea aplicaciones web interactivas en Python usando un modelo de componentes inspirado en React. ReactPy te permite escribir código Python tipo JSX que se renderiza en el DOM. Comunidad más pequeña, pero interesante para desarrolladores que quieren el modelo mental de React sin salir de Python. **[Repositorio de ReactPy](https://github.com/reactive-python/reactpy)**

- **[Anvil](https://anvil.works/)**: Una plataforma para construir apps web full-stack usando solo Python. Tanto el código del cliente como el del servidor son Python. Anvil gestiona el hosting y el despliegue. Nota: Anvil es una plataforma comercial con un nivel gratuito; no es totalmente open source. **[Repositorio de Anvil](https://github.com/anvil-works/anvil-runtime)**

### Microframeworks

Frameworks minimalistas, con dependencias casi nulas, para proyectos pequeños, uso embebido o situaciones donde quieres control total sobre cada componente.

- **[Bottle](https://bottlepy.org/)** (0.13.3): Un micro framework web de un solo archivo sin dependencias fuera de la biblioteca estándar de Python. Bottle sigue mantenido (última versión abril de 2025). Bueno para sistemas embebidos, prototipos rápidos o situaciones donde añadir dependencias es un problema. **[Repositorio de Bottle](https://github.com/bottlepy/bottle)**

- **[CherryPy](https://cherrypy.dev/)** (18.10.0): Un framework web minimalista de Python que te permite construir aplicaciones web de la misma forma que construyes cualquier otro programa Python orientado a objetos. CherryPy incluye su propio servidor HTTP con pool de hilos listo para producción. Sigue mantenido (última versión junio de 2024). **[Repositorio de CherryPy](https://github.com/cherrypy/cherrypy)**

### Frameworks heredados e históricos

Estos frameworks tienen importancia histórica y algunos aún corren en producción, pero no se recomiendan para proyectos nuevos en 2026.

<Accordion group="legacy" label="¿Por qué están en una sección aparte?" expanded="false">
Estos frameworks fueron importantes en la historia web de Python. Algunos todavía reciben versiones de mantenimiento. Pero para proyectos nuevos en 2026, los frameworks de arriba ofrecen mejor rendimiento, soporte de Python moderno, comunidades activas y documentación actualizada. Si mantienes una app existente en alguno de estos, está bien. Simplemente no empieces proyectos nuevos con ellos.
</Accordion>

- **[Zope](https://www.zope.dev/)** y **BlueBream**: Zope es históricamente importante por su arquitectura de componentes, que influyó en muchos frameworks posteriores. Zope 5.13 se publicó en marzo de 2025. BlueBream 1.0 se publicó en 2011 y está esencialmente congelado. Si necesitas el modelo de componentes de Zope, considera primero alternativas modernas. **[Repositorio de Zope](https://github.com/zopefoundation/Zope)**

- **[web2py](http://www.web2py.com)**: La propia documentación de web2py dice: «no recomendado para proyectos nuevos, considera usar py4web en su lugar». La encuesta de JetBrains muestra un 3% de uso, plano desde 2021. Si estás en web2py, mira py4web como ruta de migración.

- **[CubicWeb](https://www.cubicweb.org)** (4.10.0): Construido sobre principios de la Web Semántica con énfasis en la reutilización mediante componentes y modelos de datos explícitos. La versión 4.10.0 se publicó en abril de 2025, pero la comunidad es extremadamente de nicho. Solo relevante si necesitas específicamente capacidades de web semántica / datos enlazados.

- **[web.py](https://webpy.org/)**: Un framework web tan simple como potente, pero efectivamente congelado. La última versión, 0.62, fue en noviembre de 2020. Todavía cae algún commit ocasional, pero no hay desarrollo activo. Si usas web.py para algo simple, Bottle es una alternativa mejor mantenida.

- **[Hug](https://hugapi.github.io/hug/)**: La última versión significativa fue la v2.6.1 en febrero de 2020. El dominio original `hug.rest` puede que ya no resuelva. El proyecto ahora vive en GitHub Pages. 187 issues abiertos sin resolución. No lo uses para proyectos nuevos; FastAPI cubre el mismo caso de uso con mantenimiento activo.

## Django vs Flask vs FastAPI: ¿cuál deberías elegir?

Es la comparativa más buscada del mundo web de Python, y con razón: Django, Flask y FastAPI siguen siendo las tres opciones más probadas en producción. La elección depende de lo que estés construyendo.

<Notice type="info" title="El panorama en 2026">
Encuesta JetBrains 2024: FastAPI 38%, Django 35%, Flask 34%. Stack Overflow 2025: FastAPI 14,8%, Flask 14,4% globalmente entre todos los frameworks web. FastAPI lleva el impulso, pero Django y Flask tienen un ecosistema profundo y un historial probado. Los tres son aptos para producción.
</Notice>

<Tabs>
<Tab name="Django">
**Ideal para:** Aplicaciones web full-stack, apps con mucho admin, sitios de contenido, cualquier cosa que necesite ORM + auth + admin
**Versión de Python:** 3.10+
**Dependencia clave:** Django ORM (integrado)
**Instalación:** `pip install django==5.2.*`
**Fortalezas:** Ecosistema completo, panel de administración, ORM, comunidad enorme, versiones LTS
**Debilidades:** Arquitectura monolítica, más lento para trabajo de API pura, mentalidad centrada en plantillas
**Inicio rápido:**
```bash
pip install django==5.2.*
django-admin startproject myproject
cd myproject
python manage.py runserver
# Visita http://localhost:8000/
```
</Tab>
<Tab name="Flask">
**Ideal para:** APIs ligeras, microservicios, cuando quieres control total sobre tu stack
**Versión de Python:** 3.8+
**Dependencia clave:** Werkzeug, Jinja2
**Instalación:** `pip install flask`
**Fortalezas:** Minimalista, flexible, enorme ecosistema de extensiones, fácil de aprender
**Debilidades:** Solo WSGI (sin async nativo), sin ORM ni admin integrados
**Inicio rápido:**
```bash
pip install flask
```
```python
from flask import Flask
app = Flask(__name__)

@app.route("/")
def hello():
    return "Hello, World!"
```
```bash
flask run
# Visita http://localhost:5000/
```
</Tab>
<Tab name="FastAPI">
**Ideal para:** APIs REST/GraphQL, APIs async, microservicios, código con tipado seguro
**Versión de Python:** 3.8+
**Dependencia clave:** Pydantic v2, Starlette
**Instalación:** `pip install "fastapi[standard]"`
**Fortalezas:** Docs OpenAPI automáticas, async nativo, type hints, rápido (literalmente)
**Debilidades:** Ecosistema más joven, sin ORM ni admin integrados, solo ASGI
**Inicio rápido:**
```bash
pip install "fastapi[standard]"
```
```python
from fastapi import FastAPI
app = FastAPI()

@app.get("/")
def hello():
    return {"message": "Hello, World!"}
```
```bash
fastapi dev main.py
# Visita http://localhost:8000/docs para la documentación de API autogenerada
```
</Tab>
</Tabs>

**Guía rápida de decisión:**

- **¿Necesitas ORM, panel de administración y autenticación de usuarios de serie?** Django.
- **¿Construyes una API REST con documentación automática y soporte async?** FastAPI.
- **¿Quieres sobrecarga mínima y control total sobre cada componente?** Flask.
- **¿Ya estás en Django pero quieres la ergonomía de API estilo FastAPI?** Django Ninja (no cambies de framework, añádelo).
- **¿Desarrollador en solitario que no quiere un frontend JavaScript?** Django + HTMX o Streamlit/NiceGUI.

El patrón HTMX + Django merece mención: Django 6.0 añade parciales de plantilla específicamente para apoyar este enfoque. Para operadores en solitario que quieren construir apps renderizadas en servidor sin mantener un frontend React/Vue, Django + HTMX es un stack práctico y de bajo mantenimiento.

## Recomendaciones de despliegue para frameworks web de Python

Una vez elegido el framework, tienes que desplegarlo. Aquí está la guía práctica para la audiencia de bitdoze: autoalojado en un VPS con Docker o bare metal.

<Notice type="success" title="El autoalojamiento ahorra dinero">
Un VPS de 5-10 $/mes de [Hetzner Cloud](https://go.bitdoze.com/hetzner) o [DigitalOcean Droplets](https://go.bitdoze.com/do) puede manejar tráfico considerable para la mayoría de aplicaciones web Python. Las plataformas gestionadas con recursos equivalentes suelen costar más de 50-100 $/mes. Si ejecutas un proyecto secundario, un MVP de startup o una herramienta interna, el autoalojamiento en un VPS es la opción rentable. Opciones económicas como [Hostinger VPS](https://go.bitdoze.com/hostinger-vps) empiezan aún más abajo, y [Vultr](https://go.bitdoze.com/vultr) ofrece regiones globales si necesitas desplegar más cerca de tus usuarios.
</Notice>

_Los precios de VPS subieron en todos los proveedores en 2026 — si estás reconsiderando una máquina alquilada, mira [qué cambió y cuándo gana un mini PC](/es/subidas-precios-vps/)._

**Django:** Gunicorn (WSGI) detrás de Nginx o Caddy. Para despliegue basado en Docker, usa [Dokploy para autoalojar](/es/instalar-dokploy/). Gestiona el proxy inverso, SSL y el despliegue desde Git. Django 5.2 en un VPS de 5 $ con 1-2 GB de RAM es suficiente para la mayoría de proyectos.

**FastAPI:** Uvicorn o Granian (servidor ASGI). Granian es un servidor HTTP basado en Rust que muestra un throughput 2-4x mayor que Uvicorn en benchmarks publicados (los resultados varían según la carga de trabajo). Ponlo detrás de Nginx o Caddy para SSL y archivos estáticos:

```bash
pip install fastapi granian
granian app:app --interface asgi --port 8000
```

**Flask:** Gunicorn (WSGI) detrás de un proxy inverso. Flask no soporta ASGI de forma nativa, pero Quart (mantenido por el mismo equipo de Pallets) te da la API de Flask con soporte async.

**Streamlit:** Proxy inverso con Nginx + servicio systemd, o Docker. Consulta la guía completa sobre cómo [desplegar Streamlit en un VPS](/es/desplegar-streamlit-vps-cloudflare/). También puedes [ejecutar apps Python en Docker](/es/docker-ejecutar-python/) para despliegues aislados y reproducibles.

**Gradio:** Hosting gratuito en Hugging Face Spaces para demos. Para producción, autoaloja detrás de Nginx con systemd o Docker.

**Reflex:** Comando `reflex deploy` integrado para Reflex Cloud (tiene nivel gratuito). El autoalojamiento requiere la configuración VPS estándar.

Para gestionar tus proyectos Python, recomiendo [configurar proyectos Python con uv](/es/empezar-uv/). Es significativamente más rápido que pip y gestiona los entornos virtuales limpiamente. También puedes [desplegar proyectos Python con Dokploy y uv](/es/dokploy-python-railpack-uv/) para un pipeline CI/CD completo.

<ListCheck>
<ul>
<li>VPS aprovisionado (1-2 GB de RAM mínimo, 2+ GB recomendado para Django/FastAPI)</li>
<li>Python 3.10+ instalado (usa uv o pyenv para gestionar versiones)</li>
<li>Proxy inverso configurado (Nginx, Caddy o Traefik)</li>
<li>Certificados SSL/TLS (Caddy los aprovisiona automáticamente, o usa Certbot con Nginx)</li>
<li>Servicio systemd o Docker Compose para la gestión de procesos</li>
<li>Reglas de firewall (permite solo 80, 443 y tu puerto SSH)</li>
</ul>
</ListCheck>

Para la gestión de VPS, consulta los [mejores paneles de servidor autoalojados](/es/mejores-paneles-autoalojados/) si quieres una GUI para gestionar tus despliegues.

## Cómo elegir el framework web de Python adecuado

El framework «correcto» depende de lo que construyes, quién lo construye y cuánta complejidad quieres gestionar. Esta es la matriz de decisión que uso:

<Tabs>
<Tab name="Construir una API">
**Recomendación:** FastAPI o Litestar
**Por qué:** FastAPI es el líder del mercado con la comunidad más grande, documentación autogenerada y validación con Pydantic v2. Litestar es la alternativa emergente con más estructura integrada (DTOs, DI, GraphQL). Ambos son ASGI y rinden bien.
**Opción por defecto en solitario:** FastAPI. Más tutoriales, más respuestas en Stack Overflow, más ejemplos en producción.
</Tab>
<Tab name="App full-stack">
**Recomendación:** Django o Django + HTMX
**Por qué:** Django te da ORM, admin, auth y plantillas de serie. Con HTMX puedes construir UIs interactivas sin un frontend JavaScript separado. Django 5.2 LTS tiene soporte hasta 2028.
**Opción por defecto en solitario:** Django + HTMX. La menor carga de mantenimiento para un desarrollador en solitario.
</Tab>
<Tab name="Demo de IA/ML">
**Recomendación:** Gradio o Streamlit
**Por qué:** Gradio está construido específicamente para demos de modelos ML y se integra directamente con Hugging Face Spaces (hosting gratis). Streamlit es mejor para dashboards de datos y herramientas de data science más amplias.
**Opción por defecto en solitario:** Gradio para demos de ML, Streamlit para dashboards de datos.
</Tab>
<Tab name="Dashboard de datos">
**Recomendación:** Streamlit o Dash
**Por qué:** Streamlit es el más rápido para prototipar. Dash da más control sobre la personalización de gráficos y está construido sobre Plotly. Para herramientas internas, la simplicidad de Streamlit gana.
**Opción por defecto en solitario:** Streamlit.
</Tab>
<Tab name="UI en Python puro">
**Recomendación:** NiceGUI o Reflex
**Por qué:** NiceGUI es más simple para empezar y tiene una API limpia. Reflex compila a React y te da una app full-stack con un build de frontend real. Elige NiceGUI para herramientas rápidas, Reflex para apps web en producción.
**Opción por defecto en solitario:** NiceGUI para herramientas internas, Reflex para apps orientadas al usuario.
</Tab>
</Tabs>

<Accordion group="faq" label="¿Y si estoy empezando?" expanded="false">
Empieza con Flask o FastAPI. Flask te enseña los fundamentos del desarrollo web (enrutado, plantillas, ciclo petición/respuesta) con la mínima magia. FastAPI te enseña patrones modernos de Python (type hints, Pydantic, async) que se transfieren al resto del ecosistema. Ambos tienen excelentes tutoriales oficiales. Construye un proyecto pequeño (un acortador de URLs, una API de tareas, un blog) y aprenderás lo suficiente para evaluar otros frameworks.
</Accordion>

<Accordion group="faq" label="¿Puedo cambiar de framework más adelante?" expanded="false">
Depende del cambio. Pasar de Flask a FastAPI es relativamente suave: ambos son ligeros y los patrones de enrutado son similares. Pasar de Django a FastAPI es más difícil porque el ORM, el admin y el middleware de Django están profundamente integrados. Django Ninja te da APIs estilo FastAPI dentro de Django, lo que suele ser mejor que cambiar por completo. La clave: mantén tu lógica de negocio separada del código del framework. Si tu lógica principal está en módulos Python puros (sin ataduras a decoradores del framework o modelos del ORM), cambiar se vuelve mucho más fácil.
</Accordion>

### Otros factores a considerar

**Tamaño y alcance del proyecto**: los frameworks full-stack (Django) son mejores para aplicaciones grandes. Los microframeworks (Flask, Bottle) encajan en proyectos pequeños. Los frameworks de API (FastAPI, Litestar) están construidos expresamente para servicios.

**Curva de aprendizaje**: Django tiene la curva de aprendizaje inicial más pronunciada pero la documentación más completa. Flask es el más fácil para empezar. FastAPI está en medio: los type hints y los conceptos de modelos de Pydantic cuestan un poco al principio, pero la documentación autogenerada compensa de inmediato.

**Comunidad y soporte**: Django (88k estrellas), FastAPI (101k estrellas) y Flask (72k estrellas) tienen las comunidades más grandes. Frameworks más pequeños como Litestar y NiceGUI crecen rápido pero tienen menos preguntas respondidas disponibles.

**Viabilidad a largo plazo**: Django existe desde 2005 y tiene versiones LTS con más de 3 años de soporte. FastAPI y Flask se mantienen activamente con respaldo sólido de financiación y comunidad. Los frameworks más nuevos conllevan más riesgo: evalúa el historial del mantenedor y el modelo de financiación.

**Rendimiento**: para throughput puro de API, los frameworks ASGI (FastAPI, Litestar, Sanic, Robyn) superan a los WSGI (Flask, Django) bajo carga concurrente. Pero para la mayoría de aplicaciones, la elección del framework importa menos que tus consultas a la base de datos y tu estrategia de caché.

## Conclusión

El desarrollo web con Python en 2026 es más diverso que nunca. FastAPI ha superado a Django y Flask en adopción, pero los tres siguen siendo opciones aptas para producción para diferentes tipos de proyectos. La explosión de la UI en «Python puro» (Gradio, Streamlit, Reflex, NiceGUI) significa que los desarrolladores Python pueden construir aplicaciones web completas sin escribir JavaScript. Las herramientas basadas en Rust (Robyn, Granian, uv) siguen elevando el techo de rendimiento.

El mejor framework es el que encaja con tu proyecto, tu equipo y tus restricciones de despliegue. Si eres un operador en solitario en un VPS, FastAPI o Flask te dan la menor fricción. Si necesitas un panel de administración y un ORM, Django sigue siendo la respuesta. Si construyes una demo de IA, Gradio es la opción por defecto. Elige uno, construye algo este fin de semana y despliégalo.
