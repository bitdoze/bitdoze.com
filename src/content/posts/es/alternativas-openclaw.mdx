OpenClaw demostró que podías ejecutar un asistente de IA autoalojado en tu propio servidor. Siempre encendido, siempre alcanzable por Telegram o Slack, y sin depender del SaaS de nadie. Yo mismo lo ejecuto y escribí una [guía de configuración completa](/es/guia-configuracion-openclaw/) si quieres probar el original. Pero ya no es la única opción. Estas diez alternativas a OpenClaw abordan la misma idea de formas distintas: algunas son más pequeñas y enfocadas, otras intentan hacer más, y otras están construidas para hardware que no esperarías.

He analizado las diez a fondo. Este resumen te da recuentos de estrellas actuales, modelos de seguridad, pasos de instalación y señales de salud del proyecto para que elijas dónde invertir tu tiempo.

## 1. NanoClaw

<Button text="Repositorio GitHub" link="https://github.com/nanocoai/nanoclaw" variant="solid" color="green" size="md" icon="github" />

NanoClaw es un asistente de IA basado en TypeScript construido sobre el Agent SDK de Claude. La principal diferencia con otros bots de esta lista es el aislamiento real por contenedor: los agentes corren dentro de contenedores Docker, no detrás de comprobaciones de permisos a nivel de aplicación. También tiene Agent Swarms, donde equipos de agentes especializados colaboran en tareas.

El proyecto se movió de `qwibitai/nanoclaw` a [`nanocoai/nanoclaw`](https://github.com/nanocoai/nanoclaw) y publicó una reescritura v2. 31.024 estrellas a octubre de 2026. Ahora tiene web en [nanoclaw.dev](https://nanoclaw.dev) y docs en [docs.nanoclaw.dev](https://docs.nanoclaw.dev). Escribimos una [guía de despliegue completa de NanoClaw](/es/guia-despliegue-nanoclaw/) que cubre la configuración de WhatsApp, contenedores, skills y tareas programadas.

<Notice type="warning" title="El flujo de instalación v1 está muerto">
El viejo repo `qwibitai/nanoclaw` devuelve un 301. El flujo `git clone … && claude /setup` ya no funciona. Los usuarios de v1 deberían ejecutar `bash migrate-v2.sh` en lugar de reconfigurar a mano. Si sigues alguna guía que mencione `qwibitai` o `/setup`, está desactualizada.
</Notice>

### Qué hace

- Los agentes se ejecutan dentro de contenedores Linux con aislamiento de archivos
- Canales: Slack, Telegram, Discord, WhatsApp, iMessage, CLI
- Agent Swarms para colaboración multi-agente
- Memoria y contexto aislados por grupo (cada grupo tiene su propio CLAUDE.md)
- Sistema de skills donde los contribuidores añaden skills de Claude Code en lugar de funciones
- Tareas programadas con contexto por grupo
- Pasarela de credenciales: los secretos se gestionan fuera del contenedor del agente
- Agentes en Slack: una app de Slack por agente, cada una con su propia identidad de bot, contenedor y memoria. Puedes crear compañeros desde el chat

### Enfoque de seguridad

El modelo de seguridad de NanoClaw es a nivel de SO, no a nivel de aplicación:

- **Aislamiento por contenedor**: cada agente corre en su propio contenedor Docker con solo los directorios montados explícitamente visibles
- **Sin red por defecto**: los contenedores no tienen acceso a red salvo que lo actives
- **Aislamiento de procesos**: los procesos del contenedor no pueden acceder a procesos del host
- **Ejecución sin root**: los contenedores corren como usuario no-root

Esto pone a NanoClaw por delante de proyectos que dependen de listas de permitidos o restricciones de rutas. El agente tendría que escapar del contenedor primero, y ese es un listón mucho más alto.

### Cómo empezar

```bash
git clone https://github.com/nanocoai/nanoclaw.git nanoclaw-v2
cd nanoclaw-v2
bash nanoclaw.sh
```

`nanoclaw.sh` instala Node, pnpm y Docker si faltan, configura una pasarela de credenciales, construye el contenedor del agente y empareja tu primer canal (Slack, Telegram, Discord, WhatsApp, iMessage o CLI). Claude Code solo se invoca automáticamente para diagnosticar fallos.

**Verifica**: envía un mensaje al canal emparejado y confirma que el bot responde. Ejecuta `docker ps` y confirma que el contenedor del agente está arriba.

**Modo de fallo**: si vienes de v1, ejecuta `bash migrate-v2.sh` en lugar de empezar de cero. Se encarga de la migración de la configuración.

### Para quién es

NanoClaw es la elección si te importa la seguridad a nivel de contenedor, o si quieres enjambres multi-agente. La función de compañeros en Slack es realmente útil: puedes crear agentes especializados desde el chat, cada uno con su propia identidad y memoria. El trade-off es que solo funciona con Claude (sin soporte multi-modelo) y que el código se personaliza a través de Claude Code en lugar de archivos de configuración. Si necesitas soporte multi-proveedor, mira [NullClaw](/es/guia-despliegue-nullclaw/) o [nanobot](/es/guia-configuracion-nanobot/).

## 2. nanobot

<Button text="Repositorio GitHub" link="https://github.com/HKUDS/nanobot" variant="solid" color="blue" size="md" icon="github" />

nanobot viene de HKUDS (Universidad de Hong Kong) y ha crecido rápido. 49.436 estrellas a octubre de 2026. El planteamiento es similar al de NanoClaw pero mucho más ambicioso: un framework de agente ligero (~3.500 líneas de código) que se conecta a básicamente todas las plataformas de chat. Ya no es solo un "bot": nanobot ahora se llama a sí mismo un framework de agente de IA personal con WebUI, una TUI nativa y delegación multi-agente. La documentación se movió a [nanobot.wiki](https://nanobot.wiki). Escribimos una [guía de configuración completa de nanobot](/es/guia-configuracion-nanobot/) que cubre MiniMax M2.5, GLM-5 y Brave Search si quieres probarlo.

### Qué hace

- Canales: WebUI, API, Telegram, Feishu, Slack, Discord, Teams, email, Mattermost, Linear, WeChat y otros
- Delegación multi-agente: delega tareas a sub-agentes especializados
- Instalable vía pip: `pip install nanobot-ai` (o el instalador gestionado)
- Sistema de memoria integrado
- Soporta modelos locales a través de vLLM
- Funciona con OpenRouter, Anthropic, OpenAI, DeepSeek, Groq, Gemini y otros
- Despliegue con Docker disponible
- Python 3.11+

La cobertura de canales es lo que diferencia a nanobot. Si necesitas tu bot en WhatsApp y Discord y Slack a la vez, la mayoría de las alternativas no lo hacen sin trabajo extra considerable. La WebUI significa que también puedes chatear desde un navegador sin ninguna plataforma de mensajería.

### Instalación

```bash
pip install nanobot-ai   # o el instalador gestionado
nanobot webui            # abre la configuración en el navegador
# En un VPS / headless: nanobot webui --no-open
# Solo terminal: nanobot onboard --wizard
```

La WebUI es la ruta recomendada en escritorio para la primera ejecución. En un VPS sin entorno gráfico, usa `nanobot webui --no-open` e imprimirá la URL para acceder en remoto. El comando `onboard --wizard` te guía para elegir plataforma de chat y conectar un proveedor LLM en la terminal.

**Verifica**: abre la URL de la WebUI impresa en la primera ejecución (o la salida de `--no-open`) y envía un mensaje de prueba. Deberías recibir una respuesta del modelo configurado.

### Soporte de modelos locales

nanobot puede conectarse a un servidor vLLM local, lo que significa que puedes ejecutar todo el stack sin costes de API tras la inversión inicial en hardware. Si ya tienes una instalación de Ollama o vLLM, apuntar nanobot a ella es sencillo. Consulta la [página de proveedores de nanobot.wiki](https://nanobot.wiki) para los nombres actuales de los flags.

```bash
# Ejemplo: usando un endpoint vLLM local
nanobot config set llm.base_url http://localhost:8000/v1
nanobot config set llm.model your-local-model
```

### Para quién es

nanobot es la elección pragmática si necesitas soporte multi-canal o quieres algo que instales con pip y tengas corriendo en cinco minutos. El respaldo universitario y la comunidad grande significan que los bugs se corrigen y las funciones se añaden con regularidad. La delegación multi-agente es útil para flujos de trabajo cargados de tareas. El trade-off es que con tantas integraciones, la configuración puede volverse densa.

## 3. memU

<Button text="Repositorio GitHub" link="https://github.com/NevaMind-AI/MemU" variant="solid" color="purple" size="md" icon="github" />

memU es distinto del resto de proyectos aquí. No es realmente un chatbot. Es un framework de memoria construido para agentes 24/7, y da la casualidad de que incluye un bot (en memu.bot) como implementación de referencia.

La idea central: la mayoría de chatbots lo olvidan todo entre sesiones, e incluso los que tienen memoria solo hacen recuperación básica. memU trata la memoria como un sistema de archivos, con categorías, elementos y referencias cruzadas, e intenta predecir lo que vas a necesitar antes de que lo pidas.

14.564 estrellas a octubre de 2026. La última release etiquetada es v1.5.1 (2026-03-23). Sin releases etiquetadas desde marzo aunque el repo sigue activo. La página del proyecto ahora es [memu.pro](https://memu.pro).

### Cómo funciona la memoria

memU organiza todo en tres capas:

| Capa | Qué almacena | Propósito |
|---|---|---|
| Recursos | Conversaciones en bruto, documentos, imágenes | Datos originales |
| Elementos | Hechos extraídos, preferencias, habilidades | Conocimiento buscable |
| Categorías | Temas auto-organizados | Navegación y contexto |

La metáfora del "sistema de archivos" significa que la memoria de tu agente se ve así:

```
memory/
├── preferences/
│   ├── communication_style.md
│   └── topic_interests.md
├── knowledge/
│   ├── domain_expertise/
│   └── learned_skills/
└── context/
    ├── recent_conversations/
    └── pending_tasks/
```

Los recuerdos nuevos se auto-categorizan. Los recuerdos relacionados se enlazan entre sí. El sistema afirma un 92% de precisión en el benchmark Locomo, que mide cómo de bien los sistemas de memoria retienen y recuperan información en conversaciones largas.

### Comportamiento proactivo

Aquí es donde memU se pone interesante. En lugar de limitarse a responder cuando se le pregunta, monitoriza conversaciones e intenta anticipar lo que necesitarás a continuación. El agente puede:

- Pre-cargar contexto relevante antes de que lo pidas explícitamente
- Notar patrones en lo que estás trabajando y sacar a la superficie recuerdos relacionados
- Redactar tareas de acción a partir del flujo de la conversación
- Aprender tus preferencias con el tiempo y ajustar las respuestas

Que esto sea útil o molesto probablemente depende de tu tolerancia a las sugerencias no solicitadas. Lo veo funcionando bien para alguien que usa un asistente de IA todo el día, menos para uso ocasional.

### Instalación

<Tabs>
<Tab name="Cloud">

La versión alojada en [memu.pro](https://memu.pro) corre de forma continua. Si quieres probar un sistema de memoria sin autoalojar, este es el camino más rápido.

</Tab>
<Tab name="Self-hosted">

```bash
pip install memu-py

# Prueba en memoria (sin base de datos)
export OPENAI_API_KEY=your_key
cd tests
python test_inmemory.py

# Con PostgreSQL para almacenamiento persistente
docker run -d \
  --name memu-postgres \
  -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=memu \
  -p 5432:5432 \
  pgvector/pgvector:pg16

python test_postgres.py
```

</Tab>
</Tabs>

**Verifica**: ejecuta el script de prueba en memoria y confirma que imprime un recall con éxito.

memU también soporta OpenRouter, así que puedes enrutar por el proveedor de modelo que prefieras:

```python
from memu import MemoryService

service = MemoryService(
    llm_profiles={
        "default": {
            "provider": "openrouter",
            "base_url": "https://openrouter.ai",
            "api_key": "your_openrouter_api_key",
            "chat_model": "anthropic/claude-3.5-sonnet",
        },
    },
)
```

### Para quién es

memU tiene más sentido si estás construyendo tu propio agente y quieres una capa de memoria en condiciones debajo. También merece un vistazo si te frustra lo superficial que es la memoria en otros bots. Para quien evalúe frameworks de memoria en general, mira nuestra comparativa de [sistemas de memoria autoalojados para agentes como Cognee y Hindsight](/es/cognee-vs-hindsight/).

La desventaja es la complejidad. No es un bot de "clonar y ejecutar" como NanoClaw. Es un framework, y tendrás que integrarlo en algo.

## 4. bitdoze-bot

<Button text="Repositorio GitHub" link="https://github.com/bitdoze/bitdoze_bot" variant="solid" color="red" size="md" icon="github" />

Este es mi proyecto. Lo construí porque quería un bot de Discord donde varios agentes especializados trabajaran juntos en lugar de un único modelo respondiendo a todo.

bitdoze-bot usa el [framework Agno](/es/empezar-agno/) para orquestación multi-agente. Defines "equipos" de agentes en carpetas de workspace, cada agente con sus propias herramientas y personalidad, y un coordinador enruta los mensajes entrantes al especialista adecuado.

Escribí una guía de construcción detallada: [Crea tu propio bot de Discord con IA con equipos Agno](/es/crear-tu-propio-agente-ia/).

<YouTubeEmbed
  url="https://www.youtube.com/embed/yoWGFO7tvpc"
  label="Demo multi-agente de bitdoze-bot en Discord"
/>

### Qué hace

- Centrado en Discord (responde a las menciones)
- Equipos multi-agente: un coordinador + agentes especialistas (código, investigación, ops, lo que definas)
- Configuración por workspace: cada agente tiene su propia carpeta con instrucciones, herramientas y permisos
- Memoria y aprendizaje: guarda contexto entre conversaciones y aprende de las correcciones
- Heartbeat + cron: chequeos de salud programados y tareas recurrentes
- Permisos de herramientas y registro de auditoría
- Observabilidad: logs estructurados para cada ejecución de agente

### La configuración por equipos

El enfoque multi-agente es la principal diferencia con todo lo demás de esta lista. En lugar de un modelo intentando hacerlo todo, repartes responsabilidades:

```
workspaces/
├── main/
│   └── agent.yaml          # Coordinador - enruta a especialistas
├── coding/
│   └── agent.yaml          # Especialista en código
├── research/
│   └── agent.yaml          # Especialista en investigación web
└── ops/
    └── agent.yaml          # Especialista en ops de servidores
```

Cuando llega un mensaje, el coordinador decide qué especialista lo gestiona. Puedes empezar solo con el agente `main` e ir añadiendo especialistas según los necesites.

### Cómo empezar

Necesitas Python 3.12+, un token de bot de Discord y una API key de tu proveedor de modelo.

```bash
git clone https://github.com/bitdoze/bitdoze_bot.git
cd bitdoze_bot
cp .env.example .env
# Edita .env con el token de Discord y las API keys

# Instala con UV
uv sync
uv run python main.py
```

**Verifica**: menciona al bot en Discord y confirma que responde un especialista.

### Para quién es

Si quieres ir más allá de un chatbot de agente único y experimentar con coordinación multi-agente, este es el proyecto a mirar. La configuración por workspaces hace fácil añadir nuevos especialistas sin tocar el código del núcleo. El trade-off es que es solo para Discord y el proyecto más pequeño aquí por recuento de estrellas. Pero es uno que uso a diario, y el enfoque multi-agente ha merecido la configuración extra.

## 5. PicoClaw

<Button text="Repositorio GitHub" link="https://github.com/sipeed/picoclaw" variant="solid" color="gray" size="md" icon="github" />

PicoClaw toma el enfoque opuesto a todo lo demás de esta lista. En lugar de añadir funciones, las recorta. El proyecto es una reescritura en Go de nanobot que compila a un único binario, usa menos de 10 MB de RAM y arranca en menos de un segundo. Sipeed (la empresa de hardware RISC-V) lo construyó para correr en sus placas LicheeRV-Nano de 10 $, lo que dice mucho del presupuesto de recursos con el que trabajaban. Escribimos una [guía de configuración completa de PicoClaw](/es/guia-configuracion-picoclaw/) que cubre MiniMax M2.5, GLM-5 y Discord si quieres probarlo.

30.081 estrellas a octubre de 2026. Última release v0.3.1 (2026-07-03). El proyecto ahora tiene sitio oficial en [picoclaw.io](https://picoclaw.io) y docs en [docs.picoclaw.io](https://docs.picoclaw.io).

### Qué hace

- Asistente de IA en binario único, sin dependencias en runtime
- Canales: Telegram, Discord, WhatsApp (QR o bridge), QQ, Matrix, IRC, WeCom
- 30+ proveedores vía `model_list`, incluido proxy LiteLLM (100+ upstream), Azure OpenAI con Entra ID, AWS Bedrock
- Acceso a herramientas: comandos shell, operaciones de archivos, búsqueda web
- Almacenamiento de archivos por workspace para memoria y logs
- Modo CLI para uso local, modo gateway para canales de chat
- Transcripción de mensajes de voz a través del Whisper de Groq
- Soporte de protocolo MCP con gestión de servidores MCP en la Web UI
- WebUI Launcher para configuración y chat desde el navegador

### Comparativa de recursos

Lado a lado con los dos con los que más se le compara. Las cifras son de los README de cada proyecto:

| Métrica | OpenClaw | nanobot | PicoClaw |
|---|---|---|---|
| **RAM** | &gt;1GB | &gt;100MB | menos de 10MB |
| **Arranque (núcleo 0,8GHz)** | &gt;500s | &gt;30s | menos de 1s |
| **Coste mínimo de hardware** | Mac Mini 599 $ | ~50 $ SBC | ~10 $ placa |

El precio de 599 $ del Mac mini de esa tabla está desfasado a estas alturas. Las configuraciones y precios actuales están en la guía del [mejor Mac mini para OpenClaw](/es/mejor-mac-mini-openclaw/).

Si tienes un NanoKVM o MaixCAM por ahí, PicoClaw puede convertirlo en un asistente siempre encendido. Ese es un caso de uso que ningún otro proyecto de esta lista puede tocar.

### Cómo empezar

El WebUI Launcher es la ruta recomendada en escritorio. Te da configuración y chat por navegador sin tocar la CLI:

```bash
# Descarga el binario precompilado de releases, o compila desde el código:
git clone https://github.com/sipeed/picoclaw.git
cd picoclaw
make build

# Opción 1: WebUI launcher (recomendado en escritorio)
picoclaw

# Opción 2: onboarding por CLI
picoclaw onboard
# Edita ~/.picoclaw/config.json con tus API keys

# Chatea directamente
picoclaw agent -m "What is 2+2?"

# O arranca como gateway para Telegram/Discord
picoclaw gateway
```

**Verifica**: `picoclaw agent -m "What is 2+2?"` devuelve una respuesta. Los logs del gateway muestran el canal conectado.

**Modo de fallo**: las claves sensibles ahora viven en `.security.yml`, no en `config.json`. Si restauras desde una copia antigua, los secretos no se transferirán. Vuélvelos a introducir con el asistente onboard o la WebUI.

<Notice type="warning" title="Sin token cripto">
El README de PicoClaw lleva una advertencia explícita: PicoClaw no ha emitido ningún token cripto. Cualquier cosa en pump.fun o plataformas similares que diga ser PicoClaw es una estafa. Esto importa si descargas binarios de cualquier sitio que no sean las releases oficiales de GitHub.
</Notice>

### Para quién es

PicoClaw es la elección si te importa la eficiencia de recursos por encima de todo, o si quieres ejecutar un bot en hardware que se ahogaría con Python. El código Go es pequeño y legible, y el despliegue de binario único significa que no hay nada que instalar. El soporte de más de 30 proveedores vía `model_list` (incluido proxy LiteLLM) significa que puedes enrutar por casi cualquier API de modelo. El trade-off es que el conjunto de funciones es más estrecho que en nanobot o ZeroClaw, y la comunidad aún se está formando.

## 6. IronClaw

<Button text="Repositorio GitHub" link="https://github.com/nearai/ironclaw" variant="solid" color="blue" size="md" icon="github" />
<Button text="Sitio web" link="https://ironclaw.com" variant="solid" color="gray" size="md" />

IronClaw viene de NEAR AI y toma un enfoque de seguridad primero que va mucho más allá de lo que intentan los demás proyectos. Es una reescritura completa en Rust del concepto OpenClaw, y el principal punto de venta es el sandbox WASM. Cada herramienta no confiable corre dentro de un contenedor WebAssembly aislado con permisos explícitos basados en capacidades. Tus API keys nunca se exponen al código de las herramientas. Las peticiones HTTP solo van a hosts que hayas aprobado.

12.677 estrellas a octubre de 2026. Última release v1.4.1 (2026-09-29). La descripción del repo ahora dice "Agent OS focused on privacy, security and extensibility", el mismo espacio de posicionamiento que OpenFang. IronClaw alcanzó la línea estable v1.x en 2026 y ya no es una herramienta solo-REPL: hay una WebUI en [ironclaw.com](https://ironclaw.com), una bandeja de notificaciones durable y subagentes en segundo plano.

Si alguna vez te ha dado respeto dar acceso shell a un agente de IA en un equipo con datos reales, IronClaw se construyó para esa ansiedad.

### Qué hace

- Asistente de IA nativo en Rust con WebUI, REPL, webhook HTTP y canales basados en WASM (Telegram, Slack)
- Sandbox WASM para toda la ejecución de herramientas con permisos basados en capacidades
- Protección de credenciales: los secretos se inyectan en el límite del host, el código de la herramienta nunca los ve
- Defensa contra prompt injection con detección de patrones y saneado de contenido
- Lista de endpoints permitidos para que el agente solo alcance hosts que apruebes
- PostgreSQL con pgvector para memoria (búsqueda híbrida texto completo + vector)
- Subagentes en segundo plano: un turno padre genera hijos que ejecutan y entregan resultados por su cuenta
- Bandeja de notificaciones durable para resultados de tareas asíncronas
- Contenedores sandbox persistentes por usuario en el perfil local-Docker
- Auto-expansible: describe la herramienta que necesitas e IronClaw la construye como módulo WASM
- Soporte de protocolo MCP para conectar servidores de herramientas externos

### El modelo de seguridad

Aquí es donde IronClaw se separa. El pipeline de seguridad para la ejecución de herramientas es así:

1. La petición de la herramienta llega al validador de endpoints permitidos
2. La petición se escanea en busca de fugas de credenciales
3. Las credenciales se inyectan en el límite del host (el código de la herramienta nunca las retiene)
4. La petición se ejecuta dentro del sandbox WASM
5. La respuesta se vuelve a escanear en busca de fugas de credenciales
6. El resultado vuelve al agente

También hay límites de tasa por herramienta y topes de recursos (memoria, tiempo de CPU, duración de ejecución). Las reglas de política te permiten fijar niveles de severidad para distintas situaciones: bloquear, avisar, revisar o sanear.

Ningún otro proyecto de esta lista tiene algo cercano a este nivel de aislamiento. NanoClaw tiene aislamiento por contenedor, pero los contenedores WASM de IronClaw toman un enfoque distinto, con permisos basados en capacidades integrados.

### Cómo empezar

IronClaw v1.4 es WebUI-first. El viejo flujo de compilar-desde-código para la REPL ya no es el camino principal. Consulta [ironclaw.com/docs](https://ironclaw.com/docs) para el método de instalación actual. La línea v1.4 introdujo perfiles de sandbox gestionados, un perfil de preview en Railway y activación con Google OAuth para las extensiones.

Si prefieres compilar desde el código:

```bash
git clone https://github.com/nearai/ironclaw.git
cd ironclaw
cargo build --release

# Configura PostgreSQL con pgvector
createdb ironclaw
psql ironclaw -c "CREATE EXTENSION IF NOT EXISTS vector;"

# Ejecuta el asistente de configuración
ironclaw onboard
```

Necesitarás Rust 1.85+, PostgreSQL 15+ con pgvector y una cuenta de auth (el asistente gestiona el flujo OAuth a través de tu navegador).

**Verifica**: la WebUI carga tras la configuración, o el estado del daemon `ironclaw` muestra running.

**Modo de fallo**: IronClaw requiere PostgreSQL. Si no lo tienes corriendo, el asistente onboard fallará en el paso de conexión a la BD. En un VPS, instala primero postgresql-15 y pgvector.

### Para quién es

IronClaw es para quien quiere las garantías de seguridad más fuertes disponibles en este espacio. El sandbox WASM, el aislamiento de credenciales y los subagentes en segundo plano lo convierten en la opción más segura para ejecutar un agente de IA con acceso real a herramientas en una máquina de producción. El código Rust da rendimiento nativo y seguridad de memoria. Las desventajas: requiere infraestructura PostgreSQL, y el requisito de auth de NEAR AI puede no gustar a quien quiera una instalación autoalojada totalmente independiente. Si quieres trabajo autónomo en segundo plano sin los trade-offs de seguridad, los subagentes en segundo plano de IronClaw (v1.4+) merecen un vistazo.

## 7. ZeroClaw

<Button text="Repositorio GitHub" link="https://github.com/zeroclaw-labs/zeroclaw" variant="solid" color="blue" size="md" icon="github" />

ZeroClaw empezó como un asistente basado en Rust que llevaba la eficiencia de recursos más lejos que PicoClaw. Ha crecido hasta algo mayor: 33.050 estrellas a octubre de 2026, v0.8.6 (2026-10-18), y ahora se llama a sí mismo "un runtime de agentes". El binario de release incluye un host de plugins WebAssembly, un registro de plugins para paquetes de canales y herramientas, y principals autenticados con OIDC.

Escribimos una [guía de configuración completa de ZeroClaw](/es/guia-configuracion-zeroclaw/) que cubre MiniMax M2.5, GLM-5 y Discord si quieres probarlo.

### Qué hace

- Binario único en Rust con más de 30 canales (Discord, Telegram, Matrix, email, voz, webhooks, CLI y más)
- ~20 proveedores LLM integrados (OpenRouter, Anthropic, OpenAI, Ollama, Gemini, Groq, Mistral, xAI, DeepSeek y más)
- Memoria híbrida SQLite: búsqueda por palabra clave FTS5 + embeddings vectoriales con similitud coseno
- Motor SOP (Standard Operating Procedure): pasos tipados, disparadores cron/filesystem/calendario, plano de aprobación para comportamiento programado y autónomo
- Host de plugins WASM con registro de plugins para canales y herramientas
- Emparejamiento de gateway con códigos de un solo uso de 6 dígitos y auth por bearer token
- Sandboxing de workspace, listas de comandos permitidos y protección de rutas prohibidas
- Almacenamiento de secretos cifrado (ChaCha20-Poly1305)
- Soporte Docker con imágenes de producción distroless
- Comando `zeroclaw migrate openclaw` integrado para cambiar desde OpenClaw
- Configuración TOML en lugar de JSON

### Enfoque de seguridad

Los valores de seguridad por defecto de ZeroClaw son más estrictos que en la mayoría de proyectos de esta lista. El gateway se vincula a `127.0.0.1` y se niega a hacerse público sin un túnel. Las listas de canales permitidos vacías rechazan todos los mensajes por defecto (lo contrario de la mayoría de bots). Hay un flujo de código de emparejamiento de 6 dígitos antes de que el gateway acepte peticiones de webhook.

```toml
[autonomy]
workspace_only = true
allowed_commands = ["git", "npm", "cargo", "ls", "cat", "grep"]
forbidden_paths = ["/etc", "/root", "/proc", "/sys", "~/.ssh", "~/.gnupg", "~/.aws"]

[secrets]
encrypt = true
```

14 directorios del sistema y 4 dotfiles sensibles están bloqueados por defecto. Los intentos de escape por symlink se detectan mediante canonicalización de rutas.

### Cómo empezar

El instalador curl es el camino más rápido:

```bash
curl -fsSL https://raw.githubusercontent.com/zeroclaw-labs/zeroclaw/master/install.sh | sh
"${CARGO_HOME:-$HOME/.cargo}/bin/zeroclaw" quickstart
```

Compilar desde el código (aún soportado, y necesario en algunas plataformas):

```bash
git clone https://github.com/zeroclaw-labs/zeroclaw.git
cd zeroclaw
cargo build --release --locked
cargo install --path . --force --locked

# Configuración interactiva
zeroclaw onboard --interactive

# Chat
zeroclaw agent -m "Hello!"

# Arranca todos los canales
zeroclaw daemon
```

En una Raspberry Pi con 1 GB de RAM, usa `CARGO_BUILD_JOBS=1 cargo build --release` para evitar que el kernel mate rustc.

**Verifica**: `zeroclaw agent -m "Hello!"` responde. El daemon muestra los canales online.

<Notice type="warning" title="Riesgo al actualizar a 0.8.x">
Si ejecutas ZeroClaw 0.7.x, lee la sección de breaking changes de v0.8.6 antes de actualizar. El emparejamiento del gateway, las conexiones remotas ZeroCode, la automatización del navegador, las descargas en redes privadas y la versión WIT de los plugins cambiaron. Vuelve a comprobar el emparejamiento del gateway tras actualizar.
</Notice>

### Para quién es

ZeroClaw es la elección si quieres bajo consumo de recursos con valores de seguridad serios y un rango amplio de proveedores integrados. El motor SOP ahora cubre comportamiento programado y autónomo, que antes era el nicho de OpenFang. El sistema de plugins permite extenderlo sin tocar el núcleo. Si migras desde OpenClaw, el comando de migración integrado hace el cambio sencillo. El trade-off es el tiempo de compilación si compilas desde el código (el instalador curl lo evita).

## 8. NullClaw

<Button text="Repositorio GitHub" link="https://github.com/nullclaw/nullclaw" variant="solid" color="purple" size="md" icon="github" />

NullClaw lleva la eficiencia de recursos al límite absoluto. Es un binario Zig estático: 678 KB, ~1 MB de RAM en runtime, arranca en menos de 2 milisegundos en Apple Silicon. El proyecto incluye más de 50 proveedores LLM, 19 canales de chat, memoria híbrida (FTS5 + vector) y sandboxing multicapa. Escribimos una [guía de despliegue completa de NullClaw](/es/guia-despliegue-nullclaw/) que cubre proveedores, canales, memoria, sandboxing y despliegue en hardware edge.

La filosofía "null overhead, null compromise" significa cero dependencias en runtime más allá de libc. Suelta el binario en cualquier hardware con CPU y funciona. Eso incluye placas ARM de 5 $ y SBCs RISC-V.

8.133 estrellas a octubre de 2026. Última release v2026.5.29 (2026-05-29). Versionado por calendario. Cadencia de releases más lenta que sus pares, pero el repo recibió pushes tan recientemente como octubre de 2026.

### Qué hace

- Binario estático de 678 KB sin dependencias en runtime
- 19 canales: CLI, Telegram, Signal, Discord, Slack, iMessage, Matrix, WhatsApp, Nostr, Mattermost, IRC, Line, Lark, QQ, OneBot, Email, DingTalk, MaixCam, Webhook
- 50+ proveedores LLM vía interfaz compatible con OpenAI (OpenRouter, Anthropic, OpenAI, Ollama, Groq, Mistral, xAI, DeepSeek y más)
- Memoria híbrida SQLite: búsqueda por palabra clave FTS5 + embeddings vectoriales con similitud coseno
- Sandboxing multicapa: Landlock, Firejail, Bubblewrap, Docker (autodetectado)
- Emparejamiento de gateway con códigos de 6 dígitos y auth por bearer token
- Secretos cifrados (ChaCha20-Poly1305)
- Subagentes, streaming, voz, túneles, periféricos hardware, soporte de servidores MCP
- `nullclaw migrate openclaw` integrado para cambiar desde OpenClaw
- Compilación cruzada para ARM, x86 y RISC-V desde cualquier plataforma
- Config compatible con OpenClaw (snake_case): proveedores bajo `models.providers`, modelo bajo `agents.defaults.model.primary`

### Huella de recursos

La misma comparativa, con ZeroClaw y NullClaw añadidos. Todas las cifras vienen de los README de cada proyecto, así que trátalas como afirmaciones y no como mediciones:

| Métrica | OpenClaw | nanobot | PicoClaw | ZeroClaw | **NullClaw** |
|---|---|---|---|---|---|
| **RAM** | &gt;1GB | &gt;100MB | &lt;10MB | &lt;5MB | **~1 MB** |
| **Arranque (0,8 GHz)** | &gt;500s | &gt;30s | &lt;1s | &lt;10ms | **&lt;8 ms** |
| **Binario** | ~28MB | N/A | ~8MB | 3,4MB | **678 KB** |
| **Tests** | n/a | n/a | n/a | 1.017 | **5.300+** |
| **Hardware mínimo** | Mac Mini 599 $ | ~50 $ SBC | ~10 $ placa | ~10 $ | **placa de 5 $** |

### Cómo empezar

```bash
# Instala Zig 0.15.2
curl -L https://ziglang.org/download/0.15.2/zig-linux-x86_64-0.15.2.tar.xz | tar -xJ
sudo mv zig-linux-x86_64-0.15.2 /usr/local/zig
sudo ln -s /usr/local/zig/zig /usr/local/bin/zig

# Clona y compila
git clone https://github.com/nullclaw/nullclaw.git
cd nullclaw
zig build -Doptimize=ReleaseSmall

# Configuración (no interactiva)
nullclaw onboard --api-key sk-... --provider openrouter

# Comprueba la salud de los canales
nullclaw channel status
nullclaw channel start telegram

# Arranca
nullclaw daemon
```

Para recomendaciones de modelos, [MiniMax M2.5 y GLM-5](/es/mejores-modelos-opensource-openclaw/) funcionan bien con NullClaw a través de OpenRouter o endpoints API directos.

Si quieres una UI en lugar de editar JSON, prueba [NullHub (beta)](https://github.com/nullclaw/nullhub). Proporciona UI de configuración, orquestación, observabilidad y seguimiento de tareas para el ecosistema Null.

**Verifica**: `nullclaw channel status` muestra tus canales. `nullclaw channel start telegram` pone el canal de Telegram online.

### Para quién es

NullClaw es para quien quiere la huella más pequeña posible con el conjunto de funciones más amplio. Si tienes una Raspberry Pi Zero, un SBC ARM barato o cualquier dispositivo edge por ahí, NullClaw lo convierte en un asistente de IA completo. Los 19 canales y más de 50 proveedores hacen improbable que topes con un muro en conectividad. El formato de config compatible con OpenClaw hace la migración más fácil que en la mayoría. El trade-off es que Zig es menos familiar que Rust o Python, y la comunidad es más nueva. Pero la suite de más de 5.300 tests y el desarrollo activo sugieren que el proyecto es sólido.

## 9. OpenFang

<Button text="Repositorio GitHub" link="https://github.com/RightNow-AI/openfang" variant="solid" color="red" size="md" icon="github" />

<Notice type="warning" title="El desarrollo lleva en silencio desde mayo de 2026">
La última release de OpenFang (v0.6.9) y el último commit en main son ambos del 2026-05-12. Son más de cinco meses sin actividad mientras todos los demás proyectos de este resumen publicaban releases. Los forks principales tienen 2 estrellas cada uno, así que no hay continuación comunitaria. Si quieres agentes autónomos programados con mantenimiento activo, mira el motor SOP de ZeroClaw (v0.8.3+) o los subagentes en segundo plano de IronClaw (v1.4+). Si aún quieres probar OpenFang, trátalo como sin mantenimiento hasta que retome la actividad.
</Notice>

OpenFang se llama a sí mismo un "Agent Operating System". Construido en Rust (137K líneas de código, 14 crates, más de 1.767 tests), compila a un único binario de ~32 MB. La parte interesante son los Hands: agentes autónomos que corren según horarios, construyen grafos de conocimiento y reportan a tu panel sin que tú los invoques. Escribimos una [guía de configuración completa de OpenFang](/es/guia-configuracion-openfang/) que cubre GLM-5, MiniMax M2.5, Discord, el sistema Hands y la configuración de seguridad.

18.229 estrellas a octubre de 2026. No archivado, pero inactivo.

### Qué hace

- Binario único en Rust de ~32 MB con 40 adaptadores de canal (Telegram, Discord, Slack, WhatsApp, Signal, Matrix, Teams, LINE, IRC y 31 más)
- 7 Hands autónomos: Clip (vídeo), Lead (ventas), Collector (OSINT), Predictor (pronósticos), Researcher (investigación profunda), Twitter (social), Browser (automatización web)
- 27 proveedores LLM incluidos MiniMax, Zhipu, Anthropic, OpenAI, Ollama, vLLM y OpenRouter
- 16 sistemas de seguridad discretos: sandbox WASM con doble medición, registro de auditoría Merkle, taint tracking, manifiestos firmados con Ed25519, protección SSRF
- 53 herramientas integradas + soporte MCP + protocolo Agent-to-Agent (A2A)
- Memoria SQLite + embeddings vectoriales con sesiones canónicas y compactación
- Panel integrado en localhost:4200 (app de escritorio Tauri 2.0 también disponible)
- Migración desde OpenClaw: `openfang migrate --from openclaw`

### El sistema Hands

Los Hands son lo que separa a OpenFang de los chatbots. Cada Hand es un agente autónomo preconstruido que empaqueta un manifiesto HAND.toml, un system prompt multifase, experiencia de dominio (SKILL.md) y guardarraíles. Activas uno y corre según un horario. El Hand Researcher cruza fuentes y genera informes citados. El Hand Lead descubre y puntúa prospectos a diario. El Hand Collector monitoriza objetivos con detección de cambios y análisis de sentimiento.

```bash
openfang hand activate researcher
openfang hand status researcher
```

También puedes construir tus propios Hands y publicarlos en FangHub.

### Enfoque de seguridad

OpenFang lanzó el modelo de seguridad más profundo de cualquier proyecto de esta lista. Los 16 sistemas incluyen sandboxing WASM (el código de las herramientas físicamente no puede escapar), registros de auditoría con cadena de hashes Merkle (altera una entrada y la cadena se rompe), seguimiento de flujo de información por taint, manifiestos de agente firmados con Ed25519, protección SSRF y zeroización automática de secretos. Cada capa opera de forma independiente.

### Cómo empezar

```bash
# Instala
curl -fsSL https://openfang.sh/install | sh

# Inicializa
openfang init

# Arranca el daemon
openfang start

# El panel está en http://localhost:4200
```

Para recomendaciones de modelos, [GLM-5 y MiniMax M2.5](/es/mejores-modelos-opensource-openclaw/) funcionan bien. GLM-5 combina bien con el Hand Researcher dados sus resultados en BrowseComp.

**Consejo de producción**: trata OpenFang como sin mantenimiento hasta que retome actividad. Si lo ejecutas de todos modos, fíjalo a un commit concreto y no lo expongas a entrada no confiable sin revisar tú mismo la config de seguridad.

### Para quién es

OpenFang merece leerse si quieres ver cómo es una arquitectura de Agent OS: Hands, 40 adaptadores, 16 capas de seguridad. Pero la inactividad es un problema real. Sin mantenimiento significa vulnerabilidades sin parchear y ninguna corrección de bugs. Si quieres trabajo autónomo programado, el motor SOP de ZeroClaw o los subagentes en segundo plano de IronClaw son las alternativas con mantenimiento activo. Solo ejecuta OpenFang si aceptas el riesgo de mantenimiento y te sientes cómodo revisando parches de seguridad por tu cuenta.

## 10. Hermes Agent

<Button text="Repositorio GitHub" link="https://github.com/NousResearch/hermes-agent" variant="solid" color="green" size="md" icon="github" />

Hermes Agent es un asistente de IA auto-mejorable de Nous Research. La función estrella es un bucle de aprendizaje: el agente crea skills a partir de tareas complejas, mejora esas skills en ejecuciones posteriores y recuerda quién eres entre sesiones mediante MEMORY.md, USER.md y búsqueda de sesiones FTS5. ## Nuevas alternativas a OpenClaw a vigilar (finales de 2026)

Son tiempos tempranos para las cuatro: equipos pequeños, moviéndose rápido; evalúalas en consecuencia.

**AstrBot** ([AstrBotDevs/AstrBot](https://github.com/AstrBotDevs/AstrBot), 43,9k estrellas) es un asistente de IA y framework de desarrollo maduro en Python que integra muchas plataformas IM, LLMs y plugins. Es un proyecto más antiguo que fue re-descubierto como alternativa a OpenClaw. Si quieres amplitud de plataformas desde el primer momento, merece un vistazo.

**Poco** ([poco-ai/poco-claw](https://github.com/poco-ai/poco-claw), 1,4k estrellas, MIT) es un "compañero de bolsillo" construido sobre Python 3.12 + FastAPI + Next.js. Con Docker, servidores de larga duración con canales, DMs e hilos. Convierte mensajes en tareas rastreables con salidas de archivos compartidas. La UI más bonita de los nuevos participantes. Docs en docs.poco-ai.com.

**Kai** ([SimonSchubert/Kai](https://github.com/SimonSchubert/Kai), 1,3k estrellas) es una "alternativa a OpenClaw en tu bolsillo" basada en Kotlin. Ángulo móvil.

**thClaws** ([thClaws/thClaws](https://github.com/thClaws/thClaws), 1,2k estrellas) es un agente en Rust con GUI, CLI, modo headless y webapp desde un único binario. Multi-proveedor.

Recuentos de estrellas a 27 de octubre de 2026.

## ¿Cuál deberías elegir?

La mejor alternativa a OpenClaw depende de lo que necesites:

<ListCheck>
<ul>
<li>¿Quieres seguridad a nivel de contenedor con enjambres multi-agente y compañeros en Slack? NanoClaw v2 aísla los agentes en contenedores Docker y soporta Agent Swarms. Mira la [guía de despliegue](/es/guia-despliegue-nanoclaw/).</li>
<li>¿Necesitas estar en Telegram, Discord, WhatsApp y Slack a la vez con delegación multi-agente? nanobot lo hace.</li>
<li>¿Construyes tu propio agente y necesitas un sistema de memoria de verdad? memU es el framework de memoria a mirar.</li>
<li>¿Quieres equipos multi-agente en Discord? bitdoze-bot lo hace con Agno.</li>
<li>¿Hardware extremadamente limitado o un binario Go único sin dependencias? PicoClaw.</li>
<li>¿Necesitas aislamiento de seguridad serio con herramientas en sandbox WASM y subagentes en segundo plano? IronClaw es la opción endurecida.</li>
<li>¿Quieres trabajo autónomo programado? Primero el motor SOP de ZeroClaw, luego los subagentes en segundo plano de IronClaw, OpenFang tercero (con la salvedad de la inactividad).</li>
<li>¿Quieres el binario más pequeño en absoluto (678 KB, ~1 MB RAM) con 19 canales y soporte de hardware edge? [NullClaw](/es/guia-despliegue-nullclaw/).</li>
<li>¿Quieres un asistente auto-mejorable con modo de voz, búsqueda de sesiones, plugins y la migración más fácil desde OpenClaw? [Hermes Agent](/es/guia-configuracion-hermes-agent/).</li>
</ul>
</ListCheck>

Todos funcionan en un VPS básico. Un [Hetzner CX22 VPS](https://go.bitdoze.com/hetzner) (unos 5-6 $/mes) es suficiente para cualquiera de ellos, o un [VPS Hostinger económico](https://go.bitdoze.com/hostinger-vps) si quieres ubicaciones en EE. UU. o almacenamiento NVMe. Antes de comprometerte con un proveedor, aquí está [cómo medir el rendimiento de un VPS antes de decidir](/es/benchmark-servidores-cloud/). Los costes de API dependen del modelo que elijas y de cuánto chatees, pero 15-50 $/mes cubre a la mayoría. Modelos como MiniMax M2.5 vía [la API de MiniMax](https://go.bitdoze.com/minimax) o [GLM-5 vía Z.ai](https://go.bitdoze.com/glm) mantienen los costes en el extremo bajo. Para recomendaciones de modelos, mira nuestra guía de [mejores modelos open source para OpenClaw](/es/mejores-modelos-opensource-openclaw/).

Si aún no has probado ningún bot de IA autoalojado, recomendaría empezar con [el propio OpenClaw](/es/guia-configuracion-openclaw/). Es el más documentado, tiene la comunidad más grande (393k estrellas) y el asistente de configuración hace la primera ejecución bastante indolora. Una vez que sepas qué querrías cambiar de él, estas alternativas empiezan a tener más sentido.

<Accordion label="Preguntas frecuentes" group="faq" expanded="true">

**¿Puedo cambiar de OpenClaw a uno de estos sin perder mis conversaciones?**

No directamente en la mayoría de los proyectos. Cada uno almacena la memoria de forma distinta. Tendrías que exportar desde OpenClaw e importar a mano, o simplemente empezar de cero. memU tiene las opciones de importación más flexibles al estar diseñado como framework de memoria. La excepción es Hermes Agent, que tiene una herramienta de migración integrada (ahora distribuida vía el plugin `agent-importers`): ejecuta `hermes plugins install agent-importers` y luego `hermes claw migrate` (añade `--migrate-secrets` para las API keys). El formato de config de NullClaw es compatible con OpenClaw (snake_case), lo que facilita el traslado a nivel de configuración. NanoClaw tiene una migración aparte de v1 a v2 (`migrate-v2.sh`), que es una migración distinta. No confundas las dos.

**¿Funciona alguno en una Raspberry Pi?**

NanoClaw y nanobot pueden correr en una Pi 4 con 4GB+ de RAM. El rendimiento será limitado. memU con PostgreSQL necesita más recursos. bitdoze-bot depende de cuántos agentes ejecutes. PicoClaw es el claro ganador aquí, corriendo en placas desde 10 $ con menos de 10 MB de RAM. ZeroClaw es un segundo cercano, aunque necesita más RAM al compilar (usa `CARGO_BUILD_JOBS=1` en una Pi de 1 GB). NullClaw lo lleva más lejos: el binario de 678 KB usa solo ~1 MB de RAM y corre en placas de 5 $ incluida la Raspberry Pi Zero 2 W. Hermes Agent corre en Android/Termux vía un repo APT firmado, lo que lo convierte en la opción de bolsillo. Si una Pi se queda corta para tu carga, un mini PC x86 compacto como el [ASUS DC510](https://go.bitdoze.com/asus-dc510) ejecuta cualquiera de estos con espacio para un modelo local. Mira nuestra guía del [mejor mini PC para LLMs locales y Ollama](/es/mejores-mini-pc-llm-local/) para los niveles de hardware.

**¿Puedo usar modelos locales en lugar de proveedores API?**

nanobot tiene soporte nativo de vLLM. NanoClaw solo usa el Agent SDK de Claude (sin soporte de otros modelos). bitdoze-bot funciona con cualquier endpoint compatible con OpenAI, así que puedes apuntarlo a Ollama o vLLM. memU soporta proveedores LLM personalizados. PicoClaw funciona con más de 30 proveedores incluido proxy LiteLLM, lo que cubre casi cualquier instalación local. ZeroClaw tiene un proveedor Ollama integrado y soporta cualquier endpoint compatible con OpenAI vía el proveedor `custom:`. NullClaw soporta más de 50 proveedores incluidos Ollama y cualquier endpoint compatible con OpenAI. OpenFang soporta 27 proveedores incluidos Ollama, vLLM y LM Studio. Hermes Agent soporta Ollama, vLLM y cualquier endpoint compatible con OpenAI. Si quieres ejecutar todo en local con calidad nivel Claude, mira la guía de [mejores LLMs open source para reemplazar a Claude](/es/mejores-llms-opensource-alternativa-claude/). Para hardware y configuración, mira nuestra guía de [ejecutar OpenClaw con Ollama](/es/openclaw-ollama-modelos-locales/) o la [guía de Ollama en Docker](/es/ollama-docker-instalacion/) para la instalación con Docker.

**¿Cuánta programación requieren?**

NanoClaw se personaliza mediante comandos de Claude Code en lugar de archivos de configuración. nanobot tiene un asistente WebUI y `nanobot onboard --wizard` para configuración por terminal, casi cero código para uso básico. PicoClaw tiene un WebUI Launcher y asistente onboard por CLI. ZeroClaw tiene un asistente onboard interactivo y config TOML. NullClaw usa `nullclaw onboard` y un archivo de config JSON. OpenFang tiene `openfang init` y un `config.toml`. Hermes Agent usa `hermes setup` con asistente guiado y guarda la config en `~/.hermes/config.yaml`. IronClaw v1.4 es WebUI-first. bitdoze-bot necesita algo de configuración YAML para los agentes. memU requiere trabajo de integración en Python al ser un framework, no un bot independiente.

**¿Cómo sé si un proyecto open source está abandonado?**

Comprueba tres cosas: fecha del último commit en la rama por defecto, última release etiquetada y actividad de los forks. GitHub muestra todo esto en la página del repo y la pestaña insights. OpenFang es el ejemplo práctico: último commit 2026-05-12, última release v0.6.9 (2026-05-12), forks principales con 2 estrellas cada uno. Son cinco meses de silencio mientras sus pares publicaban varias releases. Revisa también los tiempos de respuesta a issues abiertos. Si los mantenedores no responden a los issues, el proyecto está efectivamente muerto aunque el repo no esté archivado. La fila "Última release" de nuestra tabla comparativa de arriba te da esta señal de un vistazo.

**¿Cuál es el mejor para trabajo autónomo y programado?**

El motor SOP de ZeroClaw (v0.8.3+) es la mejor opción con mantenimiento activo: pasos tipados, disparadores cron/filesystem/calendario y un plano de aprobación. Los subagentes en segundo plano de IronClaw (v1.4+) son el segundo: un turno padre genera hijos que ejecutan y entregan resultados por su cuenta. El sistema Hands de OpenFang se construyó para esto, pero el proyecto está inactivo (ver sección 9). Para multi-agente conversacional (distinto de la autonomía programada), NanoClaw v2 tiene compañeros en Slack y Agent Swarms, nanobot tiene delegación y NullClaw tiene subagentes.
