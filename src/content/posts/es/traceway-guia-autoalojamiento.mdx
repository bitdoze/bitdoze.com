Las facturas de observabilidad crecen sin avisar. Un día registras unos pocos servicios y al mes siguiente la factura de Datadog compite con tus servidores. Esta guía enseña cómo **autoalojar Traceway**, la **plataforma de observabilidad open source** con licencia MIT, como **alternativa gratuita a Datadog**. Traceway 2.0 se lanzó el 2026-09-20 con funciones nuevas (RUM, guardias on-call, SLOs, profiling) y cambios incompatibles. Todo abajo está actualizado a la rama 2.x.

## ¿Qué es Traceway?

[Traceway](https://github.com/tracewayapp/traceway) es una plataforma de observabilidad de código abierto que reúne logs, trazas, métricas, session replay, excepciones, trazado de IA, RUM y guardias on-call. Ingiera datos directamente por OTLP/HTTP sin necesidad de collector ni SDKs propietarios.

Ronda las 1.786 estrellas en GitHub con lanzamientos casi semanales desde septiembre de 2026 (última versión revisada: `backend/v2.0.16`) bajo licencia MIT pura, sin restricciones open-core.

<Notice type="info" title="Proyecto joven pero funcional">
Traceway avanza muy rápido. Traceway 2.0 fue una actualización con cambios incompatibles en tablas de telemetría y APIs, así que prueba las actualizaciones antes de aplicarlas en producción y revisa siempre el changelog.
</Notice>

### Qué incluye

| Funcionalidad | Qué hace |
| --- | --- |
| Logs | Búsqueda estructurada vinculada a trazas en menos de un segundo |
| Trazas | Cascadas de spans de extremo a extremo entre servicios |
| Métricas | Métricas de host, runtime y personalizadas con paneles configurables |
| Excepciones | Stack traces normalizadas con SHA-256 agrupadas con source maps |
| Session Replay | Grabación de sesiones previas a errores en web (cualquier framework JS) y Flutter |
| Observabilidad de IA | Coste, tokens, latencia y conversaciones completas de LLMs |
| Endpoints | Latencia P50/P95/P99 por ruta con puntuación Apdex |
| RUM | Core Web Vitals, alertas de regresión por release y SLOs de frontend |
| On-Call y alertas | Rotaciones, escalados, entrega por SMS y confirmación en un clic |
| SLOs | Presupuestos de error con alertas de burn-rate multiventana |
| Profiling | Flame graphs de Go pprof y perfiles OTLP (experimental) |
| Simbolización | Source maps, iOS dSYM, Android R8 y Flutter mediante `npx traceway-sourcemaps` |
| Fleet Overview | CPU/RAM/disco por organización y nodos Kubernetes con `kubectl apply` |
| Skills + CLI + MCP | Consulta telemetría desde agentes IA (`npx skills add tracewayapp/skills --all`) |

### Por qué Traceway frente a las alternativas

| | Empresarial (Datadog/New Relic) | OSS DIY (Prometheus + Loki + Tempo) | Traceway |
| --- | --- | --- | --- |
| Precio | Por evento, host y usuario | Gratis con alta carga operativa | Autoalojado gratis, cloud tarifa fija |
| Configuración | SDK por lenguaje | Unir 6 herramientas | `docker compose up -d` |
| Licencia | Propietaria | Mixta (BSL/open-core) | MIT sin asteriscos |
| OTel | Envuelto en SDK | Requiere Collector | Ingesta nativa OTLP/HTTP |
| Replay + trazas + IA | Tres productos distintos | Cableado manual | Un sistema, un trace ID |
| RUM + SLOs + On-Call | Productos y facturas aparte | No incluido | Integrado |
| Profiling | Nivel Enterprise | pprof + Grafana manual | Integrado (experimental) |

## Arquitectura

| Servicio | Tecnología | Función |
| --- | --- | --- |
| Backend | Go 1.26, Gin | Ingesta OTLP, API REST, alertas y migraciones |
| Frontend | SvelteKit 2, Svelte 5, Tailwind CSS v4 | SPA del panel |
| Bases de datos | ClickHouse + PostgreSQL | Telemetría en ClickHouse y datos relacionales en PostgreSQL |

El backend expone los endpoints OTLP/HTTP en `/api/otel/v1/traces`, `/api/otel/v1/metrics` y `/api/otel/v1/logs`, más un volumen blob (`traceway-storage`) para source maps, grabaciones de sesión y trazas de IA.

Traceway soporta **solo OTLP/HTTP, sin gRPC**. Si tu SDK usa gRPC por defecto (Python lo hace), tus datos desaparecerán sin error.

## Desplegar Traceway con Docker Compose

La ruta recomendada usa la imagen precompilada `ghcr.io/tracewayapp/traceway:minimal`.

```bash
mkdir -p /opt/traceway && cd /opt/traceway
```

```yaml
services:
  traceway:
    image: ghcr.io/tracewayapp/traceway:minimal
    ports: ["80:80"]
    environment:
      CLICKHOUSE_SERVER: "clickhouse:9000"
      CLICKHOUSE_DATABASE: "traceway"
      CLICKHOUSE_USERNAME: "default"
      CLICKHOUSE_PASSWORD: clickhouse
      CLICKHOUSE_TLS: "false"
      POSTGRES_HOST: "postgres"
      POSTGRES_PORT: "5432"
      POSTGRES_DATABASE: "traceway"
      POSTGRES_USERNAME: "traceway"
      POSTGRES_PASSWORD: traceway
      POSTGRES_SSLMODE: "disable"
      JWT_SECRET: change-me-openssl-rand-hex-32   # generate with: openssl rand -hex 32
      # APP_BASE_URL: "https://traceway.example.com"
      # TRUSTED_PROXIES: "172.18.0.0/16"
    volumes:
      - traceway-storage:/app/storage
    depends_on:
      clickhouse: { condition: service_healthy }
      postgres:  { condition: service_healthy }
    restart: unless-stopped
  clickhouse:
    image: clickhouse/clickhouse-server:24.8-alpine
    environment: { CLICKHOUSE_DB: traceway, CLICKHOUSE_PASSWORD: clickhouse }
    volumes: [clickhouse-data:/var/lib/clickhouse]
    healthcheck:
      test: ["CMD", "clickhouse-client", "--password", "clickhouse", "--query", "SELECT 1"]
      interval: 5s
      timeout: 3s
      start_period: 10s
      retries: 10
    restart: unless-stopped
  postgres:
    image: postgres:17
    environment: { POSTGRES_USER: traceway, POSTGRES_PASSWORD: traceway, POSTGRES_DB: traceway }
    volumes: [postgres-data:/var/lib/postgresql/data]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U traceway"]
      interval: 5s
      timeout: 3s
      start_period: 10s
      retries: 10
    restart: unless-stopped
volumes:
  clickhouse-data: {}
  postgres-data: {}
  traceway-storage: {}
```

<Notice type="warning" title="Define un JWT_SECRET real">
Genera una clave aleatoria con <code>openssl rand -hex 32</code> antes del primer arranque y mantenla estable. Cambiarla invalida sesiones y tokens CLI/MCP.
</Notice>

Si prefieres almacenamiento S3 en lugar de volumen local para `traceway-storage`, define `STORAGE_TYPE=s3`, `S3_BUCKET`, `S3_REGION` y opcionalmente `S3_ENDPOINT` (para MinIO o Cloudflare R2).

Arranca el stack y comprueba el endpoint de salud:

```bash
docker compose up -d
curl -s http://localhost/health
```

<Notice type="info" title="El primer arranque pasa por /register">
Abre <code>http://tu-ip/register</code> para crear tu primera cuenta. No existen credenciales por defecto en despliegues Docker. Crea un proyecto OpenTelemetry y copia tu <strong>project token</strong>.
</Notice>

## Verificar que funciona

<ListCheck>

- `curl http://localhost/health` devuelve `200`
- El panel carga en `http://tu-ip`
- Has registrado tu usuario y creado un proyecto con su project token
- `docker compose ps` muestra los tres servicios como `running` o `healthy`

</ListCheck>

| Síntoma | Causa | Solución |
| --- | --- | --- |
| OTLP `401` vacío | Falta cabecera `Authorization: Bearer <project_token>` | Añade la cabecera con prefijo `Bearer` en cada exportador |
| No llegan datos (Python) | El SDK usa gRPC por defecto | Define `OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf` |
| `413` al exportar | Lote supera 10 MB | Limita `maxExportBatchSize` (512 spans es seguro) |
| `503` + `Retry-After` | Saturación de ingesta | Escala ClickHouse o el backend |
| Página de Logs vacía | Falta puente de logging | Conecta `LoggingHandler` (Python), `slog` (Go) o Monolog (PHP) |
| Sin datos del navegador | Snippet antiguo que carga `@tracewayapp/browser`, un paquete que no existe en npm | Instala `@tracewayapp/frontend@2` e inicializa con la cadena de conexión (ver el SDK de navegador más abajo) |

<Notice type="error" title="OTLP solo por HTTP, sin gRPC">
Es el error más común. Traceway no tiene endpoint gRPC. En Python define siempre <code>export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf</code>.
</Notice>

Monitoriza también el propio servidor con [Beszel y Uptime Kuma](/es/beszel-uptime-kuma/).

## Instrumentar Node.js, Python y Frontend (SDK 2.x)

### Node.js (Express con OTLP/HTTP y Bearer token)

```bash
mkdir traceway-demo && cd traceway-demo
npm init -y
npm install express @opentelemetry/api @opentelemetry/sdk-node \
  @opentelemetry/auto-instrumentations-node \
  @opentelemetry/exporter-trace-otlp-http \
  @opentelemetry/exporter-metrics-otlp-http \
  @opentelemetry/exporter-logs-otlp-http \
  @opentelemetry/sdk-metrics @opentelemetry/sdk-logs @opentelemetry/resources
```

Crea `telemetry.mjs`:

```javascript
import { register } from "node:module";
register("@opentelemetry/instrumentation/hook.mjs", import.meta.url);
import { NodeSDK } from "@opentelemetry/sdk-node";
import { OTLPTraceExporter } from "@opentelemetry/exporter-trace-otlp-http";
import { OTLPMetricExporter } from "@opentelemetry/exporter-metrics-otlp-http";
import { OTLPLogExporter } from "@opentelemetry/exporter-logs-otlp-http";
import { PeriodicExportingMetricReader } from "@opentelemetry/sdk-metrics";
import { BatchLogRecordProcessor } from "@opentelemetry/sdk-logs";
import { resourceFromAttributes } from "@opentelemetry/resources";
import { getNodeAutoInstrumentations } from "@opentelemetry/auto-instrumentations-node";

const BASE = "http://your-server-ip/api/otel";
const headers = { Authorization: "Bearer your-project-token" };

new NodeSDK({
  resource: resourceFromAttributes({ "service.name": "my-service" }),
  traceExporter: new OTLPTraceExporter({ url: `${BASE}/v1/traces`, headers }),
  metricReaders: [new PeriodicExportingMetricReader({
    exporter: new OTLPMetricExporter({ url: `${BASE}/v1/metrics`, headers }),
    exportIntervalMillis: 30000,
  })],
  logRecordProcessors: [new BatchLogRecordProcessor({
    exporter: new OTLPLogExporter({ url: `${BASE}/v1/logs`, headers }),
  })],
  instrumentations: [getNodeAutoInstrumentations()],
}).start();
```

Crea `index.js`:

```javascript
const express = require('express');
const app = express();

app.get('/', (req, res) => {
  res.json({ message: 'Traceway is watching' });
});

app.get('/slow', async (req, res) => {
  await new Promise(resolve => setTimeout(resolve, 2000));
  res.json({ message: 'This one took a while' });
});

app.listen(3000, () => console.log('App running on port 3000'));
```

Ejecuta con `node --import ./telemetry.mjs index.js`.

### Python (Flask)

```bash
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
pip install flask opentelemetry-instrumentation-flask opentelemetry-distro opentelemetry-exporter-otlp-proto-http
```

Configura `OTLPSpanExporter(endpoint="http://your-server-ip/api/otel/v1/traces", headers={"Authorization": "Bearer your-project-token"})` y mantén la variable `OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf` activa al arrancar.

### Frontend Session Replay (SDK 2.x)

El SDK 1.x (`@tracewayapp/frontend@1`, inicializado con `init(connectionString, options)`) sigue funcionando contra los servidores actuales, pero RUM y el nuevo modelo de replay requieren 2.x. La cadena de conexión no cambia: token de proyecto, `@` y una URL que termina en `/api/report`:

```html
<script src="https://cdn.jsdelivr.net/npm/@tracewayapp/frontend@2/dist/traceway.iife.global.js"></script>
<script>
  Traceway.init("your-project-token@https://your-server-ip/api/report");
</script>
```

Sube tus source maps desde CI con la CLI `traceway-sourcemaps`. Viene en su propio paquete y usa un token de subida dedicado (se genera en la página Connection del proyecto), no el project token:

```bash
npm install -D @tracewayapp/sourcemap-upload
npx traceway-sourcemaps --url https://your-server-ip --token your-upload-token --directory ./dist
```

## Checklist de endurecimiento para producción

<ListCheck>

- Configura HTTPS con un proxy inverso delante: [proxy inverso Traefik en Docker](/es/traefik-proxy-docker/), [certificado wildcard Let's Encrypt con Traefik](/es/traefik-certificado-wildcard/) o [CloudPanel como proxy para Docker y Dockge](/es/configurar-dockge-cloudpanel/).
- Usa un `JWT_SECRET` real (`openssl rand -hex 32`) y define `APP_BASE_URL` y `TRUSTED_PROXIES`.
- Pon el panel y la ingesta OTLP detrás del proxy inverso con HTTPS: la ingesta comparte el puerto 80 con el panel, así que no hay un puerto de ingesta aparte que restringir; protege los tokens de proyecto (recuerda [por qué Docker se salta tu firewall](/es/docker-evita-firewall/) y [cómo asegurar Docker con UFW](/es/informe-seguridad-bsi-docker-ufw/)).
- Haz copias de seguridad de las tres piezas: **ClickHouse**, **PostgreSQL** y **almacenamiento blob** (`traceway-storage` o S3).
- Activa automonitorización con `MONITORING_TRACEWAY_URL="<project_token>@https://tu-host"`.

</ListCheck>

Si ClickHouse llena el disco, amplía almacenamiento siguiendo [añadir un nuevo disco a Ubuntu LVM](/es/anadir-disco-lvm/).

## Actualizar Traceway (notas de migración 1.x a 2.x)

Dentro de 2.x basta con `docker compose pull && docker compose up -d`.

<Notice type="warning" title="V2.0 es una actualización incompatible">
Traceway 2.0 (2026-09-20) cambió las tablas de telemetría. Haz copia completa de ClickHouse, PostgreSQL y blob storage, detén los backends 1.x antes de arrancar 2.x y define <code>V2_MOVE_OVER=true</code> si quieres copiar historial a las nuevas tablas (detalles en la <a href="https://docs.tracewayapp.com/server/upgrade-v2-tables">guía oficial de migración</a>).
</Notice>

## Preguntas frecuentes

<Accordion label="¿Cómo se compara Traceway con Grafana + Loki + Tempo?" group="faq" expanded="true">
El stack de Grafana exige configurar y mantener cuatro sistemas separados. Traceway reúne logs, trazas, métricas, RUM, SLOs y on-call en un único Docker Compose. Si empiezas desde cero, ahorra horas de mantenimiento.
</Accordion>

<Accordion label="¿Puedo usar mi instrumentación OpenTelemetry existente?" group="faq">
Sí. Apunta el exportador a tu instancia de Traceway, añade la cabecera `Authorization: Bearer <project_token>` y asegúrate de usar HTTP (`OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf`).
</Accordion>

<Accordion label="¿Cuánto espacio en disco consume?" group="faq">
v2.0 ocupa algo más por las nuevas tablas de telemetría. Arranca con 20 GB para varios servicios y revisa el crecimiento real. Cuando necesites más espacio, [añade un disco nuevo en Ubuntu LVM](/es/anadir-disco-lvm/).
</Accordion>

<Accordion label="¿Soporta alertas y guardias?" group="faq">
Sí: Slack, GitHub Issues, correo, webhooks, Pushover, Telegram y guardias on-call con SMS y políticas de escalado.
</Accordion>

<Accordion label="¿Existe una versión cloud gestionada?" group="faq">
Sí, en cloud.tracewayapp.com con el mismo código MIT: plan Free (10k excepciones/mes, 1 GB ingesta, 3 proyectos) y Premium a 24,99 $/mes (1M excepciones, 150 GB ingesta, proyectos ilimitados). Sin cobros por host ni asiento.
</Accordion>

<Accordion label="¿Soporta Traceway gRPC?" group="faq">
No, solo OTLP sobre HTTP (`OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf`, o `http/json` en PHP).
</Accordion>

<Accordion label="¿Necesito un OpenTelemetry Collector?" group="faq">
No es obligatorio; tus SDKs pueden enviar directamente a `/api/otel/v1/traces`, `/metrics` y `/logs`.
</Accordion>
