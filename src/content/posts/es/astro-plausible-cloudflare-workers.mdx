[Plausible Analytics](https://plausible.io/) es una alternativa a Google Analytics de código abierto y centrada en la privacidad. Es ligera (script de menos de 1 KB), no usa cookies y no rastrea datos personales. Con más de 19.000 suscriptores de pago y 260.000 millones de páginas vistas registradas, es la herramienta de analítica centrada en la privacidad más popular entre los desarrolladores.

Puedes autoalojar Plausible en tus propios servidores. Consulta [Instalar Plausible con un clic](/es/instalar-plausible-analytics/) para una configuración rápida, o usa uno de los [mejores paneles de servidores autoalojados](/es/mejores-paneles-autoalojados/) para un despliegue sencillo.

[Astro](https://astro.build/) es un framework web construido para la velocidad, y ahora se ejecuta de forma nativa en Cloudflare. Puedes [desplegar tu sitio Astro en Cloudflare](/es/desplegar-astrojs-cloudflare/) o [crear un blog gratis con Astro y Cloudflare](/es/crear-blog-astro-gratis/) para empezar. Para un análisis más profundo de los frameworks disponibles, consulta la [comparativa Astro vs Next.js vs TanStack Start](/es/astro-vs-nextjs-vs-tanstack-start-cual-gana/).

## ¿Por qué hacer proxy de Plausible Analytics a través de Cloudflare Workers?

Los bloqueadores de anuncios y los navegadores centrados en la privacidad bloquean habitualmente las solicitudes a `plausible.io`. Esto puede hacerte perder entre el 20 y el 30 % de tus datos de analítica. Si usas herramientas como [NextDNS](https://go.bitdoze.com/nextdns) o bloqueadores de anuncios en el navegador en tus propios dispositivos, ya sabes lo agresivos que son bloqueando scripts de analítica.

Un proxy resuelve esto enrutando las solicitudes de Plausible a través de tu propio dominio. Para los navegadores de tus visitantes, el script de analítica parece parte de tu sitio, no un rastreador de terceros. Los bloqueadores de anuncios no pueden distinguirlo del tráfico normal del sitio.

<Notice type="info" title="Funciona con cualquier sitio estático">
Este enfoque de proxy funciona con cualquier generador de sitios estáticos o framework, no solo con Astro. Hugo, Next.js, Eleventy, HTML puro. Si puedes añadir una etiqueta script en el head, puedes usar esta configuración. El Cloudflare Worker se encarga del proxy independientemente de tu herramienta de build.
</Notice>

Para más información sobre cómo bloquear anuncios y rastreadores a nivel de DNS, consulta [cómo bloquear anuncios y rastreo con protección DNS](/es/bloquear-anuncios-malware-dns/).

## ¿Por qué usar Cloudflare Workers en lugar de redirecciones?

Si despliegas en Cloudflare Pages, podrías pensar que puedes usar el archivo `_redirects` para hacer proxy de las solicitudes de Plausible. No puedes. Cloudflare Pages solo admite redirecciones a rutas relativas. No puede hacer proxy hacia URLs externas.

Intentar añadir una redirección de proxy como esta fallará:

```sh
Found invalid redirect lines:
09:59:12.187	  - #1: /js/script.js https://domain.com/js/plausible.outbound-links.js 200
09:59:12.187	    Proxy (200) redirects can only point to relative paths. Got https://domain.com/js/plausible.outbound-links.js
09:59:12.187	  - #2: /api/event https://domain.com/api/event 200
09:59:12.187	    Proxy (200) redirects can only point to relative paths. Got https://domain.com/api/event
```

Los Cloudflare Workers no tienen esta limitación. Pueden hacer fetch a cualquier URL externa y devolver la respuesta, lo que los convierte en la herramienta adecuada para hacer proxy de Plausible en Cloudflare.

## Hacer proxy de Plausible a través de Cloudflare Workers (paso a paso)

Cloudflare Workers ofrece un plan gratuito con 100.000 solicitudes al día. Es más que suficiente para la mayoría de los sitios. Todo lo que necesitas es una cuenta gratuita de Cloudflare.

### Paso 2: Añade el código del Worker (ES Modules)

Haz clic en **Edit Code**, borra el código por defecto y sustitúyelo por el código de abajo.

<Notice type="info" title="La sintaxis de Service Worker está obsoleta">
Cloudflare ha marcado como obsoleta la sintaxis antigua `addEventListener('fetch', ...)`. El código de abajo usa el formato recomendado de ES Modules. Si actualizas desde una configuración anterior, reemplaza todo el script del worker.
</Notice>

<Tabs>
  <Tab name="Proxy en la nube (Plausible.io)">
    Usa esta versión si estás en el servicio cloud alojado de Plausible.

```js
// Sustituye 'pa-XXXXX.js' por el ID de script específico de tu sitio
// Lo encuentras en Plausible: Site Settings → General → Data Snippets
const ProxyScript = 'https://plausible.io/js/pa-XXXXX.js';
const ScriptPath = '/theone/script';
const Endpoint = '/theone/event';

export default {
  async fetch(request, env, ctx) {
    ctx.passThroughOnException();
    const url = new URL(request.url);
    const pathname = url.pathname;

    if (pathname.startsWith(ScriptPath)) {
      return getScript(request, ctx);
    } else if (pathname === Endpoint) {
      return postData(request);
    }

    return new Response(null, { status: 404 });
  }
}

async function getScript(request, ctx) {
  let response = await caches.default.match(request);
  if (!response) {
    response = await fetch(ProxyScript);
    ctx.waitUntil(caches.default.put(request, response.clone()));
  }
  return response;
}

async function postData(request) {
  const req = new Request(request);
  req.headers.delete('cookie');
  return await fetch('https://plausible.io/api/event', req);
}
```

Sustituye `pa-XXXXX.js` por el ID de script específico de tu sitio. Lo encuentras en tu panel de Plausible en **Site Settings → General → Data Snippets**. El segmento de ruta `theone` puede ser lo que quieras. Solo mantenlo igual en `ScriptPath` y `Endpoint`.

  </Tab>

<Notice type="info" title="Optimización de rendimiento (opcional)">
Puedes reducir la latencia del proxy de ~140 ms a ~9 ms devolviendo una respuesta 202 inmediata y reenviando el evento de forma asíncrona. En la función `postData`, sustituye el `return` final por `ctx.waitUntil(fetch(...))` y devuelve un `new Response('OK', { status: 202 })`. Nota: algunos usuarios han reportado problemas con el acceso al stream de la solicitud después de enviar la respuesta, así que pruébalo con cuidado.
</Notice>

Deberías ver código JavaScript como respuesta (el script de Plausible). Si obtienes un 404, comprueba que la variable `ScriptPath` de tu worker coincide con la ruta de URL que estás probando.

### Paso 4: Ejecuta el proxy como un subdirectorio

Ejecutar el proxy bajo un subdirectorio de tu dominio principal (p. ej., `example.com/theone/`) es mejor que usar un subdominio separado. Mantiene las solicitudes como first-party, lo que evita restricciones de cookies y se ve más limpio en los logs de red.

Para configurarlo, añade una ruta de Worker en la sección **Routes** de los ajustes de tu Worker:

**Route**: `*example.com/theone/*`

Sustituye `theone` por el segmento de ruta que elegiste en el código del worker. Selecciona tu dominio en el desplegable de zona.

### Paso 5: Añade el snippet de Plausible a tu sitio Astro

<Notice type="warning" title="El formato del snippet ha cambiado">
El antiguo formato `data-domain` / `data-api` está obsoleto. Plausible ahora usa un script específico por sitio (`pa-XXXXX.js`) con una llamada `plausible.init()` para el endpoint. Usa el formato de abajo.
</Notice>

Añade este snippet al `<head>` de tu sitio Astro. En Astro, puedes colocarlo en tu archivo de layout principal (p. ej., `src/layouts/Layout.astro`):

```html
<script async src="https://yourdomain.com/theone/pa-XXXXX.js"></script>
<script>
  window.plausible=window.plausible||function(){(plausible.q=plausible.q||[]).push(arguments)};
  plausible.init=plausible.init||function(i){plausible.o=i||{}};
  plausible.init({
    endpoint: "https://yourdomain.com/theone/event"
  })
</script>
```

Sustituye lo siguiente:
- **`yourdomain.com`**: el dominio real de tu sitio
- **`theone`**: la ruta del subdirectorio que configuraste en los pasos 2 y 4
- **`pa-XXXXX.js`**: el ID de script específico de tu sitio en Plausible (Site Settings → General → Data Snippets)

La URL de `endpoint` debe coincidir con la variable `Endpoint` de tu Worker, y el `src` del script debe coincidir con `ScriptPath`. La URL del script pasa por tu Worker (que sirve el script de Plausible en caché), y la URL del endpoint enruta los eventos de analítica a través de tu Worker hacia la API de Plausible.

Ya deberías tener Plausible Analytics funcionando a través de Cloudflare Workers, servido desde tu propio dominio.

## Solución de problemas comunes

<Accordion label="Los datos de analítica no aparecen" group="faq" expanded="true">
Abre las herramientas de desarrollo de tu navegador (pestaña Red) y recarga tu sitio. Busca solicitudes a tu ruta de subdirectorio (p. ej., `/theone/script` y `/theone/event`). Si la solicitud del script devuelve 200 pero la del evento falla, comprueba que la URL de `endpoint` de tu snippet coincide exactamente con la variable `Endpoint` del Worker. Si no aparece ninguna de las dos solicitudes, verifica que el snippet está en el `<head>` y que no lo bloquean las cabeceras Content-Security-Policy.
</Accordion>

<Accordion label="El Worker devuelve 404" group="faq">
Verifica que el patrón de ruta del Worker coincide con tu subdirectorio. La ruta debe ser `*example.com/theone/*` (fíjate en el `/*` final). Comprueba también que las variables `ScriptPath` y `Endpoint` del código del Worker coinciden con las rutas de tu snippet. Asegúrate de que el Worker está desplegado (no solo guardado como borrador).
</Accordion>

<Accordion label="Errores de CORS en la consola" group="faq">
Como el proxy se ejecuta en tu propio dominio, las solicitudes deberían ser same-origin y CORS no debería activarse. Si ves errores de CORS, lo más probable es que la ruta del Worker esté mal configurada. Puede que las solicitudes lleguen a Plausible directamente en lugar de pasar por el Worker. Revisa el patrón de ruta y asegúrate de que las URLs del snippet apuntan a tu dominio, no a `plausible.io`.
</Accordion>

<Accordion label="El panel de Plausible muestra 0 visitantes" group="faq">
Primero, verifica que estás mirando el sitio correcto en tu panel de Plausible. Si cambiaste recientemente al nuevo formato de snippet, asegúrate de que el antiguo snippet `data-domain` está completamente eliminado. Tener ambos puede causar conflictos. Comprueba también que tu propio navegador no esté bloqueando las solicitudes durante las pruebas (desactiva el bloqueador de anuncios para tu propio dominio).
</Accordion>

## Preguntas frecuentes

<Accordion label="¿Funciona esto con frameworks distintos de Astro?" group="faq" expanded="true">
Sí. El proxy con Cloudflare Worker es completamente agnóstico al framework. Funciona con cualquier generador de sitios estáticos (Hugo, Eleventy, Next.js, Gatsby) o incluso con HTML puro. El único requisito es poder añadir una etiqueta script en el `<head>` de tu sitio. El Worker se encarga de todo el proxy independientemente de lo que haya generado el HTML.
</Accordion>

<Accordion label="¿Qué es el Managed Proxy de Plausible?" group="faq">
El Managed Proxy de Plausible es una función exclusiva del plan Enterprise. En lugar de configurar y mantener tu propio Cloudflare Worker, añades un registro CNAME que apunta a la infraestructura de proxy de Plausible. Ellos se encargan del resto. Es una buena opción para equipos que quieren la ventaja del proxy sin gestionar Workers, pero requiere un plan Enterprise.
</Accordion>

<Accordion label="¿Cuánto tráfico admite el plan gratuito de Workers?" group="faq">
El plan gratuito de Cloudflare Workers permite 100.000 solicitudes al día. Como el script de Plausible queda en caché en el Worker, la mayoría de las páginas vistas solo cuentan como una solicitud (el POST del evento). Para un sitio con tráfico medio, 100.000 solicitudes se traducen en unas 80.000 a 100.000 páginas vistas al día. Eso cubre a la gran mayoría de los sitios. Si necesitas más, el plan de pago de Cloudflare ($5/mes) incluye 10 millones de solicitudes al mes.
</Accordion>

<Accordion label="¿Puedo usar Cloudflare Zaraz en su lugar?" group="faq">
Cloudflare Zaraz es un gestor de etiquetas que carga scripts de terceros a través de la infraestructura de Cloudflare. De momento, Plausible no está soportado oficialmente como integración de Zaraz. El enfoque de proxy con Worker descrito en este artículo sigue siendo la forma recomendada de hacer proxy de Plausible en Cloudflare. Si Zaraz añade soporte para Plausible en el futuro, podría simplificar la configuración.
</Accordion>
