Once you have [OpenClaw running on a VPS or Mac Mini](/clawdbot-setup-guide/), you start wanting visibility into what your agent is doing: which sessions are active, what it's spending on API calls, which scheduled jobs ran overnight. That's where OpenClaw dashboards come in.

Things changed a lot since early 2026. OpenClaw now ships an official Control UI served by the gateway itself, so the question is no longer "which dashboard?" but "do I need more than the built-in one?" Beyond the official UI, a handful of community command centers and monitors are still actively maintained, several older projects have gone dormant or been archived, and a few new entrants have jumped past the old favorites in stars. Here's the current state, checked against GitHub and the official docs in October 2026.

## Start here: the official OpenClaw Control UI

Before installing anything third-party, know that OpenClaw ships three interfaces: the CLI, a TUI, and the **Control UI**, a web dashboard served by the gateway on port 18789. If you're on a recent version, you already have a dashboard. No install, no extra process, no separate auth layer.

Launch it with:

```bash
openclaw dashboard                      # opens http://localhost:18789
```

### What the Control UI covers

The Control UI is a Vite + Solid single-page app that the gateway serves on the same port. It handles most day-to-day needs for a single-agent setup.

<ListCheck>
<ul>
<li>**Chat and sessions**: Talk to your agent, browse session history, see what's running</li>
<li>**Usage page**: Context meters and token breakdowns per session</li>
<li>**Tool activity**: Symbols showing which tools the agent called and when</li>
<li>**Plugin UI catalog**: Discover and configure plugin interfaces and MCP Apps</li>
<li>**Config editor**: Inspect and edit your OpenClaw config from the browser</li>
</ul>
</ListCheck>

Two config knobs matter for operators:

```bash
# optional: gateway.controlUi.enabled: false   # hot-applies, disables UI only
# optional: gateway.controlUi.basePath: "/openclaw"
```

Setting `OPENCLAW_CONFIG_READONLY=1` shows a clean read-only banner instead of an editable config, which is useful if you want the dashboard visible but config changes locked down. You can customize the banner text with `OPENCLAW_CONFIG_READONLY_NOTICE`.

**Verify it works**: run `openclaw dashboard`, open the Usage page, and confirm the session count matches what the `openclaw` CLI reports. **Failure mode:** dashboard won't load → gateway not running, `gateway.controlUi.enabled` set to `false`, or you're on an old OpenClaw version that predates the Control UI.

<Notice type="warning" title="Don't Expose 18789 Publicly">
The Control UI is served by the gateway, which means port 18789 carries both the API and the web UI. Never expose it directly to the internet. Bind behind Tailscale, an SSH tunnel, or a reverse proxy with auth. More on this in the [security section](#how-to-secure-any-openclaw-dashboard) below.
</Notice>

### When you need a third-party dashboard

The Control UI covers sessions, chat, usage meters, and config. It does not give you cost analytics with budget caps, kanban-based task orchestration pipelines, drag-and-drop widget grids, soul/identity editors, multi-machine fleet views, or terminal-style monitors. If any of those matter to you, the community projects below fill the gaps. If they don't, the Control UI plus the CLI is probably all you need.

## Autensa (Mission Control): best for autonomous task pipelines

<Button text="GitHub Repository" link="https://github.com/crshdn/mission-control" variant="solid" color="blue" size="md" />

Mission Control rebranded to **Autensa** and became something more ambitious than a kanban board. It's now an "Autonomous Product Engine" (v2.5.1, 2026-04-29) with a pipeline that runs Research → Ideation → Swipe-to-approve → Build → Test → Review → Pull Request. The old seven-stage kanban is gone. This is a full product development workflow with AI planning at each step.

Five things set it apart from everything else here:

<ListCheck>
<ul>
<li>**Product Autopilot**: Scheduled market research produces scored feature ideas; you swipe to approve, and agents pick up the work</li>
<li>**Convoy Mode**: Run 3 to 5 parallel agents with a DAG dependency graph, stall/zombie detection, auto-nudge, and crash-recovery checkpoints</li>
<li>**Per-task cost tracking with budget caps**: See exactly what each task spent, set hard limits before agents run wild</li>
<li>**Operator Chat**: Send notes and mid-build messages to agents without breaking their context</li>
<li>**SQLite storage, WebSocket dispatch**: No external database; tasks dispatch to agents in real time over the gateway</li>
</ul>
</ListCheck>

There's a [live demo](https://missioncontrol.ghray.com) if you want to poke around before installing.

```bash
git clone https://github.com/crshdn/mission-control.git
cd mission-control
npm install
cp .env.example .env.local
# Set OPENCLAW_GATEWAY_URL and OPENCLAW_GATEWAY_TOKEN in .env.local
# Get the token: openclaw config get gateway.auth.token
npm run dev
```

Open `http://localhost:4000`.

**Verify**: create a test task and confirm it spawns an agent session that appears in the live event feed. **Failure mode:** missing or invalid `OPENCLAW_GATEWAY_TOKEN` → WebSocket connect fails and tasks queue without dispatching.

<Notice type="warning" title="Name Collision">
Searching "OpenClaw mission control" hits an archived 4,100-star repo (`abhi1693/openclaw-mission-control`) that is no longer maintained. The active project is `crshdn/mission-control` (Autensa). See the [warning section](#warning-some-openclaw-mission-control-results-are-archived) for details.
</Notice>

**Cost note**: Autopilot and Convoy Mode spawn agents on schedules. That's real token spend even when idle. Enable budget caps on day one and consider pairing with a [cheaper model](/best-opensource-models-for-openclaw/) once you know the workflow.

## OpenClaw Studio: best clean web dashboard

<Button text="GitHub Repository" link="https://github.com/grp06/openclaw-studio" variant="solid" color="green" size="md" />

OpenClaw Studio is a clean, official-adjacent web UI (2,033 ⭐) with chat, approvals, job/cron configuration, and an agent overview. It connects to the gateway over WebSocket and its docs are the best source for the three real deployment topologies you'll encounter.

```bash
npx -y openclaw-studio@latest           # Node 20.9+ required
# Opens http://localhost:3000, connects to ws://localhost:18789
```

**Verify**: open `http://localhost:3000`, confirm the gateway status indicator shows connected, and send a test chat message. **Failure mode:** Node < 20.9 (npx refuses to run), upstream URL typo (`ws://` vs `wss://` when TLS is in the path), or Tailscale not running on the gateway host.

The three topologies:

<Tabs>
<Tab name="Local / Local">

Both the gateway and Studio on the same box. This is the default and simplest setup. Studio connects to `ws://localhost:18789` and everything stays on one machine. No extra networking.

</Tab>
<Tab name="Cloud Gateway + Local Studio">

Gateway runs on a VPS; Studio runs on your laptop. Expose the gateway over Tailscale on the server side:

```bash
# on the gateway host
tailscale serve --yes --bg --https 443 http://127.0.0.1:18789
```

Then point Studio's upstream at `wss://<gateway-host>.ts.net` instead of `ws://localhost:18789`. If you want to [self-host your Tailscale control server with Headscale](/headscale-self-hosted-tailscale-setup/), the pattern is identical.

</Tab>
<Tab name="Cloud / Cloud">

Both gateway and Studio on a VPS. Same as local/local but behind Tailscale or a reverse proxy for remote access. Studio must reach the gateway over `ws://` (plain) on the same host or `wss://` over TLS. Mixing the two is the most common config error.

</Tab>
</Tabs>

For the full topology comparison including `wss://` details, the project's docs are worth reading. If you're deciding between mesh VPN options, see the [Tailscale vs Headscale vs NetBird comparison](/netbird-vs-headscale-vs-tailscale/).

## AI Maestro: best OpenClaw command center for multi-machine fleets

<Button text="GitHub Repository" link="https://github.com/23blocks-OS/ai-maestro" variant="solid" color="purple" size="md" />

AI Maestro started as a fix for running 35 agents across multiple terminals and having to relay context between them by hand. It has grown into a full multi-agent operating system (v0.106.29, 839 ⭐, very active, pushed 2026-10-30) built around a peer mesh where machines join as equal nodes and every agent is visible from one dashboard.

<ListCheck>
<ul>
<li>**Multi-machine mesh**: No central server; machines connect as peers and new computers join automatically</li>
<li>**Agent Messaging Protocol (AMP)**: Agents coordinate directly with priority levels and cryptographic signatures</li>
<li>**Approval cards**: Review and approve agent actions from the dashboard before they execute</li>
<li>**Matrix board**: Eisenhower-style priority view for task management across the fleet</li>
<li>**Masked Secrets cards**: Agents use credentials by name without ever seeing the actual values</li>
<li>**Works with any agent**: Full support for Claude Code, Codex, and Grok Build; launch-only for Pi, OpenClaw, and GitHub Copilot CLI</li>
</ul>
</ListCheck>

```bash
curl -fsSL https://raw.githubusercontent.com/23blocks-OS/ai-maestro/main/scripts/remote-install.sh | sh
```

Dashboard opens at `http://localhost:23000`. Requires Node.js 18+ and tmux.

**Verify**: after install, confirm a second machine can join the mesh and both appear in the fleet view. **Failure mode:** tmux missing on a fresh VPS (`apt install tmux` or `dnf install tmux` first); curl-pipe-to-sh blocked by a corporate proxy: download the script manually and inspect it.

**Cost note**: fleet-scale agent coordination burns tokens even at idle, and usage scales with fleet size. Pair AI Maestro with a cost-tracking dashboard and consider [cheaper model subscriptions via OpenCode Go vs ClinePass](/opencode-go-vs-clinepass-cheap-models/) to keep the bill sane. The mobile-friendly pages also mean you can [control AI agents from your phone](/control-ai-agents-from-phone-moshi-herdr/) when you're away from the desk.

**When to use it**: If you're running 10+ agents and need them to coordinate without you acting as the go-between. Overkill for a single-agent setup.

## OpenClaw Agent Dashboard: best security-hardened monitor

<Button text="GitHub Repository" link="https://github.com/tugcantopaloglu/openclaw-dashboard" variant="solid" color="blue" size="md" />

This project jumped from 60 to 700 stars in eight months. It's the most security-conscious dashboard on the list: PBKDF2 password hashing (100,000 iterations), optional TOTP MFA (Google Authenticator, Authy, 1Password compatible), rate limiting, HSTS, CSP headers, path traversal protection, and a full audit log, all with zero external dependencies. Pure Node.js, no database, no framework.

Beyond security, the feature list has grown since early 2026: session management, cost analysis, rate limit monitoring, memory file viewer (MEMORY.md, HEARTBEAT.md, daily notes), cron job management, Tailscale integration, and a live feed of agent messages. New additions include a Files Manager, Service Control, Log Viewer, a 30-day activity heatmap with streaks, and keyboard shortcuts.

<ListCheck>
<ul>
<li>**TOTP MFA**: Optional two-factor auth, enabled from Settings → Security</li>
<li>**Zero dependencies**: Pure Node.js with no npm packages required</li>
<li>**Cost analysis**: Spending breakdowns by model, session, and time period</li>
<li>**Memory viewer**: Browse MEMORY.md, HEARTBEAT.md, and daily memory notes</li>
<li>**Cron management**: View, enable/disable, and manually trigger scheduled jobs</li>
<li>**Files Manager & Log Viewer**: Browse workspace files and gateway logs from the UI</li>
</ul>
</ListCheck>

```bash
git clone https://github.com/tugcantopaloglu/openclaw-dashboard.git
cd openclaw-dashboard
node server.js
```

Visit `http://localhost:7000` and register an account on first launch.

<Notice type="info" title="Security Setup">
The first time you run it, a recovery token prints to the console. Save it. You'll need it if you forget your password. To enable MFA, go to Settings → Security → Enable MFA after logging in. The full auth model is described in the [OpenClaw security guide](/openclaw-security-guide/).
</Notice>

**Verify**: register, save the recovery token, then check that cost analysis shows the current day's spend and the cron list matches your scheduled jobs. **Failure mode:** forgot to save the recovery token → it is your only password reset path; port 7000 already in use → change the port or kill the conflicting process.

## LobsterBoard: best drag-and-drop dashboard builder

<Button text="GitHub Repository" link="https://github.com/Curbob/LobsterBoard" variant="solid" color="green" size="md" />

LobsterBoard takes a different approach from everything else on this list. Instead of a fixed layout, it's a drag-and-drop dashboard builder with 60+ widgets. System stats, weather, RSS feeds, stock tickers, Claude API cost tracking, active session monitors, smart home sensors. Pick what matters and arrange it however you want. Five themes ship out of the box: Default, Terminal CRT, Paper, Feminine, and Feminine Dark.

It runs as a single Node.js server with no framework and no build step. Config saves to a single JSON file. Everything runs locally, with no cloud dependency.

<ListCheck>
<ul>
<li>**60+ widgets**: System monitoring, AI cost tracking, smart home, finance, media, and more</li>
<li>**5 themes**: Including a Terminal CRT mode and a Paper theme</li>
<li>**Remote server monitoring**: Install `lobsterboard-agent` on other VPS boxes to pull their stats into your grid</li>

## Claw Dashboard: best terminal-style monitor

<Button text="GitHub Repository" link="https://github.com/spleck/claw-dashboard" variant="solid" color="green" size="md" />

If you live in the terminal and want something that looks like btop or htop rather than a web app, Claw Dashboard is the one. ASCII art logo, gradient colors, donut charts, progress bars, all rendered with the `blessed` library and refreshed every two seconds. It shows per-core CPU usage, memory gauges, GPU stats (Apple Silicon only), top processes, and active OpenClaw sessions.

The project is active (pushed 2026-10-26, npm 2.2.0) and has picked up quality-of-life features: a command palette (`Ctrl+K`), widget reorder (`w`), pinning (`Alt+1-9`), snapshots, and export scheduling.

```bash
npx claw-dashboard                      # one-shot, no global install
# or: npm install -g claw-dashboard && clawdash
```

Keyboard controls: `q` to quit, `r` to refresh, `s` for settings, `Ctrl+K` for the command palette.

**Verify**: `clawdash` renders and the session list matches the gateway. **Failure mode:** Node < 22 is a hard requirement. That's the most likely install failure on older VPS images. Check with `node --version`. GPU stats only appear on Apple Silicon; on Linux you'll get CPU/memory/processes but no GPU gauge. For SSH workflows where you'd rather have a persistent terminal session, the [best terminal multiplexers](/best-terminal-multiplexers/) guide covers tmux and Zellij alternatives.

**Best for**: Quick monitoring without opening a browser. Works great on a [Mac Mini](/best-mac-mini-for-openclaw/) where you're SSH'd in anyway.

## VidClaw: task board and soul editor

<Button text="GitHub Repository" link="https://github.com/madrzak/vidclaw" variant="solid" color="purple" size="md" />

VidClaw focuses on what your agent is working on rather than the infrastructure around it. It has a Kanban board where tasks get assigned to OpenClaw skills, a soul editor for SOUL.md, IDENTITY.md, and USER.md with persona templates and version history, and usage tracking parsed directly from session transcripts. Model switching from the dashboard hot-reloads via a config watcher.

The security model is the simplest on this list: it binds to localhost only. You access it over an SSH tunnel. SSH is the auth layer.

```bash
cd ~/.openclaw/workspace
git clone https://github.com/madrzak/vidclaw.git dashboard
cd dashboard
./setup.sh
```

Access over an SSH tunnel: `ssh -L 3333:localhost:3333 root@your-server`, then open `http://localhost:3333`. The [OpenClaw security guide](/openclaw-security-guide/) covers the tunnel pattern in more detail.

**Verify**: open the tunneled URL and confirm transcript-derived usage numbers match a known session. **Failure mode:** running setup from the wrong directory: it must live under `~/.openclaw/workspace`.

<Notice type="warning" title="Maintenance & License">
VidClaw has been stalled since March 2026 (last push 2026-03-18). It also has **no license file**. Default copyright applies, which technically means no reuse rights. For personal self-hosted use this rarely matters in practice, but know what you're getting into. The kanban and soul editor work fine as-is; just don't expect updates.
</Notice>

## Do you even need a third-party dashboard?

For most single-agent setups: no. The `openclaw dashboard` Control UI plus the `openclaw` CLI and the official TUI cover sessions, chat, usage, config, and basic monitoring. That's roughly 80% of what people look at.

Third-party dashboards earn their keep for specific gaps: cost analytics with budget caps, task orchestration pipelines (kanban → PR), drag-and-drop widget grids, soul/identity editors, multi-machine fleet views, and terminal-style monitors. If you don't hit any of those, try the free official UI for a week before installing anything.

## How to secure any OpenClaw dashboard

Every dashboard on this page connects to the same thing: your OpenClaw gateway. If the gateway or the dashboard port is exposed to the internet, you've handed over your agent. Here's the consolidated picture.

**Which dashboards have auth:**

- OpenClaw Agent Dashboard has TOTP MFA with PBKDF2 password hashing, rate limiting, and an audit log.
- Autensa (Mission Control) has bearer token auth, Zod validation, and path traversal protection.
- Clawd Control generates a password on first run.
- VidClaw binds to localhost only, so the SSH tunnel is the auth.
- The Control UI is authorized by the gateway on every request and honors `OPENCLAW_CONFIG_READONLY=1`.
- Assume anything not listed has none. The old Clawtrol had no auth at all.

**The standard pattern for all of them:**

<Notice type="warning" title="Never Expose These Ports">
Never raw-expose these ports to the public internet: **3000, 3100, 3333, 4000, 4781, 7000, 7001, 8080, 18789**. Bind to localhost and reach the dashboard through an SSH tunnel or `tailscale serve`. If you need a reverse proxy instead, the [SSH, Caddy, and Docker dashboard setup with security](/hermes-dashboard-guide/) guide covers the same pattern for any dashboard.
</Notice>

The topology you want:

```
  [ VPS ]                                [ Your laptop / phone ]
  ┌─────────────────────────┐            ┌──────────────────────┐
  │ OpenClaw Gateway :18789 │◄──mesh────►│ Browser / terminal   │
  │   (Control UI)          │  VPN or    │                      │
  │ Dashboard :3000/:7000   │  SSH       │ ssh -L 7000:...      │
  │ Dashboard :8080/:23000  │  tunnel    │ tailscale serve      │
  │ All bound to 127.0.0.1  │            └──────────────────────┘
  └─────────────────────────┘
       ✗ No direct public internet access
```

<ListCheck>
<ul>
<li>**Bind localhost**: don't change the default bind to 0.0.0.0 just to "make it work remotely"</li>
<li>**Tunnel or mesh VPN**: SSH tunnel or `tailscale serve` for access; [Tailscale vs Headscale vs NetBird comparison](/netbird-vs-headscale-vs-tailscale/) if you need to pick one</li>
<li>**Auth enabled**: TOTP MFA where available; don't rely on "nobody knows the port"</li>
<li>**Token rotated**: `openclaw config get gateway.auth.token` to check; rotate it if it's ever been pasted into a chat or repo</li>
<li>**Host patched**: [secure your VPS with CrowdSec](/crowdsec-secure-server/) and keep the box updated; if you want to [self-host your Tailscale control server with Headscale](/headscale-self-hosted-tailscale-setup/), that's one less third party in the path</li>
</ul>
</ListCheck>

**Common failure**: "it works on my laptop but not remotely". The bind is localhost, which is correct behavior. Use a tunnel; don't change the bind. And if you test with a public bind temporarily, immediately re-close the firewall rule.

## Pairing your dashboard with the right setup

A dashboard is only as useful as what it's monitoring. A few things are worth sorting before you install one.

If you're watching costs, an efficient model matters more than the dashboard UI. The [best open source models for OpenClaw](/best-opensource-models-for-openclaw/) guide covers [GLM-5](https://go.bitdoze.com/glm) and [MiniMax M2.5](https://go.bitdoze.com/minimax), which together cost a fraction of Claude API. Most dashboards make the cost difference obvious once you switch. For the API-side story, [cheap model subscriptions via OpenCode Go vs ClinePass](/opencode-go-vs-clinepass-cheap-models/) shows how to keep token bills low across tools.

Before installing any dashboard that connects to your gateway, make sure your instance is locked down. The [OpenClaw security guide](/openclaw-security-guide/) covers CVE-2026-25253, the ClawHub supply chain attack, and step-by-step hardening procedures.

Several dashboards show active tool calls in real time, which makes search integration worth setting up. The [DuckDuckGo OpenClaw search guide](/duckduckgo-openclaw-search/) walks through adding free web search with no API key.

If you're evaluating dashboards as part of deciding which agent platform to use, the [OpenClaw alternatives](/openclaw-alternatives/) roundup covers NanoClaw, IronClaw, NullClaw, and others that bring their own dashboard approaches. For NanoClaw's container-based approach, see the [NanoClaw deploy guide](/nanoclaw-deploy-guide/). For the smallest possible footprint with a Zig binary, see the [NullClaw deploy guide](/nullclaw-deploy-guide/).

If you haven't installed OpenClaw yet, the [OpenClaw setup guide](/clawdbot-setup-guide/) covers the full installation on a [Hetzner Cloud VPS](https://go.bitdoze.com/hetzner) or Mac Mini, including the gateway token most of these dashboards need. On a budget, a [Hostinger KVM VPS](https://go.bitdoze.com/hostinger-vps) runs the dashboard tier fine. The agents are the cost, not the UI. Still choosing the hardware? See the [best Mac mini for OpenClaw](/best-mac-mini-for-openclaw/).

For giving your OpenClaw agents persistent memory across sessions, [Hindsight](/hindsight-docker-deploy/) has a direct integration with server-side access control and auto-managed embeddings. It's a step up from the basic file-based memory most agents ship with.

<Notice type="info" title="Cost Note">
Dashboards that spawn agents (Autensa's Autopilot, AI Maestro's fleet coordination) burn tokens even at idle. Set budget caps before you enable autonomous modes. For local models that cost nothing per token, see [running OpenClaw with Ollama](/openclaw-ollama-local-models/).
</Notice>

<Accordion label="Frequently Asked Questions" group="faq" expanded="true">

**Are any OpenClaw dashboards official?**

Yes. The Control UI (`openclaw dashboard`, port 18789) and the TUI are both official. They ship with OpenClaw itself. Everything else in this list is community-built. The official interfaces are the right starting point for most people.

**Is OpenClaw Mission Control still maintained?**

The one by crshdn is. It rebranded to **Autensa** and is actively developed (v2.5.1, 2,155 ⭐). But the 4,100-star `abhi1693/openclaw-mission-control` is **archived** (August 2026), and development moved to Wardn AI, a different product. If you search "OpenClaw mission control" and hit the archived repo, don't install it.

**What's the best OpenClaw dashboard for cost tracking?**

OpenClaw Agent Dashboard has built-in cost analysis with breakdowns by model, session, and time period. Autensa goes further with per-task cost tracking and budget caps. If costs are your main concern, the dashboard matters less than the model. See the [best open source models for OpenClaw](/best-opensource-models-for-openclaw/).

**Can I run two dashboards at once?**

Yes. A common pairing is Autensa for task creation alongside Claw Dashboard for quick system checks. They read different parts of the OpenClaw gateway independently. The Control UI can stay on alongside any of them without conflicts. Just keep everything behind the same tunnel or mesh VPN.

**Is LobsterBoard free for commercial use?**

No. Business Source License 1.1 (the README's license; GitHub's field says "Other") permits personal and non-commercial self-hosting. Commercial deployments need a separate license from the author. Note that several projects here are not MIT: Clawe is AGPL-3.0, VidClaw has no license at all.

**Which dashboard should I try first?**

The Control UI. It's already installed. If you need cost analysis or cron monitoring, add OpenClaw Agent Dashboard next. For task orchestration and autonomous workflows, Autensa. For multi-machine fleets, AI Maestro. In that order.

**Which works on a Mac Mini?**

Claw Dashboard is the best terminal option. It even shows GPU stats on Apple Silicon. The Control UI over Tailscale works for web access. For the remote-screen niche that Clawtrol used to fill, look at openclaw-nerve (verify its README first) or just use VNC over Tailscale. Hardware details are in the [best Mac mini for OpenClaw](/best-mac-mini-for-openclaw/) guide. If you'd rather run an x86 box like the [ASUS DC510 mini PC](https://go.bitdoze.com/asus-dc510) instead of a Mac Mini, the dashboard options are the same minus the Apple Silicon GPU stats.

</Accordion>

The official Control UI changed the default question from "which dashboard?" to "do I need more than the built-in one?" For most single-agent setups, the answer is no. But once costs need budget caps, tasks need orchestration pipelines, or agents spread across machines, the community tools earn their keep. Start with whatever fits your scale; most run alongside each other without conflicts.
