The first thing people notice when they open Fish Shell is the autocomplete: you start typing and gray text appears after your cursor, predicting what you want. It feels like the shell reads your mind. Compared to [Bash or Zsh](/fish-shell-vs-bash-vs-zsh/), where you need plugins for anything like this, Fish does it from a fresh install. This guide covers both halves of Fish Shell autocomplete: autosuggestions (the gray inline predictions) and tab completions (the pager menu that appears when you press Tab), and how to configure and extend them.

<Notice type="info" title="Written against fish 4.9.x">
Fish 4.0 rewrote the shell in Rust (February 2025) and the completion internals have shifted repeatedly since then. This guide targets fish 4.9.3 (September 2026). If you're on Ubuntu 24.04, plain `apt install fish` gives you 3.7.x. See the prerequisites below before trying anything here.
</Notice>

## Fish Shell autosuggestions: how they work

Autosuggestions are the grayed-out text that appears as you type. Fish pulls these from three sources: your command history, available completions (command names, options), and valid file paths. In practice, history matches are usually what you see first: the more you use a command, the faster it shows up as a suggestion. Autosuggestions work alongside [Fish Shell syntax highlighting](/fish-shell-syntax-highlighting/), which colors the command line in real time to validate what you're typing.

### How to accept autosuggestions

| Key | Action |
|---|---|
| **→** or **Ctrl+F** | Accept the full suggestion |
| **Alt+→** or **Alt+F** | Accept the first word of the suggestion (press repeatedly for more) |
| **Ctrl+←** / **Ctrl+→** | Accept one token at a time |
| **Shift+←** / **Shift+→** | Accept one "big word" (stops at word boundaries, not punctuation) |
| **Shift+Delete** | Delete the displayed suggestion from history (fish 4.0+) |
| Keep typing | Ignore the suggestion entirely |

Accepting word by word is useful when the suggestion is close but not exactly right. If Fish suggests `git commit -m "fix auth bug"` and you want `git commit -m "fix login flow"`, press Alt+→ three times to accept `git commit -m` and then type your own message.

<Notice type="success" title="One binding worth learning">
Shift+Delete removes the currently-displayed suggestion from history. This is the practical fix for "Fish keeps suggesting that one long command I ran once and will never run again." During up-arrow history search, Shift+Delete deletes the current entry.
</Notice>

### How Fish ranks suggestions

Fish picks suggestions from command history, completions, and valid file paths. The docs don't state an exact priority order, but in practice history matches are what you see first, most recent first. If you've run `docker compose up -d` twenty times this week, typing `do` will almost certainly suggest that full command. Multi-line history entries also feed suggestions (fish 4.1+): individual lines from multi-line commands can appear as suggestions.

For managing what's in your history (searching, deleting entries, syncing across machines), see [Fish Shell history: search, delete and sync](/fish-shell-history-persistence/).

### Disabling autosuggestions

Some people find them distracting. Turn them off:

```fish
set -g fish_autosuggestion_enabled 0
```

Add that to `~/.config/fish/config.fish` to make it permanent. Remove the line to bring suggestions back.

## Fish Shell tab completion

Press Tab and Fish shows possible completions in a pager menu below your command line. Each completion comes with a description, so you can see what `-v` does before you run it.

### Navigating the completion menu

| Key | Action |
|---|---|
| **Tab** | Open completions, or cycle forward through them |
| **Shift+Tab** | From the command line, completes the current token and opens the pager's search mode; once the pager is open, cycles backward |
| **Arrow keys** / **PageUp** / **PageDown** | Navigate the completion list |
| **Enter** | Accept the highlighted completion |
| **Ctrl+S** | Open a search prompt within the completion menu (useful when there are many results) |

Since fish 4.2, mouse support works too: clicking moves the cursor and selects pager items.

### Where Fish completions come from

Fish looks for completions in a specific order. The first match wins: user completions shadow system ones.

The lookup order (`$fish_complete_path`):

1. `~/.config/fish/completions/`: user completions (your custom files go here)
2. `/etc/fish/completions/`: sysadmin completions (system-wide, not in home)
3. `~/.local/share/fish/vendor_completions.d/`: third-party completions (user)
4. `/usr/share/fish/vendor_completions.d/`: third-party completions (system; note: `vendor_completions.d`, not `completions/`)
5. Completions shipped with fish: **embedded in the fish binary** since fish 4.2; list them with `status list-files`
6. Man-page-generated completions: cached in `~/.cache/fish/generated_completions/` (moved from `~/.local/share/fish` in fish 4.0)

Fish generates completions from man pages in a background job and caches the results. The built-in completions for `git`, `docker`, `ssh`, `systemctl`, `apt`, `brew`, `npm`, and hundreds of other commands ship inside the fish program itself. Since fish 4.8, they're no longer installed as files under `$PREFIX/share/fish` (only `share/fish/man` is still there).

### Controlling file completion

<Notice type="warning" title="Alt+E and Alt+O do not complete files">
In current fish, Alt+E (and Alt+V) opens the command line in `$VISUAL`/`$EDITOR`, and Alt+O opens the file at the cursor in a pager. There is no default key binding that forces file completion. The real controls are in the completion definition itself.
</Notice>

File completion is offered by default in addition to your completions. You control it per command or per option:

```fish
# kill file completions for the whole command
complete -c myprog -f

# kill file completions for one option
complete -c myprog -s o -l output --no-files -ra "yes no"

# re-enable file completions for one option
complete -c myprog -l config-file --force-files -r

# -x = --exclusive = -r -f combined (takes a value, no file completions)
complete -c git-wrapper -x
```

Since fish 4.9, a wrapping command's `--no-files`/`--force-files` takes precedence over the wrapped command's settings, which is useful when you're aliasing or wrapping tools that have their own completion rules.

### Completion performance & fish_update_completions

Man-page completions are generated in a background job and cached in `~/.cache/fish/generated_completions/`. If you install new programs and their completions don't appear, force a full sweep:

```fish
fish_update_completions
```

This parses the man pages installed on your system and creates completion files. It never overwrites custom completions you've written. Runtime depends on how many man pages are installed. On a minimal VPS it's fast; on a full desktop it can take noticeably longer. Fish is free software, so the only cost here is background CPU during the man-page sweep.

Fish 4.7 fixed a groff escape-handling bug that affected completions generated from help2man 1.50+ and coreutils 9.10 pages. Fish 4.9 fixed slow tab completion on directories with slow symlink resolution (network mounts, NFS). If you work over SSH against NFS home directories, upgrade to 4.9.x.

### Case sensitivity

Tab completion in Fish is smart-case by default: type `doc` and it matches both `Documents/` and `docker`. Since fish 4.3, an uppercase prefix no longer hides lowercase matches: typing `DOC` still completes `Documents/`, and typing the exact case inserts that case. (Earlier versions switched to strict case-sensitivity when you typed an uppercase letter; that behavior changed in 4.3.0.)

## Writing custom completions in Fish

This is where Fish's completion system gets useful. You can add completions for your own scripts, internal tools, or commands that don't have good completions yet. The conditional helpers and functions that power this build on [Fish Shell functions and custom commands](/fish-shell-functions-custom-commands/).

Completion files go in `~/.config/fish/completions/` and are named after the command: `mycommand.fish` for the command `mycommand`.

### Basic example

Say you have a script called `deploy` that takes subcommands `staging`, `production`, and `rollback`:

```fish
# ~/.config/fish/completions/deploy.fish

# deploy takes no file arguments
complete -c deploy -f

# subcommands: only shown before a subcommand is typed
complete -c deploy -n "not __fish_seen_subcommand_from staging production rollback" \
    -a "staging production rollback" -d "Deployment target"

# flags
complete -c deploy -s v -l verbose -d "Verbose output"
complete -c deploy -s d -l dry-run -x -d "Show what would happen"
complete -c deploy -l env -r -a "staging production" -d "Environment"
```

A few details about the `complete` syntax:

- **`-r` / `--require-parameter`**: marks an option as taking a value. Without it, `deploy --env <TAB>` won't offer candidates; only `--env=val` (attached form) works. Always add `-r` to options that take arguments.
- **`-x` / `--exclusive`**: shorthand for `-r -f`: takes a value and suppresses file completions. This is the most common idiom for options like `--dry-run` that shouldn't trigger file completion.
- **`-o` / `--old-option`**: handles single-dash long options (e.g. `-output` instead of `--output`).
- **`-k` / `--keep-order`**: preserves the order of candidates instead of sorting alphabetically.

Now `deploy` followed by Tab shows your three subcommands, and `deploy --` shows the flags.

### Context-aware completions

Completions can be conditional. Use `-n` (condition) to show certain completions only in certain contexts:

```fish
# Only show these when no subcommand has been given yet
complete -c deploy -n "not __fish_seen_subcommand_from staging production rollback" \
    -a "staging production rollback"

# Only show branch names after "deploy staging"
complete -c deploy -n "__fish_seen_subcommand_from staging" \
    -a "(git branch --format='%(refname:short)')" -d "Git branch"
```

The `__fish_seen_subcommand_from` helper checks whether any of the given words have appeared in the command line. Fish ships with several helper functions like this. Look through `status list-files` or the [official timedatectl example](https://fishshell.com/docs/current/completions.html) for a real-world pattern.

Useful bundled helpers: `__fish_complete_directories`, `__fish_complete_path`, `__fish_complete_pids`, `__fish_complete_users`, `__fish_complete_groups`, `__fish_complete_suffix` (pairs with `--keep-order`), `__fish_print_hostnames`, `__fish_print_interfaces`, `__fish_print_filesystems`.

### Completions with dynamic data

The `-a` flag accepts command substitutions. The command inside `()` runs every time you press Tab, so completions stay up to date. Each line of output becomes one candidate:

```fish
# Complete running Docker container names
complete -c myapp -l container \
    -a "(docker ps --format '{{.Names}}')" \
    -d "Container name"

# Complete from a config file
complete -c myapp -l profile \
    -a "(cat ~/.myapp/profiles | string split \\n)" \
    -d "Config profile"
```

Anything after a **tab** character in a candidate line becomes the description shown in the pager. Use `string join \t` to build candidates with inline descriptions:

```fish
complete -c myapp -l env \
    -a "(string join \t staging 'Staging environment' production 'Production environment')" \
    -d "Environment"
```

### Completions for aliases and wrappers

If you alias or wrap a command, you can make the wrapper inherit the original's completions with `--wraps` (or `-w`):

```fish
# gco inherits all of git's completions
complete -c gco -w git
```

This is the single biggest time-saver in Fish's completion system. Your `gco`, `gc`, `gcb` aliases get full git completions for free.

Fish 4.0 also detects cursor-sync editors through `--wraps` (e.g. `complete --wraps my-vim vim`), so wrapped editors keep their completion behavior.

For the difference between aliases and abbreviations, and when to use each, see [Fish Shell abbreviations vs aliases](/fish-shell-abbreviations-vs-aliases/). Abbreviations (`abbr -a gco git checkout`) expand before running, so they don't need completions at all. Since fish 4.9, abbreviations can carry descriptions shown in the completion pager. Ctrl+Space types the literal abbreviation without expanding.

### Verify completions without pressing Tab

<Notice type="success" title="Verify it works">
`complete -C` prints what the completion pager would offer without touching the pager. Use it to test your completion files from scripts, CI, or just a quick terminal check.
</Notice>

```fish
complete -C "deploy "         # what Tab would offer after "deploy "
complete -C "deploy --"       # flag completions
complete -C "deploy staging " # context-dependent completions
```

This works in scripts and CI too, which makes it a regression test for completion files. If you change a completion and want to confirm it still works, pipe `complete -C` through `grep`.

A few extras:
- `complete -C"foo " >/dev/null` forces a completion file to load (fish 4.1+), useful when you've just written one and don't want to restart the shell.
- `complete --escape` escapes special characters in `-C` output.

### Removing or overriding completions

To erase all completion definitions for a command:

```fish
complete -e deploy
```

Since fish 4.0, `complete -e` also prevents autoloading. Use it when a broken or stale completion file keeps loading from `~/.config/fish/completions/`.

To override a system completion without deleting it, drop a same-named file in a directory that comes earlier in `$fish_complete_path`. Since `~/.config/fish/completions/` is first in the lookup order, a file there shadows anything from vendor or system paths.

## What changed in Fish 4.x

If you wrote completions or tuned your config before fish 4.0, here's what changed:

<ListCheck>
<ul>
<li><strong>Shift+Delete</strong> (4.0) removes the displayed autosuggestion from history</li>
<li><strong>Dotfile completion</strong> (4.0): scripted completions can offer dot-prefixed results (e.g. `git add .gitignore`); plain file completion hides dotfiles unless the token starts with `.`</li>
<li><strong>Fuzzy option matching</strong> (4.0): `--fb` completes `--foobar` via subsequence filtering</li>
<li><strong>Multi-line autosuggestions</strong> (4.1): suggestions work on multi-line command lines; individual lines from multi-line history entries can appear</li>
<li><strong>Mouse support</strong> (4.2): clicking moves the cursor and selects pager items</li>
<li><strong>Embedded completions</strong> (4.2/4.8): shipped completions live inside the fish binary, not as files in `share/fish`</li>
<li><strong>Abbreviation descriptions</strong> (4.9): abbreviations can show descriptions in the completion pager</li>
<li><strong>Pager polish</strong> (4.6-4.9): descriptions left-justified per column, repaints no longer reset the pager, shared-prefix truncation shows `…/foo.fish` style results</li>
</ul>
</ListCheck>

## Autosuggestions vs tab completions

These are two separate features that people sometimes confuse:

| | Autosuggestions | Tab completions |
|---|---|---|
| Trigger | Automatic as you type | Press Tab |
| Display | Gray text after cursor | Menu below command line |
| Source | History + completions + file paths | Completions (man pages, built-in, custom) |
| Accept | → / Ctrl+F (full), Alt+→ (first word) | Enter / Tab |
| Shows options | One suggestion at a time | All matching options |
| Delete entry | Shift+Delete | N/A |

They work together. Autosuggestions give you quick history recall without stopping. Tab completions give you a browseable list when you need to explore options.

## Searchable history: Ctrl+R

Autosuggestions draw on the same history data, one guess at a time. The full history search is **Ctrl+R**, which opens the history pager:

- **↑** does a prefix search through history (type a few characters, then press up)
- **Ctrl+R** opens the history pager with a search prompt
- **Ctrl+R** / **Ctrl+S** page through results
- Search is case-insensitive unless your query contains an uppercase letter

This is the same history data that feeds autosuggestions. For managing it (deleting entries, syncing across machines), see [Fish Shell history: search, delete and sync](/fish-shell-history-persistence/).

## Tuning completion behavior

Fish colors the completion pager based on these variables:

```fish
set fish_color_search_match --background=yellow  # history search matches and selected pager items (background only)
set fish_pager_color_completion normal             # regular completion text
set fish_pager_color_description grey              # description text
set fish_pager_color_prefix cyan --underline       # matched prefix
set fish_pager_color_selected_background --background=blue  # selected item background
set fish_pager_color_secondary_completion normal   # secondary completions (shared prefix)
set fish_pager_color_secondary_description grey    # secondary descriptions
set fish_pager_color_secondary_prefix cyan         # secondary prefix
```

You can also set these through `fish_config`, which opens a browser interface with live previews. For a curated look at prompt themes and colors, see [Fish Shell themes and prompts](/fish-shell-themes-prompts/).

## Troubleshooting Fish autocomplete

<Accordion label="Completions missing after installing a new program" group="troubleshooting">
The man-page sweep hasn't run yet. Run `fish_update_completions` to generate completions from installed man pages. It never overwrites custom completions you've written. On a minimal VPS this is fast; on a full desktop with hundreds of man pages it can take noticeably longer.
</Accordion>

<Accordion label="A broken or stale completion keeps loading" group="troubleshooting">
The file is still in `~/.config/fish/completions/`. Run `complete -e <cmd>` to erase definitions and block autoloading (fish 4.0+), then delete the file. If the completion is coming from a vendor directory, check `~/.local/share/fish/vendor_completions.d/` and `/usr/share/fish/vendor_completions.d/`.
</Accordion>

<Accordion label="Fish never offers file paths" group="troubleshooting">
The command or option is marked `-f`/`--no-files` in its completion definition. Use `-F`/`--force-files` on the specific option to re-enable files. To see the completion definitions for a command, run `complete -c <cmd>` with no other arguments.
</Accordion>

<Accordion label="That one awful suggestion keeps appearing" group="troubleshooting">
It's in your history. Press **Shift+Delete** while the suggestion is displayed to remove it. For bulk history management, see the [history guide](/fish-shell-history-persistence/).
</Accordion>

<Accordion label="Tab is slow on NFS or network mounts" group="troubleshooting">
Slow symlink resolution on network filesystems. Fixed in fish 4.9.0, so upgrade fish. The fix targets directories with slow symlinks, so NFS home directories are the main beneficiary.
</Accordion>

<Accordion label="Everything here acts differently" group="troubleshooting">
You're on fish 3.x from distro apt. The behaviors in this guide (Shift+Delete, `complete -e` autoload blocking, embedded completions, the lookup order) require fish 4.0+. Go back to the prerequisites section and use the release-4 PPA.
</Accordion>

## Fish vs Zsh and Bash autocomplete

In [Zsh](/fish-shell-vs-zsh/), you get similar autosuggestions with the `zsh-autosuggestions` plugin (see the [best Oh My Zsh plugins](/best-oh-my-zsh-plugins/) if you go that route). Zsh's `compinit` completion system is powerful but needs configuration. If you want to set up autocomplete in Zsh from scratch, see [how to enable command autocomplete in Zsh](/enable-command-autocomplete-in-zsh/).

Bash has basic tab completion through `readline` and `bash-completion`. It works for simple cases but doesn't generate completions from man pages and shows no descriptions.

Fish's advantage is that all of this works without setup. You install fish and the autocomplete is there: history-based suggestions, described completions from man pages, and a pager that's navigable with keyboard or mouse. The comparison is not close.

## FAQ

<Accordion label="How do I turn off autosuggestions in Fish?" group="faq" expanded="true">
Add `set -g fish_autosuggestion_enabled 0` to `~/.config/fish/config.fish`. Remove the line to bring them back.
</Accordion>

<Accordion label="Why doesn't Fish complete my new command?" group="faq">
Either the completion file doesn't exist or the man-page sweep hasn't run. Try `fish_update_completions` first. If that doesn't help, check whether a completion file exists in `~/.config/fish/completions/` and test it with `complete -C "yourcommand "`.
</Accordion>

<Accordion label="Where are Fish completions stored?" group="faq">
Completions ship inside the fish binary (since 4.2) and can be listed with `status list-files`. Custom completions live in `~/.config/fish/completions/`. Third-party completions go in `vendor_completions.d/` directories. Man-page-generated completions are cached in `~/.cache/fish/generated_completions/`. The full lookup order is in the "Where Fish completions come from" section above.
</Accordion>

<Accordion label="What's the difference between autosuggestions and tab completions in Fish?" group="faq">
Autosuggestions are the gray inline prediction that appears as you type: one suggestion at a time, sourced from history and completions. Tab completions are the menu that appears when you press Tab: a browseable list of all matching options with descriptions. See the comparison table above.
</Accordion>

<Accordion label="Does Fish autocomplete work over SSH?" group="faq">
Yes. Autocomplete is shell-side. There is nothing to install on the client. When you SSH into a server running fish, the suggestions come from the remote shell's history and completions, not your local machine. Make sure fish is the remote login shell (`chsh -s /usr/bin/fish`).
</Accordion>
