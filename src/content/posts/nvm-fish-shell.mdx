The original nvm (Node Version Manager) is a Bash script. It doesn't work in Fish. If you try sourcing it in Fish, you get syntax errors because nvm relies on POSIX shell features that [Fish deliberately doesn't support](/fish-shell-vs-bash-vs-zsh/).

The fix is **nvm.fish**, a separate Node version manager written entirely in Fish. Same concept (install and switch between Node versions), different implementation. It's made by the same person who built [Fisher](/best-fish-shell-plugins/), and it works well. If you want to use NVM with Fish Shell, this is the tool to reach for. It runs on fish 3.x and 4.x, so the Rust-rewrite era of fish hasn't broken anything.

This guide covers the full setup, including what nvm.fish won't do, which is worth knowing before you rely on it.

## Install nvm.fish with Fisher

<ListCheck>
<ul>
<li>Fish 3.x or 4.x installed (see the <a href="/install-fish-shell-ubuntu/">Ubuntu</a> or <a href="/fish-shell-macos-setup/">macOS</a> guides if you need it)</li>
<li>Fisher (installed below if you don't have it)</li>
<li>Network access to `nodejs.org` or a mirror</li>
<li>About 10 minutes</li>
</ul>
</ListCheck>

You need [Fisher](/best-fish-shell-plugins/) first. If you don't have it:

```fish
curl -sL https://raw.githubusercontent.com/jorgebucaran/fisher/main/functions/fisher.fish | source && fisher install jorgebucaran/fisher
```

Then install nvm.fish:

```fish
fisher install jorgebucaran/nvm.fish
```

That's it. You don't need any additional configuration. Restart your shell or open a new terminal tab.

<Notice type="info" title="Project status (2026)">
nvm.fish's latest tagged release is **2.2.17 (2025-02-07)**. The `main` branch reports version 2.2.18, with commits since the last tag being mostly Dependabot and CI. The project is not archived and still works fine, but it's low-maintenance. I still recommend it for pure-Fish simplicity. If you need heavy multi-runtime tooling, look at fnm or mise later in this article.
</Notice>

<Button text="nvm.fish on GitHub" link="https://github.com/jorgebucaran/nvm.fish" variant="outline" color="gray" />

### Verify the install

```fish
fisher list          # should show jorgebucaran/nvm.fish
nvm -v               # prints a version number
nvm -h               # shows the command list
```

If `fisher list` doesn't show `jorgebucaran/nvm.fish`, the install didn't complete. Re-run the `fisher install` command. If `nvm -v` doesn't print a version, your shell hasn't reloaded. Open a new terminal.

### Update or pin nvm.fish

To upgrade later:

```fish
fisher update jorgebucaran/nvm.fish
```

To pin a specific version (Fisher supports `@tag`, `@branch`, or `@commit`):

```fish
fisher install jorgebucaran/nvm.fish@2.2.17
```

Check what's installed with `fisher list`. Note: a bare `fisher install` resolves to whatever Fisher's default is, so check `nvm -v` after a fresh install to confirm which version you got.

## Install Node versions

```fish
# Latest release line
nvm install latest

# Latest LTS line (currently Node 26, Lithium)
nvm install lts

# A specific major line
nvm install 24
nvm install 22

# An exact version
nvm install 22.11.0

# An LTS line by codename
nvm install jod      # Node 22
nvm install krypton  # Node 24
nvm install lithium  # Node 26
```

Current LTS lines as of late 2026:

| Line | Codename | LTS since | EOL | Status |
|---|---|---|---|---|
| 22 | Jod | 2024-10-29 | 2027-04-30 | Maintenance |
| 24 | Krypton | 2025-10-28 | 2028-04-30 | Maintenance |
| 26 | Lithium | 2026-10-28 | 2029-04-30 | Active LTS |

Node 18 (Hydrogen) and Node 20 (Iron) are end-of-life. Don't install them for anything you plan to keep running.

nvm.fish downloads pre-built Node binaries and stores them in `~/.local/share/nvm/` (following the XDG Base Directory spec). Each version gets its own directory. To see everything available on the mirror:

```fish
nvm list-remote          # all versions
nvm list-remote 24       # filter by regex
```

### Verify Node is installed

```fish
node --version    # e.g. v26.13.0
npm --version
nvm current       # shows the active version
nvm list          # shows all installed versions
```

If `node --version` says "command not found", you haven't activated a version yet. Run `nvm use <version>` or set a default (next section).

On disk, each installed Node version is a full runtime, roughly 100 to 200 MB unpacked per version. Check with `du -sh ~/.local/share/nvm/*` for the real number. `nvm uninstall` frees the space.

## Switch between versions

```fish
# Activate a specific version (current session only)
nvm use 24
nvm use lts
nvm use latest

# Drop back to the system-installed Node
nvm use system

# Return to your configured default
nvm use default

# Read the nearest .nvmrc or .node-version (no argument)
nvm use

# Check what's active
nvm current

# List installed versions
nvm list

# List installable versions from the mirror
nvm list-remote

# Silent mode (no output), useful in scripts and the autoswitch function below
nvm use --silent 24
nvm use -s 24
```

`nvm use` changes the active Node version for your current shell session only. When you open a new terminal, it starts on whatever `nvm_default_version` is set to (or nothing, if you haven't set one). It does **not** read the directory's `.nvmrc` on its own. See the next section.

**Verify:** after `nvm use 24`, run `node --version`. It should show `v24.x.x`. `nvm list` marks the active version.

## Set a default Node version

Without a default, new shell sessions won't have any nvm-managed Node on the PATH. Set one with a universal variable:

```fish
set --universal nvm_default_version 24
```

Now every new interactive Fish session starts with Node 24 active. You can use `lts`, `latest`, a codename like `jod`, or a specific version number.

What happens at startup: `conf.d/nvm.fish` runs `nvm use --silent $nvm_default_version`, but only in interactive shells. This is the only auto-activation nvm.fish does. Non-interactive shells (scripts, `fish -c`, CI runners) skip it entirely. See ["What nvm.fish won't do"](#what-nvmfish-wont-do) for the implications.

**Verify:** open a brand-new terminal tab and run `nvm current`. It should show your default version. `node --version` should work without any manual `nvm use`.

## Switch versions per project (.nvmrc / .node-version)

This is where nvm.fish handles project-specific Node versions, but it's more manual than you might expect.

Create a `.nvmrc` file in a project's root directory:

```bash
echo "22" > ~/projects/legacy-app/.nvmrc
echo "24" > ~/projects/new-app/.nvmrc
```

Then, when you're in the project directory, run `nvm use` (no arguments). It reads the nearest `.nvmrc` or `.node-version` file and activates that version:

```fish
cd ~/projects/legacy-app
nvm use          # reads .nvmrc → activates Node 22
node --version   # v22.x.x

cd ~/projects/new-app
nvm use          # reads .nvmrc → activates Node 24
node --version   # v24.x.x
```

First time in a project? `nvm install` (no arguments) also reads `.nvmrc`. It installs the specified version and activates it:

```fish
cd ~/projects/new-app
nvm install      # installs the .nvmrc version and activates it
```

The lookup walks *up* the directory tree until it finds a `.nvmrc` or `.node-version` file, so running `nvm use` from a subdirectory works too.

<Notice type="warning" title="nvm.fish does not auto-switch on cd">
There is no cd hook in nvm.fish. No version of it has ever auto-switched Node versions when you `cd` into a directory. You must run `nvm use` manually. New terminal sessions start on `nvm_default_version`, not the directory's `.nvmrc`. If you want true auto-switching, see the opt-in function below.
</Notice>

<Notice type="info" title=".nvmrc formats">
nvm.fish supports the same `.nvmrc` formats as the original nvm: version numbers (`22`, `22.11`, `22.11.0`), `lts`, `latest`, and LTS codenames (`jod`, `krypton`, `lithium`). Files named `.node-version` work too. Parsing is strict: no trailing comments or whitespace. A `.nvmrc` containing `22 # my project` will fail to match.
</Notice>

**Verify:** `cd` into the project, run `nvm use`, then `node --version`. It should match the `.nvmrc` value.

### Want true auto-switching on cd?

nvm.fish doesn't do this, but you can add it with a custom Fish function. Drop this in `~/.config/fish/functions/_nvm_autoswitch.fish`:

```fish
function _nvm_autoswitch --on-variable PWD --description "Switch Node on .nvmrc dirs"
    set --local dir $PWD
    while test -n "$dir" -a "$dir" != "/"
        if test -f $dir/.nvmrc -o -f $dir/.node-version
            nvm use --silent
            return
        end
        set dir (dirname $dir)
    end
end
```

This is **not built into nvm.fish**. It's your own function. It fires whenever `$PWD` changes, walks up looking for `.nvmrc`, and runs `nvm use --silent` (a no-op when the right version is already active). It doesn't handle deactivation when you leave a project directory. This snippet is straightforward but should be tested on your fish version before you depend on it. If you're building custom helpers like this, see [writing your own Fish shell functions](/fish-shell-functions-custom-commands/).

## Install default global packages

If you want certain npm packages installed every time you install a new Node version:

```fish
set --universal nvm_default_packages yarn typescript tsx
```

Now `nvm install 24` will also run `npm install -g yarn typescript tsx` after downloading Node.

Note that npm global package trees are **per installed Node version**, not shared. Each new version gets its own set of globals. If you're managing dependencies across versions, see [how to update all Node.js dependencies to the latest version](/nodejs-update-dependencies/).

## Uninstall Node versions

```fish
nvm uninstall 24.22.2
nvm uninstall v22
```

This removes the installed binaries from the nvm data directory and frees the disk space.

### Remove nvm.fish completely (rollback)

If you want to tear the whole thing down:

```fish
fisher remove jorgebucaran/nvm.fish
set --erase --universal nvm_default_version
set --erase --universal nvm_default_packages
```

Then remove the data directory. **Double-check the path before running `rm -rf`**, especially if you set a custom `$nvm_data`:

```fish
# Default location (XDG):
rm -rf ~/.local/share/nvm/

# Or if you set a custom nvm_data:
# rm -rf ~/.nvm/
```

Open a new terminal and verify `nvm` is gone: `nvm -v` should say "command not found". Node itself is also gone. Reinstall it via your distro packages, Homebrew, or nvm.fish again.

## Mirror, data directory & architecture

Three config knobs worth knowing:

Change the download mirror if you are behind a corporate proxy or somewhere `nodejs.org` is slow:

```fish
set --global nvm_mirror https://npmmirror.com/mirrors/node
```

Default is `https://nodejs.org/dist`.

The data directory is where Node versions are stored (default: `$XDG_DATA_HOME/nvm`, i.e. `~/.local/share/nvm/`):

```fish
set --global nvm_data ~/.nvm
```

If you previously used the Bash-based nvm and have Node versions in `~/.nvm/`, this lets nvm.fish use that same directory. Versions installed by either tool should work.

For Alpine/musl systems where the default glibc binaries won't run, override the architecture:

```fish
set --global nvm_arch x64-musl
```

Without this, installs on musl-based systems (Alpine containers, some embedded Linux) will download binaries that fail at runtime.

<Notice type="warning" title="Don't set these as universal">
`nvm_data` and `nvm_mirror` must be set with `set --global`, not `set --universal`. The plugin's update logic erases universal values for these two and resets them as global. `nvm_default_version` and `nvm_default_packages` *are* universal, so don't mix up the rules.
</Notice>

## What nvm.fish won't do

This is the part most guides skip. nvm.fish has real limits:

There is no auto-switch on cd. No `--on-variable PWD` hook exists in the plugin. You run `nvm use` manually in each project, or build the custom function shown above.

It has no direnv/.envrc integration. nvm.fish doesn't read `.envrc` files. There's an [open issue about it](https://github.com/jorgebucaran/nvm.fish/issues) (2025). If you use direnv for environment management, you'll need to bridge the two with your own functions.

Startup activation is interactive-only. The `status is-interactive` gate means non-interactive fish sessions never get the default Node version on PATH. This affects scripts, `fish -c` one-liners, CI runners, and some terminal multiplexer configurations.

### On servers and in CI

nvm.fish is a developer shell tool. Don't depend on it in non-interactive contexts. On a server or in CI, use one of these instead:

- An absolute path: `~/.local/share/nvm/v24.22.2/bin/node`
- A Docker image with Node baked in
- Distro or package-manager Node (`apt install nodejs`, `brew install node`)

<Notice type="warning" title="Non-interactive shells get no Node">
If you're running `fish -c "node script.js"` or a CI step with fish, the default version is not activated. Node won't be on PATH. Use an absolute path or a package-manager Node for anything non-interactive.
</Notice>

## nvm.fish vs nvm (the Bash version)

| | nvm.fish | nvm (Bash) |
|---|---|---|
| Shell support | Fish only | POSIX shells (bash, zsh, sh…); Fish only via wrappers |
| Written in | Fish | Bash/POSIX sh |
| Installation | Fisher plugin | curl script |
| Current version | 2.2.17 (2025-02-07) | v0.40.8 (2026-09-21) |
| Startup cost | None until a default is set; then one silent `nvm use` per interactive shell | Sources a ~4,000-line script every session |
| `.nvmrc` support | Yes | Yes |
| Tab completions | Yes (Fish native) | Basic |
| LTS codenames | Yes | Yes |

The performance difference is real. The Bash-based nvm sources its entire script in every new session, a long-standing complaint. nvm.fish only loads when you run `nvm`, or runs one silent `nvm use` at startup if you set a default. It is still orders of magnitude lighter.

If you need the Bash version on macOS or Ubuntu, see [installing Node.js with the original nvm on macOS and Ubuntu](/install-nodejs-using-nvm-macos-ubuntu/). Wrappers like FabioAntunes/fish-nvm run real nvm.sh inside Fish, but they're barely maintained (last release 2023). You're better off with nvm.fish or fnm.

## nvm.fish vs fnm vs Volta vs mise

There are other Node version managers that work with Fish:

| | nvm.fish | fnm | Volta | mise |
|---|---|---|---|---|
| Version | 2.2.17 (2025-02) | v1.39.0 (2026-03) | v2.0.2 (2024-12) | v2026.11.0 (2026-11) |
| Language | Fish | Rust | Rust | Rust |
| Stars | ~2.7k | ~27k | ~13k | ~36k |
| Cross-shell | Fish only | Any (via `fnm env`) | Any | Any |
| Auto-switch on cd | No (manual `nvm use`) | Yes (`--use-on-cd`) | Per-project pinning | Yes (`.tool-versions` / `.node-version`) |
| Multi-runtime | Node only | Node only | Node, Python, … | Node, Python, Ruby, Go, … |
| Maintenance | Low | Active | Low | Very active |

My default is nvm.fish for pure-Fish simplicity when you only manage Node. For cross-shell support and real auto-switching, fnm is the fastest option. For polyglot/multi-tool setups (Node + Python + Go and friends), mise is the modern 2026 default. Volta's per-project pinning is nice, but don't start new projects on it. Development has slowed.

If you're evaluating the Node ecosystem more broadly, [Bun, an all-in-one JavaScript runtime and package manager](/bun-package-manager/) is worth knowing about.

<Tabs>
<Tab name="fnm">
Install with `brew install fnm` or `cargo install fnm`. Then create `~/.config/fish/conf.d/fnm.fish`:

```fish
fnm env --use-on-cd --shell fish | source
```

The explicit `--shell` flag is faster and avoids process-tree detection. fnm's `--use-on-cd` is a real cd hook: it switches versions when you enter a project directory.
</Tab>
<Tab name="Volta">
Install:

```fish
curl https://get.volta.sh | bash
```

Then add to `~/.config/fish/config.fish`:

```fish
set -gx VOLTA_HOME ~/.volta
fish_add_path $VOLTA_HOME/bin
```

Volta 2.0 dropped old glibc support (CentOS 6 gone), moved the Windows installer to winget, and added ARM Linux/Windows builds plus a macOS universal binary. Works, but development is slow. Treat it as mature but stale.
</Tab>
<Tab name="mise">
Install from [mise.jdx.dev](https://mise.jdx.dev). Then add to `~/.config/fish/config.fish`:

```fish
~/.local/bin/mise activate fish | source
```

(Homebrew installs activate without this line.) mise manages Node, Python, Ruby, Go, and more from one tool, with `.tool-versions` / `.mise.toml` config files. If you're managing more than just Node, this is the strongest option right now.
</Tab>
</Tabs>

## Troubleshooting

<Accordion label="nvm: command not found" group="troubleshooting" expanded="true">
Fisher didn't install correctly, or your shell hasn't reloaded. Run `fisher list` to check if `jorgebucaran/nvm.fish` appears. If it's missing, re-run `fisher install jorgebucaran/nvm.fish`. If it's listed but `nvm` still doesn't work, open a new terminal. The function autoloads on first use in a fresh session.
</Accordion>

<Accordion label="Node not found after install" group="troubleshooting">
You installed a version but haven't activated it. Run `nvm use <version>`. Or set a default so every new shell gets it: `set --universal nvm_default_version lts`. If `node --version` still fails, check `nvm list`. Is the version installed?
</Accordion>

<Accordion label=".nvmrc not being read automatically" group="troubleshooting">
This is expected behavior. nvm.fish reads `.nvmrc` only when you run `nvm install` or `nvm use` with no version argument. No version of nvm.fish auto-switches on `cd`. Run `nvm use` in the project directory. Also check your `.nvmrc` content: parsing is strict. A file containing `22 # comment` or trailing whitespace will fail to match. Keep it to a bare version number or codename.
</Accordion>

<Accordion label="Error in _nvm_index_update / 'test: Missing argument' / 'Invalid redirection target'" group="troubleshooting">
This is [issue #255](https://github.com/jorgebucaran/nvm.fish/issues/255) (opened 2026-08-19, reported on fish 4.8.1 + WSL). The mirror index (`$nvm_mirror/index.tab`) isn't fetched or created. Workarounds:

```fish
mkdir -p ~/.local/share/nvm   # ensure the data dir exists
nvm install lts               # retry
```

If that doesn't work, reinstall via Fisher: `fisher remove jorgebucaran/nvm.fish && fisher install jorgebucaran/nvm.fish`.
</Accordion>

<Accordion label="No Node in tmux / VS Code terminal / fish -c" group="troubleshooting">
nvm.fish's startup hook runs only in interactive shells (`status is-interactive`). tmux panes that don't run an interactive startup, VS Code integrated terminals with certain configs, and `fish -c` one-liners all skip it. Fix: use an absolute path (`~/.local/share/nvm/v24.22.2/bin/node`) or ensure your tmux/terminal config starts fish interactively. For tmux configuration details, see [best terminal multiplexers (tmux and friends)](/best-terminal-multiplexers/).
</Accordion>

<Accordion label="Install fails on Alpine / musl" group="troubleshooting">
The default Node binaries are glibc-linked and won't run on musl systems. Set the architecture override:

```fish
set --global nvm_arch x64-musl
```

Then retry `nvm install lts`.
</Accordion>

<Accordion label="Shell startup slower than expected" group="troubleshooting">
Once `nvm_default_version` is set, every interactive shell runs a silent `nvm use` at startup. This is still far lighter than sourcing the Bash nvm script, but it's not zero. If startup time matters, unset the default and activate versions manually per project.
</Accordion>

For anything else, check the [upstream issues list](https://github.com/jorgebucaran/nvm.fish/issues). 13 issues were open as of November 2026.
