Installing the latest Fish Shell on Ubuntu means using the official PPA, because Ubuntu's own repositories ship stale versions. Ubuntu 24.04 LTS still carries fish 3.7.0, and even the newest 26.04 release has 4.2.1. The latest stable Fish is **4.9.3** (released September 8, 2026). The Fish team's PPA gets you the current release in three commands. This guide covers desktop and VPS/server installs, switching your default shell safely, configuration, plugins, and the gotchas that bite people in production.

If you're on a Mac, see my [Fish Shell macOS setup guide](/fish-shell-macos-setup/) instead.

## Install Fish Shell on Ubuntu from the official PPA

The Fish team maintains a PPA on Launchpad that tracks the latest stable release. Add it, update, and install:

```bash
sudo add-apt-repository ppa:fish-shell/release-4
sudo apt update
sudo apt install fish
```

(`apt-add-repository` also works: it's a legacy alias for `add-apt-repository`.)

Verify it installed correctly:

```bash
fish --version
```

You should see `fish, version 4.9.3`. Now confirm the package came from the PPA and not Ubuntu's repos:

```bash
apt policy fish
```

The candidate line should show `ppa.launchpadcontent.net/fish-shell/release-4/...` as the source. If it shows the Ubuntu archive instead, the PPA wasn't added properly or `apt update` hasn't run. See the troubleshooting section below.

Why the PPA matters: a quick comparison of what each source ships:

| Ubuntu release | Ubuntu repos | Official PPA |
|---|---|---|
| 24.04 LTS (noble) | 3.7.0 | 4.9.3 |
| 25.10 (questing) | 4.0.6 | 4.8.0 |
| 26.04 (resolute) | 4.2.1 | 4.9.3 |

Even the newest Ubuntu release is months behind the PPA. If you want current fish, use the PPA.

## What's new in Fish Shell 4.6 to 4.9

If you're coming from fish 4.5 or earlier, here's what changed in the four feature releases since. This is a highlight list, not a changelog. See the [GitHub releases page](https://github.com/fish-shell/fish-shell/releases) for everything.

<Accordion label="Highlights from Fish 4.6 to 4.9" group="whats-new" expanded="false">

- **4.6.0**: fish accepts `|&` (Bash-compatible shorthand for piping stdout and stderr together, alongside fish's own `&|`). Supports `SHELL_PROMPT_PREFIX`, `SHELL_PROMPT_SUFFIX`, and `SHELL_WELCOME` environment variables (set by systemd's `run0`). Emoji default width is now 2. Set `$fish_emoji_width` to 1 if lines misalign in your terminal.

- **4.7.0**: Non-interactive shells no longer set the default theme variables (`fish_color_*`). History no longer gets corrupted with NUL bytes on SIGTERM/SIGHUP. `fish_update_completions` handles newer groff escapes.

- **4.8.0**: `cd` supports `-L` and `-P` flags (logical vs physical path resolution). Abbreviations gained `--position=command|anywhere`, `--regex`, `--command`, `--set-cursor`, and `--function`. Cleaner upgrade path: fish no longer creates the `__fish_initialized` universal variable and won't drop a surprise `fish_frozen_theme.fish` in your `conf.d/` when upgrading from 3.x-era defaults.

- **4.9.x**: Abbreviations can have a **description** shown in the completion pager (`abbr -a --description "git status" gst git status`). Faster tab completion in directories with slow symlinks (network mounts, NFS home directories). Konsole kitty-keyboard-protocol workaround.

</Accordion>

## Try Fish without switching your default shell

You don't have to commit right away. Just type:

```bash
fish
```

This drops you into a Fish session. You get [autosuggestions](/fish-shell-autocomplete-suggestions/), [syntax highlighting](/fish-shell-syntax-highlighting/), and tab completions immediately. Play around. Type a few commands. If you don't like it, type `exit` and you're back in Bash.

## Set Fish as your default shell on Ubuntu

Once you're ready to commit, use the flow recommended by the official fish docs. First make sure fish is listed in `/etc/shells`, then switch your login shell:

```bash
command -v fish | sudo tee -a /etc/shells
chsh -s "$(command -v fish)"
```

The `$(command -v fish)` form is path-proof: it works regardless of where fish is installed. The hardcoded `/usr/bin/fish` works fine for PPA builds too, but the dynamic form won't break if you later switch to a standalone binary or a different install prefix.

Log out and back in (or open a new terminal). Verify the switch:

<ListCheck>
<ul>
<li><code>echo $SHELL</code> shows <code>/usr/bin/fish</code></li>
<li><code>getent passwd $USER</code> shows fish as your login shell</li>
</ul>
</ListCheck>

To roll back to Bash later:

```bash
chsh -s /usr/bin/bash
```

<Notice type="warning" title="Login shell PATH gotcha">
Fish does not read <code>/etc/profile</code> or <code>/etc/profile.d/</code>. If tools like nvm, SDKman, or corporate login scripts set up your PATH via login profiles, you'll end up with an incomplete PATH after switching to fish. You have two options: replicate the PATH setup in <code>~/.config/fish/config.fish</code> using <code>fish_add_path</code> (see my [NVM with Fish Shell](/nvm-fish-shell/) guide for the nvm case), or leave Bash as your login shell and just point your terminal emulator at fish for interactive use. On servers where login scripts layer PATH setup, that second option is the safer default.
</Notice>

<Notice type="warning" title="Keep Bash installed">
Don't remove Bash. Many system scripts depend on it, and you'll want it around for running POSIX shell scripts. Fish replaces your interactive shell, not your system's script interpreter. If you're still weighing shells, my [Fish Shell vs Bash vs Zsh](/fish-shell-vs-bash-vs-zsh/) comparison covers the tradeoffs.
</Notice>

## Install Fish Shell from standalone binaries

If your Ubuntu release isn't in the PPA support list (EOL releases like 23.04/23.10, or very old setups), or you'd rather not add a third-party repo on a locked-down server, the fish project publishes static Linux builds on GitHub releases. For 4.9.3 these are `fish-4.9.3-linux-x86_64.tar.xz` (~3.2 MB) and `fish-4.9.3-linux-aarch64.tar.xz` (~2.9 MB).

<Notice type="info" title="When to use this">
The standalone binary is a fallback. For most users the PPA (above) is the better path: it integrates with apt, gets security updates, and handles dependencies. Use the static builds when the PPA doesn't cover your release or you can't add third-party repositories.
</Notice>

Download and extract:

```bash
# For x86_64
wget https://github.com/fish-shell/fish-shell/releases/download/4.9.3/fish-4.9.3-linux-x86_64.tar.xz
# For aarch64 (ARM64)
# wget https://github.com/fish-shell/fish-shell/releases/download/4.9.3/fish-4.9.3-linux-aarch64.tar.xz

tar -xf fish-4.9.3-linux-x86_64.tar.xz
```

The extracted directory contains the fish binary and supporting files. Move it somewhere permanent and add it to your PATH:

```bash
sudo mv fish-4.9.3-linux-x86_64 /opt/fish
sudo ln -s /opt/fish/bin/fish /usr/local/bin/fish
fish --version
```

These are official static builds from the fish project. I haven't tested the exact tarball layout on every Ubuntu release. If the binary doesn't run due to missing shared libraries, check the extracted directory for a `README` or install `libpcre2-8-0` and `libcrypt1` from apt.

## Initial configuration

Fish's config file lives at `~/.config/fish/config.fish`. The file is optional: fish runs fine without it and won't create it for you. Create it when you want custom settings. Here's a basic starting config:

```fish
# ~/.config/fish/config.fish

# Add custom paths
fish_add_path ~/bin
fish_add_path ~/.local/bin

# Disable the greeting message
set -g fish_greeting

# Set your preferred editor
set -gx EDITOR vim
```

A few things to note:

- `fish_add_path` is the Fish way to add directories to your `$PATH`. Don't try to use `export PATH=...` like in Bash.
- `set -g` sets a global variable for the current session. `set -gx` also exports it to child processes.
- `set -g fish_greeting` with no value suppresses the default "Welcome to fish" message.

### Modular configuration with conf.d

Fish sources every `.fish` file in `~/.config/fish/conf.d/` at startup. This is cleaner than dumping everything into one file. For example, you could create:

```fish
# ~/.config/fish/conf.d/aliases.fish
abbr -a gst git status
abbr -a gco git checkout
abbr -a gp git push
```

I cover abbreviations vs aliases in detail in [Fish Shell abbreviations vs aliases](/fish-shell-abbreviations-vs-aliases/). Short version: Fish abbreviations expand into the full command before executing, which is better than aliases in most cases.

Since fish 4.8 and 4.9, abbreviations can do more. You can attach a description (shown in the completion pager) and control where the abbreviation expands:

```fish
# Description shown when the abbreviation appears in completions
abbr -a --description "git status" gst git status

# Expand anywhere in the command line, not just at the start
abbr -a --position anywhere -- -C --color
```

See [abbreviations with descriptions and custom positions](/fish-shell-abbreviations-vs-aliases/) for the full set of flags.

## Install a plugin manager

Fish works fine without plugins, but a plugin manager lets you add things like better git integration, fzf search, and [Node version management](/nvm-fish-shell/).

**Fisher** is the most popular choice (v4.4.8, actively maintained):

```fish
curl -sL https://raw.githubusercontent.com/jorgebucaran/fisher/main/functions/fisher.fish | source && fisher install jorgebucaran/fisher
```

Now you can install plugins with `fisher install`. For example:

```fish
fisher install PatrickF1/fzf.fish
fisher install jorgebucaran/nvm.fish
```

If you want a more opinionated framework rather than a lightweight installer, [Oh My Fish (OMF) themes and plugins](/oh-my-fish-install-themes-plugins/) is the alternative: it has its own theme system and package format.

I have a full guide on [the best Fish Shell plugins and tools](/best-fish-shell-plugins/) if you want recommendations.

## Set up your prompt

Fish comes with a decent default prompt, but you have several options for customizing it.

<Tabs>
<Tab name="Built-in themes">
Run `fish_config` and a browser window opens where you can pick from several built-in prompt styles and color schemes.

If you're on a remote server over SSH and can't open a browser, use the terminal interface instead:

```fish
fish_config theme show
fish_config theme choose "Solarized Light"
```

`fish_config theme show` lists available themes right in your terminal. `fish_config theme choose` applies one without needing a browser. This is the flow to use on a headless VPS.
</Tab>
<Tab name="Tide">
Tide is a popular Fish-native prompt with a configuration wizard. Install it via Fisher:

```fish
fisher install IlanCosman/tide@v6
```

Then run `tide configure` to walk through the setup. Tide is at v6.2.1 (November 2026). The `@v6` pin is correct and tracks the current major.
</Tab>

## Useful things to know right away

**Command history search.** Press `Ctrl+R` to search your history. Fish uses glob syntax by default, so `git*commit` matches any history entry containing "git" followed later by "commit". The search is case-insensitive unless your query contains uppercase letters. I cover history management in depth in my [Fish Shell history and persistence guide](/fish-shell-history-persistence/).

**Autosuggestions.** As you type, Fish shows grayed-out suggestions based on your history and available completions. Press the right arrow key to accept, or `Alt+Right` to accept one word at a time.

**Tab completions.** Fish generates completions from man pages automatically. Try typing `git checkout` and pressing tab. You'll see branch names, flags, and more without installing anything extra.

**Web configuration.** Run `fish_config` to open a browser-based tool for changing your colors, prompt, and viewing defined functions. It's a quick way to see what's available.

## Running Fish on a server or VPS

If you want fish on a production server or VPS, a few constraints are worth knowing.

**Per-user only.** Don't `chsh` root or service accounts. Install fish and switch to it for your own interactive login. Leave root, `www-data`, and anything systemd or cron runs alone.

**Scripts are unaffected.** Fish as your interactive shell doesn't change what systemd units, cron jobs, or CI pipelines execute. Those still use `/bin/sh` or `bash` via their shebangs. Your existing scripts keep working exactly as they did.

**Docker images.** Fish isn't in slim or alpine Docker images. Keep using `bash -c` or `sh` in Dockerfiles and CI configs. See my [Install Docker and Docker Compose on Ubuntu ARM](/install-docker-ubuntu-arm/) guide if you're setting up containers on a server.

**Cost.** Everything here is free and open source. The only cost is about 10 MB of disk for the fish install.

If you're setting up a fresh Ubuntu VPS to try this on, [Hetzner Cloud](https://go.bitdoze.com/hetzner) has affordable Linux boxes that work well for this.

## Common issues

<Accordion label="PPA added but still getting fish 3.7.0" group="issues" expanded="true">
Run `apt policy fish` to check where the candidate package is coming from:

```bash
apt policy fish
```

If the candidate shows the Ubuntu archive instead of `ppa.launchpadcontent.net`, the PPA either wasn't added correctly or `apt update` hasn't run since adding it. Re-run:

```bash
sudo add-apt-repository ppa:fish-shell/release-4
sudo apt update
sudo apt install fish
```

Also note: on interim Ubuntu releases the PPA build lags behind the latest. Ubuntu 25.10 gets fish 4.8.0 from the PPA, not 4.9.3. LTS releases (22.04, 24.04, 26.04) get the newest builds.
</Accordion>

<Accordion label="Fish doesn't appear in /etc/shells" group="issues">
If `chsh` complains, you may need to add Fish to the allowed shells manually:

```bash
command -v fish | sudo tee -a /etc/shells
chsh -s "$(command -v fish)"
```

If fish was installed from the standalone binary, `command -v fish` will return the path where you linked it (e.g. `/usr/local/bin/fish`), and that's what gets added to `/etc/shells`.
</Accordion>

<Accordion label="Bash scripts don't work in Fish" group="issues">
That's expected. Fish has its own syntax. Run Bash scripts with `bash script.sh` or add `#!/bin/bash` at the top and make them executable. Your existing scripts don't need to change, just run them explicitly with Bash.
</Accordion>

<Accordion label="Environment variables from .bashrc are missing" group="issues">
Fish doesn't read `.bashrc` or `.bash_profile`. You need to set your environment variables in `~/.config/fish/config.fish` using `set -gx`:

```fish
set -gx JAVA_HOME /usr/lib/jvm/java-21
set -gx GOPATH ~/go
fish_add_path $GOPATH/bin
```

The same applies to PATH entries added by tools like nvm or SDKman in login profiles. Replicate them in `config.fish` or use fish only as your interactive shell. See [NVM with Fish Shell](/nvm-fish-shell/) for the nvm case.
</Accordion>
