## What TinyFish does

  url="https://www.youtube.com/embed/Hu_OGbBEW3M"

TinyFish now ships eight products, all with a Tiny prefix. You only need the first two to start:

- **TinySearch**: free within 30 requests/min and 12,000/day. Takes a query and returns structured JSON. The results are rank-stable and clean, so an LLM can parse them without guessing. Typical latency is 1-3 seconds, and you can pass location and language hints.
- **TinyFetch**: free within 150 URLs/min and 1,000 URLs/day, up to 10 URLs per request. Renders each page in a real Chromium browser (JavaScript, SPAs, the works), strips navigation bars, cookie banners, ads, and scripts, and returns markdown, HTML, or JSON. Your model stops paying tokens for junk HTML.
- **TinyAgent** (formerly Agent): natural-language browser automation. $0.016 per step, 2 concurrent runs by default.
- **TinyBrowser** (formerly Browser): raw CDP browser sessions. $0.002 per minute, 5 concurrent sessions.
- **TinyMonitor**: scheduled page or topic tracking. $0.005 per completed check plus the underlying Search or Fetch call.
- **TinyResearch**: cited multi-source reports. $2 per `deep` run, $3 per `max` run. Must be enabled per account.
- **TinySet**: structured datasets from a prompt. $0.10 per row.
- **TinyAnswer**: a single answer with citations. Must be enabled per account.

Everything except Search and Fetch is metered from a prepaid Wallet. For coding agent use, Search and Fetch cover most of what you need, as long as you stay inside the free allowance.

### Why this matters for coding agents

Most coding agents rely on the model's training data for anything outside your codebase. That works for stable patterns and well-documented APIs. It falls apart for:

- **Recent releases**: a library that shipped breaking changes last week
- **Version-specific quirks**: "does this Docker image still support ARM64 in v3?"
- **Community solutions**: the GitHub issue where someone already solved your exact problem
- **Documentation lookups**: reading the actual docs instead of guessing from memory

Giving your agent a search+fetch pipeline turns it from "I think this is how it works" to "here is the current documentation, and here are three GitHub issues confirming this behavior."


## Getting more out of Search and Fetch

Both APIs gained options that cut noise and tokens. All of them are documented in the TinySearch and TinyFetch references on [docs.tinyfish.ai](https://docs.tinyfish.ai/).

### Search options

- `include_domains` / `exclude_domains`: a comma-separated string, not an array. The `site:` operator still works in the query but is deprecated for domain filtering.
- `recency_minutes`: only results from the last N minutes. You cannot combine it with `after_date` / `before_date` (format `YYYY-MM-DD`).
- `domain_type`: `web` (default), `news` (adds publisher and date), or `research_paper` (adds authors, venue, year, citation count, PDF URL). Date filters are not supported for papers, use `pub_year_min` / `pub_year_max`.
- `purpose`: a short note on why you are searching (up to 2,000 characters). It improves ranking.
- `location` and `language`: geo and language hints.
- `page`: 0 to 10 for more results.

```bash
curl -G "https://api.search.tinyfish.ai" \
  -H "X-API-Key: $TINYFISH_API_KEY" \
  --data-urlencode "query=docker compose release" \
  --data-urlencode "domain_type=news" \
  --data-urlencode "recency_minutes=1440"
```

### Fetch options

- `include_selectors` / `exclude_selectors`: 1-20 CSS selectors each. Exclusions are applied first. Pull only `main` or `article` and the model never sees the rest.
- `ttl`: omit it and any cached entry is accepted. `0` forces a live fetch, `N` accepts a cache entry younger than N seconds.
- Conditional fetch: for a single URL, send `if_none_match` or `if_modified_since` together with `include_etag_and_last_modified` to skip unchanged pages.
- `purpose`: why you fetch, same idea as in Search.
- `iframe_links`: also return iframe URLs, next to `links` and `image_links`.
- `highlights`: ranked verbatim passages that answer a question (`query`, `max_passages` 1-20). It is beta and enabled per account, otherwise the API returns 403 FORBIDDEN.

```bash
curl -X POST https://api.fetch.tinyfish.ai \
  -H "X-API-Key: $TINYFISH_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"urls": ["https://docs.docker.com/compose/how-tos/startup-order/"], "include_selectors": ["main"], "ttl": 0}'
```

Failed URLs come back in an `errors[]` array with a code. The ones worth handling in an agent loop: `bot_blocked` (retry later or escalate to TinyAgent), `login_required` (the page needs auth), `selector_not_matched` (your selector found nothing, retry without it), and `timeout` (set your client timeout to 150 seconds or more, the backend allows 110 seconds per URL).

### Staying inside the free fetch cap

<ListCheck>
<ul>
<li>Batch up to 10 URLs per request instead of looping one by one</li>
<li>Search first, then fetch only the best 2-3 URLs</li>
<li>Use `include_selectors` so the agent does not refetch a page to get a different part of it</li>
<li>Leave `ttl` unset so cached pages are reused, and use `ttl: 0` only when you need a live copy</li>
<li>Check your usage with `tinyfish fetch usage --status completed --start-after 2026-11-27T00:00:00Z --limit 1000 --pretty`</li>
</ul>

## Setting up TinyFish with Pi coding agent

Pi already has TinyFish support through the [pi-tinyfish](https://github.com/x1any/pi-tinyfish) package. It adds two tools to your agent: `tinyfish_search` and `tinyfish_fetch`. Install takes one command.

### Step 1: Get your API key

Sign up at [agent.tinyfish.ai](https://agent.tinyfish.ai/). No credit card. Copy the API key from the dashboard.

### Step 2: Install pi-tinyfish

<Tabs>
<Tab name="npm">
```bash
pi install npm:pi-tinyfish
```
</Tab>
<Tab name="git">
```bash
pi install git:github.com/x1any/pi-tinyfish
```
</Tab>
</Tabs>

### Step 3: Set the API key

```bash
export TINYFISH_API_KEY="your_api_key_here"
```

Add that to your shell profile (`~/.bashrc`, `~/.zshrc`, or `~/.config/fish/config.fish`) so it persists across sessions.

### Step 4: Use it

That is it. Next time you start Pi in a project, the agent can call `tinyfish_search` and `tinyfish_fetch` as tools. When it needs to look up something about a library, check docs, or verify a config format, it will search the web and fetch the relevant pages automatically.

The search latency is typically 1-3 seconds. Fetch can take a few seconds longer depending on the page. Both tools default to sensible timeouts (10s for search, 150s for fetch).

<Notice type="success" title="Token savings">
TinyFetch strips navigation, scripts, and boilerplate from pages before returning content. Your model processes the article text, not three kilobytes of cookie consent banners and footer links. That cuts the tokens you pay for on every fetch.
</Notice>

## Using TinyFish with Hermes Agent

[Hermes Agent](/hermes-agent-setup-guide/) from Nous Research has a built-in web search tool, but TinyFish gives you more control over the search results and adds clean page fetching that Hermes does not have out of the box.

There are three ways to wire TinyFish into Hermes:

### Option 1: MCP Server

TinyFish runs a hosted MCP server at `https://agent.tinyfish.ai/mcp`. It uses OAuth: you sign in with your TinyFish account on first use. Add it to your Hermes MCP config:

```json
{
  "mcpServers": {
    "tinyfish": {
      "url": "https://agent.tinyfish.ai/mcp"
    }
  }
}
```

This gives Hermes access to Search and Fetch through the standard MCP protocol, plus the heavier tools (TinyAgent, monitors, research, datasets). The agent sees them as native tools. If your client cannot do OAuth, send `Authorization: Bearer <API key>` instead.

### Option 2: Agent Skill

Install the TinyFish skill from the cookbook:

```bash
npx skills add github.com/tinyfish-io/tinyfish-cookbook --skill use-tinyfish
```

This teaches Hermes when to reach for Search vs Fetch vs Agent, and how to call them correctly. The skill includes decision logic: use search for finding URLs, fetch for reading known pages, and escalate to agent only when interactive browser automation is needed.

### Option 3: CLI wrapper

If you prefer shell-based integration, install the CLI:

```bash
npm install -g @tiny-fish/cli
tinyfish auth login
```

Then Hermes can call `tinyfish search query "..."` and `tinyfish fetch content get <urls>` through its terminal access. The CLI writes results to the filesystem instead of piping through the model's context, which keeps token usage low.

### Which approach to pick

MCP is the cleanest if your Hermes version supports it. The skill approach works well if you want the agent to understand the tool hierarchy (search first, fetch second, agent last). CLI is the fallback that works everywhere.

If you are building something custom or your agent does not support MCP, use the REST endpoints directly:


## TinyMonitor, TinyResearch, TinySet, and TinyAnswer

These four sit outside the daily coding-agent loop. Unlike Search and Fetch they are paid from your Wallet (TinyMonitor also draws on the free Search/Fetch allowance for its underlying call), and TinyResearch and TinyAnswer must be enabled on your account.

**TinyMonitor** watches a webpage or a topic on a schedule. Page monitors re-fetch a URL with `ttl` 0 and diff the content, good for a pricing or status page. Topic monitors re-run a search and flag new URLs, with 1-10 results per run and a minimum interval of 30 minutes. You can describe the change that matters ("the price drops below $500") and TinyFish assesses it. Delivery is the dashboard, a webhook (every scheduled run, retried 3 times), or email (only on change unless you enable "Email every run"). A check costs $0.005 plus the underlying Search or Fetch call, failed checks are free, and you get 50 monitors per account. A daily monitor is about $0.15 a month, an hourly one about $3.65.

**TinyResearch** takes a question and returns a cited report. It costs $2.00 per run in `deep` mode and $3.00 in `max` mode, charged on completion. Failed, cancelled, or timed-out runs are free. A `deep` run usually takes 5-20 minutes, `max` 5-45 minutes, and up to 5 runs can be active at once. If it is not enabled for your account the API returns 403. Useful parameters: `output_language` (a BCP 47 code), `domain_filter`, and `prior_run_id` for follow-ups. Each follow-up is a new paid run.

```python
from tinyfish import TinyFish

client = TinyFish()
report = client.research.run(
    query="Compare long-duration energy storage approaches",
    mode="deep",
)
```

```bash
curl --no-buffer https://agent.tinyfish.ai/v1/automation/run-research \
  -H "X-API-Key: $TINYFISH_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"query": "Compare long-duration energy storage approaches", "mode": "deep", "output_language": "en"}'
```

The curl call streams Server-Sent Events (`created`, `plan_updated`, `sources_searched`, `source_fetched`, `final_result`, `done`). There is also an async variant and a way to poll a run by ID.

**TinySet** builds a table. You describe the rows and TinyFish finds them on the web. It costs $0.10 per row, `target_rows` ranges from 1 to 250 (default 100), column planning takes up to a minute, and a run takes about 5-20 minutes. Skipped, failed, or cancelled rows are free.

```bash
tinyfish dataset create "Specialty coffee shops in Oakland with their website and rating" --rows 25 --pretty
```

```bash
curl -X POST https://agent.tinyfish.ai/v1/datasets \
  -H "X-API-Key: $TINYFISH_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt": "Specialty coffee shops in Oakland with their website and rating", "target_rows": 25}'
```

Pick TinySet when you know the columns and want many rows. Pick TinyResearch when you want a cited report.

**TinyAnswer** returns one answer with citations. It must be enabled per account and works with a personal API key only:

```bash
curl -X POST https://api.answer.tinyfish.ai/ \
  -H "X-API-Key: $TINYFISH_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"question": "What is the default TTL for TinyFetch?"}'
```

The mental model: TinySearch for links, TinyFetch for pages you already know, TinyAnswer for a quick cited answer, TinyResearch when the question needs evidence across several sources, TinySet for tables, TinyMonitor for watching something over time.

## Is TinyFish still free?

Yes, inside the allowance. Search is free up to 30 requests per minute and 12,000 per day, and Fetch up to 150 URLs per minute and 1,000 per day, at any Wallet balance. Past that you pay from the Wallet.

TinyFish moved from credit plans to a prepaid Wallet. There are no plans and no minimums. New accounts start with $8 in Wallet funds, no card needed, and up to $5 more for finishing onboarding steps. Deposits start at $10, and you can turn on auto-reload.

| Product | Cost | Limit |
|---------|------|-------|
| **TinySearch** | Free within the allowance, at any Wallet balance | 30 requests/min, 12,000/day (docs) |
| **TinyFetch** | Free within the allowance, at any Wallet balance | 150 URLs/min, 1,000 URLs/day, 10 URLs per request |
| **TinyAgent** | $0.016/step | 2 concurrent runs |
| **TinyBrowser** | $0.002/min | 5 concurrent sessions |
| **TinyMonitor** | $0.005/check + the underlying Search or Fetch | 50 monitors |
| **TinyResearch** | $2 (`deep`) or $3 (`max`) per run | 5 concurrent runs, enabled per account |
| **TinySet** | $0.10/row | 1-250 rows per dataset |

Limits are per person or organization. Enterprise adds custom limits, SSO, audit logs, and an SLA. The Search and Fetch allowance resets at 00:00 UTC, and failed fetches do not count against it. What happens past the allowance is covered in the warning at the top of this guide. If you run legacy credit plans, your rates and balance are shown in the dashboard.

TinyFish also runs programs. Students get $35 in Wallet credits with a school email. Ambassadors get bounties, event funding, and referral rewards. TinyFish for Startups gives up to $12,000 in value, 4x the default rate limits for Search and Fetch, and Wallet credits.

## What I like and what I do not

I have been using TinyFish through Pi and Mastra for months. Here is the honest take.

**What works well:** The search results are clean and fast. Fetch renders SPAs properly, which matters for React-based docs sites. The free allowance covers daily coding agent use without issues in my setup. Token savings from clean content are noticeable. The CLI + skill combo works across every agent I have tried.

**What could be better:** Fetch can be slow on heavy pages (5-10 seconds for JavaScript-heavy sites). Search occasionally returns stale results for very recent events. The free Fetch allowance is now capped at 1,000 URLs a day, so a runaway agent loop can burn through it, and past that you need Wallet funds at a rate the docs do not state. TinyAgent ($0.016 per step) and TinyBrowser ($0.002 per minute) add up fast if you need interactive automation.

**Bottom line:** For giving your coding agent the ability to read current documentation and search the web, the free Search + Fetch allowance works well if you batch and filter. I have it wired into Pi through pi-tinyfish, into Mastra through the SDK, and use the CLI for everything else. It has become a standard part of my agent setup.
