All models except Max Preview accept text, image, and video input. The open-weight models (27B, 35B-A3B) are on HuggingFace with community quantizations: GGUF for llama.cpp/Ollama, NVFP4 for NVIDIA GPUs, and FP8 for datacenter cards. That community traction matters because it means active quant maintenance and good tooling support.

### Qwen 3.6 Plus: the workhorse for coding agents

This is the one I use most. $0.33/M input tokens with a 1M context window. It builds on a hybrid architecture that combines efficient linear attention with sparse mixture-of-experts routing. Alibaba tuned it specifically for agentic coding and front-end development.

The 1M context window matters for agent work. When Hermes or OpenCode processes a large repo, the model needs to hold the full file structure, multiple related files, and the conversation history without dropping pieces. 1M tokens handles that. Two operational limits to know: max completion tokens is 65,536 and max prompt tokens is 983,616. If your agent generates very long outputs, it will truncate at 65K.

On SWE-bench Verified, the vendor-claimed score is 78.8%. Independent testing by Vals AI shows 73.4%. Both numbers are in the [benchmarks section](#qwen-36-benchmarks-swe-bench-terminal-bench--design-arena) with full attribution. The cache read price of ~$0.033/M is the agent-workflow money saver: when the model re-reads the same project files across turns, those tokens cost almost nothing.

### Qwen 3.6 Flash: budget 1M-context option

The model the original version of this article missed. Qwen 3.6 Flash (`qwen/qwen3.6-flash`) gives you the same 1M context window at roughly 57% of the input price: $0.1875/M input, $1.125/M output for prompts up to 256K tokens. Over 256K, it jumps to $0.75/$3.00.

Same multimodal input support (text+image+video). If Plus output pricing at $1.95/M hurts on output-heavy agent work, Flash is the alternative. The tradeoff: expect lower accuracy on hard coding tasks compared to Plus. For routine edits, boilerplate, and documentation, the gap is small enough that the price difference wins. If you want to push costs even lower, check the [cheapest AI models for Hermes Agent](/best-cheap-models-hermes-agent/) for sub-$1/M options.

### Qwen 3.6 27B: self-hosted coding (Apache 2.0)

A dense 27B parameter model under Apache 2.0. The Ollama quantized build is 18-19GB on disk. That means a 24GB GPU works, but with less headroom than you might expect for KV cache at long contexts. For CPU inference, 64GB+ RAM is the realistic minimum.

It has a 262K context window and a built-in thinking mode for extended reasoning. Community quantizations cover most hardware: GGUF (unsloth) for llama.cpp and Ollama, NVFP4 for NVIDIA consumer cards, FP8 for datacenter GPUs. For hardware picks, see the [best mini PCs for local LLMs and Ollama](/best-mini-pc-local-llm/). If you want a quiet home LLM box, an [ASUS mini PC](https://go.bitdoze.com/asus-dc510) works for lighter quantized workloads, but for 27B at 262K context you want real GPU muscle.

<Notice type="warning" title="VRAM headroom">
A 24GB card running the 18-19GB quant leaves about 5GB for KV cache. At long contexts (100K+ tokens), that gets tight fast. If you see OOM errors during long agent sessions, reduce `num_ctx` or switch to the 35B-A3B model.
</Notice>

### Qwen 3.6 35B-A3B: budget self-hosting

MoE model with 35B total parameters but only 3B active per token. Runs fast on less hardware than the 27B dense model. Apache 2.0, 262K native context (extensible to 1M via YaRN).

Two honesty notes the old version of this article got wrong. First, on-disk size is ~23GB (MoE overhead makes it larger than the 27B despite fewer active params). Second, "CPU-only at usable speeds" is true for short completions but painful for long agent generations. A coding agent generating 5K-token diffs on CPU will test your patience. If you want to self-host for OpenClaw specifically, the [best local models for OpenClaw](/openclaw-ollama-local-models/) guide has tested pairings.

## Setting up Qwen 3.6 with your AI coding agents

Before you start:

<ListCheck>
<ul>
<li>An OpenRouter API key (or local Ollama for self-hosted models)</li>
<li>One of the agents installed: [Hermes Agent](/hermes-agent-setup-guide/), [OpenCode](/opencode-setup-guide/), or [OpenClaw](/clawdbot-setup-guide/)</li>
<li>For self-hosting: 24GB GPU for 27B (tight) or ~23GB disk for 35B-A3B, plus 64GB RAM if running CPU-only</li>
<li>Model IDs stay `qwen/qwen3.6-plus` on OpenRouter unless your agent version requires a newer ID</li>
</ul>
</ListCheck>

### Hermes Agent

```bash
# Via OpenRouter (recommended)
hermes config set model qwen/qwen3.6-plus

# Or set OpenRouter key if not already configured
echo "OPENROUTER_API_KEY=your-key" >> ~/.hermes/.env
```

Verify: run a test prompt, then check your OpenRouter activity page shows `qwen/qwen3.6-plus` as the model. If it shows something else, you are hitting a fallback.

### OpenCode

```
/connect
# Select OpenRouter or OpenCode Go
```

Then `/models` to pick Qwen 3.6 Plus. If you are on OpenCode Go flat-rate, the model is included without per-token charges.

### OpenClaw

Edit your config:

```json
{
  "agents": {
    "defaults": {
      "model": {
        "primary": "qwen/qwen3.6-plus",
        "fallback": ["minimax/minimax-m2.7"]
      }
    }
  }
}
```

Restart the gateway:

```bash
openclaw gateway restart
```

Verify: check the gateway logs on the first request. You should see the model name in the request line. The MiniMax fallback is useful when Qwen hits rate limits. For more model options for OpenClaw, see the [best open source models for OpenClaw](/best-opensource-models-for-openclaw/).

### Ollama: Run Qwen 3.6 locally

<Notice type="warning" title="Correct Ollama tag">
The 35B-A3B tag is `qwen3.6:35b`, not `35b-a3b`. Using the wrong tag gives you a "model not found" error. This is a real copy-paste failure mode from the original version of this article.
</Notice>

```bash
# Pull the dense 27B (18-19GB on disk)
ollama pull qwen3.6:27b

# Or the MoE variant (23GB on disk)
ollama pull qwen3.6:35b

# Newer option: Qwen 3.8 is also on Ollama now
ollama pull qwen3.8
```

Then configure your agent to use the local Ollama endpoint:

```bash
# Hermes
echo "OPENAI_BASE_URL=http://localhost:11434/v1" >> ~/.hermes/.env
echo "OPENAI_API_KEY=ollama" >> ~/.hermes/.env
hermes config set model ollama/qwen3.6:27b
```

Memory note: longer `num_ctx` = more VRAM usage. Do not set 262K context on a 24GB card with the 27B model loaded. Start with `num_ctx=8192` and increase until you find the ceiling.

See the [Ollama Docker setup guide](/ollama-docker-install/) for running Ollama on a server. For hardware picks, the [best mini PCs for local LLMs and Ollama](/best-mini-pc-local-llm/) covers what works at each model size.

## Troubleshooting: pricing shocks, rate limits & Ollama OOM

<Accordion label="My OpenRouter bill jumped 4x mid-month" group="trouble" expanded="true">
You crossed the 256K token tier. Qwen 3.6 Plus charges $1.30/M input (vs $0.325/M) and $3.90/M output (vs $1.95/M) for prompts over 256K tokens. Fix: cap your agent's context size, summarize conversation history before it grows, or switch to Qwen 3.6 Flash (cheaper tier, still 1M context). Check the prompt token count in your agent's logs to see where you are.
</Accordion>

<Accordion label="Getting 429 / rate limit errors on OpenRouter">
The free tier has rate limits. Move to paid credits on OpenRouter, or switch to [OpenCode Go](/opencode-go-plan/) flat-rate if you want predictable costs. For self-hosted, Ollama has no rate limits.
</Accordion>

<Accordion label="Ollama OOM or painfully slow">
Reduce `num_ctx` (start at 8192). On a small GPU, use `qwen3.6:35b` instead of `27b` (3B active params, faster). For further reduction, look at community GGUF quants at lower bit depths. If running CPU-only, expect 10-30x slower generation than GPU. The 35B-A3B is tolerable for short completions on CPU, not for long agent diffs.
</Accordion>

<Accordion label="Output gets cut off mid-generation">
Qwen 3.6 Plus has a 65,536 max completion token limit. If your agent generates longer output, it truncates. Split the task into smaller chunks or use a model with higher completion limits for code-generation-heavy workflows.
</Accordion>

<Accordion label="Agent ignores project context despite 1M window">
The 1M window helps, but retrieval and context staging still matter. If your agent is not pulling in the right files, check its file-selection logic rather than blaming the model context size.
</Accordion>

<Accordion label="Is Qwen 3.6 Plus free anywhere?" group="faq" expanded="true">
OpenRouter offers a free tier for Qwen 3.6 Plus with rate limits. [OpenCode Go](/opencode-go-plan/) ($10/month) includes it without per-token charges up to the monthly usage cap. Direct from Alibaba, there is no free tier but the per-token pricing is competitive.

<Accordion label="Can I run Qwen 3.6 locally?" group="faq">
Yes. Qwen 3.6 27B and Qwen 3.6 35B-A3B are both open-weight under Apache 2.0. The 27B quantized build is 18-19GB (fits a 24GB GPU with ~5GB headroom for KV cache). The 35B-A3B is 23GB on disk despite only 3B active params. Pull with `ollama pull qwen3.6:27b` or `ollama pull qwen3.6:35b` (not `35b-a3b`). For hardware picks, see the [best mini PCs for local LLMs and Ollama](/best-mini-pc-local-llm/).
</Accordion>

<Accordion label="How does Qwen 3.6 Plus compare to Claude Sonnet?" group="faq">
Qwen 3.6 Plus costs $0.33/M input versus Claude Sonnet at roughly $3/M input. That is about 9x cheaper. On SWE-bench Verified, Vals AI measured Qwen 3.6 Plus at 73.4% (vendor claims 78.8%). Claude scores higher on some hard benchmarks, but for the price difference, Qwen 3.6 Plus is the better value for most coding tasks. Use Claude for the hardest problems, Qwen for everything else.
</Accordion>

<Accordion label="What happened to Qwen 3.6 Max Preview?" group="faq">
It was a limited preview, is not on OpenRouter today, and has been superseded by Qwen 3.7 Max, Qwen 3.8 Max, and Qwen 4 Max. The benchmark sweep claim from the original article ("#1 on six coding benchmarks") could not be verified at update time. For maximum accuracy regardless of cost, look at the current Max-tier models. For daily driving, Plus is still the value pick.
</Accordion>

<Accordion label="Does Qwen 3.6 work with MCP servers?" group="faq">
Yes. Qwen 3.6 Plus supports function calling and structured output, which is what MCP servers use under the hood. When you connect MCP servers through OpenCode, Hermes Agent, or OpenClaw, Qwen 3.6 Plus handles the tool calls like any other compatible model.
</Accordion>

<Accordion label="Qwen 3.6 vs 3.7 vs 3.8: which should I start with?" group="faq">
New projects: start with Qwen 3.7 Plus ($0.32/$1.28, cheaper output). Budget projects: Qwen 3.7 Flash ($0.03/$0.13) or Qwen 3.8 27B ($0.06/M input). Existing projects on 3.6: stay put until you have a reason to migrate. See the [comparison section](#should-you-still-pick-qwen-36-in-2026) for the full matrix.
</Accordion>

</Accordion>
