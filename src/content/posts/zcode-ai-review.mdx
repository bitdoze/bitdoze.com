In this updated ZCode review I look at Z.AI's free AI coding agent as it stands in November 2026: what changed in v3.17.2, how Goal Mode handles long unattended tasks, and where the whole package lands against Cursor. If you want a free desktop coding agent that keeps working while you walk away, ZCode is the one I keep coming back to: hook up a model, set a goal, and let it iterate.

ZCode is the official desktop app from [Z.AI](https://go.bitdoze.com/glm), the team behind GLM. File manager, terminal, Git, browser preview, and agent chat sit in one window. Open a project, describe what you need, and the agent reads files, writes code, runs commands, and commits. The harness went open source under Apache-2.0 at [github.com/zai-org/ZCode](https://github.com/zai-org/ZCode). It had 8,638 stars and 2,695 forks as of mid-November 2026. The app itself is at **v3.17.2** (released November 3, 2026).

Since my last update of this review: a Sites plugin for one-click website deploys, workflow auto-resume after quota resets, MCP servers that start without Node, a batch of plan-mode security hardening, and a macOS 13+ floor. The full changelog is in the next section. For the wider field of agents and IDEs, see my [best AI coding tools and agents compared](/ai-coding-tools/) roundup.

## What shipped since late October (v3.17.1 to v3.17.2)

ZCode has been shipping multiple releases a month. If you tried an older build earlier this year, here is the short version of where things stand. The harness was open-sourced and the legacy snapshot/upload pipeline was stripped out back in v3.14.0. Both good moves that raised the trust floor. Since then the pace continued. Between v3.17.1 (October 30) and v3.17.2 (November 3-4, 2026):

<ListCheck>

- The **Sites plugin** is the official one-click website deployment option and the first built-in deploy path. Useful if you want to push a static site without wiring up your own pipeline.
- **Workflow auto-resume after quota reset** means workflows paused because you ran out of credits pick back up automatically when the 5-hour pool refills. This is a big deal for long `/workflow` and Goal Mode runs on the Lite plan.
- With **Node-less MCP startup**, MCP servers now start with a bundled runtime, so you no longer need Node installed on the host. There is also a draft MCP configuration GUI instead of hand-editing JSON.
- **Plan-mode security hardening** blocks high-risk operations even in plan mode, restricts subtask permissions to match the main session, runs custom command scripts only after explicit permission, narrows local web-page preview scope, and stops corrupted config files from being silently overwritten (data-loss fix).
- **No-progress auto-stop** ends repeated executions that make no progress automatically, with a notification, instead of burning tokens forever. Pairs well with Goal Mode overnight runs.
- Kimi K3.1 Pro and MiniMax M3.1 Flash are now configurable alongside the existing roster.
- **One-click update-all plugins**, compact searchable remote-device list, and stop/restart remote services from the menu.
- **Off-peak plans no longer auto-renew** after expiration. Billing behavior change worth knowing before you subscribe.
- **Installer size significantly reduced** and streaming-reply stutter on long conversations largely fixed.

</ListCheck>

<Notice type="warning" title="macOS 13+ required from v3.17.2">

From v3.17.2 the macOS builds run Electron 44 (Chromium 152) and require **macOS 13 Ventura** minimum. macOS 12 (Monterey) and earlier are no longer supported. If you are stuck on an older macOS, grab the last compatible build from the GitHub releases archive or upgrade the OS.

</Notice>

<Notice type="warning" title="Stuck on v3.15.1 auto-update?">
Version 3.15.1 had a known updater bug where "Restart to Update" could hang in a loop on macOS and Linux. Z.AI fixed it in v3.15.3 with recovery steps (force-quit via Activity Monitor on macOS, system monitor on Linux). If your older install refuses to self-update, download the fresh installer directly from `zcode.z.ai`.
</Notice>

## What is ZCode? Z.AI's free, open-source AI coding agent

ZCode calls itself an "Agentic Development Environment". Marketing language, but it matches how the app behaves. The agent is the product; the UI follows. Cursor and Windsurf are editors with chat stapled on. ZCode inverts that: you open a workspace, describe a task, and the agent drives file operations, terminal commands, Git, and browser previews while you watch (or don't).

Here's the workspace you see when you open it:

<Image src={zcodeWelcome} alt="ZCode workspace showing task list, file tree, terminal, and agent chat" />

<ListCheck>

- The **ZCode Agent** is the default agent built for GLM-5.3 (stable 1M context for long tasks), with long-task planning, multi-turn context, and continuous code changes across files.
- With **Goal Mode**, set a verifiable session objective with `/goal`. The agent keeps iterating until the goal is verified complete.
- **Workflows** let one script orchestrate several sub-agents on a complex task, with per-sub-agent models and adjustable concurrency. Start one with `/workflow`.
- **Execution Modes** cover five levels from "ask before everything" to "full access". Cycle through them with Shift+Tab.
- **Multi-Model Support** covers GLM-5.3, Claude, GPT, Kimi K3.1 Pro, DeepSeek, [MiniMax](https://go.bitdoze.com/minimax) M3.1 Flash, [MiMo](https://go.bitdoze.com/mimo), [OpenCode Go](https://go.bitdoze.com/opencode-go), or any compatible provider.
- **Bot Channel** connects WeChat or Feishu so you can control ZCode tasks from your phone's chat app, including Feishu group chats.
- **Remote Control** connects your phone to the desktop session with a QR code and keeps tasks moving.
- **Idle-time tasks** queue non-urgent work that ZCode completes for free during spare capacity, without eating plan quota (rolling out to subscribers).
- **AGENTS.md Memory** is a project-level instructions file that ZCode reads at the start of every task.

</ListCheck>

### The ZCode Agent and AGENTS.md

The agent handles complex project understanding, long-task planning, and continuous code changes across multiple files. GLM-5.3's stable 1M context window means the agent can hold an entire mid-size codebase in view without constant re-reads.

<Image src={zcodeAgentFramework} alt="ZCode Agent new task interface showing model picker, context, and execution modes" />

To add context, click the **+** button at the bottom-left of the chat input:

- **Attachments** upload screenshots, documents, and requirement material
- **@ mentions** reference files in the workspace so the agent can locate relevant code
- **# conversations** link a past conversation to bring its context into the current task
- **/ commands** call saved prompts to reuse a fixed workflow
- **$$ skills** invoke reusable skill playbooks

For project instructions, ZCode reads an `AGENTS.md` file from your project root and loads it into every conversation. Put your project conventions, architecture notes, and coding standards here.

| Source | Path | Scope |
| --- | --- | --- |
| User global | `~/.zcode/AGENTS.md` | All projects |
| Workspace | `AGENTS.md` in project root | Current project |

<Notice type="info" title="AGENTS.md replaces CLAUDE.md">

ZCode uses `AGENTS.md` instead of `CLAUDE.md`. If you have an existing Claude Code project, ZCode copies `CLAUDE.md` content into `AGENTS.md` during onboarding. After that, only `AGENTS.md` is read.

</Notice>

### Execution modes

Five modes control how much freedom the agent gets. Press **Shift + Tab** while the chat input is focused to cycle through them.

<Image src={zcodeExecutionModes} alt="ZCode execution modes selector showing Default, Confirm, Auto Edit, Plan, and Full Access" />

| Mode | What Happens | Good For |
| --- | --- | --- |
| **Default Mode** | Standard task strategy with balanced confirmations | Everyday development, routine edits |
| **Confirm Before Changes** | Asks before every file edit or command | Critical code, production configs |
| **Auto Edit** | Edits files automatically, commands still need confirmation | Routine iteration with fewer interruptions |
| **Plan Mode** | Creates a plan first, then implements after approval | Complex multi-step tasks |
| **Full Access** | Minimal interruptions, agent proceeds continuously | Low-risk tasks where you want speed |

From v3.17.2, plan mode got a security pass: high-risk operations can no longer be allowed even in plan mode, and subtask permissions are restricted to match the main session. If you were relying on plan mode as a safety net for dangerous commands, it now acts like one.

### Version control

ZCode handles versioning at two levels.

At conversation level, every message creates a checkpoint. Review all file changes after any interaction in a multi-file diff view, undo only the last interaction's changes, or jump back to the state after any specific message.

The built-in Git panel shows modified files with status markers. You can write commit messages and commit with one click, switch branches, and browse commit history.

## Installation

ZCode is a desktop app for macOS (Apple Silicon and Intel), Windows (x64 and ARM64), and Linux (x64 and ARM64).

<ListCheck>

- **macOS 13 Ventura or later** (from v3.17.2, older macOS is no longer supported)
- **Windows 10/11** (x64 or ARM64)
- **Linux** x64 or ARM64 (DEB, RPM, or AppImage)
- A Z.AI account (for the free trial or Coding Plan) or any provider API key
- ~500 MB disk for the app; more for project workspaces

</ListCheck>

### macOS

1. Download the DMG from [zcode.z.ai](https://zcode.z.ai/en/docs/install)
2. Open the DMG file
3. Drag **ZCode.app** to your **Applications** folder
4. Launch from Launchpad

macOS 12 (Monterey) and earlier will not run v3.17.2+. The app needs macOS 13 Ventura minimum. If you see a "you cannot open this app" error on an older OS, that's the cause.

### Windows

1. Download the installer from [zcode.z.ai](https://zcode.z.ai/en/docs/install)
2. Double-click the installer
3. Follow the setup wizard

v3.17.2 fixed Win64 installer compatibility and added taskbar/tray unread notifications.

### Linux (DEB, RPM, AppImage)

Linux is fully supported. Pick between AppImage, DEB, and RPM builds for x64 and ARM64 on the [download page](https://zcode.z.ai/en/docs/install). Closing the window keeps the app in the system tray, which is what lets scheduled and idle-time tasks keep running in the background.

<Notice type="warning" title="DEB vs AppImage: pick one">

Z.AI recommends the **DEB package over AppImage** on Debian/Ubuntu. Do not install both. They overwrite each other's URL handler and you'll get weird `zcode://` link failures. Also: don't run ZCode with sudo.

</Notice>

### Linux troubleshooting

Common failure modes on Linux and WSL:

**AppImage won't start: `dlopen(): error loading libfuse.so.2`**. New distros ship FUSE 3 only. Fix:

```bash
sudo apt install libfuse2
```

Keep the AppImage at a fixed path (e.g. `~/Applications/ZCode.AppImage`) so desktop integration does not break after updates.

**NVIDIA/GPU startup errors**. Launch with software rendering if the GPU driver stack is fighting Electron.

**WSLg quirks**. Launch ZCode and the browser from the same WSL environment. CJK input needs IBus or Fcitx5 configured inside WSL.

### Verify your download and first launch

GitHub releases attach a `SHA256SUMS` file. Verify before you run anything:

```bash
sha256sum -c SHA256SUMS
```

Then first launch: the app opens, the workspace loads, and you see the welcome screen with the file tree and chat panel. If the window opens but the workspace is blank, restart once. First-run indexing can lag on very large repos.

## Goal Mode: set an objective and walk away

This is the feature that keeps me on ZCode. Type `/goal <objective>` and the agent keeps iterating toward a verifiable goal. You don't type "continue" every few minutes or babysit the run.

<Image src={zcodeGoalMode} alt="Goal Mode showing the agent iterating toward a verifiable objective with progress tracking" />

The `/goal` command cheat sheet:

```text
/goal                    Show the current goal and status
/goal <objective>        Set or replace the session goal
/goal replace <obj>      Explicitly replace the current goal
/goal pause              Pause goal-driven iteration (keeps state)
/goal resume             Resume from where you paused
/goal clear              Remove the goal entirely
```

One goal per session. Plain-language goal changes work too; you don't need the exact subcommand syntax.

Verification is evidence-based. A plan, a checklist, or elapsed effort does not count as "done." The agent looks at changed files, command output, and test results. Any unfinished to-do item blocks the verdict from being "complete." Checklist items stay in the iteration where they first appeared, so you get a readable history of what was tried and when.

<Image src={goalModeLoop} alt="Goal Mode iteration loop diagram: set objective, agent round, evidence check, complete or next round, with auto-pause on stop" />

State persists across interruptions. Pausing keeps completed rounds, tool history, and files. Closing the session and reopening restores the goal. Stopping a running task auto-pauses the goal so it doesn't burn quota unattended. Combined with v3.17.2's no-progress auto-stop, Goal Mode is now safe to leave running overnight. If the agent gets stuck in a loop, it stops and notifies instead of draining credits.

Good use cases:

- "Refactor the whole module and keep the tests passing"
- "Fix all TypeScript compile errors"
- "Get this page's Lighthouse performance score above 90"

The summary panel in the top-right shows goal status, elapsed time, total tokens, and iteration count. Pair Goal Mode with **Full Access** or **Auto Edit** to minimize interruptions and keep iterations flowing.

<Notice type="success" title="Smoke test">

Before trusting Goal Mode on a long task, run a quick one: set `/goal add a README.md with a project overview and verify it exists`. Watch the evidence check. The agent should confirm the file was created and read its contents before declaring "complete." If it claims done without evidence, something is wrong.

</Notice>

## Automations, Browser Automation & Repo Wiki

Three features that don't always make the highlight reel but earn their keep in daily use.

### Automations (scheduled and idle-time tasks)

Automations come in two flavors. Scheduled tasks take a time and a repeat rule; results land in a session. Create one via a form, "Create in chat," or from four built-in templates: weekday standup digest, daily risk scan, Friday release brief, Wednesday doc sync check. Idle-time tasks have no schedule. The agent runs them on spare capacity for free, without eating plan quota (rolling out to subscribers).

You can also just describe the schedule in plain language: *"Every weekday at 9am, summarize this project's code changes and open follow-ups."* On Linux, remember the app needs to stay in the system tray for background tasks to run.

### Browser Automation (Browser Use plugin)

The agent can drive the built-in browser panel: open URLs, click, fill forms, scroll, take screenshots, and react to page state. The official **Browser Use plugin** is on by default and ships two skills: one for general browser driving, one for walkthrough-style UI testing. Desktop-only for now. This is a step beyond the passive browser preview the app had at launch. The agent can interact with pages.

### Repo Wiki

Point ZCode at a codebase and it generates an architecture wiki per workspace. Every claim carries a source location you can click through to. That helps you verify the agent understood the code before you trust its refactoring plan. Language and model are selectable. Access it via the file-tree icon. Great for onboarding to an unfamiliar repo.

## Bot Channel & Remote Control

Two ways to keep tabs on ZCode when you're away from your desk.

Bot Channel connects WeChat and Feishu to your ZCode workspace. Message the bot from your phone's chat app to check task progress, send instructions, and keep the agent moving.

<Image src={zcodeBotChannel} alt="Bot Channel overview showing WeChat and Feishu integration options" />

Setting up Feishu:

1. Open **Bots** settings in ZCode's left sidebar
2. Click **Create Bot** and select Feishu
3. Scan the QR code. ZCode creates the Feishu app automatically
4. Send `/bind pairing-code` in the Feishu conversation
5. The bot is ready to use

WeChat works similarly. Scan to sign in and bind automatically. Since v3.15 the bot can collaborate inside Feishu group chats and standalone topics. v3.17.2 fixed result-push notifications for WeChat automation tasks. Z.AI has said DingTalk, Discord, and WeCom support is coming, but none of those are shipped as of v3.17.2. Don't buy based on the roadmap alone.

Remote Control lets your phone connect to the current desktop workspace. Scan a QR code, and your phone shows a live view of the session. Read agent responses, send new instructions, confirm or stop long-running tasks.

<Image src={zcodeRemoteControl} alt="Remote Control entry point showing QR code dialog for mobile connection" />

The desktop stays as the runtime. The phone only handles display and text input. One phone connection per session. v3.17.2 added account login for mobile Remote Control, a device manager in settings, a compact searchable remote-device list, and the ability to stop/restart remote services from the menu. For longer-lived access from chat apps, use Bot Channel instead. If you want a similar phone-to-agent setup with different tooling, I covered [how to control AI agents from your phone with Moshi + Herdr](/control-ai-agents-from-phone-moshi-herdr/) in a separate guide.

## Frequently asked questions

<Accordion label="Is ZCode free?" group="faq" expanded="true">

ZCode itself is free and open source (Apache-2.0). You pay for the AI models you connect, either through Z.AI's GLM Coding Plans (from $18/month), OpenRouter credits, Anthropic API usage, or whichever provider you choose. New users get a 5-day free trial with 5M tokens/day total (3M GLM-5.3 + 2M GLM-5-turbo), granted only during the trial.

</Accordion>

<Accordion label="What's new in ZCode v3.17.2?">

The November 2026 release added the Sites plugin (one-click website deployment), workflow auto-resume after quota resets, Node-less MCP startup, plan-mode security hardening (high-risk ops blocked), no-progress auto-stop with notification, Kimi K3.1 Pro and MiniMax M3.1 Flash model options, one-click update-all plugins, and a macOS 13+ system requirement.

</Accordion>

<Accordion label="How does ZCode compare to Cursor?">

Cursor is a VS Code fork with AI editing features and a larger extension ecosystem. ZCode is a standalone agent-first environment: open source, with Goal Mode (evidence-based auto-iteration), multi-agent workflows, Bot Channel (WeChat/Feishu), skills, and conversation-level rollback. Pick Cursor for IDE-native editing workflows; pick ZCode for unattended long tasks and agent-driven development.

</Accordion>

<Accordion label="What is the GLM Coding Plan and how does quota work?">

The GLM Coding Plan is Z.AI's subscription for coding-tool usage, starting at $18/month. Usage is metered in credits with a rolling 5-hour pool (2,000/12,000/28,000 credits for Lite/Pro/Max) and a weekly cap (10,000/60,000/140,000). Off-peak hours (outside Mon-Fri 14:00-18:00 SGT) charge 0.5x the standard credit rate. When quota runs out, plan tools stop until the next 5-hour refresh. Your account balance is never charged automatically.

</Accordion>

<Accordion label="Does ZCode work on Linux?">

Yes. AppImage, DEB, and RPM builds for x64 and ARM64. Prefer the DEB package over AppImage on Debian/Ubuntu, and don't install both (they overwrite each other's URL handler). On new distros, AppImage needs `libfuse2`. Closing the window keeps the app in the system tray so background tasks keep running.

</Accordion>

<Accordion label="Can I use ZCode with local models?">

Yes. ZCode supports any OpenAI or Anthropic-compatible API endpoint. Point it at a local inference server and it works with whatever model you're running. A good starting setup is to [self-host models with Ollama and Open WebUI](/ollama-docker-install/) on your own hardware, with no API costs and full data control.

</Accordion>

<Accordion label="Does ZCode run on macOS 12?">

No. From v3.17.2, ZCode requires macOS 13 Ventura or later (Electron 44 / Chromium 152). macOS 12 (Monterey) and earlier are no longer supported. Either upgrade the OS or grab an older build from the GitHub releases archive.

</Accordion>

<Accordion label="What happened to the 1.5x quota benefit?">

ZCode previously marketed "~1.5x effective quota" for GLM Coding Plan subscribers versus other tools. As of November 2026, that claim is no longer present in the official docs. The documented benefits are: the 5-day free trial, off-peak 0.5x credit rates, and free idle-time tasks (rolling out). Check the Z.AI subscribe page for the current offering before making a decision based on the old multiplier.

</Accordion>
