## What the heck is Astro anyway?

[Astro](https://astro.build/) is a modern static site generator. You build pages with your favorite UI framework (React, Vue, Svelte) or with plain Markdown, and Astro ships zero JavaScript by default.

While other frameworks send megabytes of JS to the browser, Astro delivers mostly HTML. Pages load fast on their own, without a cache plugin doing the heavy lifting.

Version timeline, so you know where you stand (checked Oct 2026): Astro 5 shipped Dec 2024, Astro 6 landed Mar 2026, and **Astro 7** arrived Jun 22, 2026 with a Rust-based compiler. The current release is 7.3.8 (Oct 8, 2026). The theme in this guide runs Astro 7.

### Why Astro is perfect for your blog

- Static HTML and zero JS by default: your pages are plain files on a CDN, which is what search engines and slow phones want
- Islands architecture: only the interactive parts get hydrated
- Use any UI framework you like, or none at all
- Markdown support for writing posts
- Zero-config defaults, so you spend time writing instead of wiring

Think of Astro as the mullet of web frameworks: business in the front (static HTML for speed) and party in the back (JavaScript only where you need it). Today we're using it to build you a blog that does not need a devops babysitter. Already running a WordPress site? Check out [how I migrated my WordPress site to Astro](/wordpress-to-astro-migration/), it was way less painful than I expected.

## Level 2: Node your way to success (5 minutes)

Before we get coding, install Node.js and npm:

1. Visit [nodejs.org](https://nodejs.org/)
2. Download the **LTS** version (24.x as of Oct 2026; anything v22.12.0+ works)
3. Install it like any other app
4. Open Terminal/Command Prompt and type:

```bash
node --version   # expect v22.12.0 or newer (Astro 7 requirement)
npm --version    # expect 10.8.2 or newer
```

If you see numbers in the right range, you're good. If you see numbers in the *wrong* range (`v18.x`, `v20.x`), you now own a known failure mode: `npm install` will throw engine errors and the dev server will refuse to start. Fix it before moving on.

For the curious: Node 26 becomes LTS on 2026-10-28. You don't need to chase the newest version, you just need to clear the v22.12.0 floor.

### Update `src/config/site.ts` (your blog's identity)

This is now the single identity file. Edit the obvious strings, leave the structure alone:

```typescript
export const siteConfig = {
  // Identity
  title: "Your Amazing Blog Title",
  brandName: "Your Blog Name",
  logoText: "Your Blog Name",
  author: "Your Name",
  description: "Your captivating blog description",
  heroDescription: "One or two sentences under your hero headline.",
  footerDescription: "What your blog is about, in one line.",
  postsPerPage: 11,
  // Below this you'll find hero { title, titleAccent, primaryCta, ... }
  // and homepage { showFeaturedPosts, showTaxonomyCards, ... }
  // leave the rest alone for now
};
```

Note for anyone following old tutorials: there is **no `name` key** anymore. If a blog post tells you to set `siteConfig.name`, it's describing a dead version of the theme. `title` and `brandName` are your new friends.

### Update `src/config/config.json` (contact stuff only)

`config.json` no longer holds your site title or URL. It only holds the contact form endpoint and contact details:

```json
{
  "params": {
    "contact_form_action": "#"
  },
  "contactinfo": {
    "address": "",
    "email": "you@example.com",
    "phone": ""
  }
}
```

Leave `contact_form_action` as `"#"` until you have a form endpoint, then [add a contact form to Astro for free, no backend needed](/add-contact-form-astro/) and point the action at your endpoint.

### Menus and socials (unchanged)

Navigation lives in `src/config/menu.json` and social icons live in `src/config/social.json`, same as in the old guide. Paths and shapes are in "Customize even more" further down if you need them.

<Notice type="info" title="The one-line mental model">
`site.ts` = identity · `config.json` = contact · `menu.json` = nav · `social.json` = socials. Keep this straight and the theme never fights you.
</Notice>

**Verify:** with `npm run dev` still running, change `title` and `brandName` in `site.ts`, save, and hard-refresh `http://localhost:4321`. The hero/footer text should change. If the dev server throws a TypeScript error, you probably removed a comma or a quote, the error line points right at it.

```markdown
## Hello World!

- To rant
- To teach
- To learn
- To procrastinate productively

Stay tuned for more!

![Celebration](https://media.giphy.com/media/3o6fJ1BM7R2EBRDnxK/giphy.gif)
```

Two frontmatter notes. First, `featured: true` (optional) surfaces the post in the homepage "Featured Posts" grid, so use it for your best stuff. Second, on image paths: the content schema got stricter in the 2026 update. Rather than trusting any path you see in a tutorial (including the one above), copy the `image:` line from one of the demo posts you haven't deleted yet, and point it at an image you actually added. On a bad path you get a broken image or a build error, not a friendly hint.

4. Save and refresh `http://localhost:4321`

**Achievement unlocked:** first post published.

**Verify:** the post shows up on the homepage *and* opens on its own page. Want media in your posts later? Here's [how to add YouTube videos to your Astro blog](/add-youtube-videos-astro-blog/).

**Broken looks like:** an error mentioning an unclosed tag or invalid HTML. Astro 7 got stricter, pasted HTML now fails the build instead of being silently fixed. See the Troubleshooting section at the bottom.

<li>Push a throwaway branch and grab its free **preview deployment** URL from the Deployments tab</li>

</ul>
</ListCheck>

Those preview deployments are your free staging environment. Use them for risky theme edits before merging to `main`.

## "But why Astro?" (for the skeptics)

"Couldn't I just use WordPress/Wix/Medium?" Sure, you could also use a butter knife to cut down a tree. Here's the honest case, numbers included:

- Astro 7's Rust compiler built this very blog's 743 pages in 47s, down from 103s on Astro 6. That's the [Astro 7 benchmark: build times cut in half on a 743-page site](/astro-7-faster-builds/). For a ten-post blog, builds are instant either way, the point is the tooling grows with you.
- The speed your readers feel comes from static HTML and zero JS by default. Your pages are files served from a CDN. Nothing to patch, no PHP to keep updating, no cache plugin doing heroics.
- Cost and ops stay boring: $0 per month and the only moving parts are git and a build. Compare that to managed builder plans or a WordPress host with staging, backups, and a security plugin subscription.
- A static site is a tiny attack surface, but you still own your GitHub account security (turn on 2FA) and dependency updates via upstream merges. Nothing is "set and forget".
- WordPress IS the right call for heavy plugin ecosystems, multiple non-technical editors, or a shop with real e-commerce needs. If that's you, read [an honest Astro vs WordPress cost and ops breakdown](/astro-vs-wordpress/) before committing to anything.

Building it yourself also means you can say "oh, my blog? I built it with Astro" at parties, if that's your thing.

## Troubleshooting

### Site won't build?

- Check terminal errors
- Validate Markdown syntax
- Run `npm run build` locally for clues

### Build fails with "unclosed tag" or invalid HTML

Astro 7 stopped auto-correcting broken markup. Unclosed tags and unterminated attributes now **fail the build**, and the error prints the file and line number.

- **Fix:** open that file, close the tag (or terminate the attribute), run `npm run build` locally, push again. Pasting HTML from the web is the usual culprit.

### Works locally, fails on Cloudflare

If the build goes green on your machine and red in the Cloudflare log, check the Node version on the build host. The theme ships `.node-version` pinned to `22.12.0` and Cloudflare's build image reads it automatically.

- **Fix:** if you moved the theme into your own repo, keep the `.node-version` file. If you can't, set `NODE_VERSION=22.16.0` (or any 22.12+) in the Pages project's build environment variables.

### npm install fails or throws engine errors

Seeing `EBADENGINE` or "unsupported engine"? Your Node is below the v22.12.0 floor.

- **Fix:** check `node --version`, upgrade Node ([nvm guide here](/install-nodejs-using-nvm-macos-ubuntu/)), then:

```bash
npm cache clean --force
```

- Delete `node_modules` & `package-lock.json`, reinstall.

### Images missing?

- Check paths
- Use relative paths or full URLs
- Put images in `public/images/`

### The "Use this template" button is missing on GitHub

The theme repo isn't flagged as a GitHub template, so the button often doesn't render. Use **Fork** (Level 4, Method A) or the clone-and-push route (Method B).

### Everything exploded?

Deep breath. Read the last error in the build log, check the Node version, and rebuild locally. Those three catch almost everything. If it's still broken, the theme's GitHub issues are the right place to ask.
