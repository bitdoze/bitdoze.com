Fish Shell history is one of those features that works well enough you stop thinking about it. Commands save automatically, autosuggestions pull from past entries, and Ctrl+R finds things fast. But the details matter when you want to clean up a leaked secret, keep failed experiments out of your suggestions, or share history across machines.

This guide covers the full fish shell history picture: where the history file lives on disk, how search works (it is not what most people assume), how to delete and filter entries, private mode for sensitive sessions, and syncing across machines with atuin. Updated for fish 4.9.3 (Sept 2026).

All behavior described here is sourced from the official fish documentation and CHANGELOG through fish 4.9.3 (released 2026-09-08). No invented benchmarks or anecdotes. Where something is version-dependent, I note the version.
</Notice>

## Where the Fish Shell history file lives

Fish stores history in a single plain-text file:

```
~/.local/share/fish/fish_history
```

If you have `XDG_DATA_HOME` set, the path is `$XDG_DATA_HOME/fish/fish_history` instead.

Each entry uses a YAML-style format with a command, a timestamp, and optionally a list of file paths that appeared in the command:

```
- cmd: git commit -m "fix auth"
  when: 1708784400
  paths:
    - src/auth.ts
```

The `paths:` field is what powers Fish's file-path autosuggestions. You do not need to create it by hand. Fish writes it automatically.

You can also point Fish at a different history file per session by setting the `fish_history` variable:

```fish
set fish_history work
# History now goes to ~/.local/share/fish/work_history
```

Anything other than the default name also prevents Fish from importing your Bash history on a new machine. Handy for presentations or when you want a clean slate.

### Size limit

Fish caps history at **262,144 items** (256 x 1024). This limit has been in place since fish 3.7.0. When the cap is reached, the oldest entries are trimmed. There is no `HISTSIZE`-style variable to change it. See [how Fish Shell compares to Bash and Zsh](/fish-shell-vs-bash-vs-zsh/) for more on the config differences. In practice you will never hit 262k entries unless you script history additions.

**Verify:**

```fish
ls -la ~/.local/share/fish/fish_history
head -5 ~/.local/share/fish/fish_history
wc -l ~/.local/share/fish/fish_history
```

You should see the file, a few `- cmd:` entries, and a line count. If the file does not exist yet, run any command and it will appear.

Since the file is plain text, it drops into any backup as-is. More on that in the [backup section](#saving-appending-and-backing-up-the-history-file).

## Searching Fish Shell history

Fish gives you three ways to search history: arrow keys, the Ctrl+R pager, and the `history search` command. Here is what each one does.

### Arrow keys (contains-based)

Press the **up arrow** to cycle through previous commands, newest first. If you have already typed something, the up arrow searches for commands **containing** that string anywhere, not just starting with it.

Type `git` and press up arrow. You will see `git commit`, `git push`, but also `sudo apt install git`, because the match is on "contains", not "starts with". This trips up people coming from Bash, where up-arrow is prefix-based. (The official docs use the same example: type `make`, press up, get all commands containing "make".)

**Token search:** press `Alt+Up` or `Alt+Down` to search for history commands containing a token that matches the word under your cursor. Useful when a long command has a distinctive argument in the middle.

**Verify the contains behavior:** type `git`, press up. If both `git commit` and `sudo apt install git` appear, the search is contains-based as expected.

### Ctrl+R and the history pager

Press `Ctrl+R` to open Fish's history pager. It is not a plain reverse-search prompt. It is a full pager with its own keys:

- **Type** to refine the search (the search bar is selected when the pager opens)
- **Ctrl+R** again pages to older matches
- **Ctrl+S** pages to newer matches
- **Escape** or **PageDown** stops searching and leaves the search string editable on the command line
- **Enter** runs the selected command

Interactive search is **smart-case**: case-insensitive unless your search string contains an uppercase character. So `docker` matches `Docker` and `docker`, but `Docker` only matches `Docker`.

Glob syntax works inside the pager (since fish 4.0.0). Type `git*fix` to match commands containing "git" followed later by "fix".

If you use vi-mode, `/` opens the same pager.

The [fzf.fish plugin](/best-fish-shell-plugins/) replaces Ctrl+R with an fzf-powered fuzzy finder that shows a preview and supports multi-select. I prefer it over the built-in pager for heavy use, but the pager is solid once you know the keys.

### The history command

For precise, scriptable searching, use `history search`:

```fish
# Search for commands containing "docker"
history search docker

# Search by prefix
history search --prefix "git commit"

# Exact match
history search --exact "git push origin main"

# Show timestamps
history search --show-time docker

# Custom timestamp format (strftime)
history search --show-time="%Y-%m-%d %H:%M:%S " docker

# Limit results
history search --max 10 docker

# Case-sensitive search
history search --case-sensitive Docker

# Oldest first instead of newest first
history search --reverse docker
```

By default, `history search` is case-insensitive and sorts newest first. Add `--reverse` to flip the order. Add `--color never` if you are piping to another tool and want clean output (fish 4.4.0 added `--color auto|always|never`).

**Verify:**

```fish
history search --show-time --max 5 docker
```

You should see timestamps and at most 5 lines.

<Notice type="warning" title="Multiline commands break naive pipes">
History entries can span multiple lines (autosuggestions have included multiline commands since fish 4.3.0). If you pipe `history search` output to a newline-based tool like `grep` or `while read`, multiline entries get split incorrectly. Use <code>--null</code> with <code>read -z</code> for safe processing:
</Notice>

```fish
history search --null docker | while read -z entry
    echo "--- $entry"
end
```

## Deleting and clearing Fish Shell history

Sometimes you run a command with a typo, or accidentally paste a password on the command line. Fish lets you clean up after the fact and prevent it next time.

### Interactive deletion

```fish
history delete docker
```

This searches for commands matching "docker" and shows numbered matches. Enter specific entry numbers, a range, or `all` to remove every match. Press Enter with no input to delete nothing (cancel).

### Exact deletion

```fish
history delete --exact --case-sensitive "docker login -p my_secret_password"
```

This removes that one specific command without prompting. This is the builtin's contract. The interactive picker above is the `history` *function*'s behavior layered on top.

**Pattern cleanup:** if you rotated a password and the old one is in your history, delete by prefix:

```fish
history delete --prefix "mysql -p"
```

**Verify:** `history search --exact "<deleted command>"` should return nothing.

### Deleting while you type (Shift+Delete)

Press **Shift+Delete** to remove the current history item (or the displayed autosuggestion) from history instantly. This is the fastest "oops, I should not have typed that" tool. It works during up-arrow search too (since fish 4.0.0).

You can also use `fish_config` (the web-based config UI) to browse and delete history entries. The deletion flow there got more usable in fish 4.7.0.

<Notice type="warning" title="fish_config startup bug in 4.7.0">
Fish 4.7.0 had a regression that stopped <code>fish_config</code> from starting. Fixed in 4.7.1 (2026-05-08). If <code>fish_config</code> will not launch, upgrade to 4.7.1 or later.
</Notice>

### Auto-removing failed commands with sponge

The [sponge plugin](/best-fish-shell-plugins/) automatically removes commands that exit with a non-zero code from your history. Install it with fisher (or through [Oh My Fish (OMF)](/oh-my-fish-install-themes-plugins/)):

```fish
fisher install meaningful-ooo/sponge
```

Sponge works via event handlers. It deletes entries *after* the command runs. This is because Fish writes history *before* executing the command (so long-running commands are visible to new sessions immediately), which means a pre-exec filter cannot check the exit code.

<Notice type="warning" title="sponge is unmaintained">
meaningful-ooo/sponge has not been updated since January 2024 (last push 2024-01-21). It may still work on fish 4.x, but test before relying on it. The safer primary workflow is the <code>fish_should_add_to_history</code> filter plus <code>history delete</code> for cleanup (covered next). Sponge is a nice-to-have, not a foundation.
</Notice>

## Controlling what goes into history

### Leading space skips history (built-in)

Prefixing a command with a space prevents Fish from saving it to history. This has been built-in **since fish 2.0.0 (2013)**. It is the equivalent of Bash's `HISTCONTROL=ignorespace`, and you do not need to configure anything.

The command is still recallable with up-arrow until you run the next command. After that, it is gone from the persisted history.

**Verify:** run this (note the leading space):

```fish
 echo "this should not be saved"
```

Then search:

```fish
history search --exact 'echo "this should not be saved"'
```

No match. That is the built-in behavior doing its job.

### The fish_should_add_to_history function

For programmatic control over what gets saved, define `fish_should_add_to_history`. Fish 4.0.0 added this hook.

```fish
# ~/.config/fish/functions/fish_should_add_to_history.fish
function fish_should_add_to_history
    # Re-implement the leading-space rule (see warning below)
    string match -qr '^\s' -- $argv[1]; and return 1

    # Don't save very short commands
    test (string length -- $argv[1]) -lt 3; and return 1

    # Don't save commands matching sensitive patterns
    string match -qr 'password|secret|token|api.key' -- $argv[1]; and return 1

    return 0
end
```

The contract (from the official docs):

- `$argv[1]` is the commandline about to be executed.
- The function runs **before** the command executes, so `$status` is not available. This is by design. Commands are written to history before running, so long-running or `exec` commands show up in new sessions immediately.
- Return 0 to save the command. Return non-zero to skip it. Skipped commands are still recallable for one command execution, then gone.

<Notice type="warning" title="Defining this function disables the leading-space rule">
If <code>fish_should_add_to_history</code> exists, it takes over all history-filtering duties. The built-in "space skips history" rule stops applying unless your function re-implements it. That is why the example above checks for a leading space with <code>string match -qr '^\s'</code>. Without that line, space-prefixed commands would get saved again. See the <a href="/fish-shell-functions-custom-commands/">fish_should_add_to_history function guide</a> for more function patterns.
</Notice>

Here is how the decision flows when a command is entered:

- If `fish_should_add_to_history` does **not** exist: the command is saved unless it starts with a space.
- If the function **does** exist: the function decides everything. Return 0 saves, non-zero skips. The leading-space rule is bypassed unless the function checks for it.

## Private mode: commands that never touch history

Sometimes you need to run commands without any trace: screencasts, shared sessions, or sensitive work on a production box. Fish has three distinct mechanisms, each with a different tradeoff.

<Tabs>
<Tab name="Screencast / demo">

```fish
fish --private
# or: fish -P
# or inside a session: set fish_private_mode
```

Hides existing history and writes nothing to disk. Old history is invisible (so no autosuggestion leaks), and nothing you type persists. Scripts can test for it:

```fish
if test -n "$fish_private_mode"
    echo "running in private mode"
end
```

Best for demos, recordings, and shared screens.

</Tab>
<Tab name="Sensitive one-off session">

```fish
set fish_history ""
```

History is not stored at all for this session. The session-name trick sets the history file to an empty name, so nothing is written. This also inhibits Bash-history import on new machines.

Best when you want a normal-looking session (history search still works within the session) but zero persistence.

</Tab>
<Tab name="Separate project history">

```fish
set fish_history work
```

History goes to a separate `work_history` file. Anything other than the default name also inhibits Bash-history import, which keeps your presentation machine clean.

Best when you want history for a specific project but not mixed into your main file.

</Tab>
</Tabs>

For cleaning up after the fact (rather than preventing), use `history clear-session`, covered in the next section.

**Ops note:** private mode is the cheapest way to demo on a production VPS without leaking hostnames, paths, or keys. One flag, zero cleanup.

## History across multiple sessions

Fish handles multi-session history differently from Bash. Each Fish session keeps its own in-memory history and writes to the shared history file as you run commands:

- When you run a command, it goes to the current session's memory and is written to `fish_history` on disk.
- Other running sessions do not see the new command immediately.
- New sessions that start after the command was saved will see it.
- `history merge` forces the current session to load commands from other sessions.

One nuance from the docs: Fish ordinarily ignores history changes from sessions started *after* the current one. So if you open a new terminal, run something, then switch back to an older terminal, the old one will not see the new command unless you merge.

### Merging history

```fish
history merge
```

This pulls in history from other Fish sessions. Useful when you ran something in another tab and want it available with Ctrl+R or up-arrow.

Bind it to a key for quick access:

```fish
bind \em 'history merge; commandline -f repaint'
```

Now `Alt+M` merges and repaints the prompt.

**Verify:** open two terminal panes. In one, run `echo test-12345`. In the other, run `history merge` then `history search test-12345`. It should appear.

### Clearing history

```fish
# Clear everything (prompts for confirmation)
history clear

# Clear only the current session's history
history clear-session

# Clear without the confirmation prompt (for scripts)
builtin history clear
```

`clear-session` is useful when you have been experimenting and do not want those commands polluting your history, but you want to keep everything from before.

<Notice type="warning" title="builtin history clear skips the prompt">
<code>builtin history clear</code> bypasses the confirmation prompt. It is convenient in scripts but irreversible without a backup. Double-check before running it, especially in a script that might execute unexpectedly.
</Notice>

**Failure mode (operator note):** before fish 4.7.0, sessions killed by `kill` or SSH disconnects could corrupt `fish_history` with NUL bytes. Fixed in 4.7.0 (issue #10300). Fish 4.8.1 fixed another edge case where history search would "forget" commands that were re-run in concurrent sessions. If you run many panes in [terminal multiplexers like tmux](/best-terminal-multiplexers/) on a VPS and see weird history behavior, check your fish version first.

## Syncing Fish Shell history across machines with atuin

Fish does not sync history between machines natively. The old advice was to symlink or sync `fish_history` via dotfiles, but that breaks down fast: two machines writing to the same file concurrently have no merge semantics, and you end up with conflicts or lost entries.

The current standard answer is **atuin**. It is a shell history tool that stores commands in a local SQLite database (capturing the command, exit code, working directory, hostname, and duration), replaces Ctrl+R and optionally up-arrow with a better search UI, and offers optional **end-to-end encrypted sync** between machines. As of November 2026, atuin has 32k+ GitHub stars on v18.24.5 and is actively maintained. It supports Fish, and your existing `fish_history` is not replaced. atuin imports it.

### Setup

1. Install the atuin binary (see the [official installation docs](https://docs.atuin.sh/latest/guide/installation/) for the one-liner for your OS).

2. Add the init snippet to `~/.config/fish/config.fish`, inside the interactive guard:

```fish
if status is-interactive
    atuin init fish | source
end
```

3. Register an account (or log in on additional machines):

```fish
atuin register -u <your-username> -e <your-email>
# On other machines: atuin login -u <your-username>
```

4. Import your existing Fish history:

```fish
atuin import auto
```

5. Sync:

```fish
atuin sync
```

**Verify:**

```fish
atuin stats
atuin history list | head
```

You should see your imported entries and usage stats. Press Ctrl+R and the atuin search UI should open.

<Button text="atuin documentation" link="https://docs.atuin.sh" variant="outline" color="gray" size="sm" icon="arrow-right" />

### Hardening and ops notes

<Notice type="info" title="Keep secrets out of your synced history">
atuin syncs everything it captures. Use <code>history_filter</code> in <code>~/.config/atuin/config.toml</code> to keep sensitive commands out of the shared store:
</Notice>

```toml
# ~/.config/atuin/config.toml
history_filter = [
    "password",
    "secret",
    "token",
    "api.key",
    "curl.*-u ",
]
```

Other things worth knowing. Your encryption key protects synced data: lose it and you lose sync access (the local store is fine), so back it up. atuin replaces Ctrl+R by default, but many operators keep native up-arrow and only bind atuin to Ctrl+R; the config switch exists in atuin's settings. If you do not want Atuin Cloud, you can run the sync server yourself. It runs fine on [an affordable VPS like Hetzner](https://go.bitdoze.com/hetzner). Good fit if you already have a small box for backups or monitoring. And if you want out, atuin keeps its own SQLite store and does not modify your `fish_history`. Uninstall it and your original history is untouched.

**Failure mode:** putting `atuin init fish | source` outside the `if status is-interactive` block causes errors on non-interactive shells (scripts, SCP, etc.). Always guard it.

**Cost note:** Atuin Cloud has a free tier and small paid plans for heavier use. Self-hosting the sync server costs whatever a small VPS runs, order of $5/month.

## Saving, appending and backing up the history file

### Saving history manually

```fish
history save
```

This forces an immediate write to disk. Fish auto-saves periodically and on exit, so you should not normally need this. The docs note it is "provided for internal use." Fish 4.1.0 added robustness improvements to the save routines, but relying on manual saves is not a substitute for understanding when Fish writes (on every command).

### Appending commands without running them

```fish
history append "some command I want to remember"
```

This adds the command to history without executing it. Useful for bookmarking commands you want to find later with Ctrl+R.

### Backup and restore

The history file is trivially portable:

```fish
cp ~/.local/share/fish/fish_history ~/fish_history_backup
```

To restore:

```fish
cp ~/fish_history_backup ~/.local/share/fish/fish_history
history merge
```

<Notice type="warning" title="Restoring old backups">
Fish rejects legacy 1.x-format history files. You will see "unsupported history file format 1.x" and the file will not load. If you are restoring a backup from a pre-3.0 Fish install onto a modern system, it silently will not work. Convert it or start fresh. Also: do not hand-edit <code>fish_history</code> while Fish sessions are open. Use <code>history delete</code> instead. Concurrent writes from an open session will clobber your edits.
</Notice>

**Verify:** after backing up, `head -2 ~/fish_history_backup` should show `- cmd:` entries. Restore to a scratch path first and inspect it before overwriting your live file.

If you manage dotfiles across machines, you can include the history file in your sync, but concurrent writes from multiple machines will cause conflicts. For real multi-machine sync, use atuin (see the [sync section](#syncing-fish-shell-history-across-machines-with-atuin) above).

## Useful history tips

**Use abbreviations instead of hunting history.** If you type a command every day, add it as an [abbreviation](/fish-shell-abbreviations-vs-aliases/) instead of searching for it each time.

**Combine with fzf.** The [fzf.fish plugin](/best-fish-shell-plugins/) replaces Ctrl+R with a fuzzy search that is faster to browse. It shows a preview and supports multi-select.

**Delete by pattern after secret rotation.** If you changed a password and the old one is in your history, `history delete --prefix "mysql -p"` cleans it up in one shot.

**Custom timestamps for audit lookups.** `history search --show-time="%Y-%m-%d %H:%M:%S " --max 20 docker` gives you a timestamped trail. Useful when you are reconstructing what happened on a box.

## FAQ

<Accordion label="Where does fish store its history file?" group="faq" expanded="true">
Fish stores history in `~/.local/share/fish/fish_history` (or `$XDG_DATA_HOME/fish/fish_history`). You can point a session at a different file with `set fish_history <name>`, which writes to `<name>_history` instead.
</Accordion>

<Accordion label="How do I delete one entry from fish history?" group="faq">
Three options: `history delete --exact --case-sensitive "<command>"` for a silent one-shot removal, `history delete <search-term>` for an interactive picker, or **Shift+Delete** while the entry is displayed (works during up-arrow search and for autosuggestions).
</Accordion>

<Accordion label="Does fish have a history size limit like HISTSIZE?" group="faq">
Yes. Fish caps history at 262,144 items (256 x 1024), enforced since fish 3.7.0. Oldest entries are trimmed when the cap is hit. There is no variable to change it.
</Accordion>

<Accordion label="How do I run a command without fish saving it?" group="faq">
Prefix the command with a space (built-in since fish 2.0.0). For an entire session, use `fish --private` or `set fish_history ""`. For programmatic filtering, define `fish_should_add_to_history`, but note that defining it disables the built-in leading-space rule unless your function re-implements it.
</Accordion>

<Accordion label="Why won't my old history backup load?" group="faq">
Fish rejects legacy 1.x-format history files ("unsupported history file format 1.x"). If your backup is from a pre-3.0 Fish install, it will not load on modern Fish. Start fresh or convert the file.
</Accordion>

<Accordion label="Does fish sync history between machines?" group="faq">
Not natively. The reliable answer is [atuin](#syncing-fish-shell-history-across-machines-with-atuin), which stores history in SQLite and offers end-to-end encrypted sync. Symlinking the raw `fish_history` file is fragile. Concurrent writes from multiple machines cause conflicts.
</Accordion>
