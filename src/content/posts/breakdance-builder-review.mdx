## What is Breakdance?

<Picture formats={["webp"]} fallbackFormat="webp" src={img1} alt="Breakdance Builder editor with elements panel and live preview" />

Breakdance is a full site builder from Soflyy, the same team behind Oxygen Builder and WP All Import. You control headers, footers, archive templates, blog layouts, and individual pages from one place. The editor runs on React, which keeps it snappy. Changes preview in real time without page reloads.

It works with any WordPress theme, but most people disable the active theme and let Breakdance handle everything. The Pro version ships 145 elements and connects to WooCommerce, ACF, and popular email marketing services. Soflyy has been building WordPress products for over 15 years, with 200,000+ active installations across their tools. Louis Reingold leads development. They built Oxygen first, then Breakdance as a more accessible version with a better UI and a flatter learning curve. Breakdance now has 100,000+ creators using it.

Dynamic data support means you can loop over posts, use ACF fields in templates, and display conditional content based on user roles or post categories. ## What's new in Breakdance 3.0: build with AI agents

Breakdance 3.0 shipped on October 26, 2026. The current maintenance release is 3.0.1 (October 28). The headline feature: you can now connect AI agents to your WordPress site over [Model Context Protocol (MCP)](/mcp-introduction-beginners/), the open standard that lets agents call external tools. If you've used MCP for [connecting Codex or Claude Code to external tools](/composio-mcp-guide/), the mental model is the same, but here the "tool" is your WordPress site.

Here's how it works. The agent writes HTML and CSS. Breakdance's conversion layer turns that into native Breakdance elements and global selectors through a new **Fundamentals** element category. The output stays a real Breakdance site, fully editable in the builder with breakpoints, CSS variables, and fonts preserved. Not pasted code you can never touch again.

Beyond agent building, 3.0 brought three more changes worth knowing about. The **Selectors panel** was overhauled: selectors now emit without the automatic `.breakdance` wrapper (a class like `.card` stays `.card` instead of becoming `.breakdance .card`), which means lower CSS specificity and cleaner output. Legacy selectors keep working in a separate panel with an optional one-click convert. **Global CSS Variables** now support any unit or string value. You can define `--section-spacing: 96px` and use it directly in Design controls, organized in collections. And click/hover/scroll **Interactions** are built in, so entrance animations no longer require custom code.

### Setting up Agents & MCP

The setup path is short. In your WordPress admin: **Breakdance > Settings > Agents & MCP**. Install and activate the **Agent Connector**, then click **Connect**. The Connection Wizard walks you through picking your agent: Claude, Codex, ChatGPT, Cursor, or anything that supports MCP. The RC 2 release added a setup wizard that takes a fresh install to a connected agent in a few clicks.

<ListCheck>
<ul>
<li>Admin access to the WordPress site</li>

<li>A backup or snapshot in place before the agent touches anything</li>
<li>Preferably a staging copy rather than your production site</li>

**Verify it works:** after connecting, ask the agent for a trivial page change (rename a heading, add a section). Open the Breakdance builder and confirm the change appears as editable Breakdance elements, not raw HTML blocks.

<Notice type="warning" title="Agent can't connect?">
Check the **"Enable MCP Access"** toggle in the same Agents & MCP settings screen. This is the documented first troubleshooting step. If that's off, nothing else matters.
</Notice>

### Security notes before you connect an agent

This is where the operator hat goes on. The Breakdance docs recommend installing **Universal Abilities** to give the agent full control of WordPress, including managing plugins, files, and site settings. That is a large blast radius. Some practical advice before you wire an agent into anything real:

<Notice type="warning" title="Universal Abilities = full WordPress control">
Installing Universal Abilities gives the agent access to plugins, files, and site settings. Treat this like handing someone root on your server. Only do it when you understand what the agent will touch.
</Notice>

<Notice type="info" title="Operator checklist before connecting">
Connect agents to a staging copy first. Use a dedicated admin user for the agent (not your main account). <a href="/best-free-wordpress-backup-plugins/" target="_blank" rel="noopener noreferrer">Back up your WordPress site first</a> before letting an agent run <code>replace_url</code>, <code>soft_reset</code>, or <code>total_reset</code>. MCP access runs through the WP admin of a public site, so standard hardening applies: HTTPS-only, restrict <code>/wp-admin</code>, and don't expose the connector wider than needed.
</Notice>

The official Security Considerations page in the Breakdance docs is worth reading before you enable anything: [breakdance.com/documentation](https://breakdance.com/documentation/).

## WP-CLI and automation

If you run WordPress on a VPS, say <a href="https://go.bitdoze.com/hetzner" target="_blank" rel="noopener noreferrer">Hetzner Cloud</a>, WP-CLI is already part of your toolkit. Since 2.7, Breakdance ships its own set of commands. This matters for repeatable deploys, migration scripts, and cache invalidation from CI.

```bash
wp breakdance status                 # mode + directory checks
wp breakdance clear_cache            # clears generated CSS, regenerates Global Settings CSS
wp breakdance replace_url 'https://old.example.com' 'https://new.example.com'
wp breakdance export_settings --file=breakdance_settings.json
wp breakdance import_settings breakdance_settings.json
wp breakdance license <key>          # also: wp breakdance license clear
wp breakdance theme off              # disable themeless toggle from CLI
wp breakdance soft_reset             # refresh setup resources (mutates site)
wp breakdance total_reset            # destructive; asks for confirmation
```

**Verify:** run `wp breakdance status` after install or after a migration. It checks the current mode and directory health. If something's off with permissions or paths, this is where you'll see it.

If you're self-hosting and need to [install WordPress with Docker Compose](/install-wordpress-docker/), WP-CLI is native to the container and these commands slot straight into your deploy routine.

<Notice type="warning" title="Exports are not backups, and some commands are destructive">
The docs explicitly warn: "Exports are not full backups; protect license keys." An export gives you settings, not your content or database. Also: <code>soft_reset</code> mutates the site (refreshes setup resources), and <code>total_reset</code> is destructive and prompts for confirmation. Never run <code>total_reset</code> on production as a "fix". <code>replace_url</code> is the safe migration path vs. raw SQL search/replace.
</Notice>

## How it works

The building model is simple: themeless by default, everything is a template. Headers, footers, archives, singles: all built in Breakdance and assigned by conditions.

### Setup

<Picture formats={["webp"]} fallbackFormat="webp" src={img4} alt="Breakdance theme selection on setup" />

On first install you choose whether to keep your WordPress theme or disable it. Disabling it gives you a clean canvas and avoids CSS conflicts. For most people, disabling the theme is the right call. You can also do it from the CLI with `wp breakdance theme off`.

### Global styles

<Picture formats={["webp"]} fallbackFormat="webp" src={img5} alt="Breakdance global settings panel" />

Set brand colors, typography, button styles, and container defaults once and they apply across the whole site. This is the right way to build: consistent design without manually touching every element. Version 2.8 added renameable color variables (call it `--brand-primary` instead of `--color-1`), and 3.0 extended this with **Global CSS Variables** that support any value type, so `--section-spacing: 96px` is usable directly in Design controls, organized in collections.

### Headers and footers

<Picture formats={["webp"]} fallbackFormat="webp" src={img6} alt="Breakdance header builder with dropdown menus" />

The header builder handles dropdown menus and mega menus without extra plugins. You can assign different headers to different page types. Building a multi-level nav takes minutes here.

### Forms, popups, dynamic data

Built-in form builder with 14+ field types, conditional logic, spam protection, and direct integrations with Mailchimp, ConvertKit, and others. No need for a separate forms plugin on most sites. That alone saves $50-80/year vs. a forms SaaS. Popups are also built in.

Dynamic data comes from WordPress core fields, custom post types, and ACF. The Post Loop Builder displays grids, lists, masonry, or sliders of posts filtered by category, tag, or custom query. Version 2.8 added conditional form emails per template and the `breakdance_form_validate_field` PHP filter for custom validation.

### Client editing

Breakdance has a "User Access" mode that lets clients edit content without touching styling. Works well for handing off a finished site without worrying that someone will break the design.

## Performance

Breakdance only loads CSS and JS for the elements used on each page. The React editor is fast, images lazy-load, and the output is clean. The performance story improved through 2026: version 2.7 cut the plugin download size by ~50%, and 3.0 produces cleaner selectors (no `.breakdance` wrapper, so lower CSS specificity and less to override):

```css
/* Before 3.0 */
.breakdance .card { padding: 24px; }

/* After 3.0 */
.card { padding: 24px; }
```

Legacy selectors keep working through the Legacy panel with an optional one-click convert, so existing custom CSS doesn't break.

For self-hosters, after big design changes run `wp breakdance clear_cache` to regenerate CSS. Server-side caching is where the biggest gains land once the builder output is clean. You can [stack Cloudflare, Varnish, and Redis on top](/speed-up-wordpress-with-cloudflare-varnish-and-redis/) of any WordPress install. If you want to take it further and [deploy Breakdance as a static WordPress site](/breakdance-kinsta-static-site/), that's the fastest path.

Cost order of magnitude: a small VPS runs ~$5-10/month, managed WordPress hosting ~$10-25/month, and a static deploy can hit free-tier pricing. If you'd rather not tune a server yourself, managed hosting like <a href="https://go.bitdoze.com/cloudways" target="_blank" rel="noopener noreferrer">Cloudways</a> handles the caching layer for you. For edge delivery, <a href="https://go.bitdoze.com/bunny" target="_blank" rel="noopener noreferrer">Bunny.net</a> is a solid CDN that pairs well with any of these.

<Notice type="info" title="Cache clearing after design changes">
Breakdance generates CSS per page. After major design or global-style changes, run <code>wp breakdance clear_cache</code> or use the built-in cache clear to make sure visitors see the updated styles immediately.
</Notice>
