## What you're actually buying (and why Multi-PAN died)

Two different smart-home roles use the same class of 802.15.4 radio chip and get conflated in Amazon titles:

- **A Zigbee coordinator** forms and controls your Zigbee 3.0 mesh. Either **ZHA** (built into Home Assistant) or **Zigbee2MQTT** talks to the coordinator, and every Zigbee sensor, dimmer, and plug routes through it.
- **A Thread border router (OTBR)** bridges Matter-over-Thread devices onto your home IP network.

Here is the rule that saves a weekend of troubleshooting: **one radio chip should run one protocol.** Two years ago, vendors advertised "multiprotocol" (Multi-PAN) firmware that time-sliced Zigbee and Thread on a single chip. It caused dropped packets and unstable meshes whenever both networks got busy, and Nabu Casa officially deprecated multi-protocol firmware as a result.

Today, a single-radio dongle like the SONOFF MG24 or Home Assistant Connect ZBT-2 runs **either** Zigbee **or** Thread depending on which firmware you flash. If you want both Zigbee and Thread, you have three clean choices:
1. Buy two USB dongles ($35.90 MG24 for Zigbee + $24.90 MG21 for Thread).
2. Use an existing Apple TV 4K or HomePod mini as your Thread border router (Home Assistant discovers Apple's Thread network automatically) and dedicate your dongle to Zigbee.
3. Buy a dual-radio PoE unit like the [SMLIGHT SLZB-MR1](/go/smlight-slzb-mr1/) that puts two physical radios in one enclosure.

The [Home Assistant hardware guide](/best-home-assistant-hardware/) covers the server side; this guide covers the radio.

## Chipsets in 2026: EFR32MG24 (`ember`) vs CC2652P (`zstack`)

If you read forum threads from 2022–2024, people warned against Silicon Labs ("Plus-E") dongles on Zigbee2MQTT because the old `ezsp` driver was marked experimental. That changed completely when Zigbee2MQTT introduced the modern **`ember` driver** (requiring NCP firmware 7.4.x / 8.0.x+).

| Chip family | Examples | Z2M `adapter:` setting | Status in 2026 |
| --- | --- | --- | --- |
| **Silicon Labs EFR32MG24** | SONOFF MG24, Dongle Max, HA ZBT-2 | `ember` | **Current top tier.** Fast, more RAM/flash for large meshes, first-class in both ZHA and Z2M. |
| **Silicon Labs EFR32MG21** | SONOFF Lite MG21, ZBDongle-E | `ember` | Proven budget generation; make sure it runs `ember`-compatible 7.4+ firmware. |
| **TI CC2652P / CC2652P7** | Older ZBDongle-P, classic SLZB-06 | `zstack` | Rock-solid Zigbee workhorse, weak Thread story. |

I run Zigbee2MQTT on my own Home Assistant box with a SONOFF coordinator, and moving onto an MG24-class stick with `ember` is as boring and reliable as smart-home radio gets.

## Placement matters more than antenna gain

Zigbee and Thread run on 2.4GHz, and active USB 3.0 ports and external SSD cables radiate broadband radio noise right across the 2.4GHz band — the [ZHA documentation warns about this explicitly](https://www.home-assistant.io/integrations/zha/#best-practices-to-avoid-pairingconnection-difficulties). Two rules fix 90% of dropped-sensor complaints:

1. **Never plug a USB dongle straight into the back of a mini PC or Pi.** Always use a 1–1.5m shielded USB 2.0 extension cable to move the radio away from USB 3 ports, metal cases, and SSD enclosures.
2. **Use a PoE network coordinator if your server is in a rack or basement.** My HA host sits in a rack next to my mini PCs and NAS — the worst possible RF environment. An Ethernet/PoE coordinator lets you mount the antenna in a central hallway while Home Assistant talks to its serial socket over TCP (`tcp://ip:6638`). It also eliminates USB passthrough headaches when migrating VMs across a [Proxmox cluster](/best-mini-pc-proxmox/).

## Day-one Zigbee2MQTT & ZHA setup: `by-id` paths, TCP sockets, and channel 25

Three configuration habits prevent the most common Home Assistant radio failures:

### 1. Always use `/dev/serial/by-id/` for USB dongles

Never configure ZHA or Zigbee2MQTT with `/dev/ttyUSB0` or `/dev/ttyACM0`. If you plug in a UPS cable or reboot the host, Linux can swap `ttyUSB0` and `ttyUSB1`, taking your entire Zigbee network down. Find the persistent hardware ID in your terminal (or HA's **Settings > System > Hardware > All Hardware**):

```bash
ls -l /dev/serial/by-id/
```

Then configure Zigbee2MQTT's `configuration.yaml` using that full path and the `ember` driver (for MG24 / MG21 / ZBT-2 sticks):

```yaml
serial:
  port: /dev/serial/by-id/usb-ITead_Sonoff_Zigbee_3.0_USB_Dongle_Plus_V2_...
  adapter: ember
  baudrate: 115200
  rtscts: false
```

### 2. Connecting a PoE / Ethernet coordinator over TCP

For network coordinators like the [SONOFF Dongle Max](/go/sonoff-dongle-max/) or [SMLIGHT SLZB-06U](/go/smlight-slzb-06u/), first give the coordinator a **DHCP reservation (static IP)** on your router so its IP never changes after a power outage. Then point Zigbee2MQTT directly at its TCP socket:

```yaml
serial:
  port: tcp://192.168.1.50:6638
  adapter: ember   # or zstack for CC2652P-based SLZB-06 models
```

### 3. Pick Zigbee channel 25 (or 20) before pairing devices

Zigbee channel numbers (11–26) and 2.4GHz Wi-Fi channels (1, 6, 11) use different numbering for the exact same frequency spectrum. By default, many coordinators start on Zigbee channel 11 or 15, which can collide with Wi-Fi channel 1 or 6.

| Your 2.4GHz Wi-Fi channels | Safest Zigbee channels | Why |
| --- | --- | --- |
| Wi-Fi on **1 and 6** (keep 11 light) | **Zigbee 25** (or 20) | Channel 25 sits at the top edge of the band, clear of Wi-Fi 1 and 6 |
| Wi-Fi on **1, 6, and 11** (crowded apartment) | **Zigbee 15 or 20** (or 25) | Channels 15 and 20 sit in the narrow guard bands between Wi-Fi 1/6 and 6/11 |

Set `channel: 25` in Zigbee2MQTT (or inside ZHA's network settings) **on day one before pairing sensors** — changing the Zigbee channel later often forces sleepy battery sensors to be manually re-paired.

## FAQ

<Accordion label="Do I need a Zigbee coordinator for Home Assistant?" group="faq" expanded="true">
Yes, if you want to pair Zigbee devices directly to Home Assistant without vendor hubs (like Philips Hue or Aqara bridges). Neither the Home Assistant Green nor a mini PC has a built-in 802.15.4 radio; a USB or PoE coordinator adds that radio for ZHA or Zigbee2MQTT.
</Accordion>

<Accordion label="Can one dongle run Zigbee and Thread at the same time?" group="faq">
No — not reliably. Nabu Casa deprecated experimental Multi-PAN firmware because sharing one radio chip between Zigbee and Thread caused dropped packets and mesh freezes. Dedicate one radio per protocol: either run two USB dongles, use an Apple TV / HomePod mini for Thread alongside a Zigbee stick, or buy a dual-radio PoE unit like the SMLIGHT SLZB-MR1.
</Accordion>

<Accordion label="ZHA or Zigbee2MQTT — which should I choose in 2026?" group="faq">
Both support the coordinators on this page. Choose **ZHA** if you want native one-click setup inside Home Assistant with zero extra containers. Choose **Zigbee2MQTT** if you want the widest device compatibility for brand-new sensors, richer exposed attributes, and a mesh that stays up independently when Home Assistant restarts.
</Accordion>

<Accordion label="What is the difference between SONOFF MG24, ZBDongle-E, and ZBDongle-P?" group="faq">
The **Dongle Plus MG24** is the newest 2025/2026 model built on Silicon Labs' EFR32MG24 chip (`ember` driver). The **ZBDongle-E** used the older EFR32MG21 chip, and the **ZBDongle-P** used Texas Instruments' CC2652P (`zstack` driver). For a new build today, buy the MG24.
</Accordion>

<Accordion label="Is an Ethernet / PoE coordinator better than a USB dongle?" group="faq">
Radio performance is identical once properly placed, but a PoE coordinator lets you mount the antenna in the middle of your house while your server stays in a basement or metal rack. It also connects over TCP/IP, so Proxmox high-availability migrations work without USB passthrough lock-in.
</Accordion>
