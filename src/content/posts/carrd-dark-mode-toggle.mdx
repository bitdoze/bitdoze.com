## Why Add Dark Mode to Your Carrd Site

Five reasons, one line each:

1. Reduced eye strain: dark interfaces are easier in low light.
2. Battery savings: on OLED screens dark pixels draw less power.
3. User preference: a lot of people simply prefer dark UI. The option is cheap respect.
4. Light sensitivity: some visitors genuinely need darker interfaces, and for them dark mode is an accessibility feature.
5. Modern expectation: every major app ships a dark theme now.

Dark mode is not a novelty anymore. Visitors look for the switch, and when it is missing they bounce to a site that has it.

## How Dark Mode Works on Carrd

Carrd has no built-in dark mode. I re-checked the docs and the changelog in September 2026: there is still no theme-switch feature. Custom code is the only path.

The approach here is the standard one:

1. A `data-theme` attribute on the page root (`light` or `dark`)
2. CSS variables for colors, swapped by `[data-theme="dark"]`
3. A toggle button that flips the attribute
4. `localStorage` so the choice survives reloads
5. `prefers-color-scheme` as the default before the visitor picks anything

The upgrade over a naive snippet is the **two-embed pattern**. Embed #1 is a tiny bootstrap in a Hidden → Head embed that sets `data-theme` before the page paints. Embed #2 holds the toggle UI and the click handler (Inline or Hidden → Body End).

<Notice type="info" title="Why two embeds?">
An all-in-one Inline embed applies the theme from JavaScript after the first paint. Dark-system users see a white flash on every load. The head bootstrap runs before paint, so the first frame is already the right theme.
</Notice>

Two embeds, then pick one of three toggle styles. Every block below is copy-pasteable.

<Notice type="warning" title="Style: Hidden, Location: Head (not Inline)">
The white-flash fix needs a Hidden embed targeted at the Head. An Inline-only setup makes it impossible, because Inline code renders in the page body after paint. We will use both styles: Hidden → Head for the bootstrap, Inline (or Hidden → Body End) for the toggle.
</Notice>

Paste this into the Code field:

```html
<script>
(function () {
  var t;
  try { t = localStorage.getItem('theme'); } catch (e) {}
  if (!t) t = window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
  document.documentElement.setAttribute('data-theme', t);
})();
</script>
<style>
  :root { color-scheme: light; }
  [data-theme="dark"] { color-scheme: dark; }
</style>
```

What it does:

- Reads `localStorage.theme` inside `try/catch`, so private modes that throw on storage access do not break the page
- Falls back to `prefers-color-scheme: dark` when the visitor never picked a theme
- Sets `data-theme` on the document root before first paint
- Emits `color-scheme: light|dark` so native form controls, scrollbars, and autofill follow the theme (`color-scheme` is supported in Chrome/Edge 81+, Firefox 96+, Safari 13+)

Carrd does not inject any `color-scheme` hint on published sites. I checked the raw HTML of a published sample in September 2026: nothing there. The snippet sets it itself. Do not assume the platform does it for you.

**Verify:** publish, open the site in an incognito window on a machine or phone set to dark mode. The page should come up dark with no white flash. If you still get a flash, the head embed is missing, mis-located, or you are looking at a cached page (hard refresh).

### Option 1: Floating Toggle Button

My default pick. A small fixed button in the corner, works with any layout, stays out of the way. This version swaps a single sun/moon emoji, keeps `aria-pressed` in sync, scopes transitions so first paint stays instant, respects `prefers-reduced-motion`, survives private-mode storage errors, follows live system theme changes, and adds a view-transition cross-fade where the browser supports it.

```html
<style>
  /* Light mode (default) colors */
  :root {
    --dm-bg-primary: #ffffff;
    --dm-bg-secondary: #f8fafc;
    --dm-text-primary: #1e293b;
    --dm-text-secondary: #64748b;
    --dm-border: #e2e8f0;
    --dm-accent: #3b82f6;
  }

  /* Dark mode colors */
  [data-theme="dark"] {
    --dm-bg-primary: #0f172a;
    --dm-bg-secondary: #1e293b;
    --dm-text-primary: #f1f5f9;
    --dm-text-secondary: #94a3b8;
    --dm-border: #334155;
    --dm-accent: #60a5fa;
  }

  /* Apply colors to Carrd elements */
  [data-theme="dark"] body,
  [data-theme="dark"] #wrapper,
  [data-theme="dark"] #main,
  [data-theme="dark"] section {
    background-color: var(--dm-bg-primary) !important;
  }

  [data-theme="dark"] h1,
  [data-theme="dark"] h2,
  [data-theme="dark"] h3,
  [data-theme="dark"] h4,
  [data-theme="dark"] p,
  [data-theme="dark"] span,
  [data-theme="dark"] li,
  [data-theme="dark"] a:not(.button) {
    color: var(--dm-text-primary) !important;
  }

  /* Style form inputs */
  [data-theme="dark"] input,
  [data-theme="dark"] textarea,
  [data-theme="dark"] select {
    background-color: var(--dm-bg-secondary) !important;
    color: var(--dm-text-primary) !important;
    border-color: var(--dm-border) !important;
  }

  /* Smooth transitions, scoped so the first paint is instant */
  @media (prefers-reduced-motion: no-preference) {
    [data-theme-ready] body,
    [data-theme-ready] #wrapper,
    [data-theme-ready] #main,
    [data-theme-ready] section,
    [data-theme-ready] h1,
    [data-theme-ready] h2,
    [data-theme-ready] h3,
    [data-theme-ready] h4,
    [data-theme-ready] p,
    [data-theme-ready] span,
    [data-theme-ready] li,
    [data-theme-ready] a:not(.button),
    [data-theme-ready] input,
    [data-theme-ready] textarea {
      transition: background-color 0.3s ease, color 0.3s ease, border-color 0.3s ease;
    }
  }

  /* Toggle button */
  .theme-toggle {
    position: fixed;
    bottom: 25px;
    left: 25px;
    width: 50px;
    height: 50px;
    border-radius: 50%;
    border: none;
    cursor: pointer;
    display: flex;
    align-items: center;
    justify-content: center;
    font-size: 24px;
    z-index: 9999;
    background: var(--dm-bg-secondary);
    box-shadow: 0 4px 15px rgba(0, 0, 0, 0.15);
    transition: transform 0.2s, background-color 0.3s;
  }

  .theme-toggle:hover {
    transform: scale(1.1);
  }

  .theme-toggle:focus-visible {
    outline: 2px solid var(--dm-accent);
    outline-offset: 2px;
  }
</style>

<button class="theme-toggle" id="themeToggle" aria-label="Toggle dark mode" aria-pressed="false">
  <span aria-hidden="true">☀️</span>
</button>

<script>
(function () {
  var toggle = document.getElementById('themeToggle');

  function apply(theme) {
    document.documentElement.setAttribute('data-theme', theme);
    document.documentElement.setAttribute('data-theme-ready', '');
    toggle.setAttribute('aria-pressed', theme === 'dark' ? 'true' : 'false');
    toggle.firstElementChild.textContent = theme === 'dark' ? '🌙' : '☀️';
  }

  function current() {
    return document.documentElement.getAttribute('data-theme') || 'light';
  }

  apply(current());

  toggle.addEventListener('click', function () {
    var next = current() === 'dark' ? 'light' : 'dark';
    try { localStorage.setItem('theme', next); } catch (e) {}
    if (document.startViewTransition) {
      document.startViewTransition(function () { apply(next); });
    } else {
      apply(next);
    }
  });

  window.matchMedia('(prefers-color-scheme: dark)')
    .addEventListener('change', function (e) {
      var saved = null;
      try { saved = localStorage.getItem('theme'); } catch (err) {}
      if (!saved) apply(e.matches ? 'dark' : 'light');
    });
})();
</script>
```

Notes on the moving parts:

- Transitions only apply after `data-theme-ready` is set on the root, so the initial theme does not animate in.
- `document.startViewTransition` is progressive enhancement (Chrome/Edge 111+, Firefox 144+, Safari 18+). Unsupported browsers just swap instantly.
- The system-change listener only runs when the visitor has no saved choice. Once they click the toggle, their pick wins until they clear it.
- Emoji render differently on Windows and older Android. If you want pixel-consistent icons, replace the `☀️` / `🌙` characters with inline SVG sun and moon shapes.

**Verify:** click the toggle and colors should cross-fade. Reload and the theme should stick (`localStorage.theme` holds `light` or `dark`). Tab to the button and you should see the focus ring, with `aria-pressed` flipping in DevTools → Elements.

### Dark Mode Design Tips

Test contrast. Text must stay readable on the dark background. Run the palette through a contrast checker when unsure.

Don't go pure black. `#000000` is harsh. Use dark grays like `#0f172a` or `#1e293b` instead.

Lighten your accent color. Colors that work on white often look muddy on dark. `#3b82f6` becomes `#60a5fa` in the palette above for exactly this reason.

Check every section. Walk the whole page in both themes. Some elements will need extra selectors (next section).

Consider images. Logos and graphics designed for white backgrounds may need a second version, a filter, or a subtle frame.

## Handling Carrd-Specific Elements and Images

Carrd generates stable structural selectors: `#wrapper`, `#main`, and `.inner` are present on published sites (verified in the raw HTML of a published sample in September 2026). Template-specific class names vary, so stubborn elements need extra targeting.

```css
/* Target specific Carrd elements */
[data-theme="dark"] .inner,
[data-theme="dark"] .content,
[data-theme="dark"] [class*="style1"],
[data-theme="dark"] [class*="style2"] {
  background-color: var(--dm-bg-primary) !important;
  color: var(--dm-text-primary) !important;
}

/* Target buttons (keep a:not(.button) for text links, style .button separately) */
[data-theme="dark"] .button.primary {
  background-color: var(--dm-accent) !important;
}

/* Target icons */
[data-theme="dark"] .icon {
  filter: brightness(0) invert(1);
}
```

<Notice type="warning" title="Template variance">
The `style1`…`style5` class names differ per template, and tricks like `[data-theme="dark"] .inner > * { background: transparent !important }` can wipe button and card backgrounds on some templates. Test on yours. If buttons lose their background in dark mode, remove that rule first. Nothing here is universal. Verify every override on your published page.
</Notice>

Background images do not respond to `background-color` overrides. If a section refuses to darken, the culprit is probably a background image. Swap it, or dim it with an overlay:

```css
[data-theme="dark"] img {
  opacity: 0.9;
  filter: brightness(0.95);
}

/* Or give images a subtle frame */
[data-theme="dark"] img {
  border: 1px solid var(--dm-border);
  border-radius: 8px;
}
```

If you run a sticky header, expect one clash: a still-light header bar on an otherwise dark page. The [sticky header for Carrd](https://www.bitdoze.com/add-stickey-header-carrd/) guide shows which selectors to hit so the bar darkens with the rest.

## Testing and Troubleshooting Your Carrd Dark Mode Toggle

Embeds render nothing in the builder, so every check below happens on the published site.

<ListCheck>
<ul>
<li>Publish, then open the site in an incognito window on a system set to dark: theme applies with no white flash</li>
<li>Click the toggle, reload: the choice persists in `localStorage` (key `theme`)</li>
<li>DevTools console is clean (no `Uncaught SecurityError` from `localStorage` in private mode)</li>
<li>Keyboard Tab reaches the toggle and the focus ring is visible</li>
<li>`aria-pressed` (or `aria-checked` on Option 2) flips in the Elements panel when you toggle</li>
<li>With no saved choice, switch the OS theme live: the page follows</li>
</ul>
</ListCheck>

If something misbehaves:

<Accordion label="White flash still appears" group="troubleshooting" expanded="true">
The head bootstrap is missing, set to the wrong location (it must be Style: Hidden, Location: Head), or you are looking at a cached copy. Confirm the embed exists with the right style and location, then hard-refresh or test in a private window. Also verify once on your own published site that the head code runs before paint. Carrd's injection order is worth a single end-to-end check since the builder will not show you.
</Accordion>

<Accordion label="Toggle clicks but nothing changes" group="troubleshooting">
Three usual suspects: a script error in the console (paste the whole code block again, unclosed tags are the common cause), the dark CSS selectors not matching your template, or the site not actually published after your edit. Check the console first, then inspect the `<html>` element. `data-theme` should flip when you click.
</Accordion>

<Accordion label="Buttons or cards lost their background in dark mode" group="troubleshooting">
That is the `[data-theme="dark"] .inner > * { background: transparent !important }` rule biting. It is template-dependent and often too aggressive. Remove it and give `.button` and card containers their own background overrides instead.
</Accordion>

<Accordion label="Toggle covers the mobile menu or social icons" group="troubleshooting">
`z-index: 9999` plus a corner position will overlap Carrd's chrome on small screens. Lower the z-index, or reposition the toggle to a free corner (see the positioning section). Test at phone width, not just desktop.
</Accordion>

<Accordion label="Some sections never change color" group="troubleshooting">
Either the template uses `styleN` classes your selectors miss, or the section background is an image. Inspect the element, add its class to the dark CSS block, and swap or dim background images. Inline SVG icons also ignore color overrides. Recolor them with `fill`/`stroke` rules or a `filter`.
</Accordion>

<Accordion label="Preference not saving or Uncaught SecurityError in console" group="troubleshooting">
Private browsing modes can block `localStorage`. The code wraps every read/write in `try/catch`, so the toggle still works for the session. It just cannot remember the choice. Nothing to fix; it degrades on purpose.
</Accordion>

<Notice type="info" title="Rollback">
Nothing outside the two embeds is modified. Delete both Embed elements and publish: the site is back to stock. To clear one visitor's stuck preference, open DevTools → Application → Local Storage and remove the `theme` key.
</Notice>
