## When to Use a Countdown Timer on Your Carrd Site

Countdown timers earn their place when a real deadline exists:

1. **Product launches** - building anticipation before release
2. **Sales and promotions** - a limited-time offer with a hard end
3. **Event registration** - signup deadlines
4. **Coming soon pages** - telling visitors when to come back
5. **Webinars and live events** - counting down to a start time

A ticking clock creates urgency that static text can't match. It also creates a hard requirement: for a launch or a sale, the timer has to hit zero at the same instant for every visitor. That detail trips people up, so don't skip the [timezone section](#setting-your-target-date-timezone-safe) below.

## How to Add a Custom Countdown Timer to Carrd

Every design in this article goes through the same element: the Embed. The flow never changes - add the element, set Type to Code, paste a snippet, publish.

### Step 1: Add an Embed Element (Type: Code, Style: Inline)

Click the `+` button in the builder and add an **Embed** element, then set:

- **Type:** Code
- **Style:** Inline

Paste your HTML/CSS/JS into the code field. `Inline` renders the countdown right where you placed the element in the layout. The other option, `Hidden`, injects the code into the page's Head, Body Top, or Body End - right for global scripts like analytics, wrong for a visible countdown. (Older tutorials mention an "Above" style; that option no longer exists.)

To find or re-edit the embed later, use the Elements Panel Carrd added in August 2026: **More Actions → Elements…** lists every element on the page, which beats hunting through a crowded layout.

<Notice type="warning" title="Embeds are invisible in the builder">
Carrd's docs say it plainly: the embed element doesn't output anything in the builder. A blank spot where your countdown should be is normal. Publish the site and it appears. This is the number one false alarm with custom code on Carrd.
</Notice>

### Step 2: Choose Your Countdown Style

Pick one of the five designs below and paste it into the embed's code field. The only edit you have to make is the target date at the top of the script, covered in [Setting Your Target Date](#setting-your-target-date-timezone-safe).

<Notice type="info" title="Running two timers on one page?">
Each snippet uses its own IDs (<code>countdown1</code>…<code>countdown5</code>), so different styles coexist. Two copies of the same style won't: duplicate IDs mean only the first timer ticks. Rename the numeric suffixes on the second one (<code>days1</code> → <code>days6</code>, <code>countdown1</code> → <code>countdown6</code>) and it works.
</Notice>

## Option 1: Modern Card Countdown Timer

Clean gradient cards with the label under each number. The hover lift is subtle and the cards wrap on mobile.

```html
<style>
  .countdown-modern {

    padding: 20px 0;
  }

  .countdown-item {
    background: linear-gradient(135deg, #667eea 0%, #764ba2 100%);
    border-radius: 16px;
    padding: 25px 20px;
    min-width: 100px;
    text-align: center;
    box-shadow: 0 10px 30px rgba(102, 126, 234, 0.3);
    transition: transform 0.3s;
  }

  .countdown-item:hover {
    transform: translateY(-5px);
  }

  .countdown-value {
    font-size: 48px;
    font-weight: 700;
    color: white;
    line-height: 1;
    margin-bottom: 8px;
  }

  .countdown-label {
    font-size: 14px;
    color: rgba(255, 255, 255, 0.8);
    text-transform: uppercase;
    letter-spacing: 2px;
  }

  @media (max-width: 500px) {
    .countdown-item {
      min-width: 70px;
      padding: 18px 15px;
    }
    .countdown-value {
      font-size: 32px;
    }
    .countdown-label {
      font-size: 11px;
    }
  }

  @media (prefers-reduced-motion: reduce) {
    .countdown-item {
      transition: none;
    }
    .countdown-item:hover {
      transform: none;
    }
  }
</style>

<div class="countdown-modern" id="countdown1" role="timer">
  <div class="countdown-item">
    <div class="countdown-value" id="days1">00</div>
    <div class="countdown-label">Days</div>
  </div>
  <div class="countdown-item">
    <div class="countdown-value" id="hours1">00</div>
    <div class="countdown-label">Hours</div>
  </div>
  <div class="countdown-item">
    <div class="countdown-value" id="minutes1">00</div>
    <div class="countdown-label">Minutes</div>
  </div>
  <div class="countdown-item">
    <div class="countdown-value" id="seconds1">00</div>
    <div class="countdown-label">Seconds</div>
  </div>
</div>

<script>
(function() {
  // March 1, 2027 at 09:00 UTC - Date.UTC months are 0-indexed too (2 = March)
  var targetDate = Date.UTC(2027, 2, 1, 9, 0, 0);

  function updateCountdown() {
    var distance = targetDate - Date.now();

    if (distance < 0) {
      clearInterval(iv);
      document.getElementById('countdown1').innerHTML = '<p style="font-size: 24px; font-weight: 700; color: #667eea;">Event has started!</p>';
      return;
    }

    var days = Math.floor(distance / 86400000);
    var hours = Math.floor((distance % 86400000) / 3600000);
    var minutes = Math.floor((distance % 3600000) / 60000);
    var seconds = Math.floor((distance % 60000) / 1000);

    document.getElementById('days1').innerHTML = (days < 10 ? '0' : '') + days;
    document.getElementById('hours1').innerHTML = (hours < 10 ? '0' : '') + hours;
    document.getElementById('minutes1').innerHTML = (minutes < 10 ? '0' : '') + minutes;
    document.getElementById('seconds1').innerHTML = (seconds < 10 ? '0' : '') + seconds;
  }

  var iv = setInterval(updateCountdown, 1000);
  updateCountdown();
})();
</script>
```

**To customize:** change the `Date.UTC(2027, 2, 1, 9, 0, 0)` line. It's the one line you edit. Months are 0-indexed (January = 0, March = 2). Publish and watch it tick; if it shows "Event has started!" on load, your target date is in the past.

## Setting Your Target Date (Timezone-Safe)

Every snippet sets its deadline on one line:

```javascript
var targetDate = Date.UTC(2027, 2, 1, 9, 0, 0);
```

This is the line you change. `Date.UTC(year, month, day, hour, minute, second)` takes the same arguments as `new Date(...)`, and months are still 0-indexed: January = 0, March = 2, December = 11.

Future-dated examples:

- March 1, 2027 at 09:00 UTC: `Date.UTC(2027, 2, 1, 9, 0, 0)`
- December 25, 2027 at 09:00 UTC: `Date.UTC(2027, 11, 25, 9, 0, 0)`
- July 4, 2027 at 18:00 UTC: `Date.UTC(2027, 6, 4, 18, 0, 0)`

One habit that saves you a republish: while testing, pick a date comfortably in the future. A countdown whose target already passed renders its expiry message on load, which looks broken even though the code is fine. When the real date is set, roll the year instead of leaving an old date in place.

### Visitor-Local vs UTC Deadlines

`Date.UTC(...)` and `new Date(y, m, d)` look interchangeable but aren't:

- `new Date(2027, 2, 1)` counts down to midnight **in each visitor's timezone**. A visitor in London hits zero five hours before a visitor in New York. For a global deadline (a launch, a sale end, a webinar start), that's a real bug: some visitors see "Sale has ended!" while others still see hours left.
- `Date.UTC(2027, 2, 1, 9, 0, 0)` is one fixed instant. Every visitor's timer hits zero at the same moment; each browser just renders the remaining time against its own clock.

Rule of thumb: global deadline → `Date.UTC`. Local event (doors open, in-store promo) → visitor-local `new Date(y, m, d)` is fine.

<Tabs>
<Tab name="Date.UTC">

```javascript
var targetDate = Date.UTC(2027, 2, 1, 9, 0, 0);
```

</Tab>
<Tab name="ISO string">

```javascript
var targetDate = new Date("2027-03-01T09:00:00Z").getTime();
```

</Tab>
</Tabs>

Both are the same instant: March 1, 2027 at 09:00 UTC. Pick whichever syntax you'd rather read six months from now.

<Notice type="info" title="The month is 0-indexed">
In both `new Date(y, m, d)` and `Date.UTC(y, m, d, ...)`, January is month 0 and December is month 11. It bites everyone once. If your countdown is off by exactly a month, this is why.
</Notice>

## What Happens When the Countdown Ends

Every snippet swaps the timer for a message at zero and stops its own interval, so it doesn't keep ticking invisibly forever. Two patterns cover most needs:

<Tabs>
<Tab name="Show a message">

```javascript
if (distance < 0) {
  clearInterval(iv);
  document.getElementById('countdown1').innerHTML = '<p>We are live!</p>';
  return;
}
```

</Tab>
<Tab name="Redirect on expiry">

```javascript
if (distance < 0) {
  clearInterval(iv);
  window.location.href = 'https://yoursite.com/launch';
  return;
}
```

</Tab>
</Tabs>

<Notice type="info" title="Stop the clock">
`setInterval` keeps firing after expiry unless you clear it. The `clearInterval(iv)` call in these snippets shuts the timer down the moment the message or redirect runs. Without it, the interval ticks on doing nothing.
</Notice>

Point the redirect at a page on your own [custom domain](https://www.bitdoze.com/carrd-add-domain/) so the URL survives a redesign. Pro Plus ($49/yr) also ships native Redirects and a Framing option under Publish → Settings, but a three-line JavaScript redirect inside the embed is enough for most countdowns.

One security note, in case you're weighing an iframe-based timer instead: published Carrd sites send `content-security-policy: frame-ancestors https://carrd.com` and `x-frame-options: deny`. That only restricts who can iframe your Carrd page. Inline scripts like these snippets run fine, and so do third-party widget scripts.

## Troubleshooting and FAQ

<Accordion label="Why is my countdown not showing in the Carrd builder?" group="faq">
Embed elements render nothing in the builder - Carrd's docs state this directly. Publish the site and hard-refresh the live page. If it's still blank after publishing, open DevTools and check the console for a script error.
</Accordion>

<Accordion label="Why does my countdown immediately say 'Event has started!'?" group="faq">
Your target date is in the past. Check the `Date.UTC(...)` line at the top of the script and roll it forward. Remember the month is 0-indexed: `Date.UTC(2027, 2, 1)` is March 1, 2027, not February 1.
</Accordion>

<Accordion label="Why does my countdown hit zero at the wrong time?" group="faq">
You probably used `new Date(y, m, d)`, which counts down to midnight in each visitor's local timezone. For a deadline that must hit at the same instant worldwide, switch to `Date.UTC(y, m, d, h, min, s)` or `new Date("2027-03-01T09:00:00Z").getTime()`.
</Accordion>

<Accordion label="Do I need a paid plan for a Carrd countdown timer?" group="faq">
Yes. The Embed element requires Pro Standard or higher, $19/year minimum. Free and Pro Lite plans can't add custom code at all, so there's no free-tier workaround inside Carrd.
</Accordion>

<Accordion label="Can I add two or more countdowns to one page?" group="faq">
Yes. Different styles coexist because their IDs differ (`countdown1` through `countdown5`). Two copies of the same style collide - rename the numeric suffixes on the second timer's IDs and update the script to match.
</Accordion>

<Accordion label="Why does the flip clock show the wrong days after 100 days?" group="faq">
The days field has two digit-cards, so it can't display a three-digit number. `pad2(150)` returns "150" and `dStr[1]` grabs the middle digit. The snippet clamps it with `Math.min(days, 99)`, or you can add a third card for real triple digits.
</Accordion>

<Accordion label="Are these countdown snippets accessible?" group="faq">
Mostly, yes. Each container has `role="timer"`, and the animated styles include a `prefers-reduced-motion` guard that kills the flip and hover effects for users who opt out. Don't add `aria-live` to a per-second timer; a live region announcing every tick is worse than announcing nothing.
</Accordion>
