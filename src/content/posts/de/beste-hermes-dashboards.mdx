Hermes Agent von Nous Research ist der am schnellsten wachsende Open-Source-AI-Agent auf GitHub mit über 214K Stars. Der Kern-Agent ist CLI-first: Er läuft aus deinem Terminal mit `hermes` oder in einer vollen TUI mit `hermes --tui`. Das ist großartig für Entwickler, die im Terminal leben. Aber du musst deinen Agent auch von einem Browser-Tab bei der Arbeit, einem Handy auf dem Sofa oder einem Tablet im Café checken.

Das Ökosystem hat mit Dashboard-Web-UIs, Desktop-Apps, Android-Apps, iOS-Apps und Messaging-Integrationen reagiert. Es gibt inzwischen über 10 Wege, außerhalb des Terminals mit Hermes Agent zu interagieren. Dieser Guide vergleicht jede wichtige Option, damit du die richtige für deinen Workflow wählst.

## Die besten Hermes-Agent-Web-Dashboards

Web-Dashboards laufen im Browser und sind ideal für Remote-Verwaltung von jedem Gerät. Du kannst sie auf einem VPS selbst hosten, lokal laufen lassen oder per SSH tunneln. Die Hauptoptionen unten decken alles vom offiziellen eingebauten Panel bis zu vollen IDE-artigen Workspaces ab.

### Offizielles Hermes-Web-Dashboard

Das eingebaute Dashboard ist Teil des Hermes-Kernpakets (kommt mit Hermes Agent v0.16+). Starte es mit `hermes dashboard` und du bekommst ein FastAPI/Uvicorn-Backend mit einem React-19- + TypeScript- + Tailwind-Frontend auf Port 9119.

**Was du bekommst:**

- **Statusseite:** Live-Übersicht mit Auto-Refresh alle 5 Sekunden
- **Chat:** eingebettete PTY-backed TUI via WebSocket, volles Terminal-Erlebnis im Browser
- **Config-Editor:** formularbasierter YAML-Editor mit über 150 Feldern, kein manuelles Dateieditieren mehr
- **Sessions:** Konversationsverlauf durchsuchen (FTS5), exportieren und aufräumen
- **Logs:** Agent-, Gateway- und Fehler-Logs mit Level-/Komponenten-Filterung und Live-Tail
- **Analytics:** Token-Verbrauch über 7/30/90 Tage, Kosten-Tracking, Aufschlüsselung pro Modell
- **Cronjobs:** geplante Aufgaben anlegen, pausieren/fortsetzen, triggern und bearbeiten
- **Skills & MCP:** Skills durchsuchen und togglen; MCP-Server hinzufügen/testen/aktivieren/deaktivieren
- **Profile:** Agent-Profile erstellen, wechseln, klonen, verwalten
- **API-Keys:** Env-Var-Manager mit geschwärzten Anzeigewerten
- **Gateway-Gesundheit:** Status von über 20 Messaging-Plattform-Verbindungen überwachen

Auth-Optionen sind OAuth via Nous Portal, Benutzername/Passwort und selbstgehostetes OIDC. Sechs eingebaute Themes plus ein Custom-Theme-System sind dabei.

Voraussetzung: Installiere zuerst die Web- und PTY-Extras.

```bash
pip install -e ".[web,pty]"
```

- Chat-Skin-Option (Labs): Terminal-UI oder Chat-Bubbles mit Tool-Cards und Foto-Anhängen

### Langlebige Aufgaben und Push-Benachrichtigungen

Es gibt keine weit verbreitete standalone „Hermes Dispatch"-App mit öffentlichem Installationsweg, die an die großen Dashboards oben heranreicht. Für Hintergrundarbeit und Handy-Benachrichtigungen nutze stattdessen den offiziellen Stack:

- **Hermes Kanban / async Subagents** auf dem Server für langlebige Jobs, die Handy-Disconnects überstehen (siehe [Hermes-Kanban-Setup-Anleitung](/de/hermes-kanban-einrichten/))
- **ntfy** als Hermes-Messaging-Kanal für Push-Alerts auf Android/iOS ([offizielle ntfy-Doku](https://hermes-agent.nousresearch.com/docs/user-guide/messaging/ntfy))
- **Telegram-/Discord-Gateway** für Fire-and-forget-Aufgabennachrichten ohne weiteren Client

Wenn der Agent ein Android-Gerät steuern soll (ADB-artige Fernsteuerung), schau dir Community-Bridge-Projekte wie [raulvidis/hermes-android](https://github.com/raulvidis/hermes-android) an. Das ist eine Device-Control-Bridge, kein Chat-Dashboard.

**Ideal für:** Serverseitige Langläufer-Jobs mit Handy-Alerts, ohne auf ein mobiles Nischenprodukt angewiesen zu sein.

iOS-Sandboxing verhindert, dass Hermes Agent direkt auf einem iPhone oder iPad läuft. Alle iOS-Apps sind Clients, die sich per SSH oder API mit einer Remote-Hermes-Instanz verbinden. Du brauchst also zuerst ein irgendwo laufendes Hermes. Wenn du einen kostenlosen API-Key zum Starten brauchst, schau dir an, wie man [Hermes Agent mit kostenlosen Modellen auf Nous Portal](/hermes-agent-mimo-v2-pro/) einrichtet.
</Notice>

### ScarfGo

Der native iOS-Begleiter zur Scarf-macOS-App ([awizemann/scarf](https://github.com/awizemann/scarf)). Verfügbar via TestFlight, erfordert iOS 18.0+. Nutzt SSH für die Verbindung über die Citadel-Library, es wird also kein ssh-Binary auf dem Gerät gebraucht.

**Funktionen:**

- Ed25519-Schlüsselpaar in der iOS-Keychain
- Multi-Server-Support
- Projekt-bezogener Chat
- Session-Resume
- Memory-Editor, Cron-Liste, Skills-Tree
- Profil-Wechsel (ScarfGo v2.13+)
- Voice-Chat-Support
- Connection-Pooling pro Server

**Ideal für:** Nutzer, die Scarf schon unter macOS laufen haben und dasselbe Erlebnis auf dem iPhone wollen. Die macOS-App und der iOS-Begleiter sind füreinander gebaut.

### Onepilot

Eine native iOS-App im App Store (Freemium): [Onepilot: AI agents & SSH](https://apps.apple.com/am/app/onepilot-ai-agents-ssh/id6759485908). Unterstützt iPhone und iPad. Doku: [onepilotapp.com/agents/hermes](https://onepilotapp.com/agents/hermes). Das kommt einem vollen Entwicklungs-Cockpit auf iOS am nächsten.

**Was sie kann:**

- Deployed Hermes über SSH mit einem geführten Wizard
- Echtes Terminal (nicht nur Chat-Oberfläche)
- Syntax-gehighlighteter Datei-Browser
- Git-Tab mit Diffs
- Cron-Verwaltung
- Unterstützt außerdem OpenClaw, Claude Code und Codex CLI
- Verdrahtet Telegram/Discord/Slack während des Deployments

Wie die Entwickler es sagen: „There is no official Hermes app." Onepilot positioniert sich als das Nächstbeste. Der SSH-Tunnel gibt dir vollen Host-Zugriff (Dateien, Shell, Git), du kannst also mehr als nur mit dem Agent chatten.

**Ideal für:** iOS-Nutzer, die eine volle Entwicklungsumgebung auf Handy oder Tablet wollen, nicht nur eine Chat-Oberfläche.

### Hermes AI: Personal Agent

Eine unabhängige iOS-App von Ilya Vishneuski ([App Store](https://apps.apple.com/us/app/hermes-ai-personal-agent/id6759341434)). Erfordert iOS 17.0+ (auch gelistet für Mac mit Apple Silicon und visionOS). 11,9 MB Download. Nicht mit Nous Research affiliiert.

**Funktionen:** Echtzeit-Chat, Task-Tracking und Output-Review, sensible Aktionen genehmigen/ablehnen, sichere Session-Verwaltung über Geräte hinweg. Bietet eine Managed-Agent-Abo-Option für Nutzer, die nicht selbst hosten wollen.

<Notice type="warning" title="Premium-Preise">
App-Store-In-App-Käufe listen Premium aktuell bei etwa 19,99 $ und 199,99 $ (Tiers können sich ändern). Das Free-Tier ist begrenzt. Vergleiche diese Kosten sorgfältig mit kostenlosen Self-Hosted-Clients wie ScarfGo oder Hermes Mobile, bevor du dich festlegst.
</Notice>

**Ideal für:** Nutzer, die ein gemanagtes Hermes-Abo-Erlebnis auf iOS wollen, statt sich mit dem eigenen Server zu verbinden.

### Hermes Mobile von uzairansar

Ein nativer iOS-Client in der TestFlight-Beta ([uzairansar.com/hermes-mobile](https://www.uzairansar.com/hermes-mobile)), gebaut mit SwiftUI. Verbindet sich mit einer selbstgehosteten Hermes-WebUI-Instanz. Er stellt kein gehostetes Backend bereit.

**Funktionen:**

- Sessions vom iPhone wieder öffnen
- Antworten live streamen
- Fotos, Dateien und Share-Sheet-Inhalte anhängen
- Modell, Reasoning-Level, Workspace und Run-Optionen wählen
- Projektdateien durchsuchen
- Tasks, Skills, Memory und Nutzungsstatistiken ansehen

**Ideal für:** Nutzer, die Hermes WebUI schon selbst hosten und einen nativen iOS-Client zur Interaktion wollen.

## Mobiler Zugriff über Messaging-Kanäle

Der einfachste Weg, Hermes auf dein Handy zu bekommen: Nutze das eingebaute Messaging-Gateway. Keine extra Apps zu installieren; chatte einfach über Telegram, Discord, WhatsApp, Signal oder Slack mit deinem Agent.

<Notice type="info" title="Schnellster Weg zum mobilen Zugriff">
Telegram ist der schnellste Weg, Hermes auf dein Handy zu bekommen. Setup dauert unter 5 Minuten und du bekommst Cross-Device-Sync, Voice-Memos und dieselbe Chat-App, die du vermutlich eh offen hast.
</Notice>

| Kanal | Setup | Vorteile | Nachteile |
|---|---|---|---|
| Telegram | Niedrig | Schnellster Weg, Voice-Memos, Cross-Device-Sync | Einzel-Session-Ansicht, Verzögerung durch Nachrichten-Warteschlange |
| Discord | Niedrig | Reactions, Threads, Kanal pro Thema | Mehr Setup als Telegram |
| WhatsApp | Mittel | Hat jeder | Erfordert Telefonnummer und Kopplung |
| Signal | Mittel | Datenschutzfokussiert | Weniger funktionsreich |
| Slack | Mittel | Teamfreundlich, Kanäle | Erfordert Workspace |

Das Setup ist unkompliziert:

```bash
# Configure the messaging gateway
hermes gateway setup
# Follow prompts for your platform (e.g., Telegram bot token)

# Start the gateway
hermes gateway start
```

**Telegram-Limitierungen**, die man aus dem Community-Feedback kennen sollte: Du bekommst nur eine Einzel-Session-Ansicht, es gibt eine Verzögerung durch die Nachrichten-Warteschlange, keinen sichtbaren Token-Zähler oder Modell-Info, und Context-Window-Resets werden nicht kommuniziert. Für gelegentliche Nutzung super. Für schwere Entwicklungsarbeit nimm ein richtiges Dashboard oder eine Desktop-App.

## Sicherheitsüberlegungen für Remote-Zugriff

Jedes dem Netzwerk exponierte Dashboard oder jede Mobile-App braucht richtige Sicherheit. Das ist nicht verhandelbar: Ein Hermes-Dashboard ohne Auth gibt jedem volle Kontrolle über deinen Agent, deine API-Keys und potenziell deinen Server.

<Notice type="error" title="Niemals ohne Auth exponieren">
`hermes dashboard --host 0.0.0.0` ohne aktivierte Authentifizierung laufen zu lassen ist eine offene Hintertür. Kombiniere öffentlich erreichbare Dashboards immer mit Auth und HTTPS.
</Notice>

### SSH-Tunnel (am einfachsten)

Der einfachste sichere Weg ist, den Dashboard-Port durch SSH zu tunneln:

```bash
# Tunnel WebUI (port 8787)
ssh -N -L 8787:127.0.0.1:8787 user@your-server

# Tunnel Official Dashboard (port 9119)
ssh -L 9119:localhost:9119 user@your-vps

# Then open http://localhost:8787 or http://localhost:9119 locally
```

### Tailscale (am sichersten für den Alltag)

Installiere Tailscale auf deinem Server und Handy/Laptop. Greif über die Tailscale-IP auf das Dashboard zu. Keine Ports zum öffentlichen Internet exponiert. Der Hermes Android Client hat eingebauten Tailscale-Support.

### Passwortschutz

```bash
# Password protect the official dashboard
cat >> ~/.hermes/.env <<'EOF'
HERMES_DASHBOARD_BASIC_AUTH_USERNAME=admin
HERMES_DASHBOARD_BASIC_AUTH_PASSWORD=your-strong-password
HERMES_DASHBOARD_BASIC_AUTH_SECRET=$(openssl rand -base64 32)
EOF
chmod 600 ~/.hermes/.env
hermes dashboard --host 0.0.0.0 --no-open
```

### Auth-Support nach Dashboard

| Dashboard | Passwort | OIDC | WebAuthn/Passkeys |
|---|---|---|---|
| Offizielles Dashboard | Ja | Ja (selbstgehostet) | Nein |
| Hermes WebUI | Ja | Ja | Ja |
| Hermes Studio | Ja | Nein | Nein |
| Hermes Workspace | Ja | Je nach Deployment | Nein |
| Hermes Control Interface | Ja (bcrypt + RBAC) | Nein | Nein |
| Scarf | macOS-Keychain | Nein | Nein |

Für das komplette Security-Setup inklusive Caddy-Reverse-Proxy-Konfiguration und Docker-Networking siehe unsere [Hermes-Agent-Dashboard-Setup-Anleitung](/hermes-dashboard-guide/).

## FAQ

<Accordion label="Gibt es eine offizielle Hermes-Agent-Mobile-App?" group="faq" expanded="true">
Nein. Es gibt keine offizielle Mobile-App von Nous Research. Das gesamte mobile Ökosystem ist Community-gebaut. Offizielle Kanäle sind CLI, das Web-Dashboard (`hermes dashboard`) und die Desktop-App (`hermes desktop`). Alle Android- und iOS-Apps in diesem Guide sind Drittanbieter-Projekte.
</Accordion>

<Accordion label="Kann ich Hermes Agent auf meinem Handy laufen lassen?" group="faq">
Auf Android, ja. Hermes Agent Android (Google Play) führt die volle Hermes-Runtime direkt auf dem Gerät aus. Du brauchst deinen eigenen API-Key und etwa 200 MB Speicher. Auf iOS, nein. iOS-Sandboxing verhindert, dass Hermes direkt läuft. Alle iOS-Apps verbinden sich per SSH oder API mit einer Remote-Hermes-Instanz.
</Accordion>

<Accordion label="Was ist das beste kostenlose Hermes-Dashboard?" group="faq">
Das offizielle eingebaute Dashboard (`hermes dashboard`) und Hermes WebUI von nesquena sind beide kostenlos und exzellent. Das offizielle ist am einfachsten aufzusetzen, weil es schon bei Hermes dabei ist. Hermes WebUI ist sparsamer mit Ressourcen (kein Build-Schritt, kein Framework) und mobiler responsiver. Wenn du auch einen kostenlosen API-Key brauchst, schau dir an, wie man [Hermes Agent mit kostenlosen Modellen auf Nous Portal](/hermes-agent-mimo-v2-pro/) einrichtet.
</Accordion>

<Accordion label="Wie greife ich remote auf mein Hermes-Dashboard zu?" group="faq">
Drei Optionen, von einfach bis aufwendig: (1) SSH-Tunnel: `ssh -L 9119:localhost:9119 user@your-vps`, dann localhost:9119 öffnen. (2) Tailscale: auf beiden Geräten installieren, über die Tailscale-IP zugreifen. (3) Reverse Proxy mit Auth: Caddy oder Nginx mit HTTPS und Basic Auth oder OIDC. Exponiere ein Dashboard niemals öffentlich ohne Authentifizierung.
</Accordion>

<Accordion label="Welches Hermes-Dashboard verbraucht die wenigsten Ressourcen?" group="faq">
Hermes WebUI von nesquena. Es nutzt Pythons Standard-Library-HTTP-Server und Vanilla-JavaScript – kein Node.js, kein Bundler, kein Framework. Der Start ist schnell und der Speicherverbrauch minimal im Vergleich zu den React-/Vue-basierten Alternativen.
</Accordion>

<Accordion label="Kann ich mehrere Dashboards gleichzeitig nutzen?" group="faq">
Ja. Dashboards sind unabhängige Webanwendungen auf verschiedenen Ports. Du kannst das offizielle Dashboard auf Port 9119, Hermes WebUI auf 8787, Hermes Studio auf 8648, Hermes Workspace auf 3000 und HCI auf 10274 gleichzeitig laufen lassen. Sie lesen alle aus demselben Hermes-Datenverzeichnis, Sessions, Config und Profile sind also geteilt.
</Accordion>

<Accordion label="Ist Hermes Studios BSL-1.1-Lizenz ein Problem?" group="faq">
Für persönliche Nutzung nicht. Für kommerzielle Nutzung prüfe die Lizenzbedingungen. BSL-1.1 (Business Source License) schränkt kommerzielle Nutzung typischerweise für eine feste Zeit ein (oft 2–4 Jahre), danach konvertiert sie zu MIT. Brauchst du ein voll MIT-lizenziertes Dashboard für kommerzielle Nutzung, nimm stattdessen das offizielle Dashboard oder Hermes WebUI.
</Accordion>
