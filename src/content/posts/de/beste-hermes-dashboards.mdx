## Die besten Hermes-Agent-Web-Dashboards

Web-Dashboards laufen im Browser und eignen sich für Remote-Verwaltung von jedem Gerät. Du kannst sie auf einem VPS selbst hosten, lokal laufen lassen oder per SSH tunneln. Die Optionen unten beginnen mit den beiden offiziellen, dem Admin-Dashboard und der Webapp, und decken danach vier Community-Projekte bis hin zu einem vollen IDE-artigen Workspace.

### Offizielles Hermes-Web-Dashboard

Das eingebaute Dashboard ist Teil des Hermes-Kernpakets (kommt mit Hermes Agent v0.16+; v0.23.4 ist das aktuelle Release, Stand November 2026). Starte es mit `hermes dashboard` und du bekommst ein FastAPI/Uvicorn-Backend mit einem React-19- + TypeScript- + Tailwind-Frontend auf Port 9119.

Was du bekommst:

- Eine Statusseite mit Live-Übersicht, die sich alle 5 Sekunden selbst aktualisiert
- Ein Chat-Tab, das die PTY-gestützte TUI über WebSocket einbettet, also volles Terminal-Erlebnis im Browser
- Ein formularbasierter Config-Editor, der die 150+ Felder von `config.yaml` abdeckt
- Session-Browsing mit FTS5-Suche, Export und Aufräumen
- Agent-, Gateway- und Fehler-Logs mit Level- und Komponentenfiltern und Live-Tail
- Token-Analytics für 7, 30 oder 90 Tage, mit Kosten-Tracking und Aufschlüsselung pro Modell
- Eine Cron-Seite zum Planen, Pausieren, Fortsetzen, Triggern und Bearbeiten von Jobs über alle Profile
- Skills- und MCP-Seiten zum Durchsuchen und Togglen von Skills sowie zum Hinzufügen, Testen, Aktivieren und Deaktivieren von MCP-Servern
- Profile erstellen, wechseln und klonen, dazu Seiten für API-Keys, Webhooks, Pairing und Kanäle
- Eine System-Seite mit Host-Metriken, Update-Badge, Gateway-Start/Stop/Neustart und `doctor`, Security-Audit, Backup und Restore mit einem Klick

Als Auth gibt es OAuth via Nous Portal, Benutzername/Passwort und selbstgehostetes OIDC; ein Bind an eine Nicht-Loopback-Adresse startet ohne eines davon nicht (Details im Security-Abschnitt unten). Acht eingebaute Themes sind dabei, und du kannst ein eigenes Theme oder Plugin hinzufügen, ohne zu forken.

Voraussetzung: Installiere zuerst die Web- und PTY-Extras.

```bash
pip install -e ".[web,pty]"
```

**Ideal für:** Selbstgehostetes Management mit dem einfachsten Setup und ohne Extra-Abhängigkeiten.

**Kompromisse:** Ein Bind an eine Nicht-Loopback-Adresse startet ohne Auth-Provider nicht.

#### Themes und Plugins

Das Dashboard bringt acht eingebaute Themes mit: Hermes Teal, Hermes Teal Large, Nous Blue, Midnight, Ember, Mono, Cyberpunk und Rosé. Du musst nichts forken, um weiterzukommen. Die Seite [Extending the Dashboard](https://hermes-agent.nousresearch.com/docs/user-guide/features/extending-the-dashboard) dokumentiert drei Ebenen zum Einstecken:

- Ein Theme ist eine YAML-Datei in `~/.hermes/dashboard-themes/`. Jedes Feld ist optional, ein Theme kann also aus nur zwei Farben bestehen. Es kann Palette, Typografie, Layout (Radius, Dichte und die Varianten `standard`, `cockpit` und `tiled`), Bild-Assets, Chrome pro Komponente und rohes CSS setzen.
- Ein UI-Plugin ist ein Verzeichnis mit einer `manifest.json` und einem vorgebauten JavaScript-Bundle in `~/.hermes/plugins/<name>/dashboard/`. Es kann einen Tab hinzufügen, eine eingebaute Seite ersetzen, über Slots Widgets in eine eingebaute Seite injizieren oder Shell-Slots füllen. Es ruft das SDK auf `window.__HERMES_PLUGIN_SDK__` auf, statt React mitzubündeln.
- Ein Backend-Plugin ist eine Python-Datei mit einem FastAPI-Router. Ihre Routen werden unter `/api/plugins/<name>/` eingehängt.

Alle drei werden zur Laufzeit geladen, ohne Repo-Klon und ohne Build des Dashboards selbst. Die Desktop-App hat ein eigenes Plugin-SDK (`@hermes/plugin-sdk`), ein Dashboard-Plugin funktioniert also nicht in Desktop.

### Offizielle Webapp: der Desktop-Workspace im Browser

Das Gateway kann den Desktop-Workspace an einen normalen Browser ausliefern. Die Doku ist deutlich, was es ist: das ist nicht das Web Dashboard. Du bekommst die chat-first Desktop-UI mit Sessions, Profilen, Capabilities, Messaging, Artifacts, geplanten Jobs, dem Dateibaum des Hosts, Git-Review, Vorschauen und der Terminal-Leiste. Nur native Features bleiben in der Desktop-App: globale Shortcuts, Always-on-top-Overlays, OS-Fensterinspektion, das Starten externer Terminals und der Updater.

Einmal einschalten:

```bash
hermes config set webapp.enabled true
hermes gateway restart
hermes webapp            # builds the bundle when out of date, opens a one-use sign-in link
hermes webapp --status   # is the gateway serving it, and on which address
```

Es läuft unter `http://127.0.0.1:9120`. Der Link aus `hermes webapp` funktioniert einmal, innerhalb von 60 Sekunden, und der Browser tauscht ihn gegen eine Anmeldung ein, die Reloads und Gateway-Neustarts übersteht. Ein neuer Tab oder eine nackte URL zeigt Anweisungen statt Zugriff, führe also `hermes webapp` nochmal aus für einen neuen Link. Chats laufen auf dem Gateway, demselben Prozess, der CLI, Desktop-App und Messaging bedient.

Es unterscheidet sich in seinem Zweck von `hermes dashboard`. Das Dashboard auf Port 9119 ist das Admin-Panel (Status, Config, API Keys, Sessions, Logs, Analytics, Cron, Skills, MCP, System), und sein optionales Chat-Tab bettet die TUI über ein Pseudo-Terminal ein. Die Webapp auf Port 9120 ist der Ort, an dem du arbeitest, mit denselben Konversationen und Bereichen wie die Desktop-App plus einer Terminal-Leiste, die die interaktive Shell des Hosts ausführt. Nutze das Dashboard zum Verwalten und die Webapp zum Chatten.

Von einem anderen Rechner aus liegt die Webapp hinter demselben Anmelde-Gate wie das Dashboard. Setze `webapp.host` auf `0.0.0.0` oder auf eine IP-Adresse der Maschine (eine LAN- oder Tailscale-Adresse), oder bleib bei Loopback und setze `webapp.public_url` hinter einem Reverse Proxy. In der Desktop-App schaltet Settings, Web Access es für andere Geräte hinter einer Anmeldung mit deinem Nous-Konto ein. Behandle die URL wie Shell-Zugriff und bevorzuge einen SSH-Tunnel, Tailscale oder ein anderes VPN. Plain HTTP auf einem anderen Host verliert außerdem Mikrofon, Zwischenablage-Einfügen und Systembenachrichtigungen, nutze also HTTPS oder einen Tunnel.

**Ideal für:** Der Desktop-Workspace im Browser auf einem Handy oder einem anderen Rechner, ohne Installation. Es ist kostenlos.

**Kompromisse:** Ein angemeldeter Webapp-Nutzer kann beliebige Befehle als das OS-Konto ausführen, unter dem Hermes läuft, behandle die URL also wie Shell-Zugriff. Die Doku sagt nicht, ob die Webapp den Bots-Bereich von Bot Mode enthält, behandle das Roster vorerst als Feature der Desktop-App.

**Ideal für:** Nutzer, die eine leichtgewichtige Web-UI ohne Abhängigkeiten wollen, die ohne Anpassungen direkt in mobilen Browsern funktioniert.

### Hermes Control Interface (HCI)

<Button text="GitHub-Repository" link="https://github.com/xaspx/hermes-control-interface" variant="solid" color="green" size="md" />

HCI ist das sicherheitsfokussierte Admin-Panel. 903 Stars (November 2026), MIT, Vanilla-JS + Vite + Express. Es priorisiert RBAC, CSRF, Rate-Limiting und Auditierbarkeit über optischen Schliff.

Was du bekommst:

- Passwort-Gate mit bcrypt-Hashing, CSRF auf mutierenden Endpunkten, Rate-Limiting
- ~20 Berechtigungen über Admin-/Viewer-/Custom-Rollen
- Browser-Terminal (xterm.js), Datei-Explorer, Sessions, Cron, System-Metriken

```bash
git clone https://github.com/xaspx/hermes-control-interface.git
cd hermes-control-interface
cp .env.example .env   # set HERMES_CONTROL_PASSWORD + HERMES_CONTROL_SECRET
npm install && npm run build

```

Erfordert Node.js 20+ und die `hermes`-CLI im PATH auf derselben Maschine.

**Ideal für:** Teams, die granulare Zugriffskontrolle und eine gehärtete Admin-Fläche wichtiger finden als eine hübsche Chat-UI.

**Kompromisse:** Der letzte Push kam am 2026-06-28, fünf Monate vor dem Check im November 2026, plane also Zeit ein, es selbst zu pflegen.

### Scarf-Dashboard: macOS-nativ

<Button text="GitHub-Repository" link="https://github.com/awizemann/scarf" variant="solid" color="purple" size="md" />

Eine native macOS-App (Swift/SwiftUI), die Hermes SQLite direkt für Echtzeitdaten liest. 923 Stars (November 2026), MIT-lizenziert, letzter Push am 2026-11-26. Die Releases kommen als Developer-ID-signierte, notarisierte Universal-Binaries (Apple Silicon und Intel) von [GitHub Releases](https://github.com/awizemann/scarf/releases), weil Scarf nicht-sandboxed Zugriff auf `~/.hermes/` und das `hermes`-Binary braucht. Updates kommen über Sparkle.

Ihre Fenster decken ein Dashboard, Analytics, einen Sessions-Browser, einen Activity-Feed, Live-Chat (Rich ACP oder Terminal), einen Memory-Editor, einen Skills-Browser, eine Plattformen-GUI, Personalities, einen Cron-Manager, Health-Monitoring, Gateway-Kontrolle und eigene Projekt-Dashboards ab, die Agents über JSON-Widgets automatisch generieren können.

Multi-Window-Support lässt dich mehrere Hermes-Server gleichzeitig überwachen (lokal + remote über SSH). Ein Menüleisten-Statusicon hält die Agent-Gesundheit immer sichtbar. Scarf für macOS sammelt außerdem Nutzungsstatistiken: Event-Namen und eine gehashte Installations-ID, nie Inhalte, Pfade oder Hostnamen. #### Bot Mode: ein Roster von Bots

Die größte Änderung in Hermes Desktop ist Bot Mode. Es ist in der Desktop-App enthalten und standardmäßig aktiv (geprüft gegen v0.23.4). Ein Bots-Tab sitzt in der linken Sidebar neben Sessions, und eine Routines-Kachel dockt neben der Konversation an, solange der Bots-Tab aktiv ist.

Ein Bot ist ein Hermes-Profil mit eigener Rolle, eigenem Modell, Memory, Skills und Avatar. Seine Config, sein Memory, seine Skills, Credentials und sein Chat-Verlauf liegen unter `~/.hermes/profiles/<name>/`. Bot Mode ist eine UI über dieses Primitiv, keine zweite Runtime. `hermes -p <bot> chat` öffnet denselben Agent aus einer Shell, und eine Routine ist ein einfacher Cronjob mit dem Namen `[bot:<name>] <routine>`, der in `hermes cron list` auftaucht. Das Öffnen eines lokalen Bots führt `hermes gateway ensure --json` für sein Profil aus, was sich an das laufende Gateway anhängt oder eines startet. Desktop zu schließen stoppt das Gateway nicht; `hermes gateway stop` tut es.

Was der Bots-Bereich gegenüber nackten Profilen hinzufügt:

- Ein dauerhafter Bot Chat pro Bot. Klicke den Bot an und du bist wieder in derselben Konversation, und `/new` innerhalb eines Bot Chats wird zu `/compact` umgeleitet, damit der Verlauf bleibt.
- Ein Roster mit Avatar, letzter Nachricht und Unread-Status, dazu Sektionen (Ordner wie Clients oder Team), Hide Bot, Duplicate und Delete Profile (endgültig). Sektion und Hidden-Status werden in den Profil-Metadaten des Bots gespeichert und folgen dem Bot also zu jedem Desktop auf diesem Backend.
- New Agent: ein Name, Title und Description, und der Bot stellt sich innerhalb von Sekunden in seinem Bot Chat vor. Der Advanced-Bereich klont ein bestehendes Profil oder startet frisch, fixiert Modell und Provider pro Bot, setzt eine eigene `SOUL.md` und aktiviert Skills, Toolsets und MCP-Server pro Bot.
- Routines: wiederkehrende Aufgaben, die an den Bot gebunden sind, der sie ausführt, mit Schedule-Picker und einem rohen Schedule-Feld. Läufe landen im eigenen Chat-Verlauf des Bots.
- Gruppenchats mit 2 bis 6 Bots. Deine Nachricht löst bis zu drei serielle Runden mit Member-Turns aus, begrenzt auf 10 Nachrichten pro Senden. Bots ziehen einander mit `@name` hinzu und eskalieren Ermessensfragen mit `@user` an dich, was einen "needs you"-Badge an den Raum heftet.
- Bot-zu-Bot-Nachrichten. Tippe `@researcher have a look at this` in einem beliebigen Chat, und der aktive Bot verfasst seine eigene Nachricht und schickt sie mit `message_agent`. Die Zustellung ist kein live Interrupt. Der empfangende Bot hebt die Nachricht bei seinem nächsten Turn ab, und ein Loop-Guard (`gateway.bot_loop_guard.max_hops`, Standard 4) verhindert, dass zwei Bots einander ewig beschäftigen.

Bot Mode funktioniert auch gegen ein Remote-Backend. Gateway-eigene Gruppenchats laufen weiter, wenn Desktop geschlossen ist, und ein Gruppenchat kann sich über mehrere Maschinen erstrecken, wobei Bots auf anderen Rechnern über ihre eigenen Gateways beitreten. Um Bot Mode auszuschalten, nutze Capabilities, Plugins, Bots. Es ist kein Neustart nötig, und Profile, Sessions und Cronjobs bleiben unangetastet. Installiere nicht das alte Standalone-Plugin. [NousResearch/Hermes-Bot-Mode](https://github.com/NousResearch/Hermes-Bot-Mode) ist archiviert (letzter Push 2026-08-17), und aktuelle Desktop-Builds haben Bot Mode eingebaut.

Bots, Routinen und Gruppenchats anzulegen dauert eine Weile, dafür gibt es einen eigenen Abschnitt in [unserer Hermes-Agent-Setup-Anleitung](/hermes-agent-setup-guide/).

#### Desktop mit einem Remote-Backend verbinden

Desktop kann ein Hermes-Backend auf einer anderen Maschine steuern: ein VPS, ein Homeserver, ein Mini hinter Tailscale. Es gibt keinen reinen Remote-Download. Installiere das Paket und öffne dann Settings, Gateways. Der Verbindungsmodus bietet drei Alternativen zum lokalen Gateway:

- Remote gateway: die URL eines `hermes serve`-Backends, das du selbst betreibst (Standardport 9119), dann anmelden
- Hermes Cloud: einmal anmelden und einen Agent auf deinem Konto wählen
- SSH: ein SSH-Host

Das Remote-Backend muss bereits `hermes serve` ausführen; Desktop hängt sich an und startet es nicht. Ein Bind an eine Nicht-Loopback-Adresse aktiviert das im Security-Abschnitt unten beschriebene Dashboard-Auth-Gate. Nutze OAuth über Nous Portal für alles, was über deine eigene Maschine hinaus erreichbar ist, und Benutzername/Passwort nur in einem vertrauenswürdigen LAN oder VPN. Unter Tailscale binde das Backend an die Tailscale-IP der Maschine und nutze `http://<tailscale-ip>:9119` als Remote-URL.

**Ideal für:** Nutzer, die das offizielle, von Nous Research gepflegte Desktop-Erlebnis wollen, und alle, die Bot Mode wollen, weil der Bots-Bereich Teil dieser App ist.

**Kompromisse:** Es gibt keine Bundles für Intel-Macs oder für macOS 12 oder älter; diese Maschinen nutzen den CLI-Installer.

## Mobiler Zugriff über Messaging-Kanäle

Der einfachste Weg, Hermes auf dein Handy zu bekommen: Nutze das eingebaute Messaging-Gateway. Keine extra Apps zu installieren; chatte einfach über Telegram, Discord, WhatsApp, Signal oder Slack mit deinem Agent.

<Notice type="info" title="Schnellster Weg zum mobilen Zugriff">
Telegram ist der schnellste Weg, Hermes auf dein Handy zu bekommen. Das Setup dauert unter 5 Minuten und du bekommst Cross-Device-Sync, Voice-Memos und dieselbe Chat-App, die du vermutlich eh offen hast.
</Notice>

| Kanal | Setup | Vorteile | Nachteile |
|---|---|---|---|
| Telegram | Niedrig | Schnellster Weg, Voice-Memos, Cross-Device-Sync | Einzel-Session-Ansicht, Verzögerung durch Nachrichten-Warteschlange |
| Discord | Niedrig | Reactions, Threads, Kanal pro Thema | Mehr Setup als Telegram |
| WhatsApp | Mittel | Hat jeder | Erfordert Telefonnummer und Kopplung |
| Signal | Mittel | Datenschutzfokussiert | Weniger funktionsreich |
| Slack | Mittel | Teamfreundlich, Kanäle | Erfordert Workspace |

Das Setup ist unkompliziert:

```bash
# Messaging-Gateway konfigurieren
hermes gateway setup
# Den Abfragen für deine Plattform folgen (z. B. Telegram-Bot-Token)

# Gateway starten
hermes gateway start
```

**Telegram-Limitierungen**, die man kennen sollte (aus dem Community-Feedback): Du bekommst nur eine Einzel-Session-Ansicht, es gibt eine Verzögerung durch die Nachrichten-Warteschlange, keinen sichtbaren Token-Zähler oder Modell-Info, und Context-Window-Resets werden nicht kommuniziert. Für gelegentliche Nutzung super. Für intensive Entwicklungsarbeit nimm ein richtiges Dashboard oder eine Desktop-App.

## Sicherheitsüberlegungen für Remote-Zugriff

Jedes dem Netzwerk ausgesetzte Dashboard und jede Mobile-App braucht Auth. Das ist nicht verhandelbar. Ein Hermes-Dashboard ohne Auth gibt jedem volle Kontrolle über deinen Agent, deine API-Keys und potenziell deinen Server.

<Notice type="error" title="Niemals ohne Auth exponieren">
Seit der Härtung im Juni 2026 startet `hermes dashboard` mit einem Bind an eine Nicht-Loopback-Adresse ohne Auth-Provider nicht, und `--insecure` wird akzeptiert, aber ignoriert. Ältere Builds starteten `hermes dashboard --host 0.0.0.0` ganz ohne Auth, was eine offene Hintertür war. Aktualisiere alles älter als v0.23.2 (dieses Release behebt auch CVE-2026-130164), und kombiniere öffentlich erreichbare Dashboards immer mit Auth und HTTPS.
</Notice>

### Das Dashboard-Auth-Gate

Das Gate schaltet sich ein, sobald der Bind-Host etwas anderes ist als `127.0.0.1`, `::1` oder `localhost`. Drei Provider sind dabei: Benutzername/Passwort (für ein vertrauenswürdiges Netzwerk oder VPN, nie das öffentliche Internet), OAuth über Nous Portal (das richtige für internet-facing Deployments und für eine Remote-Verbindung von Hermes Desktop) und selbstgehostetes OIDC. Es versagt geschlossen. Ist das Gate aktiv und kein Provider registriert, verweigert `hermes dashboard` das Binden. Führst du es interaktiv ohne Provider aus, bietet es an, sofort einen einzurichten. Docker und andere nicht-interaktive Läufe überspringen die Abfrage und beenden sich mit dem Fail-closed-Fehler. Um zu sehen, wo ein Backend steht, prüfe seinen Status-Endpunkt von der Maschine selbst:

```bash
curl -s http://127.0.0.1:9119/api/status | jq '.auth_required, .auth_providers'
```

`auth_required: true` bedeutet, dass das Gate aktiv ist.

### SSH-Tunnel (am einfachsten)

Der einfachste sichere Weg ist, den Dashboard-Port durch SSH zu tunneln. Das Backend bleibt auf Loopback, das Gate aktiviert sich also nie und kein Port wird exponiert:

```bash
# WebUI tunneln (Port 8787)
ssh -N -L 8787:127.0.0.1:8787 user@your-server

# Offizielles Dashboard tunneln (Port 9119)
ssh -L 9119:localhost:9119 user@your-vps

# Webapp tunneln (Port 9120) für den Desktop-Workspace im Browser
ssh -L 9120:127.0.0.1:9120 user@your-vps

# Danach lokal http://localhost:8787 oder http://localhost:9119 öffnen
```

### Tailscale (am sichersten für den regelmäßigen Gebrauch)

Installiere Tailscale auf deinem Server und deinem Handy oder Laptop und greife über die Tailscale-IP auf das Dashboard zu. Kein Port ist ins öffentliche Internet exponiert. Der Bind ist nicht-loopback, das Auth-Gate aktiviert sich also trotzdem, und ein Provider kommt zuerst. Die Hermes-Doku nennt das Binden an die Tailscale-IP der Maschine die saubere Option für ein `hermes serve`-Backend, mit dem sich Desktop verbindet. Ares hat eingebauten Tailscale-Support, und Hermex' Setup-Anleitung empfiehlt Tailscale Serve, das das Dashboard hinter einem HTTPS-Namen in deinem Tailnet platziert.

### Passwortschutz

Setze Benutzername und Passwort mit `hermes dashboard password`. Es schreibt `username`, einen scrypt-`password_hash` und (falls fehlend) ein Signatur-`secret` unter `dashboard.basic_auth` in `config.yaml`. Es speichert oder druckt das Passwort nie und nimmt es nie als Argument. Es fragt im Terminal ab oder liest die erste Zeile von stdin mit `--password-stdin`, funktioniert also in Skripten, Containern und Service-Setups.

```bash
# Das Passwort kommt aus einer Secret-Datei, nie von der Kommandozeile
hermes dashboard password --username admin --password-stdin < /run/secrets/dashboard_password

# Jetzt kann der Bind an Nicht-Loopback starten
hermes dashboard --host 0.0.0.0 --no-open
```

Eine Änderung von Benutzername oder Passwort beendet jede Session. `/auth/password-login` ist pro Client-IP rate-limitiert (10 Versuche pro Minute, dann HTTP 429). Benutzername/Passwort ist für ein vertrauenswürdiges LAN oder VPN. Für alles im öffentlichen Internet registriere die Installation stattdessen mit deinem Nous-Portal-Konto: `hermes dashboard register` schreibt `HERMES_DASHBOARD_OAUTH_CLIENT_ID` nach `~/.hermes/.env`.

### Hinter einem Reverse Proxy

Lass das Backend auf Loopback und Caddy oder Nginx TLS terminieren:

```bash
hermes dashboard --host 127.0.0.1 --port 9119 --no-open
```

Setze dann `dashboard.public_url` (oder `HERMES_DASHBOARD_PUBLIC_URL`) auf die vollständige öffentliche URL und füge die exakte IP des Proxies zu `dashboard.trusted_proxies` hinzu, wenn der TLS-Terminator aus einem anderen Container oder Host verbindet:

```yaml
dashboard:
  public_url: "https://dashboard.example.com/hermes"
  trusted_proxies: ["172.20.0.5"]
```

Eine Nicht-Loopback-`public_url` aktiviert immer das Auth-Gate, obwohl das Backend an Loopback bindet, konfiguriere also zuerst einen Provider, sonst versagt Hermes beim Start geschlossen. `0.0.0.0/0` und `::/0` werden als Trusted Proxies abgelehnt, und zwar aus gutem Grund: Mit einem so breiten Bereich kann jeder Container in einem vertrauenswürdigen Netzwerk Forwarding-Header liefern. Nutze die exakte Proxy-IP oder ein begrenztes CIDR. Der Hostname in `public_url` wird auch als HTTP-Host- und WebSocket-Origin-Wert akzeptiert, Wildcards nicht. Das ist der DNS-Rebinding-Schutz.

### Desktop und die Webapp gegen ein Remote-Backend

Dieselben Provider schützen die beiden neueren Oberflächen. Hermes Desktop verbindet sich aus Settings, Gateways mit einem `hermes serve`-Backend: Remote gateway (die URL des Backends, Standardport 9119), Hermes Cloud (anmelden und einen Agent wählen) oder SSH. Die App erkennt, welchen Provider das Backend anbietet, und zeigt entweder ein Anmeldeformular oder Sign in with Nous Research. Die Webapp nutzt die Dashboard-Anmeldung: Setze `webapp.host` auf eine LAN- oder Tailscale-Adresse oder `webapp.public_url` hinter einem Proxy, und das Gateway verlangt sie.

Die Doku legt den Blast-Radius offen dar. Ein angemeldeter Webapp-Nutzer kann beliebige Befehle als das OS-Konto ausführen, unter dem Hermes läuft. Die Credentials, die Desktop für seine Gateways speichert, liegen in `gateway-connections.json` und `gateway-connection-tokens.json` in deinem Hermes-Home, nur für den Eigentümer lesbar (0600), als Klartext, weil der Server der Webapp sie lesen muss. Bevorzuge einen SSH-Tunnel, Tailscale oder ein anderes VPN, statt einen der beiden Ports zu öffnen.

| Dashboard | Passwort | OIDC | WebAuthn/Passkeys |

## FAQ

<Accordion label="Gibt es eine offizielle Hermes-Agent-Mobile-App?" group="faq" expanded="true">
Nein. Es gibt keine offizielle Mobile-App von Nous Research. Jede Mobile-App kommt aus der Community. Die offiziellen Oberflächen sind die CLI, die Desktop-App (`hermes desktop`), deren Browserversion, die Webapp (`hermes webapp`) und das Admin-Dashboard (`hermes dashboard`). Ein Handy-Browser kann auch die offizielle Webapp öffnen. Jede oben behandelte Android- und iOS-App ist ein Drittanbieter-Projekt.
</Accordion>

<Accordion label="Kann ich Hermes Agent auf meinem Handy laufen lassen?" group="faq">
Auf Android, ja. Hermes Agent Android (Google Play) führt die volle Hermes-Runtime direkt auf dem Gerät aus. Du brauchst deinen eigenen API-Key und etwa 200MB Speicher. Auf iOS, nein. iOS-Sandboxing verhindert, dass Hermes direkt läuft. Alle iOS-Apps verbinden sich per SSH oder API mit einer Remote-Hermes-Instanz.
</Accordion>

<Accordion label="Was ist das beste kostenlose Hermes-Dashboard?" group="faq">
Das offizielle eingebaute Dashboard (`hermes dashboard`) und Hermes WebUI von nesquena sind beide kostenlos und gut. Das offizielle Dashboard ist am einfachsten aufzusetzen, weil es bei Hermes dabei ist, und die offizielle Webapp (`hermes webapp`) ist ebenfalls kostenlos, wenn du vor allem chatten statt verwalten willst. Hermes WebUI ist sparsamer mit Ressourcen (kein Build-Schritt, kein Framework) und auf Mobilgeräten angenehmer zu bedienen. Wenn du auch einen kostenlosen API-Key brauchst, schau dir an, wie man [Hermes Agent mit kostenlosen Modellen auf Nous Portal](/hermes-agent-mimo-v2-pro/) einrichtet.
</Accordion>

<Accordion label="Wie greife ich remote auf mein Hermes-Dashboard zu?" group="faq">
Vier Wege, grob von einfach bis aufwendig: (1) SSH-Tunnel: `ssh -L 9119:localhost:9119 user@your-vps`, dann localhost:9119 öffnen; kein Auth-Gate, weil das Backend auf Loopback bleibt. (2) Tailscale: auf beiden Geräten installieren und die Tailscale-IP nutzen; das Gate ist aktiv, setze also zuerst ein Passwort. (3) Die offizielle Webapp: `hermes webapp` liefert den Desktop-Workspace auf Port 9120, und Settings, Web Access in der Desktop-App schaltet es für andere Geräte hinter einer Anmeldung mit deinem Nous-Konto ein. (4) Reverse Proxy mit HTTPS: Backend auf `127.0.0.1` lassen, `dashboard.public_url` setzen und für alles Öffentliche OAuth mit `hermes dashboard register` registrieren. Das Flag `--insecure` tut nichts mehr, es gibt also keinen Weg um das Gate herum.
</Accordion>

<Accordion label="Welches Hermes-Dashboard verbraucht die wenigsten Ressourcen?" group="faq">
Hermes WebUI von nesquena. Es nutzt Pythons Standard-Library-HTTP-Server und Vanilla-JavaScript, ohne Node.js, ohne Bundler und ohne Framework. Der Start ist schnell und der Speicherverbrauch ist minimal im Vergleich zu den React-/Vue-basierten Alternativen.
</Accordion>

<Accordion label="Kann ich mehrere Dashboards gleichzeitig nutzen?" group="faq">
Ja. Dashboards sind unabhängige Webanwendungen auf verschiedenen Ports. Du kannst das offizielle Dashboard auf Port 9119, die Webapp auf 9120, Hermes WebUI auf 8787, Ekko Studio auf 8648, Hermes Workspace auf 3000 und HCI auf 10274 gleichzeitig laufen lassen. Sie lesen alle aus demselben Hermes-Datenverzeichnis, Sessions, Config und Profile sind also geteilt.
</Accordion>

<Accordion label="Ist die BSL-1.1-Lizenz von Ekko Studio (früher Hermes Studio) ein Problem?" group="faq">
Für persönliche Nutzung nicht. Für kommerzielle Nutzung prüfe die Lizenzbedingungen. Ekko Studios BSL-1.1 (Business Source License) erlaubt nur nicht-kommerzielle Nutzung; Verkauf, SaaS-Hosting oder das Einbetten in ein kommerzielles Produkt braucht eine separate kommerzielle Lizenz. Die Lizenzdatei nennt den 2029-05-10 als Wechseldatum, an dem sie zu Apache 2.0 konvertiert. Brauchst du ein vollständig MIT-lizenziertes Dashboard für kommerzielle Nutzung, wähle stattdessen das offizielle Dashboard oder Hermes WebUI.
</Accordion>

<Accordion label="Braucht Bot Mode die Hermes-Desktop-App?" group="faq">
Für die Roster-UI, ja. Der Bots-Bereich, der Routinen-Editor und das Gruppenchat-Fenster leben in der Desktop-App, wo Bot Mode standardmäßig aktiv ist. Die Bots selbst brauchen sie nicht: Ein Bot ist ein Hermes-Profil, `hermes -p <bot> chat` öffnet also denselben Agent aus einer Shell, und `hermes cron list` zeigt seine Routinen als Jobs mit dem Namen `[bot:<name>]`. Auf einem headless VPS installiere Desktop auf deinem Laptop und verbinde es über Settings, Gateways mit dem VPS. Bot-zu-Bot-Nachrichten laufen nur in den Bot Chats, die der Bots-Bereich einricht, dieser Teil hängt also an Desktop, sofern du die Installation nicht von Hand markierst. Gruppenchats, die einem Gateway gehören, laufen mit geschlossenem Desktop weiter. Die Anleitung dazu steht in der [Hermes-Agent-Setup-Anleitung](/hermes-agent-setup-guide/).
</Accordion>

<Accordion label="Was ist der Unterschied zwischen Webapp und Dashboard?" group="faq">
`hermes dashboard` auf Port 9119 ist das Admin-Panel: Status, Config, API Keys, Sessions, Logs, Analytics, Cron, Skills, MCP und System, mit einem optionalen Chat-Tab, das die TUI einbettet. Die Webapp auf Port 9120 ist der Desktop-Workspace im Browser, ausgeliefert vom Gateway: dieselbe chat-first UI, Dateibaum, Git-Review und Terminal-Leiste wie die Desktop-App. Schalte sie ein mit `hermes config set webapp.enabled true`, `hermes gateway restart`, dann `hermes webapp`. Nutze das Dashboard zum Verwalten und die Webapp zum Arbeiten.
</Accordion>
