## Wann sich ein Countdown-Timer auf deiner Carrd-Seite lohnt

Countdown-Timer verdienen ihren Platz, wenn eine echte Deadline existiert:

1. **Produkt-Launches** – Vorfreude vor dem Release aufbauen
2. **Sales und Promotions** – ein zeitlich begrenztes Angebot mit hartem Ende (ein echtes Enddatum schlägt „nur für kurze Zeit“-Copy); kombiniere es mit einer [Carrd-Preistabelle](/de/carrd-preistabelle-hinzufuegen/), damit der Rabatt sichtbar ist, während die Uhr läuft
3. **Event-Anmeldungen** – Anmeldefristen
4. **Coming-soon-Seiten** – Besuchern sagen, wann sie wiederkommen sollen
5. **Webinare und Live-Events** – Countdown bis zur Startzeit

Eine tickende Uhr erzeugt eine Dringlichkeit, die statischer Text nicht erreicht. Sie stellt aber auch eine harte Anforderung: Bei einem Launch oder Sale muss der Timer für jeden Besucher zum selben Zeitpunkt null erreichen. An dem Detail scheitern viele – überspringe deshalb nicht den [Zeitzonen-Abschnitt](#ziel-datum-und-uhrzeit-festlegen-zeitzonensicher) weiter unten.

## So fügst du einen eigenen Countdown-Timer in Carrd ein

Jedes Design in diesem Artikel läuft über dasselbe Element: das Embed. Der Ablauf ändert sich nie – Element hinzufügen, Type auf Code setzen, Snippet einfügen, veröffentlichen.

### Schritt 1: Ein Embed-Element hinzufügen (Type: Code, Style: Inline)

Klicke im Builder auf den `+`-Button und füge ein **Embed**-Element hinzu, dann setze Type auf Code und Style auf Inline.

Füge dein HTML/CSS/JS in das Code-Feld ein. `Inline` rendert den Countdown genau dort, wo du das Element im Layout platziert hast. Die andere Option, `Hidden`, injiziert den Code in den Head, Body Top oder Body End der Seite – richtig für globale Skripte wie Analytics, falsch für einen sichtbaren Countdown. (Ältere Tutorials erwähnen einen „Above“-Style; diese Option existiert nicht mehr.)

Um das Embed später wiederzufinden oder zu bearbeiten, nutze das Elements-Panel: **More Actions → Elements…** listet jedes Element auf der Seite – und zeigt seit Oktober 2026 auch den Sichtbarkeitsstatus jedes Elements, inklusive vom Publishing ausgeschlossener oder per CSS versteckter Elemente. Praktisch, wenn ein Embed „verschwindet“: Prüfe erst das Panel, bevor du den Code verdächtigst.

<Notice type="warning" title="Embeds sind im Builder unsichtbar">
Carrds Doku sagt es unmissverständlich: Das Embed-Element gibt im Builder nichts aus. Eine leere Stelle, wo dein Countdown sein sollte, ist normal. Veröffentliche die Seite und er erscheint. Das ist der Fehlalarm Nummer eins bei eigenem Code in Carrd.
</Notice>

### Schritt 2: Countdown-Style auswählen

Wähle eines der fünf Designs unten und füge es in das Code-Feld des Embeds ein. Die einzige Änderung, die du machen musst, ist das Zieldatum oben im Skript, behandelt in [Ziel-Datum und Uhrzeit festlegen](#ziel-datum-und-uhrzeit-festlegen-zeitzonensicher).

<Notice type="info" title="Zwei Timer auf einer Seite?">
Jedes Snippet nutzt eigene IDs (<code>countdown1</code>…<code>countdown5</code>), verschiedene Styles koexistieren also. Zwei Kopien desselben Styles tun es nicht: Doppelte IDs bedeuten, dass nur der erste Timer tickt. Benenne jede <code>id</code> in der zweiten Kopie um (<code>days1</code> → <code>days6</code>, <code>countdown1</code> → <code>countdown6</code>, <code>dayCircle</code> → <code>dayCircle2</code>, <code>day1Card</code> → <code>day1Card2</code>) und die passenden <code>getElementById</code>-Strings in ihrem Skript – dann funktioniert es.
</Notice>

```html
  }

  .countdown-value {
    font-size: 48px;

    color: white;

  }

  .countdown-label {

  }

<div class="countdown-modern" id="countdown1" role="timer">
  <div class="countdown-item">
    <div class="countdown-value" id="days1">00</div>
    <div class="countdown-label">Days</div>
  </div>
  <div class="countdown-item">
    <div class="countdown-value" id="hours1">00</div>
    <div class="countdown-label">Hours</div>
  </div>
  <div class="countdown-item">
    <div class="countdown-value" id="minutes1">00</div>
    <div class="countdown-label">Minutes</div>
  </div>
  <div class="countdown-item">
    <div class="countdown-value" id="seconds1">00</div>
    <div class="countdown-label">Seconds</div>
  </div>
</div>

<script>
(function() {
  // March 1, 2027 at 09:00 UTC - Date.UTC months are 0-indexed too (2 = March)
  var targetDate = Date.UTC(2027, 2, 1, 9, 0, 0);

  function updateCountdown() {
    var distance = targetDate - Date.now();

    if (distance < 0) {
      clearInterval(iv);
      document.getElementById('countdown1').innerHTML = '<p style="font-size: 24px; font-weight: 700; color: #667eea;">Event has started!</p>';
      return;
    }

    var days = Math.floor(distance / 86400000);
    var hours = Math.floor((distance % 86400000) / 3600000);
    var minutes = Math.floor((distance % 3600000) / 60000);
    var seconds = Math.floor((distance % 60000) / 1000);

    document.getElementById('days1').innerHTML = (days < 10 ? '0' : '') + days;
    document.getElementById('hours1').innerHTML = (hours < 10 ? '0' : '') + hours;
    document.getElementById('minutes1').innerHTML = (minutes < 10 ? '0' : '') + minutes;
    document.getElementById('seconds1').innerHTML = (seconds < 10 ? '0' : '') + seconds;
  }

  var iv = setInterval(updateCountdown, 1000);
  updateCountdown();
})();
</script>
```

Anpassen: Ändere die Zeile `Date.UTC(2027, 2, 1, 9, 0, 0)`. Es ist die eine Zeile, die du bearbeitest. Monate sind 0-indiziert (Januar = 0, März = 2). Veröffentliche und sieh ihm beim Ticken zu; zeigt er beim Laden „Event has started!“, liegt dein Zieldatum in der Vergangenheit.

## Ziel-Datum und Uhrzeit festlegen (zeitzonensicher)

Jedes Snippet setzt seine Deadline in einer Zeile:

```javascript
var targetDate = Date.UTC(2027, 2, 1, 9, 0, 0);
```

Das ist die Zeile, die du änderst. `Date.UTC(year, month, day, hour, minute, second)` nimmt dieselben Argumente wie `new Date(...)`, und Monate sind weiterhin 0-indiziert: Januar = 0, März = 2, Dezember = 11.

Beispiele in der Zukunft:

- 1. März 2027 um 09:00 UTC: `Date.UTC(2027, 2, 1, 9, 0, 0)`
- 25. Dezember 2027 um 09:00 UTC: `Date.UTC(2027, 11, 25, 9, 0, 0)`
- 4. Juli 2027 um 18:00 UTC: `Date.UTC(2027, 6, 4, 18, 0, 0)`

Eine Gewohnheit, die dir ein Republish erspart: Wähl zum Testen ein Datum bequem in der Zukunft. Ein Countdown, dessen Ziel schon verstrichen ist, rendert beim Laden seine Ablauf-Nachricht – das wirkt kaputt, obwohl der Code in Ordnung ist. Wenn das echte Datum steht, roll das Jahr weiter, statt ein altes Datum stehen zu lassen.

### Besucher-lokale vs. UTC-Deadlines

`Date.UTC(...)` und `new Date(y, m, d)` sehen austauschbar aus, sind es aber nicht:

- `new Date(2027, 2, 1)` zählt bis Mitternacht **in der Zeitzone jedes einzelnen Besuchers**. Ein Besucher in London erreicht null fünf Stunden vor einem Besucher in New York. Für eine globale Deadline (ein Launch, ein Sale-Ende, ein Webinar-Start) ist das ein echter Bug: Manche Besucher sehen „Sale has ended!“, während andere noch Stunden Rest sehen.
- `Date.UTC(2027, 2, 1, 9, 0, 0)` ist ein fester Zeitpunkt. Der Timer jedes Besuchers erreicht null im selben Moment; jeder Browser rendert die Restzeit nur gegen seine eigene Uhr.

Faustregel: globale Deadline → `Date.UTC`. Lokales Event (Einlass, Promo im Laden) → besucher-lokales `new Date(y, m, d)` ist okay.

<Tabs>
<Tab name="Date.UTC">

```javascript
var targetDate = Date.UTC(2027, 2, 1, 9, 0, 0);
```

</Tab>
<Tab name="ISO-String">

```javascript
var targetDate = new Date("2027-03-01T09:00:00Z").getTime();
```

</Tab>
</Tabs>

Beide sind derselbe Zeitpunkt: 1. März 2027 um 09:00 UTC. Nimm die Syntax, die du in sechs Monaten lieber lesen willst.

<Notice type="info" title="Der Monat ist 0-indiziert">
Sowohl in `new Date(y, m, d)` als auch in `Date.UTC(y, m, d, ...)` ist Januar Monat 0 und Dezember Monat 11. Es erwischt jeden einmal. Ist dein Countdown um genau einen Monat daneben, ist das der Grund.
</Notice>

## Countdown-Farben und -Fonts anpassen

Jeder Style nutzt schlichte CSS-Farben, deine Marke zu treffen ist also eine Hex-Änderung:

Gradient-Hintergründe nehmen zwei Hex-Farben:

```css
background: linear-gradient(135deg, #667eea 0%, #764ba2 100%);
/* Change the hex colors to match your brand */
```

Vollfarben sind noch simpler:

```css
background: #1a1a2e;  /* Dark background */
color: #10b981;       /* Accent color */
```

Die Kreisringe nehmen zwei Stroke-Farben:

```css
stroke: #10b981;  /* Progress color */
stroke: #e6e6e6;  /* Background circle */
```

Die Snippets nutzen alle System-Font-Stacks, sie funktionieren also überall ohne Ladekosten. Willst du deinen Marken-Font: Ab Pro Standard gibt es Local Fonts – Carrd hat im August 2026 sechs weitere hinzugefügt (Geist Pixel, Smooch Sans, Tangerine und ein paar andere). Lade den Font auf der Seite und überschreibe dann im `<style>`-Block des Embeds:

```css
.countdown-value { font-family: 'Smooch Sans', sans-serif; }
```

<Notice type="info" title="Bleib barrierefrei">
Die animierten Styles in diesem Artikel kommen mit einem `prefers-reduced-motion`-Guard, und jeder Container trägt `role="timer"`. Wenn du den Code für eine eigene Variante adaptierst, behalte diesen Block:

```css
@media (prefers-reduced-motion: reduce) {
  .countdown-item:hover { transform: none; }
  .flip-card.flip .flip-card-inner { animation: none; }
  .circle-progress { transition: none; }
}
```

Überspringe `aria-live` bei einem Timer im Sekundentakt. Eine Live-Region würde Screenreadern jeden Tick vorlesen.
</Notice>

Dieselbe Embed-Technik deckt auch andere Injektionen ab – ein [Cookie-Hinweis](/de/carrd-cookie-hinweis-hinzufuegen/) funktioniert exakt genauso.

## Was passiert, wenn der Countdown endet

Jedes Snippet tauscht den Timer bei null gegen eine Nachricht und stoppt sein eigenes Intervall, es tickt also nicht unsichtbar ewig weiter. Zwei Muster decken die meisten Fälle ab:

<Tabs>
<Tab name="Nachricht zeigen">

```javascript
if (distance < 0) {
  clearInterval(iv);
  document.getElementById('countdown1').innerHTML = '<p>We are live!</p>';
  return;
}
```

</Tab>
<Tab name="Redirect bei Ablauf">

```javascript
if (distance < 0) {
  clearInterval(iv);
  window.location.href = 'https://yoursite.com/launch';
  return;
}
```

</Tab>
</Tabs>

<Notice type="info" title="Halte die Uhr an">
`setInterval` feuert nach dem Ablauf weiter, wenn du es nicht leerst. Der `clearInterval(iv)`-Aufruf in diesen Snippets fährt den Timer in dem Moment herunter, in dem Nachricht oder Redirect laufen. Ohne ihn tickt das Intervall weiter und tut nichts.
</Notice>

Wenn die Uhr null erreicht, ist der Tausch der CTA gegen ein [Popup-Modal](/de/carrd-popup-modal/), das die Warteliste einsammelt, der nächste Schritt.

Richte den Redirect auf eine Seite deiner eigenen [Custom Domain](/de/carrd-domain-verbinden/), damit die URL ein Redesign überlebt. Pro Plus (49 $/Jahr) bringt außerdem native Redirects und eine Framing-Option unter Publish → Settings, aber ein dreizeiliger JavaScript-Redirect im Embed reicht für die meisten Countdowns.

Ein Security-Hinweis, falls du stattdessen einen iframe-basierten Timer abwägst: Veröffentlichte Carrd-Seiten senden `content-security-policy: frame-ancestors https://carrd.com` und `x-frame-options: deny`. Das beschränkt nur, wer deine Carrd-Seite iframen darf. Inline-Skripte wie diese Snippets laufen problemlos, ebenso Drittanbieter-Widget-Skripte.

## Eigener Embed vs. Countdown-Widgets von Drittanbietern

Dienste wie der [Elfsight Countdown Timer](https://elfsight.com/countdown-timer-widget/) lassen sich in dasselbe Embed-Element einfügen, das du gerade genutzt hast, und sie sind echte Produkte mit visuellen Editoren, Count-up-Modus und verzögerten Starts. Der Haken sind die Kosten. Stand Oktober 2026 fährt Elfsight vier Tiers: Lite 0 $, Basic 5 $/Monat, Pro 10 $/Monat, Premium 20 $/Monat – pro Widget, also 60–240 $/Jahr, sobald du den Free-Tier verlässt. Prüfe die aktuellen Preise, bevor du budgetierst; Widget-Preise ändern sich oft, und die Abrechnungsbasis geht aus ihrer Website nicht klar hervor.

| | Eigener Embed (dieser Artikel) | Drittanbieter-Widget |
|---|---|---|
| Jährliche Kosten | 0 $ extra (Pro Standard ist ohnehin erforderlich) | 5–20 $/Monat pro Widget (60–240 $/Jahr) zusätzlich zu Carrd |
| Externe Requests | Keine | Vendor-JS bei jedem Pageview |
| No-Code-Bearbeitung | Nein – du bearbeitest das Snippet | Ja – visuelles Dashboard |
| Vendor-Badge | Keins | Free-Tiers fügen meist eins hinzu |

Der eigene Embed gewinnt bei Kosten und Seitengewicht. Du brauchst Pro Standard ohnehin für jedes Embed, der Mehrpreis dieser Snippets ist also null, und nichts funkt nach Hause. Ein Widget verdient seine Gebühr nur, wenn du brauchst, was Code nicht einfach liefern kann:

<li>Einen visuellen Editor, den ein nicht-technischer Kunde anpassen kann</li>

Eins, das Leute verwirrt: Carrds eigenes **Widget**-Element unterstützt Stripe, Gumroad, Facebook, PayPal und Typeform. Kein Countdown dabei. Carrds Countdown lebt im separaten **Timer**-Element, und sobald du über seine Styling-Optionen hinauswächst, landest du beim Embed-Element.

## Fehlerbehebung und FAQ

<Accordion label="Warum zeigt mein Countdown nichts im Carrd-Builder?" group="faq">
Embed-Elemente rendern nichts im Builder – Carrds Doku sagt das direkt. Veröffentliche die Seite und lade die Live-Seite hart neu. Bleibt sie nach dem Veröffentlichen leer, öffne die DevTools und prüfe die Konsole auf Skriptfehler. Fehlt er auch nach dem Veröffentlichen noch, öffne <strong>More Actions → Elements…</strong> – seit Oktober 2026 zeigt das Panel, ob ein Element vom Publishing ausgeschlossen oder per CSS versteckt ist.
</Accordion>

<Accordion label="Warum sagt mein Countdown sofort „Event has started!“?" group="faq">
Dein Zieldatum liegt in der Vergangenheit. Prüfe die `Date.UTC(...)`-Zeile oben im Skript und roll sie nach vorn. Denk an den 0-indizierten Monat: `Date.UTC(2027, 2, 1)` ist der 1. März 2027, nicht der 1. Februar.
</Accordion>

<Accordion label="Warum erreicht mein Countdown zur falschen Zeit null?" group="faq">
Du hast wahrscheinlich `new Date(y, m, d)` genutzt, das bis Mitternacht in der lokalen Zeitzone jedes Besuchers zählt. Für eine Deadline, die weltweit zum selben Moment fallen muss, wechsle zu `Date.UTC(y, m, d, h, min, s)` oder `new Date("2027-03-01T09:00:00Z").getTime()`.
</Accordion>

<Accordion label="Brauche ich einen bezahlten Plan für einen Carrd-Countdown-Timer?" group="faq">
Ja. Das Embed-Element erfordert Pro Standard oder höher, mindestens 19 $/Jahr. Free- und Pro-Lite-Pläne können gar keinen eigenen Code einfügen, es gibt also keinen Free-Tier-Workaround innerhalb von Carrd.
</Accordion>

<Accordion label="Kann ich zwei oder mehr Countdowns auf eine Seite setzen?" group="faq">
Ja. Verschiedene Styles koexistieren, weil sich ihre IDs unterscheiden (`countdown1` bis `countdown5`). Zwei Kopien desselben Styles kollidieren – benenne jede ID in der zweiten Kopie um und passe die `getElementById`-Strings in ihrem Skript entsprechend an.
</Accordion>

<Accordion label="Warum zeigt die Flip-Clock nach 100 Tagen falsche Tage?" group="faq">
Das Tage-Feld hat zwei Ziffern-Karten, es kann also keine dreistellige Zahl anzeigen. `pad2(150)` gibt „150“ zurück, und `dStr[1]` greift die mittlere Ziffer. Das Snippet klemmt es mit `Math.min(days, 99)`, oder du fügst eine dritte Karte für echte dreistellige Werte hinzu.
</Accordion>

<Accordion label="Sind diese Countdown-Snippets barrierefrei?" group="faq">
Größtenteils ja. Jeder Container hat `role="timer"`, und die animierten Styles enthalten einen `prefers-reduced-motion`-Guard, der die Flip- und Hover-Effekte für Nutzer killt, die sich dagegen entscheiden. Füge kein `aria-live` zu einem Timer im Sekundentakt hinzu; eine Live-Region, die jeden Tick vorliest, ist schlimmer als gar nichts anzusagen.
</Accordion>

<Accordion label="Kann ich den Timer mit Carrds kostenlosem 7-Tage-Pro-Trial testen?" group="faq">
Wahrscheinlich nicht. Der Trial deckt Forms, Widgets, das Verbinden einer [eigenen Domain mit Carrd](/de/carrd-domain-verbinden/) und Carrds native Analytics ab – aber das Embed-Element (eigener Code) steht nicht auf der dokumentierten Feature-Liste des Trials unter carrd.com/docs/pro/trial. Du brauchst Pro Standard (19 $/Jahr), um diese Snippets einzufügen und zu veröffentlichen.
</Accordion>

## Fazit

Carrds eingebautes Timer-Element deckt die Basics ab, aber ein eigener Embed ist der Weg zu einem Countdown, der zu deinem Design passt. Wähl einen Style, ändere eine `Date.UTC`-Zeile, veröffentliche und prüfe, dass er tickt. Du gibst weniger aus als auf dem Widget-Weg und lieferst null externe Skripte aus.

Kombiniere den Timer mit einem [Popup-Modal](/de/carrd-popup-modal/) für E-Mail-Capture, einem [WhatsApp-Button](/de/carrd-whatsapp-button/), damit Besucher dich erreichen, wenn die Uhr null erreicht, und einem [Cookie-Hinweis](/de/carrd-cookie-hinweis-hinzufuegen/), falls du EU-Traffic bedienst.
