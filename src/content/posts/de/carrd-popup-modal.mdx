## Warum Popups zu deiner Carrd-Site hinzufügen

Popups funktionieren für konkrete Jobs:

1. E-Mail-Capture. Baue deine Newsletter-Liste auf, ohne beste Platzierungen auf der Seite für Signup-Formulare zu opfern.
2. Ankündigungen. Erzähl Besuchern von Sales, neuen Produkten oder Updates, die es wert sind, gewusst zu werden.
3. Bild-Lightboxen. Zeig größere Versionen von Portfolio-Bildern oder Produktfotos.
4. Exit-Intent. Fange Besucher ab, bevor sie gehen, mit einem letzten Angebot.
5. Willkommensnachrichten. Begrüße Erstbesucher oder markiere etwas Dringendes.

Setz sie mit Bedacht ein. Lass keins aufpoppen in der Sekunde, in der jemand auf deiner Seite landet. Gib ihnen ein paar Sekunden, sich erstmal umzusehen.

Frequency Capping zählt genauso viel wie Timing. Der gesamte Code unten nutzt `sessionStorage`, ein Besucher sieht das Popup also einmal pro Browser-Session. Tausche `localStorage` ein (mit einem Ablauf-Timestamp), wenn du einmal pro Woche willst. Diese Entscheidung lebt im Code. Du brauchst dafür kein Plugin.

## Wie du ein Popup-Modal zu Carrd hinzufügst

Das Setup ist für alle drei Optionen dasselbe. Ein Embed-Element hält dein HTML, CSS und ein bisschen JavaScript. Dann wählst du den Popup-Typ, der zu deinem Ziel passt.

### Schritt 1: Ein Embed-Element hinzufügen

Klicke im Carrd-Editor auf das `+`-Zeichen und füge ein Embed-Element irgendwo auf der Seite hinzu (die Platzierung im visuellen Editor ist egal; die echte Platzierung setzen wir in den Einstellungen). Konfiguriere es so:

- **Type:** Code
- **Style:** Hidden, **Body End**

<Picture formats={["webp"]} fallbackFormat="webp" src={imag1} alt="Carrd Embed-Element-Einstellungen mit Type auf Code und Style auf Hidden, daneben das Location-Dropdown" />

Der Screenshot zeigt das Location-Dropdown auf Head. Stell es für Option 1 und 3 auf **Body End**. Option 2 ist die Ausnahme: Ihr Trigger-Button ist auf der Seite sichtbar, dieses Embed nutzt also **Style: Inline** (Details in Option 2).

<Notice type="info" title="Type muss Code sein">
Setze Type auf <strong>Code</strong>, nicht Iframe. Das Popup-Markup, die Styles und das Skript leben alle in diesem einen Embed. Carrd erlaubt hier ausdrücklich <code>&lt;style&gt;</code>- und <code>&lt;script&gt;</code>-Tags.
</Notice>

Hidden-Embeds können in den Head, Body Top oder Body End. Head funktioniert, aber `<div>`-Markup in `<head>` zu injizieren funktioniert nur, weil der HTML-Parser es gewaltsam in `<body>` verschiebt. Fragil und verwirrend beim Debuggen. Body End gibt dir deterministische DOM-Reihenfolge: Dein Markup landet vor dem Skript, das es abfragt, keine Parser-Tricks. Das ist der Default, den ich für jedes Carrd-Embed-Popup empfehle.

![Diagramm eines Carrd-Seiten-DOM mit dem Popup-Embed auf Body End und dem Modal, das im Browser-Top-Layer über dem Seiten-Content rendert](@assets/images/26/01/carrd-popup-embed-placement.svg)

Sobald du den Code eingefügt hast (nächster Schritt), veröffentliche und prüfe die Live-URL. Dort passiert der echte Carrd-Popup-Code-Test. Mehr dazu im Verifizieren-Abschnitt.

### Schritt 2: Wähle deinen Popup-Typ

Drei Versionen, drei Jobs. Such dir eine pro Seite aus.

## Option 1: Zeitgesteuertes E-Mail-Capture-Popup

Dieses Popup erscheint nach einer Verzögerung und enthält ein E-Mail-Signup-Formular. Es ist der richtige Default für Newsletter-Wachstum. Es ist das klassische Carrd-E-Mail-Popup.

Die Version unten nutzt das native `<dialog>`-Element und `showModal()`. Das bringt dir viel gratis: Escape schließt es, die Seite dahinter kann nicht geklickt oder getabbt werden, solange es offen ist, und es rendert im Top-Layer des Browsers, also kein z-index-Kampf mit Carrds Markup. Eins macht `showModal()` nicht: Die Seite dahinter am Scrollen hindern. Deshalb enthält das CSS eine Ein-Zeilen-`:has()`-Regel, die das Scrollen sperrt, solange der Dialog offen ist. Browser-Support ist universell seit Firefox 98 und Safari 15.4 (März 2022) laut MDNs Compat-Daten, geprüft September 2026.

<script>
  const dlg = document.getElementById('emailModal');

  // Show once per session. The flag is set when the popup is SHOWN,
  // not when it closes, so a visitor who navigates away mid-popup
  // doesn't get ambushed again on the next page.
  if (!sessionStorage.getItem('modalShown')) {
    setTimeout(function () {
      dlg.showModal();
      sessionStorage.setItem('modalShown', 'true');
    }, 3000); /* keep in sync with --popup-delay */
  }

  // Backdrop click closes. The click target is the <dialog> element itself
  // (the .modal-inner wrapper covers the dialog box, so only true backdrop
  // clicks land here).
  dlg.addEventListener('click', function (e) {
    if (e.target === dlg) dlg.close();
  });

  // Bots fill the hidden honeypot field; real visitors never see it.
  dlg.querySelector('form').addEventListener('submit', function (e) {
    if (this.elements.website.value) e.preventDefault();
  });

  // Escape handling is native with <dialog>. No keydown handler needed.
</script>
```

### Anpassungsoptionen

Um die Verzögerung zu ändern, aktualisiere sowohl `--popup-delay` (Dokumentation) als auch den `setTimeout(..., 3000)`-Aufruf. 3000 = 3 Sekunden. Auf Mobilgeräten konvertieren 4 bis 5 Sekunden besser als 1 bis 2; die Leute orientieren sich noch.

Alles läuft über die CSS-Variablen oben für Farben: `--popup-accent` ist der Button, `--popup-bg` die Karte, `--popup-text` die Überschrift, `--popup-secondary` der unterstützende Text.

Um deinen E-Mail-Dienst anzubinden, ersetze `YOUR_FORM_ENDPOINT` durch die Form-Action-URL deines E-Mail-Providers. Dann angleiche den `name` des E-Mail-Inputs an das, was der Provider erwartet: `email` funktioniert für Buttondown, Kit nutzt `email_address`, und Mailchimp nutzt `EMAIL`. Kopiere ihn im Zweifel aus dem eigenen Formular-HTML des Providers; ein falscher Feldname heißt, dass das Signup still fehlschlägt. Das Formular öffnet die Bestätigungsseite des Providers in einem neuen Tab (`target="_blank"`), damit Besucher nicht von deiner Site gerissen werden. Wenn der Endpoint deines Providers CORS unterstützt, kannst du ihn per `fetch()` abschicken und stattdessen ein Inline-Dankeschön zeigen. Dieser Weg ist provider-spezifisch. Verifiziere ihn vor dem Livegang. Ein Feld, das du in Ruhe lässt: `website` ist ein Honeypot. Bots füllen es, Menschen nicht, und das Skript bricht jeden Submit ab, bei dem es nicht leer ist.

### Troubleshooting

- **Popup zeigt nicht im Editor.** Erwartet. Carrd führt Embed-Code im Builder nicht aus. Teste immer die veröffentlichte URL in einem frischen Inkognito-Fenster.
- **Nichts rendert überhaupt.** Drei Checks: Type ist **Code** (nicht Iframe), Style ist **Hidden**, und dein Plan ist Pro Standard oder höher. Free- und Pro-Lite-Accounts verwerfen eigenen Code still.
- **Popup wiederholt sich auf jeder Seite.** Die Zeile `sessionStorage.setItem('modalShown', 'true')` muss im Show-Pfad laufen (direkt nach `showModal()`). Sie nur in einem Close-Handler laufen zu lassen, reicht nicht. Der Code oben macht das korrekt. Wenn du ihn bearbeitet hast, prüfe, dass du sie nicht verschoben hast.
- **Formular postet, aber nichts kommt in deinem ESP an.** Die Action-URL ist falsch oder unvollständig. Vergleiche sie Zeichen für Zeichen mit dem Endpoint, den dein Provider dir gibt, und prüfe das Submission-Log des Providers, bevor du annimmst, das Popup sei kaputt.
- **Der Hintergrund scrollt hinter dem Popup weiter.** `showModal()` sperrt das Scrollen nicht von allein. Prüfe, dass die `body:has(dialog#emailModal[open])`-Regel noch in deinem CSS ist und dass die ID darin zu deinem Dialog passt.

<Accordion label="Brauchst du eine alte div-basierte Version für antike Browser?">
<p><code>&lt;dialog&gt;</code> wird in jedem Browser unterstützt, der seit März 2022 erschienen ist. Solange du keine Analytics hast, die einen nennenswerten Anteil an Pre-2022-Browsern zeigen, lass es bleiben.</p>
<p>Wenn du sie unterstützen musst, baue das Overlay mit zwei verschachtelten <code>div</code>-Elementen und einem <code>.active</code>-Klassen-Toggle, wie es frühere Versionen dieser Anleitung nutzten. Drei Dinge zum Hinzufügen, damit es benutzbar bleibt:</p>
<p>1. Accessibility: <code>role="dialog"</code>, <code>aria-modal="true"</code> und <code>aria-labelledby</code>, das auf den Titel zeigt; bewege den Fokus beim Öffnen auf den Close-Button und stelle ihn beim Schließen wieder her.</p>
<p>2. Scroll-Lock: <code>document.body.style.overflow = 'hidden'</code> versagt auf iOS Safari. Nutze dort stattdessen das <code>position: fixed</code>-Body-Pattern.</p>
<p>3. Animationen: Wickle jede Transition und jedes Keyframe in <code>@media (prefers-reduced-motion: no-preference)</code> und füge <code>z-index: 9999</code> hinzu, damit das Overlay Carrds Markup überdeckt.</p>
</Accordion>

## Option 2: Klick-getriggertes Popup

Dieses Popup öffnet, wenn der Besucher einen Button klickt. Besser für Produktdetails, AGB, Preistabellen oder alles, was zu lang für die Hauptseite ist. Wenn du einen [floating WhatsApp-Chat-Button](/de/carrd-whatsapp-button/) auf Carrd genutzt hast, ist das Interaktionsmodell dasselbe: ein persistenter Trigger, den der Besucher selbst drückt.

Die Version unten nutzt die Popover API. Das Ergebnis ist ein Carrd-Popup ohne JavaScript: Der Trigger-Button spricht mit dem Popover über das `popovertarget`-Attribut, Light-Dismiss (Klick außerhalb) ist nativ, Escape funktioniert nativ, und das Panel rendert im Top-Layer. Browser-Support: Chrome/Edge 114+, Safari 17+, Firefox 125+ (MDN-Compat-Daten, geprüft September 2026). Sicher auf jedem Evergreen-Browser.

<Notice type="info" title="Dieses Embed nutzt Style: Inline">
Der Code unten enthält einen sichtbaren „Learn More“-Button, setze dieses Embed-Element also auf <strong>Type: Code, Style: Inline</strong> und ziehe es an die Stelle, wo der Button erscheinen soll. Ein Hidden-Body-End-Embed würde den Button unter deine ganze Site schieben. Das Popover selbst öffnet trotzdem zentriert über der Seite.
</Notice>

    <button class="click-modal-btn" popovertarget="svcModal" popovertargetaction="hide">Got It</button>
  </div>
</div>
```

Kein `<script>`-Block. Das Default-`popover`-Verhalten (`popover="auto"`) gibt dir Light-Dismiss, Escape und Top-Layer-Rendering von allein. Leaner wird ein Carrd-Dialog nicht.

### Den Trigger-Button hinzufügen

Drei Wege, den Trigger zu verdrahten, sortiert danach, wie sehr ich ihnen vertraue:

1\. Trigger-Button im Embed (Pro Standard, funktioniert überall). Der `<button popovertarget="svcModal">` im Code oben ist Teil des Embed-Markups. Füge den ganzen Block in ein Inline-Embed an der Stelle ein, wo der Button sitzen soll, veröffentliche, fertig. Null JavaScript, null Pro-Plus-Voraussetzung.

2\. Nativer Carrd-Button + Events (Pro Plus). Du willst Carrds eigenes Button-Styling? Auf Pro Plus fügst du ein natives Button-Element hinzu, setzt seine URL auf `browser:none`, dann öffne Settings → Events → On Click und führe aus:

```js
document.getElementById('svcModal').showPopover();
```

Für diesen Weg lösche die Zeile `<button class="popup-trigger" ...>` aus dem Embed. Ohne sichtbares Markup stellst du das Embed auf Hidden, Body End, damit das Popover nicht an eine Sektion gebunden ist. Vergiss die Idee, `popovertarget` als eigenes Attribut an den nativen Button zu hängen: Carrd rendert Buttons als `<a>`-Links, und `popovertarget` funktioniert nur auf `<button>`- und `<input>`-Elementen. Das On-Click-Event ist der dokumentierte Carrd-Weg und der saubere, wenn du den Plan hast.

3\. `javascript:`-URLs, undokumentiert. Nutzung auf eigenes Risiko. `javascript:document.getElementById('svcModal').showPopover()` ins URL-Feld eines Buttons zu schreiben kann funktionieren, aber `javascript:` gehört nicht zu Carrds dokumentierten URL-Typen (die dokumentierte Liste umfasst site/email/phone/sms/skype/browser/section/scroll-point/clipboard/copy, Stand September 2026).

<Notice type="warning" title="javascript:-URLs sind undokumentiert">
Carrd kann <code>javascript:</code>-URLs ohne Warnung oder Changelog-Eintrag streichen oder blockieren. Wenn du diesen Trick nutzt, teste ihn auf der Live-Site, bevor du den Link teilst, und teste nach jedem Carrd-Update neu. Nimm lieber Weg 1 oder 2.
</Notice>

Wenn der Trigger nichts tut, müssen `popovertarget` und die Popover-`id` exakt übereinstimmen, inklusive Groß-/Kleinschreibung. `popovertarget="svcModal"` gehört zu `id="svcModal"`. Ein Tippfehler und der Button ist taub.

### Mobile-Fallback: Scroll-Depth-Trigger

Bei mobilen Besuchern zeigt sich Intent als Scrollen, nicht als Hovern nahe dem Schließen-Button. Füge diesen Block in dasselbe Embed ein, unterhalb des vorhandenen schließenden `</script>`-Tags (er hat eigene `<script>`-Tags, also nicht in das erste nisten). Er feuert einmal, wenn der Besucher 50 % der Seite passiert, und respektiert dasselbe `exitModalShown`-Flag:

```html
<script>
  // Mobile fallback: show once at 50% scroll depth
  window.addEventListener('scroll', function () {
    if (exitShown || sessionStorage.getItem('exitModalShown')) return;
    var scrolled = window.scrollY / (document.body.scrollHeight - window.innerHeight);
    if (scrolled > 0.5) {
      showExitModal();
    }
  }, { passive: true });
</script>
```

Tune den `0.5`-Schwellenwert an deine Seitenlänge. Auf einer langen Sales-Page ist 0.7 oft weniger nervig; auf einer kurzen One-Page-Site 0.4. Das `{ passive: true }`-Flag verhindert, dass der Scroll-Handler die Scroll-Performance bremst.

**Verifizieren:** Öffne die Site auf einem Desktop und einem echten Phone. Auf dem Desktop feuert das Popup genau einmal, wenn der Cursor oben aus dem Fenster wandert. Auf dem Smartphone feuert es genau einmal, wenn du über die Seitenmitte scrollst. Keins von beiden feuert in derselben Session nochmal.

## Verifizieren, Failure-Modes und Rollback

<Notice type="info" title="Teste auf der veröffentlichten Site">
Carrd führt Embed-Code in der Builder-Vorschau nicht aus, nur die Live-URL sagt dir also etwas. Jeder Check unten läuft gegen die veröffentlichte Site, in einem Inkognito-Fenster (frisches <code>sessionStorage</code>), auf Desktop und einem echten Phone.
</Notice>

Nach dem Veröffentlichen gehe diese Checkliste durch:

<ListCheck>
<ul>
<li>Öffne die Live-URL im Inkognito-Fenster und bestätige, dass das richtige Popup für seinen Trigger feuert (Verzögerung, Klick, Exit oder Scroll-Tiefe)</li>
<li>Drücke Escape. Das Popup sollte schließen (Optionen 1 und 2 machen das nativ)</li>
<li>Klicke außerhalb der Karte. Ein Backdrop-Klick sollte es schließen</li>
<li>Schließe und lade im selben Tab neu. Es sollte NICHT wieder erscheinen (Session-Capping funktioniert)</li>
<li>Schicke das Formular mit einer echten Adresse ab und bestätige, dass es in deinem ESP-Dashboard landet</li>
<li>Wiederhole den Trigger-Test auf einem echten Phone, besonders das Scroll-Fallback für Option 3</li>
<li>Wenn du einen `javascript:`-URL-Trigger genutzt hast, teste ihn auf der Live-Site nochmal, bevor du den Link teilst</li>
</ul>
</ListCheck>

Dinge, die brechen, und der Fix:

- **Vorschau und Live-Site widersprechen sich.** Vertraue immer der Live-URL. Veröffentliche neu, wenn der Editor Änderungen zeigt, die die Live-Site nicht hat.
- **Embed rendert nicht.** Type ist nicht Code, Style ist falsch (Hidden, Body End für Optionen 1 und 3; Inline für Option 2), oder dein Plan liegt unter Pro Standard. In dieser Reihenfolge.
- **Popup erscheint hinter dem Seiten-Content.** Nur ein Problem für die alten div-Versionen. Die brauchen `z-index: 9999`. Die `<dialog>`- und Popover-Versionen leben im Top-Layer und überspringen diese ganze Bug-Klasse.
- **Dieselbe Option zweimal eingefügt, beide kaputt.** ID-Kollisionen. Benenne jede ID, Klasse, Variable und Funktion im zweiten Block um, oder halte ein Popup pro Seite.
- **Exit-Popup feuert nie auf Phones.** Erwartet. Keine Maus. Füge das Scroll-Depth-Fallback hinzu.
- **Hintergrund scrollt hinter einem div-basierten Popup auf iOS.** Der `overflow: hidden`-Body-Lock hält auf iOS Safari nicht immer. Nutze das `position: fixed`-Body-Pattern im Legacy-Code und teste auf einem echten iPhone.
- **Mailchimp-Fake-Signups.** Regeneriere den Embedded-Formular-Code, damit reCAPTCHA funktioniert, dann ersetze den Endpoint.
- **Ein Trigger-Button tut nichts.** Bei Popovers muss `popovertarget` exakt zur `id` passen. Bei `javascript:`-URLs gehe davon aus, dass Carrd sie ignoriert hat. Nutze stattdessen einen Button im Embed oder Pro-Plus-Events.

Zum Entfernen des Popups (Rollback) lösche das Embed-Element im Carrd-Builder und veröffentliche neu. Es gibt keine Theme-Dateien, kein siteweites JavaScript, nichts sonst aufzuräumen. Das ist die Schönheit des Embed-Ansatzes. Wenn du lokal getestet hast, beachte, dass `sessionStorage`-Keys wie `modalShown` und `exitModalShown` pro Tab persistieren; nutze Inkognito für saubere Tests oder lösche sie in DevTools → Application → Session Storage. Die ESP-Verdrahtung musst du nur rückgängig machen, wenn du eine eigene Liste für das Popup angelegt hast.

## Tipps für effektive Popups

Sei nicht nervig. Zeig das Popup einmal pro Session, nicht bei jedem Seitenaufruf. Der gesamte Code oben nutzt `sessionStorage`, um wiederholte Popups zu verhindern.

Frequency-Cap smart. `sessionStorage` = einmal pro Session (das nutzt der Code). Für hartnäckige Angebote gibt dir `localStorage` plus ein 7-Tage-Ablauf-Timestamp einmal pro Woche. Weniger Impressionen, weniger Irritation, ähnliche Conversion.

Mach das Schließen leicht. Der Schließen-Button sollte offensichtlich sein. Lass Leute außerhalb klicken, um zu schließen. Unterstütze die Escape-Taste. Optionen 1 und 2 bekommen alle drei gratis.

Biete Mehrwert. Niemand will sich für „Updates“ anmelden. Biete etwas Konkretes: einen Rabatt, einen kostenlosen Guide, exklusiven Content.

Kombiniere Angebote mit Dringlichkeit. Ein Rabatt konvertiert besser mit einer Deadline daneben. Leg einen [gestylten Countdown-Timer](/de/carrd-countdown-stylen/) in den Popup-Body oder die Sektion, auf die er verlinkt.

Teste auf Mobilgeräten. Manche Popup-Styles funktionieren auf kleinen Screens nicht gut. Prüfe dein Design auf echten Phones, nicht nur in der responsiven Vorschau des Editors.

Bedenke das Timing. Sofortige Popups wirken aggressiv. 3–5 Sekunden warten oder auf Scroll zu triggern funktioniert oft besser.

Respektiere Accessibility-Defaults. Behalte `prefers-reduced-motion`-Wrapper um Animationen (schon im Code) und unterstütze immer Escape plus Click-Outside. Die `<dialog>`- und Popover-Versionen handhaben das Fokus-Verhalten nativ.
