[Herdr](https://herdr.dev/) ist eine kostenlose Apache-2.0-Runtime für Coding-Agents mit über 52.000 GitHub-Stars und besteht heute aus zwei offiziellen Produkten: **Herdr TUI (`v0.9.5`)** in deinem Terminal sowie den nativen **Herdr Desktop (`v0.1.16`) + Mobile-Apps** auf Basis von `herdr-core` (`v0.1.21`).

Wer drei, fünf oder zehn KI-Coding-Agents parallel laufen lässt (Claude Code in einem Pane, Codex im nächsten, OpenCode oder Pi im dritten), verliert in normalen Tabs schnell den Überblick. Herdr löst genau das mit einer Live-Status-Sidebar (`working`, `blocked`, `done`, `idle`), persistenten Hintergrund-Sessions und Multi-Machine-SSH.

Seit meinem ersten Test im Juli 2026 hat sich das Projekt massiv verändert: Damals ein Solo-Projekt mit 15.000 Stars unter AGPL, heute unterstützt von Y Combinator und einer $6M-Seed-Runde (Bessemer Venture Partners), umgestellt auf **Apache-2.0**, samt nativer Desktop-App und kostenloser iOS-/Android-App.

<Notice type="info" title="Zwei offizielle Herdr-Produkte mit getrennten Daemons">
**Herdr TUI (`herdr` v0.9.5)** läuft im Terminal auf einem eigenen Server. **Herdr Desktop (`herdr-app` v0.1.16)** und **Herdr Mobile** laufen auf **`herdr-core` (`hc` v0.1.21)** mit dem offenen OSC-7501-Protokoll. Beide **teilen keine laufenden Agents**: Panes aus `herdr` TUI erscheinen nicht in `herdr-app` oder Herdr Mobile.
</Notice>

## Was ist Herdr und wie unterscheiden sich beide Linien?

Herdr hält deine Agents in einem Hintergrund-Daemon am Leben, sodass geschlossene Fenster, SSH-Abbrüche oder Laptop-Standby keine Arbeit stoppen, und zeigt in einer gemeinsamen Sidebar, welcher Agent auf welcher Maschine gerade auf dich wartet.

| Produktlinie | Binary / Repo | Aktuelle Version (Nov 2026) | Passt am besten zu | Erweiterungen | Offizielle Mobile-App |
|---|---|---|---|---|---|
| **Herdr TUI** | `herdr` (`herdrdev/herdr`, 52K+ Stars) | `v0.9.5` (14. Okt. 2026) | Terminal-Puristen, reine SSH-VPS, Ghostty/Kitty/WezTerm | TUI-Plugins (`herdr plugin install` + `herdr plugin update`) | Nein (Moshi, ColliePWA oder SSH) |
| **Herdr App + Core** | `herdr-app` + `hc` (`herdrdev/herdr-app`, `herdrdev/herdr-core`) | `v0.1.16` / `v0.1.21` (Nov 2026) | Natives GPU-Fenster, Agent-gebaute UIs, offizielle Handy-Steuerung | 312+ Layouts & 576+ JS-Mods (`herdr.dev/gallery`) | Ja (kostenlos für iOS, iPadOS & Android per SSH/Tailscale) |

![Herdr-Architektur mit Client-Server-Modell, PTY-Panes, Agent-Status-Sidebar und Socket-API](@assets/images/26/07/herdr-architecture.webp)

Beide Linien nutzen echte PTYs im lokalen Hintergrunddienst ohne Cloud-Vermittler. Herdr TUI bleibt eine ~11 MB große Rust-Binary in deinem gewohnten Terminal; Herdr Desktop kombiniert `herdr-core` mit einer nativen Rust/GPUI-Oberfläche (samt Ghostty-Terminal-Engine), deren Layouts und JavaScript-Mods dein Agent direkt auf der Platte umbauen kann.

![Offizielle Herdr Mobile Inbox auf dem iPhone mit Agents sortiert nach Needs you, Done, Working und Idle](@assets/images/26/11/herdr-mobile-inbox.webp)

## Herdr installieren (TUI oder Desktop + Core)

<Tabs>
<Tab name="Herdr TUI (Linux / macOS)">

```bash
curl -fsSL https://herdr.dev/install.sh | sh
# oder: brew install herdr
# oder: mise use -g herdr

herdr --version
```

`herdr update` aktualisiert die Binary und zeigt an, welche laufenden Server noch auf der alten Version stehen.

</Tab>
<Tab name="Herdr TUI (Windows / Nix)">

```powershell
# Windows PowerShell
irm https://herdr.dev/install.ps1 | iex
```

Für Nix stellt `herdrdev/herdr-nix` vorgebaute Binaries über Cachix bereit, sodass kein Rust+Zig-Quellbau mehr nötig ist.

</Tab>
<Tab name="Herdr Desktop App + Core">

```bash
# macOS (Apple Silicon)
brew install --cask herdr-app

# Linux (x86_64 und ARM64, benötigt Vulkan)
curl -fsSL https://releases.herdr.dev/app/install.sh | sh

# Eigenständiges herdr-core (hc) für einen Headless-Linux-VPS
curl -fsSL https://releases.herdr.dev/core/install.sh | sh
```

</Tab>
</Tabs>

### Erste Schritte und Remote-SSH

Starte in der TUI eine benannte Session mit `herdr session attach work`. Wenn du auf `v0.9.5` aktualisiert hast, führe `herdr integration install codex` erneut aus (v0.9.5 hat die fehleranfälligen Codex-Turn-Hooks entfernt und nutzt wieder saubere Screen-Erkennung):

```bash
herdr integration install claude
herdr integration install codex
herdr integration install copilot
```

![Herdr Remote-SSH-Workflow zwischen Laptop und VPS-Session-Server](@assets/images/26/07/remote-ssh-workflow.webp)

```bash
# Multi-Machine-Sidebar in TUI (v0.9.0+)
herdr machine add workbox --label "Build box"
herdr --remote workbox

# Remote-Maschine in herdr-core (v0.1.21+)
hc machine add box@my-server
hc run --on my-server --bg claude
hc ls
```

<Notice type="warning" title="Remote-Linux-Agents nach SSH-Logout am Leben halten">
Falls systemd deine Prozesse beim Ausloggen beendet, aktiviere Linger auf dem VPS (`sudo loginctl enable-linger $USER`). Ab `herdr-core v0.1.21` warnen `hc machine add` und `hc server status` automatisch mit dem passenden Befehl.
</Notice>

## Agent-zu-Agent-Orchestrierung

Sowohl `herdr` TUI als auch `herdr-core` erlauben es einem Haupt-Agenten, Helfer zu starten, per `wait` auf Ergebnisse zu warten und Ausgaben direkt auszulesen.

![Orchestrierungs-Flussdiagramm: Haupt-Agent startet Hilfs-Agents über die Socket-API und liest Ergebnisse aus](@assets/images/26/07/orchestration-flowchart.webp)

```bash
# In herdr-core (hc)
hc run --bg --name review codex "review src/x.rs. Done: hc send $HC_TERMINAL_ID"
hc wait review
hc read --lines 60 review
hc send review "prüfe auch die Edge-Case-Tests"
```

Mit `hc --skill` liest jeder Agent die komplette Anleitung auf einmal ein. Für strukturierte Aufgaben-Boards lohnt sich zusätzlich ein Blick auf [Hermes Kanban](/de/hermes-kanban-einrichten/).

## Herdr vs tmux vs Zellij

| Merkmal | Herdr TUI (`v0.9.5`) | Herdr App + Core (`v0.1.16`) | tmux | Zellij |
|---|---|---|---|---|
| Agent-Status-Sidebar | Ja (Hooks + Screen) | Ja (offenes OSC 7501) | Nein | Nein |
| Orchestrierung (`wait`/`send`) | Ja (`herdr`) | Ja (`hc`) | Nur Scripting | Nur Plugins |
| Maus-Bedienung | Ja | Natives GPU-Fenster (GPUI) | Config nötig | Ja |
| Multi-Machine-SSH | Ja (`herdr machine add`) | Ja (`hc machine add`) | Manuell | Manuell |
| Offizielle Mobile-App | Nein (Moshi / ColliePWA / SSH) | Ja (iOS, iPadOS, Android) | Nein | Nein |
| Plugin-Sandboxing | Nein (Trusted Code) | Nein (Trusted JS-Mods) | Nein | Ja (WASM) |
| Lizenz | Apache-2.0 | Apache-2.0 | ISC | MIT |

Den kompletten Vergleich inklusive [Superlogical Rex](/de/superlogical-rex/) und [Tern](/de/tern-terminal/) findest du bei den [besten Terminal-Multiplexern](/de/beste-terminal-multiplexer/).

## Ehrliche Vorbehalte vor dem Umstieg

<ListCheck>
<ul>
<li><strong>Zwei getrennte Daemons:</strong> Panes aus <code>herdr</code> TUI erscheinen nicht in <code>herdr-app</code> oder Herdr Mobile. Entscheide dich pro Workflow für eine Runtime.</li>
<li><strong>Pre-1.0-Tempo:</strong> <code>0.9.x</code> und <code>0.1.x</code> entwickeln sich schnell; Mod-APIs und Hooks ändern sich gelegentlich.</li>
<li><strong>Keine Sandbox:</strong> TUI-Plugins und Desktop-JS-Mods laufen mit deinen Nutzerrechten. Vor der Installation kurz prüfen.</li>
<li><strong>Desktop-Telemetrie per Default:</strong> Herdr TUI sendet keine Telemetrie; in <code>herdr-app</code> lässt sie sich unter Settings &gt; Privacy abschalten.</li>
<li><strong>Host-Reboots:</strong> Client schließen unterbricht nichts, ein Server-Neustart schon. Mit <code>restore_screen = true</code> in <code>herdr-core</code> bleibt zumindest der letzte Bildschirminhalt sichtbar.</li>
</ul>
</ListCheck>

## Häufige Fragen (FAQ)

<Accordion label="Ist Herdr kostenlos und Open Source?" group="faq" expanded="true">
Ja. Herdr TUI, Herdr Desktop App und `herdr-core` stehen unter **Apache-2.0** (2026 von AGPL-3.0 umgestellt). Auch die offizielle Herdr Mobile App für iOS und Android ist kostenlos und ohne Account nutzbar.
</Accordion>

<Accordion label="Sollte ich mit Herdr TUI oder der Herdr Desktop App starten?" group="faq">
Nimm **Herdr Desktop App** (`herdr-app`), wenn du ein natives GPU-Fenster, 312+ Community-Layouts und die kostenlose offizielle Herdr Mobile App willst. Nimm **Herdr TUI** (`herdr`), wenn du in Ghostty, WezTerm oder Kitty bleiben und das TUI-Plugin-Ökosystem nutzen möchtest.
</Accordion>

<Accordion label="Warum erscheinen meine TUI-Sessions nicht in Herdr Desktop oder Mobile?" group="faq">
Beide nutzen eigene Hintergrund-Server (`herdr` vs `herdr-core` / `hc`). Sie können parallel auf demselben Host laufen, teilen sich aber keine Panes.
</Accordion>
