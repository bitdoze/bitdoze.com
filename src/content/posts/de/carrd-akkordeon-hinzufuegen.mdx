```html
<button class="accordion" aria-expanded="false">Your question here?</button>
<div class="panel">
  <p>Your answer goes here. You can include multiple paragraphs, lists, or inline HTML.</p>
```

## Das Akkordeon barrierefrei machen (aria-expanded)

Das Markup nutzt bereits echte `<button>`-Elemente, Tastatur-Support kommt also gratis. Was fehlt, ist der Zustand: Screenreader können nicht erkennen, ob eine Frage offen ist. Zwei Zeilen fixen das.

Der Click-Handler macht aktuell `this.classList.toggle("active")` und ignoriert das Ergebnis. Fange den neuen Zustand ab und spiegele ihn nach `aria-expanded`:

<Tabs>
<Tab name="Basis-Skript">

```html
<script>
  // Accordion script
  var acc = document.getElementsByClassName("accordion");
  for (var i = 0; i < acc.length; i++) {
    acc[i].addEventListener("click", function () {
      this.classList.toggle("active");
      var panel = this.nextElementSibling;
      if (panel.style.maxHeight) {
        panel.style.maxHeight = null;
      } else {
        panel.style.maxHeight = panel.scrollHeight + "px";
      }
    });
  }
</script>
```

</Tab>
<Tab name="Barrierefrei (aria-expanded)">

```html
<script>
  // Accordion script (accessible)
  var acc = document.getElementsByClassName("accordion");
  for (var i = 0; i < acc.length; i++) {
    acc[i].addEventListener("click", function () {
      var open = this.classList.toggle("active");
      this.setAttribute("aria-expanded", open);
      var panel = this.nextElementSibling;
      panel.style.maxHeight = open ? panel.scrollHeight + "px" : null;
    });
  }
</script>
```

</Tab>
<Tab name="Multi-Embed-sicher">

```html
<script>
  // Accordion script (multi-embed safe)
  var acc = document.getElementsByClassName("accordion");
  for (var i = 0; i < acc.length; i++) {
    if (acc[i].dataset.bound) continue; // already wired by another copy
    acc[i].dataset.bound = "1";
    acc[i].addEventListener("click", function () {
      this.classList.toggle("active");
      var panel = this.nextElementSibling;
      if (panel.style.maxHeight) {
        panel.style.maxHeight = null;
      } else {
        panel.style.maxHeight = panel.scrollHeight + "px";
      }
    });
  }
</script>
```

</Tab>
</Tabs>

Mit dem barrierefreien Skript braucht außerdem jedes `<button class="accordion">` ein `aria-expanded="false"` im Markup (bereits in Schritt 3 ergänzt). `classList.toggle` gibt den neuen Zustand zurück – derselbe Klick, der das Panel öffnet, setzt das Attribut also auf `true`, und der nächste Klick stellt es zurück.

<Notice type="info" title="Nicht live getestet">
Diese Zwei-Zeilen-Variante war Stand Oktober 2026 noch nicht durch einen echten Carrd-Publish gelaufen. Es ist eine kleine Änderung am Basis-Skript, verifiziere sie also auf deiner veröffentlichten Seite: Klicke eine Frage und inspiziere den Button in den DevTools, um zu bestätigen, dass <code>aria-expanded</code> zwischen false und true wechselt.
</Notice>

## Mehrere Akkordeon-Bereiche auf derselben Seite einbetten

Brauchst du zwei oder mehr getrennte FAQ-Gruppen auf einer Carrd-Seite, füge pro Gruppe ein Inline-Embed hinzu. Ein Haken: Das Skript des Plugins hängt einen Click-Handler an jeden `.accordion`-Button auf der Seite, nicht nur an die im eigenen Embed. Bei zweimal eingefügtem kompletten Code bekommen die Buttons der ersten Gruppe zwei Handler. Jeder Klick öffnet das Panel und schließt es sofort wieder – die Gruppe wirkt tot.

Der Fix ist, diese Version des `<script>`-Blocks in jeder Kopie zu nutzen. Sie überspringt Buttons, die eine andere Kopie bereits verdrahtet hat. Willst du zusätzlich das `aria-expanded`-Verhalten, bleibt der Guard oben in der Schleife und die zwei Aria-Zeilen wandern in den Listener, so:

```html
<script>
  // Accordion script (multi-embed safe + accessible)
  var acc = document.getElementsByClassName("accordion");
  for (var i = 0; i < acc.length; i++) {
    if (acc[i].dataset.bound) continue; // already wired by another copy
    acc[i].dataset.bound = "1";
    acc[i].addEventListener("click", function () {
      var open = this.classList.toggle("active");
      this.setAttribute("aria-expanded", open);
      var panel = this.nextElementSibling;
      panel.style.maxHeight = open ? panel.scrollHeight + "px" : null;
    });
  }
</script>
```

Der `<style>`-Block darf in jedem Embed dupliziert bleiben; identische CSS-Regeln kollidieren nicht. Jeder Button braucht weiterhin sein `<div class="panel">` direkt dahinter, weil das Skript das Element öffnet, das unmittelbar auf den geklickten Button folgt.

## Fehlerbehebung: Carrd-Akkordeon funktioniert nicht

Wenn dein Carrd-Akkordeon nach dem Veröffentlichen nicht funktioniert, ist die Ursache fast immer eine dieser.

Erscheint das Akkordeon nach dem Veröffentlichen nicht, prüfe, ob Type des Embed-Elements auf Code und Style auf Inline steht und ob es in dem Abschnitt liegt, in dem du es erwartest. Bestätige außerdem, dass dein Carrd-Plan Embeds unterstützt (Pro Standard oder höher).

Siehst du das Embed-Element nicht unter Add Element, liegt der Plan unter Pro Standard. Der Free-Tier deckelt auf 3 Seiten und schließt Embeds komplett aus. Upgrade, oder teste erst mit dem 7-Tage-Pro-Trial.

Sieht das Akkordeon kaputt oder ungestylt aus, stelle sicher, dass du den kompletten Code – inklusive des `<style>`-Blocks oben – in das Code-Feld eingefügt hast.

Färbt sich der ganze Abschnitt grau, nutzt deine Kopie einen nackten `.active`-Selektor, der Carrds aktiven Abschnitt trifft. Ändere ihn zu `.accordion.active` (siehe Schritt 4).

Tut ein Klick auf eine Frage nichts, öffne die Browser-Konsole und suche nach JavaScript-Fehlern. Hast du den kompletten Code in zwei Embeds eingefügt, bekommen die Buttons der ersten Gruppe zwei Click-Handler, die sich gegenseitig auslöschen. Nutze das Skript aus dem Abschnitt zu mehreren Akkordeons weiter oben.

Ist der Text auf dem Handy zu klein, ergänze eine font-size-Überschreibung im Style-Abschnitt des Codes. Zum Beispiel: `.accordion { font-size: 16px; }` und `.panel p { font-size: 15px; }`.

Zeigt der Download-Link eine Cloudflare- oder Zwischenseite, öffne ihn in einem normalen Browser. Der Link sitzt hinter einer Bot-Challenge für automatisierte Tools; die Plugin-Seite selbst ist live und per Hand erreichbar.

Alles rückgängig machen: Lösche das Embed-Element und veröffentliche erneut. Nichts anderes in Carrd wird angefasst – ein Rollback ist so einfach.

## Alternativen zum Code-Embed-Ansatz

Wenn du lieber keinen rohen Code pflegen willst oder ein anderes visuelles Design suchst, gibt es drei andere Wege. Mein Standard bleibt das CarrdMe-Snippet oben: kostenlos, kein Branding, komplett bearbeitbar und der kleinste Treffer beim Seitengewicht.

### No-JavaScript-Option: `<details>/<summary>`

Da das Inline-Embed beliebiges HTML annimmt, bekommst du mit nativem `<details>/<summary>` ein funktionierendes Akkordeon ohne eine Zeile JavaScript. Der Browser übernimmt Auf- und Zuklappen:

```html
<details class="faq">
  <summary>What is your refund policy?</summary>
  <p>Full refund within 30 days. Contact support@example.com to start the process.</p>
</details>

<details class="faq">
  <summary>How do I contact support?</summary>
  <p>Email us at support@example.com. We respond within 24 hours.</p>
</details>
```

Style `summary` wie die `.accordion`-Leiste (Hintergrund, Padding, border-radius, Cursor) und tausche das Plus-Icon gegen eine `summary::before`-Regel. Der Tradeoff ist die Animation: Standardmäßig gibt es keine weiche max-height-Transition. Die neueren `interpolate-size`- und `transition-behavior: allow-discrete`-CSS können sie animieren, aber der Browser-Support ist Stand Oktober 2026 noch lückenhaft – ich würde die Animation hier weglassen.

Die JS-Version ist animiert und nimmt das Aria-Upgrade an. `<details>/<summary>` ist kugelsicher, aber nicht animiert.

<Notice type="info" title="Nicht live getestet">
Diese Variante war Stand Oktober 2026 nicht durch einen echten Carrd-Publish gelaufen. Das Embed nimmt beliebiges HTML an, sie sollte also rendern – prüfe sie aber auf deiner veröffentlichten Seite, bevor du sie Besuchern auslieferst.
</Notice>

## Zeigt Google mein FAQ-Akkordeon als Rich Result?
