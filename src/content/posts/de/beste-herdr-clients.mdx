Herdr hat keine offizielle Web-UI, keine offizielle Mobile-App und keine offizielle Desktop-App. Das ist keine Lücke, sondern das Design. Herdr ist eine Runtime: Ein Hintergrund-Server besitzt echte PTYs, Agents wie Claude Code, Codex, OpenCode, Gemini CLI und Pi laufen darin, und jedes Interface ist nur ein Client, der sich verbindet. Die Frage ist also, welche Herdr-Clients du für welchen Job nutzt. Dieser Guide vergleicht das gesamte Client-Ökosystem Seite an Seite: die eingebaute TUI, fünf Community-Herdr-Web-UIs, die Mobile-Apps und die Desktop-Apps. Du bekommst eine Entscheidungstabelle, die Sicherheitslage jedes Clients, die Versions-Fallen und ein gehärtetes VPS-Setup, das du heute Abend aufsetzen kannst. Wie die Runtime selbst funktioniert, liest du zuerst in [unserem Herdr-Review](/de/herdr-agent-multiplexer/). Was du in den Panes laufen lässt, steht in den [besten AI-Coding-Tools und -Agents](https://www.bitdoze.com/ai-coding-tools/).

<Notice type="info" title="Es gibt keine offizielle Herdr-Web-UI">
Die offiziellen Clients sind die TUI (`herdr`), die CLI/Socket-API, schlichtes SSH, `herdr --remote` und das Multi-Machine-Fenster (seit v0.9.0). Alles andere (ColliePWA, herdr-web-ui, Heeler, herdrm, herdrweb, Herdr UI) stammt aus der Community. Reddit-Threads zeigen, dass die Verwirrung echt ist: Leute fragen: „Was ist der Unterschied zur eingebauten Web-UI?“, und die Antwort lautet, dass es keine gibt. Auf [herdr.dev/compare](https://herdr.dev/compare/) heißt es dazu: „Jede UI – unsere eingeschlossen – ist nur ein Client, der sich andockt.“
</Notice>

## Was zählt als Herdr-Client? (Runtime vs. Interface, in 90 Sekunden)

Herdr ist ein Hintergrund-Session-Server plus ein oder mehrere Terminal-Clients. Der Server besitzt echte PTYs; deine Coding-Agents laufen in diesen PTYs. Client schließen, SSH verlieren, Laptop in den Ruhemodus schicken – die Agents laufen weiter. Trenne dich mit `ctrl+b q` von der Session und klinke dich mit `herdr` wieder ein. Das ist der Teil, den tmux-Nutzer schon kennen.

Der Teil, den tmux nicht hat: Jedes Pane ist markiert als **working / blocked / done / idle / unknown**. Herdr erkennt, welcher Agent im Pane läuft, und verfolgt seinen tatsächlichen Zustand. Genau dieser State ist der Grund, warum Handy-Apps und Web-Dashboards hier nützlich sind. In tmux ist ein Handy-Client nur ein Bildschirm, der zeigt, was im Buffer steht. In Herdr kann ein Client „diese drei Agents brauchen deine Freigabe“ anzeigen und dich per Fingertipp antworten lassen.

Unter der Haube ist es eine einzelne Rust-Binary. Kein Electron, kein Account, keine Telemetrie, Apache-2.0. Der Socket liegt unter `~/.config/herdr/herdr.sock` (Windows nutzt eine Named Pipe unter `%APPDATA%\herdr\`). Plugins erweitern Herdr über ein `herdr-plugin.toml`-Manifest und normale Befehle. Mehr zum Trust-Modell weiter unten. Zum Zeitpunkt dieses Tests: stabile Version v0.9.3 (29. September 2026) und etwa 42,7k Sterne auf [github.com/herdrdev/herdr](https://github.com/herdrdev/herdr). Prüfe beide Zahlen bei Bedarf noch einmal; 0.9.x entwickelt sich schnell.

## Herdr-Clients auf einen Blick: die Entscheidungstabelle

| Situation | Bester Client | Freigabe / Exposure | Bewegliche Teile |
|---|---|---|---|
| An der Tastatur der Box | Eingebaute TUI (`herdr`) | Keine | Null extra Services |
| Remote am Laptop | `herdr --remote` / `herdr machine add` | Nur SSH | SSH-Config |
| Agents von Android aus prüfen/freigeben | ColliePWA oder Moshi (Play Store) | Loopback + `tailscale serve`, oder SSH/Mosh | 1 User-Service, oder moshi-hook |
| iPhone als echte Konsole | Heeler oder Moshi (App Store), oder SSH/Mosh | SSH oder Tailnet | 1 Herdr-Plugin, moshi-hook oder nichts |
| Chat-ähnliche Freigaben + Push im Browser | devswha/herdr-web-ui | Loopback + Tailscale | Herdr-Plugin, Port 7317 |
| Volle TUI-Treue im Browser | kcosr/herdr-web | Loopback, Port 8787 | Rust-Bridge, eigene Kopie interner API (experimentell) |
| Native macOS-Konsole über Maschinen | herdrm | SSH | `brew`-Installation |
| Natives Desktop-Fenster auf demselben Daemon | Herdr UI | Nur lokaler Daemon, kein Port | `brew`/`curl`, signierter macOS-Build |
| Desktop-App auf macOS, Linux oder Windows | Moshi Desktop | Loopback + dein SSH | `curl`/`brew`, ~11 MB Tauri-App |
| Git-Worktrees + Web-UI ohne Herdr-Backend | alecuba16/herdr-webui | Loopback, Port 8787 | Eigenes Backend (anderes Kaliber) |

![Flussdiagramm, das deine Situation (Schreibtisch, Handy, Browser, macOS) dem besten Herdr-Client zuordnet](@assets/images/26/10/herdr-client-decision-flow.webp)

Ein ehrlicher Absatz vor den Client-Abschnitten: Von allen Herdr-Clients hier lautet die Antwort für viele von euch „nichts über die TUI hinaus". Wenn du an derselben Maschine sitzt, auf der die Agents laufen, oder mit `ssh` plus `herdr` zufrieden bist, hör hier auf. Füge einen Third-Party-Client hinzu, wenn ein echtes Szenario auftaucht. „Ich will einen blockierten Claude Code vom Sofa aus approven" ist ein echtes Szenario. „Ich habe ein hübsches Dashboard gesehen" ist keins.

## Fang mit der eingebauten TUI an (und schlichtem SSH)

Was du bekommst, bevor du irgendetwas Drittes installierst, ist schon der größte Teil des Werts.

```bash
# Linux / macOS
curl -fsSL https://herdr.dev/install.sh | sh
# oder: brew install herdr
# oder: mise use -g herdr

# Windows (PowerShell): unsignierte Binary, SmartScreen warnt möglicherweise
irm https://herdr.dev/install.ps1 | iex

# Prüfen
herdr -V
herdr status
```

`herdr status` ist deine maßgebliche Übersicht: Es zeigt die Server-Version und verbundene Clients. Nach `herdr update` listet Herdr außerdem, welche laufenden Server noch auf der alten Version sind (seit 0.9.2), inklusive der Befehle zum Neustart jedes einzelnen Servers.

Der tägliche Ablauf ist kurz: `cd ~/project && herdr`, splitten mit `ctrl+b v` (Maus-Split/Ziehen geht auch), trennen mit `ctrl+b q`, später mit `herdr` wieder einklinken. Schlichtes SSH ist offiziell auch der empfohlene Handy-Pfad: Die TUI passt sich schmalen Bildschirmen an, und die Doku zeigt die Nutzung vom Handy über SSH. Empfohlene Handy-Clients laut Projekt: Moshi auf dem iPhone, ansonsten eine beliebige SSH-App.

Für Remote-Arbeit zählen seit 0.9 zwei Dinge:

```bash
# Lokale UI rendert die Session eines Remote-Servers (behält lokales Einfügen von Zwischenablage-Bildern)
herdr --remote workbox

# Multi-Machine-Fenster (v0.9.0+): eine Sidebar, lokale + SSH-Maschinen
herdr machine add workbox --label "Build box"
herdr machine status          # v0.9.2+: prüft alle 30 s neu
herdr machine reconnect       # behandelt MFA direkt im Terminal
```

Leg den Host vorher in `~/.ssh/config` an. Config und Logs liegen in `~/.config/herdr/` (`config.toml`, `herdr.log`, `herdr-server.log`, Sockets, Plugins). Config neu laden mit `herdr server reload-config`.

<Notice type="warning" title="Trennen ist nicht Stoppen">
`herdr server stop` beendet jeden Pane-Prozess – also alle deine Agents. Trenne die Verbindung stattdessen mit `ctrl+b q`. Nach einem Neustart wird das Layout wiederhergestellt, und Agent-Konversationen können nur fortgesetzt werden, wenn die Integrationen native Session-IDs gemeldet haben (`herdr integration install codex|claude|cursor`) oder der Agent Resume selbst meldet (neu in v0.9.2).
</Notice>

Während du den Tag im Terminal verbringst, [mach die TUI mit Oh-My-Zsh-Plugins wohnlich](/de/beste-oh-my-zsh-plugins/) und installiere [zoxide für schnellere Terminal-Navigation](https://www.bitdoze.com/zoxide/). Beides zahlt sich aus, egal ob du je eine Web-UI anfasst.

## Beste Herdr-Web-UI: fünf Community-Optionen im Vergleich

Es gibt keine offizielle Herdr-Web-UI (die Repos namens „herdr-web-ui“ und „herdr-webui“ sind beide Community-Projekte). Stattdessen existiert eine Reihe von Drittanbieter-Clients, die alle auf der Socket-API aufbauen und standardmäßig nur an Loopback binden. Hier der Stand von Oktober 2026 (Sternezahlen ändern sich täglich, also am besten kurz selbst prüfen).

| Projekt | Sterne (Okt 2026) | Port | Installation | Auth-Modell | Funktioniert nicht mehr, wenn… |
|---|---|---|---|---|---|
| [devswha/herdr-web-ui](https://github.com/devswha/herdr-web-ui) | 284 | 7317 | `herdr plugin install` | Loopback + Tailscale-QR | Agent-UIs sich ändern (Chat-Transkripte) |
| [AltanS/collie](https://github.com/AltanS/collie) | 1,2k | Loopback | `curl … collie start` | Tailnet-Identität + Device-Pairing | tmux-/zellij-Modus (experimentell) |
| [sarathsp06/herdrweb](https://github.com/sarathsp06/herdrweb) | 6 | 7331 | eine Go-Binary | Keine, bewusst Loopback-only | Selten; kleines Projekt |
| [kcosr/herdr-web](https://github.com/kcosr/herdr-web) | 41 | 8787 | Release-Tarball + APK | Origin-Allowlist (keine Auth) | Herdr-Upgrades (kopierte interne API) |
| [alecuba16/herdr-webui](https://github.com/alecuba16/herdr-webui) | 34 | 8787 | Vorgefertigter Tarball | Loopback | Es ersetzt das Backend; siehe unten |

Alle binden Loopback. Keine bringt eine echte Authentifizierung mit. Du bist selbst für das Exposure-Modell verantwortlich. Das ist das Thema des Security-Abschnitts weiter unten.

![Eine Herdr-Web-UI im Browser: Agents-Sidebar mit working/blocked/done-Status-Chips, einer Approval-Karte für einen ausstehenden Befehl und einem Live-Terminal-Pane](@assets/images/26/10/herdr-web-ui-interface.webp)

Die Bausteine sind bei allen fünf gleich: eine Agent-Sidebar mit State-Chips, irgendeine Form von Approval-Karte oder Quick Reply und eine Live-Terminal-Ansicht pro Pane. Was sich unterscheidet, ist der Transport (Plugin vs. Standalone-Binary), die Darstellungstreue (Chat-Transkript vs. echtes Terminal) und wie sehr du dem Auth-Modell vertraust.

### herdr-web-ui: Chat-ähnliche Approvals als herdr-Plugin

Der „Messaging-App“-Kandidat in dieser Runde. Agent-Transkripte rendern als Chat (Claude Code, Codex, omp, omo, gjc, pi), das Live-Terminal ist einen Klick entfernt, und Freigaben werden zu antippbaren Karten – inklusive einer Validierung vor dem Absenden, dass die Anfrage noch aktuell ist. Es ist eine PWA mit Esc-/Tab-/Ctrl-Tastenleiste über der Tastatur, Web Push, einem File-Browser und einem QR-Code auf deine Tailscale-Adresse.

![herdr-web-ui im Browser: Workspace-Sidebar links, Agent-Panes mit Tabs und ein Live-Terminal mit Test-Output](@assets/images/26/10/herdr-web-ui-app.webp)

```bash
# benötigt herdr 0.9.0+, Bun 1.4+, Node 18+
herdr plugin install devswha/herdr-web-ui
# läuft auf 127.0.0.1:7317; prüfen:
ss -tlnp | grep 7317
curl -I http://127.0.0.1:7317
```

MIT-lizenziert und installiert sich als normales herdr-Plugin. Ein guter Standard, wenn du Push + Freigaben im Browser willst, ohne dich um einen separaten Server zu kümmern.

### ColliePWA: der beliebteste Third-Party-Herdr-Client

[ColliePWA](https://colliepwa.dev) (AltanS/collie, 1,2k Sterne) ist eine Mobile-first-PWA und der beliebteste Third-Party-Client überhaupt. Der Startbildschirm beantwortet zuerst „Was braucht deine Eingabe?“: blockierte Agents stehen ganz oben, dazu kommen Push-Benachrichtigungen bei blockierten Agents, Quick Replies über `quick-replies.toml`, ein Sondertastenfeld, eine schreibgeschützte „Changes“-Ansicht für Git-Diffs und Dateianhänge. Device-Pairing-Tokens fungieren als Schreib-Zugangsdaten, und „Crews“ bündeln mehrere Maschinen hinter einer URL mit Failover. Sechs UI-Sprachen. Herdr ist das primäre Backend; tmux und zellij sind experimentelle Extras.

![Collie-PWA auf einem Handy: Agent-Inbox gruppiert nach Projekt mit needs-you-, unseen-, working-, done- und idle-Zählern](@assets/images/26/10/collie-dashboard.webp)

```bash
curl -fsSL https://colliepwa.dev/install.sh | sh
collie start        # erkennt herdr/tmux/zellij automatisch; bindet Loopback
# .env: COLLIE_TRUSTED_USER=you@example.com
```

Läuft als systemd-User-Service mit einer Bun-Bridge. Das README nimmt beim Thema Freigabe kein Blatt vor den Mund: **„Niemals `tailscale funnel` hierfür verwenden“**. Behandle die URL wie ein Root-Login. Stell `tailscale serve` davor, damit das Tailnet `Tailscale-User-Login` injiziert und Clients den Identity-Header nicht fälschen können. Es gibt eine interaktive Demo auf colliepwa.dev, wenn du die UI vor der Installation ausprobieren willst. Windows-ZIP-Builds gibt es seit v1.16.0 (experimentell). Querverweis auf den Mobile-Abschnitt: Das ist meine Standardwahl für Android.

### herdrweb: eine One-Binary-Agent-Inbox

Entwickelt, weil „eine Handytastatur tmux in einen winzigen Wut-Simulator verwandelt“ (so der Autor auf r/herdr). Jeder Agent über jeden Space hinweg, sortiert blocked → working → idle, mit einem rohen Terminal-Pane, einer Tastenleiste, einer Slash-Command-Palette, Bildanhängen (die Bridge schreibt die Datei host-seitig und legt den Pfad in deinen Draft), einem Shiki-Diff-Viewer und PWA + Web Push. Nutzt echte RPCs (`pane.read`, `agent.prompt`, `agent.send_keys`), kein Screen-Scraping.

![herdrweb-Agent-Inbox auf einem Handy: jeder Agent über jeden Space hinweg, sortiert working, done, idle](@assets/images/26/10/herdrweb-inbox.webp)

```bash
curl -fsSL https://raw.githubusercontent.com/sarathsp06/herdrweb/main/install.sh | sh
herdrweb -service install && herdrweb -service start   # 127.0.0.1:7331
ss -tlnp | grep 7331
```

Eine eigenständige Go-Binary (SvelteKit-Frontend eingebettet). `-service install` schreibt eine systemd-User-Unit (oder launchd auf macOS). **Keine Authentifizierung, bewusst auf Loopback beschränkt** („ein Bediener, eine Maschine“). Die vom Autor empfohlene Freigabe ist `tailscale serve --bg --https=443 127.0.0.1:7331`. Kleine Sternezahl, aber die sauberste Architektur der Gruppe. MIT.

### kcosr/herdr-web: ein vollwertiges Browser-Terminal

Wenn du die echte TUI im Browser willst (vim, htop, Full-Screen-TUIs, kein umgebauter Chat), ist es dieser. Eine Rust-HTTP/WebSocket-Bridge plus ein React-Frontend mit einem Ghostty-Web/WASM-Renderer. Drag-and-Drop-Uploads in Panes, synchronisiertes Multi-Client-Viewing (zwei Browser auf demselben Pane), eine Android-APK via Capacitor und Launcher-Presets in `~/.config/herdr-web/launcher-presets.json`. Release-Tarballs für Linux x86_64 und macOS; lauscht auf `http://127.0.0.1:8787`; braucht ein laufendes herdr v0.7.2+.

![kcosr/herdr-web auf dem Desktop: ein Chat-Transkript neben echten Terminal-Panes im Browser](@assets/images/26/10/herdr-web-desktop.webp)

<Notice type="warning" title="Experimentell: eigene Kopie privater Herdr-Internals">
kcosr/herdr-web liefert `vendor/herdr-compat` mit – eine ausdrücklich als experimentell markierte Kopie interner Herdr-Strukturen, bei der Änderungen an Runtime und API erwartet werden. Bei herdr-Upgrades kann das brechen (für v0.9 musste wenige Tage nach dem Release ein Kompatibilitäts-Update nachgereicht werden). Das Host-/Origin-Allowlisting ist ein DNS-Rebinding-Schutz, **keine Authentifizierung**. Beachte außerdem: herdr core erlaubt nur einen Terminal-Attach-Owner pro Pane; die Bridge arbeitet daran vorbei. Rechne mit häufigen Änderungen; pinne Versionen und teste Upgrades, bevor du sie übernimmst.
</Notice>

### alecuba16/herdr-webui: Git-Worktrees und eine Web-UI (mit einem Haken)

Die Option, die einer IDE am nächsten kommt: Workspace- und Worktree-Navigation, Terminal-Attach, eine volle Git-UI (Status, Diffs, Staging, Commits, Stash, Blame), ein File-Explorer mit CodeMirror-Editor und Agent-Status-Erkennung für rund 20 CLIs. Vorgefertigte Tarballs für Linux x86_64 und macOS; ein Rust-Axum-Server auf `http://127.0.0.1:8787`; er kann sich selbst als Service installieren (`install-linux`).

![alecuba16/herdr-webui: Dateibaum, Git-Changes-Ansicht und Agent-Panes in einer Web-UI im IDE-Stil](@assets/images/26/10/herdr-webui-git.webp)

Der Haken laut README: Es bringt sein eigenes Backend mit und **kann ganz ohne herdr-Binary laufen**. `--backend-mode external-herdr` (herdr 0.9.0+) klinkt sich stattdessen an einen echten herdr-Server an. Das macht es zu einem anderen Produkt als die übrigen in diesem Abschnitt. Nützlich, aber nicht das Thema dieses Artikels – erwähnenswert, jedoch nicht dein primärer herdr-Client.

<Notice type="warning" title="Plugins laufen ohne Sandbox">
„Ein Plugin ist gewöhnlicher Code, der auf deinem Rechner läuft.“ So formuliert es die offizielle Doku auf [herdr.dev/docs/plugins](https://herdr.dev/docs/plugins/). `herdr plugin install owner/repo` zeigt das Manifest zur Vorschau an, bevor du bestätigst; pinne mit `--ref`, deinstalliere mit `herdr plugin uninstall <id>`. Es gibt kein `plugin update`; reinstalliere zum Aktualisieren. Der Marketplace-Auto-Index öffentlicher Repos mit dem Tag `herdr-plugin` aktualisiert sich alle 30 Minuten, was zeigt, wie jung ein Teil dieses Codes noch ist. Prüfe jedes Plugin vor der Installation und wirf einen Blick auf unsere Shortlist der [besten Herdr-Plugins](/de/beste-herdr-plugins/) für die zehn, die sich zuerst lohnen.
</Notice>

## Herdr-Mobile-App-Optionen: Agents vom Handy aus beantworten

Die Suchnachfrage nach „herdr mobile app“ ist hoch und nach den Web-UIs das zweithäufigste Thema. Es gibt sogar einen „Herdr Mobile“-Eintrag auf Google Play und ein `herdr-mobile-relay`-Projekt im Netz (beides habe ich nicht selbst geprüft; vor einer Installation genau ansehen). Die verlässlichen Optionen teilen sich in zwei Lager, und die Community ist bei beiden meinungsstark. Terminal-native Nutzer setzen auf SSH + Mosh („Mosh ist ehrlich gesagt die einzig richtige Antwort“). Handy-Tipper wollen eine Inbox mit Buttons zum Antippen („Meine Daumen sind fürs Tippen auf Buttons gemacht, nicht für Strg-Tastenkombinationen“). Beides ist legitim. Wenn du das volle Terminal-first-Handy-Setup mit Push-Freigaben willst, deckt unser [Schritt-für-Schritt-Moshi-+-Herdr-Handy-Setup](https://www.bitdoze.com/control-ai-agents-from-phone-moshi-herdr/) diesen Ablauf komplett ab.

Hier die Befehle pro Plattform; die Unterabschnitte darunter beschreiben, wie es sich mit jeder lebt.

<Tabs>
  <Tab name="Android (Collie PWA)">
    ```bash
    curl -fsSL https://colliepwa.dev/install.sh | sh
    collie start
    # .env: COLLIE_TRUSTED_USER=you@example.com
    tailscale serve --bg --https=443 127.0.0.1:<collie-port>

  </Tab>
  <Tab name="iPhone (Heeler)">

    # auf dem Host, auf dem herdr läuft (braucht Node 20+, herdr 0.7.5+, StreamLocal-Forwarding)
    herdr plugin install ZingerLittleBee/Heeler/plugin --ref main --yes
    herdr plugin action invoke heeler.pair    # QR-Code in der App scannen
    ```
    Der Transport ist herdrs JSON-API über SSH-`direct-streamlocal` auf `herdr.sock`. Keine offenen Ports.
  </Tab>
  <Tab name="Jedes Handy (SSH + Mosh)">
    ```bash
    # Host
    sudo apt install -y mosh
    # Handy: beliebiger SSH-Client (JuiceSSH auf Android, Termius, Moshi auf iPhone)
    ssh you@server && herdr
    # optional: mosh you@server  (überlebt Netzwechsel)
    ```
    Null extra Services. Die TUI passt sich schmalen Bildschirmen an.
  </Tab>
</Tabs>

<Notice type="warning" title="Push-Benachrichtigungen brauchen HTTPS">
Web Push erfordert einen sicheren Kontext. Schlichtes `http://ip:7331` lehnt das Push-Abo stillschweigend ab. Nutze `tailscale serve` (oder einen anderen TLS-Proxy), registriere jedes Gerät separat und teste die eingebaute „Send test notification“-Funktion in den UI-Einstellungen, bevor du der Pipeline vertraust.
</Notice>

### Collie auf Android: der PWA-Weg

Zum Home-Screen hinzufügen, und du hast ein echtes App-Icon, Web Push, wenn ein Agent blockiert, Quick Replies und ein Sondertastenfeld. Kein Play Store nötig – ganz bewusst (genauso unter iOS). Device-Pairing fungiert als Schreib-Zugangsdaten, sodass eine geklaute URL allein nur Lesezugriff gibt. Mit `tailscale serve` davor mappt `COLLIE_TRUSTED_USER=you@example.com` den injizierten `Tailscale-User-Login`-Header auf deine Identität; Clients können diesen Header nicht fälschen, solange ihnen nicht das Tailnet gehört. Das ist das ausgereifteste Sicherheitsmodell im Ökosystem. Meine Standardwahl für Android.

### Heeler fürs iPhone: natives iOS mit QR-Pairing

[Heeler](https://heeler.bybee.dev) (ZingerLittleBee/Heeler, 428 Sterne) ist eine native SwiftUI-App im App Store (TestFlight-Fallback, falls dein Land sie nicht hat; prüfe Preis und Verfügbarkeit). Es ist eine Agent-Konsole, nach „blocked“ zuerst sortiert, mit einem Live-Terminal auf libghostty-Basis: natives Scrollback und Touch-Scrolling, das auch Full-Screen-TUIs steuert. Der Composer nutzt die volle iOS-Tastatur (Autokorrektur, IME, Diktat) und schickt die Nachricht komplett ab, wenn du sie sendest. SFTP-Anhänge bis 64 MiB, Worktrees, SSH-Jump-Host-Support, Ende-zu-Ende-verschlüsselter Push mit Live Activities (laut PRIVACY.md kann das Relay den Inhalt nicht lesen).

Host-Anforderungen: Node 20+, herdr 0.7.5+ und sshd mit StreamLocal-Forwarding (der OpenSSH-Standard). Das Pairing läuft QR-basiert über ein herdr-Plugin: `herdr plugin action invoke heeler.pair`, scannen, fertig. Apache-2.0 und ausdrücklich nicht mit dem herdr-Projekt verbunden.

![Heeler auf dem iPhone: die Agents-Konsole listet Sessions mit working/idle-State, Host und Diff-Stats pro Agent](@assets/images/26/10/heeler-iphone.webp)

### Moshi (iOS + Android): das App-Store-Terminal, das Herdr kennt

[Moshi](https://getmoshi.app) ist ein Mobile-Terminal, das um Agent-CLIs herum gebaut ist statt um generisches SSH, und es ist in beiden Stores (iOS 17+, Android 10+). Der kostenlose Tarif deckt ein volles SSH-Terminal mit unbegrenzten Sessions ab, dazu Push-Benachrichtigungen für Agent-Events (mit Ratenlimit), Diktat und biometrischen Key-Schutz. Pro (7,99 $/Monat oder 69,99 $/Jahr, drei Geräte) schaltet frei, was es zu einem echten Herdr-Client macht: Mosh-Transport, die Multiplexer-UI für tmux/Zellij/Herdr, Image-Paste, einen Diff-Viewer und unbegrenzte Inbox-Aktionen.

Zwei Teile sind Herdr-spezifisch. Der Session-Picker listet laufende Herdr-Sessions mit einem Ctrl-B-Tastenpanel und Gesten für schmale Bildschirme, und die Agent-Inbox sortiert Ereignisse in „Needs you / Working / Done“, sodass du nicht durchs Scrollback scrollen musst, um das blockierte Pane zu finden. Beim Paaren eines Hosts wird `moshi-hook` installiert – ein kleiner Daemon, der die eigenen Hooks der Agents liest (Claude Code `PreToolUse`/`Notification`/`Stop`, Codex, OpenCode) und Freigabe-Prompts in Approve/Deny-Pushes auf dem Lockscreen verwandelt. Er taggt Events mit `$HERDR_SESSION`, sodass ein Tipp auf eine Karte dich direkt in genau dieser Session landen lässt.

![Moshi auf dem iPhone mit einer Claude-Code-Session über Mosh und hervorgehobener Funktion zum Einfügen von Screenshots in den Chat](@assets/images/26/09/moshi-dash.webp)

Das ist die Option, die ich jemandem empfehlen würde, der eine echte App statt eines PWA-Workflows will. Das volle Host-Setup (VPS, Hooks, Mosh-Fallen) steht im [Moshi-+-Herdr-Handy-Guide](https://www.bitdoze.com/control-ai-agents-from-phone-moshi-herdr/). Moshi bietet außerdem eine Desktop-App, weiter unten behandelt.

### Schlichtes SSH + Mosh: der offiziell empfohlene Weg

Null extra Services, null Web-Freigabe und die Antwort, die die herdr-Docs zuerst geben: Irgendeine SSH-App, `ssh you@server`, `herdr`. Wenn Netzabbrüche ein Thema sind, füge Mosh hinzu: „Mosh ist ehrlich gesagt die richtige Antwort … ohne Kompromisse“ lautet der Grundtenor auf r/herdr, und er passt zur Grundhaltung dieses Artikels, möglichst wenig bewegliche Teile zu betreiben. Reddit-Nutzer machen genau das: herdr + mosh auf dem Hauptgerät, eine SSH-App auf dem Handy über Tailscale.

Zwei weitere Optionen, die man kennen sollte, weil im Ökosystem jede Woche neue Clients erscheinen: [herdr-remote](https://github.com/dcolinmorgan/herdr-remote) (407 Sterne) liefert eine macOS-Menüleisten-App, ein Handy-Web-Dashboard und One-Tap-Freigaben direkt aus **Telegram** (`/agents`, `/reply`, `/trust`, `/interrupt`, plus ein tägliches `/digest`). Nützlich, wenn du in Telegram lebst; sein Relay bindet `127.0.0.1:8375` und will `HERDR_RELAY_TOKEN` gesetzt haben, bevor irgendein Tunnel läuft. TermRover (termrover.sh) und ShadowTerm sind kommerzielle SSH-/Mosh-Mobile-Terminals; TermRover liefert eine Herdr-kompatible „Agents Fleet“-Ansicht über Hosts hinweg. Alle drei verdienen einen eigenen genauen Blick; keins ist bisher in meinem Standard-Stack.

## Herdr-Desktop-Apps: Herdr UI, herdrm und Moshi Desktop (und warum „Manager-Apps" eine Falle sind)

Wenn du eine echte herdr-Desktop-App willst statt eines Terminal-Fensters, ist [herdrm](https://github.com/missuo/herdrm) (missuo/herdrm, 623 Sterne) die polierteste Antwort auf macOS. Natives SwiftUI + SwiftTerm, kein Electron, macOS 14+, Universal Binary, signiert und notarisiert, Sparkle-Auto-Updates. Eine Sidebar aus Spaces und Agents über lokale + SSH-Geräte hinweg (Remote-Sockets via `ssh -L`, Reconnect pro Gerät mit 1s→30s-Backoff), ⌘K-Suche über jedes Gerät, Benachrichtigungen mit Click-to-Jump und Datei-/Bild-Paste in Agent-Panes (Remote-Pastes streamen über SSH in einen 7-Tage-/50-MB-Cache). Der Unterschied, der zählt: Es attacht echte PTYs via `herdr agent attach`. Es ist ein Client, kein Chat-Wrapper.

```bash
brew install owo-network/brew/herdrm
```

![herdrm auf macOS: eine Spaces/Agents-Sidebar über lokale und SSH-Geräte neben einer Live-Agent-Konsole](@assets/images/26/10/herdrm-desktop.webp)

Auth-Reihenfolge: OpenSSH-Keys/Agent, dann Tailscale SSH (1.98.0+), dann im Keychain gespeichertes Passwort. Das Projekt sagt „early stage"; das README dankt Heeler für Transport-Muster.

### Herdr UI: ein natives Fenster auf demselben Daemon

[Herdr UI](https://herdrui.dev) (penso/herdr-gpui, Apache-2.0, von Fabien Penso) ist der neueste Client auf dieser Liste und der einzige, der ein echtes Desktop-Fenster ist statt eines Terminals oder einer Browser-Seite. Er klinkt sich an den Herdr-Daemon an, den du schon betreibst: TUI und Fenster zeigen dieselben Panes, und die App installiert oder aktualisiert den Daemon selbst nie. Was das Fenster der TUI voraus hat: Arbeit aus Issues verteilen, Side-by-Side-Review, Checkpoints, Teleport zwischen Maschinen und eine Geräte-Übersicht. Ausdrücklich nicht mit dem herdr-Projekt verbunden.

<YouTubeEmbed url="https://www.youtube.com/watch?v=iFQpQHTN4iI" label="Herdr UI im Rundgang: Ein nativer Desktop-Client für den Herdr-Daemon" />

```bash
# macOS 14.2+ (signiert, notarisiert, universal)
brew install penso/tap/herdr-gpui

# Linux x86_64/ARM64 (glibc 2.39+): .deb/.rpm/Arch mit Prüfsumme über APT, DNF oder pacman
curl -fsSL https://herdrui.dev/install.sh | sh

# Windows (experimentell, unsigniert, kein Auto-Update; WSL-Daemons funktionieren)
irm https://herdrui.dev/install.ps1 | iex
```

Es gibt keinen lauschenden Port abzusichern: Es zeichnet die Panes des lokalen Daemons in ein GPU-gerendertes Fenster, sodass die Regel „Jede Web-UI ist eine Root-Shell“ hier nicht greift. Die Reihenfolge läuft umgekehrt: Installiere zuerst herdr, weil Herdr UI nur an einen Daemon andockt, der schon läuft.

Update: Das Herdr-Projekt hat inzwischen seine eigene offizielle native App veröffentlicht (`herdrdev/herdr-app`), auf demselben GPUI-Stack gebaut, mit einem Twist: Das gesamte Interface besteht aus Dateien, die dein Agent umschreiben kann. Unser [Herdr-App-Galerie-Rundgang](/de/herdr-app-layouts-und-mods/) behandelt die App, das Layout-/Mod-System und 20+ Community-Kreationen mit Screenshots.

Jetzt die Falle. herdr.dev/compare unterscheidet die Runtime von Desktop-„Manager-Apps“ (Conductor, Emdash, Superset) und Terminal-Apps (cmux, Warp), deren Agents **stoppen, wenn die App beendet wird**. Diese Apps besitzen die Runtime. herdrm, Herdr UI, Heeler, Collie und der Rest verbinden sich nur damit. Dieser eine Unterschied (Client vs. Runtime-Owner) ist der ganze Grund, warum ein Herdr-Ökosystem überhaupt existieren kann. Wenn du ein Tool wählst, das die Agents selbst verwaltet, hängst du wieder an der Roadmap eines einzelnen Anbieters.

### Moshi Desktop: die plattformübergreifende Antwort

herdrm läuft nur unter macOS, aber [Moshi Desktop](https://getmoshi.app/desktop) deckt den Rest ab: macOS (Apple-Silicon- und Intel-`.dmg`), Windows-x86_64-`.exe` und Linux-`.AppImage`, für alle kostenlos, etwa 11 MB dank Tauri statt gebündeltem Chromium (ein GPU-gerendertes Go-Rewrite ist in der Alpha). Dasselbe Team liefert außerdem eine `moshi`-CLI: `curl -fsSL https://getmoshi.app/install.sh | sh`, dann öffnet `moshi` dieselbe UI in einem Browser auf `127.0.0.1` – eine Loopback-Web-UI für Leute, die gar keine Desktop-App wollen.

Es ist ein Client im hier relevanten Sinn: Deine tmux- und Herdr-Sessions bleiben im Multiplexer, und Desktop liest sie über `moshi-hook` (Loopback-only-Gateway; Remote-Hosts laufen über dein eigenes SSH). Obendrauf kommen eine Chat-Ansicht, Diffs, an Output gepinnte Code-Kommentare, Dev-Server-Previews, die es tunneln kann, und One-Tap-Freigaben. Wenn du es schließt, wird kein einziger Agent beendet – damit ist der komplette „Manager-Apps sind eine Falle“-Test bestanden. Auf macOS lässt es sich auch über `brew tap rjyo/moshi` installieren.

## Security first: Jede Herdr-Web-UI ist eine Root-Shell

Behandle die URL jeder Herdr-Web-UI wie ein Root-Login auf deiner Maschine. Nicht „nur ein Dashboard“. Der Client kann deine Dateien lesen, Befehle in deinen Panes ausführen und alles anfassen, was deine Agent-Sessions an Zugangsdaten halten. Das ist genau der Zweck des Produkts. Die einzige Frage ist, wer diese URL erreichen kann.

Die Auth-Realität pro Client:

- `herdrweb` hat keine Authentifizierung und bleibt bewusst auf Loopback beschränkt („ein Bediener, eine Maschine“).
- `kcosr/herdr-web` nutzt Host-/Origin-Allowlisting. Das Repo sagt es selbst: Das ist ein DNS-Rebinding-Schutz, **keine Benutzer-Authentifizierung**.
- `herdr-web-ui` nutzt standardmäßig Loopback, mit Tailscale-QR für den Handy-Pfad.
- `ColliePWA` hat das ausgereifteste Modell. `tailscale serve` injiziert `Tailscale-User-Login`, `COLLIE_TRUSTED_USER` mappt es auf eine Identität, und Device-Pairing-Tokens sichern Schreibzugriffe ab.
- `alecuba16/herdr-webui` bindet Loopback und kann ganz ohne herdr laufen; sein möglicher Schaden („Blast Radius“) beschränkt sich also auf das, was sein eigenes Backend tut.

Das Muster, das funktioniert: Loopback binden, `tailscale serve` davor (TLS + Identity-Header), nur von Geräten in deinem Tailnet öffnen.

![Diagramm des sicheren Herdr-Web-UI-Exposure-Modells: Tailscale serve steht vor einem Loopback-only-Client](@assets/images/26/10/herdr-webui-security-topology.webp)

<Notice type="error" title="Niemals ins Internet exponieren">
Niemals `0.0.0.0` binden. Niemals `tailscale funnel`. Wenn ein Client die Maschine verlassen muss, gehört er hinter Tailnet-Identität (oder ein gleichwertiges Mesh-VPN) mit TLS. Außerdem: `pane_history = true` in herdr ist experimentell und aus gutem Grund AUS. Persistierte Screens können Secrets enthalten, und es einzuschalten schreibt sie auf die Disk. Wenn du schon Docker-Stacks aus einer Web-UI verwaltest, [gilt dasselbe Loopback-+-Tailscale-Muster für Dockge](https://www.bitdoze.com/dockge-install/).
</Notice>

<ListCheck>
  <ul>
    <li>Loopback-Binding bestätigt: `ss -tlnp | grep -E '7317|7331|8787'` zeigt `127.0.0.1`, nicht `0.0.0.0`</li>
    <li>Freigegeben per `tailscale serve`, niemals `tailscale funnel`</li>
    <li>`COLLIE_TRUSTED_USER` gesetzt (Collie) oder Device-Pairing registriert (Heeler/herdr-web-ui)</li>
    <li>Push über HTTPS von jedem registrierten Gerät getestet</li>
    <li>Plugins vor der Installation geprüft, `--ref` gepinnt, ungenutzte deinstalliert</li>
    <li>`~/.config/herdr` mit restriktiven Berechtigungen im Backup enthalten</li>
  </ul>
</ListCheck>

### Happy Path

1. VPS provisionieren, einen Non-Root-User anlegen, dann:

```bash
sudo apt update && sudo apt install -y tailscale
sudo tailscale up
```

2. Herdr installieren und verifizieren:

```bash
curl -fsSL https://herdr.dev/install.sh | sh
herdr -V && herdr status
```

3. Echte Arbeit starten: `cd ~/project && herdr`, starte deinen Agent in einem Pane so wie sonst auch und trenne die Sitzung mit `ctrl+b q`.

4. Installiere exakt **einen** Client. Handy-first: Collie. Inbox-first: herdrweb.

```bash
# Option A: Collie
curl -fsSL https://colliepwa.dev/install.sh | sh
collie start

# Option B: herdrweb
curl -fsSL https://raw.githubusercontent.com/sarathsp06/herdrweb/main/install.sh | sh
herdrweb -service install && herdrweb -service start
```

5. Stell es ins Tailnet:

<Tabs>
  <Tab name="tailscale serve (empfohlen)">
    ```bash
    tailscale serve --bg --https=443 127.0.0.1:7331
    # Handy-Browser: https://<host>.tailnet.ts.net
    ```
    TLS + Identity-Header + Web Push funktioniert. Das ist der Standard. Nutze `tailscale serve status`, um zu sehen, was veröffentlicht ist, und `tailscale serve reset`, um es wieder zu entfernen.
  </Tab>
  <Tab name="Nur SSH-Tunnel">
    ```bash
    ssh -L 7331:127.0.0.1:7331 you@vps
    # Laptop-Browser: http://127.0.0.1:7331
    ```
    Keine Tailscale-Abhängigkeit, kein Identity-Header und **kein Web Push** (braucht HTTPS). Okay für einen schnellen Blick; nervig als täglicher Handy-Workflow.
  </Tab>
</Tabs>

6. Optional auf einem Mac: `brew install owo-network/brew/herdrm`, dann `herdr machine add workbox --label "Build box"`, sodass eine Sidebar Laptop und VPS abdeckt.

### Rollback / Tear-down

```bash
collie stop                      # oder: herdrweb -service stop / -service uninstall
herdr plugin uninstall <id>      # heeler- / herdr-web-ui-Plugins entfernen
tailscale serve reset            # HTTPS-Freigabe aufheben
```

`herdr server stop` **nur**, wenn du die Agents wirklich beenden willst, nicht für „ich bin für heute fertig“. Auf dem VPS besteht der ganze Stack aus 2–3 nativen Binaries; zum Entfernen löschst du die Service-Unit und das Config-Verzeichnis.

## Versions-Fallen und Failure Modes (0.9.x bewegt sich schnell)

<Notice type="warning" title="0.9.x bewegt sich schnell">
Jeder Client setzt ein anderes herdr-Minimum voraus: herdr-web-ui braucht 0.9.0+, Heeler 0.7.5+ (plus Node 20), kcosr/herdr-web 0.7.2+, alecuba16-External-Mode 0.9.0+. Prüfe am Upgrade-Tag beide Seiten zusammen.
</Notice>

1. **`herdr server stop` killt Agent-Prozesse.** Trennen ≠ Stoppen. Ein Neustart stellt das Layout wieder her, und Conversation-Resume braucht `herdr integration install codex|claude|cursor` (oder einen Agenten, der Resume selbst meldet, v0.9.2+). Verifiziere mit `herdr status`.
2. **Client neuer als Server** nach `herdr update`. Der alte Server läuft weiter; 0.9.2+ listet, welche Server noch veraltet sind, mit Restart-Befehlen. Einen Remote-Server zu ersetzen fragt zuerst nach, weil dabei Pane-Prozesse gestoppt werden. `herdr update --handoff` migriert live (experimentell).
3. **State-Erkennung falsch** (Codex-False-Idle, Claude-Spinner, OpenCode-V2-States). Chat-Transkript-Clients jagen Agent-UI-Änderungen hinterher; die 0.9.2-/0.9.3-Changelogs sind voller Detection-Fixes. Fix: `herdr agent explain <agent> --verbose` zeigt, welche Detection-Regel gegriffen hat, und `herdr server update-agent-manifests` zieht neue Manifeste.
4. **API-Drift.** kcosr/herdr-web bindet eine eigene Kopie des privaten herdr-Protokolls ein und braucht Updates pro herdr-Release. Geh davon aus, dass es bei Major-Upgrades bricht, und pinne Versionen.
5. **Push schlägt still fehl** ohne HTTPS-Secure-Context. Schlichtes `http://ip:7331` nimmt keine Push-Abos an. Pro Gerät registrieren, dann die eingebaute Test-Benachrichtigung nutzen.
6. **Heeler-/SSH-Macken.** StreamLocal-Forwarding muss an sein (OpenSSH-Standard; das Onboarding warnt, wenn deaktiviert). Gespeicherte Maschinen beantworten nie interaktive Prompts, sodass ein Host-Key-Wechsel oder MFA die Maschine „Attention“ zeigen lässt. Einmal `herdr --remote host` interaktiv laufen lassen oder `herdr machine reconnect` (v0.9.2). Passphrase-geschützte Keys müssen im ssh-agent liegen.
7. **Veralteter Multi-Machine-State.** Die Zeilen einer getrennten Maschine bleiben sichtbar, aber gedimmt und gecacht; du kannst nicht hineintippen. Lokal öffnet immer zuerst, sodass ein langsamer VPS deinen Laptop nicht aufhält.
8. **Die CLI zielt immer auf einen Server**, selbst in der 0.9-Multi-Machine-UI. `herdr --machine <label>` (v0.9.1+) leitet Befehle weiter. IDs gelten immer pro Server. Lies sie aus dem `--json`-Output, rate nie.
9. **Schalte kein tmux zwischen herdr und den Agent.** Herdr sieht sonst tmux, nicht den Agent, und die Erkennung bricht ab. Wähle eine Schicht.
10. **Windows-Macken.** `install.ps1` ist eine unsignierte Binary, bei der SmartScreen warnen kann; `install.cmd` ist der Fallback, wenn Endpoint Security den One-Liner blockiert. Schau auf [herdr.dev/docs/windows-beta](https://herdr.dev/docs/windows-beta/), was noch nicht unterstützt wird (direktes Terminal-Attach, Live-Handoff, Clipboard-Image-Bridge).

## Watchlist: Herdr Cloud und wie schnell dieses Ökosystem sich bewegt

Herdr Cloud steht auf einer Warteliste: ein Relay, das deine Maschinen ohne SSH-Setup verbindet, mit Ende-zu-Ende-verschlüsseltem Terminal-Traffic. Der Pitch lautet „Die Cloud verbindet sie nur, statt die Agents selbst zu hosten“ – es könnte also irgendwann die `tailscale serve`-Verkabelung im Referenz-Setup ersetzen. Tritt der Warteliste bei, wenn du neugierig bist; plane noch nicht fest damit.

Das Ökosystem bewegt sich schnell. Mehrere unabhängige Clients erschienen innerhalb weniger Wochen nach dem Multi-Machine-Support von v0.9, und der Plugin-Marketplace indiziert alle 30 Minuten neu. Die Sternezahl (42,7k, Stand Oktober 2026) zieht weiter neue Entwickler an. Manche dieser Clients werden in sechs Monaten Abandonware sein. Halte deinen Stack bei herdr plus einem Client, dann bleibt ein späterer Client-Wechsel einfach. Wenn du verfolgen willst, bei welchen Projekten sich ein GitHub-Star lohnt, ist unsere laufende Liste [empfehlenswerter KI-Repos inklusive des Herdr-Ökosystems](/de/top-ki-github-repos/) ein guter Anlaufpunkt.

## FAQ

<Accordion label="Gibt es eine offizielle Herdr-Web-UI oder Mobile-App?" group="faq" expanded="true">
Nein. Die offiziellen Clients sind die TUI, die CLI/Socket-API, schlichtes SSH, `herdr --remote` und das Multi-Machine-Fenster. Alles andere (ColliePWA, herdr-web-ui, Heeler, herdrm, herdrweb, Herdr UI) stammt aus der Community. Die Namensverwirrung ist dokumentiert: Leute fragen: „Was ist der Unterschied zur eingebauten Web-UI?“, und die Antwort lautet, dass es keine gibt.
</Accordion>

<Accordion label="Herdr vs. tmux für Coding-Agents: was soll ich nutzen?" group="faq">
Herdr legt Agent-bewussten State (working/blocked/done), eine Socket-API und ein Client-Ökosystem auf den tmux-artigen Workflow; tmux plus Mosh bleibt eine legitime terminal-native Antwort. Wenn du nur persistente Panes brauchst, reicht tmux. [Unser Herdr-Review](/de/herdr-agent-multiplexer/) deckt den vollen Vergleich ab. Für eine andere Sicht aufs Multiplexing selbst macht [Superlogical Rex](/de/superlogical-rex/) das Terminal zum Multiplexer, statt einen darin laufen zu lassen (vorerst nur macOS). Alle sechs Optionen sind in unserem [Terminal-Multiplexer-Guide](/de/beste-terminal-multiplexer/) verglichen.
</Accordion>

<Accordion label="Kann ich Claude-Code-Prompts von meinem Handy aus freigeben?" group="faq">
Ja. Collie liefert Karten zum Antippen, herdr-web-ui rendert Freigaben als antippbare Chat-Karten, Heeler bietet verschlüsselten Push plus Live Activities, und Moshi verwandelt Prompts via moshi-hook in Approve/Deny-Pushes auf dem Lockscreen. Alle vier setzen Loopback-Binding plus ein Tailnet voraus, keine öffentliche URL.
</Accordion>

<Accordion label="Ist es sicher, eine Herdr-Web-UI ins Internet zu stellen?" group="faq">
Nein. Loopback binden und `tailscale serve` davor. Niemals `tailscale funnel`, niemals `0.0.0.0`. Die URL ist ein Root-Login auf alles, was der herdr-Prozess erreichen kann: Dateien, Befehle, Agent-Credentials.
</Accordion>

<Accordion label="Kostet das Herdr-Ökosystem etwas?" group="faq">
Nein. Herdr und alle hier behandelten Clients sind kostenlos und Open Source; TermRover und ShadowTerm sind die kommerziellen Ausnahmen. Jeder kleine VPS reicht, Größenordnung 4–5 €/Monat, und es wird keine GPU benötigt; Coding-Agents sind API-limitiert.
