## Warum Dark Mode auf deiner Carrd-Website

Fünf Gründe, je eine Zeile:

1. Weniger Augenbelastung: dunkle Interfaces sind bei wenig Licht angenehmer.
2. Akkueinsparung: auf OLED-Bildschirmen verbrauchen dunkle Pixel weniger Strom.
3. Nutzerpräferenz: viele Menschen bevorzugen einfach eine dunkle UI. Die Option ist billiger Respekt.
4. Lichtempfindlichkeit: manche Besucher brauchen dunklere Interfaces wirklich, für sie ist Dark Mode ein Barrierefreiheits-Feature.
5. Moderne Erwartung: jede größere App liefert inzwischen ein Dark Theme.

Dark Mode ist keine Neuheit mehr. Besucher suchen den Schalter, und wenn er fehlt, springen sie zu einer Seite ab, die ihn hat.

## Wie Dark Mode auf Carrd funktioniert

Carrd hat keinen eingebauten Dark Mode. Ich habe die Doku und das Changelog im September 2026 nochmal geprüft: Es gibt immer noch kein Theme-Switch-Feature. Custom Code ist der einzige Weg.

Der Ansatz hier ist der Standard:

1. Ein `data-theme`-Attribut auf dem Seiten-Root (`light` oder `dark`)
2. CSS-Variablen für Farben, getauscht über `[data-theme="dark"]`
3. Ein Toggle-Button, der das Attribut umkippt
4. `localStorage`, damit die Wahl Reloads überlebt
5. `prefers-color-scheme` als Standard, bevor der Besucher irgendwas wählt

Das Upgrade gegenüber einem naiven Snippet ist das **Zwei-Embed-Muster**. Embed Nr. 1 ist ein winziges Bootstrap in einem Hidden → Head-Embed, das `data-theme` setzt, bevor die Seite rendert. Embed Nr. 2 enthält die Toggle-UI und den Click-Handler (Inline oder Hidden → Body End).

<Notice type="info" title="Warum zwei Embeds?">
Ein All-in-one-Inline-Embed wendet das Theme per JavaScript erst nach dem ersten Paint an. Nutzer mit dunklem System sehen bei jedem Laden einen weißen Blitz. Das Head-Bootstrap läuft vor dem Paint, der erste Frame hat also schon das richtige Theme.
</Notice>

Größere Seiten sind kein Problem. Multi-Section-Websites, die mit Carrds Page-Element gebaut sind, behalten das Theme automatisch. Es ist alles ein Dokument, `data-theme` und `localStorage` bleiben also über Sektionen hinweg erhalten.

Head-Skripte laufen per Spezifikation vor dem Paint, der Fix ist also im Prinzip solide. Carrds genaue Injektionsreihenfolge ist trotzdem eine Bestätigung auf deiner eigenen veröffentlichten Website wert. Siehe die Test-Checkliste unten.

<Notice type="warning" title="Style: Hidden, Location: Head (nicht Inline)">
Der Weißer-Blitz-Fix braucht ein Hidden-Embed, das auf den Head zielt. Eine reine Inline-Einrichtung macht es unmöglich, weil Inline-Code im Seiten-Body nach dem Paint rendert. Wir nutzen beide Styles: Hidden → Head für das Bootstrap, Inline (oder Hidden → Body End) für den Toggle.
</Notice>

Füge das in das Code-Feld ein:

```html
<script>
(function () {
  var t;
  try { t = localStorage.getItem('theme'); } catch (e) {}
  if (!t) t = window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
  document.documentElement.setAttribute('data-theme', t);
})();
</script>
<style>
  :root { color-scheme: light; }
  [data-theme="dark"] { color-scheme: dark; }
</style>
```

Was es tut:

- Liest `localStorage.theme` innerhalb von `try/catch`, damit private Modi, die bei Storage-Zugriff werfen, die Seite nicht brechen
- Fällt auf `prefers-color-scheme: dark` zurück, wenn der Besucher nie ein Theme gewählt hat
- Setzt `data-theme` auf dem Dokument-Root vor dem ersten Paint
- Gibt `color-scheme: light|dark` aus, damit native Formularcontrols, Scrollbars und Autofill dem Theme folgen (`color-scheme` wird in Chrome/Edge 81+, Firefox 96+, Safari 13+ unterstützt)

Carrd injiziert auf veröffentlichten Websites keinen `color-scheme`-Hinweis. Ich habe das rohe HTML einer veröffentlichten Beispielseite im September 2026 geprüft: nichts da. Das Snippet setzt es selbst. Geh nicht davon aus, dass die Plattform es für dich erledigt.

**Verifizieren:** veröffentlichen, die Seite in einem Inkognito-Fenster auf einem Rechner oder Handy mit Dark Mode öffnen. Die Seite sollte dunkel und ohne weißen Blitz kommen. Wenn du immer noch einen Blitz siehst, fehlt das Head-Embed, sitzt an der falschen Stelle, oder du siehst eine gecachte Seite (harte Aktualisierung).

```html
    try { localStorage.setItem('theme', next); } catch (e) {}
    if (document.startViewTransition) {
      document.startViewTransition(function () { apply(next); });
    } else {
      apply(next);
    }
  });

  window.matchMedia('(prefers-color-scheme: dark)')
    .addEventListener('change', function (e) {
      var saved = null;
      try { saved = localStorage.getItem('theme'); } catch (err) {}
      if (!saved) apply(e.matches ? 'dark' : 'light');
    });
})();
</script>
```

Anmerkungen zu den beweglichen Teilen:

- Transitions gelten erst, nachdem `data-theme-ready` auf dem Root gesetzt ist, das initiale Theme animiert also nicht ein.
- `document.startViewTransition` ist Progressive Enhancement (Chrome/Edge 111+, Firefox 144+, Safari 18+). Nicht unterstützte Browser wechseln einfach sofort.
- Der System-Change-Listener läuft nur, wenn der Besucher keine gespeicherte Wahl hat. Sobald er den Toggle klickt, gewinnt seine Wahl, bis er sie löscht.
- Emojis rendern unter Windows und älterem Android unterschiedlich. Wenn du pixelkonsistente Icons willst, ersetze die `☀️`-/`🌙`-Zeichen durch Inline-SVG-Sonnen- und -Mondformen.

**Verifizieren:** klicke den Toggle und die Farben sollten weich überblenden. Neu laden und das Theme sollte kleben (`localStorage.theme` hält `light` oder `dark`). Tabbe zum Button und du solltest den Fokusring sehen, mit `aria-pressed`, das in DevTools → Elements umkippt.

### Dark-Mode-Design-Tipps

Kontrast testen. Text muss auf dem dunklen Hintergrund lesbar bleiben. Lass die Palette im Zweifel durch einen Kontrast-Checker laufen.

Nicht rein schwarz gehen. `#000000` ist hart. Nutze stattdessen dunkle Grautöne wie `#0f172a` oder `#1e293b`.

Deine Akzentfarbe aufhellen. Farben, die auf Weiß funktionieren, wirken auf Dunkel oft matschig. `#3b82f6` wird in der Palette oben genau deshalb zu `#60a5fa`.

Jede Sektion prüfen. Geh die ganze Seite in beiden Themes durch. Manche Elemente brauchen extra Selektoren (nächster Abschnitt).

An Bilder denken. Logos und Grafiken, die für weiße Hintergründe designed wurden, brauchen eventuell eine zweite Version, einen Filter oder einen dezenten Rahmen.

## Umgang mit Carrd-spezifischen Elementen und Bildern

Carrd generiert stabile strukturelle Selektoren: `#wrapper`, `#main` und `.inner` sind auf veröffentlichten Websites vorhanden (im rohen HTML eines veröffentlichten Beispiels im September 2026 verifiziert). Template-spezifische Klassennamen variieren, störrische Elemente brauchen also extra Targeting.

```css
/* Target specific Carrd elements */
[data-theme="dark"] .inner,
[data-theme="dark"] .container,
[data-theme="dark"] [class*="style1"],
[data-theme="dark"] [class*="style2"] {
  background-color: var(--dm-bg-primary) !important;
  color: var(--dm-text-primary) !important;
}

/* Target Carrd buttons (ul.buttons > li > a.button); a:not(.button) above only covers text links */
[data-theme="dark"] .buttons .button {
  background-color: var(--dm-accent) !important;
}

/* Target Carrd icons (ul.icons > li > a > svg) */
[data-theme="dark"] .icons svg {
  filter: brightness(0) invert(1);
}
```

<Notice type="warning" title="Template-Varianz">
Die `style1`…`style5`-Klassennamen unterscheiden sich je nach Template, und Tricks wie `[data-theme="dark"] .inner > * { background: transparent !important }` können auf manchen Templates Button- und Card-Hintergründe auslöschen. Teste auf deinem. Wenn Buttons im Dark Mode ihren Hintergrund verlieren, entferne zuerst diese Regel. Nichts davon ist universell. Verifiziere jedes Override auf deiner veröffentlichten Seite.
</Notice>

Hintergrundbilder reagieren nicht auf `background-color`-Overrides. Wenn eine Sektion sich weigert dunkler zu werden, ist wahrscheinlich ein Hintergrundbild der Übeltäter. Tausche es aus oder dimme es mit einem Overlay:

```css
[data-theme="dark"] img {
  opacity: 0.9;
  filter: brightness(0.95);
}

/* Or give images a subtle frame */
[data-theme="dark"] img {
  border: 1px solid var(--dm-border);
  border-radius: 8px;
}
```

Wenn du einen Sticky Header betreibst, rechne mit einem Konflikt: eine noch helle Header-Leiste auf einer ansonsten dunklen Seite. Die [Sticky-Header-für-Carrd](/de/carrd-sticky-header-hinzufuegen/)-Anleitung zeigt, welche Selektoren du ansteuern musst, damit die Leiste mit dem Rest dunkler wird.

## Deinen Carrd-Dark-Mode-Umschalter testen und troubleshooten

Embeds rendern nichts im Builder, jede Prüfung unten passiert also auf der veröffentlichten Website.

<ul>
<li>Veröffentlichen, dann die Seite in einem Inkognito-Fenster auf einem auf Dark eingestellten System öffnen: Theme wird ohne weißen Blitz angewendet</li>

Wenn sich etwas daneben benimmt:

<Accordion label="Der weiße Blitz erscheint trotzdem" group="troubleshooting" expanded="true">
Das Head-Bootstrap fehlt, ist auf die falsche Location gesetzt (es muss Style: Hidden, Location: Head sein), oder du siehst eine gecachte Kopie. Bestätige, dass das Embed mit dem richtigen Style und der richtigen Location existiert, dann hart aktualisieren oder in einem privaten Fenster testen. Verifiziere außerdem einmal auf deiner eigenen veröffentlichten Website, dass der Head-Code vor dem Paint läuft. Carrds Injektionsreihenfolge ist einen einzigen End-to-End-Check wert, weil der Builder es dir nicht zeigt. Wenn das Head-Embed stimmt und ein kurzer Blitz bleibt, verschiebe auch den `<style>`-Block des Toggles in das Head-Embed (siehe Schritt 2).
</Accordion>

<Accordion label="Toggle klickt, aber nichts ändert sich" group="troubleshooting">
Drei übliche Verdächtige: ein Script-Fehler in der Konsole (füge den ganzen Codeblock nochmal ein, ungeschlossene Tags sind die häufige Ursache), die Dark-CSS-Selektoren treffen dein Template nicht, oder die Website wurde nach deiner Bearbeitung nicht wirklich veröffentlicht. Prüfe zuerst die Konsole, dann inspiziere das `<html>`-Element. `data-theme` sollte beim Klicken umkippen.
</Accordion>

<Accordion label="Buttons oder Cards haben im Dark Mode ihren Hintergrund verloren" group="troubleshooting">
Das ist die `[data-theme="dark"] .inner > * { background: transparent !important }`-Regel, die zubeißt. Sie ist template-abhängig und oft zu aggressiv. Entferne sie und gib `.button` und Card-Containern stattdessen eigene Hintergrund-Overrides.
</Accordion>

<Accordion label="Toggle verdeckt das Mobile-Menü oder Social Icons" group="troubleshooting">
`z-index: 9999` plus eine Eckposition überlappt Carrds Chrome auf kleinen Bildschirmen. Senke den z-index oder positioniere den Toggle in eine freie Ecke (siehe den Positionierungs-Abschnitt). Teste auf Handy-Breite, nicht nur Desktop.
</Accordion>

<Accordion label="Manche Sektionen ändern nie ihre Farbe" group="troubleshooting">
Entweder nutzt das Template `styleN`-Klassen, die deine Selektoren verfehlen, oder der Sektionshintergrund ist ein Bild. Inspiziere das Element, füge seine Klasse dem Dark-CSS-Block hinzu und tausche oder dimme Hintergrundbilder. Inline-SVG-Icons ignorieren Farb-Overrides ebenfalls. Färbe sie mit `fill`/`stroke`-Regeln oder einem `filter` um.
</Accordion>

<Accordion label="Präferenz speichert nicht oder Uncaught SecurityError in der Konsole" group="troubleshooting">
Private Browsing-Modi können `localStorage` blockieren. Der Code umwickelt jeden Lese-/Schreibzugriff mit `try/catch`, der Toggle funktioniert also weiter für die Session. Er kann sich die Wahl nur nicht merken. Nichts zu fixen; es degradiert absichtlich.
</Accordion>

<Notice type="info" title="Rollback">
Nichts außerhalb der beiden Embeds wird verändert. Lösche beide Embed-Elemente und veröffentliche: die Website ist wieder im Originalzustand. Um die klemmende Präferenz eines einzelnen Besuchers zu löschen, öffne DevTools → Application → Local Storage und entferne den `theme`-Schlüssel.
</Notice>

## FAQ: Carrd-Dark-Mode-Fragen

<Accordion label="Hat Carrd einen eingebauten Dark Mode?" group="faq" expanded="true">
Nein. Stand September 2026 gibt es kein Theme-Switch-Feature in Carrd. Ich habe die Doku und das Changelog geprüft. Ein Custom-Code-Embed ist der Weg, und diese Anleitung ist der Copy-Paste-Pfad.

<Accordion label="Warum blitzt meine Carrd-Website weiß auf, bevor der Dark Mode lädt?" group="faq">
Das ist FOUC (flash of unstyled content), in diesem Fall ein Blitz des falschen Themes. Ein All-in-one-Inline-Embed wendet den Dark Mode per JavaScript erst nach dem ersten Paint an, Dark-Mode-Nutzer sehen also zuerst Weiß. Das Hidden → Head-Bootstrap aus Schritt 1 setzt `data-theme` vor dem Paint und entfernt den Blitz.
</Accordion>

<Accordion label="Welchen Carrd-Plan brauche ich für Dark Mode?" group="faq">
Pro Standard (19 $/Jahr für 10 Websites) oder höher, weil Embeds der Auslieferungsmechanismus sind. Pro Lite (9 $/Jahr) hat gar keine Embeds. Pro Plus (49 $/Jahr) lohnt sich nur, wenn du die erweiterten Einstellungen brauchst. Carrd hat eine 7-tägige kostenlose Pro-Testversion ohne Kreditkarte, falls du das nur einmal bauen willst. Preise von September 2026; auf carrd.co/pro nachprüfen.
</Accordion>

<Accordion label="Funktioniert der Dark-Mode-Toggle auf einer Multi-Section-Carrd-Website?" group="faq">
