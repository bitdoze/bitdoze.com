## Warum ein Testimonial-Slider auf Carrd

Ein Carrd Testimonial-Karussell schlägt eine Wand statischer Zitate:

1. Spart Platz. Zeige 5–10 Testimonials auf dem Platz von einem.

2. Hält den Content frisch. Besucher, die auf der Seite bleiben, sehen verschiedene Zitate, ohne zu scrollen.

3. Zieht Aufmerksamkeit. Bewegung fällt ins Auge und lenkt den Fokus auf deinen Social Proof.

4. Sieht professionell aus. Es ist ein gängiges Pattern auf gut designten Sites.

5. Funktioniert auf Mobilgeräten. Swipe-freundliches Design für Touch-Geräte.

## Wie du einen Testimonial-Slider zu Carrd hinzufügst

So fügst du Testimonials zu Carrd in drei Stilen hinzu: ein Embed-Element einfügen, eines der Snippets unten reinkopieren, veröffentlichen, dann auf der Live-URL verifizieren. Der Workflow ist kurz, aber der Teil mit Veröffentlichen-und-Verifizieren ist nicht optional.

![Wie ein Carrd Testimonial-Slider vom Embed zur Live-Seite kommt: Element im Builder hinzufügen, Embed-Code inline, Änderungen veröffentlichen, Live-Site zeigt den Slider – mit Warnung, dass der Builder nichts rendert, bis du veröffentlichst](@assets/images/26/01/carrd-testimonial-slider-workflow.svg)

### Schritt 1: Ein Embed-Element in Carrd hinzufügen

Klicke auf das `+`-Zeichen und füge ein Embed-Element hinzu:

- Type: Code
- Style: **Inline** (wichtig: so wird der Slider auf deiner Seite angezeigt)

<Picture formats={["webp"]} fallbackFormat="webp" src={imag1} alt="Einstellungspanel des Carrd Embed-Elements mit Type auf Code und dem Style-Dropdown" />

Der Screenshot stammt aus dem Back-to-Top-Tutorial, deshalb zeigen seine Style-Dropdowns Hidden und Head. Für den Slider öffne dasselbe Style-Dropdown und wähle **Inline**.

Auf einer langen Seite nutzt du das Elements Panel (More Actions, dann Elements – seit dem 07.08.2026 im Builder), um direkt zu dem gerade hinzugefügten Embed zu springen statt zu scrollen.

Das ist derselbe Embed-Workflow, den jedes Carrd-Widget auf dieser Site nutzt. Wenn du ein zweites durchgearbeitetes Beispiel willst, bevor du Testimonials anfasst, [füge zuerst einen Back-to-Top-Button per Embed hinzu](/de/carrd-zurueck-nach-oben-button/).

<Notice type="warning" title="Du siehst den Slider nicht im Builder">
Carrd rendert Embed-Code nicht im Editor. Klicke nach dem Einfügen auf **Publish Changes**, öffne die Live-URL und lade hart neu. Der Slider erscheint dort, wo das Embed in der Sektions-Reihenfolge sitzt. Eine leere Stelle im Builder heißt nicht, dass etwas kaputt ist.
</Notice>

<Notice type="info" title="Profi-Tipp: Code und Markup trennen">
Halte das sichtbare Embed rein presentational. Lege HTML und CSS ins Inline-Embed und die `<script>`-Hälfte in ein zweites Embed mit Style **Hidden** und Platzierung **Body End**. Carrd dokumentiert beide Styles plus die Platzierungen Head, Body Top und Body End für Hidden-Embeds in den <a href="https://carrd.co/docs/building/embedding-custom-code" target="_blank" rel="noopener noreferrer">offiziellen Embedding-Docs</a>.
</Notice>

**Verifizieren:** Publish Changes, Live-URL öffnen, hart neu laden. Erwartetes Ergebnis: Der Slider rendert unterhalb der Embed-Position mit dem ersten Testimonial sichtbar. Kaputt sieht so aus: eine leere Lücke auf der Live-Seite (Code fehlt oder Style steht auf Hidden) oder roher Code-Text auf der Seite (Type steht auf etwas anderem als Code).

Eine vierte Slide braucht einen vierten Punkt. Track, Autoplay und Swipe-Logik zählen die Slides zur Laufzeit. Die Punkte sind hardcodiert. Wenn du eine Slide hinzufügst, füge ihren Button hinzu:

```html
<!-- Add inside .testimonial-dots when you add a 4th slide -->
<button class="testimonial-dot" onclick="goToSlide(3)" aria-label="Go to testimonial 4"></button>
```

Für barrierearmes Autoplay und eine Offscreen-Pause füge diese Zeilen am Ende desselben Script-Blocks ein. Sie tauschen das Intervall gegen abgesicherte Start/Stop-Helper, überspringen Autoplay komplett für Reduced-Motion-Nutzer, rotieren nur, solange der Slider auf dem Screen ist, und pausieren, wenn Tastaturfokus reinkommt. Nur Standard-Browser-APIs (`IntersectionObserver` und `matchMedia`). Teste auf deiner veröffentlichten Site; die Builder-Vorschau führt Embed-Skripte nicht aus.

```js
// Accessibility + offscreen pause. Paste at the end of the existing <script> block.
var reduceMotion = window.matchMedia('(prefers-reduced-motion: reduce)').matches;
var rotationStopped = false; // set to true to turn autoplay off completely

function startAuto() {
  if (reduceMotion || rotationStopped || slideInterval) return;
  slideInterval = setInterval(nextSlide, 5000);
}

function stopAuto() {
  clearInterval(slideInterval);
  slideInterval = null;
}

// Replaces the plain setInterval start and the mouse and touch handlers above
stopAuto();
startAuto();

testimonialTrack.onmouseenter = stopAuto;
testimonialTrack.onmouseleave = startAuto;

var swipeStart = testimonialTrack.ontouchstart;
var swipeEnd = testimonialTrack.ontouchend;
testimonialTrack.ontouchstart = function (e) { swipeStart(e); stopAuto(); };
testimonialTrack.ontouchend = function (e) { swipeEnd(e); stopAuto(); startAuto(); };

document.querySelector('.testimonial-slider').addEventListener('focusin', stopAuto);
document.querySelector('.testimonial-slider').addEventListener('focusout', startAuto);

if (!reduceMotion) {
  var testimonialObserver = new IntersectionObserver(function (entries) {
    entries.forEach(function (entry) {
      if (entry.isIntersecting) { startAuto(); } else { stopAuto(); }
    });
  }, { threshold: 0.3 });
  testimonialObserver.observe(document.getElementById('testimonialTrack'));
}

document.addEventListener('visibilitychange', function () {
  if (document.hidden) { stopAuto(); } else { startAuto(); }
});
```

Weil `startAuto()` idempotent ist (es weigert sich, ein zweites Intervall zu stapeln) und der Block die Maus- und Touch-Handler neu zuweist, ist das Einfügen nach dem Original-Skript sicher. Wenn du diesen Block überspringst, funktioniert der Slider trotzdem – er rotiert dann nur weiter, während er offscreen ist.

## Deinen Testimonial-Slider anpassen

### Eigene Testimonials einfügen

Ersetze den Platzhalter-Content in jeder Slide:

1. Ändere den Absatz-Text zu deinem echten Testimonial.
2. Aktualisiere den Namen zum Namen deines Kunden.
3. Ändere Rolle und Firma.
4. Ersetze die Bild-URL durch das Foto deines Kunden (Platzhalter-Dienste wie pravatar.cc sind nur zum Testen).

Halte das `alt`-Attribut beschreibend. Der Name des Kunden funktioniert gut. Generische oder leere Alts lassen Screenreader-Nutzer hängen und verschenken einen leichten Accessibility-Gewinn.

### Mehr Slides hinzufügen

Kopiere einen kompletten Slide-Block und füge ihn nach der letzten Slide ein. Der Slider passt sich an jede Slide-Anzahl an, weil Track, Autoplay und Swipe-Logik die Slide-Elemente zur Laufzeit zählen. **Aber bei Option 1 musst du auch für jede neue Slide einen passenden Punkt-Button hinzufügen.** Die Punkte sind hardcodiert, eine vierte Slide ohne vierten Button ist per Klick nicht erreichbar (Swipe und Autoplay zeigen sie trotzdem). Option 2 braucht nichts extra: Ihr `1 / N`-Zähler wird aus der Slide-Anzahl berechnet.

```html
<!-- Add inside .testimonial-dots when you add a 4th slide -->
<button class="testimonial-dot" onclick="goToSlide(3)" aria-label="Go to testimonial 4"></button>
```

![Anatomie des Copy-Paste-Testimonial-Sliders: Der Wrapper hält Container und Track mit einem Slide-Block pro Testimonial plus eine Punkte-Reihe mit einem passenden Punkt-Button pro Slide; Callouts markieren, wo Slides und Punkte hinzukommen](@assets/images/26/01/carrd-testimonial-slider-anatomy.svg)

### Autoplay-Geschwindigkeit ändern

Finde die `setInterval`-Aufrufe und ändere die Zahl (in Millisekunden):

- `5000` = 5 Sekunden
- `7000` = 7 Sekunden
- `3000` = 3 Sekunden

Option 1 wiederholt `5000` an jeder Stelle, die den Timer neu startet (Initialstart, Maus-verlässt, Swipe-Ende und die optionalen Accessibility- und Toggle-Blöcke). Ändere alle auf denselben Wert. Option 2 nutzt `6000` am Ende ihres Skripts. Dieselbe Änderung.

### Autoplay deaktivieren

Entferne oder kommentiere den `setInterval`-Codeblock aus, wenn du nur manuelle Navigation willst. Bei Option 1 rufen die Mouse-Leave- und Swipe-Handler ebenfalls `setInterval`, also entferne diese Zeilen auch. Wenn du das Accessibility-Upgrade in Option 1 eingefügt hast, ändere stattdessen `var rotationStopped = false;` zu `var rotationStopped = true;`. Das blockiert jeden Neustart-Pfad.

### Die Farben anpassen

Jedes Snippet bringt seine Farben auf `:root` mit. Das funktioniert für ein Embed. Bei zwei Embeds auf einer Seite sind `:root`-Custom-Properties seiten-global, zwei Widgets, die `--testimonial-accent` neu definieren, überschreiben sich also gegenseitig. Scope die Variablen stattdessen auf den Widget-Wrapper:

```css
.testimonial-slider {
  --testimonial-bg: #ffffff;
  --testimonial-text: #1f2937;
  --testimonial-secondary: #6b7280;
  --testimonial-accent: #4f46e5;
  --testimonial-quote: #e5e7eb;
  --testimonial-radius: 16px;
  --testimonial-max-width: 700px;
}
```

Dasselbe Prinzip für die anderen beiden Snippets: Verschiebe die Variablen auf `.card-slider` oder `.testimonial-grid`. Behalte die Variablennamen und den Rest des CSS unverändert.

## Troubleshooting beim Carrd Testimonial-Slider

<Notice type="error" title="Häufigstes Problem: Im Builder rendert nichts">
Embeds geben im Carrd-Editor nichts aus. Beginne mit dem ersten Punkt unten, bevor du irgendetwas anderes debuggst.
</Notice>

### Slider zeigt weder im Builder noch auf der Live-Site

**Symptom.** Du hast den Code eingefügt und siehst eine leere Stelle.

**Ursache.** Der Builder rendert Embed-Code nie. Wenn die Live-Seite auch leer ist, hast du noch nicht veröffentlicht, oder der Embed-Style ist Hidden und es gibt keinen sichtbaren Content an der Platzierung.

**Fix.** Klicke Publish Changes, öffne die Live-URL, lade hart neu. Bestätige, dass Type Code und Style Inline ist. Erwartetes Ergebnis: Der Slider erscheint an der Position des Embeds in der Sektions-Reihenfolge. Roher Code-Text auf der Seite heißt, dass Type auf etwas anderem als Code steht.

### Zwei Slider (oder ein Slider + ein anderes Embed) behindern sich

**Symptom.** Ein Klick auf einen Punkt bewegt den falschen Slider, oder die Browser-Konsole beschwert sich über doppelte IDs oder `goToSlide`.

**Ursache.** Die Snippets hardcodieren IDs (`testimonialTrack`, `cardTrack`) und die globale `goToSlide`-Funktion. Dasselbe Snippet zweimal einzufügen, kollidiert.

**Fix.** Benenne IDs, Klassen und Funktionen für jede Instanz um. Für einen zweiten Slider nutze `testimonialTrack2`, `goToSlide2` und so weiter. Halte jede Umbenennung in HTML und JS konsistent, inklusive der `onclick`-Attribute auf den Punkten.

### Slider breiter als seine Sektion

**Symptom.** Der Slider überläuft seine Spalte oder ignoriert dein Section-Padding.

**Ursache.** Das fixe `max-width: 700px` oder `800px` geht von einer Full-Width-Sektion aus.

**Fix.** Senke `--testimonial-max-width` (Option 1) oder das `max-width` auf `.card-slider` und `.testimonial-grid`, oder verschiebe das Embed in eine Full-Width-Sektion. Die Mobile-Media-Queries schrumpfen das Padding unter 600 px schon.

### Theme-Variablen leaken zwischen Embeds

**Symptom.** Zwei Embeds ändern gegenseitig ihre Farben, und der zuletzt geladene gewinnt.

**Ursache.** Auf `:root` deklarierte Custom Properties sind seiten-global.

**Fix.** Scope sie auf den Widget-Wrapper. Siehe „Die Farben anpassen“ im Abschnitt „Deinen Testimonial-Slider anpassen“ oben.

### Autoplay läuft offscreen oder in Hintergrund-Tabs weiter

**Symptom.** Das Intervall feuert weiter, während der Slider weggescrollt oder der Tab versteckt ist. Verschwendete Zyklen, und es stört Screenreader-Nutzer.

**Ursache.** `setInterval` läuft bedingungslos.

**Fix.** Nutze das Accessibility-Upgrade in Option 1. Es koppelt die Rotation an `IntersectionObserver`, `matchMedia('(prefers-reduced-motion: reduce)')`, Tastaturfokus und `visibilitychange`. Wenn du nur den Hintergrund-Tab-Teil willst, ist das der minimale Patch für Option 1 (füge ihn am Ende ihres Skripts ein):

```js
document.addEventListener('visibilitychange', function () {
  clearInterval(slideInterval);
  slideInterval = null;
  if (!document.hidden) {
    slideInterval = setInterval(nextSlide, 5000);
  }
});
```

### Avatar-Bilder brechen oder lösen Privacy-Warnungen aus

**Symptom.** Avatare liefern 404, oder dein Consent-Tool meldet einen Third-Party-Request beim Seitenaufruf.

**Ursache.** `i.pravatar.cc` ist ein Live-Drittanbieter-Dienst. Okay zum Testen. Auf einer veröffentlichten Seite ist es ein externer Request, der bei jedem Besucher feuert – schlechte DSGVO-Optik für EU-Publikum und ein Single Point of Failure mehr.

**Fix.** Hoste Kundenfotos selbst: Lade sie als Carrd-Bild-Assets hoch oder zeig mit dem `img`-`src` auf deine eigenen Media-URLs. Behalte beschreibende `alt`-Texte so oder so bei. Wenn deine veröffentlichte Site Third-Party-Requests macht, füge einen [Cookie-Hinweis für Carrd](/de/carrd-cookie-hinweis-hinzufuegen/) hinzu, damit die Offenlegung zum Verhalten passt.

## Accessibility: Das Karussell screenreader-freundlich machen

Out of the box pausieren diese Slider nur bei Hover. Das <a href="https://www.w3.org/WAI/ARIA/apg/patterns/carousel/" target="_blank" rel="noopener noreferrer">W3C-ARIA-Authoring-Practices-Karussell-Pattern</a> verlangt von jedem auto-rotierenden Karussell mehr. Die Kurzversion:

<ListCheck>
<ul>
<li>Rotation bei Hover pausieren und wenn Tastaturfokus ins Karussell kommt</li>
<li>Eine sichtbare Stopp- und Start-Rotations-Kontrolle anbieten</li>
<li>Jeden Punkt-Button so labeln, dass er die Slide benennt, die er öffnet</li>
<li>Den Container mit einem Klartext-Label als Karussell markieren</li>
<li>Auto-Rotation für prefers-reduced-motion-Nutzer komplett überspringen</li>
</ul>
</ListCheck>

Der barrierefreie Autoplay-Block unter Option 1 deckt die Fokus-Pause, den Reduced-Motion-Skip und die Offscreen-Pause ab. Für die Markup-Seite füge dem Option-1-Wrapper und -Track diese Attribute hinzu:

```html
<div class="testimonial-slider" aria-roledescription="carousel" aria-label="Customer testimonials">
  <div class="testimonial-container">
    <div class="testimonial-track" id="testimonialTrack" aria-live="off">
```

`aria-live="off"` auf dem Track ist Absicht. Solange die Rotation läuft, ist jede Änderung anzusagen nur Rauschen. Wenn du Autoplay komplett deaktivierst, wechsle zu `aria-live="polite"`, damit manuelle Navigation angesagt wird.

Labele jeden Punkt-Button nach seinem Ziel, zum Beispiel `aria-label="Go to testimonial 4"`.

Für die Stopp- und Start-Kontrolle setze einen Button innerhalb von `.testimonial-slider`, direkt über den Punkten. Er baut auf dem barrierefreien Autoplay-Block auf, also füge diesen Block zuerst ein. Der Toggle flippt `rotationStopped`, was Hover, Fokus, Swipe und Scroll davon abhält, die Rotation neu zu starten, nachdem ein Besucher sie gestoppt hat. Carrds CSS resettet Button-Styles, deshalb gibt das Snippet dem Button seinen eigenen Look:

```html
<style>
  .testimonial-toggle {
    display: block;
    margin: 20px auto 0;
    padding: 6px 14px;
    border: 1px solid var(--testimonial-secondary);
    border-radius: 6px;
    background: transparent;
    color: var(--testimonial-secondary);
    font-size: 14px;
    cursor: pointer;
  }
</style>
<button class="testimonial-toggle" onclick="toggleAutoplay()" aria-label="Stop auto-rotating testimonials">Stop rotation</button>
```

```js
// Paste after the accessible autoplay block, inside the same <script>
var testimonialToggle = document.querySelector('.testimonial-toggle');

function toggleAutoplay() {
  rotationStopped = !rotationStopped;
  if (rotationStopped) {
    stopAuto();
    testimonialToggle.textContent = 'Start rotation';
    testimonialToggle.setAttribute('aria-label', 'Start auto-rotating testimonials');
  } else {
    startAuto();
    testimonialToggle.textContent = 'Stop rotation';
    testimonialToggle.setAttribute('aria-label', 'Stop auto-rotating testimonials');
  }
}
```

Diese Ergänzungen nutzen Standard-Browser-APIs (`IntersectionObserver`, `matchMedia`, `addEventListener`). Sie sind nicht gegen eine spezifische Carrd-Theme-Kombination getestet, also verifiziere auf deiner veröffentlichten Site.

**Verifizieren:** Veröffentliche, öffne die Live-Seite und drücke Tab, bis der Fokus den Slider erreicht. Die Rotation sollte stoppen. Drücke den Stopp-Button, und die Rotation sollte gestoppt bleiben. Aktiviere „Reduce Motion“ in deinen OS-Einstellungen und lade neu: Nichts sollte auto-rotieren. Kaputt sieht so aus: Rotation läuft weiter, während ein Punkt-Button Fokus hat, oder es gibt keinen Weg, das Karussell zu stoppen, ohne die Seite zu verlassen.

## Tipps für bessere Testimonials

Nutze echte Fotos. Stockfotos sehen fake aus. Frag Kunden nach Porträtfotos oder nutze ihre LinkedIn-Fotos mit Erlaubnis.

Halte Zitate kurz. Lange Testimonials verlieren Aufmerksamkeit. Kürze auf die stärksten 2–3 Sätze.

Bring konkrete Zahlen. „Tolle Arbeit!“ ist vergessbar. „Hat unsere Conversion-Rate um 40 % erhöht“ bleibt hängen.

Diversifiziere deine Testimonials. Zeig verschiedene Kundentypen und verschiedene Vorteile, die sie bekommen haben.

Pflege ein Source-of-Truth-Dokument. Eine schlichte Tabelle mit freigegebenen Zitaten, Namen, Rollen und Foto-URLs macht ein Embed-Update zu einer Zwei-Minuten-Aufgabe statt zu einer Ausgrabung. Senjas Collection-Formular löst dasselbe Problem mit Software, wenn du über eine Tabelle hinauswächst.

Social Proof funktioniert am besten mit einem leichten nächsten Schritt. Auf Service-Sites kombiniere den Slider mit einem [WhatsApp-Chat-Button](/de/carrd-whatsapp-button/), damit überzeugte Besucher dir sofort schreiben können.
