## Wie die Fish Audio API funktioniert

Jeder Request geht an `https://api.fish.audio` mit einem `Authorization: Bearer <key>`-Header und einem `model`-Header zur Auswahl der Engine. TTS-Requests senden JSON (oder MessagePack für Inline-Referenz-Audio) und erhalten gestückelte Audio-Bytes in mp3, wav, pcm oder opus. Da das Audio in Chunks streamt, kann die Wiedergabe starten, bevor die Generierung endet.

![Lebenszyklus eines Fish Audio TTS-Requests mit Client, api.fish.audio, TTS-Job und zurückgegebenen Audio-Bytes](@assets/images/26/11/fish-audio-api-lifecycle.webp)

*Der Lebenszyklus eines TTS-Requests: ein POST rein, gestückelte Audio-Bytes raus, JSON-Fehlermeldungen bei Problemen.*

Die API-Oberfläche deckt mehr ab als reines TTS. Es gibt einen Speech-to-Text-Endpunkt, einen Echtzeit-Transkriptions-WebSocket, Verwaltung für Stimmmodelle und Voice Design anhand eines Text-Prompts. Dieses Tutorial nutzt POST /v1/tts, POST /v1/asr, POST /model und den TTS-WebSocket.

![Übersicht der Fish Audio API-Endpunkte inklusive tts, asr, Modellerstellung, Echtzeit-WebSockets, Voice Design und MCP](@assets/images/26/11/fish-audio-api-endpoints.webp)

## Einen Fish Audio API-Key besorgen

Keys erstellst du direkt in der Web-App, ohne separate Entwickler-Registrierung. Melde dich bei fish.audio an, bestätige deine E-Mail-Adresse und öffne die Get-Started-Seite unter `fish.audio/app/developers/get-started/`. Klicke auf "Get your API key", und der Key wird mit einem Klick erzeugt. Derselbe Key funktioniert für die REST-API, das Python SDK und das JavaScript SDK. Vorhandene Keys findest du auf der API-Keys-Seite unter `fish.audio/app/api-keys`.

<Notice type="warning" title="Der Key wird nur einmal angezeigt">
Kopiere ihn sofort. Wenn du ihn verlierst, musst du auf der API-Keys-Seite einen neuen erstellen. Committe ihn niemals in git.
</Notice>

![Schritte in der Fish Audio Dokumentation zum Erstellen eines Accounts und Generieren eines API-Keys mit einem Klick](@assets/images/26/11/fish-audio-api-key-steps.webp)

*Die offiziellen Schritte zur Key-Erstellung aus docs.fish.audio.*

Speichere ihn als Umgebungsvariable, da jedes SDK und Beispiel in den Docs genau das erwartet:

```bash
export FISH_API_KEY="your_api_key_here"
```

Falls doch einmal ein Key geleakt wird, dokumentiert Fish Audio einen [Revoke-Endpunkt für offengelegte Keys](https://docs.fish.audio/api-reference/endpoint/apikey/revoke-api-keys), der keine Anmeldung erfordert, damit Secret-Scanner Keys aus öffentlichen Repos direkt sperren können. Der Widerruf ist dauerhaft, und der Key liefert sofort 401 zurück.

Die Bedingungen stammen aus Fish Audios [Ankündigung der kostenlosen S2.1-Pro-API](https://fish.audio/blog/s2-1-pro-free-api/), die ich am 26. November 2026 gelesen habe:

- Anfragen können zur Verbesserung der Modellqualität genutzt werden.
- Einige kommerzielle Szenarien können Einschränkungen unterliegen, und Produkte mit mehr als 1 Million $ ARR sollen vor Nutzung des kostenlosen Tarifs Kontakt mit Fish Audio aufnehmen.

## Dein erster TTS-Aufruf in Python und curl

Installiere das offizielle Python SDK mit `pip install fish-audio-sdk` und erzeuge dann einen Clip mit dem kostenlosen Modell:

<Tabs>
<Tab name="Python">

```python
from fishaudio import FishAudio
from fishaudio.utils import save

client = FishAudio()  # reads FISH_API_KEY

audio = client.tts.convert(
    text="Hello! Welcome to Fish Audio.",
    model="s2.1-pro-free",
)
save(audio, "welcome.mp3")
```

</Tab>
<Tab name="curl">

```bash
curl -X POST https://api.fish.audio/v1/tts \
  -H "Authorization: Bearer $FISH_API_KEY" \
  -H "Content-Type: application/json" \
  -H "model: s2.1-pro-free" \
  -d '{
    "text": "Hello! Welcome to Fish Audio.",
    "format": "mp3"
  }' \
  --output welcome.mp3
```

</Tab>
</Tabs>

Spiele die Datei unter Linux mit `mpg123 welcome.mp3` oder unter macOS mit `afplay welcome.mp3` ab. Das ist schon der komplette Ablauf.

<Notice type="info" title="Der model-Header fällt stillschweigend zurück">
Laut der [Text-to-Speech-Referenz](https://docs.fish.audio/api-reference/endpoint/openapi-v1/text-to-speech) läuft dein Request auf dem kostenpflichtigen Motor `s2.1-pro`, wenn du den `model`-Header weglässt oder falsch schreibst. Laut [Quickstart](https://docs.fish.audio/developer-guide/getting-started/quickstart) liefern Bezahlmodelle `402`, bis du API-Guthaben auflädst. Das Python SDK nutzt denselben Standardwert. Übergib `model` deshalb bei jedem Aufruf explizit. Der ASR-Endpunkt zeigt dasselbe Fallback-Verhalten, wie im Abschnitt zur Transkription beschrieben.
</Notice>

Weitere gültige TTS-Engines sind `s2-pro`, das veraltete `s1` und `drama-3`. `drama-3` ist das ausdrucksstärkste Modell für 50 $ pro Million Bytes, mit 80 % Rabatt auf 10 $ bis zum 30. November 2026. Meide `s1` für neuen Code, da es am 31. Dezember 2026 abgeschaltet wird und auf `s2.1-pro` umleitet.

![Fish Audio API Quickstart-Dokumentationsseite mit den ersten TTS-Request-Beispielen](@assets/images/26/11/fish-audio-api-quickstart.webp)

*Der offizielle Quickstart mit cURL-, Python- und JavaScript-Varianten des ersten Requests.*

Nützliche Felder im Request-Body aus dem OpenAPI-Schema:

| Feld | Standard | Bedeutung |
| --- | --- | --- |
| `text` | erforderlich | Der vorzulesende Text |
| `reference_id` | null | ID des Stimmmodells, String oder Array für mehrere Sprecher |
| `format` | `mp3` | `wav`, `pcm`, `mp3` oder `opus` |
| `sample_rate` | Format-Standard | 44100 Hz bei den meisten Formaten, 48000 Hz bei opus |
| `mp3_bitrate` | `128` | 64, 128 oder 192 kbps |
| `latency` | `normal` | `normal` beste Qualität, `balanced` geringere Latenz, `low` niedrigste Latenz |
| `prosody` | null | Tempo (0.5 bis 2.0) und Lautstärke in dB, z. B. `{"speed": 1.2}` |
| `temperature` | 0.7 | Höher wirkt ausdrucksstärker, niedriger konsistenter |
| `chunk_length` | 300 | Größe der Textsegmente bei der Verarbeitung |
| `normalize` | true | Schreibt Zahlen, Daten und Einheiten vor der Synthese aus |

Für Dialoge mit mehreren Sprechern in der S2-Familie übergibst du `reference_id` als Array und markierst den Text mit Sprecher-Tags:

```python
audio = client.tts.convert(
    text="<|speaker:0|>Good morning!<|speaker:1|>Morning! How are you?",
    reference_id=["voice-id-alice", "voice-id-bob"],
    model="s2.1-pro-free",
)
```

## Streaming-Wiedergabe für niedrige Latenz

Es gibt zwei Streaming-Modi. HTTP-Streaming ist standardmäßig aktiv, weil der Server gestückelte Antwort-Bytes sendet, die du sofort schreiben oder abspielen kannst.

<Tabs>
<Tab name="Python">

```python
from fishaudio import FishAudio

client = FishAudio()

with open("out.mp3", "wb") as f:
    for chunk in client.tts.stream(
        text="Streaming keeps latency low.",
        model="s2.1-pro-free",
    ):
        f.write(chunk)  # or send to a speaker as it arrives
```

</Tab>
<Tab name="curl">

```bash
curl --request POST https://api.fish.audio/v1/tts \
  --header "Authorization: Bearer $FISH_API_KEY" \
  --header "Content-Type: application/json" \
  --header "model: s2.1-pro-free" \
  --no-buffer \
  --data '{ "text": "Streaming keeps latency low.", "format": "mp3" }' \
  --output out.mp3
```

</Tab>
</Tabs>

Der zweite Modus ist ein WebSocket für Text, der noch entsteht, typischerweise Tokens aus einem LLM. Das Python SDK übernimmt das Protokoll über `tts.stream_websocket`, das ein Iterable aus Strings und Events annimmt, wie im [SDK WebSocket Guide](https://docs.fish.audio/developer-guide/sdk-guide/python/websocket) gezeigt:

```python
from fishaudio import FishAudio
from fishaudio.types import TextEvent, FlushEvent

client = FishAudio()

def script():
    yield TextEvent(text="First sentence. ")
    yield "Second sentence. "
    yield FlushEvent()  # force generation of everything buffered
    yield "Third sentence."

for chunk in client.tts.stream_websocket(
    script(),
    reference_id="YOUR_VOICE_ID",
    model="s2.1-pro-free",
):
    pass  # play or forward each chunk
```

Ein `FlushEvent` erzwingt die sofortige Generierung des gepufferten Texts, womit du in einem Voice-Agenten Gesprächspausen und Turn-Grenzen steuerst. Bei der Latenz setzt das REST-Schema standardmäßig `latency: normal`, während der SDK-Guide schreibt, dass `balanced` beim Streaming der SDK-Standard ist und die schnellste Time-to-First-Audio liefert. Setze den Wert explizit, falls es dir darauf ankommt. Fish Audios [Ankündigung des kostenlosen Tarifs](https://fish.audio/blog/s2-1-pro-free-api/) nennt rund 70 ms Time-to-First-Audio für S2.1 Pro bei einem einzelnen Request, und die Modellübersicht gibt 100 ms für s2-pro an. Beides sind Herstellerangaben, die ich nicht selbst gemessen habe.

Wenn du das in ein Agent-Framework einbaust, habe ich eine Schritt-für-Schritt-Anleitung für [Fish Audio TTS in Mastra](/mastra-fish-audio-tts/) geschrieben. Die Streaming-Beispiele dort nutzen genau diese Bausteine.

## Emotions-Tags und Referenzstimmen

S2-Modelle lesen Hinweise in natürlicher Sprache in eckigen Klammern direkt aus deinem Text aus. Das gehört zu den wenigen Fähigkeiten von Fish Audio, die die meisten anderen TTS-APIs nicht bieten.

```text
[happy] What a beautiful day!
[sad][whispering] I miss you so much.
[very excited] This is absolutely amazing!
```

Die [Emotions-Referenz](https://docs.fish.audio/api-reference/emotion-reference) dokumentiert 24 Basisemotionen (`[happy]`, `[sad]`, `[angry]`, `[calm]`, `[sarcastic]`) plus 25 erweiterte Emotionen. Dazu kommen 6 Ton-Marker wie `[whispering]` und `[emphasis]`, menschliche Laute (`[laughing]`, `[sighing]`, `[clear throat]`) sowie Pausen (`[break]`, `[long-break]`). Setze satzbezogene Hinweise an den Satzanfang und kombiniere Intensitätszusätze wie `[slightly sad]` oder `[extremely angry]`. Eckige Klammern akzeptieren freie Hinweise wie `[warm and tired]` in 13 unterstützten Sprachen, darunter Englisch, Spanisch, Japanisch, Chinesisch und Arabisch.

Emotions-Tags zählen zur Textlänge, plane sie also bei den Bytes mit ein. Laut Dokumentation des MCP-Servers werden Tags dort pro Byte abgerechnet, und die REST-API zählt sie vermutlich genauso, da sie pro Eingabe-UTF-8-Byte berechnet.

Achte auf einen Migrationsunterschied. Das eingestellte Modell `s1` nutzte runde Klammern wie `(happy)`, während alle aktuellen Modelle eckige Klammern erwarten. Ältere Tutorials mit runden Klammern richten sich an `s1`.

Für Stimmen übergibst du `reference_id` mit einer Stimmmodell-ID. Jede Stimme in der öffentlichen Bibliothek auf fish.audio hat eine, sichtbar in der URL der Stimmenseite, zum Beispiel `fish.audio/m/ca3007f96ae7499ab87d27ea3599956a`:

```python
audio = client.tts.convert(
    text="This is a custom voice from the Fish Audio library.",
    reference_id="ca3007f96ae7499ab87d27ea3599956a",
    model="s2.1-pro-free",
)
```

Die Bibliothek umfasst sehr viele Community-Stimmen, wodurch die Qualitätsunterschiede groß sind. Teste jede Stimme gründlich, bevor du dich in Produktion festlegst.

## Eine Stimme über die API klonen

Voice Cloning ist ein Multipart-POST an `/model` (Achtung: nicht unter `/v1`). Du lädst eine oder mehrere Audioproben hoch und erhältst eine Stimmmodell-ID zurück, wie in der [Create-Model-Referenz](https://docs.fish.audio/api-reference/endpoint/model/create-model) beschrieben:

<Tabs>
<Tab name="Python">

```python
from fishaudio import FishAudio

client = FishAudio()

with open("sample.wav", "rb") as f:
    voice = client.voices.create(
        title="My Voice",
        voices=[f.read()],
        description="Cloned from a studio sample",
        visibility="private",
    )

print(voice.id, voice.state)
```

</Tab>
<Tab name="curl">

```bash
curl --request POST https://api.fish.audio/model \
  --header "Authorization: Bearer $FISH_API_KEY" \
  --form type=tts \
  --form title="My Voice" \
  --form "description=Cloned from a studio sample" \
  --form visibility=private \
  --form train_mode=fast \
  --form voices=@sample.wav
```

</Tab>
</Tabs>

Proben können als wav, mp3, m4a oder opus vorliegen. Ziele auf mindestens 10 Sekunden sauberes Audio mit nur einem Sprecher pro Clip. Ein bis zwei Minuten verbessern die Stimmähnlichkeit. Die Option `enhance_audio_quality` ist standardmäßig aktiv und entrauscht das Eingangsmaterial. Lass sie also an, sofern deine Aufnahme nicht bereits Studioqualität hat. Mit dem Standardwert `train_mode=fast` wechselt das Feld `state` von `created` zu `trained` (oder `failed`). Danach nutzt du die ID genau wie eine Stimme aus der Bibliothek:

```python
audio = client.tts.convert(
    text="Now I speak in my cloned voice.",
    reference_id=voice.id,
    model="s2.1-pro-free",
)
```

Du kannst Stimmen auch per One-Shot klonen, indem du `references=[ReferenceAudio(audio=..., text=...)]` (aus `fishaudio.types`) direkt im TTS-Request übergibst. Das SDK übernimmt die MessagePack-Kodierung für dich. Bei rohem `curl` musst du manuell packen, weshalb `POST /model` samt anschließendem Aufräumen für einmalige CLI-Skripte einfacher ist. Den kompletten Klon-Workflow samt Web-UI beschreibe ich in meinem Guide [Stimme mit Fish Audio klonen](/de/fish-audio-stimme-klonen/).

## Audio mit dem ASR-Endpunkt transkribieren

[`POST /v1/asr`](https://docs.fish.audio/api-reference/endpoint/openapi-v1/speech-to-text) transkribiert eine Audiodatei pro Request. Beide Modelle kosten 0,36 $ pro Audiostunde, und Fehler werden nicht berechnet. Schicke die Datei als Multipart-Form-Data und wähle das Modell über den `model`-Header:

```bash
curl --request POST https://api.fish.audio/v1/asr \
  --header "Authorization: Bearer $FISH_API_KEY" \
  --header "model: transcribe-1-pro" \
  --form audio=@conversation.wav \
  --form ignore_timestamps=false
```

Dieser Header ist strikt. Sende `model: transcribe-1-pro` exakt in Kleinbuchstaben wie dokumentiert. Jeder Tippfehler oder ein fehlender Header leitet deinen Aufruf stillschweigend auf die ältere `transcribe-1`-Engine für kurze Clips ohne Sprechertrennung um und rechnet ihn dort ab.

`ignore_timestamps` steht standardmäßig auf `true`, sodass du wortgenaue `segments` und `speaker_turns` nur bekommst, wenn du wie oben `false` setzt. Die Antwort ist JSON mit `text`, `duration` in Sekunden (inklusive Stille), `segments` sowie `speaker_turns` bei Aufnahmen mit mehreren Sprechern. Bei `transcribe-1-pro` werden Sprecherwechsel auch inline in `text` mit `<|speaker:0|>`-Tags markiert, und Hinweise wie `[laughter]` bleiben im Transkript erhalten, sofern du nicht `tag_audio_events=false` übergibst. `transcribe-1-pro` verarbeitet Aufnahmen bis zu 60 Minuten in wav, mp3, AAC/m4a, flac, ogg, webm und mov (bei Videodateien nutzt es die erste Audiospur).

Achte bei längeren Aufnahmen auf eine Timeout-Falle in Produktion. Standard-Timeouts des SDKs können mitten in der Datei ablaufen. Deshalb empfiehlt die Doku `RequestOptions(timeout=900)` in Python und `setGlobalDispatcher` aus `undici` in Node, um das 5-Minuten-Limit von fetch zu umgehen.

Mit 0,36 $ pro Stunde konkurriert der Preis mit den Transkriptions-Anbietern aus meinem Vergleich [OpenAI Whisper Alternativen](/de/openai-whisper-alternativen/), auch wenn [AssemblyAI](/de/assemblyai-review/) tiefere Batch-Funktionen bietet. Für einfachere lokale Ausgaben sieh dir mein [Python Text-to-Speech-Skript mit uv](/uv-text-to-speech-script/) an.

## Fehler, Rate Limits und Preise

Fehlerantworten sind JSON mit `status` und `message`. Die wichtigsten Statuscodes:

| Status | Bedeutung | Was zu tun ist |
| --- | --- | --- |
| 400 | Ungültige `reference_id` oder Parameter | `message` lesen und Request korrigieren |
| 401 | Fehlender oder ungültiger API-Key | `FISH_API_KEY` prüfen |
| 402 | Kein Guthaben für ein Bezahlmodell | `s2.1-pro-free` nutzen oder Guthaben aufladen |
| 413 | Request zu groß | Lange Audios in mp3 oder opus komprimieren |
| 429 | Nebenläufigkeits-Limit erreicht | Mit exponentiellem Backoff erneut versuchen |
| 503 | Dienst überlastet | Mit Backoff erneut versuchen |

Rate Limits zählen gleichzeitige Requests statt Requests pro Sekunde, geteilt über alle API-Keys des Accounts. Auf der [Seite für Preise und Rate Limits](https://docs.fish.audio/developer-guide/models-pricing/pricing-and-rate-limits) erhält Starter (unter 100 $ eingezahlt) 5 gleichzeitige Requests, ab 100 $ sind es 15 und ab 1.000 $ sind es 50. HTTP-429-Antworten lassen den `Retry-After`-Header weg. Implementiere exponentielles Backoff also selbst. Im Starter-Tarif ergibt eine 4-Sekunden-Antwort eines Voice-Agenten rund 75 Requests pro Minute, während 60-Sekunden-Hörbuch-Chunks auf etwa 5 Requests pro Minute sinken.

Die vollständige Preistabelle mit Stand 26. November 2026:

| Modell | Preis |
| --- | --- |
| `s2.1-pro` / `s2-pro` TTS | 15,00 $ pro Million UTF-8-Bytes |
| `s2.1-pro-free` TTS | 0,00 $, kein SLA, Fair Use gilt |
| `drama-3` TTS | 50,00 $ pro Million Bytes |
| `transcribe-1` / `transcribe-1-pro` | 0,36 $ pro Audiostunde |
| `transcribe-stream-1` Echtzeit-ASR | 0,36 $ pro Sitzungsstunde (Preview) |
| `voice-design-1` | 0,01 $ pro erfolgreichem Request |

Für den API-Zugang gibt es keine Abogebühren und keine monatlichen Mindestumsätze. Abgerechnet wird rein per Pay-as-you-go über vorausbezahltes Guthaben.

## Die Abkürzung über den MCP-Server

Wenn dein Client MCP unterstützt, kannst du dir zum Ausprobieren das Programmieren sparen. Fish Audio betreibt einen Streamable-HTTP-[MCP-Server](https://docs.fish.audio/overview/mcp) unter `https://api.fish.audio/mcp` mit OAuth-Anmeldung und stellt Stimmsuche, Cloning, TTS, Transkription sowie Bild- und Videogenerierung als Tools bereit. In Claude Code genügt ein einziger Befehl:

```bash
claude mcp add --transport http fish-audio https://api.fish.audio/mcp
```

Führe `/mcp` in Claude Code zur Anmeldung aus und starte Stimmsuchen oder das Vorlesen von `intro.md` direkt per Prompt. MCP-Aufrufe ziehen Web-App-Credits ab (1 Credit pro UTF-8-Byte TTS-Eingabe inklusive Audio-Tags) statt API-Guthaben. Tariflimits gelten je Tool, wobei Video mindestens Plus erfordert und kostenlose Tarife Bilder deckeln. Damit eignet sich MCP am besten für schnelles Prototyping.

## Hinweise für den Produktivbetrieb

Ein paar Dinge, die ich vor dem Go-Live fest einbauen würde:

<ListCheck>
<ul>
<li><strong>Generierungen cachen.</strong> Hashe den Request-Body (Text, Stimme, Einstellungen), speichere das Audio auf der Platte oder im Object Storage und spare bei Wiederholungen Latenz und Kosten. Bei Temperatur 0.7 schwankt die Ausgabe zwischen Läufen, sodass ein Cache auch genau den Take bewahrt, den du abgenommen hast.</li>
<li><strong>Nur wiederholbare Fehler erneut senden.</strong> 429 und 5xx bekommen exponentielles Backoff mit Jitter. 400, 401 und 402 werden beim Wiederholen nie erfolgreich. Behebe stattdessen den Request. Fehler werden nicht berechnet.</li>
<li><strong>Verbindungen warm halten.</strong> Nutze HTTP-Keep-Alive-Verbindungen wieder, wenn du direkt nacheinander generierst, damit der TLS-Aufbau keine Sub-Sekunden-Generierung ausbremst.</li>
<li><strong>Entscheiden, wann das kostenlose Modell reicht.</strong> Für Prototypen, interne Tools und Bots mit wenig Traffic reicht `s2.1-pro-free`. Wechsle auf `s2.1-pro`, sobald du eine TTFA-Garantie oder ein DPA brauchst oder dich 1 Million $ ARR näherst, ab der Rücksprache nötig ist.</li>
<li><strong>Lange Transkriptionen nicht aufteilen.</strong> Sprecherlabels bleiben nur innerhalb einer einzelnen Antwort konsistent. Schicke also ein komplettes Gespräch in einem einzigen `/v1/asr`-Aufruf.</li>
</ul>
</ListCheck>

Falls du lieber selbst hostest, läuft das Open-Weights-Schwesterprojekt [fish-speech](https://github.com/fishaudio/fish-speech) auf deiner eigenen GPU. Laut README stehen der Code und die Drama-3-Gewichte unter der Fish Audio Community License, während S2-Pro-Gewichte die Fish Audio Research License nutzen. Lies beide Lizenzen vor dem kommerziellen Einsatz genau, oder vergleiche freizügigere Engines in [beste Open-Source-TTS-Engines](/de/beste-open-source-tts-engines/).

## FAQ

<Accordion label="Ist die Fish Audio API kostenlos?" group="faq">
Ja, für die Entwicklung. Das Modell `s2.1-pro-free` kostet 0 $ pro Million UTF-8-Bytes unter einer Fair Use Policy und entspricht demselben Modell wie `s2.1-pro`. Die Einschränkungen sind kein SLA, keine Latenz-Garantie, Anfragen dürfen zur Modellverbesserung genutzt werden, und ab 1 Million $ ARR soll man Fish Audio kontaktieren. Am 26. November 2026 lief das angekündigte kostenlose Zeitfenster bis zum 30. November 2026. Prüfe also auf der Preisseite, was heute gilt.
</Accordion>

<Accordion label="Wo finde ich meinen Fish Audio API-Key?" group="faq">
Melde dich auf fish.audio an und öffne die Get-Started-Seite unter `fish.audio/app/developers/get-started/`. Klicke auf "Get your API key", und er wird mit einem Klick erzeugt. Der Key wird nur einmal angezeigt, kopiere ihn also sofort. Vorhandene Keys verwaltest du unter `fish.audio/app/api-keys`.
</Accordion>

<Accordion label="Wie viel kostet die Fish Audio API?" group="faq">
Kostenpflichtiges TTS auf `s2.1-pro` oder `s2-pro` kostet 15 $ pro Million UTF-8-Bytes Eingabetext, etwa 180.000 englische Wörter oder 12 Stunden Sprache. `drama-3` liegt regulär bei 50 $ pro Million Bytes. Transkription kostet 0,36 $ pro Audiostunde sowohl für `transcribe-1` als auch für `transcribe-1-pro`. Es gibt keine monatlichen Mindestumsätze, sondern reines Prepaid-Pay-as-you-go.
</Accordion>

<Accordion label="Welche Rate Limits hat die Fish Audio API?" group="faq">
Die Limits zählen gleichzeitige Requests statt Requests pro Sekunde: 5 im Starter-Tarif (unter 100 $ eingezahlt), 15 ab 100 $ und 50 ab 1.000 $. Alle API-Keys des Accounts teilen sich denselben Pool. Da 429-Antworten keinen `Retry-After`-Header enthalten, musst du exponentielles Backoff selbst implementieren.
</Accordion>

<Accordion label="Darf ich Ausgaben der Fish Audio API kommerziell nutzen?" group="faq">
Bezahlte Nutzung ist der sichere Weg. Für `s2.1-pro-free` heißt es in der Ankündigung, dass manche kommerziellen Szenarien eingeschränkt sein können. Produkte über 1 Million $ ARR sollen zuerst Kontakt mit Fish Audio aufnehmen. Kostenlose Anfragen können auch zur Modellverbesserung genutzt werden. Schicke also keine sensiblen Texte über den kostenlosen Tarif. Lies vor dem Produktivstart die aktuellen Bedingungen auf der Preisseite.
</Accordion>

<Accordion label="Wie klone ich eine Stimme mit der Fish Audio API?" group="faq">
Sende einen Multipart-POST an `https://api.fish.audio/model` mit `type=tts`, einem `title` und einer oder mehreren Audiodateien unter `voices`. Es funktionieren wav, mp3, m4a und opus, wobei mindestens 10 Sekunden sauberes Audio mit einem einzigen Sprecher empfohlen sind. Die Antwort enthält die Stimm-ID, die du anschließend als `reference_id` in TTS-Requests übergibst.
</Accordion>

<Accordion label="Unterstützt die Fish Audio API Streaming?" group="faq">
Ja, auf zwei Arten. Jede TTS-Antwort kommt ohnehin gestückelt über HTTP, sodass `--no-buffer` in curl oder `tts.stream()` in Python Audio während der Generierung abspielt. Für Token-für-Token-Eingaben aus einem LLM öffnet `stream_websocket()` im Python SDK eine WebSocket-Sitzung mit Flush-Events zur Turn-Steuerung.
</Accordion>

<Accordion label="Welche Sprachen unterstützt die Fish Audio API?" group="faq">
S2.1 Pro unterstützt 83 Sprachen mit einem einzigen Modell, ohne sprachspezifische Endpunkte oder Preise. Die Emotions-Referenz listet 13 Sprachen für Emotions-Marker, darunter Englisch, Spanisch, Japanisch, Chinesisch und Arabisch. Das Body-Feld `language` steuert lediglich die Textnormalisierung, nicht die Stimme selbst.
</Accordion>
