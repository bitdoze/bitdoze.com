[Carrd.co](https://go.bitdoze.com/carrd) ist eine exzellente Plattform für One-Page-Websites, aber die Navigation wird knifflig, sobald du mehr als ein paar Sektionen hast. Ein Seitenmenü löst das, indem es die Navigation aus dem Bildschirm tuckt, bis der Besucher sie braucht. Kein verschwendeter Platz, kein überladener Header.

Ein Carrd-Seitenmenü funktioniert gut, weil:

1. **Es den Content-Platz maximiert.** Die Navigation bleibt versteckt, bis der Besucher den Hamburger-Button tippt, und hält den Fokus auf deinem Inhalt.
2. **Bessere Organisation** für Websites mit mehreren Sektionen. Besucher können in jeden Bereich springen, ohne zu scrollen.
3. **Mobilfreundlich.** Das Slide-in-Panel nutzt touch-freundliche Ziele (40px+) und behandelt den iOS-Scroll-Lock sauber.
4. **Anpassbare Positionierung.** Von links oder rechts öffnen, den Button schweben lassen oder an einem Punkt der Seite festpinnen.

## So fügst du das Carrd-Seitenmenü hinzu

Der Ansatz ist geradlinig: Füge einen HTML/CSS/JS-Block in ein Embed-Element ein. Keine externen Abhängigkeiten, keine API-Keys, kein Build-Schritt.

<Notice type="info" title="Veröffentlichen zum Testen">
Embed-Elemente sind in der Carrd-Builder-Vorschau unsichtbar. Nach dem Hinzufügen des Codes veröffentliche deine Website und öffne die Live-URL. Nutze Strg+Shift+R (oder Cmd+Shift+R auf dem Mac) für eine harte Aktualisierung, um gecachte Styles zu umgehen.
</Notice>

### 1. Ein Embed-Element hinzufügen (Type: Code, Style: Hidden, Body End)

Klicke auf den `+`-Button im Carrd-Builder, füge ein **Embed**-Element hinzu und setze:

- **Type:** Code
- **Style:** Hidden, Body End

Das injiziert deinen Code am Ende des `<body>` der Seite, außerhalb von Carrds eigenem Layout, er lädt also auf jeder Sektion, ohne Platz in deinem Design einzunehmen. Vermeide hier Head: Das Snippet enthält sichtbares Markup (den Button und das Panel), und `<head>` ist kein gültiger Ort dafür.

document.addEventListener('DOMContentLoaded', function() {
  // Get elements
  const toggleBtn = document.getElementById('sidebarToggle');
  const closeBtn = document.getElementById('sidebarClose');
  const overlay = document.getElementById('sidebarOverlay');
  const sidebar = document.getElementById('sidebarMenu');
  const body = document.body;
  let savedScrollTop = 0;

  // Get CSS variables
  const sidebarPosition = getComputedStyle(document.documentElement)
    .getPropertyValue('--sidebar-position').trim();
  const isFloating = getComputedStyle(document.documentElement)
    .getPropertyValue('--menu-button-floating').trim() === 'true';
  const floatPosition = getComputedStyle(document.documentElement)
    .getPropertyValue('--menu-button-float-position').trim();
  const floatSide = getComputedStyle(document.documentElement)
    .getPropertyValue('--menu-button-float-side').trim();

  // Set button positioning classes
  if (isFloating) {
    toggleBtn.classList.add('floating');
    if (floatPosition === 'bottom') {
      toggleBtn.classList.add('float-bottom');
    } else {
      toggleBtn.classList.add('float-top');
    }
    if (floatSide === 'right') {
      toggleBtn.classList.add('float-right');
    } else {
      toggleBtn.classList.add('float-left');
    }
  } else {
    toggleBtn.classList.add('static');
  }

  // Set data attributes for positioning
  toggleBtn.setAttribute('data-position', sidebarPosition);
  closeBtn.setAttribute('data-position', sidebarPosition);
  sidebar.setAttribute('data-position', sidebarPosition);

  // Open sidebar function
  function openSidebar() {
    sidebar.classList.add('active');
    overlay.classList.add('active');
    toggleBtn.classList.add('active');
    body.classList.add('sidebar-open');

    // Accessibility: update ARIA states
    toggleBtn.setAttribute('aria-expanded', 'true');
    toggleBtn.setAttribute('aria-label', 'Close menu');
    sidebar.removeAttribute('aria-hidden');

    // iOS scroll-lock: use position: fixed to prevent background scroll
    savedScrollTop = window.pageYOffset || document.documentElement.scrollTop;
    body.style.position = 'fixed';
    body.style.top = '-' + savedScrollTop + 'px';
    body.style.width = '100%';

    // Focus management: move focus into sidebar
    sidebar.focus({ preventScroll: true });
  }

  // Close sidebar function
  function closeSidebar() {
    sidebar.classList.remove('active');
    overlay.classList.remove('active');
    toggleBtn.classList.remove('active');
    body.classList.remove('sidebar-open');

    // Accessibility: update ARIA states
    toggleBtn.setAttribute('aria-expanded', 'false');
    toggleBtn.setAttribute('aria-label', 'Open menu');
    sidebar.setAttribute('aria-hidden', 'true');

    // iOS scroll-lock: restore scroll position
    body.style.position = '';
    body.style.top = '';
    body.style.width = '';
    // Jump straight back even if the site uses smooth scrolling
    const html = document.documentElement;
    html.style.scrollBehavior = 'auto';
    window.scrollTo(0, savedScrollTop);
    html.style.scrollBehavior = '';

    // Focus management: return focus to toggle button
    toggleBtn.focus({ preventScroll: true });
  }

  // Tab-key focus trap inside sidebar when open
  sidebar.addEventListener('keydown', function(e) {
    if (e.key === 'Tab' && sidebar.classList.contains('active')) {
      const focusable = sidebar.querySelectorAll(
        'a[href], button, [tabindex]:not([tabindex="-1"])'
      );
      const first = focusable[0];
      const last = focusable[focusable.length - 1];

      if (e.shiftKey && (document.activeElement === first || document.activeElement === sidebar)) {
        e.preventDefault();
        last.focus();
      } else if (!e.shiftKey && document.activeElement === last) {
        e.preventDefault();
        first.focus();
      }
    }
  });

  // Event listeners
  toggleBtn.addEventListener('click', function(e) {
    e.stopPropagation();
    if (sidebar.classList.contains('active')) {
      closeSidebar();
    } else {
      openSidebar();
    }
  });

  closeBtn.addEventListener('click', closeSidebar);
  overlay.addEventListener('click', closeSidebar);

  // Close sidebar when clicking on navigation links
  const navLinks = document.querySelectorAll('.sidebar-nav a, .contact-button');
  navLinks.forEach(function(link) {
    link.addEventListener('click', function() {
      closeSidebar();
    });
  });

  // Close sidebar on Escape key
  document.addEventListener('keydown', function(e) {
    if (e.key === 'Escape' && sidebar.classList.contains('active')) {
      closeSidebar();
    }
  });

  // Handle window resize
  window.addEventListener('resize', function() {
    if (window.innerWidth > 768 && sidebar.classList.contains('active')) {
      closeSidebar();
    }
  });
});
</script>

### Button-Positionierungs-Optionen: floating vs. static

**Floating-Modus** (`--menu-button-floating: true`): Der Hamburger-Button ist `position: fixed` und bleibt sichtbar, während der Besucher scrollt. In welcher Ecke er sitzt, steuerst du über `--menu-button-float-position` und `--menu-button-float-side`.

**Static-Modus** (`--menu-button-floating: false`): Der Button wird relativ zu der Stelle positioniert, wo das Embed-Element auf der Seite sitzt.

<Notice type="warning" title="Static-Modus erfordert ein Inline-Embed">
Wenn du `--menu-button-floating: false` setzt, sitzt der Button nur in deinem Layout, wenn das Embed-Element **Style: Inline** nutzt (nicht Hidden). Ein Hidden-Body-End-Embed setzt den Code hinter all of Carrds Content, ein statischer Button würde also ganz unten auf der Seite landen. Ein Inline-Embed zeigt außerdem nur in der Sektion, in der du es platzierst. Für die meisten Setups behalte den Floating-Modus an und nutze das Hidden-Body-End-Embed.
</Notice>

### 3. Die Menülinks auf die richtige Sektion zeigen lassen

Das ist der Schritt, den die meisten verpassen. Deine Seitenmenü-Links nutzen Anker-Hashes (`#about`, `#services` usw.), aber die funktionieren nur, wenn deine Carrd-Website passende Sections-Namen hat.

<Notice type="info" title="Sections-Namen müssen zu deinen href-Werten passen">
Füge im Carrd-Builder ein **Control**-Element hinzu (klicke `+`) und wähle **Section Break**. Gib ihm einen Namen, der zu deinem Link passt. Zum Beispiel `about` für den `#about`-Link. Sections-Namen dürfen nur **Kleinbuchstaben, Zahlen und Bindestriche** enthalten (keine Leerzeichen, keine Großbuchstaben).
</Notice>

So funktionieren Carrd-Sektionen und -Anker:

1. **Section Breaks** erzeugen benannte Sektionen. Füge einen über `+` → Control → Section Break hinzu. Der Name wird das Ankerziel.
2. **Die erste Sektion heißt automatisch `home`.** Deshalb funktioniert `#home` auf den meisten Carrd-Websites out of the box.
3. **Single-Section-Websites** können stattdessen **Scroll Points** nutzen. Füge ein Scroll-Point-Control ein und verlinke es mit `#scrollpoint-name`.
4. **Deep-Linking funktioniert.** Teile `yoursite.carrd.co/#services` und es landet auf der richtigen Sektion.
5. **Wenn Links nicht springen**, prüfe, ob die Section-Break-Namen im Builder exakt mit deinen `href`-Werten übereinstimmen. Ein Tippfehler oder ein Großbuchstabe bricht den Link still.

Für Smooth-Scrolling-Verhalten beim Klicken auf Anker-Links siehe das [Carrd-Smooth-Scroll- und Anker-Links-Tutorial](/de/carrd-smooth-scroll/).

### 4. Die Menüpunkte anpassen

Bearbeite den `<ul class="sidebar-nav">`-Block, damit er zu den Sektionen deiner Website passt:

```html
<ul class="sidebar-nav">
  <li><a href="#home">Home</a></li>
  <li><a href="#about">About</a></li>
  <li><a href="#services">Services</a></li>
  <li><a href="#portfolio">Portfolio</a></li>
  <li><a href="#testimonials">Testimonials</a></li>
  <li><a href="#blog">Blog</a></li>
</ul>
```

Füge `<li><a href="#section">Section Name</a></li>`-Einträge hinzu oder entferne sie. Jeder `href` muss auf einen echten Section-Break-Namen auf deiner Carrd-Website zeigen.

### 5. Den Kontakt-Button anpassen

Der Kontakt-Button unten im Seitenmenü:

```html
<a href="#contact" class="contact-button">Contact Us</a>
```

Ändere den `href` auf eine beliebige URL (interner Anker oder externer Link) und aktualisiere den Button-Text passend zu deinem Bedarf.

## Die wichtigsten Features

### Mobile-Optimierung

Das Seitenmenü ist voll responsiv mit Breakpoints bei 768px und 480px. Auf kleineren Bildschirmen wird das Seitenmenü schmaler, die Schriftgrößen sinken und der Button schrumpft, bleibt aber über 40px für Touch-Ziele.

- Touch-freundliche Button-Größen (mindestens 40px am kleinsten Breakpoint)
- Optimierte Abstände für mobile Bildschirme
- Internes Scrollen auf kurzen Viewports (das Seitenmenü nutzt `overflow-y: auto`)

<Notice type="warning" title="iOS-Safari-Scroll-Lock">
`overflow: hidden` allein verhindert das Hintergrund-Scrollen auf iOS Safari nicht. Das ist ein bekannter WebKit-Bug, seit 2014 offen. Der Code oben nutzt `position: fixed` auf dem Body-Element als Workaround, plus `touch-action: none` auf der `body.sidebar-open`-Klasse, was die meisten Fälle abdeckt. Hinweis: iOS 26 hat eine gemeldete Regression beim Overlay-Scroll-Blocking. Teste auf einem physischen Gerät.
</Notice>

### Flüssige Animationen

Das Seitenmenü bringt mehrere Animationseffekte mit:

- Slide-in/Slide-out-Transitions (konfigurierbare Geschwindigkeit via `--sidebar-animation-speed`)
- Hamburger-Icon, das zu einem X morpht, wenn das Menü offen ist
- Hover-Effekte auf Menüpunkten mit einem Links-Rahmen-Akzent-Highlight
- Button-Skalierung und Schatten-Effekte beim Hover

### Barrierefreiheit

Der Code kommt mit sauberen ARIA-Attributen und Tastatur-Support:

- **Toggle-Button** hat `aria-label` (wechselt zwischen "Open menu" / "Close menu"), `aria-expanded` und `aria-controls`
- **Seitenmenü** nutzt `aria-hidden="true"` im geschlossenen Zustand, beim Öffnen wird es entfernt
- **Hamburger-Spans** sind `aria-hidden="true"` markiert (dekorativ, werden nicht angesagt)
- **Close-Button** hat `aria-label="Close menu"`
- **Tab-Key-Focus-Trap** hält den Fokus im Seitenmenü, solange es offen ist
- **Fokus-Rückgabe:** Schließen des Seitenmenüs gibt den Fokus an den Toggle-Button zurück
- **Escape-Taste** schließt das Seitenmenü
- **Hoher Kontrast** über Farb-Optionen via CSS-Variablen

### Browser-Kompatibilität

Der Code nutzt moderne CSS-Features (Custom Properties, Flexbox, Transitions), die von allen aktuellen Browsern unterstützt werden. Wenn das Seitenmenü hinter anderen Carrd-Elementen erscheint, erhöhe die z-index-Werte: `.sidebar-overlay` (Standard 999), `.sidebar-menu` (Standard 1000), `.sidebar-menu-toggle` (Standard 1001).

## Troubleshooting

<Accordion label="Meine veröffentlichte Website ist blank" group="troubleshooting">

Ein JavaScript-Syntaxfehler bricht die gesamte Carrd-Website. Öffne die Browser-DevTools (F12), prüfe die Konsole auf Fehler, fixe die Syntax in deinem Embed-Element und veröffentliche erneut. Carrds Doku sagt, dass „even a simple syntax error will break the site."

</Accordion>

<Accordion label="Der Menü-Button erscheint nicht" group="troubleshooting">

Du nutzt wahrscheinlich den Static-Modus (`--menu-button-floating: false`) mit einem Hidden-Embed. Statische Buttons sitzen nur aus **Inline**-Embeds in deinem Layout; aus einem Hidden-Body-End-Embed landet der Button ganz unten auf der Seite. Wechsle zum Floating-Modus (`--menu-button-floating: true`) oder ändere den Embed-Style auf Inline.

</Accordion>

<Accordion label="Seitenmenü-Links springen nicht zu Sektionen" group="troubleshooting">

Deine Section-Break-Namen stimmen nicht mit deinen `href`-Werten überein. Prüfe im Carrd-Builder den Namen jedes Section Breaks. Er darf nur Kleinbuchstaben, Zahlen und Bindestriche enthalten. Wenn dein Link zum Beispiel `#about` ist, muss die Sektion exakt `about` heißen (nicht `About`, nicht `about-us`, außer die Sektion heißt `about-us`). Siehe den [Anker-Schritt](#3-die-menülinks-auf-die-richtige-sektion-zeigen-lassen) oben.

</Accordion>

<Accordion label="Seitenmenü erscheint hinter anderen Elementen" group="troubleshooting">

Z-index-Konflikt. Das Seitenmenü nutzt z-index 1000, das Overlay 999 und der Toggle 1001. Wenn Carrd-Elemente oder andere Embeds höhere z-index-Werte haben, erhöhe diese Zahlen im CSS. Das Overlay sollte immer unter dem Seitenmenü liegen, und der Toggle sollte immer oben sein.

</Accordion>

<Accordion label="Hintergrund scrollt auf dem iPhone" group="troubleshooting">

Das ist der iOS-Safari-WebKit-Bug. `overflow: hidden` auf `<body>` verhindert das Scrollen nicht. Der Code nutzt `position: fixed` auf dem Body plus `touch-action: none` auf `body.sidebar-open` als Workaround. Wenn es trotzdem scrollt, prüfe, ob beides noch in deiner Code-Kopie steckt. Teste auf einem physischen iPhone, nicht nur im Simulator.

</Accordion>

<Accordion label="Änderungen erscheinen nicht nach dem Speichern" group="troubleshooting">

Embed-Elemente rendern nicht in der Carrd-Builder-Vorschau. Du musst die Website veröffentlichen, um Änderungen zu sehen. Nach dem Veröffentlichen mit Strg+Shift+R hart aktualisieren (Cmd+Shift+R auf dem Mac), um den Browser-Cache zu umgehen.

</Accordion>

## Fazit

Ein Carrd-Seitenmenü gibt deiner One-Page-Website professionelle Navigation, ohne Content-Platz zu opfern. Der Ansatz erfordert mindestens Carrd Pro Standard (19 $/Jahr) — ein Embed-Element, einmal Code einfügen, fertig.

Die CSS-Variablen machen es einfach, dein Branding zu treffen, die ARIA-Attribute halten es barrierefrei, und die Mobile-Breakpoints kümmern sich um kleinere Bildschirme. Bewahre eine Kopie des Codes an einem sicheren Ort auf — da er auf jeder Sektion der Website läuft, kann ein Syntaxfehler die ganze Seite lahmlegen, bis du fixst und neu veröffentlichst.

Wenn du mehr Carrd-Anpassung erkunden willst, schau in den [Carrd.co Review](/de/carrd-review/) für eine komplette Aufschlüsselung, was jeder Plan bietet, oder stöbere auf [carrdme.com](https://carrdme.com/) durch die komplette Liste der Plugins und Tutorials.
