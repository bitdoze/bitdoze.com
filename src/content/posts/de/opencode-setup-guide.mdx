## Was OpenCode eigentlich ist

OpenCode ist ein terminalbasierter KI-Coding-Agent. Er liest deine Codebase, plant Änderungen, bearbeitet Dateien, führt Befehle aus und iteriert über Fehlschläge – dieselbe Schleife, die Claude Code durchläuft, nur Open Source und providerunabhängig. Er funktioniert mit Anthropic, OpenAI, Google, Alibaba, MiniMax, DeepSeek, Xiaomi, Moonshot und über 70 weiteren Providern. Über Ollama kannst du auch lokale Modelle nutzen.

Der entscheidende Unterschied zu Claude Code: Du wählst Modell und Provider selbst. Wenn Claude Sonnet für eine Aufgabe zu teuer ist, wechselst du zu Qwen 3.6 Plus für 0,33 $/M Input-Tokens. Brauchst du maximales Reasoning, wechselst du zu GLM 5.2. Du kontrollierst die Kosten.

## OpenCode auf einem VPS installieren

Das Install-Skript erledigt alles. Auf einem Linux-VPS:

```bash
curl -fsSL https://opencode.ai/install | bash
```

Das installiert die `opencode`-Binary. Prüfe, ob sie funktioniert:

```bash
opencode --version
```

Andere Installationsmethoden, falls das Skript für dein Setup nicht funktioniert:

### Was du brauchst

- Node.js 18+ (das Install-Skript kümmert sich auf den meisten Systemen darum)
- Einen API-Key von mindestens einem Provider
- Einen Terminal-Emulator mit Bild-Support, wenn du Screenshots per Drag-and-drop einfügen willst (WezTerm, Ghostty, Kitty oder Alacritty)

Auf einem headless VPS brauchst du den Bild-Support nicht. OpenCode funktioniert problemlos über einfaches SSH.

## Einen Modell-Provider konfigurieren

OpenCode unterstützt drei Wege, Modelle anzubinden – vom einfachsten bis zum flexibelsten.

### Option 1: OpenCode Zen (am einfachsten)

OpenCode Zen ist der eingebaute Provider. Du meldest dich bei [opencode.ai/auth](https://opencode.ai/auth) an, bekommst einen API-Key und fügst ihn in OpenCode ein. Der Zen-Provider hat eine kuratierte Liste von Modellen, die vom OpenCode-Team getestet und verifiziert wurden.

Führe `/connect` in der TUI aus, wähle `opencode` und füge deinen Key ein.

### Option 2: OpenRouter (die meisten Modelle)

OpenRouter gibt dir über einen einzigen API-Key Zugriff auf mehr als 200 Modelle. Das nutze ich für den Großteil meiner Arbeit.

```bash
# Add your OpenRouter key
echo "OPENROUTER_API_KEY=your-key-here" >> ~/.config/opencode/.env
```

Führe dann in OpenCode `/connect` aus und wähle OpenRouter.

### Option 3: Direkte Provider-Keys

Für bestimmte Provider kannst du Umgebungsvariablen direkt setzen:

```bash
# MiniMax
echo "MINIMAX_API_KEY=your-key" >> ~/.config/opencode/.env

# Z.AI (GLM)
echo "ZAI_API_KEY=your-key" >> ~/.config/opencode/.env

# Xiaomi MiMo
echo "MIMO_API_KEY=your-key" >> ~/.config/opencode/.env

# DeepSeek
echo "DEEPSEEK_API_KEY=your-key" >> ~/.config/opencode/.env

# Moonshot (Kimi)
echo "MOONSHOT_API_KEY=your-key" >> ~/.config/opencode/.env
```

## Mit OpenCode im Alltag arbeiten

### Ein Projekt initialisieren

Wenn du OpenCode zum ersten Mal in einem Projekt öffnest:

```bash
cd /path/to/project
opencode
```

Dann führe aus:

```
/init
```

OpenCode analysiert deine Codebase und legt eine `AGENTS.md`-Datei im Projekt-Root an. Diese Datei beschreibt OpenCode deine Projektstruktur, Coding-Patterns und Konventionen. Du kannst sie manuell bearbeiten, um eigene Anweisungen hinzuzufügen.

### Plan-Modus vs. Build-Modus

Das ist der Workflow, zu dem ich immer wieder zurückkehre. Drücke **Tab**, um zwischen den Modi zu wechseln:

**Plan-Modus** (read-only): OpenCode liest deine Codebase und beschreibt, wie es ein Feature implementieren würde. Es werden keine Änderungen vorgenommen. Du prüfst den Plan, gibst Feedback, iterierst.

**Build-Modus** (read-write): OpenCode nimmt die tatsächlichen Änderungen an deinen Dateien vor.

Das Muster:

1. Wechsle mit Tab in den Plan-Modus
2. Beschreibe, was du willst
3. Prüfe den Plan, ergänze Constraints oder Bilder
4. Wechsle mit Tab in den Build-Modus
5. Sag ihm, er soll loslegen

Das ist sicherer, als den Agent sofort loslaufen zu lassen – besonders bei Produktionscode.

### Dateien referenzieren

Nutze `@`, um OpenCode auf bestimmte Dateien zu verweisen:

```
Look at @src/api/auth.ts and add the same pattern to @src/api/settings.ts
```

### Rückgängig machen und wiederholen

Wenn OpenCode eine Änderung macht, die dir nicht gefällt:

```
/undo
```

Das macht die Änderungen rückgängig und zeigt deinen ursprünglichen Prompt wieder an, damit du ihn umformulieren kannst.

```
/redo
```

Holt die Änderungen zurück, wenn du es dir anders überlegst.

### Konversationen teilen

```
/share
```

Erstellt einen Link zu deiner aktuellen Konversation. Nützlich, um Teamkollegen zu zeigen, was der Agent gemacht hat, oder eine zweite Meinung zum Plan einzuholen.

## Das richtige Modell für die Aufgabe wählen

Nicht jede Aufgabe braucht das teuerste Modell. Das nutze ich:

| Aufgabe | Modell | Warum |
|------|-------|-----|
| Schnelle Edits, Datei-Refactoring | MiniMax M2.7 | Günstig und schnell, bewältigt die meisten Edits problemlos |
| Frontend-Arbeit, UI-Generierung | Qwen 3.6 Plus | Stark bei „Vibe Coding" und Design |
| Komplexe Multi-File-Änderungen | GLM 5.2 | Beste Coding-Genauigkeit, den Preis wert |
| Langer Kontext, große Repos | DeepSeek V4 Pro | 1M Kontext, niedrige Halluzinationsrate |
| Standard für den Alltag | MiniMax M2.7 oder Qwen 3.6 Plus | Ausgewogenes Verhältnis von Kosten und Qualität |

Wechsle Modelle in OpenCode mit `/models`. Kein Neustart nötig.

## OpenCode vs. Claude Code vs. Codex CLI

| Feature | OpenCode | Claude Code | Codex CLI |
|---------|----------|-------------|-----------|
| **Preis** | Kostenlos (API-Nutzung bezahlen) | 20 $/Monat + API | In ChatGPT enthalten |
| **Modellauswahl** | 75+ Provider | Nur Anthropic | Nur OpenAI |
| **Open Source** | Ja | Nein | Ja |
| **Plan-Modus** | Ja (Tab-Taste) | Nein (/plan nutzen) | Nein |
| **Bild-Support** | Drag-and-drop | Bilder einfügen | Nein |
| **MCP-Server** | Ja | Ja | Ja |
| **Undo/Redo** | /undo, /redo | Git-basiert | Nein |
| **VPS-tauglich** | Ja | Ja | Ja |

Der größte Vorteil von OpenCode gegenüber Claude Code ist die Modellauswahl. Du bist nicht an Anthropics Preise gebunden. Wenn Claude Sonnet zu teuer wird, wechselst du für Routineaufgaben zu einem günstigeren Modell und hebst Claude für die harten Fälle auf.

Der größte Vorteil gegenüber Codex CLI ist der Plan-Modus und die Möglichkeit, mit Nicht-OpenAI-Modellen zu arbeiten.

Wenn du lieber den MCP-Server-Ansatz nutzen willst:

```bash
# After deploying Hindsight (see the guide linked above)
# Add it as an MCP server in your opencode config
```

Das ist nützlich, wenn du über mehrere Sessions hinweg am selben Projekt arbeitest und OpenCode sich an Entscheidungen, Konventionen und vergangene Debugging-Sessions erinnern soll.

## OpenCode auf einem VPS über SSH betreiben

OpenCode funktioniert über SSH. Ich betreibe es auf einem Hetzner-VPS für 6 $/Monat und verbinde mich von meinem Laptop aus. Ein paar Tipps:

Nutze **tmux**, damit deine Session überlebt, wenn die SSH-Verbindung abbricht:

```bash
tmux new -s code
cd /path/to/project
opencode
```

Wenn du die Session detachst (`Ctrl+B, D`) und dich später neu verbindest, bringt dich `tmux attach -t code` genau dorthin zurück, wo du aufgehört hast.

Für ein besseres Terminal-Erlebnis über SSH nutze **mosh** statt plain SSH. Es handhabt Netzwerkabbrüche und Roaming besser:

```bash
mosh user@your-vps-ip
```

## FAQ

<Accordion label="Ist OpenCode wirklich kostenlos?" group="faq" expanded="true">
Die Software ist kostenlos und Open Source. Du zahlst für die LLM-API-Nutzung. Bei OpenCode Go sind das 5 $ im ersten Monat, danach 10 $/Monat. Bei direkten Provider-Keys zahlst du pro Token. MiniMax M2.7 über OpenRouter kostet 0,30 $/M Input-Tokens – das sind für typische Coding-Nutzung grob 3–7 $/Monat.
</Accordion>

<Accordion label="Kann ich OpenCode mit lokalen Modellen über Ollama nutzen?" group="faq">
Ja. Setze `OPENAI_BASE_URL=http://localhost:11434/v1` und `OPENAI_API_KEY=ollama` in deiner OpenCode-Config. Wähle dann das lokale Modell in OpenCode. Unser [Ollama-Docker-Guide](/ollama-docker-install/) zeigt die Einrichtung von Ollama. Die Performance hängt von deiner Hardware ab – ein 7B-Modell bewältigt einfache Edits, aber komplexe Multi-File-Aufgaben brauchen mindestens ein 32B-Modell.
</Accordion>

<Accordion label="Wie schneidet OpenCode im Vergleich zu Aider ab?" group="faq">
Beide sind Terminal-Coding-Agents. OpenCode hat eine umfangreichere TUI mit Plan-Modus, Bild-Support und Sharing. Aider ist minimalistischer und hat eine stärkere Git-Integration. Aider unterstützt mehr obskure Modell-Provider. Für die meisten Entwickler ist OpenCode der bessere Daily Driver.
</Accordion>

<Accordion label="Kann ich OpenCode neben Hermes Agent nutzen?" group="faq">
Ja, die beiden ergänzen sich. OpenCode ist für Coding-Aufgaben – Dateien bearbeiten, Builds laufen lassen, Bugs fixen. Hermes Agent ist für breitere Aufgaben – Websuchen, geplante Jobs, Messaging, Serververwaltung. Betreibe beide auf demselben VPS.
</Accordion>

<Accordion label="Welchen VPS brauche ich?" group="faq">
Jeder Linux-VPS mit 1 GB+ RAM reicht. OpenCode selbst ist leichtgewichtig – die schwere Arbeit passiert beim API-Provider. Ein Hetzner CX22 für 6 $/Monat oder ein Äquivalent ist mehr als genug. Unser [VPS-Hosting-Vergleich](/vps-ai-coding-setup/) zeigt die Optionen.
</Accordion>
