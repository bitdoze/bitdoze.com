Ladybird hat am 23. November 2026 seine erste Alpha veröffentlicht. Es ist der erste herunterladbare Browser seit Jahren, der auf einer Engine läuft, die sonst niemand geschrieben hat: kein Blink, kein WebKit, kein Gecko. Ich habe ihn auf meinem MacBook Pro installiert, vier Tabs geöffnet und sieben Minuten später die Aktivitätsanzeige angeschaut. Das Ergebnis: 19 Prozesse und 2,86 GB.

Diese Zahl ist der Grund für den Artikel. Mein Fazit nach einer Sitzung: Die Engine entscheidet nicht, wie viel Speicher ein Browser braucht. Chrome, das WebKit von Safari und eine komplett neu gebaute Engine wie Ladybird werden alle schwer, sobald du das Web so öffnest, wie es heute ist. Unten findest du, was die Alpha ist, was andere gefunden haben, die Zahlen von meinem Bildschirm und warum der Speicherverbrauch meiner Meinung nach hoch bleibt, egal welchen Browser du installierst.

<Notice type="info" title="So habe ich getestet">
Ein MacBook Pro (Apple M1 Pro), die Ladybird-Alpha von der Download-Seite, vier offene Tabs (eine Google-Suche, ein laufendes YouTube-Video, die Ladybird-Einstellungen und Gmail), abgelesen in der macOS-Aktivitätsanzeige 7 Minuten und 31 Sekunden nach dem Start. Chrome oder Safari habe ich nicht daneben laufen lassen, also ist nichts davon ein direkter Benchmark. Alles, was ich über Ergebnisse anderer schreibe, ist mit der Quelle verlinkt.
</Notice>

## Was Ladybird ist

Ladybird ist ein Browser mit eigener Engine. HTML, CSS, das DOM, das Layout, JavaScript und WebAssembly sind von Grund auf neu implementiert, so steht es in den [Release Notes](https://github.com/LadybirdBrowser/ladybird/releases/tag/2026.47.7). Er begann als Browser des Hobby-Betriebssystems SerenityOS und wird heute von einer US-amerikanischen Non-Profit-Organisation entwickelt, die sich über Sponsoren und Spenden statt über Suchmaschinen-Deals finanziert ([OMG! Ubuntu](https://www.omgubuntu.co.uk/2026/11/ladybird-browser-enters-alpha)).

Ein paar Teile kommen trotzdem von außen. Simon Willison nennt [HarfBuzz für die Textdarstellung, Skia für 2D-Grafik, ffmpeg für Video und SQLite](https://simonwillison.net/2026/Nov/23/ladybird) als externe Komponenten. "Von Grund auf" meint die Engine, nicht jede Bibliothek.

| | Ladybird Alpha |
|---|---|
| Plattformen | Macs mit Apple Silicon (macOS 14.4 oder neuer), Linux x86-64 und Arm64 |
| Nicht dabei | Windows, Intel-Macs, Smartphones |
| Updates | Rolling Channel mit automatischen Updates |
| Sprachen der Engine | C++, Umstieg auf Rust läuft (die JavaScript-Engine und die Stilberechnung sind bereits Rust) |
| Entwicklerwerkzeuge | WebDriver und das Firefox-DevTools-Protokoll |
| Fahrplan | Beta 2027, stabile Version 2028 (laut Projekt-FAQ, [zusammengefasst von Sulat](https://news.sulat.com/2026/11/24/ladybird-browser)) |

Das Team ist ehrlich über den Stand. In Andreas Klings [Ankündigung](https://ladybird.org/posts/alpha/) steht: Manche Seiten funktionieren nicht, der Browser stürzt ab, und für die Sicherheit gibt es keine Zusagen.

<Notice type="warning" title="Melde dich nirgends an, was wichtig ist">
Das Projekt bittet Sicherheitsforscher, ihn zu hacken, und gibt "heute keine Sicherheitsversprechen". Simon Willison nutzt ihn nur für anonymes Surfen, nicht für GitHub oder Gmail. Bei meinem Test war Gmail offen, das würde ich auf einem Rechner, der dir wichtig ist, nicht tun. Nimm ein Wegwerfkonto oder eine virtuelle Maschine.
</Notice>

## Installation

<Tabs>
<Tab name="macOS">
Lade das Disk-Image von [ladybird.org/download](https://ladybird.org/download/) herunter, öffne es und ziehe Ladybird in den Ordner Programme. Der Build ist nur für Apple Silicon.
</Tab>
<Tab name="Linux (Flatpak)">
Das Projekt empfiehlt das Flatpak. Diese beiden Befehle stammen von [Linux und Ich](https://linuxundich.de/en/ladybird-alpha-browser-engine-linux), der sie unter TUXEDO OS ausgeführt hat. Ich habe sie selbst nicht ausgeführt.

```bash
flatpak install --from https://flatpak.ladybird.org/ladybird.flatpakref
flatpak run org.ladybird.Ladybird
```
</Tab>
<Tab name="Ubuntu (apt)">
Für Ubuntu 24.04 und 26.04 gibt es ein apt-Repository, Updates kommen über die normale Software-Aktualisierung. Diese Befehle stammen von [OMG! Ubuntu](https://www.omgubuntu.co.uk/2026/11/ladybird-browser-enters-alpha); ich habe sie nicht ausgeführt.

```bash
sudo wget -qO /etc/apt/keyrings/ladybird.asc 'https://apt.ladybird.org/ladybird.asc'

# Ubuntu 26.04 LTS
sudo wget -qO /etc/apt/sources.list.d/ladybird.sources 'https://apt.ladybird.org/ladybird-resolute.sources'

# Ubuntu 24.04 LTS (oder Linux Mint 22.x)
sudo wget -qO /etc/apt/sources.list.d/ladybird.sources 'https://apt.ladybird.org/ladybird-noble.sources'

sudo apt update && sudo apt install ladybird
```
</Tab>
</Tabs>

## So schneidet er ab

Ladybird misst sich an den Web Platform Tests, der gemeinsamen Testsuite, mit der Browserhersteller die Standardunterstützung prüfen. Das sind die Zahlen von Ende Oktober aus dem [Oktober-Newsletter](https://ladybird.org/newsletter/2026-10-31):

| Browser | Bestandene Subtests | Anteil an Chrome |
|---|---|---|
| Chrome | 2.244.397 | 100 % |
| Firefox | 2.189.315 | 97,5 % |
| Ladybird | 2.184.722 | 97,3 % |
| Safari Technology Preview | 2.172.990 | 96,8 % |

Die Prozentwerte sind meine Rechnung. Das misst die Abdeckung von Standards, nicht wie viele echte Seiten laufen, und der Großteil des Oktobersprungs kam innerhalb von fünf Tagen, nachdem das Team KI-Coding-Agents auf die Suite angesetzt hatte. Kling hat außerdem Claude Code und Codex genutzt, um Teile der JavaScript-Engine von C++ nach Rust zu portieren, wie er in [Ladybird adopts Rust, with help from AI](https://ladybird.org/posts/adopting-rust/) beschreibt. Wie sich solche Agents für deine Arbeit schlagen, zeigen mein [Vergleich von KI-Coding-Tools](/ai-coding-tools/) und der [Freebuff-Test](/de/freebuff-kostenloser-ki-coding-agent/) mit den kostenlosen Optionen.

Beim Tempo sind die Zahlen am schwächsten. Ladybirds August-Newsletter nennt die eigenen Benchmark-Werte "noch bescheidene Zahlen neben den ausgereiften Engines", wie [Sulat zitiert](https://news.sulat.com/2026/11/24/ladybird-browser), und das Speedometer-Ergebnis oben ist ein Notebook an einem Tag.

*Vier Tabs, ein laufendes Video, sieben Minuten nach dem Start. Die Gmail-Adresse und meinen macOS-Kontonamen habe ich unkenntlich gemacht.*

Was das Feld sagt:

- 19 Prozesse und 285 Threads für vier Tabs.
- Speicher 2,86 GB und separat eine Zeile "Resident memory" mit 1,51 GB. Die Aktivitätsanzeige zeigt beide, ich bin dem Unterschied nicht nachgegangen und nenne deshalb im ganzen Artikel die Hauptzahl 2,86 GB.
- CPU 39 % für die Gruppe im Moment des Screenshots.
- Drei Prozesse belegen 710, 694 und 672 MB. Der nächste hat 298 MB, dann 139 und 129 MB, der Rest ist klein.

![Balkendiagramm des Speichers pro Ladybird-Prozess: drei mit 710, 694 und 672 MB, dann 298, 139 und 129 MB, dann sieben unter 50 MB](@assets/images/26/11/ladybird-memory-by-process.webp)

*Einzeln aufgeführte Prozesse aus dem Screenshot. Sieben weitere waren unter "and 7 more" eingeklappt. Welcher Prozess zu welchem Tab gehört, lässt sich in der Aktivitätsanzeige nicht erkennen.*

Die drei größten Prozesse summieren sich auf 2.076 MB, mehr als 70 % der Gruppe. Eine einzelne Zahl wie "Ladybird braucht 53 MB" ergibt nur Sinn, wenn man eine einzige Zeile betrachtet.

### Warum die Zahl eines einzelnen Prozesses täuscht

Mehrere Kommentatoren auf Hacker News nannten niedrige Werte. Einer berichtete von "53mb Speicher mit mehreren offenen Tabs", ein anderer von "weniger als 100 mb RAM". Ein Dritter ergänzte bei einer ähnlichen Behauptung das fehlende Stück: Ladybird öffnet Tabs als eigene Prozesse, der Hauptprozess ist also nicht die Summe, und ein einziger YouTube-Tab belegte 300 MB in einem eigenen WebContent-Prozess.

Simon Willisons Prozessbaum zeigt dasselbe bei sieben Tabs:

![Diagramm des Ladybird-Prozessbaums: Der UI-Prozess startet einen Hub, der WebContent-Prozesse, RequestServer, Compositor und MediaServer verwaltet, mit den Speicherwerten aus Simon Willisons Baum](@assets/images/26/11/ladybird-process-tree.webp)

*Prozessnamen und Größen aus [Simon Willisons Baum](https://simonwillison.net/2026/Nov/23/ladybird) (16 Prozesse, rund 2,1 GB). Die Rollen stammen aus Ladybirds Newslettern von [September](https://ladybird.org/newsletter/2026-09-30) und [Oktober](https://ladybird.org/newsletter/2026-10-31). Die Summen für Tabs und Hilfsprozesse sind meine Rechnung.*

Seine sieben Tabs belegten 1.448 MB, einer davon 819 MB. Die Hilfsprozesse (UI, Hub, Netzwerk, Compositor, Medien) kamen auf weitere 655 MB. Der "schwere" Teil sind also ein paar Tabs, der "Overhead" ist real, aber kleiner.

## Warum der Speicher bei jeder Engine hoch bleibt

Meine Lesart, nachdem ich meine Zahlen neben die aller anderen gelegt habe: Vier Dinge treiben den Speicherverbrauch eines Browsers, und keines hängt davon ab, wer die Engine geschrieben hat.

**1. Jeder moderne Browser zahlt für Isolation.** Engadgets [Erklärung zu Chrome und RAM](https://www.engadget.com/2294261/why-google-chrome-using-so-much-ram/) sagt, Browserhersteller müssten wählen: Prozesse über Tabs teilen und Speicher sparen oder jeder Seite einen eigenen Prozess geben. Chrome wählt das Zweite. Ein Absturz bleibt in einem Tab, und eine feindliche Seite kann nicht so leicht in deinem Banking-Tab mitlesen. Ladybird hat dieselbe Entscheidung getroffen und im Oktober noch nachgelegt: eigene Prozesse für Netzwerk, Bilddekodierung, Audio und Video sowie eigene Renderer für seitenübergreifende iframes. Mehr Wände, mehr Speicher. Das ist der Preis des Sicherheitsmodells, kein Zeichen für schlechten Code.

**2. Das Web besteht aus Apps.** Gmail plus ein YouTube-Player ist keine kleine Last. Ein Anbieterartikel setzt schwere Web-Apps bei [200 bis 500 MB pro Tab](https://supasidebar.com/blog/reduce-chrome-memory-usage-tabs-2026) an. Sieh das als grobe Orientierung, denn die Quelle verkauft einen Tab-Manager. Meine drei größten Prozesse (710, 694 und 672 MB) liegen über diesem Bereich, und ich kann nicht sagen, welche Tabs das waren.

**3. Speicher wird festgehalten, nicht freigegeben.** Ladybirds September-Newsletter beschreibt Seiten, die sich per Timer selbst neu laden. Hintergrund-Tabs von Politico erreichten nach vier Stunden 11 GB, die von El País nach zwanzig Stunden 15 GB, weil jedes ersetzte Dokument am Leben blieb. Das wurde im September behoben, und im Oktober stand ein ähnlicher Fix für Gmail. Eine brandneue Engine mit modernem Garbage Collector ist trotzdem darüber gestolpert, weil das Web Seiten enthält, die sich schlecht benehmen.

**4. Freier RAM ist verschwendeter RAM.** Engadgets Argument: Ein Browser, der freien Speicher mit vorbereiteten Tabs füllt, macht seinen Job. Auf meinem Mac waren 83 % des Speichers belegt, bei 549 laufenden Prozessen, und der Browser war nur einer davon. Als ein Nutzer Anfang November Ladybirds Speicherverbrauch ansprach, antwortete Kling, das Team habe dort noch Arbeit vor sich, so [PiunikaWeb](https://piunikaweb.com/2026/11/05/ladybird-update-makes-scrolling-and-text-selection-much-smoother/).

Zwei Einschränkungen, denn das ist eine einzige Sitzung. Erstens ist eine Alpha der schlechteste Fall für den Speicher, weil Optimierung nach den Funktionen kommt. Zweitens habe ich Chrome und Safari nicht daneben laufen lassen und behaupte deshalb nicht, Ladybird sei gleich auf. Meine Aussage ist enger: Eine 2026 komplett neu gebaute Engine ohne Chromes Vorgeschichte ist dem Problem nicht entkommen, also erwarte ich nicht, dass ein Engine-Wechsel es löst.

Derselbe Druck taucht außerhalb von Browsern auf. Desktop-Apps auf Electron-Basis bringen ihr eigenes Chromium mit, und mein Vergleich [Orca vs T3 Code](/de/orca-vs-t3-code/) stellt eine Electron-App einem Server mit Web-Clients gegenüber. Auf dem Mac haben Container dasselbe Problem, deshalb habe ich die [Docker-Desktop-Alternativen](/de/beste-docker-desktop-alternativen/) nach RAM und Leerlaufverbrauch verglichen.

## Was du gegen hohen Browser-Speicher tun kannst

- **Summiere die ganze Gruppe.** Suche in der Aktivitätsanzeige nach dem Browsernamen und lies das Gruppenfeld, nicht eine einzelne Zeile. Ladybirds September-Newsletter beschreibt außerdem einen nativen Task-Manager mit Prozessbaum und sortierbarer Speicherspalte, den ich aber nicht geöffnet habe.
- **Schließe die schweren Tabs, nicht die leichten.** Drei Prozesse waren über 70 % meines Gesamtwerts. Sie zu finden geht schneller, als alles zu schließen.
- **Schalte den Inhaltsblocker ein.** Er ist standardmäßig aus. Der September-Newsletter führt einen Fall mit durchdrehender CPU auf ein Werbeskript zurück, das ein Blocker entfernt hatte. Ob er den Speicher senkt, habe ich nicht gemessen.
- **Nimm einen Browser, der Tabs entlädt.** Laut Engadget hat Chrome Memory Saver, und Firefox entlädt Tabs, wenn dem System der Speicher knapp wird.
- **Kauf Speicher für deine echte Arbeit.** Wenn du lokale Modelle oder viele Agents laufen lässt, ist der Browser-Overhead die kleinere Rechnung. Mein [Mac-mini-Guide für OpenClaw](/best-mac-mini-for-openclaw/) rechnet das durch.

## Solltest du ihn nutzen?

<ListCheck>
- Nutze ihn, um deine eigene Seite in einer vierten Engine zu testen. WebDriver und das Firefox-DevTools-Protokoll sind in der Alpha enthalten. Mein [Test von Modern Web Guidance](/modern-web-guidance-legacy-scan/) behandelt Audits, die sich mit einer zusätzlichen Engine gut ergänzen.
- Nutze ihn zum anonymen Surfen auf einem Rechner, auf dem ein Absturz nichts kostet.
- Nutze ihn, wenn du eine gemeinnützige Engine unterstützen willst. Zu den Sponsoren gehören Cloudflare, Proton und Shopify, laut [OMG! Ubuntu](https://www.omgubuntu.co.uk/2026/11/ladybird-browser-enters-alpha) und Sulat.
- Nutze ihn nicht als täglichen Browser. Keine Erweiterungen, kein Import, ruckelndes Video und keine Sicherheitszusagen.
- Lass ihn weg, wenn du Windows oder einen Intel-Mac brauchst. Beides fehlt in der Alpha.
</ListCheck>

Wenn du Browser automatisierst, zählt eine unabhängige Engine heute weniger als eine stabile. Tools wie [Pinchtab](/pinchtab-browser-ai-agents/) steuern Chrome oder Chromium, weil Seiten genau dagegen getestet werden. Ladybirds WebDriver-Unterstützung ist beobachtenswert, aber keine Wette.

## Mein Fazit

Ladybird beeindruckt für eine Alpha. Echte Seiten rendern, das Team liefert schnell, und die Engine besteht rund 97 % der Web-Platform-Tests-Subtests von Chrome. Im einzigen Benchmark, den ich gefunden habe, ist er langsamer als Chrome und Firefox, und er braucht mehr Feinschliff.

Beim Speicher bin ich nicht überzeugt, dass irgendeine Engine mir einen leichten Browser gibt. Vier Tabs kosteten 2,86 GB auf einer komplett neuen Engine, und die Erklärung (Isolation, App-große Seiten, festgehaltener Speicher, ein Mac, der schon bei 83 % lag) gilt genauso für Chrome und WebKit. Das ist meine Lesart aus einer einzigen Sitzung, keine Messung. Was ich als Nächstes nachschaue, ist der November-Newsletter, der die ersten Zahlen nach der Alpha enthalten sollte.

## FAQ

<Accordion label="Ist Ladybird ein Fork von Chromium oder Firefox?" group="faq" expanded="true">
Nein. In den Release Notes steht, dass HTML, CSS, das DOM, das Layout, JavaScript und WebAssembly komplett neu implementiert sind. Er nutzt aber Bibliotheken wie Skia, HarfBuzz, ffmpeg und SQLite, laut Simon Willison.
</Accordion>

<Accordion label="Kann ich Ladybird als täglichen Browser nutzen?" group="faq">
Noch nicht. Das Projekt sagt, manche Seiten funktionieren nicht und er stürzt ab, und es gibt keine Sicherheitszusagen. Es gibt kein Erweiterungssystem und keinen Import aus anderen Browsern.
</Accordion>

<Accordion label="Braucht Ladybird weniger Speicher als Chrome?" group="faq">
Das habe ich nicht gemessen. Meine Sitzung mit vier Tabs belegte 2,86 GB, verteilt auf 19 Prozesse. Kommentatoren auf Hacker News nannten niedrigere Werte, aber mindestens einer meinte einen einzelnen Prozess und nicht die Gruppe. Vergleiche deshalb nur Summen.
</Accordion>

<Accordion label="Hat Ladybird Erweiterungen oder einen Werbeblocker?" group="faq">
Ein Erweiterungssystem gibt es nicht. Es gibt einen eingebauten Inhaltsblocker mit Filterlisten wie EasyList, der aus ist, bis du ihn auf der Willkommensseite oder in den Einstellungen aktivierst.
</Accordion>

<Accordion label="Gibt es eine Windows-Version?" group="faq">
Nicht in der Alpha. Laut Projekt kommt Windows in einer späteren Phase. HWBusters berichtet, dass vorerst empfohlen wird, die Linux-Version in WSL2 zu bauen.
</Accordion>

<Accordion label="Kann ich Ladybird zum Testen meiner Website nutzen?" group="faq">
Ja, das ist heute der klarste Einsatz. Er unterstützt WebDriver für automatisierte Tests und das Firefox-DevTools-Protokoll. Rechne mit Lücken: Simon Willison stieß bei Datasette Lite auf einen Service-Worker-Fehler und meldete ein Issue.
</Accordion>

<Accordion label="Wer finanziert Ladybird?" group="faq">
Eine US-Non-Profit-Organisation, finanziert über Spenden und Sponsoren. Das Projekt sagt, es nehme keine Standard-Suchmaschinen-Deals an, und Sponsoren hätten kein Mitspracherecht bei der technischen Roadmap.
</Accordion>
