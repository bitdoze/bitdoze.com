## What is happening to OpenAI's whisper-1 API in 2026 and 2027?

OpenAI deprecated `whisper-1`, `gpt-4o-transcribe`, `gpt-4o-mini-transcribe`, `gpt-4o-transcribe-diarize`, and the `/v1/audio/translations` endpoint on August 26, 2026, with a scheduled shutdown on **February 26, 2027** (per the [OpenAI deprecations schedule](https://developers.openai.com/api/docs/deprecations)).

Swapping the model string to OpenAI's recommended replacement (`gpt-transcribe`) is not always a drop-in fix. Here is the current OpenAI speech-to-text lineup (verified on the [OpenAI pricing docs](https://developers.openai.com/api/docs/pricing) on November 23, 2026):

| OpenAI model | Status | Per-minute rate | Hourly rate | Migration catch |
|---|---|---|---|---|
| `gpt-transcribe` | Active | $0.0045/min (est.) | $0.27/hr | 25 MB file cap; no built-in diarization or SRT/VTT |
| `gpt-live-transcribe` | Active | $0.017/min (est.) | $1.02/hr | Realtime WebSocket streaming only; no speaker labels |
| `gpt-realtime-translate` | Active | $0.034/min (est.) | $2.04/hr | Replaces `/v1/audio/translations` via Realtime sessions |
| `whisper-1` | Shuts down Feb 26, 2027 | $0.006/min | $0.36/hr | Word timestamps & SRT/VTT lived here |
| `gpt-4o-transcribe` | Shuts down Feb 26, 2027 | $0.006/min (est.) | $0.36/hr | Token-billed ($2.50 in / $10 out per 1M) |
| `gpt-4o-mini-transcribe` | Shuts down Feb 26, 2027 | $0.003/min (est.) | $0.18/hr | Token-billed ($1.25 in / $5 out per 1M) |
| `gpt-4o-transcribe-diarize` | Shuts down Feb 26, 2027 | $0.006/min (est.) | $0.36/hr | Speaker-labeled file transcription lived here |

Notice the two real friction points in OpenAI's migration path. First, the file upload cap stays at **25 MB**, so any meeting or podcast longer than ~25 minutes of MP3 still requires chunking with `ffmpeg`. Second, OpenAI's own [transcription guide](https://developers.openai.com/api/docs/guides/transcription) points out that changing only the model ID does not preserve word timestamps, SRT/VTT subtitle export, or speaker-labeled transcripts. If your pipeline relies on speaker labels or hour-long recordings, moving off OpenAI's audio endpoint saves you from rewriting around missing features.

**Verdict:** Clean one-line migration inside the `openai` SDK at $0.27/hour, as long as your clips stay under 25 MB and do not need speaker labels.

- **Best for:** Existing OpenAI apps transcribing short voice memos or clips where plain text is enough.

## How do AssemblyAI and Fish Audio compare in real tests?

Across six identical audio files (593 spoken words), AssemblyAI made 1 word error (0 errors on DevOps jargon) and separated all five real speakers accurately, while Fish Audio made 13 errors on technical terms but answered 6 times faster (1.2 seconds vs 7.7 seconds).

### Test files and scoring method

I created six recordings, two from real human voices and four from `edge-tts`, and sent each file to both cloud APIs with default settings.

| File | Length | Contents |
|---|---|---|
| `dictation-clean.wav` | 56 s | Synthetic voice reading an incident update with DevOps jargon, two filler words, and a self-correction |
| `dictation-noisy.wav` | 56 s | Same audio mixed with pink noise 10 dB below the speech |
| `dialogue.wav` | 32 s | Two synthetic voices taking six alternating turns |
| `librispeech.wav` | 52 s | Five clips from five real speakers in the [LibriSpeech](https://www.openslr.org/12) validation set |
| `spanish.wav` | 19 s | One Spanish speaker to check automatic language detection |
| `jfk.wav` | 11 s | The 1961 inauguration clip from the [OpenAI Whisper repository](https://github.com/openai/whisper/blob/main/tests/jfk.flac) |

On AssemblyAI I called the pre-recorded API with `speech_models: ["assemblyai-stt-3-7"]`, `speaker_labels: true` on the multi-speaker files, and `language_detection: true` on the Spanish clip. On Fish Audio I called `POST /v1/asr` with the `model: transcribe-1-pro` header and default fields, plus `ignore_timestamps=false` for the dialogue.

To score each output, I lowercased the text, stripped punctuation, and ignored formatting choices like `4` vs `four` or `OK` vs `Okay`. Spoken fillers and the false start counted as real words, so verbatim retention counted as correct.

The synthetic voices came from [edge-tts](/uv-text-to-speech-script/), which is cleaner than a laptop microphone in a busy room. That is why I included the five LibriSpeech readers and the 1961 JFK recording. Every file ran twice. Treat the table as a real-world sanity check, not a lab benchmark.

Here is the command that built the DevOps dictation file from `script.txt`:

```bash
uvx edge-tts --voice en-US-AndrewNeural \
  --file script.txt --write-media dictation.mp3
ffmpeg -i dictation.mp3 -ar 16000 -ac 1 dictation.wav
```

### Fillers, self-corrections, and speaker diarization

Both standard APIs transcribe verbatim. Every "um", "uh", and "restart the, no wait" lands in the JSON. That is right for archival transcripts and frustrating when you want paste-ready notes.

AssemblyAI offers a separate Dictation API that returns verbatim `text` plus a cleaned `llm_response` in one call. On my 56-second clip it dropped every filler, collapsed the self-correction into `"First, I tried to reload the NGINX pods."`, kept every product name intact, and finished in 0.9 to 1.6 seconds. The price is $0.62/hour, roughly three times the batch API.

Fish Audio has no built-in cleanup flag. Its form parameters cover timestamps, speaker count hints, language hints, and audio events, so you have to chain your own LLM pass for filler removal.

For diarization, both APIs split the synthetic two-voice dialogue across all six turns cleanly. AssemblyAI returns an `utterances` array with speaker letters and millisecond timings. Fish Audio embeds inline tags like `<|speaker:0|>` and, with timestamps enabled, a `speaker_turns` array in seconds (pass `diarize=false` to strip the markers). On the five real LibriSpeech speakers, AssemblyAI labelled all five cleanly from A to E. Fish Audio returned four IDs and merged two different voices under one speaker label.

### Request latency

Wall-clock time from upload start to final text:

| File | AssemblyAI (batch) | Fish Audio |
|---|---|---|
| DevOps dictation (56 s) | 7.7 s | 1.2 s |
| Dialogue (32 s) | 6.3 s | 1.1 s |

The gap is pure architecture. Fish Audio is synchronous: open one HTTP request, receive the transcript a second later. AssemblyAI's batch endpoint uses a job queue: upload (~1.6 s), submit job, poll (~5 s). That fixed overhead means even an 11-second recording takes 4.7 seconds.

Waiting 7 seconds on a push-to-talk hotkey gets old in five minutes. Waiting 7 seconds in a background job or webhook pipeline does not matter at all. When a person is waiting interactively, use AssemblyAI's Dictation API (under 2 seconds on the same clip), streaming, or Fish Audio. For high-volume batch work, AssemblyAI's queue runs up to 200 concurrent jobs on paid accounts and posts finished transcripts to a webhook.

## What are the best local open-source Whisper alternatives?

Running transcription locally costs $0 per hour and keeps private audio off third-party servers. You can either swap stock PyTorch Whisper for a faster C++/CTranslate2 runtime (`faster-whisper` or `whisper.cpp`), switch to newer open-weight models like NVIDIA Parakeet v3 and Mistral Voxtral, or install a free offline desktop dictation app.

### 1. Faster Whisper runtimes with OpenAI-compatible APIs

If your existing code already posts to OpenAI's `/v1/audio/transcriptions` endpoint, you can point `OPENAI_BASE_URL` at a self-hosted container with zero SDK rewrites:

- **[Speaches](https://github.com/speaches-ai/speaches) (formerly `faster-whisper-server`, MIT):** Docker server powered by `faster-whisper` (CTranslate2) on CPU or NVIDIA CUDA. It speaks OpenAI's exact transcription API, streams over SSE, and unloads idle models automatically so it plays nicely on a homelab box.
- **[whisper.cpp](https://github.com/ggml-org/whisper.cpp) (`whisper-server`, MIT):** Zero-Python C/C++ binary running quantized GGML Whisper models on x86/ARM CPUs, Apple Metal, CUDA, or Vulkan. Launch it with `--inference-path /v1/audio/transcriptions` for OpenAI SDK compatibility.

Start Speaches on CPU with Docker Compose:

```yaml
services:
  speaches:
    image: ghcr.io/speaches-ai/speaches:latest-cpu
    ports:
      - "8000:8000"
    volumes:
      - speaches-models:/home/ubuntu/.cache/huggingface/hub
    restart: unless-stopped

volumes:
  speaches-models:
```

Pull `faster-whisper-small` (uses about 1 GB RAM and transcribes short phrases in 1-3 seconds on 4 CPU cores) and test it with standard OpenAI `curl` syntax:

```bash
curl -s -X POST http://localhost:8000/v1/models/Systran/faster-whisper-small

curl -s http://localhost:8000/v1/audio/transcriptions \
  -F "file=@dictation.wav" \
  -F "model=Systran/faster-whisper-small"
```

### 2. Newer open-weight models replacing Whisper itself

If you are ready to move past the 2022 Whisper architecture entirely, three open-weight families now beat stock Whisper on speed, size, or streaming:

- **NVIDIA Parakeet TDT 0.6B v3 (CC-BY-4.0):** Built for fast batch transcription across 25 European languages. It runs far faster than Whisper `large-v3` on consumer hardware and powers desktop apps like FluidVoice and Handy.
- **Mistral Voxtral Mini 4B Realtime (Apache-2.0):** Native streaming open-weight model covering 13 languages, suited to low-latency voice pipelines on a local GPU.
- **Moonshine (MIT):** Compact on-device speech-to-text models designed for phones, laptops, and edge hardware across 10 languages.

### 3. Free local desktop dictation apps

If you do not want to manage Docker containers or write scripts and just want offline voice typing into any app:

- **[Hex](/hex-dictation/) (MIT, Mac/Windows/Linux):** Rust app with Metal and Vulkan GPU acceleration, custom models, vocabulary lists, a CLI, and optional AI cleanup via OpenCode.
- **FluidVoice (GPL-3.0, macOS):** Runs Parakeet and Whisper locally on Apple silicon with built-in filler cleanup.
- **Handy (MIT, Mac/Windows/Linux):** Lightweight push-to-talk dictation using Whisper or Parakeet v3 locally.

## How to transcribe audio with AssemblyAI and Fish Audio

Both APIs run from plain `curl` and `jq` without installing a client library. AssemblyAI uses an upload-submit-poll workflow for batch files (or a single POST for the Dictation API), while Fish Audio completes in one synchronous multipart request.

### AssemblyAI (best for technical jargon, diarization, and long files)

**Verdict:** 1 word error across 593 tested words, 5/5 real speaker accuracy, 10-hour max file duration, and $50 in free no-card credit.

- **Best for:** Engineering teams migrating off `whisper-1` who need accurate product names, long recordings, word timestamps, or reliable speaker labels.
- **Strengths:** Writes `kubectl`, `NGINX`, and `/var/log/syslog` accurately, offers a sub-2-second Dictation API with filler removal, and handles up to 200 concurrent batch jobs on paid accounts.
- **Trade-offs:** Standard batch endpoint adds 5-8 seconds of queue latency even on short clips; speaker diarization adds $0.02/hour.
- **Pricing:** $0.21/hour (`assemblyai-stt-3-7`), $0.15/hour (`universal-2`, 99 languages), $0.62/hour (Dictation API).

Create an API key at [AssemblyAI](https://go.bitdoze.com/assemblyai) and run (my [AssemblyAI review](/assemblyai-review/) covers the streaming, dictation, and summary APIs):

```bash
export ASSEMBLYAI_API_KEY=your_key

# 1. Upload the file and get a temporary URL
upload_url=$(curl -s -X POST https://api.assemblyai.com/v2/upload \
  -H "authorization: $ASSEMBLYAI_API_KEY" \
  --data-binary @dialogue.wav | jq -r .upload_url)

# 2. Start the job
id=$(curl -s -X POST https://api.assemblyai.com/v2/transcript \
  -H "authorization: $ASSEMBLYAI_API_KEY" \
  -H "content-type: application/json" \
  -d "{\"audio_url\": \"$upload_url\",
       \"speech_models\": [\"assemblyai-stt-3-7\"],
       \"speaker_labels\": true}" \
  | jq -r .id)

# 3. Poll until it finishes
while :; do
  result=$(curl -s https://api.assemblyai.com/v2/transcript/$id \
    -H "authorization: $ASSEMBLYAI_API_KEY")
  status=$(echo "$result" | jq -r .status)
  [ "$status" = "completed" ] && break
  [ "$status" = "error" ] && { echo "$result" | jq -r .error; break; }
  sleep 1
done

# 4. Print one line per speaker turn
echo "$result" | jq -r '.utterances[] | "Speaker \(.speaker): \(.text)"'
```

Watch two details: pass `authorization` with the raw key (no `Bearer` prefix), and upload with `--data-binary @file` (using `-d` sends the filename as plain text and triggers a transcoding error). Call `curl -X DELETE` on the transcript URL afterward if you do not want AssemblyAI retaining the transcript.

For fast interactive dictation with automatic filler cleanup (up to 20 minutes), one request to the Dictation API replaces all four steps:

```bash
curl -s -X POST https://dictation.assemblyai.com/v1/transcribe \
  -H "Authorization: $ASSEMBLYAI_API_KEY" \
  -F "audio=@dictation.wav;type=audio/wav" \
  | jq -r '"Verbatim: \(.text)", "Cleaned:  \(.llm_response)"'
```

On macOS, AssemblyAI also publishes [Blurt](https://github.com/AssemblyAI/blurt), a free MIT-licensed desktop dictation app backed by your own API key at $0.62/hour.

Grab a key from [Fish Audio](https://go.bitdoze.com/fish-audio) and run:


Omit the timestamp field for plain text with inline markers, or add `-F "diarize=false"` to drop speaker labels altogether. Fish Audio accepts WAV, MP3, AAC, FLAC, Ogg, WebM, and MOV up to 60 minutes. Set a generous HTTP client timeout (the docs recommend 900 seconds), since nothing streams back until the whole file finishes. Non-developers can upload audio directly in the Fish Audio web app.
