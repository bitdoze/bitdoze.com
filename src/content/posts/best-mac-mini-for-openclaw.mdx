## Why a Mac mini for OpenClaw (the honest answer)

There are four real reasons, and then one reason not to bother.

First, idle power. Apple's own support page lists the M6 Mac mini at 4W idle, measured at the wall ([Apple](https://support.apple.com/en-us/103253)). That is closer to a Raspberry Pi than to a desktop. An always-on agent box runs 24/7, and at the US residential average of 18.31 cents per kWh ([EIA](https://www.eia.gov/electricity/monthly/epm_table_grapher.php?t=epmt_5_6_a)), the whole year of idling costs about $6.40. More on that math below.

Second, macOS-only integrations. OpenClaw's iMessage channel needs a Mac: it works through `imsg`, a Swift CLI that reads the Messages database and sends through Messages.app automation ([docs.openclaw.ai](https://docs.openclaw.ai/channels/imessage), [github.com/openclaw/imsg](https://github.com/openclaw/imsg/)). The Apple Notes, Reminders, and Shortcuts skills are the same story. If your agent lives in iMessage threads with your family or touches your Apple account's data, no Linux box substitutes cleanly.

Third, it is silent and tiny. The Mac mini is 5 by 5 inches, 1.5 pounds, and rated at 5 dBA at idle, which is functionally inaudible ([Apple specs](https://www.apple.com/mac-mini/specs/)). It sits on a shelf next to the router and you forget it exists.

Fourth, demand says something. When the M6 mini launched, The Verge reported that last-gen Mac minis "became scarce due to higher than expected demand for running AI agents" ([The Verge](https://www.theverge.com/tech/984190/apple-mac-mini-m6-m5-pro-price-specs)). A lot of people already made this exact choice.

Now the counterpoint, because it matters: the OpenClaw gateway itself is a light Node.js process. If your agent talks to Claude, GPT, or another cloud API, the model lives on someone else's hardware and your box just passes messages. A $349 Intel N150 mini PC running Linux does that job for less than half the price, and a Raspberry Pi works too: OpenClaw's own docs call a 1GB Pi the minimum and recommend 2GB+ ([OpenClaw docs](https://docs.openclaw.ai/install/raspberry-pi)). Buy the Mac mini for the macOS features or for local models, not because the gateway needs it.

## What I run, and where 24GB runs out

My own OpenClaw box is a Mac mini M4 Pro with 24GB of unified memory, and I'll be blunt about it: 24GB is too little for local models. The gateway, the channels, and everything macOS-specific run beautifully, but once you point a real model at it the memory ceiling shows up fast. That's why I'm steering you away from calling 24GB "the local-model config" in this guide. Today's 24GB M5 Pro base config has the same ceiling, so treat the $1,599 Amazon unit as a gateway-plus-macOS machine and buy 48GB or more if local inference is the plan.

## What OpenClaw actually needs

The official requirements are short ([OpenClaw install docs](https://docs.openclaw.ai/install/)):

- Node 24.16+ or Node 26.1+, with Node 26 recommended. The installer provisions it automatically.
- macOS, Linux, or Windows.
- Enough disk for the app and your logs.

That's it. There is no CPU floor worth quoting and no RAM floor beyond what the OS needs, because the heavy lifting happens at the model provider. The memory question only appears when you point OpenClaw at a local model server: the managed llama.cpp setup uses recipes with an 8GiB host-memory floor at the small end and checks available RAM and disk before downloading ([local models docs](https://docs.openclaw.ai/gateway/local-models)).

So the decision tree is simple. Cloud models: any Mac mini works, including the cheapest. Local models: memory decides everything, which is what the next section is for. For model picks once the hardware is sorted, see the [OpenClaw + Ollama local models guide](/openclaw-ollama-local-models/) and the [best open-source models for OpenClaw](/best-opensource-models-for-openclaw/).

## How much memory for local models

On Apple silicon the GPU and CPU share unified memory, and macOS caps how much of it the GPU can pin (wire) at roughly 75% by default. On a 24GB Mac that ceiling is about 17.8GiB; a model that doesn't fit under the cap spills layers to the CPU and slows down hard. You can raise it with `sudo sysctl iogpu.wired_limit_mb=<MB>`, which takes effect immediately but is undocumented and resets on reboot ([llmconfigurator](https://llmconfigurator.com/en/guides/troubleshooting/increase-metal-vram-limit-apple-silicon), [example measurement on a 24GB M4 mini](https://mac-mini-m4-doc.masterfabric.co/)).

Treat this table as a rule of thumb, not a guarantee. Download sizes are from the [Ollama library](https://ollama.com/library), and real memory use adds the KV cache and context on top, so leave headroom.

| Unified memory | Default GPU cap | Realistic model size | Example Ollama models (download size) | Verdict |
| --- | --- | --- | --- | --- |
| 16GB | ~12GB | Up to ~8B | llama3.1:8b (4.9GB) | Cloud first; small local models fit |
| 24GB | ~17.8GiB | 8-14B | qwen3:14b (9.3GB), gpt-oss:20b (14GB) | Small models only, my own 24GB box tops out here |
| 32GB | ~24GB | Up to ~30B | qwen3:32b (20GB) | Maxes out the M6, still tight |
| 48-64GB (M5 Pro) | ~36-48GB | 30-70B | llama3.3:70b (43GB) | Where local models actually start |
| 128GB (EVO-X2 / Studio) | ~96GB | 70B-120B | gpt-oss:120b (65GB) | Local frontier-class models |

Bandwidth decides speed, not capacity. The M6 gives you 153GB/s at 16GB and 170GB/s at 24-32GB, the M5 Pro 307GB/s, and the M5 Max in a Mac Studio 460-614GB/s ([Apple tech specs](https://www.apple.com/mac-mini/specs/), [Mac Studio specs](https://support.apple.com/en-us/128107)). A 32B model on an M6 runs but generates slowly; on an M5 Pro it runs about twice as fast per token. That is what you pay for above 24GB.

## Run it headless and keep it online

A Mac mini as an always-on agent host needs four settings and one command. The steps below follow the pattern Mac-server guides like [macrun.dev](https://macrun.dev/mac-mini-server) and [hometechops](https://hometechops.com/mac/mac-mini-home-server-setup) use:

```bash
sudo pmset -a sleep 0        # never idle-sleep
sudo pmset -a displaysleep 10
sudo pmset -a autorestart 1  # boot again after power loss
sudo pmset -a womp 1         # wake for network access
```

Check it stuck with `pmset -g`. In System Settings > Energy, that maps to "Prevent automatic sleeping when the display is off", "Wake for network access", and "Start up automatically after power failure". Turn on Remote Login (SSH) and Screen Sharing under General > Sharing, and you can unplug the monitor for good.

Two real gotchas. First, automatic login is unavailable while FileVault is on, and without automatic login the Mac sits at the login window after a reboot with nothing in your user session running. The trade-off: encryption or unattended restarts. One partial fix exists if your macOS supports it: `sudo fdesetup authrestart` reboots once without stopping at the FileVault unlock screen, which covers planned restarts but not a power cut. Second, OpenClaw itself: install the gateway as a LaunchAgent so it survives reboots independent of login items ([OpenClaw install docs](https://docs.openclaw.ai/install/)):

```bash
openclaw onboard --install-daemon   # or: openclaw gateway install
openclaw gateway status
```

For remote access off your LAN, the sane options are Tailscale, Headscale, or Netbird; the trade-offs are in [this comparison](/netbird-vs-headscale-vs-tailscale/). Then harden the gateway before you expose anything: auth is on by default, and the [OpenClaw security guide](/openclaw-security-guide/) covers the rest.

### The UPS question

An agent box that reboots dirty after every blip eventually corrupts something you care about. For the Mac mini plus router and modem, the right size is the [CyberPower CP850PFCLCD](/go/cyberpower-cp850pfclcd/) at $169.95: 850VA/510W of pure sine wave output, which matters because modern PSUs with active PFC can shut down on the stepped "simulated sine" cheap UPSes output. It gives you roughly 30 minutes at a ~100W load and far longer at the Mac's actual 4-15W draw. The full reasoning, including the pure-sine rule and runtime math, is in the [best UPS for home servers](/best-ups-for-home-server/) guide.

If you only want the router and modem on battery (so your WAN stays up through short cuts), the cheap option is the [APC Back-UPS BE425M](/go/apc-be425m/) at $62.50, 4.5★ from 11,415 ratings. Keep the Mac on the CyberPower.
