### Check live prices and stock yourself

Do not budget off a screenshot. Here is a 60-second check you can run before every order:

<ListCheck>
- Open the Hetzner Cloud Console, go to your project, Servers, and try to create a Cost-Optimized server. A disabled Create button means unorderable right now
- Run the API snippet below to confirm current prices per location
- Write down the date and time of the check next to the price in your budget notes
</ListCheck>

```bash
# Read-only token is enough. Create one in your Hetzner Cloud project:
# Project -> Security -> API Tokens -> Generate API Token (Read)

export HCLOUD_TOKEN="your-project-token"

# Price for cx23 per location and per billing type
curl -s -H "Authorization: Bearer $HCLOUD_TOKEN" \
  "https://api.hetzner.cloud/v1/server_types?name=cx23" | jq '.server_types[0].prices[]'

# Same thing with the hcloud CLI
hcloud server-type describe cx23 -o json | jq '.prices[]'

# What types exist at all
hcloud server-type list -o table
```

Verify: the curl call returns a JSON list of price objects with `location` and `price_monthly` fields. Expected output includes `gross`/`net` values around €5.49 net for cx23 in EU locations.

Failure modes: a 401 means the token is missing or wrong (`HCLOUD_TOKEN` not exported). `jq: command not found` means you need `apt install jq` or equivalent. And the big one: **the API returning a price does not mean the plan is orderable**. Orderability is only confirmed by an enabled Create button in the Console. That mismatch has been the normal state for CX/CAX since late June 2026.

## Why Hetzner raised prices twice in 2026

The April wave has an official explanation. On February 23, 2026, Hetzner's PR manager Christian Fitz published a statement saying the cost to operate its infrastructure and to buy new hardware had "increased dramatically", and confirmed the April 1 adjustment would apply to both new orders and existing products. The statement does not name DRAM or any specific component. The June 15 wave was documented only on the Hetzner docs price-adjustment page (ID GE-D9256), cloud servers only, with no separate press release.

Background, not from Hetzner: reporting from cloudtally.eu (published March 2, 2026, reviewed April 18, 2026) ties the increases to DRAM contract prices surging on AI and HBM demand, with TrendForce forecasting a 90-95% quarter-over-quarter increase for Q1 2026 and wafer capacity reallocated away from conventional DRAM. The same reporting notes OVHcloud raised only 5-10% for April through September 2026, which makes Hetzner's 30%+ look less like an industry tax and more like a specific catch-up on memory-exposed hardware.

<Notice type="info" title="Treat current prices as the baseline">
    Memory prices are not expected to normalize before 2028 on current forecasts. Do not budget assuming a rollback, and do not delay a migration waiting for prices to come back down. If anything, assume one more adjustment is possible.
</Notice>

## Grandfathering rules: who keeps the old price

The effective-date rules from the June 15 documentation, in operator terms:

<ListCheck>
- Servers ordered before June 15, 2026, 08:00 CEST keep their previous price. That includes orders placed before the deadline but delivered after it
- Any rescale on or after June 15 moves the server to the current price list. Up or down. There is no "downgrade to save money" path that preserves old pricing
- The docs carry this warning verbatim: "certain changes to servers with legacy pricing may trigger a switch to the current pricing." Rebuilds, certain migrations, and support-side changes can forfeit the old price
- Servers ordered after June 15 pay the new list, including anything you order today
</ListCheck>

<Notice type="warning" title="Rescaling reprices your server">
    If you hold a pre-June-15 server at old prices, that server is an asset. Do not casually rescale it "just in case." The dangerous failure mode is a legacy-priced box you rescale at 2 a.m. during an incident and only notice on the next bill. Model the new list price first, then decide.
</Notice>

### Rescaling and migrating between plans

If you are moving anyway (new workload, or the old server is already on current pricing), the operator flow is the same as before, with two new checks:

<ListCheck>
- Assess 30 days of CPU, RAM, disk, and traffic usage first. Metrics beat vibes. If you do not have monitoring, that is the real task, not the rescale
- Choose the plan line: under 50% average CPU suits Cost-Optimized when it is orderable; 50-80% wants CPX; over 80% wants CPX or CCX with dedicated vCPUs
- Create the new server and test it under realistic load before cutting over DNS or traffic
- If you only wanted a smaller bill: stop. Rescaling down on/after June 15, 2026 gives you the new, higher list price on the smaller plan. Run the numbers before touching anything
- If you want to preserve an old price: leave the server alone
</ListCheck>

The classic "I rescaled down and my bill went up" failure is now the default behavior, not an edge case. Migrating down in specs does not migrate down in price list.

## The plan structure explained (CX Gen3, CAX, CPX Gen2, CCX)

Hetzner organizes cloud servers by generation and performance class instead of by hardware type. Three lines, and where you can get them:

<Accordion label="Shared: Cloud Regular Performance (CPX Gen2)" group="plans">

CPX Gen2 runs on the latest AMD hardware at each location (AMD EPYC-Genoa as of 2025). Consistent performance, larger disks than the cost-optimized line.

Use these for: production workloads that need consistent performance, databases, anything that is now blocked from the CX line.

Current prices: see the CPX table above. CPX22 starts at €19.49/month excl. IPv4 in EU.

</Accordion>

<Accordion label="Shared: Cloud Cost-Optimized (CX Gen3 / CAX)" group="plans">

CX Gen3 runs on older x86 hardware (Intel or AMD, you cannot pick). CAX runs on Ampere ARM. Half the disk of the equivalent CPX, same RAM.

Use these for: development, testing, staging, side projects, small WordPress sites, CI runners, monitoring stacks. When you can order them.

Current prices: see the CX/CAX tables above. CX23 is €5.49/month excl. IPv4 in EU, and unorderable as of October 2026.

</Accordion>

<Accordion label="Dedicated: Cloud General Purpose (CCX Gen)" group="plans">

CCX gives you dedicated vCPUs on current hardware. No noisy-neighbor CPU contention.

Use these for: high-traffic applications, production databases, anything with latency requirements or an SLA.

Current prices: see the CCX table above. CCX13 starts at €42.99/month in EU. The 16 vCPU and up sizes are serious monthly spend now.

</Accordion>

## Is Hetzner still worth it in 2026?

Short answer: yes when you can get a cost-optimized server, no longer obviously yes when you cannot. The old "4x cheaper" line from this article's earlier days is dead. Like-for-like against DigitalOcean, a CX23 at €5.99 including IPv4 is about 3.6x cheaper than a $24/month 2 vCPU/4GB droplet. When the only orderable Hetzner option is a CPX22 at €19.99, that gap is gone.

## Backups, storage costs and hardening

Everything around the server got more expensive in April 2026 and stayed there. Volumes are €0.0572/GB/month, snapshots are €0.0143/GB/month, Object Storage is €6.49 base plus €0.0087/GB. Backups are priced as a percentage of server price (about 20% at last check, confirm on the current docs page before you quote it), which means backup cost rose in lockstep with the June server increases.

<Notice type="info" title="Backup cost scales with server price">
    On a CPX22 at €19.49/month, a 20% backup add-on is about €3.90/month. On the old €7.99 CPX22 it was about €1.60. Same percentage, more than double the money. For small boxes, an offsite rsync or restic job to S3-compatible storage can be cheaper than the built-in snapshot percentage. For anything with data you care about, pay for backups either way.
</Notice>

<ListCheck>
- Monitor resources actively. Set alerts for CPU, RAM, disk, and traffic. Cheap servers die from silent disk fill, not from CPU
- Implement caching. Redis or Memcached in front of a database removes more load than a plan upgrade
- Optimize databases. Indexing and query plans before you buy vCPUs
- Use a CDN. Offload static assets so the VPS serves dynamic traffic only. [Bunny.net CDN](https://go.bitdoze.com/bunny) is a cheap, fast option I run for this
- Schedule intensive tasks. Backups, rebuilds, and batch jobs off-peak
- Right-size. Start small, grow when metrics say so. Right-sizing is easier when hourly billing is an option
- Use hourly billing for experiments. Spin up, measure, tear down
- Enable backups on anything with real data. The 20% is worth it, and price it at the new server rate
- Protect the box. Now that you pay more per server, lock it down: UFW or Hetzner Cloud Firewall with least privilege, unattended-upgrades, non-root users for app workloads, SSH keys only. ## Frequently asked questions

<Accordion label="Is Hetzner CX23 available?" group="faq">

No, not for new orders as of the September and October 2026 checks. All eight CX/CAX plans show a disabled Create button, with a capacity notice running since about June 26, 2026. Existing CX23 servers keep running at their current prices. Hetzner frames this as limited stock on older hardware kept in service, not a discontinuation. Check the Console on the day, and date-stamp whatever you find.

</Accordion>

<Accordion label="Can I rescale from CPX to CX, or downgrade?" group="faq">

Hetzner supports rescaling between shared plans in the Console, though exactly which paths are offered depends on location and architecture, so verify in the rescale dialog before assuming it. The critical fact is pricing: any rescale on or after June 15, 2026 moves the server to the current price list, whether you scale up or down. The old "you cannot downgrade from Regular to Cost-Optimized without creating a new server" answer is out of date; the new trap is that a downgrade no longer downgrades your bill.

</Accordion>

<Accordion label="Which locations offer Cost-Optimized plans?" group="faq">

EU only: Nuremberg (Germany), Falkenstein (Germany), Helsinki (Finland). CX and CAX have never existed in the US or Singapore. Singapore runs CPX Gen2 and CCX. The US locations (Ashburn, Hillsboro) run CPX Gen1 and CCX, and those were repriced in both 2026 waves as well. Earlier versions of this article listed Singapore for cost-optimized plans. That was incorrect.

</Accordion>

<Accordion label="Is Hetzner still cheaper than DigitalOcean, Vultr and Linode?" group="faq">

When CX/CAX are orderable, yes by a wide margin: about 3.6x cheaper than a $24 DigitalOcean droplet for the same 2 vCPU/4GB class, plus 20TB of included traffic. When only CPX is orderable, the gap closes to roughly parity, and the US clouds' steady 2026 pricing starts to look reasonable. Competitor prices in this article are a September 2026 snapshot; verify before you commit.

</Accordion>

<Accordion label="ARM or x86 for Docker containers?" group="faq">

If your images are multi-arch, CAX runs containers fine and the Ampere cores are quick. But it is no longer a money saver: at June 2026 prices CAX costs 9-39% more than the same-spec CX. Check the image tags on Docker Hub first. Plenty of commercial and legacy images are still x86-only. When in doubt, CX is the boring default.

</Accordion>

<Accordion label="Does my old CX Gen2 or CPX Gen1 server keep its price?" group="faq">

Yes, if you leave it alone. Servers ordered before June 15, 2026, 08:00 CEST keep their previous price, and older plan types from before the 2025 restructure keep running even though they are unorderable since January 1, 2026. The warning is the fine print: "certain changes to servers with legacy pricing may trigger a switch to the current pricing." Do not rescale or rebuild a grandfathered box unless you have priced the new list first.

</Accordion>
