## Why your VPS needs an SMTP relay

VPS providers block outbound port 25 by default. That's a spam-prevention measure and you usually can't get it removed. Even when port 25 is open, direct-to-MX mail from a bare VPS IP lands in spam: no sending reputation, no rDNS/PTR matching your domain, and the IP may already be on blocklists.

The relay model is straightforward. Your apps send to local Postfix. Postfix forwards everything through an authenticated, encrypted connection (port 587) to the mail provider. The provider handles delivery, reputation, and DKIM signing.

```
WordPress / cron / system mail
        │
        ▼
Postfix on your VPS  ──✗ direct (port 25 blocked)
        │
        │  relayhost [smtp.zeptomail.com]:587 (TLS + auth)
        ▼
Recipient inbox
```

What a relay fixes:

<ListCheck>
<ul>
<li>Port 25 blocks: mail routes through 587 instead</li>
<li>Spam-folder delivery: provider reputation and DKIM signing</li>
<li>Per-app SMTP config: one Postfix setup covers every app on the server</li>
<li>Credential rotation: one place to update passwords</li>
</ul>
</ListCheck>

## Step 1: Configure ZeptoMail (Zoho CPaaS)

<Button text="Create a free Zoho CPaaS account" link="https://cpaas.zoho.com/" variant="solid" color="blue" size="md" />

Sign up, complete the customer validation form (see the warning above), then add your domain and associate it with an Agent. Once verified, open the Agent's SMTP/API tab to get your credentials. You'll need these in Step 4.

### Add the DKIM and CNAME DNS records

After adding your domain, Zoho shows you DKIM record(s) and a CNAME record (the CNAME is a return-path/bounce alias). Publish both record types in your DNS and click Verify.

<Notice type="info" title="SPF is no longer required">
SPF verification was removed in June 2024. The return-path CNAME covers alignment. Only DKIM and CNAME records are needed.
</Notice>

Propagation can take up to 48 hours. Zoho rechecks automatically and emails you when the domain is verified. You can confirm the records are live before clicking Verify:

```bash
dig TXT selector._domainkey.yourdomain.com +short
dig CNAME mail.yourdomain.com +short
```

The output should match what the dashboard shows. Common DNS pitfalls: records not yet propagated (wait, don't re-add them), records in the wrong zone (subdomain vs apex), or Cloudflare proxying the CNAME (set these records to "DNS only" in Cloudflare).

### Get your SMTP credentials

| Setting | Value |
|---------|-------|
| Server | `smtp.zeptomail.com` |
| Ports | 465 (SSL) or 587 (TLS) |
| Username | `emailapikey` |
| Password | From dashboard → Agent → SMTP/API |
| TLS | TLS v1.2 supported |
| Max message | 15 MB |

A few notes: the username is literally `emailapikey`, not your Zoho login. If your app chokes on long passwords, the dashboard has an option to generate a shorter (weaker) one. Some apps prefer using the From address as the username; Zoho supports that fallback. And if your dashboard shows a region-specific endpoint (`smtp.zeptomail.eu` or similar), use exactly what your dashboard shows.

## Step 2: Install Postfix on Ubuntu

Many provider images ship Postfix preinstalled, so check first:

```bash
dpkg -l postfix
```

If it's not there (or you want a clean install):

```bash
sudo apt update
sudo apt install -y mailutils
```

Choose **Internet Site** during the debconf dialog and enter your domain (e.g., `yourdomain.com`). If you answered wrong, re-run `sudo dpkg-reconfigure postfix`.

On [Hetzner Cloud](https://go.bitdoze.com/hetzner) servers, Postfix is often preinstalled, but it depends on the base image. If you want to [compare Hetzner, Vultr, and DigitalOcean VPS plans](/digitalocean-vs-vultr-vs-hetzner/) before choosing a server, provider images differ in what ships out of the box.

Verify the install:

```bash
postfix --version
```

## Step 3: Configure Postfix as an SMTP relay

If you've used Postfix with external SMTP servers before, the shape is familiar. Here's the [general recipe for external SMTP relay](/postfix-external-smtp/) if you want the broader context.

Edit `/etc/postfix/main.cf`:

```bash
sudo nano /etc/postfix/main.cf
```

Add (or replace any existing `relayhost` block) at the end:

```
# Zoho CPaaS (formerly ZeptoMail) SMTP relay
relayhost = [smtp.zeptomail.com]:587
smtp_sasl_auth_enable = yes
smtp_sasl_password_maps = hash:/etc/postfix/sasl_passwd
smtp_sasl_security_options = noanonymous
smtp_tls_security_level = encrypt
smtp_tls_note_starttls_offer = yes
header_size_limit = 4096000
sender_canonical_classes = envelope_sender, header_sender
sender_canonical_maps = regexp:/etc/postfix/sender_canonical
smtp_header_checks = regexp:/etc/postfix/smtp_header_checks
```

Why `encrypt` instead of `may`: opportunistic TLS (`may`) allows a plaintext fallback. ZeptoMail requires STARTTLS (error 530 without it) and speaks TLS 1.2, so enforce encryption. `smtp_tls_note_starttls_offer = yes` is optional but helps when debugging TLS negotiation.

Postfix's default `message_size_limit` is 10 MB, safely under ZeptoMail's 15 MB ceiling, so defaults are fine.

Watch for a stale `relayhost` line from a previous relay setup. Replace it, don't stack lines.

## Step 4: Store the SMTP credentials in sasl_passwd

Create `/etc/postfix/sasl_passwd`:

```bash
sudo nano /etc/postfix/sasl_passwd
```

Add your ZeptoMail credentials. The username is `emailapikey`, not your Zoho login:

```
[smtp.zeptomail.com]:587 emailapikey:YOUR_SMTP_PASSWORD
```

Generate the hash database and lock down the file:

```bash
sudo postmap /etc/postfix/sasl_passwd
sudo chown root:root /etc/postfix/sasl_passwd /etc/postfix/sasl_passwd.db
sudo chmod 0600 /etc/postfix/sasl_passwd /etc/postfix/sasl_passwd.db
```

<Notice type="warning" title="Credential file security">
Your SMTP password lives in plain text in this file. The 0600 root-only permissions are mandatory. After every edit, re-run `sudo postmap`, or a stale `.db` file means auth failures that look like bad credentials.
</Notice>

Failure modes here: password pasted with a trailing newline or quotes (causes 535), special characters in the password (use the dashboard's shorter-password option if needed), editing `sasl_passwd` but forgetting `sudo postmap` and `sudo postfix reload`.

## Step 5: Rewrite the sender address

Without this, ZeptoMail rejects emails from WordPress or other apps because the "From" domain doesn't match your verified domain. The official error: `553 Relaying disallowed as <address>`, meaning you're sending from an unverified 'from' domain. Since April 2024, unverified sender addresses can't send at all, so the rewrite must target an address on your **verified domain**.

Create `/etc/postfix/sender_canonical`:

```
/.+/ noreply@yourdomain.com
```

Create `/etc/postfix/smtp_header_checks`:

```
/From:.*/ REPLACE From: noreply@yourdomain.com
```

Or with a display name:

```
/From:.*/ REPLACE From: Your Name <noreply@yourdomain.com>
```

Use an email address on the domain you verified in Zoho CPaaS. The `sender_canonical_classes` line in Step 3 covers both the envelope sender and the header sender. Both get rewritten.

Watch for: rewriting to an address on an unverified domain (still 553), display-name commas or quoting in the REPLACE line, and forgetting that `sender_canonical_classes` must list both `envelope_sender` and `header_sender`.

If you'd rather fix this per-app in WordPress instead of at the server level, the FluentSMTP route linked in the intro handles it without touching Postfix.

## Step 6: Check /etc/mailname

If your VPS hostname is a subdomain (e.g., `cloud.yourdomain.com`), Postfix may try to use that as the sending domain. Fix it:

```bash
sudo nano /etc/mailname
```

Set it to just the root domain:

```
yourdomain.com
```

## Step 7: Validate and reload Postfix

Run `postfix check` before reloading: it catches syntax errors without touching live mail:

```bash
sudo postfix check
sudo postfix reload
```

`postfix check` prints nothing when the config is clean. If it warns about something, fix it before reloading.

Check the queue:

```bash
postqueue -p
```

The queue should be empty or flushing. Permission errors on map files usually mean the `chown`/`chmod` steps from Step 4 didn't run.

## Step 8: Test the SMTP relay

Send a test message:

```bash
echo "test message" | mail -s "test subject" you@example.com
```

Watch the logs to confirm delivery.

<Tabs>
<Tab name="/var/log/mail.log">
On Ubuntu 22.04 and most provider images:

```bash
tail -f /var/log/mail.log
```

A successful send looks like:

```
postfix/smtp: status=sent (250 Message received)
```
</Tab>
<Tab name="journalctl (24.04+)">
On Ubuntu 24.04+ where mail.log may be journald-only:

```bash
journalctl -u postfix -f
```

Same expected output: `status=sent (250 Message received)`.
</Tab>
</Tabs>

After the test succeeds, confirm three things: the message arrived (not just queued), the From header shows your rewritten address (check the received message headers), and the Zoho dashboard logs show the delivery record (60-day retention).

If `mail` returns "command not found," mailutils didn't install. Back to Step 2. If mail is stuck, run `postqueue -p` and read the error line in the log.

Once this works, every app on the server routes through ZeptoMail automatically: WordPress, cron job notifications, system mail. That includes the alerts in our [Linux CPU monitoring and email alerts guide](/monitor-cpu-usage-and-send-email-alerts-in-linux/).

## Troubleshooting: ZeptoMail SMTP error codes

| Code | Message | Cause |
|------|---------|-------|
| 530 | Must issue a STARTTLS command first | Connecting without TLS (port 587 without STARTTLS, or plain port 25) |
| 535 | Authentication Failed | Invalid key/username, expired credits, blocked credits, or blocked account |
| 553 | Relaying disallowed as `<addr>` | Sending from an unverified 'from' domain |
| 552 | 5.7.1 virus detected | Antivirus hit in the message |
| n/a | 5.2.1 Subject is Mandatory | Empty subject line |
| n/a | 5.2.0 Email size exceeded the policy | Over the 15 MB size limit |

### 535 authentication failed

This is the one that silently kills mail at 3am. The username must be `emailapikey` (not your Zoho login). Check the credential line in `/etc/postfix/sasl_passwd` for trailing newlines or quotes. Run `sudo postmap /etc/postfix/sasl_passwd` after any edit.

But the sneakier cause: **expired credits or a blocked account**. Mail just stops. Check your credit status and account status in the dashboard. If the password has special characters, try the dashboard's shorter-password option.

<Notice type="error" title="Credits expire silently">
Mail dies quietly when credits run out or expire. Enable credit-expiry notifications in the dashboard and consider auto top-up (see below). This is the 3am failure mode nobody plans for.
</Notice>

### 553 relaying disallowed

Sending from an unverified 'from' domain, exactly what Step 5 prevents. Make sure the rewrite in `/etc/postfix/sender_canonical` points to an address on your verified domain. Re-check domain status in the dashboard. If the domain verification is still pending, wait for Zoho's confirmation email.

### 530 must issue a STARTTLS command first

You're connecting without encryption: port 587 without TLS, or plain port 25. The fix is `smtp_tls_security_level = encrypt` in Step 3, and using port 587 with TLS (or 465 with SSL). This is why the config in this guide uses `encrypt` instead of `may`.

### Mail stuck in the queue

Run `postqueue -p` to see what's queued, then `postqueue -f` to flush. Read the deferred-cause line in the log. It maps back to one of the error codes above.

## Keep it running: costs, limits, and hardening

### How billing works

1 email credit = 10,000 emails. The first credit is free. Credits are valid for 6 months from purchase.

<Notice type="info" title="Billing is per recipient, not per message">
An email with 1 To and 3 CC counts as 4 against your credit. If you send contact-form notifications with CCs, you'll burn credits 2-4x faster than the "10k sends" mental model suggests. At 1 recipient per mail you get 10,000 sends per credit.
</Notice>

Auto top-up exists and is worth enabling: it triggers at a minimum-credit threshold (max 2 credits per top-up by default). For a relay, this is the difference between mail flowing and 535 errors at 3am. Dedicated IPs are available for high-volume senders; they are not needed at typical VPS/WordPress volumes.

Check current credit pricing in your dashboard or at [zoho.com/cpaas/pricing.html](https://www.zoho.com/cpaas/pricing.html). Prices are per-credit and vary by region. For context, credit costs are pennies next to [VPS price increases](/vps-price-increases/) over the past couple of years.

### Hardening and limits

### Rollback: remove the relay

If you need to back out, comment out the relay, SASL, TLS, and sender-rewrite lines you added in `/etc/postfix/main.cf`:

```
# relayhost = [smtp.zeptomail.com]:587
# smtp_sasl_auth_enable = yes
# smtp_sasl_password_maps = hash:/etc/postfix/sasl_passwd
# smtp_sasl_security_options = noanonymous
# smtp_tls_security_level = encrypt
# smtp_tls_note_starttls_offer = yes
# sender_canonical_classes = envelope_sender, header_sender
# sender_canonical_maps = regexp:/etc/postfix/sender_canonical
# smtp_header_checks = regexp:/etc/postfix/smtp_header_checks
```

Then:

```bash
sudo postfix check && sudo postfix reload
```

Mail will attempt direct delivery again, but port 25 may still be blocked by your provider, so expect mail to queue up if you don't have another relay configured.

## Alternatives to ZeptoMail

ZeptoMail works well for me, but there are other options depending on your volume and budget:

- **Amazon SES** costs ~$0.10 per 1,000 emails. Cheapest at scale, but you manage reputation and setup yourself. Good if you're already on AWS.
- **Postmark** runs ~$15/month for 10,000 emails. Known for fast delivery and strong deliverability. More expensive but hands-off.
- **Resend** has a free tier, with paid plans around ~$20/month for more volume. Modern API, popular with developers. Relatively new.
- **Brevo (formerly Sendinblue)** starts at ~$9/month. It combines transactional and marketing email if you need both.

For a small VPS running a few WordPress sites, ZeptoMail's pay-as-you-go model is hard to beat on price. If you send more than 50,000 emails/month, Amazon SES is usually the cheaper option.

Two more paths worth knowing: [Mail.Baby cheap SMTP service review](/mail-baby-review/) covers a direct competitor for the same job, and [Cloudflare Email Sending for static sites](/emdash-send-email/) is a lightweight alternative if you don't need a full relay. Zoho also publishes its own comparison pages (Postmark, SES, SendGrid, SparkPost) if you want to see their side-by-side. And if you're migrating from Resend, ZeptoMail has a one-click migration tool (domains, templates, webhooks) as of July 2026.

<Accordion label="Is ZeptoMail free? What does 10,000 emails mean?" group="faq">

<Accordion label="Can I send newsletters or marketing email through this relay?" group="faq">

</Accordion>

<Accordion label="Do I need to add an SPF record?" group="faq">
No. SPF verification was removed in June 2024. Domain verification uses DKIM records and a CNAME (return-path alias) only. The return-path CNAME handles what SPF used to cover.
</Accordion>

<Accordion label="Do I need a dedicated IP?" group="faq">
Not at typical VPS or WordPress volumes. A dedicated IP only matters when you're sending sustained high volume and need to control your own sending reputation. For most setups, the shared IP pool works fine.
</Accordion>

<Accordion label="My test mail works but WordPress mail doesn't. Why?" group="faq">
