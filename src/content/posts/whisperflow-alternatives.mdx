WhisperFlow is a voice keyboard. You talk, it types into whichever app has focus, on a phone or a desktop. The app does that job, but it is proprietary, sold by subscription, and it has no API, so you cannot script it or feed it a folder of recordings.

If you are shopping for WhisperFlow alternatives for that reason, two hosted speech-to-text APIs now cover it: AssemblyAI and Fish Audio. I built six audio files, sent each one to both, and scored every transcript with a word error rate script. The whole test cost under 10 cents of credit on each account.

AssemblyAI won on the things I care about. It returned no mistakes on the DevOps jargon file, labelled five real speakers correctly, and charges $0.21 an hour. Fish Audio answered in about a second instead of seven, includes speaker labels in the price, and adds cues like `[applause]` to the text. On plain speech from real people both were word perfect.

## Which WhisperFlow do you mean?

Four products share the name, and search engines mix them up. This article is about the first one.

| Name | Where | What it is |
|---|---|---|
| Whisper Flow | [whisperflow.org](https://whisperflow.org/) | Voice keyboard for iPhone, iPad, Android, macOS and Windows, published by Butterfly AI LLC |
| Wispr Flow | [wisprflow.ai](https://wisprflow.ai/) | The app many people mean when they type "Whisper Flow". Pro costs $15 per user a month, or $12 billed yearly |
| Whisper One | [whisperflow.app](https://whisperflow.app/) | Mac-only dictation on the Fn key. 8,000 free characters a month, transcription in the cloud |
| WhisperFlow | [GitHub](https://github.com/namandhakad712/whisperflow) | Open-source local dictation on whisper.cpp. Apache-2.0, Windows only for now |

The confusion goes deeper than spelling. [APKPure](https://apkpure.com/whisper-flow-ai-voice-keyboard/com.whisperflow.app) lists an Android build from the same publisher called "Wisper Flow: AI Voice Keyboard", one letter away from the competitor's name.

If you came here for the open-source project, the rest of this article does not apply. It already runs on your own machine, which neither API does.

## What you give up with WhisperFlow

These are facts from the official site and the store listings, checked on November 23, 2026. I did not install the app.

- The annual plan costs $144 and the monthly plan $12, so paying for a year up front saves nothing.
- The free plan runs out fast: 1,000 words a week and 30 seconds per recording on Android, 2,000 words a week on iOS.
- Prices differ by store. The site quotes $12 a month, while the [App Store listing](https://apps.apple.com/app/id6762070326) shows in-app purchases from $5.99 to $69.99 under the names LifeTalk and Talk-AI.
- Windows is a direct `.exe` download, and the download link on the site says "Please disable the firewall when install".
- The [Android listing](https://play.google.com/store/apps/details?id=com.linguaflow.app) shows ads and averages 3.3 stars from 536 reviews. Recent reviews mention the app switching languages on its own, and asking for payment again on a second device.
- There is no API and no CLI. The documentation on the site is a FAQ, a privacy policy, the terms, and a page on deleting your account.

None of that matters if you dictate a few messages a day. WhisperFlow is still the better pick when:

- You type by voice on a phone. Neither API is a keyboard.
- You want zero setup and no code.
- You need the on-device mode for offline use or privacy. Both APIs are cloud only.
- You dictate for hours every day. A flat $144 a year beats $0.62 an hour once you pass about 38 minutes of speech a day.

## How I tested

I built six files, two of them from real recordings, and sent each to both APIs with default settings.

| File | Length | Contents |
|---|---|---|
| `dictation-clean.wav` | 56 s | A synthetic voice reading an incident update with DevOps jargon, two filler words and a self-correction |
| `dictation-noisy.wav` | 56 s | The same audio with pink noise mixed in 10 dB below the speech |
| `dialogue.wav` | 32 s | Two synthetic voices, six alternating turns |
| `librispeech.wav` | 52 s | Five clips from five real speakers in the [LibriSpeech](https://www.openslr.org/12) validation set |
| `spanish.wav` | 19 s | One Spanish voice, to check language detection |
| `jfk.wav` | 11 s | The 1961 inauguration clip from the [Whisper repository](https://github.com/openai/whisper/blob/main/tests/jfk.flac) |

On the AssemblyAI side I used the pre-recorded API with `speech_models` set to `assemblyai-stt-3-7`, `speaker_labels` on for the two multi-speaker files, and `language_detection` on for the Spanish one. On the Fish Audio side I called `POST /v1/asr` with the `model: transcribe-1-pro` header and the default fields, plus `ignore_timestamps=false` for the dialogue.

Scoring: I lowercased each transcript, stripped punctuation, and ignored formatting-only differences such as `4` for `four` or `OK` for `Okay`. Fillers and the false start count as spoken words, so keeping them is correct and dropping them is an error.

Three synthetic voices came from [edge-tts](/uv-text-to-speech-script/), which is why I added the LibriSpeech clips and the 1961 recording. Synthetic speech is easier to transcribe than a person on a laptop mic. I ran every file twice. Treat the table as a direction, not a benchmark.

This is the command that produced the jargon file, with the script saved in `script.txt`:

```bash
uvx edge-tts --voice en-US-AndrewNeural \
  --file script.txt --write-media dictation.mp3
ffmpeg -i dictation.mp3 -ar 16000 -ac 1 dictation.wav
```

## Accuracy

Errors per file, out of the words spoken:

| File | Words | AssemblyAI | Fish Audio |
|---|---|---|---|
| DevOps dictation, clean | 140 | 0 | 5 |
| DevOps dictation, noisy | 140 | 0 | 7 |
| Two-voice dialogue | 85 | 0 | 0 |
| Five real speakers | 146 | 0 | 0 |
| Spanish clip | 60 | 1 | 1 |
| JFK clip | 22 | 0 | 0 |
| **Total** | **593** | **1** | **13** |

The only AssemblyAI error in the whole run was one letter: it heard `correo` where the speaker said `correos`. Fish Audio made the same mistake. Every other Fish Audio error sits in the jargon file:

| What was said | AssemblyAI | Fish Audio |
|---|---|---|
| `kubectl`, spoken "kube control" | kubectl | Kube control |
| `nginx`, spoken "engine X" | NGINX | nginx on the clean file, engine X on the noisy one |
| `/var/log/syslog` | /var/log/syslog | var log sys log |
| "PagerDuty paged" | paged | page |

This is the difference that matters for DevOps work. Say "engine X" or "kube control" and AssemblyAI writes the product name. Fish Audio writes what it hears. The noise changed nothing on either side, so 10 dB of background hiss was not the problem.

Two smaller things I noticed:

- Fish Audio gave me different jargon on two identical requests. The first clean run came back as `engine X` and `Kuba control`, the second as `nginx` and `Kube control`. AssemblyAI's text changed only in punctuation.
- On the 1961 clip Fish Audio added `[echo]`, `[applause]` and `[crowd cheering]` to the text. That is on by default, and `tag_audio_events=false` turns it off. AssemblyAI returned plain words.

## Fillers and self-corrections

Both APIs transcribe verbatim by default. The "um", the "uh" and the "restart the, no wait" all landed in the text. That is right for a transcript and wrong for a draft you want to paste.

AssemblyAI sells a fix for that. The Dictation API returns the verbatim `text` and a cleaned `llm_response` in one call, and it handled my file the way I wanted: fillers gone, the false start collapsed to "First, I tried to reload the NGINX pods.", jargon kept. It took 0.9 to 1.6 seconds for the 56 second clip. The price is $0.62 an hour, about three times the plain API.

Fish Audio documents no equivalent. Its request fields cover timestamps, speaker counts, language hints and audio event tags, and nothing for cleanup, so you would add your own LLM step.

## Speaker labels

Both APIs split the two-voice dialogue into six correct turns. AssemblyAI returns an `utterances` array with a letter per speaker and times in milliseconds. Fish Audio puts inline markers like `<|speaker:0|>` in the text and, when you ask for timestamps, a `speaker_turns` array in seconds. Send `diarize=false` if you want the markers gone.

The real speakers separated the two. AssemblyAI labelled the five LibriSpeech readers A to E, one per clip. Fish Audio returned four labels and gave two different readers the same one.

## Speed

Wall clock for one request, from the start of the upload to the final text:

| File | AssemblyAI | Fish Audio |
|---|---|---|
| DevOps dictation (56 s) | 7.7 s | 1.2 s |
| Dialogue (32 s) | 6.3 s | 1.1 s |
| Five real speakers (52 s) | 7.5 s | 1.1 s |
| Spanish (19 s) | 6.1 s | 0.6 s |
| JFK (11 s) | 4.7 s | 0.4 s |

Fish Audio is synchronous: the request returns when the transcript is ready. AssemblyAI is a job queue: upload, submit, poll. Uploading took about 1.6 seconds of each run and the job itself about 5, so the gap is overhead, and it barely shrinks on short clips (4.7 seconds for an 11 second file).

The seven second wait would annoy me on a hotkey, and I would never notice it in a nightly batch. If a person is waiting on the text, use the Dictation API (under 2 seconds on the same clip) or a streaming model. For batch work the queue is the feature: up to 200 jobs run in parallel on a paid account, and a webhook can deliver each result.

## Transcribe a file with AssemblyAI

You need a key from [AssemblyAI](https://go.bitdoze.com/assemblyai), plus `curl` and `jq`. The flow is upload, submit, poll:

```bash
export ASSEMBLYAI_API_KEY=your_key

# 1. Upload the file and get a temporary URL
upload_url=$(curl -s -X POST https://api.assemblyai.com/v2/upload \
  -H "authorization: $ASSEMBLYAI_API_KEY" \
  --data-binary @dialogue.wav | jq -r .upload_url)

# 2. Start the job
id=$(curl -s -X POST https://api.assemblyai.com/v2/transcript \
  -H "authorization: $ASSEMBLYAI_API_KEY" \
  -H "content-type: application/json" \
  -d "{\"audio_url\": \"$upload_url\",
       \"speech_models\": [\"assemblyai-stt-3-7\"],
       \"speaker_labels\": true}" \
  | jq -r .id)

# 3. Poll until it finishes
while :; do
  result=$(curl -s https://api.assemblyai.com/v2/transcript/$id \
    -H "authorization: $ASSEMBLYAI_API_KEY")
  status=$(echo "$result" | jq -r .status)
  [ "$status" = "completed" ] && break
  [ "$status" = "error" ] && { echo "$result" | jq -r .error; break; }
  sleep 1
done

# 4. Print one line per speaker turn
echo "$result" | jq -r '.utterances[] | "Speaker \(.speaker): \(.text)"'
```

The header is `authorization` with the raw key and no `Bearer`. Upload with `--data-binary @file`; `-d` sends the file path as text and the job fails later with a transcoding error. Delete the transcript afterwards with `curl -X DELETE` on the transcript URL if you do not want it stored.

For dictation with cleanup, one request to the Dictation API replaces all four steps (it takes recordings up to 20 minutes):

```bash
curl -s -X POST https://dictation.assemblyai.com/v1/transcribe \
  -H "Authorization: $ASSEMBLYAI_API_KEY" \
  -F "audio=@dictation.wav;type=audio/wav" \
  | jq -r '"Verbatim: \(.text)", "Cleaned:  \(.llm_response)"'
```

## Transcribe a file with Fish Audio

One request to [Fish Audio](https://go.bitdoze.com/fish-audio), one response:

```bash
export FISH_API_KEY=your_key

curl -s -X POST https://api.fish.audio/v1/asr \
  -H "Authorization: Bearer $FISH_API_KEY" \
  -H "model: transcribe-1-pro" \
  -F "audio=@dialogue.wav" \
  -F "ignore_timestamps=false" \
  | jq -r '.speaker_turns[] | "\(.speaker): \(.text)"'
```

Drop the two form fields for plain text with inline markers. Add `-F "diarize=false"` to get text with no markers at all.

Limits from the docs: 60 minutes per request, and WAV, MP3, AAC, FLAC, Ogg, WebM and MOV accepted. Set your HTTP timeout high (the docs suggest 900 seconds), because nothing comes back until the whole file is transcribed. Accounts with less than $100 prepaid get 5 concurrent requests, and each running request holds one of them.

If you do not want to write code, the Fish Audio docs point to an upload page in its web app, and AssemblyAI has a playground in the dashboard plus [Blurt](https://github.com/AssemblyAI/blurt), a free MIT-licensed macOS dictation app that uses your own key.
