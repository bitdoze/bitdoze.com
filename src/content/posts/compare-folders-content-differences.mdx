To compare two folders, run `diff -rq old new`. It lists every file that exists in only one of the two folders and every common file whose content differs. Add `-x node_modules` to skip a folder by name. `diff -u` then shows what changed inside one file, `git diff --no-index` counts the changed lines, and `rsync -n` says what a sync would do.

My case was a zip of finished code. I contracted someone to fix a few issues on this Astro site. He sent the result as an archive, and before copying anything over I needed to see which files he had modified.

Every output block below is real. The `diff`, `find`, `sha256sum`, `comm` and `grep` runs come from GNU diffutils 3.10, findutils 4.9.0, coreutils 9.4 and grep 3.11 in an Ubuntu 24.04 container. `rsync` 3.5.1 and `git` 2.43.0 ran on the host. The two folders are `old`, my checkout, and `new`, the unzipped delivery. Between them, three files changed, `README.md` is gone, `new` adds one post, and both sides carry `node_modules`. I ran nothing on macOS, so the macOS notes quote its man pages.

You need `diff`, which Linux and macOS ship. `git` and `rsync` cover the later sections and need no repository. `grep` shows up throughout, and the [Linux commands reference](/linux-commands/) has its options. For two long paths, [zoxide](/zoxide/) jumps between directories.

## Which command answers which question

| You want to know | Command | Reads file contents |
|---|---|---|
| Which files exist on one side only, and which common files differ | `diff -rq -x node_modules old new` | Yes: every common file, on both sides |
| Which names exist on each side, without reading the files | `diff <(cd old && find . \| sort) <(cd new && find . \| sort)` | No |
| What changed inside one file | `diff -u old/package.json new/package.json` | That pair only |
| How many lines changed in each file | `git diff --no-index --stat old new` | Yes |
| Which files were added, modified or deleted | `git diff --no-index --name-status old new` | Yes |
| What a sync would copy, overwrite or delete | `rsync -rn -avi --delete new/ old/` | No: size and time only; with `-c`, yes |
| Whether two files are byte for byte the same | `git hash-object a b` | Those two only |

`diff -rq` reads every file that exists on both sides. `rsync -n` looks at size and modification time only, so it opens no file, and it misses one kind of change.

## How do I compare two folders and see the different files?

Run `diff -rq old new`. It prints one `Only in` line per file that exists on one side only and one `Files ... differ` line per common file whose content differs.

`-r` (`--recursive`) descends into subfolders. `-q` (`--brief`) prints one line per file instead of the changed lines.

```bash
diff -rq old new
echo "exit status: $?"
```

```text
Only in old: README.md
Files old/node_modules/astro/package.json and new/node_modules/astro/package.json differ
Files old/package.json and new/package.json differ
Files old/public/favicon.ico and new/public/favicon.ico differ
Only in new/src: .DS_Store
Only in new/src/assets: brand logo.svg
Files old/src/config/menu.json and new/src/config/menu.json differ
Only in new/src/content/posts: contractor-notes.mdx
Files old/src/layouts/Base.astro and new/src/layouts/Base.astro differ
exit status: 1
```

Two kinds of line:

- `Only in old: README.md`: the entry exists on one side only. The folder is the path you gave `diff` and the name after the colon is the entry. A folder present on one side only gets one line for the folder.
- `Files old/package.json and new/package.json differ`: the same relative path on both sides, with different content.

Two lines are noise. The `node_modules` folder of this site holds 35,940 files, and `.DS_Store` is a settings file macOS Finder writes into folders. Without `-r`, `diff` compares only the top-level files and prints `Common subdirectories: old/src and new/src` for each subfolder.

### Leave the noise out

`-x NAME` (`--exclude=PATTERN`) skips every file or folder with that name, at any depth. Repeat it per name and quote a pattern with wildcards, as in `-x '*.md'`, which skips every Markdown file. `-X FILE` (`--exclude-from=FILE`) reads the patterns from a file, one per line.

```bash
diff -rq -x node_modules -x .DS_Store old new
echo "exit status: $?"
```

```text
Only in old: README.md
Files old/package.json and new/package.json differ
Files old/public/favicon.ico and new/public/favicon.ico differ
Only in new/src/assets: brand logo.svg
Files old/src/config/menu.json and new/src/config/menu.json differ
Only in new/src/content/posts: contractor-notes.mdx
Files old/src/layouts/Base.astro and new/src/layouts/Base.astro differ
exit status: 1
```

`-s` (`--report-identical-files`) makes `diff` list the files it found equal as well, five here. That is the proof that a file missing from the shorter list is identical:

```bash
diff -rqs -x node_modules -x .DS_Store old new
```

```text
Only in old: README.md
Files old/astro.config.mjs and new/astro.config.mjs are identical
Files old/package.json and new/package.json differ
Files old/public/favicon.ico and new/public/favicon.ico differ
Files old/scripts/build.sh and new/scripts/build.sh are identical
Only in new/src/assets: brand logo.svg
Files old/src/config/menu.json and new/src/config/menu.json differ
Files old/src/consts.ts and new/src/consts.ts are identical
Files old/src/content/posts/add-accordion-carrd.mdx and new/src/content/posts/add-accordion-carrd.mdx are identical
Only in new/src/content/posts: contractor-notes.mdx
Files old/src/layouts/Base.astro and new/src/layouts/Base.astro differ
Files old/src/pages/index.astro and new/src/pages/index.astro are identical
```

### Exit status in scripts

`diff` exits with 0 for a match, 1 for differences and 2 when it could not finish:

```bash
diff -rq old/src/pages new/src/pages
echo "exit status: $?"
diff -rq old missing
echo "exit status: $?"
```

```text
exit status: 0
diff: missing: No such file or directory
exit status: 2
```

Exit 1 is a normal result, so `diff -rq old new || echo "they differ"` prints its message for a mistyped path as well. Branch on the status:

```bash
diff -rq -x node_modules -x .DS_Store old new > /tmp/differences.txt
case $? in
  0) echo "same" ;;
  1) echo "differences in /tmp/differences.txt" ;;
  *) echo "diff could not finish, check the paths" ;;
esac
```

```text
differences in /tmp/differences.txt
```

On identical folders that prints `same`; on a missing path, `diff could not finish, check the paths`. The redirect comes first so the output lands in the file while `$?` is still `diff`'s.

### Symbolic links

`diff` follows a symbolic link and compares what it points to. Say `new/astro.config.mjs` is a link to my copy instead of a file:

```bash
rm new/astro.config.mjs
ln -s ../old/astro.config.mjs new/astro.config.mjs
diff -rq -x node_modules -x .DS_Store old new | grep astro.config
echo "grep exit status: $?"
```

```text
grep exit status: 1
```

The link resolves to identical content, so `diff` says nothing. `--no-dereference` compares the link itself:

```bash
diff -rq --no-dereference -x node_modules -x .DS_Store old new | grep astro.config
```

```text
File old/astro.config.mjs is a regular file while file new/astro.config.mjs is a symbolic link
```

A broken link changes the exit status. `diff` prints `diff: new/astro.config.mjs: No such file or directory`, lists the rest, and exits with 2. `find new -xtype l` names such links before `diff` trips over them.

### Flags for folder comparisons

| Flag | Long form | Effect |
|---|---|---|
| `-r` | `--recursive` | Descends into subfolders |
| `-q` | `--brief` | One line per differing file |
| `-s` | `--report-identical-files` | Lists identical files too |
| `-x PATTERN` | `--exclude=PATTERN` | Skips matching names at any depth |
| `-X FILE` | `--exclude-from=FILE` | Reads the patterns from a file |
| `-N` | `--new-file` | A missing file counts as empty, so it shows as added or removed lines |
| none | `--unidirectional-new-file` | Like `-N`, for files missing from the first folder only |
| none | `--no-dereference` | Compares links as links |
| none | `--strip-trailing-cr` | Treats CRLF and LF alike |
| none | `--ignore-file-name-case` | `Menu.json` matches `menu.json` |
| `-i`, `-w`, `-b`, `-B` | `--ignore-case`, `--ignore-all-space`, `--ignore-space-change`, `--ignore-blank-lines` | Ignores case, whitespace or blank lines inside files |

On macOS `diff` is the BSD implementation. Its [man page](https://keith.github.io/xcode-man-pages/diff.1.html), dated January 7, 2025, lists the same `-r`, `-q`, `-s`, `-x`, `-X`, `-N` and `--no-dereference` and defines the same exit statuses. It adds `-P` as the short form of `--unidirectional-new-file`. In folder mode the BSD `diff` compares only regular files and folders and prints a diagnostic for anything else. I did not run it.

<Notice type="warning" title="Check which diff you are running">
Some Linux systems ship a Rust rewrite instead of GNU. [uutils coreutils is the default since Ubuntu 25.10](https://uutils.org/users/), and one host I ran this on prints `diff (pi-uu-diff) 0.8.0` for `diff --version`. Its `-rq`, `-r`, `-rqs` and `-rqN` output matched GNU line for line on these two folders. Two differences showed up. The `diff -r` header omitted the options, and `-q` together with `--brief` stopped with `error: the argument '--brief' cannot be used multiple times`. Check `diff --version` before a script parses the output.
</Notice>

```text
Only in new/src/assets: brand logo.svg
Only in new/src/content/posts: contractor-notes.mdx
```

The common files that differ:

```bash
diff -rq old new | grep differ
```

```bash
diff -rq old new | grep -v node_modules
```

`^` anchors the pattern at the start of the line and `-v` inverts the match. `diff` has still read `node_modules` to produce those lines, so `-x` is for big folders and `grep -v` for noise you noticed late.

### Names with spaces

Only the `: ` separates a folder from a file name in that line. A parse that splits on spaces loses everything after the first space:

```bash
diff -rq old new | grep '^Only in' | awk '{print $4}'
```

```text
README.md
.DS_Store
brand
contractor-notes.mdx
```

The fourth word of `Only in new/src/assets: brand logo.svg` is `brand`. Take everything after the last `: ` instead, as the script below does.

## See what changed inside the files

`diff -rq` stops at the file name. For the content of one file:

```bash
diff -u old/package.json new/package.json
echo "exit status: $?"
```

```text
--- old/package.json	2026-11-10 09:00:00.000000000 +0000
+++ new/package.json	2026-11-20 18:30:00.000000000 +0000
@@ -3,6 +3,7 @@
   "type": "module",
   "version": "1.2.0",
   "dependencies": {
-    "astro": "^4.16.0"
+    "astro": "^4.16.0",
+    "@astrojs/sitemap": "^3.2.1"
   }
 }
exit status: 1
```

`---` and `+++` name the two files and `@@ -3,6 +3,7 @@` gives the line numbers on each side. `-` lines are gone and `+` lines are new. The contractor added the sitemap integration.

Without `-q`, `diff -r` prints the changes of every differing file, in its older default format:

```bash
diff -r -x node_modules -x .DS_Store old new
```

```text
Only in old: README.md
diff -r -x node_modules -x .DS_Store old/package.json new/package.json
6c6,7
<     "astro": "^4.16.0"
---
>     "astro": "^4.16.0",
>     "@astrojs/sitemap": "^3.2.1"
Binary files old/public/favicon.ico and new/public/favicon.ico differ
Only in new/src/assets: brand logo.svg
diff -r -x node_modules -x .DS_Store old/src/config/menu.json new/src/config/menu.json
3a4
>   { "text": "Deals", "link": "/deals/" },
Only in new/src/content/posts: contractor-notes.mdx
diff -r -x node_modules -x .DS_Store old/src/layouts/Base.astro new/src/layouts/Base.astro

```

`6c6,7` means line 6 of the first file became lines 6 and 7 of the second. `3a4` means the second file adds a line 4 after line 3. `<` lines come from the first file, `>` lines from the second. A binary file gets one `Binary files ... differ` line.

### Treat a missing file as empty with `-N`

For a patch, a file that exists on one side only should appear as content. `-N` (`--new-file`) compares it with an empty file:

```bash
diff -r old/src/content/posts new/src/content/posts
echo "exit status: $?"
diff -rN old/src/content/posts new/src/content/posts
echo "exit status: $?"
```

```text
Only in new/src/content/posts: contractor-notes.mdx
exit status: 1
diff -rN old/src/content/posts/contractor-notes.mdx new/src/content/posts/contractor-notes.mdx
0a1,5
> ---
> title: What Changed in This Delivery
> date: 2026-11-20
> ---
> Sitemap integration and a new menu entry.
exit status: 1
```

`--unidirectional-new-file` does the same for files missing from the first folder only, so `README.md` stays an `Only in old` line. Keep `-N` out of `-q` runs. There it turns `Only in` lines into `Files ... differ` lines and hides the side the file is on.

### One patch for the whole delivery

`-u` with `-r` and `-N` makes one patch of the comparison. `git apply --stat` reads it outside any repository:

```bash
diff -ruN -x node_modules -x .DS_Store old new > delivery.patch
git apply --stat delivery.patch
```

```text
 README.md                              |    3 ---
 package.json                           |    3 ++-
 src/assets/brand logo.svg              |    1 +
 src/config/menu.json                   |    1 +
 src/content/posts/contractor-notes.mdx |    5 +++++
 src/layouts/Base.astro                 |    1 +
 6 files changed, 10 insertions(+), 4 deletions(-)
```

The favicon is missing because `diff` writes `Binary files ... differ` into the patch and no data, so binary changes need a copy by hand. Inside `old`, `git apply --check ../delivery.patch` says `applies cleanly`. `git apply` puts the patch on and `git apply -R` takes it back.

## Count the changed lines with git

`git diff --no-index` compares two paths that need no repository. The [git commands reference](/git-commands/) has a section on `git diff` as well. Say `new/scripts/build.sh` lost its executable bit, `chmod 644 new/scripts/build.sh`. `--stat` gives one line per file:

```bash
git diff --no-index --stat old new
echo "exit status: $?"
```

```text
 old/README.md => /dev/null                              |   3 ---
 {old => new}/node_modules/astro/package.json            |   2 +-
 {old => new}/package.json                               |   3 ++-
 {old => new}/public/favicon.ico                         | Bin 514 -> 584 bytes
 {old => new}/scripts/build.sh                           |   0
 /dev/null => new/src/.DS_Store                          | Bin 0 -> 6148 bytes
 /dev/null => new/src/assets/brand logo.svg              |   1 +
 {old => new}/src/config/menu.json                       |   1 +
 /dev/null => new/src/content/posts/contractor-notes.mdx |   5 +++++
 {old => new}/src/layouts/Base.astro                     |   1 +
 10 files changed, 11 insertions(+), 5 deletions(-)
exit status: 1
```

`{old => new}/package.json` is git's way of writing the two paths of one file. `old/README.md => /dev/null` is a deletion. `{old => new}/scripts/build.sh` shows zero changed lines because git counts a mode change as a modification. `diff -q` prints nothing for that pair, because it reads content only. `--summary` names the change:

```bash
git diff --no-index --summary old new
```

```text

 create mode 100644 new/src/.DS_Store
 create mode 100644 new/src/assets/brand logo.svg
 create mode 100644 new/src/content/posts/contractor-notes.mdx
```

`--name-status` gives the same as one letter per file: `A` added, `M` modified, `D` deleted. It prints the old path for `M` and `D` and the new path for `A`. git 2.43.0 takes no pathspec in this mode and answers with the usage text and exit status 129, so the noise goes through `grep`. The [git documentation](https://git-scm.com/docs/git-diff) says newer releases accept pathspecs after two folders. I did not run that.

```bash
git diff --no-index --name-status old new | grep -v -e node_modules -e .DS_Store
```

## Preview a sync with an rsync dry run

`rsync -n` says what would happen if you made the differences go away:

```bash
rsync -rn -avi --delete --exclude node_modules --exclude .DS_Store new/ old/
```

```text
sending incremental file list
*deleting   README.md
.d..t...... ./
>f.st...... package.json
>f.st...... public/favicon.ico
.f...p..... scripts/build.sh
.d..t...... src/
.d..t...... src/assets/
>f+++++++++ src/assets/brand logo.svg
>f.st...... src/config/menu.json
.d..t...... src/content/posts/
>f+++++++++ src/content/posts/contractor-notes.mdx
>f.st...... src/layouts/Base.astro

sent 624 bytes  received 74 bytes  1,396.00 bytes/sec
total size is 1,816  speedup is 2.60 (DRY RUN)
```

`-n` (`--dry-run`) changes nothing. `-a` is recursive and preserves permissions, times, links, owner and group. `-v` prints the file list and `-i` (`--itemize-changes`) adds the code in front of each name. `--delete` makes the destination a mirror, so rsync lists files that the source lacks too. `--exclude` does for rsync what `-x` does for `diff`. The [rsync exclude guide](/exclude-directories-files-copy-remote-machine/) has the pattern rules.

The codes:

| Code | Meaning |
|---|---|
| `>f+++++++++` | New file rsync would copy: `>` sent, `f` file, nine `+` for new |
| `>f.st......` | File rsync would overwrite: size (`s`) and time (`t`) differ |
| `.f...p.....` | File rsync does not copy and only gives new permissions (`p`) |
| `.d..t......` | Folder whose timestamp rsync would update |
| `cd+++++++++` | Folder rsync would create |
| `*deleting` | File the source lacks, so rsync would delete it |

The first character is the action (`>` copy, `.` no copy, `c` create, `*` message) and the second the type (`f` file, `d` folder). The other nine are attributes in a fixed order: checksum, size, time, permissions, owner, group, access time, ACLs, extended attributes. In those nine, `.` is unchanged, `+` is new and a letter is changed. This run copies six files, deletes one and fixes one permission. `diff -rq` listed eight files here, the same seven plus `src/consts.ts`, which the dry run has not seen.

### Why does the dry run skip a file that changed?

rsync's quick check compares size and modification time only, in whole seconds by default, so an edit that keeps both gets no line. To show it, I changed one letter in `new/src/consts.ts` and gave the file the size and timestamp of the old copy:

```bash
sed -i 's/Bitdoze/Bitdozc/' new/src/consts.ts
touch -r old/src/consts.ts new/src/consts.ts
diff -q old/src/consts.ts new/src/consts.ts
stat -c '%s bytes, %y, %n' old/src/consts.ts new/src/consts.ts
```

```text
Files old/src/consts.ts and new/src/consts.ts differ
88 bytes, 2026-11-10 09:00:00.000000000 +0000, old/src/consts.ts
88 bytes, 2026-11-10 09:00:00.000000000 +0000, new/src/consts.ts
```

`diff` sees the change and the dry run does not. `grep consts` on the dry run's output prints nothing. `-c` (`--checksum`) makes `rsync` hash every file of equal size first:

```bash
rsync -rnc -avi --delete --exclude node_modules --exclude .DS_Store new/ old/ | grep consts
```

```text
>fc........ src/consts.ts
```

The `c` in the third position is the checksum difference. `-c` reads every file on both sides, so it costs what `diff -rq` costs.

### The slash at the end of the source

A trailing slash on the source means the contents of the folder. Without it `rsync` copies the folder itself into the destination, one level too deep:

```bash
mkdir -p slash/src slash/dst
echo one > slash/src/file.txt
echo keep > slash/dst/file.txt
rsync -rn -avi slash/src slash/dst
rsync -rn -avi slash/src/ slash/dst
```

```text
sending incremental file list
cd+++++++++ src/
>f+++++++++ src/file.txt

sent 107 bytes  received 23 bytes  260.00 bytes/sec
total size is 4  speedup is 0.03 (DRY RUN)
sending incremental file list
>f.s....... file.txt

sent 87 bytes  received 19 bytes  212.00 bytes/sec
total size is 4  speedup is 0.04 (DRY RUN)
```

The first run would create `dst/src/` and leave `dst/file.txt` alone. The second would replace `dst/file.txt`. On `old` and `new`, `rsync -rn -avi --delete new old` starts with `cd+++++++++ new/`, so `new` would land in `old/new/` and nothing in `old/` would change.

`-n` is the only thing between this command and a real sync, so leave it in until every line of the output is expected. For the real run, `--backup --backup-dir` moves everything the sync overwrites or deletes into a folder:

```bash
cp -a old old.copy
rsync -a --delete --backup --backup-dir=../removed new/ old.copy/
ls removed
```

```text
README.md
node_modules
package.json
public
src
```

`removed/` holds the five entries the sync replaced or deleted. That folder is the undo. The sync itself was incomplete, and `diff -rq` on the result says so:

```bash
diff -rq old.copy new
```

```text
Files old.copy/src/consts.ts and new/src/consts.ts differ
```

`consts.ts` kept its old content because the quick check saw no reason to copy it. So the order is dry run, real run, then `diff -rq` on the result. Add `-c` when a file can change without changing its size or second.

## Sort the output with a small script

When the next command needs the lists, turn the lines into `added`, `removed` and `modified` records:

```bash
#!/usr/bin/env bash
# tree-diff.sh OLD NEW
# Prints one line per file that NEW adds, removes or modifies relative to OLD,
# with the path relative to the tree root.
# A name that contains ": " or " and " is misparsed. Use
# git diff --no-index --name-status for trees with such names.
old=${1%/}; new=${2%/}

report=$(diff -rq -x node_modules -x .DS_Store "$old" "$new"); status=$?
if [ "$status" -gt 1 ]; then
  printf 'diff exited with status %s\n' "$status" >&2
  exit "$status"
fi

while IFS= read -r line; do
  case $line in
    "Only in $new: "*|"Only in $new/"*)
      path=${line#Only in }; name=${path##*: }
      dir=${path%: "$name"}; rel=${dir#"$new"}
      printf 'added    %s\n' "${rel:+${rel#/}/}$name"
      ;;
    "Only in $old: "*|"Only in $old/"*)
      path=${line#Only in }; name=${path##*: }
      dir=${path%: "$name"}; rel=${dir#"$old"}
      printf 'removed  %s\n' "${rel:+${rel#/}/}$name"
      ;;
    "Files $old/"*" differ")
      rel=${line#Files "$old"/}; rel=${rel%" and "*}
      printf 'modified %s\n' "$rel"
      ;;
    "File "*)
      printf 'conflict %s\n' "$line"
      ;;
  esac
done <<< "$report"
```

Save it as `tree-diff.sh`. The name is everything after the last `: `, so spaces survive. A failure of `diff` ends the script with `diff`'s own exit status instead of a half list. `sort` groups the records by label:

```bash
bash tree-diff.sh old new | sort
```

```text
added    src/assets/brand logo.svg
added    src/content/posts/contractor-notes.mdx
modified package.json
modified public/favicon.ico
modified src/config/menu.json
modified src/consts.ts
modified src/layouts/Base.astro
removed  README.md
```

The count is the check: eight lines from `diff -rq`, eight records from the script. A folder on one side only gives one record for the folder, `added    src/components`, because that is the line `diff` prints. The script misparses a name that contains `: ` or ` and `, so use `git diff --no-index --name-status` for such folders.

## Compare checksums when dates and modes do not matter

`diff -rq` needs both folders on one machine and reads them together. A checksum list splits that in two: hash every file once, keep the small list, compare lists instead of folders. Dates, permissions and names play no part in a hash.

```bash
(cd old && find . -type f -not -path './node_modules/*' -not -name .DS_Store -exec sha256sum {} + | sort -k 2) > old.sha
(cd new && find . -type f -not -path './node_modules/*' -not -name .DS_Store -exec sha256sum {} + | sort -k 2) > new.sha
head -3 old.sha
```

```text
b22c6fd0ac24afafa671f33d166ff29e4f44a5b6130b8da1783c499bf0f916f0  ./README.md
120ba8fb0361a1d1cc97a40129d83406307d6e1f131ea3601c607b6980e78f22  ./astro.config.mjs
13d8cf208372a9146bf8b5c49a492d58df8d78185651c3b2f641cefb012d79fa  ./package.json
```

Each line is the SHA-256 of the content, two spaces, then the path. Run the second line on the other machine and copy `new.sha` over; the rest works on two text files. `comm` prints the lines unique to the first file (`-23`) or to the second (`-13`), with `cut` taking the path after the hash:

```bash
comm -23 <(cut -d' ' -f3- old.sha) <(cut -d' ' -f3- new.sha)
```

```text
./README.md
```

```bash
comm -13 <(cut -d' ' -f3- old.sha) <(cut -d' ' -f3- new.sha)
```

```text
./src/assets/brand logo.svg
./src/content/posts/contractor-notes.mdx
```

A path with two different hashes is the same name with different content. This pipeline keeps the paths `diff` reports on both sides:

```bash
diff old.sha new.sha | grep '^[<>]' | sed -E 's/^[<>] [0-9a-f]{64}  //' | sort | uniq -d
```

```text
./package.json
./public/favicon.ico
./src/config/menu.json
./src/consts.ts
./src/layouts/Base.astro
```

For the same content under different names, group by hash. `new` has one SVG in two places, `src/assets/brand logo.svg` and `public/brand-logo.svg`. `-w 64` compares only the hash and `-D` prints every line that has a twin:

```bash
cp "new/src/assets/brand logo.svg" new/public/brand-logo.svg
(cd new && find . -type f -not -path './node_modules/*' -not -name .DS_Store -exec sha256sum {} + | sort -k 2) > new.sha
sort new.sha | uniq -w 64 -D
```

```text
678f2b25181b2d024f509ee159abb63795427c002f01682a3d8b8a3032d0f918  ./public/brand-logo.svg
678f2b25181b2d024f509ee159abb63795427c002f01682a3d8b8a3032d0f918  ./src/assets/brand logo.svg
```

For two files, `git hash-object` gives identical content the same id, whatever the name, date or mode:

```bash
git hash-object old/src/pages/index.astro new/src/pages/index.astro "new/src/assets/brand logo.svg" new/public/brand-logo.svg new/package.json
```

```text
6f9d3c0b6d62b942e5f2b930b539176944540fe0
6f9d3c0b6d62b942e5f2b930b539176944540fe0
```

The same `find` builds such lists on a Mac, the tool behind [finding the largest files on a Mac](/mac-find-big-files/). If one folder sits on another machine, run the `find` line there and copy the list. Hashing through an [NFS](/setup-nfs-linux/) mount pulls every byte over the network. The `sed` in that pipeline only strips the hash prefix. [sed search and replace](/sed-search-replace/) shows the full syntax. For folders a backup tool manages, that tool's own check comes first, for example [Pluton](/pluton-self-hosted-backup/) for Restic repositories.

## What goes wrong and the fix

Each row comes from a run on `old` and `new` or from a scratch pair built to trigger it.

| What you see | Why | Fix |
|---|---|---|
| Thousands of `node_modules` or `.DS_Store` lines | `diff` compares everything it finds | `-x node_modules -x .DS_Store` |
| `Only in old/: README.md` | A trailing slash on a folder argument | Pass `old` and `new` without it, or strip it like the script (`${1%/}`) |
| `diff: new/x: No such file or directory`, exit status 2 | A symbolic link points to nothing | `find new -xtype l`, then `--no-dereference` |
| `File old/x is a regular file while file new/x is a directory` | A file became a folder, or the reverse | Decide by hand which is right; the tools only report it |
| `cd+++++++++ new/` in a dry run | The source lost its trailing slash | `new/ old/` |
| A changed file missing from a sync | Same size and same second as the old copy | `-c`, then `diff -rq` on the result |
| Two equal-looking files reported different | CRLF against LF line endings | `--strip-trailing-cr` |

## FAQ

<Accordion label="Does diff -rq compare file contents or only names and dates?" group="faq">
It compares contents. `diff` reads every common file and compares the bytes, and a changed date or permission produces no line. That is why `diff -q` says nothing about `scripts/build.sh` after `new` dropped its executable bit, while `git diff --no-index --summary` shows `mode change 100755 => 100644`.
</Accordion>

<Accordion label="How do I compare only the folder structure?" group="faq">
Compare sorted name lists instead of contents: `diff <(cd old && find . | sort) <(cd new && find . | sort)`. It reads no file and answers which names exist on each side. `diff -rq` answers that too, and which common files differ.
</Accordion>

<Accordion label="How do I list the files that exist on one side only?" group="faq">
`diff -rq old new | grep '^Only in'` keeps those lines, four in `old` and `new`. `Only in old` names a file that `new` lacks and `Only in new` one that `old` lacks. `comm -23` and `comm -13` on two checksum lists give the same split as bare paths.
</Accordion>

<Accordion label="What do the exit codes of diff -rq mean in a script?" group="faq">
0 means no differences, 1 means `diff` found differences and 2 means trouble, as in `diff: missing: No such file or directory`. Exit 1 is a normal result, so test for 2 separately. `diff -rq a b || echo failed` prints its message on both.
</Accordion>

<Accordion label="What makes rsync ignore an edited file?" group="faq">
rsync's quick check compares size and modification time only, in whole seconds by default. A file edited with the same length and timestamp, like `src/consts.ts` in the example, gets no line. Add `-c` and rsync hashes files of equal size first. The line then reads `>fc........ src/consts.ts`.
</Accordion>

<Accordion label="How do I compare two folders on different machines?" group="faq">
Build the `sha256sum` list from the checksum section on each side, copy the two list files to one machine and compare them with `comm` or `diff`. You read each folder once, on the machine that holds it. `diff -rq` never sees the other folder.
</Accordion>

<Accordion label="Can I undo a sync that used --delete?" group="faq">
Not after the fact, so run the same command with `-n` first and read every line. For the real run add `--backup --backup-dir=../removed`. On `old` and `new` that folder then held the five entries the sync had overwritten or deleted.
</Accordion>

<Accordion label="Does this work on macOS?" group="faq">
The BSD `diff` on macOS takes the same `-r`, `-q`, `-s`, `-x`, `-N` and `--no-dereference` flags and prints the same two line types. Its man page is dated January 7, 2025; I did not run it here. rsync differs. Since macOS 15.4 macOS ships only openrsync as `rsync`, so `brew install rsync` gets you rsync 3.
</Accordion>
